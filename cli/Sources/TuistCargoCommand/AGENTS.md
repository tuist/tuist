# Cargo decoration

`tuist cargo` forwards Cargo's command line without redefining its test semantics. The same command can be installed as a mise Cargo wrapper. `test-build` is Tuist's build-once nextest shard planner; `nextest run` applies a shard only when explicitly configured.

- Project, server, and network configuration is exclusively `tuist.toml` plus environment overrides, even in a checkout that also has `Tuist.swift`. Use `ConfigLoader.loadCargoConfig`; do not add Cargo options to the ProjectDescription Swift configuration API.
- Caching is opportunistic by default: use only the bundled, protocol-compatible `tuist-cargo-cache` sibling, otherwise ordinary Cargo, without a `[cargo]` configuration section or enablement knob. Never resolve an external cache-tool executable. The copied native engine uses `CacheURLStore` endpoint discovery and `GetCacheTokenService`; remote setup failure leaves isolated local caching available. Clear inherited internal `TUIST_CARGO_CACHE_*` settings and ignore independent cache-tool configuration. Remote storage uses Kura's standard Bazel Remote Execution API; do not reintroduce an alternative HTTP bridge. Disable target views, lanes, scheduler and learned-incremental rewriting to preserve Cargo planning. Executable/link caching remains bypassed pending divergence qualification.
- Collect bounded, allowlisted metrics from native stats version 5 after the subprocess finishes; emit optional wire version 1, not private agent events. `CargoCacheDetailsReport` separately collects the native public NDJSON inspection stream: keyed task outcomes, averaged measured per-key operations, actual SHA-256 CAS operations and observed closure references. Bound inspection to 64 files / 8 MB / 30,000 records, 2,000 tasks, 5,000 CAS operations, 128 references per task and a 4 MB wire payload; reject nonregular/symlink files and flag incomplete capture. Do not reconstruct task rows from compiler observations or aggregate counters. Never infer per-action local/remote provenance or wall-clock savings. Reports are bounded by file count, individual/aggregate bytes and saturated integer counters; refreshed cache credentials live in mode-0600 files in the private invocation directory and never enter reports.
- The CLI entry point dispatches Cargo before generic flag stripping and command analytics. Preserve Cargo's `--quiet`/`--verbose` arguments; compiler hooks must not authenticate or publish CLI command events.
- Compiler observers write invocation-local records, never upload or acquire authentication. Skip compiler probes and cached restores. Preserve existing global compiler wrappers without wrapping their cached results as rustc executions; these wrappers bypass native caching and compiler observation. Custom workspace wrappers must not be mistaken for real rustc executions.
- The primary command inherits terminal stdio. Pin rustup's default toolchain before Cargo changes directories, as its proxy does. Cargo's nightly `-C` option is forwarded without observation; sharding rejects it rather than executing an unfiltered suite.
- Keep output, argument order, failures and signals intact. Nested Cargo commands must not recursively decorate the same session.
- Nextest discovery and JUnit are distinct: enumeration is not execution. Never report tests omitted by fail-fast as passing. Nextest commands do not submit build reports: their wall time includes test execution. `test-build` remains a build report for the explicit compile-once/archive phase.
- Stable test identities use nextest binary IDs and Rust namespaces, not artifact hashes or checkout paths.
- Nextest binaries are concurrent module-level units, not Xcode's `parallelizable_modules` suite-level units. Declare `concurrent_modules` and reuse the shared measured-concurrency planner with a longest-binary floor. Binary/suite timings use complete attempt timestamp windows, including retry delays and ignoring skipped cases; preserve individual work durations. Do not claim summed fallback timings as measured evidence: omit module execution mode when timestamps or run wall time are missing. Never infer utilization from CPU count or nextest's thread limit.
- Analytics failures must not change Cargo's exit status. Planning/downloading failures must fail a shard rather than execute the entire suite.
- Repeatable archive upload/download, exactly-once shard execution, no worker recompilation, merged reporting, and fail-closed checks live in `cli/Tests/Fixtures/CargoSharding/AGENTS.md`.
- Keep documentation and bounded parsing tests aligned with each supported workflow. Coverage and selection must never infer unobserved execution.
