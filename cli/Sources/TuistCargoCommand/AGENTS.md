# Cargo decoration

`tuist cargo` forwards Cargo's command line without redefining its test semantics. Plain `cargo test` (including doctests) reports validated standard libtest outcomes on stable Rust. `test --no-run` with shard-count options plans target-level shards; `TUIST_SHARD_INDEX` applies assignments to `test`. Plain tests enforce shared mute/skip quarantine. Nextest remains optional for richer timing, retries, and archive sharding. The same command can be installed as a mise Cargo wrapper. `test-build` is Tuist's build-once nextest shard planner; `nextest run` applies a shard only when explicitly configured.

## Compilation cache

- The implementation is Swift in this module, not a vendored engine, external cache tool, Rust executable, or mechanical translation. There are two exceptions, both embedded C built with `xcrun clang` into the cache: `CargoReadRecorder`'s interposer, which must be a dylib loaded into rustc and build scripts, and `CargoHookServer`'s client. Cargo starts that client for every rustc instead of the Swift binary (about 35 ms of startup per hook); it carries no cache logic. It asks the outer command over a private Unix socket, writes a hit's messages, or runs the command the server returns and streams rustc's stderr through the server, which certifies metadata before returning the bytes to forward. After rustc exits, the server admits and certifies the outputs (and stores and shims a build script's compilation, which Cargo runs next) before reporting the exit, then publishes on the connection's thread; the session waits for those publications before reporting and collecting units. The client stays rustc's parent so jobserver descriptors, stdin and the process group are Cargo's. It drops `DYLD_*` on entry as the `/bin/sh` wrapper it replaces did (SIP), runs from its stable path in the cache (Cargo keys `.rustc_info.json` on the wrapper's path and modification time, so a per-session copy made Cargo probe rustc on every build; recorded build-script runs drop it from `RUSTC_WRAPPER` because it equals `TUIST_CARGO_SCRIPT`), and runs `tuist cargo __compiler` when the server is unreachable before rustc started; once rustc ran, a lost connection exits with rustc's status. The pruner never evicts the client or the recorder: Cargo starts them by path for every compilation of a running build. Server-side probes drop `CARGO_MAKEFLAGS`/`MAKEFLAGS`/`MFLAGS`, and `CommandRunner` inherits jobserver descriptors only when they are pipes: in the server the hook's descriptor numbers name its own sockets and kqueues, and inheriting them made every probe fail and silently turned the per-crate cache off. Preparation failures other than a refusal are logged under `TUIST_DEBUG`. `tuist cargo __compiler` remains the invocation-local compiler wrapper. Keep it free of authentication and command-event publication. Keep debug diagnostics on stderr rather than bootstrapping the generic Noora logger; stdout belongs to Cargo/rustc's protocol.
- `CargoCacheSetup` reads Tuist's existing configuration, resolves `CacheURLStore` and `GetCacheTokenService`, and refreshes a private mode-0600 token file. Failed remote setup leaves an isolated local cache. Support-cache pruning runs at most hourly (stamp `.tuist-cargo-pruned` in the `Cargo` category): walking every support cache costs more than a warm build. Reporting metadata (one `git rev-parse` for the commit and branch, the origin URL, and the rust version from the session's toolchain identity) is gathered alongside the build, and the `cc` shim's `xcrun`/`otool` probe is remembered per developer directory and compiler identity. Inject endpoint/token services, `CacheDirectoriesProviding`, and `FileSysteming`. Store entries in the shared `Cargo` cache category so `XDG_CACHE_HOME`, normal cache cleaning, support-cache retention, and runner byte budgets apply. The shared pruner addresses individual action/blob files and staging entries beneath each project, not the perpetually hot project directory. Every layer stores blobs through `CargoBlobStore` (`blobs/<hash>`, published by clone, hash and atomic `rename`); reads renew a blob's modification time when it is more than an hour old, so active contents stay recent without changing the identity verified digests are recorded with. There is no `[cargo]` configuration section or enablement knob. Clear inherited internal cache settings. Remote reads and writes use Kura's shared REAPI transport and server-issued cache grants; do not add client-side CI-provider or branch eligibility gates. Denied uploads preserve the local entry and never fail the build.
- `CargoCacheInvocation` admits pure libraries emitting dep-info, metadata, and an rlib, including workspace/path libraries and generated sources. Registry leaves retain the full-package fast path. Other libraries hash every source an earlier compilation's dep-info named (including non-Rust includes), found through a source list under a declared key (relocated arguments, keyed environment, root source and extern digests) in `CargoReadIndex`, locally and remotely, plus the entries of every directory holding a source so a file that would change module resolution misses. Without a list the compilation runs first and is keyed afterwards from the dep-info rustc writes anyway (sources must predate preparation); there is no separate discovery run of rustc unless no cache directory exists. A deferred compilation also runs recorded where the recorder exists: only after rustc does admission see every source, and when it refuses one (assembly or `#[link]` in a submodule) the same build stores the recorded result instead. When dep-info names other sources than the list, the list is replaced and the compilation is published under the new key on the same build. `cli/Tests/Fixtures/CargoCache/sources_e2e.sh` covers added and edited submodules and ambiguous modules. Keys also cover complete direct extern artifacts, compiler/toolchain libraries (the sysroot's top-level `lib` files plus the host `lib/rustlib/<host>` tree from `--print target-libdir`, excluding its linker-only `bin`; other installed targets and `rust-src` stay out of keys), arguments, working directory and the keyed build environment (an allowlist: `CARGO_*`, `RUSTC*`, `RUST_*`, `RUSTFLAGS`, `OUT_DIR`, `SDKROOT`, `RUSTUP_TOOLCHAIN` and `*_DEPLOYMENT_TARGET`). Never hash the concurrently changing `target/.../deps` directory. Exclude Tuist credentials/reporting settings and bounded CI metadata prefixes only when compiler dep-info proves the crate did not read them (including unset `option_env!` inputs). Version-6 keys are relocatable; keep Command/Action and invocation key versions aligned. Recheck fingerprints before publication and restoration. Resolve bare and absolute compiler paths like the process launcher. Accept the known rustup proxy only with a pinned toolchain, including both proxy and compiler bytes; arbitrary custom launchers bypass caching.
- A dependency can export generic MIR or macros with backend filesystem reads absent from dep-info. Require every explicit `.rlib`/`.rmeta` extern to have a private session-local admission certificate tied to its exact artifact digest. Publish certificates only after source/dependency validation and fingerprint rechecking. Certify atomically installed metadata before forwarding rustc's metadata artifact notification: Cargo starts pipelined dependents at that boundary, before upstream codegen finishes. This certificate establishes input admission, not compilation success; never publish cache entries for failed compilations. Certify rlibs after successful compilation and both artifacts after verified restoration. Admission propagates through the dependency closure; missing/corrupt certificates bypass caching, not compilation. Scan every discovered input for assembly (including `naked_asm`), native-link attributes and identifier concatenation; ordinary `concat!` remains supported. Match code tokens only: comments and string/char literal contents are blanked first, and sources that do not lex bypass caching. `link` is rejected only as `link(`, so identifiers and prose such as "symbolic link" stay eligible. Strict admission rejects proc-macro consumers transitively, native search paths/bundling, nonstandard codegen, incremental compilation, custom targets and executables; recorded invocations (below) take what it rejects. Do not substitute metadata-only output equality for this contract: changing rustc's emit modes changes metadata, and metadata does not cover backend reads.
- Reject grouped Rust short options such as `-gL` that hide search paths or codegen/unstable flags; supported joined codegen, search and lint operands remain eligible. Bypass Rust caching under inherited `LD_`/`DYLD_` loader overrides, including library-search settings: hashing their string values cannot cover injected code or its reads. Only the recorder sets `DYLD_INSERT_LIBRARIES` itself, for the processes it records. This conservative boundary also bypasses ordinary Linux Cargo jobs when Cargo supplies `LD_LIBRARY_PATH`; Linux caching is not qualified by the arm64 macOS workload.
- `CargoRelocation` makes keys and stored text path-free, like Bazel's execroot-relative actions. It maps the sysroot, Cargo home, `TUIST_CARGO_TARGET_DIR` and `TUIST_CARGO_WORKSPACE_ROOT` (longest first) to `@@TUIST_*@@` placeholders in every key input, dep-info file and stored stderr, and every hooked compilation runs with matching `--remap-path-prefix` flags (the workspace maps to relative paths). Remapping does not cover what a crate embeds itself (for example `env!("CARGO_MANIFEST_DIR")` in a proc macro): `boundRoots` scans outputs for root paths, ignoring the Mach-O `__LINKEDIT` segment and a dylib's own `LC_ID_DYLIB` install name, and an output naming a root its key did not include is not stored. Units bound to a root restore only where that root is the same.
- `CargoRecordedInvocation` keys what strict admission cannot key in advance (proc-macro consumers, assembly, native libraries and their dependents, and linked binaries, stored with their executable bit; a build script's binary is stored before `CargoBuildScript` shims it, and a hit installs the shim), like Bazel's dependency discovery or blaze's read tracking. On arm64 macOS, `CargoReadRecorder` compiles its embedded C interposer with `xcrun clang` into the cache and injects it with `DYLD_INSERT_LIBRARIES`; it logs file opens, stats, directory listings, `readlink`, environment reads, process spawns and network connections. Recorded processes exec the resolved binary directly because SIP strips `DYLD_*` through `/usr/bin/env`; reentrancy uses a pthread key because `__thread` aborts dyld. Reads under `/dev/` are not inputs (`/dev/null`'s modification time changes whenever anything writes to it). Spawns are counted only when they happen: `posix_spawn`/`posix_spawnp` log after succeeding (with the guard held, since one searches PATH through the other), and an `execve` that returns logs `Y` to withdraw its attempt, so PATH searches no longer make build scripts that run `rustc` uncacheable. A `POSIX_SPAWN_SETEXEC` spawn replaces the process, so it is logged like `execve`. Processes of allowed programs (the linker) do not count towards the processes that loaded the recorder. `CargoReadSet` refuses to cache when a child did not load the recorder, on any network connection, or on writes outside the outputs. Keys take two steps: a declared key (relocated arguments, keyed environment, externs by content, toolchain identity including the linker for proc macros and binaries) selects the read set of an earlier run in `CargoReadIndex` (local and REAPI), and that set's current contents, missing paths and directory listings complete the key. The unrecorded linker searches a link's `native=`/`all=` directories, so the declared key also holds the content of every native library in them outside the sysroot (more than 64 in one directory bypass caching). A link reads every rlib of its closure whole, so those reads stay in its read set even under the target directory: a `-sys` crate's bundled archive changes its rlib but not the metadata of the crates between it and the binary. Never certify recorded outputs for strict dependents. Linux has no recorder, so these compilations still run there.
- `CargoBuildScript` caches build-script runs, like a Bazel action whose outputs are `OUT_DIR` and stdout. After compiling a `build_script_<stem>` crate (Cargo names it after the script's file stem, so `build = "build/main.rs"` gives `build_script_main`), it moves the binary to `*.tuist-real`, records its declared hash in `*.tuist-made-of` and installs a shell shim that runs `$TUIST_CARGO_SCRIPT cargo __script`. In a served session that is the hook client, which sends an `S` request so the outer process decides and stores the run (no Swift startup per script); otherwise it is `tuist cargo __script`. The runner records the run, stores the relocated `OUT_DIR`, stdout and stderr under `script-actions/`, and restores them only into an empty `OUT_DIR` when the recorded reads still match. Cargo's `rerun-if` handling stays authoritative for when a script runs.
- `CargoInputHasher` shares compiler/toolchain and immutable extern digests only inside the outer command's private session, publishing bounded identity/digest records atomically, and keeps the records it read or wrote in memory so hooks served by the same process skip the record files and their locks. A session served by the hook server keeps its records in memory only, seeded from the persistent toolchain records, and writes no record files; a hook in another process (the fallback) hashes for itself. Source admission remains invocation-local. Batch toolchain memo reads without caching directory discovery or skipping per-file identity checks. Serialize toolchain tree hashing per session with an advisory file lock so concurrent compilers reuse one hasher's records instead of all hashing the toolchain at once; lock failure only loses that sharing. Recheck device/inode/size/mode and exact mtime/ctime on every use; coarse timestamps require rehashing and mutations during reads reject the entry. Missing/corrupt/unwritable session records fall back to hashing. The outer command resolves the toolchain and linker identities and hashes the toolchain files strict keys take into those records while Cargo is probed and units restore, before any hook starts; hooks still recheck every record's identity. The toolchain identity is also recorded under the sysroot compiler's absolute path, which build scripts name in `RUSTC`, and asks that compiler for `-vV` directly; the linker identity's `xcrun` answers persist in the cache with the developer directory and the identities of its `clang`, `ld` and `SDKSettings.json`, unless `SDKROOT` or `TOOLCHAINS` select them. One `rustup show active-toolchain` names the toolchain directory Cargo is taken from. Source admission uses a complete bounded read and its exact digest in the key; do not independently read one source version for admission and another for hashing. Keep stat/streaming operations narrow because FileSystem does not expose this identity. Reject file/output symlinks, incomplete or oversized input sets; toolchain file links may resolve only within the toolchain. Inputs must remain stable through probing, compilation and reuse.
- Compiler dep-info must agree with the discovered source set before publication (the registry-leaf fast path requires package-local dependencies). Exclude volatile wrapper/session/jobserver settings only when dep-info proves they were not read. Never cache failed compiler executions. Ignore valid terminal-width arguments in keys. Publish and restore only empty stdout and stderr made of rustc's JSON messages (artifact notifications, diagnostics and future-incompatibility reports). Stored diagnostics carry a leading `tuist-diagnostic-width` marker with the width they were rendered at, and restore only at that width (a hit replays them, so Cargo still shows a cached crate's warnings); invalid/duplicate width arguments retain their original keys. An explicit empty project-write grant in the server-issued token is an advisory session-local read-only hint, refreshed with the token; skip known-denied remote publication without changing local caching or Kura's authoritative authorization. Unknown token formats still attempt uploads. Hits must not become compiler-observation rows.
- `CargoCompilationCache` uses the existing `TuistREAPI` transport with project-scoped SHA-256 Command/Action indexes and content blobs, never a new HTTP protocol. Verify every output digest and the complete expected output set, including bounded crate-prefixed split-debug objects, before materialization. Probe the complete local cache before constructing a remote transport. Kura's tenant/account header and REAPI project instance name are separate: `owner/project` becomes header `owner` plus instance `project`, never instance `owner/project`. Cache metadata calls use a one-second request timeout; large artifacts retain the shared transfer guards. A failed remote read disables publication for that compiler and opens a private session-scoped circuit so later compilers do not repeatedly wait on the same unavailable endpoint; a new Cargo command retries normally. Publish remote action results only after all referenced blobs exist. Corrupt, missing, unsupported, or unavailable entries fall back to compilation. Cache failures must not replace Cargo/compiler failures.
- `CargoClangInvocation` shares that storage through `CargoCacheAction` for individual native C compilations inside build scripts. Initial support is arm64 macOS with the default Apple `cc`, not C++, arbitrary compilers, or script execution. Preserve explicit compiler selection and pass through cc-rs probes/non-C actions. Install a stable project-cache wrapper path so cc-rs's environment tracking does not invalidate no-op builds; keep its compiler identity outside the `.xctoolchain` path to preserve cc-rs's flag generation. Keys include the fresh driver plan, complete expanded preprocessor output, discovered source/header contents, resolved SDK metadata, real compiler binary, OS build, arguments, cwd and environment. Repeat discovery before restoration and after successful compilation; rehash inputs before publication/materialization. Admit only parsed known flags, empty or identifier-only literal asm templates, and no config files, injected libraries/options, modules/PCH, plugins, external assemblers or auxiliary outputs. `cargo __native` uses the same early dispatch, failure fallback and bounded measurements as the Rust hook. Its tests are in `cli/Tests/Fixtures/CargoCache/native_e2e.py`; do not claim Linux, x86-64 or cross-worker qualification.
- Native version-3 keys re-resolve input symlinks at every fingerprint and include both the original path and resolved target path/content. This admits SDK header links without relaxing the output-symlink restriction. Remote native admission initially requires a source of at least 32 KiB as a cost heuristic: small cc-rs actions often compile faster than remote discovery/transfer. The stable shell wrapper bypasses those small inputs without starting Swift; failed size probes still use full admission. Preserve inherited shell options and explicit compiler selection. Local-only caching retains the full native admission above. The threshold is a cost heuristic, not a correctness condition or prediction of every compilation's cost. Reject unsupported Rust extern types before toolchain discovery. Keep the registry fast path's stricter source validation before permissive root validation: digest-bound admission memoization is not interchangeable between policies.
- Install native interception only through the stable `cc` PATH shim, never a higher-priority `CC_<target>` override. Preserve compiler selection performed later by build scripts and cc-rs. When executing the shim, remove its own directory from the current PATH and resolve the compiler again; preserve other PATH entries and bypass caching for non-Apple selections. Do not shadow cc-rs's separate `clang` selection.
- Hooks served by `CargoHookServer` use the session's REAPI connection directly. `CargoRemoteCache` shares it with hooks in other processes (the shell-wrapper fallback) through bounded atomic request/response files in a private command-session directory; the broker runs only when there is no hook server. Only transport is shared; each hook still owns admission, fingerprints, output verification and measurements. Reserve metadata lookups and cache-hit downloads separately from publication at request admission and execution. Wait cancellation-aware for local capacity before starting the remote-operation deadline; normal concurrency must not bypass hits or declare the endpoint unhealthy. Count server-owned lane reservations until backend execution and cancellation cleanup finish, even when clients remove their requests. Start the client's bounded response wait after server acceptance, with a separate local-delivery margin; pre-acceptance stalls and local materialization failures must not open the remote-failure circuit. Keep remote metadata waits short and transfer waits bounded. Cancel and await the server before deleting its session directory; unavailable transport must fall back to compilation. Standalone compiler hooks retain direct REAPI transport.
- Negotiate REAPI capabilities in the session relay alongside Cargo startup, including compression and split/splice support. Mark connection preparation separately from readiness so compiler hooks do not spend their metadata deadline waiting for negotiation. Cancel and await preparation when Cargo completes, including no-op builds. If creating the relay directory fails, keep children local-only rather than negotiating per compiler. Missing or corrupt entry blobs remain counted failures but do not open the endpoint circuit.
- `TUIST_CARGO_KEY_TRACE=<directory>` writes each strict key's relocated inputs as `<crate>-<key>.json`, like blaze's `BLAZE_KEY_TRACE`, so two builds' misses can be diffed.
- `CargoUnitCache` follows blaze v1's dependency units: around the outer Cargo command, it restores registry/git dependency units (their `deps` outputs, `build/<unit>` script runs and `.fingerprint/<unit>`) into the target profile before Cargo starts, and publishes them after a successful build. Units restored here skip rustc, build scripts and proc macros entirely, and are path-independent because Cargo's unit hashes and fingerprints contain no checkout path. Cargo stays the freshness authority: it rebuilds units whose fingerprints disagree, so the key (`rustc -vV`, profile, command kind, unit-selecting options, flag/profile environment and every discovered Cargo config file) only selects a manifest, it does not certify units. Like blaze's per-project list, the key leaves out `Cargo.lock`: a manifest accumulates units across lockfiles and feature sets (newest first, at most 4000), and restoration skips units whose registry package (`<name>-<version>`, from dep-info) the current lockfile lacks. A unit is a dependency only when every dep-info source is in Cargo home's registry/git checkouts (or the target directory); a build-script run additionally needs every compiled unit of its package to qualify. Paths into the checkout, the target directory or Cargo home in its output beyond its `OUT_DIR` (a `-sys` crate's registry `include` directory, another crate's `OUT_DIR`) and absolute `rerun-if-changed` paths inside those roots bind the unit to them, as for compiled outputs; absolute `rerun-if-changed` paths outside every root keep the run from being a unit. Publish only units created during this command, so stale leftovers of a local target never enter a manifest; units restored by this command that Cargo left untouched (same size and restoration time, no extra fingerprint files) keep their manifest records without being read again. Blobs are cloned into the store and hashed once; restoration and collection run on four threads (APFS serializes directory updates, so more threads multiply kernel time). Restoration `clonefile`s each blob straight into an absent destination and verifies the blob through a persistent identity memo (`<cache>/verified`, seeded when a blob is stored) rather than rehashing it. Blob use marks renew only when older than an hour, after verification, and the verified digest is recorded again under the blob's new ctime. A target without the profile directory is restored from a snapshot instead: the first file-by-file restoration of a selection into an absent profile clones the profile into `<cache>/snapshots/<selection digest>` (two kept) with every file's identity; later ones check those identities and `clonefile` the whole directory, renamed into place with `RENAME_EXCL`. A snapshot whose files changed, or that holds anything besides the selection's files and directories, is discarded and the build restores file by file; restoration recomputes the absent units under Cargo's lock and saves a snapshot only when it wrote every one of them, so a Cargo that built in the profile meanwhile keeps its units and they never enter a snapshot. The manifest also carries Cargo's `.rustc_info.json`, restored when absent so Cargo skips its rustc probes. Write outputs before fingerprints, share one modification time per restoration, verify every blob digest, and hold Cargo's `.cargo-lock` while restoring or collecting. Target-triple builds bypass it. Failures fall back to an ordinary Cargo build. `cli/Tests/Fixtures/CargoCache/units_e2e.sh` covers moved checkouts, snapshots, other lockfiles, configuration misses and corrupt blobs.
- `CargoCacheMeasurement` emits version-1 bounded aggregate and public inspection records. Key timings measure actual index operations, not compilation, hashing, or artifact transfers. CAS timings describe the measured batch operation shared by its blobs; byte counts describe uncompressed content. Transfers are observed, not inferred from task hits. The shared client distinguishes blobs actually uploaded from objects already present. No predictions or estimated savings are implemented.
- `CargoCacheJournal` follows blaze: no build waits for the network. Hooks append the cache-relative index files they use (`actions/`, `script-actions/`, `reads/`) to `$TUIST_CARGO_SESSION/cache-used`; the outer command records them, capped, in the unit manifest. The next build fetches that manifest as soon as its key is known (the remote connection is negotiated while Cargo is probed) and downloads the listed index files and their outputs in parallel while units restore and Cargo runs, skipping entries whose outputs a restored unit already carries. With a remote, the outer command sets `TUIST_CARGO_WRITE_BEHIND=1`: hooks write publications under the session instead of uploading, and the outer command uploads their blobs in one batch and then their action results after Cargo exits, including when the build fails. A hook that cannot record a publication uploads it itself. Prefetch only warms the local store; every entry is still verified as on any other lookup.
- Keep `CargoCacheReport` and `CargoCacheDetailsReport` bounded by file count, bytes, records, keys, and wire size. Aggregate up to 4096 report files within the 8 MB budget (not the inspection detail's smaller file cap); mark available details truncated when the aggregate scan is cut short. Never collect arbitrary compiler arguments, environment values, or credentials in telemetry, or infer local/remote hit provenance. Historical server payload fields remain compatible, but unsupported counters stay zero.

## Cargo and nextest semantics
- Build metadata reuses `custom_metadata`, `TUIST_BUILD_TAGS` and `TUIST_BUILD_VALUE_*`; explicit values override allowlisted live-wrapper observations. Because older Cargo receivers had no metadata field, omit the entire field until credential-free discovery advertises expanded support (greater than 20), even for small maps. Runner names require opt-in. See `server/docs/build-metadata.md`.

- Project, server, and network configuration is exclusively `tuist.toml` plus environment overrides, even in checkouts with `Tuist.swift`. Use `ConfigLoader.loadCargoConfig`; do not extend ProjectDescription for Cargo settings.
- Dispatch Cargo before generic flag stripping and command analytics. Preserve Cargo's quiet/verbose flags, output, argument order, failures, and signals. Nested Cargo commands must not recursively decorate a session.
- Compiler observers record actual executions only. Preserve existing global compiler wrappers without interpreting their results as compiler executions; they bypass Tuist caching/observation. Leave custom workspace wrappers authoritative.
- Inherit terminal stdio for the primary command, except standard plain-Cargo test reporting, which tees bounded stdout/stderr through `CommandRunner.runWithOutputHandler` (synchronous, backpressured readers, no stderr collector) (stdin and foreground process group remain inherited; automatic color detection can differ). Nonexecuting, quiet, Cargo-verbose (`-v`/`-vv`/`--verbose` or `CARGO_TERM_VERBOSE`), alternate-format, and uncaptured-output test commands retain inherited stdio; `CARGO_TERM_QUIET` also bypasses observation. Pin rustup's default toolchain before Cargo changes directories. Forward nightly `-C` without observation; sharding rejects it rather than executing an unfiltered suite.
- `CargoTestService` observes explicit `test`/`t` invocations without adding harness flags, nightly requirements, or nextest. `CargoTestReport` aligns independent stdout sections and stderr headings after execution, validates summary counts/statuses, and uniquely attributes binaries through package-relative Cargo metadata paths and explicit package selections. Count summary outcomes in a single pass and explicitly unwrap decimal totals with `Int(..., radix: 10)` before comparing them. FileSystem's `INCITS_4_1986` adds throwing unlabeled string initializers for `Int`/`Int64`/`UInt`/`UInt64`; Swift 6.2 (Linux CI) prefers these in comparisons, unlike Xcode's Swift 6.3. Removing `filter` alone does not fix the overload resolution. Integration-test identities match nextest's `<package>::<target>` IDs; never prefer a cwd-relative path over a sibling package. Reject unresolved package selections rather than widening them: `--no-deps` metadata omits non-member dependencies that `cargo test -p` can execute. Combined workspace/package selections must retain all workspace candidates. Omit absolute doctest names so checkout paths never become identities. Edition-2024 merged doctest sections belong to one `<package>::doctest/<library>` module, disjoint from nextest integration IDs such as `<package>::doc`. If descendants retain pipes beyond the post-exit drain window, discard the capture without waiting for them. Unknown/custom harnesses, incomplete or ambiguous reports, and exceeded capture/parser limits produce no test report, never invented passing cases. Only suite elapsed times are measured: case and namespace durations use the shared contract's zero fallback, without concurrency calibration, retries, or enumeration. The `cargo test`/`cargo test · <label>` scheme is the server's untimed-case signal: exclude those case timings from rolling histories and aggregate duration analytics, but retain outcomes and measured zero timings from other runners. Escape nextest labels that collide with the reserved untimed schemes using the `cargo nextest run · ` prefix; preserve ordinary labels. Self-hosted servers need this feature's migration and ingestion changes before upgrading the CLI. Preserve Cargo failures even when collection/reporting fails. `cli/Tests/Fixtures/CargoTestReporting/AGENTS.md` covers the real stable Cargo fixture.
- Plain `test`/`t` build reports use the latest provisional `Finished ... profile ... target(s) in ...` stderr timestamp, confirmed by the subsequent `Running`/`Doc-tests` heading, or by successful command completion with complete empty stdout for packages without runnable tests. A completion line alone is not proof of successful outer compilation: Cargo can dump nested Cargo output after a build-script failure. Stop scanning at `--- stdout`/`--- stderr` transcript boundaries, and stop at the first runtime heading so later harness output cannot become a build boundary. Retain the confirmed timestamp independently of bounded test output so failed tests, oversized capture, or inherited-pipe drain timeouts do not discard it. Exclude compiler rows ending beyond the measured build window, allowing one millisecond for independent rounding, so nested compilations inside tests do not leak into the outer build timeline. If both the boundary and a parsed test report are absent, a failed command with an observed failed compiler invocation can produce a failed build only while the scanner remains in the compile phase, with complete bounded capture and empty stdout. Discarded capture, oversized stderr lines, runtime headings, or test stdout must not turn nested compiler failures into outer build failures. Never infer a failed build from task cancellation. Otherwise omit unmeasured builds instead of guessing from the command exit or successful compiler rows, and explain missing measurements when `TUIST_DEBUG=1`. Executing tests with inherited-stdio reporting bypasses (including list, quiet, verbose, alternate-format and uncaptured-output modes) omit build reports too. `test --no-run` remains a build-only report. Start the shared command/compiler-observation clock after cache setup, and freeze command completion before metadata collection or upload.
- Nextest enumeration is not execution. Never report tests omitted by fail-fast as passing. Nextest commands do not submit build reports because their wall time includes tests; `test-build` reports the compile-once/archive phase.
- Stable identities use nextest binary IDs and Rust namespaces, not artifact hashes or checkout paths.
- Nextest binaries are concurrent module-level units, not Xcode suite-level units. Declare `concurrent_modules` and reuse the shared measured-concurrency planner with a longest-binary floor. Binary/suite timings use complete attempt timestamp windows, including retry delays and ignoring skips. Omit concurrency evidence when timestamps or wall time are missing; never infer utilization from CPU count or thread limits.
- Analytics failures must not change Cargo's exit status. Planning/downloading failures must fail a shard rather than execute the entire suite.
- Plain Cargo selection always executes through Cargo, preserving target runners and doctest environments. Muting keeps the original package selection and adds `--no-fail-fast` only when absent. Sharding and skip quarantine require one selected package: narrowing a multi-package command changes Cargo's unified dependency features.
