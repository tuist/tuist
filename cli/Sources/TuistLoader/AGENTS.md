# TuistLoader

## Manifest and package contracts
- Mark script-generated `.generated(...)` sources with `SourceFile.contentHashIsPlaceholder = true`. Keep their existing path-derived hash unchanged for artifact and selective-testing compatibility; it is not proof of generated bytes. Resource-accessor content hashes remain actual byte checksums.
- Scheme build-action targets and Build For override keys use the same resolved project paths. Merge purposes for aliases of the same target and keep one target entry in first-occurrence order.
- Map the manifest's `coverage` options (`enabled`, `prefixMapping`) into generated-project configuration unchanged; both default to off, and coverage prefix mapping stays disabled by default for `xccov` compatibility. The CLI overrides `enabled` per command (`BinaryCacheCoverage.resolved`), never here.
- Preserve native package dynamic-linkage hints and their platform conditions when mapping manifest dependencies; do not infer linkage from the embedding role.
- Swift package bundle identifiers preserve underscores as hyphens, including leading, trailing, and repeated underscores, so targets such as `IssueReporting` and `_IssueReporting` can coexist as embedded dynamic frameworks.
- `ManifestLoader` uses start/end tokens to parse manifest output and caches results.
- Swift package targets using tools version 5.9 or newer carry their package name compiler argument in target settings so graph transformations preserve package access.
- Opted-in local package test targets may reference external products resolved from `Tuist/Package.swift`; map these through the same dependency path as production targets. Remote package tests remain excluded. Missing external products on tagged local package tests identify the test and product and direct users to declare the providing package in `Tuist/Package.swift` and run `tuist install`.
- A local path package overrides remote packages with the same identity and remote packages whose identity (the name part of a registry `scope.name`) matches its manifest name, since its own identity comes from its directory name. `.product(name:package:)` references to an overridden `scope.name` resolve against the local package. Remote packages that only share a manifest name are never merged.
- Source-built manifest evaluation and helper compilation search both `Modules/` and the dylib's directory for `ProjectDescription.swiftmodule`, supporting native SwiftPM and Swift Build outputs without modifying build artifacts.
