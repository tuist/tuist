# TuistGenerator (Project Generation)

This module implements the project generation pipeline (transforming manifests into Xcode projects/workspaces).

## Responsibilities
- Build descriptors (`ProjectDescriptor`, `WorkspaceDescriptor`, `SchemeDescriptor`) used to write `.xcodeproj`.
- Orchestrate side effects required for generation (e.g., writing schemes, side-effect descriptors).
- Translate `ProjectDescription`/graph models into `XcodeProj` structures.

## Related Context
- Core domain models: `cli/Sources/TuistCore/AGENTS.md`
- Manifest loading: `cli/Sources/TuistLoader/AGENTS.md`

## Invariants
- `ProjectDescriptor`/`WorkspaceDescriptor` are the handoff types to XcodeProj writers.
- Side effects are collected explicitly and executed outside pure mapping.
- Both `.pbxproj` and `.xcproj` writers serialize with stable references and compare bytes before rewriting unchanged project bodies. Switching formats removes the stale body file; project side effects run after references are finalized.
- Compiler-cache debugging runs through the native scheme mapper for both project and workspace Run/Test actions, including autogenerated schemes. Keep explicit debugger settings and disabled debugger attachment intact; source an action's custom initializer, or `~/.lldbinit-Xcode` falling back to `~/.lldbinit` when no custom initializer exists and the user file is present, before appending Tuist source maps. Home files load through LLDB's command-file API without echoing commands or stopping on errors, but with diagnostics visible; never source both home files. Read reverse prefix mappings from the selected action's `TARGET_TEMP_DIR/compilation-prefix-map.json`. Do not shell-parse exported mapping settings: Xcode expands path variables after tokenizing lists, so quotes and backslashes introduced by expansion are literal path characters.
- Preserve `Derived/TuistCacheDebugging` during project cleanup: another workspace sharing the project may still reference those per-scheme files. Each action refreshes its own initializer before debugging.
- Preserve real directories for generated sources, Info.plists, and entitlements during early Derived cleanup so unchanged files retain their mtimes. Unlink directory symlinks, including dangling links, before writing generated files; never clean through a symlink root. After their generating mappers run, describe stale-file cleanup from the mapped targets; execution removes only obsolete Tuist-owned files and compares active paths using the volume's case-sensitivity.
- Targets with buildable folders exclude `.gitkeep` and `.DS_Store` through Xcode build settings, preserving existing exclusions. Xcode enumerates synchronized folders independently of Tuist's filtered globs, including files added after generation.
- Explicitly dynamic native package products remain linked by hosted tests, independently of embedding. Tuist omits a test's explicit embed when the host embeds that product under the same platform condition; Xcode may synthesize automatic-product embedding separately. Static targets still receive build-only dependencies.
- With `enableCaching` on Xcode 27+, `XcodeCachePrefixMappingWorkspaceMapper` gives every project `SWIFT_OTHER_PREFIX_MAPPINGS`/`CLANG_OTHER_PREFIX_MAPPINGS` for the SwiftPM scratch directory (`/^spm`), build directories (`/^intermediates`, `/^products`), and the Tuist root directory (`/^root`, located from the workspace path like the scratch directory, so a workspace generated below the root still keeps `Tuist/.build` relative). Keep per-project mapping enabled by default for backwards compatibility, including projects outside the located root. Preserve explicit manifest opt-outs to `NO` for shared multi-project namespaces. An external package's `PROJECT_DIR` is `tuist-derived/Projects/<name>` while its sources stay in `checkouts/`. The root directory goes in `TUIST_PREFIX_MAPPING_ROOT_DIR` and each mapping is a quoted `"$(TUIST_PREFIX_MAPPING_ROOT_DIR)/…=/^…"` token: Xcode splits unquoted list elements at spaces, so expanded paths must be absolute and normalized. Compilation-cache scanners sort nested prefixes ahead of their parents; declaration order is not what picks the winning mapping.
- Coverage builds disable prefix mapping by default for `xccov` compatibility. `enableCoveragePrefixMapping` keeps the mappings enabled only for teams explicitly remapping coverage themselves; do not switch Tuist's coverage reader implicitly.
