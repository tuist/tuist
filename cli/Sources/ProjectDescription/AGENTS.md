# ProjectDescription

Public manifest DSL. Loading belongs to TuistLoader; graph/generation logic belongs
to feature modules. Keep Codable/Equatable models stable across released manifests.

## Invariants
- Manifest types are `Codable`/`Equatable` and designed to be stable across versions.
- Native `.package(product:)` dependencies may use `runtimeDynamic` or `runtimeDynamicEmbedded` as explicit linkage hints for hosted tests. Xcode still resolves their build type; existing `runtime` and `runtimeEmbedded` declarations retain their behavior. `.external(name:)` dependencies become Tuist-generated targets with linkage represented by their product types, so they do not require these native-package hints.
- `Project` maps 1:1 to `Project.swift` manifests and includes targets, schemes, settings, and packages.
- `coverage: .coverage(enabled:prefixMapping:)` groups the coverage generation options, both off by default. It lives in its own `.options` overload, so the overload without it keeps its released signature for typed references, and `GenerationOptions` decodes a missing `coverage` key as off. `enabled` makes the repository read and warm the instrumented binary-cache variant (Debug configurations only), links the profile runtime and turns on coverage in automatic schemes and in user-defined test actions whose `TestActionOptions.codeCoverage` is `.inherit` (what `.options(coverage: nil)`, the default, produces; `.enabled`/`.disabled`, from `true`/`false`, win; test plans decide for themselves). `TestActionOptions.coverage` stays a deprecated `Bool` (true only for `.enabled`) so released manifests that read it keep compiling, and the manifest JSON keeps an optional Boolean `coverage` key, absent for `.inherit`. `prefixMapping` (formerly the canary-only `enableCoveragePrefixMapping`; `TUIST_COVERAGE_PREFIX_MAPPING` overrides it, applied in `Tuist.resolvingCoverage`) is the explicit opt-in for teams remapping coverage with tools such as `llvm-cov`; it requires `enableCaching`, and the default stays compatible with `xccov`. Both values feed build settings and cache keys, so they must match on every machine sharing a cache.

- `InstallOptions.ManifestEnvironment.automatic` hides GitHub CI metadata and rotating credentials from cached manifest evaluation, preserving platform/toolchain and application inputs. Document that native SwiftPM resolution retains known credentials for fetching and evaluates manifests with them too. `.automatic(including:)` and `.all` restore intentional CI/credential-dependent manifest inputs; explicit exclusions affect native resolution as well.

- `includeLocalPackageTestTargets` opts local path package tests into generation, including cross-package products available through `Tuist/Package.swift`; remote package tests stay excluded.
