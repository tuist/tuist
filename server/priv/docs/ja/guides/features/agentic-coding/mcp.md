# Model Context Protocol

[Model Context Protocol (MCP)](https://modelcontextprotocol.io/docs/getting-started/intro)は、AIエージェントが外部サービスやデータソースと対話できるようにするオープンスタンダードです。[Claude](https://claude.ai/)、[Claude Code](https://docs.anthropic.com/en/docs/claude-code)、[Codex](https://developers.openai.com/codex/)などのアプリケーションや、[Zed](https://zed.dev)、[Cursor](https://www.cursor.com)、[Visual Studio Code](https://code.visualstudio.com)などのエディタをTuistと相互運用可能にします。

Tuistは、`https://tuist.dev/mcp`にサーバーサイドのModel Context Protocolエンドポイントをホストしています。クライアントをこれに接続することで、エージェントはテストインサイト、flakyテスト分析などを含むTuistプロジェクトデータにアクセスできます。ほとんどのツールは、認証済みユーザーがダッシュボードで既に表示できるTuistデータを読み取ります。各ツールは、読み取り専用かどうか、元に戻しにくい変更を引き起こす可能性があるか（`destructiveHint`）、およびTuistの外部にアクセスできるか（`openWorldHint`）を示すアノテーションを公開します。状態を変更するツールは、アカウントまたはプロジェクトに対するユーザーの権限によって制限され、以下の通りです：

- **組織とメンバー**：`create_organization`、`add_organization_member`（既存のユーザーを追加するか、メンバーのロールを変更）、`invite_organization_member`（任意のアドレスに招待メールを送信）、および`cancel_organization_invitation`。
- **プロジェクト**：`create_project`、`start_project_logo_upload`および`complete_project_logo_upload`（ロゴを置き換え）、`connect_project_repository`および`disconnect_project_repository`（GitHubリポジトリリンク）。
- **テスト**：`update_test_case`（テストケースをミュート、スキップ、再有効化、またはflakyとしてフラグ付け；変更はアカウントのWebhookエンドポイントに到達する可能性があります）。
- **通知ルール**：`create_notification_rule`、`update_notification_rule`、および`delete_notification_rule`。
- **CIランナー**：`create_runner_profile`、`update_runner_profile`（キャッシュボリュームを保存するジョブを絞り込むと、保留中の保存が破棄されます）、`delete_runner_profile`、および`delete_runner_volume`（ボリュームの保存内容を削除）。
- **サンドボックス**：`create_sandbox`、`pause_sandbox`、`resume_sandbox`、`archive_sandbox`、および`delete_sandbox`（ディスクを削除）。
- **フィードバック**：`report_feedback`（ツールやプロンプトに関するレポートをTuistチームに送信；tuist.devのみ）。
- **Organization AI**：`save_organization_ai_model`、`remove_organization_ai_model`、`set_organization_ai_default_model`、`save_organization_ai_task_route`、`remove_organization_ai_task_route`、および`remove_organization_ai_provider`（プロバイダーのキーとモデルを削除し、AnthropicでリンクされたClaude組織を解除）。
- **エージェント統合**：`connect_amp_workspace`（ワークスペースのOrbsにアカウントへのCIアクセスを付与）、`disconnect_amp_workspace`、および`connect_claude_environment`（Claude Managed Agents環境がTuistサンドボックスでセッションを実行できるようにする）。

`add_organization_member`、`cancel_organization_invitation`、`complete_project_logo_upload`、`disconnect_project_repository`、`update_test_case`、`update_notification_rule`、`delete_notification_rule`、`update_runner_profile`、`delete_runner_profile`、`delete_runner_volume`、`delete_sandbox`、`disconnect_amp_workspace`、`remove_organization_ai_provider`、`remove_organization_ai_model`、および`remove_organization_ai_task_route`は、既存の状態を置き換えたり削除したりするため、`destructiveHint: true`を公開します。`invite_organization_member`、`update_test_case`、`connect_claude_environment`、`remove_organization_ai_provider`、および`report_feedback`は、メールを送信したり、外部のWebhookエンドポイントに通知したり、Anthropicを呼び出したり、Tuistチームにレポートを送信したりするため、`openWorldHint: true`を公開します。

個人のClaudeおよびChatGPTサブスクリプションはダッシュボードのAI設定でのみ接続されるため、サブスクリショントークンやサインイン情報がModel Context Protocolクライアントを経由することはありません。アカウント設定ツールにはユーザー認証が必要です。プロジェクトトークンや通常のアカウントトークンでは利用できません。ユーザーがブラウザでクライアントを承認したり、`auth.md`登録を主張したりすると、Tuistはその認証情報をModel Context Protocolエンドポイント上でのみユーザーに関連付け、設定ツールが要求されたワークフローを完了できるようにします。

Tuistは[2026-07-28プロトコル](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http)を実装しています。リクエストはステートレスです：クライアントは各リクエストとともにプロトコルメタデータを送信し、初期化なしで直接ツールを呼び出すことができます。`server/discover`は、サーバーの識別情報、機能、サポートされているバージョン、および手順を返します。セッション識別子や独立したイベントストリームはありません。2025-06-18または2025-03-26の初期化フローを使用するクライアントも引き続きサポートされており、それらもサーバーセッションなしで動作します。

## Model Context Protocolとスキル

Model Context Protocolツールと<.localized_link href="/guides/features/agentic-coding/skills">スキル</.localized_link>は、その機能において重複する可能性があります。現在の重複状況を考慮し、ワークフローごとに一つのアプローチを選択し、同じフロー内で両方を混在させるのではなく一貫して使用してください。

プラグインインストールをサポートするクライアントの場合、<.localized_link href="/guides/features/agentic-coding/plugins">Tuistプラグイン</.localized_link>を使用して両方を一緒にインストールしてください。

## 設定

クライアントのリモートModel Context Protocolサーバーとして`https://tuist.dev/mcp`を追加してください。サーバーの初期化手順と公開サーバーカードは、動的クライアント登録を使用したOAuth 2.0と標準的なブラウザ認可フローをインラインで説明しており、エージェントに外部の認証ドキュメントを取得またはフォローさせることはありません。これらのサーバー全体の指示はワークフローガイダンスを一般的なものに保っています：ツール認証はローカルコマンドラインツールやビルドシステム統合を認証せず、エージェントは関連するTuistツールを通じて要求された変更を確認する必要があります。ビルドシステム固有の設定と認証チェックは、統合ガイドとプロンプトに記載されています。Tuistは引き続き、[Open Authorization](https://oauth.net/2/)ディスカバリーメタデータと現在の[auth.mdプロトコル](https://workos.com/auth-md)を`https://tuist.dev/auth.md`で個別に公開しています。

組織のいずれかがシングルサインオンを強制している場合、ブラウザでクライアントを承認するには、その組織を通じてサインインしたセッションが必要であり、必要に応じてTuistはまずプロバイダーにリダイレクトします。<.localized_link href="/guides/integrations/authentication/sso#choose-an-enrollment-policy">シングルサインオン</.localized_link>をご覧ください。

このエンドポイントは、古いセッションベースのライフサイクル alongside、ステートレスな`2026-07-28` Model Context Protocolリクエストライフサイクル（`server/discover`を含む）を受け入れます。既存のクライアントは現在の接続方法を继续使用できます。

Model Context Protocolイベントをサポートするクライアントは、プロジェクトイベントをサブスクライブできます。利用可能なイベントと配信要件については、[Events](#events)をご覧ください。

リモートブラウザ認証をすでにサポートしているクライアントは、ブラウザでの認証を続けることができます。`auth.md`をサポートするクライアントとエージェントは、匿名で登録したり、信頼されたプロバイダーIDアサーションを提示したり、サービス認証された電子メールクレームを開始したりできます。登録によりTuist署名付きIDアサーションが返され、エージェントはこれを標準トークンエンドポイントで1時間有効のアクセストークンと交換します。Tuistは公開署名鍵を公開し、標準的なトークン失効とプロバイダーセキュリティイベント配信をサポートしています。

認証されていないエージェントは、Model Context Protocolエンドポイントから返される`WWW-Authenticate`ヘッダーを読み取り、保護リソースメタデータを取得し、認可サーバーメタデータを取得して、その`agent_auth.skill`URLに従う必要があります。Tuistは、言語モデル駆動型クライアントがネイティブクライアント統合に頼らずにフローを発見できるよう、未承認レスポンスボディにも同じローカルの`auth_md`URLを返します。デプロイメント固有のドキュメントが、エンドポイント名、リクエストボディ、クレームポーリング、アサーション交換に関する信頼できる情報源となります。

エージェントが電子メールクレームを開始する前に、ユーザーにTuistアカウントの電子メールアドレスを確認してもらう必要があります。プロバイダープロフィール、Git設定、環境変数、またはセッションメタデータからそのアドレスを推測してはいけません。

このエンドポイントは`mcp`スコープグループを使用します。匿名の事前クレーム資格情報は機能の発見と公開されている統合ガイダンスの読み取りが可能ですが、サインインしたユーザーとしては扱われません。ブラウザでの承認またはクレーム後、資格情報はユーザー単位のスコープとなり、各ツールはダッシュボードと同じ認可チェックを適用します。詳細については、<.localized_link href="/guides/server/authentication#scope-groups">スコープグループのドキュメント</.localized_link>をご覧ください。

ツールは、認証済みユーザーがすでに読み取り権限を持つプロジェクトに解決されます。XcodeおよびGradleビルドツールは、ビルドUUIDまたはダッシュボードURLを受け入れます。UUIDは正確に1つのプロジェクトを識別する必要があります。複数のプロジェクトにまたがる場合、ツールは他のプロジェクトのレポートを選択するのではなく、見つからないという結果を返します。プロジェクトスコープのダッシュボードおよびAPI読み取りは引き続き利用可能です。報告されたアクター識別子は未検証のラベルであり、資格情報や追加のアクセス権ではありません。

ビルド一覧および詳細ツールは、オプションの`tuist_version`メタデータを公開します。XcodeおよびCargoには報告元のTuist CLI、GradleにはTuist Gradleプラグイン、Mixには`tuist_ex`ライブラリが含まれます。Xcodeは、リンクされたプロジェクト生成イベントから`tuist_generation_version`も公開しますが、これはアップロード元のCLIと異なる場合があります。欠落している観測値はnullとして扱われ、サーバーや他のレポートから推測されません。Bazelは既存の`bazel_version`を使用し、Struoの実行詳細は`once_version`を公開します。これらのフィールドは報告されたバージョンを示すものであり、検証済みのIDやワイヤー契約バージョンではありません。RESTビルドエンドポイントも同じメタデータを公開します。既存の統合およびflaky-testスキルはバージョンフィールドに依存せず、ワークフローの変更は不要です。

Tuistオペレーターが顧客のアカウントを調査する際は、すべての呼び出しを記録するTuistの内部運用ツールを通じて行います。このエンドポイントへの直接接続では、ユーザー自身の所属範囲を超えるアクセスは得られません。

### Pulse

Pulseは、アカウントの運用メトリクス、ログ、トレース、エラーに対する読み取り専用ツールを公開しており、すべて`account_handle`で指定されます。最初の3つはPulseページとそのREST APIを反映しています。残りの5つはエージェントがテレメトリーを直接探索できるようにするもので、REST相当機能はありません。

| ツール | 目的 | `/api/accounts/:account_handle/pulse`以下のREST相当機能 |
| --- | --- | --- |
| `query_pulse` | Pulseページテーブル | `GET /:signal` |
| `get_pulse_analytics` | Pulseページウィジェット | `GET /:signal/analytics` |
| `get_pulse_error_issue` | 1つのエラー課題とそのイベント | `GET /errors/issues/:fingerprint` |
| `query_pulse_metrics` | インスタントまたはレンジPromQL | なし |
| `list_pulse_labels` | ラベル名、または1つのラベルの値 | なし |
| `search_pulse_logs` | フィルター付きログエントリ | なし |
| `search_pulse_traces` | フィルター付きスパン | なし |
| `get_pulse_trace` | 1つのトレースのすべてのスパン | なし |

Pulseは、アカウントまたはプロジェクトが公開されていても、サーバー構成組織の現在のメンバーに制限されています。ユーザー認証、またはユーザー関連付けられた`mcp`資格情報とアカウント読み取り権限が必要です。プロジェクトトークン、通常のアカウントトークン、匿名登録、および組織メンバーシップのないオペレーターアクセスでは、Pulseへのアクセスは付与されません。資格情報で別のバックエンドやテレメトリーテナントを選択することはできず、サーバー構成のアカウントのみがPulseテレメトリーを持つため、どのツールも他のアカウントのデータを読み取ることはできません。ブラウザエージェントは、そのページのアカウントスコープ内にあるPulseページでのみこれらのツールを受け取ります。

RESTにはユーザー資格情報が必要です。OAuthおよび`auth.md`ユーザー関連付けは`/mcp`エンドポイントでのみ利用可能です。関連するアカウントのメンバーシップや可視性に関係なく、現在のユーザーを持たないアカウント資格情報は拒否されます。

`query_pulse`は、`signal`（`metrics`、`logs`、`traces`、または`errors`）、オプションの`query`、および`range`（`15m`、`1h`、`6h`、または`24h`、デフォルトは`1h`）を取ります。メトリクスはPromQL式を受け入れます。ログ、トレース、エラーは、ログボディ、スパン名、エラー課題タイトルに対してマッチする大文字小文字を区別しないリテラルテキストを受け入れます。`*`（デフォルト）はすべてを選択します。トレース行は個々のスパンです。エラー行は課題です。サービスとフィンガープリントでグループ化されたイベントであり、イベント数、影響を受けたアカウント、ウィンドウ内の最初と最後の発生、最新イベントのタイトル、原因、レベル、プラットフォームを含みます。テーブルは`search`、`page`（デフォルトは`1`）、`page_size`（`1`–`100`、デフォルトは`20`）、`sort_by`、および`sort_order`（`asc`または`desc`）を受け入れます。ソート列はシグナルによって異なり、ツールスキーマに記載されています。フィルターには、ログとエラー用の`service`および`level`が含まれます。フィルター演算子は対応する`_op`引数（`eq`、`contains`、または`not_contains`）を使用し、デフォルトでは完全一致となります。

ソート列は、メトリクス用が`name`/`value`、ログ用が`timestamp`/`service`/`level`/`message`/`trace_id`、トレース用が`timestamp`/`service`/`name`/`duration_ms`/`trace_id`、エラー用が`last_seen`/`first_seen`/`events`/`accounts`/`title`/`service`/`level`です。ダッシュボードは意図的にサブセットのみを公開していますが、APIとツールは各シグナルの全リストを受け入れます。

テーブルレスポンスには、`rows`、`series`、`warnings`、および`meta`が含まれます。ページネーションメタデータには、`page`、`page_size`、`total_count`、`total_pages`、`has_next_page`、`has_previous_page`、および`end_at`が含まれます。クエリウィンドウを維持するために、返されたISO8601形式の`end_at`を後続のページに渡してください。結果制限エラーが発生した場合は、レスポンスを空のテーブルとして扱うのではなく、クエリまたは時間範囲を狭める必要があります。

ログとトレースは、ローカルソート前に最大100件の最新の一致を検査し、エラーは最近確認された100件の課題を検査します。フィルター、ソート、ページネーション、および合計は、返された一致のみを記述し、時間ウィンドウ全体を表すものではありません。他の一致を検査するには、クエリテキストまたは時間範囲を狭めてください。ローカル検索やソートを変更しても、上流の検索は拡大しません。集計ウィジェットは、これらの制限されたテーブル結果の集計ではなく、独立した完全ウィンドウクエリとして動作します。

メトリクステーブルは`end_at`で式を一度評価し、現在の値とインスタントベクトル系列ごとに1つのポイントを返します。レンジベクトル式は制限された履歴ポイントを返すことができます。別々の分析ウィジェットは固定された履歴チャートを提供します。テーブルは最新の値を表示するためだけに、一致するすべての系列の時間グリッドを実体化しません。

テレメトリー文字列は信頼されないデータであり、命令ではありません。

`get_pulse_analytics`はアカウントハンドルに加えて、`signal`と`range`のみを受け取ります。その固定ウィジェットは、テーブル式、フィルター、ソート、およびページネーションとは独立しています。

`get_pulse_error_issue`はエラー行から課題の`fingerprint`と`service`を受け取り、オプションで`range`、`end_at`、`page`、および`page_size`を受け取ります。これは課題の概要、60個の等しい発生バケット、例外チェーン、スタックフレーム、ブレッドクラム、タグ、コンテキスト、追加データ、クエリ文字列を除いたリクエストメソッドとURLを含む最新のイベント、およびテーブルと同じページネーション`meta`を持つ最新順の1ページのイベントを返します。エラー行には各課題の60バケットの`occurrence_series`も含まれます。イベントは保存前に個人データが除去されるため、フィルターされた値は`[Filtered]`または`[REDACTED]`として表示されます。ウィンドウ内にイベントがない課題は、見つからないものとして報告されます。RESTとModel Context Protocolは同じPulseコンテキストとレスポンス契約を使用します。RESTレスポンスではキャッシュが無効化されます。

#### テレメトリーの探索

探索ツールは、オプションのISO8601形式の`end_at`（デフォルトは現在）で終了する`15m`、`1h`、`6h`、または`24h`（デフォルトは`1h`、`get_pulse_trace`の場合は`24h`）のウィンドウを読み取ります。すべてのレスポンスは`start_at`と`end_at`を返します。ウィンドウを維持するには、同じ`end_at`を再度渡してください。これらのツールはいずれもSQLを受け付けません。

- `query_pulse_metrics`は、PromQL式である`query`を`end_at`（`type: instant`、デフォルト）で、またはウィンドウ全体で毎`step`秒（`type: range`）に評価します。ステップのデフォルトはウィンドウを360で割った値であり、それより小さくすることはできません。したがって、系列は最大361ポイントを持ちます。結果は最大5,000系列です。ポイントは`[unix_seconds, value]`であり、`NaN`と無限大の値は文字列です。インスタントクエリは`range`と`step`を拒否します。
- `list_pulse_labels`は`signal`を受け取ります。`label`がない場合はラベル名を一覧表示し、`label`がある場合はそのラベルの値を一覧表示します。メトリクスの場合、`__name__`はメトリクス名を一覧表示し、他のラベルの値には`match`（`up`などの系列セレクター）が必要です。ログとトレースのラベル値は`filters`を受け入れます。トレースラベル名はトレーススキーマから取得され、これを受け入れません。ログとトレースの値にはウィンドウ内のエントリ数が含まれ、頻度の高いものが先に表示されるため、サービス別のエラーなどの内訳としても機能します。`search`はリテラルテキストを含む名前または値のみを保持し、`limit`は`1`–`1000`（デフォルト`100`）を受け入れます。ログラベル名の検出は、各種類の属性セットを最大1,000件検査し、フィルターが受け入れるキーのみを一覧表示します。
- `search_pulse_logs`は最大`limit`件のエントリ（`1`–`100`、デフォルト`50`）を、`newest`または`oldest`順で返します。これらのエントリの本文には`text`が含まれ、すべてのフィルターに一致します。各エントリには、`severity_text`、`body`、`trace_id`、`span_id`、`scope_name`、およびマージされたリソースとログの`attributes`が含まれます。`span_id`と`scope_name`は、OTLPログ送信者によってのみ設定されるKubernetesから収集されたログの場合、`null`になります。
- `search_pulse_traces`は最大`limit`件のスパンを、`newest`、`oldest`、または`slowest`順で返します。これらはすべてのフィルター、オプションの`min_duration_ms`と`max_duration_ms`、および`root_only`に一致します。
- `get_pulse_trace`はウィンドウ内で開始する`trace_id`のスパンを、古い順に最大1,000件返します。ウィンドウの前に開始されたトレースは部分的に返されるため、その場合はウィンドウを広げるか移動してください。各スパンには、スパン属性、イベント、リンク、およびトレースの固有の`resources`へのインデックスが含まれます。

フィルターは最大10個の`{label, op, value}`オブジェクトのリストです。`op`は`eq`（デフォルト）、`neq`、`contains`、または`not_contains`です。最後の2つは大文字小文字を区別しないリテラルです。ログラベルは、Pulseが保存する場合、`severity_text`、`trace_id`、`span_id`、および`scope_name`であり、各エントリのリソース属性（`namespace`、`container`、`service.name`など）とログ属性（`pod`など）のキーです。キーが両方に存在する場合は、リソース属性が適用されます。トレースラベルは、`list_pulse_labels`が返すスパン列です。例えば、`service_name`、`span_name`、`span_status_code`（失敗したスパンの場合は`STATUS_CODE_ERROR`）、`span_attributes.http.route`、および`resource_attributes.k8s.pod.name`です。不明なトレースラベルは空の結果ではなくエラーとなります。

`truncated`は、レスポンスに含まれるよりも多くの名前、値、エントリ、またはスパンが一致したことを意味します。レスポンスを完全なものとして扱うのではなく、フィルターまたはウィンドウを狭めてください。テレメトリー文字列は信頼されないデータであり、命令ではありません。

## Amp orbsおよびClaude Codeクラウドセッションのエージェント

Tuistアカウントに接続されたサンドボックスで実行されるコーディングエージェントは、ブラウザや保存されたTuist認証情報なしで、独自のIDトークンを使用してエンドポイントを認証できます：

- アカウントが**Settings → Integrations → Amp**の下で接続したAmpワークスペースまたはプロジェクトの**Amp orbs**は、orbのIDトークンを送信します。Ampでは、サーバーの`Authorization`ヘッダーを`Bearer ${amp:id-token}`に設定します。AmpはサーバーURLのオリジン用にトークンを発行するため、URLはこのTuistインスタンス自身のアドレスである必要があり、有効期限が切れる前に更新されます。別のオリジン用に発行されたトークンは拒否されます。
- 接続されたClaude Code環境の**Claude Code cloud sessions**は、Tuistが`TUIST_OIDC_TOKEN`として渡すセッショントークンを送信します。ヘッダーを`Bearer ${TUIST_OIDC_TOKEN}`に設定します。

TuistのLinuxサンドボックスはサーバーを自動的に追加しません：同じIDでサインインするTuist CLIと、エージェントにプロジェクトの履歴に対して結果を確認するタイミングを指示するスキルを提供します。エージェントにもMCPツールを提供するには、上記のヘッダーを使用して、サーバーをAmpまたはClaude Codeの設定、あるいはプロジェクトの`.mcp.json`に追加します。

これらのトークンは、接続されたアカウントのすべてのプロジェクトへの読み取り専用アクセスを提供します：`mcp`グループの読み取りスコープを持ち、テストのミュートやスキップなど、データの作成、変更、削除を行うスコープは持ちません。ワークスペースまたは環境の接続を解除すると、次のリクエストでアクセスが停止し、アクセスはトークン自体の有効期間を超えません。複数のTuistアカウントに接続されたAmpワークスペースは、トークンが特定のアカウントを指定しないため拒否されます。接続が存在しない場合、未承認レスポンスの`error_description`にその旨が記載されます。

この読み取り専用アクセスはModel Context Protocolエンドポイントにのみ適用されます。同じサンドボックス内のコマンドラインツールとビルドシステム統合は、引き続きトークンを交換して接続のCIアクセスを行います。

## WebMCP

[WebMCP](https://webmachinelearning.github.io/webmcp)をサポートするブラウザでは、Tuistのページが`document.modelContext`でツールを登録するため、ブラウザ組み込みのエージェントは追加の設定なしでそれらを呼び出すことができます。呼び出しはTuistサーバー上で実行されます。

- **Website and documentation pages**は、ドキュメントおよびソースツール（`search_tuist`、`search_tuist_code`、`list_tuist_files`、および`read_tuist_file`）を登録します。サインインは不要です。
- サインインしている場合、**An account's dashboard pages**はそのアカウント用のTuist読み取り専用ツールを登録します。各ページは、表示内容に応じてプロジェクトのビルドシステム用のツールのみを登録します：GradleプロジェクトのビルドページはGradleビルドツールを取得し、テストページはテストおよびカバレッジツールを、ランナーページはランナーツールを、サンドボックスページはサンドボックストールを取得します。すべてのページはさらにドキュメントツール、`list_projects`、および`get_project`を取得します。ツールはサインインしたユーザーとして実行されるため、ダッシュボードで読み取れるデータと、現在閲覧中のアカウントのデータにのみアクセスできます。別のページまたはアカウントに移動すると、ツールはそのページのツールに置き換えられます。

データを作成、変更、または削除するツールはWebMCPでは利用できません。ブラウザエージェントはユーザーが追加することなくツールを受け取り、ビルドおよびテストによって生成されるコンテンツを読み取るためです。これらのツールを使用するには、MCPクライアントを`/mcp`エンドポイントに接続してください。

組織がシングルサインオンを強制している場合は、そのプロバイダーを使用してダッシュボードにサインインし、ツールを使用してください。

## ビルドシステム統合は2つの認証情報を使用します

Model Context Protocolツールに使用される認証情報は、GradleプラグインやBazelのリモートサービスを認証しません。エージェントがGradleまたはBazel統合を編集または検証する前に、次を実行する必要があります：

```bash
tuist auth whoami --url https://tuist.dev
```

そのコマンドが認証されていない場合、エージェントは停止し、ユーザーに次を実行するよう依頼する必要があります：

```bash
tuist auth login --url https://tuist.dev
```

ローカルまたはセルフホスト型デプロイメントの場合、両方のコマンドおよび`tuist.toml`内のURLを置き換えてください。ホスト名の表記はすべて同一に保ってください。例えば、`localhost`と`127.0.0.1`は別々の保存済み認証情報を使用します。


## 機能

### ツール

以下のツールは、Tuist Model Context Protocolサーバーを通じて利用可能です：

すべてのツールは、人間が読める説明と明確な入力および出力スキーマを公開します。成功した呼び出しは、公開された出力スキーマに準拠した構造化コンテンツを返し、さらに構造化コンテンツをまだ消費しないクライアント向けにテキストとしてシリアル化された同じ結果を返します。

`build_run_id`、`test_run_id`、`test_case_id`、`bundle_id`、`run_id`、`generation_id`、または`cache_run_id`など、単一レコードの識別子を受け取るツールは、そのレコードのTuistダッシュボードURLも受け入れます。識別子を抽出するのではなく、ブラウザからURLを直接貼り付けてください。

`get_xcode_build`、`get_test_run`、`get_gradle_build`、および`get_project`には`side_quests`を含めることができます：プロジェクトが使用していないが、レコードが役立つと示すTuist機能です。それぞれに`id`、証拠を示す`tip`、および`docs`リンクがあります。エージェントはまずユーザーのリクエストを完了し、該当するサイドクエストに言訳し、ユーザーが同意した場合のみアクションを実行することが求められます。これらは、ユーザーセッション、MCPトークン、またはエージェントIDで接続するかにかかわらず、プロジェクトのアカウントメンバーにのみ返されます：

| ID | ツール | 推奨される状況 |
|----|------|----------------|
| `xcode_compilation_cache` | `get_xcode_build` | Xcode 26以降で処理されたクリーンビルドが、キャッシュ可能なコンパイルタスクを一切実行しなかった場合。 |
| `gradle_build_cache` | `get_gradle_build` | ビルドがキャッシュ可能なタスクを実行したが、Gradleのビルドキャッシュがいずれのタスクに対してもキーを計算しなかった場合。これはビルドキャッシュが無効になっていたことを意味します。 |
| `flaky_test_quarantine` | `get_test_run` | 実行に不安定なテストが含まれており、プロジェクト内の有効な自動化がそれらをミュートまたはスキップしていない場合。Struoプロジェクトでは推奨されません。 |
| `test_sharding` | `get_test_run` | Tuistがシャード化できるビルドシステムにおいて、シャード化されていないCI実行が10分以上かかった場合。ヒントには、選択的テストがいつ、いくつのテストをすでにスキップしたかが示されます。 |
| `tuist_runners` | `get_xcode_build`, `get_test_run` | CI実行がGitHub Actions、Bitrise、GitLab CI、またはBuildkiteのマシンを使用しており、そのアカウントでTuist Runners上のジョブが一度も実行されていない場合。tuist.devのみで利用可能です。 |
| `pull_request_comments` | `get_xcode_build`, `get_test_run` | GitHub Actionsの実行が、GitHubリポジトリに接続されていないプロジェクトに属している場合。 |
| `other_build_systems` | `get_project` | アカウントがサポートされているすべてのビルドシステムでTuistを使用していない場合。ヒントには他のビルドシステムを識別するファイルが一覧表示されるため、エージェントはリポジトリを確認できます。 |

#### ドキュメントおよびコミュニティ検索

この読み取り専用ツールは、ドキュメントウェブサイトを動かす同じ検索エンジンを使用して、Tuistのドキュメント、[アプリケーションプログラミングインターフェース](https://en.wikipedia.org/wiki/API)リファレンス、GitHubリリース、コミュニティフォーラム、およびGitHubイシューを検索します。リリース結果には、製品、バージョン、公開日、プレリリースステータスが含まれます。デフォルトでは安定版リリースが検索され、`include_prereleases`を使用してプレリリースを含めることができます。このツールは、`https://tuist.dev/mcp`のTuistホスト型サーバーでのみ利用可能です。

| ツール | 説明 | 必須パラメータ |
|------|-------------|---------------------|
| `search_tuist` | 公開されているTuistドキュメント、アプリケーションプログラミングインターフェースリファレンス、GitHubリリース、コミュニティディスカッション、およびGitHubイシューを検索します。オプションで、1つの`source`（`docs`、`api_reference`、`releases`、`forum`、`issues`）に制限できます。 | `query` |

#### フィードバック

エージェントは、Tuistツールやプロンプトが期待通りに動作しなかった場合（結果が不明確、エラー、データ欠落、機能欠落など）、Tuistチームに通知できます。エージェントはレポートを提案し、ユーザーが同意した場合のみ送信することが求められます。各レポートはTuistサポートとの会話を開始し、サポートからメールで返信が届く場合があります。レポートには、エージェントの期待値、実際の発生事象、オプションの提案、TuistユーザーID、ハンドル、メールアドレス、所属組織が含まれます。エージェントは問題が発生したアカウントとプロジェクトを指定することもでき、チームはどの組織に対応すべきかを把握できます。受け入れられるのはユーザーが所属するアカウントのみです。Tuistユーザーとしてサインインしたエージェントのみがレポートを送信でき、各ユーザーは1時間あたり最大10件のレポートを作成できます。このツールは、`https://tuist.dev/mcp`のTuistホスト型サーバーでのみ利用可能です。

| ツール | 説明 | 必須パラメータ |
|------|-------------|---------------------|
| `report_feedback` | Tuistツールまたはプロンプトの問題を報告します。オプションで、発生した`tool_name`、`account_handle`および`project_handle`を指定し、`suggestion`を追加できます。 | `category`, `expected`, `actual` |

#### ソースに基づく回答

これらの読み取り専用ツールにより、エージェントはホスト型サーバーとともにデプロイされた正確な公開Tuistソースリビジョンを、現在の動作に依存する回答の信頼できる情報源として使用できます。`https://tuist.dev/mcp`でのみ利用可能です。

互換性のあるクライアントは、初期化中にツールのソースリビジョン、リンク、結果制限に関する事実上の説明を、インラインOAuth認証情報とともに受け取ります。これらの説明は回答スタイルや検証ワークフローを規定するものではありません。ユーザーは`ask_tuist`プロンプトを最初に呼び出さずに直接質問でき、明示的なソースに基づくワークフローのためにプロンプトは引き続き利用可能です。

すべての操作には、並行性、期間、走査、読み取りバイト数、およびレスポンスサイズに対する固定制限があります。検索および一覧結果には`truncated`および`truncation_reason`フィールドが含まれます。結果が切り捨てられた場合は、結果を完全なものとして扱うのではなく、パス、ファイルパターン、または検索語句を絞り込んでください。

| ツール | 説明 | 必須パラメータ |
|------|-------------|---------------------|

#### Xcodeビルド

Xcode、Gradle、Bazel、Mix、Cargo向けのビルド詳細ツールは、既存の`custom_metadata: {tags, values}`形式を公開し、報告されたインフラストラクチャ観測値も含みます。値は文字列のまま保持され、不明なキーも保存されます。例えば、`tuist.cpu.available_processors`はランタイムで利用可能な論理プロセッサ数を示し、`tuist.gradle.max_workers`はGradleのワーカー上限、`tuist.jvm.max_heap_bytes`はJVMヒープ上限であり、ホストメモリではありません。これらは信頼されていないクライアント観測値であり、検証済みのランナーIDではありません。観測値がない場合はそのまま欠落したままとなり、インポートされたログや古いクライアントにはインフラストラクチャメタデータがない場合があります。Struoメタデータは、クライアント/プロトコルの協調更新を待っています。

| `list_xcode_build_cache_tasks` | 特定のXcodeビルド実行のキャッシュ可能タスク（キャッシュヒット/ミス）を一覧表示します。 | `build_run_id` |
| `list_xcode_build_cas_outputs` | 特定のXcodeビルド実行の[コンテンツアドレサブルストレージ](https://en.wikipedia.org/wiki/Content-addressable_storage)出力を一覧表示します。 | `build_run_id` |

`list_xcode_build_steps`はデフォルトで20ステップのページを返します（`page_size`で最大100）。ナビゲーションには`page`と`pagination_metadata`を使用します。`search`を使用してタイトル、プロジェクト、またはターゲットを一致させるか、正確な`project`、`target`、`category`（例：`swiftCompilation`）、および`status`（`success`または`failure`）でフィルタリングします。`duration_ms`でソートすると遅い順（デフォルト）、`start_ms`でソートすると時系列順になります。ステップIDは同順位を解決するために使用され、64ビット精度を完全に保持するために10進数文字列として返されます。IDはビルドごとにスコープされており、ビルド間で一致させてはいけません。

オプションの`start_ms`と`end_ms`は、ビルド開始からのミリ秒単位の時間範囲と重なるステップを選択します。終了時間は除外されます。どちらのツールも、ビルドUUIDまたはダッシュボードURLを`build_run_id`として受け入れます。返されたステップ`id`を変更せずに`step_id`として渡し、そのログを取得します。ログはステップあたり最大64 KiBまで保持され、`log_truncated`で省略された出力を示します。

Xcodeビルドが処理されると、ステップはデフォルトで収集されます。記録されたステップデータは90日間保持されます。リストレスポンスには`availability`が含まれます。記録されたステップが存在する場合は`available`（フィルタに一致するものがなくても）、ビルドがまだ処理中でステップがない場合は`processing`、ステップが記録されていないか期限切れの場合は`unavailable`となります。

同じ操作は、HTTP APIの`GET /api/projects/{account_handle}/{project_handle}/xcode/builds/{build_id}/steps`および`GET /api/projects/{account_handle}/{project_handle}/xcode/builds/{build_id}/steps/{step_id}`で利用可能で、同じフィルタとページネーションが適用されます。どちらの場合も、ビルドのプロジェクトに対する読み取りアクセス権が必要です。

GradleおよびBazelのステップリストはデフォルトで20件の結果を返し（最大100件）、`search`、正確な`project`、`target`、`category`、および`status`、重複する`start_ms` / `end_ms`フィルタ（終了は除外）、および`duration_ms`または`start_ms`での並べ替えをサポートします。返されたIDは変更せずに渡してください。これらはビルドごとにスコープされています。リストは`time_origin`と`coverage`を公開します。古いGradleレポートは、ビルド開始がアップロードされていないため`first_recorded_timestamp`を使用します。Bazelプロファイルは、`trace_profile`カバレッジと時間原点としての`profile_start`を使用して、記録されたすべての間隔を公開します。古いビルドは保持されたBEPサマリーにフォールバックします。ソースレコードは90日後に期限切れになります。Bazelの詳細には、公開されている場合にサニタイズされたアクションログが含まれます。失敗したタスクまたは構成ステップのGradle詳細には、Tuist Gradleプラグインが`log`として報告した失敗メッセージ（例外メッセージとその原因チェーンをGradleのコンソールが表示する形式）が含まれ、スタックトレースやタスク出力はなく、プロジェクト内のパスは相対パス化され、認証情報やその他のローカルパスは編集されます。ステップあたり最大16 KiB、ビルドあたり最大32件の失敗したステップです。他のGradleステップ、古いプラグインバージョンによって報告されたビルド、および認証情報なしのレポートでは`log`はnullです。構成ステップは、失敗した場合に`failure`を、それ以外の場合は`unknown`を報告します。`compare_builds`プロンプトはこのカバレッジを使用して、完全なBazelトレースと保持されたサマリーを区別し、より広範な呼び出し出力を確認する前に、エージェントをアクションの結果とログを含むステップ詳細へ誘導します。

単一ステップツール`get_gradle_build_step`および`get_bazel_build_step`はIDによってステップを取得し、時間フィルタを受け入れません。時間範囲でステップをフィルタリングするには、対応するリストツールを使用してください。

保持されたサマリーから返されたBazelステップIDは、リスト取得とステップフェッチの間に完全なプロファイルが到着した場合でも読み取り可能です。ステップデータが期限切れになったインデックス付きプロファイルは、利用不可を報告します。Gradleステップリストには、期間がゼロのキャッシュ済みおよびスキップされた操作が含まれます。

これらのプロジェクトスコープのツールは、実行間で永続的なビルド識別子を検査します。`list_build_entities`から始め、返された安定した`id`と同じ`kind`を`get_build_entity`または`list_build_entity_history`に渡し、`account_handle`および`project_handle`と一緒に指定します。ビルドまたは呼び出し識別子は必要ありません。

これらのツールは段階的に展開されており、有効になっているプロジェクトのデータのみを返します。それ以外のプロジェクトでは、空の結果ではなくエラーを返します。種類は、そのビルドツールチェーンを使用するプロジェクトでのみ利用可能です。ツールは境界付きの`start_at`/`end_at`フィルタ、`environment`（`any`、`ci`、または`local`）、および正確な`branch`を受け入れます。`list_build_entities`は`q`を受け入れ、`list_build_entity_history`は不透明な`after`/`before`カーソルをサポートします。不明なタイミングやキャッシュの観測は、ゼロやミスとして扱われるのではなく、利用不可のままとなります。履歴は、既存の実行ツールを使用したドリルダウンのために、記録された親とネイティブ実行を参照します。

`get_build_entity`メトリクスには`duration_samples`が含まれ、これは記録されたタイミングを持つ観測の数です。実際のゼロ期間の観測はカウントされますが、タイミングが欠落している観測はカウントされません。この数は観測数より少なくなる可能性があります。利用できない期間統計はnullのままです。

Xcodeモジュールの期間は、ビルドログで測定されたターゲットコンパイルから取得されます。モジュールキャッシュの解決やコンパイル作業のないターゲットは、期間サンプルに寄与しません。コンパイルの観測はXcodeビルドを参照し、キャッシュイベントは生成コマンドまたはキャッシュコマンドを参照します。

Bazelアクションは、ターゲットラベル、ニーモニック、および設定された主要な出力によって識別され、入力依存のキャッシュダイジェストに頼ることなく、個別のアクションと構成を区別します。履歴はBEPで報告された実行を記録し、キャッシュルックアップやトレースプロファイルのフェーズは記録しません。完全な実行カバレッジには`--build_event_publish_all_actions`が必要です。アーティファクトの配信はベストエフォートであるため、観測が欠落していることは作業が実行されなかった証拠ではありません。安定した識別子や実行開始情報を持たない古いKuraペイロードは受け入れられますが、インデックス化されません。終了時間の測定値が存在しない場合は利用不可のままとなり、実際のゼロ期間の観測はカウントされます。

Mixモジュールの期間は、含まれるファイルのコンパイルを測定するものであり、独立して測定されたモジュールの作業ではありません。Struoアクションは、クライアントがターゲットマッピングを報告した場合、宣言されたターゲット/機能/インデックススロットを使用します。診断ラベルだけでは安定した識別子とはなりません。既存のクライアントと実行レベルのツールは変更なくサポートされます。

Cargoクレートは、正確に記録されたクレートルート、名前、および種類によってグループ化されます。チェックアウトパスの変更により履歴が分割される可能性があり、ビルドプロファイル、機能、およびターゲットトリプルは区別されません。履歴はrustc呼び出しを測定し、ファイルごとの作業やキャッシュヒットは測定しません。欠落しているジョブは、削除や完全なワークスペース在庫の確立を示すものではありません。

分析読み取りにはメモリと実行時間の制限があります。クエリがこれらの制限を超えると、ツールは空の結果を捏造する代わりにエラーを返します。

新しい観測はデプロイ後にインデックス化されます。この機能は既存の実行テレメトリをバックフィルしません。識別子メタデータは、<.localized_link href="/guides/server/data-retention">データ保持ポリシー</.localized_link>に基づき、個々の観測よりも長く保持されます。

### イベント

ステートレスな`2026-07-28` Model Context Protocolライフサイクルを使用するクライアントは、`events/list`を呼び出してイベントとそのペイロードスキーマを検出できます。

| イベント | 送信タイミング | サブスクリプションフィルタ |
|-------|-----------------|---------------------|
| `test_case.marked_flaky` | テストケースが不安定でない状態から不安定な状態に変化します。 | `account_handle`, `project_handle` |
| `build.failed` | ローカルまたは継続的インテグレーションのXcode、Gradle、Bazelビルドが失敗して終了します。 | `account_handle`, `project_handle` |
| `test_run.failed` | ローカルまたは継続的インテグレーションのテスト実行が失敗して終了します。マージされたシャーディング実行や中断された実行も含まれます。 | `account_handle`, `project_handle` |
| `ci_job.failed` | Tuistランナージョブが失敗して完了します。 | `account_handle` |

サブスクライブするには、クライアントはイベント名、上記の`arguments`にリストされたハンドル、および`https://`コールバックURLと`whsec_`署名シークレットを含む`webhook`配信を指定して`events/subscribe`を呼び出します。プロジェクトイベントにはアカウントメンバーシップと対応するテストまたはビルドデータへの読み取りアクセスが必要です。ランナージョブイベントにはアカウントメンバーシップとランナー読み取りアクセスが必要です。クレーム済みの[`auth.md`](https://workos.com/auth-md)アクセストークン、クレーム済みのアカウントトークン、ブラウザ認証グラントでサブスクリプションを作成できます。関連する認証情報が有効でなくなると配信は停止します。各ユーザーは最大25件のアクティブなサブスクリプションを保持できます。Tuistはサブスクリプションを保存する前にコールバックに検証チャレンジを送信します。コールバックは同じ`challenge`値を含むオブジェクトを返す必要があります。サブスクリプションはデフォルトで7日間有効で、再度サブスクライブすることで更新でき、ユーザーのアクセス権限または認証情報が削除されると配信が停止します。オプションの`ttlMs`は1時間から30日の間で制限されます。Tuistはタイムアウトしたコールバックを再試行し、5分間にわたる少なくとも3回連続のタイムアウト後にサブスクリプションを解除します。コールバックを復旧した後に再度サブスクライブしてください。

イベントが発生すると、Tuistはそのリソース識別子とダッシュボードURLをコールバックに送信します。ビルドおよびテスト実行の失敗には`is_ci`と`git_branch`も含まれるため、クライアントはローカルの失敗を無視したり、ブランチでフィルタしたりできます。ビルドイベントには`build_system`が含まれます。ランナージョブイベントには`workflow_job_id`と`workflow_run_id`の両方が含まれます。リクエストにはサブスクリプション識別子と[Standard Webhooks](https://www.standardwebhooks.com/)署名ヘッダーが含まれ、クライアントが発信元を検証できます。Tuistは失敗した配信を再試行するため、クライアントは安定した`eventId`を使用して重複を除外する必要があります。ペイロードにはテスト名、ログ、失敗メッセージは含まれません。クライアントは上記のツールを通じてこれらの詳細を取得し、チームに通知するかデバッグを開始するかを決定できます。クライアントは`events/unsubscribe`を使用して配信を停止できます。
