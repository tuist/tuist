# Gradle テストインサイト {#gradle-test-insights}

> [!IMPORTANT]
> **要件**
>
> - `dev.tuist` Gradle プラグインが適用されていること（詳細は <.localized_link href="/guides/get-started/gradle-project">Gradle プロジェクトを始める</.localized_link> を参照）。

Tuist の Gradle プラグインは、各テストタスクの実行後にテスト結果を自動的にアップロードし、Tuist ダッシュボードでテストのパフォーマンスと不安定なテストを可視化します。

プラグインを適用すると、テストインサイトは自動的に収集されます。追加の設定は不要です。

Tuist ダッシュボードでテストインサイトにアクセスし、時間経過とともにどのように変化するかを確認できます：

![テストインサイト付きダッシュボード](/images/guides/features/build-insights/tests-dashboard.png)

## 追跡対象 {#what-is-tracked}

このプラグインは、すべての Gradle `Test` タスクの結果を収集します。対象には以下が含まれます：
- 個々のテストケースの合否ステータスと実行時間
- テストスイートおよびクラス構造
- 複数回の実行にわたる不安定なテストの検出

<.localized_link href="/guides/features/test-code-coverage/gradle">コードカバレッジ</.localized_link> を有効にすると、テストが実行したコードもアップロードされます。

## アップロード動作の設定 {#configure-upload-behavior}

デフォルトでは：
- ローカルビルドの場合、テスト結果はバックグラウンドでアップロードされます。
- CI 実行の場合、短命なエージェントでのテレメトリ損失を防ぐため、テスト結果はフォアグラウンドでアップロードされます。

`settings.gradle.kts` 内の `tuist` ブロックで `uploadInBackground` を使用して、この動作を上書きできます：

```kotlin
tuist {
    uploadInBackground = false // always upload in the foreground
}
```

### Git ヒストリー {#git-history}

CI では、プラグインはテスト実行を報告する際に、チェックアウトのコミットヒストリーもアップロードします。これには、コミット SHA、その親コミット、コミット日時、およびその実行とプルリクエストのベースブランチが属していたブランチが含まれます。ファイルの内容、コミットメッセージ、または作者情報はアップロードされません。これは、デフォルトブランチにマージされたコミット（例えば、マージキューによってテストされたコミット）を Tuist が識別するために使用されます。プラグインはチェックアウトが既に持っているヒストリーを読み取り、チェックアウトにベースブランチがない場合は、リモートに対して最新のコミットを問い合わせます（`git ls-remote`）。コードカバレッジ以外の場合、ヒストリーは取得されません。コードカバレッジを使用する場合、ファイルの内容なしで浅いチェックアウトが深化され、プルリクエストが分岐した地点を特定し、Tuist が既に持っているコミットに到達できるようにします。これにより、親コミットのないコミットがアップロードされることはありません。

| 変数 | 効果 |
| --- | --- |
| `TUIST_GIT_UPLOAD_ENABLED=false` | Git ヒストリーの読み取りやアップロードを行いません。 |
| `TUIST_GIT_UNSHALLOW_ENABLED=false` | リモートに接続せず、チェックアウトのみを読み取ります。 |
| `TUIST_GIT_BRANCH=<branch>` | CI プロバイダーやチェックアウトの情報よりも優先して、実行のブランチ名を設定します。ブランチではなくコミットをチェックアウトする、Tuist が認識しない CI システムで使用してください。設定しない場合、これらの実行にはブランチ情報がありません。 |
