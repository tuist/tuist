# Once の不安定なテスト {#once-flaky-tests}

> [!IMPORTANT]
> **要件**
>
> - 構造化された個別のテスト結果を用いて <.localized_link href="/guides/features/test-insights/once">Once テストインサイト</.localized_link> を設定します。

<!-- @snippet: ./_intro -->

## 不安定な検出の仕組み {#how-it-works}

### テストの再試行 {#test-retries}

ランナーが同じテストに対する複数の試行を報告すると、Tuist はそれらを保持します。失敗した後に成功したテストは不安定として報告され、継続して失敗するテストは失敗のままとなります。サポートされている場合は、基盤となるランナーで再試行を有効にしてください。Once を Tuist に接続しても、すべてのテストターゲットに自動的に再試行が追加されるわけではありません。

### クロスラン検出 {#cross-run-detection}

共有されたテスト履歴により、Tuist は CI における同じテストとコミットの成功および失敗の結果を比較できます。この比較には、Once がコミットと CI コンテキストを報告する必要があります。ローカル実行は表示されますが、自動的なクロスランの不安定証拠にはなりません。

ケースはネイティブターゲット、スイート、およびケース名によって識別されます。履歴を維持するためにこれらの識別子を安定させ、ターゲット全体の結果から信頼性を推測するのではなく、完全なケースごとのレポートを使用してください。

## 不安定なテストの調査 {#investigate-flaky-tests}

Tuist でテストケースの履歴を開き、その試行、失敗、および影響を受けた CI コミットを比較します。共有テストクエリは <.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocol ツール</.localized_link> からも利用可能であり、コーディングエージェントが同じ報告結果を調査できます。

## 不安定なテストの管理 {#managing-flaky-tests}

失敗を調査している間、詳細ページからテストを不安定としてマークしたり、マークを解除したりできます。デフォルトの不安定テスト検出自動化は、回復ウィンドウ（通常は別のトリガーがない状態で 14 日間）の後にフラグをクリアします。

Once プロジェクトは現在、**Automations** 設定タブを公開していません。検出と保存されたテスト状態は利用可能ですが、隔離強制機能を持つビルドシステム向けに文書化されている設定ワークフローは、Once ではまだ公開されていません。

## 隔離 {#quarantining}

Tuist は報告されたケースを保存された隔離状態に関連付けることができますが、ネイティブの Once クライアントは現在、Tuist の **Muted** または **Skipped** ポリシーを取得して適用しません。Tuist でその状態を変更しても、Once によるテストの実行が停止したり、その失敗によって CI のブロックが解除されることはありません。

実行時の隔離が必要な場合は、ランナー独自のフィルタリングまたは失敗ポリシーを使用してください。コマンドの終了コードを変更するためにダッシュボードの状態のみに依存しないでください。
