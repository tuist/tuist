# Once の不安定なテスト {#once-flaky-tests}

> [!IMPORTANT]
> **要件**
>
> - 構造化された個別のテスト結果を使って <.localized_link href="/guides/features/test-insights/once">Once テストインサイト</.localized_link> を設定してください。

<!-- @snippet: ./_intro -->

## 不安定なテストの検出方法 {#how-it-works}

### テストの再試行 {#test-retries}

ランナーが同じテストに対して複数の試行を報告すると、Tuist はそれらを保持します。一度失敗してから成功したテストは不安定として報告され、継続して失敗するテストは失敗のままです。サポートされている場合は、基盤となるランナーで再試行を有効にしてください。Once を Tuist に接続しても、すべてのテストターゲットに自動的に再試行が追加されるわけではありません。

### 複数実行にわたる検出 {#cross-run-detection}

共有されたテスト履歴により、Tuist は CI 上で同じテストとコミットに対する成功および失敗の結果を比較できます。この比較には、Once がコミットと CI コンテキストを報告する必要があります。ローカルでの実行は表示されますが、自動的な複数実行にわたる不安定性の証拠にはなりません。

テストケースはネイティブターゲット、スイート、およびケース名で識別されます。履歴を維持するためにこれらの識別子を安定させ、ターゲット全体の結果から信頼性を推測するのではなく、ケースごとの完全なレポートを使用してください。

## 不安定なテストの調査 {#investigate-flaky-tests}

Tuist でテストケースの履歴を開き、試行、失敗、および影響を受けた CI コミットを比較してください。共有テストクエリは <.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocol ツール</.localized_link> からも利用可能であり、コーディングエージェントが同じ報告結果を調査できます。

## 不安定なテストの管理 {#managing-flaky-tests}

失敗を調査している間、詳細ページからテストを不安定としてマークしたり、そのマークを解除したりできます。デフォルトの不安定なテスト検出自動化は、回復期間（通常は別のトリガーがない状態で 14 日間）の後にフラグをクリアします。

Once プロジェクトでは現在、**Automations** 設定タブは公開されていません。検出と保存されたテスト状態は利用できますが、隔離強制機能を備えたビルドシステム向けに文書化されている設定ワークフローは Once ではまだ公開されていません。

## 隔離 {#quarantining}

Tuist は報告されたケースを保存された隔離状態に帰属させることができますが、ネイティブの Once クライアントは現在、Tuist の **Muted** または **Skipped** ポリシーを取得して適用しません。Tuist でその状態を変更しても、Once によるテストの実行が停止したり、その失敗が CI のブロックを解除したりすることはありません。

実行時の隔離が必要な場合は、ランナー独自のフィルタリングまたは失敗ポリシーを使用してください。コマンドの終了コードを変更するためにダッシュボードの状態だけに依存しないでください。
