# Rust の不安定なテスト {#rust-flaky-tests}

Tuist は Cargo テストの結果の不整合を検出し、**テスト → 不安定なテスト** で調査を支援します。

> [!IMPORTANT] Requirements
> - <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link> を設定してください。

## 不安定な検出の仕組み {#how-it-works}

Tuist は同じコミットに対する CI 実行を比較します。ある実行では成功し、別の実行では失敗するテストは不安定としてマークできます。

各実行を通常のコマンドで報告します:

```sh
tuist cargo test --workspace
```

Cargo は失敗したテストを自動的に再試行しません。同じコミットで CI ジョブを再実行すると、クロスラン検出のための別の結果が得られます。

## 不安定なテストの管理 {#managing-flaky-tests}

### 自動クリア

検出と回復はプロジェクトの「不安定なテスト検出」オートメーションを通じて実行されます。デフォルトでは、再トリガーがない状態で 14 日経過すると不安定フラグがクリアされます。**設定 → オートメーション** で回復期間とアクションを編集できます。

### 手動管理

**テスト → 不安定なテスト** を開いてテストの履歴を確認します。詳細ページから手動で不安定としてマークしたり、マークを解除したりできます。

## 隔離と負荷テスト {#quarantine}

詳細ページからテストをミュートまたはスキップするか、**設定 → オートメーション** で隔離を設定します。次の `tuist cargo test` でプロジェクトの現在の隔離状態を取得します:

- **ミュート**されたテストは引き続き実行され、実際の結果を報告しますが、その失敗によってコマンドが失敗することはありません。他のテストの失敗、コンパイルエラー、クラッシュ、および不完全な結果は通常どおり失敗します。
- **スキップ**されたテストは実行から除外され、隔離されたスキップとして報告されます。マッチングにはパッケージ、ターゲット、Rust モジュールパス、およびテスト名が含まれるため、類似した名前のテストは独立して扱われます。

ミュートは選択されたワークスペースのパッケージとフィーチャを保持し、ミュートされたターゲットが失敗しても選択されたすべてのターゲットを実行します。スキップ隔離では単一のパッケージを選択する必要があります。マルチパッケージのワークスペースコマンドではなく `tuist cargo test -p store` を使用してください。Tuist はマルチパッケージのスキップを拒否します。これは、コマンドを狭めることで Cargo の統合された依存関係フィーチャが変更される可能性があるためです。

隔離は <.localized_link href="/guides/features/test-sharding/rust">分割された Cargo 実行</.localized_link> にも適用されます。Tuist が状態を取得できない場合、警告を出して隔離なしで実行します。失敗は抑制されません。意図的に隔離なしで実行するには:

```sh
TUIST_TEST_SKIP_QUARANTINE=1 tuist cargo test --workspace
```

適用には標準の libtest ハーネスとキャプチャされたデフォルト出力が必要です。quiet、verbose、代替フォーマット、または未キャプチャの出力を使用するコマンドは、隔離を適用する必要がある場合に失敗します。ターゲットの帰属が曖昧な場合は、`-p <package>` で正確なワークスペースパッケージを選択してください。カスタムハーネス、パッケージ/ターゲット名のグロブ、および未解決のパッケージ選択はサポートされていません。ドックテストもミュートまたはスキップできますが、Rustdoc のテストフィルタリングはすべての可能な例の名前のペアを区別できません。例をスキップすると有効な例もスキップされてしまう場合、または部分的なドックテストの除外に `--exact` が使用されている場合、Tuist はスキップされた例を実行したり有効なテストを黙って省略したりするのではなく、診断情報とともに失敗します。調査中は上記のオーバーライドを使用してください。

Tuist は新しい Cargo テストの負荷テストを行いません。調査中に失敗するテストを繰り返すには、Cargo テストフィルタを使用します:

```sh
tuist cargo test -p store rejects_invalid_token
```

## Slack 通知 {#notifications}

テストが不安定になったときにチームに通知するため、<.localized_link href="/guides/integrations/slack#flaky-test-alerts">Slack 不安定なテストアラート</.localized_link> を設定してください。
