# Rustの不安定なテスト {#rust-flaky-tests}

TuistはCargoテスト結果の不整合を検出し、**テスト → 不安定なテスト**で調査を支援します。

> [!IMPORTANT]
> **要件**
>
> - <.localized_link href="/guides/features/test-insights/rust">Rustテストインサイト</.localized_link>を設定してください。

## 不安定な検出の仕組み {#how-it-works}

Tuistは同じコミットに対するCI実行を比較します。ある実行では合格し、別の実行では失敗するテストは、不安定としてマークできます。

通常のコマンドで各実行を報告します:

```sh
tuist cargo test --workspace
```

Cargoは失敗したテストを自動的に再試行しません。同じコミットでCIジョブを再実行すると、クロスラン検出のための別の結果が得られます。

## 不安定なテストの隔離 {#quarantining}

詳細ページからテストをミュートまたはスキップするか、**設定 → オートメーション**で隔離を設定します。次の`tuist cargo test`でプロジェクトの現在の隔離状態を取得します:

- **ミュート**されたテストは引き続き実行され、実際の結果を報告しますが、その失敗によってコマンドが失敗することはありません。他のテストの失敗、コンパイルエラー、クラッシュ、および不完全な結果は通常どおり失敗します。
- **スキップ**されたテストは実行から除外され、隔離されたスキップとして報告されます。マッチングにはパッケージ、ターゲット、Rustモジュールパス、およびテスト名が含まれるため、類似した名前のテストは独立して扱われます。

ミュートは選択されたワークスペースのパッケージとフィーチャーを維持し、ミュートされたターゲットが失敗しても、選択されたすべてのターゲットを実行します。スキップ隔離には1つの選択されたパッケージが必要です。`tuist cargo test -p store`を使用し、複数パッケージのワークスペースコマンドは使用しないでください。Tuistは複数パッケージのスキップを拒否します。これは、コマンドを狭めることでCargoの統合された依存関係フィーチャーが変更される可能性があるためです。

隔離は<.localized_link href="/guides/features/test-sharding/rust">分割されたCargo実行</.localized_link>にも適用されます。Tuistが状態を取得できない場合、警告を表示して隔離なしで実行します。失敗は抑制されません。意図的に隔離なしで実行するには:

```sh
TUIST_TEST_SKIP_QUARANTINE=1 tuist cargo test --workspace
```

### 制限事項 {#limitations}

- 強制には標準のlibtestハーネスとキャプチャされたデフォルト出力が必要です。quiet、verbose、alternate-format、または未キャプチャ出力を使用するコマンドは、隔離を適用する必要がある場合に失敗します。
- ターゲットの帰属があいまいな場合は、`-p <package>`を使用して正確なワークスペースパッケージを選択してください。カスタムハーネス、パッケージ/ターゲット名のグロブ、および解決されていないパッケージの選択はサポートされていません。
- ドックテストもミュートまたはスキップできますが、Rustdocのテストフィルタリングはすべての可能な例の名前のペアを区別できません。例をスキップすると有効な例もスキップされる場合、または部分的なドックテストの除外が`--exact`を使用する場合、Tuistはスキップされた例を実行したり、有効なテストを黙って省略したりするのではなく、診断情報を出して失敗します。調査中は上記のオーバーライドを使用してください。

## 新しいテストのストレステスト {#stress-testing-new-tests}

Tuistは新しいCargoテストのストレステストを行いません。調査中に失敗するテストを繰り返すには、Cargoテストフィルタを使用します:

```sh
tuist cargo test -p store rejects_invalid_token
```
