不安定なテストを隔離することで、修正中にCIがブロックされるのを防ぎます。デフォルトでは**手動操作**です。ダッシュボードのテストケース詳細ページから、テストを隔離したり、解除したり、モードを切り替えます。**設定 → 自動化**の下で**自動化アラート**を設定すれば、不安定さのしきい値を超えたときにテストが自動的にミュート（またはスキップ）され、回復すると解除されます。手動か自動かを問わず、すべての遷移はテストケースの監査ログに記録されます。

デフォルトでは、トリガー条件が満たされなくなるまで回復を待ちます。そのため、古い不安定な実行がトリガーウィンドウから外れるまで、テストは隔離されたままになります。より早く回復させるには、**回復条件**を**新しい不安定な実行なし**に設定します。これにより、回復ウィンドウ（日数または実行回数）の間に新しい不安定な実行が発生しなければテストは回復し、新しい不安定な実行が発生するたびに待機状態がリセットされます。回復後は、新しい不安定な実行が発生した場合のみ再び隔離されます。
