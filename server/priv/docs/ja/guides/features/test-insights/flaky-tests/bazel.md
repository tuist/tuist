# Bazelの不安定なテスト {#bazel-flaky-tests}

`tuist bazel test` は各呼び出しの前にTuistの検疫ポリシーを取得し、基盤となる `bazel test` の実行に適用します。

## 検疫の適用 {#applying-quarantine}

テストのページで状態を **Muted** に変更し、次に実行します：

```sh
tuist bazel test -- //app:tests
```

`--` 以降の引数は `bazel test` に転送されます。`--path` を使用してプロジェクトと作業ディレクトリを選択し、`--bazel` を使用して `bazelisk` などの別の実行ファイルを選択します。通常の `bazel test` でもテスト結果は報告されますが、Tuistの検疫ポリシーの取得や強制は行いません。

検疫には名前付きのBazel構成も再試行も必要ありません。**Flaky Tests**、**Quarantined Tests**、および個別のテストページは、他のビルドシステムと同じ手動での状態変更をサポートしています。**Settings → Automations** を使用して、不安定性のしきい値、検疫アクション、および復旧アクションを設定します。

### ミュート {#mute}

主要な検疫ワークフローとして **Mute** を使用します。ミュートされたケースは引き続き実行され、その失敗は表示されたままになり、正常な兄弟ケースは結果に影響を与え続けます。新しい実行は、ターゲットからどのケースも除外することなく、復旧のための証拠を提供します。

Tuistは一時的なローカルビルドイベントファイルと参照される `test.xml` レポートを読み取ります。完全なレポートが、失敗した各ターゲット内の報告されたすべての失敗をミュートされたケースに帰属させる場合にのみ、Bazelのテスト失敗の終了コードを成功に変更します。

ビルドエラー、タイムアウト、中断された実行、欠落または不正な形式のレポート、不完全なイベントストリーム、およびミュートセット外の失敗は、Bazelの失敗ステータスを保持します。ローカルイベントファイルは64メビバイト、個別のレポートは5メビバイトに制限されています。Tuistはミュートされた失敗を検証し、古くなったスキップされたターゲットから復旧するために独自のローカルビルドイベントファイルを必要とするため、明示的な `--build_event_json_file` をアクティブなミュートまたはスキップされたケースと組み合わせることはできません。リモートビルドイベントの報告は `tuist bazel setup` を通じて設定されたままです。

元のBazel呼び出しとレポートは実際の結果を保持します。Tuistのサーバーは、レポートが処理される前に状態が変更された場合でも、呼び出し開始時にケースが検疫されていたかどうかを記録します。

### スキップ {#skip}

**スキップ**は、そのターゲット内の正常なケースも含めて**Bazel ターゲット全体**を除外する場合にのみ使用してください。単一のケースを**スキップ済み**としてマークすると、このターゲット全体に影響する効果があります。Bazel の個別ケースフィルター構文はテストフレームワークに依存し、普遍的にサポートされているわけではありません。そのため、Tuist はテストスイートの展開を有効にした状態でネイティブの除外ターゲットパターンを使用します。明示的なターゲット、ワイルドカード選択、および `test_suite` ルール内のテストは、Bazel の通常の選択動作を維持します。

このコマンドはすべての検疫ページを取得し、ターゲットの重複を排除します。Bazelの完全なイベントログが、ターゲットの構成または実行前に欠落しているスキップされたターゲットを特定した場合、Tuistは警告でそれを示し、その古くなった除外なしで再試行します。元のリクエストされたパターンと他のすべての除外は保持されます。復旧は5回の再試行に制限されます。その他の読み込み失敗と不完全な証拠はBazelのエラーを保持します。古くなったケースを **Enabled** に戻して、そのポリシーを永続的に削除します。ターゲットパターンを直接渡してください。`--target_pattern_file` は検疫除外と組み合わせることができません。テストターゲットが残っていない場合、Bazelは通常の「テストが見つかりません」終了ステータスを保持し、これは誤って空になったテスト選択も捕捉します。

このコマンドは除外されたすべてのターゲットラベルを出力するため、ビルドログには、検疫ポリシーがどのターゲット（それらの正常なケースを含む）を除外しているかが表示されます。

### 検疫されたテストの再実行 {#running-quarantined-tests-again}

修正を調査または検証するには、両方の検疫ポリシーをバイパスします：

```sh
tuist bazel test --no-quarantine -- --nocache_test_results //app:tests
```

ケースを **Enabled** に戻して、後続の通常の実行にそのターゲットを含めます。スキップされたケースは、明示的に含まれるまで新しい実行を生成しないため、成功した新しい実行に基づく自動化は、それらを復旧させる前に検証実行が必要です。

検疫取得エラーは、テストを実行する前にコマンドを停止します。また、コマンドは20,000ケースを超えるポリシーまたは境界サイズを超えるターゲット引数を拒否します。部分的なポリシーが適用されることはありません。ポリシーなしで意図的に実行したい場合は `--no-quarantine` を使用します。

## オプションの構成と再試行 {#optional-configuration-and-retries}

リポジトリが `.bazelrc` で名前付き `ci` 構成を定義している場合、`--config=ci` でそれを選択できます：

```sh
tuist bazel test -- --config=ci //app:tests
```

これはリポジトリで定義された構成であり、Tuistの前提条件ではありません。リポジトリで定義されていない場合は、このオプションを省略してください。

再試行もオプションであり、検疫とは独立しています。`--flaky_test_attempts=3` は、テストごとに最大 **3回のBazel試行** を有効にしますが、追加の3回の再試行ではありません。チームは `.bazelrc` に既存の再試行構成を保持するか、明示的に渡すことができます：

```sh
tuist bazel test -- --flaky_test_attempts=3 //app:tests
```

`ci` を定義するリポジトリの場合、オプションを組み合わせることができます：

```sh
tuist bazel test -- --config=ci --flaky_test_attempts=3 //app:tests
```

## 不安定性の検出 {#detecting-flakiness}

Tuistは、Bazelの `test.xml` レポートからの個別のケースを使用して、継続的インテグレーションにおける同じコミットとターゲット選択の実行間および再試行間での不一致の結果を検出します。ローカル実行は表示されますが、テストケースを自動的に不安定としてフラグ付けしません。ビルド環境がすでに公開していない場合は、コミットとブランチのメタデータを提供します：

```sh
tuist bazel test -- \
  --build_metadata=CI=true \
  --build_metadata=GIT_COMMIT="$GIT_COMMIT" \
  --build_metadata=GIT_BRANCH="$GIT_BRANCH" //app:tests
```

Tuistが結果を観察するには、再試行が実際に実行される必要があります。Bazelターゲットの不安定サマリーだけでは、どの個別のケースが不安定であったかは識別できません。利用できないか解析できないレポートは、ケースレベルの証拠を提供できません。

ケースは、ターゲットラベル、クラス名（スイート名にフォールバック）、およびテスト名によって識別されます。これにより、異なるクラス内の同名のメソッドが分離されます。異なる包含スイート名を使用した古いレポートは、古い識別子の下で履歴を保持します。それらの検疫状態は新しい識別子に適用する必要があります。失敗が現在のクラス識別子ではなく古いスイートベースのミュートと一致する場合、コマンドはどのポリシーを再適用する必要があるかを警告し、失敗をブロックし続けます。複数のクラスが古い識別子を共有していた可能性があるため、ポリシーは自動的に転送されません。

基礎となる動作については、Bazelの [test filters](https://bazel.build/docs/user-manual#test-filter)、[command options](https://bazel.build/reference/command-line-reference)、および [build-event descriptions](https://bazel.build/remote/bep-glossary) を参照してください。
