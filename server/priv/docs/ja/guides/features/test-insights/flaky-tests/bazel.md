# Bazelの不安定なテスト {#bazel-flaky-tests}

`tuist bazel test` は、各呼び出しの前にTuistの検疫ポリシーを取得し、基盤となる `bazel test` の実行に適用します。

## 検疫の適用 {#applying-quarantine}

テストのページで状態を **ミュート** に変更し、次に実行します：

```sh
tuist bazel test -- //app:tests
```

`--` 以降の引数は `bazel test` に転送されます。`--path` を使用してプロジェクトと作業ディレクトリを選択し、`--bazel` を使用して `bazelisk` などの別の実行ファイルを選択してください。通常の `bazel test` でもテスト結果は報告されますが、Tuistの検疫ポリシーの取得や適用は行われません。

検疫には、名前付きBazel構成も再試行も必要ありません。**不安定なテスト**、**検疫中のテスト**、および個々のテストのページは、他のビルドシステムと同じ手動での状態変更をサポートしています。**設定 → オートメーション** を使用して、不安定性のしきい値、検疫アクション、および復旧アクションを設定してください。

### ミュート {#mute}

主要な検疫ワークフローとして **ミュート** を使用してください。ミュートされたケースは引き続き実行され、その失敗は表示されたままになり、正常な兄弟ケースは結果に影響を与え続けます。新しい実行は、ターゲットからどのケースも除外することなく、復旧のための証拠を提供します。

Tuistは一時的なローカルビルドイベントファイルと参照される `test.xml` レポートを読み取ります。完全なレポートが、失敗した各ターゲット内の報告されたすべての失敗をミュートされたケースに帰属させる場合にのみ、Bazelのテスト失敗による終了コードを成功に変更します。

ビルドエラー、タイムアウト、中断された実行、欠落または不正な形式のレポート、不完全なイベントストリーム、およびミュートセット外の失敗は、Bazelの失敗ステータスを維持します。ローカルイベントファイルは64 MiBに、個々のレポートは5 MiBに制限されています。Tuistはミュートされた失敗を検証し、古くなったスキップされたターゲットから復旧するために独自のローカルビルドイベントファイルを必要とするため、明示的な `--build_event_json_file` をアクティブなミュートまたはスキップされたケースと組み合わせることはできません。リモートビルドイベントの報告は `tuist bazel setup` を介して設定されたままです。

元のBazel呼び出しとレポートは実際の結果を維持します。Tuistのサーバーは、レポートが処理される前に状態が変更された場合でも、呼び出し開始時にケースが検疫されていたかどうかを記録します。

### スキップ {#skip}

そのターゲット内の正常なケースを含め、**Bazelターゲット全体** を除外する意図がある場合にのみ **スキップ** を使用してください。単一のケースを **スキップ** としてマークすると、このターゲット全体の効果が生じます。Bazelの個別ケースフィルター構文はテストフレームワークに依存し、普遍的にサポートされているわけではありません。したがって、Tuistはテストスイート展開を有効にしたネイティブの否定ターゲットパターンを使用します。明示的なターゲット、ワイルドカード選択、および `test_suite` ルール内のテストは、Bazelの通常の選択動作を維持します。

このコマンドはすべての検疫ページを取得し、ターゲットの重複を排除します。Bazelの完全なイベントログが、ターゲット構成または実行前に欠落しているスキップされたターゲットを特定した場合、Tuistは警告でそれを示し、その古くなった除外なしで再試行します。元のリクエストされたパターンと他のすべての除外は保持されます。復旧は5回の再試行に制限されます。その他の読み込み失敗と不完全な証拠はBazelのエラーを維持します。古くなったケースを **有効** に戻して、そのポリシーを永久に削除してください。ターゲットパターンを直接渡してください。`--target_pattern_file` は検疫除外と組み合わせることができません。テストターゲットが残っていない場合、Bazelは通常の「テストが見つかりません」終了ステータスを維持し、誤って空になったテスト選択も捕捉します。

このコマンドは除外されたすべてのターゲットラベルを出力するため、ビルドログには、検疫ポリシーが除外するターゲット（それらの正常なケースを含む）が表示されます。

### 検疫されたテストの再実行 {#running-quarantined-tests-again}

修正を調査または検証するには、両方の検疫ポリシーをバイパスします：

```sh
tuist bazel test --no-quarantine -- --nocache_test_results //app:tests
```

ケースを **有効** に戻して、後続の通常の実行にそのターゲットを含めます。スキップされたケースは、明示的に含まれるまで新しい実行を生成しないため、成功した新しい実行に基づくオートメーションは、それらを復旧させる前に検証実行が必要です。

検疫取得エラーは、テストを実行する前にコマンドを停止させます。また、コマンドは20,000ケースを超えるポリシーまたは境界サイズを超えるターゲット引数を拒否します。部分的なポリシーが適用されることはありません。ポリシーなしで意図的に実行したい場合は `--no-quarantine` を使用してください。

## オプションの構成と再試行 {#optional-configuration-and-retries}

リポジトリが `.bazelrc` で名前付き `ci` 構成を定義している場合、`--config=ci` で選択できます：

```sh
tuist bazel test -- --config=ci //app:tests
```

これはリポジトリで定義された構成であり、Tuistの前提条件ではありません。リポジトリで定義されていない場合は、このオプションを省略してください。

再試行もオプションであり、検疫とは独立しています。`--flaky_test_attempts=3` は、テストごとに最大 **3回のBazel試行** を有効にしますが、追加の再試行を3回行うわけではありません。チームは、`.bazelrc` に既存の再試行構成を保持するか、明示的に渡すことができます：

```sh
tuist bazel test -- --flaky_test_attempts=3 //app:tests
```

`ci` を定義するリポジトリの場合、オプションを組み合わせることができます：

```sh
tuist bazel test -- --config=ci --flaky_test_attempts=3 //app:tests
```

## 不安定性の検出 {#detecting-flakiness}

Tuistは、Bazelの `test.xml` レポートからの個別のケースを使用して、連続的インテグレーションにおける同じコミットとターゲット選択の実行間および再試行間での一貫性のない結果を検出します。ローカル実行は表示されますが、テストケースを自動的に不安定としてフラグ付けしません。ビルド環境がすでに公開していない場合は、コミットとブランチのメタデータを提供してください：

```sh
tuist bazel test -- \
  --build_metadata=CI=true \
  --build_metadata=GIT_COMMIT="$GIT_COMMIT" \
  --build_metadata=GIT_BRANCH="$GIT_BRANCH" //app:tests
```

Tuistが結果を観察するには、再試行が実際に実行される必要があります。Bazelターゲットの不安定なサマリーだけでは、どの個別のケースが不安定であったかを特定できません。利用できないか解析できないレポートは、ケースレベルの証拠を提供できません。

ケースは、ターゲットラベル、クラス名（スイート名にフォールバック）、およびテスト名によって識別されます。これにより、異なるクラス内の同名のメソッドが区別されます。異なる包含スイート名を使用した古いレポートは、古いIDの下で履歴を保持します。その検疫状態は新しいIDに適用する必要があります。失敗が現在のクラスIDではなく古いスイートベースのミュートと一致する場合、コマンドはどのポリシーを再適用する必要があるかを警告し、失敗をブロックし続けます。複数のクラスが古いIDを共有していた可能性があるため、ポリシーは自動的に転送されません。

基盤となる動作については、Bazelの [テストフィルター](https://bazel.build/docs/user-manual#test-filter)、[コマンドオプション](https://bazel.build/reference/command-line-reference)、および [ビルドイベントの説明](https://bazel.build/remote/bep-glossary) を参照してください。
