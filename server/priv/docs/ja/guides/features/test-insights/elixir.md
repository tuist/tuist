# Elixirのテストインサイト {#elixir-test-insights}

TuistのHexパッケージは、各テスト実行後にElixirプロジェクトのテスト結果をアップロードし、Tuistダッシュボード上でテストのパフォーマンスや不安定なテストを可視化します。

> [!IMPORTANT]
> **要件**
>
> - <.localized_link href="/guides/get-started/elixir-project">Elixirでの開始</.localized_link>を完了してください

## テスト実行を報告する {#report-your-test-runs}

共有セットアップによりテスト統合がインストールされます。`mix test` は引き続き同じ引数、出力、終了コードで使用できます：

```bash
mix test test/my_app_test.exs:12 --trace
```

Tuistは実行が完了した時点でレポートを送信するため、追加のテストエイリアスは不要です。

Tuistダッシュボードでテストインサイトにアクセスし、時間経過に伴う変化を確認できます：

![Phoenixアプリケーションのテストダッシュボード](/images/guides/features/elixir/tests-dashboard.png)

## 追跡対象 {#what-is-tracked}

このパッケージはExUnitの結果を収集します。対象には以下が含まれます：
- 個々のテストの合否ステータスと実行時間
- 各テストが属するモジュールおよび `describe` ブロック
- 各失敗のメッセージと場所
- 複数回の実行にわたる不安定なテストの検出
- ブランチとコミット、継続的インテグレーション環境ではプロバイダーと実行情報
- 継続的インテグレーション環境では、チェックアウトの [Git履歴](#git-history)

Doctestは他のテストと同様に報告されます。`--cover` を使用すると、その実行の行カバレッジもアップロードされます：<.localized_link href="/guides/features/test-code-coverage/elixir">Elixirのコードカバレッジ</.localized_link>を参照してください。

> [!NOTE]
> このパッケージは、既存のフォーマッターに加えてExUnitフォーマッターを追加することでレポートを送信します。コマンドラインで `--formatter` を指定すると、Mixがリスト全体を置き換えるため、実行は報告されず、タスクから警告が表示されます。

### Git履歴 {#git-history}

継続的インテグレーション環境では、このパッケージはチェックアウトのコミット履歴（コミットSHA、親コミット、コミット日時、実行およびプルリクエストのベースブランチ）もアップロードします。ファイルの内容、コミットメッセージ、著者はアップロードされません。これにより、Tuistはデフォルトブランチに取り込まれたコミット（例えばマージキューでテストされたもの）を識別できます。パッケージはチェックアウトに既に存在する履歴を読み取り、ベースブランチがない場合はリモートに対して最新のコミットを問い合わせます（`git ls-remote`）。コードカバレッジ（`--cover`）以外の場合、履歴は取得されません。コードカバレッジを使用する場合、ファイルの内容なしで浅いチェックアウトを深化させ、プルリクエストの分岐点を特定し、継続的インテグレーション環境ではTuistが既に保持しているコミットに到達できるようにします。これにより、親コミットのないコミットがアップロードされることはありません。

| 変数 | 効果 |
| --- | --- |
| `TUIST_GIT_UPLOAD_ENABLED=false` | Git履歴の読み取りまたはアップロードを行いません。 |
| `TUIST_GIT_UNSHALLOW_ENABLED=false` | リモートに接続せず、チェックアウトのみを読み取ります。 |

## トラブルシューティング {#troubleshooting}

レポート送信はテストの結果に影響しません：レポートを送信できない場合、実行は通常通り終了し、何も出力されません。レポートが送信されなかった理由を確認するには、`TUIST_DEBUG=1` を設定してください：

```bash
TUIST_DEBUG=1 mix test
```
