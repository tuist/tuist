# Elixirテストのインサイト {#elixir-test-insights}

TuistのHexパッケージは、各テスト実行後にElixirプロジェクトのテスト結果をアップロードし、Tuistダッシュボードでテストのパフォーマンスと不安定なテストを可視化します。

> [!IMPORTANT]
> **要件**
>
> - <.localized_link href="/guides/get-started/elixir-project">Elixirプロジェクトを始める</.localized_link>を完了してください

## テスト実行を報告する {#report-your-test-runs}

共有セットアップによりテスト統合がインストールされます。`mix test`を引き続き使用し、同じ引数、出力、および終了コードを維持します:

```bash
mix test test/my_app_test.exs:12 --trace
```

Tuistは実行が完了するとレポートを送信するため、追加のテストエイリアスは不要です。

Tuistダッシュボードでテストのインサイトにアクセスし、時間経過による変化を確認できます:

![Phoenixアプリケーションのテストダッシュボード](/images/guides/features/elixir/tests-dashboard.png)

## 追跡される情報 {#what-is-tracked}

このパッケージはExUnitの結果を収集し、以下を含みます:
- 個々のテストの合否ステータスと実行時間
- 各テストが属するモジュールと`describe`ブロック
- 各失敗のメッセージと場所
- 複数回の実行にわたる不安定なテストの検出
- ブランチとコミット、およびCI環境ではプロバイダーと実行
- CI環境では、チェックアウトの[Git履歴](#git-history)

Doctestは他のテストと同様に報告されます。`--cover`を使用すると、実行の行カバレッジもアップロードされます:<.localized_link href="/guides/features/test-code-coverage/elixir">Elixirコードカバレッジ</.localized_link>をご覧ください。

> [!NOTE]
> このパッケージは、既存のフォーマッターに加えてExUnitフォーマッターを通じてレポートを送信します。コマンドラインで`--formatter`を指定すると、Mixがリスト全体を置き換えるため、実行は報告されず、タスクから警告が表示されます。

### Git履歴 {#git-history}

CI環境では、パッケージはチェックアウトのコミット履歴（コミットSHA、その親、コミット日時、および実行とそのプルリクエストのベースブランチ）もアップロードします。ファイルの内容、コミットメッセージ、または作者はアップロードされません。これにより、Tuistはデフォルトブランチにマージされたコミット（例えばマージキューでテストされたもの）を識別できます。パッケージはチェックアウトに既に存在する履歴を読み取り、ベースブランチがない場合はリモートに対して最新のコミットを要求します（`git ls-remote`）。コードカバレッジ（`--cover`）以外では、履歴を取得しません。コードカバレッジを使用する場合、ファイルの内容なしで浅いチェックアウトを深くし、プルリクエストの分岐点を見つけ、CI環境ではTuistが既に持っているコミットに到達できるようにするため、親コミットなしでコミットがアップロードされることはありません。

| 変数 | 効果 |
| --- | --- |
| `TUIST_GIT_UPLOAD_ENABLED=false` | Git履歴を読み取ったりアップロードしたりしません。 |
| `TUIST_GIT_UNSHALLOW_ENABLED=false` | リモートに接続せず、チェックアウトのみを読み取ります。 |

## トラブルシューティング {#troubleshooting}

レポート送信はテストの結果を変更しません。レポートを送信できない場合、実行は通常通り終了し、何も出力されません。レポートが送信されなかった理由を確認するには、`TUIST_DEBUG=1`を設定してください:

```bash
TUIST_DEBUG=1 mix test
```
