# Elixirテストのインサイト {#elixir-test-insights}

TuistのHexパッケージは、各テスト実行後にElixirプロジェクトのテスト結果をアップロードし、Tuistダッシュボードでテストのパフォーマンスと不安定なテストを可視化します。

> [!IMPORTANT]
> **要件**
>
> - <.localized_link href="/guides/get-started/elixir-project">Elixirプロジェクトを始めよう</.localized_link>を完了する

## テスト実行を報告する {#report-your-test-runs}

共有セットアップによりテスト統合がインストールされます。`mix test`を引き続き使用でき、引数、出力、終了コードは同じです：

```bash
mix test test/my_app_test.exs:12 --trace
```

Tuistは実行が完了した時点でレポートを送信するため、追加のテストエイリアスは不要です。

Tuistダッシュボードでテストのインサイトにアクセスし、時間経過に伴う変化を確認できます：

![Phoenixアプリケーションのテストダッシュボード](/images/guides/features/elixir/tests-dashboard.png)

## 収集される情報 {#what-is-tracked}

このパッケージはExUnitの結果を収集します。対象には以下が含まれます：
- 個々のテストの合否ステータスと実行時間
- 各テストが属するモジュールおよび`describe`ブロック
- 各失敗のメッセージと発生箇所
- 複数回の実行にわたる不安定なテストの検出
- ブランチとコミット、継続的インテグレーションではプロバイダーと実行
- 継続的インテグレーションでは、チェックアウトの[Git履歴](#git-history)

Doctestも他のテストと同様に報告されます。`--cover`を使用すると、実行の行カバレッジもアップロードされます：<.localized_link href="/guides/features/test-code-coverage/elixir">Elixirコードカバレッジ</.localized_link>をご覧ください。

> [!NOTE]
> このパッケージは、既存のフォーマッターに加えてExUnitフォーマッターを追加してレポートを送信します。コマンドラインで`--formatter`を指定すると、Mixはリスト全体を置き換えるため、実行は報告されず、タスクから警告が表示されます。

### Git履歴 {#git-history}

継続的インテグレーションでは、このパッケージはチェックアウトのコミット履歴（コミットSHA、親コミット、コミット日時、実行およびそのプルリクエストのベースブランチ）もアップロードします。ファイルの内容、コミットメッセージ、著者はアップロードされません。これにより、Tuistはデフォルトブランチにマージされたコミット（例えばマージキューでテストされたコミット）を識別できます。パッケージはチェックアウトに既に存在する履歴を読み取り、ベースブランチがない場合はリモートに対して最新のコミットを問い合わせます（`git ls-remote`）。コードカバレッジ（`--cover`）以外では、履歴を取得しません。コードカバレッジ有効時には、ファイルの内容なしで浅いチェックアウトを深化させ、プルリクエストの分岐点を特定し、継続的インテグレーションではTuistが既に保持するコミットに到達できるようにします。これにより、親コミットのないコミットがアップロードされることはありません。

| 変数 | 効果 |
| --- | --- |
| `TUIST_GIT_UPLOAD_ENABLED=false` | Git履歴の読み取りやアップロードを行いません。 |
| `TUIST_GIT_UNSHALLOW_ENABLED=false` | リモートに接続せず、チェックアウトのみを読み取ります。 |

## トラブルシューティング {#troubleshooting}

レポート送信はテストの結果を変更しません。レポートを送信できない場合、実行は通常通り終了し、何も出力されません。レポートが送信されなかった理由を確認するには、`TUIST_DEBUG=1`を設定してください：

```bash
TUIST_DEBUG=1 mix test
```
