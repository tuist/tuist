# Struo テストインサイト {#struo-test-insights}

<a id="once-test-insights"></a>

Struo はテスト結果を Tuist に報告するため、ローカルおよび CI での実行全体を追跡し、失敗を調査し、個々のワーカーからレポートを集めることなく遅いテストを見つけられます。

> [!IMPORTANT]
> **要件**
>
> - <.localized_link href="/guides/get-started/struo-project">Struo を使い始める</.localized_link>を完了してください。
> - 構造化された結果を報告するテストターゲットを使用してください。利用可能な詳細は、ターゲットの種類とテストランナーによって異なります。

## テスト実行を報告する {#report-your-test-runs}

スイート全体を実行するか、ターゲットを選択してください:

```bash
struo test
struo test MyTests
```

Struo はネイティブなテストイベントをストリーミングし、完了した結果を Tuist の共有テストモデルに公開します。**テスト**および**テスト実行**で実行を表示でき、個々のケースにも共有されたテスト履歴があります。<.localized_link href="/guides/features/test-sharding/struo">ホスト型シャーディング実行</.localized_link>では、診断イベントストリームを再度カウントするのではなく、ワーカーごとに 1 つのレポートを結合された実行として公開します。

## 追跡対象 {#what-is-tracked}

- 報告されたテストターゲット、スイート、および個々のケース。
- 合格、不合格、スキップされた結果。ランナーが提供する場合、所要時間も含まれます。
- ホスト型シャーディングレポートでランナーが提供する失敗メッセージ。
- テストが失敗して後で合格した場合の、順序付けられた再試行回数と不安定な結果。
- Struo が提供するブランチ、コミット、および CI コンテキスト。

テストの識別には、ネイティブなターゲット、スイート、およびケース名を使用します。シャーディングバッチ ID はスケジューリング単位であり、テスト名ではありません。

通常の `struo test` レポートは結果と再試行回数を保持しますが、現在、共有テスト履歴には失敗メッセージが含まれていません。ホスト型シャーディングレポートには失敗メッセージを含めることができますが、どちらの報告パスもソース位置を提供しません。Tuist で利用できない診断情報のために、CI ログを保存してください。

すべてのテストターゲットが同じ詳細を提供するわけではありません。一部のランナーは個々のケースを報告し、他のランナーは概要のみを報告します。正確なファイルまたはケースの実行は別の機能です。ケースごとの分析や細かなスケジューリングに依存する前に、[Struo のテストエコシステムカバレッジ](https://struo.run/docs/guide/graph/testing#understand-current-ecosystem-coverage)を確認してください。

## 不安定なテスト {#flaky-tests}

Tuist は報告された試行回数と CI 履歴を使用して、一貫性のない結果を特定します。試行を報告することは再試行を有効にすることと同じではありません。再試行をサポートするランナーで再試行を設定してください。検出と現在の隔離境界については、<.localized_link href="/guides/features/test-insights/flaky-tests/struo">Struo の不安定なテスト</.localized_link>を参照してください。

## 選択とコードカバレッジ {#selection-and-code-coverage}

Struo は `--changed-path` を使用して、ローカルグラフから保守的にテストを選択できます。これは Struo 独自の選択であり、Tuist のホスト型カバレッジベースのテスト選択ではありません:

```bash
struo test --changed-path src/library.rs
```

ネイティブな Struo レポートは現在、コードカバレッジを Tuist にアップロードしません。成功したテストレポートやシャードプランは、コードカバレッジダッシュボードに入力されません。

## トラブルシューティング {#troubleshooting}

実行が見つからない場合は、有効なキャッシュプロバイダーが Tuist プロジェクトを指していることを確認し、`struo auth login --provider tuist` で再度認証してください。ライブレポートはベストエフォート型であり、レポートサービスが利用できない場合でも、それ以外では成功しているテストコマンドを失敗に変えることはありません。

実行の概要と構造化されたテスト失敗は、完全なプロセスログではありません。このサーバーは現在、Struo の生アクションログストリームを取り込んでいません。構造化された結果に含まれない出力については、CI ログを保存してください。
