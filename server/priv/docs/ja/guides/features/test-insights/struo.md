# Struo テストインサイト {#struo-test-insights}

<a id="once-test-insights"></a>

Struo はテスト結果を Tuist に報告するため、個々のワーカーからレポートを集めなくても、ローカルおよび CI での実行全体を追跡し、失敗を調査し、遅いテストを見つけることができます。

> [!IMPORTANT]
> **要件**
>
> - <.localized_link href="/guides/get-started/struo-project">Struo を使い始める</.localized_link>を完了してください。
> - 構造化された結果を報告するテストターゲットを使用してください。利用可能な詳細は、ターゲットの種類とテストランナーによって異なります。

## テスト実行を報告する {#report-your-test-runs}

スイート全体を実行するか、ターゲットを選択します:

```bash
struo test
struo test MyTests
```

Struo はネイティブのテストイベントをストリーミングし、完了した結果を Tuist の共有テストモデルに公開します。**Tests** と **Test Runs** に実行が表示され、個々のケースにも共有テスト履歴があります。<.localized_link href="/guides/features/test-sharding/struo">ホスト型シャーディング実行</.localized_link> では、診断イベントストリームを再度カウントするのではなく、ワーカーごとに 1 つのレポートを組み合わせた実行に公開します。

## 追跡対象 {#what-is-tracked}

- 報告されたテストターゲット、スイート、および個々のケース。
- 合格、不合格、スキップされた結果。ランナーから提供される場合は所要時間も含まれます。
- ホスト型シャーディングレポートでランナーから提供される失敗メッセージ。
- テストが失敗して後で合格した場合の、順序付けられた再試行回数と不安定な結果。
- Struo から提供されるブランチ、コミット、および CI コンテキスト。

テストの識別には、ネイティブのターゲット名、スイート名、およびケース名が使用されます。シャーディングバッチ ID はスケジュール単位であり、テスト名ではありません。

通常の `struo test` レポートは結果と再試行回数を保持しますが、現在、共有テスト履歴には失敗メッセージが含まれていません。ホスト型シャーディングレポートには失敗メッセージを含めることができますが、いずれの報告経路もソース位置を提供しません。Tuist で利用できない診断情報については、CI ログを保持してください。

すべてのテストターゲットが同じ詳細を提供するわけではありません。一部のランナーは個々のケースを報告し、他のランナーはサマリーのみを報告します。正確なファイルまたはケースの実行は別の機能です。ケースごとの分析やきめ細かいスケジューリングをあてにする前に、[Struo のテストエコシステムカバレッジ](https://struo.run/docs/guide/graph/testing#understand-current-ecosystem-coverage)を確認してください。

## 不安定なテスト {#flaky-tests}

Tuist は報告された試行回数と CI 履歴を使用して、一貫性のない結果を特定します。試行を報告することは再試行を有効にすることとは異なります。再試行をサポートするランナーで再試行を設定してください。検出と現在の隔離境界については、<.localized_link href="/guides/features/test-insights/flaky-tests/struo">Struo の不安定なテスト</.localized_link>を参照してください。

## 選択とコードカバレッジ {#selection-and-code-coverage}

Struo は `--changed-path` を使用して、ローカルグラフから保守的にテストを選択できます。これは Struo 独自の選択であり、Tuist のホスト型カバレッジベースのテスト選択ではありません:

```bash
struo test --changed-path src/library.rs
```

ネイティブの Struo レポートは現在、コードカバレッジを Tuist にアップロードしません。成功したテストレポートやシャードプランでも、コードカバレッジダッシュボードにはデータが入力されません。

## トラブルシューティング {#troubleshooting}

実行が見つからない場合は、有効なキャッシュプロバイダーがあなたの Tuist プロジェクトを指していることを確認し、`struo auth login --provider tuist` で再度認証してください。ライブレポートはベストエフォート型であり、レポートサービスが利用できない場合でも、それ以外では成功しているテストコマンドを失敗に変えることはありません。

実行サマリーと構造化されたテスト失敗は、完全なプロセスログではありません。このサーバーは現在、Struo の生のアクションログストリームを取り込んでいません。構造化された結果に含まれない出力については、CI ログを保持してください。
