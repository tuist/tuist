# スナップショット {#snapshots}

> [!IMPORTANT]
> **招待制**
>
> スナップショットは現在、招待制です。アカウントへのアクセスをリクエストするには、[お問い合わせ](mailto:contact@tuist.dev)いただくか、[コミュニティ Slack](https://slack.tuist.dev) までご連絡ください。

スナップショットテストは UI を画像としてレンダリングし、参照画像と比較して視覚的な回帰を検出します。これらの参照画像をリポジトリにコミットする代わりに、各テスト実行でレンダリングされた画像を Tuist にアップロードします。Tuist はそれらを**ベースライン**と比較し、ダッシュボードで変更箇所を表示し、誰かが変更を承認するまで実行を失敗させます。

- Git に参照画像が含まれないため、チェックアウトのサイズが小さく保たれ、PNG ファイルでのコンフリクト解消も不要になります。
- レビュアーはコードの隣で変更を確認できます。並列表示、差分表示、ワイプまたはオニオンスキンオーバーレイによる表示が可能です。
- 変更はダッシュボードまたはプルリクエスト上で承認または拒否され、ブランチがマージされるとその承認が新しいベースラインとなります。

## 仕組み {#how-it-works}

1. テストは、たとえばすべての SwiftUI または Compose プレビューの画像をレンダリングします。
2. Tuist CLI または Gradle プラグインは、それらを現在のコミットの**スナップショットビルド**としてアップロードします。
3. Tuist がベースラインを選択します。これは、ブランチの起点となったコミットにおけるデフォルトブランチのビルドです。
4. 各画像はベースラインと比較され、変更あり、追加、削除、または変更なしとしてマークされます。
5. ビルドには次の判定が下されます。

| 判定 | 実行 | 条件 |
| --- | --- | --- |
| ベースライン | 合格 | ビルドがデフォルトブランチからのものであるため、以降のビルドはこれと比較されます。 |
| 合格 | 合格 | 画像の変更または削除がありません。新しい画像にはレビューは不要です。 |
| レビューが必要 | 不合格 | 画像が変更または削除されており、まだ誰もレビューしていません。 |
| 承認済み | 合格 | 誰かが変更を承認しました。 |
| 拒否済み | 不合格 | 誰かが変更を拒否しました。 |

ビルドは **セット** 内で比較されます。例えば `ios-iphone` や `android-phone` です。デバイス構成ごとに 1 つのセットを使用し、異なるサイズでレンダリングされた画像同士が比較されないようにしてください。

## ダッシュボードで変更をレビュー {#dashboard}

すべてのスナップショットビルドには、プロジェクトのダッシュボードにある**テスト → スナップショット**の下にページがあります。そこにはビルドの判定、ブランチ、コミット、プルリクエスト、ベースラインが表示され、画像はステータスとグループ別に一覧表示されます。**変更を承認**または**変更を拒否**を使用してビルドをレビューしてください。レビューは後から変更できます。

![レビューが必要なスナップショットビルド。変更された画像がベースラインと並べて表示されています](/images/guides/features/snapshots/review.png)

**サイドバイサイド**、変更されたピクセルを強調表示する**差分**、ベースラインと新しい画像の間をスライドさせる**ワイプ**、そして一方を他方にフェードインさせる**オニオン**を切り替えることができます。各画像は全画面で開くことができます。

![ベースラインと新しい画像の間をスライドさせるワイプモード](/images/guides/features/snapshots/wipe.png)

## プルリクエストで変更をレビュー {#pull-request}

<.localized_link href="/guides/integrations/gitforge/github">GitHub アプリ</.localized_link>がインストールされている場合、プルリクエストのすべてのスナップショットビルドには`tuist/snapshots (<set>)`という名前のチェックが付きます。変更のレビューが必要な間、またはレビュアーが変更を拒否した後は、そのチェックは不合格となり、必須であればマージをブロックします。

![変更が拒否されたためスナップショットチェックが不合格となっている、プルリクエストのマージボックス](/images/guides/features/snapshots/github-pr-checks.png)

そのチェックはセット内の変更、追加、削除された画像の数をカウントし、ダッシュボード内のビルドへのリンクを提供します。GitHub から離れることなく、チェックのページから変更を承認または拒否できます。チェックはレビュアーの名前で更新され、拒否されたビルドも後から承認できます。

![変更が拒否された後の GitHub 上のスナップショットチェック。承認ボタンが表示されています](/images/guides/features/snapshots/github-check-run.png)

承認してもテストは再実行されません。チェックが合格になります。同じブランチの後続のビルドは、まったく同じ変更である限り承認状態を維持するため、CI を再実行したり、レビュー対象の画像に触れないコミットをプッシュしたりしても合格します。画像に対するその他の変更には新しいレビューが必要です。ブランチがマージされると、デフォルトブランチのビルドが新しいベースラインとなります。
