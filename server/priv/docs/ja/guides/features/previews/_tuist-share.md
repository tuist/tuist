## tuist share でのトラック {#share-tracks}

`tuist share` で公開するワークフローでは、`--track` を使ってトラックを選択します:

```bash
tuist share App --track beta
tuist share App --track nightly
```

## リリースノート {#release-notes}

環境グループにはトラックを、個別のビルドの目的にはリリースノートを使用します:

```bash
tuist share App --track QA --release-notes "Fix sign-in and improve the checkout flow"
```

`App` をアプリ名、アプリケーションファイルのパス、または実行可能配布物とその `--executable` オプションに置き換えます。リリースノートは任意のプレーンテキストで、最大 10,000 文字です。最初の空白でない行がプレビュー一覧で一行スニペットとして表示されるため、ビルド番号やその他の識別情報が一目で確認できます。長い行は切り詰められ、詳細ページに全文が表示されます。検索は表示名と完全なリリースノートに一致し、スニペットに表示されていない行も対象になります。複数行のノートもサポートされており、例えば `--release-notes "$(< release-notes.txt)"` のように指定できます。これらはアプリの表示名やトラックを変更しません。

### 互換性 {#preview-metadata-compatibility}

リリースノートは追加メタデータであり、プレビューの識別情報には含まれません。新旧のクライアントからのアップロードは、プラットフォームをまたいで同じプレビューにグループ化されます。最初の空白でないノートが保持されます。後続のアップロードで以前欠けていたノートを埋めることはできますが、既存のノートを上書きすることはできません。`release_notes` を省略したり、`null` を送信したり、空または空白のみの文字列を送信しても、ノートはクリアされません。既存のプレビューにはバックフィルが行われず、ノートなしでも有効です。

リスト API のオプションの `track` クエリパラメータは、大文字小文字を区別せずにトラック名全体と一致し、既存のトラックストレージと整合しています。これを省略するか空の値 (`?track=`) を送信すると、すべてのトラックが一覧表示されます。トラック名は固定された値のリストではなく、自由な文字列のままです。`GET /api/projects/:account_handle/:project_handle/previews/tracks` は、ビルドの一覧と同じプレビュー読み取り権限の下で、ソートされ大文字小文字を区別せずにグループ化された名前付きトラックを含む `{total_count, tracks: [{name, count}]}` を返します。カウントはページネーション、検索、選択されたトラックとは独立してプロジェクト全体を対象とし、合計には未追跡のプレビューも含まれます。バンドル識別子を持つ一覧可能なプレビューのみがカウントされます。リスト API は、表示名または完全なリリースノートのリテラルで大文字小文字を区別しない部分文字列に対するオプションの `search` も受け付け、ページネーションの前にトラックと組み合わされます。既存の `display_name` フィルタリングは引き続き完全一致です。

古いクライアントは、いずれのフィールドも送信せずにプレビューのアップロードと一覧取得を継続できます。新しいクライアントは、トラックやノートを省略した古いレスポンスを受け入れ、将来のサーバーによって追加された不明なレスポンスプロパティを無視します。API 統合でも同様に不明なレスポンスプロパティを無視し、追加メタデータの互換性を維持する必要があります。

セルフホストデプロイメントでこれらの機能を使用するには、リリースノートとトラックフィルタリングをサポートするサーバーバージョンと、更新されたクライアントが必要です。古いサーバーはノートや不明なクエリパラメータを無視する場合があります。

## プル/マージリクエストのコメント {#pullmerge-request-comments}

> [!WARNING]
> **Git プラットフォームとの統合が必要**
>
> プル/マージリクエストへの自動コメントを取得するには、<.localized_link href="/guides/server/accounts-and-projects">リモートプロジェクト</.localized_link> を <.localized_link href="/guides/server/authentication">Git プラットフォーム</.localized_link> と統合してください。

Tuist プロジェクトが Git プラットフォームと接続されたら、CI でのアプリケーションビルド成功後に <.localized_link href="/cli/share">`tuist share`</.localized_link> を追加します。Tuist はプル/マージリクエストに直接プレビューリンクを投稿するため、レビュアーはローカルでビルドせずにテストできます:

## 自動化 {#automations}

`--json` を使用して `tuist share` から JSON 出力を取得します:

```bash
tuist share --json
```

結果をカスタム自動化に使用します。例えば、CI から Slack メッセージを投稿するなどです。`url` キーには完全なプレビューリンクが含まれ、`qrCodeURL` はデバイスでプレビューを開くための QR コード画像を指します:

```json
{
  "id": 1234567890,
  "url": "https://cloud.tuist.io/preview/1234567890",
  "qrCodeURL": "https://cloud.tuist.io/preview/1234567890/qr-code.svg"
}
```
