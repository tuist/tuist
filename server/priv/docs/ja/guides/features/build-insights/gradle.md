# Gradleビルドインサイト {#gradle-build-insights}

TuistのGradleプラグインはビルド分析をTuistに送信でき、タスクの実行状況とビルドパフォーマンスを可視化します。

## アップロード動作の設定 {#configure-upload-behavior}

デフォルトでは:
- ローカルビルドの場合、ビルド分析はバックグラウンドでアップロードされます。
- CI実行の場合、短期間のエージェントでテレメトリが失われるのを防ぐため、ビルド分析はフォアグラウンドでアップロードされます。

`tuist`拡張機能内の`uploadInBackground`を使用して、この動作を制御できます:

```kotlin
tuist {
    uploadInBackground = false // always upload in the foreground
}
```

## 設定リファレンス {#configuration-reference}

`uploadInBackground`オプションは、`settings.gradle.kts`内の`tuist`拡張ブロックで使用できます:

| オプション | 型 | デフォルト | 説明 |
| --- | --- | --- | --- |
| `uploadInBackground` | `Boolean?` | `null`（ローカルではバックグラウンド、CIではフォアグラウンド） | ローカルビルドのビルドインサイトをバックグラウンドでアップロードするかどうか。 |

この設定は、`buildCache`ブロック内のリモートキャッシュ設定に影響しません。

## レポートアクター情報の付与 {#report-actor-claim}

ビルドおよびテストレポートのリクエストには、`TUIST_ACTOR_ID`を組織スコープのラベルに明示的に設定するか、設定で`buildInsights.actorId`を構成した場合のみ、オプションの`x-tuist-actor-id`ヘッダーが含まれます。デフォルトではラベルは送信されず、プラグインはオペレーティングシステムのユーザー名を検出しません。環境変数による上書きが優先されます。報告される識別子を省略するには、いずれかの上書きを空の文字列に設定してください。これにより、個々の認証情報によって確立された識別情報が削除されるわけではありません。無効な上書きは、フォールバックではなく付与情報を省略します。カスタムプロキシが不明なヘッダーを拒否する場合、`TUIST_ACTOR_ID=""`でオプトアウトしてください。

```kotlin
tuist {
    buildInsights {
        actorId = providers.environmentVariable("CORPORATE_ACTOR_ID").getOrElse("")
    }
}
```

アクター識別子は、スペース以外の印刷可能ASCII文字で1〜128バイトです。プロジェクトのレポートを表示できるすべての人（プロジェクトが公開されている場合は一般の閲覧者を含む）に表示され、レポートとともにエクスポートされます。公開したくない機密情報や個人情報は含めないでください。ダッシュボードでは、検証済みの個別認証情報が優先されます。それ以外の場合、クライアントから送信された識別子は明示的に**未検証**として扱われます。これらは権限を付与したり、Tuistユーザーに自動的にリンクしたりすることはありません。古いサーバーはこの属性ヘッダーを無視し、新しいサーバーはこれを含まない古いクライアントを引き続き受け入れます。識別子のない新しい共有トークンレポートは、公開組織ではなく**不明**として表示されます。過去のレポートは以前の属性情報を保持します。ビルドおよびテストの一覧では、検証済みユーザーのフィルターと未検証の報告識別子のフィルターが区別されています。

## ネットワーク信頼による公開 {#network-trusted-publishing}

セルフホスト型のデプロイメントでは、開発者の認証情報なしで、信頼されたネットワークからのGradleビルドおよびテストレポートを明示的に許可できます。オペレーターはまずインスタンスで`TUIST_NETWORK_TRUSTED_INSIGHTS_ACCESS=true`を設定し、再起動する必要があります。これはサポートされているすべてのプロジェクトに適用され、ダッシュボードの設定項目はありません。<.localized_link href="/guides/server/self-host/server#network-trusted-access">セルフホスティングガイド</.localized_link>を参照してください。

リポジトリ内で宛先を一度設定します:

```kotlin
tuist {
    project = "organization/project"
    url = "https://tuist.internal.example"
    buildCache { enabled = false }
}
```

ビルドおよびテストのレポートには、認証済みキャッシュエンドポイントの検出は必要ありません。インスタンスが別途ネットワーク信頼によるキャッシュアクセスを有効にしている場合、または開発者がトークンを準備している場合を除き、キャッシュを無効にしてください。署名されていないテストレポートは、シャードおよび既存ビルドの参照を省略し、隔離や不安定さの自動化をトリガーしません。認証情報が実際に存在しない場合、隔離の検索はスキップされます。有効な認証情報がある場合、既存の認証済み動作が維持されます。認証情報が存在する場合、それらが使用され、無効な認証情報は資格情報なしでの公開へのフォールバックではなく失敗します。認証情報がない場合、プラグインはセルフホスト型サーバーが資格情報なしでのレポートを許可しているかどうかを自動的に検出します。クライアントフラグや`buildInsights`設定は必要ありません。資格情報なしのクライアントをアップグレードする前に、すべてのサーバーレプリカを検出対応バージョンにアップグレードしてください。検出機能のない古いサーバー、無効化されたインスタンス、および検出エラーが発生した場合は引き続き認証が必要であり、認証済み公開は互換性を保ちます。明示的に空の`TUIST_TOKEN`は、資格情報なしでの公開を有効にするのではなく、安全側に倒れて失敗します。シークレットのないフォークまたはDependabotジョブの場合は、その変数を空の文字列として定義するのではなく、削除してください。

サーバーは資格情報なしのレポートIDを割り当てます。送信を繰り返すと2番目のレポートが作成される可能性があります。このモードは冪等な再試行や認証済みテストレポートとの相関を保証しません。このようなレポートはVCSコメントや自動的な失敗エージェントイベントをトリガーできません。ネットワークアクセスは公開の信頼境界であり、報告されたアクターの身元の証明ではありません。

## カスタムメタデータ {#custom-metadata}

異なるチーム、ハードウェア、またはワークフローからの実行を比較するため、Gradleビルドにタグとキーバリューデータを付加します。タグはダッシュボードのフィルターとして利用でき、値は各ビルドの詳細ページ、アプリケーションプログラミングインターフェース、およびModel Context Protocolツールに表示されます。

環境変数でメタデータを設定します:

```sh
export TUIST_BUILD_TAGS="nightly,android"
export TUIST_BUILD_VALUE_TICKET="TUIST-123"
export TUIST_BUILD_VALUE_RUNNER="macos-14"
```

`settings.gradle.kts`でメタデータを構成することもできます:

```kotlin
tuist {
    buildInsights {
        tag("nightly")
        tag("android")
        value("ticket", "TUIST-123")
        value("runner", "macos-14")
    }
}
```

両方の場所で同じ値が構成されている場合、`settings.gradle.kts`の値が優先されます。

タグには文字、数字、ハイフン、アンダースコアのみを使用できます。ビルドには最大50個のタグを付けることができ、各タグは最大50文字まで含めることができます。ビルドには最大20個のキーバリューエントリを付けることができ、各キーは最大50文字、各値は最大500文字まで含めることができます。これらはXcodeビルドメタデータで使用されるのと同じサーバー側の制限です。プラグインはレポートを送信する前に、無効なタグおよびサイズ超過または空のメタデータエントリをスキップするため、無効な構成でもビルドインサイトレポートの残りが保存されないことはありません。タグの制約を満たさない値には、キーバリューメタデータを使用してください。

カスタムメタデータは、ダッシュボード、アプリケーションプログラミングインターフェース、およびModel Context Protocolツールを通じてプロジェクトメンバーに表示されます。認証情報、アクセストークン、その他の機密データには使用しないでください。Tuistはこのメタデータを含むGradleビルドデータを90日間保持します。詳細については、<.localized_link href="/guides/server/data-retention">データ保持ポリシー</.localized_link>を参照してください。
