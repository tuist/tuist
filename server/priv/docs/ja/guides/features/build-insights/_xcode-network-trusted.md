## プライベートネットワークでの認証不要なレポート {#network-trusted-publishing}

セルフホスト環境では、開発者がサインインせずに完了したレポートを公開できます。オペレーターはインスタンスで `TUIST_NETWORK_TRUSTED_INSIGHTS_ACCESS=true` を設定し、<.localized_link href="/guides/server/self-host/server#network-trusted-access">セルフホスティングガイド</.localized_link> に記載されている手順で再起動する必要があります。これはサポートされているすべてのプロジェクトに適用され、ダッシュボードの設定項目はありません。スキームのポストアクションやターミナルで使用される環境変数で、セルフホストURLとプロジェクトを設定してください。CLIは認証情報がない場合、自動的にインスタンスのポリシーを検出します:

```sh
export TUIST_URL="https://tuist.internal.example"
tuist inspect build
# To publish local test results:
tuist inspect test
```

認証情報が実際に存在しない場合、アクティビティログとXCResultバンドルはローカルで解析され、構造化されたレポートとして送信されます。生のアーカイブ、添付ファイル、カバレッジ/履歴のアップロード、リモートプロセッサ、シャード参照、選択的実行の証拠は一切送信されません。レポートは引き続き表示可能ですが、認証されたテストケースの状態を更新したり、隔離/失敗の自動化をトリガーすることはできません。ダッシュボードやその他の特権コマンドには依然としてサインインが必要です。インスタンスが別途ネットワーク信頼キャッシュアクセスを有効にしているか、認証情報が用意されていない限り、キャッシュ統合は無効のままにしてください。

既存の認証情報は認証済み状態を維持します。無効、破損、空欄、または更新拒否された認証情報はフェイルクローズとなりディスク上に残るため、後続のコマンドが暗黙的に未署名状態になることはありません。回復措置として、再度サインインするか明示的にサインアウトしてください。認証不要クライアントをアップグレードする前に、すべてのサーバーレプリカをディスカバリー対応バージョンにアップグレードし、リダイレクトのない最終的なサーバーURLを設定してください。ディスカバリー機能のない古いサーバー、無効化されたインスタンス、およびディスカバリー失敗時は依然として認証が必要です。クライアント側のオプトインは不要です。`TUIST_ACTOR_ID=""` を個別に設定して構成済みのアクター要求を省略できます。検証済みの認証情報のIDには影響しません。
