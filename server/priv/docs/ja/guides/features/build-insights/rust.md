# Rust ビルドインサイト {#rust-build-insights}

ビルドインサイトは、Cargo ビルドのボトルネックを特定し、チーム全体に影響が出る前に回帰を検出するのに役立ちます。ローカルビルドと CI を比較してビルド時間の変化を確認したり、各ビルドでコンパイルされたクレートを検査したりできます。

> [!IMPORTANT] Requirements
> - <.localized_link href="/guides/get-started/rust-project">Rust プロジェクトのセットアップ</.localized_link>に従って、プロジェクトを接続し認証を行ってください。

## ビルドを報告する {#report-your-builds}

Tuist を介して通常の Cargo コマンドを実行します:

```sh
tuist cargo build --workspace
tuist cargo check --all-targets
tuist cargo +nightly build --features tracing
```

mise を使用している場合は、<.localized_link href="/guides/get-started/rust-project#keep-typing-cargo">Cargo ラッパーを設定</.localized_link>して、通常の `cargo` コマンドを引き続き使用できるようにしてください。引数、ツールチェーンの選択、出力、および終了コードはそのまま維持されます。

## ビルドの遅延要因を見つける {#explore-your-builds}

ダッシュボードの **ビルド → ビルド実行** からビルドを開きます。日付、環境、Rust バージョンのフィルターを使用して、類似したビルドを比較します。ビルドとそのキャッシュカウンターは、`tuist build cargo list` および `tuist build cargo show`、`GET /api/projects/{account_handle}/{project_handle}/cargo/builds`、そして `list_cargo_builds` および `get_cargo_build` の <.localized_link href="/guides/features/agentic-coding/mcp">MCP ツール</.localized_link> でも利用可能です。

**概要** では、**コンパイラジョブ** を使用して遅いクレートを見つけます。**期間** または **開始後**（Cargo コマンド開始からの時間）で並べ替えるか、クレート名またはルートソースファイルで検索します。

各行はクレートに対する 1 つの `rustc` 呼び出しであり、複数のソースファイルを含む場合があります。**クレートルート** はそのルートソースファイルを識別します。期間はファイル単独ではなく、コンパイラジョブ全体に対するものです。クレートは、異なるターゲットや構成に応じて複数回表示される場合があります。コンパイラメッセージは **警告** と **エラー** にグループ化されます。

### ビルド間でクレートを追跡する {#crate-history}

段階的なクレート履歴ロールアウトに参加しているプロジェクトでは、**ビルド → クレート** に観測されたクレートとそのコンパイル履歴が表示されます。クレートを開いて、ビルド間での記録された期間と結果を比較し、コンパイルをその Cargo ビルドまで遡ります。同じ在庫情報は、プロジェクト API の `/cargo/crates` および `kind: cargo_crates` を持つ共有 MCP ビルドエンティティツールを通じて利用可能です。

クレートは、記録された正確なルートパス、名前、および種類によってグループ化されます。チェックアウトパスを変更すると履歴が分断される可能性があります。プロファイル、機能、およびターゲットトリプルは区別されません。これは観測されたコンパイラジョブの在庫であり、ワークスペース内のすべてのクレートではありません。キャッシュ済みまたは最新のクレートは、コンパイルサンプルを作成しません。

### ビルドレポートの属性付け {#report-attribution}

認証されたレポートは、個人資格情報の背後にいる個人を識別します。共有資格情報は個人を識別する必要はありません。オプションで、レポート送信マシン上の安定した不透明な識別子に `TUIST_ACTOR_ID` を設定できます。これはデフォルトでオフになっており、未検証の主張として表示され、承認には決して使用されません。古いサーバーはこの主張を無視する場合があります。秘密情報を含まないでください。

## タイミングを読み解く {#timing-boundaries}

ビルド期間は、Cargo コマンド全体にかかった時間です。コンパイラジョブは並列で実行できるため、それらの期間の合計はビルド期間と一致しません。

Cargo は再ビルドが必要なクレートのみをコンパイルします。すでに最新の状態にあるクレートはコンパイラリストに表示されません。Tuist のコンパイルキャッシュを使用すると、復元されたジョブはコンパイラ実行としてではなく、キャッシュ測定値に表示されます。

Tuist はビルドスクリプトを個別に測定したり、ビルドタイムラインを表示したりしません。大規模なビルドでは最初の 500 件のコンパイラジョブが表示され、さらに記録されている場合は通知が表示されます。

## キャッシュ測定値を読み解く {#cache-measurements}

`tuist cargo` には、Tuist CLI で実装された実験的なコンパイルキャッシュが含まれています。セットアップ、Kura を介したリモート読み書き、サポートされているコンパイル、およびトラブルシューティングについては、<.localized_link href="/guides/features/cache/rust">Rust キャッシュガイド</.localized_link> に従ってください。

プロジェクトサイドバーの **Cargo キャッシュ** を開いて、ビルド間のキャッシュヒット率、記録された転送、レイテンシ、およびスループット測定値を追跡します。日付または環境でフィルターをかけ、日次トレンドと個別ビルドのヒット率を切り替えたり、最近のビルドを開いてそのキャッシュアクティビティを検査したりします。キャッシュ測定値のないビルドは、ゼロとしてカウントされるのではなく、利用不可のままとなります。

ビルドの **キャッシュ** タブを開いて、タスクヒット、タスクミス、ヒット率、およびダウンロードおよびアップロードされたバイト数を確認します。このタブは、ビルドがキャッシュデータを報告する場合に表示されます。

- **キャッシュ可能なタスク** は、どのコンパイラおよびビルドスクリプトタスクがキャッシュされた出力を再利用したかを示します。タスクを検索またはフィルターし、キャッシュの読み取り/書き込みレイテンシを検査し、行を展開してその出力を確認します。
- **CAS 出力** は、アーティファクトのダウンロードとアップロード、およびそれらのサイズ、期間、スループットを示します。チャートは完了した転送をカウントします。すでに存在するアーティファクトと失敗した試行はテーブルに残ります。

**ヒット** はキャッシュされた出力が再利用されたことを意味します。**ミス** はタスクが代わりにコンパイルされたことを意味します。ヒットはローカルとリモートに分割されません。CAS 出力は記録されたアーティファクト操作を示します。

詳細な記録が欠落しているか不完全な場合、ページには通知が表示されます。サマリーは依然としてビルド全体をカバーします。回避された推定コンパイラ作業は **経過したビルド時間の節約ではありません**。

> [!WARNING] Experimental compilation cache
> 最初のバージョンは、入力と出力が検証されたレジストリのリーフライブラリのみをキャッシュします。ワークスペースクレート、ビルドスクリプト、手続き型マクロ、他のクレートへの依存関係、増分コンパイル、ネイティブリンク、および実行可能ファイルは通常どおりビルドされます。キャッシュキーは絶対パスを保持するため、異なるチェックアウトパス間での再利用はまだサポートされていません。

### テストを実行するビルド {#builds-that-run-tests}

`tuist cargo test` は、テストを含むコマンド全体の期間を報告します。また、<.localized_link href="/guides/features/test-insights/rust">Rust テストインサイト</.localized_link> を介して、doctest を含む個々のテスト結果も報告します。個々のテスト結果は **テスト** の下に表示され、コマンドの期間はビルドインサイトに表示されます。

## その他のコンパイラツール {#other-compiler-tools}

Tuist は、`RUSTC_WRAPPER`、`CARGO_BUILD_RUSTC_WRAPPER`、または Cargo 構成を通じて構成された既存のコンパイララッパーを保持し、`RUSTC_WORKSPACE_WRAPPER` をそのまま残します。既存のグローバルラッパーがあると、Tuist のキャッシュとコンパイラオブザーバーが無効になります。Tuist は、そのラッパーが実際に rustc を実行したかどうかを確認できません。カスタムワークスペースラッパーも同様に、レポートに含まれるコンパイラジョブが少なくなる可能性があります。

Tuist は rustup を介して Cargo を検出します。カスタムインストールを使用している場合は、`TUIST_CARGO_EXECUTABLE` をその実行可能ファイルのパスに設定してください。直接ツールチェーンパスで Cargo を呼び出すと、mise のラッパーがバイパスされます。Cargo エイリアスは、`build` などの組み込みコマンドを置き換えることはできません。

Cargo のナイトリー `-C` オプションを使用する場合は、代わりにまずワークスペースに移動してください。Tuist は `-C` コマンドを転送しますが、そのビルドタイミングは収集しません。

## トラブルシューティング {#troubleshooting}

ビルドがダッシュボードに表示されない場合は、デバッグ出力を有効にしてレポートが送信されなかった理由を確認してください:

```sh
TUIST_DEBUG=1 tuist cargo build --workspace
```

レポート機能はビルドの結果を変更しません。
