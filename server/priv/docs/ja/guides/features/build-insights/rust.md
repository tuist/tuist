# Rust ビルドインサイト {#rust-build-insights}

ビルドインサイトは、Cargo ビルドのボトルネックを特定し、チーム全体に影響が出る前に回帰を検出するのに役立ちます。ローカルビルドと CI を比較してビルド時間の変化を確認したり、各ビルドでコンパイルされたクレートを検査したりできます。

> [!IMPORTANT]
> **要件**
>
> - プロジェクトの接続と認証を行うには、<.localized_link href="/guides/get-started/rust-project">Rust プロジェクトのセットアップ</.localized_link>に従ってください。

## ビルドを報告する {#report-your-builds}

Tuist を介して通常の Cargo コマンドを実行します。

```sh
tuist cargo build --workspace
tuist cargo check --all-targets
tuist cargo +nightly build --features tracing
```

mise を使用している場合は、通常の `cargo` コマンドを引き続き使用できるように <.localized_link href="/guides/get-started/rust-project#keep-typing-cargo">Cargo のラッパーを設定</.localized_link>してください。引数、ツールチェーンの選択、出力、および終了コードは変わりません。

## ビルドが遅い原因を見つける {#explore-your-builds}

ダッシュボードの **Builds → Build Runs** からビルドを開きます。日付、環境、Rust バージョンのフィルターを使用して、類似したビルドを比較します。ビルドとそのキャッシュカウンターは、`tuist build cargo list` および `tuist build cargo show`、`GET /api/projects/{account_handle}/{project_handle}/cargo/builds`、そして `list_cargo_builds` と `get_cargo_build` の <.localized_link href="/guides/features/agentic-coding/mcp">MCP ツール</.localized_link> からも利用できます。

**概要** で、**コンパイラジョブ** を使用して遅いクレートを見つけます。**Duration** または **Started after**（Cargo コマンド開始からの経過時間）で並べ替えるか、クレート名またはルートソースファイルで検索します。

各行はクレートに対する `rustc` の呼び出し 1 回分であり、複数のソースファイルを含む場合があります。**Crate root** はそのルートソースファイルを識別します。所要時間はファイル単独ではなく、コンパイラジョブ全体に対するものです。クレートは、異なるターゲットや構成のために複数回表示される場合があります。コンパイラのメッセージは **Warnings** と **Errors** にグループ化されます。

### ビルド間でクレートを追跡する {#crate-history}

プロジェクトで利用可能な場合、**Builds → Crates** に観測されたクレートとそのコンパイル履歴が表示されます。クレートを開いて、ビルド間の記録された所要時間と結果を比較し、コンパイルからその Cargo ビルドへとさかのぼります。同じインベントリは、プロジェクト API の `/cargo/crates` および `kind: cargo_crates` を持つ共有 MCP ビルドエンティティツールからも利用できます。

クレートは、記録された正確なルートパス、名前、および種類によってグループ化されます。チェックアウトパスを変更すると履歴が分断される可能性があります。プロファイル、フィーチャー、およびターゲットトリプルは区別されません。これは観測されたコンパイラジョブのインベントリであり、ワークスペース内のすべてのクレートではありません。キャッシュ済みまたは最新のクレートは、コンパイルサンプルを作成しません。

### ビルドレポートの属性 {#report-attribution}

認証されたレポートは、個人用資格情報の背後にいる個人を識別します。共有資格情報は個人を識別する必要はありません。オプションで、レポートを送信するマシン上で `TUIST_ACTOR_ID` を安定した不透明な識別子に設定できます。これはデフォルトでオフになっており、未検証の主張として表示され、認可には決して使用されません。古いサーバーはこの主張を無視する場合があります。シークレットを含めないでください。

## タイミングを読み解く {#timing-boundaries}

ビルドの所要時間は、Cargo コマンド全体にかかった時間です。コンパイラジョブは並列で実行できるため、それらの所要時間の合計はビルドの所要時間と一致しません。

Cargo は再ビルドが必要なクレートのみをコンパイルします。すでに最新のクレートはコンパイラリストに表示されません。Tuist のコンパイルキャッシュを使用する場合、復元されたジョブはコンパイラの実行としてではなく、キャッシュ測定値に表示されます。

Tuist はビルドスクリプトを個別に測定せず、ビルドのタイムラインも表示しません。大規模なビルドでは最初の 500 件のコンパイラジョブが表示され、さらに多くのジョブが記録されている場合はその旨の通知が表示されます。

## キャッシュ測定値を読み解く {#cache-measurements}

`tuist cargo` には、Tuist CLI に実装された実験的なコンパイルキャッシュが含まれています。セットアップ、Kura を介したリモート読み書き、サポートされるコンパイル、およびトラブルシューティングについては、<.localized_link href="/guides/features/cache/rust">Rust キャッシュガイド</.localized_link>に従ってください。

プロジェクトのサイドバーで **Cargo Cache** を開き、ビルド全体のキャッシュヒット率、記録された転送量、レイテンシ、およびスループットの測定値を追跡します。日付または環境でフィルターをかけ、日次トレンドと個別ビルドのヒット率を切り替えたり、最近のビルドを開いてそのキャッシュアクティビティを検査したりできます。キャッシュ測定値のないビルドは、ゼロとしてカウントされるのではなく、利用不可のままとなります。

ビルドの **Cache** タブを開いて、タスクのヒット、タスクのミス、ヒット率、およびダウンロードおよびアップロードされたバイト数を確認します。このタブは、ビルドがキャッシュデータを報告する場合に表示されます。

- **Cacheable Tasks** は、どのコンパイラおよびビルドスクリプトタスクがキャッシュされた出力を再利用したかを示します。タスクを検索またはフィルターし、キャッシュの読み書きレイテンシを検査し、行を展開してその出力を確認します。
- **CAS Outputs** は、アーティファクトのダウンロードとアップロード、それらのサイズ、所要時間、およびスループットを示します。チャートは完了した転送をカウントします。すでに存在するアーティファクトと失敗した試行はテーブルに残ります。

**Hit** は、キャッシュされた出力が再利用されたことを意味します。**Missed** は、タスクが代わりにコンパイルされたことを意味します。ヒットはローカルとリモートに分割されません。CAS Outputs は記録されたアーティファクト操作を示します。

詳細な記録が欠落しているか不完全な場合、ページに通知が表示されます。サマリーは依然としてビルド全体をカバーします。回避された推定コンパイラ作業量は、**節約された経過ビルド時間ではありません**。

増分コンパイルは通常どおりビルドされます。

### テストを実行するビルド {#builds-that-run-tests}

`tuist cargo test` は、テストを含むコマンド全体の所要時間を報告します。また、<.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link> を介して、doctest を含む個々のテスト結果も報告します。個々のテスト結果は **Tests** の下に表示され、コマンドの所要時間はビルドインサイトに表示されます。

## その他のコンパイラツール {#other-compiler-tools}

Tuist は、`RUSTC_WRAPPER`、`CARGO_BUILD_RUSTC_WRAPPER`、または Cargo 構成を通じて構成された既存のコンパイララッパーを保持し、`RUSTC_WORKSPACE_WRAPPER` をそのまま残します。事前に存在するグローバルラッパーがあると、Tuist のキャッシュとコンパイラオブザーバーが無効になります。Tuist は、そのラッパーが実際に rustc を実行したかどうかを確認できません。カスタムワークスペースラッパーも同様に、レポートに含まれるコンパイラジョブが少なくなる可能性があります。

Tuist は rustup を介して Cargo を検出します。カスタムインストールを使用している場合は、`TUIST_CARGO_EXECUTABLE` をその実行ファイルのパスに設定してください。直接ツールチェーンパスで Cargo を呼び出すと、mise のラッパーがバイパスされます。Cargo エイリアスは、`build` などの組み込みコマンドを置き換えることはできません。

Cargo のナイトリー `-C` オプションを使用する場合は、代わりにまずワークスペースに移動してください。Tuist は `-C` コマンドを転送しますが、そのビルドタイミングは収集しません。

## トラブルシューティング {#troubleshooting}

ビルドがダッシュボードに表示されない場合は、デバッグ出力を有効にして、レポートが送信されなかった理由を確認します。

```sh
TUIST_DEBUG=1 tuist cargo build --workspace
```

レポート送信は、ビルドの結果を変更しません。
