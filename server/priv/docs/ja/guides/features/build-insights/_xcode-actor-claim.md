## レポートアクタークレーム {#report-actor-claim}

レポート作成リクエストには、`TUIST_ACTOR_ID` を組織スコープのラベル（例: `TUIST_ACTOR_ID=employee-123 tuist inspect build`）に明示的に設定した場合のみ、オプションの `x-tuist-actor-id` ヘッダーが含まれます。デフォルトではラベルは送信されず、Tuist はオペレーティングシステムのユーザー名を検出しません。`TUIST_ACTOR_ID` が空の場合、報告される識別子は省略されますが、認証情報ベースの検証済み ID は削除されません。識別子は、スペース以外の印刷可能 ASCII で 1〜128 バイトである必要があります。無効なオーバーライドは、フォールバックせずに省略されます。カスタムプロキシが不明なヘッダーを拒否する場合は、空の環境オーバーライドを使用してオプトアウトしてください。

検証済みの個別認証情報が優先されます。それ以外の場合、クライアントから報告された識別子は **未検証** と表示され、権限を付与したり、ユーザーに自動的にリンクしたりすることはありません。識別子は、プロジェクトのレポートを表示できるすべての人（プロジェクトが公開されている場合は公開ビューアーを含む）に表示され、データエクスポートにも含まれるため、機密情報を含めないでください。これは、ビルド、テスト、およびコマンドイベントのレポートに適用されます。古いサーバーはこのオプションのヘッダーを無視し、新しいサーバーはこのヘッダーなしで古いクライアントを受け入れます。識別子のない新しい共有トークンレポートは、公開組織ではなく **不明** と表示されます。履歴レポートは以前の帰属を保持します。ビルドおよびテストの一覧では、検証済みユーザーと未検証の報告識別子を区別します。セルフホストインスタンスが認証情報不要のレポートを明示的に有効にし、クライアントがそのポリシーを検出しない限り、認証は引き続き必要です。

### スキームのポストアクション {#actor-claim-post-actions}

アクタークレームはデフォルトで無効になっています。スキームのポストアクション用に構成するには、シェルエクスポートに頼らず、そのスクリプト内で `TUIST_ACTOR_ID` を設定してください。Dock から起動した Xcode は、`~/.zshrc` の変数を継承しません。Homebrew で構成されたクレームを明示的に抑制するには、次を使用してください。

```sh
export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"
export TUIST_ACTOR_ID=""
tuist inspect build
```

Mise を使用する場合、Mise が環境を読み込んだ後に値をオーバーライドします。

```sh
$HOME/.local/bin/mise x -C "$SRCROOT" -- env TUIST_ACTOR_ID="" tuist inspect build
```

オプトインするには、空の値ではなく明示的なラベルを使用してください。
