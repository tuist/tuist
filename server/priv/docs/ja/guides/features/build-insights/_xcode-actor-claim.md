## レポートのアクタークレーム {#report-actor-claim}

レポート作成リクエストには、`TUIST_ACTOR_ID` を組織スコープのラベル（例: `TUIST_ACTOR_ID=employee-123 tuist inspect build`）に明示的に設定した場合のみ、オプションの `x-tuist-actor-id` ヘッダーが含まれます。デフォルトではラベルは送信されず、Tuist はオペレーティングシステムのユーザー名を検出しません。`TUIST_ACTOR_ID` が空の場合、報告される識別子は省略されますが、認証情報に基づく検証済みIDは削除されません。識別子はスペース以外の印刷可能ASCII文字で1〜128バイトである必要があります。無効なオーバーライドはフォールバックせずに省略されます。カスタムプロキシが不明なヘッダーを拒否する場合は、空の環境変数オーバーライドを使用してオプトアウトしてください。

検証済みの個人用認証情報が優先されます。それ以外の場合、クライアントから報告された識別子は **未検証** として表示され、権限を付与したりユーザーに自動的にリンクしたりすることはありません。識別子はプロジェクトのレポートを表示できるすべての人（プロジェクトが公開されている場合は公開ビューアを含む）に表示され、データエクスポートにも含まれるため、機密情報を含めないでください。これはビルド、テスト、およびコマンドイベントのレポートに適用されます。古いサーバーはこのオプションのヘッダーを無視し、新しいサーバーはこのヘッダーなしで古いクライアントを受け入れます。識別子のない新しい共有トークンレポートは、発行元組織ではなく **不明** と表示されます。過去のレポートは以前の帰属情報を保持します。ビルドおよびテストの一覧では、検証済みユーザーと未検証の報告識別子が区別されます。セルフホストインスタンスが認証情報不要のレポートを明示的に有効にし、クライアントがそのポリシーを検出しない限り、認証は引き続き必要です。

### スキームのポストアクション {#actor-claim-post-actions}

アクタークレームはデフォルトで無効になっています。スキームのポストアクション用に設定するには、シェルのエクスポートに頼らず、そのスクリプト内で `TUIST_ACTOR_ID` を設定してください。Dockから起動したXcodeは、`~/.zshrc` の変数を継承しません。Homebrewを使用して設定済みのクレームを明示的に抑制するには、次を使用します。

```sh
export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"
export TUIST_ACTOR_ID=""
tuist inspect build
```

Miseを使用する場合、Miseが環境を読み込んだ後に値をオーバーライドします。

```sh
$HOME/.local/bin/mise x -C "$SRCROOT" -- env TUIST_ACTOR_ID="" tuist inspect build
```

オプトインするには、空の値ではなく明示的なラベルを使用してください。
