# Gradle のコードカバレッジ {#gradle-code-coverage}

コードカバレッジは、テストが実行したコードの行を示します。Tuist Gradle プラグインは JaCoCo を使ってテストタスクのカバレッジを測定し、各テスト実行時にアップロードします。Tuist はコミット内の複数の実行を集約して 1 つの数値にまとめ、プロジェクト全体、各 Gradle プロジェクト、および各ファイルごとに表示します。ダッシュボードの **Code Coverage** ページでは、コミットごとの数値とブランチごとの推移を確認できます。

> [!IMPORTANT]
> **要件**
>
> - `dev.tuist` Gradle プラグインが適用されていること（詳細は <.localized_link href="/guides/get-started/gradle-project">Get started with a Gradle project</.localized_link> を参照）
> - プロジェクトが Git リポジトリ内にあること：リポジトリ外での実行ではテスト結果はアップロードされますが、カバレッジはアップロードされません

## セットアップ {#setup}

### カバレッジを有効にする {#turn-coverage-on}

`settings.gradle.kts` の `tuist` ブロックでカバレッジを有効にします：

```kotlin
tuist {
    coverage {
        enabled = true
    }
}
```

あるいは、CI ジョブなどの単一の呼び出しに対して環境変数で有効にすることもできます。この設定はどちらの場合でも優先されます：

```sh
TUIST_TEST_COVERAGE=1 ./gradlew test
```

カバレッジの有効・無効に応じてテストタスクのビルドキャッシュエントリは別々になります（[Performance impact](#performance-impact) を参照）。CI とローカルビルドがビルドキャッシュを共有している場合は、設定による制御を推奨します。CI でのみカバレッジを有効にすると、相互にテスト結果を再利用することを防げます。

カバレッジが有効な場合、プラグインはすべての JVM プロジェクトに Gradle の `jacoco` プラグインを適用します。JaCoCo のエージェントは、あなたが手動でプラグインを適用した場合と同様に、プロジェクトのリポジトリから取得されます。すでに JaCoCo を構成しているプロジェクトはその設定を維持し、独自のレポートも引き続き機能します。

プラグインはリポジトリ内のコードのカバレッジのみを報告するため、JaCoCo の対象もそれに限定されます。テストタスクが JaCoCo の `includes` を自ら設定しない限り、エージェントはリポジトリがコンパイルするクラスのパッケージのみを計測対象とします。依存関係にも同じパッケージのクラスが含まれている場合（例えば `android.util.Log` のテスト用スタブなど）、そのパッケージ内で計測されるのはリポジトリのクラスのみです。依存関係、Android フレームワーク、およびテストフレームワークは計測対象外となり、JaCoCo のデータ量とテストタスクのビルドキャッシュエントリを小さく保ちます。

実行のカバレッジが部分的な場合、プラグインは理由を含む警告をログに出力します（例：ビルドがテストを実行しなかったプロジェクト）。ユニットテストのないプロジェクト（テストソースを持たない JVM ライブラリの `test` タスクや、インストゥルメント化されたテストのみを持つ Android ライブラリなど）は、除外されたものとしてカウントされません。

### Android プロジェクト {#android-projects}

プラグインは Android プロジェクトのローカルユニットテスト（例：`testDebugUnitTest`）を計測します。デバイスやエミュレータ上で実行されるインストゥルメント化されたテストは計測されません。

ユニットテストで Robolectric を使用している場合は、Robolectric が読み込むクラスを JaCoCo に含めるよう指示してください。Robolectric は独自のクラスローダーでアプリのクラスを定義するため、JaCoCo はデフォルトでこれらのクラスをスキップし、テストが実行するコードが未カバーとして表示されてしまいます。Android プロジェクトの `build.gradle.kts` で以下を設定します：

```kotlin
pluginManager.withPlugin("jacoco") {
    tasks.withType<Test>().configureEach {
        extensions.configure<JacocoTaskExtension> {
            isIncludeNoLocationClasses = true
            excludes = listOf("jdk.internal.*")
        }
    }
}
```

このブロックはカバレッジが有効な場合にのみ適用されます。これは、プラグインが `jacoco` を適用するのがそのタイミングだからです。

Android のユニットテストはデフォルトで JUnit 4 で実行され、カバレッジは記録されますが [which code each test ran](#per-test-evidence) は記録されません。これを記録するには、JUnit Vintage を介して JUnit Platform 上で実行してください。

### シャード化された実行 {#sharded-runs}

<.localized_link href="/guides/features/test-sharding/gradle">shard your tests</.localized_link> する場合、カバレッジを有効にして実行された各シャードは、自身が実行したテストのカバレッジを報告し、Tuist は 1 つの実行に含まれるシャードを 1 つの数値に統合します。シャードは意図的にスイートの一部を実行するため、コミットのカバレッジが不完全になることはありません。

### CI で各コミットを完了させる {#complete-each-commit}

コミットのカバレッジ情報は、しばしば複数のジョブ（シャードごとに 1 つなど）から提供されます。Tuist は最後のジョブが報告を終えたタイミングを自動検出できないため、明示的に通知する必要があります。コミットに関連するすべてのテストジョブが終了したら、それらすべてに依存するジョブで以下を実行してください：

```sh
./gradlew tuistCoverageComplete
```

単一のジョブでコミットのすべてのテストを実行する場合は、テスト失敗時も含め、テスト実行後のステップとしてタスクを実行してください。テストが失敗した実行でもカバレッジは報告されます。

タスクはチェックアウトの `HEAD`（テストが実行されたコミット）からコミットを読み取ります。別のコミットを指定するには `-Ptuist.coverage.commit=<sha>` を渡してください。コミットが完了するまで、そのカバレッジは **In progress** と表示され、ブランチの推移には含まれません。

## 動作原理 {#how-it-works}

### Tuist が計測するもの {#what-tuist-measures}

- **プロジェクト。** 各 Gradle プロジェクトはダッシュボード上のモジュールとして扱われ、それぞれ独自のカバレッジを持ちます。
- **プロダクトコードのみ。** テストソースセットからコンパイルされたクラスはテストコードです。Tuist はこれらを保存しますが、すべての数値からは除外します。
- **リポジトリ内のファイル。** クラスは、リポジトリ内のパスに基づき、コンパイル元のソースファイルに対応付けられます。生成されたソースや Git が無視するファイルは報告されません。
- **各行の実行有無。** JaCoCo はコードが実行されたかどうかを記録し、実行回数は記録しません。そのため、ダッシュボード上の実行回数は 0 または 1 となります。

### 各テストが実行したコード {#per-test-evidence}

JUnit Platform（JUnit 5、または JUnit Vintage を介した JUnit 4）上で実行されるテストの場合、プラグインは各テストが実行したコードと、テストメソッド外（`@BeforeAll` など）で実行されたコードも記録します。これにより、Tuist は実行から除外されたテストのカバレッジを過去のデータから補完できます（[Skipped tests](#skipped-tests) を参照）。テスト側に追加の設定は不要です。

これは、各テスト用 JVM が一度に 1 つのテストを実行する場合に機能します。JUnit の並列実行を有効にしない限り、Gradle はこの方法でテストを実行します。`maxParallelForks` を使用して複数の JVM でテストクラスを実行しても問題ありません。1 つの JVM 内で同時に実行されるテストもカバレッジには計上されますが、個別のテストごとの記録は行われません。

### ビルドキャッシュ {#build-cache}

ビルドキャッシュから復元されたテストタスク、または最新状態のテストタスクは、テストを実行しません。それでもカバレッジはアップロードされます。JaCoCo のデータはタスクの出力の一つであり、同じ入力に対してテストを実行した実行によって記録されたものです。

### スキップされたテスト {#skipped-tests}

実行からテストが除外された場合、Tuist は実行対象のコードに変更がない限り、以前の実行データからカバレッジを補完します。補完できない場合、コミットのカバレッジは **Incomplete** となります。実行から除外されるパターン：

- **プロジェクトのテストタスクが除外された場合**（`-x :app:test` を使用）。コードに変更がない直近の実行データからカバレッジが引き継がれます。
- **一部のプロジェクトのテスト**（`./gradlew :core:test` を使用）、または **一部のテスト**（`--tests` を使用）。この実行は指定された部分のみをカバーするため、コミットの他の部分を実行する別の実行がない限り、コミットは不完全となります。
- **最初の失敗で停止したテストタスク**（`failFast`）。

意図的に除外されたテストは、コミットを不完全にはしません：

- **ビルドスクリプト内のフィルター**（`filter { excludeTestsMatching(...) }` など）。これらはテストスイートの実行対象を定義します。
- **ビルドスクリプトで無効化されたテストタスク**。`enabled = false` または `onlyIf` によってスキップされます。
- **<.localized_link href="/guides/features/test-insights/flaky-tests/gradle">quarantine</.localized_link> によってスキップされたテスト。** これらは削除されたものとして扱われるため、これらのテストのみがカバーしていた行は未カバーとして計上されます。
- **他のシャードのテスト**。[テストをシャーディング](#sharded-runs)している場合です。

### 完全および不完全なコミット {#commit-status}

| ステータス | 意味 |
| --- | --- |
| 進行中 | 実行からカバレッジが報告されていますが、`tuistCoverageComplete` がまだこのコミットに対して実行されていません。 |
| 完了 | コミットの実行に含まれるすべてのテストが実行されたか、引き継がれたか、意図的に除外されました。 |
| 不完全 | 一部のカバレッジを特定できなかったため、数値は下限となります。 |
| 未測定 | このコミットに対してカバレッジを報告した実行がありません。 |

ブランチのトレンドには、完了したコミットのみが含まれます。

## パフォーマンスへの影響 {#performance-impact}

JaCoCo はテスト用 JVM がクラスをロードする際にインストルメンテーションを行うため、コンパイル済みクラスやコンパイルタスクのビルドキャッシュエントリは、カバレッジの有無にかかわらず同じままです。SBOM ジェネレーターなど、すべての依存関係設定を読み取るタスクも JaCoCo エージェントの影響を受けるため、カバレッジを有効にすると出力が変化します。テストの実行速度はわずかに低下し、プラグインはテストタスクの終了後に JaCoCo のデータを読み取ります。カバレッジの有無でビルドキャッシュエントリは別になるため、カバレッジなしの結果がキャッシュされている場合でも、カバレッジありでの初回実行ではテストが実行されます。

## 制限事項 {#limitations}

- **Isolated Projects および configuration on demand。** これらのビルドではすべてのプロジェクトが構成されないため、プラグインは実行からどのプロジェクトのテストが除外されたかを判別できず、一部のプロジェクトのテストのみを実行した場合でも完了として扱われます。
- **フォークからのプルリクエストからはカバレッジを取得できません。** カバレッジは Tuist で認証された実行によってのみアップロードされ、CI は通常、フォークから開かれたプルリクエストに対してシークレットや ID トークンを提供しません。

## カバレッジのクエリ {#querying}

ダッシュボードの **Code Coverage** ページには、各コミットの数値、モジュール、ファイル、および各実行でカバーされた行が表示されます。同じデータは、<.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocol server</.localized_link> を介してエージェントからも利用可能です。
