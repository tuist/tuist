# Gradle コードカバレッジ {#gradle-code-coverage}

コードカバレッジは、テストがコードのどの行を実行したかを示します。Tuist Gradle プラグインは JaCoCo を使用してテストタスクのカバレッジを測定し、各テスト実行時にそれをアップロードします。Tuist は、プロジェクト全体、各 Gradle プロジェクト、および各ファイルについて、コミット内の複数の実行結果を 1 つの数値に集約します。ダッシュボードの **コードカバレッジ** ページでは、コミットごとの数値と各ブランチの推移を確認できます。

> [!IMPORTANT]
> **要件**
>
> - `dev.tuist` Gradle プラグインが適用されていること（詳細は <.localized_link href="/guides/get-started/gradle-project">Gradle プロジェクトで始める</.localized_link> を参照）
> - プロジェクトが Git リポジトリ内にあること：リポジトリ外での実行はテスト結果のみをアップロードし、カバレッジはアップロードしません

## セットアップ {#setup}

### カバレッジの有効化 {#turn-coverage-on}

`settings.gradle.kts` の `tuist` ブロックでカバレッジを有効にします：

```kotlin
tuist {
    coverage {
        enabled = true
    }
}
```

または、CI ジョブなどの単一の呼び出しに対して環境変数で有効にすることもできます。この場合、環境変数の設定が優先されます：

```sh
TUIST_TEST_COVERAGE=1 ./gradlew test
```

カバレッジが有効なテストタスクと無効なテストタスクは、別々のビルドキャッシュエントリを持ちます（[パフォーマンスへの影響](#performance-impact) を参照）。そのため、CI とローカルビルドがビルドキャッシュを共有する場合は、設定による有効化をお勧めします。CI でのみカバレッジを有効にすると、互いのテスト結果の再利用を防ぐことができます。

カバレッジが有効な場合、プラグインはすべての JVM プロジェクトに Gradle の `jacoco` プラグインを適用します。JaCoCo エージェントは、あなたが自分でプラグインを適用した場合と同様に、プロジェクトのリポジトリから取得されます。すでに JaCoCo を構成しているプロジェクトは、その設定を維持し、独自のレポートも引き続き機能します。

このプラグインはリポジトリ内のコードのカバレッジのみを報告するため、JaCoCo の対象をそれに限定します。テストタスクが JaCoCo の `includes` を自身で設定しない限り、エージェントはリポジトリがコンパイルするクラスのパッケージのみをインストルメントします。依存関係、Android フレームワーク、およびテストフレームワークはインストルメントされずに実行されるため、JaCoCo のデータとテストタスクのビルドキャッシュエントリを小さく保つことができます。

### Android プロジェクト {#android-projects}

このプラグインは、`testDebugUnitTest` などの Android プロジェクトのローカルユニットテストを測定します。デバイスやエミュレータ上で実行されるインストルメントテストは測定されません。

ユニットテストで Robolectric を使用している場合は、Robolectric が読み込むクラスを JaCoCo に含めるよう指示してください。Robolectric は独自のクラスローダーでアプリのクラスを定義するため、JaCoCo はデフォルトでそのようなクラスをスキップします。その結果、それらのテストが実行するコードはカバーされていないとして表示されてしまいます。Android プロジェクトの `build.gradle.kts` で以下を設定します：

```kotlin
pluginManager.withPlugin("jacoco") {
    tasks.withType<Test>().configureEach {
        extensions.configure<JacocoTaskExtension> {
            isIncludeNoLocationClasses = true
            excludes = listOf("jdk.internal.*")
        }
    }
}
```

このブロックは、プラグインが `jacoco` を適用するとき、つまりカバレッジが有効な場合にのみ適用されます。

Android のユニットテストはデフォルトで JUnit 4 で実行され、カバレッジは記録されますが、[各テストが実行したコード](#per-test-evidence) は記録されません。これを記録するには、JUnit Vintage を介して JUnit Platform で実行してください。

### シャード化された実行 {#sharded-runs}

<.localized_link href="/guides/features/test-sharding/gradle">テストをシャード化</.localized_link> する場合、カバレッジを有効にして実行された各シャードは、自身が実行したテストのカバレッジを報告し、Tuist は 1 回の実行に含まれるシャードの結果を 1 つの数値にマージします。シャードは意図的にスイートの一部を実行するため、コミットのカバレッジが不完全になることはありません。

### CI で各コミットを完了させる {#complete-each-commit}

コミットのカバレッジは、シャードごとに 1 つなど、複数のジョブから得られることがよくあります。Tuist は最後に報告されたジョブを自動で検出できないため、明示的に通知する必要があります。コミットに関連するすべてのテストジョブが終了したら、それらすべてに依存するジョブで以下を実行します：

```sh
./gradlew tuistCoverageComplete
```

単一のジョブでコミットのすべてのテストを実行する場合は、テストの失敗時も含め、テスト実行後のステップとしてタスクを実行してください。テストが失敗した実行でも、カバレッジは報告されます。

このタスクは、チェックアウトの `HEAD`（テストが実行されたコミット）からコミットを読み取ります。別のコミットを指定するには、`-Ptuist.coverage.commit=<sha>` を渡してください。コミットが完了するまで、そのカバレッジは **進行中** と表示され、ブランチの推移には含まれません。

## 仕組み {#how-it-works}

### Tuist が測定するもの {#what-tuist-measures}

- **プロジェクト。** 各 Gradle プロジェクトはダッシュボード上のモジュールとして扱われ、それぞれ独自のカバレッジを持ちます。
- **プロダクトコードのみ。** テストソースセットからコンパイルされたクラスはテストコードです。Tuist はこれらを保存しますが、あらゆる数値計算からは除外します。
- **リポジトリ内のファイル。** クラスは、リポジトリ内のパスに基づき、コンパイル元のソースファイルに対応します。生成されたソースや Git が無視するファイルは報告されません。
- **各行の実行有無。** JaCoCo はコードが実行されたかどうかを記録し、実行回数は記録しません。そのため、ダッシュボード上の実行回数は 0 または 1 となります。

### 各テストが実行したコード {#per-test-evidence}

JUnit Platform（JUnit 5、または JUnit Vintage を介した JUnit 4）で実行されるテストの場合、プラグインは各テストが実行したコードと、`@BeforeAll` などのテスト外の部分で各テストクラスが実行したコードも記録します。これにより、Tuist は実行から除外されたテストのカバレッジを過去のデータから引き継ぐことができます（[スキップされたテスト](#skipped-tests) を参照）。テスト側に追加の設定は不要です。

これは、各テスト JVM が一度に 1 つのテストを実行する場合に機能します。JUnit の並列実行を有効にしない限り、Gradle はこの方法でテストを実行します。`maxParallelForks` を使用して複数の JVM でテストクラスを実行しても問題ありません。1 つの JVM 内で同時に実行されるテストもカバレッジには計上されますが、個別のテストごとの詳細は記録されません。

### ビルドキャッシュ {#build-cache}

ビルドキャッシュから復元されたテストタスク、または最新の状態であるテストタスクは、テストを実行しません。しかし、そのカバレッジは依然としてアップロードされます。JaCoCo のデータはタスクの出力の一つであり、同じ入力に対してテストを実行した実行によって記録されたものだからです。

### スキップされたテスト {#skipped-tests}

実行からテストが除外された場合、Tuist は、実行されたコードに変更がない限り、以前の実行からカバー範囲を引き継ぎます。引き継げない場合、コミットのカバレッジは **不完全** となります。実行から除外されるパターン：

- **プロジェクトのテストタスクが除外された場合**（`-x :app:test` を使用）。これらのテストは、コードに変更がない最後の実行結果から引き継がれます。
- **一部のプロジェクトのテスト**（`./gradlew :core:test` を使用）、または **一部のテスト**（`--tests` を使用）。この実行は要求された部分のみをカバーするため、コミットの他の実行ですべてが実行されない限り、コミットは不完全となります。
- **最初の失敗で停止したテストタスク**（`failFast`）。

意図的に除外され、コミットを不完全にしないテストもあります：

- **ビルドスクリプト内のフィルター**（`filter { excludeTestsMatching(...) }` など）。これらはテストスイートで実行する対象を定義します。
- **ビルドスクリプトで無効にしたテストタスク**。`enabled = false` を使用するか、それらをスキップする `onlyIf` を設定することで無効にします。
- **<.localized_link href="/guides/features/test-insights/flaky-tests/gradle">隔離</.localized_link> によってスキップされたテスト。** これらは削除されたものとして扱われ、これらのテストのみがカバーしていた行は未カバーとして計上されます。
- **他のシャードのテスト**。[テストをシャーディング](#sharded-runs) している場合です。

### 完全および不完全なコミット {#commit-status}

| ステータス | 意味 |
| --- | --- |
| 進行中 | 実行からカバレッジが報告されていますが、コミットに対して `tuistCoverageComplete` がまだ実行されていません。 |
| 完了 | コミットの実行に含まれるすべてのテストが実行されたか、引き継がれたか、意図的に除外されました。 |
| 不完全 | 一部のカバレッジを特定できなかったため、数値は下限値となります。 |
| 未測定 | コミットに対してカバレッジを報告した実行がありません。 |

ブランチのトレンドには、完了したコミットのみが含まれます。

## パフォーマンスへの影響 {#performance-impact}

JaCoCo はテスト JVM がクラスをロードする際にインストゥルメンテーションを行うため、コンパイル済みクラスやコンパイルタスクのビルドキャッシュエントリは、カバレッジの有無にかかわらず同じままです。SBOM ジェネレーターなど、すべての依存関係構成を読み取るタスクも JaCoCo エージェントの影響を受けるため、カバレッジを有効にすると出力が変化します。テストの実行速度はわずかに低下し、プラグインはテストタスクの終了後に JaCoCo のデータを読み取ります。カバレッジ有効時と無効時のテストタスクは別々のビルドキャッシュエントリを持つため、カバレッジ無効時の結果がキャッシュされていても、カバレッジ有効での初回実行ではテストが実際に実行されます。

## 制限事項 {#limitations}

- **Isolated Projects と Configuration on Demand。** これらのビルドではすべてのプロジェクトを設定しないため、プラグインは実行からどのプロジェクトのテストが除外されたかを判別できず、一部のプロジェクトのテストのみを実行した場合でも完了として扱われます。
- **フォークからのプルリクエストからはカバレッジを取得できません。** カバレッジは Tuist で認証された実行によってのみアップロードされ、CI は通常、フォークから開かれたプルリクエストに対してシークレットや ID トークンを提供しません。

## カバレッジのクエリ {#querying}

ダッシュボードの **コードカバレッジ** ページでは、各コミットの合計値、モジュール、ファイル、および各実行でカバーされた行を表示します。同じデータは、<.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocol サーバー</.localized_link> を介してエージェントからも利用可能です。
