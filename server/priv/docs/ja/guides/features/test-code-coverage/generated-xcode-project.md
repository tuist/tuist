# 生成されたXcodeプロジェクト {#generated-xcode-project-code-coverage}

コードカバレッジは、テストが実行したコードの行を示します。Tuistは `tuist test` の各実行の行カバレッジをアップロードし、コミット内の複数の実行をプロジェクト全体、各ターゲット、および各ファイルごとに1つの数値に集約します。ダッシュボードの **コードカバレッジ** ページでは、コミットごとの値とブランチごとの推移を表示します。

<!-- @snippet: ./_xcode-requirements -->

Tuistが処理をスキップしても、この数値は正確に保たれます。<.localized_link href="/guides/features/cache/module-cache">バイナリキャッシュ</.localized_link> から取得したターゲットはカバレッジカウンタ付きでビルドされるため、ソースからビルドした場合と同様にコードが計測されます。また、<.localized_link href="/guides/features/selective-testing/generated-xcode-project">選択的テスト</.localized_link> がテストターゲットをスキップした場合、そのターゲットは以前の実行で持っていたカバレッジを維持します。これは、Tuistが各実行で記録する [ターゲットレベルのカバレッジ](#target-level-coverage) によって実現されます。

## セットアップ {#setup}

### カバレッジを有効にする {#turn-coverage-on}

`Tuist.swift` の生成オプションでカバレッジを有効にし、デフォルトではオフになっているカバレッジのアップロードもオンにします。

```swift
import ProjectDescription

let tuist = Tuist(
    testInsights: .testInsights(coverage: .coverage(upload: true)),
    project: .tuist(
        generationOptions: .options(
            coverage: .coverage(enabled: true)
        )
    )
)
```

生成オプションを有効にすると:

- Tuistが生成するすべてのスキームのテストアクションはカバレッジを収集します。また、`coverage` を未設定のまま定義したスキームのテストアクションも同様です。`.options(coverage: false)` または `.options(coverage: true)` を指定したスキームは、その値を保持します。テストプラン自体がカバレッジを決定します。Tuistが生成するテストプランの場合、`.testPlans(_:coverage:)` に `coverage: true` を渡してください。
- プロジェクト独自のターゲットは、Debug構成においてカバレッジカウンタ付きでバイナリキャッシュから読み込まれ、ウォーミングされます。[仕組み](#instrumented-binaries) を参照してください。

`TUIST_COVERAGE_ENABLED` および `TUIST_COVERAGE_UPLOAD` 環境変数（`1` または `0`）は、`enabled` および `upload` より優先されます。キャッシュをウォーミングするコマンドと読み込むコマンドで一貫性を持たせるため、単一のコマンドではなく、CIワークフローなどの環境全体に対して設定してください。

> [!IMPORTANT] KEEP THE VALUE THE SAME EVERYWHERE
> 生成オプションは、プロジェクトのターゲットのキャッシュキーと、テストターゲットの選択的テスト用ハッシュを変更します。キャッシュを共有するすべてのマシンで同じ値を使用し、環境（例: `Environment.isCI`）から派生させないでください。カバレッジ無効で実行した場合、カバレッジ有効で実行した際のバイナリや選択的テストの結果は再利用されません。

### スキームを除外する {#leave-schemes-out}

一部のスィートはカバレッジの対象外とするべきです。例えば、別のプロセスからアプリやCLIを操作する受入テストやエンドツーエンドテストは、カバレッジ計測の対象とならないコードを実行するため、計測を行っても処理が遅くなるだけです。それらのスキームのテストアクションでカバレッジを無効にしてください。

```swift
.scheme(
    name: "AcceptanceTests",
    testAction: .targets(
        ["AcceptanceTests"],
        options: .options(coverage: false)
    )
)
```

`Tuist.swift` オプションや `TUIST_COVERAGE_ENABLED` の設定に関わらず、このスキームはカバレッジを無効にしたままとなり、その実行結果はコミットのカバレッジに含まれません。カバレッジはスキーム単位で収集されるため、特定のテストターゲットを除外するには、それを独自のスキームに移してください。

### テストを実行する {#run-your-tests}

通常通り、`tuist test` でテストを実行します。

```sh
tuist test
```

Tuistは、実行中に収集されたカバレッジをテスト結果とともにアップロードします。これには、<.localized_link href="/guides/features/test-sharding/generated-xcode-project">シャード化された実行</.localized_link> や、`--without-building` を使用して別のジョブでビルドされた製品をテストする実行が含まれます。フォークからのプルリクエストを実行するジョブなど、Tuistへのカバレッジ送信を防ぎたい場合は、`TUIST_COVERAGE_UPLOAD=0` を設定してください。

### CIで各コミットを完了させる {#complete-each-commit}

コミットのカバレッジは、スキームごと、シャードごと、またはプラットフォームごとの複数のジョブから得られることがよくあります。Tuistは最後に報告されたジョブを自動検出できないため、明示的に通知する必要があります。コミットに関連するすべてのテストジョブが終了したら、それらすべてに依存するジョブで次を実行してください。

```sh
tuist coverage complete
```

このコマンドは、チェックアウトまたはCIプロバイダーからコミットを読み取ります。別のコミットを指定するには、`--commit <sha>` を渡してください。コミットが完了するまで、そのカバレッジは **進行中** と表示され、ブランチの推移には含まれません。

### デフォルトブランチで全スィートを実行する {#full-runs}

> [!IMPORTANT] SET UP A FULL RUN
> 選択的テストは、スキップされたターゲットのカバレッジを引き継ぐための以前の実行が存在する場合にのみ、コミットのカバレッジを完全な状態に保ちます。デフォルトブランチで、選択的テストなしですべてのテストを実行するジョブをスケジュールしてください。
>
> ```sh
> tuist test --no-selective-testing
> ```
>
> マージごとに1回実行するのが理想的です。変更の少ないリポジトリであれば、毎日または毎週でも十分な場合があります。記録されたカバレッジは90日後に期限切れになるため、それより頻繁に実行してください。

引き継がれたカバレッジは完全な実行に依存します。完全な実行は、期限切れ前に各ターゲットの記録済みカバレッジを更新し、選択的実行ではビルドされないファイルの最新の状態をTuistに提供します。完全な実行の間でリポジトリの変更が多いほど、選択的実行は変更されたファイルを多く検出し、コミットのカバレッジが **不完全** になる頻度が高まります。

## ターゲットレベルのカバレッジ {#target-level-coverage}

実行のカバレッジは、実行全体が何を処理したかを示すものであり、各テストターゲットが何を処理したかを示すものではありません。選択的テストがターゲットをスキップする場合、Tuistはそのターゲットのカバレッジを引き継ぐために、以前の執行でそのターゲットが何を処理したかを知る必要があります。

そのため、Tuistは各実行において、各テストターゲットが実行したファイルと行も記録します。これはXcodeが各テストプロセス用に書き出すカバレッジから読み取られるため、追加の設定やリンクは不要です。記録はmacOSおよびiOSシミュレータで行われ、デバイス上では行われません。UIテストは、操作対象のアプリに関する情報を一切記録しません。アプリのコードは独自のプロセスで実行されるためです。

## 仕組み {#how-it-works}

### インストゥルメント化されたバイナリ {#instrumented-binaries}

バイナリキャッシュからのターゲットは事前ビルドされたバイナリであり、テスト実行はそのバイナリがカバレッジカウンタ付きでビルドされていた場合にのみコードを計測できます。カバレッジ有効時、バイナリキャッシュはプロジェクト独自のターゲットのインストゥルメント化された変種を保持し、すべてのコマンドはその変種を読み込んでウォーミングします。

- **Debug構成** はインストゥルメント化された変種を使用します。`tuist cache` がこれをウォーミングし、`tuist generate` および `tuist test` がこれを読み込みます。
- **Release構成** は常にプレーンな変種を使用するため、配布物にはカバレッジカウンタが含まれません。
- **外部パッケージ** は常にプレーンな変種を使用します。Tuistはリポジトリ内のコードのみを計測します。

`tuist test` がインストゥルメント化されたバイナリを検出できるよう、テストジョブと同じ環境でカバレッジ有効状態でキャッシュをウォーミングしてください。実行がカバレッジを収集したが、ターゲットをプレーンなバイナリとしてキャッシュから取得した場合、Tuistは警告を発し、そのコードは計測されません。<.localized_link href="/guides/features/cache/module-cache#code-coverage">モジュールキャッシュ</.localized_link> には、これらの変種の詳細な説明があります。

### マシン間でのパス {#paths-across-machines}

インストゥルメント化されたバイナリは、ビルド時のチェックアウトに対する相対パスでソースパスを記録するため、CIでウォーミングされたバイナリは、どの開発者のマシン上でも正しいファイルを計測します。

<.localized_link href="/guides/features/cache/xcode-cache">Xcodeキャッシュ</.localized_link>も同様に、プレフィックスマッピングを通じて機能します。Xcode独自のカバレッジレポートはマッピングされたパスを解決できないため、Tuistはカバレッジを収集するビルドにおいてデフォルトでこれを無効にしています。Xcode 27以降では、`enableCaching` を有効にした状態で `prefixMapping: true` を使用すると、この設定が維持され、カバレッジビルド間でチェックアウトをまたいでコンパイル結果を共有できます。

```swift
.options(coverage: .coverage(enabled: true, prefixMapping: true))
```

Tuistのアップロードはマッピングされたパスを解決しますが、Xcodeのカバレッジレポートや `xccov` はそれらのファイルを除外することがあります。詳細は <.localized_link href="/guides/features/cache/xcode-cache#coverage-with-prefix-mapping">プレフィックスマッピングを使用したカバレッジ</.localized_link> を参照してください。

### スキップされたテスト {#skipped-tests}

選択的テストは、以前の成功した実行が同じハッシュで既にテスト済みの場合、そのテストターゲットをスキップします。ハッシュはターゲットのソース、そのテスト、およびすべての依存関係を含むため、同じハッシュは同じコードに対する同じテストを意味します。Tuistは、以前の実行がそのターゲットに対して記録した [ターゲットレベルのカバレッジ](#target-level-coverage) を再利用します。もし記録されていなかった場合（例えば、当時カバレッジが無効だったか、実行が90日以上前のものである場合）、引き継ぐデータがなく、コミットは **不完全** となります。

選択的実行はすべてのファイルをビルドするわけではありません。コンパイルされなかったファイルについては、ファイルがその後変更されていない限り、直近の以前の完全実行から行数を取得します。これが、デフォルトブランチでの [完全実行](#full-runs) が重要な理由です。

`--skip-test-targets` や `-skip-testing` を使用して自分でスキップしたテストは引き継がれません。それらのテストを実行しなかったコミットは、そのコミット内の他の実行でテストされない限り **不完全** となります。検疫によってスキップされたテストはカバレッジの対象外です。Tuistはこれらを引き継がず、それらを理由にコミットを **不完全** とマークすることもありません。

### 完全なコミットと不完全なコミット {#commit-status}

ダッシュボード上の各コミットにはステータスがあります。

| ステータス | 意味 |
| --- | --- |
| 進行中 | 実行からカバレッジが報告されていますが、まだ `tuist coverage complete` がそのコミットに対して実行されていません。 |
| 完了 | コミットのスキームに含まれるすべてのテストが実行されたか、引き継がれました。 |
| 不完全 | 一部のカバレッジを確定できなかったため、数値は下限値となります。 |
| 未計測 | コミットに対してカバレッジを報告した実行がありません。 |

ブランチのトレンドには完全なコミットのみが含まれます。コミットは、例えば以下の場合に不完全となります。

- 選択的テストが引き継げないターゲットをスキップした場合。以前の実行でそのターゲットのカバレッジが記録されていなかった、選択的実行がビルドしなかったファイルが最後の完全実行以降に変更された、あるいは `Package.resolved`、`Project.swift`、または `.xcconfig` のようにすべてのターゲットに影響するファイルがコミットで変更されたなど。
- 実行が `--skip-test-targets` または `-skip-testing` でテストをスキップし、そのコミット内の他の実行でもそれらが実行されなかった場合。
- 実行がバイナリキャッシュからターゲットをプレーンなバイナリとして取得した場合。
- スキームのすべての実行が `-only-testing` で絞り込まれていた場合。
- スキームのカバレッジが、未コミットの変更があるチェックアウト上でのCI実行からのみ得られた場合。

## パフォーマンスへの影響 {#performance-impact}

カバレッジの収集はオーバーヘッドを追加しますが、主にテスト終了後、Xcodeがカバレッジレポートを書き出し、Tuistがカバレッジをエクスポートしている間です。テストのビルドと実行にかかる時間は、カバレッジなしの場合とほぼ同じです。インストゥルメント化されたビルドは、DerivedDataおよびDebugバイナリキャッシュにより多くのディスク容量を消費します。Releaseビルドおよびアーカイブは影響を受けません。

## 制限事項 {#limitations}

### カバレッジを収集するスキームのReleaseビルド {#release-builds}

スキームのテストアクションがカバレッジを収集する場合、Xcodeはそのスキーム用に `xcodebuild build` がソースからコンパイルするターゲットを、Release構成を含めあらゆる構成でインストゥルメント化します。`xcodebuild archive` はこの設定を無視するため、アーカイブは決してインストゥルメント化されません。アーカイブを配布するか、`.options(coverage: false)` を指定したスキームからRelease製品をビルドしてください。

### その他のカバレッジツール {#other-coverage-tools}

`-enableCodeCoverage YES` は、Xcodeと同様に、実行がカバレッジを収集するかどうかを決定するだけです。Tuistがキャッシュからインストゥルメント化されたバイナリを読み込むようになるわけではないため、代わりに `Tuist.swift` オプションまたは `TUIST_COVERAGE_ENABLED` を使用してください。

別のカバレッジツールにデータを提供するには、`tuist test` に各実行のカバレッジをLCOV形式で書き出させます。これはTuistがアップロードするものと同じカバレッジであり、リポジトリ相対パスとバイナリキャッシュからのコードが含まれます。

```sh
tuist test --coverage-output-path coverage
```

各実行は `coverage/<result bundle name>.lcov` を書き出します。シャード化された実行のファイルは `lcov -a` でマージしてください。このオプションを使用するには、カバレッジのアップロードが有効である必要があります。

Xcode独自のカバレッジレポートおよびそれを読み取るツールは、その実行中にXcodeがビルドしたターゲットのみを含み、バイナリキャッシュから来たコードは決して含みません。Tuistのアップロードは両方を計測します。Xcodeのレポートで特定ターゲットのカバレッジを確認したい場合は、そのターゲットをソースからビルドするようにプロジェクトを生成してください。`tuist generate MyTarget` は `MyTarget` をソースとして保持し、残りはキャッシュから取得します。

## カバレッジのクエリ {#querying}

`tuist coverage` コマンドは、ダッシュボードに表示される内容を読み取ります。`--commit` なしの場合、`--branch` の最新かつ完全なコミット、またはデフォルトブランチの最新かつ完全なコミットを読み取ります。

```sh
tuist coverage show                          # the project's coverage and its targets
tuist coverage files --commit <sha>          # files, least covered first
tuist coverage file Sources/Cart.swift --lines  # a file's functions, with per-line counts
```

すべて `--json` を受け付け、スクリプトで使用できます。同じデータは、<.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocolサーバー</.localized_link> を介してエージェントからも利用可能です。
