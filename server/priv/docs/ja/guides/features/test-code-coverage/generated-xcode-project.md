# 生成されたXcodeプロジェクト {#generated-xcode-project-code-coverage}

> [!NOTE] EARLY ACCESS
> Xcodeプロジェクトのコードカバレッジは早期アクセス段階です。[お問い合わせ](mailto:contact@tuist.dev)いただければ、アカウントで有効にします。それまで、Tuistは実行時にアップロードされるカバレッジを保存しません。

コードカバレッジは、テストがコードのどの行を実行したかを示します。Tuistは`tuist test`の実行ごとにラインカバレッジをアップロードし、コミットに含まれるすべての実行をプロジェクト全体、各ターゲット、各ファイルについて1つの数値に集約します。ダッシュボードの**コードカバレッジ**ページでは、コミットごとの値とブランチごとの推移を確認できます。

Tuistが処理をスキップしても、この数値は正確に保たれます。<.localized_link href="/guides/features/cache/module-cache">バイナリキャッシュ</.localized_link>から取得したターゲットはカバレッジカウンタ付きでビルドされるため、ソースからビルドした場合と同様にコードが計測されます。また、<.localized_link href="/guides/features/selective-testing/generated-xcode-project">選択的テスト</.localized_link>でテストターゲットがスキップされた場合、そのターゲットは以前の実行で得られたカバレッジを維持します。これは、Tuistが実行ごとに記録する[ターゲットレベルのカバレッジ](#target-level-coverage)を通じて実現されます。

## セットアップ {#setup}

### カバレッジを有効にする {#turn-coverage-on}

`Tuist.swift`の生成オプションでカバレッジを有効にし、デフォルトでは無効になっているカバレッジのアップロードも有効にします。

```swift
import ProjectDescription

let tuist = Tuist(
    testInsights: .testInsights(coverage: .coverage(upload: true)),
    project: .tuist(
        generationOptions: .options(
            coverage: .coverage(enabled: true)
        )
    )
)
```

生成オプションを有効にすると:

- Tuistが生成するすべてのスキームのテストアクションはカバレッジを収集します。また、`coverage`を設定せずに定義したスキームのテストアクションも同様です。`.options(coverage: false)`または`.options(coverage: true)`を設定したスキームは、その値を保持します。テストプランは自身でカバレッジを決定します。Tuistが生成するテストプランの場合、`coverage: true`を`.testPlans(_:coverage:)`に渡してください。
- プロジェクト独自のターゲットは、Debug構成においてカバレッジカウンタ付きでバイナリキャッシュから読み込まれ、ウォームアップされます。[仕組み](#instrumented-binaries)をご覧ください。

`TUIST_COVERAGE_ENABLED`および`TUIST_COVERAGE_UPLOAD`環境変数(`1`または`0`)は、`enabled`および`upload`よりも優先されます。単一のコマンドではなく、CIワークフローなど環境全体に対して設定し、キャッシュをウォームアップするコマンドと読み取るコマンドの間で一貫性を保ってください。

> [!IMPORTANT] KEEP THE VALUE THE SAME EVERYWHERE
> 生成オプションは、プロジェクトのターゲットのキャッシュキーと、テストターゲットの選択的テスト用ハッシュを変更します。キャッシュを共有するすべてのマシンで同じ値を使用し、環境(例えば`Environment.isCI`)から導出しないでください。カバレッジを無効にした実行は、カバレッジを有効にした実行のバイナリや選択的テストの結果を再利用しません。

### スキームを対象外にする {#leave-schemes-out}

一部のスィートはカバレッジの対象から外すべきです。例えば、別のプロセスからアプリやCLIを操作する受け入れテストやエンドツーエンドテストは、カバレッジツールが検知できないコードを実行するため、収集しても低速化するだけです。これらのスキームのテストアクションでカバレッジを無効にしてください。

```swift
.scheme(
    name: "AcceptanceTests",
    testAction: .targets(
        ["AcceptanceTests"],
        options: .options(coverage: false)
    )
)
```

このスキームは、`Tuist.swift`オプションや`TUIST_COVERAGE_ENABLED`の設定に関わらずカバレッジを無効のまま維持し、その実行結果はコミットのカバレッジに計上されません。カバレッジはスキーム単位で収集されるため、特定のテストターゲットを対象外にするには、専用のスキームに移してください。

### テストを実行する {#run-your-tests}

通常通り、`tuist test`を使用してテストを実行します。

```sh
tuist test
```

Tuistは、実行中に収集されたカバレッジをテスト結果とともにアップロードします。これには、<.localized_link href="/guides/features/test-sharding/generated-xcode-project">分割実行</.localized_link>や、`--without-building`を使用して別のジョブでビルドされた製品をテストする実行が含まれます。フォークからのプルリクエストを実行するジョブなど、特定の実行のカバレッジをTuistに送信しない場合は、`TUIST_COVERAGE_UPLOAD=0`を設定してください。

### CI上で各コミットを完了させる {#complete-each-commit}

コミットのカバレッジは、スキーム、シャード、プラットフォームごとに分かれた複数のジョブから報告されることがあります。Tuistは最後に報告されたジョブを自動で検知できないため、明示的に通知する必要があります。コミットに関連するすべてのテストジョブが終了したら、それらすべてに依存するジョブで次のコマンドを実行してください。

```sh
tuist coverage complete
```

このコマンドは、チェックアウトまたはCIプロバイダーからコミットを読み取ります。別のコミットを指定するには、`--commit <sha>`を渡してください。コミットが完了するまで、そのカバレッジは**進行中**として表示され、ブランチの推移には含まれません。

### デフォルトブランチで全スィートを実行する {#full-runs}

> [!IMPORTANT] SET UP A FULL RUN
> 選択的テストは、スキップされたターゲットのカバレッジを引き継ぐための以前の実行が存在する場合にのみ、コミットのカバレッジを完了状態に保つことができます。デフォルトブランチでは、選択的テストを使わずにすべてのテストを実行するジョブをスケジュールしてください。
>
> ```sh
> tuist test --no-selective-testing
> ```
>
> マージごとに1回実行するのが理想的です。変更の少ないリポジトリであれば、毎日または毎週でも十分な場合があります。記録されたカバレッジは90日後に失効するため、それより頻繁に実行してください。

引き継がれたカバレッジは完全な実行に依存しています。完全な実行は、失効前に各ターゲットの記録済みカバレッジを更新し、選択的実行ではビルドされないファイルの最新状態をTuistに提供します。完全な実行の間にリポジトリの変更が多いほど、選択的実行は変更されたファイルを多く発見し、コミットのカバレッジは**不完全**になりやすくなります。

## ターゲットレベルのカバレッジ {#target-level-coverage}

実行のカバレッジは、実行全体が何を処理したかを示すものであり、各テストターゲットが個別に何を処理したかを示すものではありません。選択的テストでターゲットがスキップされた場合、Tuistはそのターゲットのカバレッジを引き継ぐために、以前の実行でそのターゲットが処理した内容を知る必要があります。

そのため、Tuistは各実行において、各テストターゲットが処理したファイルと行も記録します。これはXcodeが各テストプロセス用に書き出すカバレッジデータから読み取られるため、追加の設定やリンクは不要です。記録はmacOSおよびiOSシミュレーターで行われ、実機では行われません。UIテストは、駆動対象のアプリに関する情報を一切記録しません。アプリのコードは独自のプロセスで実行されるためです。

## 仕組み {#how-it-works}

### インストルメント済みバイナリ {#instrumented-binaries}

バイナリキャッシュからのターゲットは事前ビルドされたバイナリであり、テスト実行はそのバイナリがカバレッジカウンタ付きでビルドされていた場合にのみコードを計測できます。カバレッジが有効な場合、バイナリキャッシュはプロジェクト独自のターゲットのインストルメント済みvariantを保持し、すべてのコマンドはそのvariantを読み取り、ウォームアップします。

- **Debug構成**はインストルメント済みvariantを使用します。`tuist cache`がこれをウォームアップし、`tuist generate`および`tuist test`がこれを読み取ります。
- **Release構成**は常にプレーンなvariantを使用するため、配布物にはカバレッジカウンタが含まれません。
- **外部パッケージ**は常にプレーンなvariantを使用します。Tuistはリポジトリ内のコードのみを計測します。

テストジョブと同じ環境でカバレッジを有効にしてキャッシュをウォームアップし、`tuist test`がインストルメント済みバイナリを見つけられるようにしてください。実行がカバレッジを収集しようとしても、キャッシュからプレーンなバイナリを取得した場合、Tuistは警告を表示し、そのコードは計測されません。<.localized_link href="/guides/features/cache/module-cache#code-coverage">モジュールキャッシュ</.localized_link>には、これらのvariantの詳細な説明があります。

### マシン間でのパス {#paths-across-machines}

インストルメント済みバイナリは、ビルド時のチェックアウトに対する相対パスでソースパスを記録するため、CIでウォームアップされたバイナリは、どの開発者のマシンでも正しいファイルを計測します。

<.localized_link href="/guides/features/cache/xcode-cache">Xcodeキャッシュ</.localized_link>も同様にプレフィックスマッピングを通じて動作しますが、Xcode独自のカバレッジレポートはマッピングされたパスを解決できないため、カバレッジを収集するビルドではTuistがデフォルトでこれを無効にします。Xcode 27以降では、`enableCaching`を有効にした状態で`prefixMapping: true`を保持することで、カバレッジビルドでもチェックアウト間でコンパイル結果を共有できます。

```swift
.options(coverage: .coverage(enabled: true, prefixMapping: true))
```

Tuistのアップロードはマッピングされたパスを解決しますが、Xcodeのカバレッジレポートや`xccov`ではそれらのファイルが除外される場合があります。<.localized_link href="/guides/features/cache/xcode-cache#coverage-with-prefix-mapping">プレフィックスマッピングによるカバレッジ</.localized_link>をご覧ください。

### スキップされたテスト {#skipped-tests}

選択的テストは、以前の成功した実行で同じハッシュを用いてすでにテスト済みの場合、そのテストターゲットをスキップします。ハッシュにはターゲットのソース、そのテスト、およびすべての依存関係が含まれるため、同じハッシュは同じコードに対する同じテストを意味します。Tuistは、以前の実行でそのターゲットに対して記録された[ターゲットレベルのカバレッジ](#target-level-coverage)を再利用します。もし記録がなかった場合（例えば、当時カバレッジが無効だったか、実行が90日以上前である場合）、引き継ぐデータがなく、コミットは**不完全**となります。

選択的実行はすべてのファイルをビルドするわけではありません。コンパイルされなかったファイルについては、ファイルがその後変更されていない限り、直近の完全な実行からの行数を採用します。これが、デフォルトブランチでの[完全な実行](#full-runs)が重要である理由です。

`--skip-test-targets`または`-skip-testing`を使用して自分でスキップしたテストは引き継がれません。それらを実行しなかったコミットは、そのコミット内の他の実行で実行されない限り、**不完全**となります。検疫によってスキップされたテストはカバレッジに含まれません。Tuistはそれらを引き継がず、そのためコミットを**不完全**としてマークすることもありません。

### 完全なコミットと不完全なコミット {#commit-status}

ダッシュボード上の各コミットにはステータスがあります。

| ステータス | 意味 |
| --- | --- |
| 進行中 | 実行からカバレッジが報告されていますが、そのコミットに対して`tuist coverage complete`がまだ実行されていません。 |
| 完了 | コミットのスキームにおけるすべてのテストが実行されたか、引き継がれました。 |
| 不完全 | 一部のカバレッジを特定できなかったため、数値は下限値となります。 |
| 未計測 | コミットに対してカバレッジを報告した実行がありません。 |

ブランチのトレンドには完全なコミットのみが含まれます。コミットが不完全になる例としては、以下のような場合です。

- 選択的テストが引き継げないターゲットをスキップした場合：以前の実行でそのターゲットのカバレッジが記録されていなかった、選択的実行がビルドしなかったファイルが最後の完全な実行以降に変更された、あるいは`Package.resolved`、`Project.swift`、`.xcconfig`など、すべてのターゲットに影響するファイルがコミットで変更された。
- 実行が`--skip-test-targets`または`-skip-testing`でテストをスキップし、そのコミット内の他の実行でもそれらが実行されなかった場合。
- 実行がバイナリキャッシュからプレーンなバイナリとしてターゲットを取得した場合。
- スキームのすべての実行が`-only-testing`で絞り込まれていた場合。
- スキームのカバレッジが、未コミットの変更があるチェックアウトでのCI実行からのみ得られた場合。

## パフォーマンスへの影響 {#performance-impact}

カバレッジの収集はオーバーヘッドを追加しますが、主にテスト終了後、Xcodeがカバレッジレポートを書き出し、Tuistがカバレッジをエクスポートする間にかかります。テストのビルドと実行にかかる時間は、カバレッジなしの場合とほぼ同じです。インストルメント済みビルドは、DerivedDataおよびDebugバイナリキャッシュにより多くのディスク容量を消費します。Releaseビルドとアーカイブは影響を受けません。

## 制限事項 {#limitations}

### カバレッジを収集するスキームのReleaseビルド {#release-builds}

スキームのテストアクションがカバレッジを収集する場合、Xcodeはそのスキーム用にソースからコンパイルするターゲットを`xcodebuild build`でインストルメントします。これはRelease構成を含め、すべての構成に適用されます。`xcodebuild archive`はこの設定を無視するため、アーカイブは決してインストルメントされません。アーカイブを配布するか、`.options(coverage: false)`を持つスキームからReleaseプロダクトをビルドしてください。

### 他のカバレッジツール {#other-coverage-tools}

`-enableCodeCoverage YES`は、Xcodeと同様に、実行がカバレッジを収集するかどうかのみを決定します。Tuistがキャッシュからインストルメント済みバイナリを読み取るようにはならないため、代わりに`Tuist.swift`オプションまたは`TUIST_COVERAGE_ENABLED`を使用してください。

他のカバレッジツールにデータを提供するには、`tuist test`に各実行のカバレッジをLCOVとして書き出させます。これはTuistがアップロードするものと同じカバレッジであり、リポジトリ相対パスとバイナリキャッシュからのコードが含まれます。

```sh
tuist test --coverage-output-path coverage
```

各実行は`coverage/<result bundle name>.lcov`を書き出します。シャーディングされた実行のファイルは`lcov -a`でマージしてください。このオプションにはカバレッジアップロードが有効である必要があります。

Xcode独自のカバレッジレポートおよびそれを読み取るツールは、その実行中にXcodeがビルドしたターゲットのみを含み、バイナリキャッシュからのコードは決して含みません。Tuistのアップロードは両方を計測します。Xcodeのレポートで特定ターゲットのカバレッジを確認したい場合は、そのターゲットをソースからビルドするようにプロジェクトを生成してください。`tuist generate MyTarget`は`MyTarget`をソースとして保持し、残りはキャッシュから取得します。

## カバレッジのクエリ {#querying}

`tuist coverage`コマンドは、ダッシュボードに表示される内容を読み取ります。`--commit`がない場合、`--branch`またはデフォルトブランチの最新の完全なコミットを読み取ります。

```sh
tuist coverage show                          # the project's coverage and its targets
tuist coverage files --commit <sha>          # files, least covered first
tuist coverage file Sources/Cart.swift --lines  # a file's functions, with per-line counts
```

すべてスクリプト用に`--json`を受け付けます。同じデータは、<.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocolサーバー</.localized_link>を通じてエージェントからも利用可能です。
