# 生成されたXcodeプロジェクト {#generated-xcode-project-code-coverage}

<!-- @snippet: ./_xcode-early-access -->

コードカバレッジは、テストが実行したコードの行を示します。Tuistは`tuist test`の実行ごとにラインカバレッジをアップロードし、コミット内のすべての実行をプロジェクト全体、各ターゲット、各ファイルについて1つの数値に集約します。ダッシュボードの**コードカバレッジ**ページでは、コミットごとの値とブランチごとの推移を表示します。

Tuistが処理をスキップしても、この数値は正確さを保ちます。<.localized_link href="/guides/features/cache/module-cache">バイナリキャッシュ</.localized_link>から取得したターゲットはカバレッジカウンター付きでビルドされるため、ソースからビルドした場合と同様にコードが計測されます。また、<.localized_link href="/guides/features/selective-testing/generated-xcode-project">選択的テスト</.localized_link>でテストターゲットがスキップされた場合、そのターゲットは以前の[ターゲットレベルのカバレッジ](#target-level-coverage)を保持します。これはTuistが各実行時に記録するものです。

## セットアップ {#setup}

### カバレッジを有効にする {#turn-coverage-on}

`Tuist.swift`の生成オプションでカバレッジを有効にし、デフォルトでは無効になっているカバレッジのアップロードもオンにしてください。

```swift
import ProjectDescription

let tuist = Tuist(
    testInsights: .testInsights(coverage: .coverage(upload: true)),
    project: .tuist(
        generationOptions: .options(
            coverage: .coverage(enabled: true)
        )
    )
)
```

生成オプションがオンの場合：

- Tuistが生成するすべてのスキームのテストアクションはカバレッジを収集します。また、`coverage`を設定せずに定義したスキームのテストアクションも同様です。`.options(coverage: false)`または`.options(coverage: true)`を持つスキームは、その設定値を維持します。テストプランはカバレッジを独自に決定します。Tuistが生成するテストプランの場合、`.testPlans(_:coverage:)`に`coverage: true`を渡してください。
- プロジェクト独自のターゲットは、Debug構成においてカバレッジカウンター付きでバイナリキャッシュから読み込まれ、ウォームアップされます。詳細は[仕組み](#instrumented-binaries)をご覧ください。

`TUIST_COVERAGE_ENABLED`および`TUIST_COVERAGE_UPLOAD`環境変数（`1`または`0`）は、`enabled`および`upload`の設定よりも優先されます。単一のコマンドではなく、CIワークフローなどの環境全体に対して設定し、キャッシュをウォームアップするコマンドと読み取るコマンドの間で一貫性を保ってください。

> [!IMPORTANT] KEEP THE VALUE THE SAME EVERYWHERE
> 生成オプションは、プロジェクトのターゲットのキャッシュキーとテストターゲットの選択的テスト用ハッシュを変更します。キャッシュを共有するすべてのマシンで同じ値を使用し、環境（例えば`Environment.isCI`）から導出しないようにしてください。カバレッジが無効な実行は、カバレッジが有効な実行のバイナリや選択的テストの結果を再利用しません。

### スキームを除外する {#leave-schemes-out}

一部のスーツはカバレッジの対象外とするべきです。例えば、別のプロセスからアプリやCLIを操作する受け入れテストやエンドツーエンドテストは、カバレッジツールが検知できないコードを実行するため、収集しても低速化するだけです。それらのスキームのテストアクションでカバレッジを無効にしてください。

```swift
.scheme(
    name: "AcceptanceTests",
    testAction: .targets(
        ["AcceptanceTests"],
        options: .options(coverage: false)
    )
)
```

`Tuist.swift`オプションや`TUIST_COVERAGE_ENABLED`の設定に関わらず、このスキームはカバレッジを無効のまま維持し、その実行結果はコミットのカバレッジに含まれません。カバレッジはスキーム単位で収集されるため、特定のテストターゲットを除外するには、それを専用のスキームに移してください。

### テストを実行する {#run-your-tests}

通常通り、`tuist test`を使用してテストを実行してください。

```sh
tuist test
```

Tuistは、テスト結果とともに実行中に収集されたカバレッジをアップロードします。これには<.localized_link href="/guides/features/test-sharding/generated-xcode-project">シャーディング実行</.localized_link>や、`--without-building`を使用して別のジョブでビルドされた製品をテストする実行が含まれます。フォークからのプルリクエストを実行するジョブなど、Tuistへのカバレッジ送信を防ぎたい場合は、`TUIST_COVERAGE_UPLOAD=0`を設定してください。

### CI上で各コミットを完了させる {#complete-each-commit}

コミットのカバレッジは、スキーム、シャード、プラットフォームごとに分かれた複数のジョブから寄せられることがよくあります。Tuistは最後に報告されたジョブを自動で検知できないため、明示的に通知する必要があります。コミットに関連するすべてのテストジョブが終了したら、それらすべてに依存するジョブで次のコマンドを実行してください。

```sh
tuist coverage complete
```

このコマンドはチェックアウトまたはCIプロバイダーからコミットを読み取ります。別のコミットを指定するには`--commit <sha>`を渡してください。コミットが完了するまで、そのカバレッジは**進行中**として表示され、ブランチの推移には含まれません。

### デフォルトブランチで全スイートを実行する {#full-runs}

> [!IMPORTANT] SET UP A FULL RUN
> 選択的テストは、スキップされたターゲットのカバレッジを引き継ぐための以前の実行が存在する場合にのみ、コミットのカバレッジを完全な状態に保つことができます。デフォルトブランチでは、選択的テストなしで全テストを実行するスケジュールを設定してください。
>
> ```sh
> tuist test --no-selective-testing
> ```
>
> マージごとに1回実行するのが理想的です。変更の少ないリポジトリであれば、毎日または毎週でも十分かもしれません。記録されたカバレッジは90日後に期限切れになるため、それより頻繁に実行してください。

引き継がれたカバレッジは完全な実行に依存しています。完全な実行は、期限切れ前に各ターゲットの記録されたカバレッジを更新し、選択的実行ではビルドされないファイルの最新の状態をTuistに提供します。完全な実行の間に変更が多いリポジトリほど、選択的実行は変更されたファイルを多く発見し、コミットのカバレッジが**不完全**になりやすくなります。

## ターゲットレベルのカバレッジ {#target-level-coverage}

ある実行のカバレッジは、その実行全体で何が実行されたかを示すものであり、各テストターゲットが個別に何を実行したかを示すものではありません。選択的テストでターゲットがスキップされた場合、Tuistはそのターゲットのカバレッジを引き継ぐために、以前の執行でそのターゲットが何を実行したかを知る必要があります。

そのため、Tuistは各実行時に、各テストターゲットが実行したファイルと行も記録します。これはXcodeが各テストプロセス用に書き出すカバレッジデータから読み取られるため、追加のリンクや設定は不要です。この記録はmacOSおよびiOSシミュレーター上で行われ、実機では行われません。UIテストは、操作対象アプリのコードが別プロセスで動作するため、アプリに関する情報を一切記録しません。

## 仕組み {#how-it-works}

### インストルメント済みバイナリ {#instrumented-binaries}

バイナリキャッシュからのターゲットは事前ビルドされたバイナリであり、テスト実行はそのバイナリがカバレッジカウンター付きでビルドされている場合にのみコードを計測できます。カバレッジが有効な場合、バイナリキャッシュはプロジェクト独自のターゲットのインストルメント済みバリアントを保持し、すべてのコマンドがそのバリアントを読み取り、ウォームアップします。

- **Debug構成**はインストルメント済みバリアントを使用します。`tuist cache`がこれをウォームアップし、`tuist generate`および`tuist test`がこれを読み取ります。
- **Release構成**は常にプレーンなバリアントを使用するため、配布物にカバレッジカウンターが含まれることはありません。
- **外部パッケージ**は常にプレーンなバリアントを使用します。Tuistはリポジトリ内のコードのみを計測します。

テストジョブと同じ環境でカバレッジを有効にしてキャッシュをウォームアップし、`tuist test`がインストルメント済みバイナリを見つけられるようにしてください。実行がカバレッジを収集しようとしても、キャッシュからプレーンなバイナリとしてターゲットを取得した場合、Tuistは警告を発し、そのコードは計測されません。詳細は<.localized_link href="/guides/features/cache/module-cache#code-coverage">モジュールキャッシュ</.localized_link>をご覧ください。

### マシン間でのパス {#paths-across-machines}

インストルメント済みバイナリは、ビルド時のチェックアウトに対する相対パスでソースパスを記録するため、CIでウォームアップされたバイナリは、どの開発者のマシンでも正しいファイルを計測します。

<.localized_link href="/guides/features/cache/xcode-cache">Xcodeキャッシュ</.localized_link>もプレフィックスマッピングを通じて同様に動作しますが、Xcode自体のカバレッジレポートはマッピングされたパスを解決できないため、Tuistはカバレッジを収集するビルドでこれをデフォルトで無効にします。Xcode 27以降では、`enableCaching`が有効な場合、`prefixMapping: true`によってこれが維持され、カバレッジビルド間でチェックアウトをまたいでコンパイル結果が共有されます。

```swift
.options(coverage: .coverage(enabled: true, prefixMapping: true))
```

Tuistのアップロードはマッピングされたパスを解決しますが、Xcodeのカバレッジレポートや`xccov`ではそれらのファイルが除外される場合があります。詳細は<.localized_link href="/guides/features/cache/xcode-cache#coverage-with-prefix-mapping">プレフィックスマッピングによるカバレッジ</.localized_link>をご覧ください。

### スキップされたテスト {#skipped-tests}

選択的テストは、以前の成功した実行が同じハッシュですでにテスト済みの場合、そのテストターゲットをスキップします。このハッシュはターゲットのソース、そのテスト、およびすべての依存関係を含むため、同じハッシュは同じコードに対する同じテストを意味します。Tuistは、以前の実行がそのターゲットに対して記録した[ターゲットレベルのカバレッジ](#target-level-coverage)を再利用します。もし記録されていなかった場合（例えば、当時カバレッジが無効だったか、実行が90日以上前である場合）、引き継ぐデータがなく、コミットは**不完全**となります。

選択的実行はすべてのファイルをビルドするわけではありません。コンパイルしなかったファイルについては、ファイルがその後変更されていない限り、Tuistは直近の以前の完全実行から行数を取得します。これが、デフォルトブランチでの[完全実行](#full-runs)が重要な理由です。

`--skip-test-targets`または`-skip-testing`を使用して自分でスキップしたテストは引き継がれません。それらのテストを実行しなかったコミットは、そのコミットの別の実行でテストされない限り、**不完全**となります。検疫によってスキップされたテストはカバレッジに含まれません。Tuistはこれらを引き継がず、そのためコミットを**不完全**ともマークしません。

### 完全および不完全なコミット {#commit-status}

ダッシュボード上の各コミットにはステータスがあります。

| ステータス | 意味 |
| --- | --- |
| 進行中 | 実行がカバレッジを報告していますが、`tuist coverage complete`がまだそのコミットに対して実行されていません。 |
| 完了 | コミットのスキームにおけるすべてのテストが実行されたか、引き継がれました。 |
| 不完全 | 一部のカバレッジを特定できなかったため、数値は下限値となります。 |
| 未計測 | コミットに対してカバレッジを報告した実行がありません。 |

ブランチのトレンドには完全なコミットのみが含まれます。コミットが不完全になるのは、例えば以下の場合です。

- 選択的テストが引き継げないターゲットをスキップした場合：以前の実行でそのターゲットのカバレッジが記録されていなかった、選択的実行がビルドしなかったファイルが最後の完全実行以降に変更された、あるいは`Package.resolved`、`Project.swift`、または`.xcconfig`など、すべてのターゲットに影響するファイルがコミットで変更された。
- 実行が`--skip-test-targets`または`-skip-testing`でテストをスキップし、そのコミットの他の実行でもそれらが実行されなかった場合。
- 実行がバイナリキャッシュからプレーンなバイナリとしてターゲットを取得した場合。
- スキームのすべての実行が`-only-testing`で絞り込まれていた場合。
- スキームのカバレッジが、未コミットの変更があるチェックアウトでのCI実行からのみ得られた場合。

## パフォーマンスへの影響 {#performance-impact}

カバレッジの収集はオーバーヘッドを追加しますが、主にテスト終了後、Xcodeがカバレッジレポートを書き出し、Tuistがカバレッジをエクスポートしている間です。テストのビルドと実行にかかる時間は、カバレッジなしの場合とほぼ同じです。インストルメント済みビルドは、DerivedDataおよびDebugバイナリキャッシュでより多くのディスク容量を消費します。Releaseビルドとアーカイブは影響を受けません。

## 制限事項 {#limitations}

### カバレッジを収集するスキームのReleaseビルド {#release-builds}

スキームのテストアクションがカバレッジを収集する場合、Xcodeはそのスキーム用にソースからコンパイルするターゲットを`xcodebuild build`によってインストルメントします。これはRelease構成を含め、あらゆる構成に適用されます。`xcodebuild archive`はこの設定を無視するため、アーカイブはインストルメントされません。アーカイブを配布するか、`.options(coverage: false)`を持つスキームからRelease製品をビルドしてください。

### その他のカバレッジツール {#other-coverage-tools}

`-enableCodeCoverage YES`は、Xcodeと同様に、実行がカバレッジを収集するかどうかを決定するだけです。これはTuistにキャッシュからインストルメント済みバイナリを読み取らせるものではないため、代わりに`Tuist.swift`オプションまたは`TUIST_COVERAGE_ENABLED`を使用してください。

他のカバレッジツールにデータを提供するには、`tuist test`に各実行のカバレッジをLCOV形式で書き出させます。これはTuistがアップロードするカバレッジと同じもので、リポジトリ相対パスとバイナリキャッシュからのコードが含まれています。

```sh
tuist test --coverage-output-path coverage
```

各実行は`coverage/<result bundle name>.lcov`を書き出します。シャーディングされた実行のファイルは`lcov -a`でマージしてください。このオプションにはカバレッジアップロードが有効である必要があります。

Xcode自体のカバレッジレポートおよびそれを読み取るツールは、その実行中にXcodeがビルドしたターゲットのみを含み、バイナリキャッシュから来たコードは決して含みません。Tuistのアップロードは両方を計測します。Xcodeのレポートでターゲットのカバレッジを確認したい場合は、そのターゲットをソースからビルドするようにプロジェクトを生成してください。`tuist generate MyTarget`は`MyTarget`をソースとして保持し、残りはキャッシュから取得します。

## カバレッジのクエリ {#querying}

`tuist coverage`コマンドは、ダッシュボードに表示される内容を読み取ります。`--commit`がない場合、これらは`--branch`またはデフォルトブランチの最新の完全なコミットを読み取ります。

```sh
tuist coverage show                          # the project's coverage and its targets
tuist coverage files --commit <sha>          # files, least covered first
tuist coverage file Sources/Cart.swift --lines  # a file's functions, with per-line counts
```

すべてがスクリプト用に`--json`を受け入れます。同じデータは、<.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocolサーバー</.localized_link>を通じてエージェントでも利用可能です。
