# Rust のコードカバレッジ {#rust-code-coverage}

コードカバレッジは、テストが実行したコードの行を示します。Tuist は LLVM のソースベースのカバレッジを使用して `cargo test` 実行ごとの行カバレッジを測定し、コミット内のすべての実行をプロジェクト、各パッケージ、および各ファイルごとに 1 つの数値に集約します。ダッシュボードの **コードカバレッジ** ページでは、コミットごとおよび各ブランチのトレンドとして表示されます。

> [!IMPORTANT]
> **要件**
>
> - <.localized_link href="/guides/get-started/rust-project">Rust プロジェクトのセットアップ</.localized_link> に従ってください
> - Rust ツールチェーンの LLVM ツール (`llvm-tools`)。Tuist は rustup が管理するツールチェーンにこれらをインストールします。
> - Git リポジトリ内にあるプロジェクト

## セットアップ {#setup}

### カバレッジを有効にする {#turn-coverage-on}

ワークスペースのルート `Cargo.toml` に以下を追加してください:

```toml
[workspace.metadata.tuist.test_insights.coverage]
upload = true
```

代わりに `tuist.toml` で Tuist を設定している場合は、そこに `[test_insights.coverage]` と `upload = true` を追加してください。

その後、通常どおりテストを実行してください:

```sh
tuist cargo test --workspace
```

Tuist はリポジトリのクレートを `-C instrument-coverage` でビルドし、テストを実行して、実行のテスト結果とともにカバレッジをアップロードします。テストの出力と終了コードは変わりません。単一の実行で設定を上書きするには、`TUIST_COVERAGE_UPLOAD=1` または `TUIST_COVERAGE_UPLOAD=0` を設定してください。

カバレッジは、Tuist がカバレッジを収集する各実行と一緒にアップロードする Git 履歴に依存しており、これによりコミットがそのブランチ上に配置されます。Git リポジトリ外での実行では、テスト結果はアップロードされますが、カバレッジはアップロードされません。

### 分割された実行 {#sharded-runs}

<.localized_link href="/guides/features/test-sharding/rust">テストを分割</.localized_link> する場合、カバレッジを有効にして実行される各シャードは独自のターゲットのカバレッジを報告し、Tuist は実行のシャードを 1 つの数値にマージします。シャードは意図的にスイートの一部を実行するため、コミットのカバレッジが不完全になることはありません。

### CI で各コミットを完了させる {#complete-each-commit}

コミットのカバレッジは多くの場合、複数のジョブから得られます。シャードごとまたは機能セットごとに 1 つずつです。Tuist は最後のジョブがいつ報告したかを判断できないため、明示的に通知する必要があります。コミットのすべてのテストジョブが完了したら、それらすべてに依存するジョブで以下を実行してください:

```sh
tuist cargo coverage-complete
```

このコマンドはチェックアウトからコミットを読み取るか、プルリクエストで CI プロバイダーが報告するコミットを使用します。別のコミットを指定するには `--commit <sha>` を渡してください。コミットが完了するまで、そのカバレッジは **進行中** と表示され、ブランチのトレンドには含まれません。

## 動作原理 {#how-it-works}

### Tuist が測定するもの {#what-tuist-measures}

- **パッケージ。** 各 Cargo パッケージはダッシュボード上のターゲットとなり、独自のカバレッジを持ちます。
- **製品コードのみ。** 統合テスト、ベンチマーク、および例 (`tests/`、`benches/`、`examples/` ディレクトリ、およびそれらの種類のターゲット) はテストコードです。Tuist はこれらを保存しますが、すべての数値からは除外します。`#[cfg(test)]` モジュール内のユニットテストはソースファイルの一部であるため、`cargo llvm-cov` と同様に、その行もカウントされます。
- **関数。** 各行は、その直上で始まる最も近い関数に属します。ジェネリック関数は、インスタンス化された型の数に関係なく 1 回としてカウントされます。
- **Doctests** は通常どおり実行されますが、測定されません。

Tuist は、後でカバレッジベースのテスト選択を行うために、各テストバイナリが実行したコードも記録します。`cargo test` はバイナリのテストを 1 つのプロセスで実行するため、その記録は個々のテストではなくバイナリ全体に属します。

### スキップされたテスト {#skipped-tests}

実行自体の引数によってテストが除外される場合 (テスト名フィルター、`--skip`、`--ignored`、`-p`、`--exclude`、`--lib`、または `--test` など)、何も除外しない別のコミットの実行も行われていない限り、コミットのカバレッジは **不完全** となります。すべてのテストバイナリが実行される前に `cargo test` を停止させる失敗も同じ効果をもたらします。残りのバイナリの実行を継続するには `--no-fail-fast` を追加してください。

意図的に除外され、コミットを不完全にしないテストもあります:

- **<.localized_link href="/guides/features/test-insights/flaky-tests/rust">検疫</.localized_link> によってスキップされるテスト。** これらは削除されたかのように除外されるため、これらだけがカバーしていた行は未カバーとしてカウントされます。
- **他のシャードのターゲット** (テストを分割する場合)
- **無視されたテスト** (`#[ignore]`)。デフォルトでは実行されません。

### 完了したコミットと不完全なコミット {#commit-status}

ダッシュボード上の各コミットにはステータスがあります:

| ステータス | 意味 |
| --- | --- |
| 進行中 | 実行がカバレッジを報告していますが、`tuist cargo coverage-complete` がまだコミットに対して実行されていません。 |
| 完了 | コミットの実行におけるすべてのテストが実行されたか、意図的に除外されました。 |
| 不完全 | 一部のカバレッジを特定できなかったため、数値は下限となります。 |
| 未測定 | コミットに対してカバレッジを報告した実行がありません。 |

ブランチのトレンドには、完了したコミットのみが含まれます。

## パフォーマンスへの影響 {#performance-impact}

インストルメントされたコードの実行は若干遅くなります。Tuist はリポジトリ内のクレートのみをインストルメントします。依存関係は通常のビルドと同様にビルドされ、キャッシュから提供されます。Tuist は独自のクレートの両方のバリアントを target ディレクトリに保持するため、カバレッジありとなしの実行を切り替えても、コードが変更されていない限り再ビルドされません。

## 制限事項 {#limitations}

- **ターゲット固有の `rustflags` を持つカスタム `rustc-wrapper`。** プロジェクトが独自の `rustc-wrapper` を設定している場合、Tuist は代わりに Cargo の `build.rustflags` に `-C instrument-coverage` を追加します。Cargo 設定ファイル内の `target.<triple>.rustflags` エントリがこれらを置き換えるため、そこにフラグを自分で追加してください。テストがカバレッジを書き込まなかった実行では、その旨が報告されます。
- **設定されたターゲットランナー。** Tuist は独自のランナーを介してテストバイナリを開始します。Cargo 設定ファイル内の `target.<triple>.runner` がこれを置き換えます。実行のカバレッジは引き続きアップロードされますが、Tuist はどのテストバイナリが何を実行したかを識別できません。`CARGO_TARGET_<TRIPLE>_RUNNER` 環境変数を通じて設定されたランナーは引き続き機能します。
- **フォークからのプルリクエストからはカバレッジを取得できません。** カバレッジは Tuist で認証された実行によってのみアップロードされ、CI は通常、フォークから開かれたプルリクエストからシークレットや ID トークンを除外します。

## カバレッジのクエリ {#querying}

ダッシュボードの **コードカバレッジ** ページには、各コミットの図、パッケージ、ファイル、および各ファイルが保持する関数が表示されます。同じデータは、<.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocol サーバー</.localized_link> を介してエージェントからも利用できます。
