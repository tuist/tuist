# Rustのコードカバレッジ {#rust-code-coverage}

コードカバレッジは、テストがコードのどの行を実行したかを示します。TuistはLLVMのソースベースのカバレッジを使用して、すべての `cargo test` 実行の行カバレッジを測定し、コミットの実行結果をプロジェクト、各パッケージ、各ファイルごとに1つの数値に集約します。ダッシュボードの **コードカバレッジ** ページでは、コミットごとの結果と各ブランチのトレンドを表示します。

> [!IMPORTANT]
> **要件**
>
> - <.localized_link href="/guides/get-started/rust-project">Rustプロジェクトのセットアップ</.localized_link> に従ってください
> - RustツールチェーンのLLVMツール（`llvm-tools`）。Tuistはrustupが管理するツールチェーンにこれらをインストールします。
> - Gitリポジトリ内のプロジェクト

## セットアップ {#setup}

### カバレッジを有効にする {#turn-coverage-on}

ワークスペースのルート `Cargo.toml` に以下を追加してください：

```toml
[workspace.metadata.tuist.test_insights.coverage]
upload = true
```

代わりに `tuist.toml` でTuistを設定している場合は、そこに `[test_insights.coverage]` と `upload = true` を追加してください。

その後、通常通りテストを実行します：

```sh
tuist cargo test --workspace
```

Tuistはリポジトリのクレートを `-C instrument-coverage` でビルドし、テストを実行して、実行のテスト結果とともにカバレッジをアップロードします。テストの出力と終了コードは変更されません。単一の実行で設定を上書きするには、`TUIST_COVERAGE_UPLOAD=1` または `TUIST_COVERAGE_UPLOAD=0` を設定します。

カバレッジは、Tuistが収集する各実行と一緒にアップロードするGit履歴に依存しており、これによりコミットがそのブランチに配置されます。Gitリポジトリ外での実行は、テスト結果をアップロードしますが、カバレッジはアップロードしません。

### 分割された実行 {#sharded-runs}

<.localized_link href="/guides/features/test-sharding/rust">テストを分割</.localized_link> すると、カバレッジを有効にして実行される各シャードが自身のターゲットのカバレッジを報告し、Tuistは実行のシャードを1つの数値に統合します。シャードは意図的にスイートの一部を実行するため、コミットのカバレッジが不完全になることはありません。

### CIで各コミットを完了させる {#complete-each-commit}

コミットのカバレッジは、多くの場合、複数のジョブ（シャードごとまたは機能セットごと）から得られます。Tuistは最後に報告されたジョブを自動で検出できないため、明示的に指示する必要があります。コミットのすべてのテストジョブが終了したら、それらすべてに依存するジョブで以下を実行します：

```sh
tuist cargo coverage-complete
```

このコマンドはチェックアウトからコミットを読み取るか、CIプロバイダーがプルリクエストで報告するコミットを使用します。別のコミットを指定するには `--commit <sha>` を渡します。コミットが完了するまで、そのカバレッジは **進行中** と表示され、ブランチのトレンドには含まれません。

## 仕組み {#how-it-works}

### Tuistが測定するもの {#what-tuist-measures}

- **パッケージ。** 各Cargoパッケージはダッシュボード上のターゲットとなり、独自のカバレッジを持ちます。
- **製品コードのみ。** 統合テスト、ベンチマーク、および例（`tests/`、`benches/`、`examples/` ディレクトリ、およびそれらの種類のターゲット）はテストコードです。Tuistはこれらを保存しますが、すべての数値からは除外します。`#[cfg(test)]` モジュール内のユニットテストはソースファイルの一部であるため、`cargo llvm-cov` の場合と同様に、その行もカウントされます。
- **関数。** 各行は、その直上で始まる関数に属します。ジェネリック関数は、いくつの型でインスタンス化されていても1回としてカウントされます。
- **Doctest** は通常通り実行されますが、測定されません。

Tuistは、後でカバレッジベースのテスト選択を行うために、各テストバイナリが実行したコードも記録します。`cargo test` はバイナリのテストを1つのプロセスで実行するため、その記録は個々のテストではなく、バイナリ全体に属します。

### スキップされたテスト {#skipped-tests}

実行自体の引数（テスト名フィルター、`--skip`、`--ignored`、`-p`、`--exclude`、`--lib`、または `--test` など）によってテストが除外される場合、何も除外せずに実行された別のコミットの実行がない限り、コミットのカバレッジは **不完全** となります。すべてのテストバイナリが実行される前に `cargo test` が停止するような失敗も同様の影響を与えます。残りのバイナリの実行を継続するには `--no-fail-fast` を追加してください。

意図的に除外され、コミットを不完全にしないテストもあります：

- **<.localized_link href="/guides/features/test-insights/flaky-tests/rust">隔離</.localized_link> によってスキップされるテスト。** これらは削除されたものとして扱われるため、これらだけがカバーしていた行は未カバーとしてカウントされます。
- **他のシャードのターゲット**（テストを分割した場合）。
- **無視されたテスト**（`#[ignore]`）。デフォルトでは実行されません。

### 完了および不完全なコミット {#commit-status}

ダッシュボード上の各コミットにはステータスがあります：

| ステータス | 意味 |
| --- | --- |
| 進行中 | 実行からカバレッジが報告されていますが、`tuist cargo coverage-complete` がまだそのコミットに対して実行されていません。 |
| 完了 | コミットの実行におけるすべてのテストが実行されたか、意図的に除外されました。 |
| 不完全 | 一部のカバレッジを特定できなかったため、数値は下限となります。 |
| 未測定 | コミットに対してカバレッジを報告した実行がありません。 |

ブランチのトレンドには完了したコミットのみが含まれます。

## パフォーマンスへの影響 {#performance-impact}

インストルメント化されたコードは若干遅くなります。Tuist はリポジトリ内のクレートのみをインストルメント化します。依存関係は通常のビルドと同様にビルドされ、キャッシュから引き続き取得されます。Tuist は独自のクレートの両方のバリアントを target ディレクトリに保持するため、カバレッジありとなしの実行を切り替えても、コードが変更されていない限り再ビルドされません。

## 制限事項 {#limitations}

- **ターゲット固有の `rustflags` を使用するカスタム `rustc-wrapper`。** プロジェクトが独自の `rustc-wrapper` を設定している場合、Tuist は代わりに Cargo の `build.rustflags` に `-C instrument-coverage` を追加します。Cargo 設定ファイル内の `target.<triple>.rustflags` エントリがこれらを置き換えるため、そこにフラグを自分で追加してください。テストでカバレッジデータが書き込まれなかった実行はその旨を報告します。
- **設定されたターゲットランナー。** Tuist は独自のランナーを通じてテストバイナリを開始します。Cargo 設定ファイル内の `target.<triple>.runner` がこれを置き換えます。実行のカバレッジは引き続きアップロードされますが、Tuist はどのテストバイナリが何を実行したかを識別できません。`CARGO_TARGET_<TRIPLE>_RUNNER` 環境変数で設定されたランナーは引き続き動作します。
- **フォークからのプルリクエストからはカバレッジを取得できません。** カバレッジは Tuist で認証された実行によってのみアップロードされ、CI は通常、フォークから開かれたプルリクエストからシークレットや ID トークンを withholding します。

## カバレッジのクエリ {#querying}

ダッシュボードの **コードカバレッジ** ページには、各コミットの図、パッケージ、ファイル、および各ファイルに含まれる関数が表示されます。同じデータは、<.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocol サーバー</.localized_link> を介してエージェントからも利用できます。
