# Rustのコードカバレッジ {#rust-code-coverage}

コードカバレッジは、テストがコードのどの行を実行したかを示します。Tuistは、LLVMのソースベースのカバレッジを使用して `cargo test` の各行のカバレッジを測定し、コミット内の実行結果をプロジェクト、各パッケージ、および各ファイルごとに1つの数値に集約します。ダッシュボードの **コードカバレッジ** ページでは、コミットごとの値と各ブランチの推移を表示します。

> [!IMPORTANT]
> **要件**
>
> - <.localized_link href="/guides/get-started/rust-project">Rustプロジェクトのセットアップ</.localized_link> に従ってください
> - RustツールチェーンのLLVMツール（`llvm-tools`）。Tuistは、rustupが管理するツールチェーンにこれらをインストールします。
> - Gitリポジトリにあるあなたのプロジェクト

## セットアップ {#setup}

### カバレッジを有効にする {#turn-coverage-on}

ワークスペースのルート `Cargo.toml` にこれを追加してください：

```toml
[workspace.metadata.tuist.test_insights.coverage]
upload = true
```

代わりに `tuist.toml` でTuistを設定している場合は、そこに `[test_insights.coverage]` と `upload = true` を追加してください。

その後、通常通りにテストを実行します：

```sh
tuist cargo test --workspace
```

Tuistはリポジトリのクレートを `-C instrument-coverage` でビルドし、テストを実行して、その実行のテスト結果とともにカバレッジをアップロードします。テストの出力と終了コードは変化しません。単一の実行に対して設定を上書きするには、`TUIST_COVERAGE_UPLOAD=1` または `TUIST_COVERAGE_UPLOAD=0` を設定します。

カバレッジは、Tuistが収集する各実行と一緒にアップロードするGit履歴に依存しており、これによりコミットがそのブランチ上に配置されます。Gitリポジトリ外での実行は、テスト結果をアップロードしますが、カバレッジはアップロードしません。ブランチではなくコミットのチェックアウトから実行した場合、ブランチが存在せず、コミットもブランチ上に配置されません。Tuistが認識しないCIシステム上では、<.localized_link href="/guides/features/test-insights/rust#continuous-integration">継続的インテグレーション</.localized_link> で説明されているように、`TUIST_GIT_BRANCH` でブランチ名を指定してください。

### 分割された実行 {#sharded-runs}

<.localized_link href="/guides/features/test-sharding/rust">テストを分割</.localized_link> する場合、カバレッジを有効にして実行される各シャードは独自のターゲットのカバレッジを報告し、Tuistは1回の実行におけるシャードを1つの数値に統合します。シャードは意図的にスイートの一部を実行するため、コミットのカバレッジが不完全になることはありません。

### CI上で各コミットを完了させる {#complete-each-commit}

コミットのカバレッジは、多くの場合、複数のジョブ（シャードごとまたは機能セットごと）から得られます。Tuistは最後に報告されたジョブを自動で検出できないため、明示的に通知する必要があります。コミットに対するすべてのテストジョブが終了したら、それらすべてに依存するジョブで次を実行します：

```sh
tuist coverage complete
```

このコマンドは、チェックアウトの `HEAD` （テストが実行されたコミット）からコミットを読み取ります。別のコミットを指定するには `--commit <sha>` を渡してください。コミットが完了するまで、そのカバレッジは **進行中** と表示され、ブランチの推移には含まれません。

## 仕組み {#how-it-works}

### Tuistが測定するもの {#what-tuist-measures}

- **パッケージ。** 各Cargoパッケージはダッシュボード上のターゲットとなり、独自のカバレッジを持ちます。
- **製品コードのみ。** 統合テスト、ベンチマーク、および例（`tests/`、`benches/`、および `examples/` ディレクトリ、およびそれらの種類のターゲット）はテストコードです。Tuistはこれらを保存しますが、あらゆる数値からは除外します。`#[cfg(test)]` モジュール内のユニットテストはソースファイルの一部であるため、`cargo llvm-cov` と同様に、その行もカウントされます。
- **関数。** 各行は、その直上から始まる最も近い関数に属します。ジェネリック関数は、いくつの型でインスタンス化されていても1回としてカウントされます。
- **ドックテスト** は通常通り実行されますが、測定されません。

Tuistは、後でカバレッジベースのテスト選択を行うために、各テストバイナリが実行したコードも記録します。`cargo test` はバイナリのテストを1つのプロセスで実行するため、その記録は個々のテストではなく、バイナリ全体に属します。

### スキップされたテスト {#skipped-tests}

実行自体の引数（テスト名フィルター、`--skip`、`--ignored`、`-p`、`--exclude`、`--lib`、または `--test` など）によってテストが除外される場合、何も除外せずに実行された別のコミットの実行がない限り、そのコミットのカバレッジは **不完全** となります。すべてのテストバイナリが実行される前に `cargo test` が停止するような失敗も同じ影響を与えます。残りのバイナリの実行を継続するには `--no-fail-fast` を追加してください。

意図的に除外され、コミットを不完全にしないテストもあります：

- **<.localized_link href="/guides/features/test-insights/flaky-tests/rust">隔離</.localized_link> によってスキップされるテスト。** これらは削除されたものとして扱われるため、これらだけがカバーしていた行は未カバーとしてカウントされます。
- **他のシャードのターゲット**（テストを分割する場合）。
- **無視されたテスト**（`#[ignore]`）。デフォルトでは実行されません。

### 未コミットの変更 {#uncommitted-changes}

追跡対象ファイルに未コミットの変更があるチェックアウトからの実行は、そのコミットのものではないコードを測定するため、そのカバレッジはコミットにカウントされません。実行時に警告が表示され、変更されたファイルが一覧表示されます。CIジョブがソースの隣に書き込むファイル（ビルド出力やカバレッジレポートなど）は、Gitが追跡していない限り変更としてカウントされません。そのような実行のみがコミットを測定した場合、そのカバレッジは **不完全** となり、`tuist coverage complete` がその理由を示します。

### 完了したコミットと不完全なコミット {#commit-status}

ダッシュボード上の各コミットにはステータスがあります：

| ステータス | 意味 |
| --- | --- |
| 進行中 | 実行からカバレッジが報告されていますが、`tuist coverage complete` がそのコミットに対してまだ実行されていません。 |
| 完了 | コミットの実行に含まれるすべてのテストが実行されたか、意図的に除外されました。 |
| 不完全 | 一部のカバレッジを特定できなかったため、数値は下限となります。 |
| 未測定 | コミットに対してカバレッジを報告した実行がありません。 |

ブランチのトレンドには、完了したコミットのみが含まれます。

## パフォーマンスへの影響 {#performance-impact}

インストルメント化されたコードは若干遅く実行されます。Tuist はリポジトリ内のクレートのみをインストルメント化します。依存関係は通常のビルドと同様にビルドされ、キャッシュから引き続き提供されます。Tuist は独自のクレートの両方のバリエーションを target ディレクトリに保持するため、カバレッジありとなしの実行を切り替えても、コードが変更されていない限り再ビルドされません。

## 制限事項 {#limitations}

- **ターゲット固有の `rustflags` を持つカスタム `rustc-wrapper`。** プロジェクトが独自の `rustc-wrapper` を設定している場合、Tuist は代わりに Cargo の `build.rustflags` に `-C instrument-coverage` を追加します。Cargo 設定ファイル内の `target.<triple>.rustflags` エントリはこれらを置き換えるため、そこにフラグを自分で追加してください。テストがカバレッジを書き込まなかった実行では、その旨が表示されます。
- **設定されたターゲットランナー。** Tuist は独自のランナーを介してテストバイナリを開始します。Cargo 設定ファイル内の `target.<triple>.runner` がこれを置き換えます。実行のカバレッジは引き続きアップロードされますが、Tuist はどのテストバイナリが何を実行したかを識別できません。`CARGO_TARGET_<TRIPLE>_RUNNER` 環境変数を通じて設定されたランナーは機能し続けます。
- **フォークからのプルリクエストからはカバレッジを取得できません。** カバレッジは Tuist で認証された実行によってのみアップロードされ、CI は通常、フォークから開かれたプルリクエストからシークレットや ID トークンを withheld します。

## カバレッジのクエリ {#querying}

ダッシュボードの **コードカバレッジ** ページには、各コミットの数値、そのパッケージ、ファイル、および各ファイルが保持する関数が表示されます。同じデータは、<.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocol サーバー</.localized_link> を介してエージェントからも利用可能です。
