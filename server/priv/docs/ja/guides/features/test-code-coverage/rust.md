# Rustのコードカバレッジ {#rust-code-coverage}

コードカバレッジは、テストが実行したコードの行を示します。Tuistは、LLVMのソースベースのカバレッジを使用して `cargo test` の各行のカバレッジを測定し、コミットの複数の実行結果をプロジェクト全体、各パッケージ、各ファイルごとに1つの数値に集約します。ダッシュボードの **コードカバレッジ** ページでは、コミットごとの値と各ブランチの推移を確認できます。

> [!IMPORTANT]
> **要件**
>
> - <.localized_link href="/guides/get-started/rust-project">Rustプロジェクトのセットアップ</.localized_link> に従ってください
> - RustツールチェーンのLLVMツール（`llvm-tools`）。Tuistは、rustupが管理するツールチェーンにこれらをインストールします。
> - Gitリポジトリ内のプロジェクト

## セットアップ {#setup}

### カバレッジを有効にする {#turn-coverage-on}

ワークスペースのルートにある `Cargo.toml` に以下を追加してください：

```toml
[workspace.metadata.tuist.test_insights.coverage]
upload = true
```

代わりに `tuist.toml` でTuistを設定している場合は、そこに `[test_insights.coverage]` と `upload = true` を追加してください。

その後、通常通りテストを実行します：

```sh
tuist cargo test --workspace
```

Tuistはリポジトリのクレートを `-C instrument-coverage` でビルドし、テストを実行して、その実行のテスト結果とともにカバレッジをアップロードします。テストの出力と終了コードは変更されません。単一の実行に対して設定を上書きするには、`TUIST_COVERAGE_UPLOAD=1` または `TUIST_COVERAGE_UPLOAD=0` を設定します。

カバレッジは、Tuistが各収集実行時にアップロードするGit履歴に依存しており、これによりコミットがそのブランチ上に配置されます。Gitリポジトリの外での実行は、テスト結果をアップロードしますが、カバレッジはアップロードしません。

### 分割された実行 {#sharded-runs}

<.localized_link href="/guides/features/test-sharding/rust">テストを分割</.localized_link> すると、カバレッジを有効にして実行される各シャードは自身のターゲットのカバレッジを報告し、Tuistはその実行のシャードを1つの数値にマージします。シャードは意図的にスイートの一部のみを実行するため、コミットのカバレッジが不完全になることはありません。

### CIで各コミットを完了させる {#complete-each-commit}

コミットのカバレッジは、多くの場合複数のジョブから生成されます：シャードごとまたは機能セットごとです。Tuistは最後に報告されたジョブを自動検出できないため、明示的に通知する必要があります。コミットに対するすべてのテストジョブが完了したら、それらすべてに依存するジョブで以下を実行します：

```sh
tuist coverage complete
```

このコマンドは、チェックアウトの `HEAD` からコミットを読み取ります。これはテストが実行されたコミットです。別のコミットを指定するには `--commit <sha>` を渡します。コミットが完了するまで、そのカバレッジは **進行中** と表示され、ブランチの推移には含まれません。

## 仕組み {#how-it-works}

### Tuistが測定するもの {#what-tuist-measures}

- **パッケージ。** 各Cargoパッケージはダッシュボード上のターゲットとなり、独自のカバレッジを持ちます。
- **製品コードのみ。** 統合テスト、ベンチマーク、および例（`tests/`、`benches/`、`examples/` ディレクトリ、およびそれらの種類のターゲット）はテストコードです。Tuistはこれらを保存しますが、すべての数値からは除外します。`#[cfg(test)]` モジュール内のユニットテストはソースファイルの一部であるため、`cargo llvm-cov` と同様に、その行もカウントされます。
- **関数。** 各行は、その直上で始まる最も近い関数に属します。ジェネリック関数は、いくつの型でインスタンス化されていても1回だけカウントされます。
- **Doctest** は通常通り実行されますが、測定されません。

Tuistは、後でカバレッジベースのテスト選択を行うために、各テストバイナリが実行したコードも記録します。`cargo test` はバイナリのテストを1つのプロセスで実行するため、その記録は個々のテストではなくバイナリ全体に属します。

### スキップされたテスト {#skipped-tests}

実行自体の引数によってテストが除外される場合（テスト名フィルター、`--skip`、`--ignored`、`-p`、`--exclude`、`--lib`、または `--test` など）、何も除外していないそのコミットの別の実行も行われていない限り、コミットのカバレッジは **不完全** となります。すべてのテストバイナリが実行される前に `cargo test` を停止させる失敗も同じ効果をもたらします。残りのバイナリの実行を継続するには `--no-fail-fast` を追加してください。

意図的に除外され、コミットを不完全にしないテストもあります：

- **<.localized_link href="/guides/features/test-insights/flaky-tests/rust">隔離</.localized_link> によってスキップされるテスト。** これらは削除されたかのように除外されるため、これらだけがカバーしていた行は未カバーとしてカウントされます。
- **他のシャードのターゲット**（テストを分割する場合）
- **無視されたテスト**（`#[ignore]`）。デフォルトでは実行されません。

### 未コミットの変更 {#uncommitted-changes}

追跡対象ファイルに未コミットの変更があるチェックアウトからの実行は、コミットのものではないコードを測定するため、そのカバレッジはコミットにカウントされません。実行は警告を発し、変更されたファイルをリストアップします。CIジョブがソースの隣に書き込むファイル（ビルド出力やカバレッジレポートなど）は、Gitが追跡していない限り変更としてカウントされません。そのような実行のみがコミットを測定した場合、そのカバレッジは **不完全** となり、`tuist coverage complete` がその理由を示します。

### 完了および未完了のコミット {#commit-status}

ダッシュボード上の各コミットにはステータスがあります：

| ステータス | 意味 |
| --- | --- |
| 進行中 | 実行がカバレッジを報告していますが、`tuist coverage complete` がそのコミットに対してまだ実行されていません。 |
| 完了 | コミットの実行に含まれるすべてのテストが実行されたか、意図的に除外されています。 |
| 不完全 | 一部のカバレッジを特定できなかったため、数値は下限値となります。 |
| 未測定 | コミットに対してカバレッジを報告した実行がありません。 |

ブランチのトレンドには完了したコミットのみが含まれます。

## パフォーマンスへの影響 {#performance-impact}

インストルメント化されたコードは若干低速に動作します。Tuist はリポジトリ内のクレートのみをインストルメント化するため、依存関係は通常のビルドと同様にビルドされ、キャッシュから提供されます。Tuist は独自のクレートの両方のバリアントを target ディレクトリに保持するため、コードが変更されていない限り、カバレッジありとなしの実行を切り替えても再ビルドされません。

## 制限事項 {#limitations}

- **ターゲット固有の `rustflags` を持つカスタム `rustc-wrapper`。** プロジェクトが独自の `rustc-wrapper` を設定している場合、Tuist は代わりに Cargo の `build.rustflags` に `-C instrument-coverage` を追加します。Cargo 設定ファイル内の `target.<triple>.rustflags` エントリがこれらを置き換えるため、そこにフラグを自分で追加してください。テストがカバレッジを書き込まなかった実行はその旨を報告します。
- **構成されたターゲットランナー。** Tuist は独自のランナーを介してテストバイナリを開始します。Cargo 設定ファイル内の `target.<triple>.runner` がこれを置き換えます。実行のカバレッジは引き続きアップロードされますが、Tuist はどのテストバイナリが何を実行したかを判別できません。`CARGO_TARGET_<TRIPLE>_RUNNER` 環境変数を通じて設定されたランナーは引き続き機能します。
- **フォークからのプルリクエストからはカバレッジを取得できません。** カバレッジは Tuist で認証された実行によってのみアップロードされ、CI は通常、フォークから開かれたプルリクエストからシークレットや ID トークンを withholding します。

## カバレッジのクエリ {#querying}

ダッシュボードの **コードカバレッジ** ページには、各コミットの数値、パッケージ、ファイル、および各ファイルが保持する関数が表示されます。同じデータは、<.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocol サーバー</.localized_link> を介してエージェントでも利用できます。
