# Rust コードカバレッジ {#rust-code-coverage}

コードカバレッジは、テストが実行したコードの行を示します。Tuist は LLVM のソースベースのカバレッジを使用して `cargo test` の各実行の行カバレッジを測定し、コミットの実行をプロジェクト、各パッケージ、および各ファイルごとに 1 つの数値に集約します。ダッシュボードの **コードカバレッジ** ページでは、コミットごとの数値と各ブランチのトレンドとして表示されます。

> [!IMPORTANT]
> **要件**
>
> - <.localized_link href="/guides/get-started/rust-project">Rust プロジェクトのセットアップ</.localized_link>に従ってください
> - Rust ツールチェーンの LLVM ツール（`llvm-tools`）。Tuist は rustup が管理するツールチェーンにこれらをインストールします。
> - Git リポジトリ内のプロジェクト

## セットアップ {#setup}

### カバレッジを有効にする {#turn-coverage-on}

ワークスペースのルート `Cargo.toml` にこれを追加してください：

```toml
[workspace.metadata.tuist.test_insights.coverage]
upload = true
```

代わりに `tuist.toml` で Tuist を設定している場合は、そこに `[test_insights.coverage]` と `upload = true` を追加してください。

その後、通常通りテストを実行してください：

```sh
tuist cargo test --workspace
```

Tuist はリポジトリのクレートを `-C instrument-coverage` でビルドし、テストを実行して、その実行のテスト結果とともにカバレッジをアップロードします。テストの出力と終了コードは変更されません。単一の実行に対して設定を上書きするには、`TUIST_COVERAGE_UPLOAD=1` または `TUIST_COVERAGE_UPLOAD=0` を設定してください。

カバレッジは、Tuist が収集する各実行と一緒にアップロードする Git ヒストリーに依存しており、これによりコミットがそのブランチ上に配置されます。Git リポジトリ外での実行は、テスト結果をアップロードしますが、カバレッジはアップロードしません。

### 分割実行 {#sharded-runs}

<.localized_link href="/guides/features/test-sharding/rust">テストを分割</.localized_link>すると、カバレッジを有効にして実行された各シャードが独自のターゲットのカバレッジを報告し、Tuist は実行のシャードを 1 つの数値にマージします。シャードは意図的にスイートの一部を実行するため、コミットのカバレッジが不完全になることはありません。

### CI で各コミットを完了させる {#complete-each-commit}

コミットのカバレッジは、多くの場合複数のジョブから得られます：シャードごとまたは機能セットごとに 1 つです。Tuist は最後に報告されたものがいつなのかを判断できないため、明示的に通知する必要があります。コミットのすべてのテストジョブが終了したら、それらすべてに依存するジョブで次を実行してください：

```sh
tuist cargo coverage-complete
```

このコマンドはチェックアウトの `HEAD` からコミットを読み取ります。これはテストが実行されたコミットです。別のコミットを指定するには `--commit <sha>` を渡してください。コミットが完了するまで、そのカバレッジは **進行中** と表示され、ブランチのトレンドには含まれません。

## 仕組み {#how-it-works}

### Tuist が測定するもの {#what-tuist-measures}

- **パッケージ。** 各 Cargo パッケージはダッシュボード上のターゲットとなり、独自のカバレッジを持ちます。
- **プロダクトコードのみ。** 統合テスト、ベンチマーク、および例（`tests/`、`benches/`、および `examples/` ディレクトリ、およびそれらの種類のターゲット）はテストコードです。Tuist はこれらを保存しますが、すべての数値からは除外します。`#[cfg(test)]` モジュール内のユニットテストはソースファイルの一部であるため、`cargo llvm-cov` と同様に、その行もカウントされます。
- **関数。** 各行は、その直上で始まる関数に属します。ジェネリック関数は、いくつの型でインスタンス化されていても 1 回だけカウントされます。
- **ドキュメントテスト** は通常通り実行されますが、測定されません。

Tuist は、後でカバレッジベースのテスト選択を行うために、各テストバイナリが実行したコードも記録します。`cargo test` はバイナリのテストを 1 つのプロセスで実行するため、その記録は個々のテストではなくバイナリ全体に属します。

### スキップされたテスト {#skipped-tests}

実行の引数によってテストが除外される場合（テスト名フィルター、`--skip`、`--ignored`、`-p`、`--exclude`、`--lib`、または `--test` など）、何も除外しなかったコミットの別の実行も行われない限り、コミットのカバレッジは **不完全** となります。すべてのテストバイナリが実行される前に `cargo test` を停止させる失敗も同じ効果をもたらします。残りのバイナリの実行を継続するには `--no-fail-fast` を追加してください。

一部のテストは意図的に除外されており、コミットを不完全にはしません：

- **<.localized_link href="/guides/features/test-insights/flaky-tests/rust">検疫</.localized_link> によってスキップされるテスト。** これらは削除されたかのように除外されるため、これらだけがカバーしていた行は未カバーとしてカウントされます。
- **他のシャードのターゲット**（テストを分割する場合）。
- **無視されたテスト**（`#[ignore]`）。デフォルトでは実行されません。

### 未コミットの変更 {#uncommitted-changes}

追跡対象ファイルに未コミットの変更があるチェックアウトからの実行は、コミットのものではないコードを測定するため、そのカバレッジはコミットにカウントされません。実行は警告を発し、変更されたファイルをリストします。CI ジョブがソースの隣に書き込むファイル（ビルド出力やカバレッジレポートなど）は、Git が追跡していない限り変更としてカウントされません。そのような実行のみがコミットを測定した場合、そのカバレッジは **不完全** となり、`tuist cargo coverage-complete` が理由を示します。

### 完了および未完了のコミット {#commit-status}

ダッシュボード上の各コミットにはステータスがあります：

| ステータス | 意味 |
| --- | --- |
| 進行中 | 実行がカバレッジを報告していますが、`tuist cargo coverage-complete` がまだコミットに対して実行されていません。 |
| 完了 | コミットの実行に含まれるすべてのテストが実行されたか、意図的に除外されています。 |
| 不完全 | 一部のカバレッジを特定できなかったため、数値は下限となります。 |
| 未測定 | コミットに対してカバレッジを報告した実行がありません。 |

ブランチのトレンドには完了したコミットのみが含まれます。

## パフォーマンスへの影響 {#performance-impact}

インストルメント化されたコードは若干低速に動作します。Tuist はリポジトリ内のクレートのみをインストルメント化するため、依存関係は通常のビルドと同様にビルドされ、キャッシュから引き続き提供されます。Tuist は独自のクレートの両方のバリアントを target ディレクトリに保持するため、カバレッジありとなしの実行を切り替えても、コードが変更されていない限り再ビルドされません。

## 制限事項 {#limitations}

- **ターゲット固有の `rustflags` を持つカスタム `rustc-wrapper`。** プロジェクトが独自の `rustc-wrapper` を設定している場合、Tuist は代わりに Cargo の `build.rustflags` に `-C instrument-coverage` を追加します。Cargo 設定ファイル内の `target.<triple>.rustflags` エントリはこれらを置き換えるため、そこにフラグを自分で追加してください。テストがカバレッジを書き込まなかった実行はその旨を報告します。
- **設定されたターゲットランナー。** Tuist は独自のランナーを介してテストバイナリを開始します。Cargo 設定ファイル内の `target.<triple>.runner` がこれを置き換えます。実行のカバレッジは引き続きアップロードされますが、Tuist はどのテストバイナリが何を実行したかを識別できません。`CARGO_TARGET_<TRIPLE>_RUNNER` 環境変数を通じて設定されたランナーは引き続き機能します。
- **フォークからのプルリクエストからはカバレッジを取得できません。** カバレッジは Tuist で認証された実行によってのみアップロードされ、CI は通常、フォークから開かれたプルリクエストからシークレットや ID トークンを withholding します。

## カバレッジのクエリ {#querying}

ダッシュボードの **コードカバレッジ** ページには、各コミットの数値、そのパッケージとファイル、および各ファイルが持つ関数が表示されます。同じデータは、<.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocol サーバー</.localized_link> を介してエージェントでも利用できます。
