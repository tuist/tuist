# Rustのコードカバレッジ {#rust-code-coverage}

コードカバレッジは、テストがコードのどの行を実行したかを示します。TuistはLLVMのソースベースのカバレッジを用いてすべての `cargo test` 実行の行カバレッジを測定し、コミットごとの実行結果をプロジェクト全体、各パッケージ、各ファイルについて1つの数値に集約します。ダッシュボードの **コードカバレッジ** ページでは、コミットごとの値とブランチごとのトレンドが表示されます。

> [!IMPORTANT]
> **要件**
>
> - <.localized_link href="/guides/get-started/rust-project">Rustプロジェクトのセットアップ</.localized_link> に従ってください
> - RustツールチェーンのLLVMツール（`llvm-tools`）。Tuistはrustupが管理するツールチェーンにこれらをインストールします。
> - Gitリポジトリ内のプロジェクト

## セットアップ {#setup}

### カバレッジを有効にする {#turn-coverage-on}

リポジトリのルートにある `tuist.toml` に以下を追加してください：

```toml
[test_insights.coverage]
upload = true
```

その後、通常どおりテストを実行します：

```sh
tuist cargo test --workspace
```

Tuistはリポジトリのクレートを `-C instrument-coverage` でビルドし、テストを実行して、そのカバレッジを実行のテスト結果とともにアップロードします。テストの出力や終了コードは変わりません。1回の実行だけ設定を上書きするには、`TUIST_COVERAGE_UPLOAD=1` または `TUIST_COVERAGE_UPLOAD=0` を設定します。

カバレッジは、Tuistがカバレッジ収集時に各実行と一緒にアップロードするGit履歴に依存しており、これによりコミットがそのブランチ上に配置されます。Gitリポジトリ外での実行では、テスト結果はアップロードされますが、カバレッジはアップロードされません。

### 分割実行 {#sharded-runs}

<.localized_link href="/guides/features/test-sharding/rust">テストを分割</.localized_link> すると、カバレッジを有効にして実行された各シャードが独自のターゲットのカバレッジを報告し、Tuistはその実行のシャードを1つの数値に統合します。シャードは意図的にスイートの一部のみを実行するため、コミットのカバレッジが不完全になることはありません。

### CIで各コミットを完了させる {#complete-each-commit}

コミットのカバレッジは、シャードごとまたは機能セットごとに1つなど、複数のジョブから得られることがよくあります。Tuistは最後に報告されたジョブを自動で検出できないため、明示的に完了を通知する必要があります。コミットのすべてのテストジョブが終了したら、それらすべてに依存するジョブで以下を実行します：

```sh
tuist cargo coverage-complete
```

このコマンドはチェックアウトからコミットを読み取るか、プルリクエストでCIプロバイダーが報告するコミットを使用します。別のコミットを指定するには `--commit <sha>` を渡してください。コミットが完了するまで、そのカバレッジは **進行中** と表示され、ブランチのトレンドには含まれません。

## 仕組み {#how-it-works}

### Tuistが測定するもの {#what-tuist-measures}

- **パッケージ。** 各Cargoパッケージはダッシュボード上のターゲットとなり、独自のカバレッジを持ちます。
- **製品コードのみ。** 結合テスト、ベンチマーク、例（`tests/`、`benches/`、`examples/` ディレクトリおよびそれらの種類のターゲット）はテストコードです。Tuistはこれらを保存しますが、すべての数値からは除外します。`#[cfg(test)]` モジュール内のユニットテストはソースファイルの一部であるため、`cargo llvm-cov` と同様にその行数としてカウントされます。
- **関数。** 各行は、その直上にある最も近い関数に属します。ジェネリック関数は、いくつの型でインスタンス化されても1回だけカウントされます。
- **Doctests** は通常どおり実行されますが、測定対象ではありません。

Tuistは後でカバレッジベースのテスト選択を行うために、各テストバイナリが実行したコードも記録します。`cargo test` はバイナリのテストを1つのプロセスで実行するため、その記録は個々のテストではなくバイナリ全体に属します。

### スキップされたテスト {#skipped-tests}

実行自体の引数によってテストが除外される場合（テスト名フィルター、`--skip`、`--ignored`、`-p`、`--exclude`、`--lib`、または `--test` など）、何も除外せずに実行された別のコミットの実行がない限り、そのコミットのカバレッジは **不完全** となります。すべてのテストバイナリが実行される前に `cargo test` を停止させる失敗も同様です。残りのバイナリの実行を継続するには `--no-fail-fast` を追加してください。

意図的に除外され、コミットを不完全にしないテストもあります：

- **<.localized_link href="/guides/features/test-insights/flaky-tests/rust">隔離</.localized_link> によってスキップされるテスト。** これらは削除されたものとして扱われるため、これらのテストのみがカバーしていた行は未カバーとしてカウントされます。
- テストを分割する場合の **他のシャードのターゲット**
- **無視されるテスト**（`#[ignore]`）。デフォルトでは実行されません。

### 完了および不完全なコミット {#commit-status}

ダッシュボード上の各コミットにはステータスがあります：

| ステータス | 意味 |
| --- | --- |
| 進行中 | 実行がカバレッジを報告していますが、`tuist cargo coverage-complete` がそのコミットに対してまだ実行されていません。 |
| 完了 | コミットの実行におけるすべてのテストが実行されたか、意図的に除外されました。 |
| 不完全 | 一部のカバレッジを特定できなかったため、数値は下限値となります。 |
| 測定されていません | コミットに対してカバレッジを報告した実行がありません。 |

ブランチのトレンドには、完了したコミットのみが含まれます。

## パフォーマンスへの影響 {#performance-impact}

インストルメントされたコードは若干遅く実行されます。Tuist はリポジトリ内のクレートのみをインストルメントします。依存関係は通常のビルドと同様にビルドされ、キャッシュから提供され続けます。Tuist は独自のクレートの両方のバリアントを target ディレクトリに保持するため、カバレッジありとなしの実行を切り替えても、コードが変更されない限り再ビルドされません。

## 制限事項 {#limitations}

- **ターゲット固有の `rustflags` を持つカスタム `rustc-wrapper`。** プロジェクトが独自の `rustc-wrapper` を設定している場合、Tuist は代わりに Cargo の `build.rustflags` に `-C instrument-coverage` を追加します。Cargo 設定ファイル内の `target.<triple>.rustflags` エントリがこれらを置き換えるため、そこでフラグを自分で追加してください。テストがカバレッジを書き込まなかった実行はその旨を報告します。
- **設定されたターゲットランナー。** Tuist は独自のランナーを介してテストバイナリを開始します。Cargo 設定ファイル内の `target.<triple>.runner` がこれを置き換えます。実行のカバレッジは引き続きアップロードされますが、Tuist はどのテストバイナリが何を実行したかを判別できません。`CARGO_TARGET_<TRIPLE>_RUNNER` 環境変数を通じて設定されたランナーは引き続き機能します。
- **フォークからのプルリクエストからはカバレッジを取得できません。** カバレッジは Tuist で認証された実行によってのみアップロードされ、CI は通常、フォークから開かれたプルリクエストからシークレットや ID トークンを除外します。

## カバレッジのクエリ {#querying}

ダッシュボードの **コードカバレッジ** ページには、各コミットの数値、そのパッケージ、ファイル、および各ファイルが持つ関数が表示されます。同じデータは、<.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocol サーバー</.localized_link> を介してエージェントからも利用できます。
