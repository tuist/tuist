# Rustのコードカバレッジ {#rust-code-coverage}

コードカバレッジは、テストがコードのどの行を実行したかを示します。TuistはLLVMのソースベースのカバレッジを使用して、`cargo test`の実行ごとにラインカバレッジを測定し、コミット内のすべての実行をプロジェクト、各パッケージ、各ファイルについて1つの数値に集約します。ダッシュボードの**Code Coverage**ページでは、コミットごとの結果とブランチごとの推移を確認できます。

> [!IMPORTANT]
> **要件**
>
> - <.localized_link href="/guides/get-started/rust-project">Rustプロジェクトのセットアップ</.localized_link>に従ってください
> - RustツールチェーンのLLVMツール（`llvm-tools`）。Tuistは、rustupが管理するツールチェーンにこれらをインストールします。
> - Gitリポジトリ内にあるプロジェクト

## セットアップ {#setup}

### カバレッジを有効にする {#turn-coverage-on}

ワークスペースのルートにある`Cargo.toml`にこれを追加してください：

```toml
[workspace.metadata.tuist.test_insights.coverage]
upload = true
```

代わりに`tuist.toml`でTuistを設定している場合は、そこに`[test_insights.coverage]`を追加し、`upload = true`を設定してください。

その後、通常通りテストを実行してください：

```sh
tuist cargo test --workspace
```

Tuistはリポジトリのクレートを`-C instrument-coverage`付きでビルドし、テストを実行して、その実行のテスト結果とともにカバレッジをアップロードします。テストの出力や終了コードは変更されません。単一の実行に対して設定を上書きするには、`TUIST_COVERAGE_UPLOAD=1`または`TUIST_COVERAGE_UPLOAD=0`を設定してください。

カバレッジは、Tuistがカバレッジ収集時に各実行と一緒にアップロードするGit履歴に依存しており、これによりコミットがそのブランチ上に配置されます。Gitリポジトリ外での実行は、テスト結果をアップロードしますが、カバレッジはアップロードしません。

### 分割された実行 {#sharded-runs}

<.localized_link href="/guides/features/test-sharding/rust">テストを分割</.localized_link>すると、カバレッジを有効にして実行される各シャードが自身のターゲットのカバレッジを報告し、Tuistはその実行のシャードを1つの数値にマージします。シャードは意図的にスイートの一部のみを実行するため、コミットのカバレッジが不完全になることはありません。

### CIで各コミットを完了させる {#complete-each-commit}

コミットのカバレッジは、多くの場合複数のジョブから得られます。シャードごと、または機能セットごとに1つです。Tuistは最後のジョブがいつ報告を終えたかを判断できないため、明示的に通知する必要があります。コミットのすべてのテストジョブが完了したら、それらすべてに依存するジョブで次のコマンドを実行してください：

```sh
tuist cargo coverage-complete
```

このコマンドは、チェックアウトの`HEAD`（テストが実行されたコミット）からコミットを読み取ります。別のコミットを指定するには、`--commit <sha>`を渡してください。コミットが完了するまで、そのカバレッジは**進行中**として表示され、ブランチの推移には含まれません。

## 仕組み {#how-it-works}

### Tuistが測定するもの {#what-tuist-measures}

- **パッケージ。** 各Cargoパッケージはダッシュボード上のターゲットとなり、独自のカバレッジを持ちます。
- **プロダクトコードのみ。** 統合テスト、ベンチマーク、および例（`tests/`、`benches/`、`examples/`ディレクトリ、およびそれらの種類のターゲット）はテストコードです。Tuistはこれらを保存しますが、すべての数値からは除外します。`#[cfg(test)]`モジュール内のユニットテストはソースファイルの一部であるため、`cargo llvm-cov`の場合と同様に、その行数がカウントされます。
- **関数。** 各行は、その直上で開始される最も近い関数に属します。ジェネリック関数は、インスタンス化された型の数に関係なく1回だけカウントされます。
- **Doctests**は通常通り実行されますが、測定されません。

Tuistは、後でカバレッジベースのテスト選択を行うために、各テストバイナリが実行したコードも記録します。`cargo test`はバイナリのテストを1つのプロセスで実行するため、その記録は個々のテストではなく、バイナリ全体に属します。

### スキップされたテスト {#skipped-tests}

実行自体の引数によってテストが除外される場合（テスト名フィルター、`--skip`、`--ignored`、`-p`、`--exclude`、`--lib`、または`--test`など）、何も除外しない別のコミットの実行も行われない限り、そのコミットのカバレッジは**不完全**となります。すべてのテストバイナリが実行される前に`cargo test`を停止させる失敗も同じ影響を与えます。残りのバイナリの実行を継続するには、`--no-fail-fast`を追加してください。

意図的に除外されるテストもあり、コミットを不完全にはしません：

- **<.localized_link href="/guides/features/test-insights/flaky-tests/rust">検疫</.localized_link>によってスキップされるテスト。** これらは削除されたものとして扱われるため、これらだけがカバーしていた行は未カバーとしてカウントされます。
- **他のシャードのターゲット**（テストを分割した場合）
- **無視されたテスト**（`#[ignore]`）。デフォルトでは実行されません。

### 完了したコミットと不完全なコミット {#commit-status}

ダッシュボード上の各コミットにはステータスがあります：

| ステータス | 意味 |
| --- | --- |
| 進行中 | 実行がカバレッジを報告していますが、`tuist cargo coverage-complete`がそのコミットに対してまだ実行されていません。 |
| 完了 | コミットの実行に含まれるすべてのテストが実行されたか、意図的に除外されました。 |
| 不完全 | 一部のカバレッジを特定できなかったため、数値は下限となります。 |
| 未測定 | コミットに対してカバレッジを報告した実行がありません。 |

ブランチのトレンドには、完了したコミットのみが含まれます。

## パフォーマンスへの影響 {#performance-impact}

インストルメントされたコードは若干遅く実行されます。Tuistはリポジトリ内のクレートのみをインストルメントします。依存関係は通常のビルドと同様にビルドされ、キャッシュから提供され続けます。Tuistは独自のクレートの両方のバリアントをtargetディレクトリに保持するため、カバレッジありとなしの実行を切り替えても、コードが変更されない限り再ビルドされません。

## 制限事項 {#limitations}

- **ターゲット固有の`rustflags`を持つカスタム`rustc-wrapper`。** プロジェクトが独自の`rustc-wrapper`を設定している場合、Tuistは代わりにCargoの`build.rustflags`に`-C instrument-coverage`を追加します。Cargo設定ファイル内の`target.<triple>.rustflags`エントリはこれらを置き換えるため、そこにフラグを自分で追加してください。テストがカバレッジを書き込まなかった実行はその旨を報告します。
- **設定されたターゲットランナー。** Tuistは独自のランナーを介してテストバイナリを開始します。Cargo設定ファイル内の`target.<triple>.runner`がその役割を引き継ぎます。実行のカバレッジは引き続きアップロードされますが、Tuistはどのテストバイナリが何を実行したかを判別できません。`CARGO_TARGET_<TRIPLE>_RUNNER`環境変数を通じて設定されたランナーは引き続き機能します。
- **フォークからのプルリクエストからはカバレッジを取得できません。** カバレッジはTuistで認証された実行によってのみアップロードされ、CIは通常、フォークから開かれたプルリクエストからシークレットやIDトークンを除外します。

## カバレッジのクエリ {#querying}

ダッシュボードの**コードカバレッジ**ページには、各コミットの図、パッケージ、ファイル、および各ファイルが持つ関数が表示されます。同じデータは、<.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocolサーバー</.localized_link>を通じてエージェントでも利用できます。
