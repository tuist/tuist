# Elixirのコードカバレッジ {#elixir-code-coverage}

コードカバレッジは、テストが実行したコードの行を示します。Hexパッケージは `mix test --cover` の各実行における行カバレッジをアップロードし、Tuistはコミット内の実行をプロジェクト全体、各OTPアプリケーション、および各ファイルごとに1つの数値に集約します。ダッシュボードの **コードカバレッジ** ページでは、コミットごとの結果と各ブランチの推移を表示します。

> [!IMPORTANT]
> **必要条件**
>
> - パッケージ経由で `mix test` をルーティングする <.localized_link href="/guides/get-started/elixir-project">共有Elixirセットアップ</.localized_link> を完了してください

## セットアップ {#setup}

### カバレッジを有効にしてテストを実行する {#run-your-tests}

Tuistを使用しない場合の `mix test` と同様に、`--cover` を指定します:

```sh
mix test --cover
```

パッケージは、実行のテスト結果とともにカバレッジをアップロードします。スイートが終了すると、同じ `test_coverage` オプションで構成されたMixのカバレッジツールと同様の処理を行います:

- **サマリー。** 各モジュールのカバレッジと合計値を表示します。`summary: false` でこれを無効にできます。
- **閾値。** 合計値が閾値を下回ると、実行は終了ステータス3で失敗します。デフォルトの閾値は90%ですが、以下のように設定可能です:

```elixir
def project do
  [
    test_coverage: [summary: [threshold: 80]]
  ]
end
```

Mixと同様に、閾値はサマリーに属するため、`summary: false` は両方を無効にします。実行を失敗させずにサマリーを表示するには、`threshold: 0` を設定してください。`test_coverage: [ignore_modules: [...]]` にリストされたモジュールは、サマリーとアップロードから除外されます。

Tuistはコミットごとにカバレッジを追跡するため、プロジェクトはGitリポジトリ内にある必要があります。リポジトリ外での実行では、テスト結果はアップロードされますが、カバレッジはアップロードされません。

カバレッジは、パッケージがアップロードする <.localized_link href="/guides/features/test-insights/elixir#git-history">Git履歴</.localized_link> に依存しており、これによりコミットがそのブランチ上に配置されます。継続的インテグレーション（CI）上の実行では常にこれがアップロードされ、`--cover` を使用した実行では任意のマシンでアップロードされます。`--cover` を使用すると、パッケージはプルリクエストの分岐点も特定します。ベースブランチを取得し、必要に応じて浅いクローンを深化させます。CI環境では、ファイルの内容なしで浅いチェックアウトも深化され、Tuistが既に保持しているコミットに到達するまで続行されるため、親コミットのないコミットがアップロードされることはありません。リモートへの接続を防ぐには、`TUIST_GIT_UNSHALLOW_ENABLED=false` を設定してください。

### シャード化された実行 {#sharded-runs}

<.localized_link href="/guides/features/test-sharding/elixir">テストをシャード化</.localized_link> する場合、各シャードを `--cover` で実行します:

```sh
MIX_ENV=test TUIST_SHARD_INDEX=0 mix tuist.test --cover
```

新しいランナーでは、シャードガイドの <.localized_link href="/guides/features/test-sharding/elixir#test-phase">テストフェーズ</.localized_link> に記載されているブートストラップコマンドを使用し、シャードがビルドをダウンロードする前にMixがすべての依存関係をコンパイルしないようにしつつ、それに `--cover` を追加してください。

シャードは自身のカバレッジのみを報告し、スイートの一部しか実行しないため閾値のチェックは行いません。Tuistは実行内の各シャードを1つの数値に統合します。

各シャードは、ダウンロードしたビルドにカバレッジカウンタを追加します。代わりに一度だけ行うには、ビルドフェーズにも `--cover` を渡します:

```sh
MIX_ENV=test mix tuist.test.build --shard-max 5 --cover
```

パイプライン実行間でビルドディレクトリを保持し、カバレッジを収集しない実行で再利用する場合は、これをオフにしておき、そのビルドにカウンタが含まれないようにしてください。

### CI上で各コミットを完了させる {#complete-each-commit}

コミットのカバレッジは、シャードごと、データベースバージョンごと、またはアプリケーションごとなど、複数のジョブから提供されることがあります。Tuistは最後のジョブが報告を終えたタイミングを自動検出できないため、明示的に通知する必要があります。コミットに関するすべてのテストジョブが終了したら、それらすべてに依存するジョブで以下を実行します:

```sh
MIX_ENV=test mix tuist.coverage.complete
```

タスクは `GIT_COMMIT` またはチェックアウトの `HEAD` からコミットを読み取ります。別のコミットを指定するには `--commit <sha>` を渡してください。コミットが完了するまで、そのカバレッジは **進行中** と表示され、ブランチの推移からは除外されます。

## 動作原理 {#how-it-works}

### ネイティブ行カウンタ {#native-line-counters}

Mixのカバレッジツールは、各実行の開始時にErlangの `cover` 向けにすべてのモジュールを再コンパイルするため、大規模なプロジェクトでは遅くなります。パッケージは代わりにランタイムのネイティブ行カウンタを使用して計測します。前回の実行以降にコンパイルによって書き込まれたモジュールのみを再コンパイルし、ランタイムをそれらのカウンタに切り替えて、スイート終了時に読み取ります。Mixのカバレッジツールは使用されませんが、そのサマリーと閾値の設定は維持されます。

パッケージは、以下の場合にMixのカバレッジツールにフォールバックし、同じアップロード処理を行います:

- アンブレラプロジェクトのルート。ネイティブ計測を行うには、各アプリケーション内でテストを実行してください。
- 独自の `test_coverage: [tool: ...]` を設定しているプロジェクト。
- JITのないランタイム。ネイティブ計測ができないためです。

### Tuistが計測する内容 {#what-tuist-measures}

- **アプリケーション。** 各OTPアプリケーションはダッシュボード上のターゲットとなり、それぞれ独自のカバレッジを持ちます。
- **製品コードのみ。** テストパス以下のファイルはテストコードです。Tuistはこれらを保存しますが、すべての数値計算からは除外します。
- **ファイルごとの行数。** 行は、所属するモジュールの数に関係なく、ファイルごとに1回カウントされます。
- **関数。** 各行は、その直上最も近くで始まる節を持つ関数に属します。コンパイラやマクロが生成する `__info__/1` や `__schema__/1` などの関数はリストされませんが、それらの行はファイルのカウントに含まれます。

したがって、Tuistの数値はMix自体のカバレッジレポートとは幾つかの点で異なります。テストコードを除外し、モジュールごとではなくファイルごとに行をカウントします。また、ネイティブ計測ではアプリケーション起動時に実行されるコードも認識し、コンパイラが決して実行されないことを証明した行を除外します（Mixのツールではこれらの行は「未カバー」として報告されます）。

### スキップされたテスト {#skipped-tests}

Tuistは、実行が除外したテストのカバレッジを引き継ぐことができません。パッケージは各テストの実行内容ではなく、実行全体の実行内容を記録するためです。そのため、実行の引数（`--only`、`--exclude`、`--failed`、`--stale`、`--name-pattern`、`--max-failures`、またはテストファイルや行の指定）によってテストが除外された場合、何も除外していない同じバリアントの実行も同時に行われない限り、コミットのカバレッジは **不完全** となります。`--exclude slow` と `--only slow` のように、それぞれがテストを除外する2つの実行は、合わせてすべてのテストを実行した場合でも、コミットを不完全な状態にします。

意図的に除外され、コミットを不完全にしないテストもあります:

- **テストヘルパーの除外設定。** `ExUnit.start(exclude: [...])` がデフォルトで除外するテストは、プロジェクトのスイートがデフォルトで実行する範囲の選択であり、Tuistはこれらを欠落としてカウントしません。それらのカバレッジをコミットに追加するには、`--include` または `--only` を使用して別のジョブで実行してください。
- **コード内でスキップされたテスト**。`@tag :skip` を使用します。
- **<.localized_link href="/guides/features/test-insights/flaky-tests/elixir#quarantining">検疫</.localized_link>によってスキップされたテスト。** これらは削除されたものとして除外されるため、それらだけがカバーしていた行は未カバーとしてカウントされます。

### 完全および不完全なコミット {#commit-status}

ダッシュボード上の各コミットにはステータスがあります:

| ステータス | 意味 |
| --- | --- |
| 進行中 | 実行がカバレッジを報告していますが、`mix tuist.coverage.complete` がそのコミットに対してまだ実行されていません。 |
| 完了 | コミットの実行におけるすべてのテストが実行されたか、意図的に除外されました。 |
| 不完全 | 一部のカバレッジを特定できなかったため、数値は下限となります。 |
| 未測定 | コミットに対してカバレッジを報告した実行がありません。 |

ブランチのトレンドには完全なコミットのみが含まれます。コミットが不完全になる例としては、以下のような場合です:

- バリアントのすべての実行が、独自の引数によってテストを除外しました。
- バリアントのすべての実行で、一部のシャードが欠落していました。
- バリアントのカバレッジが、未コミットの変更があるチェックアウトでのCI実行からのみ提供されました。

バリアントとは、`--scheme` で渡すラベル（データベースバージョンなど）のことです。ラベルのない実行は1つのバリアントとして扱われます。コミットの数値はすべての実行を統合しますが、Tuistは各バリアントの完全性を個別に確認するため、各バリアントには何も除外しない実行が必要です。

## パフォーマンスへの影響 {#performance-impact}

カバレッジの収集にはオーバーヘッドがかかるため、`--cover` を使用した実行は使用しない実行よりも時間がかかります。初回実行ではモジュールが行カウンター付きで再コンパイルされますが、以降の実行では変更された部分のみが再コンパイルされるため、コストは大幅に低減されます。大規模なプロジェクトでは、ネイティブ計測はMixのカバレッジツールよりもはるかに高速です。

## 制限事項 {#limitations}

- **HTMLレポートはありません。** ネイティブ計測では `test_coverage: [output: ...]` ディレクトリにレポートを書き出さず、設定されている場合は実行時に警告が表示されます。代わりに、ダッシュボードのファイルページでカバーされた行を確認できます。
- **リトライではカバレッジは追加されません。** <.localized_link href="/guides/features/test-insights/flaky-tests/elixir#test-retries">テストリトライ</.localized_link>を使用する場合、カバレッジは初回試行のものとなります。初回試行ですでに失敗したテストが実行されているため、欠落する行は不安定なテストがリトライ時に到達したが初回試行時には到達しなかった行のみです。
- **フォークからのプルリクエストからはカバレッジを取得できません。** カバレッジはTuistで認証された実行によってのみアップロードされます。CIは通常、フォークから開かれたプルリクエストに対してシークレットやIDトークンを提供しないため、これらの実行はカバレッジを報告しません。マージされると、コミットは認証情報を使用してあなたのブランチで実行され、通常通りカバレッジを報告します。

## カバレッジのクエリ {#querying}

ダッシュボードの **コードカバレッジ** ページでは、各コミットの数値、アプリケーション、ファイル、および各実行でカバーされた行を表示します。同じデータは、<.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocolサーバー</.localized_link>を通じてエージェントからも利用可能です。
