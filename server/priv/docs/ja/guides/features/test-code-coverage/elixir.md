# Elixir のコードカバレッジ {#elixir-code-coverage}

コードカバレッジは、テストが実行したコードの行を示します。Hex パッケージは `mix test --cover` の各実行における行カバレッジをアップロードし、Tuist はコミットに含まれるすべての実行をプロジェクト全体、各 OTP アプリケーション、および各ファイルごとに 1 つの数値に集約します。ダッシュボードの **コードカバレッジ** ページでは、コミットごとの結果とブランチごとの推移を確認できます。

> [!IMPORTANT] REQUIREMENTS
> - <.localized_link href="/guides/get-started/elixir-project">共有 Elixir セットアップ</.localized_link> を完了してください。これにより `mix test` がパッケージ経由でルーティングされます。

## セットアップ {#setup}

### カバレッジを有効にしてテストを実行する {#run-your-tests}

Tuist を使わない場合の `mix test` と同様に、`--cover` を渡します:

```sh
mix test --cover
```

パッケージは実行のテスト結果とともにカバレッジをアップロードします。スイートが完了すると、同じ `test_coverage` オプションで設定された Mix のカバレッジツールと同様の処理を行います:

- **サマリー。** 各モジュールのカバレッジと合計値を表示します。`summary: false` で無効化できます。
- **閾値。** 合計値が閾値を下回ると、終了ステータス 3 で実行を失敗させます。デフォルトの閾値は 90% です。別の値を設定するには次のようにします:

```elixir
def project do
  [
    test_coverage: [summary: [threshold: 80]]
  ]
end
```

Mix と同様、閾値はサマリーの一部であるため、`summary: false` は両方を無効にします。実行を失敗させずにサマリーを表示するには、`threshold: 0` に設定します。`test_coverage: [ignore_modules: [...]]` に指定されたモジュールは、サマリーとアップロードから除外されます。

Tuist はコミットごとにカバレッジを追跡するため、プロジェクトは Git リポジトリ内にある必要があります。リポジトリ外での実行はテスト結果をアップロードしますが、カバレッジはアップロードされません。

カバレッジは、パッケージがアップロードする <.localized_link href="/guides/features/test-insights/elixir#git-history">Git ヒストリー</.localized_link> に依存しており、これによりコミットが対応するブランチに配置されます。継続的インテグレーション上での実行は常にこれをアップロードし、`--cover` を使用した実行はどのマシンでもこれをアップロードします。`--cover` を使用すると、パッケージはプルリクエストの分岐元も特定します。ベースブランチを取得し、必要に応じて浅いクローンを深化させます。リモートへの通信を防ぐには `TUIST_GIT_UNSHALLOW_ENABLED=false` を設定します。

### シャード化された実行 {#sharded-runs}

<.localized_link href="/guides/features/test-sharding/elixir">テストをシャード化</.localized_link> する場合、各シャードを `--cover` で実行します:

```sh
MIX_ENV=test TUIST_SHARD_INDEX=0 mix tuist.test --cover
```

新しいランナーでは、シャード化ガイドの <.localized_link href="/guides/features/test-sharding/elixir#test-phase">テストフェーズ</.localized_link> にあるブートストラップコマンドを使用します。これにより、シャードがビルドをダウンロードする前に Mix がすべての依存関係をコンパイルすることを防ぎます。このコマンドに `--cover` を追加してください。

シャードは自身のカバレッジのみを報告し、スイートの一部しか実行しないため閾値チェックは行いません。Tuist は実行内のすべてのシャードを 1 つの数値に統合します。

各シャードは、ダウンロードしたビルドにカバレッジカウンターを追加します。代わりに一度だけ行う場合は、ビルドフェーズにも `--cover` を渡します:

```sh
MIX_ENV=test mix tuist.test.build --shard-max 5 --cover
```

パイプラインの実行間でビルドディレクトリを保持し、カバレッジを収集しない実行で再利用する場合は、これを省略してください。そうすることで、そのビルドにはカウンターが含まれない状態になります。

### CI で各コミットを完了させる {#complete-each-commit}

コミットのカバレッジは、シャードごと、データベースバージョンごと、またはアプリケーションごとなど、複数のジョブから得られることがよくあります。Tuist は最後に報告されたジョブを自動検出できないため、明示的に完了を通知する必要があります。コミットに関連するすべてのテストジョブが終了したら、それらすべてに依存するジョブで次を実行します:

```sh
MIX_ENV=test mix tuist.coverage.complete
```

タスクは `GIT_COMMIT` またはチェックアウトの `HEAD` からコミットを読み取ります。別のコミットを指定するには `--commit <sha>` を渡します。コミットが完了するまで、そのカバレッジは **進行中** と表示され、ブランチの推移には含まれません。

## 仕組み {#how-it-works}

### ネイティブな行カウンター {#native-line-counters}

Mix のカバレッジツールは、各実行の開始時に Erlang の `cover` 用にすべてのモジュールを再度コンパイルするため、大規模なプロジェクトでは遅くなります。このパッケージは代わりにランタイムのネイティブな行カウンターを使用して計測します。前回の実行以降にコンパイルによって書き込まれたモジュールのみを再コンパイルし、ランタイムをこれらのカウンターに切り替えて、スイート完了時に読み取ります。Mix のカバレッジツールは使用されませんが、そのサマリーと閾値の設定は維持されます。

パッケージは、以下の場合に Mix のカバレッジツールにフォールバックし、同じ方法でアップロードを行います:

- アンブレラプロジェクトのルート。ネイティブな計測を行うには、各アプリケーション内でテストを実行してください。
- 独自の `test_coverage: [tool: ...]` を設定しているプロジェクト。
- JIT なしで実行されるランタイム。ネイティブな計測が行えません。

### Tuist が計測する対象 {#what-tuist-measures}

- **アプリケーション。** 各 OTP アプリケーションはダッシュボード上のターゲットとして扱われ、それぞれ独自のカバレッジを持ちます。
- **プロダクトコードのみ。** テストパス配下のファイルはテストコードです。Tuist はこれらを保存しますが、すべての数値からは除外します。
- **ファイルごとの行数。** 行は、それが属するモジュールの数に関係なく、ファイルごとに 1 回だけ計上されます。
- **関数。** 各行は、その直上で最も近い位置から始まる節を持つ関数に属します。コンパイラーやマクロが生成する `__info__/1` や `__schema__/1` などの関数は一覧に表示されませんが、それらの行はファイルの計測対象に含まれます。

したがって、Tuist の数値は Mix のカバレッジレポートとは以下の点で異なります。テストコードを除外し、モジュール単位ではなくファイル単位で行を計上します。また、ネイティブな計測ではアプリケーション起動時に実行されるコードも認識し、コンパイラーが決して実行されないことを証明した行を除外します（Mix のツールではこれらの行は未カバーとして報告されます）。

### スキップされたテスト {#skipped-tests}

Tuist は、実行から除外されたテストのカバレッジを引き継ぐことができません。パッケージは各テストの実行内容ではなく、実行全体が実行した内容を記録するためです。そのため、`--only`、`--exclude`、`--failed`、`--stale`、`--name-pattern`、`--max-failures`、またはテストファイルや行の指定によって実行からテストが除外されると、何も除外しない同じバリアントの実行も行われない限り、コミットのカバレッジは **不完全** となります。`--exclude slow` と `--only slow` のように、それぞれがテストを除外する 2 つの実行を行った場合、合わせてすべてのテストを実行してもコミットは不完全のままです。

意図的に除外され、コミットを不完全にしないテストもあります:

- **テストヘルパーの除外設定。**`ExUnit.start(exclude: [...])` がデフォルトで除外するテストは、プロジェクトのスイートがデフォルトで実行する対象を選択した結果であるため、Tuist はこれらを欠落として扱いません。別のジョブで `--include` または `--only` を使用してこれらを実行し、コミットのカバレッジに含めてください。
- **コード内でスキップされたテスト**。`@tag :skip` を使用します。
- **<.localized_link href="/guides/features/test-insights/flaky-tests/elixir#quarantining">隔離</.localized_link> によってスキップされたテスト。** これらは削除されたものとして扱われるため、これらのテストのみがカバーしていた行は未カバーとして計上されます。

### 完全および不完全なコミット {#commit-status}

ダッシュボード上の各コミットにはステータスがあります:

| ステータス | 意味 |
| --- | --- |
| 進行中 | 実行からカバレッジが報告されていますが、`mix tuist.coverage.complete` がそのコミットに対してまだ実行されていません。 |
| 完了 | コミットの実行に含まれるすべてのテストが実行されたか、意図的に除外されました。 |
| 不完全 | 一部のカバレッジを特定できなかったため、数値は下限値となります。 |
| 未測定 | コミットに対してカバレッジを報告した実行がありません。 |

ブランチのトレンドには完了したコミットのみが含まれます。コミットが不完全になる例としては、以下のような場合です:

- あるバリアントのすべての実行で、独自の引数によってテストが除外されました。
- あるバリアントのすべての実行で、一部のシャードが欠落していました。
- あるバリアントのカバレッジが、未コミットの変更があるチェックアウト上での CI 実行からのみ提供されました。

バリアントとは、`--scheme` で渡すラベル（データベースのバージョンなど）のことです。ラベルのない実行はすべて同じバリアントとして扱われます。コミットの数値はすべての実行を統合しますが、Tuist は各バリアントの完全性を個別に確認するため、各バリアントには何も除外しない実行が必要です。

## パフォーマンスへの影響 {#performance-impact}

カバレッジの収集にはオーバーヘッドがかかるため、`--cover` を使用した実行は使用しない場合よりも時間がかかります。初回実行ではモジュールが行カウンター付きで再コンパイルされますが、以降の実行では変更された部分のみが再コンパイルされるため、コストは大幅に低減します。大規模なプロジェクトでは、ネイティブな計測は Mix のカバレッジツールよりもはるかに高速です。

## 制限事項 {#limitations}

- **HTML レポートはありません。** ネイティブな計測では `test_coverage: [output: ...]` ディレクトリにレポートを書き込まないため、設定されている場合は実行時に警告が表示されます。代わりに、ダッシュボードのファイルページでカバーされた行を確認できます。
- **リトライによってカバレッジは追加されません。**<.localized_link href="/guides/features/test-insights/flaky-tests/elixir#test-retries">テストのリトライ</.localized_link> を使用する場合、カバレッジは初回試行のものとなります。この試行ですでに失敗したテストが実行されているため、欠落する行は、不安定なテストがリトライ時には到達するものの初回試行では到達しなかった行のみです。
- **フォークからのプルリクエストからはカバレッジを取得できません。** カバレッジは Tuist で認証された実行によってのみアップロードされます。CI は通常、フォークから開かれたプルリクエストに対してシークレットや ID トークンを提供しないため、これらの実行からはカバレッジが報告されません。マージされると、コミットは認証情報を使用してあなたのブランチ上で実行され、通常通りカバレッジを報告します。

## カバレッジのクエリ {#querying}

ダッシュボードの **コードカバレッジ** ページでは、各コミットの数値、そのアプリケーションとファイル、および各実行がカバーした行が表示されます。同じデータは、<.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocol サーバー</.localized_link> を介してエージェントからも利用可能です。
