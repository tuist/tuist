# Elixirのコードカバレッジ {#elixir-code-coverage}

コードカバレッジは、テストがコードのどの行を実行したかを示します。Hexパッケージは、`mix test --cover` の各実行における行カバレッジをアップロードし、Tuistはコミット内の複数の実行をプロジェクト全体、各OTPアプリケーション、および各ファイルごとに1つの数値に集約します。ダッシュボードの **コードカバレッジ** ページでは、コミットごとの結果とブランチごとの推移を確認できます。

> [!IMPORTANT]
> **前提条件**
>
> - <.localized_link href="/guides/get-started/elixir-project">Elixirプロジェクトの共通セットアップ</.localized_link> を完了してください。これにより、`mix test` がパッケージ経由でルーティングされます。

## セットアップ {#setup}

### カバレッジを有効にしてテストを実行する {#run-your-tests}

Tuistを使用しない場合の `mix test` と同様に、`--cover` を指定します:

```sh
mix test --cover
```

パッケージは、実行のテスト結果とともにカバレッジをアップロードします。スイートが完了すると、Mixのカバレッジツールと同じ動作を行い、同じ `test_coverage` オプションで設定されます:

- **サマリー。** 各モジュールのカバレッジと合計値を表示します。`summary: false` でこれを無効にできます。
- **閾値。** 合計値が閾値を下回ると、終了ステータス3で実行が失敗します。デフォルトの閾値は90%ですが、任意の値を設定できます:

```elixir
def project do
  [
    test_coverage: [summary: [threshold: 80]]
  ]
end
```

Mixと同様、閾値はサマリーの一部であるため、`summary: false` は両方を無効にします。実行を失敗させずにサマリーを表示するには、`threshold: 0` を設定します。`test_coverage: [ignore_modules: [...]]` にリストされたモジュールは、サマリーとアップロードから除外されます。

Tuistはコミットごとにカバレッジを追跡するため、プロジェクトはGitリポジトリ内にある必要があります。リポジトリ外での実行では、テスト結果はアップロードされますが、カバレッジはアップロードされません。

カバレッジは、パッケージがアップロードする <.localized_link href="/guides/features/test-insights/elixir#git-history">Git履歴</.localized_link> に依存しており、これによりコミットがそのブランチ上に配置されます。継続的インテグレーション（CI）上の実行では常にこれがアップロードされ、`--cover` を使用した実行では任意のマシンでアップロードされます。`--cover` を使用すると、パッケージはプルリクエストの分岐点も特定します。ベースブランチを取得し、必要に応じて浅いクローンを深化させます。CI環境では、ファイルの内容なしで浅いチェックアウトも深化され、Tuistが既に持っているコミットに到達するまで続けられるため、親コミットのないコミットがアップロードされることはありません。リモートへの接続を防ぐには、`TUIST_GIT_UNSHALLOW_ENABLED=false` を設定します。

### 分割実行 {#sharded-runs}

<.localized_link href="/guides/features/test-sharding/elixir">テストを分割</.localized_link> する場合、各シャードを `--cover` で実行します:

```sh
MIX_ENV=test TUIST_SHARD_INDEX=0 mix tuist.test --cover
```

新しいランナー上では、シャーディングガイドの <.localized_link href="/guides/features/test-sharding/elixir#test-phase">テストフェーズ</.localized_link> からブートストラップコマンドを使用し、それに `--cover` を追加します。これにより、シャードがビルドをダウンロードする前にMixがすべての依存関係をコンパイルすることを防ぎます。

シャードは自身のカバレッジのみを報告し、スイートの一部しか実行しないため、閾値のチェックは行いません。Tuistは、実行内のすべてのシャードを1つの数値に統合します。

各シャードは、ダウンロードしたビルドにカバレッジカウンターを追加します。代わりに一度だけ行うには、ビルドフェーズにも `--cover` を渡します:

```sh
MIX_ENV=test mix tuist.test.build --shard-max 5 --cover
```

パイプライン実行間でビルドディレクトリを保持し、カバレッジを収集しない実行で再利用する場合は、このオプションを外しておきます。そうすることで、そのビルドにはカウンターが含まれないままになります。

### CI上で各コミットを完了させる {#complete-each-commit}

コミットのカバレッジは、シャードごと、データベースバージョンごと、またはアプリケーションごとなど、複数のジョブから得られることがよくあります。Tuistは最後に報告されたジョブを自動で検出できないため、明示的に通知する必要があります。コミットに関連するすべてのテストジョブが終了したら、それらすべてに依存するジョブで以下を実行します:

```sh
MIX_ENV=test mix tuist.coverage.complete
```

タスクは `GIT_COMMIT` またはチェックアウトの `HEAD` からコミットを読み取ります。別のコミットを指定するには、`--commit <sha>` を渡します。コミットが完了するまで、そのカバレッジは **進行中** と表示され、ブランチの推移からは除外されます。

## 仕組み {#how-it-works}

### ネイティブな行カウンター {#native-line-counters}

Mixのカバレッジツールは、各実行の開始時にErlangの `cover` 用にすべてのモジュールを再コンパイルするため、大規模なプロジェクトでは遅くなります。代わりに、パッケージはランタイムのネイティブな行カウンターを使用してカウントします。前回の実行以降にコンパイルによって書き込まれたモジュールのみを再コンパイルし、ランタイムをこれらのカウンターに切り替え、スイートが完了した時点で読み取ります。Mixのカバレッジツールは使用されませんが、そのサマリーと閾値の設定は維持されます。

パッケージは、以下のケースでMixのカバレッジツールにフォールバックし、同じアップロード処理を行います:

- アンブレラプロジェクトのルート。ネイティブなカウントを行うには、各アプリケーション内でテストを実行してください。
- 独自の `test_coverage: [tool: ...]` を設定しているプロジェクト。
- JITのないランタイム。ネイティブなカウントができないためです。

### Tuistが測定するもの {#what-tuist-measures}

- **アプリケーション。** 各OTPアプリケーションはダッシュボード上のターゲットとなり、それぞれ独自のカバレッジを持ちます。
- **プロダクトコードのみ。** テストパス下のファイルはテストコードです。Tuistはこれらを保存しますが、すべての数値計算からは除外します。
- **ファイルごとの行数。** 行は、それが属するモジュールの数に関係なく、ファイルごとに1回カウントされます。
- **関数。** 各行は、その直近上位で始まる節を持つ関数に属します。コンパイラやマクロが生成する関数（`__info__/1` や `__schema__/1` など）はリストされませんが、それらの行はファイルのカウントに含まれます。

したがって、Tuistの数値はMix自体のカバレッジレポートとは以下の点で異なります。テストコードを除外し、モジュール単位ではなくファイル単位で行をカウントします。また、ネイティブなカウントでは、アプリケーションの起動中に実行されるコードも検出し、コンパイラが決して実行されないことを証明した行を除外します（Mixのツールではこれらは「未カバー」として報告されます）。

### スキップされたテスト {#skipped-tests}

Tuistは、実行が除外したテストのカバレッジを引き継ぐことができません。パッケージは各テストの実行内容ではなく、実行全体の実行内容を記録するためです。そのため、実行の引数（`--only`、`--exclude`、`--failed`、`--stale`、`--name-pattern`、`--max-failures`、またはテストファイルや行の指定）によってテストが除外されると、何も除外しない同じバリアントの実行も行われない限り、コミットのカバレッジは **不完全** となります。`--exclude slow` と `--only slow` のように、それぞれがテストを除外する2つの実行は、合わせてすべてのテストを実行した場合でも、コミットを不完全な状態にします。

意図的に除外され、コミットを不完全にしないテストもあります:

- **テストヘルパーの除外設定。** `ExUnit.start(exclude: [...])` がデフォルトで除外するテストは、プロジェクトのスイートがデフォルトで実行する範囲の選択であり、Tuistはこれらを欠落としてカウントしません。これらのカバレッジをコミットに追加するには、別のジョブで `--include` または `--only` を使用して実行します。
- **コード内でスキップされたテスト**。`@tag :skip` を使用します。
- **<.localized_link href="/guides/features/test-insights/flaky-tests/elixir#quarantining">検疫</.localized_link>でスキップされたテスト。** これらは削除されたものとして除外されるため、それらだけがカバーしていた行は未カバーとしてカウントされます。

### 完全および不完全なコミット {#commit-status}

ダッシュボード上の各コミットにはステータスがあります:

| ステータス | 意味 |
| --- | --- |
| 進行中 | 実行がカバレッジを報告していますが、`mix tuist.coverage.complete` がそのコミットに対してまだ実行されていません。 |
| 完了 | コミットの実行に含まれるすべてのテストが実行されたか、意図的に除外されました。 |
| 不完全 | 一部のカバレッジを特定できなかったため、数値は下限となります。 |
| 未測定 | コミットに対してカバレッジを報告した実行がありません。 |

ブランチのトレンドには完了したコミットのみが含まれます。コミットが不完全になる例としては、以下のような場合です:

- バリアントのすべての実行が、独自の引数によってテストを除外しました。
- バリアントのすべての実行で、一部のシャードが欠落していました。
- バリアントのカバレッジが、未コミットの変更があるチェックアウトでのCI実行からのみ得られました。

バリアントとは、`--scheme` で渡すラベル（データベースのバージョンなど）のことです。ラベルのない実行は1つのバリアントとして扱われます。コミットの数値はすべての実行を統合しますが、Tuistは各バリアントの完全性を個別に確認するため、各バリアントには何も除外しない実行が必要です。

## パフォーマンスへの影響 {#performance-impact}

カバレッジの収集にはオーバーヘッドがかかるため、`--cover` を使用した実行は使用しない場合よりも時間がかかります。初回の実行ではモジュールが行カウンター付きで再コンパイルされますが、以降の実行では変更された部分のみが再コンパイルされるため、コストは大幅に低減します。大規模なプロジェクトでは、ネイティブなカウントはMixのカバレッジツールよりもはるかに高速です。

## 制限事項 {#limitations}

- **HTMLレポートはありません。** ネイティブなカウントでは `test_coverage: [output: ...]` ディレクトリにレポートを書き出さず、設定されている場合は実行時に警告が表示されます。代わりに、ダッシュボードのファイルページでカバーされた行を確認できます。
- **リトライではカバレッジは追加されません。** <.localized_link href="/guides/features/test-insights/flaky-tests/elixir#test-retries">テストのリトライ</.localized_link>を使用する場合、カバレッジは初回試行のものになります。初回試行ですでに失敗したテストが実行されているため、欠落する行は、不安定なテストがリトライ時には到達するが初回試行時には到達しなかった行のみです。
- **フォークからのプルリクエストからはカバレッジを取得できません。** カバレッジはTuistで認証された実行によってのみアップロードされます。CIは通常、フォークから開かれたプルリクエストに対してシークレットやIDトークンを提供しないため、これらの実行ではカバレッジが報告されません。マージされると、コミットは認証情報を使用してあなたのブランチで実行され、通常通りカバレッジを報告します。

## カバレッジのクエリ {#querying}

ダッシュボードの **コードカバレッジ** ページでは、各コミットの数値、アプリケーション、ファイル、および各実行でカバーされた行が表示されます。同じデータは、<.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocolサーバー</.localized_link>を通じてエージェントからも利用可能です。
