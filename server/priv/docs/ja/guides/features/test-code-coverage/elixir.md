# Elixirのコードカバレッジ {#elixir-code-coverage}

コードカバレッジは、テストが実行したコードの行を示します。Hexパッケージは `mix test --cover` の各実行における行カバレッジをアップロードし、Tuistはコミット内のすべての実行をプロジェクト全体、各OTPアプリケーション、および各ファイルごとに1つの数値に集約します。ダッシュボードの **コードカバレッジ** ページでは、コミットごとの結果とブランチごとの推移を確認できます。

> [!IMPORTANT] REQUIREMENTS
> - <.localized_link href="/guides/get-started/elixir-project">共有Elixirセットアップ</.localized_link>を完了してください。これにより、 `mix test` がパッケージ経由でルーティングされます。

## セットアップ {#setup}

### カバレッジ付きでテストを実行する {#run-your-tests}

Tuistを使用しない場合の `mix test` と同様に、 `--cover` を渡します:

```sh
mix test --cover
```

パッケージは、実行のテスト結果とともにカバレッジをアップロードします。スイートが終了すると、同じ `test_coverage` オプションで設定されたMixのカバレッジツールと同様の処理が行われます:

- **サマリー。** 各モジュールのカバレッジと合計値を表示します。 `summary: false` でこれを無効にできます。
- **閾値。** 合計値が閾値を下回ると、実行は終了ステータス3で失敗します。閾値を設定しない場合のデフォルトは90%です:

```elixir
def project do
  [
    test_coverage: [summary: [threshold: 80]]
  ]
end
```

Mixと同様、閾値はサマリーの一部であるため、 `summary: false` は両方を無効にします。実行を失敗させずにサマリーを表示するには、 `threshold: 0` を設定してください。 `test_coverage: [ignore_modules: [...]]` にリストされたモジュールは、サマリーとアップロードから除外されます。

Tuistはコミットごとにカバレッジを追跡するため、プロジェクトはGitリポジトリ内にある必要があります。リポジトリ外での実行では、テスト結果はアップロードされますが、カバレッジはアップロードされません。

カバレッジは、パッケージがアップロードする <.localized_link href="/guides/features/test-insights/elixir#git-history">Git履歴</.localized_link> に依存しており、これによりコミットがそのブランチ上に配置されます。継続的インテグレーション上での実行は常にこれをアップロードし、 `--cover` 実行はどのマシンでもこれをアップロードします。 `--cover` を使用すると、パッケージはプルリクエストの分岐元も特定します。ベースブランチを取得し、必要に応じて浅いクローンを深くします。リモートへの連絡を防ぐには、 `TUIST_GIT_UNSHALLOW_ENABLED=false` を設定してください。

### シャード化された実行 {#sharded-runs}

<.localized_link href="/guides/features/test-sharding/elixir">テストをシャード化</.localized_link>する場合、各シャードを `--cover` で実行してください:

```sh
MIX_ENV=test TUIST_SHARD_INDEX=0 mix tuist.test --cover
```

新しいランナーでは、シャード化ガイドの <.localized_link href="/guides/features/test-sharding/elixir#test-phase">テストフェーズ</.localized_link> にあるbootstrapコマンドを使用します。これにより、シャードがビルドをダウンロードする前にMixがすべての依存関係をコンパイルすることを防ぎ、それに `--cover` を追加します。

シャードは自身のカバレッジのみを報告し、スイートの一部のみを実行するため、閾値のチェックは行いません。Tuistは実行の各シャードを1つの数値に統合します。

各シャードは、ダウンロードしたビルドにカバレッジカウンタを追加します。代わりに一度だけ行うには、ビルドフェーズにも `--cover` を渡してください:

```sh
MIX_ENV=test mix tuist.test.build --shard-max 5 --cover
```

パイプライン実行間でビルドディレクトリを保持し、カバレッジを収集しない実行で再利用する場合は、これをオフにしておきます。そうすることで、そのビルドにはカウンタが含まれなくなります。

### CIで各コミットを完了させる {#complete-each-commit}

コミットのカバレッジは、多くの場合複数のジョブ（シャードごと、データベースバージョンごと、またはアプリケーションごと）から得られます。Tuistは最後に報告されたジョブを自動で検出できないため、明示的に指示する必要があります。コミットのすべてのテストジョブが終了したら、それらすべてに依存するジョブで次を実行してください:

```sh
MIX_ENV=test mix tuist.coverage.complete
```

タスクは `GIT_COMMIT` またはチェックアウトの `HEAD` からコミットを読み取ります。別のコミットを指定するには、 `--commit <sha>` を渡してください。コミットが完了するまで、そのカバレッジは **進行中** と表示され、ブランチの推移には含まれません。

## 仕組み {#how-it-works}

### ネイティブ行カウンタ {#native-line-counters}

Mixのカバレッジツールは、各実行の開始時にErlangの `cover` 用にすべてのモジュールを再コンパイルするため、大規模なプロジェクトでは低速になります。このパッケージは代わりにランタイムのネイティブ行カウンタを使用して計測します。前回の実行以降にコンパイルによって書き込まれたモジュールのみを再コンパイルし、ランタイムをこれらのカウンタに切り替えて、スイート終了時に読み取ります。Mixのカバレッジツールは使用されませんが、そのサマリーと閾値の設定は維持されます。

パッケージは、以下の場合にMixのカバレッジツールにフォールバックし、同じアップロード処理を行います:

- アンブレラプロジェクトのルート。ネイティブ計測を行うには、各アプリケーション内でテストを実行してください。
- 独自の `test_coverage: [tool: ...]` を設定しているプロジェクト。
- JITのないランタイム。ネイティブ計測が不可能です。

### Tuistが計測するもの {#what-tuist-measures}

- **アプリケーション。** 各OTPアプリケーションはダッシュボード上のターゲットとなり、独自のカバレッジを持ちます。
- **プロダクトコードのみ。** テストパス下のファイルはテストコードです。Tuistはこれらを保存しますが、すべての数値からは除外します。
- **ファイルごとの行。** 行は、それが属するモジュールの数に関わらず、ファイルごとに1回だけ計数されます。
- **関数。** 各行は、その直上で最も近く開始される節を持つ関数に属します。コンパイラやマクロが生成する関数（ `__info__/1` や `__schema__/1` など）はリストされませんが、それらの行はファイルの計数に含まれます。

したがって、Tuistの数値はMix独自のカバレッジレポートとは以下の点で異なります。テストコードを除外し、モジュール単位ではなくファイル単位で行を計数します。また、ネイティブ計測ではアプリケーション起動時に実行されるコードも認識し、コンパイラが決して実行されないことを証明した行を除外します（Mixのツールではこれらの行は「未カバー」として報告されます）。

### スキップされたテスト {#skipped-tests}

Tuistは、実行で除外されたテストのカバレッジを引き継ぐことができません。パッケージは各テストの実行内容ではなく、実行全体の結果を記録するためです。そのため、実行の引数（ `--only` 、 `--exclude` 、 `--failed` 、 `--stale` 、 `--name-pattern` 、 `--max-failures` 、またはテストファイルや行の指定）によってテストが除外されると、何も除外していない同じバリアントの実行も行われていない限り、コミットのカバレッジは **不完全** となります。 `--exclude slow` と `--only slow` のように、それぞれがテストを除外する2つの実行は、合わせてすべてのテストを実行した場合でも、コミットを不完全な状態にします。

意図的に除外され、コミットを不完全にしないテストもあります:

- **テストヘルパーの除外設定。** `ExUnit.start(exclude: [...])` がデフォルトで除外するテストは、プロジェクトのデフォルトのスイート実行範囲としての選択であり、Tuistはこれらを欠落として計数しません。 `--include` または `--only` を使用して別のジョブでこれらを実行し、コミットのカバレッジに追加してください。
- **コード内でスキップされたテスト** 。 `@tag :skip` を使用します。
- **<.localized_link href="/guides/features/test-insights/flaky-tests/elixir#quarantining">隔離</.localized_link>によってスキップされたテスト。** これらは削除されたものとして扱われるため、これらのテストのみがカバーしていた行は未カバーとして計数されます。

### 完全および不完全なコミット {#commit-status}

ダッシュボード上の各コミットにはステータスがあります:

| ステータス | 意味 |
| --- | --- |
| 進行中 | 実行からカバレッジが報告されていますが、 `mix tuist.coverage.complete` がそのコミットに対してまだ実行されていません。 |
| 完了 | コミットの実行に含まれるすべてのテストが実行されたか、意図的に除外されました。 |
| 不完全 | 一部のカバレッジを特定できなかったため、数値は下限となります。 |
| 未測定 | コミットに対してカバレッジを報告した実行がありません。 |

ブランチのトレンドには完全なコミットのみが含まれます。コミットが不完全になる例としては、以下のような場合です:

- バリアントのすべての実行で、独自の引数によってテストが除外されました。
- バリアントのすべての実行で、一部のシャードが欠落していました。
- バリアントのカバレッジが、未コミットの変更を含むチェックアウトでのCI実行からのみ提供されました。

バリアントとは、 `--scheme` で渡すラベル（データベースバージョンなど）のことです。ラベルのない実行は1つのバリアントとして扱われます。コミットの図はすべての実行を統合しますが、Tuistは各バリアントの完全性を個別に確認するため、各バリアントには何も除外しない実行が必要です。

## パフォーマンスへの影響 {#performance-impact}

カバレッジの収集にはオーバーヘッドがかかるため、 `--cover` を使用した実行は使用しない場合よりも時間がかかります。最初の実行ではモジュールが行カウンタ付きで再コンパイルされますが、以降の実行では変更部分のみが再コンパイルされるため、コストは大幅に低減します。大規模なプロジェクトでは、ネイティブ計測はMixのカバレッジツールよりもはるかに高速です。

## 制限事項 {#limitations}

- **HTMLレポートなし。** ネイティブ計測では `test_coverage: [output: ...]` ディレクトリにレポートを書き込まないため、設定されている場合は実行時に警告が表示されます。代わりに、ダッシュボードのファイルページでカバーされた行を確認できます。
- **再試行ではカバレッジは追加されません。** <.localized_link href="/guides/features/test-insights/flaky-tests/elixir#test-retries">テスト再試行</.localized_link>を使用する場合、カバレッジは初回試行のものになります。この試行ですでに失敗したテストが実行されているため、欠落する行は不安定なテストが再試行では到達するものの初回試行では到達しなかった行のみです。
- **フォークからのプルリクエストからはカバレッジを取得できません。** カバレッジはTuistで認証された実行によってのみアップロードされます。CIは通常、フォークから開かれたプルリクエストに対してシークレットやIDトークンを提供しないため、これらの実行からはカバレッジが報告されません。マージされると、コミットは資格情報を使用してあなたのブランチで実行され、通常通りカバレッジを報告します。

## カバレッジのクエリ {#querying}

ダッシュボードの **コードカバレッジ** ページには、各コミットの図、アプリケーション、ファイル、および各実行でカバーされた行が表示されます。同じデータは、 <.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocolサーバー</.localized_link>を通じてエージェントからも利用可能です。
