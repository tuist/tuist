# Slack 用 Tuist インテグレーション {#slack}

Slack 用 Tuist インテグレーションは、ビルド、テスト、バンドルのインサイトをあなたのチャンネルに直接表示します。モニタリングを「チームが忘れずに行う必要がある作業」から「自動で行われるもの」へと変えます。例えば、ビルドパフォーマンス、キャッシュヒット率、バンドルサイズの傾向に関する毎日のサマリーを受け取ったり、主要な指標が悪化したりテストが不安定になった瞬間に即時アラートを受け取ったりできます。

このページでは、インテグレーションの機能、チャンネルごとにインストールする方法、Tuist がデータをどのように扱うかについて説明します。Tuist がサードパーティのデータを収集、管理、保存する方法の詳細については、[プライバシーポリシー](https://tuist.dev/privacy)をご覧ください。

## インテグレーションの仕組み {#how-it-works}

Tuist は Slack の [Incoming Webhooks](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks) を介して Slack に通知を送信します。このインテグレーションが要求するスコープは `incoming-webhook` のみです。各通知宛先（プロジェクトレポート、アラートルール、不安定なテストのアラート、自動化アクション）は、インストール時に選択した単一の Slack チャンネルに対応します。Slack はチャンネルごとに 1 つの Webhook URL を作成し、Tuist はそれを保存してメッセージを配信します。

Tuist はワークスペースからメッセージ、メンバーリスト、その他のデータを読み取ることはありません。このインテグレーションは、明示的に承認したチャンネルへの通知の書き込みのみを行います。

## セットアップ {#setup}

### プロジェクトレポート {#project-reports}

プロジェクトレポートは、プロジェクトのビルド、テスト、キャッシュの指標に関する毎日のサマリーを、選択した Slack チャンネルに配信します。

1. Tuist ダッシュボードでプロジェクトの通知設定を開きます。
2. **Select Slack channel** をクリックし、Tuist が投稿先のワークスペースとチャンネルを選択します。Slack から `incoming-webhook` スコープの承認と単一チャンネルの選択を求められます。
3. 毎日のレポートを受信したい曜日と時間を選択します。

![Slack レポート設定を含む通知設定を示す画像](/images/guides/integrations/slack/notifications-settings.png)

設定が完了すると、Tuist は選択したチャンネルに自動的な毎日のレポートを送信します：

### アラートルール {#alert-rules}

アラートルールは、主要な指標が大幅に悪化したときに Slack で通知し、ビルドの遅延、キャッシュの劣化、テストの低速化をできるだけ早く検知するのに役立ちます。

アラートルールを作成するには、プロジェクトの通知設定に移動し、**Add alert rule** をクリックします。次の項目を設定できます：

- **Name**：アラートの説明的な名前
- **Category**：測定対象（ビルド時間、テスト時間、キャッシュヒット率、またはバンドルサイズ）
- **Metric**：データの集計方法（p50、p90、p99、または平均）
- **Deviation**：アラートをトリガーする変化率
- **Rolling window**：比較対象とする直近の実行数
- **Branch**：キャッシュヒット率のアラートの場合、比較を単一ブランチ上の実行に制限します。空のままにするとすべてのブランチを対象とします。バンドルサイズのアラートは常に単一ブランチを対象とします。
- **Slack channel**：宛先チャンネル。上記と同じ `incoming-webhook` フローを通じてチャンネルを承認します。

例えば、過去 100 回のビルドと比較して p90 ビルド時間が 20% 以上増加した場合にトリガーされるアラートを作成できます。

キャッシュヒット率のアラートをデフォルトブランチに限定することは、そのブランチのみがキャッシュを生成する場合に有効です。低レベルのモジュールに触れるプルリクエストブランチは正当にキャッシュミスとなり、それらを含めると期待される悪化に対してアラートが発火してしまいます。

キャッシュヒット率のアラートは、公平に比較できるウィンドウのみを比較します。両方のウィンドウにはローリングウィンドウサイズと同じ数の実行が含まれている必要があり、2 つのウィンドウの片方にしか現れないキャッシュデータソースは双方から除外されます。したがって、実行数がローリングウィンドウサイズの 2 倍にまだ達していないブランチや、何も一致しないブランチ名はルールをトリガーしません。トラフィックの少ないブランチにルールを限定する場合は、ブランチがウィンドウを満たせるようにローリングウィンドウを十分に小さくしてください。

アラートがトリガーされると、Slack チャンネルに次のようなメッセージが届きます：

<img src="/images/guides/integrations/slack/alert.png" alt="Slack アラートメッセージを示す画像" style="max-width: 500px;" />

### 不安定なテストのアラート {#flaky-test-alerts}

不安定なテストのアラートは、Tuist が新しい不安定なテストを検出した瞬間にトリガーされ、チームに影響が出る前にテストの不安定性を検知するのに役立ちます。

不安定なテストのアラートルールを作成するには、プロジェクトの通知設定に移動し、**Add flaky test alert rule** をクリックします。次の項目を設定できます：

- **Name**：アラートの説明的な名前
- **Trigger threshold**：アラートをトリガーするために必要な過去 30 日間の不安定な実行の最小回数
- **Slack channel**：宛先チャンネル。`incoming-webhook` フローを通じて承認されます。

テストが不安定になり、しきい値を満たすと、テストケースを調査するための直接リンクを含む通知が届きます：

<img src="/images/guides/integrations/slack/flaky-test-alert.png" alt="Slack の不安定なテストアラートメッセージを示す画像" style="max-width: 500px;" />

### 遅いテストのアラート {#slow-test-alerts}

遅いテストのアラートは、個々のテストケースの実行時間が設定した期間を超えると通知し、Test Cases テーブルで遅いテストを確認する必要をなくします。

作成するには、プロジェクトの **Settings → Automations** に移動し、**Add automation** をクリックして、**When** の下で **Test duration** を選択します。次の項目を設定できます：

- **Statistic**：テストケースの実行時間の平均、p50、p90、または p99。
- **Comparison** と **Seconds**：例えば、10 秒以上。
- **Window**：統計が計算されるカレンダーウィンドウ（例：`30d`）。
- **Actions**：デフォルトで **Send Slack notification** アクションが追加されます。テストをミュートまたはスキップすることもできます。

実行時間は、Test Cases テーブルと同様に、すべてのブランチでの CI およびローカル実行に基づいて計算されます。測定されるには、ウィンドウ内に少なくとも 5 回の実行が必要です。各テストケースはしきい値を超えたときに 1 回トリガーされます。**Recovery** が有効な場合、テストが回復ウィンドウの間しきい値を下回ると、オートメーションが再アームされ（回復アクションを実行します）。

## 統合の切断 {#disconnect}

通知を停止するには、Tuist ダッシュボードでレポート、アラートルール、またはオートメーションアクションから設定済みの Slack チャンネルを削除してください。Tuist のアクセスを完全に無効にするには、Slack 内で **Settings & administration → Manage apps** を経由して Webhook 統合を削除してください。
