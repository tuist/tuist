# データ保持 {#data-retention}

Tuistは、アップロードされたアーティファクトファイルとダッシュボードやインサイトで使用されるレコードに対して、それぞれ別の保持ポリシーを適用します。期限切れのアーティファクトファイルを削除しても、関連するインサイトのレコードは削除されません。

アーティファクトファイルについて、ホスト型Tuistサーバーではプランに基づく保持期間が適用され、最大30日までです。セルフホスト型インスタンスでは、アーティファクトのクリーンアップはデフォルトで無効になっており、オペレーターはオプトインして、サポートされている各アーティファクトタイプごとに個別の保持期間を設定できます。

## アーティファクトファイル {#artifact-files}

### ホスト型Tuistサーバー {#hosted-artifact-files}

これらの保持期間は、ホスト型Tuistサーバー上でアーティファクトファイルが利用可能である期間を定義します。

| アーティファクト | Airおよびオープンソース | Pro | Enterprise |
| --- | --- | --- | --- |
| キャッシュアーティファクト（Xcodeキャッシュ、モジュールキャッシュ、Gradleキャッシュ、Bazelリモートキャッシュファイル、およびTuist RunnerからのGitLab CIキャッシュアーカイブを含む） | 14日間 | 30日間 | 30日間 |
| アプリプレビューのビルドとアイコン | 30日間 | 30日間 | 30日間 |
| ビルドアーカイブ | 7日間 | 30日間 | 30日間 |
| 実行アーティファクト（結果バンドルとセッションアーカイブを含む） | 7日間 | 30日間 | 30日間 |
| テスト実行の添付ファイル | 30日間 | 30日間 | 30日間 |
| シャードバンドル | 7日間 | 14日間 | 30日間 |

有効なアカウントプランがホスト型の保持期間を決定します。アカウントに有効なサブスクリプションがない場合、TuistはAirの保持期間を適用します。一部のアーティファクトタイプは再生成されることが想定されているため、より短い保持期間が設定されています。

Tuistがテスト実行IDを記録する前に作成されたテスト添付ファイルは、自動削除の対象から除外されます。これらのファイルは、保持期間のクリーンアップ中にTuistが無制限な過去の所有権検索を回避している間も利用可能です。

### セルフホスト型インスタンス {#self-hosted-artifact-files}

セルフホスト型のアーティファクトクリーンアップはオプトイン式で、アーティファクトタイプごとに個別に設定でき、30日間の上限はありません。サポートされているアーティファクトタイプとデプロイメントオプションについては、<.localized_link href="/guides/server/self-host/server#artifact-retention">セルフホスト型アーティファクト保持構成</.localized_link>をご覧ください。

## ダッシュボードとアクティビティデータ {#dashboard-and-activity-data}

ダッシュボードとアクティビティのレコードには、アーティファクトファイルのクリーンアップとは独立した保持ポリシーがあります。以下の保持期間は、Enterpriseを含むホスト型プランによって変化しません。

### Xcodeビルドおよびテストのインサイト {#xcode-build-and-test-insights}

コアとなるXcodeビルドおよびテストのレコードには、現在、固定された時間ベースの削除スケジュールはありません。タイムラインステップやマシンメトリクスなどの他のレポートデータは、個別に期限切れになります：

| データ | 保持期間 |
| --- | --- |
| ビルドサマリー、ファイルごとおよびターゲットごとのビルドレコード、ビルドの問題 | 固定された時間ベースの削除スケジュールなし |
| テスト実行、モジュールおよびスイートの結果、個々のテスト結果 | 固定された時間ベースの削除スケジュールなし |
| ビルドタイムラインのステップとキャプチャされたログ | 90日間 |
| ビルドマシンのメトリクス | 90日間 |
| Xcodeプロジェクトグラフのレコード | 30日間 |

これらのレコードは、[アーティファクトファイルの保持期間](#hosted-artifact-files)でカバーされるダウンロード可能なビルドアーカイブ、結果バンドル、およびテスト添付ファイルとは別物です。Enterpriseでは、それらのファイルは30日間保持されます。関連するビルドおよびテストのレコードは、ファイルの有効期限が切れた後も利用可能です。固定された時間ベースの削除スケジュールがないレコードであっても、永続的な可用性を保証するものではありません。

### その他のダッシュボードおよびアクティビティデータ {#other-dashboard-and-activity-data}

Bazelインデックス付きプロファイルのステップには、アクションと安全に関連付けられる場合、アクションごとのリモートキュー、入力フェッチ、実行、および出力アップロードのタイミング（null許容）が含まれます。これらは、キャッシュされたアーティファクトや課金レコードとは独立して、プロファイルの90日間の保持期間を共有します。

| データ | 保持期間 |
| --- | --- |
| Gradleビルドレコード、タスクレコード、失敗したタスクおよび構成ステップのエラーメッセージ、キャッシュイベントレコード、Mixビルドレコード、コンパイル済みファイルレコード、ビルドステップレコードと診断情報、Cargoビルドレコード（集計コンパイルキャッシュ測定値を含む）とコンパイラ観測値、Bazel呼び出し、Bazelトレースプロファイル、インデックス付きプロファイルステップとアクション診断、保留中のBazelプロファイルおよびテスト取り込みレコード、Bazel呼び出しログ、Bazelリモートアクションキャッシュ観測値 | 90日間 |
| 永続的なモジュール詳細ページ上のXcodeモジュールコンパイルおよびキャッシュ履歴 | 30日間 |
| 永続的な詳細ページ上のタスク、宣言されたOnceアクション、Bazel BEPアクション、コンパイル済みファイルおよびモジュールの観測値 | 上記のXcodeモジュールを除き90日間 |
| 永続的なタスク/アクション/モジュール/ファイルの識別メタデータ | 観測値がない場合は365日間 |
| Runnerジョブログ、アーカイブされたRunnerログ、Runnerジョブのマシンメトリクス | 90日間 |
| コードカバレッジ行の詳細（各テスト実行の行ごとおよび関数ごとのカバレッジ。ファイルのカバレッジページに表示） | 31日間 |
| 各テスト実行のコードカバレッジ合計 | 365日間 |
| コミットのコードカバレッジ（合計、ターゲット、ファイルごとの数値） | 3年間。プルリクエストによってのみ追加されたコミットの場合は90日間 |
| Webhook配信履歴 | 固定された削除スケジュールなし |

永続的な詳細URLは、特定のビルドが引き続き利用可能であることに依存しません。識別メタデータは個々の観測値よりも長く存続する可能性があるため、詳細ページには選択した期間の履歴がない場合があります。新しい履歴は、機能のデプロイ後に受信したレポートからインデックス付けされます。既存の実行レベルの履歴は遡及的にコピーされません。

ClickHouseの内部`system.*`運用ログテーブルは、Tuistの製品データ保持ポリシーではなく、ClickHouse層で構成されます。デフォルトでは上限がありません。バンドルされているセルフホスト型Docker Composeおよび組み込みHelm ClickHouse構成では、<.localized_link href="/guides/server/self-host/server#capping-operational-log-retention">運用ログの保持期間に上限を設定</.localized_link>することで制限できます。
