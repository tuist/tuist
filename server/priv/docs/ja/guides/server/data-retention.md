# データの保持 {#data-retention}

Tuistは、アップロードされたアーティファクトファイルとダッシュボードおよびインサイト用のレコードに対して、それぞれ別の保持ポリシーを適用します。期限切れのアーティファクトファイルを削除しても、関連するインサイトのレコードは削除されません。

アーティファクトファイルの場合、ホスト型Tuistサーバーではプランに基づいた保持期間が適用され、最大30日までとなります。セルフホスト型インスタンスでは、アーティファクトのクリーンアップはデフォルトで無効になっており、管理者はオプトインして、サポートされている各アーティファクトタイプごとに個別の保持期間を設定できます。

## アーティファクトファイル {#artifact-files}

### ホスト型Tuistサーバー {#hosted-artifact-files}

これらの保持期間は、ホスト型Tuistサーバー上でアーティファクトファイルが利用可能な期間を定義します。

| アーティファクト | Airおよびオープンソース | Pro | Enterprise |
| --- | --- | --- | --- |
| キャッシュアーティファクト（Xcodeキャッシュ、モジュールキャッシュ、Gradleキャッシュ、Bazelリモートキャッシュファイル、Tuist RunnerからのGitLab CIキャッシュアーカイブを含む） | 14日間 | 30日間 | 30日間 |
| アプリプレビュービルドとアイコン | 30日間 | 30日間 | 30日間 |
| ビルドアーカイブ | 7日間 | 30日間 | 30日間 |
| 実行アーティファクト（結果バンドル、セッションアーカイブ、Bazelリモートアクションログを含む） | 7日間 | 30日間 | 30日間 |
| テスト実行の添付ファイル | 30日間 | 30日間 | 30日間 |
| シャードバンドル | 7日間 | 14日間 | 30日間 |

有効なアカウントプランがホスト型の保持期間を決定します。アカウントに有効なサブスクリプションがない場合、TuistはAirの保持期間を適用します。一部のアーティファクトタイプは再生成されることを想定しているため、より短い保持期間が設定されています。

Tuistがテスト実行IDを記録する前に作成されたテスト添付ファイルは、自動削除の対象外です。保持期間のクリーンアップ中にTuistが無制限な履歴所有権の検索を行わないよう、これらのファイルは引き続き利用可能です。

### セルフホスト型インスタンス {#self-hosted-artifact-files}

セルフホスト型アーティファクトのクリーンアップはオプトイン方式で、アーティファクトタイプごとに個別に設定可能であり、30日間の上限はありません。サポートされているアーティファクトタイプとデプロイオプションについては、<.localized_link href="/guides/server/self-host/server#artifact-retention">セルフホスト型アーティファクト保持設定</.localized_link>をご覧ください。

## ダッシュボードとアクティビティデータ {#dashboard-and-activity-data}

ダッシュボードとアクティビティのレコードには、アーティファクトファイルのクリーンアップとは独立した保持ポリシーがあります。以下の保持期間は、Enterpriseを含むホスト型プランによって変化しません。

### Xcodeビルドとテストのインサイト {#xcode-build-and-test-insights}

コアとなるXcodeビルドおよびテストのレコードには、現在、固定された時間ベースの削除スケジュールはありません。タイムラインステップやマシンメトリクスなどの他のレポートデータは、別途有効期限が設定されます。

| データ | 保持期間 |
| --- | --- |
| ビルドサマリー、ファイルごとおよびターゲットごとのビルドレコード、ビルドの問題 | 固定された時間ベースの削除スケジュールなし |
| テスト実行、モジュールおよびスイートの結果、個別のテスト結果 | 固定された時間ベースの削除スケジュールなし |
| ビルドのタイムラインステップとそのキャプチャされたログ | 90日間 |
| ビルドマシンのメトリクス | 90日間 |
| Xcodeプロジェクトグラフのレコード | 30日間 |

これらのレコードは、[アーティファクトファイルの保持期間](#hosted-artifact-files)でカバーされるダウンロード可能なビルドアーカイブ、結果バンドル、テスト添付ファイルとは別物です。Enterpriseでは、それらのファイルは30日間保持されます。関連するビルドおよびテストのレコードは、ファイルの有効期限が切れた後も利用可能です。固定された時間ベースの削除スケジュールがないレコードであっても、永続的な可用性が保証されるわけではありません。

### その他のダッシュボードおよびアクティビティデータ {#other-dashboard-and-activity-data}

Bazelのインデックス付きプロファイルステップには、アクションに安全に関連付けられる場合、アクションごとのリモートキュー、入力フェッチ、実行、出力アップロードのタイミング（null許容）が含まれます。これらは、キャッシュされたアーティファクトや課金レコードとは独立して、プロファイルと同じ90日間の保持期間を共有します。

| データ | 保持期間 |
| --- | --- |
| Gradleビルドレコード、タスクレコード、失敗したタスクおよび構成ステップのエラーメッセージ、キャッシュイベントレコード、Mixビルドレコード、コンパイル済みファイルレコード、ビルドステップレコードおよび診断情報、Cargoビルドレコード（集計コンパイルキャッシュ測定値を含む）およびコンパイラ観測値、Bazel呼び出し、Bazelトレースプロファイル、インデックス付きプロファイルステップおよびアクション診断、保留中のBazelプロファイルおよびテスト取り込みレコード、Bazel呼び出しログ、Bazelリモートアクションキャッシュ観測値、リモートで実行されたアクションのレコード（コマンド、環境、プラットフォーム、終了コード、および出力の開始部分） | 90日間 |
| Bazel呼び出しの開始（完了まで実行中としてリストされる） | 2日間 |
| 永続的なモジュール詳細ページ上のXcodeモジュールコンパイルおよびキャッシュ履歴 | 30日間 |
| 永続的な詳細ページ上のタスク、宣言されたStruoアクション、Bazel BEPアクション、コンパイル済みファイルおよびモジュールの観測値 | 90日間（上記のXcodeモジュールを除く） |
| 永続的なタスク/アクション/モジュール/ファイルの識別メタデータ | 観測値がない場合は365日間 |
| Runnerジョブログ、アーカイブされたRunnerログ、Runnerジョブのマシンメトリクス | 90日間 |
| コードカバレッジ行の詳細（各テスト実行の行ごとおよび関数ごとのカバレッジ。ファイルのカバレッジページに表示） | 31日間 |
| 各テスト実行のコードカバレッジ合計 | 365日間 |
| コミットのコードカバレッジ（合計、ターゲット、ファイルごとの数値） | 3年間。プルリクエストによってのみ追加されたコミットの場合は90日間 |
| Webhook配信履歴 | 固定された削除スケジュールなし |

永続的な詳細URLは、特定のビルドが引き続き利用可能であることに依存しません。識別メタデータは個々の観測値よりも長期間存続するため、選択した期間中に詳細ページに履歴が存在しない場合があります。新しい履歴は、機能のデプロイ後に受信したレポートからインデックス化されます。既存の実行レベルの履歴は遡及的にコピーされません。

ClickHouseの内部`system.*`運用ログテーブルは、Tuistの製品データ保持ポリシーではなく、ClickHouse層で構成されます。デフォルトでは上限が設定されていません。バンドルされているセルフホスト用Docker Composeおよび埋め込みHelm ClickHouse構成では、<.localized_link href="/guides/server/self-host/server#capping-operational-log-retention">運用ログの保持に上限を設定する</.localized_link>で説明されているように、これらに上限を設定できます。
