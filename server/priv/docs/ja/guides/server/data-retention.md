# データ保持 {#data-retention}

Tuistは、アップロードされたアーティファクトファイルと、ダッシュボードおよびインサイトのために使用されるレコードに対して、それぞれ異なる保持ポリシーを適用します。期限切れのアーティファクトファイルを削除しても、関連するインサイトのレコードは削除されません。

アーティファクトファイルの場合、ホスト型Tuistサーバーではプランに基づいた保持期間が適用され、最大30日までとなります。セルフホスト型のインスタンスでは、アーティファクトのクリーンアップはデフォルトで無効になっており、管理者がオプトインして、サポートされている各アーティファクトタイプごとに個別の保持期間を設定できます。

## アーティファクトファイル {#artifact-files}

### ホスト型Tuistサーバー {#hosted-artifact-files}

これらの保持期間は、ホスト型Tuistサーバー上でアーティファクトファイルが利用可能な期間を定義します。

| アーティファクト | Airおよびオープンソース | Pro | Enterprise |
| --- | --- | --- | --- |
| キャッシュアーティファクト（Xcodeキャッシュ、モジュールキャッシュ、Gradleキャッシュ、Bazelリモートキャッシュファイル、Tuist RunnersからのGitLab CIキャッシュアーカイブを含む） | 14日 | 30日 | 30日 |
| アプリプレビューのビルドとアイコン | 30日 | 30日 | 30日 |
| ビルドアーカイブ | 7日 | 30日 | 30日 |
| 実行アーティファクト（結果バンドルとセッションアーカイブを含む） | 7日 | 30日 | 30日 |
| テスト実行の添付ファイル | 30日 | 30日 | 30日 |
| シャードバンドル | 7日 | 14日 | 30日 |

有効なアカウントプランが、ホスト型の保持期間を決定します。アカウントに有効なサブスクリプションがない場合、TuistはAirの保持期間を適用します。一部のアーティファクトタイプは再生成されることが想定されているため、より短い保持期間が適用されます。

Tuistがテスト実行IDを記録する前に作成されたテスト添付ファイルは、自動削除の対象外です。保持期間のクリーンアップ中にTuistが無制限な履歴所有権の検索を回避している間、これらのファイルは引き続き利用可能です。

### セルフホスト型インスタンス {#self-hosted-artifact-files}

セルフホスト型のアーティファクトクリーンアップはオプトイン方式で、各アーティファクトタイプごとに個別に設定でき、30日の上限はありません。サポートされているアーティファクトタイプとデプロイオプションについては、<.localized_link href="/guides/server/self-host/server#artifact-retention">セルフホスト型アーティファクト保持構成</.localized_link>をご覧ください。

## ダッシュボードおよびアクティビティデータ {#dashboard-and-activity-data}

ダッシュボードおよびアクティビティのレコードには、アーティファクトファイルのクリーンアップとは独立した保持ポリシーがあります。以下の保持期間は、Enterpriseを含め、ホスト型プランによって変わりません。

### Xcodeビルドおよびテストのインサイト {#xcode-build-and-test-insights}

コアとなるXcodeビルドおよびテストのレコードには、現在、固定された時間ベースの削除スケジュールはありません。タイムラインステップやマシンメトリクスなどの他のレポートデータは、個別に期限切れになります：

| データ | 保持期間 |
| --- | --- |
| ビルドサマリー、ファイル別およびターゲット別ビルド記録、ビルドの問題 | 固定された時間ベースの削除スケジュールなし |
| テスト実行、モジュールおよびスイートの結果、個々のテスト結果 | 固定された時間ベースの削除スケジュールなし |
| ビルドタイムラインのステップとキャプチャされたログ | 90日 |
| ビルドマシンのメトリクス | 90日 |
| Xcodeプロジェクトグラフの記録 | 30日 |

これらの記録は、[アーティファクトファイルの保持期間](#hosted-artifact-files)で対象となるダウンロード可能なビルドアーカイブ、結果バンドル、テスト添付ファイルとは別物です。Enterpriseでは、それらのファイルは30日間保持されます。関連するビルドおよびテストの記録は、ファイルの有効期限が切れた後も利用可能です。固定された時間ベースの削除スケジュールがない記録であっても、永久な可用性を保証するものではありません。

### その他のダッシュボードおよびアクティビティデータ {#other-dashboard-and-activity-data}

| データ | 保持期間 |
| --- | --- |
| Gradleビルド記録、タスク記録、キャッシュイベント記録、Mixビルド記録、コンパイル済みファイル記録、ビルドステップ記録と診断情報、Cargoビルド記録（集計コンパイルキャッシュ測定値を含む）とコンパイラ観測値、Bazel呼び出し、Bazelトレースプロファイル、インデックス付きプロファイルステップとアクション診断情報、保留中のBazelプロファイルおよびテスト取り込み記録、Bazel呼び出しログ、Bazelリモートアクションキャッシュ観測値 | 90日 |
| 永続的なモジュール詳細ページ上のXcodeモジュールコンパイルおよびキャッシュ履歴 | 30日 |
| 永続的な詳細ページ上のタスク、宣言されたOnceアクション、Bazel BEPアクション、コンパイル済みファイルおよびモジュールの観測値 | 上記のXcodeモジュールを除き90日 |
| 永続的なタスク/アクション/モジュール/ファイルの識別メタデータ | 観測値がない場合365日 |
| ランナージョブログ、アーカイブされたランナーログ、ランナージョブのマシンメトリクス | 90日 |
| Webhook配信履歴 | 固定された削除スケジュールなし |

永続的な詳細URLは、特定のビルドが引き続き利用可能であることに依存しません。識別メタデータは個々の観測値よりも長生きするため、詳細ページには選択した期間の履歴がない場合があります。新しい履歴は、機能のデプロイ後に受信したレポートからインデックス付けされます。既存の実行レベルの履歴は遡及的にコピーされません。

ClickHouseの内部`system.*`運用ログテーブルは、Tuistの製品データ保持ポリシーではなく、ClickHouse層で構成されます。デフォルトでは上限がありません。バンドルされているセルフホスト型Docker Composeおよび組み込みHelm ClickHouse構成では、<.localized_link href="/guides/server/self-host/server#capping-operational-log-retention">運用ログの保持上限設定</.localized_link>で説明されているように、これらに上限を設定できます。
