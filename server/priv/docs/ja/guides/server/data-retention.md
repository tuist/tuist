# データ保持 {#data-retention}

Tuistは、アップロードされたアーティファクトファイルとダッシュボードおよびインサイトに使用されるレコードに対して、それぞれ別の保持ポリシーを適用します。期限切れのアーティファクトファイルを削除しても、関連するインサイトレコードは削除されません。

アーティファクトファイルの場合、ホスト型Tuistサーバーではプランに基づく保持期間が適用され、最大30日までとなります。セルフホスト型インスタンスでは、アーティファクトのクリーンアップはデフォルトで無効になっており、オペレーターはオプトインして、サポートされている各アーティファクトタイプごとに個別の保持期間を設定できます。

## アーティファクトファイル {#artifact-files}

### ホスト型Tuistサーバー {#hosted-artifact-files}

これらの保持期間は、ホスト型Tuistサーバー上でアーティファクトファイルが利用可能である期間を定義します。

| アーティファクト | Airおよびオープンソース | Pro | Enterprise |
| --- | --- | --- | --- |
| キャッシュアーティファクト（Xcodeキャッシュ、モジュールキャッシュ、Gradleキャッシュ、Bazelリモートキャッシュファイル、およびTuist RunnersからのGitLab CIキャッシュアーカイブを含む） | 14日 | 30日 | 30日 |
| アプリプレビュービルドとアイコン | 30日 | 30日 | 30日 |
| ビルドアーカイブ | 7日 | 30日 | 30日 |
| 実行アーティファクト（結果バンドルとセッションアーカイブを含む） | 7日 | 30日 | 30日 |
| テスト実行添付ファイル | 30日 | 30日 | 30日 |
| シャードバンドル | 7日 | 14日 | 30日 |

有効なアカウントプランがホスト型の保持期間を決定します。アカウントに有効なサブスクリプションがない場合、TuistはAirの保持期間を適用します。一部のアーティファクトタイプは再生成されることを想定しているため、より短い保持期間が設定されています。

Tuistがテスト実行識別子を記録する前に作成されたテスト添付ファイルは、自動削除の対象外です。これらのファイルは、保持クリーンアップ中にTuistが無制限な履歴所有権の検索を回避している間も利用可能な状態のままとなります。

### セルフホスト型インスタンス {#self-hosted-artifact-files}

セルフホスト型のアーティファクトクリーンアップはオプトイン方式で、アーティファクトタイプごとに個別に設定でき、30日の上限はありません。サポートされているアーティファクトタイプとデプロイオプションについては、<.localized_link href="/guides/server/self-host/server#artifact-retention">セルフホスト型アーティファクト保持設定</.localized_link>をご覧ください。

## ダッシュボードおよびアクティビティデータ {#dashboard-and-activity-data}

ダッシュボードおよびアクティビティレコードには、アーティファクトファイルのクリーンアップとは独立した保持ポリシーがあります。以下の保持期間は、Enterpriseを含め、ホスト型プランによって変わりません。

### Xcodeビルドおよびテストのインサイト {#xcode-build-and-test-insights}

コアとなるXcodeのビルドおよびテストレコードには、現在、時間ベースの固定削除スケジュールはありません。タイムラインステップやマシンメトリクスなどの他のレポートデータは、個別に有効期限が設定されます：

| データ | 保持期間 |
| --- | --- |
| ビルドサマリー、ファイルごとおよびターゲットごとのビルドレコード、ビルドの問題 | 時間ベースの固定削除スケジュールなし |
| テスト実行、モジュールおよびスイートの結果、個々のテスト結果 | 時間ベースの固定削除スケジュールなし |
| ビルドタイムラインステップとそのキャプチャされたログ | 90日 |
| ビルドマシンのメトリクス | 90日 |
| Xcodeプロジェクトグラフのレコード | 30日 |

これらのレコードは、[アーティファクトファイルの保持期間](#hosted-artifact-files)でカバーされるダウンロード可能なビルドアーカイブ、結果バンドル、およびテスト添付ファイルとは別物です。Enterpriseでは、これらのファイルは30日間保持されます。関連するビルドおよびテストレコードは、ファイルの有効期限が切れた後も利用可能です。時間ベースの固定削除スケジュールがないレコードであっても、永久に利用可能であることは保証されません。

### その他のダッシュボードおよびアクティビティデータ {#other-dashboard-and-activity-data}

Bazelインデックス付きプロファイルステップには、アクションと安全に関連付けられる場合、null許容のアクションごとのリモートキュー、入力フェッチ、実行、および出力アップロードのタイミングが含まれます。これらは、キャッシュされたアーティファクトや課金レコードとは独立して、プロファイルの90日の保持期間を共有します。

| データ | 保持期間 |
| --- | --- |
| Gradleビルドレコード、タスクレコード、失敗したタスクおよび構成ステップのエラーメッセージ、キャッシュイベントレコード、Mixビルドレコード、コンパイル済みファイルレコード、ビルドステップレコードおよび診断情報、Cargoビルドレコード（集計コンパイルキャッシュ測定値を含む）およびコンパイラ観測値、Bazel呼び出し、Bazelトレースプロファイル、インデックス付きプロファイルステップおよびアクション診断情報、保留中のBazelプロファイルおよびテスト取り込みレコード、Bazel呼び出しログ、およびBazelリモートアクションキャッシュ観測値 | 90日 |
| Bazel呼び出しの開始（完了まで実行中としてリストされる） | 2日 |
| 永続的なモジュール詳細ページ上のXcodeモジュールコンパイルおよびキャッシュ履歴 | 30日 |
| 永続的な詳細ページ上のタスク、宣言されたOnceアクション、Bazel BEPアクション、コンパイル済みファイルおよびモジュールの観測値 | 90日（上記のXcodeモジュールを除く） |
| 永続的なタスク/アクション/モジュール/ファイルの識別メタデータ | 観測値がない場合は365日 |
| ランナージョブログ、アーカイブされたランナーログ、およびランナージョブのマシンメトリクス | 90日 |
| コードカバレッジ行の詳細（各テスト実行の行ごとおよび関数ごとのカバレッジ。ファイルのカバレッジページに表示） | 31日 |
| 各テスト実行のコードカバレッジ合計 | 365日 |
| コミットのコードカバレッジ（合計、ターゲット、およびファイルごとの数値） | 3年。プルリクエストのみによって追加されたコミットの場合は90日 |
| Webhook配信履歴 | 固定削除スケジュールなし |

永続的な詳細URLは、特定のビルドが利用可能であり続けることに依存しません。識別メタデータは個々の観測値よりも長く存続する可能性があるため、詳細ページには選択した期間の履歴が存在しない場合があります。新しい履歴は、機能のデプロイ後に受信したレポートからインデックス化されます。既存の実行レベルの履歴は遡及的にコピーされません。

ClickHouseの内部`system.*`運用ログテーブルは、Tuistのプロダクトデータ保持ポリシーではなく、ClickHouse層で構成されます。デフォルトでは無制限ですが、バンドルされているセルフホスト用Docker Composeおよび組み込みHelm ClickHouse構成で上限を設定できます。詳細は<.localized_link href="/guides/server/self-host/server#capping-operational-log-retention">運用ログの保持に上限を設定する</.localized_link>をご覧ください。
