# データ保持 {#data-retention}

Tuistは、アップロードされたアーティファクトファイルとダッシュボードおよびインサイトに使用されるレコードに対して、それぞれ異なる保持ポリシーを適用します。期限切れのアーティファクトファイルを削除しても、関連するインサイトレコードは削除されません。

アーティファクトファイルの場合、ホスト型Tuistサーバーではプランに基づいた保持期間が適用され、最大30日までとなります。セルフホスト型インスタンスでは、アーティファクトのクリーンアップはデフォルトで無効になっており、オペレーターはオプトインして、サポートされている各アーティファクトタイプごとに個別の保持期間を設定できます。

## アーティファクトファイル {#artifact-files}

### ホスト型Tuistサーバー {#hosted-artifact-files}

これらの保持期間は、ホスト型Tuistサーバー上でアーティファクトファイルが利用可能な期間を定義します。

| アーティファクト | Airおよびオープンソース | Pro | Enterprise |
| --- | --- | --- | --- |
| キャッシュアーティファクト（Xcodeキャッシュ、モジュールキャッシュ、Gradleキャッシュ、Bazelリモートキャッシュファイル、Tuist RunnersからのGitLab CIキャッシュアーカイブを含む） | 14日間 | 30日間 | 30日間 |
| アプリプレビュービルドとアイコン | 30日間 | 30日間 | 30日間 |
| ビルドアーカイブ | 7日間 | 30日間 | 30日間 |
| 実行アーティファクト（結果バンドルとセッションアーカイブを含む） | 7日間 | 30日間 | 30日間 |
| テスト実行の添付ファイル | 30日間 | 30日間 | 30日間 |
| シャードバンドル | 7日間 | 14日間 | 30日間 |

有効なアカウントプランがホスト型の保持期間を決定します。アカウントに有効なサブスクリプションがない場合、TuistはAirの保持期間を適用します。一部のアーティファクトタイプは再生成されることを想定しているため、より短い保持期間が設定されています。

Tuistがテスト実行IDを記録する前に作成されたテスト添付ファイルは、自動削除の対象から除外されます。これらのファイルは、保持クリーンアップ中にTuistが無制限な履歴所有権の照会を回避している間も利用可能な状態のままとなります。

### セルフホスト型インスタンス {#self-hosted-artifact-files}

セルフホスト型のアーティファクトクリーンアップはオプトイン方式で、アーティファクトタイプごとに個別に設定でき、30日間の上限はありません。サポートされているアーティファクトタイプとデプロイオプションについては、<.localized_link href="/guides/server/self-host/server#artifact-retention">セルフホスト型アーティファクト保持設定</.localized_link>をご覧ください。

## ダッシュボードおよびアクティビティデータ {#dashboard-and-activity-data}

ダッシュボードおよびアクティビティのレコードには、アーティファクトファイルのクリーンアップとは独立した保持ポリシーがあります。以下の保持期間は、Enterpriseを含め、ホスト型プランによって変化しません。

### Xcodeビルドおよびテストのインサイト {#xcode-build-and-test-insights}

主要なXcodeビルドおよびテストのレコードには、現在、固定された時間ベースの削除スケジュールはありません。タイムラインステップやマシンメトリクスなどの他のレポートデータは、別途有効期限が設定されます。

| データ | 保持期間 |
| --- | --- |
| ビルドサマリー、ファイル別およびターゲット別のビルド記録、ビルドの問題 | 固定された時間ベースの削除スケジュールなし |
| テスト実行、モジュールおよびスイートの結果、個々のテスト結果 | 固定された時間ベースの削除スケジュールなし |
| ビルドのタイムラインステップとそのキャプチャされたログ | 90日間 |
| ビルドマシンのメトリクス | 90日間 |
| Xcodeプロジェクトグラフの記録 | 30日間 |

これらの記録は、[アーティファクトファイルの保持期間](#hosted-artifact-files)で対象となるダウンロード可能なビルドアーカイブ、結果バンドル、テスト添付ファイルとは別ものです。Enterpriseでは、これらのファイルは30日間保持されます。関連するビルドおよびテストの記録は、ファイルの有効期限が切れた後も利用可能です。固定された時間ベースの削除スケジュールがない記録であっても、永久に利用可能であることを保証するものではありません。

### その他のダッシュボードおよびアクティビティデータ {#other-dashboard-and-activity-data}

| データ | 保持期間 |
| --- | --- |
| Gradleビルド記録、タスク記録、キャッシュイベント記録、Mixビルド記録、コンパイル済みファイル記録、ビルドステップ記録と診断情報、Cargoビルド記録（集計コンパイルキャッシュ測定値を含む）とコンパイラ観察情報、Bazel呼び出し、Bazelトレースプロファイル、インデックス付きプロファイルステップとアクション診断情報、保留中のBazelプロファイルおよびテスト取り込み記録、Bazel呼び出しログ、Bazelリモートアクションキャッシュ観察情報 | 90日間 |
| 永続的なモジュール詳細ページにおけるXcodeモジュールのコンパイルおよびキャッシュ履歴 | 30日間 |
| 永続的な詳細ページにおけるタスク、宣言されたOnceアクション、Bazel BEPアクション、コンパイル済みファイルおよびモジュールの観察情報 | 上記のXcodeモジュールを除き90日間 |
| 永続的なタスク/アクション/モジュール/ファイルの識別メタデータ | 観察情報がない場合は365日間 |
| ランナージョブログ、アーカイブされたランナーログ、ランナージョブのマシンメトリクス | 90日間 |
| Webhook配信履歴 | 固定された削除スケジュールなし |

永続的な詳細URLは、特定のビルドが利用可能であることに依存しません。識別メタデータは個々の観察情報よりも長く存続するため、選択した期間中に詳細ページに履歴が存在しない場合があります。新しい履歴は、機能のデプロイ後に受信したレポートからインデックス化されます。既存の実行レベルの履歴は遡ってコピーされません。

ClickHouseの内部`system.*`運用ログテーブルは、Tuistの製品データ保持ポリシーではなく、ClickHouse層で構成されます。デフォルトでは上限がありません。バンドルされているセルフホスト型Docker Composeおよび組み込みHelm ClickHouse構成では、これらに上限を設定できます。詳細は<.localized_link href="/guides/server/self-host/server#capping-operational-log-retention">運用ログの保持期間の上限設定</.localized_link>をご覧ください。
