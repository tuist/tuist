# 問題の報告 {#issue-reporting}

Tuist の使用中に、バグや予期しない動作に遭遇することがあります。その場合は、修正できるよう報告してください。

## GitHub Issues をチケット管理プラットフォームとして利用しています {#github-issues-is-our-ticketing-platform}

問題は Slack や他のプラットフォームではなく、[GitHub Issues](https://github.com/tuist/tuist/issues) として GitHub で報告してください。GitHub は問題の追跡と管理に適しており、コードベースに近く、進捗状況を追跡できます。さらに、詳細な説明を促すことで、報告者が問題を考え直し、より多くのコンテキストを提供するよう促します。

## コンテキストが重要です {#context-is-crucial}

十分なコンテキストがない問題は不完全とみなされ、追加のコンテキストを求められます。提供されない場合、問題はクローズされます。次のように考えてください：提供するコンテキストが多いほど、私たちが問題を理解し修正しやすくなります。したがって、問題を修正してほしい場合は、できるだけ多くのコンテキストを提供してください。以下の質問に答えてみてください：

- 何をしようとしていましたか？
- グラフはどのような構造ですか？
- 使用している Tuist のバージョンは何ですか？
- これがブロック要因になっていますか？

最小限の**再現プロジェクト**の提供も必須です。

## 再現プロジェクト {#reproducible-project}

### 再現プロジェクトとは何ですか？ {#what-is-a-reproducible-project}

再現プロジェクトは、問題をデモンストレーションするための小さな Tuist プロジェクトです。この問題はしばしば Tuist のバグによって引き起こされます。再現プロジェクトには、バグを明確に示すために必要な最小限の機能のみを含めるべきです。

### なぜ再現テストケースを作成すべきですか？ {#why-should-you-create-a-reproducible-test-case}

再現プロジェクトにより、問題の原因を特定でき、それが修正への第一歩となります！バグ報告で最も重要なのは、バグを再現するために必要な正確な手順を記述することです。

再現プロジェクトは、バグを引き起こす特定の環境を共有するのに適しています。あなたの再現プロジェクトは、あなたを支援したい人々を助ける最良の方法です。

### 再現プロジェクトの作成手順 {#steps-to-create-a-reproducible-project}

- 新しい Git リポジトリを作成します。
- リポジトリディレクトリで `tuist init` を使用してプロジェクトを初期化します。
- 確認したエラーを再現するために必要なコードを追加します。
- コードを公開し（GitHub アカウントが適しています）、問題を作成する際にそのリンクを貼ります。

### 再現プロジェクトの利点 {#benefits-of-reproducible-projects}

- **影響範囲の縮小：** エラー以外のすべてを取り除くことで、バグを探す必要がなくなります。
- **機密コードを公開する必要がありません：** メインサイトを公開できない場合（多くの理由があります）があります。その一部を再現テストケースとして再作成することで、機密コードを公開せずに問題を公に示すことができます。
- **バグの証明：** sometimes バグはマシン上の設定の組み合わせによって引き起こされます。再現テストケースにより、貢献者がビルドを取得し、自分のマシンでテストできます。これにより、問題の原因を検証し絞り込むのに役立ちます。
- **バグ修正の支援を受けられます：** 他の人が問題を再現できれば、問題を修正できる可能性が高まります。まず再現できなければ、バグを修正することはほぼ不可能です。
