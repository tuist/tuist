# 互換性 {#compatibility}

Tuist CLI は、キャッシュ、ビルドおよびテストのインサイト、プレビュー、レジストリなどの機能のために Tuist サーバーと通信します。サーバーは CLI のアップグレード時期とは無関係に継続的に提供されるため、サーバー側の変更が現在実行中の CLI バージョンを壊してはいけません。これを保証するため、サーバーは定義された期間において最新の CLI リリースとの互換性を維持します。

## サポート期間 {#support-window}

Tuist サーバーは **過去 3 か月** 以内にリリースされた CLI をサポートします。この期間内ではサーバーは後方互換性を維持します。過去 3 か月以内にリリースされた任意の CLI は、サーバーに対してビルド、キャッシング、テストの実行を継続でき、サーバー側の変更による障害を気にすることなく、独自のスケジュールで CLI をアップグレードできます。

CLI は [セマンティック バージョニング](https://semver.org) に従います。過去 3 か月以内に公開されたすべてのリリースがサポート対象です。

## サポート期間外 {#outside-the-window}

サポート期間より古い CLI リリースは非推奨とみなされます。サーバーは引き続き応答しますが、以下の点に注意してください。

- 新しいサーバー側の機能がそのバージョンでは動作しない場合があります。
- サーバー依存のコマンドが、アップグレードを促す警告を表示することがあります。

非推奨バージョンでの動作は保証されません。該当するバージョンを使用している場合は、サポート期間内のリリースにアップグレードしてください。

## 互換性の維持方法 {#how-we-keep-the-promise}

後方互換性は想定ではなく検証により確保されます。すべてのサーバーデプロイメントでは、**サポート期間内にある最も古い CLI リリース**（現在は `{{minimum_supported_cli_version}}`）を対象に、キャッシュのプルパスをエンドツーエンドで exercising する自動受け入れテストを実行します。もし変更によってそのバージョンが壊れる場合、デプロイメントは本番環境に到達する前にブロックされます。これは最新の CLI に対するテストと並行して実行されるため、古いクライアントにおける回帰は、最新クライアントにおける回帰と同じ方法で検出されます。

## 推奨事項 {#recommendation}

サポート対象期間内に留まるため、CLI は少なくとも 3 か月に一度アップグレードしてください。CI で CLI バージョンを固定し、定期的なリズムで更新することで、チームが一貫したサポート対象リリースを利用し続けられます。
