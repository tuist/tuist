# დიბაგინგი {#debugging}

ღიაობა პრაქტიკული უპირატესობაა: კოდი ხელმისაწვდომია, შეგიძლიათ მისი ადგილობრივად გაშვება და კოდინგ-აგენტების გამოყენება კითხვებზე სწრაფი პასუხის მისაღებად და კოდბაზაში შესაძლო ბაგების დიბაგინგისთვის.

თუ დიბაგინგის დროს აღმოაჩენთ ნაკლულ ან არასრულ დოკუმენტაციას, განაახლეთ ინგლისური დოკები `docs/` საქაღალდეში და გახსენით PR.

## თრედების დამპების გადაღება CI-ზე {#thread-dump-ci}

როდესაც CLI დროდადრო იჭედება, შეგიძლიათ თრედის დამპის გადაღება პროცესის შეჩერების გარეშე. ჩართეთ სიგნალის ობრაბოტკა და გაუგზავნეთ `SIGUSR1` მიმდინარე `tuist` პროცესს.

```bash
export TUIST_THREAD_DUMP_SIGNAL=1
export TUIST_THREAD_DUMP_SAMPLE=1 # macOS only, captures all threads via /usr/bin/sample
tuist generate &
TUIST_PID=$!
sleep 600
kill -USR1 "$TUIST_PID"
wait "$TUIST_PID"
```

თუ `TUIST_THREAD_DUMP_SAMPLE` არ არის დაყენებული, ობრაბოტკა ბეჭდავს მიმდინარე თრედის სტეკს. გამოტანა იწერება stderr-ში, ამიტომ ის ჩანს CI ლოგებში.

## კოდინგ-აგენტების გამოყენება {#use-coding-agents}

კოდინგ-აგენტები სასარგებლოა:

- კოდბაზის სკანირება იმის დასადგენად, სად არის რეალიზებული ქცევა.
- პრობლემების ადგილობრივად რეპროდუცირება და სწრაფი იტერაცია.
- Tuist-ში შემავალი მონაცემების ნაკადის ტრასირება ფესვის მიზეზის საპოვნელად.

გაუზიარეთ რაც შეიძლება მცირე რეპროდუქცია და მიუთითეთ აგენტი კონკრეტულ კომპონენტზე (CLI, სერვერი, ქეში, დოკები ან სახელმძღვანელო). რაც უფრო ფოკუსირებულია მოცულობა, მით უფრო სწრაფი და ზუსტია დიბაგინგის პროცესი.

### ხშირად საჭირო პრომპტები (FNP) {#frequently-needed-prompts}

#### მოულოდნელი პროექტის გენერაცია {#unexpected-project-generation}

პროექტის გენერაცია მაძლევს რაღაცას, რასაც არ ველოდი. გაუშვით Tuist CLI ჩემი პროექტის წინააღმდეგ `/path/to/project` მისამართზე, რათა გაიგოთ, რატომ ხდება ეს. გააკეთეთ გენერატორის პაიპლაინის ტრასირება და მიუთითეთ კოდის ის გზები, რომლებიც პასუხისმგებელნი არიან გამოტანაზე.

#### რეპროდუცირებადი ბაგი გენერირებულ პროექტებში {#reproducible-bug-in-generated-projects}

ეს ჰგავს ბაგს გენერირებულ პროექტებში. შექმენით რეპროდუცირებადი პროექტი `examples/` საქაღალდეში, არსებული მაგალითების გამოყენებით როგორც მინიშნება. დაამატეთ მიღების ტესტი, რომელიც ჩავარდება, გაუშვით ის `xcodebuild`-ით მხოლოდ ამ ტესტის შერჩევით, გაასწორეთ პრობლემა, ხელახლა გაუშვით ტესტი იმის დასადასტურებლად, რომ ის გადის და გახსენით PR.
