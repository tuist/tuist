# დაგდება {#debugging}

ღიაობა პრაქტიკული უპირატესობაა: კოდი ხელმისაწვდომია, შეგიძლიათ მისი ადგილობრივად გაშვება და კოდირების აგენტების გამოყენება კითხვებზე სწრაფი პასუხების მისაღებად და კოდბაზაში შესაძლო ბაგების დასადგენად.

თუ დაგდების დროს აღმოაჩენთ დაკარგულ ან არასრულ დოკუმენტაციას, განაახლეთ ინგლისური დოკები `docs/` საქაღალდეში და გახსენით PR.

## ნაკადების დამპების ჩაჭერა CI-ზე {#thread-dump-ci}

როდესაც CLI დროდადრო იჭედება, შეგიძლიათ ნაკადის დამპის ჩაჭერა პროცესის შეწყვეტის გარეშე. ჩართეთ სიგნალის დამმუშავებელი და გაუგზავნეთ `SIGUSR1` მიმდინარე `tuist` პროცესს.

```bash
export TUIST_THREAD_DUMP_SIGNAL=1
export TUIST_THREAD_DUMP_SAMPLE=1 # macOS only, captures all threads via /usr/bin/sample
tuist generate &
TUIST_PID=$!
sleep 600
kill -USR1 "$TUIST_PID"
wait "$TUIST_PID"
```

თუ `TUIST_THREAD_DUMP_SAMPLE` არ არის დაყენებული, დამმუშავებელი ბეჭდავს მიმდინარე ნაკადის სტეკს. გამონატანი იწერება stderr-ში, ამიტომ ის ჩანს CI ლოგებში.

## კოდირების აგენტების გამოყენება {#use-coding-agents}

კოდირების აგენტები სასარგებლოა შემდეგისთვის:

- კოდბაზის სკანირება იმის დასადგენად, თუ სად არის რეალიზებული ქცევა.
- პრობლემების ადგილობრივად აღწარმოება და სწრაფი იტერაცია.
- Tuist-ში შეყვანის ნაკადის ტრასირება ფუნდამენტური მიზეზის დასადგენად.

გაუზიარეთ მაქსიმალურად მცირე აღწარმოება და მიუთითეთ აგენტი კონკრეტულ კომპონენტზე (CLI, სერვერი, ქეში, დოკები ან სახელმძღვანელო). რაც უფრო ფოკუსირებულია სკოპი, მით უფრო სწრაფი და ზუსტია დაგდების პროცესი.

### ხშირად საჭირო მოთხოვნები (FNP) {#frequently-needed-prompts}

#### მოულოდნელი პროექტის გენერაცია {#unexpected-project-generation}

პროექტის გენერაცია მაძლევს იმას, რასაც არ ველოდი. გაუშვით Tuist CLI ჩემი პროექტის წინააღმდეგ `/path/to/project` მისამართზე, რათა გაიგოთ, რატომ ხდება ეს. გააკეთეთ გენერატორის პაიპლაინის ტრასირება და მიუთითეთ კოდის გზები, რომლებიც პასუხისმგებელნი არიან გამონატანზე.

#### აღწარმოებადი ბაგი გენერირებულ პროექტებში {#reproducible-bug-in-generated-projects}

ეს ჰგავს ბაგს გენერირებულ პროექტებში. შექმენით აღწარმოებადი პროექტი `examples/` საქაღალდეში, არსებული მაგალითების გამოყენებით როგორც მითითება. დაამატეთ მიღების ტესტი, რომელიც ვერდება, გაუშვით ის `xcodebuild`-ის მეშვეობით მხოლოდ ამ ტესტის შერჩევით, გაასწორეთ პრობლემა, ხელახლა გაუშვით ტესტი მისი წარმატების დასადასტურებლად და გახსენით PR.
