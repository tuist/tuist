# დებაგინგი {#debugging}

ღიაობა პრაქტიკული უპირატესობაა: კოდი ხელმისაწვდომია, შეგიძლიათ მისი ადგილობრივად გაშვება და კოდინგ-აგენტების გამოყენება კითხვებზე სწრაფი პასუხების მისაღებად და კოდბაზაში პოტენციური ბაგების აღმოსაჩენად.

თუ დებაგინგისას აღმოაჩენთ, რომ დოკუმენტაცია ნაკლული ან არასრულია, განაახლეთ ინგლისურენოვანი დოკუმენტაცია საქაღალდეში `server/priv/docs/en` და გახსენით PR.

## ნაკადის დამპების გადაღება CI-ზე {#thread-dump-ci}

როცა CLI დროდადრო იჭედება, შეგიძლიათ პროცესის შეწყვეტის გარეშე გადაიღოთ ნაკადის დამპი. ჩართეთ სიგნალის ობრაბოტიკა და გაუგზავნეთ `SIGUSR1` მიმდინარე `tuist` პროცესს.

```bash
export TUIST_THREAD_DUMP_SIGNAL=1
export TUIST_THREAD_DUMP_SAMPLE=1 # macOS only, captures all threads via /usr/bin/sample
tuist generate &
TUIST_PID=$!
sleep 600
kill -USR1 "$TUIST_PID"
wait "$TUIST_PID"
```

თუ `TUIST_THREAD_DUMP_SAMPLE` არ არის დაყენებული, ობრაბოტიკა ბეჭდავს მიმდინარე ნაკადის სტეკს. გამოტანა იწერება stderr-ში, ამიტომ ის ჩანს CI ლოგებში.

## კოდინგ-აგენტების გამოყენება {#use-coding-agents}

კოდინგ-აგენტები სასარგებლოა შემდეგი მიზნებისთვის:

- კოდბაზის სკანირება იმის დასადგენად, თუ სად არის რეალიზებული კონკრეტული ქცევა.
- პრობლემების ადგილობრივად გამეორება და სწრაფი იტერაციები.
- Tuist-ში შეყვანების ნაკადის კვალდაკვალება ფუნდამენტური მიზეზის დასადგენად.

გაუზიარეთ მაქსიმალურად მცირე რეპროდუქცია და მიუთითეთ აგენტზე კონკრეტული კომპონენტი (CLI, სერვერი, ქეში, დოკუმენტაცია ან სახელმძღვანელო). რაც უფრო ვიწროა მოცულობა, მით უფრო სწრაფი და ზუსტია დებაგინგის პროცესი.

### ხშირად საჭირო მოთხოვნები (FNP) {#frequently-needed-prompts}

#### მოულოდნელი პროექტის გენერაცია {#unexpected-project-generation}

პროექტის გენერაცია მაძლევს შედეგს, რომელსაც არ ველოდი. გაუშვით Tuist CLI ჩემი პროექტის წინააღმდეგ მისამართზე `/path/to/project`, რათა გაიგოთ, რატომ ხდება ეს. დააკვირდით გენერატორის პაიპლაინს და მიუთითეთ კოდის ის ნაწილები, რომლებიც პასუხისმგებელნი არიან შედეგზე.

#### გამეორებადი ბაგი გენერირებულ პროექტებში {#reproducible-bug-in-generated-projects}

ეს ჰგავს ბაგს გენერირებულ პროექტებში. შექმენით გამეორებადი პროექტი საქაღალდეში `examples/`, არსებული მაგალითების გამოყენებით როგორც საცნობარო. დაამატეთ მიღების ტესტი, რომელიც ჩავარდება, გაუშვით ის `xcodebuild`-ით მხოლოდ ამ ტესტის შერჩევით, გაასწორეთ პრობლემა, ხელახლა გაუშვით ტესტი დადასტურებისთვის, რომ ის გადის, და გახსენით PR.
