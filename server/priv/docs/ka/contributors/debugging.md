# დიბაგინგი {#debugging}

გახსნილობა პრაქტიკული უპირატესობაა: კოდი ხელმისაწვდომია, შეგიძლიათ მისი ადგილობრივად გაშვება და კოდინგ-აგენტების გამოყენება კითხვებზე სწრაფი პასუხის მისაღებად და კოდბაზაში შესაძლო ბაგების დიბაგინგისთვის.

თუ დიბაგინგისას აღმოაჩენთ ნაკლულ ან არასრულ დოკუმენტაციას, განაახლეთ ინგლისური დოკები `server/priv/docs/en` საქაღალდეში და გახსენით PR.

## თრედების დამპების გადაღება CI-ზე {#thread-dump-ci}

როდესაც CLI პერიოდულად იყინება, შეგიძლიათ თრედის დამპის გადაღება პროცესის შეწყვეტის გარეშე. ჩართეთ სიგნალის ჰენდლერი და გაუგზავნეთ `SIGUSR1` მიმდინარე `tuist` პროცესს.

```bash
export TUIST_THREAD_DUMP_SIGNAL=1
export TUIST_THREAD_DUMP_SAMPLE=1 # macOS only, captures all threads via /usr/bin/sample
tuist generate &
TUIST_PID=$!
sleep 600
kill -USR1 "$TUIST_PID"
wait "$TUIST_PID"
```

თუ `TUIST_THREAD_DUMP_SAMPLE` არ არის დაყენებული, ჰენდლერი ბეჭდავს მიმდინარე თრედის სტეკს. გამოტანა იწერება stderr-ზე, ამიტომ ის ჩანს CI ლოგებში.

## კოდინგ-აგენტების გამოყენება {#use-coding-agents}

კოდინგ-აგენტები სასარგებლოა შემდეგი მიზნებისთვის:

- კოდბაზის სკანირება იმის დასადგენად, სად არის რეალიზებული ქცევა.
- პრობლემების ადგილობრივად რეპროდუცირება და სწრაფი იტერაცია.
- შეყვანის ნაკადის ტრასირება Tuist-ში ფესვის მიზეზის საპოვნელად.

გაუზიარეთ რაც შეიძლება მცირე რეპროდუქცია და მიმართეთ აგენტი კონკრეტულ კომპონენტზე (CLI, სერვერი, ქეში, დოკები ან სახელმძღვანელო). რაც უფრო ფოკუსირებულია მოცულობა, მით უფრო სწრაფი და ზუსტია დიბაგინგის პროცესი.

### ხშირად საჭირო პრომპტები (FNP) {#frequently-needed-prompts}

#### მოულოდნელი პროექტის გენერაცია {#unexpected-project-generation}

პროექტის გენერაცია მაძლევს რაღაცას, რასაც არ ველოდი. გაუშვით Tuist CLI ჩემი პროექტის წინააღმდეგ `/path/to/project` მისამართზე, რათა გაიგოთ, რატომ ხდება ეს. დატრასეთ გენერატორის პაიპლაინი და მიუთითეთ კოდის ის გზები, რომლებიც პასუხისმგებელია გამოსავალზე.

#### განმეორებადი ბაგი გენერირებულ პროექტებში {#reproducible-bug-in-generated-projects}

ეს ჰგავს ბაგს გენერირებულ პროექტებში. შექმენით განმეორებადი პროექტი `examples/` საქაღალდეში, არსებული მაგალითების გამოყენებით როგორც მითითება. დაამატეთ მარცხიანი მიღების ტესტი, გაუშვით ის `xcodebuild`-ის საშუალებით მხოლოდ ამ ტესტის შერჩევით, გაასწორეთ პრობლემა, ხელახლა გაუშვით ტესტი მისი წარმატების დასადასტურებლად და გახსენით PR.
