# დებაგინგი {#debugging}

ღიაობა პრაქტიკული უპირატესობაა: კოდი ხელმისაწვდომია, შეგიძლიათ გაუშვათ ის ლოკალურად და გამოიყენოთ კოდირების აგენტები კითხვებზე სწრაფი პასუხების მისაღებად და კოდბაზაში პოტენციური ბაგების დებაგინგისთვის.

თუ დებაგინგის დროს აღმოაჩენთ ნაკლულ ან არასრულ დოკუმენტაციას, განაახლეთ ინგლისური დოკუმენტაცია `server/priv/docs/en` საქაღალდეში და გახსენით PR.

## თრედების დამპების გადაღება CI-ზე {#thread-dump-ci}

როდესაც CLI პერიოდულად იჭედება, შეგიძლიათ გადაიღოთ თრედის დამპი პროცესის შეჩერების გარეშე. ჩართეთ სიგნალის ობრაბოტიკა და გაუგზავნეთ `SIGUSR1` მიმდინარე `tuist` პროცესს.

```bash
export TUIST_THREAD_DUMP_SIGNAL=1
export TUIST_THREAD_DUMP_SAMPLE=1 # macOS only, captures all threads via /usr/bin/sample
tuist generate &
TUIST_PID=$!
sleep 600
kill -USR1 "$TUIST_PID"
wait "$TUIST_PID"
```

თუ `TUIST_THREAD_DUMP_SAMPLE` არ არის დაყენებული, ობრაბოტიკა ბეჭდავს მიმდინარე თრედის სტეკს. გამონატანი იწერება stderr-ში, ამიტომ ის ჩანს CI-ის ლოგებში.

## კოდირების აგენტების გამოყენება {#use-coding-agents}

კოდირების აგენტები სასარგებლოა შემდეგი მიზნებისთვის:

- კოდბაზის სკანირება იმის დასადგენად, თუ სად არის რეალიზებული ქცევა.
- პრობლემების ლოკალურად რეპროდუცირება და სწრაფი იტერაცია.
- Tuist-ში შეყვანების ნაკადის ტრასირება ფესვამდე მისასვლელად.

გაუზიარეთ მაქსიმალურად მცირე რეპროდუქცია და მიმართეთ აგენტი კონკრეტულ კომპონენტზე (CLI, სერვერი, ქეში, დოკუმენტაცია ან სახელმძღვანელო). რაც უფრო ფოკუსირებულია სკოუპი, მით უფრო სწრაფი და ზუსტია დებაგინგის პროცესი.

### ხშირად საჭირო მოთხოვნები (FNP) {#frequently-needed-prompts}

#### მოულოდნელი პროექტის გენერაცია {#unexpected-project-generation}

პროექტის გენერაცია მაძლევს იმას, რასაც არ ველოდი. გაუშვით Tuist CLI ჩემი პროექტის წინააღმდეგ `/path/to/project` მისამართზე, რათა გაიგოთ, რატომ ხდება ეს. დატრასეთ გენერატორის პაიპლაინი და მიუთითეთ კოდის იმ გზებზე, რომლებიც პასუხისმგებელია გამონატანზე.

#### რეპროდუცირებადი ბაგი გენერირებულ პროექტებში {#reproducible-bug-in-generated-projects}

ეს ჰგავს ბაგს გენერირებულ პროექტებში. შექმენით რეპროდუცირებადი პროექტი `examples/` საქაღალდეში, არსებული მაგალითების გამოყენებით როგორც მინიშნება. დაამატეთ ვალიდაციის ტესტი, რომელიც ვერდება, გაუშვით ის `xcodebuild`-ის მეშვეობით მხოლოდ ამ ტესტის შერჩევით, გაასწორეთ პრობლემა, ხელახლა გაუშვით ტესტი დადასტურებისთვის, რომ ის გადის და გახსენით PR.
