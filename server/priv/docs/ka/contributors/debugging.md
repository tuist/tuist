# დებაგინგი {#debugging}

ღიაობა პრაქტიკული უპირატესობაა: კოდი ხელმისაწვდომია, შეგიძლიათ მისი ადგილობრივად გაშვება და კოდინგ-აგენტების გამოყენება კითხვებზე სწრაფი პასუხების მისაღებად და კოდბაზაში პოტენციური ბაგების დებაგინგისთვის.

თუ დებაგინგის დროს აღმოაჩენთ ნაკლულ ან არასრულ დოკუმენტაციას, განაახლეთ ინგლისურენოვანი დოკუმენტაცია საქაღალდეში `docs/` და გახსენით PR.

## თრედების დამპების გადაღება CI-ზე {#thread-dump-ci}

როდესაც CLI პერიოდულად იჭედება, შეგიძლიათ გადაიღოთ თრედის დამპი პროცესის შეჩერების გარეშე. ჩართეთ სიგნალის ობრაბოტიკა და გაუგზავნეთ `SIGUSR1` მიმდინარე `tuist` პროცესს.

```bash
export TUIST_THREAD_DUMP_SIGNAL=1
export TUIST_THREAD_DUMP_SAMPLE=1 # macOS only, captures all threads via /usr/bin/sample
tuist generate &
TUIST_PID=$!
sleep 600
kill -USR1 "$TUIST_PID"
wait "$TUIST_PID"
```

თუ `TUIST_THREAD_DUMP_SAMPLE` არ არის დაყენებული, ობრაბოტიკა ბეჭდავს მიმდინარე თრედის სტეკს. გამოსავალი იწერება stderr-ში, ამიტომ ის ჩანს CI-ის ლოგებში.

## კოდინგ-აგენტების გამოყენება {#use-coding-agents}

კოდინგ-აგენტები სასარგებლოა შემდეგი მიზნებისთვის:

- კოდბაზის სკანირება იმის დასადგენად, სად არის რეალიზებული კონკრეტული ქცევა.
- პრობლემების ადგილობრივად რეპროდუცირება და სწრაფი იტერაცია.
- Tuist-ში შეყვანის ნაკადების ტრასირება ფუნდამენტური მიზეზის საპოვნელად.

გაუზიარეთ მაქსიმალურად მცირე რეპროდუქცია და მიმართეთ აგენტი კონკრეტული კომპონენტისკენ (CLI, სერვერი, ქეში, დოკუმენტაცია ან სახელმძღვანელო). რაც უფრო ფოკუსირებულია სკოუპი, მით უფრო სწრაფი და ზუსტია დებაგინგის პროცესი.

### ხშირად საჭირო მოთხოვნები (FNP) {#frequently-needed-prompts}

#### მოულოდნელი პროექტის გენერაცია {#unexpected-project-generation}

პროექტის გენერაცია მაძლევს შედეგს, რომელსაც არ ველოდი. გაუშვით Tuist CLI ჩემი პროექტის წინააღმდეგ მისამართზე `/path/to/project`, რათა გაიგოთ, რატომ ხდება ეს. გააკეთეთ გენერატორის პაიპლაინის ტრასირება და მიუთითეთ ის კოდის გზები, რომლებიც პასუხისმგებელია გამოსავალზე.

#### გენერირებულ პროექტებში გამეორებადი ბაგი {#reproducible-bug-in-generated-projects}

ეს ჰგავს ბაგს გენერირებულ პროექტებში. შექმენით გამეორებადი პროექტი საქაღალდეში `examples/`, არსებული მაგალითების გამოყენებით როგორც მითითება. დაამატეთ ჩავარდნილი მიღების ტესტი, გაუშვით ის `xcodebuild`-ის მეშვეობით მხოლოდ ამ ტესტის შერჩევით, გაასწორეთ პრობლემა, ხელახლა გაუშვით ტესტი მისი წარმატებით შესრულების დასადასტურებლად და გახსენით PR.
