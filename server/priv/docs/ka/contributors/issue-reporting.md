# პრობლემების შეტყობინება {#issue-reporting}

Tuist-ის მომხმარებლის სახით, შეიძლება წააწყდეთ ბაგებს ან არასწორ ქცევებს. თუ ასე მოხდება, გირჩევთ, შეატყობინოთ ისინი, რათა ჩვენ შევძლოთ მათი გამოსწორება.

## GitHub issues არის ჩვენი საფირმო პლატფორმა {#github-issues-is-our-ticketing-platform}

პრობლემები უნდა შეიტყობინოთ GitHub-ზე როგორც [GitHub issues](https://github.com/tuist/tuist/issues) და არა Slack-ში ან სხვა პლატფორმებზე. GitHub უკეთესია პრობლემების კვალის მიყოლებისა და მართვისთვის, უფრო ახლოსაა კოდთან და საშუალებას გვაძლევს დავაკვირდეთ პრობლემის განვითარებას. ამასთან, ის ხელს უწყობს პრობლემის დეტალურ აღწერას, რაც აიძულებს შემტყობინებელს იფიქროს პრობლემაზე და უზრუნველყოს მეტი კონტექსტი.

## კონტექსტი გადამწყვეტია {#context-is-crucial}

პრობლემა, რომელსაც არ აქვს საკმარისი კონტექსტი, ჩაითვლება არასრულად და ავტორს სთხოვენ დამატებით კონტექსტს. თუ ის არ მოწოდებულია, პრობლემა დაიხურება. ფიქრეთ ასე: რაც უფრო მეტ კონტექსტს მოგვაწვდით, მით უფრო ადვილია ჩვენთვის პრობლემის გაგება და მისი გამოსწორება. ამიტომ, თუ გსურთ, რომ თქვენი პრობლემა გამოსწორდეს, მოაწოდეთ რაც შეიძლება მეტი კონტექსტი. ეცადეთ უპასუხოთ შემდეგ კითხვებს:

- რა ცდილობდით გაგეკეთებინათ?
- როგორ გამოიყურება თქვენი გრაფი?
- Tuist-ის რომელ ვერსიას იყენებთ?
- აბლოკავს თუ არა ეს თქვენს მუშაობას?

ასევე მოგეთხოვებათ მინიმალური **განმეორებადი პროექტის** მოწოდება.

## განმეორებადი პროექტი {#reproducible-project}

### რა არის განმეორებადი პროექტი? {#what-is-a-reproducible-project}

განმეორებადი პროექტი არის მცირე Tuist პროექტი პრობლემის სადემონსტრაციოდ - ხშირად ეს პრობლემა გამოწვეულია Tuist-ში არსებული ბაგით. თქვენმა განმეორებადმა პროექტმა უნდა შეიცავდეს მინიმალურად საჭირო ფუნქციებს, რათა ნათლად აჩვენოს ბაგი.

### რატომ უნდა შექმნათ განმეორებადი სატესტო შემთხვევა? {#why-should-you-create-a-reproducible-test-case}

განმეორებადი პროექტი საშუალებას გვაძლევს გამოვყოთ პრობლემის მიზეზი, რაც პირველი ნაბიჯია მისი გამოსწორებისკენ! ნებისმიერი ბაგის შესახებ შეტყობინების ყველაზე მნიშვნელოვანი ნაწილია ზუსტი ნაბიჯების აღწერა, რომლებიც საჭიროა ბაგის განმეორებისთვის.

განმეორებადი პროექტი შესანიშნავი გზაა კონკრეტული გარემოს გაზიარებისთვის, რომელიც იწვევს ბაგს. თქვენი განმეორებადი პროექტი საუკეთესო გზაა იმ ადამიანების დასახმარებლად, რომლებიც გსურთ დაგეხმარონ.

### ნაბიჯები განმეორებადი პროექტის შესაქმნელად {#steps-to-create-a-reproducible-project}

- შექმენით ახალი git რეპოზიტორია.
- ინიციალიზაცია გაუკეთეთ პროექტს `tuist init`-ის გამოყენებით რეპოზიტორიის დირექტორიაში.
- დაამატეთ კოდი, რომელიც საჭიროა თქვენს მიერ ნანახი შეცდომის ხელახლა შესაქმნელად.
- გამოაქვეყნეთ კოდი (თქვენი GitHub ანგარიში კარგი ადგილია ამისთვის) და შემდეგ მიუთითეთ ბმული მასზე პრობლემის შექმნისას.

### განმეორებადი პროექტების სარგებელი {#benefits-of-reproducible-projects}

- **უფრო მცირე ზედაპირი:** ყველაფრის ამოღებით, გარდა შეცდომისა, არ გჭირდებათ ბაგის საპოვნელად ჩაღრმავება.
- **არ არის საჭირო საიდუმლო კოდის გამოქვეყნება:** შეიძლება ვერ შეძლოთ თქვენი ძირითადი საიტის გამოქვეყნება (მრავალი მიზეზის გამო). მისი მცირე ნაწილის ხელახლა შექმნა, როგორც განმეორებადი სატესტო შემთხვევა, საშუალებას გაძლევთ საჯაროდ აჩვენოთ პრობლემა საიდუმლო კოდის გამოვლენის გარეშე.
- **ბაგის დადასტურება:** ზოგჯერ ბაგი გამოწვეულია თქვენს მანქანაზე არსებული პარამეტრების გარკვეული კომბინაციით. განმეორებადი სატესტო შემთხვევა საშუალებას აძლევს მომწვდებს ჩამოტვირთონ თქვენი ბილდი და შეამოწმონ ისინი თავიანთ მანქანებზეც. ეს ეხმარება პრობლემის მიზეზის დადასტურებასა და შევიწროვებას.
- **მიიღეთ დახმარება თქვენი ბაგის გამოსწორებაში:** თუ სხვას შეუძლია თქვენი პრობლემის განმეორება, მათ ხშირად აქვთ კარგი შანსი პრობლემის გამოსწორებისა. თითქმის შეუძლებელია ბაგის გამოსწორება მისი წინასწარ განმეორების შესაძლებლობის გარეშე.
