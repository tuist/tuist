# შეცდომების შესახებ ინფორმაციის მიწოდება {#issue-reporting}

Tuist-ის მომხმარებლის სახით, შეიძლება წააწყდეთ შეცდომებს ან არასალოდინელ ქცევებს. თუ ასე მოხდება, გირჩევთ, შეატყობინოთ ეს ჩვენ, რათა შევძლოთ მათი გამოსწორება.

## GitHub issues არის ჩვენი ბილეთების პლატფორმა {#github-issues-is-our-ticketing-platform}

შეცდომები უნდა იყოს ნაჩვენები GitHub-ზე როგორც [GitHub issues](https://github.com/tuist/tuist/issues) და არა Slack-ში ან სხვა პლატფორმებზე. GitHub უკეთესია შეცდომების თვალყურის დევნისა და მართვისთვის, უფრო ახლოსაა კოდის ბაზასთან და საშუალებას გვაძლევს თვალყური ვადევნოთ პრობლემის გადაჭრის პროგრესს. ამასთან, ის ხელს უწყობს პრობლემის დეტალურ აღწერას, რაც აიძულებს მომხსენებელს დაფიქრდეს პრობლემაზე და მეტი კონტექსტი მიაწოდოს.

## კონტექსტი გადამწყვეტია {#context-is-crucial}

შეცდომა, რომელსაც არ აქვს საკმარისი კონტექსტი, ჩაითვლება არასრულყოფილად და ავტორს მოეთხოვება დამატებითი კონტექსტი. თუ ის არ იქნება მიწოდებული, შეცდომა დაიხურება. ფიქრეთ ასე: რაც უფრო მეტ კონტექსტს მოგვაწვდით, მით უფრო ადვილი იქნება ჩვენთვის პრობლემის გაგება და მისი გამოსწორება. ამიტომ, თუ გსურთ, რომ თქვენი შეცდომა გამოსწორდეს, მოგვაწოდეთ რაც შეიძლება მეტი კონტექსტი. ეცადეთ უპასუხოთ შემდეგ კითხვებს:

- რა ცდილობდით გააკეთოთ?
- როგორ გამოიყურება თქვენი გრაფი?
- Tuist-ის რომელ ვერსიას იყენებთ?
- გაბლოკავთ თუ არა ეს?

ასევე მოგეთხოვებათ მინიმალური **განმეორებადი პროექტის** მიწოდება.

## განმეორებადი პროექტი {#reproducible-project}

### რა არის განმეორებადი პროექტი? {#what-is-a-reproducible-project}

განმეორებადი პროექტი არის მცირე Tuist პროექტი, რომელიც აჩვენებს პრობლემას - ხშირად ეს პრობლემა გამოწვეულია Tuist-ში არსებული შეცდომით. თქვენმა განმეორებადმა პროექტმა უნდა შეიცავდეს მხოლოდ იმ მინიმალურ ფუნქციებს, რომლებიც აუცილებელია შეცდომის ცხადად საჩვენებლად.

### რატომ უნდა შექმნათ განმეორებადი სატესტო შემთხვევა? {#why-should-you-create-a-reproducible-test-case}

განმეორებადი პროექტი საშუალებას გვაძლევს გამოვყოთ პრობლემის მიზეზი, რაც პირველი ნაბიჯია მის გამოსწორებისკენ! ნებისმიერი შეცდომის შესახებ ინფორმაციის ყველაზე მნიშვნელოვანი ნაწილია ზუსტი ნაბიჯების აღწერა, რომლებიც საჭიროა შეცდომის განმეორებისთვის.

განმეორებადი პროექტი შესანიშნავი გზაა იმ კონკრეტული გარემოს გაზიარებისთვის, რომელიც იწვევს შეცდომას. თქვენი განმეორებადი პროექტი საუკეთესო გზაა იმ ადამიანების დასახმარებლად, რომლებიც გსურთ დაგეხმარონ.

### ნაბიჯები განმეორებადი პროექტის შესაქმნელად {#steps-to-create-a-reproducible-project}

- შექმენით ახალი git რეპოზიტორია.
- ინიციალიზაცია გაუკეთეთ პროექტს `tuist init`-ის გამოყენებით რეპოზიტორიის დირექტორიაში.
- დაამატეთ კოდი, რომელიც საჭიროა თქვენს მიერ ნანახი შეცდომის ხელახლა შესაქმნელად.
- გამოაქვეყნეთ კოდი (თქვენი GitHub ანგარიში კარგი ადგილია ამისთვის) და შემდეგ დაუკავშირეთ მას შეცდომის შექმნისას.

### განმეორებადი პროექტების სარგებელი {#benefits-of-reproducible-projects}

- **უფრო მცირე ზედაპირი:** ყველაფრის ამოღებით, გარდა შეცდომისა, არ გჭირდებათ ძიება შეცდომის საპოვნელად.
- **არ არის საჭირო საიდუმლო კოდის გამოქვეყნება:** შეიძლება ვერ შეძლოთ თქვენი მთავარი საიტის გამოქვეყნება (მრავალი მიზეზის გამო). მისი მცირე ნაწილის ხელახლა შექმნა, როგორც განმეორებადი სატესტო შემთხვევა, საშუალებას გაძლევთ საჯაროდ აჩვენოთ პრობლემა საიდუმლო კოდის გაუთქმელად.
- **შეცდომის დადასტურება:** ზოგჯერ შეცდომა გამოწვეულია თქვენს მანქანაზე არსებული პარამეტრების გარკვეული კომბინაციით. განმეორებადი სატესტო შემთხვევა საშუალებას აძლევს მომხმარებლებს ჩამოტვირთონ თქვენი ბილდი და შეამოწმონ ის თავიანთ მანქანებზეც. ეს ეხმარება პრობლემის მიზეზის დადასტურებასა და შევიწროებას.
- **მიიღეთ დახმარება თქვენი შეცდომის გამოსწორებაში:** თუ სხვას შეუძლია თქვენი პრობლემის განმეორება, მათ ხშირად აქვთ კარგი შანსი პრობლემის გამოსწორების. თითქმის შეუძლებელია შეცდომის გამოსწორება მისი წინასწარ განმეორების შესაძლებლობის გარეშე.
