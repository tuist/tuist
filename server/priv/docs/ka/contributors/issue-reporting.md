# პრობლემების შეტყობინება {#issue-reporting}

Tuist-ის მომხმარებლის სახით, შესაძლოა, წააწყდეთ შეცდომებს ან არასაიმედო ქცევებს. თუ ასე მოხდება, გირჩევთ, შეატყობინოთ ისინი, რათა ჩვენ შევძლოთ მათი გამოსწორება.

## GitHub Issues არის ჩვენი ბილეთების პლატფორმა {#github-issues-is-our-ticketing-platform}

პრობლემები უნდა იყოს შეტყობინებული GitHub-ზე [GitHub issues](https://github.com/tuist/tuist/issues)-ის სახით და არა Slack-ში ან სხვა პლატფორმებზე. GitHub უკეთესია პრობლემების კვალის დადგენისა და მართვისთვის, უფრო ახლოსაა კოდთან და საშუალებას გვაძლევს დავაკვირდეთ პრობლემის გადაჭრის პროგრესს. ამასთან, ის ხელს უწყობს პრობლემის დეტალურ აღწერას, რაც აიძულებს შემტყობინებელს, უფრო ღრმად გააზროს პრობლემა და მოგვაწოდოს მეტი კონტექსტი.

## კონტექსტი გადამწყვეტია {#context-is-crucial}

პრობლემა, რომელსაც არ აქვს საკმარისი კონტექსტი, ჩაითვლება არასრულყოფილად და ავტორს მოეთხოვება დამატებითი კონტექსტის მიწოდება. თუ ის არ იქნება მოწოდებული, პრობლემა დაიხურება. ფიქრებდით ასე: რაც უფრო მეტ კონტექსტს მოგვაწვდით, მით უფრო ადვილია ჩვენთვის პრობლემის გაგება და მისი გამოსწორება. ამიტომ, თუ გსურთ, თქვენი პრობლემა გამოასწორდეს, მოგვაწოდეთ მაქსიმალურად მეტი კონტექსტი. ეცადეთ, უპასუხოთ შემდეგ კითხვებს:

- რა ცდილობდით გაგეკეთებინათ?
- როგორ გამოიყურება თქვენი გრაფი?
- Tuist-ის რომელ ვერსიას იყენებთ?
- აფერხებთ თუ არა ეს თქვენს მუშაობას?

ასევე მოვითხოვთ, მოგვაწოდოთ მინიმალური **განმეორებადი პროექტი**.

## განმეორებადი პროექტი {#reproducible-project}

### რა არის განმეორებადი პროექტი? {#what-is-a-reproducible-project}

აღწარმოებადი პროექტი არის მცირე Tuist-ის პროექტი, რომელიც აჩვენებს პრობლემას – ხშირად ეს პრობლემა გამოწვეულია Tuist-ში არსებული ბაგით. თქვენმა აღწარმოებადმა პროექტმა უნდა შეიცავდეს მხოლოდ იმ ფუნქციების მინიმალურ ნაკრებს, რაც საჭიროა ბაგის ცხადად სადემონსტრაციოდ.

### რატომ უნდა შექმნათ აღწარმოებადი სატესტო შემთხვევა? {#why-should-you-create-a-reproducible-test-case}

განმეორებადი პროექტი საშუალებას გვაძლევს გამოვყოთ პრობლემის მიზეზი, რაც მისი გამოსწორების პირველი ნაბიჯია! ნებისმიერი შეცდომის შეტყობინების ყველაზე მნიშვნელოვანი ნაწილია იმ ზუსტი ნაბიჯების აღწერა, რომლებიც საჭიროა შეცდომის განმეორებისთვის.

განმეორებადი პროექტი შესანიშნავი გზაა იმ კონკრეტული გარემოს გაზიარებისთვის, რომელიც იწვევს შეცდომას. თქვენი განმეორებადი პროექტი საუკეთესო გზაა იმ ადამიანების დასახმარებლად, რომლებიც გსურთ, დაგეხმარონ.

### ნაბიჯები განმეორებადი პროექტის შესაქმნელად {#steps-to-create-a-reproducible-project}

- შექმენით ახალი git რეპოზიტორია.
- ინიციალიზაცია გაუკეთეთ პროექტს `tuist init`-ის გამოყენებით რეპოზიტორიის საქაღალდეში.
- დაამატეთ კოდი, რომელიც საჭიროა თქვენს მიერ ნანახი შეცდომის ხელახლა გამოსაწვევად.
- გამოაქვეყნეთ კოდი (თქვენი GitHub ანგარიში კარგი ადგილია ამისთვის) და შემდეგ მიუთითეთ მასზე ბმული პრობლემის შექმნისას.

### განმეორებადი პროექტების სარგებელი {#benefits-of-reproducible-projects}

- **პრობლემის უფრო მცირე არეალი:** ყველაფრის ამოღებით, გარდა შეცდომისა, თქვენ არ გჭირდებათ ძებნა შეცდომის საპოვნელად.
- **არ არის საჭირო საიდუმლო კოდის გამოქვეყნება:** შესაძლოა, ვერ შეძლოთ თქვენი ძირითადი პროექტის გამოქვეყნება (მრავალი მიზეზის გამო). მისი მცირე ნაწილის აღწარმოებადი სატესტო შემთხვევის სახით ხელახლა შექმნა საშუალებას გაძლევთ, საჯაროდ აჩვენოთ პრობლემა საიდუმლო კოდის გაუმჟღავნებლად.
- **ბაგის დადასტურება:** ზოგჯერ ბაგი გამოწვეულია თქვენს მანქანაზე არსებული პარამეტრების გარკვეული კომბინაციით. აღწარმოებადი სატესტო შემთხვევა საშუალებას აძლევს კონტრიბუტორებს, ჩამოტვირთონ თქვენი ბილდი და შეამოწმონ ის ასევე თავიანთ მანქანებზე. ეს ეხმარება პრობლემის მიზეზის დადასტურებასა და შევიწროვებას.
- **დახმარების მიღება თქვენი შეცდომის გამოსწორებაში:** თუ სხვას შეუძლია თქვენი პრობლემის განმეორება, მას ხშირად აქვს კარგი შანსი, გამოასწოროს ის. პრაქტიკულად შეუძლებელია შეცდომის გამოსწორება მისი წინასწარ განმეორების შესაძლებლობის გარეშე.
