# გამოშვების არხები {#release-channels}

Tuist CLI სამი განსხვავებული სტაბილურობის გარანტიით აღჭურვილი არხის მეშვეობით ვრცელდება. რეკომენდებული ინსტალაცია არის **stable**, რომელიც ნელა ვითარდება: ის არ ახლდება ყოველ ჯერზე, როცა რაიმე ფუნქცია ერწყმება ძირითად კოდს, ამიტომ განახლება აღარ ნიშნავს უკავშირო ცვლილებების პაკეტის მიღებას. ადრეულმა მომხმარებლებს შეუძლიათ **canary**-ზე თითოეული კომიტის ბილდების გაშვება, ხოლო **release candidate** არხი გუნდებს საშუალებას აძლევს წინასწარ შეამოწმოონ მომავალი ხაზი, სანამ ის სტაბილური გახდება.

## მიმდინარე გამოშვებები {#live-release-status}

სტაბილურ ვერსიაზე გადაყვანა დაგეგმილია ორშაბათობით, 06:00 UTC-ზე. წარმატებული დაგეგმილი გადაყვანის შემდეგ, შემდეგი release candidate იჭრება `main`-დან, ხოლო მომდევნო canary ვერსიები გადადიან შემდეგ მინორულ ვერსიაზე. მომავალი პერიოდებისა და ბოლო გამოშვებების, მათ შორის პატჩებისა და უკანპორტირებული შესწორებების სანახავად, იხილეთ <.localized_link href="/cli/release/calendar">გამოშვებების კალენდარი</.localized_link>.

## არხები {#the-channels}

| არხი | ვერსიის ფორმატი | სიხშირე | ნაგულისხმევად ირჩევა? |
| --- | --- | --- | --- |
| Canary | `X.Y.0-canary.N` (მაგ., `4.201.0-canary.42`) | ყოველი კომიტი `main`-ში | არა — მხოლოდ ცალსახა არჩევით |
| Release candidate | `X.Y.0-rc.N` (მაგ., `4.200.0-rc.1`) | იჭრება `main`-დან ყოველ ორშაბათს, ტესტირდება ~1 კვირა | არა — მხოლოდ ცალსახა არჩევით |
| Stable | `X.Y.Z` (მაგ., `4.200.0`, `4.200.1`) | გადაყვანილია ყოველ ორშაბათს წარმატებული ტესტირების შემდეგ | **კი** |

Canary და release candidate ბილდები ქვეყნდება როგორც წინასწარი გამოშვებები (prereleases). ისეთი ინსტრუმენტები, როგორიცაა Mise და Homebrew, გამორიცხავენ წინასწარ გამოშვებებს `latest`-ის, „უბრალო“ ინსტალაციის ან ხაზის მიმაგრების დროს, ამიტომ მათზე მხოლოდ მაშინ გადახვალთ, თუ ცალსახად მოითხოვთ.

### Canary {#canary}

`main`-ში ყოველი კომიტი აქვეყნებს canary ვერსიას. Canary ყოველთვის წარმოადგენს **შემდეგ გამოუშვებელ მინორულ ვერსიას**: როგორც კი ხაზი გამოშვებისთვის იჭრება, `main` გადადის შემდეგ მინორულ ვერსიაზე (მაგალითად, `4.200.0-canary.42`-დან `4.201.0-canary.1`-ზე). Canary სწორი არხია ადრეული მომხმარებლებისთვის, ვისაც სურს უადრესი შესაძლო სიგნალის მიღება, ან იმის დადასტურება, რომ თქვენს მიერ შეტყობინებულმა ან შეტანილმა შესწორებამ მოსალოდნელად იმუშაოს, სანამ ის stable-ში მოხვდება.

### Release candidate {#release-candidate}

როდესაც მინორული ვერსია მზადაა გამოშვებისთვის, მისი ხაზი იყინება დაცულ `releases/<major>.<minor>.x` ბრენჩზე და ქვეყნდება როგორც `X.Y.0-rc.1`. ხაზი ფუნქციების მხრივ გაყინულია; მხოლოდ კრიტიკული შესწორებები და რეგრესიები გადააქვთ, ხოლო ყოველი მიღებული შესწორება ზრდის RC-ს (`-rc.2`, `-rc.3`, …). ტესტირების პერიოდის წარმატებით დასრულების შემდეგ, ხაზი გადაყვანილი იქნება stable-ში.

### Stable {#stable}

Stable რეკომენდებული არხია და ყველა დოკუმენტაცია მასზე მიუთითებს. სტაბილური მინორული ვერსია (`X.Y.0`) ქვეყნდება მხოლოდ მაშინ, როცა release candidate წარმატებით გაივლის ტესტირებას, და ის **არ** ახლდება, როცა ახალი ფუნქციები ერწყმება `main`-ს. პატჩები (`X.Y.1`, `X.Y.2`, …) სტაბილურ ხაზზე შეიცავს მხოლოდ უკანპორტირებულ შესწორებებს, არასდროს ახალ ფუნქციებს.

## ვერსიის არჩევა {#choosing-a-version}

<.localized_link href="/guides/install-tuist">Mise</.localized_link>-ით (რეკომენდებული):

```bash
mise use tuist@latest              # Latest stable (recommended)
mise use tuist@4.200               # Pin to a stable line; receives backported fixes only
mise use tuist@4.200.1             # Pin to an exact stable patch
mise use tuist@4.201.0-rc.1        # Opt into a release candidate to soak it
mise use tuist@4.201.0-canary.42   # Opt into a specific canary build
```

Homebrew-ით, `brew install --formula tuist` ყოველთვის აინსტალირებს უახლეს სტაბილურ ვერსიას; წინასწარი გამოშვებები ფორმულის მეშვეობით არ ვრცელდება.

## რეკომენდებული სტრატეგია {#recommended-strategy}

1. **მიამაგრეთ სტაბილურ ხაზს**, მაგალითად `tuist@4.200`. ეს ხაზი იღებს მხოლოდ უკანპორტირებულ შესწორებებს, არასდროს ახალ ფუნქციებს, ამიტომ ყოველდღიური განახლებები დაბალი რისკის მქონეა.
2. **ახალი ფუნქციები გონივრულად აითვისეთ.** როცა მზად იქნებით შემდეგი მინორული ვერსიისთვის, შეამოწმეთ ის release candidate არხზე, შემდეგ კი გადაიტანეთ მიმაგრება ახალ სტაბილურ ხაზზე.
3. **სცადეთ canary** არაკრიტიკულ გარემოში, თუ ხართ ადრეული მომხმარებელი და გსურთ უადრესი შესაძლო სიგნალის მიღება.

## მხარდაჭერა და უკანპორტირება {#support-and-backports}

ნებისმიერ დროს აქტიურად მხარდაჭერილია ორი სტაბილური ხაზი:

| ხაზი | იღებს |
| --- | --- |
| მიმდინარე (`X.Y.x`) | რეგრესიები და უსაფრთხოების შესწორებები |
| წინა (`X.(Y-1).x`) | მხოლოდ კრიტიკული და უსაფრთხოების შესწორებები |
| ძველი | არა — გადადით მხარდაჭერილ ხაზზე |

შესწორებები ჯერ `main`-ზე (canary) ხვდება. რეგრესიები და უსაფრთხოების შესწორებები უკანპორტირდება მიმდინარე სტაბილურ ხაზზე, წინა ხაზი კი იღებს მხოლოდ კრიტიკულ და უსაფრთხოების შესწორებებს. სხვა ბაგების შესწორებები არ უკანპორტირდება; ისინი შემდეგ მინორულ ვერსიაში გამოიცემა. როცა ახალი ხაზი სტაბილურად ქვეყნდება, მიმდინარე ხაზი „წინა“ ხდება, ხოლო „წინა“ ხაზი წყვეტს უკანპორტირებული შესწორებების მიღებას.

არხისგან დამოუკიდებლად, Tuist სერვერი რჩება <.localized_link href="/cli/compatibility">თავსებადი</.localized_link> ნებისმიერ CLI-თან, რომელიც ბოლო 3 თვის განმავლობაში გამოიცა, ამიტომ სტაბილურ ხაზზე მიმაგრება არასდროს გაგიყვანთ მხარდაჭერილ ფანჯარას გარეთ, თუ ამ პერიოდის განმავლობაში განაახლებთ.
