# გამოშვების არხები {#release-channels}

Tuist CLI სამი არხის მეშვეობით ვრცელდება, თითოეული სტაბილურობის განსხვავებული გარანტიებით. რეკომენდებული ინსტალაცია არის **stable** და ის ნელა ვითარდება: ის არ ადიანს ყოველ ჯერზე, როცა ფუნქცია ერწყმება, ამიტომ განახლება აღარ ნიშნავს არასაკავშირო ცვლილებების პაკეტის მიღებას. ადრეულმა მომხმარებლებმა შეუძლიათ კვლავ გაუშვან კომიტ-მიხედვით ბილდები **canary**-ზე, ხოლო **release candidate** არხი საშუალებას აძლევს გუნდებს მომავალი ხაზი „დაასველონ“ სანამ ის stable გახდება.

## მიმდინარე გამოშვებები {#live-release-status}

Stable-ის პრომოცია დაგეგმილია ორშაბათობით 06:00 UTC-ზე. წარმატებული დაგეგმილი პრომოციის შემდეგ, შემდეგი release candidate იჭრება `main`-დან, ხოლო მომდევნო canaries გადადიან შემდეგ მინორზე. მომავალი ფანჯრებისა და ბოლო გამოშვებებისთვის, პატჩებისა და backport-ების ჩათვლით, იხილეთ <.localized_link href="/cli/release/calendar">გამოშვების კალენდარი</.localized_link>.

## არხები {#the-channels}

| არხი | ვერსიის ფორმატი | სიხშირე | ნაგულისხმევად იხსნება? |
| --- | --- | --- | --- |
| Canary | `X.Y.0-canary.N` (მაგ., `4.201.0-canary.42`) | ყოველი კომიტი `main`-ში | არა — ცალსახა opt-in |
| Release candidate | `X.Y.0-rc.N` (მაგ., `4.200.0-rc.1`) | იჭრება `main`-დან ყოველ ორშაბათს, „სველდება“ ~1 კვირა | არა — ცალსახა opt-in |
| Stable | `X.Y.Z` (მაგ., `4.200.0`, `4.200.1`) | პრომოცირდება ყოველ ორშაბათს სუფთა „სველების“ შემდეგ | **კი** |

Canary და release candidate ბილდები ქვეყნდება როგორც prereleases. ისეთი ინსტრუმენტები, როგორიცაა Mise და Homebrew, გამორიცხავენ prereleases-ს, როცა ხსნიან `latest`-ს, უბრალო ინსტალაციას ან ხაზის პინს, ამიტომ მათზე მოხვდებით მხოლოდ მაშინ, როცა ცალსახად მოითხოვთ.

### Canary {#canary}

ყოველი კომიტი `main`-ში აქვეყნებს canary-ს. Canary ყოველთვის წარმოადგენს **შემდეგ გამოუქვეყნებელ მინორს**: როცა ხაზი იჭრება გამოშვებისთვის, `main` გადადის შემდეგ მინორზე (მაგალითად, `4.200.0-canary.42`-დან `4.201.0-canary.1`-მდე). Canary არის შესაბამისი არხი ადრეული მომხმარებლებისთვის, ვისაც სურთ უადრესი შესაძლო სიგნალი, ან იმის დასადასტურებლად, რომ თქვენს მიერ შეტყობინებულმა ან შეტანილმა შესწორებამ მოსალოდნელად იმუშაოს, სანამ stable-ს მიაღწევს.

### Release candidate {#release-candidate}

როცა მინორი მზადაა გასაშვებად, მისი ხაზი იყინება დაცულ `releases/<major>.<minor>.x` შტოზე და ქვეყნდება როგორც `X.Y.0-rc.1`. ხაზი ფუნქციურად გაყინულია; მხოლოდ კრიტიკული შესწორებები და რეგრესიები გადააქვთ cherry-pick-ით, და ყოველი მიღებული შესწორება ზრდის RC-ს (`-rc.2`, `-rc.3`, …). სუფთა „სველების“ პერიოდის დასრულების შემდეგ, ხაზი პრომოცირდება stable-ზე.

### Stable {#stable}

Stable არის რეკომენდებული არხი და ის, რომელზეც ყველა დოკუმენტაცია მიგვითითებს. Stable მინორი (`X.Y.0`) ქვეყნდება მხოლოდ მაშინ, როცა release candidate სუფთად „დასველდა“, და ის **არ** ადიანს, როცა ახალი ფუნქციები ერწყმება `main`-ს. პატჩები (`X.Y.1`, `X.Y.2`, …) stable ხაზზე შეიცავს მხოლოდ backported შესწორებებს, არასდროს ახალ ფუნქციებს.

## ვერსიის არჩევა {#choosing-a-version}

<.localized_link href="/guides/install-tuist">Mise</.localized_link>-ით (რეკომენდებული):

```bash
mise use tuist@latest              # Latest stable (recommended)
mise use tuist@4.200               # Pin to a stable line; receives backported fixes only
mise use tuist@4.200.1             # Pin to an exact stable patch
mise use tuist@4.201.0-rc.1        # Opt into a release candidate to soak it
mise use tuist@4.201.0-canary.42   # Opt into a specific canary build
```

Homebrew-ით, `brew install --formula tuist` ყოველთვის ინსტალირებს უახლეს stable-ს; prereleases არ ვრცელდება ფორმულის მეშვეობით.

## რეკომენდებული სტრატეგია {#recommended-strategy}

1. **დააპინეთ stable ხაზზე**, მაგალითად `tuist@4.200`. ეს ხაზი იღებს მხოლოდ backported შესწორებებს, არასდროს ახალ ფუნქციებს, ამიტომ ყოველდღიური განახლებები დაბალი რისკის მქონე რჩება.
2. **ახალი ფუნქციები განზრახ მიიღეთ.** როცა მზად იქნებით შემდეგი მინორისთვის, „დაასველეთ“ ის release candidate არხზე, შემდეგ გადაიტანეთ თქვენი პინი ახალ stable ხაზზე.
3. **სცადეთ canary** არაკრიტიკულ გარემოში, თუ ხართ ადრეული მომხმარებელი, ვისაც სურთ უადრესი შესაძლო სიგნალი.

## მხარდაჭერა და backports {#support-and-backports}

ნებისმიერ დროს აქტიურად მხარდაჭერილია ორი stable ხაზი:

| ხაზი | იღებს |
| --- | --- |
| მიმდინარე (`X.Y.x`) | რეგრესიები და უსაფრთხოების შესწორებები |
| წინა (`X.(Y-1).x`) | მხოლოდ კრიტიკული და უსაფრთხოების შესწორებები |
| ძველი | არა — გადადით მხარდაჭერილ ხაზზე |

შესწორებები ჯერ `main`-ზე (canary) ხვდება. რეგრესიები და უსაფრთხოების შესწორებები backport-დება მიმდინარე stable ხაზზე, ხოლო წინა ხაზი იღებს მხოლოდ კრიტიკულ და უსაფრთხოების შესწორებებს. სხვა ბაგების შესწორებები არ backport-დება; ისინი შემდეგ მინორთან ერთად გამოიცემა. როცა ახალი ხაზი promoted ხდება stable-ზე, მიმდინარე ხაზი ხდება „წინა“, ხოლო „წინა“ ხაზი წყვეტს backports-ის მიღებას.

არხისგან დამოუკიდებლად, Tuist server რჩება <.localized_link href="/cli/compatibility">თავსებადი</.localized_link> ნებისმიერ CLI-თან, რომელიც ბოლო 3 თვის განმავლობაში გამოიცა, ამიტომ stable ხაზზე პინი არასდროს გაგიყვანთ მხარდაჭერილ ფანჯარას გარეთ, სანამ ამ პერიოდში განახლებას მოახდენთ.
