# გამოშვების არხები {#release-channels}

Tuist CLI სამი არხის საშუალებით ვრცელდება, რომლებსაც სტაბილურობის განსხვავებული გარანტიები აქვთ. რეკომენდებული ინსტალაციაა **stable** და ის ნელა ვითარდება: ყოველ ჯერზე, როცა ფუნქცია ერწყმება, ის წინ არ მიიწევს, ამიტომ განახლება აღარ ნიშნავს უკავშირო ცვლილებების პაკეტის შეთვისებას. ადრეულმა მომხმარებლებს კვლავ შეუძლიათ კომიტზე დაფუძნებული ბილდების გაშვება **canary**-ზე, ხოლო **release candidate** არხი გუნდებს საშუალებას აძლევს მომავალი ხაზი ტესტირებით შეამოწმონ, სანამ ის სტაბილური გახდება.

## მიმდინარე გამოშვებები {#live-release-status}

Stable-ის პრომოცია დაგეგმილია ორშაბათობით 06:00 UTC-ზე. წარმატებული დაგეგმილი პრომოციის შემდეგ, შემდეგი release candidate იჭრება `main`-დან, ხოლო მომდევნო canaries გადადიან შემდეგ მინორზე. მომავალი ფანჯრებისა და ბოლო გამოშვებების, მათ შორის პატჩებისა და backport-ების სანახავად, იხილეთ <.localized_link href="/cli/release/calendar">გამოშვებების კალენდარი</.localized_link>.

## არხები {#the-channels}

| არხი | ვერსიის ფორმატი | სიხშირე | ნაგულისხმევად წყდება? |
| --- | --- | --- | --- |
| Canary | `X.Y.0-canary.N` (მაგ., `4.201.0-canary.42`) | ყოველი კომიტი `main`-ში | არა — ცალსახა opt-in |
| Release candidate | `X.Y.0-rc.N` (მაგ., `4.200.0-rc.1`) | იჭრება `main`-დან ყოველ ორშაბათს, ტესტირება ~1 კვირა | არა — ცალსახა opt-in |
| Stable | `X.Y.Z` (მაგ., `4.200.0`, `4.200.1`) | პრომოცია ყოველ ორშაბათს წარმატებული ტესტირების შემდეგ | **კი** |

Canary და release candidate ბილდები ქვეყნდება როგორც prereleases. ისეთი ინსტრუმენტები, როგორიცაა Mise და Homebrew, გამორიცხავენ prereleases-ს `latest`-ის, უბრალო ინსტალაციის ან ხაზის მიმაგრების დროს, ამიტომ მათზე მოხვედრა მხოლოდ ცალსახად მოთხოვნით არის შესაძლებელი.

### Canary {#canary}

ყოველი კომიტი `main`-ში აქვეყნებს canary-ს. Canary ყოველთვის წარმოადგენს **შემდეგ გამოუქვეყნებელ მინორს**: როგორც კი ხაზი გამოშვებისთვის იჭრება, `main` გადადის შემდეგ მინორზე (მაგალითად, `4.200.0-canary.42`-დან `4.201.0-canary.1`-მდე). Canary სწორი არხია ადრეული მომხმარებლებისთვის, ვისაც ყველაზე ადრეული სიგნალი სურთ, ან იმის დასადასტურებლად, რომ თქვენს მიერ შეტყობინებულმა ან შეტანილმა გამოსწორებამ სტაბილურამდე მოღწევამდე მოსალოდნელად იმუშაოს.

### Release candidate {#release-candidate}

როდესაც მინორი მზადაა გამოშვებისთვის, მისი ხაზი იყინება დაცულ `releases/<major>.<minor>.x` ბრენჩზე და ქვეყნდება როგორც `X.Y.0-rc.1`. ხაზი ფუნქციებით გაყინულია; მხოლოდ კრიტიკული გამოსწორებები და რეგრესიები ირჩევა, და ყოველი მიღებული გამოსწორება ზრდის RC-ს (`-rc.2`, `-rc.3`, …). ტესტირების პერიოდის წარმატებით დასრულების შემდეგ, ხაზი პრომოცირდება stable-ზე.

### Stable {#stable}

Stable რეკომენდებული არხია და ყველა დოკუმენტაცია მასზე მიუთითებს. Stable მინორი (`X.Y.0`) ქვეყნდება მხოლოდ მაშინ, როცა release candidate წარმატებით გაივლის ტესტირებას, და ის **არ** მიიწევს წინ, როცა ახალი ფუნქციები ერწყმება `main`-ს. პატჩები (`X.Y.1`, `X.Y.2`, …) stable ხაზზე შეიცავს მხოლოდ backported გამოსწორებებს, არასდროს ახალ ფუნქციებს.

## ვერსიის არჩევა {#choosing-a-version}

<.localized_link href="/guides/install-tuist">Mise</.localized_link>-ით (რეკომენდებული):

```bash
mise use tuist@latest              # Latest stable (recommended)
mise use tuist@4.200               # Pin to a stable line; receives backported fixes only
mise use tuist@4.200.1             # Pin to an exact stable patch
mise use tuist@4.201.0-rc.1        # Opt into a release candidate to soak it
mise use tuist@4.201.0-canary.42   # Opt into a specific canary build
```

Homebrew-ით, `brew install --formula tuist` ყოველთვის ინსტალირებს უახლეს stable-ს; prereleases ფორმულით არ ვრცელდება.

## რეკომენდებული სტრატეგია {#recommended-strategy}

1. **მიამაგრეთ stable ხაზს**, მაგალითად `tuist@4.200`. ეს ხაზი იღებს მხოლოდ backported გამოსწორებებს, არასდროს ახალ ფუნქციებს, ამიტომ ყოველდღიური განახლებები დაბალი რისკის მქონეა.
2. **ახალი ფუნქციები განზრახ მიიღეთ.** როცა მზად იქნებით შემდეგი მინორისთვის, შეამოწმეთ ის release candidate არხზე, შემდეგ გადაიტანეთ მიმაგრება ახალ stable ხაზზე.
3. **სცადეთ canary** არაკრიტიკულ გარემოში, თუ ადრეული მომხმარებელი ხართ და ყველაზე ადრეული სიგნალი გსურთ.

## მხარდაჭერა და backports {#support-and-backports}

ნებისმიერ დროს აქტიურად მხარდაჭერილია ორი stable ხაზი:

| ხაზი | იღებს |
| --- | --- |
| მიმდინარე (`X.Y.x`) | რეგრესიები და უსაფრთხოების გამოსწორებები |
| წინა (`X.(Y-1).x`) | მხოლოდ კრიტიკული და უსაფრთხოების გამოსწორებები |
| უფრო ძველი | არა — გადადით მხარდაჭერილ ხაზზე |

გამოსწორებები ჯერ `main`-ზე (canary) ხვდება. რეგრესიები და უსაფრთხოების გამოსწორებები backport-დება მიმდინარე stable ხაზზე, წინა ხაზი კი იღებს მხოლოდ კრიტიკულ და უსაფრთხოების გამოსწორებებს. სხვა ბაგების გამოსწორებები არ backport-დება; ისინი შემდეგ მინორთან ერთად გამოიცემა. როცა ახალი ხაზი stable-ზე გადაყვანილია, მიმდინარე ხაზი ხდება „წინა“, ხოლო „წინა“ ხაზი წყვეტს backports-ის მიღებას.

არხისგან დამოუკიდებლად, Tuist სერვერი რჩება <.localized_link href="/cli/compatibility">თავსებადი</.localized_link> ნებისმიერ CLI-თან, რომელიც ბოლო 3 თვის განმავლობაში გამოვიდა, ამიტომ stable ხაზზე მიმაგრება არასდროს გაგიყვანთ მხარდაჭერილი ფანჯრიდან, თუ ამ პერიოდში განახლებას შეასრულებთ.
