# გამოშვების არხები {#release-channels}

Tuist CLI სამი არხის საშუალებით ვრცელდება, თითოეული სტაბილურობის განსხვავებული გარანტიებით. რეკომენდებული ინსტალაცია არის **stable** და ის ნელა ვითარდება: ყოველი ახალი ფუნქციის შერწყმისას ვერსია არ იცვლება, ამიტომ განახლება აღარ ნიშნავს შეუსაბამო ცვლილებების ერთდროულ მიღებას. ადრეულმა მომხმარებლებს შეუძლიათ კომიტზე დაფუძნებული ბილდების გაშვება **canary** არხზე, ხოლო **release candidate** არხი გუნდებს საშუალებას აძლევს წინასწარ შეამოწმონ მომავალი ხაზი, სანამ ის სტაბილური გახდება.

## არხები {#the-channels}

| არხი | ვერსიის ფორმატი | სიხშირე | ავტომატურად არჩევა? |
| --- | --- | --- | --- |
| Canary | `X.Y.0-canary.N` (მაგ., `4.201.0-canary.42`) | ყოველი კომიტი `main`-ში | არა — მხოლოდ ცხადად მითითებისას |
| Release candidate | `X.Y.0-rc.N` (მაგ., `4.200.0-rc.1`) | ჭრა `main`-დან ყოველ ორშაბათს, ტესტირება ~1 კვირა | არა — მხოლოდ ცხადად მითითებისას |
| Stable | `X.Y.Z` (მაგ., `4.200.0`, `4.200.1`) | ყველა ორშაბათს გადადის სტაბილურში წარმატებული ტესტირების შემდეგ | **დიახ** |

Canary და release candidate ბილდები ქვეყნდება როგორც პრერელიზები. ისეთი ინსტრუმენტები, როგორიცაა Mise და Homebrew, გამორიცხავენ პრერელიზებს `latest`-ის, „უბრალო“ ინსტალაციის ან ხაზის მიმაგრების დროს, ამიტომ მათზე მოხვდებით მხოლოდ მაშინ, როცა ცხადად მოითხოვთ.

### Canary {#canary}

ყოველი კომიტი `main`-ში აქვეყნებს canary ვერსიას. Canary ყოველთვის წარმოადგენს **შემდეგ გამოუქვეყნებელ მინორულ ვერსიას**: როგორც კი ხაზი გამოიყოფა გამოშვებისთვის, `main` გადადის შემდეგ მინორულ ვერსიაზე (მაგალითად, `4.200.0-canary.42`-დან `4.201.0-canary.1`-ზე). Canary შესაფერისი არხია ადრეული მომხმარებლებისთვის, ვისაც სურს რაც შეიძლება ადრეული სიგნალი, ან სურს შეამოწმოს, რომ თქვენს მიერ შეტანილი ან შეტანილი შესწორება მოქმედებს მოსალოდნელად, სანამ ის stable-ში მოხვდება.

### Release candidate {#release-candidate}

როდესაც მინორული ვერსია მზადაა გამოშვებისთვის, მისი ხაზი იყინება დაცულ `releases/<major>.<minor>.x` ბრენჩზე და ქვეყნდება როგორც `X.Y.0-rc.1`. ხაზი ფუნქციებით გაყინულია; მხოლოდ კრიტიკული შესწორებები და რეგრესიები გადააქვთ, და ყოველი მიღებული შესწორება ზრდის RC-ს (`-rc.2`, `-rc.3`, …). ტესტირების პერიოდის წარმატებით დასრულების შემდეგ, ხაზი გადადის სტაბილურში.

### Stable {#stable}

Stable არის რეკომენდებული არხი და ყველა დოკუმენტაცია მასზე მიუთითებს. სტაბილური მინორული ვერსია (`X.Y.0`) ქვეყნდება მხოლოდ მაშინ, როცა release candidate წარმატებით გაივლის ტესტირებას, და ის **არ** იცვლება, როცა ახალი ფუნქციები ერწყმება `main`-ს. პატჩები (`X.Y.1`, `X.Y.2`, …) სტაბილურ ხაზზე შეიცავს მხოლოდ უკან გადატანილ შესწორებებს, არასდროს ახალ ფუნქციებს.

## ვერსიის არჩევა {#choosing-a-version}

[Mise](/en/guides/install-tuist)-ით (რეკომენდებული):

```bash
mise use tuist@latest              # Latest stable (recommended)
mise use tuist@4.200               # Pin to a stable line; receives backported fixes only
mise use tuist@4.200.1             # Pin to an exact stable patch
mise use tuist@4.201.0-rc.1        # Opt into a release candidate to soak it
mise use tuist@4.201.0-canary.42   # Opt into a specific canary build
```

Homebrew-ით, `brew install --formula tuist` ყოველთვის ინსტალირებს უახლეს სტაბილურ ვერსიას; პრერელიზები ფორმულით არ ვრცელდება.

## რეკომენდებული სტრატეგია {#recommended-strategy}

1. **მიამაგრეთ სტაბილურ ხაზს**, მაგალითად `tuist@4.200`. ეს ხაზი იღებს მხოლოდ უკან გადატანილ შესწორებებს, არასდროს ახალ ფუნქციებს, ამიტომ ყოველდღიური განახლებები დაბალი რისკისაა.
2. **განზრახვით მიიღეთ ახალი ფუნქციები.** როდესაც მზად იქნებით შემდეგი მინორული ვერსიისთვის, შეამოწმეთ ის release candidate არხზე, შემდეგ გადაიტანეთ მიმაგრება ახალ სტაბილურ ხაზზე.
3. **სცადეთ canary** არაკრიტიკულ გარემოში, თუ ხართ ადრეული მომხმარებელი და გსურთ რაც შეიძლება ადრეული სიგნალი.

## მხარდაჭერა და უკან გადატანილი შესწორებები {#support-and-backports}

ნებისმიერ დროს აქტიურად მხარდაჭერილია ორი სტაბილური ხაზი:

| ხაზი | იღებს |
| --- | --- |
| მიმდინარე (`X.Y.x`) | რეგრესიები და უსაფრთხოების შესწორებები |
| წინა (`X.(Y-1).x`) | მხოლოდ კრიტიკული და უსაფრთხოების შესწორებები |
| ძველი | არაფერი — გადადით მხარდაჭერილ ხაზზე |

შესწორებები ჯერ `main`-ზე (canary) ხვდება. რეგრესიები და უსაფრთხოების შესწორებები უკან გადააქვთ მიმდინარე სტაბილურ ხაზზე, წინა ხაზი კი იღებს მხოლოდ კრიტიკულ და უსაფრთხოების შესწორებებს. სხვა ბაგების შესწორებები უკან არ გადააქვთ; ისინი შემდეგ მინორულ ვერსიაში გამოიცემა. როდესაც ახალი ხაზი სტაბილურად ქვეყნდება, მიმდინარე ხაზი „წინა“ ხდება, ხოლო „წინა“ ხაზი წყვეტს უკან გადატანილი შესწორებების მიღებას.

არხისგან დამოუკიდებლად, Tuist სერვერი რჩება [თავსებადი](/en/cli/compatibility) ნებისმიერ CLI-თან, რომელიც ბოლო 3 თვის განმავლობაში გამოიცა, ამიტომ სტაბილურ ხაზზე მიმაგრება არასდროს გაგიყვანთ მხარდაჭერილ ფარგლებს გარეთ, თუ ამ პერიოდში განახლებას მოახდენთ.
