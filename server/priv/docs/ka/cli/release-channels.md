# გამოშვების არხები {#release-channels}

Tuist CLI სამი განსხვავებული სტაბილურობის გარანტიით აღჭურვილი არხის მეშვეობით ნაწილდება. რეკომენდებული ინსტალაცია არის **stable**, რომელიც ნელა ვითარდება: ის არ ადიდებს ყოველ ჯერზე, როდესაც ფუნქცია merge-დება, ამიტომ განახლება აღარ ნიშნავს დაუკავშირებელი ცვლილებების პაკეტის შეთვისებას. ადრეულმა მომხმარებლებმა კვლავ შეუძლიათ გაუშვან თითოეული commit-ის ბილდები **canary**-ზე, ხოლო **release candidate** არხი საშუალებას აძლევს გუნდებს წინასწარ შეაფასონ მომავალი ხაზი, სანამ ის stable გახდება.

## არხები {#the-channels}

| არხი | ვერსიის ფორმატი | სიხშირე | ნაგულისხმევად გადაწყდება? |
| --- | --- | --- | --- |
| Canary | `X.Y.0-canary.N` (მაგ., `4.201.0-canary.42`) | ყოველი commit `main`-ზე | არა — მხოლოდ ცალსახა ჩართვის შემთხვევაში |
| Release candidate | `X.Y.0-rc.N` (მაგ., `4.200.0-rc.1`) | ჭრა `main`-დან ყოველ ორშაბათს, ტესტირება ~1 კვირა | არა — მხოლოდ ცალსახა ჩართვის შემთხვევაში |
| Stable | `X.Y.Z` (მაგ., `4.200.0`, `4.200.1`) | ყველა ორშაბათს გადაჰყავთ stable-ში წარმატებული ტესტირების შემდეგ | **დიახ** |

Canary და release candidate ბილდები ქვეყნდება როგორც prerelease. ისეთი ინსტრუმენტები, როგორიცაა Mise და Homebrew, გამორიცხავენ prerelease-ებს, როდესაც გადაწყვეტენ `latest`-ს, უბრალო ინსტალაციას ან ხაზის მიმაგრებას, ამიტომ მათზე მოხვედრა მხოლოდ მათი ცალსახად მოთხოვნით არის შესაძლებელი.

### Canary {#canary}

ყოველი commit `main`-ზე აქვეყნებს canary-ს. Canary ყოველთვის წარმოადგენს **შემდეგ გამოუშვებელ minor**-ს: როდესაც ხაზი გამოშვებისთვის იჭრება, `main` გადადის შემდეგ minor-ზე (მაგალითად, `4.200.0-canary.42`-დან `4.201.0-canary.1`-მდე). Canary არის სწორი არხი ადრეული მომხმარებლებისთვის, რომლებიც ეძებენ უადრეს შესაძლო სიგნალს, ან სურთ შეამოწმონ, რომ თქვენს მიერ შეტანილი ან შეტანილი გამოსწორება მოქმედებს მოსალოდნელად, სანამ ის stable-ს მიაღწევს.

### Release candidate {#release-candidate}

როდესაც minor მზადაა გამოშვებისთვის, მისი ხაზი იყინება დაცულ `releases/<major>.<minor>.x` branch-ზე და ქვეყნდება როგორც `X.Y.0-rc.1`. ხაზი არის ფუნქციებით გაყინული; მხოლოდ კრიტიკული გამოსწორებები და რეგრესიები cherry-pick-დება და ყოველი მიღებული გამოსწორება ზრდის RC-ს (`-rc.2`, `-rc.3`, …). ტესტირების პერიოდის წარმატებით დასრულების შემდეგ, ხაზი გადაჰყავთ stable-ში.

### Stable {#stable}

Stable არის რეკომენდებული არხი და ის, რომელზეც ყველა დოკუმენტაცია მიუთითებს. Stable minor (`X.Y.0`) ქვეყნდება მხოლოდ მაშინ, როდესაც release candidate წარმატებით გაივლის ტესტირებას და ის **არ** ადიდებს, როდესაც ახალი ფუნქციები merge-დება `main`-ზე. პატჩები (`X.Y.1`, `X.Y.2`, …) stable ხაზზე შეიცავს მხოლოდ backported გამოსწორებებს, არასდროს ახალ ფუნქციებს.

## ვერსიის არჩევა {#choosing-a-version}

[Mise](/en/guides/install-tuist)-ით (რეკომენდებული):

```bash
mise use tuist@latest              # Latest stable (recommended)
mise use tuist@4.200               # Pin to a stable line; receives backported fixes only
mise use tuist@4.200.1             # Pin to an exact stable patch
mise use tuist@4.201.0-rc.1        # Opt into a release candidate to soak it
mise use tuist@4.201.0-canary.42   # Opt into a specific canary build
```

Homebrew-ით, `brew install --formula tuist` ყოველთვის ინსტალირებს უახლეს stable-ს; prerelease-ები არ ნაწილდება formula-ს მეშვეობით.

## რეკომენდებული სტრატეგია {#recommended-strategy}

1. **მიამაგრეთ stable ხაზს**, მაგალითად `tuist@4.200`. ეს ხაზი იღებს მხოლოდ backported გამოსწორებებს, არასდროს ახალ ფუნქციებს, ამიტომ ყოველდღიური განახლებები დაბალი რისკის მქონე რჩება.
2. **ახალი ფუნქციები გონივრულად აითვისეთ.** როდესაც მზად ხართ შემდეგი minor-ისთვის, შეაფასეთ ის release candidate არხზე, შემდეგ გადაიტანეთ თქვენი მიმაგრება ახალ stable ხაზზე.
3. **სცადეთ canary** არაკრიტიკულ გარემოში, თუ ხართ ადრეული მომხმარებელი, რომელსაც სურს უადრესი შესაძლო სიგნალი.

## მხარდაჭერა და backport-ები {#support-and-backports}

ნებისმიერ დროს აქტიურად მხარდაჭერილია ორი stable ხაზი:

| ხაზი | იღებს |
| --- | --- |
| მიმდინარე (`X.Y.x`) | რეგრესიები და უსაფრთხოების გამოსწორებები |
| წინა (`X.(Y-1).x`) | მხოლოდ კრიტიკული და უსაფრთხოების გამოსწორებები |
| უფრო ძველი | არაფერი — გადადით მხარდაჭერილ ხაზზე |

გამოსწორებები ჯერ `main`-ზე (canary) ხვდება. რეგრესიები და უსაფრთხოების გამოსწორებები backport-დება მიმდინარე stable ხაზზე, ხოლო წინა ხაზი იღებს მხოლოდ კრიტიკულ და უსაფრთხოების გამოსწორებებს. სხვა ბაგების გამოსწორებები არ backport-დება; ისინი შემდეგ minor-თან ერთად გამოიცემა. როდესაც ახალი ხაზი promoted-დება stable-ში, ხაზი, რომელიც იყო „მიმდინარე“, ხდება „წინა“, ხოლო ხაზი, რომელიც იყო „წინა“, წყვეტს backport-ების მიღებას.

არხისგან დამოუკიდებლად, Tuist სერვერი რჩება [თავსებადი](/en/cli/compatibility) ნებისმიერ CLI-სთან, რომელიც გამოიცა ბოლო 3 თვის განმავლობაში, ამიტომ stable ხაზზე მიმაგრება არასდროს გაგიყვანთ მხარდაჭერილი ფანჯრიდან გარეთ, თუ ამ პერიოდში განახლებას მოახდენთ.
