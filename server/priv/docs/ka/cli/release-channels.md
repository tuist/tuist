# გამოშვების არხები {#release-channels}

Tuist CLI სამი განსხვავებული სტაბილურობის გარანტიით აღჭურვილი არხის მეშვეობით ვრცელდება. რეკომენდებული ინსტალაციაა **stable**, რომელიც ნელა ვითარდება: ის არ ადიდებს ყოველ ჯერზე, როდესაც ფუნქცია ერწყმება, ამიტომ განახლება აღარ ნიშნავს დაკავშირებულ ცვლილებების პაკეტის შთანთქმას. ადრეულმა მომხმარებლებმა შეუძლიათ კვლავ გაუშვან კომიტ-მიხედვით ბილდები **canary**-ზე, ხოლო **release candidate** არხი საშუალებას აძლევს გუნდებს წინასწარ შეამოწმონ მომავალი ხაზი, სანამ ის სტაბილური გახდება.

## არხები {#the-channels}

| არხი | ვერსიის ფორმატი | სიხშირე | ნაგულისხმევად გადაწყდება? |
| --- | --- | --- | --- |
| Canary | `X.Y.0-canary.N` (მაგ., `4.201.0-canary.42`) | ყოველი კომიტი `main`-ში | არა — ცალსახა ჩართვა |
| Release candidate | `X.Y.0-rc.N` (მაგ., `4.200.0-rc.1`) | ყოველ ორშაბათს იჭრება `main`-დან, ~1 კვირა სოკდება | არა — ცალსახა ჩართვა |
| Stable | `X.Y.Z` (მაგ., `4.200.0`, `4.200.1`) | ყველა ორშაბათს პრომოტირდება სუფთა სოკების შემდეგ | **დიახ** |

Canary და release candidate ბილდები გამოქვეყნდება როგორც prerelease. ისეთი ინსტრუმენტები, როგორიცაა Mise და Homebrew, გამორიცხავენ prereleases-ს, როდესაც გადაწყვეტენ `latest`-ს, უბრალო ინსტალაციას ან ხაზის მიმაგრებას, ამიტომ მათზე მოხვედრა შესაძლებელია მხოლოდ ცალსახად მოთხოვნის შემთხვევაში.

### Canary {#canary}

ყოველი კომიტი `main`-ში აქვეყნებს canary-ს. Canary ყოველთვის წარმოადგენს **შემდეგ გამოუქვეყნებელ მინორს**: როდესაც ხაზი იჭრება გამოშვებისთვის, `main` გადადის შემდეგ მინორზე (მაგალითად, `4.200.0-canary.42`-დან `4.201.0-canary.1`-მდე). Canary სწორი არხია ადრეული მომხმარებლებისთვის, ვისაც სურს უადრესი შესაძლო სიგნალი, ან რათა შეამოწმონ, რომ თქვენს მიერ შეტანილმა ან შეტანილმა შესწორებამ მოქმედებს მოსალოდნელად, სანამ ის stable-ს მიაღწევს.

### Release candidate {#release-candidate}

როდესაც მინორი მზადაა გამოშვებისთვის, მისი ხაზი იყინება დაცულ `releases/<major>.<minor>.x` ბრენჩზე და ქვეყნდება როგორც `X.Y.0-rc.1`. ხაზი ფუნქციებით გაყინულია; მხოლოდ კრიტიკული შესწორებები და რეგრესიები არის cherry-picked, და ყოველი მიღებული შესწორება ზრდის RC-ს (`-rc.2`, `-rc.3`, …). სოკის პერიოდის სუფთად დასრულების შემდეგ, ხაზი პრომოტირდება stable-ზე.

### Stable {#stable}

Stable არის რეკომენდებული არხი და ის, რომელზეც ყველა დოკუმენტაცია მიუთითებს. სტაბილური მინორი (`X.Y.0`) ქვეყნდება მხოლოდ მაშინ, როდესაც release candidate სუფთად სოკდება, და ის **არ** ადიდებს, როდესაც ახალი ფუნქციები ერწყმება `main`-ს. პატჩები (`X.Y.1`, `X.Y.2`, …) სტაბილურ ხაზზე შეიცავს მხოლოდ backported შესწორებებს, არასდროს ახალ ფუნქციებს.

## ვერსიის არჩევა {#choosing-a-version}

<.localized_link href="/guides/install-tuist">Mise</.localized_link>-ით (რეკომენდებული):

```bash
mise use tuist@latest              # Latest stable (recommended)
mise use tuist@4.200               # Pin to a stable line; receives backported fixes only
mise use tuist@4.200.1             # Pin to an exact stable patch
mise use tuist@4.201.0-rc.1        # Opt into a release candidate to soak it
mise use tuist@4.201.0-canary.42   # Opt into a specific canary build
```

Homebrew-ით, `brew install --formula tuist` ყოველთვის ინსტალირებს უახლეს stable-ს; prereleases არ ვრცელდება ფორმულით.

## რეკომენდებული სტრატეგია {#recommended-strategy}

1. **მიამაგრეთ სტაბილურ ხაზს**, მაგალითად `tuist@4.200`. ეს ხაზი იღებს მხოლოდ backported შესწორებებს, არასდროს ახალ ფუნქციებს, ამიტომ ყოველდღიური განახლებები დაბალი რისკის მქონე რჩება.
2. **განზრახ მიიღეთ ახალი ფუნქციები.** როდესაც მზად იქნებით შემდეგი მინორისთვის, სოკეთ ის release candidate არხზე, შემდეგ გადაიტანეთ თქვენი მიმაგრება ახალ სტაბილურ ხაზზე.
3. **სცადეთ canary** არაკრიტიკულ გარემოში, თუ ხართ ადრეული მომხმარებელი, ვისაც სურს უადრესი შესაძლო სიგნალი.

## მხარდაჭერა და backports {#support-and-backports}

ნებისმიერ დროს აქტიურად მხარდაჭერილია ორი სტაბილური ხაზი:

| ხაზი | იღებს |
| --- | --- |
| მიმდინარე (`X.Y.x`) | რეგრესიები და უსაფრთხოების შესწორებები |
| წინა (`X.(Y-1).x`) | მხოლოდ კრიტიკული და უსაფრთხოების შესწორებები |
| უფრო ძველი | არაფერი — გადადით მხარდაჭერილ ხაზზე |

შესწორებები ჯერ `main`-ზე (canary) ხვდება. რეგრესიები და უსაფრთხოების შესწორებები backport-დება მიმდინარე სტაბილურ ხაზზე, წინა ხაზი კი იღებს მხოლოდ კრიტიკულ და უსაფრთხოების შესწორებებს. სხვა ბაგების შესწორებები არ backport-დება; ისინი გამოიცემა შემდეგ მინორთან ერთად. როდესაც ახალი ხაზი გადაჰყავთ stable-ში, მიმდინარე ხაზი ხდება „წინა“, ხოლო „წინა“ ხაზი წყვეტს backport-ების მიღებას.

არხისგან დამოუკიდებლად, Tuist სერვერი რჩება <.localized_link href="/cli/compatibility">თავსებადი</.localized_link> ნებისმიერ CLI-თან, რომელიც ბოლო 3 თვის განმავლობაში გამოვიდა, ამიტომ სტაბილურ ხაზზე მიმაგრება არასდროს გაგიყვანთ მხარდაჭერილ ფარგლებს გარეთ, თუ ამ პერიოდში განახლებას შეასრულებთ.
