# გამოშვების არხები {#release-channels}

Tuist CLI სამი არხის მეშვეობით ვრცელდება, თითოეული სტაბილურობის განსხვავებული გარანტიით. რეკომენდებული ინსტალაციაა **stable**, რომელიც ნელა მოძრაობს: ის არ გადადის წინ ყოველ ჯერზე, როცა ფუნქცია ერწყმება, ამიტომ განახლება აღარ ნიშნავს დაკავშირებული ცვლილებების ნაკადის შთანთქმას. ადრეულმა მომხმარებლებმა შეუძლიათ კვლავ გაუშვან თითოეულ კომიტზე ბილდები **canary**-ზე, ხოლო **release candidate** არხი საშუალებას აძლევს გუნდებს მომავალი ხაზი გამოსცადონ, სანამ ის სტაბილური გახდება.

## არხები {#the-channels}

| არხი | ვერსიის ფორმატი | სიხშირე | ნაგულისხმევად ირჩევა? |
| --- | --- | --- | --- |
| Canary | `X.Y.0-canary.N` (მაგ., `4.201.0-canary.42`) | ყოველი კომიტი `main`-ზე | არა — მხოლოდ ცალსახა არჩევით |
| Release candidate | `X.Y.0-rc.N` (მაგ., `4.200.0-rc.1`) | ჭრება `main`-დან ყოველ ორშაბათს, ~1 კვირიანი ტესტირება | არა — მხოლოდ ცალსახა არჩევით |
| Stable | `X.Y.Z` (მაგ., `4.200.0`, `4.200.1`) | წინ გადადის ყოველ ორშაბათს წარმატებული ტესტირების შემდეგ | **დიახ** |

Canary და release candidate ბილდები პრერელიზებად ქვეყნდება. ისეთი ინსტრუმენტები, როგორიცაა Mise და Homebrew, გამორიცხავენ პრერელიზებს `latest`-ის, უბრალო ინსტალაციის ან ხაზის მიმაგრების დროს, ამიტომ მათზე მხოლოდ მაშინ მოხვდებით, როცა ცალსახად მოითხოვთ.

### Canary {#canary}

ყოველი კომიტი `main`-ზე აქვეყნებს canary-ს. Canary ყოველთვის წარმოადგენს **შემდეგ გამოუშვებელ მინორს**: როგორც კი ხაზი გამოშვებისთვის ჩაიჭრება, `main` გადადის შემდეგ მინორზე (მაგალითად, `4.200.0-canary.42`-დან `4.201.0-canary.1`-მდე). Canary სწორი არხია ადრეული მომხმარებლებისთვის, ვისაც სურთ უადრესი შესაძლო სიგნალი, ან ვისაც სურს დაადასტუროს, რომ თქვენს მიერ შეტანილი ან მოხსენებული შესწორება მოსალოდნელად იქცევა, სანამ ის stable-ს მიაღწევს.

### Release candidate {#release-candidate}

როცა მინორი მზადაა გამოშვებისთვის, მისი ხაზი იყინება დაცულ `releases/<major>.<minor>.x` ბრენჩზე და ქვეყნდება როგორც `X.Y.0-rc.1`. ხაზი ფუნქციურად გაყინულია; მხოლოდ კრიტიკული შესწორებები და რეგრესიები გადააქვთ, და ყოველი მიღებული შესწორება ზრდის RC-ს (`-rc.2`, `-rc.3`, …). ტესტირების პერიოდის წარმატებით დასრულების შემდეგ ხაზი სტაბილურად გადადის.

### Stable {#stable}

Stable რეკომენდებული არხია და ყველა დოკუმენტაცია მასზე მიუთითებს. სტაბილური მინორი (`X.Y.0`) ქვეყნდება მხოლოდ მაშინ, როცა release candidate-მა წარმატებით გაიარა ტესტირება, და ის **არ** გადადის წინ, როცა ახალი ფუნქციები ერწყმება `main`-ს. პატჩები (`X.Y.1`, `X.Y.2`, …) სტაბილურ ხაზზე შეიცავს მხოლოდ უკანპორტირებულ შესწორებებს, არასდროს ახალ ფუნქციებს.

## ვერსიის არჩევა {#choosing-a-version}

[Mise](/en/guides/install-tuist)-ით (რეკომენდებული):

```bash
mise use tuist@latest              # Latest stable (recommended)
mise use tuist@4.200               # Pin to a stable line; receives backported fixes only
mise use tuist@4.200.1             # Pin to an exact stable patch
mise use tuist@4.201.0-rc.1        # Opt into a release candidate to soak it
mise use tuist@4.201.0-canary.42   # Opt into a specific canary build
```

Homebrew-ით, `brew install --formula tuist` ყოველთვის ინსტალირებს უახლეს სტაბილურს; პრერელიზები ფორმულით არ ვრცელდება.

## რეკომენდებული სტრატეგია {#recommended-strategy}

1. **მიამაგრეთ სტაბილურ ხაზს**, მაგალითად `tuist@4.200`. ეს ხაზი იღებს მხოლოდ უკანპორტირებულ შესწორებებს, არასდროს ახალ ფუნქციებს, ამიტომ ყოველდღიური განახლებები დაბალი რისკის მქონე რჩება.
2. **ახალი ფუნქციები განზრახ მიიღეთ.** როცა მზად ხართ შემდეგი მინორისთვის, გამოსცადეთ ის release candidate არხზე, შემდეგ გადაიტანეთ მიმაგრება ახალ სტაბილურ ხაზზე.
3. **სცადეთ canary** არაკრიტიკულ გარემოში, თუ ხართ ადრეული მომხმარებელი, ვისაც სურთ უადრესი შესაძლო სიგნალი.

## მხარდაჭერა და უკანპორტირება {#support-and-backports}

ნებისმიერ დროს აქტიურად მხარდაჭერილია ორი სტაბილური ხაზი:

| ხაზი | იღებს |
| --- | --- |
| მიმდინარე (`X.Y.x`) | რეგრესიებსა და უსაფრთხოების შესწორებებს |
| წინა (`X.(Y-1).x`) | მხოლოდ კრიტიკული და უსაფრთხოების შესწორებები |
| ძველი | არცერთი — გადადით მხარდაჭერილ ხაზზე |

შესწორებები ჯერ `main`-ზე (canary) ხვდება. რეგრესიებსა და უსაფრთხოების შესწორებებს უკანაპორტებენ მიმდინარე სტაბილურ ხაზზე, წინა ხაზი კი იღებს მხოლოდ კრიტიკულ და უსაფრთხოების შესწორებებს. სხვა ბაგების შესწორებები არ უკანაპორტდება; ისინი შემდეგ მინორთან ერთად გამოიცემა. როცა ახალი ხაზი სტაბილურად ქვეყნდება, მიმდინარე ხაზი ხდება „წინა“, ხოლო „წინა“ ხაზი წყვეტს უკანაპორტირებული შესწორებების მიღებას.

არხისგან დამოუკიდებლად, Tuist სერვერი რჩება [თავსებადი](/en/cli/compatibility) ნებისმიერ CLI-თან, რომელიც ბოლო 3 თვის განმავლობაში გამოიცა, ამიტომ სტაბილურ ხაზზე მიმაგრება არასდროს გაგიყვანთ მხარდაჭერილ ფანჯარას გარეთ, თუ ამ პერიოდში განახლებას მოახდენთ.
