# Once პროექტი {#once-project}

::: code-group

```text [Agent prompt]
Help me get started with Tuist. Follow the setup at:
https://tuist.dev/en/docs/guides/get-started/once-project
```

:::

[Once](https://buildonce.dev) ასრულებს კეშირებად სკრიპტებს და აგების გრაფებს. დააკავშირეთ ის Tuist-თან, რათა გაუზიაროთ კეშირებული სამუშაო სხვადასხვა მანქანას, თვალყური ადევნოთ გაშვებებს რეალურ დროში და გამოაქვეყნოთ აპლიკაციები თქვენი გუნდისთვის საცდელად. შეინარჩუნეთ არსებული პროექტის წყაროები და აგების განმარტებები; ინტეგრაცია მოთავსებულია `once.toml`-ში.

## წინაპირობები

- [Once](https://buildonce.dev/docs/guide/getting-started) დაინსტალირებული და სამუშაო სივრცე ან კეშირებადი სკრიპტი.
- Tuist ანგარიში. Once-თან ინტეგრაციისთვის Tuist CLI არ არის საჭირო.

## პროექტის დაკავშირება {#connect-the-project}

რეპოზიტორიის ფესვიდან გაუშვით:

```bash
once connect --provider tuist --create
```

Once საჭიროების შემთხვევაში გაგივლით ავტორიზაციას, შექმნის Tuist პროექტს თქვენს პირად ანგარიშზე და ჩაწერს პროვაიდერის ბმულს `once.toml`-ში. იხილეთ [პროექტის დაკავშირება](https://buildonce.dev/docs/guide/infrastructure/connect) სხვა ანგარიშის ან არსებული პროექტის არჩევისთვის.

არსებული Tuist პროექტისთვის, თავად დააკონფიგურირეთ პროვაიდერი და კეშის ბმა:

```toml
[infrastructures.tuist]
kind = "tuist"
account = "acme"
project = "app"
# url = "https://your-tuist-server.example.com"

[infrastructure.cache]
provider = "tuist"
```

ჩაანაცვლეთ `acme` და `app` თქვენი ანგარიშისა და პროექტის იდენტიფიკატორებით, შემდეგ გაიარეთ ავტორიზაცია:

```bash
once auth login --provider tuist
```

დააკომიტეთ `once.toml`, რათა თქვენმა თანამშრომლებმა და CI-მ გაიზიარონ დანიშნულება, არა თქვენი სერთიფიკატები. ყოველი დეველოპერი შედის საკუთარ მანქანაზე.

## გაზიარებული კეში

ლოკალური კეში ეხმარება მხოლოდ იმ მანქანას, რომელმაც ის შექმნა. Tuist-ის კონფიგურაციის შემთხვევაში, Once-ს შეუძლია აღადგინოს შესაბამისი შედეგები, რომლებიც სხვა დეველოპერმა ან CI-მ მიიღო, იმავე სამუშაოს ხელახლა შესრულების ნაცვლად.

ჩვეულებრივად გაუშვით თქვენი კეშირებადი სკრიპტი ან გრაფის სამიზნე:

```bash
once build MyApplication
```

გახსენით **Once Cache** დაფაზე, რათა შეამოწმოთ შორეული კეშის აქტივობა. იხილეთ <.localized_link href="/guides/features/cache/once">Once cache</.localized_link> დაყენებისა და მანქანებს შორის ხელახალი გამოყენების შესამოწმებლად.

## აგების ინსაიტები

Once ბეჭდავს დაფის ბმულს გაშვების დაწყებისას. გახსენით ის, რათა თვალყური ადევნოთ გრაფს, მოქმედებების სტატუსს და კეშის გადაწყვეტილებებს გაშვების პროცესში. გამოიყენეთ **Builds** ლოკალური და CI წარმადობის შესადარებლად და წარუმატებელი მოქმედებების გამოსაკვლევად. შეინარჩუნეთ CI ლოგები პროცესის სრული გამოტანისთვის; მოქმედებების უმიზნო ლოგების შეტანა ამჟამად არ არის ხელმისაწვდომი.

იხილეთ <.localized_link href="/guides/features/build-insights/once">Once build insights</.localized_link> იმის გასაგებად, თუ რა იწერება და როგორ მივუდგეთ მას კოდირების აგენტებიდან ან Grafana-დან.

## ტესტების ინსაიტები და შარდინგი

გაუშვით თქვენი Once ტესტის სამიზნეები:

```bash
once test
```

გახსენით **Tests** მოხსენებული სუიტების, საქმეების, ხანგრძლივობებისა და შეცდომების შესამოწმებლად. შედეგები დამოკიდებულია ტესტის სამიზნის მოხსენების შესაძლებლობებზე; მოქმედება, რომელიც ასრულებს ტესტის პროცესს, არ არის ავტომატურად თითოეული საქმის ტესტის მოხსენება.

როდესაც სუიტა ერთ მანქანას აღემატება, შექმენით ჰოსტინგული შარდინგის გეგმა და გაანაწილეთ მისი პაკეტები CI მუშაკებზე. იხილეთ <.localized_link href="/guides/features/test-insights/once">Once test insights</.localized_link> და <.localized_link href="/guides/features/test-sharding/once">Once test sharding</.localized_link>.

## პრევიუები და ბანდლის ზომა

დაამატეთ არტიფაქტის ბმა იმავე პროვაიდერზე, რათა გამოაქვეყნოთ მხარდაჭერილი Android, Apple სიმულატორისა და macOS აპლიკაციები:

```toml
[infrastructure.artifacts]
name = "tuist"
```

```bash
once artifact publish MyApplication --track review
```

დაბრუნებული ბმა ხსნის თქვენი პროექტის პრევიუებს; დამუშავებას შეიძლება ცოტა ხანი დასჭირდეს. იხილეთ <.localized_link href="/guides/features/previews/once">Once previews</.localized_link> ხელმოწერის მოთხოვნებისა და აგების შემდეგ არჩევითი გამოქვეყნებისთვის.

ბანდლის ზომის თვალყურის დევნებისთვის, ცალ-ცალკე გამოიყენეთ Tuist CLI აგებულ `.app`, `.ipa`, `.xcarchive`, `.apk` ან `.aab` ფაილზე. მიჰყევით <.localized_link href="/guides/features/bundle-insights">Apple ან Android ბანდლის ინსაიტების სახელმძღვანელოს</.localized_link>; Once არტიფაქტის გამოქვეყნება ავტომატურად არ ტვირთავს ბანდლის ზომის მოხსენებას.

## უწყვეტი ინტეგრაცია

გამოიყენეთ ანგარიშის ტოკენი, რომელიც ავტორიზებულია პროექტის ოპერაციებისთვის `TUIST_TOKEN`-ში, ან გაიარეთ ავტორიზაცია მხარდაჭერილი CI პროვაიდერის OpenID Connect იდენტობის მეშვეობით:

```bash
once auth login --provider tuist --no-browser
once build MyApplication
once test
```

GitHub Actions-ზე, მიანიჭეთ სამუშაოს `id-token: write` და `contents: read`. მაგალითისთვის იხილეთ <.localized_link href="/guides/integrations/continuous-integration#once">Once უწყვეტ ინტეგრაციაზე</.localized_link>. პირადი დეველოპერის შესვლა არ არის CI სერთიფიკატი.

## შორეული შესრულება

ანგარიშებს, რომლებსაც ჩართული აქვთ შორეული შესრულება, ასევე შეუძლიათ შეასრულონ შესაბამისი გრაფის ბრძანებების მოქმედებები Tuist-ის Linux მუშაკებზე. ეს განცალკევებულია კეშირებული შედეგების გაზიარებისა და მთლიანი CI სამუშაო ნაკადის გაშვებისგან. იხილეთ <.localized_link href="/guides/features/runners/once">Once remote execution</.localized_link> მუშაკის მოთხოვნებისა და დაყენებისთვის.
