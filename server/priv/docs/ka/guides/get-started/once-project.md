# Once პროექტი {#once-project}

::: code-group

```text [Agent prompt]
Help me get started with Tuist. Follow the setup at:
https://tuist.dev/en/docs/guides/get-started/once-project
```

:::

[Once](https://buildonce.dev) ასრულებს კეშირებად სკრიპტებს და აგების გრაფებს. დააკავშირეთ ის Tuist-თან, რათა გააზიაროთ კეშირებული სამუშაოები მანქანებს შორის, თვალყური ადევნოთ გაშვებებს რეალურ დროში და გამოაქვეყნოთ აპლიკაციები თქვენი გუნდისთვის საცდელად. შეინახეთ არსებული პროექტის წყაროები და აგების განმარტებები; ინტეგრაცია მოთავსებულია `once.toml`-ში.

## წინაპირობები

- დაინსტალირებული [Once](https://buildonce.dev/docs/guide/getting-started) და სამუშაო სივრცე ან კეშირებადი სკრიპტი.
- Tuist ანგარიში. Once-თან ინტეგრაციისთვის Tuist CLI არ არის საჭირო.

## პროექტის დაკავშირება {#connect-the-project}

რეპოზიტორიის ძირიდან გაუშვით:

```bash
once connect --provider tuist --create
```

Once საჭიროების შემთხვევაში გაგივლით ავტორიზაციას, შექმნის Tuist პროექტს თქვენს პირად ანგარიშზე და ჩაწერს პროვაიდერთან მიბმას `once.toml`-ში. იხილეთ [პროექტის დაკავშირება](https://buildonce.dev/docs/guide/infrastructure/connect) სხვა ანგარიშის ან არსებული პროექტის არჩევისთვის.

არსებული Tuist პროექტისთვის, თავად დააკონფიგურირეთ პროვაიდერი და კეშთან მიბმა:

```toml
[infrastructures.tuist]
kind = "tuist"
account = "acme"
project = "app"
# url = "https://your-tuist-server.example.com"

[infrastructure.cache]
provider = "tuist"
```

შეცვალეთ `acme` და `app` თქვენი ანგარიშისა და პროექტის სახელებით, შემდეგ გაიარეთ ავტორიზაცია:

```bash
once auth login --provider tuist
```

დააკომიტეთ `once.toml`, რათა თქვენმა გუნდის წევრებმა და CI-მ გააზიარონ დანიშნულება, არა თქვენი სერთიფიკატები. ყოველი დეველოპერი ავტორიზდება საკუთარ მანქანაზე.

## გაზიარებული კეში

ლოკალური კეში ეხმარება მხოლოდ იმ მანქანას, რომელმაც ის შექმნა. Tuist-ის კონფიგურაციის შემდეგ, Once-ს შეუძლია აღადგინოს შესაბამისი შედეგები, რომლებიც სხვა დეველოპერმა ან CI-მ მიიღო, იმავე სამუშაოს ხელახლა შესრულების ნაცვლად.

გაუშვით თქვენი კეშირებადი სკრიპტი ან გრაფის მიზანი ჩვეულებრივად:

```bash
once build MyApplication
```

გახსენით **Once Cache** დაფაზე, რათა შეამოწმოთ დისტანციური კეშის აქტივობა. იხილეთ <.localized_link href="/guides/features/cache/once">Once cache</.localized_link> დაყენებისა და მანქანებს შორის ხელახალი გამოყენების შესამოწმებლად.

## აგების ანალიტიკა

Once ბეჭდავს დაფის ბმულს გაშვების დაწყებისას. გახსენით ის, რათა თვალყური ადევნოთ გრაფს, ქმედებების სტატუსსა და კეშის გადაწყვეტილებებს გაშვების მიმდინარეობისას. გამოიყენეთ **Builds** ლოკალური და CI შესრულების შესადარებლად და წარუმატებელი ქმედებების გამოსაკვლევად. შეინახეთ CI ლოგები პროცესის სრული გამონატანისთვის; ნედლი ქმედებების ლოგების შეტანა ამჟამად არ არის ხელმისაწვდომი.

იხილეთ <.localized_link href="/guides/features/build-insights/once">Once build insights</.localized_link> იმის გასაგებად, თუ რა ფიქსირდება და როგორ უნდა მიუწვდეთ მას კოდირების აგენტებიდან ან Grafana-დან.

## ტესტების ანალიტიკა და შარდინგი

გაუშვით თქვენი Once ტესტების მიზნები:

```bash
once test
```

გახსენით **Tests** მოხსენებული სუიტების, შემთხვევების, ხანგრძლივობებისა და შეცდომების შესამოწმებლად. შედეგები დამოკიდებულია ტესტის მიზნის მოხსენების შესაძლებლობებზე; ქმედება, რომელიც აწარმოებს ტესტის პროცესს, არ არის ავტომატურად თითოეული შემთხვევის ტესტის მოხსენება.

როდესაც სუიტი ერთ მანქანაზე ვეღარ ეტევა, შექმენით ჰოსტინგული შარდინგის გეგმა და გაანაწილეთ მისი პაკეტები CI მუშაკებზე. იხილეთ <.localized_link href="/guides/features/test-insights/once">Once test insights</.localized_link> და <.localized_link href="/guides/features/test-sharding/once">Once test sharding</.localized_link>.

## პრევიუები და ბანდლის ზომა

დაამატეთ არტიფაქტის მიბმა იმავე პროვაიდერთან, რათა გამოაქვეყნოთ მხარდაჭერილი Android, Apple სიმულატორისა და macOS აპლიკაციები:

```toml
[infrastructure.artifacts]
name = "tuist"
```

```bash
once artifact publish MyApplication --track review
```

მიღებული ბმული ხსნის თქვენი პროექტის პრევიუებს; დამუშავებას შეიძლება რამდენიმე წუთი დასჭირდეს. იხილეთ <.localized_link href="/guides/features/previews/once">Once previews</.localized_link> ხელმოწერის მოთხოვნებისა და აგების შემდეგ არჩევითი გამოქვეყნების შესახებ.

ბანდლის ზომის თვალყურის დევნებისთვის, ცალ-ცალკე გამოიყენეთ Tuist CLI აგებულ `.app`, `.ipa`, `.xcarchive`, `.apk` ან `.aab` ფაილზე. მიჰყევით <.localized_link href="/guides/features/bundle-insights">Apple ან Android ბანდლის ანალიტიკის სახელმძღვანელოს</.localized_link>; Once არტიფაქტის გამოქვეყნება ავტომატურად არ ტვირთავს ბანდლის ზომის მოხსენებას.

## უწყვეტი ინტეგრაცია

გამოიყენეთ ანგარიშის ტოკენი, რომელიც ავტორიზებულია პროექტის ოპერაციებისთვის `TUIST_TOKEN`-ში, ან გაიარეთ ავტორიზაცია მხარდაჭერილი CI პროვაიდერის OpenID Connect იდენტობის მეშვეობით:

```bash
once auth login --provider tuist --no-browser
once build MyApplication
once test
```

GitHub Actions-ზე, მიანიჭეთ ჯობს `id-token: write` და `contents: read`. მაგალითისთვის იხილეთ <.localized_link href="/guides/integrations/continuous-integration#once">Once უწყვეტ ინტეგრაციაზე</.localized_link>. პირადი დეველოპერის შესვლა არ არის CI სერთიფიკატი.

## დისტანციური შესრულება

ანგარიშებს, რომლებსაც ჩართული აქვთ დისტანციური შესრულება, ასევე შეუძლიათ შეასრულონ შესაბამისი გრაფის ბრძანებების ქმედებები Tuist-ის Linux მუშაკებზე. ეს განცალკევებულია კეშირებული შედეგების გაზიარებისა და მთლიანი CI სამუშაო ნაკადის გაშვებისგან. იხილეთ <.localized_link href="/guides/features/runners/once">Once remote execution</.localized_link> მუშაკის მოთხოვნებისა და დაყენების შესახებ.
