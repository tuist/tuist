# Xcode-ის პროექტი {#existing-xcode-project}

::: code-group

```text [Agent prompt]
Help me get started with Tuist. Follow the setup at:
```

მიჰყევით ამ გზას, თუ გსურთ შეინარჩუნოთ თქვენი `.xcodeproj` ან `.xcworkspace` უცვლელად და ჩართოთ Tuist-ის შესაძლებლობები პროექტის გენერაციის დანერგვის გარეშე. ქვემოთ მოცემული ყოველი სექცია იწყება იმის აღწერით, რაც დღეს აკლია, და შემდეგ გაგივლით ფუნქციას, რომელიც ამ ნაკლოვანებას აღმოფხვრის.

## წინაპირობები

- macOS **Xcode 26 ან უფრო ახალი ვერსიით** (კომპილაციის ქეში და თანამედროვე ინსაიტები მასზეა დამოკიდებული).
- <.localized_link href="/guides/install-tuist">Tuist-ის ბრძანების ხაზის ინტერფეისი</.localized_link>.

## დააკავშირეთ პროექტი

შეასრულეთ `tuist init` რეპოზიტორიის ძირში. როდესაც Tuist აღმოაჩენს თქვენს სამუშაო სივრცეს, აირჩიეთ **ინტეგრაცია `<YourApp>`**, შემდეგ გაიარეთ ავტორიზაცია ბრაუზერში და აირჩიეთ ანგარიში, რომელსაც უნდა ეკუთვნოდეს პროექტი. Tuist წერს `Tuist.swift` ძირში, რომელიც ამაგრებს პროექტის სახელს, რათა თქვენმა გუნდის წევრებმა და CI-მ გაიზიარონ ერთი და იგივე კავშირი. დააკომიტეთ ის.

თუ ამას კოდირების აგენტით ან სკრიპტით აკეთებთ, ჯერ შეასრულეთ `tuist auth login` (ბრაუზერის ნაკადი ელოდება Enter-ის დაჭერას), შემდეგ გამოიყენეთ არაინტერაქტიული ფორმა:

```bash
tuist init --build-system xcode --name <project-handle> --account <account>
```

ქვემოთ მოცემული ყველაფერი არის არასავალდებულო და დამოუკიდებელი.

## Xcode-ის კომპილაციის ქეში

Xcode 26 მოყვება ფაილის მიხედვით კომპილაციის ქეშით, მაგრამ მისი საცავი მანქანის `DerivedData` შიგნითაა განთავსებული. სუფთა ბილდი ავსებს მას ლოკალურად; გუნდის წევრები და CI გამშვებები თავიდან აწყობენ, რადგან ამ საცავს ვერ ხედავენ.

`tuist setup cache` მიმართავს Xcode-ის კომპილაციის ქეშს საერთო Tuist ქეშის ქსელისკენ. ნებისმიერ დეველოპერის მანქანაზე ან CI გაშვებაზე ქეშის მოხვედრა შემდეგ სარგებელს ანიჭებს ყველა სხვა მანქანას, რომელიც იგივე რევიზიას აწყობს.

```bash
tuist setup cache
```

ააწყეთ Xcode-ში. წაშალეთ Derived Data, ხელახლა ააწყეთ მეორე მანქანაზე ან CI გამშვებზე. მეორე ბილდი დროის მცირე ნაწილში სრულდება და Xcode-ის ბილდის ანგარიში აჩვენებს კომპილაციის ქეშის მოხვედრებს.

## ბილდის ინსაიტები

Xcode იწერს თითოეული ტარგეტის ბილდის ხანგრძლივობას ლოგში და ბილდის ანგარიშში. არცერთი მათგანი არ არის აგრეგირებული გაშვებებსა თუ მანქანებს შორის. ბილდის დროის რეგრესია, რომელიც ერთ PR-ში ხვდება, ჩვეულებრივ მხოლოდ როგორც ნელი CI საერთოდ ვლინდება, ყოველგვარი ცხადი სიგნალის გარეშე იმის შესახებ, თუ რომელმა ტარგეტმა გამოიწვია ის ან როდის.

ბილდის ინსაიტები იწერს ყოველი ბილდის ხანგრძლივობას და ფაზების დროს, რათა ტრენდი ხილული იყოს დაფაზე. ეს არის ერთხაზიანი პოსტ-მოქმედება თქვენს სქემაზე:

1. Xcode-ში: **Product → Scheme → Edit Scheme…**
2. გაშალეთ **Build → Post-actions**, დააჭირეთ **+**, აირჩიეთ **New Run Script Action**.
3. **Provide build settings from**-ის ქვეშ, აირჩიეთ თქვენი აპლიკაციის ტარგეტი.
4. ჩასვით ხაზი, რომელიც შეესაბამება Tuist-ის ინსტალაციის თქვენს გზას: ::: code-group
   ```bash [Mise]
   $HOME/.local/bin/mise x -C $SRCROOT -- tuist inspect build
   ```
   ```bash [Homebrew]
   tuist inspect build
   ```
   <!-- -->
   :::

   Xcode-ის სქემის სკრიპტები არ იღებენ მემკვიდრეობით თქვენი შელის `PATH`-ს, ამიტომ mise-ის shim თავისთავად არ იძებნება. ზემოთ მოცემული Mise ხაზი იძახებს mise-ს მისი აბსოლუტური გზით და სთხოვს მას კონფიგურაციის ჩატვირთვას `$SRCROOT`-დან, რათა აირჩიოს თქვენს პროექტში მიმაგრებული ვერსია.
5. ააწყეთ ერთხელ. ბილდი რამდენიმე წამში გამოჩნდება დაფის **Builds** ჩანართზე.

## ტესტების ინსაიტები

Xcode-ის ტესტის ლოგი ჩამოთვლის თითოეული ტესტის შედეგებს ერთი გაშვებით. ის არ აგრეგირებს ჯვარედინ გაშვების სიგნალს, რომელიც რეალურად გჭირდებათ: რამდენად ხშირად მარცხდება ტესტი, რამდენად შენელდა ის გასულ კვირაში, მარცხდება თუ არა ის მხოლოდ გარკვეულ სიმულატორებზე. ტესტი, რომელიც სანდოდან არასტაბილურისკენ გადაინაცვლებს ათი CI გაშვების განმავლობაში, იგივენაირად ჩანს, როგორც ერთი არასაიღბლო გაშვება.

ტესტების ინსაიტები იწერს ყოველი ტესტის შედეგს და ხანგრძლივობას და აკორელირებს შედეგებს გაშვებებს შორის. ნელი ტესტები, მარცხები და არასტაბილურობა ჩანს დაფის **Tests** ჩანართზე.

1. **Product → Scheme → Edit Scheme…**
2. **Test → Post-actions → +** → **New Run Script Action**.
3. **Provide build settings from** თქვენი აპლიკაციის ტარგეტი.
4. ჩასვით: ::: code-group
   ```bash [Mise]
   $HOME/.local/bin/mise x -C $SRCROOT -- tuist inspect test
   ```
   ```bash [Homebrew]
   tuist inspect test
   ```
   <!-- -->
   :::
5. შეასრულეთ ტესტის მოქმედება ერთხელ. შედეგები გამოჩნდება დაფის **Tests** ჩანართზე.

## ბანდლის ინსაიტები

IPA-ს ინსტალაციისა და ჩამოტვირთვის ზომა იცვლება ყოველი დამატებული ასეტით და ყოველი დაკავშირებული სიმბოლოთი. Xcode იტყობინება ზომებს მოთხოვნისას **Product → Show Archive**-ში, არა როგორც სერიას. PR, რომელიც დიდ ასეტს ამატებს, განურჩეველია ნებისმიერი სხვა PR-ისგან მერჯის რიგში.

ბანდლის ინსაიტები იწერს ინსტალაციისა და ჩამოტვირთვის ზომებს ყოველი ანალიზირებული ბილდისთვის და შეუძლია ჩააგდოს PR შემოწმება, როდესაც ტოტის ზღვარი ირღვევა. დაამატეთ ეს თქვენს CI-ში პირდაპირ ბილდის ნაბიჯის შემდეგ:

```bash
tuist inspect bundle App.ipa
```

გახსენით **Bundle insights** დაფაზე ტრენდის სანახავად და ზღვრების კონფიგურირებისთვის.

## პრივიუები

TestFlight ყოველ გაზიარებაზე ამატებს ბილდისა და მიმოხილვის წრიულ გზას. ხელმოწერილი `.ipa`-ის პირდაპირ გაგზავნა მოითხოვს მიმღების UDID-ს პროვიზინგის პროფილში. არცერთი არ არის მოსახერხებელი დიზაინერის ან QA-სთვის, ვისაც უბრალოდ სურს მიმდინარე ტოტის გამოცდა.

პრივიუები ბილდს აქცევს გაზიარებად ბმულად, რომელიც ერთი ბრძანებით ეშვება სიმულატორზე ან მოწყობილობაზე:

```bash
tuist xcodebuild build -scheme App -workspace App.xcworkspace -configuration Debug -sdk iphonesimulator
tuist share App
```

გაგზავნეთ ბმული. მიმღებები მას უშვებენ `tuist run <url>`-ით ან Tuist macOS აპით.

## ჩაერთეთ გუნდი

ქეში და ინსაიტები მრავლდება პროექტთან დაკავშირებული ადამიანების რაოდენობის ზრდასთან ერთად. მოიწვიეთ თქვენი გუნდის წევრები ორგანიზაციაში დაფის ანგარიშის პარამეტრებიდან და დააყენეთ <.localized_link href="/guides/integrations/authentication/sso">Single Sign-On</.localized_link> (Google, Okta, Microsoft), რათა დარეგისტრირება იყოს ერთი დაწკაპუნება და არა თითოეული პირისთვის `tuist auth login`.

## რა არის შემდეგი ნაბიჯი

თუ ამ გზას გადაიზრდებით, უდიდესი ნაბიჯი იქნება Tuist-ის მიერ გენერირებული პროექტები. ეს რეალური ცვლილებაა (მიზნები აღწერილია Swift მანიფესტებში `.xcodeproj`-ის ნაცვლად), მაგრამ სწორედ ის ხსნის მოდულის ქეშს და შერჩევით ტესტირებას. სრულად განხილულია <.localized_link href="/guides/get-started/generated-xcode-project">Generated Xcode project</.localized_link> სახელმძღვანელოში.
