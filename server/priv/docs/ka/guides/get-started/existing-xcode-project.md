# Xcode-ის პროექტი {#existing-xcode-project}

::: code-group

აირჩიეთ ეს გზა, თუ გსურთ შეინარჩუნოთ თქვენი `.xcodeproj` ან `.xcworkspace` უცვლელი და ჩართოთ Tuist-ის შესაძლებლობები პროექტის გენერაციის გარეშე. ქვემოთ მოცემული თითოეული განყოფილება იწყება იმის აღწერით, რაც დღეს არ გაქვთ, და შემდეგ გაჩვენებთ ფუნქციას, რომელიც ამ ხარვეზს ავსებს.

## წინაპირობები

- macOS **Xcode 26 ან უახლესი ვერსიით** (კომპილაციის ქეში და თანამედროვე ინსაიტები მასზეა დამოკიდებული).
- <.localized_link href="/guides/install-tuist">Tuist-ის ბრძანების სტრიქონის ინტერფეისი</.localized_link>.

## პროექტის მიერთება

გაუშვით `tuist init` რეპოზიტორიის ძირში. როდესაც Tuist აღმოაჩენს თქვენს სამუშაო სივრცეს, აირჩიეთ **Integrate `<YourApp>`**, შემდეგ გაიარეთ ავტორიზაცია ბრაუზერში და აირჩიეთ ის ანგარიში, რომელმაც უნდა ფლობდეს პროექტს. Tuist წერს `Tuist.swift` ძირში, რომელიც ამაგრებს პროექტის იდენტიფიკატორს, რათა თქვენმა კოლეგებმა და CI-მ ერთი და იგივე კავშირი გამოიყენონ. დააკომიტეთ ის.

თუ ამას მართავთ კოდირების აგენტის ან სკრიპტის საშუალებით, ჯერ გაუშვით `tuist auth login` (ბრაუზერის ნაკადი ელოდება Enter-ის დაჭერას), შემდეგ გამოიყენეთ არაინტერაქტიული ფორმა:

```bash
tuist init --build-system xcode --name <project-handle> --account <account>
```

ყველაფერი ქვემოთ არის არასავალდებულო და დამოუკიდებელი.

## Xcode-ის კომპილაციის ქეში

Xcode 26 მოყვება ფაილის დონის კომპილაციის ქეშით, მაგრამ მისი საცავი მდებარეობს მანქანის `DerivedData`-ში. სუფთა ბილდი ავსებს მას ლოკალურად; კოლეგები და CI გამშვებები თავიდან აწყობენ, რადგან ვერ ხედავენ ამ საცავს.

`tuist setup cache` მიმართავს Xcode-ის კომპილაციის ქეშს Tuist-ის საერთო ქეშის ქსელისკენ. ნებისმიერ დეველოპერის მანქანაზე ან CI გაშვებაზე ქეშის მოხვედრა (hit) შემდეგ აძლევს სარგებელს ყველა სხვა მანქანას, რომელიც იგივე რევიზიას აწყობს.

```bash
tuist setup cache
```

ააწყეთ Xcode-ში. წაშალეთ Derived Data, ხელახლა ააწყეთ მეორე მანქანაზე ან CI გამშვებზე. მეორე ბილდი დროის მცირე ნაწილში სრულდება და Xcode-ის ბილდის ანგარიში აჩვენებს კომპილაციის ქეშის მოხვედრებს.

## ბილდის ინსაიტები

Xcode იწერს თითოეული target-ის ბილდის ხანგრძლივობას ჟურნალში და ბილდის ანგარიშში. არცერთი არ არის აგრეგირებული გაშვებების ან მანქანების მიხედვით. ბილდის დროის რეგრესია, რომელიც ერთ PR-ში ხვდება, ჩვეულებრივ ვლინდება მხოლოდ როგორც ნელი CI საერთოდ, ცალსახა სიგნალის გარეშე იმის შესახებ, თუ რომელმა target-მა გამოიწვია ის ან როდის.

Build insights იწერს ყოველი ბილდის ხანგრძლივობას და ფაზების დროს, რათა ტრენდი ხილული იყოს დაფაზე. ეს არის ერთხაზიანი post-action თქვენს scheme-ზე:

1. Xcode-ში: **Product → Scheme → Edit Scheme…**
2. გაშალეთ **Build → Post-actions**, დააჭირეთ **+**, აირჩიეთ **New Run Script Action**.
3. **Provide build settings from**-ის ქვეშ, აირჩიეთ თქვენი აპლიკაციის target.
4. ჩასვით ხაზი, რომელიც შეესაბამება Tuist-ის ინსტალაციის მეთოდს: ::: code-group
   ```bash [Mise]
   $HOME/.local/bin/mise x -C $SRCROOT -- tuist inspect build
   ```
   ```bash [Homebrew]
   tuist inspect build
   ```
   <!-- -->
   :::

   Xcode-ის scheme სკრიპტები არ იღებენ მემკვიდრეობით თქვენი shell-ის `PATH`-ს, ამიტომ mise-ის shim თავისთავად არ იძებნება. ზემოთ მოცემული Mise-ის ხაზი იძახებს mise-ს აბსოლუტური გზით და სთხოვს მას კონფიგურაციის ჩატვირთვას `$SRCROOT`-დან, რათა აირჩიოს თქვენს პროექტში მიმაგრებული ვერსია.
5. ააწყეთ ერთხელ. ბილდი რამდენიმე წამში გამოჩნდება დაფის **Builds** ჩანართზე.

## ტესტების ინსაიტები

Xcode-ის ტესტის ჟურნალი ჩამოთვლის თითოეული ტესტის შედეგებს ერთი გაშვებით. ის არ აგრეგირებს cross-run სიგნალს, რომელიც რეალურად გჭირდებათ: რამდენად ხშირად მარცხდება ტესტი, რამდენად შენელდა ის გასულ კვირას, მარცხდება თუ არა მხოლოდ გარკვეულ სიმულატორებზე. ტესტი, რომელიც ათი CI გაშვების განმავლობაში სანდოობიდან flaky-მდე გადადის, ისევე გამოიყურება, როგორც ერთი არაიღბლიანი გაშვება.

Test insights იწერს ყოველი ტესტის შედეგს და ხანგრძლივობას და აკავშირებს შედეგებს გაშვებების მიხედვით. ნელი ტესტები, მარცხები და flaky ტესტები ჩანს დაფის **Tests** ჩანართზე.

1. **Product → Scheme → Edit Scheme…**
2. **Test → Post-actions → +** → **New Run Script Action**.
3. **Provide build settings from** თქვენი აპლიკაციის target.
4. ჩასვით: ::: code-group
   ```bash [Mise]
   $HOME/.local/bin/mise x -C $SRCROOT -- tuist inspect test
   ```
   ```bash [Homebrew]
   tuist inspect test
   ```
   <!-- -->
   :::
5. გაუშვით ტესტის მოქმედება ერთხელ. შედეგები გამოჩნდება დაფის **Tests** ჩანართზე.

## Bundle ინსაიტები

IPA-ს ინსტალაციისა და ჩამოტვირთვის ზომა იცვლება ყოველი დამატებული ასეტისა და დაკავშირებული სიმბოლოსთან ერთად. Xcode აჩვენებს ზომებს მოთხოვნისას **Product → Show Archive**-ში, არა როგორც სერიას. PR, რომელიც დიდ ასეტს ამატებს, განურჩევადია ნებისმიერი სხვა PR-ისგან merge რიგში.

Bundle insights იწერს ინსტალაციისა და ჩამოტვირთვის ზომებს ყოველი ანალიზირებული ბილდისთვის და შეუძლია ჩააგდოს PR-ის შემოწმება, როდესაც branch-ის ზღვარი გადაიჭრება. დაამატეთ ეს თქვენს CI-ში ბილდის ნაბიჯის შემდეგ:

```bash
tuist inspect bundle App.ipa
```

გახსენით **Bundle insights** დაფაზე ტრენდის სანახავად და ზღვრების კონფიგურირებისთვის.

## Previews

TestFlight ყოველ გაზიარებაზე ამატებს ბილდისა და გადახედვის ციკლს. ხელმოწერილი `.ipa`-ის პირდაპირი გაგზავნა მოითხოვს მიმღების UDID-ს provisioning პროფილში. არცერთი არ არის მოსახერხებელი დიზაინერის ან QA-სთვის, ვისაც უბრალოდ სურს მიმდინარე branch-ის გამოცდა.

Previews ბილდს აქცევს გაზიარებად ბმულად, რომელიც ერთი ბრძანებით გაეშვება სიმულატორზე ან მოწყობილობაზე:

```bash
tuist xcodebuild build -scheme App -workspace App.xcworkspace -configuration Debug -sdk iphonesimulator
tuist share App
```

გაგზავნეთ ბმული. მიმღებები გაუშვებენ მას `tuist run <url>`-ით ან Tuist macOS აპლიკაციით.

## გუნდის ჩართვა

ქეში და ინსაიტები მრავლდება პროექტთან დაკავშირებული ადამიანების რაოდენობის ზრდასთან ერთად. მიიწვიეთ თქვენი გუნდის წევრები ორგანიზაციაში დაფის ანგარიშის პარამეტრებიდან და დააყენეთ <.localized_link href="/guides/integrations/authentication/sso">Single Sign-On</.localized_link> (Google, Okta, Microsoft), რათა დარეგისტრება იყოს ერთი დაჭერა და არა თითოეული ადამიანისთვის `tuist auth login`.

## რა არის შემდეგი ნაბიჯი

თუ ამ გზას გადაიზრდებით, უდიდესი ნაბიჯი არის Tuist-ით გენერირებული პროექტები. ეს არის რეალური ცვლილება (მიზნები აღწერილია Swift მანიფესტებში `.xcodeproj`-ის ნაცვლად), მაგრამ სწორედ ის ხსნის მოდულის ქეშს და შერჩევით ტესტირებას. სრულად განხილულია <.localized_link href="/guides/get-started/generated-xcode-project">Generated Xcode project</.localized_link> სახელმძღვანელოში.
