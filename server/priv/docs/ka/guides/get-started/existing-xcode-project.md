მიჰყევით ამ გზას, თუ გსურთ შეინარჩუნოთ თქვენი `.xcodeproj` ან `.xcworkspace` ზუსტად ისეთი, როგორიც არის, და ჩართოთ Tuist-ის შესაძლებლობები პროექტის გენერაციის დანერგვის გარეშე. ქვემოთ მოცემული ყოველი განყოფილება იწყება იმის აღწერით, რაც დღეს აკლია, და შემდეგ გაგივლით ფუნქციას, რომელიც ამ ნაკლს ავსებს.

## წინაპირობები

- macOS **Xcode 26 ან უფრო ახალი ვერსიით** (კომპილაციის ქეში და თანამედროვე ინსაიტები მასზეა დამოკიდებული).
- <.localized_link href="/guides/install-tuist">Tuist ბრძანების ხაზის ინტერფეისი</.localized_link>.

## პროექტის მიერთება

გაუშვით `tuist init` რეპოზიტორიის ძირში. როდესაც Tuist აღმოაჩენს თქვენს სამუშაო სივრცეს, აირჩიეთ **Integrate `<YourApp>`**, შემდეგ გაიარეთ ავტორიზაცია ბრაუზერში და აირჩიეთ ანგარიში, რომელმაც უნდა ფლობდეს პროექტს. Tuist წერს `Tuist.swift` ძირში, რომელიც ამაგრებს პროექტის სახელს, რათა თქვენმა თანაგუნდელებმა და CI-მ გაიზიარონ ერთი და იგივე კავშირი. დააკომიტეთ ის.

თუ ამას კოდირების აგენტით ან სკრიპტით აკეთებთ, ჯერ გაუშვით `tuist auth login` (ბრაუზერის ნაკადი ელოდება Enter-ის დაჭერას), შემდეგ გამოიყენეთ არაინტერაქტიული ფორმა:

```bash
tuist init --build-system xcode --name <project-handle> --account <account>
```

ყველაფერი ქვემოთ არის სურვილისამებრ და დამოუკიდებელი.

## Xcode კომპილაციის ქეში

Xcode 26 მოყვება ფაილების მიხედვით კომპილაციის ქეშით, მაგრამ მისი საცავი მანქანის `DerivedData` შიგნით არის. სუფთა აგება ავსებს მას ლოკალურად; თანაგუნდელები და CI გამშვებები თავიდან აგებენ, რადგან ვერ ხედავენ ამ საცავს.

`tuist setup cache` მიმართავს Xcode-ის კომპილაციის ქეშს გაზიარებულ Tuist ქეშის ქსელზე. ნებისმიერ დეველოპერის მანქანაზე ან CI გაშვებაზე მოხვედრა შემდეგ სარგებელს ანიჭებს ყველა სხვა მანქანას, რომელიც იმავე რევიზიას აგებს.

```bash
tuist setup cache
```

ააგეთ Xcode-ში. წაშალეთ Derived Data, ხელახლა ააგეთ მეორე მანქანაზე ან CI გამშვებზე. მეორე აგება დროის ნაწილში სრულდება და Xcode-ის აგების ანგარიში აჩვენებს კომპილაციის ქეშის მოხვედრებს.

## აგების ინსაიტები

Xcode იწერს თითოეული მიზნის აგების ხანგრძლივობას ჟურნალში და აგების ანგარიშში. არცერთი არ არის აგრეგირებული გაშვებებსა თუ მანქანებს შორის. აგების დროის რეგრესია, რომელიც ერთ PR-ში ხვდება, ჩვეულებრივ ჩანს მხოლოდ როგორც ნელი CI საერთოდ, ყოველგვარი ცხადი სიგნალის გარეშე იმის შესახებ, თუ რომელმა მიზანმა გამოიწვია ის ან როდის.

Build insights იწერს ყოველი აგების ხანგრძლივობას და ფაზების დროს, რათა ტენდენცია ხილული იყოს დაშბორდზე. ეს არის ერთხაზიანი post-action თქვენს სქემაზე:

1. Xcode-ში: **Product → Scheme → Edit Scheme…**
2. გაშალეთ **Build → Post-actions**, დააჭირეთ **+**, აირჩიეთ **New Run Script Action**.
3. **Provide build settings from**-ის ქვეშ, აირჩიეთ თქვენი აპის მიზანი.
4. ჩასვით ხაზი, რომელიც შეესაბამება Tuist-ის ინსტალაციის თქვენს გზას: ::: code-group
   ```bash [Mise]
   $HOME/.local/bin/mise x -C $SRCROOT -- tuist inspect build
   ```
   ```bash [Homebrew]
   tuist inspect build
   ```
   <!-- -->
   :::

   Xcode-ის სქემის სკრიპტები არ იღებენ თქვენი shell-ის `PATH`-ს, ამიტომ mise-ის shim თავისთავად არ იძებნება. ზემოთ მოცემული Mise ხაზი იძახებს mise-ს მისი აბსოლუტური გზით და სთხოვს მას კონფიგურაციის ჩატვირთვას `$SRCROOT`-დან, რათა აირჩიოს თქვენს პროექტში მიმაგრებული ვერსია.
5. ააგეთ ერთხელ. აგება რამდენიმე წამში ჩანს დაშბორდის **Builds** ჩანართზე.

## ტესტების ინსაიტები

Xcode-ის ტესტის ჟურნალი ჩამოთვლის თითოეული ტესტის შედეგებს ერთი გაშვებით. ის არ აგრეგირებს გაშვებათაშორის სიგნალს, რომელიც რეალურად გჭირდებათ: რამდენად ხშირად მარცხდება ტესტი, რამდენად გახდა უფრო ნელი გასულ კვირაში, მარცხდება თუ არა ის მხოლოდ გარკვეულ სიმულატორებზე. ტესტი, რომელიც ათი CI გაშვების განმავლობაში სანდოობიდან არასტაბილურობისკენ გადაიხრება, ისევე ჩანს, როგორც ერთი არაიღბლიანი გაშვება.

Test insights იწერს ყოველი ტესტის შედეგს და ხანგრძლივობას და აკორელირებს შედეგებს გაშვებებს შორის. ნელი ტესტები, მარცხები და არასტაბილურობები ჩანს დაშბორდის **Tests** ჩანართზე.

1. **Product → Scheme → Edit Scheme…**
2. **Test → Post-actions → +** → **New Run Script Action**.
3. **Provide build settings from** თქვენი აპის მიზანი.
4. ჩასვით: ::: code-group
   ```bash [Mise]
   $HOME/.local/bin/mise x -C $SRCROOT -- tuist inspect test
   ```
   ```bash [Homebrew]
   tuist inspect test
   ```
   <!-- -->
   :::
5. გაუშვით ტესტის მოქმედება ერთხელ. შედეგები ჩანს დაშბორდის **Tests** ჩანართზე.

## Bundle ინსაიტები

IPA-ს ინსტალაციისა და ჩამოტვირთვის ზომა იცვლება ყოველი დამატებული აქტივით და ყოველი დაკავშირებული სიმბოლოთი. Xcode აჩვენებს ზომებს მოთხოვნისას **Product → Show Archive**-ში, არა როგორც სერიას. PR, რომელიც დიდ აქტივს ამატებს, განურჩეველია ნებისმიერი სხვა PR-ისგან merge რიგში.

Bundle insights იწერს ინსტალაციისა და ჩამოტვირთვის ზომებს ყოველი ანალიზირებული აგებისთვის და შეუძლია ჩააგდოს PR შემოწმება, როდესაც ბრენჩის ზღვარი ირღვევა. დაამატეთ ეს თქვენს CI-ში პირდაპირ აგების ნაბიჯის შემდეგ:

```bash
tuist inspect bundle App.ipa
```

გახსენით **Bundle insights** დაშბორდზე, რათა ნახოთ ტენდენცია და დააკონფიგურიროთ ზღვრები.

## Previews

TestFlight ყოველ გაზიარებაზე ამატებს აგება-და-შემოწმების სრულ ციკლს. ხელმოწერილი `.ipa` პირდაპირ გაგზავნა მოითხოვს მიმღების UDID-ს პროვიზიონირების პროფილში. არცერთი არ არის მოსახერხებელი დიზაინერისთვის ან QA-სთვის, ვისაც უბრალოდ სურს მიმდინარე ბრენჩის გამოცდა.

Previews აქცევს აგებას გაზიარებად ბმულად, რომელიც იმუშავებს სიმულატორზე ან მოწყობილობაზე ერთი ბრძანებით:

```bash
tuist xcodebuild build -scheme App -workspace App.xcworkspace -configuration Debug -sdk iphonesimulator
tuist share App
```

გაგზავნეთ ბმული. მიმღებები გაუშვებენ მას `tuist run <url>`-ით ან Tuist macOS აპით.

## ჩართეთ გუნდი

ქეში და ინსაიტები მრავლდება პროექტთან დაკავშირებული ადამიანების რაოდენობის ზრდასთან ერთად. მიიწვიეთ თქვენი გუნდის წევრები ორგანიზაციაში დაშბორდის ანგარიშის პარამეტრებიდან და მოაწყვეთ <.localized_link href="/guides/integrations/authentication/sso">Single Sign-On</.localized_link> (Google, Okta, Microsoft), რათა დარეგისტრება იყოს ერთი დაწკაპუნება და არა თითოეული პირისთვის `tuist auth login`.

## რა არის შემდეგი ნაბიჯი

თუ ამ გზას გადაიზრდებით, უდიდესი ნაბიჯი იქნება Tuist-ით გენერირებული პროექტები. ეს რეალური ცვლილებაა (მიზნები აღწერილია Swift მანიფესტებში `.xcodeproj`-ის ნაცვლად), მაგრამ სწორედ ეს ხსნის მოდულის ქეშს და შერჩევით ტესტირებას. სრულად განხილულია <.localized_link href="/guides/get-started/generated-xcode-project">Generated Xcode project</.localized_link> სახელმძღვანელოში.
