# Xcode-ის პროექტი {#existing-xcode-project}

::: code-group

```text [Agent prompt]
Help me get started with Tuist. Follow the setup at:
```

მიმართეთ ამ გზას, თუ გსურთ შეინარჩუნოთ თქვენი `.xcodeproj` ან `.xcworkspace` უცვლელი და ჩართოთ Tuist-ის შესაძლებლობები პროექტის გენერაციის მიღების გარეშე. ქვემოთ მოცემული თითოეული განყოფილება იწყება იმის აღწერით, რაც დღეს აკლია, შემდეგ კი გაგივლით ფუნქციას, რომელიც ამ ნაკლოვანებას აღმოფხვრის.

## წინაპირობები

- macOS **Xcode 26 ან უფრო ახალი ვერსიით** (კომპილაციის ქეში და თანამედროვე ინსაიტები მასზეა დამოკიდებული).
- <.localized_link href="/guides/install-tuist">Tuist-ის ბრძანების სტრიქონის ინტერფეისი</.localized_link>.

## დააკავშირეთ პროექტი

გაუშვით `tuist init` რეპოზიტორიის ძირში. როდესაც Tuist აღმოაჩენს თქვენს სამუშაო სივრცეს, აირჩიეთ **Integrate `<YourApp>`**, შემდეგ გაიარეთ ავთენტიკაცია ბრაუზერში და აირჩიეთ ანგარიში, რომელსაც უნდა ეკუთვნოდეს პროექტი. Tuist წერს `Tuist.swift` ფაილს ძირში, რომელიც ამაგრებს პროექტის სახელს, რათა თქვენმა თანაგუნდელებმა და CI-მ გაიზიარონ ერთი და იგივე კავშირი. დააკომიტეთ ის.

თუ ამას კოდირების აგენტით ან სკრიპტით აკეთებთ, ჯერ გაუშვით `tuist auth login` (ბრაუზერის ნაკადი ელოდება Enter-ის დაჭერას), შემდეგ გამოიყენეთ არაინტერაქტიული ფორმა:

```bash
tuist init --build-system xcode --name <project-handle> --account <account>
```

ქვემოთ მოცემული ყველაფერი არის არასავალდებულო და დამოუკიდებელი.

## Xcode-ის კომპილაციის ქეში

Xcode 26 მოდის ფაილის მიხედვით კომპილაციის ქეშით, მაგრამ მისი საცავი მდებარეობს მანქანის `DerivedData` საქაღალდეში. სუფთა ბილდი ავსებს მას ლოკალურად; თანაგუნდელები და CI გამშვებები თავიდან აწყობენ, რადგან ვერ ხედავენ ამ საცავს.

`tuist setup cache` მიმართავს Xcode-ის კომპილაციის ქეშს Tuist-ის საერთო ქეშის ქსელისკენ. ნებისმიერ დეველოპერის მანქანაზე ან CI გაშვებაზე ქეშის მოხვედრა შემდეგ აძლევს სარგებელს ყველა სხვა მანქანას, რომელიც იმავე რევიზიას აწყობს.

```bash
tuist setup cache
```

ბრძანება ბეჭდავს ბილდის პარამეტრებს, რომლებიც Xcode-ს სჭირდება საერთო ქეშის გამოსაყენებლად. ის არ არედაქტირებს თქვენს პროექტს, ამიტომ დაამატეთ ისინი თქვენი პროექტის ბილდის პარამეტრებში ან `.xcconfig` ფაილში, როგორც ეს აღწერილია <.localized_link href="/guides/features/cache/xcode-cache#configure-xcode-build-settings">Xcode-ის ბილდის პარამეტრების კონფიგურაცია</.localized_link>-ში.

ააწყეთ Xcode-ში, შემდეგ ააწყეთ იგივე რევიზია მეორე მანქანაზე ან CI გამშვებზე. მეორე ბილდი სრულდება დროის მცირე ნაწილში და Xcode-ის ბილდის ანგარიში აჩვენებს კომპილაციის ქეშის მოხვედრებს.

## ბილდის ინსაიტები

Xcode იწერს თითოეული ტარგეტის ბილდის ხანგრძლივობას ლოგში და ბილდის ანგარიშში. არცერთი არ არის აგრეგირებული გაშვებების ან მანქანების მიხედვით. ბილდის დროის რეგრესია, რომელიც ერთ PR-ში ხვდება, ჩვეულებრივ ჩანს მხოლოდ როგორც ნელი CI საერთოდ, ყოველგვარი აშკარა სიგნალის გარეშე იმის შესახებ, თუ რომელმა ტარგეტმა გამოიწვია ის ან როდის.

ბილდის ინსაიტები იწერს ყოველი ბილდის ხანგრძლივობას და ფაზების დროს, რათა ტენდენცია ხილული იყოს დაფაზე. ეს არის ერთხაზიანი post-action თქვენს სქემაზე:

1. Xcode-ში: **Product → Scheme → Edit Scheme…**
2. გაშალეთ **Build → Post-actions**, დააჭირეთ **+**, აირჩიეთ **New Run Script Action**.
3. **Provide build settings from**-ის ქვეშ, აირჩიეთ თქვენი აპლიკაციის ტარგეტი.
4. ჩასვით ხაზი, რომელიც შეესაბამება Tuist-ის ინსტალაციის მეთოდს: ::: code-group
   ```bash [Mise]
   $HOME/.local/bin/mise x -C $SRCROOT -- tuist inspect build
   ```
   ```bash [Homebrew]
   tuist inspect build
   ```
   <!-- -->
   :::

   Xcode-ის სქემის სკრიპტები არ იღებენ მემკვიდრეობით თქვენი shell-ის `PATH`-ს, ამიტომ mise-ის shim არ მოიძებნება თავისთავად. ზემოთ მოცემული Mise-ის ხაზი იძახებს mise-ს მისი აბსოლუტური გზით და სთხოვს მას კონფიგურაციის ჩატვირთვას `$SRCROOT`-დან, რათა აირჩიოს თქვენს პროექტში მიმაგრებული ვერსია.
5. ააწყეთ ერთხელ. ბილდი გამოჩნდება დაფის **Builds** ჩანართზე რამდენიმე წამში.

## ტესტების ინსაიტები

Xcode-ის ტესტის ლოგი ჩამოთვლის თითოეული ტესტის შედეგებს ერთი გაშვებით ერთდროულად. ის არ აგრეგირებს გაშვებებს შორის სიგნალს, რომელიც რეალურად გჭირდებათ: რამდენად ხშირად მარცხდება ტესტი, რამდენად შენელდა ის გასულ კვირას, მარცხდება თუ არა ის მხოლოდ გარკვეულ სიმულატორებზე. ტესტი, რომელიც ათი CI გაშვების განმავლობაში სანდოდან არასტაბილურად გადადის, იგივენაირად ჩანს, როგორც ერთი არაიღბლიანი გაშვება.

ტესტების ინსაიტები იწერს ყოველი ტესტის შედეგს და ხანგრძლივობას და აკორელირებს შედეგებს გაშვებებს შორის. ნელი ტესტები, მარცხები და არასტაბილურობა ჩანს დაფის **Tests** ჩანართზე.

1. **Product → Scheme → Edit Scheme…**
2. **Test → Post-actions → +** → **New Run Script Action**.
3. **Provide build settings from** თქვენი აპლიკაციის ტარგეტი.
4. ჩასვით: ::: code-group
   ```bash [Mise]
   $HOME/.local/bin/mise x -C $SRCROOT -- tuist inspect test
   ```
   ```bash [Homebrew]
   tuist inspect test
   ```
   <!-- -->
   :::
5. გაუშვით ტესტის action ერთხელ. შედეგები გამოჩნდება დაფის **Tests** ჩანართზე.

## Bundle-ის ინსაიტები

IPA-ს ინსტალაციისა და ჩამოტვირთვის ზომა იცვლება ყოველი დამატებული ასეტისა და დაკავშირებული სიმბოლოსთან ერთად. Xcode აჩვენებს ზომებს მოთხოვნისას **Product → Show Archive**-ში, არა როგორც სერიას. PR, რომელიც დიდ ასეტს ამატებს, განურჩეველია ნებისმიერი სხვა PR-ისგან merge-ის რიგში.

Bundle-ის ინსაიტები იწერს ინსტალაციისა და ჩამოტვირთვის ზომებს ყოველი ანალიზირებული ბილდისთვის და შეუძლია ჩააგდოს PR-ის შემოწმება, როდესაც ბრენჩის მიხედვით ზღვარი გადაიჭრება. დაამატეთ ეს თქვენს CI-ში ბილდის ნაბიჯის შემდეგ:

```bash
tuist inspect bundle App.ipa
```

გახსენით **Bundle insights** დაფაზე ტენდენციის სანახავად და ზღვრების კონფიგურირებისთვის.

## Previews

TestFlight ყოველ გაზიარებაზე ამატებს ბილდისა და გადახედვის ციკლს. ხელმოწერილი `.ipa`-ის პირდაპირ გაგზავნა მოითხოვს მიმღების UDID-ს პროვიზიონირების პროფილში. არცერთი არ არის მოსახერხებელი დიზაინერის ან QA-სთვის, ვისაც უბრალოდ სურს სცადოს მიმდინარე ბრენჩი.

Previews ბილდს აქცევს გაზიარებად ბმულად, რომელიც იწყება სიმულატორზე ან მოწყობილობაზე ერთი ბრძანებით:

```bash
tuist xcodebuild build -scheme App -workspace App.xcworkspace -configuration Debug -sdk iphonesimulator
tuist share App
```

გაგზავნეთ ბმული. მიმღებები გაუშვებენ მას `tuist run <url>`-ით ან Tuist macOS აპლიკაციით.

## ჩართეთ გუნდი

ქეში და ინსაიტები მრავლდება პროექტთან დაკავშირებული ადამიანების რაოდენობის ზრდასთან ერთად. მიიწვიეთ თქვენი თანაგუნდელები ორგანიზაციაში დაფის ანგარიშის პარამეტრებიდან და მოაწყვეთ <.localized_link href="/guides/integrations/authentication/sso">Single Sign-On</.localized_link> (Google, Okta, Microsoft), რომ დარეგისტრება იყოს ერთი დაწკაპუნება და არა ცალ-ცალკე `tuist auth login`.

## რა არის შემდეგი ნაბიჯი

თუ ამ გზას გადაიზრდებით, უმთავრესი ნაბიჯი არის Tuist-ით გენერირებული პროექტები. ეს ნამდვილი ცვლილებაა (მიზნები აღწერილია Swift მანიფესტებში `.xcodeproj`-ის ნაცვლად), მაგრამ სწორედ ის ხსნის მოდულის ქეშს და შერჩევით ტესტირებას. სრულად განხილულია <.localized_link href="/guides/get-started/generated-xcode-project">Generated Xcode project</.localized_link> სახელმძღვანელოში.
