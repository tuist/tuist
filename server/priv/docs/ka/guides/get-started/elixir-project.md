# Elixir-ის პროექტი {#elixir-project}

::: code-group

```text [Agent prompt]
Help me get started with Tuist. Follow the setup at:
https://tuist.dev/en/docs/guides/get-started/elixir-project
```

:::

ერთხელ დააყენეთ Tuist, შემდეგ კი განაგრძეთ `mix compile`-ისა და `mix test`-ის გამოყენება. `tuist_ex` Hex-პაკეტი აქვეშებს მხარდაჭერილ დამოკიდებულებებს და თქვენს დაფაზე აგზავნის ბილდებისა და ტესტების გაშვების შესახებ ინფორმაციას.

## წინაპირობები

- Elixir-ის პროექტი, აგებული Mix-ით, Elixir 1.18 ან უფრო ახალ ვერსიაზე.
- Tuist-ის ანგარიში.

## Tuist-ის დაყენება {#set-up-tuist}

შექმენით პროექტი Tuist-ის დაფაზე და აირჩიეთ **Mix (Elixir)** როგორც მისი ბილდის სისტემა. დაამატეთ პაკეტი დამოკიდებულებებში თქვენს `mix.exs` ფაილში:

```elixir
defp deps do
  [
    {:tuist_ex, "~> 0.3", runtime: false}
  ]
end
```

ჩამოტვირთეთ ის, დააკონფიგურირეთ თქვენი პროექტი და შედით სისტემაში:

```bash
mix deps.get
mix tuist.setup --project account/project
mix tuist.login
```

დაყენება აახლებს `mix.exs`-ს თქვენი პროექტის იდენტიფიკატორით, რთავს დამოკიდებულებების ქეშირებას და აყენებს კომპილაციისა და ტესტირების ალიასებს. ის ინარჩუნებს სხვა პარამეტრებს და სტანდარტულ სატესტო მომზადებას, მაგალითად, Phoenix-ის მონაცემთა ბაზის კონფიგურაციას. თუ უსაფრთხოდ ვერ აინტეგრირებს მორგებულ ალიასს, ის ჩერდება ფაილის შეცვლის გარეშე.

შეინახეთ განახლებული `mix.exs` Git-ში, რათა თქვენმა გუნდმა და CI-მ ერთი და იგივე კონფიგურაცია გამოიყენონ. არ არის საჭირო სკრიპტების ან შეფასების კოდის კოპირება. შესვლა ხსნის ბრაუზერს; headless შესვლისა და CI-სთვის საჭირო სერთიფიკატების შესახებ იხილეთ <.localized_link href="/guides/install-hex-package#authenticate">აუთენტიკაცია</.localized_link>.

ახლა გაუშვით თქვენი ჩვეული ბრძანებები:

```bash
mix compile
mix test
```

ბილდები ჩანს **ბილდები** განყოფილებაში, ტესტების გაშვებები — **ტესტები**-ში, ხოლო დამოკიდებულებების ქეშის აქტივობა — **Mix cache**-ში. ეს არის საერთო კონფიგურაცია სამივესთვის. არასტაბილური ტესტების აღმოჩენა იყენებს მოხსენებულ გაშვებებს; ხელახლა ცდები და CI-ში შარდინგი არის არასავალდებულო.

## დამოკიდებულებების ქეშირება

Tuist ავტომატურად ირჩევს მხარდაჭერილ Hex და Git დამოკიდებულებებს, დამოკიდებულებების სიის გარეშე. ქეშში არყოფნის შემთხვევაში კომპილაცია ჩვეულებრივად მიმდინარეობს და შედეგი ინახება; ქეშში ყოფნის შემთხვევაში ის აღდგება. ნატიური/მორგებული კომპილაცია და ლოკალური დამოკიდებულებები რჩება Mix-თან.

კომპილაცია უნდა იყოს აღწარმოებადი: განაცხადეთ დამატებითი კომპილაციის დროის შეყვანები და გამორიცხეთ დამოკიდებულებები, რომლებსაც აქვთ მოუნიმოდებელი შეყვანები ან საჭირო გვერდითი ეფექტები. მხარდაჭერილი შეყვანების, ქეშის ვერიფიკაციისა და მორგების შესახებ იხილეთ <.localized_link href="/guides/features/cache/elixir">Elixir cache</.localized_link>.

## ბილდის ანალიტიკა

ბილდის დრო, თქვენს ფაილებს შორის დამოკიდებულების გრაფი და მათი ცვლილება დროთა განმავლობაში გაძლევთ იმას, რაც საჭიროა ბილდის გრაფის ოპტიმიზაციისთვის და კომპილაციის გარემოში ხელმისაწვდომი ყველა ბირთვის მაქსიმალურად გამოყენებისთვის.

`compile` ალიასის არსებობისას, Tuist აგზავნის თითოეული ბილდის შესახებ ინფორმაციას: რამდენ ხანს გაგრძელდა, მისი გაფრთხილებები და შეცდომები, რამდენ ხანს მიმდინარეობდა თითოეული ფაილის კომპილაცია და რა ფაილებზეა ის დამოკიდებული. თქვენი შემდეგი `mix compile`-ის შემდეგ გახსენით დაფაზე **ბილდები**, რათა ნახოთ ის.

## ტესტების ანალიტიკა

Tuist იწერს თითოეული ტესტის შედეგსა და ხანგრძლივობას ყოველ `mix test` გაშვებაზე, რათა ნახოთ, როგორ იცვლება თქვენი ტესტების ნაკრები დროთა განმავლობაში, იპოვოთ ნელი ან უფრო ნელი გახდომილი ტესტები და გაიგოთ, რატომ ჩავარდა გაშვება CI-ში. მათ ნახავთ დაფაზე **ტესტები** განყოფილებაში, მოდულის, `describe` ბლოკისა და ტესტის დონეზე.

## არასტაბილური ტესტები

არასტაბილური ტესტი ერთი და იგივე კოდით ზოგჯერ წარმატებით სრულდება, ზოგჯერ კი ვარდება. Tuist ტესტს არასტაბილურად მონიშნავს, როცა ის ერთსა და იმავე კომიტზე CI-ში ჯერ ჩავარდა, შემდეგ კი წარმატებით შესრულდა. ასევე შეგიძლიათ აიძულოთ პაკეტს ხელახლა სცადოს ჩავარდნილი ტესტები, რაც მათ ერთ გაშვებაში აღმოაჩენს:

```elixir
tuist: [project: "account/project", cache: true, test_retries: 2]
```

ტესტი, რომელიც ხელახლა ცდაზე წარმატებით სრულდება, მოხსენებულია როგორც არასტაბილური და გაშვება წარმატებით სრულდება. **არასტაბილური ტესტები** გვერდი ჩამოთვლის მათ.

## ტესტების შარდინგი

ტესტების შარდინგი ანაწილებს თქვენს ტესტების ნაკრებს CI-ის გამშვებებზე. Tuist აბალანსებს შარდებს იმის მიხედვით, თუ რამდენ ხანს გაგრძელდა თითოეული სატესტო ფაილის შესრულება წინა გაშვებებში, და კომპილირებს პროექტს ერთხელ და უზიარებს ამ ბილდს ყველა გამშვებს. ერთი ბრძანება გეგმავს შარდებს:

```bash
mix tuist.test.build --shard-max 4
```

შემდეგ თითოეული გამშვები ასრულებს თავის წილს `TUIST_SHARD_INDEX`-ის მითითებით, და შედეგები დაფაზე მოდის როგორც ერთიანი ტესტების გაშვება:

```bash
TUIST_SHARD_INDEX=0 mix test
```

## ჩართეთ გუნდი

ანალიტიკის სარგებელი იზრდება პროექტთან დაკავშირებული ადამიანების რაოდენობის ზრდასთან ერთად. მიიწვიეთ თქვენი გუნდის წევრები ორგანიზაციაში დაფის ანგარიშის პარამეტრებიდან და დააყენეთ <.localized_link href="/guides/integrations/authentication/sso">ერთჯერადი შესვლა</.localized_link> (Google, Okta, Microsoft), რათა ახალი წევრების დამატება იყოს ერთი დაწკაპუნება და არა თითოეული ადამიანისთვის `mix tuist.login`-ის შესრულება.

CI-სთვის არ გამოიყენოთ პირადი შესვლა. GitHub Actions, CircleCI და Bitrise შეუძლიათ აუთენტიკაცია OpenID Connect-ის მეშვეობით; სხვა პროვაიდერებზე დააყენეთ შეზღუდული `TUIST_TOKEN`. მიჰყევით <.localized_link href="/guides/install-hex-package#authenticate">CI აუთენტიკაციის ნაბიჯებს</.localized_link>.
