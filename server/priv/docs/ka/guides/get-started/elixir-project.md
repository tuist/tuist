# Elixir-პროექტი {#elixir-project}

::: code-group

```text [Agent prompt]
Help me get started with Tuist. Follow the setup at:
https://tuist.dev/en/docs/guides/get-started/elixir-project
```

:::

ერთხელ დააყენეთ Tuist, შემდეგ კი განაგრძეთ `mix compile` და `mix test` გამოყენება. `tuist_ex` Hex-პაკეტი აქეშებს მხარდაჭერილ დამოკიდებულებებს და თქვენს დაფაზე აგზავნის ბილდებისა და ტესტების გაშვების შესახებ ინფორმაციას.

## წინაპირობები

- Elixir-პროექტი, აგებული Mix-ით, Elixir 1.18 ან უფრო გვიანვე ვერსიაზე.
- Tuist-ის ანგარიში.

## Tuist-ის დაყენება {#set-up-tuist}

შექმენით პროექტი Tuist-ის დაფაზე და აირჩიეთ **Mix (Elixir)** როგორც მისი ბილდ-სისტემა. დაამატეთ პაკეტი თქვენი `mix.exs` დამოკიდებულებებში:

<!-- @snippet: ../_tuist-ex-dependency -->

ჩამოტვირთეთ ის, დააკონფიგურირეთ თქვენი პროექტი და შედით სისტემაში:

```bash
mix deps.get
mix tuist.setup --project account/project
mix tuist.login
```

დაყენება ამოწმებს `mix.exs` თქვენი პროექტის სახელით, რთავს დამოკიდებულობების ქეშირებას და აყენებს compile და test ალიასებს. ის ინარჩუნებს სხვა პარამეტრებსა და სტანდარტულ ტესტების მომზადებას, მაგალითად, Phoenix-ის მონაცემთა ბაზის კონფიგურაციას. თუ უსაფრთხოდ ვერ აინტეგრირებს მორგებულ ალიასს, ის ჩერდება ფაილის შეცვლის გარეშე.

შეინახეთ განახლებული `mix.exs`, რათა თქვენმა გუნდმა და CI-მ ერთი და იგივე კონფიგურაცია გამოიყენონ. არ არის საჭირო სკრიპტების ან შეფასების კოდის კოპირება. შესვლა ხსნის ბრაუზერს; headless შესვლისა და CI-სთვის საჭირო მონაცემებისთვის იხილეთ <.localized_link href="/guides/install-hex-package#authenticate">აუთენტიკაცია</.localized_link>.

ახლა გაუშვით თქვენი ჩვეულებრივი ბრძანებები:

```bash
mix compile
mix test
```

ბილდები ჩანს **Builds** განყოფილებაში, ტესტების გაშვებები — **Tests**-ში, ხოლო დამოკიდებულობების ქეშის აქტივობა — **Mix cache**-ში. ეს არის საერთო კონფიგურაცია სამივესთვის. არასტაბილური ტესტების აღმოჩენა იყენებს შეტყობინებულ გაშვებებს; ხელახალი ცდები და CI-ში შარდინგი არის სურვილისამებრ.

## დამოკიდებულობების ქეშირება

Tuist ავტომატურად ირჩევს მხარდაჭერილ Hex და Git დამოკიდებულებებს, დამოკიდებულობების სიის გარეშე. ქეშში არყოფნისას კომპილაცია ჩვეულებრივად მიმდინარეობს და შედეგი ინახება; ქეშში ყოფნისას ის აღდგება. ნატიური/მორგებული კომპილაცია და ლოკალური დამოკიდებულებები რჩება Mix-თან.

კომპილაცია უნდა იყოს აღწარმოებადი: განაცხადეთ დამატებითი კომპილაციის დროის შეყვანები და გამორიცხეთ დამოკიდებულებები, რომლებსაც აქვთ არამოდელირებული შეყვანები ან საჭირო გვერდითი ეფექტები. მხარდაჭერილი შეყვანების, ქეშის ვერიფიკაციისა და მორგებისთვის იხილეთ <.localized_link href="/guides/features/cache/elixir">Elixir cache</.localized_link>.

## ბილდის ინსაიტები

ბილდის დროები, თქვენს ფაილებს შორის დამოკიდებულობების გრაფი და ის, თუ როგორ ვითარდება ორივე დროთა განმავლობაში, გაძლევთ იმას, რაც გჭირდებათ ბილდის გრაფის ოპტიმიზაციისთვის და კომპილაციის გარემოში ხელმისაწვდომი ყველა ბირთვის მაქსიმალურად გამოყენებისთვის.

`compile` ალიასის არსებობისას, Tuist იტყობინება ყოველ ბილდზე: რამდენი ხანი დასჭირდა, მისი გაფრთხილებები და შეცდომები, რამდენი ხანი დასჭირდა თითოეული ფაილის კომპილაციას და რა ფაილებზეა ის დამოკიდებული. თქვენი შემდეგი `mix compile` შემდეგ გახსენით დაფაზე **Builds**, რათა ნახოთ ის.

## ტესტების ინსაიტები

Tuist იწერს ყოველი ტესტის შედეგსა და ხანგრძლივობას ყოველ `mix test` გაშვებაში, რათა ნახოთ, თუ როგორ ვითარდება თქვენი ტესტების ნაკრები დროთა განმავლობაში, იპოვოთ ნელი ან უფრო ნელი გახდომილი ტესტები და გაიგოთ, რატომ ჩავარდა გაშვება CI-ში. თქვენ მათ ნახავთ დაფაზე **Tests** განყოფილებაში, მოდულის, `describe` ბლოკისა და ტესტის დონემდე.

## არასტაბილური ტესტები

არასტაბილური ტესტი ერთი და იგივე კოდით ზოგჯერ გადის, ზოგჯერ კი ვარდება. Tuist ტესტს არასტაბილურად მონიშნავს, როცა ის ერთსა და იმავე კომიტზე CI-ში ვარდებოდა და გადიოდა. ასევე შეგიძლიათ პაკეტს გადაატეროთ ჩავარდნილი ტესტები, რაც მათ ერთ გაშვებაში აღმოაჩენს:

```elixir
tuist: [project: "account/project", cache: true, test_retries: 2]
```

ტესტი, რომელიც ხელახალი ცდისას გადის, იტყობინება როგორც არასტაბილური და გაშვება წარმატებულია. **Flaky Tests** გვერდი მათ ჩამოთვლის.

## ტესტების შარდინგი

ტესტების შარდინგი თქვენს ტესტების ნაკრებს ანაწილებს CI რანერებზე. Tuist აბალანსებს შარდებს იმის მიხედვით, თუ რამდენი ხანი დასჭირდა თითოეულ ტესტის ფაილს ადრეულ გაშვებებში, და ერთხელ აკომპილირებს პროექტს და უზიარებს ამ ბილდს ყველა რანერს. ერთი ბრძანება გეგმავს შარდებს:

```bash
mix tuist.test.build --shard-max 4
```

შემდეგ თითოეული რანერი უშვებს თავის წილს `TUIST_SHARD_INDEX` მითითებით, და შედეგები დაფაზე მოდის როგორც ერთიანი ტესტების გაშვება:

```bash
TUIST_SHARD_INDEX=0 mix test
```

## ჩართეთ გუნდი

ინსაიტები მრავლდება პროექტთან დაკავშირებული ადამიანების რაოდენობის ზრდასთან ერთად. მიიწვიეთ თქვენი გუნდის წევრები ორგანიზაციაში დაფის ანგარიშის პარამეტრებიდან და დააყენეთ <.localized_link href="/guides/integrations/authentication/sso">Single Sign-On</.localized_link> (Google, Okta, Microsoft), რათა დარეგისტრება იყოს ერთი დაწკაპუნება და არა თითოეული პირისთვის `mix tuist.login`.

CI-სთვის არ გამოიყენოთ პირადი შესვლა. GitHub Actions, CircleCI და Bitrise შეუძლიათ აუთენტიკაცია OpenID Connect-ის მეშვეობით; სხვა პროვაიდერებზე დააყენეთ სკოპირებული `TUIST_TOKEN`. მიჰყევით <.localized_link href="/guides/install-hex-package#authenticate">CI აუთენტიკაციის ნაბიჯებს</.localized_link>.
