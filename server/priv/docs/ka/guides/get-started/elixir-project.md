ერთხელ დააყენეთ Tuist, შემდეგ კი გააგრძელეთ `mix compile` და `mix test` გამოყენება. `tuist_ex` Hex პაკეტი აკეთებს მხარდაჭერილი დამოკიდებულებების ქეშირებას და აგზავნის აგებისა და ტესტების გაშვების შესახებ ინფორმაციას თქვენს დაშბორდზე.

## წინაპირობები

- Elixir-ის პროექტი, აგებული Mix-ით, Elixir 1.18 ან უფრო გვიან ვერსიაზე.
- Tuist-ის ანგარიში.

## Tuist-ის დაყენება {#set-up-tuist}

შექმენით პროექტი Tuist-ის დაშბორდზე და აირჩიეთ **Mix (Elixir)** როგორც აგების სისტემა. დაამატეთ პაკეტი თქვენი `mix.exs` დამოკიდებულებებში:

```elixir
defp deps do
  [
    {:tuist_ex, "~> 0.3", runtime: false}
  ]
end
```

მიიღეთ ის, დააკონფიგურირეთ თქვენი პროექტი და შედით სისტემაში:

```bash
mix deps.get
mix tuist.setup --project account/project
mix tuist.login
```

დაყენება აახლებს `mix.exs` თქვენი პროექტის სახელით, რთავს დამოკიდებულებების ქეშირებას და აყენებს compile და test ალიასებს. ის ინარჩუნებს სხვა პარამეტრებს და სტანდარტულ ტესტების მომზადებას, როგორიცაა Phoenix-ის მონაცემთა ბაზის კონფიგურაცია. თუ ის ვერ შეძლებს უსაფრთხოდ ჩაართოს მორგებული ალიასი, ის ჩერდება ფაილის შეცვლის გარეშე.

დააკომიტეთ განახლებული `mix.exs`, რათა თქვენმა გუნდმა და CI-მ გამოიყენონ იგივე კონფიგურაცია. არ არის საჭირო სკრიპტების ან შეფასების კოდის კოპირება. შესვლა ხსნის ბრაუზერს; იხილეთ <.localized_link href="/guides/install-hex-package#authenticate">აუთენტიკაცია</.localized_link> headless შესვლისა და CI-ს კრედენციალებისთვის.

ახლა გაუშვით თქვენი ჩვეული ბრძანებები:

```bash
mix compile
mix test
```

აგებები ჩანს **აგებები**-ის ქვეშ, ტესტების გაშვებები **ტესტები**-ის ქვეშ, ხოლო დამოკიდებულებების ქეშის აქტივობა **Mix cache**-ის ქვეშ. ეს არის საერთო კონფიგურაცია სამივესთვის. არასტაბილური ტესტების აღმოჩენა იყენებს მოხსენებულ გაშვებებს; ხელახალი ცდები და CI შარდინგი არის სურვილისამებრ.

## დამოკიდებულებების ქეშირება

Tuist ავტომატურად ირჩევს მხარდაჭერილ Hex და Git დამოკიდებულებებს, დამოკიდებულებების სიის გარეშე. ქეშში არყოფნის შემთხვევაში კომპილაცია მიმდინარეობს ჩვეულებრივად და შედეგი ინახება; ქეშში ყოფნის შემთხვევაში ის აღდგება. ნატიური/მორგებული კომპილაცია და ლოკალური დამოკიდებულებები რჩება Mix-თან.

კომპილაცია უნდა იყოს აღწარმოებადი: გამოაცხადეთ დამატებითი კომპილაციის დროის შეყვანები და გამორიცხეთ დამოკიდებულებები, რომლებსაც აქვთ არამოდელირებული შეყვანები ან საჭირო გვერდითი ეფექტები. იხილეთ <.localized_link href="/guides/features/cache/elixir">Elixir ქეში</.localized_link> მხარდაჭერილი შეყვანების, ქეშის ვერიფიკაციისა და მორგებისთვის.

## აგების ინსაიტები

აგების დრო, დამოკიდებულებების გრაფიკი თქვენს ფაილებს შორის და ორივეს ევოლუცია დროთა განმავლობაში გაძლევთ იმას, რაც გჭირდებათ თქვენი აგების გრაფიკის ოპტიმიზაციისთვის და გარემოში არსებული ყველა ბირთვის მაქსიმალურად გამოყენებისთვის, სადაც კომპილაცია მიმდინარეობს.

`compile` ალიასის არსებობისას, Tuist იუწყება ყოველ აგებაზე: რამდენ ხანს გაგრძელდა, მისი გაფრთხილებები და შეცდომები, რამდენ ხანს დასჭირდა თითოეული ფაილის კომპილაცია და ფაილები, რომლებზეც ის არის დამოკიდებული. გახსენით **აგებები** დაშბორდზე თქვენი შემდეგი `mix compile` შემდეგ, რომ ნახოთ ის.

## ტესტების ინსაიტები

Tuist იწერს შედეგს და ხანგრძლივობას ყოველი ტესტისთვის ყოველ `mix test` გაშვებაში, რათა შეძლოთ ნახოთ, როგორ ვითარდება თქვენი ტესტების ნაკრები დროთა განმავლობაში, იპოვოთ ნელი ან უფრო ნელი გახდომილი ტესტები და გაიგოთ, რატომ ჩავარდა გაშვება CI-ში. თქვენ იპოვით მათ **ტესტები**-ის ქვეშ დაშბორდზე, მოდულის, `describe` ბლოკისა და ტესტის დონეზე.

## არასტაბილური ტესტები

არასტაბილური ტესტი გადის და ვარდება ერთი და იგივე კოდით. Tuist მონიშნავს ტესტს როგორც არასტაბილურს, როდესაც ის ჩავარდა და გაიარა იმავე კომიტზე CI-ში. ასევე შეგიძლიათ აიძულოთ პაკეტს ხელახლა სცადოს ჩავარდნილი ტესტები, რაც აღმოაჩენს მათ ერთ გაშვებაში:

```elixir
tuist: [project: "account/project", cache: true, test_retries: 2]
```

ტესტი, რომელიც გადის ხელახალი ცდისას, მოხსენებულია როგორც არასტაბილური და გაშვება წარმატებულია. **არასტაბილური ტესტები** გვერდი ჩამოთვლის მათ.

## ტესტების შარდინგი

ტესტების შარდინგი ანაწილებს თქვენს ტესტების ნაკრებს CI გამშვებებზე. Tuist აბალანსებს შარდებს იმის მიხედვით, თუ რამდენ ხანს გაგრძელდა თითოეული ტესტის ფაილი ადრეულ გაშვებებში, და ის აკომპილირებს პროექტს ერთხელ და უზიარებს ამ აგებას ყოველ გამშვებს. ერთი ბრძანება გეგმავს შარდებს:

```bash
mix tuist.test.build --shard-max 4
```

შემდეგ თითოეული გამშვები უშვებს თავის წილს `TUIST_SHARD_INDEX`-ის დაყენებით, და შედეგები მოდის დაშბორდზე როგორც ერთიანი ტესტის გაშვება:

```bash
TUIST_SHARD_INDEX=0 mix test
```

## ჩაერთეთ გუნდი

ინსაიტები მრავლდება პროექტთან დაკავშირებული ადამიანების რაოდენობის ზრდასთან ერთად. მიიწვიეთ თქვენი გუნდის წევრები ორგანიზაციაში დაშბორდის ანგარიშის პარამეტრებიდან და დააყენეთ <.localized_link href="/guides/integrations/authentication/sso">ერთჯერადი შესვლა</.localized_link> (Google, Okta, Microsoft), რათა დარეგისტრირება იყოს ერთი დაწკაპუნება და არა თითოეული პირისთვის `mix tuist.login`.

CI-სთვის, არ გამოიყენოთ პირადი შესვლა. GitHub Actions, CircleCI და Bitrise შეუძლიათ აუთენტიკაცია OpenID Connect-ის მეშვეობით; სხვა პროვაიდერებზე, დააყენეთ სკოპირებული `TUIST_TOKEN`. მიჰყევით <.localized_link href="/guides/install-hex-package#authenticate">CI აუთენტიკაციის ნაბიჯებს</.localized_link>.
