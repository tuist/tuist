# Elixir-პროექტი {#elixir-project}

::: code-group

```text [Agent prompt]
Help me get started with Tuist. Follow the setup at:
https://tuist.dev/en/docs/guides/get-started/elixir-project
```

:::

ერთხელ დააყენეთ Tuist, შემდეგ კი განაგრძეთ `mix compile` და `mix test` გამოყენება. `tuist_ex` Hex-პაკეტი აკეთებს მხარდაჭერილი დამოკიდებულებების ქეშირებას და თქვენს დაფაზე აგზავნის ბილდებისა და ტესტების გაშვების შესახებ ინფორმაციას.

## წინაპირობები

- Elixir-პროექტი, აგებული Mix-ით, Elixir 1.18 ან უფრო ახალ ვერსიაზე.
- Tuist-ის ანგარიში.

## Tuist-ის დაყენება {#set-up-tuist}

შექმენით პროექტი Tuist-ის დაფაზე და აირჩიეთ **Mix (Elixir)** როგორც ბილდის სისტემა. დაამატეთ პაკეტი თქვენი `mix.exs` დამოკიდებულებებში:

```elixir
defp deps do
  [
    {:tuist_ex, "~> 0.3", runtime: false}
  ]
end
```

მიიღეთ ის, დააკონფიგურირეთ თქვენი პროექტი და შედით სისტემაში:

```bash
mix deps.get
mix tuist.setup --project account/project
mix tuist.login
```

დაყენება აახლებს `mix.exs` თქვენი პროექტის იდენტიფიკატორით, რთავს დამოკიდებულებების ქეშირებას და აყენებს კომპილაციისა და ტესტირების ალიასებს. ის ინარჩუნებს სხვა პარამეტრებსა და სტანდარტულ ტესტების მომზადებას, მაგალითად, Phoenix-ის მონაცემთა ბაზის დაყენებას. თუ უსაფრთხოდ ვერ ახდენს მორგებული ალიასის ინტეგრაციას, ის ჩერდება ფაილის შეცვლის გარეშე.

შეინახეთ განახლებული `mix.exs`, რათა თქვენმა გუნდმა და CI-მ ერთი და იგივე კონფიგურაცია გამოიყენოს. არ არის საჭირო სკრიპტების ან შეფასების კოდის კოპირება. შესვლა ხსნის ბრაუზერს; headless შესვლისა და CI-ს მონაცემებისთვის იხილეთ <.localized_link href="/guides/install-hex-package#authenticate">აუთენტიკაცია</.localized_link>.

ახლა გაუშვით თქვენი ჩვეული ბრძანებები:

```bash
mix compile
mix test
```

ბილდები ჩანს **ბილდები**-ში, ტესტების გაშვებები — **ტესტები**-ში, ხოლო დამოკიდებულებების ქეშის აქტივობა — **Mix cache**-ში. ეს არის საერთო კონფიგურაცია სამივესთვის. არასტაბილური ტესტების აღმოჩენა იყენებს მოხსენებულ გაშვებებს; ხელახალი ცდები და CI-ს შარდინგი არის არასავალდებულო.

## დამოკიდებულებების ქეშირება

Tuist ავტომატურად ირჩევს მხარდაჭერილ Hex და Git დამოკიდებულებებს, დამოკიდებულებების სიის გარეშე. ქეშში არყოფნის შემთხვევაში კომპილაცია ჩვეულებრივად მიმდინარეობს და შედეგი ინახება; ქეშში ყოფნისას ის აღდგება. ნატიური/მორგებული კომპილაცია და ლოკალური დამოკიდებულებები რჩება Mix-თან.

კომპილაცია უნდა იყოს აღწარმოებადი: გამოაცხადეთ დამატებითი კომპილაციის დროის შეყვანები და გამორიცხეთ დამოკიდებულებები არამოდელირებული შეყვანებით ან საჭირო გვერდითი ეფექტებით. მხარდაჭერილი შეყვანების, ქეშის ვერიფიკაციისა და მორგებისთვის იხილეთ <.localized_link href="/guides/features/cache/elixir">Elixir cache</.localized_link>.

## ბილდის ანალიტიკა

ბილდის დრო, თქვენს ფაილებს შორის დამოკიდებულების გრაფი და ორივეს ევოლუცია დროთა განმავლობაში გაძლევთ იმას, რაც გჭირდებათ ბილდის გრაფის ოპტიმიზაციისთვის და კომპილაციის გარემოში ხელმისაწვდომი ყველა ბირთვის მაქსიმალურად გამოყენებისთვის.

`compile` ალიასის არსებობისას, Tuist იუწყება ყოველ ბილდს: რამდენი დრო დასჭირდა, მისი გაფრთხილებები და შეცდომები, რამდენი დრო დასჭირდა თითოეული ფაილის კომპილაციას და ფაილები, რომლებზეც ის არის დამოკიდებული. თქვენი შემდეგი `mix compile` შემდეგ გახსენით დაფაზე **ბილდები**, რათა ნახოთ ის.

## ტესტების ანალიტიკა

Tuist იწერს ყოველი ტესტის შედეგსა და ხანგრძლივობას ყოველ `mix test` გაშვებაში, რათა ნახოთ, როგორ ვითარდება თქვენი ტესტების ნაკრები დროთა განმავლობაში, იპოვოთ ნელი ან უფრო ნელი გახდებული ტესტები და გაიგოთ, რატომ ჩაიშალა გაშვება CI-ში. თქვენ მათ ნახავთ დაფაზე **ტესტები**-ში, მოდულის, `describe` ბლოკისა და ტესტის დონემდე.

## არასტაბილური ტესტები

არასტაბილური ტესტი გადის და ჩავარდება ერთი და იგივე კოდით. Tuist ტესტს არასტაბილურად ნიშნავს, როცა ის ჩავარდა და გაიარა ერთსა და იმავე კომიტზე CI-ში. ასევე შეგიძლიათ პაკეტს მოსთხოვოთ ჩაშლილი ტესტების ხელახალი ცდა, რაც მათ ერთ გაშვებაში აღმოაჩენს:

```elixir
tuist: [project: "account/project", cache: true, test_retries: 2]
```

ტესტი, რომელიც ხელახალ ცდაზე გადის, მოხსენებულია როგორც არასტაბილური და გაშვება წარმატებულია. **არასტაბილური ტესტები** გვერდი ჩამოთვლის მათ.

## ტესტების შარდინგი

ტესტების შარდინგი ანაწილებს თქვენს ტესტების ნაკრებს CI გამშვებებზე. Tuist აბალანსებს შარდებს იმის მიხედვით, თუ რამდენი დრო დასჭირდა თითოეულ ტესტის ფაილს წინა გაშვებებში, და აკომპილირებს პროექტს ერთხელ და უზიარებს ამ ბილდს ყოველ გამშვებს. ერთი ბრძანება გეგმავს შარდებს:

```bash
mix tuist.test.build --shard-max 4
```

შემდეგ თითოეული გამშვი თავის წილს უშვებს `TUIST_SHARD_INDEX` პარამეტრით და შედეგები დაფაზე ერთიანი ტესტების გაშვების სახით ჩნდება:

```bash
TUIST_SHARD_INDEX=0 mix test
```

## გუნდის ჩართვა

ანალიტიკა მრავლდება პროექტთან დაკავშირებული ადამიანების რაოდენობის ზრდასთან ერთად. მიიწვიეთ თქვენი გუნდის წევრები ორგანიზაციაში დაფის ანგარიშის პარამეტრებიდან და დააყენეთ <.localized_link href="/guides/integrations/authentication/sso">ერთჯერადი შესვლა</.localized_link> (Google, Okta, Microsoft), რათა ახალი წევრის დამატება იყოს ერთი დაწკაპუნება და არა თითოეული ადამიანისთვის `mix tuist.login`.

CI-სთვის არ გამოიყენოთ პირადი შესვლა. GitHub Actions, CircleCI და Bitrise შეუძლიათ აუთენტიკაცია OpenID Connect-ის მეშვეობით; სხვა პროვაიდერებზე დააყენეთ შეზღუდული `TUIST_TOKEN`. მიჰყევით <.localized_link href="/guides/install-hex-package#authenticate">CI აუთენტიკაციის ნაბიჯებს</.localized_link>.
