[Struo](https://struo.run) ასრულებს ქეშირებად სკრიპტებს და ბილდის გრაფებს. დააკავშირეთ ის Tuist-თან, რათა გაუზიაროთ ქეშირებული სამუშაოები სხვადასხვა მანქანას, თვალყური ადევნოთ გაშვებებს რეალურ დროში და გამოაქვეყნოთ აპლიკაციები თქვენი გუნდისთვის საცდელად. შეინახეთ არსებული პროექტის წყაროები და ბილდის განმარტებები; ინტეგრაცია მოთავსებულია `struo.toml` ფაილში.

## წინაპირობები

- [Struo 1.0.0](https://github.com/tuist/struo/releases/tag/1.0.0) ან უფრო ახალი ვერსია უნდა იყოს დაინსტალირებული, ასევე გჭირდებათ სამუშაო სივრცე ან ქეშირებადი სკრიპტი. მიჰყევით [ინსტალაციის სახელმძღვანელოს](https://struo.run/docs/guide/getting-started), ან დააფიქსირეთ ვერსია mise-ით:

  ```bash
  mise use -g github:tuist/struo@1.0.0
  ```

- Tuist-ის ანგარიში. Struo-ს ინტეგრაციისთვის Tuist CLI არ არის საჭირო.

## Once-დან Struo-ზე გადასვლა {#upgrading-from-once}

Struo არის Once-ის ახალი სახელი. გადაარქვით `once.toml` ფაილებს `struo.toml`, განაახლეთ mise-ის პინები `github:tuist/once`-დან `github:tuist/struo`-ზე და ჩაანაცვლეთ `once` ბრძანებები `struo`-ით. განაახლეთ სკრიპტის სათაურები `# once`-დან `# struo`-ზე და shebang-ები `#!/usr/bin/env -S struo exec -- bash`-ზე. გადაარქვით `ONCE_*` გარემოს ცვლადებს `STRUO_*`, მაგალითად `STRUO_CACHE_PROVIDER`; Tuist-ის ავტორიზაციის მონაცემები კვლავ იყენებენ `TUIST_TOKEN`-ს.

შეცვალეთ `.once/` ჩანაწერები ignore ფაილებში `.struo/`-ზე. გამომავალი ფაილები ახლა მოთავსებულია `.struo/out/`-ში, ხოლო საერთო ლოკალური კონტენტის ქეში იყენებს `$XDG_CACHE_HOME/struo/cas`-ს (ნაგულისხმევად `~/.cache/struo/cas`). ქეშის გასაღებები და ლოკალური საცავი იყენებენ ახალ სახელს, ამიტომ განახლების შემდეგ ელოდეთ ლოკალური ქეშის „ცივ“ მდგომარეობას ძველი ქეშის ჩანაწერების გადატანის ნაცვლად. ხელახლა შედით სისტემაში `struo auth login --provider tuist`-ით.

სახელის ცვლილება არ ცვლის Tuist-ის თავსებადობის წერტილებს: რეალური დროის ანგარიშგება კვლავ იყენებს `once.events.v1`-ს, ხოლო არსებული `/api/.../once` მარშრუტები კვლავ მხარდაჭერილია. იხილეთ [upstream-ის სახელის ცვლილების სახელმძღვანელო](https://struo.run/changelog/2026-11-18-once-is-now-struo).

## პროექტის დაკავშირება {#connect-the-project}

თქვენი რეპოზიტორიის ფესვიდან გაუშვით:

```bash
struo connect --provider tuist --create
```

Struo საჭიროების შემთხვევაში შეგიყვანთ სისტემაში, შექმნის Tuist-ის პროექტს თქვენს პირად ანგარიშზე და ჩაწერს პროვაიდერთან დაკავშირებას `struo.toml` ფაილში. იხილეთ [პროექტის დაკავშირება](https://struo.run/docs/guide/infrastructure/connect) სხვა ანგარიშის ან არსებული პროექტის არჩევისთვის.

არსებული Tuist-ის პროექტისთვის, პროვაიდერი და ქეშის დაკავშირება თავად დააკონფიგურირეთ:

```toml
[infrastructures.tuist]
kind = "tuist"
account = "acme"
project = "app"
# url = "https://your-tuist-server.example.com"

[infrastructure.cache]
provider = "tuist"
```

ჩაანაცვლეთ `acme` და `app` თქვენი ანგარიშისა და პროექტის იდენტიფიკატორებით, შემდეგ კი გაიარეთ ავტორიზაცია:

```bash
struo auth login --provider tuist
```

დააკომიტეთ `struo.toml`, რათა თქვენმა გუნდის წევრებმა და CI-მ გაიზიარონ დანიშნულება, არა თქვენი ავტორიზაციის მონაცემები. ყოველი დეველოპერი შედის სისტემაში საკუთარ მანქანაზე.

## საერთო ქეში

ლოკალური ქეში ეხმარება მხოლოდ იმ მანქანას, რომელმაც ის შეავსო. Tuist-ის კონფიგურაციის შემთხვევაში, Struo-ს შეუძლია აღადგინოს სხვა დეველოპერის ან CI-ის მიერ წარმოქმნილი შესაბამისი შედეგები იმავე სამუშაოს ხელახლა შესრულების ნაცვლად.

გაუშვით თქვენი ქეშირებადი სკრიპტი ან გრაფის მიზანი ჩვეულებრივად:

```bash
struo build MyApplication
```

გახსენით **Struo Cache** დაფაზე შორეული ქეშის აქტივობის შესამოწმებლად. იხილეთ <.localized_link href="/guides/features/cache/struo">Struo-ს ქეში</.localized_link> დაყენებისა და მანქანათშორისი გამოყენების შესამოწმებლად.

## ბილდის ინსაითები

Struo ბეჭდავს დაფის ბმულს გაშვების დაწყებისას. გახსენით ის, რათა თვალყური ადევნოთ გრაფს, მოქმედებების სტატუსსა და ქეშის გადაწყვეტილებებს გაშვების მიმდინარეობისას. გამოიყენეთ **Builds** ლოკალური და CI შესრულების შესადარებლად და წარუმატებელი მოქმედებების გამოსაკვლევად. შეინახეთ CI-ის ლოგები პროცესის სრული გამონატანისთვის; raw action log-ის შეტანა ამჟამად არ არის ხელმისაწვდომი.

იხილეთ <.localized_link href="/guides/features/build-insights/struo">Struo-ს ბილდის ინსაითები</.localized_link> იმის გასაგებად, თუ რა იწერება და როგორ მივწვდეთ მას კოდირების აგენტებიდან ან Grafana-დან.

## ტესტების ინსაითები და შარდინგი

გაუშვით თქვენი Struo-ს ტესტების მიზნები:

```bash
struo test
```

გახსენით **Tests** მოხსენებული სუიტების, ტესტქეისების, ხანგრძლივობებისა და შეცდომების შესამოწმებლად. შედეგები დამოკიდებულია ტესტის მიზნის მოხსენების შესაძლებლობებზე; მოქმედება, რომელიც ასრულებს ტესტის პროცესს, არ არის ავტომატურად თითოეული ტესტქეისის მოხსენება.

როდესაც სუიტი ერთ მანქანას აღემატება, შექმენით ჰოსტინგული შარდის გეგმა და გაანაწილეთ მისი პაკეტები CI-ის მუშაკებზე. იხილეთ <.localized_link href="/guides/features/test-insights/struo">Struo-ს ტესტების ინსაითები</.localized_link> და <.localized_link href="/guides/features/test-sharding/struo">Struo-ს ტესტების შარდინგი</.localized_link>.

## პრევიუები და ბანდლის ზომა

დაამატეთ არტიფაქტის დაკავშირება იმავე პროვაიდერთან, რათა გამოაქვეყნოთ მხარდაჭერილი Android-, Apple სიმულატორისა და macOS აპლიკაციები:

```toml
[infrastructure.artifacts]
name = "tuist"
```

```bash
struo artifact publish MyApplication --track review
```

დაბრუნებული ბმული ხსნის თქვენი პროექტის პრევიუებს; დამუშავებას შეიძლება გარკვეული დრო დასჭირდეს. იხილეთ <.localized_link href="/guides/features/previews/struo">Struo-ს პრევიუები</.localized_link> ხელმოწერის მოთხოვნებისა და ბილდების შემდეგ არჩევითი გამოქვეყნებისთვის.

ბანდლის ზომის თვალყურის სადევნებლად, გამოიყენეთ Tuist CLI ცალკე აგებულ `.app`, `.ipa`, `.xcarchive`, `.apk` ან `.aab` ფაილებთან მიმართებაში. მიჰყევით <.localized_link href="/guides/features/bundle-insights">Apple-ის ან Android-ის ბანდლის ინსაითების სახელმძღვანელოს</.localized_link>; Struo-ს არტიფაქტის გამოქვეყნება ავტომატურად არ ტვირთავს ბანდლის ზომის ანგარიშს.

## უწყვეტი ინტეგრაცია

გამოიყენეთ ანგარიშის ტოკენი, რომელიც ავტორიზებულია პროექტის ოპერაციებისთვის `TUIST_TOKEN`-ში, ან გაიარეთ ავტორიზაცია მხარდაჭერილი CI პროვაიდერის OpenID Connect იდენტობის მეშვეობით:

```bash
struo auth login --provider tuist --no-browser
struo build MyApplication
struo test
```

GitHub Actions-ზე, მიანიჭეთ ჯობს `id-token: write` და `contents: read`. იხილეთ <.localized_link href="/guides/integrations/continuous-integration#struo">Struo უწყვეტ ინტეგრაციაში</.localized_link> მაგალითისთვის. პირადი დეველოპერის შესვლა არ არის CI-ის ავტორიზაციის მონაცემი.

## შორეული შესრულება

ანგარიშებს, რომლებსაც ჩართული აქვთ შორეული შესრულება, ასევე შეუძლიათ შესაბამისი გრაფის ბრძანების მოქმედებების შესრულება Tuist-ის Linux მუშაკებზე. ეს განსხვავდება ქეშირებული შედეგების გაზიარებისა და მთლიანი CI ნაკადის შესრულებისგან. იხილეთ <.localized_link href="/guides/features/runners/struo">Struo-ს შორეული შესრულება</.localized_link> მუშაკის მოთხოვნებისა და დაყენებისთვის.
