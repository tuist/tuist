მიჰყევით ამ გზას, რომ არსებული Gradle პროექტი Tuist-ზე მიამართოთ. `dev.tuist` Gradle პლაგინი აკავშირებს Gradle-ის ლოკალურ ბილდ კეშს Tuist-ის დისტანციურ კეშთან და ატვირთავს ბილდისა და ტესტების მონაცემებს დაშბორდზე, ერთი `./gradlew` ბრძანების შეცვლის გარეშე.

ქვემოთ მოცემული თითოეული სექცია იწყება იმის აღწერით, რაც დღეს აკლიათ, შემდეგ კი გაგივლით ფუნქციას, რომელიც ამ ნაკლოვანებას ავსებს.

## წინაპირობები

- Gradle პროექტი `settings.gradle.kts`-ით (ან `settings.gradle`-ით).
- <.localized_link href="/guides/install-tuist">Tuist-ის ბრძანების ხაზის ინტერფეისი</.localized_link>.

## პროექტის დაკავშირება

Gradle პროექტის ძირიდან გაუშვით `tuist init`. აირჩიეთ **Gradle პროექტის ინტეგრაცია**, შემდეგ გაიარეთ ავთენტიკაცია ბრაუზერში და აირჩიეთ ის ანგარიში, რომელსაც უნდა ეკუთვნოდეს პროექტი.

```bash
tuist init
```

თუ ამას კოდირების აგენტით ან სკრიპტით აკეთებთ, ჯერ გაუშვით `tuist auth login` (ბრაუზერის ნაკადი ელოდება Enter-ის დაჭერას), შემდეგ გამოიყენეთ არაინტერაქტიული ფორმა:

```bash
tuist init --build-system gradle --name <project-handle> --account <account>
```

Tuist წერს `tuist.toml`-ს რეპოზიტორიის ძირში პროექტის სახელით და ბეჭდავს `plugins { ... }` ბლოკს. ჩასვით ის `settings.gradle.kts`-ის თავში:

```kotlin
plugins {
    id("dev.tuist") version "0.10.0"
}
```

შეამოწმეთ `./gradlew help`-ით. Gradle უნდა ჩაიტვირთოს შეცდომების გარეშე. თუ ვერ პოულობს პლაგინს, დარწმუნდით, რომ ბლოკი `settings.gradle.kts`-შია, არა `build.gradle.kts`-ში.

ქვემოთ მოცემული ყველაფერი არის სურვილისამებრ და დამოუკიდებელი.

## დისტანციური ბილდ კეში

Gradle-ის ლოკალური ბილდ კეში ინახავს ამოცანების გამომავალ მონაცემებს იმ მანქანაზე, რომელმაც ისინი წარმოქმნა. ერთსა და იმავე ბრენჩზე მყოფი ორი დეველოპერი ეხება კეშს საკუთარ `~/.gradle`-ში და არა ერთმანეთისაში, ხოლო CI ყოველ ჯობზე ეხება ახალ, ცარიელ კეშს.

Tuist-ის დისტანციური კეში აფართოებს იმავე გასაღები/მნიშვნელობის პროტოკოლს, რომელსაც Gradle უკვე იყენებს მანქანებს შორის. ამოცანის გამომავალი მონაცემები იტვირთება იმ მანქანაზე, რომელმაც პირველად შეასრულა ის, და იწერება ნებისმიერი სხვის მიერ, ვინც იმავე შესავალ მონაცემებს გადააწყდება. ჩართეთ ის `gradle.properties`-ში:

```properties
org.gradle.caching=true
```

შემდეგ ააწყვეთ ორ გარემოში:

```bash
./gradlew clean build --build-cache --info
```

კეშირებადი ამოცანები მეორე გაშვებაზე ანგარიშგებენ `FROM-CACHE`-ს. გახსენით **კეში** დაშბორდზე, რათა ნახოთ მოხმარების მაჩვენებლები დროთა განმავლობაში.

## ბილდის ანალიტიკა

Gradle ასხივებს ამოცანების დროებით მონაცემებს ბილდის ბოლოს და `--profile`-ით წერს თითოეული ბილდის HTML ანგარიშს. არცერთი არ აჯამებს გაშვებებს შორის. ამოცანა, რომელიც კომიტების სერიის განმავლობაში შენელდა, ნებისმიერი ერთი ბილდის ანგარიშში ისევე გამოიყურება, როგორც ყოველთვის.

`dev.tuist` პლაგინი ავტომატურად ტვირთავს ამოცანების დროებით მონაცემებს ყოველი ბილდისთვის დაშბორდზე, როგორც კი პლაგინი გამოიყენება. არაფერია დამატებითად კონფიგურირებადი. გახსენით **ბილდები** დაშბორდზე თქვენი შემდეგი `./gradlew build`-ის შემდეგ, რათა ნახოთ ტენდენცია.

## ტესტების ანალიტიკა

Gradle-ის ტესტების ანგარიშები ცხოვრობენ თითოეული ბილდისთვის `build/reports/tests/`-ქვეშ. ტესტი, რომელიც პერიოდულად მარცხდება ათი CI გაშვების განმავლობაში, ნებისმიერ კონკრეტულ ანგარიშში გამოიყურება როგორც სტაბილური ტესტი, რომელიც ერთხელ ჩავარდა.

ტესტების ანალიტიკა იწერს ყოველი ამოცანის შედეგსა და ხანგრძლივობას ყოველი `./gradlew test` გაშვებისთვის და აკორელირებს შედეგებს გაშვებებს შორის. არასტაბილური ტესტები, ნელი ტესტები და ჩავარდნები ჩნდება დაშბორდის **ტესტები** ჩანართზე. როდესაც არასტაბილურობა გროვდება, იზოლირეთ ისინი დაშბორდიდან, რათა შეწყვიტონ შერწყმების ბლოკირება.

პლაგინი ასევე მხარს უჭერს **სტრეს-ტესტირების რეჟიმს**, რომელიც ხელახლა უშვებს ბილდის მიერ შემოტანილ ტესტის საქმეებს და აღნიშნავს ნებისმიერს, რომელიც არასტაბილურად აღმოჩნდება, სანამ ისინი მიიღებენ. დაამატეთ ის `tuist` გაფართოებაში `settings.gradle.kts`-ში:

```kotlin
tuist {
    stressNewTests {
        mode = "report" // or "enforce"
    }
}
```

## ბანდლის ანალიტიკა

Android Gradle პლაგინი ანგარიშგებს წარმოქმნილი `.aab`-ის ზომას ბილდის გამომავალში. ეს რიცხვი ქრება ბრენჩთან ერთად და ზომების შედარება რელიზებს შორის არის ხელით შესრულებული აღრიცხვის სამუშაო. Play Console ანგარიშგებს იმავე რიცხვებს, მაგრამ მხოლოდ არტიფაქტის ატვირთვის შემდეგ.

ბანდლის ანალიტიკა იწერს ინსტალაციისა და ჩამოტვირთვის ზომებს ყოველი `.aab`-ისთვის (რეკომენდებული) ან `.apk`-ისთვის და შეუძლია ჩააგდოს PR შემოწმება, როდესაც ბრენჩის ზღვარი ირღვევა. დაამატეთ ეს თქვენს CI-ში ბილდის ნაბიჯის შემდეგ:

```bash
tuist inspect bundle App.aab
```

გახსენით **ბანდლის ანალიტიკა → Android** დაშბორდზე, რათა ნახოთ ტენდენცია და კონფიგურირება ზღვრები.

## პრივიუები

Play Console-ის შიდა ტესტის ტრეკი ყოველ გაზიარებაზე ამატებს გადახედვისა და გავრცელების დაყოვნებას. raw `.apk`-ის გაგზავნა Slack-ით ან ელფოსტით უფრო სწრაფია, მაგრამ კარგავს თვალყურს, თუ რომელ ბილდს ეხება კონკრეტული შეტყობინება.

პლაგინს შეუძლია პირდაპირ ააწყოს და გამოაქვეყნოს აპლიკაციის ვარიანტი, ცალკე CLI ატვირთვის გარეშე:

```bash
./gradlew :app:tuistShareDebug --track nightly
```

`tuistShare<Variant>` ამოცანის მოთხოვნა აყენებს იმ გამოძახებას გამოქვეყნებაზე; ჩვეულებრივი ბილდები არასდროს ტვირთავენ პრივიუებს. ნახეთ <.localized_link href="/guides/features/previews/gradle">Gradle პრივიუები</.localized_link> მხარდაჭერილი APK-ების, ხელმოწერისა და ინსტალაციისთვის.

## გუნდის ჩართვა

კეშის მოხმარება, ანალიტიკა და სტრეს-ტესტირება ყველა იზრდება პროექტთან დაკავშირებული ადამიანების რაოდენობასთან ერთად. მიიწვიეთ თქვენი გუნდის წევრები ორგანიზაციაში დაშბორდის ანგარიშის პარამეტრებიდან და დააყენეთ <.localized_link href="/guides/integrations/authentication/sso">ერთიანი შესვლა</.localized_link> (Google, Okta, Microsoft), რათა დარეგისტრირება იყოს ერთი დაჭერა და არა თითოეული ადამიანისთვის `tuist auth login`.

CI-ისთვის არ გამოიყენოთ პირადი შესვლა. დააყენეთ `TUIST_TOKEN` თქვენს პროექტზე მორგებული (შექმენით ის დაშბორდის პროექტის პარამეტრებიდან).

## პლაგინის სრული ცნობარი

აქ მოცემული ყველაფერი არის მინიმუმი, რათა მიიღოთ სარგებელი Tuist-ისგან Gradle პროექტზე. კონფიგურაციის პარამეტრები `tuist` გაფართოების ბლოკისთვის, `stressNewTests` რეჟიმისთვის და CI ავთენტიკაციისთვის მოცემულია [Gradle პლაგინის ინსტალაცია](https://tuist.dev/en/docs/guides/install-gradle-plugin) ცნობარში.
