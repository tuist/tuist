მიჰყევით ამ გზას, რათა არსებული Gradle პროექტი Tuist-თან დააკავშიროთ. `dev.tuist` Gradle პლაგინი აკავშირებს Gradle-ის ლოკალურ ბილდის ქეშს Tuist-ის დისტანციურ ქეშთან და ტვირთავს ბილდისა და ტესტების მონაცემებს დაშბორდზე, ისე რომ არ ცვლის არცერთ `./gradlew` ბრძანებას.

ქვემოთ მოცემული თითოეული განყოფილება იწყება იმის აღწერით, რაც დღეს აკლია, შემდეგ კი გაჩვენებთ ფუნქციას, რომელიც ამ ნაკლოვანებას აღმოფხვრის.

## წინაპირობები

- Gradle პროექტი `settings.gradle.kts`-ით (ან `settings.gradle`-ით).
- <.localized_link href="/guides/install-tuist">Tuist-ის ბრძანების ხაზის ინტერფეისი</.localized_link>.

## პროექტის დაკავშირება

Gradle პროექტის ძირიდან გაუშვით `tuist init`. აირჩიეთ **Gradle პროექტის ინტეგრაცია**, შემდეგ გაიარეთ ავთენტიფიკაცია ბრაუზერში და აირჩიეთ ანგარიში, რომელსაც უნდა ეკუთვნოდეს პროექტი.

```bash
tuist init
```

თუ ამას კოდირების აგენტით ან სკრიპტით აკეთებთ, ჯერ გაუშვით `tuist auth login` (ბრაუზერის ნაკადი ელოდება Enter-ის დაჭერას), შემდეგ გამოიყენეთ არაინტერაქტიული ფორმა:

```bash
tuist init --build-system gradle --name <project-handle> --account <account>
```

Tuist წერს `tuist.toml`-ს რეპოზიტორიის ძირში პროექტის სახელით და ბეჭდავს `plugins { ... }` ბლოკს. ჩასვით ის `settings.gradle.kts`-ის თავში:

<!-- @snippet: ../_gradle-plugin-block -->

შეამოწმეთ `./gradlew help`-ით. Gradle უნდა ჩაიტვირთოს შეცდომების გარეშე. თუ პლაგინს ვერ პოულობს, დარწმუნდით, რომ ბლოკი `settings.gradle.kts`-შია, არა `build.gradle.kts`-ში.

ქვემოთ მოცემული ყველაფერი არჩევითი და დამოუკიდებელია.

## დისტანციური ბილდის ქეში

Gradle-ის ლოკალური ბილდის ქეში ინახავს ამოცანების გამომავალ მონაცემებს იმ მანქანაზე, რომელმაც ისინი წარმოქმნა. ერთსა და იმავე ბრენჩზე მყოფი ორი დეველოპერი ეხება ქეშს საკუთარ `~/.gradle`-ში და არა ერთმანეთისაში, ხოლო CI ყოველ ჯობზე ახალ, ცარიელ ქეშს ეხება.

Tuist-ის დისტანციური ქეში აფართოებს იგივე key/value პროტოკოლს, რომელსაც Gradle უკვე იყენებს მანქანებს შორის. ამოცანის გამომავალი მონაცემები იტვირთება იმ მანქანაზე, რომელმაც პირველად შეასრულა ის, და იწერება ნებისმიერი სხვის მიერ, ვინც იგივე შემავალ მონაცემებს შეხვდება. ჩართეთ ის `gradle.properties`-ში:

```properties
org.gradle.caching=true
```

შემდეგ ააწყვეთ ორ გარემოში:

```bash
./gradlew clean build --build-cache --info
```

ქეშირებადი ამოცანები მეორე გაშვებაზე ანგარიშობენ `FROM-CACHE`-ს. გახსენით **ქეში** დაშბორდზე, რათა ნახოთ მოხმარების მაჩვენებლები დროთა განმავლობაში.

## ბილდის ინსაიტები

Gradle ასხივებს ამოცანების დროს ბილდის ბოლოს და `--profile`-ით წერს თითოეული ბილდის HTML ანგარიშს. არცერთი არ აჯამებს მონაცემებს გაშვებებს შორის. ამოცანა, რომელიც კომიტების სერიის განმავლობაში შენელდა, ნებისმიერი ცალკეული ბილდის ანგარიშში ისევე ჩანს, როგორც ყოველთვის.

`dev.tuist` პლაგინი ტვირთავს ამოცანების დროს ყოველი ბილდისთვის დაშბორდზე ავტომატურად, როგორც კი პლაგინი გამოიყენება. არაფერი დამატებითი არ არის საჭირო კონფიგურაციისთვის. გახსენით **ბილდები** დაშბორდზე თქვენი შემდეგი `./gradlew build`-ის შემდეგ, რათა ნახოთ ტენდენცია.

## ტესტების ინსაიტები

Gradle-ის ტესტების ანგარიშები ინახება თითოეული ბილდისთვის `build/reports/tests/`-ში. ტესტი, რომელიც პერიოდულად მარცხდება ათი CI გაშვების განმავლობაში, ნებისმიერ კონკრეტულ ანგარიშში ჩანს როგორც სტაბილური ტესტი, რომელიც შემთხვევით ერთხელ ჩავარდა.

ტესტების ინსაიტები იწერს ყოველი ამოცანის შედეგს და ხანგრძლივობას ყოველი `./gradlew test` გაშვებისთვის და აკორელირებს შედეგებს გაშვებებს შორის. არასტაბილური ტესტები, ნელი ტესტები და ჩავარდნები ჩანს დაშბორდის **ტესტები** ჩანართზე. როცა არასტაბილურობა გროვდება, მოათავსეთ ისინი კარანტინში დაშბორდიდან, რათა შეწყვიტონ მერჯების ბლოკირება.

პლაგინი ასევე მხარს უჭერს **სტრეს-ტესტირების რეჟიმს**, რომელიც ხელახლა უშვებს ტესტების საქმეებს, რომლებიც ბილდმა შემოიტანა და მონიშნავს ნებისმიერს, რომელიც არასტაბილურად აღმოჩნდება, სანამ ისინი მიიღებენ. დაამატეთ ის `tuist` გაფართოებაში `settings.gradle.kts`-ში:

```kotlin
tuist {
    stressNewTests {
        mode = "report" // or "enforce"
    }
}
```

## ბანდლის ინსაიტები

Android Gradle Plugin ანგარიშობს წარმოქმნილი `.aab`-ის ზომას ბილდის გამომავალში. ეს რიცხვი ქრება ბრენჩთან ერთად და ზომების შედარება რელიზებს შორის ხელით შესრულებული აღრიცხვის სამუშაოა. Play Console ანგარიშობს იგივე რიცხვებს, მაგრამ მხოლოდ არტიფაქტის ატვირთვის შემდეგ.

ბანდლის ინსაიტები იწერს ინსტალაციისა და ჩამოტვირთვის ზომებს ყოველი `.aab`-ისთვის (რეკომენდებული) ან `.apk`-ისთვის და შეუძლია ჩააგდოს PR შემოწმება, როცა ბრენჩის ზღვარი გადაიჭრება. დაამატეთ ეს თქვენს CI-ში პირდაპირ ბილდის ნაბიჯის შემდეგ:

```bash
tuist inspect bundle App.aab
```

გახსენით **ბანდლის ინსაიტები → Android** დაშბორდზე, რათა ნახოთ ტენდენცია და დააკონფიგურიროთ ზღვრები.

## პრევიუები

Play Console-ის შიდა ტესტის ტრეკი ყოველ გაზიარებაზე ამატებს გადახედვისა და გავრცელების დაყოვნებას. raw `.apk`-ის გაგზავნა Slack-ით ან ელფოსტით უფრო სწრაფია, მაგრამ კარგავს თვალყურს, თუ რომელ ბილდს ეხება კონკრეტული შეტყობინება.

პლაგინს შეუძლია ააწყოს და გამოაქვეყნოს აპლიკაციის ვარიანტი პირდაპირ, ცალკე CLI ატვირთვის გარეშე:

```bash
./gradlew :app:tuistShareDebug --track nightly
```

`tuistShare<Variant>` ამოცანის მოთხოვნა აყენებს იმ გამოძახებას გამოქვეყნების რეჟიმში; ჩვეულებრივი ბილდები არასდროს ტვირთავენ პრევიუებს. იხილეთ <.localized_link href="/guides/features/previews/gradle">Gradle პრევიუები</.localized_link> მხარდაჭერილი APK-ების, ხელმოწერისა და ინსტალაციისთვის.

## გუნდის ჩართვა

ქეშის მოხმარება, ინსაიტები და სტრეს-ტესტირება ყველა იზრდება პროექტთან დაკავშირებული ადამიანების რაოდენობასთან ერთად. მიიწვიეთ თქვენი გუნდის წევრები ორგანიზაციაში ანგარიშის პარამეტრებიდან დაშბორდზე და დააყენეთ <.localized_link href="/guides/integrations/authentication/sso">ერთიანი შესვლა</.localized_link> (Google, Okta, Microsoft), რათა დარეგისტრირება იყოს ერთი დაწკაპუნება და არა თითოეული პირისთვის `tuist auth login`.

CI-სთვის არ გამოიყენოთ პირადი შესვლა. გაიარეთ ავთენტიფიკაცია თქვენი CI პროვაიდერის OIDC იდენტობით, ან შექმენით ანგარიშის ტოკენი **CI** პრესეტით დაშბორდზე და დააყენეთ ის როგორც `TUIST_TOKEN`. იხილეთ <.localized_link href="/guides/server/authentication#gradle-plugin-authentication">Gradle პლაგინის ავთენტიფიკაცია</.localized_link>.

## პლაგინის სრული ცნობარი

აქ მოცემული ყველაფერი არის მინიმუმი, რათა მიიღოთ სარგებელი Tuist-ისგან Gradle პროექტზე. კონფიგურაციის პარამეტრები `tuist` გაფართოების ბლოკისთვის, `stressNewTests` რეჟიმისთვის და CI ავთენტიფიკაციისთვის არის [Gradle პლაგინის ინსტალაცია](https://tuist.dev/en/docs/guides/install-gradle-plugin) ცნობარში.
