# Bazel პროექტი {#bazel-project}

::: code-group

```text [Agent prompt]
Help me get started with Tuist. Follow the setup at:
https://tuist.dev/en/docs/guides/get-started/bazel-project
```

:::

მიჰყევით ამ გზას, რათა არსებული Bazel სამუშაო სივრცე Tuist-ში ჩართოთ. Tuist აწვდის [Remote Execution API](https://github.com/bazelbuild/remote-apis) ქეშს, რომელსაც Bazel უკავშირდება როგორც დისტანციურ ქეშს, და Build Event Service ნაკადს, რომელიც ყოველ ბილდსა და ტესტს დაფის ხილულ მონაცემებად აქცევს.

ქვემოთ მოცემული თითოეული განყოფილება იწყება იმის აღწერით, რაც დღეს აკლია, შემდეგ კი გაჩვენებთ ფუნქციას, რომელიც ამ ნაკლოვანებას ავსებს.

## წინაპირობები

- Bazel სამუშაო სივრცე (მის ფესვზე `WORKSPACE` ან `MODULE.bazel`) და Bazel თქვენს `PATH`-ზე.
- <.localized_link href="/guides/install-tuist">Tuist-ის ბრძანების ხაზის ინტერფეისი</.localized_link>.

## სამუშაო სივრცის მიერთება

> [!NOTE]
> `tuist init`-ში ჩაშენებული Bazel სამუშაო ნაკადი საჭიროებს Tuist CLI-ის ვერსიას, რომელიც მასთან ერთად მოდის. ადრეულ გამოშვებებში `tuist init` არ ჩამოთვლის „Bazel სამუშაო სივრცის ინტეგრაციას“ როგორც ვარიანტს. გადადით `tuist auth login`-ზე, შემდეგ კი `tuist bazel setup`-ზე სამუშაო სივრცის ფესვიდან, რაც იგივე ნაბიჯებს გაატარებთ, როგორც ქვემოთაა აღწერილი.

Bazel სამუშაო სივრცის ფესვიდან გაუშვით `tuist init`. Tuist აღმოაჩენს `WORKSPACE` / `MODULE.bazel`-ს და შესთავაზებს **Bazel სამუშაო სივრცის ინტეგრაციას**. გაიარეთ ავტორიზაცია ბრაუზერში და აირჩიეთ ის ანგარიში, რომელმაც უნდა ფლობდეს პროექტს.

```bash
tuist init
```

თუ ამას კოდირების აგენტით ან სკრიპტით მართავთ, ჯერ გაუშვით `tuist auth login` (ბრაუზერის ნაკადი ელოდება Enter-ის დაჭერას), შემდეგ კი გამოიყენეთ არაინტერაქტიული ფორმა:

```bash
tuist init --build-system bazel --name <project-handle> --account <account>
```

init-ის დასრულებისას Tuist:

1. წერს `tuist.toml`-ს სამუშაო სივრცის ფესვში პროექტის იდენტიფიკატორით.
2. წერს `.bazelrc.tuist`-ს თქვენი `.bazelrc`-ის გვერდით, მიერთებულს უახლოეს Tuist ქეშის რეგიონთან და ავტორიზებულს სამუშაო სივრცეზე მორგებული კრედენციალების დამხმარე საშუალებით.
3. ამატებს `try-import %workspace%/.bazelrc.tuist` ხაზს თქვენს `.bazelrc`-ში.

დააკომიტეთ `try-import` ხაზი. ის იდენტურია ყველა მანქანაზე. დაამატეთ `.bazelrc.tuist` თქვენს `.gitignore`-ში. კრედენციალების დამხმარე საშუალების გზა მომხმარებელზეა დამოკიდებული, ხოლო ქეშის რეგიონი — ადგილმდებარეობაზე, ამიტომ ის არ უნდა გაზიარდეს.

ქვემოთ ჩამოთვლილი ყველაფერი ავტომატურად ჩაირთვება სამუშაო სივრცის მიერთების შემდეგ.

## დისტანციური ქეში

Bazel-ის საკუთარი ლოკალური დისკური ქეში მდებარეობს `~/.cache/bazel`-ში (ან იქ, სადაც `--disk_cache` მიუთითებს). ერთი დეველოპერის მანქანაზე ქეშის მოხვედრა სხვებს არ ეხება, ხოლო CI სამუშაოს კონტეინერები ყოველ გაშვებაზე ცარიელი ქეშიდან იწყებენ.

Bazel-ის [Remote Execution API](https://github.com/bazelbuild/remote-apis) არის პროტოკოლი იმავე ქეშის გასაფართოებლად საერთო წერტილამდე. Tuist ესმის მას. როგორც კი `.bazelrc.tuist` ადგილზე იქნება, Bazel გამოტოვებს იმ მოქმედებებს, რომელთა შედეგები უკვე საერთო ქეშშია, და ნაცვლად მათ ჩამოტვირთავს. ერთი მანქანის ნამუშევარი სარგებელს მოუტანს ყველა სხვა მანქანას, რომელიც იმავე რევიზიას აგებს.

შეამოწმეთ ორი სუფთა ბილდით იმავე რევიზიისთვის (ლოკალურად, ან ერთი ლოკალური + ერთი CI):

```bash
bazel clean
bazel build //...
```

მეორე გაშვების შეჯამებამ უნდა აჩვენოს ქეშის მოხვედრები. გახსენით **Cache** დაფაზე, რათა დროთა განმავლობაში მოხვედრების მაჩვენებლები ნახოთ.

## ბილდისა და ტესტების ანალიტიკა

Bazel-ის ბილდის მოვლენების ნაკადი და თითოეული ტესტის XML ანგარიშები გამოიცემა თითოეული გამოძახებისას. მიზნების დონეზე ხანგრძლივობების შედარება კვირის განმავლობაში, ან ტესტის აღმოჩენა, რომელიც რამდენიმე CI გაშვების განმავლობაში არასტაბილური გახდა, ნიშნავს ამ მოვლენების სადმე შეგროვებას და აგრეგირებას.

Build Event Service პროტოკოლი, რომელსაც Bazel უკვე ასხივებს, ზუსტად ამისთვისაა შექმნილი. `.bazelrc.tuist`, რომელიც `tuist init`-მ დაწერა, აკონფიგურირებს BES ნაკადს Tuist-ის მიმართ, ამიტომ ბილდისა და ტესტების ანალიტიკა დაიწყებს დინებას შემდეგ `bazel build`-სა და `bazel test`-ზე. დამატებითი კონფიგურაცია არაა საჭირო. გახსენით **Builds** და **Tests** დაფაზე, რათა მონაცემები ნახოთ.

## გუნდის ჩართვა

ქეშის მოხვედრები და ანალიტიკა მრავლდება პროექტთან დაკავშირებული ადამიანების რაოდენობის ზრდასთან ერთად. მიიწვიეთ თქვენი გუნდის წევრები ორგანიზაციაში დაფის ანგარიშის პარამეტრებიდან და მოაწყვეთ <.localized_link href="/guides/integrations/authentication/sso">Single Sign-On</.localized_link> (Google, Okta, Microsoft), რათა ახალი წევრების დამატება იყოს ერთი დაწკაპუნება და არა თითოეული პირისთვის `tuist auth login`.
