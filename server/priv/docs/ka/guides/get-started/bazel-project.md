# Bazel პროექტი {#bazel-project}

::: code-group

```text [Agent prompt]
Help me get started with Tuist. Follow the setup at:
https://tuist.dev/en/docs/guides/get-started/bazel-project
```

:::

მიჰყევით ამ გზას, რათა არსებული Bazel სამუშაო სივრცე Tuist-ში ჩართოთ. Tuist აწვდის [Remote Execution API](https://github.com/bazelbuild/remote-apis) კეშს, რომელსაც Bazel უერთდება როგორც დისტანციურ კეშს, და Build Event Service ნაკადს, რომელიც ყოველ ბილდსა და ტესტს დაფის ხილულ მონაცემებად აქცევს.

ქვემოთ მოცემული ყოველი განყოფილება იწყება იმით, თუ რა აკლია დღეს, და შემდეგ გაჩვენებთ ფუნქციას, რომელიც ამ ხარვეზს ავსებს.

## წინაპირობები

- Bazel სამუშაო სივრცე (`WORKSPACE` ან `MODULE.bazel` მის ფესვში) და Bazel თქვენს `PATH`-ზე.
- <.localized_link href="/guides/install-tuist">Tuist-ის ბრძანების სტრიქონის ინტერფეისი</.localized_link>.

## სამუშაო სივრცის შეერთება

> [!NOTE]
> Bazel-ის სამუშაო ნაკადი `tuist init`-ის შიგნით საჭიროებს Tuist CLI-ის იმ ვერსიას, რომელიც მასთან ერთად მოდის. ადრეულ გამოშვებებში `tuist init` არ ჩამოთვლის „Bazel სამუშაო სივრცის ინტეგრირება“-ს როგორც ვარიანტს. გადადით `tuist auth login`-ზე, რასაც მოჰყვება `tuist bazel setup` სამუშაო სივრცის ფესვიდან, რაც ქვემოთ აღწერილ იგივე ნაბიჯებს გაივლის.

Bazel სამუშაო სივრცის ფესვიდან გაუშვით `tuist init`. Tuist აღმოაჩენს `WORKSPACE` / `MODULE.bazel`-ს და გთავაზობთ **Bazel სამუშაო სივრცის ინტეგრირება**. გაიარეთ ავთენტიკაცია ბრაუზერში და აირჩიეთ ანგარიში, რომელმაც უნდა ფლობდეს პროექტს.

```bash
tuist init
```

თუ ამას კოდირების აგენტით ან სკრიპტით აკეთებთ, ჯერ გაუშვით `tuist auth login` (ბრაუზერის ნაკადი ელოდება Enter-ის დაჭერას), შემდეგ კი გამოიყენეთ არაინტერაქტიული ფორმა:

```bash
tuist init --build-system bazel --name <project-handle> --account <account>
```

init-ის დასრულებისას Tuist:

1. წერს `tuist.toml`-ს სამუშაო სივრცის ფესვში პროექტის handle-ით.
2. წერს `.bazelrc.tuist`-ს თქვენი `.bazelrc`-ის გვერდით, მიერთებულს უახლოეს Tuist კეშის რეგიონთან და ავთენტიფიცირებულს სამუშაო სივრცისთვის ცალკეული credential helper-ის მეშვეობით.
3. ამატებს `try-import %workspace%/.bazelrc.tuist` ხაზს თქვენს `.bazelrc`-ში.

დააკომიტეთ `try-import` ხაზი. ის იდენტურია ყოველ მანქანაზე. დაამატეთ `.bazelrc.tuist` თქვენს `.gitignore`-ში. credential helper-ის გზა მომხმარებლის მიხედვითაა, ხოლო კეშის რეგიონი — ადგილმდებარეობის მიხედვით, ამიტომ ის არ უნდა გააზიაროთ.

ქვემოთ მოცემული ყველაფერი ავტომატურად ჩაირთვება, როგორც კი სამუშაო სივრცე შეერთდება.

## დისტანციური კეში

Bazel-ის საკუთარი ადგილობრივი დისკის კეში მდებარეობს `~/.cache/bazel`-ში (ან იქ, სადაც `--disk_cache` მიუთითებს). ერთი დეველოპერის მანქანაზე კეშის მოხვედრა სხვებს არ ეხება, ხოლო CI სამუშაო კონტეინერები ყოველ გაშვებაზე ცარიელი კეშიდან იწყებენ.

Bazel-ის [Remote Execution API](https://github.com/bazelbuild/remote-apis) არის პროტოკოლი იმავე კეშის გასაფართოებლად საერთო წერტილამდე. Tuist-ს ეს პროტოკოლი ესმის. როგორც კი `.bazelrc.tuist` ადგილზე იქნება, Bazel გამოტოვებს იმ მოქმედებებს, რომელთა შედეგები უკვე საერთო კეშშია, და მათ ნაცვლად ჩამოტვირთავს. ერთი მანქანის ნამუშევარი სარგებელს ანიჭებს ყოველ სხვა მანქანას, რომელიც იმავე რევიზიას აგებს.

შეამოწმეთ ორი სუფთა ბილდით იმავე რევიზიაზე (ადგილობრივად, ან ერთი ადგილობრივი + ერთი CI):

```bash
bazel clean
bazel build //...
```

მეორე გაშვების შეჯამება უნდა აჩვენებდეს კეშის მოხვედრებს. გახსენით **კეში** დაფაზე, რათა დროთა განმავლობაში მოხვედრის მაჩვენებლები ნახოთ.

## ბილდისა და ტესტების ანალიტიკა

Bazel-ის ბილდის მოვლენათა ნაკადი და თითოეული ტესტის XML ანგარიშები გამოიცემა თითოეული გამოძახებისას. მიზნების დონეზე ხანგრძლივობების შედარება ერთი კვირის განმავლობაში, ან იმ ტესტის აღმოჩენა, რომელიც რამდენიმე CI გაშვების განმავლობაში არასტაბილური გახდა, ნიშნავს ამ მოვლენების სადღაც შეგროვებასა და აგრეგაციას.

Build Event Service პროტოკოლი, რომელსაც Bazel უკვე ასხივებს, ზუსტად ამისთვის არის შექმნილი. `.bazelrc.tuist`, რომელიც `tuist init`-მ ჩაწერა, აკონფიგურირებს BES ნაკადს Tuist-ის მიმართ, ამიტომ ბილდისა და ტესტების ანალიტიკა შემდეგი `bazel build`-ისა და `bazel test`-ის დროს დაიწყებს დინებას. არაფერი დამატებითი კონფიგურაცია არ არის საჭირო. გახსენით **ბილდები** და **ტესტები** დაფაზე, რათა მონაცემები ნახოთ.

## გუნდის ჩართვა

კეშის მოხვედრები და ანალიტიკა მრავლდება პროექტთან დაკავშირებული ადამიანების რაოდენობის ზრდასთან ერთად. მიიწვიეთ თქვენი გუნდის წევრები ორგანიზაციაში დაფის ანგარიშის პარამეტრებიდან და დააყენეთ <.localized_link href="/guides/integrations/authentication/sso">Single Sign-On</.localized_link> (Google, Okta, Microsoft), რათა დარეგისტრება იყოს ერთი დაწკაპუნება და არა თითოეული ადამიანისთვის `tuist auth login`.
