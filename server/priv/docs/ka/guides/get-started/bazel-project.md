# Bazel-ის პროექტი {#bazel-project}

::: code-group

Help me get started with Tuist. Follow the setup at:
https://tuist.dev/en/docs/guides/get-started/bazel-project

მიჰყევით ამ გზას, რათა არსებული Bazel-ის სამუშაო სივრცე Tuist-ში ჩართოთ. Tuist წარმოადგენს [Remote Execution API](https://github.com/bazelbuild/remote-apis) ქეშს, რომელსაც Bazel უკავშირდება როგორც დისტანციურ ქეშს, და Build Event Service ნაკადს, რომელიც ყოველ ბილდსა და ტესტს დაფაზე ხილულ მონაცემებად აქცევს. იმის შესახებ, თუ რას სძენს Tuist Bazel-ს, იხილეთ [Bazel with Tuist](https://tuist.dev/build-systems/bazel). თუ სხვა Bazel-ის პროვაიდერიდან გადადიხართ, ცვლილებებს მოიცავს შედარებები: [BuildBuddy](https://tuist.dev/compare/buildbuddy) და [EngFlow](https://tuist.dev/compare/engflow).

ქვემოთ მოცემული ყოველი განყოფილება იწყება იმის აღწერით, რაც დღეს აკლია, და შემდეგ გაჩვენებთ ფუნქციას, რომელიც ამ ნაკლოვანებას ავსებს.

## წინაპირობები

- Bazel-ის სამუშაო სივრცე (მის ძირში `WORKSPACE` ან `MODULE.bazel`) და Bazel თქვენს `PATH`-ზე.
- <.localized_link href="/guides/install-tuist">Tuist-ის კომანდური ხაზის ინტერფეისი</.localized_link>.

## სამუშაო სივრცის დაკავშირება

Bazel-ის სამუშაო სივრცის ძირიდან გაუშვით `tuist init`. Tuist ამოიცნობს `WORKSPACE` / `MODULE.bazel`-ს და გთავაზობთ **Bazel-ის სამუშაო სივრცის ინტეგრაციას**. გაიარეთ ავტორიზაცია ბრაუზერში და აირჩიეთ ანგარიში, რომელმაც უნდა ფლობდეს პროექტს.

```bash
tuist init
```

თუ ამას კოდირების აგენტით ან სკრიპტით აკეთებთ, ჯერ გაუშვით `tuist auth login` (ბრაუზერის ნაკადი ელოდება Enter-ის დაჭერას), შემდეგ კი გამოიყენეთ არაინტერაქტიული ფორმა:

```bash
tuist init --build-system bazel --name <project-handle> --account <account>
```

init-ის დასრულებისას Tuist:

1. წერს `tuist.toml`-ს სამუშაო სივრცის ძირში პროექტის handle-ით.
2. წერს `.bazelrc.tuist`-ს თქვენი `.bazelrc`-ის გვერდით, მიერთებულს უახლოეს Tuist-ის ქეშის რეგიონთან და ავტორიზებულს სამუშაო სივრცეზე მორგებული credential helper-ის მეშვეობით.
3. ამატებს `try-import %workspace%/.bazelrc.tuist` ხაზს თქვენს `.bazelrc`-ში.

დააკომიტეთ `try-import` ხაზი. ის იდენტურია ყველა მანქანაზე. დაამატეთ `.bazelrc.tuist` თქვენს `.gitignore`-ში. Credential helper-ის გზა მომხმარებელზეა დამოკიდებული, ხოლო ქეშის რეგიონი — ადგილმდებარეობაზე, ამიტომ ის არ უნდა გაზიარდეს.

ქვემოთ მოცემული ყველაფერი ავტომატურად ჩაირთვება სამუშაო სივრცის დაკავშირების შემდეგ.

## დისტანციური ქეში

Bazel-ის საკუთარი ლოკალური დისკის ქეში მდებარეობს `~/.cache/bazel`-ში (ან იქ, სადაც `--disk_cache` მიუთითებს). ერთი დეველოპერის მანქანაზე ქეშის მოხვედრა სხვებს არ ეხება, ხოლო CI-ის ჯობის კონტეინერები ყოველ გაშვებაზე ცარიელი ქეშიდან იწყებენ.

Bazel-ის [Remote Execution API](https://github.com/bazelbuild/remote-apis) არის პროტოკოლი იმავე ქეშის გასაფართოებლად საერთო წერტილამდე. Tuist მას ესაუბრება. როგორც კი `.bazelrc.tuist` ადგილზე იქნება, Bazel გამოტოვებს იმ მოქმედებებს, რომელთა შედეგები უკვე საერთო ქეშშია, და ნაცვლად მათ ჩამოტვირთავს. ერთი მანქანის ნამუშევარი სარგებელს მოუტანს ყველა სხვა მანქანას, რომელიც იმავე რევიზიას აგებს.

შეამოწმეთ ორი სუფთა ბილდით იმავე რევიზიისთვის (ლოკალურად, ან ერთი ლოკალური + ერთი CI):

```bash
bazel clean
bazel build //...
```

მეორე გაშვების შეჯამება უნდა აჩვენებდეს ქეშის მოხვედრებს. დაფაზე გახსენით **Cache**, რათა დროთა განმავლობაში მოხვედრის მაჩვენებლები ნახოთ.

## ბილდისა და ტესტების ინსაიტები

Bazel-ის ბილდის მოვლენათა ნაკადი და თითოეული ტესტის XML ანგარიშები გამოიცემა თითოეული გამოძახებისას. მიზნების დონეზე ხანგრძლივობების შედარება ერთი კვირის განმავლობაში, ან ტესტის აღმოჩენა, რომელიც რამდენიმე CI-ის გაშვების განმავლობაში არასტაბილური გახდა, ნიშნავს ამ მოვლენების სადღაც შეგროვებასა და აგრეგაციას.

Build Event Service პროტოკოლი, რომელსაც Bazel უკვე ასხივებს, ზუსტად ამისთვისაა განკუთვნილი. `.bazelrc.tuist`, რომელიც `tuist init`-მ ჩაწერა, ასწორებს BES ნაკადს Tuist-ის მიმართ, ამიტომ ბილდისა და ტესტების ინსაიტები მოედინება შემდეგ `bazel build`-სა და `bazel test`-ზე. დამატებითი კონფიგურაცია არ არის საჭირო. დაფაზე გახსენით **Builds** და **Tests**, რათა მონაცემები ნახოთ.

## გუნდის ჩართვა

ქეშის მოხვედრები და ინსაიტები მრავლდება პროექტთან დაკავშირებული ადამიანების რაოდენობის ზრდასთან ერთად. დაფაზე ანგარიშის პარამეტრებიდან მიიწვიეთ თქვენი გუნდის წევრები ორგანიზაციაში და დააყენეთ <.localized_link href="/guides/integrations/authentication/sso">Single Sign-On</.localized_link> (Google, Okta, Microsoft), რათა დარეგისტრირება იყოს ერთი დაწკაპუნება და არა თითოეული ადამიანისთვის `tuist auth login`.
