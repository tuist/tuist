# Bazel-ის პროექტი {#bazel-project}

::: code-group

```text [Agent prompt]
Help me get started with Tuist. Follow the setup at:
https://tuist.dev/en/docs/guides/get-started/bazel-project
```

მიჰყევით ამ გზას, რათა არსებული Bazel-ის სამუშაო სივრცე Tuist-ში ჩართოთ. Tuist უზრუნველყოფს [Remote Execution API](https://github.com/bazelbuild/remote-apis) ქეშს, რომელსაც Bazel უერთდება როგორც დისტანციურ ქეშს, და Build Event Service ნაკადს, რომელიც ყოველ ბილდსა და ტესტს დაფაზე ხილულ მონაცემებად აქცევს.

ქვემოთ მოცემული ყოველი განყოფილება იწყება იმით, თუ რა აკლია დღეს, შემდეგ კი გაჩვენებთ ფუნქციას, რომელიც ამ ნაკლოვანებას აღმოფხვრის.

## წინაპირობები

- Bazel-ის სამუშაო სივრცე (მის ფესვში `WORKSPACE` ან `MODULE.bazel`) და Bazel თქვენს `PATH`-ზე.
- <.localized_link href="/guides/install-tuist">Tuist-ის ბრძანების ხაზის ინტერფეისი</.localized_link>.

## სამუშაო სივრცის დაკავშირება

Bazel-ის სამუშაო სივრცის ფესვიდან შეასრულეთ `tuist init`. Tuist ამოიცნობს `WORKSPACE` / `MODULE.bazel`-ს და გთავაზობთ **Bazel-ის სამუშაო სივრცის ინტეგრაციას**. გაიარეთ ავტორიზაცია ბრაუზერში და აირჩიეთ ანგარიში, რომელსაც უნდა ეკუთვნოდეს პროექტი.

```bash
tuist init
```

თუ ამ პროცესს კოდირების აგენტის ან სკრიპტის საშუალებით მართავთ, ჯერ შეასრულეთ `tuist auth login` (ბრაუზერის ნაკადი ელოდება Enter-ის დაჭერას), შემდეგ კი გამოიყენეთ არაინტერაქტიული ფორმა:

```bash
tuist init --build-system bazel --name <project-handle> --account <account>
```

init-ის დასრულებისას Tuist:

1. წერს `tuist.toml`-ს სამუშაო სივრცის ფესვში პროექტის handle-ით.
2. წერს `.bazelrc.tuist`-ს თქვენი `.bazelrc`-ის გვერდით, მიერთებულს Tuist-ის ქეშის უახლოეს რეგიონთან და ავტორიზებულს სამუშაო სივრცეზე მორგებული credential helper-ის საშუალებით.
3. ამატებს `try-import %workspace%/.bazelrc.tuist` ხაზს თქვენს `.bazelrc`-ში.

დააკომიტეთ `try-import` ხაზი. ის იდენტურია ყოველ მანქანაზე. დაამატეთ `.bazelrc.tuist` თქვენს `.gitignore`-ში. credential helper-ის გზა მომხმარებელზეა დამოკიდებული, ხოლო ქეშის რეგიონი — ადგილმდებარეობაზე, ამიტომ ის არ უნდა გაზიარდეს.

ქვემოთ მოცემული ყველაფერი ავტომატურად ჩაირთვება სამუშაო სივრცის დაკავშირების შემდეგ.

## დისტანციური ქეში

Bazel-ის საკუთარი ლოკალური დისკის ქეში მდებარეობს `~/.cache/bazel`-ში (ან იქ, სადაც `--disk_cache` მიუთითებს). ერთი დეველოპერის მანქანაზე ქეშის მოხვედრა სხვებს არ ეხება, ხოლო CI-ის სამუშაო კონტეინერები ყოველ გაშვებაზე ცარიელი ქეშიდან იწყებენ.

Bazel-ის [Remote Execution API](https://github.com/bazelbuild/remote-apis) არის პროტოკოლი იმავე ქეშის გაზიარებულ წერტილამდე გასავრცელებლად. Tuist „ლაპარაკობს“ ამ პროტოკოლზე. როგორც კი `.bazelrc.tuist` ადგილზე იქნება, Bazel გამოტოვებს იმ მოქმედებებს, რომელთა გამომავალი მონაცემები უკვე არის გაზიარებულ ქეშში, და ნაცვლად ამისა მათ ჩამოტვირთავს. ერთი მანქანის ნამუშევარი სარგებელს მოუტანს ყოველ სხვა მანქანას, რომელიც იმავე რევიზიას აგებს.

შეამოწმეთ ორი სუფთა ბილდით იმავე რევიზიისთვის (ლოკალურად, ან ერთი ლოკალური + ერთი CI):

```bash
bazel clean
bazel build //...
```

მეორე გაშვების შეჯამება უნდა აჩვენებდეს ქეშის მოხვედრებს. გახსენით **Cache** დაფაზე, რათა ნახოთ მოხვედრის მაჩვენებლები დროთა განმავლობაში.

## ბილდისა და ტესტების ანალიტიკა

Bazel-ის ბილდის მოვლენათა ნაკადი და თითოეული ტესტის XML ანგარიშები გამოიცემა ყოველი გამოძახებისას. მიზნის დონეზე ხანგრძლივობების შედარება კვირის განმავლობაში, ან ტესტის აღმოჩენა, რომელიც რამდენიმე CI გაშვების განმავლობაში არასტაბილური გახდა, ნიშნავს ამ მოვლენების სადმე შეგროვებასა და აგრეგირებას.

Build Event Service პროტოკოლი, რომელსაც Bazel უკვე ასხივებს, ზუსტად ამისთვის არის შექმნილი. `.bazelrc.tuist`, რომელიც `tuist init`-მ ჩაწერა, აკონფიგურირებს BES ნაკადს Tuist-ის მიმართ, ამიტომ ბილდისა და ტესტების ანალიტიკა დაიწყებს ნაკადს შემდეგ `bazel build`-ზე და `bazel test`-ზე. დამატებითი კონფიგურაცია არ არის საჭირო. გახსენით **Builds** და **Tests** დაფაზე, რათა ნახოთ მონაცემები.

## გუნდის ჩართვა

ქეშის მოხვედრები და ანალიტიკა მრავლდება პროექტთან დაკავშირებული ადამიანების რაოდენობის ზრდასთან ერთად. მიიწვიეთ თქვენი გუნდის წევრები ორგანიზაციაში დაფის ანგარიშის პარამეტრებიდან და დააყენეთ <.localized_link href="/guides/integrations/authentication/sso">Single Sign-On</.localized_link> (Google, Okta, Microsoft), რათა ახალი წევრის დამატება იყოს ერთი დაწკაპუნება და არა თითოეული პირისთვის `tuist auth login`.
