# Bazel-ის პროექტი {#bazel-project}

::: code-group

```text [Agent prompt]
Help me get started with Tuist. Follow the setup at:
https://tuist.dev/en/docs/guides/get-started/bazel-project
```

:::

ამ გზას მიჰყევით, რათა არსებული Bazel-ის სამუშაო სივრცე Tuist-ში ჩართოთ. Tuist აწვდის [Remote Execution API](https://github.com/bazelbuild/remote-apis)-ის ქეშს, რომელსაც Bazel უერთდება როგორც დისტანციურ ქეშს, და Build Event Service ნაკადს, რომელიც ყოველ ბილდსა და ტესტს დაფაზე ხილულ მონაცემებად აქცევს. იმის სანახავად, თუ რას სძენს Tuist Bazel-ს, იხილეთ [Bazel with Tuist](https://tuist.dev/build-systems/bazel). თუ სხვა Bazel-ის პროვაიდერიდან გადადიხართ, ცვლილებებს აღწერს შედარებები [BuildBuddy](https://tuist.dev/compare/buildbuddy)-თან და [EngFlow](https://tuist.dev/compare/engflow)-თან.

ქვემოთ მოცემული ყოველი განყოფილება იწყება იმის აღწერით, თუ რა აკლია დღეს, შემდეგ კი გაგივლით ფუნქციას, რომელიც ამ ნაკლოვანებას ავსებს.

## წინაპირობები

- Bazel-ის სამუშაო სივრცე (მის ფესვში `WORKSPACE` ან `MODULE.bazel`) და Bazel თქვენს `PATH`-ზე.
- <.localized_link href="/guides/install-tuist">Tuist-ის ბრძანების ხაზის ინტერფეისი</.localized_link>.

## სამუშაო სივრცის დაკავშირება

Bazel-ის სამუშაო სივრცის ფესვიდან გაუშვით `tuist init`. Tuist ამოიცნობს `WORKSPACE` / `MODULE.bazel`-ს და გთავაზობთ **Bazel-ის სამუშაო სივრცის ინტეგრაციას**. გაიარეთ ავთენტიკაცია ბრაუზერში და აირჩიეთ ანგარიში, რომელსაც უნდა ეკუთვნოდეს პროექტი.

```bash
tuist init
```

თუ ამას კოდირების აგენტით ან სკრიპტით აკეთებთ, ჯერ გაუშვით `tuist auth login` (ბრაუზერის ნაკადი Enter-ის დაჭერას ელოდება), შემდეგ კი გამოიყენეთ არაინტერაქტიული ფორმა:

```bash
tuist init --build-system bazel --name <project-handle> --account <account>
```

init-ის დასრულებისას Tuist:

1. წერს `tuist.toml`-ს სამუშაო სივრცის ფესვში პროექტის სახელით.
2. წერს `.bazelrc.tuist`-ს თქვენი `.bazelrc`-ის გვერდით, შეერთებულს უახლოეს Tuist-ის ქეშის რეგიონთან და ავთენტიფიცირებულს სამუშაო სივრცისთვის განკუთვნილი რწმუნების დამხმარე საშუალებით.
3. ამატებს `try-import %workspace%/.bazelrc.tuist` ხაზს თქვენს `.bazelrc`-ში.

დააკომიტეთ `try-import` ხაზი. ის იდენტურია ყოველ მანქანაზე. დაამატეთ `.bazelrc.tuist` თქვენს `.gitignore`-ში. რწმუნების დამხმარე საშუალების გზა მომხმარებლის მიხედვითაა, ხოლო ქეშის რეგიონი — ადგილმდებარეობის მიხედვით, ამიტომ ის არ უნდა გაზიარდეს.

ქვემოთ მოცემული ყველაფერი ავტომატურად ჩაირთვება, როგორც კი სამუშაო სივრცე დაკავშირდება.

## დისტანციური ქეში

Bazel-ის საკუთარი ლოკალური დისკური ქეში მდებარეობს `~/.cache/bazel`-ში (ან იქ, სადაც `--disk_cache` მიუთითებს). ერთი დეველოპერის მანქანაზე ქეშის მოხვედრა სხვებს არ ეხება, ხოლო CI-ის ჯობის კონტეინერები ყოველ გაშვებაზე ცარიელი ქეშიდან იწყებენ.

Bazel-ის [Remote Execution API](https://github.com/bazelbuild/remote-apis) არის პროტოკოლი იმავე ქეშის გასაფართოებლად საერთო წერტილამდე. Tuist მას ესაუბრება. როგორც კი `.bazelrc.tuist` ადგილზე იქნება, Bazel გამოტოვებს იმ მოქმედებებს, რომელთა გამოსავალი უკვე საერთო ქეშშია, და მათ ნაცვლად ჩამოტვირთავს. ერთი მანქანის ნამუშევარი სარგებლობს ყოველ სხვა მანქანას, რომელიც იმავე რევიზიას აგებს.

შეამოწმეთ ორი სუფთა ბილდით იმავე რევიზიის მიმართ (ლოკალურად, ან ერთი ლოკალური + ერთი CI):

```bash
bazel clean
bazel build //...
```

მეორე გაშვების შეჯამება უნდა აჩვენებდეს ქეშის მოხვედრებს. დაფაზე გახსენით **Cache**, რათა დროში მოხვედრის მაჩვენებლები ნახოთ.

## ბილდისა და ტესტების ანალიტიკა

Bazel-ის ბილდის მოვლენათა ნაკადი და თითოეული ტესტის XML ანგარიშები გამოიცემა ყოველი გამოძახებისას. მიზნების დონეზე ხანგრძლივობების შედარება კვირის განმავლობაში, ან ტესტის აღმოჩენა, რომელიც რამდენიმე CI-ის გაშვების განმავლობაში არასტაბილური გახდა, ნიშნავს ამ მოვლენების სადმე შეგროვებასა და აგრეგაციას.

Build Event Service-ის პროტოკოლი, რომელსაც Bazel უკვე ასხივებს, ზუსტად ამისთვისაა შექმნილი. `.bazelrc.tuist`, რომელიც `tuist init`-მ დაწერა, BES-ის ნაკადს Tuist-ის მიმართ აკონფიგურირებს, ამიტომ ბილდისა და ტესტების ანალიტიკა მომდევნო `bazel build` და `bazel test`-ზე დაიწყებს დინებას. დამატებითი კონფიგურაცია არ არის საჭირო. დაფაზე გახსენით **Builds** და **Tests**, რათა მონაცემები ნახოთ.

## გუნდის ჩართვა

ქეშის მოხვედრები და ანალიტიკა მრავლდება პროექტთან დაკავშირებული ადამიანების რაოდენობის ზრდასთან ერთად. მოიწვიეთ თქვენი გუნდის წევრები ორგანიზაციაში დაფის ანგარიშის პარამეტრებიდან და დააყენეთ <.localized_link href="/guides/integrations/authentication/sso">Single Sign-On</.localized_link> (Google, Okta, Microsoft), რათა დარეგისტრირება იყოს ერთი დაწკაპუნება და არა თითოეული ადამიანისთვის `tuist auth login`.
