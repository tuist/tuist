# Bazel-ის პროექტი {#bazel-project}

::: code-group

Help me get started with Tuist. Follow the setup at:
https://tuist.dev/en/docs/guides/get-started/bazel-project

ამ გზას მიჰყევით, რომ არსებული Bazel-ის სამუშაო სივრცე Tuist-ში ჩართოთ. Tuist აწვდის [Remote Execution API](https://github.com/bazelbuild/remote-apis) კეშს, რომელსაც Bazel უერთდება როგორც დისტანციურ კეშს, და Build Event Service ნაკადს, რომელიც ყოველ ბილდსა და ტესტს დაფაზე ხილულ მონაცემებად აქცევს. იმის შესახებ, თუ რას სძენს Tuist Bazel-ს, იხილეთ [Bazel with Tuist](https://tuist.dev/build-systems/bazel). თუ სხვა Bazel-ის პროვაიდერიდან გადმოდიხართ, ცვლილებებს მოიცავს [BuildBuddy](https://tuist.dev/compare/buildbuddy)-ისა და [EngFlow](https://tuist.dev/compare/engflow)-ის შედარებები.

ქვემოთ მოცემული ყოველი განყოფილება იწყება იმით, თუ რა აკლია დღეს, და შემდეგ გაჩვენებთ ფუნქციას, რომელიც ამ ნაკლოვანებას აღმოფხვრის.

## წინაპირობები

- Bazel-ის სამუშაო სივრცე (მის ფესვში `WORKSPACE` ან `MODULE.bazel`) და Bazel თქვენს `PATH`-ზე.
- <.localized_link href="/guides/install-tuist">Tuist-ის ბრძანების ინტერფეისი</.localized_link>.

## სამუშაო სივრცის დაკავშირება

Bazel-ის სამუშაო სივრცის ფესვიდან გაუშვით `tuist init`. Tuist პოულობს `WORKSPACE` / `MODULE.bazel`-ს და გთავაზობთ **Bazel-ის სამუშაო სივრცის ინტეგრაციას**. გაიარეთ ავთენტიკაცია ბრაუზერში და აირჩიეთ ანგარიში, რომელმაც უნდა ფლობდეს პროექტს.

```bash
tuist init
```

თუ ამას კოდირების აგენტით ან სკრიპტით აკეთებთ, ჯერ გაუშვით `tuist auth login` (ბრაუზერის ნაკადი ელოდება Enter-ის დაჭერას), შემდეგ გამოიყენეთ არაინტერაქტიული ფორმა:

```bash
tuist init --build-system bazel --name <project-handle> --account <account>
```

init-ის დასრულებისას Tuist:

1. წერს `tuist.toml`-ს სამუშაო სივრცის ფესვში პროექტის სახელით.
2. წერს `.bazelrc.tuist`-ს თქვენი `.bazelrc`-ის გვერდით, შეერთებულს უახლოეს Tuist-ის კეშის რეგიონთან და ავთენტიფიცირებულს სამუშაო სივრცისთვის განკუთვნილი ქრედენშიალის დამხმარე საშუალებით.
3. ამატებს `try-import %workspace%/.bazelrc.tuist` ხაზს თქვენს `.bazelrc`-ში.

დააკომიტეთ `try-import` ხაზი. ის იდენტურია ყოველ მანქანაზე. დაამატეთ `.bazelrc.tuist` თქვენს `.gitignore`-ში. ქრედენშიალის დამხმარე საშუალების გზა მომხმარებლის მიხედვითაა, ხოლო კეშის რეგიონი — ადგილმდებარეობის მიხედვით, ამიტომ ის არ უნდა გაიზიაროთ.

ქვემოთ მოცემული ყველაფერი ავტომატურად ჩაირთვება, როგორც კი სამუშაო სივრცე დაკავშირდება.

## დისტანციური კეში

Bazel-ის საკუთარი ადგილობრივი დისკის კეში მდებარეობს `~/.cache/bazel`-ში (ან იქ, სადაც `--disk_cache` მიუთითებს). ერთი დეველოპერის მანქანაზე კეშის მოხვედრა სხვებს არ ეხება, ხოლო CI-ის სამუშაოს კონტეინერები ყოველ გაშვებაზე ცარიელი კეშიდან იწყებენ.

Bazel-ის [Remote Execution API](https://github.com/bazelbuild/remote-apis) არის პროტოკოლი იმავე კეშის გასაფართოებლად საერთო წერტილამდე. Tuist მას „ლაპარაკობს“. როგორც კი `.bazelrc.tuist` ადგილზე იქნება, Bazel გამოტოვებს იმ მოქმედებებს, რომელთა შედეგები უკვე საერთო კეშშია, და მათ ჩამოტვირთავს. ერთი მანქანის ნამუშევარი სარგებელს ანიჭებს ყოველ სხვა მანქანას, რომელიც იმავე რევიზიას ბილდავს.

შეამოწმეთ ორი სუფთა ბილდით იმავე რევიზიისთვის (ადგილობრივად, ან ერთი ადგილობრივი + ერთი CI):

```bash
bazel clean
bazel build //...
```

მეორე გაშვების შეჯამებამ უნდა აჩვენოს კეშის მოხვედრები. გახსენით **Cache** დაფაზე, რათა დროთა განმავლობაში მოხვედრების მაჩვენებლები ნახოთ.

## ბილდისა და ტესტების ანალიტიკა

Bazel-ის ბილდის მოვლენათა ნაკადი და თითოეული ტესტის XML ანგარიშები გამოიცემა ყოველი გამოძახებისას. მიზნის დონეზე ხანგრძლივობების შედარება კვირის განმავლობაში, ან ტესტის აღმოჩენა, რომელიც რამდენიმე CI-ის გაშვების განმავლობაში არასტაბილური გახდა, ნიშნავს ამ მოვლენების სადმე შეგროვებასა და აგრეგაციას.

Build Event Service პროტოკოლი, რომელსაც Bazel უკვე ასხივებს, ზუსტად ამისთვისაა შექმნილი. `.bazelrc.tuist`, რომელიც `tuist init`-მ ჩაწერა, აკონფიგურირებს BES ნაკადს Tuist-ის მიმართ, ამიტომ ბილდისა და ტესტების ანალიტიკა დაიწყებს დინებას შემდეგ `bazel build` და `bazel test`-ზე. არაფერი დამატებითი არ არის საკონფიგურაციო. გახსენით **Builds** და **Tests** დაფაზე, რათა მონაცემები ნახოთ.

## გუნდის ჩართვა

კეშის მოხვედრები და ანალიტიკა მრავლდება პროექტთან დაკავშირებული ადამიანების რაოდენობის ზრდასთან ერთად. მიიწვიეთ თქვენი გუნდის წევრები ორგანიზაციაში დაფის ანგარიშის პარამეტრებიდან და დააყენეთ <.localized_link href="/guides/integrations/authentication/sso">Single Sign-On</.localized_link> (Google, Okta, Microsoft), რათა დარეგისტრება იყოს ერთი დაწკაპუნება და არა თითოეული პირისთვის `tuist auth login`.
