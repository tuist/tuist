# Bazel პროექტი {#bazel-project}

::: code-group

```text [Agent prompt]
Help me get started with Tuist. Follow the setup at:
https://tuist.dev/en/docs/guides/get-started/bazel-project
```

მიჰყევით ამ გზას, რათა არსებული Bazel სამუშაო სივრცე Tuist-ში ჩართოთ. Tuist უზრუნველყოფს [Remote Execution API](https://github.com/bazelbuild/remote-apis) ქეშს, რომელსაც Bazel უკავშირდება როგორც დისტანციურ ქეშს, და Build Event Service ნაკადს, რომელიც ყოველ აგებასა და ტესტს ხილულ მონაცემებად აქცევს დაშბორდზე.

ქვემოთ მოცემული ყოველი განყოფილება იწყება იმის აღწერით, თუ რა აკლია დღეს, და შემდეგ გაგივლით ფუნქციას, რომელიც ამ ნაკლოვანებას აღმოფხვრის.

## წინაპირობები

- Bazel სამუშაო სივრცე (`WORKSPACE` ან `MODULE.bazel` მის ფესვში) და Bazel თქვენს `PATH`-ზე.
- <.localized_link href="/guides/install-tuist">Tuist ბრძანების ხაზის ინტერფეისი</.localized_link> .

## სამუშაო სივრცის დაკავშირება

> [!NOTE]
> Bazel სამუშაო ნაკადი `tuist init`-ში საჭიროებს Tuist CLI-ის ვერსიას, რომელიც მასთან ერთად მოდის. ადრეულ გამოცემებში `tuist init` არ ჩამოთვლის „Bazel სამუშაო სივრცის ინტეგრაციას“ როგორც ვარიანტს. გადადით `tuist auth login`-ზე, რასაც მოჰყვება `tuist bazel setup` სამუშაო სივრცის ფესვიდან, რაც იმავე ნაბიჯებს გაგივლით, რაც ქვემოთაა.

Bazel სამუშაო სივრცის ფესვიდან გაუშვით `tuist init`. Tuist აღმოაჩენს `WORKSPACE` / `MODULE.bazel` და გთავაზობთ **Bazel სამუშაო სივრცის ინტეგრაციას**. გაიარეთ ავთენტიკაცია ბრაუზერში და აირჩიეთ ანგარიში, რომელმაც უნდა ფლობდეს პროექტს.

```bash
tuist init
```

თუ ამას კოდირების აგენტით ან სკრიპტით აკეთებთ, ჯერ გაუშვით `tuist auth login` (ბრაუზერის ნაკადი ელოდება Enter-ის დაჭერას), შემდეგ კი გამოიყენეთ არაინტერაქტიული ფორმა:

```bash
tuist init --build-system bazel --name <project-handle> --account <account>
```

როდესაც init დასრულდება, Tuist:

1. წერს `tuist.toml`-ს სამუშაო სივრცის ფესვში პროექტის handle-ით.
2. წერს `.bazelrc.tuist`-ს თქვენი `.bazelrc`-ის გვერდით, მიერთებულს უახლოეს Tuist ქეშის რეგიონთან და ავთენტიფიცირებულს სამუშაო სივრცისთვის ცალკეული credential helper-ის მეშვეობით.
3. ამატებს `try-import %workspace%/.bazelrc.tuist` ხაზს თქვენს `.bazelrc`-ში.

დააკომიტეთ `try-import` ხაზი. ის იდენტურია ყოველ მანქანაზე. დაამატეთ `.bazelrc.tuist` თქვენს `.gitignore`-ში. Credential helper-ის გზა მომხმარებელზეა დამოკიდებული, ხოლო ქეშის რეგიონი — ადგილმდებარეობაზე, ამიტომ ის არ უნდა გაზიარდეს.

ქვემოთ მოცემული ყველაფერი ავტომატურად ჩაირთვება, როგორც კი სამუშაო სივრცე დაკავშირდება.

## დისტანციური ქეში

Bazel-ის საკუთარი ადგილობრივი დისკის ქეში მდებარეობს `~/.cache/bazel`-ში (ან იქ, სადაც `--disk_cache` მიუთითებს). ერთი დეველოპერის მანქანაზე ქეშის მოხვედრა სხვებს არ ეხება, ხოლო CI სამუშაოების კონტეინერები ყოველ გაშვებაზე ცარიელი ქეშიდან იწყებენ.

Bazel-ის [Remote Execution API](https://github.com/bazelbuild/remote-apis) არის პროტოკოლი იმავე ქეშის გასაფართოებლად საერთო წერტილამდე. Tuist მას ესაუბრება. როგორც კი `.bazelrc.tuist` ადგილზე იქნება, Bazel გამოტოვებს მოქმედებებს, რომელთა შედეგები უკვე საერთო ქეშშია, და მათ ნაცვლად ჩამოტვირთავს. ერთი მანქანის ნამუშევარი სარგებელს მოუტანს ყოველ სხვა მანქანას, რომელიც იმავე რევიზიას აგებს.

შეამოწმეთ ორი სუფთა აგებით იმავე რევიზიისთვის (ადგილობრივად, ან ერთი ადგილობრივი + ერთი CI):

```bash
bazel clean
bazel build //...
```

მეორე გაშვების შეჯამება უნდა აჩვენებდეს ქეშის მოხვედრებს. გახსენით **ქეში** დაშბორდზე, რათა დროთა განმავლობაში მოხვედრის მაჩვენებლები ნახოთ.

## აგებისა და ტესტირების ინსაიტები

Bazel-ის აგების მოვლენათა ნაკადი და თითოეული ტესტის XML ანგარიშები გამოიცემა თითოეული გამოძახებისას. მიზნის დონეზე ხანგრძლივობების შედარება კვირის განმავლობაში, ან ტესტის აღმოჩენა, რომელიც რამდენიმე CI გაშვების განმავლობაში არასტაბილური გახდა, ნიშნავს ამ მოვლენების სადმე შეგროვებასა და აგრეგაციას.

Build Event Service პროტოკოლი, რომელსაც Bazel უკვე ასხივებს, ზუსტად ამისთვისაა შექმნილი. `.bazelrc.tuist`, რომელიც `tuist init`-მ დაწერა, BES ნაკადს Tuist-ის მიმართ აკონფიგურირებს, ამიტომ აგებისა და ტესტირების ინსაიტები შემდეგ `bazel build` და `bazel test`-ზე დაიწყებს დინებას. დამატებითი კონფიგურაცია არაა საჭირო. გახსენით **აგებები** და **ტესტები** დაშბორდზე მონაცემების სანახავად.

## გუნდის ჩართვა

ქეშის მოხვედრები და ინსაიტები მრავლდება პროექტთან დაკავშირებული ადამიანების რაოდენობის ზრდასთან ერთად. მიიწვიეთ თქვენი გუნდის წევრები ორგანიზაციაში დაშბორდის ანგარიშის პარამეტრებიდან და დააყენეთ <.localized_link href="/guides/integrations/authentication/sso">Single Sign-On</.localized_link> (Google, Okta, Microsoft), რათა დარეგისტრება იყოს ერთი დაწკაპუნება და არა თითოეული პირისთვის `tuist auth login`.
