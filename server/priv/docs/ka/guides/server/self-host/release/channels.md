# გამოშვების არხები {#release-channels}

Tuist-ის სერვერი და Kura-ს ქეშის სერვერი ვრცელდება GHCR-ის სამი გამოსახულების არხის მეშვეობით, რომლებსაც განსხვავებული სტაბილურობის გარანტიები აქვთ. რეკომენდებული ინსტალაციაა **stable**, რომელიც კვირაში ერთხელ გადაადგილდება: ის არ წინ მიიწევს ყოველ ჯერზე, როცა ფუნქცია ერწყმება `main`-ს, ამიტომ განახლება აღარ ნიშნავს შეუსაბამო ცვლილებების პაკეტის შთანთქმას. ადრეულმა მომხმარებლებმა მაინც შეუძლიათ გაუშვან თითოეული კომიტის ბილდები **canary**-ზე, ხოლო **release candidate** არხი საშუალებას გაძლევთ გამოცადოთ მომავალი ხაზი მანამ, სანამ ის სტაბილური გახდება.

სერვერი და Kura ორივე ერთსა და იმავე კვირეულ მატარებელზე მოძრაობს და ორივე სინქრონულად ემთხვევა <.localized_link href="/cli/release/channels">Tuist CLI-ის გამოშვების გრაფიკს</.localized_link>.

## მიმდინარე გამოშვებები {#live-release-status}

თითოეული კომპონენტის მიმდინარე გამოშვებები ნაჩვენებია ქვემოთ. იხილეთ <.localized_link href="/guides/server/self-host/release/calendar">გამოშვების კალენდარი</.localized_link> მომავალი პერიოდებისა და ბოლო გამოშვებებისთვის, პატჩებისა და ბექპორტების ჩათვლით.

## არხები {#the-channels}

| არხი | ვერსიის ფორმატი | სიხშირე | ადასტურებს `:latest`? |
| --- | --- | --- | --- |
| Canary | `X.Y.0-canary.N` (მაგ., `1.351.0-canary.5`) | ყოველი კომიტი `main`-ზე | არა, მხოლოდ ცალსახა არჩევით |
| Release candidate | `X.Y.0-rc.N` (მაგ., `1.351.0-rc.1`) | ჭრა `main`-დან ყოველ ორშაბათს, ტესტირება ~1 კვირა | არა, მხოლოდ ცალსახა არჩევით |
| Stable | `X.Y.Z` (მაგ., `1.350.2`, `1.351.0`) | წინ წაწევა ყოველ ორშაბათს სუფთა ტესტირების შემდეგ | **დიახ** |

Canary-ისა და release-candidate-ის ბილდები ქვეყნდება როგორც GitHub-ის წინასწარი გამოშვებები. ნებისმიერი ინსტრუმენტი, რომელიც გამორიცხავს წინასწარ გამოშვებებს `:latest`-ის დროს, გამოტოვებს მათ, ამიტომ მათზე მოხვდებით მხოლოდ მაშინ, როცა ცალსახად მოითხოვთ.

### Canary {#canary}

ყოველი კომიტი `main`-ზე აქვეყნებს canary-ის გამოსახულებას. Canary ყოველთვის წარმოადგენს **შემდეგ გამოუქვეყნებელ მინორულ ვერსიას**: როგორც კი ხაზი გამოიჭრება გამოშვებისთვის, `main` გადადის შემდეგ მინორულ ვერსიაზე (მაგალითად, `1.350.0-canary.42`-დან `1.351.0-canary.1`-მდე). Canary არის შესაფერისი არხი სტეიჯინგის გარემოსთვის, რომელიც ასახავს პროდაქშენს და გაძლევთ რეგრესიების შესახებ უადრეს შესაძლო სიგნალს, ან საშუალებას გაძლევთ შეამოწმოთ, რომ თქვენს მიერ შეტყობინებულმა გამოსწორებამ მოსალოდნელად იმუშაოს, სანამ ის stable-ს მიაღწევს.

```
ghcr.io/tuist/tuist:1.351.0-canary.5
ghcr.io/tuist/kura:0.55.0-canary.5
```

### Release candidate {#release-candidate}

როდესაც მინორული ვერსია მზადაა გამოშვებისთვის, მისი ხაზი იყინება დაცულ `releases/server-<major>.<minor>.x` (ან `releases/kura-<major>.<minor>.x`) ბრენჩზე და ქვეყნდება როგორც `X.Y.0-rc.1`. ხაზი არის ფუნქციურად გაყინული; მასზე მხოლოდ კრიტიკული გამოსწორებები და რეგრესიები აირჩევა, და თითოეული მიღებული გამოსწორება აიტერაციებს release candidate-ს (`-rc.2`, `-rc.3` და ა.შ.). სუფთა ტესტირების პერიოდის დასრულების შემდეგ, ხაზი წინ იწევა stable-ზე შემდეგ ორშაბათს.

```
ghcr.io/tuist/tuist:1.351.0-rc.1
ghcr.io/tuist/kura:0.55.0-rc.1
```

### Stable {#stable}

Stable არის რეკომენდებული არხი და ის, რომელზეც ყველა დოკუმენტაცია მიუთითებს. სტაბილური მინორული ვერსია (`X.Y.0`) ქვეყნდება მხოლოდ მაშინ, როცა release candidate-მა სუფთად გაიარა ტესტირება, და ის **არ** წინ მიიწევს, როცა ახალი ფუნქციები ერწყმება `main`-ს. პატჩები (`X.Y.1`, `X.Y.2` და ა.შ.) სტაბილურ ხაზზე შეიცავს მხოლოდ ბექპორტირებულ გამოსწორებებს, არასდროს ახალ ფუნქციებს. `:latest` გადაადგილდება მხოლოდ სტაბილურად წინ წაწევისას.

```
ghcr.io/tuist/tuist:1.351.0
ghcr.io/tuist/kura:0.55.0
ghcr.io/tuist/tuist:latest
ghcr.io/tuist/kura:latest
```

## ორშაბათის მატარებელი {#the-monday-train}

ყოველ ორშაბათს 06:00 UTC-ზე, სამი კომპონენტის გამოშვების მატარებლები სინქრონულად იწყებენ მუშაობას:

1. **06:00 UTC** — წინ წაწევის ჯობები იწყება. თითოეული წინ წააწევს უახლეს release-candidate ხაზს, რომელიც ჯერ არ არის სტაბილური (ჩვეულებრივ, წინა ორშაბათს გამოჭრილ ხაზს) და არაფერს აკეთებს, თუ ასეთი არ არსებობს.
2. **ყოველი წინ წაწევის დასრულების შემდეგ** — release-candidate ჯობი ჭრის შემდეგ ხაზს `main`-დან, ამიტომ ახლად გამოჭრილი ხაზი არასდროს წინ იწევა იმავე გაშვებაში.

წარუმატებელი წინ წაწევა აჩერებს ჭრას: მხოლოდ უმაღლესი release-candidate ხაზი უახლესი stable-ის ზემოთ არის არჩეული, ამიტომ შემდეგი ხაზის ჭრა წარუმატებლობის თავზე დატოვებდა იმას, რომელიც არ გამოქვეყნდა. შემდეგ ორშაბათს შეჩერებული ხაზი ავტომატურად თავიდან სცდება.

## არხის მიმაგრება {#pinning-a-channel}

მიამაგრეთ კონკრეტული ტეგი, რომელიც გსურთ თქვენს განლაგების მანიფესტში, Helm-ის მნიშვნელობებში ან Docker Compose ფაილში. მაგალითი, Helm-ის ჩარტის გამოყენებით:

```yaml
server:
  image:
    repository: ghcr.io/tuist/tuist
    tag: "1.350.2"          # Pinned to a stable patch
    # tag: "1.351.0-rc.1"   # Or opt into a release candidate to soak it
    # tag: "1.351.0-canary.5" # Or opt into a specific canary build

kuraRuntime:
  image:
    repository: ghcr.io/tuist/kura
    tag: "0.54.0"           # Same three channels apply to Kura
```

`:latest` ორივეზე `ghcr.io/tuist/tuist` და `ghcr.io/tuist/kura` თვალყურს ადევნებს უახლეს სტაბილურს, რომელიც გადაადგილდება მხოლოდ ორშაბათის წინ წაწევისას. `:latest`-ის მიმაგრება გაძლევთ კვირეულ სტაბილურ სიხშირეს ტეგის განახლების საჭიროების გარეშე; კონკრეტული ვერსიის მიმაგრება გაძლევთ სრულ კონტროლს იმაზე, თუ როდის განაახლებთ.

## რეკომენდებული სტრატეგია {#recommended-strategy}

არხები არსებობს იმისთვის, რომ შეძლოთ „უახლესი გამოსწორებების მიღება“ გააცალკევოთ „უახლესი ფუნქციების მიღებისგან“. უსაფრთხო, დაბალი ძალისხმევის ნაგულისხმევი ვარიანტია:

1. **მიამაგრეთ პროდაქშენი სტაბილურ მინორულ ხაზს**, მაგალითად `ghcr.io/tuist/tuist:1.351`. ეს ხაზი იღებს მხოლოდ ბექპორტირებულ გამოსწორებებს, არასდროს ახალ ფუნქციებს, ამიტომ ყოველდღიური განახლებები დაბალი რისკის რჩება. გაზარდეთ მიმაგრება, როცა მზად იქნებით შემდეგი მინორული ვერსიის მიღებისთვის.
2. **გაუშვით სტეიჯინგის გარემო canary-ზე ან კონკრეტულ რელიზ-კანდიდატ ტეგზე.** სტეიჯინგი იჭერს რეგრესიებს, რომლებიც წინააღმდეგ შემთხვევაში თქვენს მომხმარებლებს მიაღწევდნენ, და რაც უფრო ახლოს არის `main`-თან სტეიჯინგი, მით უფრო ადრე აღმოაჩენთ მათ. მიმდინარე რელიზ-კანდიდატ ხაზზე სტეიჯინგის გარემო კარგი შუალედური ვარიანტია: ის ამოწმებს ზუსტად იმ ბაიტებს, რომლებიც მომავალ ორშაბათს სტაბილური გახდება.
3. **მიჰყევით [სერვერის ცვლილებების ჟურნალს](/changelog), რათა ნახოთ, რა რეალურად გამოვიდა.** ყოველი სტაბილური წინ წაწევა იქ ანონსდება შესული პულ-რიკვესტების სიით.

თუ გირჩევნიათ, რომ ახალი ფუნქციები ავტომატურად გადავიდეს პროდაქშენში მათი სტაბილურობის მიღწევისას, შეინარჩუნეთ პროდაქშენი `:latest`-ზე. უბრალოდ გაითვალისწინეთ, რომ ტეგი ყოველ ორშაბათ დილით წინ მიიწევს, ამიტომ დაგეგმეთ განლაგების ფანჯარა შესაბამისად.

## ბექპორტები {#backports}

ნებისმიერ დროს აქტიურად მხარდაჭერილია ორი სტაბილური სერვერის (და Kura) ხაზი: მიმდინარე ხაზი იღებს რეგრესიებსა და უსაფრთხოების გამოსწორებებს ბექპორტ პულ-რიკვესტების სახით, ხოლო წინა ხაზი იღებს მხოლოდ კრიტიკულ და უსაფრთხოების გამოსწორებებს. ძველი ხაზები არ ბექპორტდება; განაახლეთ მხარდაჭერილ ხაზზე გამოსწორებების მიღებისთვის. როდესაც ახალი ხაზი წინ იწევა სტაბილურად, ხაზი, რომელიც იყო „მიმდინარე“, ხდება „წინა“, ხოლო ხაზი, რომელიც იყო „წინა“, წყვეტს ბექპორტების მიღებას.

ბექპორტები იჭრება მოთხოვნის შესაბამისად `X.Y.(Z+1)` პატჩ რელიზების სახით. ისინი არასდროს გადაადგილებენ `:latest`-ს.
