# ანგარიშები და პროექტები {#accounts-and-projects}

Tuist-ის ზოგიერთი ფუნქცია მოითხოვს სერვერს, რომელიც უზრუნველყოფს მონაცემთა შენახვას და შეუძლია სხვა სერვისებთან ურთიერთქმედება. სერვერთან სამუშაოდ გჭირდებათ ანგარიში და პროექტი, რომელსაც თქვენს ლოკალურ პროექტს დაუკავშირებთ.

## ანგარიშები {#accounts}

სერვერის გამოყენებისთვის საჭიროა ანგარიში. არსებობს ანგარიშების ორი ტიპი:

- **პირადი ანგარიში:** ეს ანგარიშები ავტომატურად იქმნება რეგისტრაციისას და იდენტიფიცირდება handle-ით, რომელიც მიიღება იდენტობის პროვაიდერისგან (მაგ., GitHub) ან ელფოსტის მისამართის პირველი ნაწილიდან.
- **ორგანიზაციის ანგარიში:** ეს ანგარიშები იქმნება ხელით და იდენტიფიცირდება დეველოპერის მიერ განსაზღვრული handle-ით. ორგანიზაციები საშუალებას გაძლევთ სხვა წევრები მიიწვიოთ პროექტებზე ერთობლივად მუშაობისთვის.

თუ გაქვთ გამოცდილება [GitHub](https://github.com)-თან, კონცეფცია მსგავსია: შეგიძლიათ გქონდეთ პირადი და ორგანიზაციის ანგარიშები, რომლებიც იდენტიფიცირდება *handle*-ით, რომელიც გამოიყენება URL-ების აგებისას.

> [!NOTE]
> **Cli-first**
>
> ანგარიშებისა და პროექტების მართვის უმეტესი ოპერაცია ხორციელდება CLI-ის მეშვეობით. ვმუშაობთ ვებინტერფეისზე, რომელიც გაამარტივებს ანგარიშებისა და პროექტების მართვას.


ორგანიზაციის მართვა შეგიძლიათ <.localized_link href="/cli/organization">`tuist organization`</.localized_link> ქვებრძანებებით. ახალი ორგანიზაციის ანგარიშის შესაქმნელად გაუშვით:
```bash
tuist organization create {account-handle}
```

### ორგანიზაციის წევრობა {#organization-membership}

მომხმარებლებს შეუძლიათ გახდნენ ორგანიზაციის წევრები მიწვევის, ავტომატური ერთჯერადი შესვლის (SSO) რეგისტრაციის ან <.localized_link href="/guides/integrations/authentication/scim">System for Cross-domain Identity Management provisioning</.localized_link> გზით.

ორგანიზაციის იდენტობის პროვაიდერით ავთენტიკაცია თავისთავად არ ანიჭებს წევრობას. ორგანიზაციის <.localized_link href="/guides/integrations/authentication/sso#choose-an-enrollment-policy">single sign-on enrollment policy</.localized_link> განსაზღვრავს, სჭირდება თუ არა მისი სანდო დომენის მომხმარებელს მიწვევა ან შეუძლია ავტომატურად შემოერთება.

ადმინისტრატორებს შეუძლიათ წევრის მიწვევა დაშბორდიდან ან <.localized_link href="/cli/organization/invite">`tuist organization invite`</.localized_link> ბრძანებით. გადაეცით `--role admin` ან `--role viewer`, რათა მიწვეულს მიენიჭოს `user`-ისგან განსხვავებული როლი მიღებისას.

### როლები {#roles}

ორგანიზაციის ყოველ წევრს აქვს ერთ-ერთი სამი როლიდან:

| როლი | რა უფლებებს ანიჭებს |
| --- | --- |
| **Admin** | ყველაფერი, რაც User-ს შეუძლია, პლუს ორგანიზაციის მართვა: წევრები და მიწვევები, პროექტები, გადახდები, ტოკენები, webhooks და პარამეტრები. |
| **User** | კითხვა და მოქმედება ორგანიზაციის სამუშაოზე: ბილდებისა და ტესტების გაშვება, ქეშში ჩაწერა, previews-ის შექმნა და წაშლა, სატესტო შემთხვევის სტატუსის ცვლილება. |
| **Viewer** | კითხულობს ორგანიზაციის სამუშაოს და არაფერს ცვლის. დაშბორდები, ბილდები, ტესტების გაშვებები, flaky და quarantined ტესტები, previews, bundles და runner-ების აქტივობა — ყველაფერი წაკითხვადია. ინტერაქტიული shell-ის ან VNC სესიის runner-ზე მიმაგრება არ არის შესაძლებელი, რადგან ის ბრძანებებს ასრულებს მანქანაზე. |

მიწვევისას აირჩიეთ როლი და მოგვიანებით შეცვალეთ ის დაშბორდის **Members** განყოფილებაში. ასე მინიჭებული როლი მომდევნო შესვლისას არ გადაიწერება.

## პროექტები {#projects}

თქვენი პროექტები უნდა იყოს ინტეგრირებული თქვენს ანგარიშთან remote პროექტის მეშვეობით. GitHub-თან შედარების გაგრძელებით, ეს ჰგავს ლოკალურ და remote რეპოზიტორიებს, სადაც თქვენს ცვლილებებს აგზავნით. პროექტების შესაქმნელად და სამართავად შეგიძლიათ გამოიყენოთ <.localized_link href="/cli/project">`tuist project`</.localized_link>.

პროექტები იდენტიფიცირდება სრული handle-ით, რომელიც მიიღება ორგანიზაციის handle-ისა და პროექტის handle-ის შეერთებით. მაგალითად, თუ გაქვთ ორგანიზაცია handle-ით `tuist` და პროექტი handle-ით `tuist`, სრული handle იქნება `tuist/tuist`.

ლოკალურ და remote პროექტს შორის კავშირი ხორციელდება კონფიგურაციის ფაილით. თუ არ გაქვთ, შექმენით ის `Tuist.swift` მისამართზე და დაამატეთ შემდეგი შინაარსი:

```swift
let tuist = Tuist(fullHandle: "{account-handle}/{project-handle}") // e.g. tuist/tuist
```

> [!WARNING]
> **Tuist Project-only Features**
>
> გაითვალისწინეთ, რომ ზოგიერთი ფუნქცია, როგორიცაა <.localized_link href="/guides/features/cache/module-cache">module caching</.localized_link>, მოითხოვს Tuist-ით მართულ პროექტს. თუ Tuist-ს არ იყენებთ თქვენი პროექტის მართვისთვის, ამ ფუნქციებს ვერ გამოიყენებთ.


თქვენი პროექტის URL აგებულია სრული handle-ის გამოყენებით. მაგალითად, Tuist-ის საჯარო დაშბორდი ხელმისაწვდომია [tuist.dev/tuist/tuist](https://tuist.dev/tuist/tuist) მისამართზე, სადაც `tuist/tuist` არის პროექტის სრული handle.
