# ანგარიშები და პროექტები {#accounts-and-projects}

Tuist-ის ზოგიერთი ფუნქცია საჭიროებს სერვერს, რომელიც უზრუნველყოფს მონაცემთა შენახვას და სხვა სერვისებთან ურთიერთქმედებას. სერვერთან სამუშაოდ გჭირდებათ ანგარიში და პროექტი, რომელსაც თქვენს ლოკალურ პროექტთან დააკავშირებთ.

## ანგარიშები {#accounts}

სერვერის გამოსაყენებლად დაგჭირდებათ ანგარიში. არსებობს ანგარიშების ორი ტიპი:

- **პირადი ანგარიში:** ეს ანგარიშები ავტომატურად იქმნება რეგისტრაციისას და იდენტიფიცირდება handle-ით, რომელიც მიიღება იდენტობის პროვაიდერიდან (მაგ., GitHub) ან ელფოსტის მისამართის პირველი ნაწილიდან.
- **ორგანიზაციის ანგარიში:** ეს ანგარიშები იქმნება ხელით და იდენტიფიცირდება დეველოპერის მიერ განსაზღვრული handle-ით. ორგანიზაციები საშუალებას გაძლევთ სხვა წევრები მიიწვიოთ პროექტებზე ერთობლივი მუშაობისთვის.

თუ [GitHub](https://github.com)-თან ხართ ნაცნობი, კონცეფცია მათის მსგავსია: შეგიძლიათ გქონდეთ პირადი და ორგანიზაციის ანგარიშები, რომლებიც იდენტიფიცირდება *handle*-ით, რომელიც გამოიყენება URL-ების აგებისას.

ორგანიზაციის მართვა შესაძლებელია <.localized_link href="/cli/organization">`tuist organization`</.localized_link> ქვებრძანებებით. ახალი ორგანიზაციის ანგარიშის შესაქმნელად გაუშვით:
```bash
tuist organization create {account-handle}
```

### ორგანიზაციის წევრობა {#organization-membership}

მომხმარებლებს შეუძლიათ გახდნენ ორგანიზაციის წევრები მიწვევის, ავტომატური single sign-on რეგისტრაციის ან <.localized_link href="/guides/integrations/authentication/scim">System for Cross-domain Identity Management provisioning</.localized_link>-ის მეშვეობით.

ორგანიზაციის იდენტობის პროვაიდერით ავტორიზაცია თავისთავად არ ანიჭებს წევრობას. ორგანიზაციის <.localized_link href="/guides/integrations/authentication/sso#choose-an-enrollment-policy">single sign-on რეგისტრაციის პოლიტიკა</.localized_link> განსაზღვრავს, სჭირდება თუ არა მისი სანდო დომენის მომხმარებელს მიწვევა ან შეუძლია ავტომატურად შემოერთება.

ადმინისტრატორებს შეუძლიათ წევრის მიწვევა დაშბორდიდან ან <.localized_link href="/cli/organization/invite">`tuist organization invite`</.localized_link>-ის მეშვეობით. გადაეცით `--role admin` ან `--role viewer`, რათა მიწვეულს მიანიჭოთ `user`-ისგან განსხვავებული როლი მიწვევის მიღებისას.

### როლები {#roles}

ორგანიზაციის ყოველ წევრს აქვს ერთ-ერთი სამი როლიდან:

| როლი | რა ანიჭებს |
| --- | --- |
| **ადმინისტრატორი** | ყველაფერი, რაც მომხმარებელს შეუძლია, პლუს ორგანიზაციის მართვა: წევრები და მიწვევები, პროექტები, გადახდები, ტოკენები, ვებჰუკები და პარამეტრები. |
| **მომხმარებელი** | კითხულობს და ასრულებს ორგანიზაციის სამუშაოებს: ბილდებისა და ტესტების გაშვება, ქეშში ჩაწერა, პრივიუების შექმნა და წაშლა და სატესტო შემთხვევის სტატუსის შეცვლა. |
| **დამთვალიერებელი** | კითხულობს ორგანიზაციის სამუშაოებს და არ ცვლის არაფერს. დაშბორდები, ბილდები, ტესტების გაშვებები, არასტაბილური და კარანტინში მოთავსებული ტესტები, პრივიუები, ბანდლები და runner-ების აქტივობა — ყველაფერი წასაკითხია. ინტერაქციული shell-ის ან VNC სესიის runner-თან მიმაგრება არ არის შესაძლებელი, რადგან ის ბრძანებებს ასრულებს მანქანაზე. |

აირჩიეთ როლი ვინმეს მიწვევისას და მოგვიანებით შეცვალეთ ის დაშბორდის **წევრები** განყოფილებაში. ამ გზით მინიჭებული როლი არასდროს იცვლება მომდევნო შესვლისას.

## პროექტები {#projects}

თქვენი პროექტები უნდა იყოს ინტეგრირებული თქვენს ანგარიშთან remote პროექტის მეშვეობით. GitHub-თან შედარების გაგრძელებით, ეს ჰგავს ლოკალურ და remote რეპოზიტორიებს, სადაც თქვენს ცვლილებებს აგზავნით. პროექტების შესაქმნელად და სამართავად შეგიძლიათ გამოიყენოთ <.localized_link href="/cli/project">`tuist project`</.localized_link>.

პროექტები იდენტიფიცირდება სრული handle-ით, რომელიც მიიღება ორგანიზაციის handle-ისა და პროექტის handle-ის შეერთებით. მაგალითად, თუ გაქვთ ორგანიზაცია handle-ით `tuist`, და პროექტი handle-ით `tuist`, სრული handle იქნება `tuist/tuist`.

ლოკალურ და remote პროექტს შორის კავშირი ხორციელდება კონფიგურაციის ფაილის მეშვეობით. თუ არ გაქვთ, შექმენით ის `Tuist.swift`-ში და დაამატეთ შემდეგი შინაარსი:

```swift
let tuist = Tuist(fullHandle: "{account-handle}/{project-handle}") // e.g. tuist/tuist
```

> [!WARNING]
> **Tuist-ის მხოლოდ პროექტისთვის განკუთვნილი ფუნქციები**
>
> გაითვალისწინეთ, რომ ზოგიერთი ფუნქცია, როგორიცაა <.localized_link href="/guides/features/cache/module-cache">მოდულის ქეშირება</.localized_link>, საჭიროებს Tuist-ით მართულ პროექტს. თუ Tuist-ს არ იყენებთ თქვენი პროექტის მართვისთვის, ამ ფუნქციებს ვერ გამოიყენებთ.


თქვენი პროექტის URL აგებულია სრული handle-ის გამოყენებით. მაგალითად, Tuist-ის საჯარო დაშბორდი ხელმისაწვდომია მისამართზე [tuist.dev/tuist/tuist](https://tuist.dev/tuist/tuist), სადაც `tuist/tuist` არის პროექტის სრული handle.
