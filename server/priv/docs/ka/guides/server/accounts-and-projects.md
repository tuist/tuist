# ანგარიშები და პროექტები {#accounts-and-projects}

ზოგიერთი Tuist ფუნქცია მოითხოვს სერვერს, რომელიც უზრუნველყოფს მონაცემთა შენახვას და შეუძლია ურთიერთქმედება სხვა სერვისებთან. სერვერთან ურთიერთქმედებისთვის გჭირდებათ ანგარიში და პროექტი, რომელსაც დააკავშირებთ თქვენს ლოკალურ პროექტთან.

## ანგარიშები {#accounts}

სერვერის გამოსაყენებლად დაგჭირდებათ ანგარიში. არსებობს ანგარიშების ორი ტიპი:

- **პირადი ანგარიში:** ეს ანგარიშები ავტომატურად იქმნება რეგისტრაციისას და იდენტიფიცირდება handle-ით, რომელიც მიიღება იდენტობის პროვაიდერისგან (მაგ., GitHub) ან ელფოსტის მისამართის პირველი ნაწილიდან.
- **ორგანიზაციის ანგარიში:** ეს ანგარიშები ხელით იქმნება და იდენტიფიცირდება handle-ით, რომელსაც განსაზღვრავს დეველოპერი. ორგანიზაციები საშუალებას გაძლევთ სხვა წევრები მიიწვიოთ პროექტებზე ერთობლივი მუშაობისთვის.

თუ გაცნობიერებული ხართ [GitHub](https://github.com)-თან, კონცეფცია მათი მსგავსია, სადაც შეგიძლიათ გქონდეთ პირადი და ორგანიზაციის ანგარიშები, და ისინი იდენტიფიცირდება *handle*-ით, რომელიც გამოიყენება URL-ების აგებისას.

> [!NOTE]
> **Cli-first**
>
> ანგარიშებისა და პროექტების მართვის უმეტესი ოპერაცია ხორციელდება CLI-ის მეშვეობით. ჩვენ ვმუშაობთ ვებ-ინტერფეისზე, რომელიც გაამარტივებს ანგარიშებისა და პროექტების მართვას.


ორგანიზაციის მართვა შეგიძლიათ ქვებრძანებებით <.localized_link href="/cli/organization">`tuist organization`</.localized_link>. ახალი ორგანიზაციის ანგარიშის შესაქმნელად, გაუშვით:
```bash
tuist organization create {account-handle}
```

### ორგანიზაციის წევრობა {#organization-membership}

მომხმარებლებს შეუძლიათ გახდნენ ორგანიზაციის წევრები მიწვევის, ავტომატური ერთჯერადი შესვლის (SSO) რეგისტრაციის ან <.localized_link href="/guides/integrations/authentication/scim">System for Cross-domain Identity Management provisioning</.localized_link>-ის მეშვეობით.

ორგანიზაციის იდენტობის პროვაიდერით ავთენტიკაცია თავისთავად არ ანიჭებს წევრობას. ორგანიზაციის <.localized_link href="/guides/integrations/authentication/sso#choose-an-enrollment-policy">single sign-on enrollment policy</.localized_link> განსაზღვრავს, სჭირდება თუ არა მის სანდო დომენში მყოფ მომხმარებელს მიწვევა ან შეუძლია ავტომატურად შეუერთდეს.

ადმინისტრატორებს შეუძლიათ მიიწვიონ წევრი დაშბორდიდან ან <.localized_link href="/cli/organization/invite">`tuist organization invite`</.localized_link>-ის მეშვეობით. გადაეცით `--role admin` ან `--role viewer`, რათა მიწვეულს მიანიჭოთ როლი, განსხვავებული `user`-ისგან, როდესაც ის მიიღებს მიწვევას.

### როლები {#roles}

ორგანიზაციის ყოველ წევრს აქვს ერთ-ერთი სამი როლიდან:

| როლი | რა უფლებებს ანიჭებს |
| --- | --- |
| **Admin** | ყველაფერი, რაც მომხმარებელს შეუძლია, პლუს ორგანიზაციის მართვა: წევრები და მიწვევები, პროექტები, გადახდები, ტოკენები, webhook-ები და პარამეტრები. |
| **User** | კითხულობს და ასრულებს ორგანიზაციის სამუშაოს: ბილდებისა და ტესტების გაშვება, cache-ში ჩაწერა, previews-ის შექმნა და წაშლა, და ტესტის შემთხვევის სტატუსის შეცვლა. |
| **Viewer** | კითხულობს ორგანიზაციის სამუშაოს და არაფერს ცვლის მასში. დაშბორდები, ბილდები, ტესტების გაშვებები, არასტაბილური და კარანტინში მყოფი ტესტები, previews, ბანდლები და runner-ის აქტივობა — ყველაფერი წასაკითხია. ინტერაქტიული shell-ის ან VNC სესიის მიმაგრება runner-ზე არ არის შესაძლებელი, რადგან ის ბრძანებებს ასრულებს მანქანაზე. |

აირჩიეთ როლი ვინმეს მიწვევისას და შეცვალეთ ის მოგვიანებით დაშბორდის **Members** განყოფილებაში. ამ გზით დაყენებული როლი არასდროს გადაიწერება მოგვიანებით შესვლისას.

## პროექტები {#projects}

თქვენი პროექტები უნდა იყოს ინტეგრირებული თქვენს ანგარიშთან remote პროექტის მეშვეობით. GitHub-თან შედარების გაგრძელებით, ეს ჰგავს ლოკალური და remote რეპოზიტორიის ქონას, სადაც აგზავნით ცვლილებებს. შეგიძლიათ გამოიყენოთ <.localized_link href="/cli/project">`tuist project`</.localized_link> პროექტების შესაქმნელად და მართვისთვის.

პროექტები იდენტიფიცირდება სრული handle-ით, რომელიც მიიღება ორგანიზაციის handle-ისა და პროექტის handle-ის შეერთებით. მაგალითად, თუ გაქვთ ორგანიზაცია handle-ით `tuist`, და პროექტი handle-ით `tuist`, სრული handle იქნება `tuist/tuist`.

ლოკალურ და remote პროექტს შორის კავშირი ხორციელდება კონფიგურაციის ფაილის მეშვეობით. თუ არ გაქვთ, შექმენით ის `Tuist.swift`-ში და დაამატეთ შემდეგი შინაარსი:

```swift
let tuist = Tuist(fullHandle: "{account-handle}/{project-handle}") // e.g. tuist/tuist
```

> [!WARNING]
> **Tuist Project-only Features**
>
> გაითვალისწინეთ, რომ ზოგიერთი ფუნქცია, როგორიცაა <.localized_link href="/guides/features/cache/module-cache">module caching</.localized_link>, მოითხოვს Tuist-ით მართულ პროექტს. თუ არ იყენებთ Tuist-ს თქვენი პროექტის მართვისთვის, ვერ შეძლებთ ამ ფუნქციების გამოყენებას.


თქვენი პროექტის URL აგებულია სრული handle-ის გამოყენებით. მაგალითად, Tuist-ის საჯარო დაშბორდი ხელმისაწვდომია [tuist.dev/tuist/tuist](https://tuist.dev/tuist/tuist)-ზე, სადაც `tuist/tuist` არის პროექტის სრული handle.
