# ანგარიშები და პროექტები {#accounts-and-projects}

Tuist-ის ზოგიერთ ფუნქციას სჭირდება სერვერი, რომელიც უზრუნველყოფს მონაცემთა შენახვას და შეუძლია სხვა სერვისებთან ურთიერთქმედება. სერვერთან სამუშაოდ გჭირდებათ ანგარიში და პროექტი, რომელსაც თქვენს ლოკალურ პროექტს დაუკავშირებთ.

## ანგარიშები {#accounts}

სერვერის გამოყენებისთვის დაგჭირდებათ ანგარიში. არსებობს ანგარიშების ორი ტიპი:

- **პირადი ანგარიში:** ეს ანგარიშები ავტომატურად იქმნება რეგისტრაციისას და იდენტიფიცირდება handle-ით, რომელიც მიიღება ან იდენტობის პროვაიდერისგან (მაგ., GitHub) ან ელფოსტის მისამართის პირველი ნაწილიდან.
- **ორგანიზაციის ანგარიში:** ეს ანგარიშები ხელით იქმნება და იდენტიფიცირდება handle-ით, რომელსაც დეველოპერი განსაზღვრავს. ორგანიზაციები საშუალებას გაძლევთ სხვა წევრები მიიწვიოთ პროექტებზე ერთობლივად მუშაობისთვის.

თუ [GitHub](https://github.com)-თან ხართ ნაცნობი, კონცეფცია მათი მსგავსია: შეგიძლიათ გქონდეთ პირადი და ორგანიზაციის ანგარიშები, რომლებიც იდენტიფიცირდება *handle-ით*, რომელიც გამოიყენება URL-ების აგებისას.

ორგანიზაციის მართვა შეგიძლიათ <.localized_link href="/cli/organization">`tuist organization`</.localized_link> ქვებრძანებებით. ახალი ორგანიზაციის ანგარიშის შესაქმნელად გაუშვით:
```bash
tuist organization create {account-handle}
```

### ორგანიზაციის წევრობა {#organization-membership}

მომხმარებლებს შეუძლიათ გახდნენ ორგანიზაციის წევრები მიწვევის, ავტომატური ერთჯერადი შესვლის (SSO) რეგისტრაციის ან <.localized_link href="/guides/integrations/authentication/scim">System for Cross-domain Identity Management provisioning</.localized_link>-ის მეშვეობით.

ორგანიზაციის იდენტობის პროვაიდერით ავტორიზაცია თავისთავად არ იძლევა წევრობას. ორგანიზაციის <.localized_link href="/guides/integrations/authentication/sso#choose-an-enrollment-policy">ერთჯერადი შესვლის რეგისტრაციის პოლიტიკა</.localized_link> განსაზღვრავს, სჭირდება თუ არა მისი სანდო დომენის მომხმარებელს მიწვევა ან შეუძლია ავტომატურად შემოერთება.

ადმინისტრატორებს შეუძლიათ მოიწვიონ წევრი დაშბორდიდან ან <.localized_link href="/cli/organization/invite">`tuist organization invite`</.localized_link>-ის მეშვეობით. გადაეცით `--role admin` ან `--role viewer`, რათა მიწვეულს `user`-ისგან განსხვავებული როლი მიანიჭოთ მიწვევის მიღებისას.

### როლები {#roles}

ორგანიზაციის ყოველ წევრს აქვს ერთ-ერთი სამი როლიდან:

| როლი | რა უფლებებს იძლევა |
| --- | --- |
| **ადმინისტრატორი** | ყველაფერი, რაც მომხმარებელს შეუძლია, პლუს ორგანიზაციის მართვა: წევრები და მიწვევები, პროექტები, გადახდები, ტოკენები, ვებჰუკები და პარამეტრები. |
| **მომხმარებელი** | კითხულობს და ასრულებს მოქმედებებს ორგანიზაციის სამუშაოზე: ბილდებისა და ტესტების გაშვება, ქეშში ჩაწერა, პრევიუების შექმნა და წაშლა და სატესტო შემთხვევის სტატუსის ცვლილება. |
| **მნახველი** | კითხულობს ორგანიზაციის სამუშაოს და არაფერს ცვლის. დაშბორდები, ბილდები, ტესტების გაშვებები, არასტაბილური და კარანტინში მყოფი ტესტები, პრევიუები, ბანდლები და რანერის აქტივობა — ყველაფერი წაკითხვადია. ინტერაქტიული შელის ან VNC სესიის რანერთან მიმაგრება არ არის შესაძლებელი, რადგან ის ბრძანებებს ასრულებს მანქანაზე. |

აირჩიეთ როლი ვინმეს მიწვევისას და მოგვიანებით შეცვალეთ ის დაშბორდის **წევრები** განყოფილებაში. ამ გზით მინიჭებული როლი არასდროს იცვლება მომდევნო შესვლისას.

## პროექტები {#projects}

თქვენი პროექტები უნდა იყოს ინტეგრირებული თქვენს ანგარიშთან remote პროექტის მეშვეობით. GitHub-თან შედარების გაგრძელებით, ეს ჰგავს ლოკალურ და remote რეპოზიტორიებს, სადაც თქვენს ცვლილებებს აგზავნით. პროექტების შესაქმნელად და სამართავად შეგიძლიათ გამოიყენოთ <.localized_link href="/cli/project">`tuist project`</.localized_link>.

პროექტები იდენტიფიცირდება სრული handle-ით, რომელიც მიიღება ორგანიზაციის handle-ისა და პროექტის handle-ის შეერთებით. მაგალითად, თუ გაქვთ ორგანიზაცია handle-ით `tuist` და პროექტი handle-ით `tuist`, სრული handle იქნება `tuist/tuist`.

ლოკალურ და remote პროექტს შორის კავშირი ხორციელდება კონფიგურაციის ფაილის მეშვეობით. თუ არ გაქვთ, შექმენით ის `Tuist.swift` მისამართზე და დაამატეთ შემდეგი შინაარსი:

```swift
let tuist = Tuist(fullHandle: "{account-handle}/{project-handle}") // e.g. tuist/tuist
```

> [!WARNING]
> **Tuist-ის პროექტისთვის დამახასიათებელი ფუნქციები**
>
> გაითვალისწინეთ, რომ ზოგიერთ ფუნქციას, როგორიცაა <.localized_link href="/guides/features/cache/module-cache">მოდულების ქეშირება</.localized_link>, სჭირდება Tuist-ით მართული პროექტი. თუ Tuist-ს არ იყენებთ თქვენი პროექტის მართვისთვის, ვერ შეძლებთ ამ ფუნქციების გამოყენებას.


თქვენი პროექტის URL აგებულია სრული handle-ის გამოყენებით. მაგალითად, Tuist-ის საჯარო დაშბორდი ხელმისაწვდომია მისამართზე [tuist.dev/tuist/tuist](https://tuist.dev/tuist/tuist), სადაც `tuist/tuist` არის პროექტის სრული handle.
