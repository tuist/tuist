# ანგარიშები და პროექტები {#accounts-and-projects}

Tuist-ის ზოგიერთი ფუნქცია მოითხოვს სერვერს, რომელიც უზრუნველყოფს მონაცემთა შენახვას და შეუძლია სხვა სერვისებთან ურთიერთქმედება. სერვერთან სამუშაოდ საჭიროა ანგარიში და პროექტი, რომელსაც თქვენს ლოკალურ პროექტთან დააკავშირებთ.

## ანგარიშები {#accounts}

სერვერის გამოყენებისთვის დაგჭირდებათ ანგარიში. არსებობს ანგარიშების ორი ტიპი:

- **პირადი ანგარიში:** ეს ანგარიშები ავტომატურად იქმნება რეგისტრაციისას და იდენტიფიცირდება ხელით (handle), რომელიც მიიღება ან იდენტობის პროვაიდერიდან (მაგ., GitHub) ან ელფოსტის მისამართის პირველი ნაწილიდან.
- **ორგანიზაციის ანგარიში:** ეს ანგარიშები იქმნება ხელით და იდენტიფიცირდება დეველოპერის მიერ განსაზღვრული ხელით (handle). ორგანიზაციები საშუალებას გაძლევთ სხვა წევრები მიიწვიოთ პროექტებზე ერთობლივი მუშაობისთვის.

თუ გაცნობილი ხართ [GitHub](https://github.com)-თან, კონცეფცია მათ მსგავსია: შეგიძლიათ გქონდეთ პირადი და ორგანიზაციის ანგარიშები, რომლებიც იდენტიფიცირდება *ხელით (handle)*, რომელიც გამოიყენება URL-ების აგებისას.

ორგანიზაციის მართვა შესაძლებელია <.localized_link href="/cli/organization">`tuist organization`</.localized_link> ქვებრძანებებით. ახალი ორგანიზაციის ანგარიშის შესაქმნელად გაუშვით:
```bash
tuist organization create {account-handle}
```

### ორგანიზაციის წევრობა {#organization-membership}

მომხმარებლებს შეუძლიათ გახდნენ ორგანიზაციის წევრები მიწვევის, ავტომატური ერთჯერადი შესვლის (SSO) რეგისტრაციის ან <.localized_link href="/guides/integrations/authentication/scim">დომენთაშორისი იდენტობის მართვის სისტემის (SCIM) პროვიზინგის</.localized_link> მეშვეობით.

ორგანიზაციის იდენტობის პროვაიდერით ავთენტიკაცია თავისთავად არ იძლევა წევრობას. ორგანიზაციის <.localized_link href="/guides/integrations/authentication/sso#choose-an-enrollment-policy">ერთჯერადი შესვლის (SSO) რეგისტრაციის პოლიტიკა</.localized_link> განსაზღვრავს, სჭირდება თუ არა მის სანდო დომენში მყოფ მომხმარებელს მიწვევა, თუ შეუძლია ავტომატურად შემოერთება.

ადმინისტრატორებს შეუძლიათ წევრის მიწვევა დაფლადასკიდან ან <.localized_link href="/cli/organization/invite">`tuist organization invite`</.localized_link> ბრძანებით. გადაეცით `--role admin` ან `--role viewer`, რათა მიწვეულს მიანიჭოთ `user`-გან განსხვავებული როლი მიღებისას.

### როლები {#roles}

ორგანიზაციის ყოველ წევრს აქვს ერთ-ერთი სამი როლიდან:

| როლი | რა უფლებებს იძლევა |
| --- | --- |
| **ადმინისტრატორი** | ყველაფერი, რაც მომხმარებელს შეუძლია, პლუს ორგანიზაციის მართვა: წევრები და მიწვევები, პროექტები, გადახდები, ტოკენები, ვებჰუკები და პარამეტრები. |
| **მომხმარებელი** | კითხულობს და ასრულებს მოქმედებებს ორგანიზაციის სამუშაოზე: ბილდებისა და ტესტების გაშვება, ქეშში ჩაწერა, პრევიუების შექმნა და წაშლა, სატესტო შემთხვევის მდგომარეობის ცვლილება. |
| **დამთვალიერებელი** | კითხულობს ორგანიზაციის სამუშაოს და არაფერს ცვლის. დაფლადასკები, ბილდები, ტესტების გაშვებები, არასტაბილური და კარანტინში მყოფი ტესტები, პრევიუები, ბანდლები და რანერის აქტივობა — ყველაფერი ხელმისაწვდომია წაკითხვისთვის. ინტერაქტიული შელის ან VNC სესიის რანერზე მიმაგრება არ არის ხელმისაწვდომი, რადგან ის ბრძანებებს ასრულებს მანქანაზე. |

აირჩიეთ როლი ვინმეს მიწვევისას და მოგვიანებით შეცვალეთ ის დაფლადასკის **წევრები** განყოფილებაში. ამ გზით მინიჭებული როლი მომავალში შესვლისას არ გადაიწერება.

## პროექტები {#projects}

თქვენი პროექტები უნდა იყოს ინტეგრირებული თქვენს ანგარიშთან დისტანციური პროექტის მეშვეობით. GitHub-თან შედარების გაგრძელებით, ეს ჰგავს ლოკალურ და დისტანციურ რეპოზიტორიებს, სადაც თქვენს ცვლილებებს აგზავნით. პროექტების შესაქმნელად და სამართავად შეგიძლიათ გამოიყენოთ <.localized_link href="/cli/project">`tuist project`</.localized_link>.

პროექტები იდენტიფიცირდება სრული ხელით (full handle), რომელიც მიიღება ორგანიზაციის ხელისა და პროექტის ხელის შეერთებით. მაგალითად, თუ გაქვთ ორგანიზაცია ხელით `tuist` და პროექტი ხელით `tuist`, სრული ხელი იქნება `tuist/tuist`.

ლოკალურ და დისტანციურ პროექტს შორის კავშირი ხდება კონფიგურაციის ფაილის მეშვეობით. თუ არ გაქვთ, შექმენით ის `Tuist.swift` მისამართზე და დაამატეთ შემდეგი შინაარსი:

```swift
let tuist = Tuist(fullHandle: "{account-handle}/{project-handle}") // e.g. tuist/tuist
```

> [!WARNING]
> **Tuist-ის მხოლოდ პროექტისთვის ხელმისაწვდომი ფუნქციები**
>
> გაითვალისწინეთ, რომ ზოგიერთი ფუნქცია, მაგალითად <.localized_link href="/guides/features/cache/module-cache">მოდულის ქეშირება</.localized_link>, მოითხოვს Tuist-ით მართულ პროექტს. თუ Tuist-ს არ იყენებთ თქვენი პროექტის მართვისთვის, ამ ფუნქციებს ვერ გამოიყენებთ.


თქვენი პროექტის URL აგებულია სრული ხელის გამოყენებით. მაგალითად, Tuist-ის საჯარო დაფლადასკი ხელმისაწვდომია მისამართზე [tuist.dev/tuist/tuist](https://tuist.dev/tuist/tuist), სადაც `tuist/tuist` არის პროექტის სრული ხელი.
