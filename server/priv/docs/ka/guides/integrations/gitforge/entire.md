# Entire-ის ინტეგრაცია {#entire}

Tuist-ს შეუძლია გამოაქვეყნოს კომპილაციის, ტესტების, პრივიუს და ბანდლის ანალიტიკა გახსნილ და შავ პროექტებზე [Trails](https://docs.entire.com/guides/trails/overview)-ში [Entire](https://entire.com)-ის რეპოზიტორიებში. თითოეულ Trail-ს ენიჭება Tuist-ის გეიტი შესრულების ანგარიშით, მთლიანი ცვლილებების აღმოჩენებით წარუმატებელი და არასტაბილური ტესტებისთვის, და შეჯამების კომენტარით, რომელსაც Tuist აახლებს ახალი ანალიტიკის მიღებისას, ნაცვლად იმისა, რომ ყოველ ატვირთვაზე ახალი გამოაქვეყნოს.

პლაგინის დაყენება არ ასრულებს კომპილაციებს ან ტესტებს. თქვენი არსებული სამუშაო პროცესები განაგრძობენ შედეგების ატვირთვას Tuist-ში, ხოლო ინტეგრაცია ამ შედეგებს თქვენს Trails-ში აერთიანებს.

## დაყენება {#setup}

Tuist-ის ანგარიშის ადმინისტრატორი აყენებს პლაგინს, შემდეგ კი აკავშირებს რეპოზიტორებს Tuist-ის პროექტებთან, ისევე როგორც <.localized_link href="/guides/integrations/gitforge/github">GitHub</.localized_link>-ის და <.localized_link href="/guides/integrations/gitforge/origin">Origin</.localized_link>-ის ინტეგრაციების შემთხვევაში.

1. გახსენით თქვენი ანგარიშის **Settings → Integrations**.
2. Entire-ის ბარათში აირჩიეთ **Install Entire plugin**. აირჩიეთ Entire-ის პროექტი და რეპოზიტორები, რომელთაც Tuist-თან გაზიარება გსურთ.

   ![Entire-ის პლაგინის დაყენება ანგარიშის ინტეგრაციებიდან](/images/guides/integrations/gitforge/entire/integrations.png)

3. Tuist-ში დაბრუნებისას, აირჩიეთ **Add new project connection**. **Choose repository to connect to**-ში აირჩიეთ თქვენი Tuist-ის პროექტი და Entire-ის რეპოზიტორი, შემდეგ კი აირჩიეთ **Create Connection**. თუ მხოლოდ ერთი Tuist-ის პროექტია ხელმისაწვდომი, ის ავტომატურად იქნება არჩეული.

   ![Tuist-ის პროექტის დაკავშირება Entire-ის რეპოზიტორთან](/images/guides/integrations/gitforge/entire/add-project-connection.png)

4. განაგრძეთ CI-დან შედეგების ატვირთვა თქვენი არსებული, ავთენტიფიცირებული Tuist-ის ბრძანებებით, მაგალითად, <.localized_link href="/guides/server/authentication#account-tokens">account token</.localized_link>-ის გამოყენებით. Tuist ათანამდებს შედეგებს თითოეული Trail-ის მიმდინარე head კომიტთან, ამიტომ Entire-ის სპეციფიკური ფლაგები არ არის საჭირო.

Tuist-ის პროექტს შეუძლია შეინარჩუნოს GitHub-თან კავშირი და同时 გამოაქვეყნოს Entire-ში, რაც სასარგებლოა, როცა Entire-ის რეპოზიტორი GitHub-ის რეპოზიტორის სარკეა. ინტეგრაცია არ მოითხოვს Tuist-ის CI executor-ს და არ ცვლის თქვენს CI პროვაიდერს.

## ანგარიშები და ნებართვები {#reports-and-permissions}

პლაგინის დაყენებისას, თქვენ ანიჭებთ ნებართვებს, რომლებიც მას სჭირდება Trails-ის მოსაძებნად და ანგარიშების გამოსაქვეყნებლად:

| ნებართვა | გამოყენების მიზანი |
| --- | --- |
| რეპოზიტორიის შინაარსი: კითხვა | Trail-ის მოვლენების მიღება და გახსნილი და შავი Trails-ის მოძიება მათი head კომიტებით. |
| შემოწმებები: ჩაწერა | Tuist-ის გეიტის გამოქვეყნება Trail-ის head კომიტზე. |
| აღმოჩენები: ჩაწერა | წარუმატებელი და არასტაბილური ტესტების გამოქვეყნება აღმოჩენებად, და ძველი აღმოჩენების გადაწყვეტა, რომლებსაც ახალი ანგარიში ცვლის. |
| დისკუსიები: ჩაწერა | შეჯამების კომენტარის განთავსება და განახლება. მის გარეშეც, Tuist მაინც აქვეყნებს გეიტს და აღმოჩენებს. |

Tuist-ს არ სჭირდება წვდომა თქვენს საწყის კოდზე ჩაწერისთვის ან ნებართვა Trails-ის შერწყმისთვის.

Tuist თითოეულ Trail-ზე სამ რამეს აქვეყნებს:

- **გეიტი:** Tuist-ის შემოწმება ჩნდება **Gates**-ის ქვეშ შესრულების ანგარიშით და ბმულით პროექტზე Tuist-ში. ის ჩამოთვლილია Tuist-ის პლაგინის ქვეშ, ცალკე GitHub სარკის **Checks** გეიტისგან. ის სრულდება `neutral` დასკვნით, რომელსაც Entire გადილად აჩვენებს, რადგან ატვირთული შედეგები არ ეუბნება Tuist-ს, დასრულდა თუ არა ყველა მოსალოდნელი CI სამუშაო. ის არ ბლოკავს შერწყმას, მაშინაც კი, როცა არსებობს აღმოჩენები, ამიტომ შეინარჩუნეთ თქვენი CI პროვაიდერის საჭირო შემოწმებები pass/fail აღსრულებისთვის.
- **აღმოჩენები:** წარუმატებელი ტესტები და არასტაბილური ტესტები ჩნდება მთლიანი ცვლილებების აღმოჩენებად, რომლებიც ბმულს უკავშირდება ტესტის საქმეებს Tuist-ში. აღმოჩენები არ მონაწილეობენ Entire-ის Agent review გეიტში.
- **შეჯამების კომენტარი:** ისევე, როგორც pull request კომენტარი GitHub-ზე და Origin-ზე, თითოეული პროექტი ინახავს ერთ Tuist Run Report კომენტარს თითოეული Trail-ისთვის. თუ მას წაშლით, შემდეგი ანგარიში მას ხელახლა განათავსებს.

ახალი შედეგების მიღებისას, Tuist აქვეყნებს განახლებულ ანგარიშს Trail-ის მიმდინარე head კომიტისთვის და წყვეტს აღმოჩენებს, რომლებსაც ის ცვლის. ხელახლა ცდები არ ქმნიან დუბლიკატ შეფასებებს, აღმოჩენებს ან კომენტარებს, მათ შორის მაშინაც, როცა Entire-ის პასუხი გამოქვეყნებაზე იკარგება. Trail-ის გახსნა ან ხელახლა გახსნა იღებს შედეგებს, რომლებიც უკვე ატვირთულია მისი head კომიტისთვის. თუ მიმდინარე head კომიტისთვის შედეგები არ არსებობს, Tuist არაფერ ახალს არ აქვეყნებს, ამიტომ ძველი კომიტის გეიტი ვერ დააკმაყოფილებს ახალი head-ის მოთხოვნებს. დახურული და შერწყმული Trails არ განახლდება.

Entire-ის ბარათი ჩამოთვლის პროექტ-რეპოზიტორიის კავშირებს. აირჩიეთ **Manage → Remove connection** პროექტის კავშირზე, რათა შეწყვიტოთ მისი ანგარიშგება პლაგინის წაშლის გარეშე. უკვე გამოქვეყნებული ანგარიშები რჩება Entire-ზე, ხოლო ხელახლა დაკავშირება ახალ ანგარიშებს იწყებს. პლაგინის რეპოზიტორიის წვდომის შესაცვლელად ან მის წასაშლელად, გამოიყენეთ პროექტის **Plugins** პარამეტრები Entire-ში.

## თვითმასპინძელი სერვერები {#server-configuration}

თუ თქვენს საკუთარ Tuist სერვერს მასპინძლობთ, ჯერ დაარეგისტრირეთ და დააკონფიგურირეთ Entire პლაგინი თქვენი განლაგებისთვის. მიჰყევით <.localized_link href="/guides/server/self-host/server#platform-entire">Entire-ის თვითმასპინძლობის ინსტრუქციებს</.localized_link>, შემდეგ კი დაუბრუნდით ზემოთ მოცემულ დაყენების ნაბიჯებს ანგარიშების და პროექტების დასაკავშირებლად.
