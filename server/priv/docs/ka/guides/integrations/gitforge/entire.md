# Entire-ის ინტეგრაცია {#entire}

Tuist თითოეულ დაკავშირებულ რეპოზიტორიის ღია ან შავი ვერსიის [Trail](https://docs.entire.com/guides/trails/overview)-ზე ავტომატურად ქმნის შეჯამების განხილვას. შეჯამება მოიცავს ხელმისაწვდომ ბილდის შედეგებს, ტესტების შეცდომებს და არასტაბილურ ტესტებს, ბანდლების ზომებს და აპლიკაციის პრივიუებს, სრული ანგარიშების ბმულებით Tuist-ზე.

> [!IMPORTANT]
> **ადრეული წვდომა**
>
> Entire-ის პლაგინები მოითხოვენ პარტნიორის რეგისტრაციას, ხოლო მისი Trail განხილვები და webhook კონტრაქტები ექსპერიმენტულია. თქვენს Tuist ადმინისტრატორს შეუძლია ჩართოს ინტეგრაცია ყველა ანგარიშისთვის ან შერჩეული ანგარიშებისთვის. თქვენს Entire პროექტს ასევე უნდა ჰქონდეს ნებართვა დააინსტალიროს დარეგისტრირებული პლაგინი.

## მოწყობა {#setup}

ინსტალაცია მიჰყვება იგივე ნაკადს, როგორც GitHub-ის ინტეგრაცია: დააინსტალირეთ პლაგინი თქვენი ანგარიშისთვის, შემდეგ კი დააკავშირეთ რეპოზიტორიები Tuist პროექტებთან. hosted Tuist-ზე თქვენი ადმინისტრატორი უზრუნველყოფს პლაგინის რეგისტრაციას და სერვერის კონფიგურაციას; თქვენ მხოლოდ ქვემოთ მოცემული ნაბიჯები გჭირდებათ.

1. გახსენით თქვენი ანგარიშის **პარამეტრები → ინტეგრაციები**.
2. **Entire**-ში აირჩიეთ **Install Entire plugin**. აირჩიეთ Entire პროექტი და რეპოზიტორიები, რომლებიც გსურთ გაუზიაროთ Tuist-ს.

   ![დააინსტალირეთ Entire პლაგინი ანგარიშის ინტეგრაციებიდან](/images/guides/integrations/gitforge/entire/integrations.png)

3. Tuist-ში დაბრუნებისას აირჩიეთ **Add new project connection**. **Choose repository to connect to** ველში აირჩიეთ თქვენი Tuist პროექტი და Entire რეპოზიტორია, შემდეგ კი აირჩიეთ **Create Connection**. თუ მხოლოდ ერთი Tuist პროექტია ხელმისაწვდომი, ის ავტომატურად შეირჩევა.

   ![Tuist პროექტის დაკავშირება Entire რეპოზიტორიასთან](/images/guides/integrations/gitforge/entire/add-project-connection.png)

4. აგრძელეთ თქვენი insights-ების ატვირთვა CI-დან თქვენი არსებული ავთენტიფიცირებული Tuist ბრძანებების გამოყენებით. Tuist ადარებს მათ თითოეული Trail-ის მიმდინარე commit SHA-ს; Entire-ის სპეციფიური CLI ფლაგები არ არის საჭირო.

Tuist პროექტს შეუძლია შეინარჩუნოს GitHub-თან კავშირი და ამავდროულად გამოაქვეყნოს შეჯამებები Entire-ში. ეს სასარგებლოა GitHub სარკეებისთვის. Trail შეჯამებები არ მოითხოვს Tuist-ის CI executor-ს და არ ცვლის თქვენს არსებულ CI პროვაიდერს.

Tuist ანახლებს იმავე განხილვას, როგორც კი insights-ები მოდის. Trail-ის გახსნა ან ხელახლა გახსნა ასევე იღებს მისი head commit-ისთვის ადრე ატვირთულ insights-ებს. დახურული და შერწყმული Trails არ განახლდება. ძველი commit-ების შედეგები არასოდეს წარმოდგენილია როგორც მიმდინარე head-ის შედეგები. თუ მიმდინარე commit-ისთვის insights არ არსებობს, Tuist ტოვებს არსებულ შეჯამებას უცვლელად; თითოეული შედეგი შეიცავს მის commit hash-ს.

პროექტის კავშირის წასაშლელად, გახსენით მისი **Manage** მენიუ და აირჩიეთ **Remove connection**, ისევე როგორც GitHub-ის შემთხვევაში. ეს აჩერებს მომავალ განახლებებს და შლის Tuist-ის ადგილობრივ განხილვის მაჩვენებლებს. უკვე გამოქვეყნებული კომენტარები რჩება Entire-ზე. ხელახლა დაკავშირება აღადგენს არსებულ შეჯამებას, თუ ის კვლავ ხელმისაწვდომია. პლაგინის რეპოზიტორიის წვდომის შესაცვლელად ან მისი წასაშლელად, გამოიყენეთ პროექტის **Plugins** პარამეტრები Entire-ში.

## სერვერის კონფიგურაცია {#server-configuration}

ეს სექცია განკუთვნილია Tuist სერვერის ოპერატორებისთვის. დაარეგისტრირეთ პლაგინი Entire-თან [პლაგინის რეგისტრაციის სახელმძღვანელოს](https://docs.entire.com/guides/api/plugins/register) გამოყენებით. მოითხოვეთ `contents:read` და `discussions:write`. წაკითხვის ნებართვა საჭიროა Trail ღონისძიებებისა და განხილვების აღმოჩენისთვის; რეპოზიტორიის ჩაწერის წვდომა არ არის საჭირო.

დააკონფიგურიერეთ ეს სერვერის გარემოს ცვლადები:

| ცვლადი | მიზანი |
| --- | --- |
| `TUIST_ENTIRE_PLUGIN_SLUG` | Slug, დადასტურებული Entire-ის მიერ |
| `TUIST_ENTIRE_PLUGIN_PRIVATE_KEY` | Ed25519 პირადი გასაღები PEM ფორმატში, მიწოდებული თქვენი საიდუმლოებების საცავიდან |
| `TUIST_ENTIRE_PLUGIN_KEY_ID` | Key ID JWKS-ზე დაფუძნებული გასაღების რეგისტრაციის გამოყენებისას; წინააღმდეგ შემთხვევაში არასავალდებულო |
| `TUIST_ENTIRE_CORE_URL` | Entire Core, გამოყენებული ინსტალაციის მოთხოვნებისთვის; ნაგულისხმევად `https://eu.auth.entire.io` |
| `TUIST_ENTIRE_DELIVERY_JWKS_URL` | Webhook-ის ხელმოწერის გასაღების URL, მიწოდებული Entire-ის მიერ რეგისტრაციისას |

მართული Helm განლაგებებისთვის, შეინახეთ პირადი PEM გარემოს 1Password საცავში როგორც `ENTIRE_PLUGIN/private_key`, შემდეგ კი ჩართეთ `server.config.entirePluginKey.enabled` ერთად `server.config.managedSecrets`-თან. External Secrets აწვდის `TUIST_ENTIRE_PLUGIN_PRIVATE_KEY`-ს არსებული server-config Secret-ის მეშვეობით multiline PEM-ის შეკვეცის გარეშე. ელემენტისა და ველის სახელები კონფიგურირებადია `server.config.entirePluginKey.item` და `.field`-ის მეშვეობით. ეს მითითება ნაგულისხმევად გამორთულია და არ აკონფიგურირებს slug-ს ან webhook-ის ხელმოწერის გასაღების URL-ს; მიეწოდეთ ისინი ცალ-ცალკე რეგისტრაციის შემდეგ. თითოეულ გარემოს უნდა ჰქონდეს საკუთარი ხელმოწერის გასაღები. Entire-ს გაუზიარეთ მხოლოდ საჯარო PEM, არასოდეს პირადი გასაღები.

დაარეგისტრირეთ `https://<your-tuist-host>/integrations/entire/callback` როგორც post-install URL და `https://<your-tuist-host>/webhooks/entire` როგორც webhook URL. სერვერის მიგრაციების გამოყენების შემდეგ, ჩართეთ `entire_trails` feature flag გლობალურად, რათა შესთავაზოთ ინტეგრაცია ყველა ანგარიშს, ან ჩართეთ ის შერჩეული ანგარიშებისთვის. საჯარო გაშვებისთვის, სთხოვეთ თქვენს Entire კონტაქტს, ნება დართოს ინსტალაცია პლაგინის მფლობელი პროექტის გარეთ; Tuist feature flag-ის ჩართვა არ ცვლის Entire-ის ინსტალაციის პოლიტიკას. Entire Trail შეჯამებები დამოუკიდებელია Tuist-ის CI შესრულების კონფიგურაციისა და feature flag-ისგან.

Tuist ამოწმებს ინსტალაციის ქვითრებსა და webhook ხელმოწერებს, ქმნის ხანმოკლე, რეპოზიტორიის დონეზე შეზღუდულ ტოკენებს და ადგენს თითოეული რეპოზიტორიის მიმდინარე დამუშავების რეგიონს გამოქვეყნებამდე. ტოკენები არასოდეს არის ჩაშენებული ანგარიშის ბმულებში.
