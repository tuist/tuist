# Entire-ს ინტეგრაცია {#entire}

Tuist-ს შეუძლია გამოაქვეყნოს ბილდის, ტესტების, პრევიუს და ბანდლის ანალიტიკა ღია და პროექტის [Trails](https://docs.entire.com/guides/trails/overview)-ებზე [Entire](https://entire.com)-ის რეპოზიტორიებში. თითოეულ Trail-ს ენიჭება Tuist-ის გეიტი გაშვების ანგარიშით, მთლიანი ცვლილების აღმოჩენებით ჩავარდნილი და არასტაბილური ტესტებისთვის, და შეჯამების კომენტარით, რომელსაც Tuist აახლებს ახალი ანალიტიკის მიღებისას იმის ნაცვლად, რომ ყოველი ატვირთვისთვის ახალი გამოაქვეყნოს.

პლაგინის ინსტალაცია არ ასრულებს ბილდებს ან ტესტებს. თქვენი არსებული სამუშაო პროცესები განაგრძობენ შედეგების ატვირთვას Tuist-ში, ხოლო ინტეგრაცია ამ შედეგებს თქვენს Trails-ებში აერთიანებს.

## დაყენება {#setup}

Tuist-ის ანგარიშის ადმინისტრატორი აინსტალირებს პლაგინს, შემდეგ კი აკავშირებს რეპოზიტორიებს Tuist-ის პროექტებთან, ისევე როგორც <.localized_link href="/guides/integrations/gitforge/github">GitHub</.localized_link>-ის და <.localized_link href="/guides/integrations/gitforge/origin">Origin</.localized_link>-ის ინტეგრაციების შემთხვევაში.

1. გახსენით თქვენი ანგარიშის **Settings → Integrations**.
2. Entire-ს ბარათში აირჩიეთ **Install Entire plugin**. აირჩიეთ Entire-ის პროექტი და რეპოზიტორიები, რომლებიც გსურთ გაუზიაროთ Tuist-ს.

   ![Install the Entire plugin from account integrations](/images/guides/integrations/gitforge/entire/integrations.png)

3. Tuist-ში დაბრუნებისას აირჩიეთ **Add new project connection**. **Choose repository to connect to**-ში აირჩიეთ თქვენი Tuist-ის პროექტი და Entire-ის რეპოზიტორი, შემდეგ კი აირჩიეთ **Create Connection**. თუ მხოლოდ ერთი Tuist-ის პროექტია ხელმისაწვდომი, ის ავტომატურად შეირჩევა.

   ![Connect a Tuist project to an Entire repository](/images/guides/integrations/gitforge/entire/add-project-connection.png)

4. განაგრძეთ CI-დან შედეგების ატვირთვა თქვენი არსებული, ავთენტიფიცირებული Tuist-ის ბრძანებებით, მაგალითად, <.localized_link href="/guides/server/authentication#account-tokens">account token</.localized_link>-ის გამოყენებით. Tuist ათანადებს შედეგებს თითოეული Trail-ის მიმდინარე head კომიტთან, ამიტომ Entire-ის სპეციფიკური ფლაგები არ არის საჭირო.

Tuist-ის პროექტს შეუძლია შეინარჩუნოს GitHub-თან კავშირი და პარალელურად გამოაქვეყნოს Entire-ში, რაც სასარგებლოა, როცა Entire-ის რეპოზიტორი GitHub-ის რეპოზიტორის სარკისებურია. ინტეგრაცია არ მოითხოვს Tuist-ის CI executor-ს და არ ცვლის თქვენს CI პროვაიდერს.

## ანგარიშები და ნებართვები {#reports-and-permissions}

პლაგინის ინსტალაციისას თქვენ ანიჭებთ ნებართვებს, რომლებიც მას სჭირდება Trails-ების საპოვნელად და ანგარიშების გამოსაქვეყნებლად:

| ნებართვა | გამოიყენება |
| --- | --- |
| რეპოზიტორიის შინაარსი: წაკითხვა | Trail-ის მოვლენების მიღება და ღია და პროექტის Trails-ების პოვნა მათი head კომიტებით. |
| Checks: ჩაწერა | Tuist-ის გეიტის გამოქვეყნება Trail-ის head კომიტზე. |
| Findings: ჩაწერა | ჩავარდნილი და არასტაბილური ტესტების გამოქვეყნება აღმოჩენების სახით და იმ აღმოჩენების გადაწყვეტა, რომლებსაც უფრო ახალი ანგარიში ცვლის. |
| Discussions: ჩაწერა | შეჯამების კომენტარის განთავსება და განახლება. მის გარეშეც Tuist მაინც აქვეყნებს გეიტს და აღმოჩენებს. |

Tuist-ს არ სჭირდება წვდომა თქვენს საწყის კოდზე ჩაწერისთვის ან Trails-ების შერწყმის ნებართვა.

Tuist თითოეულ Trail-ზე სამ რამეს აქვეყნებს:

- **Gate:** Tuist-ის შემოწმება ჩნდება **Gates**-ის ქვეშ გაშვების ანგარიშით და ბმულით პროექტზე Tuist-ში. ის ჩამოთვლილია Tuist-ის პლაგინის ქვეშ, ცალკე GitHub სარკის **Checks** გეიტისგან. ის სრულდება `neutral` დასკვნით, რასაც Entire გადაცემულად აჩვენებს, რადგან ატვირთული შედეგები არ ეუბნება Tuist-ს, დასრულდა თუ არა ყველა მოსალოდნელი CI დავალება. ის არ ბლოკავს შერწყმას, მაშინაც კი, როცა არსებობს აღმოჩენები, ამიტომ შეინარჩუნეთ თქვენი CI პროვაიდერის საჭირო შემოწმებები pass/fail აღსრულებისთვის.
- **Findings:** ჩავარდნილი ტესტები და არასტაბილური ტესტები ჩნდებიან მთლიანი ცვლილების აღმოჩენების სახით, რომლებიც ბმულს აკეთებენ Tuist-ის ტესტის საქმეებზე. აღმოჩენები არ მონაწილეობენ Entire-ის Agent review გეიტში.
- **Summary comment:** ისევე, როგორც pull request კომენტარი GitHub-ზე და Origin-ზე, თითოეული პროექტი ინარჩუნებს ერთ Tuist Run Report კომენტარს თითოეული Trail-ისთვის. თუ მას წაშლით, შემდეგი ანგარიში ისევ გამოაქვეყნებს მას.

ახალი შედეგების მიღებისას Tuist აქვეყნებს განახლებულ ანგარიშს Trail-ის მიმდინარე head კომიტისთვის და წყვეტს იმ აღმოჩენებს, რომლებსაც ის ცვლის. ხელახალი გაშვებები არ ქმნიან დუბლირებულ მიმოხილვებს, აღმოჩენებს ან კომენტარებს, მაშინაც კი, როცა Entire-ის პასუხი გამოქვეყნებაზე იკარგება. Trail-ის გახსნა ან ხელახლა გახსნა იღებს შედეგებს, რომლებიც უკვე ატვირთულია მისი head კომიტისთვის. თუ მიმდინარე head კომიტისთვის შედეგები არ არსებობს, Tuist არაფერ ახალს არ აქვეყნებს, ამიტომ ძველი კომიტის გეიტი ვერ დააკმაყოფილებს ახალი head-ის მოთხოვნებს. დახურული და შერწყმული Trails-ები არ განახლდება.

Entire-ს ბარათი ჩამოთვლის პროექტიდან რეპოზიტორიამდე კავშირებს. აირჩიეთ **Manage → Remove connection** პროექტის კავშირზე, რათა შეაჩეროთ მისი ანგარიშგება პლაგინის წაშლის გარეშე. უკვე გამოქვეყნებული ანგარიშები რჩება Entire-ზე, ხოლო ხელახლა დაკავშირება იწყებს ახალ ანგარიშებს. პლაგინის რეპოზიტორიის წვდომის შესაცვლელად ან მის წასაშლელად, გამოიყენეთ პროექტის **Plugins** პარამეტრები Entire-ში.

## თვითმასპინძელი სერვერები {#server-configuration}

თუ თქვენ მასპინძლობთ თქვენს საკუთარ Tuist სერვერს, ჯერ დაარეგისტრირეთ და დააკონფიგურირეთ Entire პლაგინი თქვენი განლაგებისთვის. მიჰყევით <.localized_link href="/guides/server/self-host/server#platform-entire">Entire self-hosting instructions</.localized_link>-ს, შემდეგ კი დაუბრუნდით ზემოთ მოცემულ დაყენების ნაბიჯებს ანგარიშებისა და პროექტების დასაკავშირებლად.
