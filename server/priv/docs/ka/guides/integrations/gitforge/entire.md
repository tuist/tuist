# Entire-ის ინტეგრაცია {#entire}

Tuist-ს შეუძლია აშენების, ტესტირების, პრივიუსა და ბანდლის ანალიტიკის გამოქვეყნება ღია და შავ დრაფტში მყოფ [Trails](https://docs.entire.com/guides/trails/overview)-ებზე [Entire](https://entire.com)-ის რეპოზიტორიებში. თითოეულ Trail-ს ენიჭება Tuist-ის გეიტი გაშვების ანგარიშით, მთლიანი ცვლილებების აღმოჩენებით წარუმატებელი და არასტაბილური ტესტებისთვის, და შეჯამებითი კომენტარით, რომელსაც Tuist აახლებს ახალი ანალიტიკის მიღებისას, ნაცვლად იმისა, რომ ყოველი ატვირთვისთვის ახალი განათავსოს.

პლაგინის დაყენება არ ასრულებს აშენებებს ან ტესტებს. თქვენი არსებული სამუშაო პროცესები აგრძელებენ შედეგების ატვირთვას Tuist-ში, ხოლო ინტეგრაცია ამ შედეგებს თქვენს Trails-ებში აერთიანებს.

## მორგება {#setup}

Tuist-ის ანგარიშის ადმინისტრატორი აყენებს პლაგინს, შემდეგ კი აკავშირებს რეპოზიტორიებს Tuist-ის პროექტებთან, ისევე როგორც <.localized_link href="/guides/integrations/gitforge/github">GitHub</.localized_link>-ის და <.localized_link href="/guides/integrations/gitforge/origin">Origin</.localized_link>-ის ინტეგრაციების შემთხვევაში.

1. გახსენით თქვენი ანგარიშის **Settings → Integrations**.
2. Entire-ის ბარათში აირჩიეთ **Install Entire plugin**. აირჩიეთ Entire-ის პროექტი და რეპოზიტორიები, რომლებიც გსურთ Tuist-თან გააზიაროთ.

   ![დააყენეთ Entire-ის პლაგინი ანგარიშის ინტეგრაციებიდან](/images/guides/integrations/gitforge/entire/integrations.png)

3. Tuist-ში დაბრუნებისას, აირჩიეთ **Add new project connection**. **Choose repository to connect to**-ში აირჩიეთ თქვენი Tuist-ის პროექტი და Entire-ის რეპოზიტორი, შემდეგ კი აირჩიეთ **Create Connection**. თუ მხოლოდ ერთი Tuist-ის პროექტია ხელმისაწვდომი, ის ავტომატურად იქნება არჩეული.

   ![Tuist-ის პროექტის Entire-ის რეპოზიტორიასთან დაკავშირება](/images/guides/integrations/gitforge/entire/add-project-connection.png)

4. აგრძელეთ CI-დან შედეგების ატვირთვა თქვენი არსებული, ავთენტიკირებული Tuist-ის ბრძანებებით, მაგალითად, <.localized_link href="/guides/server/authentication#account-tokens">account token</.localized_link>-ის გამოყენებით. Tuist შედეგებს უკავშირებს თითოეული Trail-ის მიმდინარე head commit-ს, ამიტომ Entire-ის სპეციფიკური ფლაგები არ არის საჭირო.

Tuist-ის პროექტს შეუძლია შეინარჩუნოს GitHub-თან კავშირი და პარალელურად გამოაქვეყნოს Entire-ში, რაც სასარგებლოა, როდესაც Entire-ის რეპოზიტორია GitHub-ის რეპოზიტორიას ასახავს. ინტეგრაცია არ მოითხოვს Tuist-ის CI executor-ს და არ ცვლის თქვენს CI პროვაიდერს.

## ანგარიშები და ნებართვები {#reports-and-permissions}

პლაგინის დაყენებისას, თქვენ ანიჭებთ მას ნებართვებს, რომლებიც საჭიროა Trails-ების მოსაძებნად და ანგარიშების გამოსაქვეყნებლად:

| ნებართვა | გამოიყენება |
| --- | --- |
| რეპოზიტორიის შიგთავსი: კითხვა | Trail-ის მოვლენების მიღება და ღია და დრაფტში მყოფი Trails-ების მოძებნა მათი head commit-ებით. |
| შემოწმებები: ჩაწერა | Tuist-ის გეიტის გამოქვეყნება Trail-ის head commit-ზე. |
| აღმოჩენები: ჩაწერა | წარუმატებელი და არასტაბილური ტესტების გამოქვეყნება აღმოჩენების სახით და ძველი აღმოჩენების გადაწყვეტა, რომლებსაც ახალი ანგარიში ცვლის. |
| დისკუსიები: ჩაწერა | შეჯამებითი კომენტარის განთავსება და განახლება. მის გარეშეც, Tuist მაინც აქვეყნებს გეიტს და აღმოჩენებს. |

Tuist-ს არ სჭირდება წვდომა თქვენს საწყის კოდზე ჩაწერისთვის ან Trails-ების შერწყმის ნებართვა.

Tuist თითოეულ Trail-ზე სამ რამეს აქვეყნებს:

- **გეიტი:** Tuist-ის შემოწმება ჩნდება **Gates**-ის ქვეშ გაშვების ანგარიშით და ბმულით Tuist-ის პროექტზე. ის ჩამოთვლილია Tuist-ის პლაგინის ქვეშ, ცალკე GitHub-ის სარკის **Checks** გეიტისგან. ის სრულდება `neutral` დასკვნით, რასაც Entire წარმატებულად აჩვენებს, რადგან ატვირთული შედეგები Tuist-ს არ ეუბნება, დასრულდა თუ არა ყველა მოსალოდნელი CI სამუშაო. ის არ ბლოკავს შერწყმას, მაშინაც კი, როცა არსებობს აღმოჩენები, ამიტომ შეინარჩუნეთ თქვენი CI პროვაიდერის საჭირო შემოწმებები pass/fail აღსრულებისთვის.
- **აღმოჩენები:** წარუმატებელი ტესტები და არასტაბილური ტესტები ჩნდებიან მთლიანი ცვლილების აღმოჩენების სახით, რომლებიც ბმულს აკეთებენ Tuist-ის ტესტის საქმეებზე. აღმოჩენები არ მონაწილეობენ Entire-ის Agent review გეიტში.
- **შეჯამებითი კომენტარი:** ისევე, როგორც pull request-ის კომენტარი GitHub-ზე და Origin-ზე, თითოეული პროექტი ინარჩუნებს ერთ Tuist Run Report კომენტარს თითოეული Trail-ისთვის. თუ წაშლით, შემდეგი ანგარიში მას ხელახლა გამოაქვეყნებს.

ახალი შედეგების მიღებისას, Tuist აქვეყნებს განახლებულ ანგარიშს Trail-ის მიმდინარე head commit-ისთვის და წყვეტს იმ აღმოჩენებს, რომლებსაც ის ცვლის. ხელახლა ცდები არ ქმნიან დუბლიკატ მიმოხილვებს, აღმოჩენებს ან კომენტარებს, მაშინაც კი, როცა Entire-ის პასუხი გამოქვეყნებაზე იკარგება. Trail-ის გახსნა ან ხელახლა გახსნა იღებს შედეგებს, რომლებიც უკვე ატვირთულია მისი head commit-ისთვის. თუ მიმდინარე head commit-ისთვის შედეგები არ არსებობს, Tuist არაფერ ახალს არ აქვეყნებს, ამიტომ ძველი commit-ის გეიტი ვერ დააკმაყოფილებს ახალი head-ის მოთხოვნებს. დახურული და შერწყმული Trails-ები არ განახლდება.

Entire-ის ბარათი ჩამოთვლის პროექტ-რეპოზიტორიის კავშირებს. აირჩიეთ **Manage → Remove connection** პროექტის კავშირზე, რათა შეაჩეროთ მისი ანგარიშგება პლაგინის წაშლის გარეშე. უკვე გამოქვეყნებული ანგარიშები რჩებიან Entire-ზე, ხოლო ხელახლა დაკავშირება ახალ ანგარიშებს იწყებს. პლაგინის რეპოზიტორიის წვდომის შესაცვლელად ან მის წასაშლელად, გამოიყენეთ პროექტის **Plugins** პარამეტრები Entire-ში.

## თვითმასპინძელი სერვერები {#server-configuration}

თუ თქვენს საკუთარ Tuist სერვერს მასპინძლობთ, ჯერ დაარეგისტრირეთ და მოარგეთ Entire პლაგინი თქვენს განლაგებას. მიჰყევით <.localized_link href="/guides/server/self-host/server#platform-entire">Entire self-hosting instructions</.localized_link>, შემდეგ კი დაუბრუნდით ზემოთ მოცემულ მორგების ნაბიჯებს ანგარიშებისა და პროექტების დასაკავშირებლად.
