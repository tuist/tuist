# HTTP პროქსი {#http-proxy}

როდესაც გარემოში დაყენებულია `HTTPS_PROXY` ან `HTTP_PROXY`, Tuist ავტომატურად მიმართავს მის მიერ მართულ HTTP შეერთებებს ამ პროქსის მეშვეობით. ეს ვრცელდება როგორც Tuist CLI-ზე, ისე Tuist Gradle პლაგინზე და არ საჭიროებს დამატებით კონფიგურაციას.

მოქმედება ემთხვევა `curl`-ის, `git`-ისა და დეველოპერული ინსტრუმენტების უმეტესობის მიერ გამოყენებულ შეთანხმებას, ამიტომ ნებისმიერი გარემო, რომელიც სხვა ინსტრუმენტებისთვის უკვე აყენებს ამ ცვლადებს, Tuist-თან ერთად მუშაობს ყოველგვარი დამატებითი ქმედების გარეშე.

## რა გადის პროქსის მეშვეობით {#what-is-proxied}

პროქსის მეშვეობით გადის მხოლოდ Tuist-ის საკუთარი HTTP კლიენტები:

- ქეშის, პრივიუსების, ანალიტიკისა და რეესტრის ბოლოწერტილები (endpoints),
- და ზარები, რომლებსაც Gradle პლაგინი აკეთებს Tuist სერვისების მიმართ (დისტანციური ბილდ ქეში, ბილდის ინსაითები, ტესტების ინსაითები, ტესტების კარანტინი, ტესტების შარდინგი).

## ცვლადების ძიების თანმიმდევრობა {#variable-lookup-order}

Tuist კითხულობს პირველ არა-ცარიელ მნიშვნელობას შემდეგი თანმიმდევრობით:

1. `HTTPS_PROXY`
2. `https_proxy`
3. `HTTP_PROXY`
4. `http_proxy`

მნიშვნელობა უნდა იყოს URL, მაგალითად `http://proxy.corp:8080`. ჩაშენებული სარწმუნოებები (`http://user:password@proxy.corp:8080`) გათვალისწინებულია.
