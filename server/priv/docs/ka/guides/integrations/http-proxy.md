# HTTP პროქსი {#http-proxy}

როდესაც გარემოში მითითებულია `HTTPS_PROXY` ან `HTTP_PROXY`, Tuist ავტომატურად მიმართავს მის მიერ მართულ HTTP კავშირებს ამ პროქსის მეშვეობით. ეს ეხება როგორც Tuist CLI-ს, ასევე Tuist Gradle პლაგინს და არ საჭიროებს დამატებით კონფიგურაციას.

ქცევა შეესაბამება `curl`-ის, `git`-ისა და სხვა დეველოპერული ინსტრუმენტების მიერ გამოყენებულ შეთანხმებას, ამიტომ ნებისმიერი გარემო, სადაც ეს ცვლადები უკვე მითითებულია სხვა ინსტრუმენტებისთვის, Tuist-თან ერთად მუშაობს თავიდანვე.

## რა გადის პროქსის მეშვეობით {#what-is-proxied}

პროქსის მეშვეობით გადის მხოლოდ Tuist-ის მიერ მართული HTTP კლიენტები:

- კეშის, პრივიუების, ანალიტიკისა და რეესტრის ბოლოწერტილები,
- და ზარები, რომლებსაც Gradle პლაგინი აკეთებს Tuist სერვისებთან (შორეული ბილდის კეში, ბილდის ინსაითები, ტესტების ინსაითები, ტესტების კარანტინი, ტესტების შარდინგი).

## ცვლადების ძიების თანმიმდევრობა {#variable-lookup-order}

Tuist კითხულობს პირველ არაცარიელ მნიშვნელობას შემდეგი თანმიმდევრობით:

1. `HTTPS_PROXY`
2. `https_proxy`
3. `HTTP_PROXY`
4. `http_proxy`

მნიშვნელობა უნდა იყოს URL, მაგალითად `http://proxy.corp:8080`. ინლაინ კრედენციალები (`http://user:password@proxy.corp:8080`) მხარდაჭერილია.
