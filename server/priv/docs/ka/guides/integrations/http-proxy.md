# HTTP პროქსი {#http-proxy}

როდესაც გარემოში დაყენებულია `HTTPS_PROXY` ან `HTTP_PROXY`, Tuist ავტომატურად მიმართავს მის მიერ მართულ HTTP შეერთებებს ამ პროქსის მეშვეობით. ეს ვრცელდება როგორც Tuist CLI-ზე, ისე Tuist Gradle პლაგინზე და არ საჭიროებს დამატებით კონფიგურაციას.

მოქმედება ემთხვევა `curl`-ის, `git`-ისა და სხვა დეველოპერული ინსტრუმენტების მიერ გამოყენებულ კონვენციას, ამიტომ ნებისმიერი გარემო, სადაც ეს ცვლადები უკვე დაყენებულია სხვა ინსტრუმენტებისთვის, Tuist-თან ერთად მუშაობს დამატებითი ქმედებების გარეშე.

## რა გადის პროქსის მეშვეობით {#what-is-proxied}

პროქსის მეშვეობით გადის მხოლოდ Tuist-ის კუთვნილი HTTP კლიენტები:

- ქეშის, პრივიუების, ანალიტიკისა და რეესტრის ენდპოინტები,
- და ზარები, რომლებსაც Gradle პლაგინი აკეთებს Tuist სერვისებთან (დაშორებული ბილდის ქეში, ბილდის ინსაითები, ტესტების ინსაითები, ტესტების კარანტინი, ტესტების შარდინგი).

## ცვლადების ძიების თანმიმდევრობა {#variable-lookup-order}

Tuist კითხავს პირველ არა-ცარიელ მნიშვნელობას შემდეგი თანმიმდევრობით:

1. `HTTPS_PROXY`
2. `https_proxy`
3. `HTTP_PROXY`
4. `http_proxy`

მნიშვნელობა უნდა იყოს URL, მაგალითად `http://proxy.corp:8080`. ინლაინ კრედენციალები (`http://user:password@proxy.corp:8080`) მიღებულია.
