# HTTP პროქსი {#http-proxy}

როდესაც გარემოში დაყენებულია `HTTPS_PROXY` ან `HTTP_PROXY`, Tuist ავტომატურად აგზავნის მის მიერ მართულ HTTP შეერთებებს ამ პროქსის მეშვეობით. ეს ვრცელდება როგორც Tuist CLI-ზე, ასევე Tuist Gradle პლაგინზე და არ საჭიროებს დამატებით კონფიგურაციას.

ქცევა ემთხვევა `curl`-ის, `git`-ისა და სხვა დეველოპერული ინსტრუმენტების მიერ გამოყენებულ კონვენციას, ამიტომ ნებისმიერი გარემო, სადაც ეს ცვლადები უკვე დაყენებულია სხვა ინსტრუმენტებისთვის, Tuist-თან ერთად მუშაობს „ყუთიდან ამოღების“ პრინციპით.

## რა გადის პროქსის მეშვეობით {#what-is-proxied}

პროქსის მეშვეობით გადის მხოლოდ Tuist-ის საკუთარი HTTP კლიენტები:

- კეშის, პრივიუების, ანალიტიკისა და რეესტრის ბოლოწერტილები (endpoints),
- და Gradle პლაგინის მიერ Tuist-ის სერვისებთან შესრულებული ზარები (დისტანციური ბილდის კეში, ბილდის ანალიტიკა, ტესტების ანალიტიკა, ტესტების კარანტინი, ტესტების შარდინგი).

## ცვლადების ძიების თანმიმდევრობა {#variable-lookup-order}

Tuist კითხულობს პირველ არაცარიელ მნიშვნელობას შემდეგი თანმიმდევრობით:

1. `HTTPS_PROXY`
2. `https_proxy`
3. `HTTP_PROXY`
4. `http_proxy`

მნიშვნელობა უნდა იყოს URL, მაგალითად `http://proxy.corp:8080`. ინლაინ ავტორიზაციის მონაცემები (`http://user:password@proxy.corp:8080`) მხარდაჭერილია.
