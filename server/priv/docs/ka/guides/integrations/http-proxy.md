# HTTP პროქსი {#http-proxy}

როდესაც გარემოში დაყენებულია `HTTPS_PROXY` ან `HTTP_PROXY`, Tuist ავტომატურად მიმართავს მის მიერ მართულ HTTP კავშირებს ამ პროქსის მეშვეობით. ეს ვრცელდება როგორც Tuist CLI-ზე, ასევე Tuist Gradle პლაგინზე, დამატებითი კონფიგურაციის საჭიროების გარეშე.

ქცევა ემთხვევა `curl`-, `git`-ისა და დეველოპერული ინსტრუმენტების უმეტესობის მიერ გამოყენებულ შეთანხმებას, ამიტომ ნებისმიერი გარემო, რომელიც სხვა ინსტრუმენტებისთვის უკვე აყენებს ამ ცვლადებს, Tuist-თან ერთად მუშაობს „ყუთიდან ამოღების“ პრინციპით.

## რა გადის პროქსის მეშვეობით {#what-is-proxied}

პროქსის მეშვეობით გადის მხოლოდ Tuist-ის მიერ მართული HTTP კლიენტები:

- კეშის, პრივიუების, ანალიტიკისა და რეესტრის ბოლოწერტილები (endpoints),
- და ზარები, რომლებსაც Gradle პლაგინი აკეთებს Tuist სერვისებთან (დაშორებული ბილდის კეში, ბილდის ინსაითები, ტესტების ინსაითები, ტესტების კარანტინი, ტესტების შარდინგი).

## ცვლადების ძიების თანმიმდევრობა {#variable-lookup-order}

Tuist კითხავს პირველ არა-ცარიელ მნიშვნელობას შემდეგი თანმიმდევრობით:

1. `HTTPS_PROXY`
2. `https_proxy`
3. `HTTP_PROXY`
4. `http_proxy`

მნიშვნელობა უნდა იყოს URL, მაგალითად `http://proxy.corp:8080`. ინლაინ კრედენშიალები (`http://user:password@proxy.corp:8080`) აღიქმება.
