# Tuist-ის ინტეგრაცია Slack-თან {#slack}

Tuist-ის Slack-ინტეგრაცია პირდაპირ თქვენს არხებში აჩენს ბილდების, ტესტებისა და ბანდლების შესახებ ინფორმაციას. ის მონიტორინგს გარდაქმნის რუტინული ამოცანიდან ავტომატურ პროცესად. მაგალითად, თქვენი გუნდი შეიძლება იღებდეს ყოველდღიურ შეჯამებებს ბილდების წარმადობის, ქეშში მოხვედრის სიხშირის ან ბანდლის ზომის ტენდენციების შესახებ, ასევე მიიღოს მყისიერი გაფრთხილებები მაშინვე, როცა საკვანძო მეტრიკა უარესდება ან ტესტი ხდება არასტაბილური.

ეს გვერდი აღწერს, რას აკეთებს ინტეგრაცია, როგორ დავაინსტალიროთ ის თითოეული არხისთვის და როგორ ამუშავებს Tuist თქვენს მონაცემებს. დეტალური ინფორმაციისთვის, თუ როგორ აგროვებს, მართავს და ინახავს Tuist მესამე მხარის მონაცემებს, იხილეთ ჩვენი [კონფიდენციალურობის პოლიტიკა](https://tuist.dev/privacy).

## როგორ მუშაობს ინტეგრაცია {#how-it-works}

Tuist აგზავნის შეტყობინებებს Slack-ში Slack-ის [Incoming Webhooks](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks)-ის მეშვეობით. ინტეგრაცია ითხოვს მხოლოდ `incoming-webhook` ნებართვას. თითოეული შეტყობინების დანიშნულების ადგილი (პროექტის ანგარიში, გაფრთხილების წესი, არასტაბილური ტესტის გაფრთხილება, ავტომატიზაციის მოქმედება) შეესაბამება ერთ Slack-არხს, რომელსაც თქვენ ირჩევთ ინსტალაციის დროს. Slack ქმნის ერთ webhook URL-ს თითოეული არხისთვის, ხოლო Tuist ინახავს მას შეტყობინებების მიწოდებისთვის.

Tuist არასდროს კითხულობს შეტყობინებებს, წევრთა სიებს ან სხვა რაიმე მონაცემს თქვენი სამუშაო სივრციდან. ინტეგრაცია მხოლოდ წერს შეტყობინებებს იმ არხებში, რომლებიც თქვენ ცალსახად დაამტკიცეთ.

## მოწყობა {#setup}

### პროექტის ანგარიშები {#project-reports}

პროექტის ანგარიშები აწვდიან თქვენი პროექტის ბილდების, ტესტებისა და ქეშის მეტრიკების ყოველდღიურ შეჯამებას თქვენს მიერ შერჩეულ Slack-არხში.

1. გახსენით თქვენი პროექტის შეტყობინებების პარამეტრები Tuist-ის დაფაზე.
2. დააჭირეთ **Select Slack channel** და აირჩიეთ სამუშაო სივრცე და არხი, სადაც გსურთ Tuist-მა გამოაქვეყნოს შეტყობინებები. Slack მოგთხოვთ `incoming-webhook` ნებართვის დამტკიცებას და ერთი არხის არჩევას.
3. აირჩიეთ კვირის დღეები და დრო, როდესაც გსურთ ყოველდღიური ანგარიშის მიღება.

### გაფრთხილების წესები {#alert-rules}

გაფრთხილების წესები გატყობინებთ Slack-ში, როდესაც საკვანძო მეტრიკები მნიშვნელოვნად უარესდება, რაც დაგეხმარებათ დროულად შეამჩნიოთ ბილდების შენელება, ქეშის დეგრადაცია ან ტესტების შენელება.

გაფრთხილების წესის შესაქმნელად, გადადით თქვენი პროექტის შეტყობინებების პარამეტრებში და დააჭირეთ **Add alert rule**. შეგიძლიათ დააკონფიგურიროთ:

- **სახელი**: გაფრთხილების აღმწერი სახელი
- **კატეგორია**: რისი გაზომვა (ბილდის ხანგრძლივობა, ტესტის ხანგრძლივობა, ქეშში მოხვედრის სიხშირე ან ბანდლის ზომა)
- **მეტრიკა**: მონაცემთა აგრეგაციის მეთოდი (p50, p90, p99 ან საშუალო)
- **გადახრა**: პროცენტული ცვლილება, რომელიც იწვევს გაფრთხილებას
- **მოძრავი ფანჯარა**: რამდენი ბოლო გაშვების შედარება
- **ბრენჩი**: ქეშში მოხვედრის სიხშირის გაფრთხილებებისთვის, შეადარეთ მხოლოდ ერთ ბრენჩზე შესრულებულ გაშვებებს. დატოვეთ ცარიელი ყველა ბრენჩის გასათვალისწინებლად. ბანდლის ზომის გაფრთხილებები ყოველთვის ერთ ბრენჩს ეხება.
- **Slack-არხი**: დანიშნულების არხი. თქვენ ამტკიცებთ არხს ზემოთ აღწერილი `incoming-webhook` ნაკადის მეშვეობით.

მაგალითად, შეგიძლიათ შექმნათ გაფრთხილება, რომელიც აქტიურდება, როდესაც ბილდის p90 ხანგრძლივობა 20%-ზე მეტით იზრდება წინა 100 ბილდთან შედარებით.

ქეშში მოხვედრის სიხშირის გაფრთხილების თქვენს ძირითად ბრენჩზე შეზღუდვა სასარგებლოა, როდესაც მხოლოდ ეს ბრენჩი ავსებს ქეშს. Pull request-ების ბრენჩები, რომლებიც ეხებიან დაბალი დონის მოდულს, კანონიერად ვერ ხვდებიან ქეშში, და მათი ჩართვა გამოიწვევდა გაფრთხილებას მოსალოდნელი გაუარესებების დროს.

ქეშში მოხვედრის სიხშირის გაფრთხილება ადარებს მხოლოდ იმ ფანჯრებს, რომელთა სამართლიანი შედარებაც შესაძლებელია. ორივე ფანჯარაში უნდა იყოს იმდენივე გაშვება, რამდენიც მოძრავი ფანჯრის ზომაა, ხოლო ქეშის მონაცემთა წყარო, რომელიც მხოლოდ ერთ-ერთ ფანჯარაში ჩანს, გამოირიცხება ორივედან. ბრენჩი, რომელმაც ჯერ არ დააგროვა მოძრავი ფანჯრის ზომაზე ორჯერ მეტი გაშვება, ან ბრენჩის სახელი, რომელიც არაფერს ემთხვევა, არასდროს გაააქტიურებს წესს. თუ წესს აზღუდავთ დაბალი აქტივობის ბრენჩზე, შეინახეთ მოძრავი ფანჯარა საკმარისად მცირე, რომ ბრენჩმა შეძლოს მისი შევსება.

როდესაც გაფრთხილება აქტიურდება, თქვენ მიიღებთ მსგავს შეტყობინებას თქვენს Slack-არხში:

### არასტაბილური ტესტების გაფრთხილებები {#flaky-test-alerts}

არასტაბილური ტესტების გაფრთხილებები აქტიურდება მაშინვე, როდესაც Tuist აღმოაჩენს ახალ არასტაბილურ ტესტს, რაც დაგეხმარებათ შეამჩნიოთ ტესტების არასტაბილურობა მანამ, სანამ ის გავლენას მოახდენს თქვენს გუნდზე.

არასტაბილური ტესტის გაფრთხილების წესის შესაქმნელად, გადადით თქვენი პროექტის შეტყობინებების პარამეტრებში და დააჭირეთ **Add flaky test alert rule**. შეგიძლიათ დააკონფიგურიროთ:

- **სახელი**: გაფრთხილების აღმწერი სახელი
- **აქტივაციის ზღვარი**: ბოლო 30 დღეში არასტაბილური გაშვებების მინიმალური რაოდენობა, რომელიც საჭიროა გაფრთხილების აქტივაციისთვის
- **Slack-არხი**: დანიშნულების არხი, რომელიც ავტორიზებულია `incoming-webhook` ნაკადის მეშვეობით.

როდესაც ტესტი ხდება არასტაბილური და აკმაყოფილებს თქვენს ზღვარს, მიიღებთ შეტყობინებას პირდაპირი ბმულით სატესტო შემთხვევის შესასწავლად:

## ინტეგრაციის გათიშვა {#disconnect}

შეტყობინების შეჩერებისთვის, წაშალეთ კონფიგურირებული Slack-არხი ანგარიშში, გაფრთხილების წესში ან ავტომატიზაციის ქმედებაში თქვენს Tuist დაფაზე. Tuist-ზე სრული წვდომის გაუქმებისთვის, წაშალეთ webhook ინტეგრაცია Slack-ის შიგნიდან გზით **Settings & administration → Manage apps**.
