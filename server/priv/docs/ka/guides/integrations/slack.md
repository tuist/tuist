# Tuist-ის ინტეგრაცია Slack-თან {#slack}

Tuist-ის ინტეგრაცია Slack-თან პირდაპირ თქვენს არხებში აჩვენებს ბილდების, ტესტებისა და ბანდლების შესახებ ინფორმაციას. ის მონიტორინგს აქცევს რუტინული მოვალეობიდან ავტომატურ პროცესად. მაგალითად, თქვენი გუნდი მიიღებს ყოველდღიურ შეჯამებებს ბილდების წარმადობის, ქეშში მოხვედრის სიხშირის ან ბანდლის ზომის ტენდენციების შესახებ, ასევე მომენტალურ გაფრთხილებებს, როდესაც ძირითადი მეტრიკა უარესდება ან ტესტი ხდება არასტაბილური.

ეს გვერდი აღწერს, რას აკეთებს ინტეგრაცია, როგორ დავაყენოთ ის თითოეული არხისთვის და როგორ ამუშავებს Tuist თქვენს მონაცემებს. დეტალური ინფორმაციისთვის იმის შესახებ, თუ როგორ აგროვებს, მართავს და ინახავს Tuist მესამე მხარის მონაცემებს, იხილეთ ჩვენი [კონფიდენციალურობის პოლიტიკა](https://tuist.dev/privacy).

## როგორ მუშაობს ინტეგრაცია {#how-it-works}

Tuist აგზავნის შეტყობინებებს Slack-ში Slack-ის [Incoming Webhooks](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks)-ის საშუალებით. ინტეგრაცია ითხოვს მხოლოდ `incoming-webhook` ნებართვას. თითოეული შეტყობინების დანიშნულება (პროექტის ანგარიში, გაფრთხილების წესი, არასტაბილური ტესტის გაფრთხილება, ავტომატიზაციის ქმედება) შეესაბამება ერთ Slack-არხს, რომელსაც თქვენ ირჩევთ დაყენებისას. Slack ქმნის ერთ webhook URL-ს თითოეული არხისთვის, ხოლო Tuist ინახავს მას შეტყობინებების მიწოდებისთვის.

Tuist არასდროს კითხულობს შეტყობინებებს, წევრთა სიებს ან სხვა მონაცემებს თქვენი სამუშაო სივრციდან. ინტეგრაცია მხოლოდ წერს შეტყობინებებს იმ არხებში, რომლებიც თქვენ ცალსახად დაუშვით.

## დაყენება {#setup}

### პროექტის ანგარიშები {#project-reports}

პროექტის ანგარიშები ყოველდღიურად აგზავნის შეჯამებას თქვენი პროექტის ბილდების, ტესტებისა და ქეშის მეტრიკების შესახებ თქვენს მიერ არჩეულ Slack-არხში.

1. გახსენით თქვენი პროექტის შეტყობინებების პარამეტრები Tuist-ის დაფაზე.
2. დააჭირეთ **Select Slack channel** და აირჩიეთ სამუშაო სივრცე და არხი, სადაც გსურთ Tuist-მა გამოაქვეყნოს შეტყობინებები. Slack გთხოვთ დაუშვათ `incoming-webhook` ნებართვა და აირჩიოთ ერთი არხი.
3. აირჩიეთ კვირის დღეები და დრო, როდესაც გსურთ ყოველდღიური ანგარიშის მიღება.

### გაფრთხილების წესები {#alert-rules}

გაფრთხილების წესები გაგაფრთხილებთ Slack-ში, როდესაც ძირითადი მეტრიკები მნიშვნელოვნად უარესდება, რაც დაგეხმარებათ დროულად შეამჩნიოთ ნელი ბილდები, ქეშის დეგრადაცია ან ტესტების შენელება.

გაფრთხილების წესის შესაქმნელად, გადადით თქვენი პროექტის შეტყობინებების პარამეტრებში და დააჭირეთ **Add alert rule**. შეგიძლიათ დააკონფიგურიროთ:

- **Name**: გაფრთხილების აღმწერი სახელი
- **Category**: რისი გაზომვა (ბილდის ხანგრძლივობა, ტესტის ხანგრძლივობა, ქეშში მოხვედრის სიხშირე ან ბანდლის ზომა)
- **Metric**: მონაცემთა აგრეგირების მეთოდი (p50, p90, p99 ან საშუალო)
- **Deviation**: პროცენტული ცვლილება, რომელიც იწვევს გაფრთხილებას
- **Rolling window**: რამდენი ბოლო გაშვება შევადაროთ
- **Branch**: ქეშში მოხვედრის სიხშირის გაფრთხილებებისთვის, შეადარეთ მხოლოდ ერთ ბრენჩზე შესრულებული გაშვებები. დატოვეთ ცარიელი ყველა ბრენჩის გასათვალისწინებლად. ბანდლის ზომის გაფრთხილებები ყოველთვის ერთ ბრენჩს ეხება.
- **Slack channel**: დანიშნულების არხი. თქვენ ანიჭებთ არხს ნებართვას იმავე `incoming-webhook` ნაკადის საშუალებით, რომელიც ზემოთ არის აღწერილი.

მაგალითად, შეგიძლიათ შექმნათ გაფრთხილება, რომელიც აქტიურდება, როდესაც p90 ბილდის ხანგრძლივობა იზრდება 20%-ზე მეტით წინა 100 ბილდთან შედარებით.

ქეშში მოხვედრის სიხშირის გაფრთხილების თქვენს ძირითად ბრენჩზე შეზღუდვა სასარგებლოა, როდესაც მხოლოდ ეს ბრენჩი ავსებს ქეშს. Pull request ბრენჩები, რომლებიც ეხებიან დაბალი დონის მოდულს, კანონიერად ვერ ხვდებიან ქეშში, და მათი ჩართვა გამოიწვევდა გაფრთხილებას მოსალოდნელი გაუარესებების დროს.

ქეშში მოხვედრის სიხშირის გაფრთხილება ადარებს მხოლოდ იმ ფანჯრებს, რომელთა შედარებაც სამართლიანია. ორივე ფანჯარაში უნდა იყოს იმდენივე გაშვება, რამდენიც rolling window-ის ზომაა, ხოლო ქეშის მონაცემთა წყარო, რომელიც მხოლოდ ერთ-ერთ ფანჯარაში ჩანს, გამოირიცხება ორივედან. ბრენჩი, რომელსაც ჯერ არ დაუგროვებია გაშვებებში rolling window-ის ზომის ორმაგი ოდენობა, ან ბრენჩის სახელი, რომელიც არაფერს ემთხვევა, შესაბამისად, არასდროს ააქტიურებს წესს. თუ წესს აკავშირებთ დაბალი აქტივობის ბრენჩთან, შეინახეთ rolling window საკმარისად მცირე, რომ ბრენჩმა შეძლოს მისი ავსება.

როდესაც გაფრთხილება აქტიურდება, თქვენს Slack-არხში მიიღებთ ასეთ შეტყობინებას:

### არასტაბილური ტესტების გაფრთხილებები {#flaky-test-alerts}

არასტაბილური ტესტების გაფრთხილებები აქტიურდება მაშინვე, როდესაც Tuist აღმოაჩენს ახალ არასტაბილურ ტესტს, რაც დაგეხმარებათ შეამჩნიოთ ტესტების არასტაბილურობა მანამ, სანამ ის გავლენას მოახდენს თქვენს გუნდზე.

არასტაბილური ტესტის გაფრთხილების წესის შესაქმნელად, გადადით თქვენი პროექტის შეტყობინებების პარამეტრებში და დააჭირეთ **Add flaky test alert rule**. შეგიძლიათ დააკონფიგურიროთ:

- **Name**: გაფრთხილების აღმწერი სახელი
- **Trigger threshold**: არასტაბილური გაშვებების მინიმალური რაოდენობა ბოლო 30 დღეში, რომელიც საჭიროა გაფრთხილების გამოსაწვევად
- **Slack channel**: დანიშნულების არხი, რომელიც ავტორიზებულია `incoming-webhook` ნაკადის საშუალებით.

როდესაც ტესტი ხდება არასტაბილური და აკმაყოფილებს თქვენს ზღვარს, მიიღებთ შეტყობინებას სატესტო შემთხვევის შესასწავლად პირდაპირი ბმულით:

## ინტეგრაციის გათიშვა {#disconnect}

შეტყობინების შეწყვეტისთვის, წაშალეთ კონფიგურირებული Slack-ის არხი ანგარიშში, გაფრთხილების წესში ან ავტომატიზაციის მოქმედებაში თქვენს Tuist-ის დაშბორდზე. Tuist-ზე სრული წვდომის გაუქმებისთვის, წაშალეთ webhook ინტეგრაცია Slack-ის შიგნიდან გზით **Settings & administration → Manage apps**.
