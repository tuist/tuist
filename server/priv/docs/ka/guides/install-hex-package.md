# Hex-პაკეტის ინსტალაცია {#install-the-hex-package}

Tuist გთავაზობთ [Hex](https://hex.pm/packages/tuist_ex)-პაკეტს, `tuist_ex`, რომელიც ინტეგრირდება თქვენს Elixir პროექტთან და საშუალებას გაძლევთ გამოიყენოთ ისეთი ფუნქციები, როგორიცაა <.localized_link href="/guides/features/build-insights/elixir">კომპილაციის ანალიტიკა</.localized_link> და <.localized_link href="/guides/features/test-insights/elixir">ტესტების ანალიტიკა</.localized_link>. ეს სახელმძღვანელო გაგივლით მის ინსტალაციასა და კონფიგურაციაში.

პაკეტი მოითხოვს Elixir 1.18 ან უფრო ახალ ვერსიას. მას არ სჭირდება Tuist-ის ბრძანებების ხაზის ინტერფეისი.

## 1. შექმენით პროექტი {#create-the-project}

შექმენით პროექტი Tuist-ის დაფაზე და აირჩიეთ **Mix (Elixir)** როგორც მისი აგების სისტემა. მისი იდენტიფიკატორი, `account/project`, აკავშირებს თქვენს Mix პროექტს მასთან.

## 2. დაამატეთ პაკეტი {#add-the-package}

დაამატეთ `tuist_ex` დამოკიდებულებებში თქვენს `mix.exs`-ში:

<!-- @snippet: ./_tuist-ex-dependency -->

შემდეგ მიიღეთ ის:

```bash
mix deps.get
```

`runtime: false` ტოვებს Tuist-ს თქვენი გამშვები აპლიკაციის გარეთ. გააგრძელეთ <.localized_link href="/guides/get-started/elixir-project#set-up-tuist">Elixir-ით დაწყება</.localized_link> კეშირების, კომპილაციის ანალიტიკისა და ტესტების ანალიტიკის ერთად კონფიგურაციისთვის. ქვემოთ მოცემული სექციები მოიცავს ავტორიზაციისა და კონფიგურაციის დეტალებს.

## 3. ავტორიზაცია თქვენი გუნდისა და უწყვეტი ინტეგრაციისთვის {#authenticate}

თითოეული გუნდის წევრი ასრულებს შემდეგს, რათა მიიღოს წვდომა Tuist-ის ფუნქციებზე თავის მანქანაზე:

```bash
mix tuist.login
```

ის ბეჭდავს მოკლე შესვლის კოდს, ხსნის ბრაუზერს, სადაც თქვენ შეჰყავთ ის და ელოდება თქვენს ავტორიზაციას. ბრაუზერის გარეშე შესასვლელად, გადაეცით თქვენი სარწმუნოებები:

```bash
mix tuist.login --email person@example.com --password secret
```

როდესაც იყენებთ თვითმასპინძელ ან ლოკალურ Tuist სერვერს, დააყენეთ მისი საბაზისო URL `mix.exs`-ში, ან გადაეცით ის `--url`-ით:

```bash
mix tuist.login --url http://localhost:8080
```

შეინარჩუნეთ ჰოსტის სახელის მართლწერის თანმიმდევრულობა. მაგალითად, `localhost`-ისთვის შენახული შესვლა განცალკევებულია `127.0.0.1`-ისთვის შენახული შესვლისგან.

GitHub Actions-ზე, CircleCI-ზე და Bitrise-ზე, უწყვეტ ინტეგრაციას არ სჭირდება შესვლის ნაბიჯი. პირველად, როდესაც ამოცანა აგზავნის ანგარიშს, ის ცვლის პროვაიდერის OpenID Connect ტოკენს Tuist-ის ტოკენზე. <.localized_link href="/guides/integrations/gitforge/github">შეაერთეთ თქვენი GitHub რეპოზიტორია</.localized_link> თქვენს Tuist პროექტთან და GitHub Actions-ზე მიანიჭეთ სამუშაოს `id-token: write` ნებართვა:

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      id-token: write
    steps:
      - uses: actions/checkout@v4
      - uses: erlef/setup-beam@v1
        with:
          elixir-version: '1.18'
          otp-version: '27'
      - run: mix deps.get
      - run: mix test
```

ნებისმიერ სხვა OpenID Connect იდენტობის პროვაიდერთან, როგორიცაა Fly.io Machines, კონფიგურირება სამუშაო იდენტობის ნდობის პოლიტიკა თქვენი ანგარიშის **სამუშაო იდენტობები** სექციაში **პარამეტრები → ავტორიზაცია** გვერდზე, რაც CI-ს ანიჭებს წვდომას ანგარიშის ყველა არსებულ და მომავალ პროექტზე. დააყენეთ `TUIST_OIDC_ACCOUNT` Tuist ანგარიშზე, რომელიც ფლობს პროექტს, და მიეწოდეთ ახლად შექმნილი იდენტობის ტოკენი პოლიტიკის აუდიტორიით `TUIST_OIDC_TOKEN`-ის მეშვეობით. ინტეგრაცია ავტომატურად ცვლის მას, როდესაც არ არის ხელმისაწვდომი ანგარიშის ტოკენი ან მოქმედი შენახული შესვლა; `mix tuist.login` ასევე იღებს მას CI-ს გარეთ. ავტომატური გაცვლები იყენებენ ხელუხლებელ სესიას მხოლოდ იმავე სერვერის, ანგარიშისა და მიწოდებული იდენტობის ტოკენისთვის. ამ იდენტობის შეცვლა იწვევს ახალ გაცვლას, ხოლო ცარიელი მიწოდებული იდენტობა ვერ ახერხებს ძველი სესიის ხელახლა გამოყენებას. Tuist სესიები გრძელდება ერთი საათი განახლების ტოკენების გარეშე, ამიტომ ხანგრძლივი სამუშაოებისთვის, შექმენით ახალი იდენტობის ტოკენი და გაუშვით `mix tuist.login` ხელახლა სესიის ამოწურვამდე. მიჰყევით <.localized_link href="/guides/server/authentication#workload-identity-trust-policies">სამუშაო იდენტობის კონფიგურაციას</.localized_link> და <.localized_link href="/guides/server/authentication#flyio-machines">Fly.io მაგალითს</.localized_link>.

ფორკებიდან შემოსულ Pull requests-ებს არ აქვთ OpenID Connect ტოკენი, ამიტომ მათი გაშვებები არ იგზავნება და ჩვეულებრივად გადიან ან ვერ გადიან. სხვა პროვაიდერებზე, დააყენეთ `TUIST_TOKEN` გარემოს ცვლადი ანგარიშის ტოკენზე. მიჰყევით <.localized_link href="/guides/server/authentication#continuous-integration">უწყვეტი ინტეგრაციის ავტორიზაციის სახელმძღვანელოს</.localized_link> ერთის შესაქმნელად.

## 4. განაგრძეთ `mix test`-ისა და `mix compile`-ის გამოყენება {#aliases}

<.localized_link href="/guides/get-started/elixir-project#set-up-tuist">საერთო კონფიგურაცია</.localized_link> აყენებს კომპილაციისა და ტესტების ალიასებს თქვენთვის. `mix test test/my_app_test.exs:12 --trace` აგზავნის გაშვების ანგარიშს იმავე გამოტანითა და გასვლის კოდით, ხოლო კომპილაციის ინტეგრაცია მოიცავს აგებებს, რომლებიც გამოწვეულია `mix test`-ით ან `mix phx.server`-ით. კომპილაცია, რომელიც არაფერს პოულობს გასაკეთებლად, არ იგზავნება.

ამოცანები ასევე მუშაობენ, როდესაც მათ საკუთარი სახელით იძახებთ. Mix-ი იწყებს ასე დაწერილ ამოცანას `dev` გარემოში, ამიტომ ამოცანას უნდა დაიწყოს თავიდან მეორე პროცესში სატესტო გარემოსთვის. დაამატეთ ამოცანები სასურველ გარემოებში ამის გამოსატოვებლად:

```elixir
def cli do
  [preferred_envs: ["tuist.test": :test, "tuist.test.build": :test]]
end
```

## კონფიგურაციის ცნობარი {#configuration-reference}

შემდეგი პარამეტრები ხელმისაწვდომია `tuist`-ის ქვეშ `mix.exs`-ის პროექტის პარამეტრებში:

| პარამეტრი | ტიპი | ნაგულისხმები | აღწერა |
| --- | --- | --- | --- |
| `project` | `String` | არ არის (სავალდებულო) | პროექტის იდენტიფიკატორი `account/project` ფორმატში. |
| `url` | `String` | `"https://tuist.dev"` | Tuist სერვერის საბაზისო URL. |
| `cache` | `boolean` ან საკვანძო სიტყვების სია | გამორთული | კონფიგურაცია ააქტიურებს დამოკიდებულებების კეშირებას. იხილეთ <.localized_link href="/guides/features/cache/elixir">Elixir კეში</.localized_link> გამონაკლისებისა და დამატებითი შეყვანებისთვის. |
| `test_retries` | `integer` | `0` | რამდენჯერ უნდა განმეორდეს ვერ გასული ტესტები; იხილეთ <.localized_link href="/guides/features/test-insights/flaky-tests/elixir#test-retries">ტესტების განმეორება</.localized_link>. |
| `tags` | სია `String`-ის | `[]` | ტეგები, რომლებიც მიებას ყოველ აგებას; იხილეთ <.localized_link href="/guides/features/build-insights/elixir#custom-metadata">მორგებული მეტამონაცემები</.localized_link>. |
| `values` | რუკა | `%{}` | საკვანძო-მნიშვნელობის მონაცემები, რომლებიც მიებას ყოველ აგებას. |

გარემოს ცვლადებს აქვთ უპირატესობა `mix.exs`-თან შედარებით:

| ცვლადი | აღწერა |
| --- | --- |
| `TUIST_PROJECT` | პროექტის იდენტიფიკატორი `account/project` ფორმატში. |
| `TUIST_URL` | Tuist სერვერის საბაზისო URL. |
| `TUIST_TOKEN` | ტოკენი ავთენტიკაციისთვის, შენახული შესვლის ნაცვლად. |
| `TUIST_OIDC_TOKEN` | ახლად გამოშვებული OpenID Connect იდენტობის ტოკენი, რომელიც იცვლება Tuist ტოკენზე. მისი აუდიტორია უნდა იყოს `tuist` GitHub Actions-ისა და Bitrise-ისთვის, ან ემთხვეოდეს ანგარიშის სამუშაო იდენტობას სხვა პროვაიდერებისთვის. გამოიყენება `mix tuist.login`-ის მიერ ან როგორც სათადარიგო ვარიანტი, როდესაც არ არის ხელმისაწვდომი ანგარიშის ტოკენი ან მოქმედი შენახული შესვლა. |
| `TUIST_OIDC_ACCOUNT` | Tuist ანგარიშის სახელი, რომელიც ფლობს პროექტს. საჭიროა ტოკენის გაცვლისას ანგარიშის სამუშაო იდენტობის მეშვეობით. ის არჩევს არსებულ სამუშაო იდენტობებს შორის და თავისთავად არ ანიჭებს წვდომას. |
| `TUIST_TEST_RETRIES` | რამდენჯერ უნდა განმეორდეს ვერ გასული ტესტები. |
| `TUIST_TAGS` | მძიმით გამოყოფილი ტეგები, რომლებიც მიებას აგებას. |
| `TUIST_VALUES` | მძიმით გამოყოფილი `key=value` წყვილები, რომლებიც მიებას აგებას. |
| `TUIST_DEBUG` | დააყენეთ `1`-ზე, რათა დაიბეჭდოს მიზეზი, თუ რატომ ვერ გაიგზავნა ანგარიში. |

ანგარიშგება არასდროს ცვლის `mix test`-ის ან `mix compile`-ის გამოსვლის კოდს. თუ ანგარიშის გაგზავნა შეუძლებელია, ამოცანა არაფერს ამბობს, თუ არ არის დაყენებული `TUIST_DEBUG=1`.

- <.localized_link href="/guides/features/build-insights/elixir">აგების ინსაიტები</.localized_link> კომპილაციის დროის, გაფრთხილებებისა და იმის თვალყურის დევნებისთვის, რაც აფერხებს თქვენს აგებებს.
