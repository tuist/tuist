## ტეგები {#tags}

ბანდლის ატვირთვისას მიამაგრეთ ტეგები, რათა განასხვაოთ ბილდის ვარიანტები, გარემოები ან გამოშვების არხები. ბანდლის ტეგები ემორჩილებიან იმავე შეთანხმებას, რასაც Build Insights-ის ტეგები:

```bash
tuist inspect bundle App.ipa --tags paid production
```

CI-ში ასევე შეგიძლიათ დააყენოთ მძიმით გამოყოფილი ტეგები `TUIST_BUNDLE_TAGS`-ის საშუალებით:

```bash
TUIST_BUNDLE_TAGS="paid,production" tuist inspect bundle App.ipa
```

ცალსახად მითითებული `--tags` ცვლის გარემოს ცვლადის ტეგებს. ტეგებში შეიძლება იყოს ასოები, ციფრები, დეფისები და ქვედატირეები; თითოეულ ბანდლზე მაქსიმუმ 10 ტეგი და თითოეულ ტეგზე 50 სიმბოლო. იგივე პარამეტრები მუშაობს Android-ის ბანდლებისთვისაც. `--json` მუშაობს მხოლოდ ლოკალურად და არ ატვირთავს ტეგებს ან ბანდლს.

ტეგები ჩანს ბანდლის სახელების გვერდით და ბანდლის დეტალებში. გამოიყენეთ დაშბორდის **ტეგები** ფილტრი და შეიყვანეთ ტეგი, რათა ჩართოთ ან ამოიღოთ ის ბანდლების სიაში. შესაბამისობა ზუსტია და მგრძნობიარეა დიდ/პატარა ასოების მიმართ, მიუხედავად იმისა, რომ ფილტრის ოპერატორებს ეწოდებათ **შეიცავს** და **არ შეიცავს**: `paid` არ ემთხვევა `paid-extra`-ს. CLI-დან გასაფილტრად:

```bash
tuist bundle list --tags paid production
```

CLI, API (`?tags=paid,production`) და MCP-ის `list_bundles` ინსტრუმენტი (`tags: ["paid", "production"]`) აბრუნებს ბანდლებს, რომლებიც შეიცავენ **ყველა** მითითებულ ტეგს. API-ს ატვირთვები იღებენ `bundle.custom_metadata.tags`-ს; სიისა და დეტალური პასუხები აბრუნებენ `custom_metadata.tags`-ს. არსებული ბანდლები ტეგების გარეშე ხელმისაწვდომია, როგორც ადრე. ტეგები ფილტრავენ ბანდლების სიას; ისინი არ ცვლიან ზომის დიაგრამებს ან ავტომატური შედარებისა და ზღვრული მნიშვნელობების საბაზისო ხაზებს.

არსებულ კლიენტებს შეუძლიათ განაგრძონ ბანდლების ატვირთვა და წაკითხვა ტეგების გარეშე. განახლებულ კლიენტებს ასევე შეუძლიათ წაიკითხონ პასუხები უფრო ძველი სერვერებიდან, რომლებიც ტოვებენ `custom_metadata`-ს. ტეგების შენახვა და ფილტრაცია მოითხოვს სერვერის ვერსიას, რომელიც მხარდაჭერს ბანდლის ტეგებს: უფრო ძველი სერვერები იგნორირებენ ატვირთვის მეტამონაცემებს და უარყოფენ ტეგების ფილტრებს. განახლებული კლიენტები ტოვებენ როგორც ატვირთვის მეტამონაცემებს, ასევე ტეგების query პარამეტრებს, როცა ტეგები არ არის მითითებული.

## ბანდლის ზომების გაგება {#understanding-sizes}

ყველა ანალიზირებული ბანდლისთვის Tuist იუწყება ორ მნიშვნელობას:

- **ინსტალაციის ზომა**: ადგილი, რომელსაც აპიკაცია იკავებს მოწყობილობაზე ინსტალაციის შემდეგ.
- **ჩამოტვირთვის ზომა**: შეკუმშული ზომა, რომელსაც მომხმარებლები ჩამოტვირთავენ. Apple-ის ბანდლებისთვის ეს მხოლოდ `.ipa`-ისთვის არის ხელმისაწვდომი (არქივის ზომა); `.xcarchive` ან `.app` შეყვანებისთვის ის არ არის ხელმისაწვდომი.

ზომები ინახება ბაიტებში და გამოისახება ათობითი შეთანხმებით, სადაც 1 MB არის 1,000,000 ბაიტი, ხოლო 1 GB — 1,000,000,000 ბაიტი — იგივე შეთანხმება, რომელსაც Apple იყენებს საცავისა და აპლიკაციების ზომების მოსაწოდებლად (იხილეთ [როგორ იზომება საცავის ტევადობა Apple-ის მოწყობილობებზე](https://support.apple.com/en-us/102119)). 733,446,863 ბაიტის ინსტალაციის ზომა გამოისახება როგორც 733.4 MB.

### კონფიგურაცია {#size-thresholds-configuration}

ზღვრების კონფიგურაციისთვის, გადადით თქვენი პროექტის **პარამეტრები > ბანდლები** ჩანართზე:

![ბანდლის ზომის ზღვრული მნიშვნელობების პარამეტრები](/images/guides/features/bundle-size/bundle-size-thresholds.png)

აირჩიეთ **ინსტალაციის ზომა** ან **ჩამოტვირთვის ზომა**, შემდეგ აირჩიეთ **ზღვრის ტიპი**:

- **პროცენტი (%)**: ზრდის შეზღუდვა საბაზისო ზომასთან მიმართებაში. მხარდაჭერილია წილადი პროცენტები, როგორიცაა `0.47`. არსებული პროცენტული ზღვრები ინარჩუნებენ თავიანთ კონფიგურირებულ მნიშვნელობებს და ქცევას.
- **აბსოლუტური ზომა (MB)**: ზრდის შეზღუდვა ფიქსირებული რაოდენობით, საბაზისო ზომისგან დამოუკიდებლად. შეიყვანეთ `1.5`, რათა დაუშვათ 1.5 MB-მდე ზრდა. MB იყენებს ათობით ერთეულებს: 1 MB = 1,000,000 ბაიტი. მნიშვნელობები უნდა იყოს დადებითი მთელი რიცხვი ბაიტებში.

![ბანდლის ზომის აბსოლუტური ზრდის ზღვრული მნიშვნელობის კონფიგურაცია](/images/guides/features/bundle-size/absolute-size-threshold.png)

ორივე ტიპი ადარებს კონფიგურირებულ **საბაზისო შტოსთან** არსებულ უახლეს ბანდლს იგივე სახელით, იგივე ბანდლის ტიპით (მაგალითად, `.app` ან `.ipa`) და მინიმუმ ერთი საერთო პლატფორმით, ამიტომ სიმულატორის `.app` შედარდება მხოლოდ სიმულატორის `.app` ატვირთვებთან. არასავალდებულო **ბანდლის სახელი** ზღუდავს წესს მხოლოდ ამ ბანდლისთვის. შემოწმება ვერ გადის მხოლოდ მაშინ, როცა ზრდა **აჭარბებს** ლიმიტს; თანაბარი ზრდა, უცვლელი ზომები და შემცირება გადის. შესაბამისი საბაზისო ხაზის ან არჩეული მეტრიკის ჩაწერილი ზომის გარეშე, წესი გამოტოვებულია. ნულოვანი ზომის საბაზისო ხაზი მხარდაჭერილია აბსოლუტური ლიმიტებისთვის; პროცენტული ლიმიტები კვლავ გამოტოვებენ მას, რადგან პროცენტული ზრდა განუსაზღვრელია.

### ვის შეუძლია მიღება {#size-thresholds-approvals}

ნაგულისხმევად, ნებისმიერს, ვისაც რეპოზიტორიაზე ჩაწერის წვდომა აქვს, შეუძლია ზომის ზრდის მიღება, რადგან GitHub ღილაკს სწორედ მათ აჩვენებს. შესაძლებლობის შესაზღუდად, დააყენეთ **ვის შეუძლია მიღება** პარამეტრი **პარამეტრები > ბანდლები** განყოფილებაში:

- **ნებისმიერი**: ნაგულისხმევი. ნებისმიერი, ვისაც რეპოზიტორიაზე ჩაწერის წვდომა აქვს.
- **არჩეული GitHub-ის მომხმარებლები**: მხოლოდ ის GitHub-ის მომხმარებლის სახელები, რომლებსაც დაამატებთ.

ვინმე, ვინც სიაში არ არის, ტოვებს შემოწმებას წარუმატებლად ახსნით, ხოლო ღილაკი რჩება იმისთვის, ვისაც მისი გამოყენება შეუძლია.
