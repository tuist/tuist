## ტეგები {#tags}

ბანდლის ატვირთვისას მიამაგრეთ ტეგები ბილდის ვარიაციების, გარემოების ან გამოშვების არხების გასარჩევად. ბანდლის ტეგები ემორჩილებიან იმავე შეთანხმებას, რასაც Build Insights-ის ტეგები:

```bash
tuist inspect bundle App.ipa --tags paid production
```

CI-ში ასევე შეგიძლიათ დააყენოთ მძიმით გამოყოფილი ტეგები `TUIST_BUNDLE_TAGS`-ის საშუალებით:

```bash
TUIST_BUNDLE_TAGS="paid,production" tuist inspect bundle App.ipa
```

ცალსახა `--tags` ცვლის გარემოს ცვლადის ტეგებს. ტეგებმა შეიძლება შეიცავდნენ ასოებს, რიცხვებს, დეფისებს და ქვედატირეებს, თითოეულ ბანდლზე მაქსიმუმ 10 ტეგი და თითო ტეგზე 50 სიმბოლო. იგივე პარამეტრები მოქმედებს Android-ის ბანდლებისთვისაც. `--json` რჩება მხოლოდ ლოკალურად და არ ატვირთავს ტეგებს ან ბანდლს.

ტეგები ჩანს ბანდლის სახელების გვერდით და ბანდლის დეტალებში. გამოიყენეთ დაშბორდის **ტეგები** ფილტრი და შეიყვანეთ ტეგი, რათა ის შეიტანოთ ან ამოიღოთ ბანდლების სიიდან. შესაბამისობა ზუსტია და მგრძნობიარეა რეგისტრის მიმართ, მიუხედავად იმისა, რომ ფილტრის ოპერატორებს ეწოდება **შეიცავს** და **არ შეიცავს**: `paid` არ ემთხვევა `paid-extra`-ს. CLI-დან ფილტრაციისთვის:

```bash
tuist bundle list --tags paid production
```

CLI, API (`?tags=paid,production`) და MCP `list_bundles` ინსტრუმენტი (`tags: ["paid", "production"]`) აბრუნებს ბანდლებს, რომლებიც შეიცავენ **ყველა** მითითებულ ტეგს. API-ს ატვირთვები იღებენ `bundle.custom_metadata.tags`; სიისა და დეტალური პასუხები აბრუნებენ `custom_metadata.tags`. არსებული ბანდლები ტეგების გარეშე რჩება ხელმისაწვდომი, როგორც ადრე. ტეგები ფილტრავენ ბანდლების სიას; ისინი არ ცვლიან ზომის დიაგრამებს ან ავტომატური შედარებისა და ზღვრული მნიშვნელობების საბაზისო ხაზებს.

არსებულ კლიენტებს შეუძლიათ განაგრძონ ბანდლების ატვირთვა და წაკითხვა ტეგების გარეშე. განახლებულ კლიენტებს ასევე შეუძლიათ წაიკითხონ პასუხები ძველი სერვერებიდან, რომლებიც არ შეიცავენ `custom_metadata`-ს. ტეგების შენახვა და ფილტრაცია მოითხოვს სერვერის ვერსიას, რომელიც მხარს უჭერს ბანდლის ტეგებს: ძველი სერვერები იგნორირებენ ატვირთვის მეტამონაცემებს და უარყოფენ ტეგების ფილტრებს. განახლებული კლიენტები გამოტოვებენ როგორც ატვირთვის მეტამონაცემებს, ასევე ტეგების მოთხოვნის პარამეტრებს, როცა ტეგები არ არის მითითებული.

## ბანდლის ზომების გაგება {#understanding-sizes}

ყოველი ანალიზირებული ბანდლისთვის Tuist იუწყება ორ მნიშვნელობას:

- **ინსტალაციის ზომა**: სივრცე, რომელსაც აპლიკაცია იკავებს მოწყობილობაზე ინსტალაციის შემდეგ.
- **ჩამოტვირთვის ზომა**: შეკუმშული ზომა, რომელსაც მომხმარებლები ჩამოტვირთავენ. Apple-ის ბანდლებისთვის ეს იუწყება მხოლოდ `.ipa`-ისთვის (არქივის ზომა); `.xcarchive` ან `.app` შემავალი მონაცემებისთვის ის არ არის ხელმისაწვდომი.

ზომები ინახება ბაიტებში და გამოისახება ათობითი შეთანხმებით, სადაც 1 MB არის 1,000,000 ბაიტი, ხოლო 1 GB არის 1,000,000,000 ბაიტი — იგივე შეთანხმება, რომელსაც Apple იყენებს საცავისა და აპლიკაციების ზომების მოსახსენებლად (იხილეთ [როგორ იზომება საცავის ტევადობა Apple-ის მოწყობილობებზე](https://support.apple.com/en-us/102119)). 733,446,863 ბაიტიანი ინსტალაციის ზომა ჩანს როგორც 733.4 MB.

### კონფიგურაცია {#size-thresholds-configuration}

ზღვრების კონფიგურირებისთვის, გადადით თქვენი პროექტის **პარამეტრები > ბანდლები** ჩანართზე:

![ბანდლის ზომის ზღვრული მნიშვნელობების პარამეტრები](/images/guides/features/bundle-size/bundle-size-thresholds.png)

აირჩიეთ **ინსტალაციის ზომა** ან **ჩამოტვირთვის ზომა**, შემდეგ აირჩიეთ **ზღვრის ტიპი**:

- **პროცენტული (%)**: ზრდის შეზღუდვა საბაზისო ზომასთან მიმართებაში. მხარდაჭერილია წილადი პროცენტები, როგორიცაა `0.47`. არსებული პროცენტული ზღვრები ინარჩუნებენ თავიანთ კონფიგურირებულ მნიშვნელობებსა და ქცევას.
- **აბსოლუტური ზომა (MB)**: ზრდის შეზღუდვა ფიქსირებული რაოდენობით, საბაზისო ზომისგან დამოუკიდებლად. შეიყვანეთ `1.5`, რათა დაუშვათ ზრდა 1.5 MB-მდე. MB იყენებს ათობით ერთეულებს: 1 MB = 1,000,000 ბაიტი. მნიშვნელობები უნდა გადაიქცეს ბაიტების დადებით მთელ რიცხვად.

![ბანდლის ზომის ზრდის აბსოლუტური ზღვრის კონფიგურაცია](/images/guides/features/bundle-size/absolute-size-threshold.png)

ორივე ტიპი ადარებს კონფიგურირებულ **საბაზისო შტოსთან** არსებულ უახლეს ბანდლს იგივე სახელით, იგივე ბანდლის ტიპით (მაგალითად, `.app` ან `.ipa`) და მინიმუმ ერთი საერთო პლატფორმით, ამიტომ სიმულატორის `.app` შედარდება მხოლოდ სიმულატორის `.app` ატვირთვებთან. არასავალდებულო **ბანდლის სახელი** ზღუდავს წესს კონკრეტული ბანდლისთვის. შემოწმება ვერ გადის მხოლოდ მაშინ, როცა ზრდა **აჭარბებს** ლიმიტს; თანაბარი ზრდა, უცვლელი ზომები და შემცირება წარმატებით გადის. შესაბამისი საბაზისო მნიშვნელობის ან არჩეული მეტრიკის ჩაწერილი ზომის გარეშე წესი გამოტოვებულია. ნულოვანი ზომის საბაზისო მნიშვნელობა მხარდაჭერილია აბსოლუტური ზღვრებისთვის; პროცენტული ზღვრები კვლავ გამოტოვებენ მას, რადგან პროცენტული ზრდა განუსაზღვრელია.

### ვის შეუძლია მიღება - შეზღუდვა {#size-thresholds-approvals}

ნაგულისხმევად, რეპოზიტორიაზე ჩაწერის წვდომის მქონე ნებისმიერ პირს შეუძლია ზომის ზრდის მიღება, რადგან GitHub ღილაკს სწორედ მათ აჩვენებს. შესაძლებლობების შესაზღუდად, დააყენეთ **ვის შეუძლია მიღება** პარამეტრი **პარამეტრები > ბანდლები** განყოფილებაში:

- **ნებისმიერი**: ნაგულისხმევი პარამეტრი. რეპოზიტორიაზე ჩაწერის წვდომის მქონე ნებისმიერი პირი.
- **შერჩეული GitHub-ის მომხმარებლები**: მხოლოდ თქვენს მიერ დამატებული GitHub-ის მომხმარებლის სახელები.

სიაში არშემავალი პირი ტოვებს შემოწმებას ვერგავლილად ახსნით, ხოლო ღილაკი რჩება იმ პირისთვის, ვისაც მისი გამოყენება შეუძლია.
