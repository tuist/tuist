## ბანდლების ზომების გაგება {#understanding-sizes}

ყველა ანალიზირებული ბანდლისთვის Tuist ორ მნიშვნელობას აწვდის:

- **ინსტალაციის ზომა**: აპლიკაციის მიერ დაკავებული სივრცე მოწყობილობაზე ინსტალაციის შემდეგ.
- **ჩამოტვირთვის ზომა**: შეკუმშული ზომა, რომელსაც მომხმარებლები ჩამოტვირთავენ. Apple-ის ბანდლებისთვის ეს მხოლოდ `.ipa`-ისთვის (არქივის ზომა) არის ხელმისაწვდომი; `.xcarchive` ან `.app` შემავალი მონაცემებისთვის ის არ არის ხელმისაწვდომი.

ზომები ინახება ბაიტებში და გამოისახება ათობითი კონვენციის გამოყენებით, სადაც 1 MB არის 1,000,000 ბაიტი, ხოლო 1 GB — 1,000,000,000 ბაიტი — იგივე კონვენცია, რომელსაც Apple იყენებს მეხსიერებისა და აპლიკაციების ზომების აღსაწერად (იხილეთ [როგორ იზომება მეხსიერების ტევადობა Apple-ის მოწყობილობებზე](https://support.apple.com/en-us/102119)). 733,446,863 ბაიტიანი ინსტალაციის ზომა გამოისახება როგორც 733.4 MB.

## უწყვეტი ინტეგრაცია {#continuous-integration}

ბანდლის ზომის დროში ცვლილების თვალყურის დევნისთვის, გაანალიზეთ ბანდლი CI-ზე. ჯერ დარწმუნდით, რომ თქვენი CI არის <.localized_link href="/guides/integrations/continuous-integration#authentication">ავტორიზებული</.localized_link>.

Tuist-მა ასევე უნდა იცოდეს, რომელ პროექტს უნდა აცნობოს ბანდლის შესახებ. თუ პროექტი ჯერ არ დაგიკავშირებიათ, გაუშვით `tuist init`, ან თავად მიუთითეთ handle:

::: code-group
```swift [Tuist.swift]
let tuist = Tuist(fullHandle: "my-account/my-project")
```
```toml [tuist.toml]
project = "my-account/my-project"
```
<!-- -->
:::

გამოიყენეთ <.localized_link href="/references/tuist-toml">`tuist.toml`</.localized_link> პროექტებისთვის, რომლებსაც არ აქვთ Swift მანიფესტი, მაგალითად Gradle პროექტები. როცა ორივე ფაილი არსებობს, `Tuist.swift` აქვს უპირატესობა.

GitHub Actions workflow-ის მაგალითი:

::: code-group
```yaml [Apple]
name: Build

jobs:
  build:
    steps:
      - # Build your app
      - name: Analyze bundle
        run: tuist inspect bundle App.ipa
        env:
          TUIST_TOKEN: ${{ secrets.TUIST_TOKEN }}
```
```yaml [Android]
name: Build

jobs:
  build:
    steps:
      - # Build your app
      - name: Analyze bundle
        # .aab is recommended over .apk for more accurate size analysis
        run: tuist inspect bundle App.aab
        env:
          TUIST_TOKEN: ${{ secrets.TUIST_TOKEN }}
```
<!-- -->
:::

## ზომის ზღვრები {#size-thresholds}

> [!WARNING]
> **Git Forge-თან ინტეგრაცია სავალდებულოა**
>
> ზომის ზღვრების გამოსაყენებლად, დააკავშირეთ [Tuist GitHub App](https://github.com/apps/tuist) თქვენს პროექტთან. ეს შეგიძლიათ გააკეთოთ თქვენი პროექტის ინტეგრაციების გვერდიდან.

ზომის ზღვრები გაძლევთ საშუალებას დაბლოკოთ pull requests, როცა ბანდლის ზომა იზრდება კონფიგურირებულ პროცენტულ ან აბსოლუტურ ზღვარს ზემოთ საბაზისო შტოსთან შედარებით. როცა ზღვარი ირღვევა, Tuist ქმნის GitHub Check Run-ს PR commit-ზე, რაც ბლოკავს merge-ს, სანამ ზომის ზრდა არ გადაწყდება:

![PR სტატუსის შემოწმება, რომელიც აჩვენებს ბანდლის ზომის ზღვრის გადაჭარბებას](/images/guides/features/bundle-size/github-pr-check-status.png)

Check run აჩვენებს საბაზისო ზომას, მიმდინარე ზომას და ცვლილებას კონფიგურირებულ ერთეულში. თუ ზრდა განზრახულია, შეგიძლიათ მიიღოთ ის პირდაპირ GitHub UI-დან **მიღება** ღილაკზე დაჭერით:

![GitHub check run, რომელიც აჩვენებს ზღვრის დარღვევას](/images/guides/features/bundle-size/github-check-run-threshold.png)

### კონფიგურაცია {#size-thresholds-configuration}

ზღვრების კონფიგურაციისთვის, გადადით თქვენი პროექტის **პარამეტრები > ბანდლები** ჩანართზე:

![ბანდლის ზომის ზღვრების პარამეტრები](/images/guides/features/bundle-size/bundle-size-thresholds.png)

აირჩიეთ **ინსტალაციის ზომა** ან **ჩამოტვირთვის ზომა**, შემდეგ აირჩიეთ **ზღვრის ტიპი**:

- **პროცენტი (%)**: ზრდის შეზღუდვა საბაზისო ზომასთან შედარებით. მხარდაჭერილია წილადი პროცენტები, როგორიცაა `0.47`. არსებული პროცენტული ზღვრები ინარჩუნებენ თავიანთ კონფიგურირებულ მნიშვნელობებს და ქცევას.
- **აბსოლუტური ზომა (MB)**: ზრდის შეზღუდვა ფიქსირებული რაოდენობით, საბაზისო ზომისგან დამოუკიდებლად. შეიყვანეთ `1.5`, რათა დაუშვათ ზრდა 1.5 MB-მდე. MB იყენებს ათობით ერთეულებს: 1 MB = 1,000,000 ბაიტი. მნიშვნელობები უნდა იყოს დადებითი მთელი რიცხვი ბაიტებში.

![ბანდლის ზომის ზრდის აბსოლუტური ზღვრის კონფიგურაცია](/images/guides/features/bundle-size/absolute-size-threshold.png)

ორივე ტიპი ადარებს ბოლო ბანდლს კონფიგურირებულ **საბაზისო შტოზე** იგივე სახელით, იგივე ბანდლის ტიპით (მაგალითად `.app` ან `.ipa`), და მინიმუმ ერთი საერთო პლატფორმით, ამიტომ სიმულატორის `.app` ადარდება მხოლოდ სიმულატორის `.app` ატვირთვებს. არასავალდებულო **ბანდლის სახელი** ზღუდავს წესს ამ ბანდლზე. შემოწმება ვერ გადის მხოლოდ მაშინ, როცა ზრდა არის **მეტია** ლიმიტზე; ტოლი ზრდა, უცვლელი ზომები და კლება გადის. შესაბამისი საბაზოს ან არჩეული მეტრიკისთვის ჩაწერილი ზომის გარეშე, წესი გამოტოვებულია. ნულოვანი ზომის საბაზო მხარდაჭერილია აბსოლუტური ლიმიტებისთვის; პროცენტული ლიმიტები აგრძელებენ მის გამოტოვებას, რადგან პროცენტული ზრდა განუსაზღვრელია.

### ვინ შეიძლება მიიღოს {#size-thresholds-approvals}

ნაგულისხმევად, ნებისმიერს, ვისაც აქვს რეპოზიტორიაზე ჩაწერის წვდომა, შეუძლია მიიღოს ზომის ზრდა, რადგან GitHub ღილაკს სწორედ მათ აჩვენებს. შესაზღუდად, დააყენეთ **ვინ შეიძლება მიიღოს** პარამეტრი **პარამეტრები > ბანდლები** ქვეშ:

- **ნებისმიერი**: ნაგულისხმევი. ნებისმიერი, ვისაც აქვს რეპოზიტორიაზე ჩაწერის წვდომა.
- **არჩეული GitHub მომხმარებლები**: მხოლოდ თქვენ მიერ დამატებული GitHub მომხმარებლის სახელები.

სიაში არმყოფი პირი ტოვებს შემოწმებას ვერგავლილად ახსნით, ხოლო ღილაკი რჩება იმისთვის, ვისაც მისი გამოყენება შეუძლია.
