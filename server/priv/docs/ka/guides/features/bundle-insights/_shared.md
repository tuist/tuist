## ტეგები {#tags}

ბანდლის ატვირთვისას მიამაგრეთ ტეგები, რათა განარჩიოთ ბილდის ვარიაციები, გარემოები ან გამოშვების არხები. ბანდლის ტეგები ემორჩილებიან იმავე შეთანხმებას, რასაც Build Insights-ის ტეგები:

```bash
tuist inspect bundle App.ipa --tags paid production
```

CI-ში ასევე შეგიძლიათ დააყენოთ მძიმით გამიჯნული ტეგები `TUIST_BUNDLE_TAGS`-ით:

```bash
TUIST_BUNDLE_TAGS="paid,production" tuist inspect bundle App.ipa
```

ცალსახად მითითებული `--tags` ცვლის გარემოს ცვლადის ტეგებს. ტეგებმა შეიძლება შეიცავდნენ ასოებს, ციფრებს, დეფისებს და ქვედა ხაზებს, თითო ბანდლზე მაქსიმუმ 10 ტეგით და 50 სიმბოლოთი თითო ტეგზე. იგივე პარამეტრები მოქმედებს Android-ის ბანდლებისთვისაც. `--json` რჩება მხოლოდ ლოკალურად და არ ატვირთავს ტეგებს ან ბანდლს.

ტეგები ჩანს ბანდლის სახელების გვერდით და ბანდლის დეტალებში. გამოიყენეთ დაშბორდის **ტეგები** ფილტრი და შეიყვანეთ ტეგი, რათა ჩართოთ ან ამოაკლოთ ის ბანდლების სიაში. შესაბამისობა ზუსტი და რეგისტრზე მგრძნობიარეა, მიუხედავად იმისა, რომ ფილტრის ოპერატორებს ეწოდება **შეიცავს** და **არ შეიცავს**: `paid` არ ემთხვევა `paid-extra`-ს. CLI-დან ფილტრაციისთვის:

```bash
tuist bundle list --tags paid production
```

CLI, API (`?tags=paid,production`) და MCP `list_bundles` ინსტრუმენტი (`tags: ["paid", "production"]`) აბრუნებს ბანდლებს, რომლებიც შეიცავენ **ყველა** მითითებულ ტეგს. API-ს ატვირთვები იღებენ `bundle.custom_metadata.tags`; სიისა და დეტალური პასუხები აბრუნებენ `custom_metadata.tags`. არსებული ბანდლები ტეგების გარეშე რჩება ხელმისაწვდომი, როგორც ადრე. ტეგები ფილტრავენ ბანდლების სიას; ისინი არ ცვლიან ზომის დიაგრამებს ან ავტომატური შედარებისა და ზღვრული მნიშვნელობების საბაზისო ხაზებს.

არსებულ კლიენტებს შეუძლიათ გააგრძელონ ბანდლების ატვირთვა და წაკითხვა ტეგების გარეშე. განახლებულ კლიენტებს ასევე შეუძლიათ წაიკითხონ პასუხები უფრო ძველი სერვერებიდან, რომლებიც გამოტოვებენ `custom_metadata`-ს. ტეგების შენახვა და ფილტრაცია მოითხოვს სერვერის ვერსიას, რომელიც მხარს უჭერს ბანდლის ტეგებს: უფრო ძველი სერვერები იგნორირებენ ატვირთვის მეტამონაცემებს და უარყოფენ ტეგების ფილტრებს. განახლებული კლიენტები გამოტოვებენ როგორც ატვირთვის მეტამონაცემებს, ასევე ტეგების მოთხოვნის პარამეტრებს, როდესაც ტეგები არ არის მითითებული.

## ბანდლის ზომების გაგება {#understanding-sizes}

ყველა ანალიზირებული ბანდლისთვის Tuist იუწყება ორ მნიშვნელობას:

- **ინსტალაციის ზომა**: ადგილი, რომელსაც აპლიკაცია იკავებს მოწყობილობაზე ინსტალაციის შემდეგ.
- **ჩამოტვირთვის ზომა**: შეკუმშული ზომა, რომელსაც მომხმარებლები ჩამოტვირთავენ. Apple-ის ბანდლებისთვის ეს იუწყება მხოლოდ `.ipa`-ისთვის (არქივის ზომა); `.xcarchive` ან `.app` შეყვანებისთვის ის არ არის ხელმისაწვდომი.

ზომები ინახება ბაიტებში და ჩანს ათობითი შეთანხმების გამოყენებით, სადაც 1 MB არის 1,000,000 ბაიტი და 1 GB არის 1,000,000,000 ბაიტი — იგივე შეთანხმება, რომელსაც Apple იყენებს საცავისა და აპლიკაციების ზომების მოსახსენებლად (იხილეთ [როგორ იზომება საცავის ტევადობა Apple-ის მოწყობილობებზე](https://support.apple.com/en-us/102119)). 733,446,863 ბაიტის ინსტალაციის ზომა ჩანს როგორც 733.4 MB.

## ზომის ზღვრული მნიშვნელობები {#size-thresholds}

> [!WARNING]
> **საჭიროა Git forge-ის ინტეგრაცია**
>
> ზომის ზღვრული მნიშვნელობების გამოსაყენებლად, დააკავშირეთ [Tuist GitHub App](https://github.com/apps/tuist) თქვენს პროექტთან. ეს შეგიძლიათ გააკეთოთ თქვენი პროექტის ინტეგრაციების გვერდიდან.

ზომის ზღვრული მნიშვნელობები გაძლევთ საშუალებას დაბლოკოთ pull requests, როდესაც ბანდლის ზომა იზრდება კონფიგურირებული პროცენტული ან აბსოლუტური ზომის ზღვარზე მეტად საბაზისო შტოსთან შედარებით. როდესაც ზღვარი ირღვევა, Tuist ქმნის GitHub Check Run-ს PR კომიტზე, რაც ბლოკავს merge-ს, სანამ ზომის ზრდა არ გადაწყდება:

![PR სტატუსის შემოწმება, რომელიც აჩვენებს ბანდლის ზომის ზღვრის გადაჭარბებას](/images/guides/features/bundle-size/github-pr-check-status.png)

### კონფიგურაცია {#size-thresholds-configuration}

ზღვრების კონფიგურაციისთვის, გადადით თქვენი პროექტის **პარამეტრები > ბანდლები** ჩანართზე:

![ბანდლის ზომის ზღვრული მნიშვნელობების პარამეტრები](/images/guides/features/bundle-size/bundle-size-thresholds.png)

აირჩიეთ **ინსტალაციის ზომა** ან **ჩამოტვირთვის ზომა**, შემდეგ აირჩიეთ **ზღვრის ტიპი**:

- **პროცენტული (%)**: ზრდის შეზღუდვა საბაზისო ზომასთან მიმართებაში. მხარდაჭერილია წილადი პროცენტები, როგორიცაა `0.47`. არსებული პროცენტული ზღვრები ინარჩუნებენ თავიანთ კონფიგურირებულ მნიშვნელობებს და ქცევას.
- **აბსოლუტური ზომა (MB)**: ზრდის შეზღუდვა ფიქსირებული რაოდენობით, საბაზისო ზომისგან დამოუკიდებლად. შეიყვანეთ `1.5`, რათა დაუშვათ 1.5 MB-მდე ზრდა. MB იყენებს ათობით ერთეულებს: 1 MB = 1,000,000 ბაიტი. მნიშვნელობები უნდა იყოს დადებითი მთელი ბაიტების რაოდენობა.

![ბანდლის ზომის ზრდის აბსოლუტური ზღვრის კონფიგურაცია](/images/guides/features/bundle-size/absolute-size-threshold.png)

ორივე ტიპი ადარებს ბოლო ბანდლს კონფიგურირებულ **საბაზისო შტოსთან** იგივე სახელით, იგივე ბანდლის ტიპით (მაგალითად, `.app` ან `.ipa`) და მინიმუმ ერთი საერთო პლატფორმით, ამიტომ სიმულატორის `.app` შედარდება მხოლოდ სიმულატორის `.app` ატვირთვებთან. არასავალდებულო **ბანდლის სახელი** ზღუდავს წესს მხოლოდ ამ ბანდლზე. შემოწმება ვერ გადის მხოლოდ მაშინ, როცა ზრდა **აჭარბებს** ლიმიტს; თანაბარი ზრდა, უცვლელი ზომები და შემცირება გადის. შესაბამისი საბაზისო ხაზის ან არჩეული მეტრიკის ჩაწერილი ზომის გარეშე წესი გამოტოვებულია. ნულოვანი ზომის საბაზისო ხაზი მხარდაჭერილია აბსოლუტური ლიმიტებისთვის; პროცენტული ლიმიტები კვლავ გამოტოვებენ მას, რადგან პროცენტული ზრდა განუსაზღვრელია.

### ვინ შეიძლება მიიღოს {#size-thresholds-approvals}

ნაგულისხმევად, ნებისმიერს, ვისაც რეპოზიტორიაში ჩაწერის უფლება აქვს, შეუძლია ზომის ზრდის მიღება, რადგან GitHub ღილაკს სწორედ მათ აჩვენებს. შესაზღუდად, დააყენეთ **ვინ შეიძლება მიიღოს** პარამეტრი **პარამეტრები > ბანდლები** განყოფილებაში:

- **ნებისმიერი**: ნაგულისხმევი. ნებისმიერი, ვისაც რეპოზიტორიაში ჩაწერის უფლება აქვს.
- **არჩეული GitHub მომხმარებლები**: მხოლოდ თქვენს მიერ დამატებული GitHub მომხმარებლის სახელები.

სიაში არმყოფი პირი ტოვებს შემოწმებას წარუმატებელს ახსნით, ხოლო ღილაკი რჩება იმისთვის, ვისაც მისი გამოყენება შეუძლია.
