## ტეგები {#tags}

ბანდლის ატვირთვისას მიამაგრეთ ტეგები, რათა განასხვავოთ ბილდის ვარიაციები, გარემოები ან გამოშვების არხები. ბანდლის ტეგები ემორჩილებიან იმავე შეთანხმებას, რასაც Build Insights-ის ტეგები:

```bash
tuist inspect bundle App.ipa --tags paid production
```

CI-ში ასევე შეგიძლიათ დააყენოთ მძიმით გამოყოფილი ტეგები `TUIST_BUNDLE_TAGS`-ით:

```bash
TUIST_BUNDLE_TAGS="paid,production" tuist inspect bundle App.ipa
```

ცალსახა `--tags` ცვლის გარემოს ცვლადის ტეგებს. ტეგებმა შეიძლება შეიცავდნენ ასოებს, ციფრებს, დეფისებს და ქვედატირეებს; თითო ბანდლზე მაქსიმუმ 10 ტეგი და თითო ტეგზე 50 სიმბოლო. იგივე პარამეტრები მოქმედებს Android-ის ბანდლებისთვისაც. `--json` რჩება მხოლოდ ლოკალურად და არ ტვირთავს ტეგებს ან ბანდლს.

ტეგები ჩანს ბანდლის სახელების გვერდით და ბანდლის დეტალებში. გამოიყენეთ დაშბორდის **ტეგები** ფილტრი და შეიყვანეთ ტეგი, რათა ის შეიტანოთ ან ამოიღოთ ბანდლების სიიდან. შესაბამისობა ზუსტია და მგრძნობიარეა რეგისტრის მიმართ, მიუხედავად იმისა, რომ ფილტრის ოპერატორები აღნიშნულია როგორც **შეიცავს** და **არ შეიცავს**: `paid` არ ემთხვევა `paid-extra`-ს. CLI-დან ფილტრაციისთვის:

```bash
tuist bundle list --tags paid production
```

CLI, API (`?tags=paid,production`) და MCP `list_bundles` ინსტრუმენტი (`tags: ["paid", "production"]`) აბრუნებენ ბანდლებს, რომლებიც შეიცავენ **ყველა** მითითებულ ტეგს. API-ს ატვირთვები იღებენ `bundle.custom_metadata.tags`-ს; სიისა და დეტალური პასუხები აბრუნებენ `custom_metadata.tags`-ს. არსებული ბანდლები ტეგების გარეშე ხელმისაწვდომი რჩება ისე, როგორც ადრე. ტეგები ფილტრავენ ბანდლების სიას; ისინი არ ცვლიან ზომის დიაგრამებს ან ავტომატური შედარებისა და ზღვრული მნიშვნელობების საბაზისო ხაზებს.

არსებულ კლიენტებს შეუძლიათ გააგრძელონ ბანდლების ატვირთვა და წაკითხვა ტეგების გარეშე. განახლებულ კლიენტებს ასევე შეუძლიათ წაიკითხონ პასუხები ძველი სერვერებიდან, რომლებიც უგულებელყოფენ `custom_metadata`-ს. ტეგების შენახვა და ფილტრაცია მოითხოვს სერვერის ვერსიას, რომელიც მხარს უჭერს ბანდლის ტეგებს: ძველი სერვერები უგულებელყოფენ ატვირთვის მეტამონაცემებს და უარყოფენ ტეგების ფილტრებს. განახლებული კლიენტები უგულებელყოფენ როგორც ატვირთვის მეტამონაცემებს, ასევე ტეგების მოთხოვნის პარამეტრებს, როდესაც ტეგები არ არის მითითებული.

## ბანდლის ზომების გაგება {#understanding-sizes}

ყოველი ანალიზირებული ბანდლისთვის Tuist იუწყება ორ მნიშვნელობას:

- **ინსტალაციის ზომა**: სივრცე, რომელსაც აპლიკაცია იკავებს მოწყობილობაზე ინსტალაციის შემდეგ.
- **ჩამოტვირთვის ზომა**: შეკუმშული ზომა, რომელსაც მომხმარებლები ჩამოტვირთავენ. Apple-ის ბანდლებისთვის ეს მოხსენებულია მხოლოდ `.ipa`-სთვის (არქივის ზომა); `.xcarchive` ან `.app` შეყვანებისთვის ის ხელმისაწვდომი არ არის.

ზომები ინახება ბაიტებში და ჩანს ათობითი შეთანხმების გამოყენებით, სადაც 1 MB არის 1,000,000 ბაიტი, ხოლო 1 GB არის 1,000,000,000 ბაიტი — იგივე შეთანხმება, რომელსაც Apple იყენებს საცავისა და აპლიკაციების ზომების მოხსენებისას (იხილეთ [როგორ იზომება საცავის ტევადობა Apple-ის მოწყობილობებზე](https://support.apple.com/en-us/102119)). 733,446,863 ბაიტიანი ინსტალაციის ზომა ჩანს როგორც 733.4 MB.

> [!WARNING]
> **Git forge-ის ინტეგრაცია აუცილებელია**

> ზომის ზღვრული მნიშვნელობების გამოყენებისთვის, დააკავშირეთ [Tuist GitHub App](https://github.com/apps/tuist) თქვენს პროექტთან. ეს შეგიძლიათ გააკეთოთ თქვენი პროექტის ინტეგრაციების გვერდიდან.

### კონფიგურაცია {#size-thresholds-configuration}

ზღვრული მნიშვნელობების კონფიგურაციისთვის, გადადით თქვენი პროექტის **პარამეტრები > ბანდლები** ჩანართზე:

![ბანდლის ზომის ზღვრული მნიშვნელობების პარამეტრები](/images/guides/features/bundle-size/bundle-size-thresholds.png)

აირჩიეთ **ინსტალაციის ზომა** ან **ჩამოტვირთვის ზომა**, შემდეგ აირჩიეთ **ზღვრის ტიპი**:

- **პროცენტული (%)**: ზრდის შეზღუდვა საბაზისო ზომასთან მიმართებაში. მხარდაჭერილია წილადი პროცენტები, როგორიცაა `0.47`. არსებული პროცენტული ზღვრები ინარჩუნებენ თავიანთ კონფიგურირებულ მნიშვნელობებს და ქცევას.
- **აბსოლუტური ზომა (MB)**: ზრდის შეზღუდვა ფიქსირებული რაოდენობით, საბაზისო ზომისგან დამოუკიდებლად. შეიყვანეთ `1.5`, რათა დაუშვათ 1.5 MB-მდე ზრდა. MB იყენებს ათობით ერთეულებს: 1 MB = 1,000,000 ბაიტი. მნიშვნელობები უნდა გადაიქცეს ბაიტების დადებით მთელ რიცხვად.

![ბანდლის ზომის ზრდის აბსოლუტური ზღვრის კონფიგურაცია](/images/guides/features/bundle-size/absolute-size-threshold.png)

ორივე ტიპი ადარებს კონფიგურირებულ **საბაზისო შტოსთან** არსებულ უახლეს ბანდლს იმავე სახელით, იმავე ბანდლის ტიპით (მაგალითად, `.app` ან `.ipa`) და მინიმუმ ერთი საერთო პლატფორმით, ამიტომ სიმულატორის `.app` ადარდება მხოლოდ სიმულატორის `.app` ატვირთვებს. არასავალდებულო **ბანდლის სახელი** ზღუდავს წესს კონკრეტული ბანდლისთვის. შემოწმება ვერ გადის მხოლოდ მაშინ, როცა ზრდა **აჭარბებს** ლიმიტს; თანაბარი ზრდა, უცვლელი ზომები და შემცირება წარმატებით გადის. შესაბამისი საბაზისო ანჩოეული მეტრიკის ჩაწერილი ზომის გარეშე წესი გამოიტოვება. ნულოვანი ზომის საბაზისო მხარდაჭერილია აბსოლუტური ლიმიტებისთვის; პროცენტული ლიმიტები კვლავ გამოტოვებენ მას, რადგან პროცენტული ზრდა განუსაზღვრელია.

### ვის შეუძლია მიღება {#size-thresholds-approvals}

ნაგულისხმევად, ზომის ზრდის მიღება შეუძლია ნებისმიერს, ვისაც აქვს რეპოზიტორიაზე ჩაწერის უფლება, რადგან GitHub ღილაკს სწორედ მათ აჩვენებს. შესაძლებლობების შესაზღუდად, დააყენეთ **ვის შეუძლია მიღება** პარამეტრი **პარამეტრები > ბანდლები** განყოფილებაში:
