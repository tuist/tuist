## ტეგები {#tags}

ატვირთვისას მიამაგრეთ ტეგები ბილდის ვარიანტების, გარემოების ან გამოშვების არხების გასარჩევად. ბანდლის ტეგები ემორჩილებიან იმავე შეთანხმებას, რასაც Build Insights-ის ტეგები:

```bash
tuist inspect bundle App.ipa --tags paid production
```

CI-ში ასევე შეგიძლიათ დააყენოთ მძიმით გამოყოფილი ტეგები `TUIST_BUNDLE_TAGS`-ის მეშვეობით:

```bash
TUIST_BUNDLE_TAGS="paid,production" tuist inspect bundle App.ipa
```

ცალსახა `--tags` ცვლის გარემოს ცვლადის ტეგებს. ტეგებში შეიძლება იყოს ასოები, ციფრები, დეფისები და ქვედატირეები; ერთ ბანდლზე მაქსიმუმ 10 ტეგი და თითო ტეგზე 50 სიმბოლო. იგივე პარამეტრები მოქმედებს Android ბანდლებისთვისაც. `--json` მუშაობს მხოლოდ ლოკალურად და არ ატვირთავს ტეგებს ან ბანდლს.

ტეგები ჩანს ბანდლის სახელების გვერდით და ბანდლის დეტალებში. გამოიყენეთ დაშბორდის **ტეგები** ფილტრი და შეიყვანეთ ტეგი, რომ ჩართოთ ან გამორიცხოთ ის ბანდლების სიაში. შესაბამისობა ზუსტია და მგრძნობიარეა რეგისტრის მიმართ, მიუხედავად იმისა, რომ ფილტრის ოპერატორებს ეწოდება **შეიცავს** და **არ შეიცავს**: `paid` არ ემთხვევა `paid-extra`-ს. CLI-დან ფილტრაციისთვის:

```bash
tuist bundle list --tags paid production
```

CLI, API (`?tags=paid,production`) და MCP-ის `list_bundles` ინსტრუმენტი (`tags: ["paid", "production"]`) აბრუნებენ ბანდლებს, რომლებიც შეიცავენ **ყველა** მითითებულ ტეგს. API-ს ატვირთვები იღებენ `bundle.custom_metadata.tags`-ს; სიისა და დეტალური პასუხები აბრუნებენ `custom_metadata.tags`-ს. არსებული ბანდლები ტეგების გარეშე ხელმისაწვდომი რჩება წინა მდგომარეობაში. ტეგები ფილტრავენ ბანდლების სიას; ისინი არ ცვლიან ზომის დიაგრამებს ან ავტომატური შედარებისა და ზღვრული მნიშვნელობების საბაზისო ხაზებს.

არსებული კლიენტები შეუძლიათ განაგრძონ ბანდლების ატვირთვა და წაკითხვა ტეგების გარეშე. განახლებული კლიენტები ასევე კითხულობენ პასუხებს ძველი სერვერებიდან, რომლებიც არ აბრუნებენ `custom_metadata`-ს. ტეგების შენახვა და ფილტრაცია საჭიროებს სერვერის ვერსიას, რომელიც მხარს უჭერს ბანდლის ტეგებს: ძველი სერვერები იგნორირებენ ატვირთვის მეტამონაცემებს და უარყოფენ ტეგების ფილტრებს. განახლებული კლიენტები ტოვებენ როგორც ატვირთვის მეტამონაცემებს, ასევე ტეგების მოთხოვნის პარამეტრებს, როცა ტეგები არ არის მითითებული.

## ბანდლის ზომების გაგება {#understanding-sizes}

ყოველი ანალიზირებული ბანდლისთვის Tuist აბრუნებს ორ მნიშვნელობას:

- **ინსტალაციის ზომა**: ადგილი, რომელსაც აპლიკაცია იკავებს მოწყობილობაზე ინსტალაციის შემდეგ.
- **ჩამოტვირთვის ზომა**: შეკუმშული ზომა, რომელსაც მომხმარებლები ჩამოტვირთავენ. Apple ბანდლებისთვის ეს მითითებულია მხოლოდ `.ipa`-ისთვის (არქივის ზომა); `.xcarchive` ან `.app` შეყვანისთვის ის ხელმისაწვდომი არ არის.

ზომები ინახება ბაიტებში და გამოისახება ათობითი შეთანხმებით, სადაც 1 MB არის 1,000,000 ბაიტი და 1 GB არის 1,000,000,000 ბაიტი — იგივე შეთანხმება, რომელსაც Apple იყენებს საცავისა და აპლიკაციების ზომების მოსახსენებლად (იხილეთ [როგორ იზომება საცავის ტევადობა Apple მოწყობილობებზე](https://support.apple.com/en-us/102119)). 733,446,863 ბაიტიანი ინსტალაციის ზომა გამოისახება როგორც 733.4 MB.

## ზომის ზღვრული მნიშვნელობები {#size-thresholds}

> [!WARNING]
> **Git Forge-თან ინტეგრაცია სავალდებულოა**
>
> ზომის ზღვრული მნიშვნელობების გამოყენებისთვის, დააკავშირეთ [Tuist GitHub App](https://github.com/apps/tuist) თქვენს პროექტთან. ეს შეგიძლიათ გააკეთოთ თქვენი პროექტის ინტეგრაციების გვერდიდან.

ზომის ზღვრული მნიშვნელობები საშუალებას გაძლევთ დაბლოკოთ pull requests, როცა ბანდლის ზომა აღემატება კონფიგურირებულ პროცენტულ ან აბსოლუტურ ზომას საბაზისო შტოსთან შედარებით. როცა ზღვარი ირღვევა, Tuist ქმნის GitHub Check Run-ს PR კომიტზე, რაც ბლოკავს merge-ს, სანამ ზომის ზრდა არ გადაწყდება:

### კონფიგურაცია {#size-thresholds-configuration}

ზღვრების კონფიგურაციისთვის, გადადით თქვენი პროექტის **Settings > Bundles** ჩანართზე:

![ბანდლის ზომის ზღვრული მნიშვნელობების პარამეტრები](/images/guides/features/bundle-size/bundle-size-thresholds.png)

აირჩიეთ **ინსტალაციის ზომა** ან **ჩამოტვირთვის ზომა**, შემდეგ აირჩიეთ **ზღვრის ტიპი**:

- **პროცენტი (%)**: ზრდის შეზღუდვა საბაზისო ზომასთან მიმართებაში. მხარდაჭერილია წილადი პროცენტები, როგორიცაა `0.47`. არსებული პროცენტული ზღვრები ინარჩუნებენ თავიანთ კონფიგურირებულ მნიშვნელობებს და ქცევას.
- **აბსოლუტური ზომა (MB)**: ზრდის შეზღუდვა ფიქსირებული რაოდენობით, საბაზისო ზომისგან დამოუკიდებლად. შეიყვანეთ `1.5`, რათა დაუშვათ 1.5 MB-მდე ზრდა. MB იყენებს ათობით ერთეულებს: 1 MB = 1,000,000 ბაიტი. მნიშვნელობები უნდა იქცეს ბაიტების დადებით მთელ რიცხვად.

![ბანდლის ზომის აბსოლუტური ზრდის ზღვრის კონფიგურაცია](/images/guides/features/bundle-size/absolute-size-threshold.png)

ორივე ტიპი ადარებს კონფიგურირებულ **საბაზისო შტოსთან** უახლეს ბანდლს იგივე სახელით, იგივე ბანდლის ტიპით (მაგალითად, `.app` ან `.ipa`) და მინიმუმ ერთი საერთო პლატფორმით, ასე რომ სიმულატორის `.app` შედარდება მხოლოდ სიმულატორის `.app` ატვირთვებთან. არჩევითი **ბანდლის სახელი** ზღუდავს წესს ამ ბანდლზე. შემოწმება ვერ გადის მხოლოდ მაშინ, როცა ზრდა არის **მეტია** ლიმიტზე; თანაბარი ზრდა, უცვლელი ზომები და შემცირება გადის. შესაბამისი საბაზისო ან არჩეული მეტრიკისთვის ჩაწერილი ზომის გარეშე, წესი გამოტოვებულია. ნულოვანი ზომის საბაზისო მხარდაჭერილია აბსოლუტური ლიმიტებისთვის; პროცენტული ლიმიტები კვლავ გამოტოვებენ მას, რადგან პროცენტული ზრდა განუსაზღვრელია.

### ვის შეუძლია მიღება {#size-thresholds-approvals}

ნაგულისხმევად, ნებისმიერს, ვისაც აქვს რეპოზიტორიაში ჩაწერის უფლება, შეუძლია ზომის ზრდის მიღება, რადგან GitHub ღილაკს სწორედ მათ აჩვენებს. შესაზღუდად, დააყენეთ **ვის შეუძლია მიღება** **Settings > Bundles**-ში:

- **ნებისმიერი**: ნაგულისხმევი. ნებისმიერი, ვისაც აქვს რეპოზიტორიაში ჩაწერის უფლება.
- **არჩეული GitHub მომხმარებლები**: მხოლოდ ის GitHub მომხმარებლის სახელები, რომლებსაც დაამატებთ.

ვინც სიაში არ არის, ტოვებს შემოწმებას წარუმატებელს ახსნით, ხოლო ღილაკი რჩება იმისთვის, ვისაც შეუძლია მისი გამოყენება.
