## ტეგები {#tags}

ბანდლის ატვირთვისას მიამაგრეთ ტეგები, რათა განასხვავოთ ბილდის ვარიანტები, გარემოები ან გამოშვების არხები. ბანდლის ტეგები ემორჩილებიან იმავე შეთანხმებას, რასაც Build Insights-ის ტეგები:

```bash
tuist inspect bundle App.ipa --tags paid production
```

CI-ში ასევე შეგიძლიათ დააყენოთ მძიმით გამოყოფილი ტეგები `TUIST_BUNDLE_TAGS`-ის საშუალებით:

```bash
TUIST_BUNDLE_TAGS="paid,production" tuist inspect bundle App.ipa
```

ცალსახად მითითებული `--tags` ცვლის გარემოს ცვლადის ტეგებს. ტეგებმა შეიძლება შეიცავდნენ ასოებს, რიცხვებს, დეფისებს და ქვედა ხაზებს; თითოეულ ბანდლზე მაქსიმუმ 10 ტეგი და თითოეულ ტეგზე მაქსიმუმ 50 სიმბოლო. იგივე პარამეტრები მოქმედებს Android-ის ბანდლებისთვისაც. `--json` რჩება მხოლოდ ლოკალურად და არ ტვირთავს არც ტეგებს და არც ბანდლს.

ტეგები ჩანს ბანდლის სახელების გვერდით და ბანდლის დეტალებში. გამოიყენეთ დაშბორდის ფილტრი **ტეგები** და შეიყვანეთ ტეგი, რათა ის შეიტანოთ ან ამოიღოთ ბანდლების სიიდან. შესაბამისობა ზუსტია და მგრძნობიარეა რეგისტრის მიმართ, მიუხედავად იმისა, რომ ფილტრის ოპერატორებს ეწოდება **შეიცავს** და **არ შეიცავს**: `paid` არ ემთხვევა `paid-extra`-ს. CLI-დან გასაფილტრად:

```bash
tuist bundle list --tags paid production
```

CLI, API (`?tags=paid,production`) და MCP-ის ინსტრუმენტი `list_bundles` (`tags: ["paid", "production"]`) აბრუნებენ ბანდლებს, რომლებიც შეიცავენ **ყველა** მითითებულ ტეგს. API-ს ატვირთვები იღებენ `bundle.custom_metadata.tags`; სიისა და დეტალების პასუხები აბრუნებენ `custom_metadata.tags`. არსებული ბანდლები ტეგების გარეშე კვლავ ხელმისაწვდომია წინაებურად. ტეგები ფილტრავენ ბანდლების სიას; ისინი არ ცვლიან ზომის დიაგრამებს ან ავტომატური შედარებისა და ზღვრული მნიშვნელობების საბაზისო ხაზებს.

არსებულ კლიენტებს შეუძლიათ განაგრძონ ბანდლების ატვირთვა და წაკითხვა ტეგების გარეშე. განახლებულ კლიენტებს ასევე შეუძლიათ წაიკითხონ პასუხები უფრო ძველი სერვერებიდან, რომლებიც გამოტოვებენ `custom_metadata`-ს. ტეგების შენახვა და გაფილტვრა მოითხოვს სერვერის ვერსიას, რომელიც მხარს უჭერს ბანდლის ტეგებს: უფრო ძველი სერვერები იგნორირებენ ატვირთვის მეტამონაცემებს და უარყოფენ ტეგების ფილტრებს. განახლებული კლიენტები გამოტოვებენ როგორც ატვირთვის მეტამონაცემებს, ასევე ტეგების მოთხოვნის პარამეტრებს, როცა ტეგები არ არის მითითებული.

## ბანდლის ზომების გაგება {#understanding-sizes}

ყოველი ანალიზირებული ბანდლისთვის Tuist იუწყება ორ მნიშვნელობას:

- **ინსტალაციის ზომა**: სივრცე, რომელსაც აპლიკაცია იკავებს მოწყობილობაზე ინსტალაციის შემდეგ.
- **ჩამოტვირთვის ზომა**: შეკუმშული ზომა, რომელსაც მომხმარებლები ჩამოტვირთავენ. Apple-ის ბანდლებისთვის ეს მხოლოდ `.ipa`-ისთვის არის მითითებული (არქივის ზომა); `.xcarchive` ან `.app` შეყვანებისთვის ის არ არის ხელმისაწვდომი.

ზომები ინახება ბაიტებში და ჩანს ათობითი შეთანხმების გამოყენებით, სადაც 1 MB არის 1,000,000 ბაიტი და 1 GB არის 1,000,000,000 ბაიტი — იგივე შეთანხმება, რომელსაც Apple იყენებს საცავისა და აპლიკაციების ზომების მითითებისას (იხილეთ [როგორ იზომება საცავის ტევადობა Apple-ის მოწყობილობებზე](https://support.apple.com/en-us/102119)). 733,446,863 ბაიტის ინსტალაციის ზომა ჩანს როგორც 733.4 MB.

## ზომის ზღვრული მნიშვნელობები {#size-thresholds}

> [!WARNING]
> **Git forge-თან ინტეგრაცია აუცილებელია**
>
> ზომის ზღვრული მნიშვნელობების გამოსაყენებლად, დააკავშირეთ [Tuist GitHub App](https://github.com/apps/tuist) თქვენს პროექტთან. ეს შეგიძლიათ გააკეთოთ თქვენი პროექტის ინტეგრაციების გვერდიდან.

ზომის ზღვრული მნიშვნელობები გაძლევთ საშუალებას დაბლოკოთ pull requests, როცა ბანდლის ზომა აღემატება კონფიგურირებულ პროცენტულ ან აბსოლუტურ ზომას საბაზისო შტოსთან შედარებით. როცა ზღვარი ირღვევა, Tuist ქმნის GitHub Check Run-ს PR-ის კომიტზე, რაც ბლოკავს merge-ს, სანამ ზომის ზრდა არ გადაწყდება:

### კონფიგურაცია {#size-thresholds-configuration}

ზღვრული მნიშვნელობების კონფიგურირებისთვის, გადადით თქვენი პროექტის **Settings > Bundles** ჩანართზე:

![ბანდლის ზომის ზღვრული მნიშვნელობების პარამეტრები](/images/guides/features/bundle-size/bundle-size-thresholds.png)

აირჩიეთ **ინსტალაციის ზომა** ან **ჩამოტვირთვის ზომა**, შემდეგ აირჩიეთ **ზღვრის ტიპი**:

- **პროცენტი (%)**: ზრდის შეზღუდვა საბაზისო ზომასთან მიმართებაში. მხარდაჭერილია წილადი პროცენტები, როგორიცაა `0.47`. არსებული პროცენტული ზღვრები ინარჩუნებენ მათ კონფიგურირებულ მნიშვნელობებსა და ქცევას.
- **აბსოლუტური ზომა (MB)**: ზრდის შეზღუდვა ფიქსირებული რაოდენობით, საბაზისო ზომისგან დამოუკიდებლად. შეიყვანეთ `1.5`, რათა დაუშვათ 1.5 MB-მდე ზრდა. MB იყენებს ათობით ერთეულებს: 1 MB = 1,000,000 ბაიტი. მნიშვნელობები უნდა იყოს დადებითი მთელი რიცხვი ბაიტებში.

![ბანდლის ზომის ზრდის აბსოლუტური ზღვრის კონფიგურაცია](/images/guides/features/bundle-size/absolute-size-threshold.png)

ორივე ტიპი ადარებს კონფიგურირებულ **საბაზისო შტოსთან** არსებულ უახლეს ბანდლს იმავე სახელით, იმავე ბანდლის ტიპით (მაგალითად `.app` ან `.ipa`) და მინიმუმ ერთი საერთო პლატფორმით, ასე რომ სიმულატორის `.app` შედარდება მხოლოდ სიმულატორის `.app` ატვირთვებთან. არასავალდებულო **ბანდლის სახელი** ზღუდავს წესს ამ კონკრეტული ბანდლისთვის. შემოწმება ვერ გადის მხოლოდ მაშინ, როცა ზრდა **აჭარბებს** ლიმიტს; თანაბარი ზრდა, უცვლელი ზომები და შემცირება გადის. შესაბამისი საბაზისო ვერსიის ან არჩეული მეტრიკის ჩაწერილი ზომის გარეშე წესი გამოიტოვება. ნულოვანი ზომის საბაზისო ვერსია მხარდაჭერილია აბსოლუტური ლიმიტებისთვის; პროცენტული ლიმიტები კვლავ გამოტოვებენ მას, რადგან პროცენტული ზრდა განუსაზღვრელია.

### ვის შეუძლია მიღება {#size-thresholds-approvals}

ნაგულისხმევად, ნებისმიერს, ვისაც რეპოზიტორიზე ჩაწერის უფლება აქვს, შეუძლია ზომის ზრდის მიღება, რადგან GitHub ღილაკს სწორედ მათ აჩვენებს. შესაზღუდად, დააყენეთ **ვის შეუძლია მიღება** პარამეტრი **Settings > Bundles** განყოფილებაში:

- **ნებისმიერი**: ნაგულისხმევი. ნებისმიერი, ვისაც რეპოზიტორიზე ჩაწერის უფლება აქვს.
- **შერჩეული GitHub მომხმარებლები**: მხოლოდ ის GitHub-ის მომხმარებლის სახელები, რომლებსაც დაამატებთ.

თუ ვინმე სიაში არ არის, შემოწმება ვერ გადის ახსნით და ღილაკი რჩება იმისთვის, ვისაც მისი გამოყენება შეუძლია.
