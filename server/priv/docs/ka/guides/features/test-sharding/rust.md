# Rust ტესტების დაყოფა {#rust-test-sharding}

Tuist ნაწილობს Cargo-ს ტესტის სამიზნეებს CI მუშაკებზე ისტორიული სამიზნე ხანგრძლივობების გამოყენებით. იუნით-ტესტების სამიზნეები, ინტეგრაციული ტესტების სამიზნეები და თითოეული ბიბლიოთეკის doctests ცალკე მოდულებია. ერთი სამიზნის ფარგლებში არსებული ტესტები ერთად რჩება.

> [!IMPORTANT] Requirements
> - მოაწყვეთ <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link> და გაიარეთ CLI-ის ავტორიზაცია დაგეგმვის სამუშაოზე და მუშაკებზე.
> - აირჩიეთ ერთი პაკეტი, გამოიყენეთ `-p <package>` workspace-ში. მრავალი პაკეტის დაყოფა მხარდაჭერილი არ არის.
> - გამოიყენეთ იგივე რევიზია, Rust-ის ინსტრუმენტები, პაკეტის შერჩევა, ფუნქციები და ტესტების ფილტრები ყოველ სამუშაოში.

## შექმენით გეგმა {#create-a-plan}

დაამატეთ shard-ების რაოდენობა `--no-run`-ს, რათა დააკომპილიროთ და ჩამოთვალოთ სამიზნეები ტესტების შესრულების გარეშე:

```sh
TUIST_SHARD_REFERENCE=my-ci-run tuist cargo test -p store --no-run --shard-max 4
```

ბრძანება ბეჭდავს JSON-ს, რომელიც შეიცავს `shard_plan_id`-ს და ნულიდან დაწყებულ `shards` მასივს. GitHub Actions-ში ის ასევე წერს `shard-plan-id`-ს და `shards`-ს `GITHUB_OUTPUT`-ში. ცხადი მითითების გარეშე, Tuist გამოიყვანს მას მხარდაჭერილი CI გარემოდან.

| პარამეტრი | აღწერა |
| --- | --- |
| `--shard-max N` | Shard-ების მაქსიმალური რაოდენობა |
| `--shard-min N` | Shard-ების მინიმალური რაოდენობა |
| `--shard-total N` | ზუსტი რაოდენობა, არსებული სამიზნეების ფარგლებში |
| `--shard-max-duration N` | სამიზნე shard-ის მაქსიმალური ხანგრძლივობა მილიწამებში |

გამოიყენეთ `--shard-total` ცალკე ან გააერთიანეთ `--shard-min` და `--shard-max`. ისტორიული ხანგრძლივობების გარეშე, დამგეგმავი იყენებს სამიზნეების ნაგულისხმევ შეფასებებს. ჩვეულებრივი `--no-run` shard-ის პარამეტრების გარეშე რჩება მხოლოდ კომპილაციის ბრძანებად.

## შეასრულეთ თითოეული shard {#execute-each-shard}

დააყენეთ გეგმის ID და shard-ის ინდექსი თითოეულ მუშაკზე, შემდეგ გამოიყენეთ იგივე Cargo ტესტის არგუმენტები:

```sh
TUIST_SHARD_PLAN_ID=<plan-id> TUIST_SHARD_INDEX=0 tuist cargo test -p store
```

ალტერნატიულად, დააყენეთ `TUIST_SHARD_REFERENCE` დაგეგმვის სამუშაოს მითითებაზე გეგმის ID-ის გადაცემის ნაცვლად. Tuist იღებს განაწილებას და სთხოვს Cargo-ს შეასრულოს მხოლოდ ეს სამიზნეები. არასწორი ან შეუთავსებელი განაწილებები აუქმებს ბრძანებას ყველა ტესტის გაშვების ნაცვლად. ცარიელი განაწილებები არ ასრულებს ტესტებს. მუშაკების შედეგები დაკავშირებულია გეგმასთან Test Insights-ში და <.localized_link href="/guides/features/test-insights/flaky-tests/rust#quarantine">კარანტინი</.localized_link> ვრცელდება თითოეულ shard-ში.

## შეზღუდვები {#limits}

ეს არის სამიზნე დონის დაყოფა და არა ერთჯერადი აგების განაწილება. თითოეულ მუშაკს სჭირდება წყაროს ასლი და თავად აგებს საკუთარ სამიზნეებს; <.localized_link href="/guides/features/cache/rust">Cargo კომპილაციის ქეში</.localized_link> შეუძლია ხელახლა გამოიყენოს შესაბამისი კომპილაციის შედეგები. Tuist არ ტვირთავს ტესტის შესრულებად ფაილებს და არ საჭიროებს სხვა Rust ტესტის გამშვებს.

დაყოფა მოითხოვს ერთ არჩეულ პაკეტს. მრავალპაკეტიანი ბრძანების შევიწროვებამ შეიძლება შეცვალოს Cargo-ს გაერთიანებული დამოკიდებულების ფუნქციები, ამიტომ Tuist უარყოფს მას სხვა ფუნქციების გრაფით ტესტების გაშვების ნაცვლად. დაგეგმეთ თითოეული პაკეტი ცალკე, სანამ მრავალპაკეტიანი დაყოფა მხარდაჭერილი იქნება.

დაყოფა მოითხოვს სტანდარტულ libtest harness-ებს და ჩაჭერილ ნაგულისხმევ გამომავალს. ჩუმად, verbose, ალტერნატიული ფორმატის, არაჩაჭერილი გამომავალი და custom-harness ბრძანებები უარყოფილია. თუ Cargo ვერ ახერხებს სამიზნის ცალსახად იდენტიფიცირებას, აირჩიეთ ზუსტი workspace პაკეტი `-p <package>`-ით. დამოკიდებულების პაკეტები, ვერსიით კვალიფიცირებული სელექტორები, პაკეტის/სამიზნის სახელის გლობები და Cargo-ს ღამის `-C` პარამეტრი მხარდაჭერილი არ არის დაყოფისთვის. შეინარჩუნეთ ტესტების შერჩევა იდენტური დაგეგმვასა და შესრულებას შორის.
