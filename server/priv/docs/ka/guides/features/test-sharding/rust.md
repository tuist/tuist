# Rust ტესტების დაყოფა {#rust-test-sharding}

Tuist ანაწილებს Cargo-ს ტესტის სამიზნეებს CI მუშაკებზე ისტორიული სამიზნე ხანგრძლივობების გამოყენებით. ერთეული ტესტების სამიზნეები, ინტეგრაციული ტესტების სამიზნეები და თითოეული ბიბლიოთეკის doctests ცალკე მოდულებია. ერთი სამიზნის ფარგლებში ტესტები ერთად რჩება.

> [!IMPORTANT] Requirements
> - მოახდინეთ კონფიგურაცია <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link> და გაიარეთ CLI-ის ავთენტიკაცია დაგეგმვის დავალებაზე და მუშაკებზე.
> - აირჩიეთ ერთი პაკეტი, `-p <package>`-ის გამოყენებით სამუშაო სივრცეში. მრავალპაკეტიანი დაყოფა არ არის მხარდაჭერილი.
> - გამოიყენეთ იგივე რევიზია, Rust-ის ინსტრუმენტების ჯაჭვი, პაკეტის შერჩევა, ფუნქციები და ტესტის ფილტრები ყველა დავალებაში.

## გეგმის შექმნა {#create-a-plan}

დაამატეთ ნაწილების რაოდენობა `--no-run`-ზე, რათა დააკომპილიროთ და ჩამოთვალოთ სამიზნეები ტესტების შესრულების გარეშე:

```sh
TUIST_SHARD_REFERENCE=my-ci-run tuist cargo test -p store --no-run --shard-max 4
```

ბრძანება ბეჭდავს JSON-ს, რომელიც შეიცავს `shard_plan_id`-ს და ნულოვანი ინდექსის მქონე `shards` მასივს. GitHub Actions-ში ის ასევე წერს `shard-plan-id`-ს და `shards`-ს `GITHUB_OUTPUT`-ში. ცხადი მითითების გარეშე, Tuist გამოიყვანს მას მხარდაჭერილი CI გარემოდან.

| პარამეტრი | აღწერა |
| --- | --- |
| `--shard-max N` | ნაწილების მაქსიმალური რაოდენობა |
| `--shard-min N` | ნაწილების მინიმალური რაოდენობა |
| `--shard-total N` | ზუსტი რაოდენობა, ხელმისაწვდომი სამიზნეების ფარგლებში |
| `--shard-max-duration N` | სამიზნე ნაწილის მაქსიმალური ხანგრძლივობა მილიწამებში |

გამოიყენეთ `--shard-total` ცალკე ან გააერთიანეთ `--shard-min` და `--shard-max`. ისტორიული ხანგრძლივობების გარეშე, დამგეგმავი იყენებს სამიზნეების ნაგულისხმევ შეფასებებს. ჩვეულებრივი `--no-run` ნაწილების პარამეტრების გარეშე რჩება მხოლოდ აგების ბრძანებად.

## თითოეული ნაწილის შესრულება {#execute-each-shard}

დააყენეთ გეგმის ID და ნაწილის ინდექსი თითოეულ მუშაკზე, შემდეგ გამოიყენეთ იგივე Cargo ტესტის არგუმენტები:

```sh
TUIST_SHARD_PLAN_ID=<plan-id> TUIST_SHARD_INDEX=0 tuist cargo test -p store
```

ალტერნატიულად, დააყენეთ `TUIST_SHARD_REFERENCE` დაგეგმვის დავალების მითითებაზე გეგმის ID-ის გადაცემის ნაცვლად. Tuist იღებს განაწილებას და სთხოვს Cargo-ს მხოლოდ ამ სამიზნეების შესრულებას. არასწორი ან შეუთავსებელი განაწილებები აფერხებენ ბრძანებას ყველა ტესტის გაშვების ნაცვლად. ცარიელი განაწილებები არ ასრულებენ ტესტებს. მუშაკების შედეგები დაკავშირებულია გეგმასთან Test Insights-ში და <.localized_link href="/guides/features/test-insights/flaky-tests/rust#quarantine">კარანტინი</.localized_link> ვრცელდება თითოეულ ნაწილში.

## შეზღუდვები {#limits}

ეს არის სამიზნე დონის დაყოფა, არა ერთჯერადი აგების განაწილება. თითოეულ მუშაკს სჭირდება წყაროს კოპირება და თავისი სამიზნეების აგება; <.localized_link href="/guides/features/cache/rust">Cargo კომპილაციის ქეში</.localized_link> შეუძლია ხელახლა გამოიყენოს შესაბამისი კომპილაციის შედეგები. Tuist არ ტვირთავს ტესტის შესრულებად ფაილებს და არ მოითხოვს სხვა Rust ტესტის გამშვებს.

დაყოფა მოითხოვს ერთ არჩეულ პაკეტს. მრავალპაკეტიანი ბრძანების შევიწროვებამ შეიძლება შეცვალოს Cargo-ს გაერთიანებული დამოკიდებულების ფუნქციები, ამიტომ Tuist უარყოფს მას ტესტების სხვა ფუნქციების გრაფით გაშვების ნაცვლად. დაგეგმეთ თითოეული პაკეტი ცალკე, სანამ მრავალპაკეტიანი დაყოფა მხარდაჭერილი იქნება.

დაყოფა მოითხოვს სტანდარტულ libtest harness-ებს და ჩაჭერილ ნაგულისხმევ გამომავალ მონაცემებს. ჩუმი, ვრცელი, ალტერნატიული ფორმატის, არაჩაჭერილი გამომავალი მონაცემების და მორგებული harness-ის ბრძანებები უარყოფილია. თუ Cargo ვერ ახდენს სამიზნის უნიკალურ იდენტიფიცირებას, აირჩიეთ ზუსტი სამუშაო სივრცის პაკეტი `-p <package>`-ის გამოყენებით. დამოკიდებულების პაკეტები, ვერსიით კვალიფიცირებული სელექტორები, პაკეტის/სამიზნის სახელის გლობები და Cargo-ს ღამის `-C` პარამეტრი არ არის მხარდაჭერილი დაყოფისთვის. შეინარჩუნეთ ტესტის შერჩევა იდენტური დაგეგმვასა და შესრულებას შორის.
