# Rust ტესტების შარდინგი {#rust-test-sharding}

Tuist ანაწილებს Cargo-ს ტესტის სამიზნეებს CI მუშაკებზე ისტორიული სამიზნე ხანგრძლივობების გამოყენებით. იუნით-ტესტის სამიზნეები, ინტეგრაციული ტესტის სამიზნეები და თითოეული ბიბლიოთეკის doctests ცალკე მოდულებია. ერთი სამიზნის ფარგლებში არსებული ტესტები ერთად რჩება.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - დააკონფიგურირეთ <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link> და გაიარეთ CLI-ის ავტორიზაცია დაგეგმვის სამუშაოზე და მუშაკებზე.
> - აირჩიეთ ერთი პაკეტი, ვორქსპეისში `-p <package>`-ის გამოყენებით. მრავალპაკეტიანი შარდინგი მხარდაჭერილი არ არის.
> - ყოველ სამუშაოზე გამოიყენეთ იგივე რევიზია, Rust-ის ინსტრუმენტთა ჯაჭვი, პაკეტის შერჩევა, ფუნქციები და ტესტის ფილტრები.

## გეგმის შექმნა {#create-a-plan}

დაამატეთ შარდების რაოდენობა `--no-run`-ში სამიზნეების კომპილირებისა და ჩამოთვლისთვის ტესტების შესრულების გარეშე:

```sh
TUIST_SHARD_REFERENCE=my-ci-run tuist cargo test -p store --no-run --shard-max 4
```

ბრძანება ბეჭდავს JSON-ს, რომელიც შეიცავს `shard_plan_id`-ს და ნულიდან დაწყებულ `shards` მასივს. GitHub Actions-ში ის ასევე წერს `shard-plan-id`-ს და `shards`-ს `GITHUB_OUTPUT`-ში. ცხადი მითითების გარეშე, Tuist მიიღებს მას მხარდაჭერილი CI გარემოდან.

| პარამეტრი | აღწერა |
| --- | --- |
| `--shard-max N` | შარდების მაქსიმალური რაოდენობა |
| `--shard-min N` | შარდების მინიმალური რაოდენობა |
| `--shard-total N` | ზუსტი რაოდენობა, ხელმისაწვდომი სამიზნეების ფარგლებში |
| `--shard-max-duration N` | შარდის მაქსიმალური ხანგრძლივობა მილიწამებში |

გამოიყენეთ `--shard-total` ცალკე ან გააერთიანეთ `--shard-min` და `--shard-max`. ისტორიული ხანგრძლივობების გარეშე, დამგეგმავი იყენებს სამიზნეების ნაგულისხმევ შეფასებებს. ჩვეულებრივი `--no-run` შარდის პარამეტრების გარეშე რჩება მხოლოდ აგების ბრძანებად.

## ყოველი შარდის შესრულება {#execute-each-shard}

დააყენეთ გეგმის ID და შარდის ინდექსი თითოეულ მუშაკზე, შემდეგ კი გამოიყენეთ იგივე Cargo ტესტის არგუმენტები:

```sh
TUIST_SHARD_PLAN_ID=<plan-id> TUIST_SHARD_INDEX=0 tuist cargo test -p store
```

ალტერნატიულად, დააყენეთ `TUIST_SHARD_REFERENCE` დაგეგმვის სამუშაოს მითითებაზე გეგმის ID-ის გადაცემის ნაცვლად. Tuist იღებს განაწილებას და სთხოვს Cargo-ს მხოლოდ ამ სამიზნეების შესრულებას. არასწორი ან შეუთავსებელი განაწილებები აფრთხილებენ ბრძანებას ყველა ტესტის გაშვების ნაცვლად. ცარიელი განაწილებები არ ასრულებენ ტესტებს. მუშაკების შედეგები დაკავშირებულია გეგმასთან Test Insights-ში და <.localized_link href="/guides/features/test-insights/flaky-tests/rust#quarantining">კარანტინი</.localized_link> ვრცელდება თითოეულ შარდში.

## შეზღუდვები {#limits}

ეს არის სამიზნის დონის შარდინგი და არა ერთჯერადი აგების განაწილება. თითოეულ მუშაკს სჭირდება წყაროს ჩექაუთი და თავისი სამიზნეების აგება; <.localized_link href="/guides/features/cache/rust">Cargo კომპილაციის ქეში</.localized_link> შეუძლია ხელახლა გამოიყენოს შესაბამისი კომპილაციის გამონატანები. Tuist არ ტვირთავს ტესტის შესრულებად ფაილებს და არ საჭიროებს სხვა Rust ტესტის გამშვებს.

შარდინგი მოითხოვს ერთ შერჩეულ პაკეტს. მრავალპაკეტიანი ბრძანების შევიწროვებამ შეიძლება შეცვალოს Cargo-ს გაერთიანებული დამოკიდებულების ფუნქციები, ამიტომ Tuist უარყოფს მას სხვა ფუნქციური გრაფით ტესტების გაშვების ნაცვლად. დაგეგმეთ თითოეული პაკეტი ცალკე, სანამ მრავალპაკეტიანი შარდინგი მხარდაჭერილი იქნება.

შარდინგი მოითხოვს სტანდარტულ libtest harness-ებს და ჩაჭერილ ნაგულისხმევ გამონატანს. ჩუმი, ვრცელი, ალტერნატიული ფორმატის, არაჩაჭერილი გამონატანის და მორგებული harness-ის ბრძანებები უარყოფილია. თუ Cargo ვერ ახდენს სამიზნის უნიკალურ იდენტიფიცირებას, აირჩიეთ ზუსტი ვორქსპეისის პაკეტი `-p <package>`-ით. დამოკიდებულების პაკეტები, ვერსიით კვალიფიცირებული სელექტორები, პაკეტის/სამიზნის სახელის გლობები და Cargo-ის ღამის `-C` პარამეტრი მხარდაჭერილი არ არის შარდინგისთვის. შეინარჩუნეთ ტესტის შერჩევა იდენტური დაგეგმვასა და შესრულებას შორის.
