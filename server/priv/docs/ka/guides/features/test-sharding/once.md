# Once-ის ტესტების დაშლა {#once-test-sharding}

როდესაც თქვენი ტესტების ნაკრები ერთ მანქანას აღემატება, Once-ს შეუძლია Tuist-ს სთხოვოს აღმოჩენილი ტესტების პაკეტების განაწილება CI სამუშაოებზე. სამუშაოები ასრულებენ დავალებებს Once-ის მეშვეობით, ხოლო Tuist აერთიანებს მათ ანგარიშებს ერთ ტესტების გაშვებად.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - დაასრულეთ <.localized_link href="/guides/get-started/once-project">Once-ის დაწყება</.localized_link>.
> - გამოიყენეთ Once-ის ის ვერსია, რომელიც აჩვენებს `once query test-plan --shards` და `once test --shard-plan`. Once 0.71.0 მხარს უჭერს მხოლოდ პორტატულ გეგმებს და არა ამ ჰოსტინგურ სამუშაო პროცესს.
> - შეარჩიეთ ტესტების მიზნების სრული აღმოჩენა და იგივე checkout და ტესტირების გარემო ხელმისაწვდომი იყოს სამუშაოებზე.

Tuist CLI შემფუთავი არ არის საჭირო. Once იყენებს თავის ნატიურ Tuist პროვაიდერს და სერთიფიკატებს.

## აღმოაჩინეთ თქვენი ტესტები {#discover-your-tests}

გაუშვით შერჩეული ტესტები აღმოჩენის დასადგენად გეგმის შედგენამდე:

```bash
once test MyTests --format json
```

ხელმისაწვდომი პაკეტის სიმკვრივე დამოკიდებულია გამშვებზე. ზოგიერთი ტესტის მიზანი მხარს უჭერს ფაილის ან საქმის პაკეტებს; სხვები რჩებიან მიზნის დონეზე. მიჰყევით [Once-ის ტესტირების სახელმძღვანელოს](https://buildonce.dev/docs/guide/graph/testing) აღმოჩენისა და პაკეტირების შესაძლებლობებისთვის.

## შექმენით ჰოსტინგური გეგმა {#create-a-hosted-plan}

გეგმის სამუშაოში გამოიყენეთ მითითება, რომელიც გაზიარებულია ამ CI შესრულების მიერ:

```bash
once query test-plan --shards 4 --reference "$CI_EXECUTION_ID" --format json
```

პასუხი შეიცავს ჰოსტინგური გეგმის ID-ს და სამუშაოების რეალურ ინდექსებს:

```json
{"shard_plan_id":"<UUID>","shards":[0,1,2,3]}
```

ააგეთ თქვენი CI მატრიცა `shards`-დან, ნაცვლად იმის ვარაუდისა, რომ ის შეიცავს ოთხ ჩანაწერს. ცარიელი გეგმა აბრუნებს ცარიელ ID-ს და მასივს, ამიტომ არ არის საჭირო სამუშაოების დაწყება. გადაეცით `--target` გეგმის შესავიწროებლად ან გაიმეორეთ `--changed-path` Once-ის გრაფზე დაფუძნებული შერჩევის გამოსაყენებლად.

მითითება ნაგულისხმევად არის `TUIST_SHARD_REFERENCE` ან აღმოჩენილი CI გაშვება. გადაეცით ის ცალსახად, როდესაც გარემოს არ აქვს მხარდაჭერილი CI იდენტიფიკატორი.

## გაუშვით თითოეული ნაწილი {#execute-each-shard}

მიეცით თითოეულ სამუშაოს დაბრუნებული გეგმის ID და მისი საკუთარი ინდექსი:

```bash
once test --shard-plan "$SHARD_PLAN_ID" --shard-index "$SHARD_INDEX" --jobs 4
```

ალტერნატიულად, დააყენეთ `TUIST_SHARD_PLAN_ID` და `TUIST_SHARD_INDEX`. სამუშაოები ჩამოტვირთავენ ზუსტად UUID-თან დაკავშირებულ გეგმას და შეასრულებენ მხოლოდ მათთვის განკუთვნილ პაკეტებს. ცარიელი დავალება არაფერს ასრულებს; დაკარგული შედეგები, წარუმატებელი პროცესები და შეწყვეტილი სამუშაო ვერ გაივლიან განყოფილებას.

ეს ანაწილებს ტესტების გეგმას და არა წინასწარ კომპილირებულ ტესტების აგების არქივს. მოამზადეთ საჭირო წყაროები, ინსტრუმენტები და აღმოჩენა სამუშაოებზე; გაზიარებულმა ქეშირებამ შეიძლება თავიდან აიცილოს შესაბამისი აგების სამუშაოს განმეორება.

## განმეორებითი გაშვებები და შედეგები {#reruns-and-results}

განმეორებითი გაშვებისთვის, გაზარდეთ `--shard-attempt`, ან დააყენეთ `TUIST_SHARD_ATTEMPT`. სხვა შემთხვევაში Once იყენებს GitHub გაშვების მცდელობას, შემდეგ კი ნაგულისხმევად 1-ს. `--shard-report-revision` ნაგულისხმევად არის 0 და შეიძლება გაიზარდოს, როდესაც ასწორებთ ანგარიშს იმავე მცდელობის ფარგლებში. ეს მრიცხველები ცალკეა ტესტის განმეორებებისგან.

გახსენით **ტესტები → ნაწილები** გეგმის, ბალანსის და მოხსენებული სამუშაოების შესამოწმებლად, შემდეგ კი გახსენით გაერთიანებული ტესტების გაშვება ინდივიდუალური შედეგებისთვის. Once-ის დაგეგმვის ერთეულები მონიშნულია როგორც **პაკეტები**; საქმეები ინარჩუნებენ თავიანთ ნატიურ მიზანს, ნაკრებს და ტესტის სახელებს.
