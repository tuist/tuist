# კეში {#cache}

ბილდის არტიფაქტები არ ნაწილდება გარემოებს შორის, რაც გაიძულებთ ერთი და იგივე კოდის ხელახლა აგებას. Tuist-ის ქეშირების ფუნქცია დისტანციურად აზიარებს არტიფაქტებს, რათა თქვენმა გუნდმა და CI-მ მიიღონ უფრო სწრაფი ბილდები უკვე აგებული კომპონენტების ხელახალი აგების გარეშე. იმის შესახებ, თუ როგორ მუშაობენ ლოკალური და დისტანციური ბილდის ქეშები სხვადასხვა ბილდ-სისტემებში და რა არის Xcode-ის საკუთარი ქეშები, იხილეთ <.localized_link href="/references/concepts/build-cache">რა არის ბილდის ქეში?</.localized_link>. იმის გასარკვევად, თუ რატომ არის ბილდები ნელი ქეშის არჩევამდე, იხილეთ [ნელი ბილდები](https://tuist.dev/solutions/slow-builds).

შეისწავლეთ ქეშის სამუშაო პროცესი, რომელიც შეესაბამება თქვენს პროექტს ან განლაგების მოდელს:

## შეზღუდეთ ატვირთვები მხოლოდ CI-სთვის {#restrict-uploads-to-ci}

ანგარიშის ადმინისტრატორებს შეუძლიათ დეველოპერებს მიაკუთვნონ მხოლოდ კითხვის უფლება, ხოლო CI-ს ნება დართონ ქეშის არტიფაქტების ატვირთვა. გახსენით ანგარიშის **ქეშის** პარამეტრები Tuist-ში და დააყენეთ **ქეშის ატვირთვის წვდომა** მნიშვნელობაზე **მხოლოდ CI და ანგარიშის ტოკენები**. ამის შემდეგ, შესვლის სესიებით ავთენტიფიცირებულ წევრებს კვლავ შეეძლებათ ქეშიდან ჩამოტვირთვა, მაგრამ ატვირთვები მოითხოვს CI OIDC ავთენტიფიკაციას ან ანგარიშის ტოკენს ქეშის ჩაწერის სკოპებით, როგორიცაა `project:cache:write` ან `ci`.

გამოიყენეთ ეს, როდესაც CI არის სანდო ქეშის მწარმოებელი და ლოკალურმა მანქანებმა მხოლოდ უნდა მოიხმარონ ქეში. პარამეტრი მოქმედებს მხოლოდ ქეშის ატვირთვის ავტორიზაციაზე.
