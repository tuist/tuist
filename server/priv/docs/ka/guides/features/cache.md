# კეში {#cache}

ბილდის არტიფაქტები არ ნაწილდება გარემოებს შორის, რაც გაიძულებთ ერთი და იგივე კოდის ხელახლა აგებას. Tuist-ის კეშინგის ფუნქცია არტიფაქტებს შორს დისტანციურად აზიარებს, რათა თქვენმა გუნდმა და CI-მ მიიღონ უფრო სწრაფი ბილდები უკვე აგებული კოდის ხელახალი აგების გარეშე. იმის შესახებ, თუ როგორ მუშაობენ ლოკალური და დისტანციური ბილდის ქეშები სხვადასხვა ბილდის სისტემებში და რა არის Xcode-ის საკუთარი ქეშები, იხილეთ <.localized_link href="/references/concepts/build-cache">რა არის ბილდის ქეში?</.localized_link>. იმის გასარკვევად, თუ რატომ არის ბილდები ნელი ქეშის არჩევამდე, იხილეთ [ნელი ბილდები](https://tuist.dev/solutions/slow-builds).

## CI-ზე ატვირთვების შეზღუდვა {#restrict-uploads-to-ci}

ანგარიშის ადმინისტრატორებს შეუძლიათ დეველოპერებისთვის მხოლოდ წაკითხვის უფლება მიანიჭონ, ხოლო CI-ს ნება დართონ ქეშის არტიფაქტების ატვირთვა. გახსენით ანგარიშის **ქეშის** პარამეტრები Tuist-ში და დააყენეთ **ქეშის ატვირთვის წვდომა** მნიშვნელობაზე **მხოლოდ CI და ანგარიშის ტოკენები**. ამის შემდეგ, შესვლის სესიებით ავტორიზებულ წევრებს შეუძლიათ ქეშიდან ჩამოტვირთვა, მაგრამ ატვირთვას სჭირდება CI OIDC ავტორიზაცია ან ანგარიშის ტოკენი ქეშის ჩაწერის სკოპებით, როგორიცაა `project:cache:write` ან `ci`.

გამოიყენეთ ეს, როდესაც CI არის სანდო ქეშის მწარმოებელი და ლოკალურმა მანქანებმა მხოლოდ უნდა მოიხმარონ ქეში. პარამეტრი მოქმედებს მხოლოდ ქეშის ატვირთვის ავტორიზაციაზე.
