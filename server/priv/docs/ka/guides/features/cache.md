# კეში {#cache}

აგების არტეფაქტები არ ნაწილდება გარემოებს შორის, რაც გაიძულებთ ერთი და იგივე კოდის ხელახლა აგებას. Tuist-ის ქეშირების ფუნქცია არტეფაქტებს დისტანციურად აზიარებს, რათა თქვენმა გუნდმა და CI-მ მიიღონ სწრაფი აგებები უკვე აგებული კომპონენტების ხელახალი აგების გარეშე. იმის გასარკვევად, თუ რატომ არის აგებები ნელი, სანამ ქეშს აირჩევთ, იხილეთ [ნელი აგებები](https://tuist.dev/solutions/slow-builds).

## CI-ზე ატვირთვების შეზღუდვა {#restrict-uploads-to-ci}

ანგარიშის ადმინისტრატორებს შეუძლიათ დეველოპერებისთვის მხოლოდ წაკითხვის უფლება მიანიჭონ, ხოლო CI-ს ნება დართონ ქეშის არტეფაქტების ატვირთვა. გახსენით ანგარიშის **ქეშის** პარამეტრები Tuist-ში და დააყენეთ **ქეშის ატვირთვის წვდომა** მნიშვნელობაზე **მხოლოდ CI და ანგარიშის ტოკენები**. ამის შემდეგ, შესვლის სესიებით ავთენტიფიცირებულ წევრებს კვლავ შეეძლებათ ქეშიდან ჩამოტვირთვა, მაგრამ ატვირთვები მოითხოვს CI OIDC ავთენტიფიკაციას ან ანგარიშის ტოკენს ქეშის ჩაწერის სკოპებით, როგორიცაა `project:cache:write` ან `ci`.

გამოიყენეთ ეს, როდესაც CI არის სანდო ქეშის მწარმოებელი, ხოლო ლოკალურმა მანქანებმა მხოლოდ უნდა მოიხმარონ ქეში. პარამეტრი მოქმედებს მხოლოდ ქეშის ატვირთვის ავტორიზაციაზე.
