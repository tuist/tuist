# კეში {#cache}

ბილდის არტეფაქტები არ ნაწილდება გარემოებს შორის, რაც გაიძულებთ ერთი და იგივე კოდის ხელახლა აწყობას. Tuist-ის ქეშინგის ფუნქცია არტეფაქტებს დისტანციურად აზიარებს, რათა თქვენმა გუნდმა და CI-მ უფრო სწრაფი ბილდები მიიღონ უკვე აწყობილის ხელახალი აწყობის გარეშე. იმის შესახებ, თუ როგორ მუშაობს ლოკალური და დისტანციური ბილდის ქეშები ბილდის სისტემებში და რა არის Xcode-ის საკუთარი ქეშები, იხილეთ <.localized_link href="/references/concepts/build-cache">რა არის ბილდის ქეში?</.localized_link>. იმის გასარკვევად, თუ რატომ არის ბილდები ნელი ქეშის არჩევამდე, იხილეთ [ნელი ბილდები](https://tuist.dev/solutions/slow-builds).

გაეცანით ქეშის სამუშაო პროცესს, რომელიც შეესაბამება თქვენს პროექტს ან განლაგების მოდელს:

## CI-ზე ატვირთვების შეზღუდვა {#restrict-uploads-to-ci}

ანგარიშის ადმინისტრატორებს შეუძლიათ დეველოპერებისთვის მხოლოდ წაკითხვის უფლება მიანიჭონ, ხოლო CI-ს ნება დართონ ქეშის არტეფაქტების ატვირთვა. გახსენით ანგარიშის **ქეშის** პარამეტრები Tuist-ში და დააყენეთ **ქეშის ატვირთვის წვდომა** მნიშვნელობაზე **მხოლოდ CI და ანგარიშის ტოკენები**. ამის შემდეგ, შესვლის სესიებით ავთენტიკირებულ წევრებს კვლავ შეეძლებათ ქეშიდან ჩამოტვირთვა, მაგრამ ატვირთვები მოითხოვს CI OIDC ავთენტიკაციას ან ანგარიშის ტოკენს ქეშის ჩაწერის სკოპებით, როგორიცაა `project:cache:write` ან `ci`.

გამოიყენეთ ეს, როდესაც CI არის სანდო ქეშის მწარმოებელი და ლოკალურმა მანქანებმა მხოლოდ უნდა მოიხმარონ ქეში. პარამეტრი მოქმედებს მხოლოდ ქეშის ატვირთვის ავტორიზაციაზე.
