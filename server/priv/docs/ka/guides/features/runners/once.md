# Once-ის დისტანციური შესრულება {#once-remote-execution}

გაზიარებული ქეში თავს არიდებს იმ სამუშაოს ხელახლა შესრულებას, რომელიც სხვა მანქანამ უკვე დაასრულა. დისტანციური შესრულება ასევე გადაიტანს შესაბამის ქეშ-გამოტოვებებს თქვენი კომპიუტერიდან: Once გრაფის ბრძანების მოქმედებებს ანაწილებს Tuist-ის ერთჯერად Linux-ის ვორკერებზე და იღებს მათ შედეგებს იმავე პროექტის ქეშის საშუალებით.

> [!NOTE]
> დისტანციური შესრულება ამჟამად მხოლოდ მიწვევითაა ხელმისაწვდომი. [დაგვიკავშირდით](mailto:contact@tuist.dev) თქვენი ანგარიშისთვის წვდომის მოსათხოვნად.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - Tuist-ის ანგარიში ჩართული დისტანციური შესრულებით და ხელმისაწვდომი შესრულების ტევადობით.
> - Once-ის ვერსია Tuist-ის დისტანციური შესრულების მხარდაჭერით.
> - თავსებადი სერვერი, რომელიც აცხადებს ვორკერის იმიჯს, ქეშის ბოლოწერტილს, კონკურენტულობას და შესრულების აბსოლუტურ დირექტორიას. სერვერები, რომლებიც გამოტოვებენ დირექტორიას, არ არიან თავსებადი მიმდინარე Once-ის კლიენტთან; Once ჩერდება სამუშაოს ატვირთვამდე.
> - ბრძანებები და ინსტრუმენტების ჯაჭვები, რომლებსაც შეუძლიათ გაშვება `linux/amd64`-ზე რეკლამირებულ ვორკერის იმიჯში.

ეს ასრულებს გრაფის მოქმედებებს, არა მთლიან CI-ს სამუშაოს. Once-ის კონფიგურაცია არ აყენებს GitHub-ის ან GitLab-ის სამუშაო ნაკადის ორკესტრაციას.

## მოწყობა {#setup}

დაასრულეთ <.localized_link href="/guides/get-started/once-project">Once-ით დაწყება</.localized_link>. აირჩიეთ იგივე Tuist-ის პროვაიდერი ქეშინგისა და შესრულებისთვის და დააფიქსირეთ სერვისის მიერ რეკლამირებული ვორკერის იმიჯი:

```toml
[infrastructures.tuist]
kind = "tuist"
account = "acme"
project = "app"
execution_image = "sha-REPLACE_WITH_THE_IMAGE_TAG"

[infrastructure.cache]
provider = "tuist"

[infrastructure.execution]
provider = "tuist"
```

გაიარეთ ავთენტიფიკაცია ისეთი რწმუნებით, რომელსაც შეუძლია წაიკითხოს და ჩაწეროს პროექტის ქეში, შემდეგ მოითხოვეთ დისტანციური შესრულება:

```bash
once build --remote MyTarget
```

ჩაანაცვლეთ მიზანი და იმიჯის ტეგი თქვენით. Once ამოწმებს რეკლამირებულ იმიჯს, შესრულების დირექტორიას, ქეშის დანიშნულებას და ანგარიშის ტევადობას სამუშაოს ატვირთვამდე. ქეშმა და შესრულებამ უნდა მიუთითონ იმავე პროექტზე.

## მოქმედებების მომზადება ვორკერებისთვის {#prepare-actions-for-workers}

- განაცხადეთ შეყვანები და გამომავალი მონაცემები. გამომავალი მონაცემები უნდა დარჩეს მოქმედების სამუშაო დირექტორიის ქვეშ.
- ინსტრუმენტების ამოცნობა ვორკერის იმიჯის შიგნით, არა საწყის კომპიუტერზე აბსოლუტური გზებით.
- გამოიყენეთ მოქმედებები, რომლებიც უსაფრთხოა განმეორებისთვის: ვორკერის შეცდომა ან სერვისის გადატვირთვა შეიძლება გამოიწვიოს კიდევ ერთი შესრულება.
- დაიცავით დროის ამოწურვა სერვისის ათწუთიანი მოქმედების ლიმიტის ფარგლებში. არა მხარდაჭერილი მოთხოვნები, მათ შორის ქსელის უარყოფა, მარცხდება, ნაცვლად იმისა, რომ ჩუმად გაეშვას ადგილობრივად.

Once პატივს სცემს ანგარიშის რეკლამირებულ მოქმედების კონკურენტულობას და ელოდება, როდესაც სერვისის რიგი სავსეა. იმიჯის ცვლილება ყოფს ბილდის კონფიგურაციას და ქეშირებულ შედეგებს, რაც ხელს უშლის თავსებად ვორკერის იმიჯებს შორის ხელახლა გამოყენებას.

## დისტანციური შესრულების ინსპექტირება {#inspect-remote-execution}

პროექტის გვერდით პანელს აქვს **დისტანციური შესრულება** გვერდი, მაგრამ Once-ის გაშვების ტელემეტრია ჯერჯერობით არ განასხვავებს დისტანციურ შესრულებას ადგილობრივი მოქმედებებისგან. გვერდი ხსნის ამ სხვაობას და ბმულს აკეთებს **ბილდის გაშვებებზე** ჩაწერილი მოქმედების დეტალებისთვის; ის არ გამოიტანს დასკვნას დისტანციური აქტივობის შესახებ ვორკერის ზოლებიდან ან არ აჩვენებს ამ მოქმედებებს როგორც დისტანციურ გამოყენებას.

იხილეთ [Once-ის დისტანციური შესრულების სახელმძღვანელო](https://buildonce.dev/docs/guide/infrastructure/tuist#run-actions-on-tuist-workers) რიგში დგომის, ავთენტიფიკაციის განახლებისა და ქეშის ბოლოწერტილის გადაკეთებებისთვის. მიჰყევით <.localized_link href="/guides/features/build-insights/once">Once-ის ბილდის ინსაიტებს</.localized_link> მიღებული გაშვებების ინსპექტირებისთვის.
