# Once-ის დისტანციური შესრულება {#once-remote-execution}

გაზიარებული ქეშირება თავს არიდებს იმ სამუშაოს განმეორებას, რომელიც სხვა მანქანამ უკვე დაასრულა. დისტანციური შესრულება ასევე გადაიტანს შესაბამის ქეშის გამოტოვებებს თქვენი კომპიუტერიდან: Once გრაფის ბრძანების მოქმედებებს ანაწილებს Tuist-ის ერთჯერად Linux-ის ვორკერებზე და იღებს მათ შედეგებს იმავე პროექტის ქეშის მეშვეობით.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - Tuist-ის ანგარიში ჩართული დისტანციური შესრულებით და ხელმისაწვდომი შესრულების სიმძლავრით.
> - Once-ის ვერსია Tuist-ის დისტანციური შესრულების მხარდაჭერით.
> - თავსებადი სერვერი, რომელიც აცხადებს ვორკერის იმიჯს, ქეშის endpoint-ს, პარალელურობას და შესრულების აბსოლუტურ დირექტორიას. სერვერები, რომლებიც ტოვებენ დირექტორიას, არ არიან თავსებადები მიმდინარე Once-ის კლიენტთან; Once ჩერდება სამუშაოს ატვირთვამდე.
> - ბრძანებები და ინსტრუმენტთა ჯაჭვები, რომლებსაც შეუძლიათ გაშვება `linux/amd64`-ზე რეკლამირებულ ვორკერის იმიჯში.

ეს ასრულებს გრაფის მოქმედებებს და არა მთლიან CI-ს საქმეს. Once-ის კონფიგურაცია არ აყენებს GitHub-ის ან GitLab-ის სამუშაო ნაკადების ორკესტრაციას.

## მოწყობა {#setup}

დაასრულეთ <.localized_link href="/guides/get-started/once-project">Once-ით დაწყება</.localized_link>. აირჩიეთ იგივე Tuist-ის პროვაიდერი ქეშირებისა და შესრულებისთვის და დააფიქსირეთ სერვისის მიერ რეკლამირებული ვორკერის იმიჯი:

```toml
[infrastructures.tuist]
kind = "tuist"
account = "acme"
project = "app"
execution_image = "sha-REPLACE_WITH_THE_IMAGE_TAG"

[infrastructure.cache]
provider = "tuist"

[infrastructure.execution]
provider = "tuist"
```

გაიარეთ ავთენტიფიკაცია ისეთი სერთიფიკატებით, რომლებსაც შეუძლიათ წაიკითხონ და ჩაწერონ პროექტის ქეში, შემდეგ მოითხოვეთ დისტანციური შესრულება:

```bash
once build --remote MyTarget
```

ჩაანაცვლეთ სამიზნე და იმიჯის ტეგი თქვენით. Once ამოწმებს რეკლამირებულ იმიჯს, შესრულების დირექტორიას, ქეშის დანიშნულების ადგილს და ანგარიშის სიმძლავრეს სამუშაოს ატვირთვამდე. ქეში და შესრულება უნდა მიუთითებდნენ ერთსა და იმავე პროექტზე.

## მოქმედებების მომზადება ვორკერებისთვის {#prepare-actions-for-workers}

- განაცხადეთ შეყვანები და გამოსავალი. გამოსავალი უნდა დარჩეს მოქმედების სამუშაო დირექტორიის ქვემოთ.
- გადაწყვიტეთ ინსტრუმენტები ვორკერის იმიჯის შიგნით, არა საწყის კომპიუტერზე აბსოლუტური გზებით.
- გამოიყენეთ მოქმედებები, რომლებიც უსაფრთხოა განმეორებისთვის: ვორკერის შეცდომა ან სერვისის გადატვირთვა შეიძლება გამოიწვიოს კიდევ ერთი შესრულება.
- შეინარჩუნეთ ტაიმაუთები სერვისის ათწუთიანი მოქმედების ლიმიტის ფარგლებში. არამხარდაჭერილი მოთხოვნები, მათ შორის ქსელის უარყოფა, მარცხდებიან და არა ჩუმად ადგილობრივად გაშვება.

Once პატივს სცემს ანგარიშის რეკლამირებულ მოქმედების პარალელურობას და იხევს უკან, როდესაც სერვისის რიგი სავსეა. იმიჯის შეცვლა ყოფს ბილდის კონფიგურაციას და ქეშირებულ შედეგებს, რაც ხელს უშლის ხელახლა გამოყენებას არათავსებად ვორკერის იმიჯებში.

იხილეთ [Once-ის დისტანციური შესრულების სახელმძღვანელო](https://buildonce.dev/docs/guide/infrastructure/tuist#run-actions-on-tuist-workers) რიგში დაყენების, ავთენტიფიკაციის განახლებისა და ქეშ-endpoint-ის გადაკეტვისთვის. მიჰყევით <.localized_link href="/guides/features/build-insights/once">Once-ის ბილდის ანალიტიკას</.localized_link> მიღებული გაშვებების შესამოწმებლად.
