# Buildkite {#buildkite}

> [!IMPORTANT]
> **მხოლოდ მიწვევით**
>
> Tuist Runners ამჟამად მხოლოდ მიწვევითაა ხელმისაწვდომი. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [საზოგადოების Slack-ში](https://slack.tuist.dev), რათა თქვენი ანგარიშისთვის წვდომა მოითხოვოთ.

Tuist აკონტროლებს თქვენს Buildkite კლასტერში განთავსებულ თვითმასპინძელ რიგებს და იქ ნაპოვნ სამუშაოებს ფლოტზე ასრულებს. თქვენი პაიპლაინები Buildkite-ზე გრძელდება; იცვლება მხოლოდ გამოთვლითი რესურსები. ფლოტზე სამუშაოს გასაშვებად სამი ცვლილებაა საჭირო: დააკავშირეთ თქვენი კლასტერი, მიანიჭეთ რიგს Tuist-ის <.localized_link href="/guides/features/runners/profiles">პროფილის</.localized_link> სახელი და მიმართეთ ის ნაბიჯიდან.

1. **მოითხოვეთ წვდომა.** ბეტა პერიოდში Runners მხოლოდ მიწვევითაა ხელმისაწვდომი. [დაგვიკავშირდით](mailto:contact@tuist.dev) იმ ანგარიშის მითითებით, რომლის გააქტიურებაც გსურთ.
2. **დააკავშირეთ თქვენი კლასტერი.** Buildkite-ში გახსენით თქვენი კლასტერი, გადადით **Agent Tokens**-ზე და შექმენით ტოკენი; ის იწყება `bkct_`-ით. თქვენს Tuist დაფაზე გადადით **Settings → Integrations**-ზე, Buildkite-ის ბარათზე აირჩიეთ **Connect** და შეიყვანეთ თქვენი ორგანიზაციის slug და ტოკენი. ტოკენი ინახება დაშიფრული და აღარასდროს ჩანს. ორგანიზაციის შესაცვლელად ან ტოკენის როტაციისთვის შემდგომში, შეცვალეთ ველები ბარათზე და აირჩიეთ **Save changes**. Tuist კლასტერის მონიტორინგს ერთ წუთში იწყებს.
3. **მიანიჭეთ რიგს Tuist პროფილის სახელი.** ყოველი გააქტიურებული ანგარიში იწყება ორი გამოსაყენებლად მზა <.localized_link href="/guides/features/runners/profiles">პროფილით</.localized_link>, `linux` და `macos`, და სამუშაო აღიქმება, როცა მისი რიგის გასაღები ემთხვევა პროფილის ლეიბლს. შექმენით თვითმასპინძელი რიგები თქვენს კლასტერში გასაღებებით `tuist-linux` და `tuist-macos`, შემდეგ მიმართეთ ერთ-ერთს ნაბიჯიდან:

   ```yaml
   # .buildkite/pipeline.yml
   steps:
     - label: "Test"
       command: tuist test
       agents:
         queue: tuist-macos # or tuist-linux
   ```

4. **გაუშვით და დააკვირდით.** სამუშაო რიგში დგება, runner-ის მიერ აღიქმება და გადაიცემა თქვენი Tuist დაფის **Runners** სექციაში, სადაც შეგიძლიათ თვალი ადევნოთ მის ლოგებს, ნაბიჯებს და მანქანის მეტრიკებს. Runner აგზავნის ლოგს სამუშაოს შიგნიდან იმ სამუშაოსთვის შეზღუდული კრედენტიალით, ამიტომ Buildkite API ტოკენი არ არის საჭირო.

## შეჩერება და გათიშვა {#pausing-and-disconnecting}

Buildkite რიგზე დისპეტჩერიზაციის შეჩერება ხელს უშლის Tuist-ს ახალი სამუშაოების აღებაში მისგან. უკვე გაშვებულ სამუშაოებზე ეს გავლენას არ ახდენს.

კლასტერის გათიშვა Buildkite ბარათზე **Settings → Integrations**-ის ქვეშ სრულად აჩერებს Tuist-ის მონიტორინგს.

## ქეშის ტომები {#cache-volumes}

შეინახეთ Xcode-ის, მოდულის და Gradle-ის ქეშები და სხვა დირექტორიები სამუშაოებს შორის <.localized_link href="/guides/features/runners/cache-volumes">ქეშის ტომების</.localized_link> გამოყენებით. დაამატეთ ისინი checkout-ის შემდეგ და იმ ბრძანებებამდე, რომლებიც მათ იყენებენ.
