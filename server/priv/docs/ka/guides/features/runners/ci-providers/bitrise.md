# Bitrise {#bitrise}

> [!IMPORTANT]
> **მხოლოდ მოწვევით**
>
> Tuist Runners ამჟამად მხოლოდ მოწვევითაა ხელმისაწვდომი. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [საზოგადოების Slack-ში](https://slack.tuist.dev), რათა თქვენს ანგარიშზე წვდომა მოითხოვოთ.

> [!WARNING]
> **მხოლოდ კერძო რეპოზიტორიები**
>
> Tuist ენდობა ყოველ Bitrise ბილდს: ბილდები იზიარებენ თქვენი ანგარიშის ქეშს და შეუძლიათ მასში ჩაწერა. არ დააკავშიროთ პული, რომლის სამუშაო ნაკადებიც აწყობენ pull request-ებს საჯარო რეპოზიტორიის ფორკებიდან.

Tuist ემსახურება თქვენი Bitrise სამუშაო სივრცის self-hosted runner პულებს. ბილდი, რომელიც ამ პულებიდან ერთ-ერთს ირჩევს, გაეშვება Tuist მანქანაზე <.localized_link href="/guides/features/runners/profiles">პროფილის</.localized_link> მიხედვით, რომელსაც პულთან დააკავშირებთ. თქვენი სამუშაო ნაკადები, ტრიგერები და ლოგები Bitrise-ზე რჩება; იცვლება მხოლოდ მანქანები.

1. **მოითხოვეთ წვდომა.** ბეტა პერიოდში Runners მხოლოდ მოწვევითაა ხელმისაწვდომი. [დაგვიკავშირდით](mailto:contact@tuist.dev) იმ ანგარიშის მითითებით, რომლის გააქტიურებაც გსურთ.
2. **დააკავშირეთ თქვენი სამუშაო სივრცე.** Bitrise-ში გახსენით **Workspace settings → Security → Workspace API tokens** და შექმენით ტოკენი **Viewer** სამუშაო სივრცის როლით და **Tester/QA** წვდომით Bitrise CI-ზე ყველა პროექტისთვის. თქვენს Tuist დაშბორდზე გადადით **Settings → Integrations**-ზე, აირჩიეთ **Connect** Bitrise ბარათზე და ჩასვით ტოკენი. Tuist კითხულობს სამუშაო სივრცეს ტოკენიდან, ინახავს ტოკენს დაშიფრულად და მას აღარასდროს აჩვენებს.
3. **შექმენით runner პული.** Bitrise-ში გახსენით **Workspace settings → Infrastructure**, აირჩიეთ **Add Runner pool** და მიანიჭეთ სახელი იმ მანქანის მიხედვით, რომელსაც ის წარმოადგენს, მაგალითად `tuist-macos`. დააკოპირეთ პულის ტოკენი: Bitrise მას მხოლოდ ერთხელ აჩვენებს.
4. **დააკავშირეთ პული Tuist პროფილთან.** Tuist-ში Bitrise ბარათზე, **Runner pools** განყოფილებაში, აირჩიეთ პული, Tuist პროფილი, რომელზეც მისი ბილდები უნდა გაეშვას, ჩასვით პულის ტოკენი და აირჩიეთ **Add pool**. ყოველი გააქტიურებული ანგარიში იწყება ორი პროფილით: `tuist-linux` და `tuist-macos`. დაამატეთ ერთი პული ყოველი პროფილისთვის, რომლის გამოყენებაც გსურთ.
5. **აირჩიეთ პული თქვენს სამუშაო ნაკადში.** Bitrise-ის Workflow Editor-ში გახსენით **Stacks & Machines** და აირჩიეთ **Self-Hosted Runner: tuist-macos**. `bitrise.yml`-ში მიუთითეთ პულის სტეკი, რომელსაც Tuist აჩვენებს პულის სახელის ქვეშ:

   ```yaml
   meta:
     bitrise.io:
       stack: agent-pool-a0c641c0-142f-427d-a326-07f0f6c2a1be
   ```

6. **გაუშვით ბილდი.** რამდენიმე წამში Tuist მანქანა უკავშირდება პულს, იღებს ბილდს და წყვეტს კავშირს მისი დასრულების შემდეგ. ბილდი ჩანს თქვენი Tuist დაშბორდის **Runners** განყოფილებაში მანქანის მეტრიკებით და ბმულით Bitrise-ზე, სადაც მისი ლოგები რჩება.

## გამოყოფილი პულები {#dedicated-pools}

გამოიყენეთ პულები, რომლებსაც Tuist-თან აკავშირებთ, მხოლოდ Tuist-ისთვის. თუ თქვენი ერთ-ერთი მანქანაც უკავშირდება დაკავშირებულ პულს, ის ეცილება Tuist-ს ამ პულის ბილდებისთვის.

## Runner-ების ლიმიტი {#runner-limit}

ყოველი Tuist მანქანა ითვლება ერთ Bitrise runner-ად, სანამ ბილდს ასრულებს, და წყვეტს თვლას კავშირის გაწყვეტისას. თქვენი Bitrise გეგმის runner-ების ლიმიტი შესაბამისად ზღუდავს, თუ რამდენი თქვენი ბილდი შეიძლება გაეშვას Tuist-ზე ერთდროულად, თქვენი Tuist კონკურენტულობის ლიმიტთან ერთად.

## კავშირის გაწყვეტა {#disconnecting}

პულის წაშლა Bitrise ბარათიდან აჩერებს Tuist-ს იმ პულის ბილდების აღებაში. უკვე გაშვებულ ბილდებს ეს არ ეხება.

**Disconnect**-ის არჩევა Bitrise ბარათზე შლის სამუშაო სივრცეს და მის ყველა პულს.
