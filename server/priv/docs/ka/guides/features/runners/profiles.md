# პროფილები {#profiles}

**პროფილი** არის ანგარიშის დონეზე განსაზღვრული, სახელდარქმეული მანქანის კონფიგურაცია. თქვენ მიუთითებთ მას სამუშაო პროცესის `runs-on`-ში და Tuist ამუშავებს დავალებას შესაბამის გამშვებზე (runner). პროფილები ინფრასტრუქტურის არჩევანს (პლატფორმა, ზომა, Ubuntu-ის ვერსია ან Xcode-ის ვერსია) ერთ ადგილას ინახავს, ნაცვლად იმისა, რომ ის ყველა სამუშაო პროცესის ფაილში იყოს გაფანტული, და გთავაზობთ სტაბილურ ლეიბლს CI-სთვის.

```yaml
jobs:
  build:
    runs-on: tuist-macos
```

ლეიბლი არის პროფილის სახელი `tuist-` პრეფიქსით. პროფილი სახელით `macos` არის `runs-on: tuist-macos`; პროფილი სახელით `linux-large` არის `runs-on: tuist-linux-large`. შესაბამისობა არ არის დამოკიდებული ასოების რეგისტრზე.

## ნაგულისხმები პროფილები {#default-profiles}

ყველა ანგარიში, რომელიც ჩართულია Runners-ისთვის, იწყება ორი პროფილით, რათა შეძლოთ ფლოტის გამოყენება რაიმეს კონფიგურაციის გარეშე:

{{runner_default_profiles_table}}

ორივე მიუთითებს თავისი პლატფორმისთვის ნაგულისხმევ <.localized_link href="/guides/features/runners/profiles#machine-shapes">კონფიგურაციაზე</.localized_link>. ისინი **დაცულია**, ამიტომ მათი წაშლა შეუძლებელია და ლეიბლები, რომლებზეც თქვენი სამუშაო პროცესებია დამოკიდებული, ყოველთვის მუშაობს. თქვენ მაინც შეგიძლიათ შეცვალოთ მათი კონფიგურაცია ან Xcode-ის ვერსია, და შეგიძლიათ შექმნათ დამატებითი პროფილები სხვა ზომების ან Xcode-ის ვერსიებისთვის.

## მანქანის კონფიგურაციები {#machine-shapes}

გამშვებიები (Runners) ხელმისაწვდომია macOS-ზე (Apple silicon, ვირტუალიზებული Mac-ის ფლოტზე) და Linux-ზე. თითოეული პროფილი აფიქსირებს ერთ მანქანის კონფიგურაციას, `(vCPUs, memory)` წყვილს, ქვემოთ მოცემული კატალოგიდან.

### Linux {#linux}

{{runner_linux_shapes_table}}

Linux-ის პროფილები ასევე ირჩევენ **Ubuntu-ის ვერსიას**, ისევე როგორც macOS-ის პროფილები ირჩევენ Xcode-ის ვერსიას:

- **Ubuntu 24.04** (`ubuntu-24.04`), ახალი პროფილების ნაგულისხმევი ვერსია.
- **Ubuntu 22.04** (`ubuntu-22.04`), სამუშაო პროცესებისთვის, რომლებსაც ის კვლავ სჭირდებათ. GitHub-მა აღნიშნა თავისი 22.04 ჰოსტინგის იმიჯი როგორც მოძველებული და წაშლის მას 2027 წლის 17 აპრილს; დაგეგმეთ მისგან გადასვლა ამ დროისთვის.

პროფილი რჩება თქვენს მიერ არჩეულ ვერსიაზე, სანამ მას არ შეცვლით, ამიტომ უფრო ახალი ნაგულისხმევი ვერსია არ გადაიყვანს თქვენს დავალებებს სხვა OS-ზე თავისით. 24.04-ზე აგებულ ბინარებს სჭირდებათ მისი უფრო ახალი glibc (2.39) და შესაძლოა არ იმუშაონ ძველ სისტემებზე, ხოლო მისი სისტემური Python უარს ამბობს `pip install`-ზე ვირტუალური გარემოს გარეთ (PEP 668). გამშვები აყენებს `ImageOS`-ს (`ubuntu24` ან `ubuntu22`), როგორც GitHub-ის ჰოსტინგზე განთავსებული გამშვებიები, რათა setup-ის ექშენებმა აირჩიონ შესაბამისი ვერსიის ბილდები.

ყველა Linux-ის პროფილი მხარდაუჭერს <.localized_link href="/guides/features/runners#android-emulators">აპარატურულად აჩქარებულ Android ემულატორებს</.localized_link> `/dev/kvm`-ის მეშვეობით. ცალკე KVM პროფილი არ არის საჭირო.

### macOS {#macos}

{{runner_macos_shapes_table}}

უფრო დიდი macOS კონფიგურაციები მუშაობენ ფლოტში ნაკლებ მანქანაზე, ამიტომ დავალებას, რომელიც ითხოვს მას, შეიძლება დასჭირდეს უფრო მეტი დრო დასაწყებად, ვიდრე იგივე დავალებას უფრო მცირე კონფიგურაციაზე. გამოიყენეთ უფრო დიდი კონფიგურაცია, როდესაც დავალება შეზღუდულია CPU-ით, და დატოვეთ ნაგულისხმევი კონფიგურაცია ყველაფერი სხვისთვის. თუ არ ხართ დარწმუნებული, გაუშვით დავალება ორივეზე და შეადარეთ ხანგრძლივობები დაშბორდზე.

macOS-ის პროფილები ასევე აფიქსირებენ **Xcode-ის ვერსიას**. ვერსია ირჩევს გამშვების იმიჯს ამ Xcode-ით წინასწარ დაინსტალირებული, რათა დავალებები დაიწყოს ინსტრუმენტების ნაკრებით უკვე ადგილზე. იხილეთ <.localized_link href="/guides/features/runners/images">იმიჯები</.localized_link> ყველაფერი სხვისთვის, რასაც თითოეული იმიჯი შეიცავს. მხარდაჭერილი ვერსიები დღეს:

{{runner_macos_xcode_versions}}

> [!NOTE]
> კატალოგი ვითარდება, როგორც ვამატებთ აპარატურას და Xcode-ის ვერსიებს. დაშბორდის **ახალი პროფილი** ფორმა და `tuist runner profile catalog` ყოველთვის აჩვენებს კონფიგურაციებს, Xcode-ის ვერსიებს და Ubuntu-ის ვერსიებს, რომლებიც ამჟამად ხელმისაწვდომია თქვენი ანგარიშისთვის, ამიტომ მიიჩნიეთ ისინი როგორც სანდო წყარო.

macOS გამშვების სახელი აჩვენებს macOS-ის ვერსიას, რომელზეც ის მუშაობს, პროფილის Xcode-ის ვერსიას და მის კონფიგურაციას, მაგალითად `tuist-macos-26.6-xcode-27.0-8vcpu-24gb-1a2b3c4d5e6f`. სახელი ჩანს დავალების **დავალების მომზადება** ეტაპზე GitHub-ზე და დავალების დეტალებში Tuist-ის დაშბორდზე.

## პროფილის შექმნა {#creating-a-profile}

1. გახსენით თქვენი ანგარიშის დაშბორდის **გამშვებიები → პროფილები** სექცია.
2. აირჩიეთ **ახალი პროფილი**.
3. მიანიჭეთ მას სახელი, აირჩიეთ პლატფორმა და აირჩიეთ კონფიგურაცია. Linux-ისთვის, ასევე აირჩიეთ Ubuntu-ის ვერსია; macOS-ისთვის, Xcode-ის ვერსია.
4. შეინახეთ, შემდეგ მიუთითეთ ის სამუშაო პროცესიდან `runs-on: tuist-<name>`-ით.

თქვენ ასევე შეგიძლიათ მართოთ პროფილები კომანდის ხაზიდან. პროფილების შექმნა, ცვლილება და წაშლა მოითხოვს ანგარიშის ადმინისტრირებას, როგორც დაშბორდზე, ან ანგარიშის ტოკენს `account:runners:write` სკოუპით:

```bash
tuist runner profile catalog
tuist runner profile create linux-large --platform linux --vcpus 8 --memory-gb 32
tuist runner profile update linux-large --vcpus 16 --memory-gb 32
tuist runner profile delete linux-large --yes
```

აგენტებს შეუძლიათ იგივეს გაკეთება <.localized_link href="/guides/features/agentic-coding/mcp">MCP სერვერის</.localized_link> მეშვეობით.

მაგალითად, პროფილი სახელით `linux-large` 8 vCPU / 32 GB კონფიგურაციაზე:

```yaml
jobs:
  integration-tests:
    runs-on: tuist-linux-large
```

ან macOS პროფილი სახელით `xcode-26-4` მიბმული Xcode `26.4.1`-ზე, რათა დავალებამ შეძლოს მუშაობა უფრო ძველ ინსტრუმენტების ნაკრებზე, როდესაც თქვენი ნაგულისხმევი `macos` პროფილი ადევნებს თვალს უახლესს:

```yaml
jobs:
  build-legacy:
    runs-on: tuist-xcode-26-4
```
