# პროფილები {#profiles}

**პროფილი** არის ანგარიშის ფარგლებში განსაზღვრული, სახელდარქმეული მანქანის კონფიგურაცია. თქვენ მას მიუთითებთ სამუშაო ნაკადის `runs-on`-ში და Tuist ამუშავებს დავალებას შესაბამის გამშვებზე (runner). პროფილები ინფრასტრუქტურის არჩევანს (პლატფორმა, ზომა, Ubuntu-ის ვერსია ან Xcode-ის ვერსია) ერთ ადგილას ინახავენ, ნაცვლად იმისა, რომ ისინი ყველა სამუშაო ნაკადის ფაილში იყოს გაფანტული, და გთავაზობენ სტაბილურ ლეიბლს CI-სთვის.

```yaml
jobs:
  build:
    runs-on: tuist-macos
```

ლეიბლი არის პროფილის სახელი `tuist-` პრეფიქსით. პროფილი სახელით `macos` არის `runs-on: tuist-macos`; პროფილი სახელით `linux-large` არის `runs-on: tuist-linux-large`. შედარება არ არის დამოკიდებული რეგისტრზე.

## ნაგულისხმები პროფილები {#default-profiles}

ყველა ანგარიში, რომლისთვისაც ჩართულია Runners, იწყება ორი პროფილით, რათა შეძლოთ ფლოტის გამოყენება ყოველგვარი კონფიგურაციის გარეშე:

{{runner_default_profiles_table}}

ორივე მიუთითებს თავისი პლატფორმის ნაგულისხმევ <.localized_link href="/guides/features/runners/profiles#machine-shapes">კონფიგურაციაზე</.localized_link>. ისინი არიან **დაცული**, ამიტომ მათი წაშლა შეუძლებელია და ლეიბლები, რომლებზეც თქვენი სამუშაო ნაკადებია დამოკიდებული, ყოველთვის წარმატებით ამოიცნობა. თქვენ მაინც შეგიძლიათ შეცვალოთ მათი კონფიგურაცია ან Xcode-ის ვერსია, ასევე შეგიძლიათ შექმნათ დამატებითი პროფილები სხვა ზომების ან Xcode-ის ვერსიებისთვის.

## მანქანის კონფიგურაციები {#machine-shapes}

გამშვები ხელმისაწვდომია macOS-ზე (Apple silicon, ვირტუალიზებული Mac-ების ფლოტზე) და Linux-ზე. თითოეული პროფილი აფიქსირებს ერთ მანქანის კონფიგურაციას, `(vCPUs, memory)` წყვილს, ქვემოთ მოცემული კატალოგიდან.

### Linux {#linux}

{{runner_linux_shapes_table}}

Linux-ის პროფილები ასევე ირჩევენ **Ubuntu-ის ვერსიას**, ისევე როგორც macOS-ის პროფილები ირჩევენ Xcode-ის ვერსიას:

- **Ubuntu 24.04** (`ubuntu-24.04`), ახალი პროფილების ნაგულისხმები ვერსია.
- **Ubuntu 22.04** (`ubuntu-22.04`), იმ სამუშაო ნაკადებისთვის, რომლებსაც ის ჯერ კიდევ სჭირდებათ. GitHub-მა გააუქმა თავისი 22.04 ჰოსტინგის იმიჯი და წაშლის მას 2027 წლის 17 აპრილს; დაგეგმეთ მისგან გადასვლა ამ ვადამდე.

პროფილი რჩება თქვენს მიერ არჩეულ ვერსიაზე, სანამ მას არ შეცვლით, ამიტომ უფრო ახალი ნაგულისხმები ვერსია არ გადაიყვანს თქვენს დავალებებს სხვა ოპერაციულ სისტემაზე. 24.04-ზე აგებული ბინარული ფაილები საჭიროებენ მის უფრო ახალ glibc-ს (2.39) და შეიძლება არ იმუშაონ ძველ სისტემებზე, ხოლო მისი სისტემური Python უარს ამბობს `pip install`-ზე ვირტუალური გარემოს გარეთ (PEP 668). გამშვები აყენებს `ImageOS`-ს (`ubuntu24` ან `ubuntu22`), როგორც ეს GitHub-ის ჰოსტინგზე განთავსებულ გამშვებებს აქვთ, რათა setup-ის ექშენებმა აირჩიონ შესაბამისი ვერსიის ბილდები.

ყველა Linux-ის პროფილი მხარდაჭერს <.localized_link href="/guides/features/runners#android-emulators">აპარატურულად აჩქარებულ Android ემულატორებს</.localized_link> `/dev/kvm`-ის მეშვეობით. ცალკე KVM პროფილი არ არის საჭირო.

### macOS {#macos}

{{runner_macos_shapes_table}}

უფრო დიდი macOS-ის კონფიგურაციები ნაკლებ მანქანაზე მუშაობენ ფლოტში, ამიტომ დავალებას, რომელიც მათ ითხოვს, შეიძლება უფრო დიდი ლოდინი დასჭირდეს დაწყებამდე, ვიდრე იმავე დავალებას უფრო მცირე კონფიგურაციაზე. გამოიყენეთ უფრო დიდი კონფიგურაცია, როდესაც დავალება CPU-ით არის შეზღუდული, და დატოვეთ ნაგულისხმები კონფიგურაცია ყველაფერი სხვისთვის. თუ არ ხართ დარწმუნებული, გაუშვით დავალება ორივეზე და შეადარეთ ხანგრძლივობები დაშბორდზე.

macOS-ის პროფილები ასევე აფიქსირებენ **Xcode-ის ვერსიას**. ვერსია ირჩევს გამშვების იმიჯს წინასწარ ინსტალირებული Xcode-ით, ამიტომ დავალებები იწყება უკვე არსებული ინსტრუმენტების ნაკრებით. იხილეთ <.localized_link href="/guides/features/runners/images">იმიჯები</.localized_link> იმის სანახავად, რას შეიცავს თითოეული იმიჯი. მხარდაჭერილი ვერსიები დღეს:

{{runner_macos_xcode_versions}}

> [!NOTE]
> კატალოგი ვითარდება, როგორც კი ვამატებთ ახალ აპარატურას და Xcode-ის ვერსიებს. დაშბორდზე არსებული **ახალი პროფილი** ფორმა და `tuist runner profile catalog` ყოველთვის აჩვენებენ კონფიგურაციებს, Xcode-ის ვერსიებს და Ubuntu-ის ვერსიებს, რომლებიც ამჟამად ხელმისაწვდომია თქვენი ანგარიშისთვის, ამიტომ მიიჩნიეთ ისინი სანდო წყაროდ.

macOS გამშვების სახელი აჩვენებს macOS-ის ვერსიას, რომელზეც ის მუშაობს, პროფილის Xcode-ის ვერსიას და მის კონფიგურაციას, მაგალითად `tuist-macos-26.6-xcode-27.0-8vcpu-24gb-1a2b3c4d5e6f`. სახელი ჩანს დავალების **Set up job** ეტაპზე GitHub-ზე და დავალების დეტალებში Tuist-ის დაშბორდზე.

## პროფილის შექმნა {#creating-a-profile}

1. გახსენით თქვენი ანგარიშის დაშბორდის **Runners → Profiles** სექცია.
2. აირჩიეთ **ახალი პროფილი**.
3. მიანიჭეთ სახელი, აირჩიეთ პლატფორმა და შეარჩიეთ კონფიგურაცია. Linux-ისთვის ასევე აირჩიეთ Ubuntu-ის ვერსია; macOS-ისთვის — Xcode-ის ვერსია.
4. შეინახეთ, შემდეგ მიუთითეთ ის სამუშაო ნაკადში `runs-on: tuist-<name>`-ის გამოყენებით.

პროფილების მართვა შესაძლებელია საბრძანებო სტრიქონიდანაც. პროფილების შექმნა, შეცვლა და წაშლა მოითხოვს ანგარიშის ადმინისტრირებას, როგორც დაშბორდზე, ან ანგარიშის ტოკენს `account:runners:write` წვდომით:

```bash
tuist runner profile catalog
tuist runner profile create linux-large --platform linux --vcpus 8 --memory-gb 32
tuist runner profile update linux-large --vcpus 16 --memory-gb 32
tuist runner profile delete linux-large --yes
```

აგენტებს შეუძლიათ იგივეს გაკეთება <.localized_link href="/guides/features/agentic-coding/mcp">MCP სერვერის</.localized_link> მეშვეობით.

მაგალითად, პროფილი სახელით `linux-large` 8 vCPU / 32 GB კონფიგურაციაზე:

```yaml
jobs:
  integration-tests:
    runs-on: tuist-linux-large
```

ან macOS პროფილი სახელით `xcode-26-4`, მიბმული Xcode `26.4.1`-ზე, რათა დავალებამ შეძლოს მუშაობა უფრო ძველ ინსტრუმენტების ნაკრებზე, მაშინ როცა თქვენი ნაგულისხმევი `macos` პროფილი მიჰყვება უახლეს ვერსიას:

```yaml
jobs:
  build-legacy:
    runs-on: tuist-xcode-26-4
```
