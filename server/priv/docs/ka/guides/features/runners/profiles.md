# პროფილები {#profiles}

**პროფილი** არის ანგარიშის ფარგლებში განსაზღვრული, სახელით მონიშნული მანქანის კონფიგურაცია. თქვენ მას მიუთითებთ სამუშაო ნაკადის `runs-on`-ში და Tuist ჯობს შესაბამის რანერზე გაგზავნის. პროფილები ინფრასტრუქტურის არჩევანს (პლატფორმა, ზომა, Ubuntu-ის ვერსია ან Xcode-ის ვერსია) ერთ ადგილას ინახავს, ნაცვლად იმისა, რომ ის ყველა სამუშაო ნაკადის ფაილში იყოს გაფანტული, და გთავაზობთ სტაბილურ ლეიბლს CI-ისთვის.

```yaml
jobs:
  build:
    runs-on: tuist-macos
```

ლეიბლი არის პროფილის სახელი `tuist-` პრეფიქსით. პროფილი სახელით `macos` არის `runs-on: tuist-macos`; პროფილი სახელით `linux-large` არის `runs-on: tuist-linux-large`. შესაბამისობა არ არის დამოკიდებული ასოების რეგისტრზე.

## ნაგულისხმები პროფილები {#default-profiles}

ყველა ანგარიში, რომელზეც ჩართულია Runners, იწყება ორი პროფილით, რათა შეძლოთ ფლოტის გამოყენება ნებისმიერი კონფიგურაციის გარეშე:

{{runner_default_profiles_table}}

ორივე მიუთითებს თავისი პლატფორმის ნაგულისხმევ <.localized_link href="/guides/features/runners/profiles#machine-shapes">კონფიგურაციაზე</.localized_link>. ისინი **დაცულია**, ამიტომ მათი წაშლა შეუძლებელია და ლეიბლები, რომლებზეც თქვენი სამუშაო ნაკადებია დამოკიდებული, ყოველთვის ამოიცნობა. თქვენ მაინც შეგიძლიათ შეცვალოთ მათი კონფიგურაცია ან Xcode-ის ვერსია, ასევე შეგიძლიათ შექმნათ დამატებითი პროფილები სხვა ზომების ან Xcode-ის ვერსიებისთვის.

## მანქანის კონფიგურაციები {#machine-shapes}

რანერები ხელმისაწვდომია macOS-ზე (Apple silicon, ვირტუალიზებული Mac-ების ფლოტზე) და Linux-ზე. თითოეული პროფილი აფიქსირებს ერთ მანქანის კონფიგურაციას, `(vCPUs, memory)` წყვილს, ქვემოთ მოცემული კატალოგიდან.

### Linux {#linux}

{{runner_linux_shapes_table}}

Linux-ის პროფილები ასევე ირჩევენ **Ubuntu-ის ვერსიას**, ისევე როგორც macOS-ის პროფილები ირჩევენ Xcode-ის ვერსიას:

- **Ubuntu 24.04** (`ubuntu-24.04`), ახალი პროფილების ნაგულისხმევი ვერსია.
- **Ubuntu 22.04** (`ubuntu-22.04`), იმ სამუშაო ნაკადებისთვის, რომლებსაც ის ჯერ კიდევ სჭირდებათ. GitHub-მა გააუქმა თავისი 22.04 ჰოსტინგის გამოსახულება და წაშლის მას 2027 წლის 17 აპრილს; დაგეგმეთ მისგან გადასვლა ამ დროისთვის.

პროფილი რჩება თქვენს მიერ არჩეულ ვერსიაზე მანამ, სანამ მას არ შეცვლით, ამიტომ უფრო ახალი ნაგულისხმევი ვერსია არ გადაიტანს თქვენს ჯობებს სხვა OS-ზე. 24.04-ზე აგებული ბინარები საჭიროებენ მის უფრო ახალ glibc-ს (2.39) და შესაძლოა არ იმუშაონ ძველ სისტემებზე, ხოლო მისი სისტემური Python უარს ამბობს `pip install`-ზე ვირტუალური გარემოს გარეთ (PEP 668). რანერი აყენებს `ImageOS`-ს (`ubuntu24` ან `ubuntu22`), როგორც ეს GitHub-ის ჰოსტინგის რანერები აკეთებენ, რათა setup-ის ექშენებმა აირჩიონ შესაბამისი ვერსიის ბილდები.

ყველა Linux-ის პროფილი მხარდაჭერს <.localized_link href="/guides/features/runners#android-emulators">აპარატურულად აჩქარებულ Android ემულატორებს</.localized_link> `/dev/kvm`-ის მეშვეობით. ცალკე KVM პროფილი არ არის საჭირო.

### macOS {#macos}

{{runner_macos_shapes_table}}

უფრო დიდი macOS-ის კონფიგურაციები ნაკლებ მანქანაზე მუშაობენ ფლოტში, ამიტომ ჯობას, რომელიც მათ ითხოვს, შეიძლება უფრო დიდი ლოდინი ჰქონდეს დაწყებამდე, ვიდრე იმავე ჯობას უფრო მცირე კონფიგურაციაზე. გამოიყენეთ უფრო დიდი კონფიგურაცია, როდესაც ჯობა CPU-ით არის შეზღუდული, და დატოვეთ ნაგულისხმევი კონფიგურაცია ყველა სხვა შემთხვევისთვის. თუ არ ხართ დარწმუნებული, გაუშვით ჯობა ორივეზე და შეადარეთ ხანგრძლივობები დაშბორდზე.

macOS-ის პროფილები ასევე აფიქსირებენ **Xcode-ის ვერსიას**. ვერსია ირჩევს რანერის გამოსახულებას წინასწარ დაინსტალირებული Xcode-ით, რათა ჯობები დაიწყოს უკვე არსებული ინსტრუმენტების ნაკრებით. იხილეთ <.localized_link href="/guides/features/runners/images">გამოსახულებები</.localized_link> ყველა სხვა კომპონენტისთვის, რომელიც თითოეულ გამოსახულებას შეიცავს. მხარდაჭერილი ვერსიები დღეს:

{{runner_macos_xcode_versions}}

> [!NOTE]
> კატალოგი ვითარდება, როგორც ვამატებთ ახალ აღჭურვილობას და Xcode-ის ვერსიებს. დაშბორდის **ახალი პროფილი** ფორმა და `tuist runner profile catalog` ყოველთვის აჩვენებს კონფიგურაციებს, Xcode-ის ვერსიებს და Ubuntu-ის ვერსიებს, რომლებიც ამჟამად ხელმისაწვდომია თქვენს ანგარიშზე, ამიტომ მიიჩნიეთ ისინი ჭეშმარიტ წყაროდ.

macOS რანერის სახელი აჩვენებს macOS-ის ვერსიას, რომელზეც ის მუშაობს, პროფილის Xcode-ის ვერსიას და მის კონფიგურაციას, მაგალითად `tuist-macos-26.6-xcode-27.0-8vcpu-24gb-1a2b3c4d5e6f`. სახელი ჩანს ჯობის **ჯობის დაყენება** ეტაპზე GitHub-ზე და ჯობის დეტალებში Tuist-ის დაშბორდზე.

## პროფილის შექმნა {#creating-a-profile}

1. გახსენით თქვენი ანგარიშის დაშბორდის **რანერები → პროფილები** სექცია.
2. აირჩიეთ **ახალი პროფილი**.
3. მიეცით სახელი, აირჩიეთ პლატფორმა და აირჩიეთ კონფიგურაცია. Linux-ისთვის ასევე აირჩიეთ Ubuntu-ის ვერსია; macOS-ისთვის — Xcode-ის ვერსია.
4. შეინახეთ, შემდეგ მიუთითეთ ის სამუშაო ნაკადიდან `runs-on: tuist-<name>`-ით.

პროფილების მართვა ასევე შეგიძლიათ ბრძანების სტრიქონიდან. პროფილების შექმნა, შეცვლა და წაშლა მოითხოვს ანგარიშის ადმინისტრაციას, როგორც დაშბორდში, ან ანგარიშის ტოკენს `account:runners:write` სკოუპით:

```bash
tuist runner profile catalog
tuist runner profile create linux-large --platform linux --vcpus 8 --memory-gb 32
tuist runner profile update linux-large --vcpus 16 --memory-gb 32
tuist runner profile delete linux-large --yes
```

აგენტებს შეუძლიათ იგივეს გაკეთება <.localized_link href="/guides/features/agentic-coding/mcp">MCP სერვერის</.localized_link> მეშვეობით.

მაგალითად, პროფილი სახელით `linux-large` 8 vCPU / 32 GB კონფიგურაციაზე:

```yaml
jobs:
  integration-tests:
    runs-on: tuist-linux-large
```

ან macOS პროფილი სახელით `xcode-26-4` მიბმული Xcode `26.4.1`-ზე, რათა ჯობამ შეძლოს მუშაობა უფრო ძველ ინსტრუმენტების ნაკრებზე, მაშინ როცა თქვენი ნაგულისხმევი `macos` პროფილი ადევნებს თვალს უახლეს ვერსიას:

```yaml
jobs:
  build-legacy:
    runs-on: tuist-xcode-26-4
```
