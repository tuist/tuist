# გამოსახულებები {#images}

Tuist Runners-ის ყოველი ამოცანა იწყება ახალ ვირტუალურ მანქანაში, რომელიც ჩაიტვირთება გამშვები გამოსახულებიდან. თქვენი <.localized_link href="/guides/features/runners/profiles">პროფილი</.localized_link> ირჩევს გამოსახულებას: პლატფორმას, Xcode-ის ვერსიას macOS-ზე და Ubuntu-ის გამოშვებას Linux-ზე. VM იშლება ამოცანის დასრულებისთანავე, ამიტომ ნებისმიერი რამ, რასაც ამოცანა აყენებს, ქრება შემდეგი ამოცანისთვის.

გამოსახულებები მიჰყვება GitHub-ზე განთავსებულ გამშვებებს იმ ასპექტებში, რომლებიც მნიშვნელოვანია სამუშაო პროცესებისთვის: იგივე მომხმარებელი, საწყისი და სამუშაო სივრცის გზები, `ImageOS`, პაროლის გარეშე `sudo` და ინსტრუმენტები, რომლებსაც iOS, macOS და Linux სამუშაო პროცესების უმეტესობა ელის. ისინი განზრახ უფრო მცირეა, ვიდრე GitHub-ის, ამიტომ განსხვავებები ჩამოთვლილია თითოეული პლატფორმისთვის ქვემოთ.

## გამოსახულების არჩევა {#choosing-an-image}

- **Xcode, Apple SDK-ები ან სიმულატორები:** macOS პროფილი, მიბმული Xcode-ის იმ ვერსიაზე, რომლითაც თქვენი პროექტი კომპილირდება.
- **Docker, Android ბილდები და ემულატორები, ან სხვა Linux ინსტრუმენტები:** Linux პროფილი Ubuntu 24.04-ზე.
- **დამოკიდებულება, რომელიც ჯერ არ უჭერს მხარს Ubuntu 24.04-ს:** Linux პროფილი Ubuntu 22.04-ზე.

macOS-ზე თქვენ ირჩევთ Xcode-ს, არა გამოსახულებას: Xcode-ის თითოეული ვერსია არის საკუთარი გამოსახულება და პროფილი, მიბმული `26.4.1`-ზე, ყოველთვის გაეშვება გამოსახულებაზე, აგებული Xcode 26.4.1-ით. ორი Xcode ვერსიის გასაშვებად, შექმენით პროფილი თითოეულისთვის.

## macOS {#macos}

macOS გამშვებები არის Apple silicon (arm64) ვირტუალური მანქანები, რომლებიც მუშაობენ **macOS 26 Tahoe**-ზე ან **macOS 27 Golden Gate**-ზე, იმის მიხედვით, თუ როგორ არის სახელდებული პროფილის **ოპერაციული სისტემა**. პროფილები, შექმნილი არჩევანის არსებობამდე, მუშაობენ Tahoe-ზე. თითოეული Xcode აგებულია ცალკე თითოეული macOS გამოშვებისთვის, ამიტომ Xcode-ის ვერსიები, რომელთა არჩევაც პროფილს შეუძლია, დამოკიდებულია მის ოპერაციულ სისტემაზე. გამშვების სახელი შეიცავს macOS-ის ზუსტ ვერსიას, მაგალითად `tuist-macos-26.6-xcode-27.0-8vcpu-24gb-…`, და ჩანს ამოცანის **ამოცანის მომზადება** ეტაპზე.

### Xcode {#xcode}

თითოეული გამოსახულება შეიცავს **ზუსტად ერთ Xcode-ს**, რომელიც არჩეულია `xcode-select`-ით, ამიტომ `xcodebuild` და `xcrun` იყენებენ მას მომზადების ეტაპის გარეშე. ეს არის მთავარი განსხვავება GitHub-ზე განთავსებული გამოსახულებებისგან, რომლებიც შეიცავენ რამდენიმე Xcode ვერსიას, რათა ამოცანის დროს გადაერთონ მათ შორის. ხელმისაწვდომი ვერსიები:

{{runner_macos_xcode_versions}}

- **გზა.** Xcode მდებარეობს `/Applications/Xcode_<version>.app`-ზე. პატჩის კომპონენტის მქონე ვერსიისთვის, `/Applications/Xcode_<major>.<minor>.app` მიუთითებს იმავე ბანდლზე, ამიტომ `Xcode_26.4.app` გადაიჭრება როგორც `Xcode_26.4.1.app`. სამუშაო პროცესები, რომლებიც აკოდირებენ GitHub-ის სტილის გზას ან ურეკავენ `xcode-select -s`-ს მისით, განაგრძობენ მუშაობას.
- **სიმულატორები.** iOS, tvOS, watchOS და visionOS სიმულატორის გარემოები, რომლებიც მოყვება ამ Xcode-ს, ჩამოტვირთულია გამოსახულებაში, ამიტომ პირველ `xcodebuild test`-ს არ სჭირდება მათი ჩამოტვირთვა.
- **Metal ინსტრუმენტთა ჯაჭვი.** Xcode 26-დან, Metal კომპილატორი არ არის ჩართული Xcode-ში და უნდა ჩამოიტვირთოს ცალკე. ყოველი გამოსახულება შეიცავს Metal ინსტრუმენტთა ჯაჭვს, რომელიც შეესაბამება მის Xcode-ს, დაყენებული იმ მომხმარებლისთვის, რომლის სახელითაც ამოცანები მუშაობენ, ამიტომ `xcrun metal` და პროექტები `.metal` წყაროებით კომპილირდებიან `xcodebuild -downloadComponent MetalToolchain`-ის გაშვების გარეშე.
- **ბეტა ვერსიები.** ბეტა პროფილები (მაგალითად `27.3-beta`) მიჰყვებიან ამ გამოშვების უახლეს ბეტა ვერსიას. როდესაც Apple გამოუშვებს ახალ ბეტას, გამოსახულება თავიდან აიგება და პროფილი გადავა მასზე თქვენი მხრიდან ცვლილების გარეშე.

### წინასწარ დაყენებული პროგრამული უზრუნველყოფა {#macos-software}

- **Apple ინსტრუმენტები:** Xcode (თითოეულ გამოსახულებაზე ერთი), სიმულატორის გარემოები, Metal ინსტრუმენტთა ჯაჭვი, `xcodes`, `xcbeautify`
- **Swift და iOS ინსტრუმენტები:** SwiftLint, SwiftFormat, SwiftGen, LicensePlist, Mint, Carthage, CocoaPods, fastlane
- **მოწყობილობები:** `libimobiledevice`, `ideviceinstaller`, `ios-deploy`
- **ენები და გარემოები:** Ruby `rbenv`-ის მეშვეობით (2.7 და ორი უახლესი 3.x გამოშვება, უახლესი როგორც ნაგულისხმევი) Bundler-თან ერთად, Node.js 24 npm, Yarn და pnpm-თან ერთად, Go, Java 21 (Temurin, დაყენებული როგორც `JAVA_HOME`)
- **პაკეტების და ვერსიების მენეჯერები:** Homebrew, mise
- **ვერსიების კონტროლი:** Git, Git LFS, Git Credential Manager, GitHub CLI (`gh`)
- **სერვისული პროგრამები:** `jq`, `yq`, `curl`, `wget`, `zip`/`unzip`, CMake, GCC, AWS CLI
- **CI აგენტები:** GitHub Actions გამშვები, Buildkite აგენტი, Bitrise აგენტი და CLI, GitLab ამოცანის შემსრულებელი
- **სხვა:** Rosetta 2, `safaridriver` ჩართული

ინსტრუმენტების ვერსიები მოდის Homebrew-დან გამოსახულების აგებისას და გამოსახულებები რეგულარულად თავიდან აიგება. გამშვებზე ზუსტი ვერსიის სანახავად, დაბეჭდეთ ის ეტაპზე, მაგალითად `swiftlint version` ან `xcodebuild -version`.

### გარემო {#macos-environment}

- **მომხმარებელი და გზები.** ამოცანები მუშაობენ `runner`-ის სახელით, საწყისი დირექტორიით `/Users/runner` და სამუშაო სივრცით `/Users/runner/work`, იგივე გზებით, რაც GitHub-ზე განთავსებულ გამშვებებზე, ამიტომ მოქმედებები, რომლებიც აკოდირებენ მათ, მუშაობენ.
- **`sudo`.** პაროლის გარეშე. VM ეკუთვნის მხოლოდ თქვენს ამოცანას.
- **Homebrew.** პრეფიქსი (`/opt/homebrew`) ეკუთვნის `runner`-ს, ამიტომ `brew install <formula>` მუშაობს `sudo`-ის გარეშე. `HOMEBREW_NO_AUTO_UPDATE` დაყენებულია.
- **გარსი.** ეტაპები მუშაობენ შესვლის გარსში, ამიტომ Homebrew, `rbenv` და Node.js არიან `PATH`-ზე. `LANG` არის `en_US.UTF-8`.
- **`ImageOS`** არის `macos26`, როგორც GitHub-ზე განთავსებულ გამშვებებზე, მომზადების მოქმედებებისთვის, რომლებიც ირჩევენ წინასწარ აგებულ ბინარებს მის მიხედვით.
- **სერტიფიკატები.** Apple-ის WWDR (G3) და Developer ID (G2) შუალედური სერტიფიკატები არიან სისტემის ნდობის საცავში ხელმოწერისა და ნოტარიზაციისთვის.
- **კონფიდენციალურობის ნებართვები.** ორი macOS კონფიდენციალურობის დამტკიცება წინასწარ არის გაცემული, როგორც GitHub-ზე განთავსებულ გამოსახულებებზე: Finder-ის სკრიპტირება Apple Events-ის მეშვეობით, რაც სჭირდება `create-dmg`-ს და `osascript`-ს, და iOS სიმულატორის წვდომა მიკროფონთან, რაც სჭირდება აპლიკაციებს, რომლებიც იწერენ აუდიოს UI ტესტებში. ნებართვები სიმულატორის შიგნით, როგორიცაა `simctl privacy`, რჩება თქვენი ამოცანის პასუხისმგებლობად.
- **დისკი.** თითოეული ამოცანა იწყება მინიმუმ 100 GB თავისუფალი დისკის სივრცით.

### არ არის შეტანილი {#macos-not-included}

- **Tuist CLI.** დააყენეთ ის ამოცანაში, მაგალითად mise-ით, რათა თქვენმა პროექტმა აკონტროლოს ვერსია.
- **სხვა Xcode ვერსიები.** გამოიყენეთ პროფილი თითოეული Xcode ვერსიისთვის `xcode-select`-ის ნაცვლად.
- **Docker.** macOS გამშვებებს არ აქვთ Docker დემონი. გამოიყენეთ Linux პროფილი; იხილეთ <.localized_link href="/guides/features/runners/docker">Docker</.localized_link>.
- **ინსტრუმენტთა ჯაჭვები, რომლებსაც GitHub აერთიანებს macOS-ზე** და რომლებიც iOS აგებისას იშვიათად სჭირდება, როგორიცაა Java-ს სხვა ვერსიები, Android SDK, .NET, Rust, Python-ის ვერსიები ან ბრაუზერები. დააყენეთ ისინი ეტაპში Homebrew-ით, mise-ით ან მომზადების მოქმედებით.

## Linux {#linux}

Linux გამშვებები არიან x86_64 (amd64) ვირტუალური მანქანები **Ubuntu 24.04**-ზე ან **Ubuntu 22.04**-ზე, პროფილის მიხედვით შერჩეული. იხილეთ <.localized_link href="/guides/features/runners/profiles#linux">პროფილები</.localized_link> რელიზის ასარჩევად.

### წინასწარ დაყენებული პროგრამული უზრუნველყოფა {#linux-software}

- **აგების ინსტრუმენტთა ჯაჭვი:** `build-essential` (GCC, G++, make), autoconf, automake, libtool, `pkg-config`, CMake, Ninja, m4, bison, flex, gettext
- **დეველოპერის სათაურები:** OpenSSL, libffi, zlib, bzip2, readline, SQLite, ncurses, libxml2, libxslt, libyaml, libcurl, uuid
- **Python:** Python 3 `pip`-ით და `venv`-ით (Ubuntu რელიზის ვერსია)
- **კონტეინერები:** Docker CLI Buildx-ით და Compose-ით; დემონი მუშაობს ამოცანის პარალელურად (იხილეთ <.localized_link href="/guides/features/runners/docker">Docker</.localized_link>)
- **Kubernetes:** `kubectl`, Helm
- **Android:** Android SDK `/usr/local/lib/android/sdk`-ზე ბრძანების ხაზის ინსტრუმენტებით, პლატფორმის ინსტრუმენტებით და ყველა პლატფორმისა და აგების ინსტრუმენტების რელიზით API 34-დან ზემოთ, ლიცენზიები მიღებულია
- **ვერსიების კონტროლი:** Git, Git LFS, OpenSSH კლიენტი, GitHub CLI (`gh`)
- **მონაცემთა ბაზის კლიენტები:** PostgreSQL, MariaDB, Redis (`redis-cli`), SQLite
- **არქივები:** `tar`, `zip`/`unzip`, `xz`, `bzip2`, `p7zip`, `zstd`
- **სახმარი პროგრამები:** `curl`, `wget`, `jq`, ripgrep, `fd`, `tree`, `less`, `vim`, HTTPie, `netcat`, `dig`, `ip`, `ping`, `file`
- **CI აგენტები:** GitHub Actions გამშვები, Buildkite აგენტი, Bitrise აგენტი და CLI, GitLab ამოცანის შემსრულებელი

### გარემო {#linux-environment}

- **მომხმარებელი და გზები.** ამოცანები მუშაობენ `runner`-ის სახელით (UID 1000) საწყისი საქაღალდით `/home/runner`, `docker` ჯგუფში, პაროლის გარეშე `sudo`-ით.
- **`ImageOS`** არის `ubuntu24` ან `ubuntu22`, რაც შეესაბამება GitHub-ზე განთავსებულ გამშვებებს.
- **Android.** `ANDROID_HOME` და `ANDROID_SDK_ROOT` მიუთითებენ SDK-ზე. ემულატორი წინასწარ არ არის დაყენებული; იხილეთ <.localized_link href="/guides/features/runners#android-emulators">Android ემულატორები</.localized_link>.
- **ლოკალი.** `LANG` და `LC_ALL` არის `C.UTF-8`, და `DEBIAN_FRONTEND` არის `noninteractive`, ამიტომ `sudo apt-get install` არ ითხოვს შეყვანას.

### არ არის შეტანილი {#linux-not-included}

Linux გამოსახულება ფარავს აგების საბაზისო საჭიროებებს და არა ყველა ენის ინსტრუმენტთა ჯაჭვს, რომელსაც GitHub წინასწარ აყენებს. დააყენეთ ის, რაც თქვენს ამოცანას სჭირდება, ჩვეულებრივი მომზადების მოქმედებებით (`actions/setup-java`, `actions/setup-node`, `actions/setup-go`, `ruby/setup-ruby`), mise-ით ან `apt-get`-ით:

- **ენის შესრულების გარემოები**, როგორიცაა Java, Node.js, Go, Ruby, .NET და Rust.
- **Android NDK.** დააყენეთ საჭირო ვერსია `"$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" "ndk;<version>"`-ით. `ANDROID_NDK_HOME` რჩება დაუყენებელი, რათა აგება ცხადად ჩავარდეს და არ მიუთითოს არარსებულ NDK-ზე.
- **ბრაუზერები** და ღრუბლის CLIs, `kubectl`-ის, Helm-ისა და `gh`-ის გარდა.

იმისთვის, რომ შეინარჩუნოთ ინსტრუმენტთა ჯაჭვი ამოცანებს შორის და არ დააყენოთ ის ყოველ ჯერზე, მოათავსეთ ის <.localized_link href="/guides/features/runners/cache-volumes">ქეშის ტომზე</.localized_link>.
