# გამოსახულებები {#images}

ყოველი Tuist Runners-ის დავალება იწყება ახალ ვირტუალურ მანქანაში, რომელიც ჩატვირთულია რანერის გამოსახულებიდან. თქვენი <.localized_link href="/guides/features/runners/profiles">პროფილი</.localized_link> ირჩევს გამოსახულებას: პლატფორმას, Xcode-ის ვერსიას macOS-ზე და Ubuntu-ის გამოშვებას Linux-ზე. VM იშლება დავალების დასრულებისას, ამიტომ ყველაფერი, რაც დავალებამ დააყენა, შემდეგი დავალებისთვის აღარ არსებობს.

გამოსახულებები მიჰყვება GitHub-ზე განთავსებულ რანერებს იმ ასპექტებში, რომლებიც მნიშვნელოვანია სამუშაო პროცესებისთვის: იგივე მომხმარებელი, საწყისი და სამუშაო სივრცის გზები, `ImageOS`, პაროლის გარეშე `sudo`, და ხელსაწყოები, რომლებსაც iOS, macOS და Linux სამუშაო პროცესები ელოდებიან. ისინი განზრახ უფრო მცირე ზომისაა, ვიდრე GitHub-ის, ამიტომ განსხვავებები ჩამოთვლილია ქვემოთ თითოეული პლატფორმისთვის.

## გამოსახულების არჩევა {#choosing-an-image}

- **Xcode, Apple SDK-ები ან სიმულატორები:** macOS პროფილი, მიბმული Xcode-ის იმ ვერსიაზე, რომლითაც თქვენი პროექტი კომპილირდება.
- **Docker, Android-ის კომპილაციები და ემულატორები, ან სხვა Linux ხელსაწყოები:** Linux პროფილი Ubuntu 24.04-ზე.
- **დამოკიდებულება, რომელიც ჯერ არ უჭერს მხარს Ubuntu 24.04-ს:** Linux პროფილი Ubuntu 22.04-ზე.

macOS-ზე თქვენ ირჩევთ Xcode-ს, არა გამოსახულებას: თითოეული Xcode-ის ვერსია არის საკუთარი გამოსახულება, და პროფილი, მიბმული `26.4.1`-ზე, ყოველთვის გაეშვება გამოსახულებაზე, აგებული Xcode 26.4.1-ით. ორი Xcode ვერსიის გასაშვებად, შექმენით ცალკე პროფილი თითოეულისთვის.

## macOS {#macos}

macOS რანერები არის Apple silicon (arm64) ვირტუალური მანქანები, რომლებიც მუშაობენ **macOS 26 Tahoe**-ზე. რანერის სახელი შეიცავს macOS-ის ზუსტ ვერსიას, მაგალითად `tuist-macos-26.6-xcode-27.0-8vcpu-24gb-…`, და ჩანს დავალების **დავალების მომზადება** ეტაპზე.

### Xcode {#xcode}

თითოეული გამოსახულება შეიცავს **ზუსტად ერთ Xcode-ს**, რომელიც არჩეულია `xcode-select`-ით, ამიტომ `xcodebuild` და `xcrun` იყენებენ მას მომზადების ეტაპის გარეშე. ეს არის მთავარი განსხვავება GitHub-ზე განთავსებული გამოსახულებებისგან, რომლებიც შეიცავენ რამდენიმე Xcode ვერსიას, რათა დავალების დროს გადაერთონ მათ შორის. ხელმისაწვდომი ვერსიები:

{{runner_macos_xcode_versions}}

- **გზა.** Xcode მდებარეობს `/Applications/Xcode_<version>.app`-ზე. პატჩის კომპონენტის მქონე ვერსიისთვის, `/Applications/Xcode_<major>.<minor>.app` მიუთითებს იმავე ბანდლზე, ამიტომ `Xcode_26.4.app` გარდაიქმნება `Xcode_26.4.1.app`-ად. სამუშაო პროცესები, რომლებიც აკოდირებენ GitHub-ის სტილის გზას ან ურეკავენ `xcode-select -s`-ს მისით, აგრძელებენ მუშაობას.
- **სიმულატორები.** iOS, tvOS, watchOS და visionOS სიმულატორის გარემოები, რომლებიც მოყვება ამ Xcode-ს, ჩამოტვირთულია გამოსახულებაში, ამიტომ პირველ `xcodebuild test`-ს არ სჭირდება მათი ჩამოტვირთვა.
- **Metal ინსტრუმენტთა ჯაჭვი.** Xcode 26-დან, Metal კომპილატორი არ არის ჩართული Xcode-ში და უნდა ჩამოიტვირთოს ცალკე. ყოველი გამოსახულება შეიცავს Metal ინსტრუმენტთა ჯაჭვს, რომელიც შეესაბამება მის Xcode-ს, დაყენებულია იმ მომხმარებლისთვის, რომლის სახელითაც დავალებები გაეშვება, ამიტომ `xcrun metal` და პროექტები `.metal` წყაროებით კომპილირდება `xcodebuild -downloadComponent MetalToolchain`-ის გაშვების გარეშე.
- **ბეტა ვერსიები.** ბეტა პროფილები (მაგალითად `27.3-beta`) ადევნებენ თვალს ამ გამოშვების უახლეს ბეტა ვერსიას. როდესაც Apple გამოუშვებს ახალ ბეტას, გამოსახულება თავიდან აიგება და პროფილი გადავა მასზე თქვენი მხრიდან ცვლილებების გარეშე.

### წინასწარ დაყენებული პროგრამული უზრუნველყოფა {#macos-software}

- **Apple ხელსაწყოები:** Xcode (თითოეულ გამოსახულებაზე ერთი), სიმულატორის გარემოები, Metal ინსტრუმენტთა ჯაჭვი, `xcodes`, `xcbeautify`
- **Swift და iOS ხელსაწყოები:** SwiftLint, SwiftFormat, SwiftGen, LicensePlist, Mint, Carthage, CocoaPods, fastlane
- **მოწყობილობები:** `libimobiledevice`, `ideviceinstaller`, `ios-deploy`
- **ენები და გარემოები:** Ruby `rbenv`-ის მეშვეობით (2.7 და ორი უახლესი 3.x გამოშვება, უახლესი როგორც ნაგულისხმევი) Bundler-თან ერთად, Node.js 24 npm, Yarn და pnpm-თან ერთად, Go, Java 21 (Temurin, დაყენებული როგორც `JAVA_HOME`)
- **პაკეტების და ვერსიების მენეჯერები:** Homebrew, mise
- **ვერსიების კონტროლი:** Git, Git LFS, Git Credential Manager, GitHub CLI (`gh`)
- **სახმარი პროგრამები:** `jq`, `yq`, `curl`, `wget`, `zip`/`unzip`, CMake, GCC, AWS CLI
- **CI აგენტები:** GitHub Actions რანერი, Buildkite აგენტი, Bitrise აგენტი და CLI, GitLab დავალების შემსრულებელი
- **სხვა:** Rosetta 2, `safaridriver` ჩართული

ხელსაწყოების ვერსიები მოდის Homebrew-დან გამოსახულების აგებისას, და გამოსახულებები რეგულარულად თავიდან აიგება. რანერზე ზუსტი ვერსიის სანახავად, დაბეჭდეთ ის ეტაპზე, მაგალითად `swiftlint version` ან `xcodebuild -version`.

### გარემო {#macos-environment}

- **მომხმარებელი და გზები.** დავალებები გაეშვება `runner`-ის სახელით, საწყისი დირექტორიით `/Users/runner` და სამუშაო სივრცით `/Users/runner/work`, იგივე გზებით, რაც GitHub-ზე განთავსებულ რანერებზე, ამიტომ მოქმედებები, რომლებიც აკოდირებენ მათ, მუშაობენ.
- **`sudo`.** პაროლის გარეშე. VM ეკუთვნის მხოლოდ თქვენს დავალებას.
- **Homebrew.** პრეფიქსი (`/opt/homebrew`) ეკუთვნის `runner`-ს, ამიტომ `brew install <formula>` მუშაობს `sudo`-ის გარეშე. `HOMEBREW_NO_AUTO_UPDATE` დაყენებულია.
- **გარსი.** ეტაპები გაეშვება შესვლის გარსში, ამიტომ Homebrew, `rbenv` და Node.js არიან `PATH`-ზე. `LANG` არის `en_US.UTF-8`.
- **`ImageOS`** არის `macos26`, როგორც GitHub-ზე განთავსებულ რანერებზე, მომზადების მოქმედებებისთვის, რომლებიც ირჩევენ წინასწარ აგებულ ბინარებს მის მიხედვით.
- **სერტიფიკატები.** Apple-ის WWDR (G3) და Developer ID (G2) შუალედური სერტიფიკატები არიან სისტემის სანდოობის საცავში ხელმოწერისა და ნოტარიზაციისთვის.
- **კონფიდენციალურობის ნებართვები.** ორი macOS კონფიდენციალურობის დამტკიცება წინასწარ არის გაცემული, როგორც GitHub-ზე განთავსებულ გამოსახულებებზე: Finder-ის სკრიპტირება Apple Events-ის მეშვეობით, რაც სჭირდება `create-dmg`-ს და `osascript`-ს, და iOS სიმულატორის წვდომა მიკროფონზე, რაც სჭირდება აპლიკაციებს, რომლებიც იწერენ აუდიოს UI ტესტებში. ნებართვები სიმულატორის შიგნით, როგორიცაა `simctl privacy`, რჩება თქვენი დავალების პასუხისმგებლობად.
- **დისკი.** ყოველი დავალება იწყება მინიმუმ 100 GB თავისუფალი დისკის სივრცით.

### არ არის ჩართული {#macos-not-included}

- **Tuist CLI.** დააყენეთ ის დავალებაში, მაგალითად mise-ით, რათა თქვენმა პროექტმა აკონტროლოს ვერსია.
- **სხვა Xcode ვერსიები.** გამოიყენეთ პროფილი თითოეული Xcode ვერსიისთვის `xcode-select`-ის ნაცვლად.
- **Docker.** macOS რანერებს არ აქვთ Docker დემონი. გამოიყენეთ Linux პროფილი; იხილეთ <.localized_link href="/guides/features/runners/docker">Docker</.localized_link>.
- **ხელსაწყოთა ჯაჭვები, რომლებსაც GitHub აერთიანებს macOS-ზე** და რომლებიც iOS აგებებს იშვიათად სჭირდებათ, მაგალითად Java-ს სხვა ვერსიები, Android SDK, .NET, Rust, Python-ის ვერსიები ან ბრაუზერები. დააყენეთ ისინი ეტაპზე Homebrew-ით, mise-ით ან მომზადების მოქმედებით.

## Linux {#linux}

Linux რანერები არიან x86_64 (amd64) ვირტუალური მანქანები **Ubuntu 24.04**-ზე ან **Ubuntu 22.04**-ზე, პროფილის მიხედვით შერჩეული. იხილეთ <.localized_link href="/guides/features/runners/profiles#linux">პროფილები</.localized_link> რელიზის ასარჩევად.

### წინასწარ დაყენებული პროგრამული უზრუნველყოფა {#linux-software}

- **აგების ხელსაწყოთა ჯაჭვი:** `build-essential` (GCC, G++, make), autoconf, automake, libtool, `pkg-config`, CMake, Ninja, m4, bison, flex, gettext
- **დეველოპმენტის სათაურები:** OpenSSL, libffi, zlib, bzip2, readline, SQLite, ncurses, libxml2, libxslt, libyaml, libcurl, uuid
- **Python:** Python 3 `pip`-ით და `venv`-ით (Ubuntu-ს რელიზის ვერსია)
- **კონტეინერები:** Docker CLI Buildx-ით და Compose-ით; დემონი გაეშვება დავალების პარალელურად (იხილეთ <.localized_link href="/guides/features/runners/docker">Docker</.localized_link>)
- **Kubernetes:** `kubectl`, Helm
- **Android:** Android SDK `/usr/local/lib/android/sdk`-ზე ბრძანების ხაზის ხელსაწყოებით, platform-tools-ით და ყოველი პლატფორმისა და build-tools-ის რელიზით API 34-დან ზემოთ, მიღებული ლიცენზიებით
- **ვერსიის კონტროლი:** Git, Git LFS, OpenSSH კლიენტი, GitHub CLI (`gh`)
- **მონაცემთა ბაზის კლიენტები:** PostgreSQL, MariaDB, Redis (`redis-cli`), SQLite
- **არქივები:** `tar`, `zip`/`unzip`, `xz`, `bzip2`, `p7zip`, `zstd`
- **სახმარი პროგრამები:** `curl`, `wget`, `jq`, ripgrep, `fd`, `tree`, `less`, `vim`, HTTPie, `netcat`, `dig`, `ip`, `ping`, `file`
- **CI აგენტები:** GitHub Actions რანერი, Buildkite აგენტი, Bitrise აგენტი და CLI, GitLab დავალების შემსრულებელი

### გარემო {#linux-environment}

- **მომხმარებელი და გზები.** დავალებები გაეშვება `runner`-ის სახელით (UID 1000) საწყისი საქაღალდით `/home/runner`, `docker` ჯგუფში, პაროლის გარეშე `sudo`-ით.
- **`ImageOS`** არის `ubuntu24` ან `ubuntu22`, რაც შეესაბამება GitHub-ზე განთავსებულ რანერებს.
- **Android.** `ANDROID_HOME` და `ANDROID_SDK_ROOT` მიუთითებს SDK-ზე. ემულატორი წინასწარ არ არის დაყენებული; იხილეთ <.localized_link href="/guides/features/runners#android-emulators">Android ემულატორები</.localized_link>.
- **ლოკალი.** `LANG` და `LC_ALL` არის `C.UTF-8`, და `DEBIAN_FRONTEND` არის `noninteractive`, ამიტომ `sudo apt-get install` არ ითხოვს შეყვანას.

### არ არის ჩართული {#linux-not-included}

Linux-ის გამოსახულება ფარავს აგების საბაზისო საჭიროებებს და არა ყოველ ენის ხელსაწყოთა ჯაჭვს, რომელსაც GitHub წინასწარ აყენებს. დააყენეთ ის, რაც თქვენს დავალებას სჭირდება, ჩვეულებრივი მომზადების მოქმედებებით (`actions/setup-java`, `actions/setup-node`, `actions/setup-go`, `ruby/setup-ruby`), mise-ით ან `apt-get`-ით:

- **ენების შესრულების გარემოები**, როგორიცაა Java, Node.js, Go, Ruby, .NET და Rust.
- **Android NDK.** დააყენეთ საჭირო ვერსია `"$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" "ndk;<version>"`-ით. `ANDROID_NDK_HOME` რჩება დაუყენებელი, რათა აგება ცხადად ჩავარდეს და არ მიუთითოს არარსებულ NDK-ზე.
- **ბრაუზერები** და ღრუბლის CLIs, `kubectl`-ის, Helm-ის და `gh`-ის გარდა.

იმისთვის, რომ შეინარჩუნოთ ხელსაწყოთა ჯაჭვი დავალებებს შორის მისი ყოველ ჯერზე დაყენების ნაცვლად, მოათავსეთ ის <.localized_link href="/guides/features/runners/cache-volumes">ქეშის ტომზე</.localized_link>.
