# Struo-ს დისტანციური შესრულება {#struo-remote-execution}

<a id="once-remote-execution"></a>

გაზიარებული ქეშირება თავიდან აცილებს იმ სამუშაოს გამეორებას, რომელიც სხვა მანქანამ უკვე დაასრულა. დისტანციური შესრულება ასევე გადაიტანს შესაბამის ქეშის გამოტოვებებს თქვენი კომპიუტერიდან: Struo გრაფის ბრძანების მოქმედებებს გეგმავს Tuist-ის ერთჯერად Linux-ის ვორკერებზე და იღებს მათ შედეგებს იმავე პროექტის ქეშის საშუალებით.

> [!NOTE]
> დისტანციური შესრულება ამჟამად მხოლოდ მიწვევითაა ხელმისაწვდომი. [დაგვიკავშირდით](mailto:contact@tuist.dev) თქვენი ანგარიშისთვის წვდომის მოსათხოვნად.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - Tuist-ის ანგარიში ჩართული დისტანციური შესრულებით და ხელმისაწვდომი შესრულების სიმძლავრით.
> - Struo-ს ვერსია Tuist-ის დისტანციური შესრულების მხარდაჭერით.
> - თავსებადი სერვერი, რომელიც აცხადებს ვორკერის იმიჯს, ქეშის ბოლო წერტილს, პარალელურობას და აბსოლუტურ შესრულების დირექტორიას. სერვერები, რომლებიც ტოვებენ დირექტორიას, არ არიან თავსებადები მიმდინარე Struo კლიენტთან; Struo ჩერდება სამუშაოს ატვირთვამდე.
> - ბრძანებები და ინსტრუმენტების ჯაჭვები, რომლებსაც შეუძლიათ გაშვება `linux/amd64` რეკლამირებული ვორკერის იმიჯის შიგნით.

ეს ასრულებს გრაფის მოქმედებებს, არა მთლიან CI სამუშაოს. Struo-ს კონფიგურაცია არ აყენებს GitHub-ის ან GitLab-ის სამუშაო ნაკადის ორკესტრაციას.

## დაყენება {#setup}

დაასრულეთ <.localized_link href="/guides/get-started/struo-project">Struo-ს დაწყება</.localized_link>. აირჩიეთ იგივე Tuist პროვაიდერი ქეშირებისა და შესრულებისთვის და დააფიქსირეთ სერვისის მიერ რეკლამირებული ვორკერის იმიჯი:

```toml
[infrastructures.tuist]
kind = "tuist"
account = "acme"
project = "app"
execution_image = "sha-REPLACE_WITH_THE_IMAGE_TAG"

[infrastructure.cache]
provider = "tuist"

[infrastructure.execution]
provider = "tuist"
```

გაიარეთ ავტორიზაცია ისეთი სერთიფიკატებით, რომლებსაც შეუძლიათ წაიკითხონ და ჩაწერონ პროექტის ქეში, შემდეგ მოითხოვეთ დისტანციური შესრულება:

```bash
struo build --remote MyTarget
```

ჩაანაცვლეთ სამიზნე და იმიჯის თეგი თქვენით. Struo ამოწმებს რეკლამირებულ იმიჯს, შესრულების დირექტორიას, ქეშის დანიშნულების ადგილს და ანგარიშის სიმძლავრეს სამუშაოს ატვირთვამდე. ქეში და შესრულება უნდა მიუთითებდნენ იმავე პროექტზე.

## მოქმედებების მომზადება ვორკერებისთვის {#prepare-actions-for-workers}

- განაცხადეთ შეყვანები და გამოყვანები. გამოყვანები უნდა დარჩნენ მოქმედების სამუშაო დირექტორიის ქვეშ.
- გააწყვეთ ინსტრუმენტები ვორკერის იმიჯის შიგნით, არა საწყის კომპიუტერზე აბსოლუტური გზებით.
- გამოიყენეთ მოქმედებები, რომლებიც უსაფრთხოა განმეორებისთვის: ვორკერის შეცდომა ან სერვისის გადატვირთვა შეიძლება გამოიწვიოს სხვა შესრულება.
- შეინახეთ დროის ამოწურვა სერვისის ათწუთიანი მოქმედების ლიმიტის ფარგლებში. არამხარდაჭერილი მოთხოვნები, მათ შორის ქსელის უარყოფა, მარცხდებიან და არ ასრულებენ ლოკალურად ჩუმად.

Struo პატივს სცემს ანგარიშის რეკლამირებულ მოქმედების პარალელურობას და იკავებს თავს, როდესაც სერვისის რიგი სავსეა. იმიჯის შეცვლა ყოფს ბილდის კონფიგურაციას და ქეშირებულ შედეგებს, რაც ხელს უშლის თავსებად ვორკერის იმიჯებში ხელახლა გამოყენებას.

## დისტანციური შესრულების ინსპექტირება {#inspect-remote-execution}

პროექტის გვერდითა პანელს აქვს **დისტანციური შესრულება** გვერდი. მისი **ანალიტიკა** ბარათი აჩვენებს შესრულებებს და შესრულების საერთო დროს შერჩეული პერიოდისთვის, როგორც აღწერილია <.localized_link href="/guides/features/cache/bazel-cache#running-actions-and-usage">მოქმედებების გაშვება და გამოყენება</.localized_link>-ში. Struo-ს 2.19.0-ის შემდგომი გამოშვებებით, თითოეული დისტანციური მოქმედება ასახელებს Struo-ს გაშვებას, რომელსაც ეკუთვნის, ამიტომ გვერდი ასევე აჩვენებს რიგისა და შესრულების დროებს და ჩამოთვლის გაშვებებს მათი დისტანციური მოქმედებებით, შედეგით და დროებით, პირველ რიგში მიმდინარე გაშვებებით. გაშვება ხსნის მის გვერდს **ბილდის გაშვებები**-ში. ძველი კლიენტების გაშვებები და დისტანციური ქეშიდან პასუხგაცემული მოქმედებები არ შედიან იქ. ახლავე მიმდინარე და რიგში მყოფი დისტანციური მოქმედებები ხელმისაწვდომია `get_remote_execution_activity` MCP ინსტრუმენტიდან და მისი REST ბოლო წერტილიდან. ორივე მოდის შესრულების სერვისიდან, არა ვორკერის ზოლებიდან.

იხილეთ [Struo-ს დისტანციური შესრულების სახელმძღვანელო](https://struo.run/docs/guide/infrastructure/tuist#run-actions-on-tuist-workers) რიგში ჩადგომის, ავტორიზაციის განახლებისა და ქეშის ბოლო წერტილის გადაფარვისთვის. მიჰყევით <.localized_link href="/guides/features/build-insights/struo">Struo ბილდის ინსაიტებს</.localized_link> მიღებული გაშვებების ინსპექტირებისთვის.
