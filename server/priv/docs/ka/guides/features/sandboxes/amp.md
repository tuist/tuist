# Amp {#amp}

> [!IMPORTANT]
> **მხოლოდ მოწვევით**
>
> Tuist Sandboxes, როგორც Linux-ზე, ისე macOS-ზე, ამჟამად მხოლოდ მოწვევითაა ხელმისაწვდომი. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [საზოგადოების Slack-ში](https://slack.tuist.dev), რათა თქვენი ანგარიშისთვის წვდომა მოითხოვოთ.

[Amp](https://ampcode.com) ყოველი ძაფის ინსტრუმენტებს [orb-ში](https://ampcode.com/docs/orbs) უშვებს — ეს არის მანქანა, სადაც ძაფის რეპოზიტორია გადმოწერილი. Tuist შეიძლება იყოს თქვენი Amp სამუშაო სივრცის [თვითმასპინძელი orb პროვაიდერი](https://ampcode.com/docs/orbs/self-hosted): ყოველი ძაფი, რომელიც მას ირჩევს, თავის Tuist <.localized_link href="/guides/features/sandboxes">sandbox-ში</.localized_link> მუშაობს, Linux-ზე ან macOS-ზე. თქვენ არაფერს უშვებთ ან მასპინძლობთ საკუთარ ხელზე.

იმისთვის, რომ თქვენი ძაფები მიმდინარე orb-ებზე დარჩეს და Apple-პლატფორმის კოდი მხოლოდ Mac-ზე ააწყოთ, გატესტოთ და გაუშვათ, გამოიყენეთ [Tuist Mac პლაგინი](#remote-mac).

## Amp-ის დაკავშირება {#connect}

თქვენ უნდა იყოთ ადმინისტრატორი როგორც Amp სამუშაო სივრცის, ისე Tuist ანგარიშის.

1. Amp-ში გახსენით თქვენი სამუშაო სივრცის **Settings → Orbs**, დააჭირეთ **Add Orb Provider** და მიანიჭეთ სახელი, მაგალითად `tuist`. წევრები პროვაიდერს ამ სახელით ირჩევენ. დააკოპირეთ `aop_live_…` ტოკენი; Amp მას მხოლოდ ერთხელ აჩვენებს.
2. Amp-ში პროვაიდერის **Edit** დიალოგში დაამატეთ **Orb ტიპები**, რომლებიც გსურთ შესთავაზოთ, და აირჩიეთ ნაგულისხმები. Linux ტიპები ემთხვევა [Amp-ის საკუთარი orb-ების](https://ampcode.com/docs/orbs/sizes-and-costs) ზომებს:

   | ტიპი | პლატფორმა | კონფიგურაცია |
   | --- | --- | --- |
   | `linux` | Linux | 4 vCPU, 8 GiB RAM, 10 GB workspace |
   | `linux-tiny` | Linux | 1 vCPU, 2 GiB RAM, 10 GB workspace |
   | `linux-small` | Linux | 2 vCPU, 4 GiB RAM, 10 GB workspace |
   | `linux-medium` | Linux | 4 vCPU, 8 GiB RAM, 10 GB workspace (იგივე, რაც `linux`) |
   | `linux-large` | Linux | 8 vCPU, 16 GiB RAM, 10 GB workspace |
   | `linux-xxlarge` | Linux | 16 vCPU, 32 GiB RAM, 10 GB workspace |
   | `linux-3xlarge` | Linux | 16 vCPU, 44 GiB RAM, 10 GB workspace |
   | `macos` | macOS Xcode-ით | 8 vCPU, 8 GiB RAM, 10 GB workspace |

3. Tuist-ში გახსენით **Sandboxes** თქვენი ანგარიშის დაფაზე, Amp ბარათზე დააჭირეთ **Connect** და ჩასვით ტოკენი.

ბარათი აჩვენებს **Connected**-ს, როგორც კი Tuist პროვაიდერს ემსახურება. ერთი Tuist ანგარიში ერთ პროვაიდერს ემსახურება. ნებისმიერი, ვისაც Amp-ში პროვაიდერის გამოყენება შეუძლია, orb-ებს ამუშავებს და ხარჯები ერიცხება დაკავშირებულ Tuist ანგარიშს. შესაჩერებლად ბარათზე დააჭირეთ **Disconnect** ან გამორთეთ პროვაიდერი Amp-ში.

## ძაფის დაწყება {#start-a-thread}

Amp-ის ახალი ძაფის შემქმნელში დააჭირეთ **Orb**, აირჩიეთ Tuist პროვაიდერი **Self-Hosted** ქვეშ და აირჩიეთ ტიპი, მაგალითად `linux-small` რეპოზიტორიისთვის, რომელსაც `linux`-ზე ნაკლები სჭირდება, ან `linux-large` იმისთვის, რომელსაც მეტი სჭირდება. Amp CLI-დან:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos
```

ძაფი მთელი სიცოცხლის განმავლობაში ინარჩუნებს orb-ის ტიპს. ტიპის მითითების გარეშე, ის იღებს პროვაიდერის ნაგულისხმევს. ყოველი ახალი ძაფისთვის ერთი ტიპის გამოსაყენებლად, აირჩიეთ პროვაიდერი და მისი ტიპი Amp-ის **Settings → Orbs** განყოფილებაში **Default Orb** ქვეშ.

Amp აკლონებს რეპოზიტორიას, უშვებს თქვენს `.agents/setup` სკრიპტს და აყენებს Git-ის სერთიფიკატებს, როგორც ყოველი orb-ის შემთხვევაში. ყოველ orb-ს ასევე შეუძლია წაიკითხოს თქვენი ანგარიშის Tuist <.localized_link href="/guides/features/cache">cache</.localized_link>.

## შეჩერება და შენახვა {#retention}

როდესაც ძაფი უმოქმედო ხდება, Amp აჩერებს მის orb-ს. შემდეგი შეტყობინება აღადგენს მას ფაილების შენარჩუნებით.

- **Linux:** გაშვებული პროცესები შეჩერების შემდეგაც რჩება. orb, რომელიც დიდი ხნით იყო შეჩერებული, გადადის საარქივო საცავში და შემდეგ შეტყობინებაზე აღდგება პროცესების გარეშე. Linux orb-ები ინარჩუნებენ ფაილებს მანამ, სანამ Amp ძაფის orb-ს არ წაშლის.
- **macOS:** orb, რომელიც 7 დღის განმავლობაში შეჩერებული იყო ან შეცდომის მდგომარეობაში იყო, იშლება. ძაფის შემდეგი შეტყობინება ახალ orb-ს იწყებს და Amp ხელახლა უშვებს `.agents/setup`-ს. მანქანაზე პირველი macOS orb აყენებს Amp CLI-ს, ამიტომ გაშვებას ორ წუთამდე შეიძლება დასჭირდეს.

orb, რომელიც უმოქმედოდ რჩება Amp-ის შეჩერების გარეშე, მაგალითად იმიტომ, რომ შეჩერების ბრძანება არ მიუვიდა, ათი წუთის შემდეგ ჩერდება თითქმის ნულოვანი CPU გამოყენებით.

## Mac-ის გამოყენება ნებისმიერი Amp ძაფიდან {#remote-mac}

Tuist Mac-ის პლაგინი Amp-ის ძაფს აწვდის macOS sandbox-ს Xcode-ით, iOS სიმულატორებით და Homebrew-ით, ხოლო ძაფი განაგრძობს მუშაობას იქ, სადაც არის, მაგალითად, Amp-ის ერთ-ერთ Linux orb-ზე. შესრულებისთვის მიმართეთ Amp-ს და ის Mac-ს მაშინ გაუშვებს, როცა ეს საჭირო იქნება:

> დაამატეთ ბნელი რეჟიმის გადამრთველი პარამეტრების ეკრანზე, გაუშვით აპლიკაცია iOS სიმულატორში და მაჩვენეთ სქრინშოტი.

Amp კოდის რედაქტირებას იქ აგრძელებს, სადაც ის მუშაობს. Mac-ზე ყოველი ბრძანების შესრულებამდე პლაგინი უშვებს `tuist sandbox sync`-ს, რომელიც აკოპირებს ფაილებს, რომლებსაც Git არ იგნორირებს — ჩაკომიტებულს თუ არა, — ხოლო შემდეგ მხოლოდ შეცვლილ ფაილებს. Mac-ის მიერ შექმნილი ბილდის პროდუქტები და სხვა იგნორირებული ფაილები იქ რჩება, რაც ბილდებს ინკრემენტულს ტოვებს. პლაგინი ამ ინსტრუმენტებს და `remote-mac` უნარს ამატებს, რომელიც Amp-ს ეუბნება, როდის და როგორ გამოიყენოს ისინი:

| ინსტრუმენტი | რა აკეთებს |
| --- | --- |
| `tuist_mac_start` | ქმნის ძაფის Mac-ს ან ხელახლა იყენებს მას და ასინქრონებს |
| `tuist_mac_shell` | ასინქრონებს, შემდეგ კი Mac-ზე ბრძანებას ასრულებს |
| `tuist_mac_screenshot` | აჩვენებს სიმულატორს ან ეკრანს ძაფში |
| `tuist_mac_download` | აბრუნებს ფაილის ასლს, მაგალითად, აწყობილ `.app`-ს |
| `tuist_mac_stop` | შლის ძაფის Mac-ს |

Mac-ს საკუთარი Tuist CLI არ აქვს: პირველი სინქრონიზაციის შემდეგ Amp რეპოზიტორიის root-ში უშვებს `mise install`-ს, რათა პროექტის მიერ მიმაგრებული Tuist დაინსტალირდეს, ხოლო `tuist_mac_shell` mise-ის shims-ებს `PATH`-ზე ამატებს. Mac-ზე ყოველი ბრძანება დამოუკიდებლად <.localized_link href="/guides/features/sandboxes#tuist-in-sandbox">შედის თქვენი ანგარიშის cache-ში</.localized_link> Tuist 4.218.0 ან უფრო გვიანი ვერსიით; 4.215.0-დან 4.217.x-მდე ვერსიებში Amp ჯერ `tuist auth login`-ს უშვებს.

ძაფი ერთ Mac-ს იყენებს. Tuist მას უმოქმედობისას აჩერებს, ხოლო შემდეგი ბრძანება აღადგენს. Amp მას შლის, როცა ამოცანა დასრულდება; დარჩენილი Mac 14 დღის შეჩერების შემდეგ იშლება. Mac-ები თქვენი Tuist ანგარიშისთვის ისევე ითვლება, როგორც ნებისმიერი სხვა sandbox.

### მოაწყვეთ {#remote-mac-setup}

1. **დააინსტალირეთ პლაგინი.** ეს ერთი ფაილია, [`tuist-mac.ts`](https://github.com/tuist/tuist/blob/main/.amp/plugins/tuist-mac.ts). იმისათვის, რომ ის თქვენი Amp სამუშაო სივრცის ყველა წევრისთვის ხელმისაწვდომი გახდეს, სამუშაო სივრცის ადმინისტრატორი ძაფში Amp-ს მიმართავს:

   > დაამატეთ https://raw.githubusercontent.com/tuist/tuist/main/.amp/plugins/tuist-mac.ts ჩვენს სამუშაო სივრცის პლაგინებში.

   Amp მას სამუშაო სივრცის [პლაგინების რეპოზიტორიაში](https://ampcode.com/docs/customize/global-plugins-and-skills) აკომიტებს და push-მდე ითხოვს ნებართვას. მის მხოლოდ საკუთარ თავზე დასაყენებლად, სთხოვეთ „ჩემი პირადი პლაგინები“, ან შეინახეთ ფაილი როგორც `.amp/plugins/tuist-mac.ts` რეპოზიტორიაში, რათა ის მხოლოდ იქ გამოიყენოთ. პლაგინი ასლია: მის განახლებისთვის, სთხოვეთ Amp-ს, ჩაანაცვლოს ის იმავე URL-ის უახლესი ვერსიით.
2. **დააინსტალირეთ Tuist CLI** იქ, სადაც Amp მუშაობს. orb-ებზე, დაამატეთ ის რეპოზიტორიის [`.agents/setup`](https://ampcode.com/docs/orbs/customizing) სკრიპტში, მაგალითად `mise use -g tuist@latest`, ან `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist`.
3. **მიეცით CLI-ს თქვენი ანგარიშის sandbox-ების გამოყენების უფლება.** orb-ებზე, დააკავშირეთ თქვენი Amp სამუშაო სივრცე თქვენს Tuist ანგარიშთან, როგორც აღწერილია <.localized_link href="/guides/server/authentication#amp-orbs">Amp orbs</.localized_link>-ში. orb-ები შემდეგ დამოუკიდებლად შედიან სისტემაში sandbox-ებზე წვდომით. სხვაგან, მაგალითად, Amp CLI-ზე Linux მანქანაზე, გაუშვით `tuist auth login` როგორც ანგარიშის წევრმა, ან დააყენეთ `TUIST_MAC_TOKEN` <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის token-ზე</.localized_link> `account:sandboxes:write` scope-ით, პლუს `ci` Mac-ის მიერ cache-ის გამოსაყენებლად. პლაგინი `TUIST_MAC_TOKEN`-ს CLI-ს `TUIST_TOKEN`-ის ნაცვლად გადასცემს, ამიტომ ისიც დააყენეთ, როცა თქვენს orb-ებს უკვე აქვთ `TUIST_TOKEN` ამ scope-ის გარეშე.
4. **მიუთითეთ, რომელი ანგარიში უნდა გამოიყენოს**, თუ რეპოზიტორიას არ აქვს `tuist.toml` `project = "<account>/<project>"`-ით. Linux-ზე, CLI-ს `Tuist.swift`-დან ანგარიშის წაკითხვა არ შეუძლია. დააყენეთ `TUIST_MAC_ACCOUNT` თქვენს ანგარიშის handle-ზე თქვენი Amp პროექტის გარემოს ცვლადებში. მის გარეშე, Amp `Tuist.swift`-ის `fullHandle`-დან ანგარიშს `tuist_mac_start`-ს გადასცემს.

CLI Mac-ს მხოლოდ `tuist.dev`-ის მეშვეობით უკავშირდება, ამიტომ ქსელურ წვდომას რომ ზღუდავს, ისეთ გარემოს მხოლოდ ამ დომენის დაშვება სჭირდება. CLI-ის გამოსაყენებლად, რომელიც `PATH`-ზე არ არის, დააყენეთ `TUIST_MAC_CLI` მის გზაზე.

აგენტებს, რომლებიც Amp პლაგინებს არ უჭერენ მხარს, მაგალითად Claude Code ან Cursor, იგივეს გაკეთება Tuist MCP სერვერისა და CLI-ის მეშვეობით შეუძლიათ, როგორც აღწერილია <.localized_link href="/guides/features/sandboxes#coding-agents">კოდირების აგენტით Mac-ზე აწყობა</.localized_link>-ში.

### გამოიყენეთ Tuist Mac-ები Amp-ის macOS Satellites-ის ნაცვლად {#remote-mac-satellites}

Amp-ს ასევე აქვს საკუთარი ღრუბლოვანი Mac-ები, [macOS Satellites](https://ampcode.com/docs/orbs/mac), ბეტა-რეჟიმში იმ სამუშაო სივრცეებისთვის, რომლებიც მოლოდინის სიაში ჩაემატნენ. როცა ძაფს ორივეს გაშვება შეუძლია, Amp-ის ჩაშენებული ინსტრუქციები macOS სამუშაოებს მის სატელიტებს უგზავნიან, ამიტომ ის იშვიათად ირჩევს პლაგინს. იმისათვის, რომ ძაფებმა Tuist Mac-ები გამოიყენონ, გააკეთეთ ერთ-ერთი შემდეგი:

- **გამორთეთ macOS Satellites საკუთარი თავისთვის.** თითოეული წევრი მათ გამორთავს Amp-ის [პარამეტრები → ექსპერიმენტული ფუნქციები](https://ampcode.com/settings/experimental-features)-ში **Mac Satellites**-ის ქვეშ.
- **გამორთეთ ისინი სამუშაო სივრცისთვის.** როცა თქვენი სამუშაო სივრცის orb-ები [Tuist-ზე მუშაობენ](#connect), სამუშაო სივრცის ადმინისტრატორს შეუძლია Amp-ის სამუშაო სივრცის პარამეტრებში, **Orbs**-ის ქვეშ, **სად მუშაობენ Orb-ები** დააყენოს **მხოლოდ Self-Hosted**. აგენტები შემდეგ Amp-ის მიერ დაჰოსტულ სატელიტებს ვერ გაუშვებენ, მაგრამ წევრები ასევე ვერ გამოიყენებენ Amp-ის ჩაშენებულ orb-ებს, ამიტომ ეს მხოლოდ მაშინ გააკეთეთ, როცა თქვენი ყველა ძაფი თქვენს საკუთარ orb პროვაიდერებზე მუშაობს.
- **მოითხოვეთ Tuist Mac-ები.** დაამატეთ „გამოიყენეთ `tuist_mac_*` ინსტრუმენტები macOS სამუშაოებისთვის, არა macOS Satellites.“ მოთხოვნაში, ან თქვენი სამუშაო სივრცის აგენტის მითითებებში Amp-ის სამუშაო სივრცის პარამეტრებში, რათა ყოველმა ძაფმა დაიცვას ის.
