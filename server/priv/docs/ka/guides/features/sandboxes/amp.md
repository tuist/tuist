# Amp {#amp}

> [!IMPORTANT]
> **მხოლოდ მოწვევით**
>
> Tuist Sandboxes, როგორც Linux-ზე, ასევე macOS-ზე, ამჟამად ხელმისაწვდომია მხოლოდ მოწვევით. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [საზოგადოების Slack-ში](https://slack.tuist.dev), რათა თქვენი ანგარიშისთვის წვდომა მოითხოვოთ.

[Amp](https://ampcode.com) თითოეული ნაკადის ინსტრუმენტებს უშვებს [orb-ში](https://ampcode.com/docs/orbs) — მანქანაზე, სადაც ნაკადის რეპოზიტორია გადმოწერილი. Tuist შეიძლება იყოს თქვენი Amp სამუშაო სივრცის [თვითმასპინძელი orb პროვაიდერი](https://ampcode.com/docs/orbs/self-hosted): ყოველი ნაკადი, რომელიც მას ირჩევს, მუშაობს საკუთარ Tuist <.localized_link href="/guides/features/sandboxes">sandbox-ში</.localized_link>, Linux-ზე ან macOS-ზე. თქვენ არ გჭირდებათ რაიმეს დამოუკიდებლად გაშვება ან ჰოსტინგი.

იმისთვის, რომ ნაკადები დარჩეს მიმდინარე orb-ებზე და Apple-პლატფორმის კოდის ბილდი, ტესტირება და გაშვება მხოლოდ Mac-ზე მოხდეს, გამოიყენეთ [Tuist Mac პლაგინი](#remote-mac).

## Amp-ის მიერთება {#connect}

თქვენ უნდა იყოთ ადმინისტრატორი როგორც Amp სამუშაო სივრცის, ასევე Tuist ანგარიშის.

1. Amp-ში გახსენით თქვენი სამუშაო სივრცის **Settings → Orbs**, დააჭირეთ **Add Orb Provider** და მიანიჭეთ სახელი, მაგალითად `tuist`. წევრები პროვაიდერს ამ სახელით ირჩევენ. დააკოპირეთ `aop_live_…` ტოკენი; Amp მას მხოლოდ ერთხელ აჩვენებს.
2. პროვაიდერის **Edit** დიალოგში Amp-ში დაამატეთ **Orb ტიპები**, რომელთა შეთავაზებაც გსურთ და აირჩიეთ ნაგულისხმევი. Linux ტიპები ემთხვევა [Amp-ის საკუთარი orb-ების](https://ampcode.com/docs/orbs/sizes-and-costs) ზომებს:

   | ტიპი | პლატფორმა | კონფიგურაცია |
   | --- | --- | --- |
   | `linux` | Linux | 4 vCPU, 8 GiB RAM, 10 GB სამუშაო სივრცე |
   | `linux-tiny` | Linux | 1 vCPU, 2 GiB RAM, 10 GB სამუშაო სივრცე |
   | `linux-small` | Linux | 2 vCPU, 4 GiB RAM, 10 GB სამუშაო სივრცე |
   | `linux-medium` | Linux | 4 vCPU, 8 GiB RAM, 10 GB სამუშაო სივრცე (იგივე, რაც `linux`) |
   | `linux-large` | Linux | 8 vCPU, 16 GiB RAM, 10 GB სამუშაო სივრცე |
   | `linux-xxlarge` | Linux | 16 vCPU, 32 GiB RAM, 10 GB სამუშაო სივრცე |
   | `linux-3xlarge` | Linux | 16 vCPU, 44 GiB RAM, 10 GB სამუშაო სივრცე |
   | `macos` | macOS ნაგულისხმევი Xcode-ით | 8 vCPU, 8 GiB RAM, 30 GB სამუშაო სივრცე |
   | `macos-xcode-<version>` | macOS ამ Xcode-ით, მაგალითად `macos-xcode-26-1-1` Xcode 26.1.1-ისთვის | 8 vCPU, 8 GiB RAM, 30 GB სამუშაო სივრცე |

3. Tuist-ში გახსენით **Sandboxes** თქვენი ანგარიშის დაფაზე, დააჭირეთ **Connect** Amp ბარათზე და ჩასვით ტოკენი.

ბარათი აჩვენებს **Connected**-ს, როდესაც Tuist ემსახურება პროვაიდერს. ერთი Tuist ანგარიში ერთ პროვაიდერს ემსახურება. ყველა, ვისაც Amp-ში პროვაიდერის გამოყენება შეუძლია, orb-ებს აშვებს და ხარჯები ერიცხება მიერთებულ Tuist ანგარიშს. გასათიშად დააჭირეთ **Disconnect** ბარათზე ან გამორთეთ პროვაიდერი Amp-ში.

## ნაკადის დაწყება {#start-a-thread}

Amp-ის ახალი ნაკადის შექმნის ფანჯარაში დააჭირეთ **Orb**, აირჩიეთ Tuist პროვაიდერი **Self-Hosted** ქვეშ და აირჩიეთ ტიპი, მაგალითად `linux-small` რეპოზიტორიისთვის, რომელსაც `linux`-ზე ნაკლები სჭირდება, ან `linux-large` იმისთვის, რომელსაც მეტი სჭირდება. Amp CLI-დან:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos
```

ნაკადი ინარჩუნებს თავის orb ტიპს მთელი სიცოცხლის განმავლობაში. ტიპის მითითების გარეშე, ის იღებს პროვაიდერის ნაგულისხმევს. ყოველი ახალი ნაკადისთვის ერთი ტიპის გამოყენებისთვის, აირჩიეთ პროვაიდერი და მისი ტიპი **Default Orb** ქვეშ Amp-ის **Settings → Orbs** მენიუში.

### Xcode-ის არჩევა {#xcode}

`macos` უშვებს ნაგულისხმევ <.localized_link href="/guides/features/sandboxes#xcode">Xcode</.localized_link>-ს. სხვისთვის დაამატეთ orb ტიპი, რომელიც მას ეწოდება, წერტილების ტირეებით ჩანაცვლებით: `macos-xcode-26-1-1` უშვებს Xcode 26.1.1-ს, `macos-xcode-27-0` Xcode 27.0-ს. დაამატეთ თითოეული Xcode-ისთვის, რომელსაც თქვენი რეპოზიტორიები ამაგრებენ, და აირჩიეთ ის ნაკადის მიხედვით, როგორც ნებისმიერი სხვა ტიპი:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos-xcode-26-1-1
```

ტიპი Xcode-ისთვის, რომელსაც Tuist არ სთავაზობს, ახალი orb-ის გაშვებისას მარცხდება. orb, რომელიც Tuist-მა უკვე გაუშვა მასზე, განაგრძობს აღდგენას მას შემდეგ, რაც Tuist შეწყვეტს ამ Xcode-ის შეთავაზებას.

Amp აკლონებს რეპოზიტორიას, უშვებს თქვენს `.agents/setup` სკრიპტს და აყენებს Git კრედენციალებს, როგორც ეს ყოველი orb-ისთვის ხდება. თითოეულ orb-ს ასევე შეუძლია წაიკითხოს თქვენი ანგარიშის Tuist <.localized_link href="/guides/features/cache">cache</.localized_link>.

## შეჩერება და შენახვა {#retention}

როდესაც ნაკადი უმოქმედო ხდება, Amp აჩერებს მის orb-ს. შემდეგი შეტყობინება აღადგენს მას ფაილების შენარჩუნებით.

- **Linux:** გაშვებული პროცესები ინარჩუნებენ სიცოცხლეს შეჩერების დროს. orb, რომელიც დიდი ხნით იყო შეჩერებული, გადადის საარქივო საცავში და აღდგება შემდეგი შეტყობინებისას, პროცესების გარეშე. Linux orbs ინარჩუნებენ თავიანთ ფაილებს მანამ, სანამ Amp წაშლის ნაკადის orb-ს.
- **macOS:** orb, რომელიც 7 დღის განმავლობაში იყო შეჩერებული ან შეცდომის მდგომარეობაში, იშლება. ნაკადის შემდეგი შეტყობინება ქმნის ახალ orb-ს და Amp კვლავ უშვებს `.agents/setup`-ს. პირველი macOS orb მანქანაზე აყენებს Amp CLI-ს, ამიტომ გაშვებამ შეიძლება ორ წუთამდე მოითხოვოს.

orb, რომელიც რჩება უმოქმედოდ Amp-ის მიერ შეჩერების გარეშე, მაგალითად, შეჩერების ბრძანების არმიღების გამო, ჩერდება ათი წუთის შემდეგ CPU-ს თითქმის ნულოვანი გამოყენებით.

## Mac-ის გამოყენება ნებისმიერი Amp ნაკადიდან {#remote-mac}

Tuist Mac პლაგინი აწვდის Amp ნაკადს macOS sandbox-ს Xcode-ით, iOS სიმულატორებითა და Homebrew-ით, მაშინ როცა ნაკადი განაგრძობს მუშაობას იქ, სადაც ის არის, მაგალითად, Amp-ის ერთ-ერთ Linux orb-ზე. სთხოვეთ Amp-ს სამუშაო და ის გაუშვებს Mac-ს, როცა ეს დასჭირდება:

> დაამატეთ ბნელი რეჟიმის გადამრთველი პარამეტრების ეკრანზე, გაუშვით აპლიკაცია iOS სიმულატორში და მაჩვენეთ სკრინშოტი.

Amp ინარჩუნებს კოდის რედაქტირებას იქ, სადაც ის მუშაობს. Mac-ზე ყოველი ბრძანების შესრულებამდე, პლაგინი უშვებს `tuist sandbox sync`-ს, რომელიც აკოპირებს ფაილებს, რომლებსაც Git არ იგნორირებს (დაკომიტებული იქნება თუ არა), ხოლო შემდეგ მხოლოდ იმ ფაილებს, რომლებიც შეიცვალა. აგების პროდუქტები და სხვა იგნორირებული ფაილები, რომლებსაც Mac ქმნის, რჩება იქ, რაც უზრუნველყოფს ინკრემენტულ აგებას. პლაგინი ამატებს ამ ინსტრუმენტებს და `remote-mac` უნარს, რომელიც ეუბნება Amp-ს, როდის და როგორ გამოიყენოს ისინი:

| ინსტრუმენტი | რა აკეთებს |
| --- | --- |
| `tuist_mac_start` | ქმნის ნაკადის Mac-ს, ან ხელახლა იყენებს მას და ასინქრონებს |
| `tuist_mac_shell` | ასინქრონებს, შემდეგ უშვებს ბრძანებას Mac-ზე |
| `tuist_mac_screenshot` | აჩვენებს სიმულატორს ან ეკრანს ნაკადში |
| `tuist_mac_download` | აბრუნებს ფაილს, მაგალითად, აგებულ `.app`-ს |
| `tuist_mac_stop` | შლის ნაკადის Mac-ს |

Mac-ს არ აქვს საკუთარი Tuist CLI: პირველი სინქრონიზაციის შემდეგ, Amp უშვებს `mise install`-ს რეპოზიტორიის ძირში, რათა დაინსტალირდეს პროექტის მიერ მიმაგრებული Tuist, ხოლო `tuist_mac_shell` ამატებს mise-ის shims-ებს `PATH`-ზე. Mac-ზე ყოველი ბრძანება <.localized_link href="/guides/features/sandboxes#tuist-in-sandbox">შედის თქვენი ანგარიშის cache-ში</.localized_link> დამოუკიდებლად Tuist 4.218.0 ან უფრო ახალი ვერსიით; 4.215.0-დან 4.217.x-მდე ვერსიებში, Amp ჯერ უშვებს `tuist auth login`-ს.

ნაკადი იყენებს ერთ Mac-ს. Amp გადასცემს `tuist_mac_start`-ს <.localized_link href="/guides/features/sandboxes#xcode">Xcode</.localized_link>-ს, რომელსაც რეპოზიტორია ამაგრებს, მაგალითად `.xcode-version`-ში, ან შეგიძლიათ მოითხოვოთ კონკრეტული ("გამოიყენე Xcode 26.1.1"); მისი გარეშე, Mac უშვებს ნაგულისხმევს. Mac ინარჩუნებს თავის Xcode-ს, ამიტომ გადართვა ნიშნავს მის გაჩერებას და სხვის გაშვებას. Tuist აჩერებს მას, როცა ის უმოქმედოა და შემდეგი ბრძანება აღადგენს მას. Amp შლის მას, როცა დავალება დასრულებულია; დარჩენილი Mac იშლება 14 დღიანი შეჩერების შემდეგ. Mac-ები ითვლება თქვენი Tuist ანგარიშისთვის, როგორც ნებისმიერი სხვა sandbox.

### მისი მოწყობა {#remote-mac-setup}

1. **დააინსტალირეთ პლაგინი.** ეს არის ერთი ფაილი, [`tuist-mac.ts`](https://github.com/tuist/tuist/blob/main/.amp/plugins/tuist-mac.ts). იმისათვის, რომ ის ხელმისაწვდომი იყოს თქვენი Amp workspace-ის ყველა წევრისთვის, workspace-ის ადმინისტრატორი სთხოვს Amp-ს ნაკადში:

   > დაამატე https://raw.githubusercontent.com/tuist/tuist/main/.amp/plugins/tuist-mac.ts ჩვენს workspace პლაგინებში.

   Amp აკომიტებს მას workspace-ის [პლაგინების რეპოზიტორიაში](https://ampcode.com/docs/customize/global-plugins-and-skills) და სთხოვს ნებართვას push-მდე. სთხოვეთ "ჩემი პირადი პლაგინები", რათა დააინსტალიროთ ის მხოლოდ საკუთარი თავისთვის, ან შეინახეთ ფაილი როგორც `.amp/plugins/tuist-mac.ts` რეპოზიტორიაში, რათა გამოიყენოთ მხოლოდ იქ. პლაგინი არის ასლი: მის განახლებამდე, სთხოვეთ Amp-ს ჩაანაცვლოს ის იმავე URL-ის უახლესი ვერსიით.
2. **დააინსტალირეთ Tuist CLI** იქ, სადაც Amp მუშაობს. orb-ებზე, დაამატეთ ის რეპოზიტორიის [`.agents/setup`](https://ampcode.com/docs/orbs/customizing) სკრიპტში, მაგალითად `mise use -g tuist@latest`, ან `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist`.
3. **მიეცით CLI-ს თქვენი ანგარიშის sandbox-ების გამოყენების უფლება.** orb-ებზე, დააკავშირეთ თქვენი Amp workspace თქვენს Tuist ანგარიშთან, როგორც ეს აღწერილია <.localized_link href="/guides/server/authentication#amp-orbs">Amp orbs</.localized_link>-ში. orb-ები შემდეგ შედიან სისტემაში დამოუკიდებლად, sandbox-ებზე წვდომით. სხვაგან, მაგალითად, Amp CLI Linux მანქანაზე, გაუშვით `tuist auth login` ანგარიშის წევრად, ან დააყენეთ `TUIST_MAC_TOKEN` <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენზე</.localized_link> `account:sandboxes:write` scope-ით, პლიუს `ci` Mac-ის მიერ cache-ის გამოსაყენებლად. პლაგინი გადასცემს `TUIST_MAC_TOKEN`-ს CLI-ს `TUIST_TOKEN`-ის ნაცვლად, ამიტომ დააყენეთ ის მაშინაც, როცა თქვენს orb-ებს უკვე აქვთ `TUIST_TOKEN` ამ scope-ის გარეშე.
4. **მიუთითეთ, რომელი ანგარიში გამოიყენოს**, თუ რეპოზიტორიას არ აქვს `tuist.toml` `project = "<account>/<project>"`-ით. Linux-ზე, CLI-ს არ შეუძლია წაიკითხოს ანგარიში `Tuist.swift`-დან. დააყენეთ `TUIST_MAC_ACCOUNT` თქვენს ანგარიშის handle-ზე თქვენი Amp პროექტის გარემოს ცვლადებში. მის გარეშე, Amp გადასცემს ანგარიშს `Tuist.swift`-ის `fullHandle`-დან `tuist_mac_start`-ზე.

CLI უკავშირდება Mac-ს მხოლოდ `tuist.dev`-ის მეშვეობით, ამიტომ გარემომ, რომელიც ზღუდავს ქსელურ წვდომას, უნდა დაუშვას მხოლოდ ეს დომენი. CLI-ის გამოსაყენებლად, რომელიც არ არის `PATH`-ზე, დააყენეთ `TUIST_MAC_CLI` მის გზაზე.

აგენტები, რომლებიც არ უჭერენ მხარს Amp პლაგინებს, მაგალითად Claude Code ან Cursor, შეუძლიათ გააკეთონ იგივე Tuist MCP სერვერისა და CLI-ის მეშვეობით, როგორც ეს აღწერილია <.localized_link href="/guides/features/sandboxes#coding-agents">აგება Mac-ზე კოდირების აგენტისგან</.localized_link>.

### გამოიყენეთ Tuist Mac-ები Amp-ის macOS Satellites-ის ნაცვლად {#remote-mac-satellites}

Amp-ს ასევე აქვს საკუთარი ღრუბლოვანი Mac-ები, [macOS Satellites](https://ampcode.com/docs/orbs/mac), ბეტა ვერსიაში იმ workspace-ებისთვის, რომლებიც შეუერთდნენ მის მოლოდინის სიას. როდესაც ნაკადს შეუძლია ორივეს გაშვება, Amp-ის ჩაშენებული ინსტრუქციები macOS სამუშაოს უგზავნიან მის სატელიტებს, ამიტომ ის იშვიათად ირჩევს პლაგინს. იმისათვის, რომ ნაკადებმა გამოიყენონ Tuist Mac-ები, გააკეთეთ ერთ-ერთი შემდეგი:

- **გამორთეთ macOS Satellites საკუთარი თავისთვის.** თითოეული წევრი თიშავს მათ **Mac Satellites** ქვეშ Amp-ის [Settings → Experimental Features](https://ampcode.com/settings/experimental-features) მენიუში.
- **გამორთეთ ისინი workspace-ისთვის.** როდესაც თქვენი workspace-ის orb-ები [მუშაობენ Tuist-ზე](#connect), workspace-ის ადმინისტრატორს შეუძლია დააყენოს **Where Orbs Run** **Self-Hosted Only**-ზე Amp-ის workspace პარამეტრებში, **Orbs** ქვეშ. აგენტები შემდეგ ვერ გაუშვებენ Amp-ის მიერ განთავსებულ სატელიტებს, მაგრამ წევრები ასევე ვერ გამოიყენებენ Amp-ის ჩაშენებულ orb-ებს, ამიტომ გააკეთეთ ეს მხოლოდ მაშინ, როცა თქვენი ყველა ნაკადი მუშაობს თქვენს საკუთარ orb პროვაიდერებზე.
- **მოითხოვეთ Tuist Mac-ები.** დაამატეთ "გამოიყენეთ `tuist_mac_*` ინსტრუმენტები macOS სამუშაოსთვის, არა macOS Satellites." prompt-ში, ან თქვენი workspace-ის აგენტის მითითებებში Amp-ის workspace პარამეტრებში, რათა ყოველმა ნაკადმა მიჰყვეს მას.
