# Amp {#amp}

> [!IMPORTANT]
> **მხოლოდ მოწვევით**
>
> Tuist Sandboxes, როგორც Linux-ზე, ისე macOS-ზე, ამჟამად მხოლოდ მოწვევითაა ხელმისაწვდომი. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [საზოგადოების Slack-ში](https://slack.tuist.dev), რათა თქვენს ანგარიშზე წვდომა მოითხოვოთ.

[Amp](https://ampcode.com) თითოეული ძაფის ინსტრუმენტებს [orb-ში](https://ampcode.com/docs/orbs) უშვებს — ეს არის მანქანა, სადაც ძაფის რეპოზიტორია გადმოწერილია. Tuist შეიძლება იყოს თქვენი Amp სამუშაო სივრცის [თვითმასპინძელი orb პროვაიდერი](https://ampcode.com/docs/orbs/self-hosted): ყოველი ძაფი, რომელიც მას აირჩევს, საკუთარ Tuist <.localized_link href="/guides/features/sandboxes">sandbox-ში</.localized_link> გაეშვება, Linux-ზე ან macOS-ზე. თქვენ თავად არაფერს უშვებთ ან მასპინძლობთ.

## Amp-ის მიერთება {#connect}

უნდა იყოთ ადმინისტრატორი როგორც Amp სამუშაო სივრცის, ისე Tuist ანგარიშისთვის.

1. Amp-ში გახსენით თქვენი სამუშაო სივრცის **Settings → Orbs**, დააჭირეთ **Add Orb Provider** და მიანიჭეთ სახელი, მაგალითად `tuist`. წევრები პროვაიდერს ამ სახელით ირჩევენ. დააკოპირეთ `aop_live_…` ტოკენი; Amp მას მხოლოდ ერთხელ აჩვენებს.
2. პროვაიდერის **Edit** დიალოგში Amp-ში, დაამატეთ ეს **Orb ტიპები** და აირჩიეთ ნაგულისხმევი:

   | ტიპი | პლატფორმა | კონფიგურაცია |
   | --- | --- | --- |
   | `linux` | Linux | 2 vCPU, 4 GiB RAM, 10 GB სამუშაო სივრცე |
   | `macos` | macOS Xcode-ით | 8 vCPU, 8 GiB RAM, 10 GB სამუშაო სივრცე |

3. Tuist-ში გახსენით **Sandboxes** თქვენი ანგარიშის დაფაზე, Amp ბარათზე დააჭირეთ **Connect** და ჩასვით ტოკენი.

ბარათი აჩვენებს **Connected**-ს, როგორც კი Tuist პროვაიდერს ემსახურება. ერთი Tuist ანგარიში ერთ პროვაიდერს ემსახურება. ნებისმიერი, ვისაც Amp-ში პროვაიდერის გამოყენება შეუძლია, orb-ებს უშვებს დახარჯვით მიერთებულ Tuist ანგარიშზე. შესაჩერებლად, ბარათზე დააჭირეთ **Disconnect**, ან გამორთეთ პროვაიდერი Amp-ში.

## ძაფის დაწყება {#start-a-thread}

Amp-ის ახალი ძაფის შემქმნელში დააჭირეთ **Orb**, აირჩიეთ Tuist პროვაიდერი **Self-Hosted** ქვეშ და აირჩიეთ `linux` ან `macos`. Amp CLI-დან:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos
```

ძაფი თავის orb ტიპს მთელი სიცოცხლის განმავლობაში ინარჩუნებს. ტიპის გარეშე, ის პროვაიდერის ნაგულისხმევს იღებს. ყოველი ახალი ძაფისთვის ერთი პლატფორმის გამოსაყენებლად, აირჩიეთ პროვაიდერი და მისი ტიპი Amp-ის **Settings → Orbs**-ში **Default Orb** ქვეშ.

Amp აკლონებს რეპოზიტორიას, უშვებს თქვენს `.agents/setup` სკრიპტს და აყენებს Git კრედენციალებს, როგორც ყოველი orb-ისთვის. თითოეულ orb-ს ასევე შეუძლია წაიკითხოს თქვენი ანგარიშის Tuist <.localized_link href="/guides/features/cache">cache</.localized_link>.

## შეჩერება და შენახვა {#retention}

როდესაც ძაფი უმოქმედო ხდება, Amp აჩერებს მის orb-ს. შემდეგი შეტყობინება აღადგენს მას ფაილების უცვლელობით.

- **Linux:** გაშვებული პროცესები შეჩერების შემდეგაც რჩება. orb, რომელიც დიდი ხნით იყო შეჩერებული, გადადის არქივის საცავში და აღდგება შემდეგი შეტყობინებისას, პროცესების გარეშე. Linux orb-ები ინარჩუნებენ თავიანთ ფაილებს, სანამ Amp ძაფის orb-ს წაშლის.
- **macOS:** orb, რომელიც 7 დღის განმავლობაში შეჩერებულია ან შეცდომის მდგომარეობაშია, იშლება. ძაფის შემდეგი შეტყობინება ახალ orb-ს იწყებს და Amp ხელახლა უშვებს `.agents/setup`-ს. მანქანაზე პირველი macOS orb აყენებს Amp CLI-ს, ამიტომ გაშვებას ორ წუთამდე შეიძლება დასჭირდეს.

orb, რომელიც უმოქმედოდ რჩება Amp-ის შეჩერების გარეშე, მაგალითად, იმიტომ, რომ შეჩერების ბრძანება არ მიუღია, ათი წუთის შემდეგ ჩერდება CPU-ს თითქმის ნულოვანი გამოყენებით.
