# Amp {#amp}

> [!IMPORTANT]
> **მხოლოდ მოწვევით**
>
> Tuist Sandboxes, როგორც Linux-ის, ისე macOS-ის ვერსიები, ამჟამად მხოლოდ მოწვევითაა ხელმისაწვდომი. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [საზოგადოების Slack-ში](https://slack.tuist.dev), რათა თქვენი ანგარიშისთვის წვდომა მოითხოვოთ.

[Amp](https://ampcode.com) თითოეული ნაკადის ინსტრუმენტებს უშვებს [orb-ში](https://ampcode.com/docs/orbs) — მანქანაზე, სადაც ნაკადის რეპოზიტორია გადმოწერილი. Tuist შეიძლება იყოს თქვენი Amp სამუშაო სივრცის [თვითმასპინძელი orb პროვაიდერი](https://ampcode.com/docs/orbs/self-hosted): ყოველი ნაკადი, რომელიც მას აირჩევს, გაეშვება საკუთარ Tuist <.localized_link href="/guides/features/sandboxes">sandbox-ში</.localized_link>, Linux-ზე ან macOS-ზე. თქვენ არაფერს უშვებთ და არ მასპინძლობთ თავად.

იმისათვის, რომ ნაკადები დარჩეს მათ მიმდინარე orb-ებზე და Apple-პლატფორმის კოდი მხოლოდ Mac-ზე ააწყოთ, გაატესტოთ და გაუშვათ, გამოიყენეთ [Tuist Mac პლაგინი](#remote-mac).

## Amp-ის მიერთება {#connect}

თქვენ უნდა იყოთ ადმინისტრატორი როგორც Amp სამუშაო სივრცეში, ისე Tuist ანგარიშში.

1. Amp-ში გახსენით თქვენი სამუშაო სივრცის **Settings → Orbs**, დააჭირეთ **Add Orb Provider** და მიანიჭეთ სახელი, მაგალითად `tuist`. წევრები პროვაიდერს ამ სახელით ირჩევენ. დააკოპირეთ `aop_live_…` ტოკენი; Amp მას მხოლოდ ერთხელ აჩვენებს.
2. პროვაიდერის **Edit** დიალოგში Amp-ში დაამატეთ **Orb ტიპები**, რომლებიც გსურთ შესთავაზოთ, და აირჩიეთ ნაგულისხმევი. Linux-ის ტიპები ემთხვევა [Amp-ის საკუთარი orb-ების](https://ampcode.com/docs/orbs/sizes-and-costs) ზომებს:

   | ტიპი | პლატფორმა | კონფიგურაცია |
   | --- | --- | --- |
   | `linux` | Linux | 4 vCPU, 8 GiB RAM, 10 GB სამუშაო სივრცე |
   | `linux-tiny` | Linux | 1 vCPU, 2 GiB RAM, 10 GB სამუშაო სივრცე |
   | `linux-small` | Linux | 2 vCPU, 4 GiB RAM, 10 GB სამუშაო სივრცე |
   | `linux-medium` | Linux | 4 vCPU, 8 GiB RAM, 10 GB სამუშაო სივრცე (იგივე, რაც `linux`) |
   | `linux-large` | Linux | 8 vCPU, 16 GiB RAM, 10 GB სამუშაო სივრცე |
   | `linux-xxlarge` | Linux | 16 vCPU, 32 GiB RAM, 10 GB სამუშაო სივრცე |
   | `linux-3xlarge` | Linux | 16 vCPU, 44 GiB RAM, 10 GB სამუშაო სივრცე |
   | `macos` | macOS ნაგულისხმევი Xcode-ით | 8 vCPU, 8 GiB RAM, 10 GB სამუშაო სივრცე |
   | `macos-xcode-<version>` | macOS ამ Xcode-ით, მაგალითად `macos-xcode-26-1-1` Xcode 26.1.1-ისთვის | 8 vCPU, 8 GiB RAM, 10 GB სამუშაო სივრცე |

3. Tuist-ში გახსენით **Sandboxes** თქვენი ანგარიშის დაფაზე, დააჭირეთ **Connect** Amp ბარათზე და ჩასვით ტოკენი.

ბარათი აჩვენებს **Connected**-ს, როდესაც Tuist ემსახურება პროვაიდერს. ერთი Tuist ანგარიში ემსახურება ერთ პროვაიდერს. ყველა, ვისაც Amp-ში პროვაიდერის გამოყენება შეუძლია, უშვებს orb-ებს და ხარჯები ერიცხება მიერთებულ Tuist ანგარიშს. გასათიშად დააჭირეთ **Disconnect** ბარათზე ან გამორთეთ პროვაიდერი Amp-ში.

## ნაკადის დაწყება {#start-a-thread}

Amp-ის ახალი ნაკადის შემქმნელში დააჭირეთ **Orb**, აირჩიეთ Tuist პროვაიდერი **Self-Hosted** ქვეშ და აირჩიეთ ტიპი, მაგალითად `linux-small` რეპოზიტორიისთვის, რომელსაც `linux`-ზე ნაკლები სჭირდება, ან `linux-large` იმისთვის, რომელსაც მეტი სჭირდება. Amp CLI-დან:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos
```

ნაკადი ინარჩუნებს თავის orb ტიპს მთელი სიცოცხლის განმავლობაში. ტიპის მითითების გარეშე, ის იღებს პროვაიდერის ნაგულისხმევს. იმისათვის, რომ ყოველ ახალ ნაკადში ერთი ტიპი გამოიყენოთ, აირჩიეთ პროვაიდერი და მისი ტიპი **Default Orb** ქვეშ Amp-ის **Settings → Orbs** განყოფილებაში.

### Xcode-ის არჩევა {#xcode}

`macos` უშვებს ნაგულისხმევ <.localized_link href="/guides/features/sandboxes#xcode">Xcode</.localized_link>-ს. სხვისთვის დაამატეთ orb ტიპი, რომელიც მის სახელს ატარებს, წერტილების დეფისებით ჩანაცვლებით: `macos-xcode-26-1-1` უშვებს Xcode 26.1.1-ს, `macos-xcode-27-0` — Xcode 27.0-ს. დაამატეთ თითოეული Xcode-ისთვის, რომელსაც თქვენი რეპოზიტორიები ამაგრებენ, და აირჩიეთ ის ნაკადის მიხედვით, როგორც ნებისმიერი სხვა ტიპი:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos-xcode-26-1-1
```

ტიპი იმ Xcode-ისთვის, რომელსაც Tuist არ სთავაზობს, ახალი orb-ის გაშვებისას მართავს შეცდომას. orb, რომელიც Tuist-მა უკვე გაუშვა ამ ტიპზე, განაგრძობს აღდგენას მას შემდეგ, რაც Tuist წყვეტს ამ Xcode-ის შეთავაზებას.

Amp აკლონებს რეპოზიტორიას, უშვებს თქვენს `.agents/setup` სკრიპტს და აყენებს Git-ის სერთიფიკატებს, როგორც ეს ყოველი orb-ისთვის ხდება. თითოეულ orb-ს ასევე შეუძლია წაიკითხოს თქვენი ანგარიშის Tuist <.localized_link href="/guides/features/cache">cache</.localized_link>.

## შეჩერება და შენახვა {#retention}

როდესაც ნაკადი უმოქმედო ხდება, Amp აჩერებს მის orb-ს. შემდეგი შეტყობინება აღადგენს მას ფაილების უცვლელობით.

- **Linux:** გაშვებული პროცესები ინარჩუნებენ სიცოცხლეს შეჩერების დროს. orb, რომელიც დიდი ხნით იყო შეჩერებული, გადადის საარქივო საცავში და აღდგება შემდეგი შეტყობინებისას, მაგრამ პროცესების გარეშე. Linux orb-ები ინარჩუნებენ თავიანთ ფაილებს მანამ, სანამ Amp არ წაშლის ნაკადის orb-ს.
- **macOS:** orb, რომელიც 7 დღის განმავლობაში შეჩერებულია ან შეცდომის მდგომარეობაშია, იშლება. ნაკადის შემდეგი შეტყობინება ქმნის ახალ orb-ს და Amp კვლავ უშვებს `.agents/setup`-ს. პირველი macOS orb მანქანაზე აყენებს Amp CLI-ს, ამიტომ გაშვებას შეიძლება ორ წუთამდე დასჭირდეს.

orb, რომელიც რჩება უმოქმედოდ Amp-ის მიერ შეჩერების გარეშე (მაგალითად, თუ შეჩერების ბრძანება არ მივიდა), ჩერდება ათი წუთის შემდეგ CPU-ს თითქმის ნულოვანი გამოყენებით.

## Mac-ის გამოყენება ნებისმიერი Amp ნაკადიდან {#remote-mac}

Tuist Mac პლაგინი Amp ნაკადს აწვდის macOS sandbox-ს Xcode-ით, iOS სიმულატორებით და Homebrew-ით, მაშინ როცა ნაკადი განაგრძობს მუშაობას იქ, სადაც ის არის, მაგალითად, Amp-ის ერთ-ერთ Linux orb-ზე. სთხოვეთ Amp-ს სამუშაოს შესრულება და ის გაუშვებს Mac-ს, როდესაც ეს საჭირო გახდება:

> დაამატე ბნელი რეჟიმის გადამრთველი პარამეტრების ეკრანზე, გაუშვი აპლიკაცია iOS სიმულატორში და მაჩვენე სკრინშოტი.

Amp ინარჩუნებს კოდის რედაქტირებას იქ, სადაც ის მუშაობს. Mac-ზე ყოველი ბრძანების შესრულებამდე პლაგინი უშვებს `tuist sandbox sync`-ს, რომელიც აკოპირებს ფაილებს, რომლებსაც Git არ იგნორირებს (მიუხედავად იმისა, არიან თუ არა ისინი კომიტებულნი), ხოლო შემდეგ მხოლოდ შეცვლილ ფაილებს. აწყობის პროდუქტები და Mac-ის მიერ შექმნილი სხვა იგნორირებული ფაილები რჩება იქ, რაც უზრუნველყოფს აწყობის ინკრემენტულობას. პლაგინი ამატებს ამ ინსტრუმენტებს და `remote-mac` უნარს, რომელიც ეუბნება Amp-ს, როდის და როგორ გამოიყენოს ისინი:

| ინსტრუმენტი | რა კეთდება |
| --- | --- |
| `tuist_mac_start` | ქმნის ნაკადის Mac-ს, ან ხელახლა იყენებს მას და ასინქრონებს |
| `tuist_mac_shell` | ასინქრონებს, შემდეგ უშვებს ბრძანებას Mac-ზე |
| `tuist_mac_screenshot` | აჩვენებს სიმულატორს ან ეკრანს ნაკადში |
| `tuist_mac_download` | აბრუნებს ფაილს, მაგალითად, აწყობილ `.app`-ს |
| `tuist_mac_stop` | შლის ნაკადის Mac-ს |

Mac-ს არ აქვს საკუთარი Tuist CLI: პირველი სინქრონიზაციის შემდეგ Amp უშვებს `mise install`-ს რეპოზიტორიის ძირში, რათა დაინსტალირდეს პროექტის მიერ მიმაგრებული Tuist, ხოლო `tuist_mac_shell` ამატებს mise-ის shims-ებს `PATH`-ში. Mac-ზე ყოველი ბრძანება <.localized_link href="/guides/features/sandboxes#tuist-in-sandbox">შედის თქვენი ანგარიშის cache-ში</.localized_link> დამოუკიდებლად Tuist 4.218.0 ან უფრო ახალი ვერსიით; 4.215.0-დან 4.217.x-მდე ვერსიების შემთხვევაში Amp ჯერ უშვებს `tuist auth login`-ს.

ნაკადი იყენებს ერთ Mac-ს. Amp გადასცემს `tuist_mac_start`-ს <.localized_link href="/guides/features/sandboxes#xcode">Xcode</.localized_link>-ს, რომელსაც რეპოზიტორია ამაგრებს (მაგალითად, `.xcode-version`-ში), ან შეგიძლიათ მოითხოვოთ კონკრეტული („გამოიყენე Xcode 26.1.1“); მის გარეშე Mac უშვებს ნაგულისხმევს. Mac ინარჩუნებს თავის Xcode-ს, ამიტომ გადართვა ნიშნავს მის შეჩერებას და სხვის გაშვებას. Tuist აჩერებს მას უმოქმედობისას და შემდეგი ბრძანება აღადგენს. Amp შლის მას, როდესაც დავალება სრულდება; მიტოვებული Mac იშლება 14 დღიანი შეჩერების შემდეგ. Mac-ები ითვლება თქვენი Tuist ანგარიშისთვის, როგორც ნებისმიერი სხვა sandbox.

### მისი დაყენება {#remote-mac-setup}

1. **დააინსტალირეთ პლაგინი.** ეს არის ერთი ფაილი, [`tuist-mac.ts`](https://github.com/tuist/tuist/blob/main/.amp/plugins/tuist-mac.ts). იმისათვის, რომ ის ხელმისაწვდომი იყოს თქვენი Amp workspace-ის ყველა წევრისთვის, workspace-ის ადმინისტრატორი სთხოვს Amp-ს ნაკადში:

   > დაამატე https://raw.githubusercontent.com/tuist/tuist/main/.amp/plugins/tuist-mac.ts ჩვენს workspace პლაგინებში.

   Amp აკომიტებს მას workspace-ის [პლაგინების რეპოზიტორიაში](https://ampcode.com/docs/customize/global-plugins-and-skills) და სთხოვს ნებართვას push-მდე. სთხოვეთ „ჩემი პირადი პლაგინები“, რათა დააინსტალიროთ ის მხოლოდ საკუთარ თავზე, ან შეინახეთ ფაილი როგორც `.amp/plugins/tuist-mac.ts` რეპოზიტორიაში, რათა გამოიყენოთ მხოლოდ იქ. პლაგინი არის ასლი: მის განახლებისთვის სთხოვეთ Amp-ს ჩაანაცვლოს ის იმავე URL-ის უახლესი ვერსიით.
2. **დააინსტალირეთ Tuist CLI** იქ, სადაც Amp მუშაობს. orb-ებზე დაამატეთ ის რეპოზიტორიის [`.agents/setup`](https://ampcode.com/docs/orbs/customizing) სკრიპტში, მაგალითად `mise use -g tuist@latest`, ან `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist`.
3. **მიეცით CLI-ს თქვენი ანგარიშის sandbox-ების გამოყენების უფლება.** orb-ებზე დააკავშირეთ თქვენი Amp workspace თქვენს Tuist ანგარიშთან, როგორც აღწერილია <.localized_link href="/guides/server/authentication#amp-orbs">Amp orbs</.localized_link>-ში. orb-ები შემდეგ დამოუკიდებლად შედიან, sandbox-ებზე წვდომით. სხვაგან, მაგალითად, Amp CLI-ზე Linux მანქანაზე, გაუშვით `tuist auth login` როგორც ანგარიშის წევრმა, ან დააყენეთ `TUIST_MAC_TOKEN` <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენზე</.localized_link> `account:sandboxes:write` scope-ით, პლუს `ci` Mac-ის მიერ cache-ის გამოსაყენებლად. პლაგინი გადასცემს `TUIST_MAC_TOKEN`-ს CLI-ს `TUIST_TOKEN`-ის ნაცვლად, ამიტომ დააყენეთ ის მაშინაც, როცა თქვენს orb-ებს უკვე აქვთ `TUIST_TOKEN` ამ scope-ის გარეშე.
4. **მიუთითეთ, რომელი ანგარიში გამოიყენოს**, თუ რეპოზიტორიას არ აქვს `tuist.toml` `project = "<account>/<project>"`-ით. Linux-ზე CLI-ს არ შეუძლია წაიკითხოს ანგარიში `Tuist.swift`-დან. დააყენეთ `TUIST_MAC_ACCOUNT` თქვენს ანგარიშის handle-ზე თქვენი Amp პროექტის გარემოს ცვლადებში. მის გარეშე, Amp გადასცემს ანგარიშს `Tuist.swift`-ის `fullHandle`-დან `tuist_mac_start`-ში.

CLI აღწევს Mac-ს მხოლოდ `tuist.dev`-ის მეშვეობით, ამიტომ გარემომ, რომელიც ზღუდავს ქსელურ წვდომას, უნდა დაუშვას მხოლოდ ეს დომენი. იმ CLI-ის გამოყენებისთვის, რომელიც არ არის `PATH`-ში, დააყენეთ `TUIST_MAC_CLI` მის გზაზე.

აგენტებს, რომლებიც არ უჭერენ მხარს Amp პლაგინებს, როგორიცაა Claude Code ან Cursor, შეუძლიათ იგივე გააკეთონ Tuist MCP სერვერისა და CLI-ის მეშვეობით, როგორც აღწერილია <.localized_link href="/guides/features/sandboxes#coding-agents">Mac-ზე აწყობა კოდინგის აგენტისგან</.localized_link>.

### Tuist Mac-ების გამოყენება Amp-ის macOS Satellites-ის ნაცვლად {#remote-mac-satellites}

Amp-ს ასევე აქვს საკუთარი ღრუბლოვანი Mac-ები, [macOS Satellites](https://ampcode.com/docs/orbs/mac), ბეტა ვერსიაში იმ workspace-ებისთვის, რომლებიც შეუერთდნენ მის მოლოდინის სიას. როდესაც ნაკადს შეუძლია ორივეს გაშვება, Amp-ის ჩაშენებული ინსტრუქციები macOS სამუშაოს აგზავნის მის სატელიტებზე, ამიტომ ის იშვიათად ირჩევს პლაგინს. იმისათვის, რომ ნაკადებმა გამოიყენონ Tuist Mac-ები, გააკეთეთ ერთ-ერთი შემდეგი:

- **გამორთეთ macOS Satellites საკუთარი თავისთვის.** თითოეული წევრი თიშავს მათ **Mac Satellites**-ის ქვეშ Amp-ის [Settings → Experimental Features](https://ampcode.com/settings/experimental-features) განყოფილებაში.
- **გამორთეთ ისინი workspace-ისთვის.** როდესაც თქვენი workspace-ის orb-ები [მუშაობენ Tuist-ზე](#connect), workspace-ის ადმინისტრატორს შეუძლია დააყენოს **Where Orbs Run** მნიშვნელობად **Self-Hosted Only** Amp-ის workspace პარამეტრებში, **Orbs**-ის ქვეშ. აგენტები შემდეგ ვერ გაუშვებენ Amp-ის მიერ დაჰოსტებულ სატელიტებს, მაგრამ წევრებიც ვერ გამოიყენებენ Amp-ის ჩაშენებულ orb-ებს, ამიტომ გააკეთეთ ეს მხოლოდ მაშინ, როცა თქვენი ყველა ნაკადი მუშაობს თქვენს საკუთარ orb პროვაიდერებზე.
- **მოითხოვეთ Tuist Mac-ები.** დაამატეთ „გამოიყენე `tuist_mac_*` ინსტრუმენტები macOS სამუშაოსთვის, არა macOS Satellites.“ მოთხოვნაში, ან თქვენი workspace-ის აგენტის მითითებებში Amp-ის workspace პარამეტრებში, რათა ყოველმა ნაკადმა დაიცვას ის.
