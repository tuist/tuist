# Amp {#amp}

> [!IMPORTANT]
> **მხოლოდ მიწვევით**
>
> Tuist Sandboxes, როგორც Linux-ზე, ასევე macOS-ზე, ამჟამად მხოლოდ მიწვევითაა ხელმისაწვდომი. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [საზოგადოების Slack-ში](https://slack.tuist.dev), რათა თქვენი ანგარიშისთვის წვდომა მოითხოვოთ.

[Amp](https://ampcode.com) თითოეული ნაკადის ინსტრუმენტებს აწარმოებს [orb-ში](https://ampcode.com/docs/orbs) — მანქანაში, სადაც ნაკადის რეპოზიტორია გადმოწერილია. Tuist შეიძლება იყოს თქვენი Amp სამუშაო სივრცის [თვითმასპინძელი orb პროვაიდერი](https://ampcode.com/docs/orbs/self-hosted): ყოველი ნაკადი, რომელიც მას ირჩევს, თავის Tuist <.localized_link href="/guides/features/sandboxes">sandbox-ში</.localized_link> ეშვება, Linux-ზე ან macOS-ზე. თქვენ არაფერს უშვებთ ან მასპინძლობთ საკუთრად.

იმისთვის, რომ თქვენი ნაკადები დარჩეს მათ მიმდინარე orb-ებზე და Apple-პლატფორმის კოდი მხოლოდ Mac-ზე ააწყოთ, ტესტიროთ და გაუშვათ, გამოიყენეთ [Tuist Mac პლაგინი](#remote-mac).

## Amp-ის დაკავშირება {#connect}

თქვენ უნდა იყოთ ადმინისტრატორი როგორც Amp სამუშაო სივრცეში, ასევე Tuist ანგარიშში.

1. Amp-ში გახსენით თქვენი სამუშაო სივრცის **Settings → Orbs**, დააჭირეთ **Add Orb Provider** და მიანიჭეთ სახელი, მაგალითად `tuist`. წევრები პროვაიდერს ამ სახელით ირჩევენ. დააკოპირეთ `aop_live_…` ტოკენი; Amp მას მხოლოდ ერთხელ აჩვენებს.
2. პროვაიდერის **Edit** დიალოგში Amp-ში დაამატეთ **Orb ტიპები**, რომლებიც გსურთ შესთავაზოთ, და აირჩიეთ ნაგულისხმები. Linux ტიპები ემთხვევა [Amp-ის საკუთარი orb-ების](https://ampcode.com/docs/orbs/sizes-and-costs) ზომებს:

   | ტიპი | პლატფორმა | კონფიგურაცია |
   | --- | --- | --- |
   | `linux` | Linux | 4 vCPU, 8 GiB RAM, 10 GB სამუშაო სივრცე |
   | `linux-tiny` | Linux | 1 vCPU, 2 GiB RAM, 10 GB სამუშაო სივრცე |
   | `linux-small` | Linux | 2 vCPU, 4 GiB RAM, 10 GB სამუშაო სივრცე |
   | `linux-medium` | Linux | 4 vCPU, 8 GiB RAM, 10 GB სამუშაო სივრცე (იგივე, რაც `linux`) |
   | `linux-large` | Linux | 8 vCPU, 16 GiB RAM, 10 GB სამუშაო სივრცე |
   | `linux-xxlarge` | Linux | 16 vCPU, 32 GiB RAM, 10 GB სამუშაო სივრცე |
   | `linux-3xlarge` | Linux | 16 vCPU, 44 GiB RAM, 10 GB სამუშაო სივრცე |
   | `macos` | macOS Xcode-ით | 8 vCPU, 8 GiB RAM, 10 GB სამუშაო სივრცე |

3. Tuist-ში გახსენით **Sandboxes** თქვენი ანგარიშის დაფაზე, Amp-ის ბარათზე დააჭირეთ **Connect** და ჩასვით ტოკენი.

ბარათი აჩვენებს **Connected**-ს, როგორც კი Tuist მოემსახურება პროვაიდერს. ერთი Tuist ანგარიში ერთ პროვაიდერს ემსახურება. ყველა, ვინც Amp-ში პროვაიდერის გამოყენებას შეძლებს, orb-ებს ამ დაკავშირებულ Tuist ანგარიშზე უშვებს და მასზე ხდება გადახდაც. შეწყვეტისთვის ბარათზე დააჭირეთ **Disconnect** ან გამორთეთ პროვაიდერი Amp-ში.

## ნაკადის დაწყება {#start-a-thread}

Amp-ის ახალი ნაკადის შემქმნელში დააჭირეთ **Orb**, აირჩიეთ Tuist პროვაიდერი **Self-Hosted** ქვეშ და აირჩიეთ ტიპი, მაგალითად `linux-small` რეპოზიტორიისთვის, რომელსაც `linux`-ზე ნაკლები სჭირდება, ან `linux-large` იმისთვის, რომელსაც მეტი სჭირდება. Amp CLI-დან:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos
```

ნაკადი თავის orb ტიპს მთელი სიცოცხლის განმავლობაში ინარჩუნებს. ტიპის მითითების გარეშე ის პროვაიდერის ნაგულისხმევს იღებს. იმისთვის, რომ ყოველ ახალ ნაკადში ერთი ტიპი გამოიყენოთ, აირჩიეთ პროვაიდერი და მისი ტიპი Amp-ის **Settings → Orbs** განყოფილებაში **Default Orb** ქვეშ.

Amp აკლონებს რეპოზიტორიას, ასრულებს თქვენს `.agents/setup` სკრიპტს და აყენებს Git-ის სერთიფიკატებს, როგორც ეს ყოველი orb-ისთვის ხდება. თითოეულ orb-ს ასევე შეუძლია წაიკითხოს თქვენი ანგარიშის Tuist <.localized_link href="/guides/features/cache">cache</.localized_link>.

## შეჩერება და შენახვა {#retention}

როდესაც ნაკადი უმოქმედო ხდება, Amp აჩერებს მის orb-ს. შემდეგი შეტყობინება აღადგენს მას ფაილების უცვლელობით.

- **Linux:** გაშვებული პროცესები შეჩერების შემდეგაც რჩება. orb, რომელიც დიდი ხნით იყო შეჩერებული, გადადის არქივის საცავში და შემდეგ შეტყობინებაზე აღდგება პროცესების გარეშე. Linux orb-ები ინარჩუნებენ ფაილებს მანამ, სანამ Amp ნაკადის orb-ს არ წაშლის.
- **macOS:** orb, რომელიც 7 დღის განმავლობაში შეჩერებულია ან შეცდომის მდგომარეობაშია, იშლება. ნაკადის შემდეგი შეტყობინება ახალ orb-ს იწყებს და Amp კვლავ ასრულებს `.agents/setup`-ს. მანქანაზე პირველი macOS orb აყენებს Amp CLI-ს, ამიტომ გაშვებას ორ წუთამდე შეიძლება დასჭირდეს.

orb, რომელიც უმოქმედოდ რჩება Amp-ის შეჩერების გარეშე, მაგალითად, შეჩერების ბრძანება თუ არ მივიდა, ათი წუთის შემდეგ ჩერდება CPU-ს თითქმის ნულოვანი გამოყენებით.

## Mac-ის გამოყენება ნებისმიერი Amp ნაკადიდან {#remote-mac}

Tuist Mac-ის პლაგინი Amp-ის ნაკადს აწვდის macOS სენდბოქსს Xcode-ით, iOS სიმულატორებითა და Homebrew-ით, ხოლო ნაკადი განაგრძობს მუშაობას იქ, სადაც არის, მაგალითად, Amp-ის ერთ-ერთ Linux orb-ზე. მიმართეთ Amp-ს სამუშაოსთვის და ის Mac-ს მაშინ ჩართავს, როცა დასჭირდება:

> დაამატეთ ბნელი რეჟიმის გადამრთველი პარამეტრების ეკრანზე, გაუშვით აპლიკაცია iOS სიმულატორში და მაჩვენეთ სკრინშოტი.

Amp კოდის რედაქტირებას იქ ახდენს, სადაც ის მუშაობს. Mac-ზე ყოველი ბრძანების შესრულებამდე პლაგინი ასრულებს `tuist sandbox sync`-ს, რომელიც აკოპირებს ფაილებს, რომლებსაც Git არ იგნორირებს — ჩაკომიტებულს თუ არა, — ხოლო შემდეგ მხოლოდ შეცვლილ ფაილებს. აწყობის პროდუქტები და Mac-ის მიერ შექმნილი სხვა იგნორირებული ფაილები იქ რჩება, რაც აწყობას ინკრემენტულს ტოვებს. პლაგინი ამ ხელსაწყოებს და `remote-mac` უნარს ამატებს, რომელიც Amp-ს ეუბნება, როდის და როგორ გამოიყენოს ისინი:

| ხელსაწყო | რა აკეთებს |
| --- | --- |
| `tuist_mac_start` | ქმნის ნაკადის Mac-ს, ან ხელახლა იყენებს მას და ასინქრონებს |
| `tuist_mac_shell` | ასინქრონებს, შემდეგ ასრულებს ბრძანებას Mac-ზე |
| `tuist_mac_screenshot` | აჩვენებს სიმულატორს ან ეკრანს ნაკადში |
| `tuist_mac_download` | აბრუნებს ფაილს, მაგალითად, აწყობილ `.app`-ს |
| `tuist_mac_stop` | შლის ნაკადის Mac-ს |

ნაკადი ერთ Mac-ს იყენებს. Tuist მას აჩერებს, როცა უმოქმედოა, და შემდეგი ბრძანება აღადგენს. Amp მას შლის, როცა დავალება დასრულებულია; დარჩენილი Mac 14 დღის შეჩერების შემდეგ იშლება. Mac-ები თქვენი Tuist ანგარიშისთვის ისევე ითვლება, როგორც ნებისმიერი სხვა სენდბოქსი.

### მოაწყეთ {#remote-mac-setup}

1. **დააინსტალირეთ პლაგინი.** ეს ერთი ფაილია, [`tuist-mac.ts`](https://github.com/tuist/tuist/blob/main/.amp/plugins/tuist-mac.ts). რომ ის თქვენი Amp სამუშაო სივრცის ყველა წევრისთვის ხელმისაწვდომი გახდეს, სამუშაო სივრცის ადმინისტრატორი ნაკადში Amp-ს მიმართავს:

   > დაამატეთ https://raw.githubusercontent.com/tuist/tuist/main/.amp/plugins/tuist-mac.ts ჩვენს სამუშაო სივრცის პლაგინებში.

   Amp მას სამუშაო სივრცის [პლაგინების რეპოზიტორიაში](https://ampcode.com/docs/customize/global-plugins-and-skills) აკომიტებს და push-მდე ითხოვს ნებართვას. ნაცვლად ამისა, მოითხოვეთ „ჩემი პირადი პლაგინები“, რომ მხოლოდ თქვენთვის დააინსტალიროთ, ან შეინახეთ ფაილი როგორც `.amp/plugins/tuist-mac.ts` რეპოზიტორიაში, რომ მხოლოდ იქ გამოიყენოთ. პლაგინი ასლია: მის განახლებისთვის, სთხოვეთ Amp-ს, ჩაანაცვლოს ის იმავე URL-დან აღებული უახლესი ვერსიით.
2. **დააინსტალირეთ Tuist CLI** იქ, სადაც Amp მუშაობს. orb-ებზე დაამატეთ ის რეპოზიტორიის [`.agents/setup`](https://ampcode.com/docs/orbs/customizing) სკრიპტში, მაგალითად `mise use -g tuist@latest`, ან `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist`-ით.
3. **მიეცით CLI-ს თქვენი ანგარიშის სენდბოქსების გამოყენების უფლება.** orb-ებზე, დააკავშირეთ თქვენი Amp სამუშაო სივრცე თქვენს Tuist ანგარიშთან, როგორც ეს აღწერილია <.localized_link href="/guides/server/authentication#amp-orbs">Amp orbs</.localized_link>-ში. orb-ები შემდეგ თავად შედიან სისტემაში, სენდბოქსებზე წვდომით. სხვაგან, მაგალითად, Amp CLI-ზე Linux მანქანაზე, გაუშვით `tuist auth login` ანგარიშის წევრის სახელით, ან დააყენეთ `TUIST_MAC_TOKEN` <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენზე</.localized_link> `account:sandboxes:write` სკოპით. პლაგინი `TUIST_MAC_TOKEN`-ს გადასცემს CLI-ს `TUIST_TOKEN`-ის ნაცვლად, ამიტომ დააყენეთ ის მაშინაც, როცა თქვენს orb-ებს უკვე აქვთ `TUIST_TOKEN` ამ სკოპის გარეშე.
4. **უთხარით, რომელი ანგარიში გამოიყენოს**, თუ რეპოზიტორიას არ აქვს `tuist.toml` `project = "<account>/<project>"`-ით. Linux-ზე CLI-ს არ შეუძლია ანგარიშის წაკითხვა `Tuist.swift`-დან. დააყენეთ `TUIST_MAC_ACCOUNT` თქვენს ანგარიშის handle-ზე თქვენი Amp პროექტის გარემოს ცვლადებში. მის გარეშე, Amp ანგარიშს `Tuist.swift`-ის `fullHandle`-დან `tuist_mac_start`-ს გადასცემს.

CLI Mac-ს მხოლოდ `tuist.dev`-ის მეშვეობით უკავშირდება, ამიტომ გარემომ, რომელიც ქსელურ წვდომას ზღუდავს, მხოლოდ ეს დომენი უნდა დაუშვას. CLI-ის გამოსაყენებლად, რომელიც `PATH`-ზე არ არის, დააყენეთ `TUIST_MAC_CLI` მის ბილიკზე.

აგენტებს, რომლებიც Amp პლაგინებს არ უჭერენ მხარს, მაგალითად Claude Code ან Cursor, იგივე შეუძლიათ Tuist MCP სერვერისა და CLI-ის მეშვეობით, როგორც ეს აღწერილია <.localized_link href="/guides/features/sandboxes#coding-agents">აწყობა Mac-ზე კოდირების აგენტიდან</.localized_link>-ში.

### გამოიყენეთ Tuist Mac-ები Amp-ის macOS Satellites-ის ნაცვლად {#remote-mac-satellites}

Amp-ს ასევე აქვს საკუთარი ღრუბლოვანი Mac-ები, [macOS Satellites](https://ampcode.com/docs/orbs/mac), ბეტა ვერსიაში იმ სამუშაო სივრცეებისთვის, რომლებიც მის მოლოდინის სიაში შევიდნენ. როდესაც ნაკადს ორივეს გაშვება შეუძლია, Amp-ის ჩაშენებული ინსტრუქციები macOS სამუშაოს მის სატელიტებს უგზავნიან, ამიტომ ის იშვიათად ირჩევს პლაგინს. რომ ნაკადებმა Tuist Mac-ები გამოიყენონ, გააკეთეთ ერთ-ერთი შემდეგი:

- **გამორთეთ macOS Satellites საკუთარი თავისთვის.** თითოეული წევრი მათ თიშავს **Mac Satellites**-ის ქვეშ Amp-ის [პარამეტრები → ექსპერიმენტული ფუნქციები](https://ampcode.com/settings/experimental-features)-ში.
- **გამორთეთ ისინი სამუშაო სივრცისთვის.** როდესაც თქვენი სამუშაო სივრცის orb-ები [Tuist-ზე მუშაობენ](#connect), სამუშაო სივრცის ადმინისტრატორს შეუძლია დააყენოს **სად მუშაობენ Orb-ები** **მხოლოდ Self-Hosted**-ზე Amp-ის სამუშაო სივრცის პარამეტრებში, **Orbs**-ის ქვეშ. აგენტები შემდეგ ვერ დაიწყებენ Amp-ის მიერ დაჰოსტებულ სატელიტებს, მაგრამ წევრები ასევე ვერ გამოიყენებენ Amp-ის ჩაშენებულ orb-ებს, ამიტომ ეს მხოლოდ მაშინ გააკეთეთ, როცა თქვენი ყველა ნაკადი თქვენს საკუთარ orb პროვაიდერებზე მუშაობს.
- **მოითხოვეთ Tuist Mac-ები.** დაამატეთ „გამოიყენეთ `tuist_mac_*` ხელსაწყოები macOS სამუშაოსთვის, არა macOS Satellites.“ მოთხოვნაში, ან თქვენი სამუშაო სივრცის აგენტის მითითებებში Amp-ის სამუშაო სივრცის პარამეტრებში, რომ ყოველი ნაკადი მიჰყვეს მას.
