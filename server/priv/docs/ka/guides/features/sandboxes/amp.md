# Amp {#amp}

> [!IMPORTANT]
> **მხოლოდ მოწვევით**
>
> Tuist Sandboxes, როგორც Linux-ზე, ისე macOS-ზე, ამჟამად მხოლოდ მოწვევითაა ხელმისაწვდომი. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [საზოგადოების Slack-ში](https://slack.tuist.dev), რათა თქვენი ანგარიშისთვის წვდომა მოითხოვოთ.

[Amp](https://ampcode.com) თითოეული ნაკადის ინსტრუმენტებს აწარმოებს [orb-ში](https://ampcode.com/docs/orbs) — მანქანაზე, სადაც ნაკადის რეპოზიტორია გადმოწერილია. Tuist შეიძლება იყოს თქვენი Amp სამუშაო სივრცის [თვითმასპინძელი orb პროვაიდერი](https://ampcode.com/docs/orbs/self-hosted): ყოველი ნაკადი, რომელიც მას ირჩევს, მუშაობს საკუთარ Tuist <.localized_link href="/guides/features/sandboxes">sandbox-ში</.localized_link>, Linux-ზე ან macOS-ზე. თქვენ არაფერს უშვებთ ან მასპინძლობთ თავად.

იმისთვის, რომ თქვენი ნაკადები დარჩეს მიმდინარე orb-ებზე და Apple-პლატფორმის კოდი მხოლოდ Mac-ზე ააწყოთ, შეამოწმოთ და გაუშვათ, გამოიყენეთ [Tuist Mac პლაგინი](#remote-mac).

## Amp-ის დაკავშირება {#connect}

უნდა იყოთ როგორც Amp სამუშაო სივრცის, ისე Tuist ანგარიშის ადმინისტრატორი.

1. Amp-ში გახსენით თქვენი სამუშაო სივრცის **Settings → Orbs**, დააჭირეთ **Add Orb Provider** და მიანიჭეთ სახელი, მაგალითად `tuist`. წევრები პროვაიდერს ამ სახელით ირჩევენ. დააკოპირეთ `aop_live_…` ტოკენი; Amp მას მხოლოდ ერთხელ აჩვენებს.
2. Amp-ში პროვაიდერის **Edit** დიალოგში დაამატეთ შესატყვისი **Orb ტიპები**, რომლებიც გსურთ შესთავაზოთ, და აირჩიეთ ნაგულისხმები. Linux ტიპები ემთხვევა [Amp-ის საკუთარი orb-ების](https://ampcode.com/docs/orbs/sizes-and-costs) მეხსიერებას. თითოეულს გარანტირებული აქვს vCPU-ის მეოთხედი თითო GiB მეხსიერებაზე და შეუძლია აფეთქდეს 16 vCPU-მდე, როცა მის მანქანას თავისუფალი ბირთვები აქვს (იხ. <.localized_link href="/guides/features/sandboxes#guaranteed-cpu">გარანტირებული CPU</.localized_link>):

   | ტიპი | კონფიგურაცია |
   | --- | --- |
   | `linux` | Linux, 8 GiB RAM, 2 გარანტირებული vCPU |
   | `linux-tiny` | Linux, 2 GiB RAM, 0.5 გარანტირებული vCPU |
   | `linux-small` | Linux, 4 GiB RAM, 1 გარანტირებული vCPU |
   | `linux-medium` | იგივე, რაც `linux` |
   | `linux-large` | Linux, 16 GiB RAM, 4 გარანტირებული vCPU |
   | `linux-xxlarge` | Linux, 32 GiB RAM, 8 გარანტირებული vCPU |
   | `linux-3xlarge` | Linux, 44 GiB RAM, 11 გარანტირებული vCPU |
   | `macos` | macOS ნაგულისხმევი Xcode-ით, 8 vCPU, 8 GiB RAM |
   | `macos-xcode-<version>` | macOS იმ [Xcode-ით](#xcode), 8 vCPU, 8 GiB RAM |

   Linux ტიპებს აქვთ 10 GB სამუშაო სივრცე, macOS ტიპებს — 30 GB.

3. Tuist-ში გახსენით **Sandboxes** თქვენი ანგარიშის დაფაზე, Amp-ის ბარათზე დააჭირეთ **Connect** და ჩასვით ტოკენი.

ბარათი აჩვენებს **Connected**-ს, როგორც კი Tuist მოემსახურება პროვაიდერს. ერთი Tuist ანგარიში ერთ პროვაიდერს ემსახურება. ყველა, ვისაც Amp-ში პროვაიდერის გამოყენება შეუძლია, orb-ებს ამოქმედებს და გადასახადი ერიცხება დაკავშირებულ Tuist ანგარიშს. შესაჩერებლად ბარათზე დააჭირეთ **Disconnect**, ან გამორთეთ პროვაიდერი Amp-ში.

## ნაკადის დაწყება {#start-a-thread}

Amp-ის ახალი ნაკადის შემდგენელში დააჭირეთ **Orb**, აირჩიეთ Tuist პროვაიდერი **Self-Hosted** ქვეშ და აირჩიეთ ტიპი, მაგალითად `linux-small` რეპოზიტორიისთვის, რომელსაც `linux`-ზე ნაკლები სჭირდება, ან `linux-large` იმისთვის, რომელსაც მეტი სჭირდება. Amp CLI-დან:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos
```

ნაკადი ინარჩუნებს თავის orb ტიპს მთელი სიცოცხლის განმავლობაში. ტიპის მითითების გარეშე, ის იღებს პროვაიდერის ნაგულისხმევს. ყოველი ახალი ნაკადისთვის ერთი ტიპის გამოყენებისთვის, აირჩიეთ პროვაიდერი და მისი ტიპი Amp-ის **Settings → Orbs** განყოფილებაში **Default Orb** ქვეშ.

### Xcode-ის არჩევა {#xcode}

`macos` აწარმოებს ნაგულისხმევ <.localized_link href="/guides/features/sandboxes#xcode">Xcode-ს</.localized_link>. სხვისთვის დაამატეთ orb ტიპი მისი სახელით, სადაც წერტილები ჩანაცვლებულია დეფისებით: `macos-xcode-26-1-1` აწარმოებს Xcode 26.1.1-ს, `macos-xcode-27-0` — Xcode 27.0-ს. დაამატეთ თითოეული Xcode-ისთვის, რომელსაც თქვენი რეპოზიტორიები ამაგრებენ, და აირჩიეთ ის ნაკადის მიხედვით, როგორც ნებისმიერი სხვა ტიპი:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos-xcode-26-1-1
```

ტიპი Xcode-ისთვის, რომელსაც Tuist არ სთავაზობს, მარცხდება ახალი orb-ის გაშვებისას. orb, რომელიც Tuist-მა უკვე გაუშვა მასზე, განაგრძობს აღდგენას მას შემდეგ, რაც Tuist შეწყვეტს იმ Xcode-ის შეთავაზებას.

Amp აკლონებს რეპოზიტორიას, ასრულებს თქვენს `.agents/setup` სკრიპტს და აყენებს Git-ის სერთიფიკატებს, როგორც ეს ყოველი orb-ისთვის ხდება. თითოეულ orb-ს ასევე შეუძლია წაიკითხოს თქვენი ანგარიშის Tuist <.localized_link href="/guides/features/cache">ქეში</.localized_link>.

## შეჩერება და შენახვა {#retention}

როცა ნაკადი უმოქმედო ხდება, Amp აჩერებს მის orb-ს. შემდეგი შეტყობინება აღადგენს მას ფაილების უცვლელობით.

- **Linux:** გაშვებული პროცესები უძლებენ შეჩერებას. orb, რომელიც დიდი ხნის განმავლობაში იყო შეჩერებული, გადადის არქივის საცავში და აღდგება შემდეგ შეტყობინებაზე, პროცესების გარეშე. Linux orb-ები ინარჩუნებენ ფაილებს, სანამ Amp არ წაშლის ნაკადის orb-ს.
- **macOS:** orb, რომელიც შეჩერებულია ან შეცდომის მდგომარეობაშია 7 დღის განმავლობაში, იშლება. ნაკადის შემდეგი შეტყობინება იწყებს ახალ orb-ს და Amp კვლავ ასრულებს `.agents/setup`-ს. პირველი macOS orb მანქანაზე აყენებს Amp CLI-ს, ამიტომ გაშვებამ შეიძლება ორ წუთამდე დრო წაიღოს.

orb, რომელიც უმოქმედო რჩება Amp-ის შეჩერების გარეშე, მაგალითად, იმიტომ, რომ შეჩერების ბრძანება არ მივიდა, ჩერდება ათი წუთის შემდეგ თითქმის ნულოვანი CPU გამოყენებით.

## Mac-ის გამოყენება ნებისმიერი Amp ნაკადიდან {#remote-mac}

Tuist Mac პლაგინი Amp ნაკადს აძლევს macOS sandbox-ს Xcode-ით, iOS სიმულატორებით და Homebrew-ით, მაშინ როცა ნაკადი განაგრძობს მუშაობას იქ, სადაც არის, მაგალითად Amp-ის ერთ-ერთ საკუთარ Linux orb-ზე. სთხოვეთ Amp-ს სამუშაო და ის გაუშვებს Mac-ს, როცა დასჭირდება:

> დაამატეთ ბნელი რეჟიმის გადართვა პარამეტრების ეკრანზე, გაუშვით აპლიკაცია iOS სიმულატორში და მაჩვენეთ სკრინშოტი.

Amp ინარჩუნებს კოდის რედაქტირებას იქ, სადაც ის მუშაობს. Mac-ზე ყოველი ბრძანების შესრულებამდე პლაგინი ასრულებს `tuist sandbox sync`-ს, რომელიც აკოპირებს ფაილებს, რომლებსაც Git არ იგნორირებს, დაკომიტებულს თუ არა, ხოლო შემდეგ მხოლოდ იმ ფაილებს, რომლებიც შეიცვალა. აწყობის პროდუქტები და სხვა იგნორირებული ფაილები, რომლებსაც Mac ქმნის, რჩება იქ, ამიტომ აწყობა ინკრემენტული რჩება. პლაგინი ამატებს ამ ინსტრუმენტებს და `remote-mac` უნარს, რომელიც Amp-ს ეუბნება, როდის და როგორ გამოიყენოს ისინი:

| ინსტრუმენტი | რა აკეთებს |
| --- | --- |
| `tuist_mac_start` | ქმნის ნაკადის Mac-ს, ან ხელახლა იყენებს მას და ასინქრონებს |
| `tuist_mac_shell` | ასინქრონებს, შემდეგ ასრულებს ბრძანებას Mac-ზე |
| `tuist_mac_screenshot` | აჩვენებს სიმულატორს ან ეკრანს ნაკადში |
| `tuist_mac_download` | აბრუნებს ფაილს, მაგალითად აწყობილ `.app`-ს |
| `tuist_mac_stop` | შლის ნაკადის Mac-ს |

Mac-ს აქვს Tuist CLI და ასრულებს პროექტის საკუთარ ვერსიას, როცა ის mise-ით არის მიმაგრებული; `tuist_mac_shell` ათავსებს mise-ის shims-ებს `PATH`-ის დასაწყისში. Mac-ზე ყოველი ბრძანება <.localized_link href="/guides/features/sandboxes#tuist-in-sandbox">შედის თქვენი ანგარიშის ქეშში</.localized_link> დამოუკიდებლად Tuist 4.218.0 ან უფრო გვიანი ვერსიით; 4.215.0-დან 4.217.x-მდე ვერსიებში Amp ჯერ ასრულებს `tuist auth login`-ს.

ნაკადი იყენებს ერთ Mac-ს. Amp გადასცემს `tuist_mac_start`-ს <.localized_link href="/guides/features/sandboxes#xcode">Xcode</.localized_link>-ს, რომელსაც რეპოზიტორია ამაგრებს, მაგალითად `.xcode-version`-ში, ან შეგიძლიათ მოითხოვოთ კონკრეტული („გამოიყენე Xcode 26.1.1“); თუ არ არის მითითებული, Mac ასრულებს ნაგულისხმევს. Mac ინარჩუნებს თავის Xcode-ს, ამიტომ გადართვა ნიშნავს მის შეჩერებას და სხვის გაშვებას. Tuist აჩერებს მას, როცა ის უმოქმედოა და შემდეგი ბრძანება აღადგენს მას. Amp შლის მას, როცა დავალება დასრულდება; მიტოვებული Mac იშლება 14 დღიანი შეჩერების შემდეგ. Mac-ები ითვლება თქვენი Tuist ანგარიშისთვის, როგორც ნებისმიერი სხვა sandbox.

### დააყენეთ {#remote-mac-setup}

1. **დააინსტალირეთ პლაგინი.** ეს არის ერთი ფაილი, [`tuist-mac.ts`](https://github.com/tuist/tuist/blob/main/.amp/plugins/tuist-mac.ts). რომ ის ხელმისაწვდომი იყოს თქვენი Amp სამუშაო სივრცის ყველასთვის, სამუშაო სივრცის ადმინისტრატორი სთხოვს Amp-ს ნაკადში:

   > დაამატე https://raw.githubusercontent.com/tuist/tuist/main/.amp/plugins/tuist-mac.ts ჩვენს სამუშაო სივრცის პლაგინებში.

   Amp აკომიტებს მას სამუშაო სივრცის [პლაგინების რეპოზიტორიაში](https://ampcode.com/docs/customize/global-plugins-and-skills) და სთხოვს ნებართვას push-მდე. სთხოვეთ „ჩემი პირადი პლაგინები“, რომ დააინსტალიროთ ის მხოლოდ საკუთარი თავისთვის, ან შეინახეთ ფაილი როგორც `.amp/plugins/tuist-mac.ts` რეპოზიტორიაში, რომ გამოიყენოთ მხოლოდ იქ. პლაგინი არის ასლი: განახლებისთვის სთხოვეთ Amp-ს ჩაანაცვლოს ის იმავე URL-ის უახლესი ვერსიით.
2. **დააინსტალირეთ Tuist CLI** იქ, სადაც Amp მუშაობს. orb-ებზე დაამატეთ ის რეპოზიტორიის [`.agents/setup`](https://ampcode.com/docs/orbs/customizing) სკრიპტში, მაგალითად `mise use -g tuist@latest`, ან `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist`.
3. **მიეცით CLI-ს თქვენი ანგარიშის sandbox-ების გამოყენების უფლება.** orb-ებზე, დააკავშირეთ თქვენი Amp სამუშაო სივრცე თქვენს Tuist ანგარიშთან, როგორც აღწერილია <.localized_link href="/guides/server/authentication#amp-orbs">Amp orbs</.localized_link>-ში. orb-ები შემდეგ დამოუკიდებლად შედიან სისტემაში, sandbox-ებზე წვდომით. სხვაგან, მაგალითად Amp CLI Linux მანქანაზე, გაუშვით `tuist auth login` როგორც ანგარიშის წევრმა, ან დააყენეთ `TUIST_MAC_TOKEN` <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენზე</.localized_link> `account:sandboxes:write` სკოუპით, პლუს `ci` Mac-ის ქეშის გამოყენებისთვის. პლაგინი გადასცემს `TUIST_MAC_TOKEN`-ს CLI-ს `TUIST_TOKEN`-ის ნაცვლად, ამიტომ დააყენეთ ის მაშინაც, როცა თქვენს orb-ებს უკვე აქვთ `TUIST_TOKEN` ამ სკოუპის გარეშე.
4. **მიუთითეთ, რომელი ანგარიში გამოიყენოს**, თუ რეპოზიტორიას არ აქვს `tuist.toml` `project = "<account>/<project>"`-ით. Linux-ზე, CLI-ს არ შეუძლია ანგარიშის წაკითხვა `Tuist.swift`-დან. დააყენეთ `TUIST_MAC_ACCOUNT` თქვენს ანგარიშის სახელზე თქვენი Amp პროექტის გარემოს ცვლადებში. მის გარეშე, Amp გადასცემს ანგარიშს `Tuist.swift`-ის `fullHandle`-დან `tuist_mac_start`-ში.

CLI უკავშირდება Mac-ს მხოლოდ `tuist.dev`-ის მეშვეობით, ამიტომ გარემომ, რომელიც ზღუდავს ქსელურ წვდომას, უნდა დაუშვას მხოლოდ ეს დომენი. CLI-ის გამოსაყენებლად, რომელიც არ არის `PATH`-ზე, დააყენეთ `TUIST_MAC_CLI` მის გზაზე.

აგენტებს, რომლებიც არ უჭერენ მხარს Amp პლაგინებს, როგორიცაა Claude Code ან Cursor, შეუძლიათ იგივე გააკეთონ Tuist MCP სერვერისა და CLI-ის მეშვეობით, როგორც აღწერილია <.localized_link href="/guides/features/sandboxes#coding-agents">Mac-ზე აწყობა კოდირების აგენტისგან</.localized_link>-ში.

### გამოიყენეთ Tuist Mac-ები Amp-ის macOS Satellites-ის ნაცვლად {#remote-mac-satellites}

Amp-ს ასევე აქვს საკუთარი ღრუბლოვანი Mac-ები, [macOS Satellites](https://ampcode.com/docs/orbs/mac), ბეტა ვერსიაში იმ სამუშაო სივრცეებისთვის, რომლებიც შეუერთდნენ მის მოლოდინის სიას. როცა ნაკადს შეუძლია ორივეს გაშვება, Amp-ის ჩაშენებული ინსტრუქციები macOS სამუშაოს უგზავნიან მის სატელიტებს, ამიტომ ის იშვიათად ირჩევს პლაგინს. რომ ნაკადებმა გამოიყენონ Tuist Mac-ები, გააკეთეთ ერთ-ერთი ამისგან:

- **გამორთეთ macOS Satellites საკუთარი თავისთვის.** თითოეული წევრი თიშავს მათ **Mac Satellites**-ის ქვეშ Amp-ის [Settings → Experimental Features](https://ampcode.com/settings/experimental-features)-ში.
- **გამორთეთ ისინი სამუშაო სივრცისთვის.** როცა თქვენი სამუშაო სივრცის orb-ები [მუშაობენ Tuist-ზე](#connect), სამუშაო სივრცის ადმინისტრატორს შეუძლია დააყენოს **Where Orbs Run** **Self-Hosted Only**-ზე Amp-ის სამუშაო სივრცის პარამეტრებში, **Orbs**-ის ქვეშ. აგენტები შემდეგ ვერ გაუშვებენ Amp-ის მიერ დაჰოსტებულ სატელიტებს, მაგრამ წევრები ასევე ვერ გამოიყენებენ Amp-ის ჩაშენებულ orb-ებს, ამიტომ გააკეთეთ ეს მხოლოდ მაშინ, როცა თქვენი ყველა ნაკადი მუშაობს თქვენს საკუთარ orb პროვაიდერებზე.
- **მოითხოვეთ Tuist Mac-ები.** დაამატეთ „გამოიყენეთ `tuist_mac_*` ინსტრუმენტები macOS სამუშაოსთვის, არა macOS Satellites.“ მოთხოვნაში, ან თქვენი სამუშაო სივრცის აგენტის მითითებებში Amp-ის სამუშაო სივრცის პარამეტრებში, რომ ყველა ნაკადმა დაიცვას ის.
