# Amp {#amp}

> [!IMPORTANT]
> **მხოლოდ მოწვევით**
>
> Tuist Sandboxes, როგორც Linux-ზე, ისე macOS-ზე, ამჟამად მხოლოდ მოწვევითაა ხელმისაწვდომი. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [საზოგადოების Slack-ში](https://slack.tuist.dev), რათა თქვენს ანგარიშზე წვდომა მოითხოვოთ.

[Amp](https://ampcode.com) თითოეული ნაკადის ინსტრუმენტებს [orb-ში](https://ampcode.com/docs/orbs) უშვებს — ეს არის მანქანა, სადაც ნაკადის რეპოზიტორია გადმოწერილია. Tuist შეიძლება იყოს თქვენი Amp სამუშაო სივრცის [თვითმასპინძელი orb პროვაიდერი](https://ampcode.com/docs/orbs/self-hosted): ყოველი ნაკადი, რომელიც მას ირჩევს, საკუთარ Tuist <.localized_link href="/guides/features/sandboxes">sandbox-ში</.localized_link> ეშვება, Linux-ზე ან macOS-ზე. თქვენ არაფერს უშვებთ და არ მასპინძლობთ.

იმისთვის, რომ ნაკადები მიმდინარე orb-ებზე დარჩეს და Apple-პლატფორმის კოდი მხოლოდ Mac-ზე ააწყოთ, გატესტოთ და გაუშვათ, გამოიყენეთ [Tuist Mac პლაგინი](#remote-mac).

## Amp-ის დაკავშირება {#connect}

თქვენ უნდა იყოთ როგორც Amp სამუშაო სივრცის, ისე Tuist ანგარიშის ადმინისტრატორი.

1. Amp-ში გახსენით თქვენი სამუშაო სივრცის **Settings → Orbs**, დააჭირეთ **Add Orb Provider** და მიანიჭეთ სახელი, მაგალითად `tuist`. მონაწილეები პროვაიდერს ამ სახელით ირჩევენ. დააკოპირეთ `aop_live_…` ტოკენი; Amp მას მხოლოდ ერთხელ აჩვენებს.
2. Amp-ში პროვაიდერის **Edit** დიალოგში დაამატეთ შესატანი **Orb ტიპები** და აირჩიეთ ნაგულისხმევი. Linux-ის ტიპები ემთხვევა [Amp-ის საკუთარი orb-ების](https://ampcode.com/docs/orbs/sizes-and-costs) მეხსიერებას. თითოეულს გარანტირებული აქვს vCPU-ის მეოთხედი თითო GiB მეხსიერებაზე და 16 vCPU-მდე იზრდება, როცა მის მანქანას თავისუფალი ბირთვები აქვს (იხ. <.localized_link href="/guides/features/sandboxes#guaranteed-cpu">გარანტირებული CPU</.localized_link>):

   | ტიპი | კონფიგურაცია |
   | --- | --- |
   | `linux` | Linux, 8 GiB RAM, 2 გარანტირებული vCPU |
   | `linux-tiny` | Linux, 2 GiB RAM, 0.5 გარანტირებული vCPU |
   | `linux-small` | Linux, 4 GiB RAM, 1 გარანტირებული vCPU |
   | `linux-medium` | იგივე, რაც `linux` |
   | `linux-large` | Linux, 16 GiB RAM, 4 გარანტირებული vCPU |
   | `linux-xxlarge` | Linux, 32 GiB RAM, 8 გარანტირებული vCPU |
   | `linux-3xlarge` | Linux, 44 GiB RAM, 11 გარანტირებული vCPU |
   | `macos` | macOS ნაგულისხმევი Xcode-ით, 8 vCPU, 8 GiB RAM |
   | `macos-xcode-<version>` | macOS იმ [Xcode-ით](#xcode), 8 vCPU, 8 GiB RAM |

   Linux-ის ტიპებს აქვთ 10 GB სამუშაო სივრცე, macOS-ის ტიპებს — 30 GB.

3. Tuist-ში გახსენით თქვენი ანგარიშის დაფაზე **Sandboxes**, Amp-ის ბარათზე დააჭირეთ **Connect** და ჩასვით ტოკენი.

ბარათი აჩვენებს **Connected**-ს, როცა Tuist პროვაიდერს ემსახურება. ერთი Tuist ანგარიში ერთ პროვაიდერს ემსახურება. ყოველი, ვინც Amp-ში პროვაიდერს იყენებს, orb-ებს ამ დაკავშირებულ Tuist ანგარიშზე უშვებს და მასზე ირიცხება გადასახადი. შესაჩერებლად ბარათზე დააჭირეთ **Disconnect** ან Amp-ში გამორთეთ პროვაიდერი.

## ნაკადის დაწყება {#start-a-thread}

Amp-ის ახალი ნაკადის შემდგენელში დააჭირეთ **Orb**, აირჩიეთ Tuist პროვაიდერი **Self-Hosted** ქვეშ და აირჩიეთ ტიპი, მაგალითად `linux-small` რეპოზიტორიისთვის, რომელსაც `linux`-ზე ნაკლები სჭირდება, ან `linux-large` იმისთვის, რომელსაც მეტი სჭირდება. Amp CLI-დან:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos
```

ნაკადი სიცოცხლის ბოლომდე ინარჩუნებს orb-ის ტიპს. ტიპის გარეშე იღებს პროვაიდერის ნაგულისხმევს. ყოველი ახალი ნაკადისთვის ერთი ტიპის გამოყენებისთვის Amp-ის **Settings → Orbs** განყოფილებაში **Default Orb** ქვეშ აირჩიეთ პროვაიდერი და მისი ტიპი.

### Xcode-ის არჩევა {#xcode}

`macos` უშვებს ნაგულისხმევ <.localized_link href="/guides/features/sandboxes#xcode">Xcode-ს</.localized_link>. სხვისთვის დაამატეთ მისი სახელის მქონე orb ტიპი, წერტილების ტირეებით ჩანაცვლებით: `macos-xcode-26-1-1` უშვებს Xcode 26.1.1-ს, `macos-xcode-27-0` — Xcode 27.0-ს. დაამატეთ თითო თითოეული Xcode-ისთვის, რომელსაც თქვენი რეპოზიტორიები ამაგრებენ, და ნაკადის მიხედვით აირჩიეთ, როგორც ნებისმიერი სხვა ტიპი:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos-xcode-26-1-1
```

Xcode-ის ტიპი, რომელსაც Tuist არ სთავაზობს, ახალი orb-ის გაშვებისას ვერდება. orb, რომელიც Tuist-მა მასზე უკვე გაუშვა, განაგრძობს აღდგენას მას შემდეგ, რაც Tuist ამ Xcode-ის შეთავაზებას შეწყვეტს.

Amp აკლონებს რეპოზიტორიას, უშვებს თქვენს `.agents/setup` სკრიპტს და აყენებს Git-ის მონაცემებს, როგორც ყოველი orb-ისთვის. თითოეულ orb-ს ასევე შეუძლია წაიკითხოს თქვენი ანგარიშის Tuist <.localized_link href="/guides/features/cache">ქეში</.localized_link>.

## შეჩერება და შენახვა {#retention}

როცა ნაკადი უმოქმედო ხდება, Amp აჩერებს მის orb-ს. შემდეგი შეტყობინება აღადგენს მას ფაილების უცვლელობით.

- **Linux:** გაშვებული პროცესები შეჩერების შემდეგ რჩება. orb, რომელიც დიდი ხნით იყო შეჩერებული, გადადის საარქივო საცავში და შემდეგ შეტყობინებაზე აღდგება პროცესების გარეშე. Linux orb-ები ინარჩუნებენ ფაილებს, სანამ Amp ნაკადის orb-ს არ წაშლის.
- **macOS:** orb, რომელიც 7 დღის განმავლობაში იყო შეჩერებული ან შეცდომის მდგომარეობაში, იშლება. ნაკადის შემდეგი შეტყობინება ახალ orb-ს უშვებს და Amp კვლავ უშვებს `.agents/setup`-ს. მანქანაზე პირველი macOS orb აყენებს Amp CLI-ს, ამიტომ გაშვებას ორ წუთამდე შეიძლება დასჭირდეს.

orb, რომელიც უმოქმედოდ რჩება Amp-ის შეჩერების გარეშე, მაგალითად იმიტომ, რომ შეჩერების ბრძანება არ მიუღია, ათი წუთის შემდეგ ჩერდება თითქმის ნულოვანი CPU გამოყენებით.

## Mac-ის გამოყენება ნებისმიერი Amp ნაკადიდან {#remote-mac}

Tuist Mac პლაგინი Amp ნაკადს აძლევს macOS sandbox-ს Xcode-ით, iOS სიმულატორებითა და Homebrew-ით, მაშინ როცა ნაკადი იქვე გრძელდება, სადაც არის, მაგალითად Amp-ის საკუთარ Linux orb-ზე. სთხოვეთ Amp-ს სამუშაო და ის Mac-ს მაშინ გაუშვებს, როცა დასჭირდება:

> დაამატეთ ბნელი რეჟიმის გადამრთველი პარამეტრების ეკრანზე, გაუშვით აპლიკაცია iOS სიმულატორში და მაჩვენეთ სკრინშოტი.

Amp კოდის რედაქტირებას იქვე აგრძელებს, სადაც ეშვება. Mac-ზე თითოეული ბრძანების წინ პლაგინი უშვებს `tuist sandbox sync`-ს, რომელიც აკოპირებს ფაილებს, რომლებსაც Git არ იგნორირებს, დაფიქსირებულებს თუ არა, ხოლო შემდეგ მხოლოდ შეცვლილებს. Mac-ის მიერ შექმნილი აწყობის პროდუქტები და სხვა იგნორირებული ფაილები იქ რჩება, ამიტომ აწყობა ინკრემენტული რჩება. პლაგინი ამატებს ამ ინსტრუმენტებს და `remote-mac` უნარს, რომელიც Amp-ს ეუბნება, როდის და როგორ გამოიყენოს ისინი:

| ინსტრუმენტი | რა აკეთებს |
| --- | --- |
| `tuist_mac_start` | ქმნის ნაკადის Mac-ს, ან ხელახლა იყენებს მას და ასინქრონებს |
| `tuist_mac_shell` | ასინქრონებს, შემდეგ კი ბრძანებას უშვებს Mac-ზე |
| `tuist_mac_screenshot` | აჩვენებს სიმულატორს ან ეკრანს ნაკადში |
| `tuist_mac_download` | აბრუნებს ფაილს, მაგალითად აწყობილ `.app`-ს |
| `tuist_mac_stop` | შლის ნაკადის Mac-ს |

Mac-ს საკუთარი Tuist CLI არ აქვს: პირველი სინქრონიზაციის შემდეგ Amp რეპოზიტორიის ძირში უშვებს `mise install`-ს, რათა პროექტის მიმაგრებული Tuist დამონტაჟდეს, ხოლო `tuist_mac_shell` mise-ის shims-ებს `PATH`-ზე ამატებს. Mac-ზე თითოეული ბრძანება ცალკე <.localized_link href="/guides/features/sandboxes#tuist-in-sandbox">შედის თქვენი ანგარიშის ქეშში</.localized_link> Tuist 4.218.0 ან უფრო ახალი ვერსიით; 4.215.0-დან 4.217.x-მდე ვერსიებში Amp ჯერ `tuist auth login`-ს უშვებს.

ნაკადი ერთ Mac-ს იყენებს. Amp `tuist_mac_start`-ს გადასცემს <.localized_link href="/guides/features/sandboxes#xcode">Xcode</.localized_link>-ს, რომელიც რეპოზიტორიაშია მიმაგრებული, მაგალითად `.xcode-version`-ში, ან შეგიძლიათ მოითხოვოთ კონკრეტული („გამოიყენე Xcode 26.1.1“); თუ არ არის მითითებული, Mac ნაგულისხმევს უშვებს. Mac ინარჩუნებს თავის Xcode-ს, ამიტომ გადართვა ნიშნავს მის შეჩერებას და სხვის გაშვებას. Tuist მას ჩერებს, როცა უმოქმედოა, და შემდეგი ბრძანება აღადგენს მას. Amp შლის მას, როცა ამოცანა დასრულდება; დარჩენილი Mac იშლება 14 დღიანი შეჩერების შემდეგ. Mac-ები ითვლება თქვენს Tuist ანგარიშზე, როგორც ნებისმიერი სხვა sandbox.

### მისი მორგება {#remote-mac-setup}

1. **დააინსტალირეთ პლაგინი.** ეს ერთი ფაილია, [`tuist-mac.ts`](https://github.com/tuist/tuist/blob/main/.amp/plugins/tuist-mac.ts). იმისთვის, რომ ის ხელმისაწვდომი იყოს თქვენი Amp სამუშაო სივრცის ყველასთვის, სამუშაო სივრცის ადმინისტრატორი ნაკადში სთხოვს Amp-ს:

   > დაამატე https://raw.githubusercontent.com/tuist/tuist/main/.amp/plugins/tuist-mac.ts ჩვენს სამუშაო სივრცის პლაგინებში.

   Amp აკომიტებს მას სამუშაო სივრცის [პლაგინების რეპოზიტორიაში](https://ampcode.com/docs/customize/global-plugins-and-skills) და push-ის წინ ითხოვს ნებართვას. ნაცვლად ამისა, სთხოვეთ „ჩემი პირადი პლაგინები“, რათა ის მხოლოდ თქვენთვის დაინსტალირდეს, ან შეინახეთ ფაილი როგორც `.amp/plugins/tuist-mac.ts` რეპოზიტორიაში, რათა მხოლოდ იქ გამოიყენოთ. პლაგინი არის ასლი: განახლებისთვის სთხოვეთ Amp-ს, ჩაანაცვლოს ის იმავე URL-ის უახლესი ვერსიით.
2. **დააინსტალირეთ Tuist CLI** იქ, სადაც Amp ეშვება. orb-ებზე დაამატეთ ის რეპოზიტორიის [`.agents/setup`](https://ampcode.com/docs/orbs/customizing) სკრიპტში, მაგალითად `mise use -g tuist@latest`, ან `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist`.
3. **მიეცით CLI-ს თქვენი ანგარიშის sandbox-ების გამოყენების უფლება.** orb-ებზე დააკავშირეთ თქვენი Amp სამუშაო სივრცე თქვენს Tuist ანგარიშთან, როგორც ეს აღწერილია <.localized_link href="/guides/server/authentication#amp-orbs">Amp orbs</.localized_link>-ში. orb-ები შემდეგ თვითონ შედიან, sandbox-ებზე წვდომით. სხვაგან, მაგალითად Amp CLI-ზე Linux მანქანაზე, გაუშვით `tuist auth login` როგორც ანგარიშის წევრმა, ან დააყენეთ `TUIST_MAC_TOKEN` <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენზე</.localized_link> `account:sandboxes:write` scope-ით, პლუს `ci` Mac-ის ქეშის გამოსაყენებლად. პლაგინი `TUIST_MAC_TOKEN`-ს გადასცემს CLI-ს `TUIST_TOKEN`-ის ნაცვლად, ამიტომ დააყენეთ ის მაშინაც, როცა თქვენს orb-ებს უკვე აქვთ `TUIST_TOKEN` ამ scope-ის გარეშე.
4. **უთხარით, რომელი ანგარიში გამოიყენოს**, თუ რეპოზიტორიას არ აქვს `tuist.toml` `project = "<account>/<project>"`-ით. Linux-ზე CLI-ს არ შეუძლია ანგარიშის წაკითხვა `Tuist.swift`-დან. დააყენეთ `TUIST_MAC_ACCOUNT` თქვენს ანგარიშის სახელზე თქვენი Amp პროექტის გარემოს ცვლადებში. მის გარეშე, Amp გადასცემს ანგარიშს `Tuist.swift`-ის `fullHandle`-დან `tuist_mac_start`-ში.

CLI Mac-ს მხოლოდ `tuist.dev`-ის მეშვეობით უკავშირდება, ამიტომ გარემომ, რომელიც ზღუდავს ქსელურ წვდომას, მხოლოდ ეს დომენი უნდა დაუშვას. იმ CLI-ის გამოსაყენებლად, რომელიც არ არის `PATH`-ზე, დააყენეთ `TUIST_MAC_CLI` მის გზაზე.

აგენტები, რომლებიც არ უჭერენ მხარს Amp პლაგინებს, როგორიცაა Claude Code ან Cursor, იგივეს აკეთებენ Tuist MCP სერვერისა და CLI-ის მეშვეობით, როგორც ეს აღწერილია <.localized_link href="/guides/features/sandboxes#coding-agents">Mac-ზე აწყობა კოდირების აგენტიდან</.localized_link>.

### Tuist Mac-ების გამოყენება Amp-ის macOS Satellites-ის ნაცვლად {#remote-mac-satellites}

Amp-ს ასევე აქვს საკუთარი ღრუბლოვანი Mac-ები, [macOS Satellites](https://ampcode.com/docs/orbs/mac), ბეტა ვერსიაში იმ სამუშაო სივრცეებისთვის, რომლებიც მის მოლოდინის სიაში შევიდნენ. როცა ნაკადს ორივეს გაშვება შეუძლია, Amp-ის ჩაშენებული ინსტრუქციები macOS სამუშაოს მის სატელიტებს უგზავნიან, ამიტომ ის იშვიათად ირჩევს პლაგინს. იმისთვის, რომ ნაკადებმა Tuist Mac-ები გამოიყენონ, გააკეთეთ ერთ-ერთი შემდეგი:

- **გამორთეთ macOS Satellites თქვენთვის.** თითოეული წევრი თიშავს მათ **Mac Satellites**-ის ქვეშ Amp-ის [Settings → Experimental Features](https://ampcode.com/settings/experimental-features)-ში.
- **გამორთეთ ისინი სამუშაო სივრცისთვის.** როცა თქვენი სამუშაო სივრცის orb-ები [Tuist-ზე ეშვება](#connect), სამუშაო სივრცის ადმინისტრატორს შეუძლია დააყენოს **Where Orbs Run** როგორც **Self-Hosted Only** Amp-ის სამუშაო სივრცის პარამეტრებში, **Orbs**-ის ქვეშ. აგენტები შემდეგ ვერ გაუშვებენ Amp-ის მიერ დაჰოსტებულ სატელიტებს, მაგრამ წევრებიც ვერ გამოიყენებენ Amp-ის ჩაშენებულ orb-ებს, ამიტომ ეს გააკეთეთ მხოლოდ მაშინ, როცა თქვენი ყველა ნაკადი თქვენს საკუთარ orb პროვაიდერებზე ეშვება.
- **მოითხოვეთ Tuist Mac-ები.** დაამატეთ „გამოიყენეთ `tuist_mac_*` ინსტრუმენტები macOS სამუშაოსთვის, არა macOS Satellites.“ პრომპტში, ან თქვენი სამუშაო სივრცის აგენტის მითითებებში Amp-ის სამუშაო სივრცის პარამეტრებში, რათა ყოველმა ნაკადმა მიჰყვეს მას.
