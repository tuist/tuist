# Rust-ის ბილდების ანალიტიკა {#rust-build-insights}

Build Insights გეხმარებათ იპოვოთ, რა ანელებს თქვენს Cargo ბილდებს და აღმოაჩინოთ რეგრესიები მანამ, სანამ ისინი გუნდს შეეხება. შეგიძლიათ შეადაროთ ლოკალური ბილდები CI-ს, ნახოთ, როგორ იცვლება ბილდის დრო და შეამოწმოთ თითოეულ ბილდში კომპილირებული კრეიტები.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - მიჰყევით <.localized_link href="/guides/get-started/rust-project">Rust პროექტის მოწყობას</.localized_link>, რათა დააკავშიროთ თქვენი პროექტი და გაიაროთ ავთენტიფიკაცია.

## ბილდების ანგარიშგება {#report-your-builds}

გაუშვით თქვენი ჩვეულებრივი Cargo ბრძანებები Tuist-ის საშუალებით:

```sh
tuist cargo build --workspace
tuist cargo check --all-targets
tuist cargo +nightly build --features tracing
```

თუ იყენებთ mise-ს, <.localized_link href="/guides/get-started/rust-project#keep-typing-cargo">მოაწყეთ Cargo wrapper</.localized_link>, რათა განაგრძოთ ჩვეულებრივი `cargo` ბრძანებების გამოყენება. არგუმენტები, ინსტრუმენტების შერჩევა, გამოსავალი და გასვლის კოდი უცვლელი რჩება.

## იპოვეთ, რა ანელებს ბილდს {#explore-your-builds}

გახსენით ბილდი დაფაზე **Builds → Build Runs** მონაკვეთიდან. გამოიყენეთ თარიღის, გარემოს და Rust-ის ვერსიის ფილტრები მსგავსი ბილდების შესადარებლად. ბილდები და მათი ქეშის მრიცხველები ასევე ხელმისაწვდომია `tuist build cargo list` და `tuist build cargo show`, `GET /api/projects/{account_handle}/{project_handle}/cargo/builds`-ის, ასევე `list_cargo_builds` და `get_cargo_build` <.localized_link href="/guides/features/agentic-coding/mcp">MCP ინსტრუმენტების</.localized_link> საშუალებით.

**Overview**-ზე გამოიყენეთ **კომპილატორის ამოცანები** ნელი კრეიტების საპოვნელად. დაალაგეთ **ხანგრძლივობის** ან **დაწყების დროის** მიხედვით (დრო Cargo ბრძანების დაწყებიდან), ან მოძებნეთ კრეიტის სახელით ან ძირითადი საწყისი ფაილით.

თითოეული სტრიქონი წარმოადგენს ერთ `rustc` გამოძახებას კრეიტისთვის, რომელიც შეიძლება შეიცავდეს მრავალ საწყის ფაილს. **კრეიტის ძირი** განსაზღვრავს მის ძირითად საწყის ფაილს; ხანგრძლივობა ეხება მთლიან კომპილატორის ამოცანას, არა მხოლოდ ამ ფაილს. კრეიტი შეიძლება გამოჩნდეს ერთზე მეტჯერ სხვადასხვა სამიზნეების ან კონფიგურაციებისთვის. კომპილატორის შეტყობინებები დაჯგუფებულია **გაფრთხილებებში** და **შეცდომებში**.

### კრეიტების თვალყურის დევნა ბილდებს შორის {#crate-history}

როდესაც თქვენი პროექტისთვის ხელმისაწვდომია, **Builds → Crates** აჩვენებს დაფიქსირებულ კრეიტებს და მათ კომპილაციის ისტორიას. გახსენით კრეიტი, რათა შეადაროთ მისი დაფიქსირებული ხანგრძლივობები და შედეგები ბილდებს შორის, შემდეგ კი მიჰყევით კომპილაციას უკან მის Cargo ბილდამდე. იგივე ინვენტარი ხელმისაწვდომია `/cargo/crates`-ის საშუალებით პროექტის API-ში და საერთო MCP build-entity ინსტრუმენტებში `kind: cargo_crates`-ით.

კრეიტები დაჯგუფებულია მათი ზუსტად დაფიქსირებული ძირითადი გზის, სახელის და ტიპის მიხედვით. Checkout გზების ცვლილებამ შეიძლება გაყოს ისტორიები; პროფილები, ფუნქციები და სამიზნე triples არ განიხილება. ეს არის დაფიქსირებული კომპილატორის ამოცანების ინვენტარი, არა თქვენი workspace-ის ყველა კრეიტი. ქეშირებული ან აქტუალური კრეიტები არ ქმნიან კომპილაციის ნიმუშებს.

### ბილდის ანგარიშების მიკუთვნება {#report-attribution}

ავთენტიფიცირებული ანგარიშები აიდენტიფიცირებს პირს პირადი მონაცემების უკან. საერთო მონაცემები არ საჭიროებს ინდივიდის იდენტიფიცირებას. სურვილისამებრ დააყენეთ `TUIST_ACTOR_ID` სტაბილურ opaque იდენტიფიკატორზე ანგარიშგების მანქანაზე; ის გამორთულია ნაგულისხმევად და ჩანს როგორც დაუდასტურებელი მოთხოვნა, არასოდეს გამოიყენება ავტორიზაციისთვის. ძველმა სერვერებმა შეიძლება უგულებელყონ მოთხოვნა. არ ჩადოთ მასში საიდუმლოები.

## დროების წაკითხვა {#timing-boundaries}

ბილდის ხანგრძლივობა არის დრო, რაც მთლიანმა Cargo ბრძანებამ წაიღო. კომპილატორის ამოცანებს შეუძლიათ პარალელურად შესრულება, ამიტომ მათი ხანგრძლივობები არ ჯამდება ბილდის ხანგრძლივობაში.

Cargo აკომპილირებს მხოლოდ იმ კრეიტებს, რომლებსაც გადაკომპილირება სჭირდებათ. კრეიტები, რომლებიც უკვე აქტუალურია, არ გამოჩნდებიან კომპილატორის სიაში. Tuist-ის კომპილაციის ქეშით, აღდგენილი ამოცანები ჩანს ქეშის გაზომვებში, არა როგორც კომპილატორის შესრულებები.

Tuist არ ზომავს ბილდის სკრიპტებს ცალ-ცალკე და არ აჩვენებს ბილდის Timeline-ს. დიდი ბილდი აჩვენებს პირველ 500 კომპილატორის ამოცანას, შეტყობინებით, თუ მეტი იყო დაფიქსირებული.

## ქეშის გაზომვების წაკითხვა {#cache-measurements}

`tuist cargo` მოიცავს ექსპერიმენტულ კომპილაციის ქეშს, რომელიც განხორციელებულია Tuist CLI-ში. მიჰყევით <.localized_link href="/guides/features/cache/rust">Rust ქეშის სახელმძღვანელოს</.localized_link> მოწყობის, Kura-ს საშუალებით დისტანციური კითხვისა და ჩაწერის, მხარდაჭერილი კომპილაციების და პრობლემების გადაჭრისთვის.

გახსენით **Cargo Cache** პროექტის გვერდით პანელში, რათა თვალყური ადევნოთ ქეშში მოხვედრის მაჩვენებლებს და დაფიქსირებულ გადაცემის, ლატენტობის და გამტარუნარიანობის გაზომვებს ბილდებს შორის. გაფილტრეთ თარიღით ან გარემოთი, გადაერთეთ ყოველდღიურ ტენდენციებსა და ინდივიდუალური ბილდის ქეშში მოხვედრის მაჩვენებლებს შორის, ან გახსენით ბოლო ბილდი მისი ქეშის აქტივობის შესამოწმებლად. ბილდები ქეშის გაზომვების გარეშე რჩება ხელმიუწვდომელი, ნულის ნაცვლად.

გახსენით ბილდის **Cache** ჩანართი, რათა ნახოთ ამოცანების ქეშში მოხვედრა, გამოტოვება, ქეშში მოხვედრის მაჩვენებელი და ჩამოტვირთული და ატვირთული ბაიტები. ჩანართი ჩნდება, როდესაც ბილდი ანგარიშგებს ქეშის მონაცემებს.

- **ქეშირებადი ამოცანები** აჩვენებს, რომელმა კომპილატორის და ბილდის სკრიპტის ამოცანებმა გამოიყენეს ქეშირებული გამოსავალი. მოძებნეთ ან გაფილტრეთ ამოცანები, შეამოწმეთ ქეშის კითხვა/ჩაწერის ლატენტობა და გაშალეთ სტრიქონი მისი გამოსავალის სანახავად.
- **CAS Outputs** აჩვენებს არტეფაქტების ჩამოტვირთვებს და ატვირთვებს, მათი ზომებით, ხანგრძლივობებით და გამტარუნარიანობით. დიაგრამა ითვლის დასრულებულ გადაცემებს; უკვე არსებული არტეფაქტები და წარუმატებელი ცდები რჩება ცხრილში.

**ქეშში მოხვედრა** ნიშნავს, რომ ქეშირებული გამოსავალი ხელახლა იქნა გამოყენებული. **გამოტოვება** ნიშნავს, რომ ამოცანა კომპილირდა. ქეშში მოხვედრა არ იყოფა ლოკალურ და დისტანციურად; CAS Outputs აჩვენებს დაფიქსირებულ არტეფაქტის ოპერაციებს.

თუ დეტალური ჩანაწერები აკლია ან არასრულია, გვერდი აჩვენებს შეტყობინებას. შეჯამება მაინც მოიცავს მთლიან ბილდს. თავიდან აცილებული სავარაუდო კომპილატორის სამუშაო **არ არის შენახული ბილდის დრო**.

### ბილდები, რომლებიც ასრულებენ ტესტებს {#builds-that-run-tests}

`tuist cargo test` ანგარიშგებს მთლიანი ბრძანების ხანგრძლივობას, მისი ტესტების ჩათვლით. ის ასევე ანგარიშგებს ინდივიდუალურ ტესტის შედეგებს, doctests-ის ჩათვლით, <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link>-ის საშუალებით. ინდივიდუალური ტესტის შედეგები ჩანს **Tests**-ის ქვეშ; ბრძანების ხანგრძლივობა ჩანს ბილდის ანალიტიკაში.

## სხვა კომპილატორის ინსტრუმენტები {#other-compiler-tools}

Tuist ინარჩუნებს არსებულ კომპილატორის wrappers-ს, კონფიგურირებულს `RUSTC_WRAPPER`, `CARGO_BUILD_RUSTC_WRAPPER` ან Cargo კონფიგურაციის საშუალებით, და ტოვებს `RUSTC_WORKSPACE_WRAPPER` უცვლელად. წინასწარ არსებული გლობალური wrapper თიშავს Tuist-ის ქეშს და კომპილატორის დამკვირვებელს: Tuist ვერ ადგენს, გაუშვა თუ არა ამ wrapper-მა rustc. მორგებული workspace wrappers-მაც შეიძლება ნაკლები კომპილატორის ამოცანა დატოვოს ანგარიშში.

Tuist პოულობს Cargo-ს rustup-ის საშუალებით. თუ იყენებთ მორგებულ ინსტალაციას, დააყენეთ `TUIST_CARGO_EXECUTABLE` მის executable გზაზე. Cargo-ს პირდაპირი toolchain გზით გამოძახება ავლინებს mise-ის wrapper-ს. Cargo alias ვერ ჩაანაცვლებს ჩაშენებულ ბრძანებას, როგორიცაა `build`.

თუ იყენებთ Cargo-ს nightly `-C` პარამეტრს, ჯერ შედით workspace-ში: Tuist გადასცემს `-C` ბრძანებებს, მაგრამ არ აგროვებს მათ ბილდის დროებს.

## პრობლემების გადაჭრა {#troubleshooting}

თუ ბილდი არ ჩანს დაფაზე, ჩართეთ debug გამოსავალი, რათა ნახოთ, რატომ არ გაიგზავნა მისი ანგარიში:

```sh
TUIST_DEBUG=1 tuist cargo build --workspace
```

ანგარიშგება არ ცვლის თქვენი ბილდის შედეგს.
