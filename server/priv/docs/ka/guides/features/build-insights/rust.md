# Rust ბილდების ანალიტიკა {#rust-build-insights}

Build Insights გეხმარებათ იპოვოთ, რა ანელებს თქვენს Cargo ბილდებს და აღმოაჩინოთ რეგრესიები სანამ ისინი მთელ გუნდს შეეხებიან. შეგიძლიათ შეადაროთ ლოკალური ბილდები CI-ს, ნახოთ როგორ იცვლება ბილდის დროები და შეამოწმოთ კრეიტები, რომლებიც თითოეულ ბილდში კომპილირდა.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - მიჰყევით <.localized_link href="/guides/get-started/rust-project">Rust პროექტის დაყენებას</.localized_link>, რათა დააკავშიროთ თქვენი პროექტი და გაიაროთ ავთენტიკაცია.

## ბილდების მოხსენება {#report-your-builds}

გაუშვით თქვენი ჩვეულებრივი Cargo ბრძანებები Tuist-ის მეშვეობით:

```sh
tuist cargo build --workspace
tuist cargo check --all-targets
tuist cargo +nightly build --features tracing
```

თუ იყენებთ mise-ს, <.localized_link href="/guides/get-started/rust-project#keep-typing-cargo">კონფიგურაციეთ Cargo wrapper</.localized_link>, რათა განაგრძოთ ჩვეულებრივი `cargo` ბრძანებების გამოყენება. თქვენი არგუმენტები, ტულჩეინის შერჩევა, გამოტანა და გამოსვლის კოდი უცვლელი რჩება.

## იპოვეთ, რა ანელებს ბილდს {#explore-your-builds}

გახსენით ბილდი დაფაზე **Builds → Build Runs**-დან. გამოიყენეთ თარიღის, გარემოს და Rust-ის ვერსიის ფილტრები მსგავსი ბილდების შესადარებლად. ბილდები და მათი ქეშის მრიცხველები ასევე ხელმისაწვდომია `tuist build cargo list` და `tuist build cargo show`, `GET /api/projects/{account_handle}/{project_handle}/cargo/builds` და `list_cargo_builds` და `get_cargo_build` <.localized_link href="/guides/features/agentic-coding/mcp">MCP ინსტრუმენტების</.localized_link> მეშვეობით.

**Overview**-ზე, გამოიყენეთ **Compiler jobs** ნელი კრეიტების საპოვნელად. დაალაგეთ **Duration**-ით ან **Started after**-ით (დრო Cargo ბრძანების დაწყებიდან), ან მოძებნეთ კრეიტის სახელით ან ძირითადი საწყისი ფაილით.

თითოეული სტრიქონი წარმოადგენს ერთ `rustc` გამოძახებას კრეიტისთვის, რომელსაც შეიძლება ბევრი საწყისი ფაილი ჰქონდეს. **Crate root** განსაზღვრავს მის ძირითად საწყის ფაილს; ხანგრძლივობა ეხება მთლიან კომპილატორის სამუშაოს, არა მხოლოდ ამ ფაილს. კრეიტი შეიძლება ერთზე მეტჯერ გამოჩნდეს სხვადასხვა მიზნებისთვის ან კონფიგურაციებისთვის. კომპილატორის შეტყობინებები დაჯგუფებულია **Warnings** და **Errors**-ში.

### კრეიტების თვალყურის დევნა ბილდებს შორის {#crate-history}

როცა თქვენი პროექტისთვის ხელმისაწვდომია, **Builds → Crates** აჩვენებს დაფიქსირებულ კრეიტებს და მათ კომპილაციის ისტორიას. გახსენით კრეიტი, რათა შეადაროთ მისი დაფიქსირებული ხანგრძლივობები და შედეგები ბილდებს შორის, შემდეგ კი მიჰყევით კომპილაციას უკან მის Cargo ბილდამდე. იგივე ინვენტარი ხელმისაწვდომია `/cargo/crates`-ით პროექტის API-ში და საერთო MCP build-entity ინსტრუმენტებით `kind: cargo_crates`-ით.

კრეიტები დაჯგუფებულია მათი ზუსტად დაფიქსირებული ძირითადი გზის, სახელის და ტიპის მიხედვით. checkout გზების ცვლილებამ შეიძლება გაყოს ისტორიები; პროფილები, ფუნქციები და target triples არ განირჩევა. ეს არის დაფიქსირებული კომპილატორის სამუშაოების ინვენტარი, არა თქვენი workspace-ის ყველა კრეიტი. ქეშირებული ან აქტუალური კრეიტები არ ქმნიან კომპილაციის ნიმუშებს.

### ბილდის მოხსენებების მიკუთვნება {#report-attribution}

ავთენტიფიცირებული მოხსენებები აიდენტიფიცირებენ პირს პირადი სერთიფიკატების უკან. გაზიარებულ სერთიფიკატებს არ სჭირდებათ ინდივიდის იდენტიფიცირება. სურვილისამებრ, დააყენეთ `TUIST_ACTOR_ID` სტაბილურ ოპაკურ იდენტიფიკატორზე მოხსენების მანქანაზე; ის გამორთულია ნაგულისხმევად და გამოისახება როგორც დაუდასტურებელი განცხადება, რომელიც არასოდეს გამოიყენება ავტორიზაციისთვის. ძველმა სერვერებმა შეიძლება უგულებელყონ განცხადება. არ ჩადოთ მასში საიდუმლოებები.

## დროების წაკითხვა {#timing-boundaries}

ბილდის ხანგრძლივობა არის დრო, რაც მთლიანმა Cargo ბრძანებამ წაიღო. კომპილატორის სამუშაოები შეიძლება პარალელურად შესრულდეს, ამიტომ მათი ხანგრძლივობები არ ჯამდება ბილდის ხანგრძლივობამდე.

Cargo კომპილირებს მხოლოდ იმ კრეიტებს, რომლებსაც გადაკომპილაცია სჭირდებათ. კრეიტები, რომლებიც უკვე აქტუალურია, არ გამოჩნდებიან კომპილატორის სიაში. Tuist-ის კომპილაციის ქეშით, აღდგენილი სამუშაოები ჩანს ქეშის გაზომვებში, არა როგორც კომპილატორის შესრულებები.

Tuist არ ზომავს build scripts-ებს ცალკე ან არ აჩვენებს ბილდის Timeline-ს. დიდი ბილდი აჩვენებს პირველ 500 კომპილატორის სამუშაოს, შეტყობინებით, თუ მეტი იყო დაფიქსირებული.

## ქეშის გაზომვების წაკითხვა {#cache-measurements}

`tuist cargo` შეიცავს ექსპერიმენტულ კომპილაციის ქეშს, რომელიც განხორციელებულია Tuist CLI-ში. მიჰყევით <.localized_link href="/guides/features/cache/rust">Rust ქეშის სახელმძღვანელოს</.localized_link> დაყენების, Kura-ს მეშვეობით დისტანციური წაკითხვების და ჩაწერების, მხარდაჭერილი კომპილაციების და პრობლემების გადაჭრისთვის.

გახსენით **Cargo Cache** პროექტის გვერდითა პანელში, რათა თვალყური ადევნოთ ქეშში მოხვედრის მაჩვენებლებს და დაფიქსირებულ გადაცემის, ლატენტურობის და გამტარუნარიანობის გაზომვებს ბილდებს შორის. გაფილტრეთ თარიღით ან გარემოთი, გადაერთეთ ყოველდღიურ ტენდენციებსა და ინდივიდუალური ბილდის ქეშში მოხვედრის მაჩვენებლებს შორის, ან გახსენით ბოლო ბილდი მისი ქეშის აქტივობის შესამოწმებლად. ბილდები ქეშის გაზომვების გარეშე რჩება ხელმისაწვდომი და არ ითვლება ნულად.

გახსენით ბილდის **Cache** ჩანართი, რათა ნახოთ ამოცანების ქეშში მოხვედრა, ამოცანების გამოტოვება, ქეშში მოხვედრის მაჩვენებელი და ჩამოტვირთული და ატვირთული ბაიტები. ჩანართი ჩნდება, როცა ბილდი აწვდის ქეშის მონაცემებს.

- **Cacheable Tasks** აჩვენებს, რომელმა კომპილატორის და build-script ამოცანებმა გამოიყენეს ქეშირებული გამოტანები. მოძებნეთ ან გაფილტრეთ ამოცანები, შეამოწმეთ ქეშის წაკითხვის/ჩაწერის ლატენტურობა და გააფართოვეთ სტრიქონი მისი გამოტანების სანახავად.
- **CAS Outputs** აჩვენებს არტეფაქტების ჩამოტვირთვებს და ატვირთვებს, მათი ზომებით, ხანგრძლივობებით და გამტარუნარიანობით. დიაგრამა ითვლის დასრულებულ გადაცემებს; უკვე არსებული არტეფაქტები და წარუმატებელი მცდელობები რჩება ცხრილში.

**Hit** ნიშნავს, რომ ქეშირებული გამოტანები ხელახლა იქნა გამოყენებული. **Missed** ნიშნავს, რომ ამოცანა კომპილირდა. ქეშში მოხვედრა არ იყოფა ლოკალურად და დისტანციურად; CAS Outputs აჩვენებს დაფიქსირებულ არტეფაქტის ოპერაციებს.

თუ დეტალური ჩანაწერები აკლია ან არასრულია, გვერდი აჩვენებს შეტყობინებას. შეჯამება კვლავ ფარავს მთლიან ბილდს. თავიდან აცილებული სავარაუდო კომპილატორის სამუშაო **არ არის შენახული ბილდის დრო**.

### ბილდები, რომლებიც ტესტებს უშვებენ {#builds-that-run-tests}

`tuist cargo test` აწვდის მთლიანი ბრძანების ხანგრძლივობას, მისი ტესტების ჩათვლით. ის ასევე აწვდის ინდივიდუალურ ტესტის შედეგებს, doctests-ების ჩათვლით, <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link>-ის მეშვეობით. ინდივიდუალური ტესტის შედეგები ჩანს **Tests**-ის ქვეშ; ბრძანების ხანგრძლივობა ჩანს ბილდის ანალიტიკაში.

## სხვა კომპილატორის ინსტრუმენტები {#other-compiler-tools}

Tuist ინარჩუნებს არსებულ კომპილატორის wrapper-ებს, რომლებიც კონფიგურირებულია `RUSTC_WRAPPER`, `CARGO_BUILD_RUSTC_WRAPPER`, ან Cargo კონფიგურაციის მეშვეობით, და ტოვებს `RUSTC_WORKSPACE_WRAPPER` უცვლელად. წინასწარ არსებული გლობალური wrapper თიშავს Tuist-ის ქეშს და კომპილატორის დამკვირვებელს: Tuist ვერ ადგენს, ნამდვილად გაუშვა თუ არა ამ wrapper-მა rustc. მორგებული workspace wrapper-ებმა ასევე შეიძლება ნაკლები კომპილატორის სამუშაო დატოვონ მოხსენებაში.

Tuist პოულობს Cargo-ს rustup-ის მეშვეობით. თუ იყენებთ მორგებულ ინსტალაციას, დააყენეთ `TUIST_CARGO_EXECUTABLE` მის executable გზაზე. Cargo-ს პირდაპირი toolchain გზით გამოძახება bypass-ს უკეთებს mise-ის wrapper-ს. Cargo alias-ს არ შეუძლია ჩაანაცვლოს ჩაშენებული ბრძანება, როგორიცაა `build`.

თუ იყენებთ Cargo-ს nightly `-C` ოფციას, ჯერ გადადით workspace-ში: Tuist გადასცემს `-C` ბრძანებებს, მაგრამ არ აგროვებს მათ ბილდის დროებს.

## პრობლემების გადაჭრა {#troubleshooting}

თუ ბილდი არ ჩანს დაფაზე, ჩართეთ debug გამოტანა, რათა ნახოთ, რატომ არ გაიგზავნა მისი მოხსენება:

```sh
TUIST_DEBUG=1 tuist cargo build --workspace
```

მოხსენება არ ცვლის თქვენი ბილდის შედეგს.
