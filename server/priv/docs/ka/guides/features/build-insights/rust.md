# Rust-ის ბილდის ანალიტიკა {#rust-build-insights}

Build Insights გეხმარებათ იპოვოთ, რა ანელებს თქვენს Cargo ბილდებს და აღმოაჩინოთ რეგრესიები მანამ, სანამ ისინი გუნდს შეეხება. შეგიძლიათ შეადაროთ ლოკალური ბილდები CI-სთან, ნახოთ, როგორ იცვლება ბილდის დროები და შეამოწმოთ თითოეულ ბილდში კომპილირებული კრეიტები.

> [!IMPORTANT] Requirements
> - მიჰყევით <.localized_link href="/guides/get-started/rust-project">Rust პროექტის მოწყობას</.localized_link>, რათა დააკავშიროთ თქვენი პროექტი და გაიაროთ აუთენტიფიკაცია.

## ბილდების ანგარიშგება {#report-your-builds}

გაუშვით თქვენი ჩვეულებრივი Cargo ბრძანებები Tuist-ის მეშვეობით:

```sh
tuist cargo build --workspace
tuist cargo check --all-targets
tuist cargo +nightly build --features tracing
```

თუ იყენებთ mise-ს, <.localized_link href="/guides/get-started/rust-project#keep-typing-cargo">მოაწყეთ Cargo wrapper</.localized_link>, რათა განაგრძოთ ჩვეულებრივი `cargo` ბრძანებების გამოყენება. თქვენი არგუმენტები, ტულჩეინის შერჩევა, გამოტანილი მონაცემები და გამოსვლის კოდი უცვლელი რჩება.

## იპოვეთ, რა ანელებს ბილდს {#explore-your-builds}

გახსენით ბილდი დაფის **Builds → Build Runs** განყოფილებიდან. გამოიყენეთ თარიღის, გარემოს და Rust-ის ვერსიის ფილტრები მსგავსი ბილდების შესადარებლად. ბილდები და მათი ქეშის მრიცხველები ასევე ხელმისაწვდომია `tuist build cargo list` და `tuist build cargo show`, `GET /api/projects/{account_handle}/{project_handle}/cargo/builds` და `list_cargo_builds` და `get_cargo_build` <.localized_link href="/guides/features/agentic-coding/mcp">MCP ინსტრუმენტების</.localized_link> მეშვეობით.

**Overview** განყოფილებაში გამოიყენეთ **Compiler jobs** ნელი კრეიტების საპოვნელად. დაალაგეთ **Duration**-ის ან **Started after**-ის (დრო Cargo ბრძანების დაწყებიდან) მიხედვით, ან მოძებნეთ კრეიტის სახელით ან ძირითადი საწყისი ფაილით.

თითოეული სტრიქონი წარმოადგენს ერთ `rustc` გამოძახებას კრეიტისთვის, რომელიც შეიძლება შეიცავდეს მრავალ საწყის ფაილს. **Crate root** განსაზღვრავს მის ძირითად საწყის ფაილს; ხანგრძლივობა ეხება მთლიან კომპილატორის სამუშაოს, არა მხოლოდ ამ ფაილს. კრეიტი შეიძლება გამოჩნდეს ერთზე მეტჯერ სხვადასხვა სამიზნეების ან კონფიგურაციებისთვის. კომპილატორის შეტყობინებები დაჯგუფებულია **Warnings** და **Errors** კატეგორიებში.

## დროების წაკითხვა {#timing-boundaries}

ბილდის ხანგრძლივობა არის დრო, რაც მთლიანმა Cargo ბრძანებამ დაიკავა. კომპილატორის სამუშაოები შეიძლება პარალელურად შესრულდეს, ამიტომ მათი ხანგრძლივობები არ შეკრდება ბილდის ხანგრძლივობასთან.

Cargo აკომპილირებს მხოლოდ იმ კრეიტებს, რომლებსაც გადაკომპილაცია სჭირდებათ. კრეიტები, რომლებიც უკვე აქტუალურია, არ გამოჩნდება კომპილატორის სიაში. Tuist-ის კომპილაციის ქეშის გამოყენებისას, აღდგენილი სამუშაოები ჩანს ქეშის გაზომვებში, არა კომპილატორის შესრულებად.

Tuist არ ზომავს ბილდის სკრიპტებს ცალკე და არ აჩვენებს ბილდის დროის ხაზს. დიდ ბილდში ჩანს პირველი 500 კომპილატორის სამუშაო, შეტყობინებით, თუ მეტი იქნა ჩაწერილი.

## ქეშის გაზომვების წაკითხვა {#cache-measurements}

`tuist cargo` მოიცავს ექსპერიმენტულ კომპილაციის ქეშს, რომელიც განხორციელებულია Tuist CLI-ში. მიჰყევით <.localized_link href="/guides/features/cache/rust">Rust ქეშის სახელმძღვანელოს</.localized_link> მოწყობის, Kura-ს მეშვეობით დისტანციური კითხვებისა და ჩაწერების, მხარდაჭერილი კომპილაციების და პრობლემების გადაჭრისთვის.

გახსენით **Cargo Cache** პროექტის გვერდითა პანელში, რათა თვალყური ადევნოთ ქეშში მოხვედრის მაჩვენებლებს და ჩაწერილ გადაცემის, ლატენტობისა და გამტარუნარიანობის გაზომვებს ბილდებში. გაფილტრეთ თარიღის ან გარემოს მიხედვით, გადაერთეთ ყოველდღიურ ტრენდებსა და ინდივიდუალური ბილდის ქეშში მოხვედრის მაჩვენებლებს შორის, ან გახსენით ბოლო ბილდი მისი ქეშის აქტივობის შესამოწმებლად. ბილდები ქეშის გაზომვების გარეშე რჩება მიუწვდომლად, ნულის ნაცვლად.

გახსენით ბილდის **Cache** ჩანართი, რათა ნახოთ ამოცანების ქეშში მოხვედრა, ამოცანების გამოტოვება, ქეშში მოხვედრის მაჩვენებელი და ჩამოტვირთული და ატვირთული ბაიტები. ჩანართი ჩნდება, როდესაც ბილდი ანგარიშგებს ქეშის მონაცემებს.

- **Cacheable Tasks** აჩვენებს, რომელმა კომპილატორისა და ბილდის სკრიპტის ამოცანებმა გამოიყენეს ქეშირებული შედეგები. მოძებნეთ ან გაფილტრეთ ამოცანები, შეამოწმეთ ქეშის კითხვის/ჩაწერის ლატენტობა და გაშალეთ სტრიქონი მისი შედეგების სანახავად.
- **CAS Outputs** აჩვენებს არტეფაქტების ჩამოტვირთვებს და ატვირთვებს, მათი ზომებით, ხანგრძლივობებითა და გამტარუნარიანობით. დიაგრამა ითვლის დასრულებულ გადაცემებს; უკვე არსებული არტეფაქტები და წარუმატებელი მცდელობები რჩება ცხრილში.

**Hit** ნიშნავს, რომ ქეშირებული შედეგები ხელახლა იქნა გამოყენებული. **Missed** ნიშნავს, რომ ამოცანა მაინცდამაინც კომპილირდა. ქეშში მოხვედრები არ იყოფა ლოკალურად და დისტანციურად; CAS Outputs აჩვენებს ჩაწერილ არტეფაქტის ოპერაციებს.

თუ დეტალური ჩანაწერები აკლია ან არასრულია, გვერდი აჩვენებს შეტყობინებას. შეჯამება მაინც მოიცავს მთლიან ბილდს. თავიდან აცილებული კომპილატორის სავარაუდო სამუშაო **არ არის დაზოგილი ბილდის დრო**.

> [!WARNING] Experimental compilation cache
> პირველი ვერსია აკეთებს ქეშს მხოლოდ რეესტრის ბოლო დონის ბიბლიოთეკებისთვის დადასტურებული შეყვანებითა და შედეგებით. სამუშაო სივრცის კრეიტები, ბილდის სკრიპტები, პროცედურული მაკროსები, დამოკიდებულებები სხვა კრეიტებზე, ინკრემენტული კომპილაცია, ნატიური დაკავშირება და შესრულებადი ფაილები ჩვეულებრივად იბილდება. ქეშის გასაღებები ინარჩუნებენ აბსოლუტურ გზებს, ამიტომ ხელახლა გამოყენება სხვადასხვა checkout გზებზე ჯერჯერობით არ არის მხარდაჭერილი.

### ბილდები, რომლებიც ტესტებს აწარმოებენ {#builds-that-run-tests}

`tuist cargo test` ანგარიშგებს მთლიანი ბრძანების ხანგრძლივობას, მისი ტესტების ჩათვლით. ის ასევე ანგარიშგებს ინდივიდუალურ ტესტის შედეგებს, doctests-ის ჩათვლით, <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link>-ის მეშვეობით. ინდივიდუალური ტესტის შედეგები ჩანს **Tests** ქვეშ; ბრძანების ხანგრძლივობა ჩანს ბილდის ანალიტიკაში.

## სხვა კომპილატორის ინსტრუმენტები {#other-compiler-tools}

Tuist ინარჩუნებს არსებულ კომპილატორის wrappers-ებს, რომლებიც კონფიგურირებულია `RUSTC_WRAPPER`, `CARGO_BUILD_RUSTC_WRAPPER`, ან Cargo კონფიგურაციის მეშვეობით და ტოვებს `RUSTC_WORKSPACE_WRAPPER` უცვლელად. წინასწარ არსებული გლობალური wrapper თიშავს Tuist-ის ქეშსა და კომპილატორის დამკვირვებელს: Tuist ვერ ადგენს, ამ wrapper-მა რეალურად გაუშვა თუ არა rustc. მორგებული სამუშაო სივრცის wrappers-ებმა ასევე შეიძლება ნაკლები კომპილატორის სამუშაო დატოვონ ანგარიშში.

Tuist პოულობს Cargo-ს rustup-ის მეშვეობით. თუ იყენებთ მორგებულ ინსტალაციას, დააყენეთ `TUIST_CARGO_EXECUTABLE` მის შესრულებად ფაილზე. Cargo-ს გამოძახება პირდაპირი ტულჩეინის გზით ავლის mise-ის wrapper-ს. Cargo alias ვერ ჩაანაცვლებს ჩაშენებულ ბრძანებას, როგორიცაა `build`.

თუ იყენებთ Cargo-ს nightly `-C` ოფციას, ჯერ გადადით სამუშაო სივრცეში: Tuist გადასცემს `-C` ბრძანებებს, მაგრამ არ აგროვებს მათ ბილდის დროებს.

## პრობლემების გადაჭრა {#troubleshooting}

თუ ბილდი არ ჩანს დაფაზე, ჩართეთ debug გამოტანა, რათა ნახოთ, რატომ არ გაიგზავნა მისი ანგარიში:

```sh
TUIST_DEBUG=1 tuist cargo build --workspace
```

ანგარიშგება არ ცვლის თქვენი ბილდის შედეგს.
