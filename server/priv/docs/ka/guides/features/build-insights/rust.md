# Rust ბილდის ინსაიტები {#rust-build-insights}

Build Insights გეხმარებათ იპოვოთ, რა ანელებს თქვენს Cargo ბილდებს და აღმოაჩინოთ რეგრესიები მანამ, სანამ ისინი გუნდს შეეხება. შეგიძლიათ შეადაროთ ლოკალური ბილდები CI-ს, ნახოთ, როგორ იცვლება ბილდის დროები და შეამოწმოთ თითოეულ ბილდში კომპილირებული კრეიტები.

> [!IMPORTANT] Requirements
> - მიჰყევით <.localized_link href="/guides/get-started/rust-project">Rust პროექტის მოწყობას</.localized_link>, რათა დააკავშიროთ თქვენი პროექტი და გაიაროთ ავთენტიკაცია.

## შეატყობინეთ თქვენი ბილდები {#report-your-builds}

გაუშვით თქვენი ჩვეულებრივი Cargo ბრძანებები Tuist-ის მეშვეობით:

```sh
tuist cargo build --workspace
tuist cargo check --all-targets
tuist cargo +nightly build --features tracing
```

თუ იყენებთ mise-ს, <.localized_link href="/guides/get-started/rust-project#keep-typing-cargo">მოაწყვეთ Cargo wrapper</.localized_link>, რათა განაგრძოთ ჩვეულებრივი `cargo` ბრძანებების გამოყენება. თქვენი არგუმენტები, ტულჩეინის შერჩევა, გამონატანი და გასვლის კოდი უცვლელი რჩება.

## იპოვეთ, რა ანელებს ბილდს {#explore-your-builds}

გახსენით ბილდი **ბილდები → ბილდის გაშვებები**-დან დაფაზე. გამოიყენეთ თარიღის, გარემოს და Rust-ის ვერსიის ფილტრები მსგავსი ბილდების შესადარებლად. ბილდები და მათი ქეშის მრიცხველები ასევე ხელმისაწვდომია `tuist build cargo list`-ის და `tuist build cargo show`-ის, `GET /api/projects/{account_handle}/{project_handle}/cargo/builds`-ის, ასევე `list_cargo_builds` და `get_cargo_build` <.localized_link href="/guides/features/agentic-coding/mcp">MCP ინსტრუმენტების</.localized_link> მეშვეობით.

**მიმოხილვა**-ზე გამოიყენეთ **კომპილატორის ამოცანები** ნელი კრეიტების საპოვნელად. დაალაგეთ **ხანგრძლივობის** ან **დაწყებული შემდეგ** (დრო Cargo ბრძანების დაწყებიდან) მიხედვით, ან მოძებნეთ კრეიტის სახელით ან ძირითადი საწყისი ფაილით.

თითოეული სტრიქონი წარმოადგენს ერთ `rustc` გამოძახებას კრეიტისთვის, რომელიც შეიძლება შეიცავდეს მრავალ საწყის ფაილს. **კრეიტის ძირი** განსაზღვრავს მის ძირითად საწყის ფაილს; ხანგრძლივობა ეხება მთლიან კომპილატორის ამოცანას, არა მხოლოდ ამ ფაილს. კრეიტი შეიძლება გამოჩნდეს ერთზე მეტჯერ სხვადასხვა სამიზნეების ან კონფიგურაციებისთვის. კომპილატორის შეტყობინებები დაჯგუფებულია **გაფრთხილებებში** და **შეცდომებში**.

### კრეიტების თვალყურის დევნა ბილდებს შორის {#crate-history}

პროექტებისთვის, რომლებიც ჩართულია კრეიტების ისტორიის ეტაპობრივად დანერგვაში, **ბილდები → კრეიტები** აჩვენებს დაფიქსირებულ კრეიტებს და მათ კომპილაციის ისტორიას. გახსენით კრეიტი, რათა შეადაროთ მისი დაფიქსირებული ხანგრძლივობები და შედეგები ბილდებს შორის, შემდეგ კი მიჰყევით კომპილაციას უკან მის Cargo ბილდამდე. იგივე ინვენტარი ხელმისაწვდომია `/cargo/crates`-ის მეშვეობით პროექტის API-ში და საერთო MCP build-entity ინსტრუმენტებში `kind: cargo_crates`-ით.

კრეიტები დაჯგუფებულია მათი ზუსტად დაფიქსირებული ძირითადი გზის, სახელის და ტიპის მიხედვით. checkout გზების ცვლილებამ შეიძლება გაყოფოს ისტორიები; პროფილები, ფუნქციები და სამიზნე ტრიპლეტები არ განირჩევა. ეს არის დაფიქსირებული კომპილატორის ამოცანების ინვენტარი, არა თქვენი workspace-ის ყველა კრეიტი. ქეშირებული ან აქტუალური კრეიტები არ ქმნიან კომპილაციის ნიმუშებს.

### ბილდის ანგარიშების მიკუთვნება {#report-attribution}

ავთენტიკირებული ანგარიშები აიდენტიფიცირებენ პირს პირადი სერთიფიკატების უკან. საერთო სერთიფიკატებს არ სჭირდებათ ინდივიდის იდენტიფიცირება. სურვილისამებრ დააყენეთ `TUIST_ACTOR_ID` სტაბილურ ოპაკურ იდენტიფიკატორზე ანგარიშის გამგზავნ მანქანაზე; ის გამორთულია ნაგულისხმევად და ჩანს როგორც დაუდასტურებელი განცხადება, რომელიც არასდროს გამოიყენება ავტორიზაციისთვის. ძველმა სერვერებმა შეიძლება უგულებელყონ განცხადება. არ ჩადოთ მასში საიდუმლოებები.

## დროების წაკითხვა {#timing-boundaries}

ბილდის ხანგრძლივობა არის დრო, რაც მთლიანმა Cargo ბრძანებამ დაიკავა. კომპილატორის ამოცანები შეიძლება პარალელურად შესრულდეს, ამიტომ მათი ხანგრძლივობები არ შეიკრიბება ბილდის ხანგრძლივობამდე.

Cargo აკომპილირებს მხოლოდ იმ კრეიტებს, რომლებსაც გადაკომპილაცია სჭირდებათ. კრეიტები, რომლებიც უკვე აქტუალურია, არ გამოჩნდებიან კომპილატორის სიაში. Tuist-ის კომპილაციის ქეშით, აღდგენილი ამოცანები ჩანს ქეშის გაზომვებში, არა კომპილატორის შესრულებებში.

Tuist არ ზომავს build სკრიპტებს ცალ-ცალკე და არ აჩვენებს ბილდის დროის ხაზს. დიდ ბილდში ჩანს პირველი 500 კომპილატორის ამოცანა, შეტყობინებით, თუ მეტი იქნა დაფიქსირებული.

## ქეშის გაზომვების წაკითხვა {#cache-measurements}

`tuist cargo` მოიცავს ექსპერიმენტულ კომპილაციის ქეშს, რომელიც განხორციელებულია Tuist CLI-ში. მიჰყევით <.localized_link href="/guides/features/cache/rust">Rust ქეშის სახელმძღვანელოს</.localized_link> მოწყობის, Kura-ს მეშვეობით დისტანციური წაკითხვებისა და ჩაწერების, მხარდაჭერილი კომპილაციების და პრობლემების გადაჭრისთვის.

გახსენით **Cargo Cache** პროექტის გვერდითა პანელში, რათა თვალყური ადევნოთ ქეშში მოხვედრის მაჩვენებლებს და დაფიქსირებულ გადაცემის, ლატენტობის და გამტარუნარიანობის გაზომვებს ბილდებს შორის. გაფილტრეთ თარიღით ან გარემოთი, გადაერთეთ ყოველდღიურ ტრენდებსა და ინდივიდუალური ბილდის ქეშში მოხვედრის მაჩვენებლებს შორის, ან გახსენით ბოლო ბილდი მისი ქეშის აქტივობის შესამოწმებლად. ბილდები ქეშის გაზომვების გარეშე რჩება მიუწვდომელი, ნულის ნაცვლად.

გახსენით ბილდის **ქეში** ჩანართი, რათა ნახოთ ამოცანის ქეშში მოხვედრები, გამოტოვებები, ქეშში მოხვედრის მაჩვენებელი და ჩამოტვირთული და ატვირთული ბაიტები. ჩანართი ჩნდება, როდესაც ბილდი ატყობინებს ქეშის მონაცემებს.

- **ქეშირებადი ამოცანები** აჩვენებს, რომელმა კომპილატორის და build სკრიპტის ამოცანებმა ხელახლა გამოიყენეს ქეშირებული გამონატანები. მოძებნეთ ან გაფილტრეთ ამოცანები, შეამოწმეთ ქეშის წაკითხვის/ჩაწერის ლატენტობა და გაშალეთ სტრიქონი მისი გამონატანების სანახავად.
- **CAS Outputs** აჩვენებს არტეფაქტების ჩამოტვირთვებს და ატვირთვებს, მათი ზომებით, ხანგრძლივობებით და გამტარუნარიანობით. დიაგრამა ითვლის დასრულებულ გადაცემებს; უკვე არსებული არტეფაქტები და წარუმატებელი ცდები რჩება ცხრილში.

**ქეშში მოხვედრა** ნიშნავს, რომ ქეშირებული გამონატანები ხელახლა იქნა გამოყენებული. **გამოტოვებული** ნიშნავს, რომ ამოცანა კომპილირდა. ქეშში მოხვედრები არ იყოფა ლოკალურ და დისტანციურად; CAS Outputs აჩვენებს დაფიქსირებულ არტეფაქტის ოპერაციებს.

თუ დეტალური ჩანაწერები აკლია ან არასრულია, გვერდი აჩვენებს შეტყობინებას. შეჯამება მაინც მოიცავს მთლიან ბილდს. თავიდან არიდებული სავარაუდო კომპილატორის სამუშაო **არ არის შენახული ბილდის დრო**.

> [!WARNING] Experimental compilation cache
> პირველი ვერსია აქეშირებს მხოლოდ რეესტრის leaf ბიბლიოთეკებს ვერიფიცირებული შეყვანებით და გამონატანებით. Workspace კრეიტები, build სკრიპტები, პროცედურული მაკროსები, სხვა კრეიტებზე დამოკიდებულებები, ინკრემენტული კომპილაცია, ნატიური ბმები და executable-ები ჩვეულებრივად იბილდება. ქეშის გასაღებები ინარჩუნებენ აბსოლუტურ გზებს, ამიტომ ხელახლა გამოყენება სხვადასხვა checkout გზებზე ჯერჯერობით მხარდაჭერილი არ არის.

### ბილდები, რომლებიც ტესტებს უშვებენ {#builds-that-run-tests}

`tuist cargo test` ატყობინებს მთლიანი ბრძანების ხანგრძლივობას, მისი ტესტების ჩათვლით. ის ასევე ატყობინებს ინდივიდუალურ ტესტის შედეგებს, doctests-ის ჩათვლით, <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link>-ის მეშვეობით. ინდივიდუალური ტესტის შედეგები ჩანს **ტესტები**-ს ქვეშ; ბრძანების ხანგრძლივობა ჩანს ბილდის ინსაიტებში.

## სხვა კომპილატორის ინსტრუმენტები {#other-compiler-tools}

Tuist ინარჩუნებს არსებულ კომპილატორის wrapper-ებს, რომლებიც კონფიგურირებულია `RUSTC_WRAPPER`-ით, `CARGO_BUILD_RUSTC_WRAPPER`-ით ან Cargo კონფიგურაციით, და ტოვებს `RUSTC_WORKSPACE_WRAPPER` უცვლელს. წინასწარ არსებული გლობალური wrapper თიშავს Tuist-ის ქეშს და კომპილატორის დამკვირვებელს: Tuist ვერ ადგენს, ნამდვილად გაუშვა თუ არა ამ wrapper-მა rustc. მორგებული workspace wrapper-ები ასევე შეიძლება დატოვონ ნაკლები კომპილატორის ამოცანა ანგარიშში.

Tuist პოულობს Cargo-ს rustup-ის მეშვეობით. თუ იყენებთ მორგებულ ინსტალაციას, დააყენეთ `TUIST_CARGO_EXECUTABLE` მის executable გზაზე. Cargo-ს გამოძახება პირდაპირი toolchain გზით ავლით mise-ის wrapper-ს. Cargo alias ვერ ჩაანაცვლებს ჩაშენებულ ბრძანებას, როგორიცაა `build`.

თუ იყენებთ Cargo-ს nightly `-C` ოფციას, ჯერ შედით workspace-ში: Tuist გადასცემს `-C` ბრძანებებს, მაგრამ არ აგროვებს მათი ბილდის დროის მონაცემებს.

## პრობლემების მოგვარება {#troubleshooting}

თუ ბილდი არ ჩანს დაშბორდზე, ჩართეთ debug გამოტანა, რათა ნახოთ, რატომ არ გაიგზავნა მისი ანგარიში:

```sh
TUIST_DEBUG=1 tuist cargo build --workspace
```

ანგარიშის გაგზავნა არ ცვლის თქვენი ბილდის შედეგს.
