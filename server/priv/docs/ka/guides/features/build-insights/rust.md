# Rust-ის აგების ინსაიტები {#rust-build-insights}

Build Insights გეხმარებათ იპოვოთ, რა ანელებს თქვენს Cargo აგებებს და აღმოაჩინოთ რეგრესიები სანამ ისინი მთელ გუნდს შეეხებიან. შეგიძლიათ შეადაროთ ლოკალური აგებები CI-სთან, ნახოთ, როგორ იცვლება აგების დროები და შეამოწმოთ კრეიტები, რომლებიც კომპილირებულია თითოეულ აგებაში.

> [!IMPORTANT] Requirements
> - მიჰყევით <.localized_link href="/guides/get-started/rust-project">Rust-ის პროექტის დაყენებას</.localized_link>, რათა დააკავშიროთ თქვენი პროექტი და გაიაროთ ავთენტიფიკაცია.

## აგებების ანგარიშგება {#report-your-builds}

გაუშვით თქვენი ჩვეულებრივი Cargo ბრძანებები Tuist-ის მეშვეობით:

```sh
tuist cargo build --workspace
tuist cargo check --all-targets
tuist cargo +nightly build --features tracing
```

თუ იყენებთ mise-ს, <.localized_link href="/guides/get-started/rust-project#keep-typing-cargo">დააკონფიგურირეთ Cargo wrapper</.localized_link>, რათა განაგრძოთ ჩვეულებრივი `cargo` ბრძანებების გამოყენება. თქვენი არგუმენტები, ხელსაწყოს შერჩევა, გამომავალი მონაცემები და გასვლის კოდი უცვლელი რჩება.

## იპოვეთ, რა ანელებს აგებას {#explore-your-builds}

გახსენით აგება **Builds → Build Runs**-დან დაშბორდზე. გამოიყენეთ თარიღის, გარემოს და Rust-ის ვერსიის ფილტრები მსგავსი აგებების შესადარებლად. აგებები და მათი ქეშის მრიცხველები ასევე ხელმისაწვდომია `tuist build cargo list` და `tuist build cargo show`-ის, `GET /api/projects/{account_handle}/{project_handle}/cargo/builds`-ის, ასევე `list_cargo_builds` და `get_cargo_build` <.localized_link href="/guides/features/agentic-coding/mcp">MCP ხელსაწყოების</.localized_link> მეშვეობით.

**Overview**-ზე, გამოიყენეთ **Compiler jobs** ნელი კრეიტების საპოვნელად. დაალაგეთ **Duration**-ის ან **Started after**-ის (დრო Cargo ბრძანების დაწყებიდან) მიხედვით, ან მოძებნეთ კრეიტის სახელით ან ძირითადი საწყისი ფაილით.

თითოეული სტრიქონი წარმოადგენს ერთ `rustc` გამოძახებას კრეიტისთვის, რომელიც შეიძლება შეიცავდეს მრავალ საწყის ფაილს. **Crate root** აიდენტიფიცირებს მის ძირითად საწყის ფაილს; ხანგრძლივობა ეხება მთლიან კომპილატორის სამუშაოს, არა მხოლოდ ამ ფაილს. კრეიტი შეიძლება გამოჩნდეს ერთზე მეტჯერ სხვადასხვა მიზნებისთვის ან კონფიგურაციებისთვის. კომპილატორის შეტყობინებები დაჯგუფებულია **Warnings** და **Errors**-ში.

## დროების წაკითხვა {#timing-boundaries}

აგების ხანგრძლივობა არის დრო, რაც მთლიანმა Cargo ბრძანებამ წაიღო. კომპილატორის სამუშაოები შეიძლება პარალელურად შესრულდეს, ამიტომ მათი ხანგრძლივობები არ შეიკრიბება აგების ხანგრძლივობაში.

Cargo კომპილირებს მხოლოდ იმ კრეიტებს, რომლებსაც გადაკომპილირება სჭირდებათ. კრეიტები, რომლებიც უკვე აქტუალურია, არ გამოჩნდება კომპილატორის სიაში. Tuist-ის კომპილაციის ქეშით, აღდგენილი სამუშაოები ჩანს ქეშის გაზომვებში, არა როგორც კომპილატორის შესრულებები.

Tuist ცალ-ცალკე არ ზომავს აგების სკრიპტებს და არ აჩვენებს აგების Timeline-ს. დიდი აგება აჩვენებს პირველ 500 კომპილატორის სამუშაოს, შენიშვნით, თუ მეტი იყო ჩაწერილი.

## ქეშის გაზომვების წაკითხვა {#cache-measurements}

`tuist cargo` მოიცავს ექსპერიმენტულ კომპილაციის ქეშს, რომელიც განხორციელებულია Tuist CLI-ში. მიჰყევით <.localized_link href="/guides/features/cache/rust">Rust-ის ქეშის სახელმძღვანელოს</.localized_link> დაყენების, Kura-ს მეშვეობით დისტანციური წაკითხვებისა და ჩაწერების, მხარდაჭერილი კომპილაციების და პრობლემების გადაჭრისთვის.

გახსენით **Cargo Cache** პროექტის გვერდითა პანელში, რათა თვალყური ადევნოთ ქეშის მოხვედრის მაჩვენებლებს და ჩაწერილ ტრანსფერის, ლატენტობის და გამტარუნარიანობის გაზომვებს აგებების მიხედვით. გაფილტრეთ თარიღის ან გარემოს მიხედვით, გადაერთეთ ყოველდღიურ ტენდენციებსა და ინდივიდუალური აგების მოხვედრის მაჩვენებლებს შორის, ან გახსენით ბოლო აგება მისი ქეშის აქტივობის შესამოწმებლად. აგებები ქეშის გაზომვების გარეშე რჩება ხელმიუწვდომლად, ნულის ნაცვლად.

გახსენით აგების **Cache** ჩანართი, რათა ნახოთ ამოცანების მოხვედრა, გამოტოვება, მოხვედრის მაჩვენებელი და ჩამოტვირთული და ატვირთული ბაიტები. ჩანართი ჩნდება, როდესაც აგება ანგარიშგებს ქეშის მონაცემებს.

- **Cacheable Tasks** აჩვენებს, რომელმა კომპილატორის და აგების სკრიპტის ამოცანებმა გამოიყენეს ქეშირებული გამომავალი მონაცემები. მოძებნეთ ან გაფილტრეთ ამოცანები, შეამოწმეთ ქეშის წაკითხვის/ჩაწერის ლატენტობა და გაშალეთ სტრიქონი მისი გამომავალი მონაცემების სანახავად.
- **CAS Outputs** აჩვენებს არტიფაქტების ჩამოტვირთვებს და ატვირთვებს, მათი ზომებით, ხანგრძლივობებით და გამტარუნარიანობით. დიაგრამა ითვლის დასრულებულ ტრანსფერებს; უკვე არსებული არტიფაქტები და წარუმატებელი ცდები რჩება ცხრილში.

**Hit** ნიშნავს, რომ ქეშირებული გამომავალი მონაცემები ხელახლა იქნა გამოყენებული. **Missed** ნიშნავს, რომ ამოცანა კომპილირდა. მოხვედრები არ იყოფა ლოკალურ და დისტანციურად; CAS Outputs აჩვენებს ჩაწერილ არტიფაქტის ოპერაციებს.

თუ დეტალური ჩანაწერები აკლია ან არასრულია, გვერდი აჩვენებს შენიშვნას. შეჯამება მაინც მოიცავს მთლიან აგებას. თავიდან აცილებული სავარაუდო კომპილატორის სამუშაო **არ არის შენახული აგების დრო**.

> [!WARNING] Experimental compilation cache
> პირველი ვერსია ქეშირებს მხოლოდ რეესტრის leaf ბიბლიოთეკებს შემოწმებული შეყვანებით და გამომავალი მონაცემებით. Workspace კრეიტები, აგების სკრიპტები, პროცედურული მაკროსები, დამოკიდებულებები სხვა კრეიტებზე, ინკრემენტული კომპილაცია, ნატიური ლინკინგი და executable ფაილები ჩვეულებრივად აგდება. ქეშის გასაღებები ინარჩუნებენ აბსოლუტურ გზებს, ამიტომ ხელახლა გამოყენება სხვადასხვა checkout გზებზე ჯერ არ არის მხარდაჭერილი.

### აგებები, რომლებიც ატარებენ ტესტებს {#builds-that-run-tests}

`tuist cargo test` ანგარიშგებს მთლიანი ბრძანების ხანგრძლივობას, მისი ტესტების ჩათვლით. ის ასევე ანგარიშგებს ინდივიდუალურ ტესტის შედეგებს, doctests-ის ჩათვლით, <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link>-ის მეშვეობით. ინდივიდუალური ტესტის შედეგები ჩანს **Tests**-ის ქვეშ; ბრძანების ხანგრძლივობა ჩანს აგების ინსაიტებში.

## სხვა კომპილატორის ხელსაწყოები {#other-compiler-tools}

Tuist ინარჩუნებს არსებულ კომპილატორის wrappers-ს, რომლებიც კონფიგურირებულია `RUSTC_WRAPPER`-ის, `CARGO_BUILD_RUSTC_WRAPPER`-ის ან Cargo კონფიგურაციის მეშვეობით, და ტოვებს `RUSTC_WORKSPACE_WRAPPER`-ს უცვლელად. წინასწარ არსებული გლობალური wrapper თიშავს Tuist-ის ქეშს და კომპილატორის დამკვირვებელს: Tuist ვერ ადგენს, ნამდვილად გაუშვა თუ არა ამ wrapper-მა rustc. მორგებული workspace wrappers-მა ასევე შეიძლება ნაკლები კომპილატორის სამუშაო დატოვოს ანგარიშში.

Tuist პოულობს Cargo-ს rustup-ის მეშვეობით. თუ იყენებთ მორგებულ ინსტალაციას, დააყენეთ `TUIST_CARGO_EXECUTABLE` მის executable გზაზე. Cargo-ს გამოძახება პირდაპირი ხელსაწყოს გზით აცილებს mise-ის wrapper-ს. Cargo alias-მა ვერ შეცვალოს ჩაშენებული ბრძანება, როგორიცაა `build`.

თუ იყენებთ Cargo-ს nightly `-C` ოფციას, ჯერ გადადით workspace-ში: Tuist გადასცემს `-C` ბრძანებებს, მაგრამ არ აგროვებს მათ აგების დროებს.

## პრობლემების გადაჭრა {#troubleshooting}

თუ აგება არ ჩანს დაშბორდზე, ჩართეთ debug გამომავალი მონაცემები, რათა ნახოთ, რატომ არ გაიგზავნა მისი ანგარიში:

```sh
TUIST_DEBUG=1 tuist cargo build --workspace
```

ანგარიშგება არ ცვლის თქვენი აგების შედეგს.
