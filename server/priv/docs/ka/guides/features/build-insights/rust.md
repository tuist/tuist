# Rust-ის ბილდების ანალიტიკა {#rust-build-insights}

Build Insights გეხმარებათ იპოვოთ, რა ანელებს თქვენს Cargo ბილდებს და აღმოაჩინოთ რეგრესიები მანამ, სანამ ისინი გუნდს შეეხებიან. შეგიძლიათ შეადაროთ ლოკალური ბილდები CI-სთან, ნახოთ, როგორ იცვლება ბილდის დროები და შეისწავლოთ კრეიტები, რომლებიც კომპილირდა თითოეულ ბილდში.

> [!IMPORTANT] Requirements
> - მიჰყევით <.localized_link href="/guides/get-started/rust-project">Rust-ის პროექტის მოწყობას</.localized_link>, რათა დააკავშიროთ თქვენი პროექტი და გაიაროთ აუთენტიფიკაცია.

## ბილდების ანგარიშგება {#report-your-builds}

ჩვეულებრივი Cargo ბრძანებები გაუშვით Tuist-ის მეშვეობით:

```sh
tuist cargo build --workspace
tuist cargo check --all-targets
tuist cargo +nightly build --features tracing
```

თუ იყენებთ mise-ს, <.localized_link href="/guides/get-started/rust-project#keep-typing-cargo">მოაწყეთ Cargo wrapper</.localized_link>, რათა განაგრძოთ ჩვეულებრივი `cargo` ბრძანებების გამოყენება. არგუმენტები, ინსტრუმენტების ჯაჭვის შერჩევა, გამოტანილი მონაცემები და გასვლის კოდი უცვლელი რჩება.

## იპოვეთ, რა ანელებს ბილდს {#explore-your-builds}

გახსენით ბილდი **ბილდები → ბილდის გაშვებები**-დან დაფაზე. გამოიყენეთ თარიღის, გარემოს და Rust-ის ვერსიის ფილტრები მსგავსი ბილდების შესადარებლად. ბილდები და მათი ქეშის მრიცხველები ასევე ხელმისაწვდომია `tuist build cargo list` და `tuist build cargo show`, `GET /api/projects/{account_handle}/{project_handle}/cargo/builds`-ის, ასევე `list_cargo_builds` და `get_cargo_build` <.localized_link href="/guides/features/agentic-coding/mcp">MCP ინსტრუმენტების</.localized_link> მეშვეობით.

**მიმოხილვა**-ზე გამოიყენეთ **კომპილატორის ამოცანები** ნელი კრეიტების საპოვნელად. დაალაგეთ **ხანგრძლივობის** ან **დაწყებული შემდეგ** (დრო Cargo ბრძანების დაწყებიდან) მიხედვით, ან მოძებნეთ კრეიტის სახელით ან ძირითადი საწყისი ფაილით.

თითოეული სტრიქონი წარმოადგენს ერთ `rustc` გამოძახებას კრეიტისთვის, რომელსაც შეიძლება ბევრი საწყისი ფაილი ჰქონდეს. **კრეიტის ძირი** განსაზღვრავს მის ძირითად საწყის ფაილს; ხანგრძლივობა ეხება მთლიან კომპილატორის ამოცანას, არა მხოლოდ იმ ფაილს. კრეიტი შეიძლება ერთზე მეტჯერ გამოჩნდეს სხვადასხვა სამიზნეების ან კონფიგურაციებისთვის. კომპილატორის შეტყობინებები დაჯგუფებულია **გაფრთხილებებში** და **შეცდომებში**.

## დროებითი მაჩვენებლების წაკითხვა {#timing-boundaries}

ბილდის ხანგრძლივობა არის დრო, რაც მთლიანმა Cargo ბრძანებამ წაიღო. კომპილატორის ამოცანები შეიძლება პარალელურად შესრულდეს, ამიტომ მათი ხანგრძლივობები არ შეიკრიბება ბილდის ხანგრძლივობაში.

Cargo აკომპილირებს მხოლოდ იმ კრეიტებს, რომლებსაც გადაკომპილაცია სჭირდებათ. კრეიტები, რომლებიც უკვე აქტუალურია, კომპილატორის სიაში არ გამოჩნდება. Tuist-ის კომპილაციის ქეშის გამოყენებისას, აღდგენილი ამოცანები ჩანს ქეშის გაზომვებში, არა როგორც კომპილატორის შესრულებები.

Tuist ცალკე არ ზომავს ბილდის სკრიპტებს და არ აჩვენებს ბილდის დროის ხაზს. დიდ ბილდში ნაჩვენებია პირველი 500 კომპილატორის ამოცანა, შეტყობინებით, თუ მეტი იყო ჩაწერილი.

## ქეშის გაზომვების წაკითხვა {#cache-measurements}

`tuist cargo` მოიცავს ექსპერიმენტულ კომპილაციის ქეშს, რომელიც განხორციელებულია Tuist CLI-ში. მიჰყევით <.localized_link href="/guides/features/cache/rust">Rust-ის ქეშის სახელმძღვანელოს</.localized_link> მოწყობის, Kura-ს მეშვეობით დისტანციური კითხვებისა და ჩაწერების, მხარდაჭერილი კომპილაციების და პრობლემების აღმოფხვრისთვის.

გახსენით **Cargo Cache** პროექტის გვერდითა პანელში, რათა თვალყური ადევნოთ ქეშში მოხვედრის მაჩვენებლებს და ჩაწერილ გადაცემის, დაყოვნებისა და გამტარუნარიანობის გაზომვებს ბილდებში. გაფილტრეთ თარიღით ან გარემოთი, გადაერთეთ ყოველდღიურ ტენდენციებსა და ინდივიდუალური ბილდის ქეშში მოხვედრის მაჩვენებლებს შორის, ან გახსენით ბოლო ბილდი მისი ქეშის აქტივობის შესასწავლად. ბილდები ქეშის გაზომვების გარეშე რჩება ხელმიუწვდომლად, ნულის სახით არ ითვლება.

გახსენით ბილდის **ქეში** ჩანართი, რათა ნახოთ ამოცანების ქეშში მოხვედრა, გამოტოვება, ქეშში მოხვედრის მაჩვენებელი და ჩამოტვირთული და ატვირთული ბაიტები. ჩანართი ჩნდება, როდესაც ბილდი ანგარიშგებს ქეშის მონაცემებს.

- **ქეშირებადი ამოცანები** აჩვენებს, რომელმა კომპილატორისა და ბილდის სკრიპტის ამოცანებმა გამოიყენეს ქეშირებული შედეგები. მოძებნეთ ან გაფილტრეთ ამოცანები, შეისწავლეთ ქეშის კითხვის/ჩაწერის დაყოვნება და გააფართოვეთ სტრიქონი მისი შედეგების სანახავად.
- **CAS შედეგები** აჩვენებს არტეფაქტების ჩამოტვირთვებსა და ატვირთვებს, მათი ზომებით, ხანგრძლივობებითა და გამტარუნარიანობით. დიაგრამა ითვლის დასრულებულ გადაცემებს; უკვე არსებული არტეფაქტები და წარუმატებელი ცდები რჩება ცხრილში.

**ქეშში მოხვედრა** ნიშნავს, რომ ქეშირებული შედეგები ხელახლა იქნა გამოყენებული. **გამოტოვება** ნიშნავს, რომ ამოცანა კომპილირდა. ქეშში მოხვედრა არ იყოფა ლოკალურად და დისტანციურად; CAS შედეგები აჩვენებს ჩაწერილ არტეფაქტის ოპერაციებს.

თუ დეტალური ჩანაწერები აკლია ან არასრულია, გვერდი აჩვენებს შეტყობინებას. შეჯამება მაინც მოიცავს მთლიან ბილდს. თავიდან არიდებული სავარაუდო კომპილატორის სამუშაო **არ არის დაზოგილი ბილდის დრო**.

> [!WARNING] Experimental compilation cache
> პირველი ვერსია ქეშირებს მხოლოდ რეესტრის ბოლო დონის ბიბლიოთეკებს ვერიფიცირებული შეყვანებითა და შედეგებით. სამუშაო სივრცის კრეიტები, ბილდის სკრიპტები, პროცედურული მაკროსები, დამოკიდებულებები სხვა კრეიტებზე, ინკრემენტული კომპილაცია, ნატიური დაკავშირება და შესრულებადი ფაილები ჩვეულებრივად კომპილირდება. ქეშის გასაღებები ინარჩუნებენ აბსოლუტურ გზებს, ამიტომ განსხვავებული checkout გზებზე ხელახლა გამოყენება ჯერჯერობით არ არის მხარდაჭერილი.

### ბილდები, რომლებიც ტესტებს აშვებენ {#builds-that-run-tests}

`tuist cargo test` ანგარიშგებს მთლიანი ბრძანების ხანგრძლივობას, მისი ტესტების ჩათვლით. ის ასევე ანგარიშგებს ინდივიდუალურ ტესტის შედეგებს, doctests-ის ჩათვლით, <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link>-ის მეშვეობით. ინდივიდუალური ტესტის შედეგები ჩანს **ტესტები**-ის ქვეშ; ბრძანების ხანგრძლივობა ჩანს ბილდის ანალიტიკაში.

## სხვა კომპილატორის ინსტრუმენტები {#other-compiler-tools}

Tuist ინარჩუნებს არსებულ კომპილატორის wrapper-ებს, რომლებიც კონფიგურირებულია `RUSTC_WRAPPER`, `CARGO_BUILD_RUSTC_WRAPPER` ან Cargo კონფიგურაციის მეშვეობით, და ტოვებს `RUSTC_WORKSPACE_WRAPPER` უცვლელად. წინასწარ არსებული გლობალური wrapper თიშავს Tuist-ის ქეშსა და კომპილატორის დამკვირვებელს: Tuist ვერ ადგენს, ამ wrapper-მა რეალურად გაუშვა თუ არა rustc. მორგებული სამუშაო სივრცის wrapper-ები ასევე შეიძლება ნაკლებ კომპილატორის ამოცანას ტოვებდნენ ანგარიშში.

Tuist პოულობს Cargo-ს rustup-ის მეშვეობით. თუ იყენებთ მორგებულ ინსტალაციას, დააყენეთ `TUIST_CARGO_EXECUTABLE` მის შესრულებად ფაილზე. Cargo-ს პირდაპირი ინსტრუმენტების ჯაჭვის გზით გამოძახება bypass-ს უკეთებს mise-ის wrapper-ს. Cargo-ს ალიასი ვერ ჩაანაცვლებს ჩაშენებულ ბრძანებას, როგორიცაა `build`.

თუ იყენებთ Cargo-ს nightly `-C` ოფციას, ჯერ გადადით სამუშაო სივრცეში: Tuist გადასცემს `-C` ბრძანებებს, მაგრამ არ აგროვებს მათ ბილდის დროებს.

## პრობლემების აღმოფხვრა {#troubleshooting}

თუ ბილდი არ ჩანს დაფაზე, ჩართეთ debug გამოტანა, რათა ნახოთ, რატომ არ გაიგზავნა მისი ანგარიში:

```sh
TUIST_DEBUG=1 tuist cargo build --workspace
```

ანგარიშგება არ ცვლის თქვენი ბილდის შედეგს.
