# Xcode-ის ბილდების ანალიტიკა {#xcode-build-insights}

დიდ პროექტებზე მუშაობა არ უნდა მოითხოვდეს ერთი და იმავე კოდის ხელახლა კომპილაციას. Tuist Build Insights საშუალებას გაძლევთ თვალი ადევნოთ ბილდების ანალიტიკას, რათა ტენდენციები გამოავლინოთ სანამ ლოკალური და CI ბილდების დრო შეზღუდვად გადაიქცევა.

ბილდების ანალიტიკა ეყრდნობა `tuist inspect build` ბრძანებას, რომელიც ჩვეულებრივ ემატება სქემის post-action-ში.

ლოკალური ბილდების დროის თვალყურის დევნის დასაწყებად, შეგიძლიათ გამოიყენოთ `tuist inspect build` ბრძანება მისი სქემის post-action-ში დამატებით:

![Post-action ბილდების ინსპექტირებისთვის](/images/guides/features/build-insights/inspect-build-scheme-post-action.png)

> [!NOTE]
> „Provide build settings from“ ველი მიანიჭეთ შესრულებად ფაილს ან თქვენს ძირითად ბილდის სამიზნეს, რათა დაიჭიროთ ბილდის კონფიგურაცია.


> [!NOTE]
> post-scheme action არ სრულდება, თუ ბილდი ვერ მოხერხდა.

>
> ამ შემთხვევაში მისი შესრულება შეგიძლიათ `runPostActionsOnFailure`-ის `YES`-ზე დაყენებით შესაბამის `project.pbxproj` `BuildAction`-ში:
>
> ```diff
> <BuildAction
>    buildImplicitDependencies="YES"
>    parallelizeBuildables="YES"
> +  runPostActionsOnFailure="YES">
> ```

[Mise](https://mise.jdx.dev/)-ისთვის, გაააქტიურეთ `tuist` post-action გარემოში:

```sh
# -C ensures that Mise loads the configuration from the Mise configuration
# file in the project's root directory.
$HOME/.local/bin/mise x -C $SRCROOT -- tuist inspect build
```

> [!TIP]
> **Mise-ის გზის რეზოლუცია**
>
> თქვენი გარემოს `PATH` არ გადაეცემა სქემის post action-ს, ამიტომ გამოიყენეთ Mise-ის აბსოლუტური გზა. ეს დამოკიდებულია იმაზე, თუ როგორ დააინსტალირეთ Mise. ბილდის პარამეტრები უნდა გადაეცემოდეს სამიზნიდან, რათა `mise` შეძლოს `$SRCROOT`-დან გაშვება.

[Homebrew](https://brew.sh/)-ისთვის, დაამატეთ Homebrew-ის გზები post-action გარემოში:

```sh
export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"
tuist inspect build
```

აქტორის პრეტენზიები ნაგულისხმევად გამორთულია. სქემის post-action-ისთვის ერთ-ერთის კონფიგურაციისას, დააყენეთ `TUIST_ACTOR_ID` ამ სკრიპტში shell export-ებზე დაყრდნობის ნაცვლად. Dock-დან გაშვებული Xcode არ იღებს ცვლადებს `~/.zshrc`-დან. Homebrew-ით კონფიგურირებული პრეტენზიის ცალსახად ჩასახშობად, გამოიყენეთ:

```sh
export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"
export TUIST_ACTOR_ID=""
tuist inspect build
```

Mise-ით, გადაწერეთ მნიშვნელობა Mise-ის გარემოს ჩატვირთვის შემდეგ:

```sh
$HOME/.local/bin/mise x -C "$SRCROOT" -- env TUIST_ACTOR_ID="" tuist inspect build
```

ჩართვისთვის გამოიყენეთ ცალსახა ლეიბლი ცარიელი მნიშვნელობის ნაცვლად.

შესვლის შემდეგ, ლოკალური ბილდები ითვალისწინება და ხელმისაწვდომია Tuist-ის დაშბორდიდან:

> [!TIP]
> დაშბორდზე სწრაფი წვდომისთვის, CLI-დან გაუშვით `tuist project show --web`.


![დაშბორდი ბილდების ანალიტიკით](/images/guides/features/build-insights/builds-dashboard.png)

## ბილდების ანალიტიკა CI-ში {#continuous-integration}

CI-ზე ბილდების ანალიტიკის თვალყურის დევნისთვის, დარწმუნდით, რომ CI არის <.localized_link href="/guides/integrations/continuous-integration#authentication">ავთენტიკირებული</.localized_link>.

Xcodebuild-ზე დაფუძნებული CI-ისთვის საჭიროა:
- გამოიყენეთ <.localized_link href="/cli/xcodebuild#tuist-xcodebuild">`tuist xcodebuild`</.localized_link> `xcodebuild` ქმედებების გამოძახებისას.
- დაამატეთ `-resultBundlePath` თქვენს `xcodebuild` ბრძანებაში.

`-resultBundlePath`-ის გარეშე, საჭირო აქტივობის ჟურნალები და შედეგების პაკეტები არ გენერირდება და `tuist inspect build` ვერ აანალიზებს ბილდს.

## კრედენშიალების გარეშე რეპორტინგი კერძო ქსელში {#network-trusted-publishing}

თვითმასპინძლული განლაგება შეუძლია დეველოპერებს საშუალება მისცეს დაასრულებული რეპორტები გამოაქვეყნონ შესვლის გარეშე. ოპერატორმა უნდა დააკონფიგურიროს `TUIST_NETWORK_TRUSTED_INSIGHTS_ACCESS=true` ინსტანციაზე და გადატვირთოს ის, როგორც აღწერილია <.localized_link href="/guides/server/self-host/server#network-trusted-access">თვითმასპინძლობის სახელმძღვანელოში</.localized_link>. ეს ვრცელდება ყველა მხარდაჭერილ პროექტზე; დაშბორდის პარამეტრი არ არსებობს. დააკონფიგურირეთ თვითმასპინძლული URL და პროექტი იმ გარემოში, რომელსაც იყენებს თქვენი სქემის post-action ან ტერმინალი. CLI ავტომატურად აღმოაჩენს ინსტანციის პოლიტიკას, როცა კრედენშიალები არ არის:

```sh
export TUIST_URL="https://tuist.internal.example"
tuist inspect build
# To publish local test results:
tuist inspect test
```

ნამდვილად არარსებული კრედენშიალების შემთხვევაში, აქტივობის ჟურნალები და XCResult პაკეტები იპარსება ლოკალურად და იგზავნება სტრუქტურირებული რეპორტების სახით. არ იგზავნება raw არქივი, დანართი, დაფარვის/ისტორიის ატვირთვა, შორეული პროცესორი, shard-ის მითითება ან შერჩევითი შესრულების მტკიცებულება. რეპორტები რჩება ხილული, მაგრამ ვერ ანახლებენ ავთენტიკირებული სატესტო შემთხვევის მდგომარეობას ან არ ამუშავებენ კარანტინის/შეცდომის ავტომატიზაციებს. დაშბორდებს და სხვა პრივილეგირებულ ბრძანებებს კვლავ სჭირდებათ შესვლა. შეინახეთ ქეშის ინტეგრაცია გამორთული, თუ ინსტანცია ცალკე არ ააქტიურებს ქსელის ნდობის ქეშზე წვდომას ან არ არის მოწოდებული კრედენშიალები.

არსებული კრედენშიალები რჩება ავთენტიკირებული. არასწორი, დაზიანებული, ცარიელი ან უარყოფილი-განახლებული კრედენშიალები ასრულებენ მუშაობას შეცდომით და რჩებიან დისკზე, რათა მომდევნო ბრძანებები ჩუმად არ გახდნენ ხელმოუწერელი. ხელახლა შედით ან ცალსახად გამოდით, როგორც განზრახული აღდგენის ქმედება. განაახლეთ ყველა სერვერის რეპლიკა აღმოჩენის შესაძლებლობის მქონე ვერსიამდე, სანამ განაახლებთ კრედენშიალების გარეშე კლიენტებს, და დააკონფიგურირეთ საბოლოო სერვერის URL გადამისამართებების გარეშე. უფრო ძველ სერვერებს აღმოჩენის გარეშე, გამორთულ ინსტანციებს და აღმოჩენის შეცდომებს კვლავ სჭირდებათ ავთენტიკაცია. კლიენტის მხრიდან ჩართვა არ არის საჭირო. დააყენეთ `TUIST_ACTOR_ID=""` დამოუკიდებლად, რათა გამოტოვოთ კონფიგურირებული აქტორის პრეტენზია; ვერიფიცირებული კრედენშიალის იდენტურობა უცვლელი რჩება.

## მანქანის მეტრიკები {#machine-metrics}

ბილდების ანალიტიკა შეიძლება მოიცავდეს მანქანის დონის შესრულების მეტრიკებს (CPU, მეხსიერება, ქსელი და დისკის გამოყენება), რომლებიც იჭერება ბილდის დროს. ამის ჩასართავად, დააყენეთ მსუბუქი ფონური დემონი, რომელიც უწყვეტად იღებს სისტემის მეტრიკებს:

```bash
tuist setup insights
```

ეს აწარმოებს ლოკალურ დემონს, რომელიც ფონში იღებს მეტრიკებს. მონაცემებს ავტომატურად იღებს `tuist inspect build` და ატვირთავს ბილდის რეპორტთან ერთად.

> [!TIP]
> **CI**
>
> გაუშვით `tuist setup insights` თქვენს CI მანქანებზე ბილდამდე, რათა ასევე დაიჭიროთ მანქანის მეტრიკები.

მანქანის მეტრიკების შეგროვების შესაჩერებლად, გაუშვით:

```bash
tuist teardown insights
```

ეს ტვირთავს დემონის LaunchAgent-ს, აშორებს მის plist-ს და შლის შეგროვებულ მეტრიკებსა და დემონის ჟურნალებს `~/.local/state`-დან, ასე რომ ფონში არაფერი რჩება გაშვებული.


## რეპორტის აქტორის პრეტენზია {#report-actor-claim}

რეპორტის შექმნის მოთხოვნები მოიცავს არასავალდებულო `x-tuist-actor-id` ჰედერს მხოლოდ მაშინ, როცა ცალსახად აყენებთ `TUIST_ACTOR_ID`-ს ორგანიზაციის დონის ლეიბლზე, მაგალითად `TUIST_ACTOR_ID=employee-123 tuist inspect build`. ლეიბლი ნაგულისხმევად არ იგზავნება და Tuist არ ავლენს ოპერაციული სისტემის მომხმარებლის სახელს. ცარიელი `TUIST_ACTOR_ID` ტოვებს რეპორტირებულ იდენტიფიკატორს, მაგრამ არ აშორებს კრედენშიალებზე დაფუძნებულ ვერიფიცირებულ იდენტურობას. იდენტიფიკატორები უნდა იყოს 1–128 ბაიტი არა-სივრცითი ბეჭდვადი ASCII; არასწორი გადაწერები გამოიტოვება უკან დაბრუნების გარეშე. თუ კუსტომური პროქსი უარყოფს უცნობ ჰედერებს, გამოდით ცარიელი გარემოს გადაწერით.

ვერიფიცირებული ინდივიდუალური კრედენშიალები აქვთ უპირატესობა; კლიენტის მიერ რეპორტირებული იდენტიფიკატორები სხვა შემთხვევაში ჩანს, როგორც **ვერიფიცირებადი** და არასდროს ანიჭებენ ნებართვებს ან არ აკავშირებენ ავტომატურად მომხმარებლებთან. იდენტიფიკატორები ხილულია ნებისმიერისთვის, ვისაც შეუძლია ნახოს პროექტის რეპორტები, მათ შორის საჯარო მაყურებლებისთვის, როცა პროექტი საჯაროა, და შედის მონაცემთა ექსპორტში, ამიტომ არ ჩართოთ საიდუმლოებები. ეს ვრცელდება ბილდის, ტესტის და ბრძანების მოვლენის რეპორტებზე. ძველი სერვერები იგნორირებენ არასავალდებულო ჰედერს, ახალი სერვერები კი იღებენ ძველ კლიენტებს მის გარეშე. ახალი გაზიარებული-ტოკენის რეპორტები იდენტიფიკატორის გარეშე აჩვენებენ **უცნობი**, გამომქვეყნებელი ორგანიზაციის ნაცვლად; ისტორიული რეპორტები ინარჩუნებენ წინა მინიჭებას. ბილდებისა და ტესტების სიები არჩევენ ვერიფიცირებულ მომხმარებლებს ვერიფიცირებადი რეპორტირებული იდენტიფიკატორებისგან. ავთენტიკაცია რჩება საჭირო, თუ თვითმასპინძლული ინსტანცია ცალსახად არ ააქტიურებს კრედენშიალების გარეშე რეპორტინგს და კლიენტი არ აღმოაჩენს ამ პოლიტიკას.

## კუსტომური მეტამონაცემები {#custom-metadata}

ბილდებს შეგიძლიათ მიამაგროთ მეტამონაცემები გარემოს ცვლადების საშუალებით, რათა გააუმჯობესოთ ფილტრაცია.

### გარემოს ცვლადები

| ცვლადი | ფორმატი | აღწერა |
|----------|--------|-------------|
| `TUIST_BUILD_TAGS` | მძიმით გამოყოფილი | რამდენიმე ტეგი ერთ ცვლადში. |
| `TUIST_BUILD_VALUE_*` | ერთი მნიშვნელობა | გასაღებ-მნიშვნელობის წყვილი, სადაც სუფიქსი არის გასაღები. |
