## მოქმედის პრეტენზიის მოხსენება {#report-actor-claim}

მოხსენების შექმნის მოთხოვნები შეიცავს არასავალდებულო `x-tuist-actor-id` ჰედერს მხოლოდ მაშინ, როცა თქვენ ცალსახად აყენებთ `TUIST_ACTOR_ID`-ს ორგანიზაციის დონეზე მიბმულ იარლიყად, მაგალითად, `TUIST_ACTOR_ID=employee-123 tuist inspect build`. იარლიყი ნაგულისხმევად არ იგზავნება და Tuist არ ამოიცნობს ოპერაციული სისტემის მომხმარებლის სახელებს. ცარიელი `TUIST_ACTOR_ID` ტოვებს გამოტოვებულ იდენტიფიკატორს, მაგრამ არ ხსნის სერთიფიკატებზე დაფუძნებულ ვერიფიცირებულ იდენტობას. იდენტიფიკატორები უნდა იყოს 1–128 ბაიტიანი არა-სივრცითი ბეჭდვადი ASCII; არასწორი გადაფარვები გამოიტოვება უკან დაბრუნების გარეშე. თუ მორგებული პროქსი უარყოფს უცნობ ჰედერებს, გამორთეთ ის ცარიელი გარემოს გადაფარვით.

ვერიფიცირებულ ინდივიდუალურ სერთიფიკატებს აქვთ უპირატესობა; კლიენტის მიერ მოხსენებული იდენტიფიკატორები წარმოდგენილია როგორც **შეუმოწმებელი** და არასდროს ანიჭებენ ნებართვებს ან ავტომატურად არ აკავშირებენ მომხმარებლებთან. იდენტიფიკატორები ხილულია ნებისმიერი პირისთვის, ვისაც შეუძლია ნახოს პროექტის მოხსენებები, მათ შორის საჯარო მაყურებლებისთვის, როცა პროექტი საჯაროა, და შედის მონაცემთა ექსპორტში, ამიტომ არ ჩაამატოთ საიდუმლოებები. ეს ვრცელდება ბილდის, ტესტისა და ბრძანების მოვლენების მოხსენებებზე. ძველი სერვერები იგნორირებენ არასავალდებულო ჰედერს, ხოლო ახალი სერვერები იღებენ ძველ კლიენტებს მის გარეშე. ახალი გაზიარებული-ტოკენის მოხსენებები იდენტიფიკატორის გარეშე აჩვენებენ **უცნობია**-ს, გამომქვეყნებელი ორგანიზაციის ნაცვლად; ისტორიული მოხსენებები ინარჩუნებენ წინა მიკუთვნებას. ბილდისა და ტესტის სიები განასხვავებენ ვერიფიცირებულ მომხმარებლებს შეუმოწმებელი მოხსენებული იდენტიფიკატორებისგან. ავთენტიკაცია რჩება სავალდებულო, თუ თვითმასპინძლობითი ინსტანსი ცალსახად არ ჩართავს სერთიფიკატების გარეშე მოხსენებას და კლიენტი არ აღმოაჩენს ამ პოლიტიკას.

### სქემის post-actions {#actor-claim-post-actions}

მოქმედის პრეტენზიები ნაგულისხმევად გამორთულია. სქემის post-action-ისთვის ერთ-ერთის კონფიგურაციისთვის, დააყენეთ `TUIST_ACTOR_ID` ამ სკრიპტში shell-ის ექსპორტებზე დაყრდნობის ნაცვლად. Dock-დან გაშვებული Xcode არ იღებს ცვლადებს `~/.zshrc`-დან. Homebrew-ით კონფიგურირებული პრეტენზიის ცალსახად ჩასახშობად, გამოიყენეთ:

```sh
export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"
export TUIST_ACTOR_ID=""
tuist inspect build
```

Mise-ით, გადაფარეთ მნიშვნელობა Mise-ის გარემოს ჩატვირთვის შემდეგ:

```sh
$HOME/.local/bin/mise x -C "$SRCROOT" -- env TUIST_ACTOR_ID="" tuist inspect build
```

ჩასართავად გამოიყენეთ ცალსახა იარლიყი ცარიელი მნიშვნელობის ნაცვლად.
