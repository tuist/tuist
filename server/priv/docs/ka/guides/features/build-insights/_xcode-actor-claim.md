## მოხსენების აქტორის პრეტენზია {#report-actor-claim}

მოხსენების შექმნის მოთხოვნები მოიცავს არასავალდებულო `x-tuist-actor-id` ჰედერს მხოლოდ მაშინ, როცა თქვენ ცალსახად აყენებთ `TUIST_ACTOR_ID`-ს ორგანიზაციის დონის იარლიყად, მაგალითად, `TUIST_ACTOR_ID=employee-123 tuist inspect build`. ნაგულისხმევად იარლიყი არ იგზავნება და Tuist არ ავლენს საოპერაციო სისტემის მომხმარებლის სახელებს. ცარიელი `TUIST_ACTOR_ID` ტოვებს გამოგზავნილ იდენტიფიკატორს, მაგრამ არ შლის სერთიფიკატებზე დაფუძნებულ დადასტურებულ იდენტობას. იდენტიფიკატორები უნდა იყოს 1–128 ბაიტი არა-სიცარიელე ბეჭდადი ASCII; არასწორი გადაფარვები გამოტოვებულია რეზერვული ვარიანტის გარეშე. თუ კუსტომური პროქსი უარყოფს უჩვეულო ჰედერებს, გამოეთიშეთ ცარიელი გარემოს გადაფარვით.

დადასტურებულ ინდივიდუალურ სერთიფიკატებს აქვთ უპირატესობა; კლიენტის მიერ მოხსენებული იდენტიფიკატორები წარმოდგენილია როგორც **დაუდასტურებელი** და არასდროს ანიჭებენ უფლებებს ან ავტომატურად არ აკავშირებენ მომხმარებლებთან. იდენტიფიკატორები ხილულია ნებისმიერი პირისთვის, ვისაც შეუძლია ნახოს პროექტის მოხსენებები, მათ შორის საჯარო მაყურებლებისთვის, როცა პროექტი საჯაროა, და შედის მონაცემთა ექსპორტში, ამიტომ არ ჩაწეროთ საიდუმლოებები. ეს ვრცელდება ბილდის, ტესტის და ბრძანების მოვლენების მოხსენებებზე. ძველი სერვერები იგნორირებენ არასავალდებულო ჰედერს, ხოლო ახალი სერვერები იღებენ ძველ კლიენტებს მის გარეშე. ახალი გაზიარებული-ტოკენის მოხსენებები იდენტიფიკატორის გარეშე აჩვენებენ **უცნობი**-ს, გამომქვეყნებელი ორგანიზაციის ნაცვლად; ისტორიული მოხსენებები ინარჩუნებენ წინა მიკუთვნებას. ბილდისა და ტესტის სიები განასხვავებენ დადასტურებულ მომხმარებლებს დაუდასტურებელი მოხსენებული იდენტიფიკატორებისგან. ავთენტიფიკაცია რჩება სავალდებულო, თუ თვითმასპინძელი ინსტანსი ცალსახად არ ჩართავს სერთიფიკატების გარეშე მოხსენებას და კლიენტი არ აღმოაჩენს ამ პოლიტიკას.

### სქემის post-actions {#actor-claim-post-actions}

აქტორის პრეტენზიები ნაგულისხმევად გამორთულია. სქემის post-action-ისთვის ერთ-ერთის კონფიგურაციისთვის, დააყენეთ `TUIST_ACTOR_ID` ამ სკრიპტში shell-ის ექსპორტებზე დაყრდნობის ნაცვლად. Xcode, რომელიც გაშვებულია Dock-დან, არ იღებს ცვლადებს `~/.zshrc`-დან. Homebrew-ით კონფიგურირებული პრეტენზიის ცალსახად ჩასახშობად, გამოიყენეთ:

```sh
export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"
export TUIST_ACTOR_ID=""
tuist inspect build
```

Mise-ით, გადაფარეთ მნიშვნელობა Mise-ის გარემოს ჩატვირთვის შემდეგ:

```sh
$HOME/.local/bin/mise x -C "$SRCROOT" -- env TUIST_ACTOR_ID="" tuist inspect build
```

გამოიყენეთ ცალსახა იარლიყი ცარიელი მნიშვნელობის ნაცვლად ჩასართავად.
