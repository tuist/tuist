## მოხსენების აქტორის პრეტენზია {#report-actor-claim}

მოხსენების შექმნის მოთხოვნები მოიცავს არასავალდებულო `x-tuist-actor-id` ჰედერს მხოლოდ მაშინ, როდესაც თქვენ ცალსახად აყენებთ `TUIST_ACTOR_ID`-ს ორგანიზაციის დონის იარლიყად, მაგალითად `TUIST_ACTOR_ID=employee-123 tuist inspect build`. იარლიყი ნაგულისხმევად არ იგზავნება და Tuist არ ავლენს საოპერაციო სისტემის მომხმარებლის სახელებს. ცარიელი `TUIST_ACTOR_ID` გამოტოვებს მოხსენებულ იდენტიფიკატორს, მაგრამ არ აშორებს სერთიფიკატებზე დაფუძნებულ ვერიფიცირებულ იდენტობას. იდენტიფიკატორები უნდა იყოს 1–128 ბაიტიანი არა-სივრცული ბეჭდვადი ASCII; არასწორი გადაფარვები გამოიტოვება უკან დაბრუნების გარეშე. თუ კუსტომური პროქსი უარყოფს უჩვეულო ჰედერებს, გამოეთიშეთ ცარიელი გარემოს გადაფარვით.

ვერიფიცირებული ინდივიდუალური სერთიფიკატები აქვთ უპირატესობა; კლიენტის მიერ მოხსენებული იდენტიფიკატორები წინააღმდეგ შემთხვევაში ჩანს როგორც **ვერიფიცირებადი** და არასდროს ანიჭებენ უფლებებს ან ავტომატურად არ აკავშირებენ მომხმარებლებთან. იდენტიფიკატორები ხილვადია ნებისმიერი პირისთვის, ვისაც შეუძლია ნახოს პროექტის მოხსენებები, მათ შორის საჯარო მაყურებლებისთვის, როდესაც პროექტი საჯაროა, და შედის მონაცემთა ექსპორტში, ამიტომ არ შეიტანოთ საიდუმლოებები. ეს ვრცელდება ბილდის, ტესტის და ბრძანების-მოვლენის მოხსენებებზე. ძველი სერვერები იგნორირებენ არასავალდებულო ჰედერს, ხოლო ახალი სერვერები იღებენ ძველ კლიენტებს მის გარეშე. ახალი გაზიარებული-ტოკენის მოხსენებები იდენტიფიკატორის გარეშე აჩვენებენ **უცნობი**-ს, გამომქვეყნებელი ორგანიზაციის ნაცვლად; ისტორიული მოხსენებები ინარჩუნებენ მათ წინა მიკუთვნებას. ბილდისა და ტესტის სიები განასხვავებენ ვერიფიცირებულ მომხმარებლებს ვერიფიცირებადი მოხსენებული იდენტიფიკატორებისგან. ავთენტიკაცია რჩება საჭირო, თუ თვითმასპინძელი ინსტანცია ცალსახად არ ჩართავს სერთიფიკატების გარეშე მოხსენებას და კლიენტი აღმოაჩენს ამ პოლიტიკას.

### სქემის post-actions {#actor-claim-post-actions}

აქტორის პრეტენზიები ნაგულისხმევად გამორთულია. სქემის post-action-ისთვის ერთის კონფიგურაციისთვის, დააყენეთ `TUIST_ACTOR_ID` იმ სკრიპტში shell-ის ექსპორტებზე დაყრდნობის ნაცვლად. Xcode, რომელიც გაშვებულია Dock-იდან, არ იღებს ცვლადებს `~/.zshrc`-დან. Homebrew-ით კონფიგურირებული პრეტენზიის ცალსახად ჩასახშობად, გამოიყენეთ:

```sh
export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"
export TUIST_ACTOR_ID=""
tuist inspect build
```

Mise-ით, გადაფარეთ მნიშვნელობა Mise-ის გარემოს ჩატვირთვის შემდეგ:

```sh
$HOME/.local/bin/mise x -C "$SRCROOT" -- env TUIST_ACTOR_ID="" tuist inspect build
```

გამოიყენეთ ცალსახა იარლიყი ცარიელი მნიშვნელობის ნაცვლად შესართავად.
