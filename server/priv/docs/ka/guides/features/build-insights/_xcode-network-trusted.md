## კრედენციალების გარეშე ანგარიშგება კერძო ქსელში {#network-trusted-publishing}

თვითმასპინძელი განლაგება შეუძლია დეველოპერებს საშუალება მისცეს დაასრულებული ანგარიშების გამოქვეყნება სისტემაში შესვლის გარეშე. ოპერატორმა უნდა დააკონფიგურიროს `TUIST_NETWORK_TRUSTED_INSIGHTS_ACCESS=true` ინსტანსზე და გადატვირთოს ის, როგორც აღწერილია <.localized_link href="/guides/server/self-host/server#network-trusted-access">თვითმასპინძლობის სახელმძღვანელოში</.localized_link>. ეს ვრცელდება ყველა მხარდაჭერილ პროექტზე; არ არსებობს პარამეტრი დაშბორდზე. დააკონფიგურირეთ თვითმასპინძელი URL და პროექტი იმ გარემოში, რომელსაც იყენებს თქვენი სქემის post-action ან ტერმინალი. CLI ავტომატურად აღმოაჩენს ინსტანსის პოლიტიკას, როდესაც კრედენციალები არ არის წარმოდგენილი:

```sh
export TUIST_URL="https://tuist.internal.example"
tuist inspect build
# To publish local test results:
tuist inspect test
```

კრედენციალების ნამდვილად არარსებობის შემთხვევაში, აქტივობის ლოგები და XCResult ბუნდლები იპარსება ლოკალურად და იგზავნება სტრუქტურირებული ანგარიშების სახით. არ იგზავნება raw არქივი, მიმაგრება, დაფარვის/ისტორიის ატვირთვა, შორეული პროცესორი, shard-ის მითითება ან შერჩევითი შესრულების მტკიცებულება. ანგარიშები რჩება ხილული, მაგრამ ვერ აახლებენ ავთენტიკაციის გასულ ტესტქეისის სტატუსს ან ვერ მართავენ კარანტინის/შეცდომების ავტომატიზაციებს. დაშბორდები და სხვა პრივილეგიური ბრძანებები კვლავ მოითხოვს სისტემაში შესვლას. დატოვეთ ქეშის ინტეგრაცია გამორთული, თუ ინსტანსი ცალკე არ იძლევა ქსელში სანდო ქეშზე წვდომას ან არ არის გამოყოფილი კრედენციალები.

არსებული კრედენციალები რჩებიან ავთენტიკაციის მქონე. არასწორი, დაზიანებული, ცარიელი ან უარყოფილი-განახლების კრედენციალები იწვევს შეცდომას და რჩებიან დისკზე, ასე რომ მოგვიანებითი ბრძანებები არ ხდებიან ჩუმად ხელმოუწერელი. ხელახლა შედით სისტემაში ან ცალსახად გამოდით, როგორც განზრახული აღდგენის მოქმედება. განაახლეთ ყველა სერვერის რეპლიკა აღმოჩენის მხარდაჭერის მქონე ვერსიამდე, სანამ განაახლებთ კრედენციალების გარეშე მომხმარებლებს, და დააკონფიგურირეთ საბოლოო სერვერის URL გადამისამართებების გარეშე. ძველ სერვერებს აღმოჩენის გარეშე, გამორთულ ინსტანსებს და აღმოჩენის შეცდომებს კვლავ სჭირდებათ ავთენტიკაცია. არ არის საჭირო კლიენტის მხრიდან opt-in. დააყენეთ `TUIST_ACTOR_ID=""` დამოუკიდებლად, რათა გამოტოვოთ კონფიგურირებული actor claim; ვერიფიცირებული კრედენციალის იდენტურობა უცვლელი რჩება.
