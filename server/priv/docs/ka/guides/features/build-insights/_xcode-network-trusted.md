## კრედენციალების გარეშე ანგარიშგება კერძო ქსელში {#network-trusted-publishing}

თვითმასპინძელი განლაგება შეუძლია დეველოპერებს საშუალება მისცეს გამოაქვეყნონ დასრულებული ანგარიშები სისტემაში შესვლის გარეშე. ოპერატორმა უნდა დააკონფიგურიროს `TUIST_NETWORK_TRUSTED_INSIGHTS_ACCESS=true` ინსტანციაზე და გადატვირთოს ის, როგორც აღწერილია <.localized_link href="/guides/server/self-host/server#network-trusted-access">თვითმასპინძლობის სახელმძღვანელოში</.localized_link>. ეს ვრცელდება ყველა მხარდაჭერილ პროექტზე; საფასურის პანელში შესაბამისი პარამეტრი არ არსებობს. დააკონფიგურირეთ თვითმასპინძელი URL და პროექტი იმ გარემოში, რომელსაც იყენებს თქვენი სქემის post-action ან ტერმინალი. CLI ავტომატურად აღმოაჩენს ინსტანციის პოლიტიკას, როდესაც კრედენციალები არ არის:

```sh
export TUIST_URL="https://tuist.internal.example"
tuist inspect build
# To publish local test results:
tuist inspect test
```

კრედენციალების ნამდვილად არარსებობის შემთხვევაში, აქტივობის ჟურნალები და XCResult ბანდლები იპარსება ლოკალურად და იგზავნება სტრუქტურირებული ანგარიშების სახით. არ იგზავნება არც raw არქივი, არც დანართი, არც დაფარვის/ისტორიის ატვირთვა, არც დისტანციური პროცესორი, არც shard-ის მითითება ან შერჩევითი შესრულების მტკიცებულება. ანგარიშები რჩება ხილული, მაგრამ ვერ აახლებენ ავთენტიფიცირებული test case-ების მდგომარეობას ან ვერ ამუშავებენ კარანტინის/შეცდომების ავტომატიზაციებს. საფასურის პანელები და სხვა პრივილეგიური ბრძანებები კვლავ მოითხოვენ სისტემაში შესვლას. დატოვეთ ქეშის ინტეგრაცია გამორთული, თუ ინსტანცია ცალკე არ ჩართავს ქსელის მიმართ ნდობით აღჭურვილ ქეშზე წვდომას ან თუ კრედენციალები არ არის გამოყოფილი.

არსებული კრედენციალები რჩება ავთენტიფიცირებული. არასწორი, დაზიანებული, ცარიელი ან უარყოფილი განახლების კრედენციალები იწვევს უსაფრთხო შეცდომას და რჩება დისკზე, რათა მოგვიანებით შესრულებულმა ბრძანებებმა ჩუმად არ გახდნენ ხელმოუწერელი. ხელახლა შედით სისტემაში ან ცალსახად გამოდით სისტემიდან, როგორც განზრახული აღდგენის მოქმედება. განაახლეთ სერვერის ყოველი რეპლიკა აღმოჩენის შესაძლებლობის მქონე ვერსიამდე, სანამ განაახლებთ კრედენციალების გარეშე მომუშავე კლიენტებს, და დააკონფიგურირეთ საბოლოო სერვერის URL გადამისამართებების გარეშე. ძველ სერვერებს აღმოჩენის ფუნქციის გარეშე, გამორთულ ინსტანციებს და აღმოჩენის შეცდომებს კვლავ სჭირდებათ ავთენტიფიკაცია. კლიენტის მხრიდან opt-in არ არის საჭირო. დააყენეთ `TUIST_ACTOR_ID=""` დამოუკიდებლად, რათა გამოტოვოთ კონფიგურირებული actor-ის პრეტენზია; ვერიფიცირებული კრედენციალის იდენტურობა უცვლელი რჩება.
