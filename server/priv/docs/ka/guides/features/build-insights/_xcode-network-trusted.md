## ანგარიშის შეყვანის გარეშე ანგარიშგება კერძო ქსელში {#network-trusted-publishing}

თავისუფლად განთავსებულმა (self-hosted) ინსტალაციამ შეიძლება მისცეს დეველოპერებს დასრულებული ანგარიშების გამოქვეყნების საშუალება ავტორიზაციის გარეშე. ოპერატორმა უნდა დააკონფიგურიროს `TUIST_NETWORK_TRUSTED_INSIGHTS_ACCESS=true` ინსტანციაზე და გადატვირთოს ის, როგორც აღწერილია <.localized_link href="/guides/server/self-host/server#network-trusted-access">თავისუფლად განთავსების სახელმძღვანელოში</.localized_link>. ეს ვრცელდება ყველა მხარდაჭერილ პროექტზე; არ არსებობს შესაბამისი პარამეტრი დაშბორდზე. დააკონფიგურირეთ თავისუფლად განთავსებული URL და პროექტი იმ გარემოში, რომელსაც იყენებს თქვენი სქემის post-action ან ტერმინალი. CLI ავტომატურად აღმოაჩენს ინსტანციის პოლიტიკას, როდესაც ანგარიშები არ არის წარმოდგენილი:

```sh
export TUIST_URL="https://tuist.internal.example"
tuist inspect build
# To publish local test results:
tuist inspect test
```

როდესაც ანგარიშები ნამდვილად არ არის წარმოდგენილი, აქტივობის ლოგები და XCResult ბუნდლები იპარსება ლოკალურად და იგზავნება სტრუქტურირებული ანგარიშების სახით. არ იგზავნება raw არქივი, დანართი, დაფარვის/ისტორიის ატვირთვა, შორეული პროცესორი, shard-ის მითითება ან შერჩევითი შესრულების მტკიცებულება. ანგარიშები რჩება ხილვადი, მაგრამ ვერ აახლებენ ავტორიზებული ტესტქეისის სტატუსს ან ვერ ამუშავებენ კარანტინის/შეცდომების ავტომატიზაციებს. დაშბორდებსა და სხვა პრივილეგიურ ბრძანებებს კვლავ სჭირდებათ ავტორიზაცია. შეინარჩუნეთ ქეშის ინტეგრაცია გამორთული, თუ ინსტანცია ცალკე არ ააქტიურებს ქსელურად სანდო ქეშზე წვდომას ან არ არის მოწოდებული ანგარიშები.

არსებული ანგარიშები რჩებიან ავტორიზებულად. არასწორი, დაზიანებული, ცარიელი ან უარყოფილი განახლების ანგარიშები ასრულებენ მუშაობას უსაფრთხოდ და რჩებიან დისკზე, რათა შემდგომი ბრძანებები არ გახდნენ ჩუმად არაავტორიზებული. ხელახლა შედით ან ცალსახად გამოდით სისტემიდან, როგორც განზრახული აღდგენის მოქმედება. განაახლეთ ყველა სერვერის რეპლიკა აღმოჩენის შესაძლებლობის მქონე ვერსიამდე, სანამ განაახლებთ ანგარიშების გარეშე მომუშავე კლიენტებს, და დააკონფიგურირეთ საბოლოო სერვერის URL გადამისამართებების გარეშე. ძველ სერვერებს აღმოჩენის ფუნქციის გარეშე, გამორთულ ინსტანციებს და აღმოჩენის შეცდომებს კვლავ სჭირდებათ ავტორიზაცია. კლიენტის მხრიდან opt-in არ არის საჭირო. დააყენეთ `TUIST_ACTOR_ID=""` დამოუკიდებლად, რათა გამოტოვოთ კონფიგურირებული actor-ის პრეტენზია; დადასტურებული ანგარიშის იდენტიფიკატორი უცვლელი რჩება.
