# Bazel-ის ბილდის ინსაიტები {#bazel-build-insights}

ყველა დასრულებული `build`, `test` და სხვა Bazel-ის ბრძანება ჩანს პროექტის **გამოძახებების** დაფაზე: ბრძანების ტიპი, გასვლის სტატუსი, დაწყებისა და დასრულების დრო, ხანგრძლივობა, აგრეთვე ქეშის მოხმარებები, გამოტოვებები, ჩამოტვირთვები და ატვირთვები, რომლებიც Bazel-მა მიანიჭა იმავე გამოძახებას.

გამოძახების მონაცემები გადაეცემა Bazel-ის [Build Event Protocol](https://bazel.build/remote/bep)-ის საშუალებით. კონფიგურაცია ავტომატურად აკავშირებს მას, როდესაც ასრულებთ `tuist bazel setup`-ს; გამოძახებების სანახავად დამატებითი ფლაგები არ არის საჭირო.

## რა ჩანს დაფაზე {#what-the-dashboard-shows}

ყოველი გამოძახება აღრიცხავს:

- Bazel-ის მიერ შესრულებულ ბრძანებას, მის გასვლის კოდს, დაწყებისა და დასრულების დროს და საერთო ხანგრძლივობას.
- მოქმედებების, სამიზნეების და პაკეტების რაოდენობას.
- შეზღუდული ბილდის დროით ღერძს და კრიტიკული გზის შეჯამებას.
- ქეშის მოხმარებებს, გამოტოვებებს, ჩამოტვირთვებს და ატვირთვებს, რომლებიც მიეკუთვნება გამოძახებას.
- პროგრესის ლოგის სტრიქონებს, რომლებიც დაფიქსირდა გაშვების დროს, შესრულების თანმიმდევრობით.
- Bazel-ის ვერსიას, git-ის შტოსა და კომიტს, როდესაც Bazel აწვდის ამ ინფორმაციას, და იმას, შესრულდა თუ არა გაშვება CI-ზე.

ქეშის აქტივობა, რომლის მიკუთვნებაც Bazel-ს არ შეუძლია დასრულებულ გამოძახებაზე (მაგალითად, როდესაც ბრძანება წყდება გაშვების შუაში), მაინც ჩანს პროექტის **მიმოხილვის** გვერდზე, როგორც ნედლი დაშორებული ქეშის დაკვირვება. ის არ განიხილება ბრძანების წარმატების, ხანგრძლივობის ან ტესტების შედეგების დასტურად.

## მორგებული მეტამონაცემები {#custom-metadata}

მიამაგრეთ გასაღებ-მნიშვნელობის მონაცემები გამოძახებებს, რათა შეადაროთ გაშვებები სხვადასხვა გუნდების, აპარატურის ან სამუშაო პროცესების მიხედვით. მნიშვნელობები ჩანს თითოეული გამოძახების დეტალურ გვერდზე, აგრეთვე აპლიკაციის პროგრამირების ინტერფეისისა და Model Context Protocol-ის ინსტრუმენტების საშუალებით.

დააყენეთ მეტამონაცემები Bazel-ის ჩაშენებული `--build_metadata` ფლაგით:

```bash
bazel build --build_metadata=TICKET=TUIST-123 --build_metadata=RUNNER=macos-14 //...
```

ან დააყენეთ ისინი ერთხელ თითოეული არხისთვის თქვენს `.bazelrc`-ში:

```text
build:ci --build_metadata=RUNNER=macos-14
```

თითოეულ გამოძახებას შეიძლება ჰქონდეს 20-მდე მორგებული ჩანაწერი. გასაღებები შეიძლება შეიცავდეს 50-მდე სიმბოლოს, ხოლო მნიშვნელობები — 500-მდე სიმბოლოს. ჩანაწერები, რომლებიც აღემატებიან ამ ზღვრებს, იშლება გამოძახების შენახვამდე, ამიტომ არასწორი ჩანაწერი არ ხელს უშლის დანარჩენი ანგარიშის ჩაწერას.

კონტექსტის გასაღებები, რომლებსაც Tuist იღებს ბილდის გარემოდან, როგორიცაა `CI`, `GIT_BRANCH` და `GIT_COMMIT`, არ ინახება როგორც მორგებული მნიშვნელობები, რადგან ისინი უკვე ავსებენ გამოძახების ძირითად ველებს.

მორგებული მეტამონაცემები ხილულია პროექტის წევრებისთვის დაფაზე, აგრეთვე აპლიკაციის პროგრამირების ინტერფეისისა და Model Context Protocol-ის ინსტრუმენტების საშუალებით. არ გამოიყენოთ ის საიდენტიფიკაციო მონაცემების, წვდომის ტოკენების ან სხვა მგრძნობიარე მონაცემებისთვის.

## გამოთიშვა {#opting-out}

Build Event Protocol-ის ნაკადი შეიცავს ბრძანების ხაზის არგუმენტებს, გარემოს მნიშვნელობებს და ბრძანების გამომავალს. Tuist ინახავს მხოლოდ ზემოთ ჩამოთვლილ დასრულებული ბრძანების ველებს და აგდებს დანარჩენს, მაგრამ თუ არ გსურთ საერთოდ გაგზავნოთ მოვლენათა ნაკადი, ხელახლა გაუშვით კონფიგურაცია:

```bash
tuist bazel setup --no-build-insights
```

გენერირებული `.bazelrc.tuist` შემდეგ აკონფიგურირებს მხოლოდ დაშორებულ ქეშს. გამოძახებები წყვეტენ დაფაზე გამოჩენას, ხოლო ქეშის დაკვირვებები რჩება **მიმოხილვის** გვერდზე.

## მონაცემთა შენახვა {#data-retention}

Tuist ინახავს Bazel-ის გამოძახებებს და მათ ლოგებს 90 დღის განმავლობაში. სრული პოლიტიკის სანახავად იხილეთ <.localized_link href="/guides/server/data-retention">მონაცემთა შენახვა</.localized_link>.
