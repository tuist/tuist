# Bazel-ის ბილდის ანალიტიკა {#bazel-build-insights}

ყველა დასრულებული `build`, `test` და სხვა Bazel-ის ბრძანება ჩანს პროექტის **გამოძახებების** დაფაზე: ბრძანების ტიპი, გასვლის სტატუსი, დაწყებისა და დასრულების დრო, ხანგრძლივობა და ქეშის მოხმარებები, გამოტოვებები, ჩამოტვირთვები და ატვირთვები, რომლებიც Bazel-მა მიანიჭა იმავე გამოძახებას.

გამოძახების მონაცემები მიეწოდება Bazel-ის [Build Event Protocol](https://bazel.build/remote/bep)-ის საშუალებით. კონფიგურაცია ავტომატურად აკავშირებს მას, როდესაც ასრულებთ `tuist bazel setup`; გამოძახებების სანახავად დამატებითი ფლაგები არ არის საჭირო.

## რა ჩანს დაფაზე {#what-the-dashboard-shows}

ყოველი გამოძახება აღრიცხავს:

- Bazel-ის მიერ შესრულებულ ბრძანებას, მის გასვლის კოდს, დაწყებისა და დასრულების დროს და საერთო ხანგრძლივობას.
- მოქმედებების, სამიზნეების და პაკეტების რაოდენობას.
- შეზღუდულ ბილდის დროის ხაზს და კრიტიკული გზის შეჯამებას.
- ქეშის მოხმარებებს, გამოტოვებებს, ჩამოტვირთვებს და ატვირთვებს, რომლებიც მიეკუთვნება გამოძახებას.
- პროგრესის ლოგის ხაზებს, რომლებიც აღბეჭდილია შესრულების დროს, შესრულების თანმიმდევრობით.
- Bazel-ის ვერსიას, git-ის შტოსა და კომიტს, როდესაც Bazel იუწყება მათ, და იმას, შესრულდა თუ არა გაშვება CI-ზე.

ქეშის აქტივობა, რომლის მიკუთვნებასაც Bazel ვერ ახერხებს დასრულებულ გამოძახებაზე, მაგალითად, როდესაც ბრძანება წყდება შესრულების შუაში, მაინც ჩანს პროექტის **მიმოხილვაში** როგორც ნედლი remote-cache დაკვირვება. ის არ განიხილება როგორც ბრძანების წარმატების, ხანგრძლივობის ან ტესტის შედეგების მტკიცებულება.

## მორგებული მეტამონაცემები {#custom-metadata}

მიამაგრეთ key-value მონაცემები გამოძახებებს, რათა შეადაროთ გაშვებები სხვადასხვა გუნდების, აპარატურის ან სამუშაო პროცესების მიხედვით. მნიშვნელობები ჩანს თითოეული გამოძახების დეტალურ გვერდზე და application programming interface-ისა და Model Context Protocol ინსტრუმენტების საშუალებით.

დააყენეთ მეტამონაცემები Bazel-ის ჩაშენებული `--build_metadata` ფლაგით:

```bash
bazel build --build_metadata=TICKET=TUIST-123 --build_metadata=RUNNER=macos-14 //...
```

ან დააყენეთ ისინი ერთხელ თითოეული lane-ისთვის თქვენს `.bazelrc`-ში:

```text
build:ci --build_metadata=RUNNER=macos-14
```

ყოველ გამოძახებას შეუძლია შეიცავდეს 20-მდე მორგებულ ჩანაწერს. გასაღებები შეიძლება შეიცავდეს 50 სიმბოლომდე, ხოლო მნიშვნელობები — 500 სიმბოლომდე. ჩანაწერები, რომლებიც აღემატება ამ ზღვრებს, იშლება გამოძახების შენახვამდე, ამიტომ არასწორი ჩანაწერი არ უშლის ხელს დანარჩენი ანგარიშის აღრიცხვას.

კონტექსტური გასაღებები, რომლებსაც Tuist იღებს ბილდის გარემოდან, როგორიცაა `CI`, `GIT_BRANCH` და `GIT_COMMIT`, არ ინახება როგორც მორგებული მნიშვნელობები, რადგან ისინი უკვე ავსებენ გამოძახების ძირითად ველებს.

მორგებული მეტამონაცემები ხილულია პროექტის წევრებისთვის დაფაზე და application programming interface-ისა და Model Context Protocol ინსტრუმენტების საშუალებით. არ გამოიყენოთ ის სერთიფიკატების, წვდომის ტოკენების ან სხვა მგრძნობიარე მონაცემებისთვის.

## გამორთვა {#opting-out}

Build Event Protocol ნაკადი შეიცავს ბრძანების ხაზის არგუმენტებს, გარემოს მნიშვნელობებს და ბრძანების გამომავალ მონაცემებს. Tuist ინახავს მხოლოდ ზემოთ ჩამოთვლილ დასრულებული ბრძანების ველებს და აგდებს დანარჩენს, მაგრამ თუ არ გსურთ ნაკადის საერთოდ გაგზავნა, ხელახლა გაუშვით კონფიგურაცია:

```bash
tuist bazel setup --no-build-insights
```

გენერირებული `.bazelrc.tuist` შემდეგ აკონფიგურირებს მხოლოდ remote cache-ს. გამოძახებები წყვეტენ გამოჩენას დაფაზე, ხოლო ქეშის დაკვირვებები რჩება **მიმოხილვის** გვერდზე.

## მონაცემთა შენახვა {#data-retention}

Tuist ინახავს Bazel-ის გამოძახებებს და მათ ლოგებს 90 დღის განმავლობაში. სრული პოლიტიკისთვის იხილეთ <.localized_link href="/guides/server/data-retention">მონაცემთა შენახვა</.localized_link>.
