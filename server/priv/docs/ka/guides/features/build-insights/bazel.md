# Bazel ბილდის ინსაიტები {#bazel-build-insights}

ყოველი დასრულებული `build`, `test` და სხვა Bazel ბრძანება ჩანს პროექტის **გამოძახებების** დაფაზე: ბრძანების ტიპი, გასვლის სტატუსი, დაწყებისა და დასრულების დრო, ხანგრძლივობა, აგრეთვე ქეშის მოხმარებები, გამოტოვებები, ჩამოტვირთვები და ატვირთვები, რომლებიც Bazel-მა მიანიჭა ამ კონკრეტულ გამოძახებას.

გამოძახების მონაცემები გადაიცემა Bazel-ის [Build Event Protocol](https://bazel.build/remote/bep)-ის საშუალებით. კონფიგურაცია ავტომატურად აერთებს მას, როცა ასრულებთ `tuist bazel setup`; გამოძახებების სანახავად დამატებითი ფლაგები არ არის საჭირო.

## რა ჩანს დაფაზე {#what-the-dashboard-shows}

ყოველი გამოძახება იწერს:

- Bazel-ის მიერ შესრულებულ ბრძანებას, მის გასვლის კოდს, დაწყებისა და დასრულების დროს და საერთო ხანგრძლივობას.
- მოქმედებების, სამიზნეების და პაკეტების რაოდენობას.
- შეზღუდულ ბილდის დროის ხაზს და კრიტიკული გზის შეჯამებას.
- ქეშის მოხმარებებს, გამოტოვებებს, ჩამოტვირთვებს და ატვირთვებს, მიკუთვნებულს გამოძახებისთვის.
- პროგრესის ლოგის ხაზებს, დაფიქსირებულს გაშვების დროს, შესრულების თანმიმდევრობით.
- Bazel-ის ვერსიას, git შტოსა და კომიტს, როცა Bazel იტყობინება მათ, და იმას, შესრულდა თუ არა გაშვება CI-ზე.

ქეშის აქტივობა, რომლის Bazel-საც არ შეუძლია მიანიჭოს დასრულებულ გამოძახებას (მაგალითად, როცა ბრძანება წყდება შუა გაშვებისას), მაინც ჩანს პროექტის **მიმოხილვის** გვერდზე, როგორც ნედლი დაშორებული ქეშის დაკვირვება. ის არ განიხილება როგორც ბრძანების წარმატების, ხანგრძლივობის ან ტესტების შედეგების მტკიცებულება.

## მორგებული მეტამონაცემები {#custom-metadata}

მიამაგრეთ გასაღები-მნიშვნელობის მონაცემები გამოძახებებს, რათა შეადაროთ გაშვებები სხვადასხვა გუნდების, აღჭურვილობის ან სამუშაო ნაკადებისგან. მნიშვნელობები ჩანს თითოეული გამოძახების დეტალურ გვერდზე და აპლიკაციის პროგრამირების ინტერფეისისა და Model Context Protocol ინსტრუმენტების საშუალებით.

დააყენეთ მეტამონაცემები Bazel-ის ჩაშენებული `--build_metadata` ფლაგით:

```bash
bazel build --build_metadata=TICKET=TUIST-123 --build_metadata=RUNNER=macos-14 //...
```

ან დააყენეთ ისინი ერთხელ თითოეული არხისთვის თქვენს `.bazelrc`-ში:

```text
build:ci --build_metadata=RUNNER=macos-14
```

თითოეულ გამოძახებას შეუძლია შეიცავდეს 20-მდე მორგებული ჩანაწერი. გასაღებები შეიძლება შეიცავდეს 50-მდე სიმბოლოს, ხოლო მნიშვნელობები — 500-მდე სიმბოლოს. ჩანაწერები, რომლებიც აღემატება ამ ზღვრებს, იშლება გამოძახების შენახვამდე, ამიტომ არასწორი ჩანაწერი არ ხელს უშლის დანარჩენი ანგარიშის ჩაწერას.

კონტექსტური გასაღებები, რომლებსაც Tuist იღებს ბილდის გარემოდან, როგორიცაა `CI`, `GIT_BRANCH` და `GIT_COMMIT`, არ ინახება როგორც მორგებული მნიშვნელობები, რადგან ისინი უკვე ავსებენ გამოძახების ძირითად ველებს.

მორგებული მეტამონაცემები ხილულია პროექტის წევრებისთვის დაფაზე და აპლიკაციის პროგრამირების ინტერფეისისა და Model Context Protocol ინსტრუმენტების საშუალებით. არ გამოიყენოთ ის სერთიფიკატების, წვდომის ტოკენების ან სხვა მგრძნობიარე მონაცემებისთვის.

## უარის თქმა {#opting-out}

Build Event Protocol ნაკადი შეიცავს ბრძანების ხაზის არგუმენტებს, გარემოს მნიშვნელობებს და ბრძანების გამომავალ მონაცემებს. Tuist ინახავს მხოლოდ ზემოთ ჩამოთვლილ დასრულებული ბრძანების ველებს და აგდებს დანარჩენს, მაგრამ თუ საერთოდ არ გსურთ ღონისძიებების ნაკადის გაგზავნა, ხელახლა გაუშვით კონფიგურაცია:

```bash
tuist bazel setup --no-build-insights
```

გენერირებული `.bazelrc.tuist` შემდეგ აკონფიგურირებს მხოლოდ დაშორებულ ქეშს. გამოძახებები წყვეტენ გამოჩენას დაფაზე, ხოლო ქეშის დაკვირვებები რჩება **მიმოხილვის** გვერდზე.

## მონაცემთა შენახვა {#data-retention}

Tuist ინახავს Bazel-ის გამოძახებებს და მათ ლოგებს 90 დღის განმავლობაში. სრული პოლიტიკის სანახავად იხილეთ <.localized_link href="/guides/server/data-retention">მონაცემთა შენახვა</.localized_link>.
