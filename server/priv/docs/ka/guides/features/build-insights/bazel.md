# Bazel ბილდის ანალიტიკა {#bazel-build-insights}

ყოველი დასრულებული `build`, `test` და სხვა Bazel ბრძანება ჩანს პროექტის **გამოძახებების** დაფაზე: ბრძანების ტიპი, გასვლის სტატუსი, დაწყებისა და დასრულების დრო, ხანგრძლივობა, ასევე ქეშის მოხვედრები, გამოტოვებები, ჩამოტვირთვები და ატვირთვები, რომლებიც Bazel-მა მიანიჭა იმავე გამოძახებას.

გამოძახების მონაცემები გადაიცემა Bazel-ის [Build Event Protocol](https://bazel.build/remote/bep)-ის საშუალებით. კონფიგურაცია ავტომატურად აკავშირებს მას, როცა ასრულებთ `tuist bazel setup`; არ არის საჭირო დამატებითი ფლაგები გამოძახებების ნახვის დასაწყებად.

## რა ჩანს დაფაზე {#what-the-dashboard-shows}

ყოველი გამოძახება აღრიცხავს:

- ბრძანება, რომელიც Bazel-მა შეასრულა, მისი გასვლის კოდი, დაწყებისა და დასრულების დრო და ჯამური ხანგრძლივობა.
- მოქმედებების, სამიზნეებისა და პაკეტების რაოდენობა.
- შეზღუდული ბილდის დროის ხაზი და კრიტიკული გზის შეჯამება.
- ქეშის მოხვედრები, გამოტოვებები, ჩამოტვირთვები და ატვირთვები, რომლებიც მიეკუთვნება გამოძახებას.
- პროგრესის ლოგის ხაზები, რომლებიც ჩაიწერა შესრულების დროს, შესრულების თანმიმდევრობით.
- Bazel-ის ვერსია, git შტო და კომიტი, როცა Bazel იუწყება მათ, და შესრულდა თუ არა გაშვება CI-ზე.

ქეშის აქტივობა, რომლის Bazel-ს არ შეუძლია მიანიჭოს დასრულებულ გამოძახებას (მაგალითად, როცა ბრძანება წყდება შესრულების შუაში), მაინც ჩანს პროექტის **მიმოხილვაზე** როგორც raw remote-cache დაკვირვება. ის არ განიხილება როგორც ბრძანების წარმატების, ხანგრძლივობის ან ტესტების შედეგების მტკიცებულება.

## მორგებული მეტამონაცემები {#custom-metadata}

მიამაგრეთ key-value მონაცემები გამოძახებებს, რათა შეადაროთ გაშვებები სხვადასხვა გუნდებიდან, აპარატურებიდან ან სამუშაო ნაკადებიდან. მნიშვნელობები ჩანს ყოველი გამოძახების დეტალურ გვერდზე და ხელმისაწვდომია application programming interface-ისა და Model Context Protocol ინსტრუმენტების საშუალებით.

დააყენეთ მეტამონაცემები Bazel-ის ჩაშენებული `--build_metadata` ფლაგით:

```bash
bazel build --build_metadata=TICKET=TUIST-123 --build_metadata=RUNNER=macos-14 //...
```

ან დააყენეთ ისინი ერთხელ ყოველი lane-ისთვის თქვენს `.bazelrc`-ში:

```text
build:ci --build_metadata=RUNNER=macos-14
```

ყოველ გამოძახებას შეიძლება ჰქონდეს 20-მდე მორგებული ჩანაწერი. გასაღებებს შეიძლება ჰქონდეთ 50 სიმბოლომდე, ხოლო მნიშვნელობებს — 500 სიმბოლომდე. ჩანაწერები, რომლებიც აღემატება ამ ზღვრებს, იშლება გამოძახების შენახვამდე, ამიტომ არასწორი ჩანაწერი არ ხელს უშლის დანარჩენი ანგარიშის ჩაწერას.

კონტექსტის გასაღებები, რომლებსაც Tuist იღებს ბილდის გარემოდან, როგორიცაა `CI`, `GIT_BRANCH` და `GIT_COMMIT`, არ ინახება როგორც მორგებული მნიშვნელობები, რადგან ისინი უკვე ავსებენ გამოძახების ძირითად ველებს.

მორგებული მეტამონაცემები ხილულია პროექტის წევრებისთვის დაფაზე და ხელმისაწვდომია application programming interface-ისა და Model Context Protocol ინსტრუმენტების საშუალებით. არ გამოიყენოთ ის სერთიფიკატების, წვდომის ტოკენების ან სხვა მგრძნობიარე მონაცემებისთვის.

## გამორთვა {#opting-out}

Build Event Protocol ნაკადი შეიცავს ბრძანების ხაზის არგუმენტებს, გარემოს მნიშვნელობებს და ბრძანების გამომავალს. Tuist ინახავს მხოლოდ ზემოთ ჩამოთვლილ დასრულებული ბრძანების ველებს და აგდებს დანარჩენს, მაგრამ თუ არ გსურთ საერთოდ გაგზავნოთ მოვლენათა ნაკადი, ხელახლა გაუშვით კონფიგურაცია:

```bash
tuist bazel setup --no-build-insights
```

შექმნილი `.bazelrc.tuist` შემდეგ აკონფიგურირებს მხოლოდ remote cache-ს. გამოძახებები წყვეტენ გამოჩენას დაფაზე, ხოლო ქეშის დაკვირვებები რჩება **მიმოხილვის** გვერდზე.

## მონაცემთა შენახვა {#data-retention}

Tuist ინახავს Bazel გამოძახებებს და მათ ლოგებს 90 დღის განმავლობაში. სრული პოლიტიკის სანახავად იხილეთ <.localized_link href="/guides/server/data-retention">მონაცემთა შენახვა</.localized_link>.
