# Bazel-ის ბილდის ანალიტიკა {#bazel-build-insights}

ყველა დასრულებული `build`, `test` და სხვა Bazel-ის ბრძანება ჩანს პროექტის **გაშვებების** დაფაზე: ბრძანების ტიპი, გასვლის სტატუსი, დაწყებისა და დასრულების დრო, ხანგრძლივობა, ასევე ქეშის მოხმარებები, გამოტოვებები, ჩამოტვირთვები და ატვირთვები, რომლებიც Bazel-მა ამ კონკრეტულ გაშვებას მიაკუთვნა.

გაშვების მონაცემები მიეწოდება Bazel-ის [Build Event Protocol](https://bazel.build/remote/bep)-ის მეშვეობით. კონფიგურაცია ავტომატურად აერთებს მას, როცა ასრულებთ `tuist bazel setup`-ს; გაშვებების სანახავად დამატებითი ფლაგები არ არის საჭირო.

## რა ჩანს დაფაზე {#what-the-dashboard-shows}

ყოველი გაშვება იწერს:

- Bazel-ის მიერ შესრულებულ ბრძანებას, მის გასვლის კოდს, დაწყებისა და დასრულების დროს და ჯამურ ხანგრძლივობას.
- მოქმედებების, სამიზნეების და პაკეტების რაოდენობას.
- შეზღუდული ბილდის დროით შკალას და კრიტიკული გზის შეჯამებას.
- ქეშის მოხმარებებს, გამოტოვებებს, ჩამოტვირთვებს და ატვირთვებს, რომლებიც მიეკუთვნება ამ გაშვებას.
- პროგრესის ლოგის ხაზებს, რომლებიც აღიბეჭდა გაშვების დროს, შესრულების თანმიმდევრობით.
- Bazel-ის ვერსიას, git-ის შტოს და კომიტს, როცა Bazel აწვდის მათ, და იმას, შესრულდა თუ არა გაშვება CI-ზე.

ქეშის აქტივობა, რომლის მიკუთვნებასაც Bazel ვერ ახდენს დასრულებულ გაშვებაზე, მაგალითად, როცა ბრძანება წყდება შესრულების შუაში, მაინც ჩანს პროექტის **მიმოხილვის** გვერდზე, როგორც ნედლი დაშორებული ქეშის დაკვირვება. ის არ განიხილება როგორც ბრძანების წარმატების, ხანგრძლივობის ან ტესტების შედეგების მტკიცებულება.

## მორგებული მეტამონაცემები {#custom-metadata}

მიამაგრეთ გაშვებებს გასაღებ-მნიშვნელობის მონაცემები, რათა შეადაროთ სხვადასხვა გუნდების, აპარატურის ან სამუშაო ნაკადების გაშვებები. მნიშვნელობები ჩანს თითოეული გაშვების დეტალურ გვერდზე და ხელმისაწვდომია აპლიკაციის პროგრამირების ინტერფეისისა და Model Context Protocol-ის ინსტრუმენტების მეშვეობით.

დააყენეთ მეტამონაცემები Bazel-ის ჩაშენებული `--build_metadata` ფლაგით:

```bash
bazel build --build_metadata=TICKET=TUIST-123 --build_metadata=RUNNER=macos-14 //...
```

ან დააყენეთ ისინი ერთხელ თითოეული არხისთვის თქვენს `.bazelrc`-ში:

```text
build:ci --build_metadata=RUNNER=macos-14
```

თითოეულ გაშვებას შეუძლია შეიცავდეს 20-მდე მორგებულ ჩანაწერს. გასაღებები შეიძლება შეიცავდეს 50 სიმბოლომდე, ხოლო მნიშვნელობები — 500 სიმბოლომდე. ზღვარს გადაცილებული ჩანაწერები იშლება გაშვების შენახვამდე, ამიტომ არასწორი ჩანაწერი არ უშლის ხელს დანარჩენი ანგარიშის ჩაწერას.

კონტექსტის გასაღებები, რომლებსაც Tuist იღებს ბილდის გარემოდან, როგორიცაა `CI`, `GIT_BRANCH` და `GIT_COMMIT`, არ ინახება როგორც მორგებული მნიშვნელობები, რადგან ისინი უკვე ავსებენ გაშვების ძირითად ველებს.

მორგებული მეტამონაცემები ხილულია პროექტის წევრებისთვის დაფაზე და ხელმისაწვდომია აპლიკაციის პროგრამირების ინტერფეისისა და Model Context Protocol-ის ინსტრუმენტების მეშვეობით. არ გამოიყენოთ ის სერთიფიკატების, წვდომის ტოკენების ან სხვა მგრძნობიარე მონაცემებისთვის.

## გამორთვა {#opting-out}

Build Event Protocol-ის ნაკადი შეიცავს ბრძანების ხაზის არგუმენტებს, გარემოს მნიშვნელობებს და ბრძანების გამონატანს. Tuist ინახავს მხოლოდ ზემოთ ჩამოთვლილ დასრულებული ბრძანების ველებს და აგდებს დანარჩენს, მაგრამ თუ არ გსურთ საერთოდ გაგზავნოთ მოვლენათა ნაკადი, ხელახლა გაუშვით კონფიგურაცია:

```bash
tuist bazel setup --no-build-insights
```

შექმნილი `.bazelrc.tuist` შემდეგ აკონფიგურებს მხოლოდ დაშორებულ ქეშს. გაშვებები წყვეტენ გამოჩენას დაფაზე, ხოლო ქეშის დაკვირვებები რჩება **მიმოხილვის** გვერდზე.

## მონაცემთა შენახვა {#data-retention}

Tuist ინახავს Bazel-ის გაშვებებს და მათ ლოგებს 90 დღის განმავლობაში. სრული პოლიტიკის სანახავად იხილეთ <.localized_link href="/guides/server/data-retention">მონაცემთა შენახვა</.localized_link>.
