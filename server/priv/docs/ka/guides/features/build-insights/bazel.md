# Bazel-ის ბილდის ანალიტიკა {#bazel-build-insights}

ყოველი დასრულებული `build`, `test` და სხვა Bazel-ის ბრძანება ჩანს პროექტის **გამოძახებების** დაფაზე: ბრძანების ტიპი, გასვლის სტატუსი, დაწყებისა და დასრულების დრო, ხანგრძლივობა და ქეშის მოხმარებები, გამოტოვებები, ჩამოტვირთვები და ატვირთვები, რომლებიც Bazel-მა ამ კონკრეტულ გამოძახებას მიაწერა.

გამოძახების მონაცემები მიეწოდება Bazel-ის [Build Event Protocol](https://bazel.build/remote/bep)-ის საშუალებით. კონფიგურაცია ავტომატურად აკავშირებს მას, როცა ასრულებთ `tuist bazel setup`-ს; გამოძახებების სანახავად დამატებითი ფლაგები არ არის საჭირო.

## რა ჩანს დაფაზე {#what-the-dashboard-shows}

ყოველი გამოძახება იწერს:

- Bazel-ის მიერ შესრულებულ ბრძანებას, მის გასვლის კოდს, დაწყებისა და დასრულების დროს და ჯამურ ხანგრძლივობას.
- მოქმედებების, სამიზნეების და პაკეტების რაოდენობას.
- შეზღუდული ბილდის დროის ხაზს და კრიტიკული გზის შეჯამებას.
- ქეშის მოხმარებებს, გამოტოვებებს, ჩამოტვირთვებს და ატვირთვებს, რომლებიც მიეწერა გამოძახებას.
- პროგრესის ლოგის ხაზებს, რომლებიც აღიბეჭდა გაშვების დროს, შესრულების თანმიმდევრობით.
- Bazel-ის ვერსიას, git-ის შტოსა და კომიტს, როცა Bazel აწვდის მათ, და იმას, შესრულდა თუ არა გაშვება CI-ზე.

ქეშის აქტივობა, რომლის Bazel-ს მიწერა შეუძლებელია დასრულებულ გამოძახებაზე (მაგალითად, როცა ბრძანება წყდება შესრულების შუაში), მაინც ჩანს პროექტის **მიმოხილვის** გვერდზე, როგორც ნედლი დაშორებული ქეშის დაკვირვება. ის არ განიხილება როგორც ბრძანების წარმატების, ხანგრძლივობის ან ტესტების შედეგების მტკიცებულება.

## მორგებული მეტამონაცემები {#custom-metadata}

მიამაგრეთ გასაღებ-მნიშვნელობის მონაცემები გამოძახებებს, რათა შეადაროთ გაშვებები სხვადასხვა გუნდების, აპარატურის ან სამუშაო ნაკადების მიხედვით. მნიშვნელობები ჩანს თითოეული გამოძახების დეტალურ გვერდზე და ხელმისაწვდომია აპლიკაციის პროგრამირების ინტერფეისისა და Model Context Protocol-ის ინსტრუმენტების საშუალებით.

დააყენეთ მეტამონაცემები Bazel-ის ჩაშენებული `--build_metadata` ფლაგით:

```bash
bazel build --build_metadata=TICKET=TUIST-123 --build_metadata=RUNNER=macos-14 //...
```

ან დააყენეთ ისინი ერთხელ თითოეული არხისთვის თქვენს `.bazelrc`-ში:

```text
build:ci --build_metadata=RUNNER=macos-14
```

თითოეულ გამოძახებას შეუძლია შეიცავდეს 20-მდე მორგებულ ჩანაწერს. გასაღებები შეიძლება შეიცავდეს 50-მდე სიმბოლოს, ხოლო მნიშვნელობები — 500-მდე სიმბოლოს. იმ ჩანაწერებს, რომლებიც აღემატება ამ ზღვრებს, გამოძახების შენახვამდე აცილებენ, ამიტომ არასწორი ჩანაწერი არ ხელს უშლის დანარჩენი ანგარიშის ჩაწერას.

კონტექსტის გასაღებები, რომლებსაც Tuist იღებს ბილდის გარემოდან, როგორიცაა `CI`, `GIT_BRANCH` და `GIT_COMMIT`, არ ინახება როგორც მორგებული მნიშვნელობები, რადგან ისინი უკვე ავსებენ გამოძახების ძირითად ველებს.

მორგებული მეტამონაცემები ხილულია პროექტის წევრებისთვის დაფაზე და ხელმისაწვდომია აპლიკაციის პროგრამირების ინტერფეისისა და Model Context Protocol-ის ინსტრუმენტების საშუალებით. არ გამოიყენოთ ის სერთიფიკატების, წვდომის ტოკენების ან სხვა მგრძნობიარე მონაცემებისთვის.

## გამორთვა {#opting-out}

Build Event Protocol-ის ნაკადი შეიცავს ბრძანების ხაზის არგუმენტებს, გარემოს მნიშვნელობებს და ბრძანების გამომავალს. Tuist ინახავს მხოლოდ ზემოთ ჩამოთვლილ დასრულებული ბრძანების ველებს და აცილებს დანარჩენს, მაგრამ თუ არ გსურთ საერთოდ გაგზავნოთ მოვლენათა ნაკადი, ხელახლა გაუშვით კონფიგურაცია:

```bash
tuist bazel setup --no-build-insights
```

გენერირებული `.bazelrc.tuist` შემდეგ აკონფიგურირებს მხოლოდ დაშორებულ ქეშს. გამოძახებები აღარ ჩანს დაფაზე, ხოლო ქეშის დაკვირვებები რჩება **მიმოხილვის** გვერდზე.

## მონაცემთა შენახვა {#data-retention}

Tuist ინახავს Bazel-ის გამოძახებებს და მათ ლოგებს 90 დღის განმავლობაში. სრული პოლიტიკის სანახავად იხილეთ <.localized_link href="/guides/server/data-retention">მონაცემთა შენახვა</.localized_link>.
