# Once-ის ბილდების ინსაიტები {#once-build-insights}

Once ასრულებს გაშვებებს Tuist-ზე მათი შესრულების პარალელურად, რაც საშუალებას გაძლევთ თვალი ადევნოთ პროგრესს საბოლოო CI ლოგის მოლოდინის გარეშე. გახსენით დაფის ბმული, რომელიც იბეჭდება გაშვების დასაწყისში, რათა შეამოწმოთ გრაფიკი, ქმედებების სტატუსი და ქეშის გადაწყვეტილებები.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - დაასრულეთ <.localized_link href="/guides/get-started/once-project">Once-ით დაწყება</.localized_link> და გაავლეთ ავთენტიფიკაცია Once-ის გამშვებ მანქანაზე.

## გაუგზავნეთ თქვენი ბილდები {#report-your-builds}

განაგრძეთ Once-ის ბრძანებების გამოყენება:

```bash
once build MyApplication
```

პირდაპირი რეპორტინგი ხდება მაქსიმალური ძალისხმევის ფარგლებში. მიუწვდომელი რეპორტინგის წერტილი ან ვადაგასული სესია არ აჩერებს ბილდს. ხელახლა შედით სისტემაში `once auth login --provider tuist`-ით, თუ სესიის ვადა ამოიწურა.

## რას აჩვენებს დაფა {#what-the-dashboard-shows}

გამოიყენეთ **ბილდები** და **ბილდების გაშვებები** გაშვებების შესადარებლად დროის, შტოებისა და ლოკალური ან CI გარემოების მიხედვით. თითოეული გაშვება შეიძლება შეიცავდეს:

- მოთხოვნილ ბრძანებას, სტატუსს, დაწყების დროს და ხანგრძლივობას.
- Once-ის ვერსიასა და მოხსენებულ ჰოსტის ინფორმაციას.
- ქმედებებსა და მათ დამოკიდებულებებს, სტატუსს, ხანგრძლივობასა და ქეშის შედეგებს.
- მოხსენებულ ქმედებების შეცდომებს.
- Git შტოს, კომიტსა და CI კონტექსტს, როდესაც ისინი მოხსენებულია კლიენტის მიერ.

მოძებნეთ და გაფილტრეთ ქმედებები ჩავარდნილი ან ნელი სამუშაოს საპოვნელად. მოხსენებული ქმედებების სახელები და საწყისი ფაილები ეხმარება სამუშაოს კოდთან დაკავშირებაში; უფრო ძველმა კლიენტებმა შეიძლება ნაკლები დეტალი მოგაწოდოთ. ქეშირებული ან გამოტოვებული ქმედებები არ არის შესრულებული სამუშაო, ხოლო დროის მონაცემების არარსებობა არ ნიშნავს ნულოვანი ხანგრძლივობის შესრულებას.

Tuist ამჟამად არ იღებს Once-ის ქმედებების ლოგების ნედლ ნაკადს. შეინახეთ CI ლოგები პროცესის სრული გამომავალი ინფორმაციისთვის; გაშვების შეჯამებები და სტრუქტურირებული შეცდომები არ ცვლის ამ ლოგებს.

**ქეში**-ს ხედი ყოფს ქმედებების გადაწყვეტილებებს შინაარსის ობიექტების გადაცემისგან. იხილეთ <.localized_link href="/guides/features/cache/once">Once-ის ქეში</.localized_link> ქეშის აქტივობის ინტერპრეტაციისთვის.

## ტესტები {#tests}

ტესტების ბრძანებები ასევე ქმნიან Once-ის გაშვებებს. მათი მოხსენებული სუიტები და ტესტები ჩანს **ტესტები**-ის ქვეშ; ჰოსტინგული შარდები ასევე აქვეყნებენ გაერთიანებულ ტესტების გაშვებას. იხილეთ <.localized_link href="/guides/features/test-insights/once">Once-ის ტესტების ინსაიტები</.localized_link>.

## კოდირების აგენტები და Grafana {#coding-agents-and-grafana}

<.localized_link href="/guides/features/agentic-coding/mcp#once-runs">Model Context Protocol-ის ინსტრუმენტები</.localized_link> საშუალებას აძლევს აგენტს ჩამოთვალოს Once-ის გაშვებები და წაიკითხოს გაშვების ქმედებებისა და ქეშის ჯამური მაჩვენებლები. იგივე მონაცემების წაკითხვა შესაძლებელია HTTP API-ის მეშვეობით.

გამოიყენეთ <.localized_link href="/guides/integrations/grafana">Grafana-ს ინტეგრაცია</.localized_link> Once-ის საბოლოო ბილდის ჯანმრთელობის მეტრიკებისთვის. Once ამჟამად არ ახსენებს ქეშის დროის დაზოგვას, ამიტომ ეს გაზომვა რჩება მიუწვდომელი და არა ნულოვანი.
