# Struo ბილდის ანალიტიკა {#struo-build-insights}

<a id="once-build-insights"></a>

Struo შესრულებისას ნაკადებს გაშვებებს Tuist-ში, რათა პროგრესს დააკვირდეთ საბოლოო CI ლოგის მოლოდინის გარეშე. გახსენით დაფის ბმული, რომელიც ბეჭდავს გაშვების დასაწყისში, რათა შეამოწმოთ მისი გრაფიკი, ქმედებების სტატუსი და კეშის გადაწყვეტილებები.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - დაასრულეთ <.localized_link href="/guides/get-started/struo-project">Struo-ს გამოყენების დაწყება</.localized_link> და დააავთენტურეთ მანქანა, რომელზეც Struo მუშაობს.

## გაგზავნეთ თქვენი ბილდები {#report-your-builds}

განაგრძეთ Struo ბრძანებების გამოყენება:

```bash
struo build MyApplication
```

პირდაპირი ანგარიშგება ხდება მაქსიმალური ძალისხმევით. მიუწვდომელი ანგარიშგების წერტილი ან ვადაგასული სესია არ აფერხებს ბილდს. თავიდან შედით `struo auth login --provider tuist`-ით, თუ სესია ამოიწურება.

## რა აჩვენებს დაფა {#what-the-dashboard-shows}

გამოიყენეთ **ბილდები** და **ბილდის გაშვებები**, რათა შეადაროთ გაშვებები დროის, ტოტებისა და ლოკალური ან CI გარემოების მიხედვით. თითოეული გაშვება შეიძლება შეიცავდეს:

- მოთხოვნილ ბრძანებას, სტატუსს, დაწყების დროსა და ხანგრძლივობას.
- Struo-ს ვერსიასა და მოხსენებულ ჰოსტის ინფორმაციას.
- ქმედებებსა და მათ დამოკიდებულებებს, სტატუსს, ხანგრძლივობასა და კეშის შედეგებს.
- მოხსენებულ ქმედების შეცდომებს.
- Git ტოტს, კომიტსა და CI კონტექსტს, როდესაც ის კლიენტის მიერ არის მოხსენებული.

მოძებნეთ და გაფილტრეთ ქმედებები, რათა იპოვოთ ჩავარდნილი ან ნელი სამუშაო. მოხსენებული ქმედებების სახელები და საწყისი ფაილები ეხმარება სამუშაოს კოდთან დაკავშირებაში; უფრო ძველმა კლიენტებმა შეიძლება ნაკლები დეტალი მოგვაწოდონ. კეშირებული ან გამოტოვებული ქმედებები არ არის შესრულებული სამუშაო, ხოლო დროის მონაცემების არარსებობა არ ნიშნავს ნულოვანი ხანგრძლივობის შესრულებას.

Tuist ამჟამად არ იღებს Struo-ს ნედლ ქმედების ლოგების ნაკადს. შეინახეთ CI ლოგები პროცესის სრული გამოსავალისთვის; გაშვების შეჯამებები და სტრუქტურირებული შეცდომები არ ცვლის ამ ლოგებს.

**კეში**-ს ხედი ყოფს ქმედებების გადაწყვეტილებებს შინაარსის ობიექტების გადაცემისგან. იხილეთ <.localized_link href="/guides/features/cache/struo">Struo კეში</.localized_link> კეშის აქტივობის ინტერპრეტაციისთვის.

## ტესტები {#tests}

ტესტების ბრძანებები ასევე ქმნიან Struo გაშვებებს. მათი მოხსენებული სუიტები და საქმეები ჩანს **ტესტები**-ის ქვეშ; ჰოსტინგული შარდები დამატებით აქვეყნებენ გაერთიანებულ ტესტების გაშვებას. იხილეთ <.localized_link href="/guides/features/test-insights/struo">Struo ტესტების ანალიტიკა</.localized_link>.

## კოდირების აგენტები და Grafana {#coding-agents-and-grafana}

<.localized_link href="/guides/features/agentic-coding/mcp#struo-runs">Model Context Protocol ინსტრუმენტები</.localized_link> აგენტს საშუალებას აძლევს ჩამოთვალოს Struo გაშვებები და წაიკითხოს გაშვების ქმედებებისა და კეშის ჯამები. იგივე წაკითხვები ხელმისაწვდომია HTTP API-ს მეშვეობით.

გამოიყენეთ <.localized_link href="/guides/integrations/grafana">Grafana ინტეგრაცია</.localized_link> Struo-ს ბილდის ჯანმრთელობის საბოლოო მეტრიკებისთვის. Struo ამჟამად არ ანგარიშობს კეშის დროის დაზოგვას, ამიტომ ეს გაზომვა რჩება მიუწვდომლად და არა ნულად.
