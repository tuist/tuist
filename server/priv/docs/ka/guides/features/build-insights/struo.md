# Struo-ს ბილდის ინსაიტები {#struo-build-insights}

<a id="once-build-insights"></a>

Struo ასრულებს გაშვებებს Tuist-ზე მათი შესრულების პარალელურად, რაც საშუალებას გაძლევთ თვალყური ადევნოთ პროგრესს CI-ის საბოლოო ლოგის მოლოდინის გარეშე. გახსენით დაფის ბმული, რომელიც ბეჭდავს გაშვების დასაწყისში, რათა შეამოწმოთ მისი გრაფიკი, ქმედებების სტატუსი და კეშის გადაწყვეტილებები.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - შეასრულეთ <.localized_link href="/guides/get-started/struo-project">დაიწყეთ Struo-თან მუშაობა</.localized_link> და გაიარეთ ავთენტიკაცია იმ მანქანაზე, რომელიც ასრულებს Struo-ს.

## აჩვენეთ თქვენი ბილდები {#report-your-builds}

განაგრძეთ Struo-ს ბრძანებების გამოყენება:

```bash
struo build MyApplication
```

პირდაპირი ანგარიშგება ხორციელდება მაქსიმალური ძალისხმევით. მიუწვდომელი ანგარიშგების წერტილი ან ვადაგასული სესია არ აფერხებს ბილდს. ხელახლა შედით სისტემაში `struo auth login --provider tuist`-ით, თუ სესიის ვადა ამოიწურა.

## რა ჩანს დაფაზე {#what-the-dashboard-shows}

გამოიყენეთ **ბილდები** და **ბილდის გაშვებები**, რათა შეადაროთ გაშვებები დროის, შტოების და ადგილობრივი ან CI გარემოების მიხედვით. თითოეული გაშვება შეიძლება შეიცავდეს:

- მოთხოვნილ ბრძანებას, სტატუსს, დაწყების დროს და ხანგრძლივობას.
- Struo-ს ვერსიას და მოხსენებულ ჰოსტის ინფორმაციას.
- ქმედებებს და მათ დამოკიდებულებებს, სტატუსს, ხანგრძლივობას და კეშის შედეგებს.
- მოხსენებულ ქმედების შეცდომებს.
- Git შტოს, კომიტს და CI კონტექსტს, როდესაც ისინი მოხსენებულია კლიენტის მიერ.

მოძებნეთ და გაფილტრეთ ქმედებები, რათა იპოვოთ წარუმატებელი ან ნელი სამუშაოები. მოხსენებული ქმედებების სახელები და საწყისი ფაილები ეხმარება სამუშაოს კოდთან დაკავშირებაში; უფრო ძველმა კლიენტებმა შეიძლება ნაკლები დეტალი მოგვაწოდონ. კეშირებული ან გამოტოვებული ქმედებები არ არის შესრულებული სამუშაო, ხოლო დროის მონაცემების არარსებობა არ ნიშნავს ნულოვანი ხანგრძლივობის შესრულებას.

Tuist ამჟამად არ იღებს Struo-ს ნედლ ქმედების ლოგის ნაკადს. შეინახეთ CI ლოგები პროცესის სრული გამომავალი მონაცემებისთვის; გაშვების შეჯამებები და სტრუქტურირებული შეცდომები არ ცვლის ამ ლოგებს.

**კეშის** ხედი ყოფს ქმედებების გადაწყვეტილებებს შინაარსის ობიექტების გადაცემისგან. იხილეთ <.localized_link href="/guides/features/cache/struo">Struo კეში</.localized_link> კეშის აქტივობის ინტერპრეტაციისთვის.

## ტესტები {#tests}

ტესტების ბრძანებები ასევე ქმნიან Struo-ს გაშვებებს. მათი მოხსენებული სუიტები და ტესტები ჩანს **ტესტების** ქვეშ; ჰოსტინგზე განთავსებული შარდები ასევე აქვეყნებენ გაერთიანებულ ტესტების გაშვებას. იხილეთ <.localized_link href="/guides/features/test-insights/struo">Struo ტესტების ინსაიტები</.localized_link>.

## კოდირების აგენტები და Grafana {#coding-agents-and-grafana}

<.localized_link href="/guides/features/agentic-coding/mcp#struo-runs">Model Context Protocol-ის ინსტრუმენტები</.localized_link> საშუალებას აძლევს აგენტს ჩამოთვალოს Struo-ს გაშვებები და წაიკითხოს გაშვების ქმედებებისა და კეშის ჯამური მაჩვენებლები. იგივე მონაცემების წაკითხვა შესაძლებელია HTTP API-ის მეშვეობით.

გამოიყენეთ <.localized_link href="/guides/integrations/grafana">Grafana-ს ინტეგრაცია</.localized_link> Struo-ს ბილდის ჯანმრთელობის საბოლოო მეტრიკებისთვის. Struo ამჟამად არ ანგარიშგებს კეშის დროის დაზოგვას, ამიტომ ეს გაზომვა რჩება მიუწვდომელი და არა ნულის ტოლი.
