## მანქანური მეტრიკები {#machine-metrics}

აგების ანალიზი შეიძლება მოიცავდეს მანქანურ დონეზე შესრულების მეტრიკებს (CPU, მეხსიერება, ქსელი და დისკის გამოყენება), რომლებიც ფიქსირდება აგების პროცესში. ამის ჩასართავად, დააყენეთ მსუბუქი ფონური დემონი, რომელიც უწყვეტად იღებს სისტემურ მეტრიკებს:

```bash
tuist setup insights
```

ეს აწარმოებს ლოკალურ დემონს, რომელიც ფონურ რეჟიმში იღებს მეტრიკებს. მონაცემები ავტომატურად იჭერება `tuist inspect build`-ით და აიტვირთება აგების ანგარიშთან ერთად.

დისკის მეტრიკები მოიცავს წაკითხვის/ჩაწერის აქტივობას და, თავსებადი CLI-ისა და სერვერის შემთხვევაში, macOS-ის სისტემური Data ტომის (`/System/Volumes/Data`) საერთო და თავისუფალ სივრცეს. თავისუფალი სივრცე არ მოიცავს გასაწმენდ სივრცეს. დისკის სივრცის დიაგრამა აჩვენებს გამოყენებულ სივრცეს (საერთოს გამოკლებული თავისუფალი) საერთო ტევადობასთან ერთად მთელი აგების განმავლობაში, არა მხოლოდ ატვირთვის მომენტში. ის არ ზომავს ცალკეულ გარე ტომებს, რომლებიც გამოიყენება checkout-ისთვის ან DerivedData-სთვის.

CLI-ის განახლების შემდეგ, გადატვირთეთ არსებული სამპლერი `tuist teardown insights`-ით, შემდეგ კი `tuist setup insights`-ით. შერჩევა უნდა მუშაობდეს აგების დროს; ძველ ანგარიშებს და ვერშესრულებულ გაზომვებს არ აქვთ დისკის სივრცის მნიშვნელობები და არ ჩანს როგორც ნული. დისკის სივრცის ნიმუშები ემორჩილებიან მანქანური მეტრიკების არსებულ 90-დღიან შენახვის პოლიტიკას.

> [!TIP]
> **CI**
>
> გაუშვით `tuist setup insights` თქვენს CI მანქანებზე აგებამდე, რათა ასევე აღრიცხოთ მანქანური მეტრიკები.

მანქანური მეტრიკების შეგროვების შესაჩერებლად, გაუშვით:

```bash
tuist teardown insights
```

ეს ტვირთავს დემონის LaunchAgent-ს, შლის მის plist-ს და წაშლის შერჩეულ მეტრიკებსა და დემონის ლოგებს `~/.local/state`-დან, ისე რომ ფონზე არაფერი დარჩეს გაშვებული.
