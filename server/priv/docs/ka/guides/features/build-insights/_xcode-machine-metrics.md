## მანქანის მეტრიკები {#machine-metrics}

აგების ანალიტიკა შეიძლება მოიცავდეს მანქანის დონის შესრულების მეტრიკებს (CPU, მეხსიერება, ქსელი და დისკის გამოყენება), რომლებიც აღირიცხება აგების პროცესში. ამის ჩასართავად, დააყენეთ მსუბუქი ფონური დემონი, რომელიც უწყვეტად იღებს სისტემურ მეტრიკებს:

```bash
tuist setup insights
```

ეს აწარმოებს ლოკალურ დემონს, რომელიც ფონურად იღებს მეტრიკებს. მონაცემებს ავტომატურად იღებს `tuist inspect build` და ატვირთავს აგების ანგარიშთან ერთად.

დისკის მეტრიკები მოიცავს წაკითხვა/ჩაწერის აქტივობას და, თავსებადი CLI-ისა და სერვერის შემთხვევაში, macOS სისტემის Data ტომზე (`/System/Volumes/Data`) არსებულ საერთო და თავისუფალ ადგილს. თავისუფალი ადგილი არ მოიცავს გასაწმენდ ადგილს. დისკის ადგილის დიაგრამა აჩვენებს გამოყენებულ ადგილს (საერთოს გამოკლებული თავისუფალი) საერთო ტევადობასთან ერთად მთელი აგების განმავლობაში, არა მხოლოდ ატვირთვის მომენტში. ის არ ზომავს ცალკეულ გარე ტომებს, რომლებიც გამოიყენება checkout-ისთვის ან DerivedData-სთვის.

CLI-ის განახლების შემდეგ, გადატვირთეთ არსებული სემპლერი ბრძანებით `tuist teardown insights`, რასაც მოჰყვება `tuist setup insights`. სემპლინგი უნდა მუშაობდეს აგების დროს; ძველ ანგარიშებსა და ვერ მოხერხებულ გაზომვებს არ აქვთ დისკის ადგილის მნიშვნელობები და არ ჩანს ნულის სახით. დისკის ადგილის სემპლები ემორჩილებიან მანქანის მეტრიკების არსებულ 90-დღიან შენახვის პოლიტიკას.

> [!TIP]
> **CI**
>
> გაუშვით `tuist setup insights` თქვენს CI მანქანებზე აგებამდე, რათა ასევე აღირიცხოს მანქანის მეტრიკები.

მანქანის მეტრიკების შეგროვების შესაჩერებლად, გაუშვით:

```bash
tuist teardown insights
```

ეს ხსნის დემონის LaunchAgent-ს, შლის მის plist-ს და აშორებს შეგროვებულ მეტრიკებსა და დემონის ჟურნალებს `~/.local/state`-დან, ისე რომ ფონზე არაფერი დარჩება გაშვებული.
