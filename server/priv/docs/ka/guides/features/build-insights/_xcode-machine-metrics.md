## მანქანური მეტრიკები {#machine-metrics}

აგების ანალიტიკა შეიძლება შეიცავდეს მანქანურ დონეზე შესრულების მეტრიკებს (CPU, მეხსიერება, ქსელი და დისკის გამოყენება), რომლებიც აღირიცხება აგების პროცესში. ამის ჩასართავად, გაუშვით მსუბუქი ფონური დემონი, რომელიც უწყვეტად იღებს სისტემურ მეტრიკებს:

```bash
tuist setup insights
```

ეს აწარმოებს ლოკალურ დემონს, რომელიც ფონურად იღებს მეტრიკებს. მონაცემებს ავტომატურად იღებს `tuist inspect build` და ატვირთავს აგების ანგარიშთან ერთად.

დისკის მეტრიკები მოიცავს წაკითხვის/ჩაწერის აქტივობას და, თავსებადი CLI-ისა და სერვერის შემთხვევაში, macOS-ის სისტემური Data ტომის (`/System/Volumes/Data`) საერთო და ხელმისაწვდომ ადგილს. ხელმისაწვდომი ადგილი არ მოიცავს გასაწმენდ ადგილს. დისკის ადგილის დიაგრამა აჩვენებს გამოყენებულ ადგილს (საერთოს გამოკლებული ხელმისაწვდომი) საერთო ტევადობასთან ერთად აგების განმავლობაში, არა მხოლოდ ატვირთვის მომენტში. ის არ ზომავს ცალკე გარე ტომებს, რომლებიც გამოიყენება checkout-ისთვის ან DerivedData-სთვის.

CLI-ის განახლების შემდეგ, გადატვირთეთ არსებული ნიმუშების აღმები `tuist teardown insights`-ით, რასაც მოჰყვება `tuist setup insights`. ნიმუშების აღება უნდა მიმდინარეობდეს აგების დროს; ძველ ანგარიშებს და ვერ მოხერხებულ გაზომვებს არ აქვთ დისკის ადგილის მნიშვნელობები და არ არის ნაჩვენები როგორც ნული. დისკის ადგილის ნიმუშები ემორჩილება მანქანური მეტრიკების არსებულ 90-დღიან შენახვის პოლიტიკას.

> [!TIP]
> **CI**
>
> გაუშვით `tuist setup insights` თქვენს CI მანქანებზე აგებამდე, რათა ასევე აღირიცხოს მანქანური მეტრიკები.

მანქანური მეტრიკების შეგროვების შესაჩერებლად, გაუშვით:

```bash
tuist teardown insights
```

ეს ტვირთავს დემონის LaunchAgent-ს, შლის მის plist-ს და შლის აღებულ მეტრიკებსა და დემონის ჟურნალებს `~/.local/state`-დან, ასე რომ ფონურად არაფერი რჩება გაშვებული.
