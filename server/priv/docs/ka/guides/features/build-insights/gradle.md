# Gradle აგების ინსაიტები {#gradle-build-insights}

Tuist-ის Gradle პლაგინს შეუძლია აგების ანალიტიკის გაგზავნა Tuist-ში, რაც საშუალებას გაძლევთ დაინახოთ ამოცანების შესრულება და აგების მუშაობა.

## ატვირთვის ქცევის კონფიგურაცია {#configure-upload-behavior}

ნაგულისხმევად:
- ლოკალური აგებებისთვის აგების ანალიტიკა იტვირთება ფონურ რეჟიმში.
- CI გაშვებებისთვის აგების ანალიტიკა იტვირთება წინა პლანზე, რათა თავიდან აიცილოთ ტელემეტრიის დაკარგვა მოკლევადიან აგენტებზე.

ამ ქცევის კონტროლი შესაძლებელია `uploadInBackground`-ის გამოყენებით `tuist` გაფართოებაში:

```kotlin
tuist {
    uploadInBackground = false // always upload in the foreground
}
```

## კონფიგურაციის ცნობარი {#configuration-reference}

`uploadInBackground` პარამეტრი ხელმისაწვდომია `tuist` გაფართოების ბლოკში `settings.gradle.kts`-ში:

| პარამეტრი | ტიპი | ნაგულისხმევი | აღწერა |
| --- | --- | --- | --- |
| `uploadInBackground` | `Boolean?` | `null` (ლოკალურად ფონურად, CI-ზე წინა პლანზე) | ატვირთოს თუ არა აგების ინსაიტები ფონურ რეჟიმში ლოკალური აგებებისთვის. |

ეს პარამეტრი არ მოქმედებს დისტანციური ქეშის პარამეტრებზე `buildCache` ბლოკში.

## მოქმედის პრეტენზიის მოხსენება {#report-actor-claim}

აგებისა და ტესტების მოხსენების მოთხოვნები შეიცავს ოპციურ `x-tuist-actor-id` ჰედერს მხოლოდ მაშინ, როდესაც თქვენ ცალსახად ანიჭებთ `TUIST_ACTOR_ID`-ს ორგანიზაციის დონის ნიშანს ან აკონფიგურირებთ `buildInsights.actorId`-ს თქვენს პარამეტრებში. ნაგულისხმევად ნიშანი არ იგზავნება და პლაგინი არ აღმოაჩენს ოპერაციული სისტემის მომხმარებლის სახელებს. გარემოს გადაფარვას აქვს უპირატესობა. დააყენეთ ნებისმიერი გადაფარვა ცარიელ სტრიქონად, რათა გამოტოვოთ მოხსენებული იდენტიფიკატორი; ეს არ შლის ინდივიდუალური სერთიფიკატებით დამყარებულ იდენტურობას. არასწორი გადაფარვები გამოტოვებენ პრეტენზიას ნაცვლად უკან დაბრუნებისა. თუ მორგებული პროქსი უარყოფს უცნობ ჰედერებს, გამორთეთ ისინი `TUIST_ACTOR_ID=""`-ით.

```kotlin
tuist {
    buildInsights {
        actorId = providers.environmentVariable("CORPORATE_ACTOR_ID").getOrElse("")
    }
}
```

მოქმედის იდენტიფიკატორები არის 1–128 ბაიტიანი არა-სიცარიელე ბეჭდვადი ASCII სიმბოლოები. ისინი ხილულია ნებისმიერი პირისთვის, ვისაც შეუძლია ნახოს პროექტის მოხსენებები, მათ შორის საჯარო მაყურებლებისთვის, როდესაც პროექტი საჯაროა, და ექსპორტირდება მოხსენებებთან ერთად. არ ჩართოთ საიდუმლოებები ან პირადი ინფორმაცია, რომლის გამოქვეყნებაც არ გსურთ. დადასტურებულ ინდივიდუალურ სერთიფიკატს აქვს უპირატესობა დაშბორდზე; კლიენტების მიერ გაგზავნილი იდენტიფიკატორები წინააღმდეგ შემთხვევაში ცალსახად **დაუდასტურებელია**. ისინი არასდროს ანიჭებენ უფლებებს ან ავტომატურად არ უკავშირდებიან Tuist მომხმარებელს. ძველი სერვერები იგნორირებენ მიკუთვნების ჰედერს, ხოლო ახალი სერვერები აგრძელებენ ძველი კლიენტების მიღებას მის გარეშე. ახალი გაზიარებული-ტოკენის მოხსენებები იდენტიფიკატორის გარეშე აჩვენებენ **უცნობია**-ს, გამომქვეყნებელი ორგანიზაციის ნაცვლად; ისტორიული მოხსენებები ინარჩუნებენ მათ წინა მიკუთვნებას. აგებისა და ტესტების სიები გამოყოფენ დადასტურებული მომხმარებლის ფილტრებს დაუდასტურებელი მოხსენებული იდენტიფიკატორის ფილტრებისგან.

## ქსელის ნდობით გამოქვეყნება {#network-trusted-publishing}

თვითმასპინძელ განლაგებებს შეუძლიათ ცალსახად დაუშვან Gradle აგებისა და ტესტების მოხსენებები მათი ნდობითი ქსელიდან დეველოპერის სერთიფიკატების გარეშე. ოპერატორმა უნდა დააკონფიგურიროს `TUIST_NETWORK_TRUSTED_REPORT_PUBLISHING=true` ინსტანციაზე და ჯერ გადატვირთოს ის. ეს ვრცელდება ყველა მხარდაჭერილ პროექტზე; დაშბორდზე შესაბამისი პარამეტრი არ არსებობს. იხილეთ <.localized_link href="/guides/server/self-host/server#network-trusted-report-publishing">თვითმასპინძლობის სახელმძღვანელო</.localized_link>.

დააკონფიგურირეთ დანიშნულების ადგილი ერთხელ რეპოზიტორიაში:

```kotlin
tuist {
    project = "organization/project"
    url = "https://tuist.internal.example"
    buildCache { enabled = false }
}
```

აგებისა და ტესტების მოხსენებას არ სჭირდება ავთენტიკაციით ქეშის ბოლო წერტილის აღმოჩენა. ქეშზე წვდომა კვლავ მოითხოვს სერთიფიკატებს: გამორთეთ ქეში, თუ დეველოპერები არ ამზადებენ ტოკენებს. ხელმოუწერი ტესტების მოხსენებები გამოტოვებენ ნაწილისა და არსებული აგების მითითებებს და არ ამუშავებენ კარანტინის ან არამდგრადობის ავტომატიზაციებს. კარანტინის ძიება გამოტოვებულია, როდესაც სერთიფიკატები ნამდვილად არ არსებობს; მოქმედი სერთიფიკატებით ინარჩუნება არსებული ავთენტიკაციის ქცევა. თუ სერთიფიკატები არსებობს, ისინი კვლავ გამოიყენება და არასწორი სერთიფიკატები იწვევენ შეცდომას ნაცვლად სერთიფიკატების გარეშე გამოქვეყნებაზე გადასვლისა. როდესაც სერთიფიკატები არ არსებობს, პლაგინი ავტომატურად აღმოაჩენს, ნებას რთავს თუ არა თვითმასპინძელი სერვერი სერთიფიკატების გარეშე მოხსენებას. არ არის საჭირო კლიენტის დროშა ან `buildInsights` პარამეტრი. განაახლეთ სერვერის ყველა რეპლიკა აღმოჩენის შესაძლებლობის მქონე ვერსიამდე, სანამ განაახლებთ სერთიფიკატების გარეშე მომუშავე კლიენტებს. უფრო ძველ სერვერებს აღმოჩენის გარეშე, გამორთულ ინსტანციებს და აღმოჩენის შეცდომებს კვლავ სჭირდებათ ავთენტიკაცია; ავთენტიკაციით გამოქვეყნება რჩება თავსებადი. ცალსახად ცარიელი `TUIST_TOKEN` იწვევს შეცდომას ნაცვლად სერთიფიკატების გარეშე გამოქვეყნების ჩართვისა. ფორკის ან Dependabot სამუშაოებისთვის საიდუმლოებების გარეშე, წაშალეთ ეს ცვლადი ნაცვლად მისი ცარიელ სტრიქონად განსაზღვრისა.

სერვერი ანიჭებს სერთიფიკატების გარეშე მოხსენების ID-ებს. გაგზავნის გამეორებამ შეიძლება შექმნას მეორე მოხსენება; ეს რეჟიმი არ იძლევა იდემპოტენტური განმეორებების ან ავთენტიკაციით ტესტების მოხსენებებთან კორელაციის გარანტიას. ასეთ მოხსენებებს არ შეუძლიათ VCS კომენტარების ან ავტომატური შეცდომის აგენტის მოვლენების გამოწვევა. ქსელზე წვდომა არის გამოქვეყნების ნდობის საზღვარი, არა მოხსენებული მოქმედის იდენტურობის დადასტურება.

## მორგებული მეტამონაცემები {#custom-metadata}

მიამაგრეთ ტეგები და გასაღები-მნიშვნელობის მონაცემები Gradle აგებებს, რათა შეადაროთ გაშვებები სხვადასხვა გუნდების, აპარატურის ან სამუშაო პროცესებისგან. ტეგები ხელმისაწვდომია დაშბორდის ფილტრებში, ხოლო მნიშვნელობები ჩანს თითოეული აგების დეტალურ გვერდზე და აპლიკაციის პროგრამირების ინტერფეისსა და Model Context Protocol ინსტრუმენტებში.

დააყენეთ მეტამონაცემები გარემოს ცვლადებით:

```sh
export TUIST_BUILD_TAGS="nightly,android"
export TUIST_BUILD_VALUE_TICKET="TUIST-123"
export TUIST_BUILD_VALUE_RUNNER="macos-14"
```

ასევე შეგიძლიათ დააკონფიგურიროთ მეტამონაცემები `settings.gradle.kts`-ში:

```kotlin
tuist {
    buildInsights {
        tag("nightly")
        tag("android")
        value("ticket", "TUIST-123")
        value("runner", "macos-14")
    }
}
```

როდესაც ერთი და იგივე მნიშვნელობა კონფიგურირებულია ორივე ადგილას, უპირატესობა ენიჭება `settings.gradle.kts`-ში მითითებულ მნიშვნელობას.

ტეგებმა უნდა შეიცავდნენ მხოლოდ ასოები, რიცხვები, დეფისები და ქვედა ტირეები. აგებას შეიძლება ჰქონდეს 50-მდე ტეგი და თითოეულ ტეგს შეიძლება ჰქონდეს 50-მდე სიმბოლო. აგებას შეიძლება ჰქონდეს 20-მდე გასაღები-მნიშვნელობის ჩანაწერი, თითოეულ გასაღებს შეიძლება ჰქონდეს 50-მდე სიმბოლო და თითოეულ მნიშვნელობას შეიძლება ჰქონდეს 500-მდე სიმბოლო. ეს იგივე სერვერის მხარის ლიმიტებია, რომლებიც გამოიყენება Xcode აგების მეტამონაცემებისთვის. პლაგინი ტოვებს არასწორ ტეგებს და ზედმეტად დიდ ან ცარიელ მეტამონაცემების ჩანაწერებს მოხსენების გაგზავნამდე, ასე რომ არასწორმა კონფიგურაციამ ვერ შეუშალოს ხელი აგების ინსაიტების მოხსენების დანარჩენი ნაწილის შენახვას. გამოიყენეთ გასაღები-მნიშვნელობის მეტამონაცემები იმ მნიშვნელობებისთვის, რომლებიც არ აკმაყოფილებენ ტეგის შეზღუდვას.

მორგებული მეტამონაცემები ხილულია პროექტის წევრებისთვის დაშბორდზე და აპლიკაციის პროგრამირების ინტერფეისისა და Model Context Protocol ინსტრუმენტების მეშვეობით. არ გამოიყენოთ ის სერთიფიკატების, წვდომის ტოკენების ან სხვა მგრძნობიარე მონაცემებისთვის. Tuist ინარჩუნებს Gradle აგების მონაცემებს, მათ შორის ამ მეტამონაცემებს, 90 დღის განმავლობაში. იხილეთ <.localized_link href="/guides/server/data-retention">მონაცემთა შენახვის პოლიტიკა</.localized_link> დეტალებისთვის.
