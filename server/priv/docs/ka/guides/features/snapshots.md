# სნეპშოტები {#snapshots}

> [!IMPORTANT]
> **მხოლოდ მოწვევით**
>
> სნეპშოტები ამჟამად მხოლოდ მოწვევითაა ხელმისაწვდომი. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [კომუნიკაციის Slack-ში](https://slack.tuist.dev), რათა თქვენს ანგარიშზე წვდომა მოითხოვოთ.

სნეპშოტ ტესტები თქვენს UI-ს გამოსახულებებად გადასცემენ და შედარებენ საცნობარ გამოსახულებებთან, რათა ვიზუალური რეგრესიები აღმოაჩინონ. იმის ნაცვლად, რომ ეს საცნობარი გამოსახულებები თქვენს რეპოზიტორიაში შეინახოთ, თქვენ ტვირთავთ ყოველი ტესტების გაშვების მიერ შექმნილ გამოსახულებებს Tuist-ში. Tuist ადარებს მათ **ბაზისურ ვერსიასთან**, აჩვენებს ცვლილებებს დაფაზე და აფერხებს გაშვებას, სანამ ვინმე არ დაამტკიცებს ცვლილებებს.

- Git-ში არ არის საცნობარი გამოსახულებები, ამიტომ კლონები პატარა ზომისაა და არავინ უწევს PNG ფაილებში კონფლიქტების გადაწყვეტას.
- მიმომხილველები ხედავენ ცვლილებებს კოდის გვერდით: გვერდიგვერდ, diff-ის სახით, ან wipe ან onion skin ოვერლეის გამოყენებით.
- ცვლილებები მტკიცდება ან უარყოფილია დაფაზე ან pull request-ზე, და დამტკიცება ხდება ახალი ბაზისური ვერსია, როგორც კი ბრენჩი შეერთდება.

## როგორ მუშაობს {#how-it-works}

1. თქვენი ტესტები ქმნიან გამოსახულებებს, მაგალითად, ყოველი SwiftUI ან Compose preview-სთვის.
2. Tuist CLI ან Gradle პლაგინი ტვირთავს მათ როგორც **სნეპშოტ ბილდს** მიმდინარე კომიტისთვის.
3. Tuist ირჩევს ბაზისურ ვერსიას: თქვენი ძირითადი ბრენჩის ბილდს იმ კომიტზე, საიდანაც თქვენი ბრენჩი დაიწყო.
4. ყოველი გამოსახულება შედარებულია თავის ბაზისურ ვერსიასთან და მონიშნულია, როგორც შეცვლილი, დამატებული, წაშლილი ან უცვლელი.
5. ბილდი იღებს ვერდიქტს:

| ვერდიქტი | გაშვება | როდის |
| --- | --- | --- |
| ბაზისური | გაიარა | ბილდი არის ძირითადი ბრენჩიდან, ამიტომ მოგვიანებითი ბილდები მასთან შედარებით მოხდება. |
| გაიარა | გაიარა | არც ერთი გამოსახულება არ შეცვლილა ან წაშლილა. ახალ გამოსახულებებს გადახედვა არ სჭირდებათ. |
| საჭიროებს გადახედვას | ვერ გაიარა | გამოსახულებები შეიცვალა ან წაიშალა, და ჯერ არავინ გადახედა მათ. |
| დამტკიცებულია | გაიარა | ვინმემ დაამტკიცა ცვლილებები. |
| უარყოფილია | ვერ გაიარა | ვინმემ უარყო ცვლილებები. |

ბილდები შედარებულია **ჯგუფის** ფარგლებში, მაგალითად `ios-iphone` ან `android-phone`. გამოიყენეთ ერთი ჯგუფი თითოეული მოწყობილობის კონფიგურაციისთვის, ისე რომ სხვადასხვა ზომის გამოსახულებები ერთმანეთთან არ შედარდეს.

## გადახედეთ ცვლილებებს დაშბორდზე {#dashboard}

ყველა სნეპშოტ ბილდს აქვს გვერდი თქვენი პროექტის დაშბორდზე **Tests → Snapshots** განყოფილებაში. ის აჩვენებს ბილდის ვერდიქტს, ბრენჩს, კომიტს, პულ-რიქვესთს და ბაზისურს, ასევე ჩამოთვლის გამოსახულებებს სტატუსისა და ჯგუფის მიხედვით. გამოიყენეთ **Approve changes** ან **Reject changes** ბილდის გადასახედად. მოგვიანებით შეგიძლიათ შეცვალოთ გადახედვის შედეგი.

![სნეპშოტ ბილდი, რომელიც საჭიროებს გადახედვას, შეცვლილი გამოსახულებით ბაზისურთან ერთად](/images/guides/features/snapshots/review.png)

გადართეთ **Side by side**, **Diff** (რომელიც აღნიშნავს შეცვლილ პიქსელებს), **Wipe** (რომელიც სრიალებს ბაზისურსა და ახალ გამოსახულებას შორის) და **Onion** (რომელიც ერთს მეორეში აქრობს). თითოეული გამოსახულების გახსნა სრულ ეკრანზეა შესაძლებელი.

![Wipe რეჟიმი, სრიალებს ბაზისურსა და ახალ გამოსახულებას შორის](/images/guides/features/snapshots/wipe.png)

## გადახედეთ ცვლილებებს პულ-რიქვესთზე {#pull-request}

<.localized_link href="/guides/integrations/gitforge/github">GitHub app</.localized_link>-ის ინსტალაციის შემთხვევაში, პულ-რიქვესთის ყოველ სნეპშოტ ბილდს ენიჭება შემოწმება სახელით `tuist/snapshots (<set>)`. სანამ ცვლილებები საჭიროებს გადახედვას, ან მას შემდეგ, რაც რევიუერმა უარყო ისინი, შემოწმება ვერ გაივლის და ბლოკავს შერწყმას, თუ ის სავალდებულოა:

![პულ-რიქვესთის შერწყმის ფანჯარა, სადაც სნეპშოტების შემოწმება ვერ გაიარა, რადგან ცვლილებები უარყოფილი იყო](/images/guides/features/snapshots/github-pr-checks.png)

შემოწმება ითვლის ჯგუფის შეცვლილ, დამატებულ და წაშლილ გამოსახულებებს და აბმავს ბილდს დაშბორდზე. დაამტკიცეთ ან უარყავით ცვლილებები შემოწმების გვერდიდან, GitHub-ის დატოვების გარეშე. შემოწმება ახლდება რევიუერის სახელით, და უარყოფილი ბილდის დამტკიცება მოგვიანებითაც არის შესაძლებელი.

![სნეპშოტების შემოწმება GitHub-ზე ცვლილებების უარყოფის შემდეგ, მათი დამტკიცების ღილაკით](/images/guides/features/snapshots/github-check-run.png)

დამტკიცება არ იწვევს ტესტების ხელახლა გაშვებას: ის ავტომატურად ავლის შემოწმებას. იგივე ბრენჩის მოგვიანებითი ბილდები ინარჩუნებენ დამტკიცებას, სანამ მათ ზუსტად იგივე ცვლილებები აქვთ, ამიტომ CI-ის ხელახლა გაშვება ან კომიტის push-ვა, რომელიც არ ეხება გადახედილ გამოსახულებებს, ასევე გაივლის. ნებისმიერი სხვა ცვლილება გამოსახულებებში საჭიროებს ახალ გადახედვას. ბრენჩის შერწყმის შემდეგ, ძირითადი ბრენჩის ბილდი ხდება ახალი ბაზისური.
