# დირექტორიების სტრუქტურა {#directory-structure}

მიუხედავად იმისა, რომ Tuist პროექტები ხშირად გამოიყენება Xcode პროექტების ჩასანაცვლებლად, მათი გამოყენება ამ შემთხვევით არ არის შეზღუდული. Tuist პროექტები ასევე გამოიყენება სხვა ტიპის პროექტების გენერირებისთვის, როგორიცაა SPM პაკეტები, შაბლონები, პლაგინები და დავალებები. ეს დოკუმენტი აღწერს Tuist პროექტების სტრუქტურას და მათი ორგანიზების წესებს. მომდევნო სექციებში განვიხილავთ, თუ როგორ უნდა განვსაზღვროთ შაბლონები, პლაგინები და დავალებები.

## სტანდარტული Tuist პროექტები {#standard-tuist-projects}

Tuist პროექტები **Tuist-ის მიერ გენერირებული პროექტების ყველაზე გავრცელებული ტიპია.** ისინი გამოიყენება აპლიკაციების, ფრეიმვორკების და ბიბლიოთეკების ასაშენებლად. Xcode პროექტებისგან განსხვავებით, Tuist პროექტები Swift-შია განსაზღვრული, რაც მათ უფრო მოქნილს და შესანახად მარტივს ხდის. Tuist პროექტები ასევე უფრო დეკლარატიულია, რაც მათ გაგებასა და ანალიზს ამარტივებს. ქვემოთ მოცემული სტრუქტურა აჩვენებს ტიპურ Tuist პროექტს, რომელიც Xcode პროექტს გენერირებს:

```bash
Tuist.swift
Tuist/
  Package.swift
  ProjectDescriptionHelpers/
Projects/
  App/
    Project.swift
  Feature/
    Project.swift
Workspace.swift
```

- **Tuist დირექტორია:** ამ დირექტორიას ორი დანიშნულება აქვს. პირველ რიგში, ის მიუთითებს **სად მდებარეობს პროექტის ფესვა**. ეს საშუალებას გვაძლევს ავაგოთ გზები პროექტის ფესვასთან მიმართებაში და ასევე გავუშვათ Tuist ბრძანებები პროექტის ნებისმიერი დირექტორიიდან. მეორეც, ის არის კონტეინერი შემდეგი ფაილებისთვის:
  - **ProjectDescriptionHelpers:** ეს დირექტორია შეიცავს Swift კოდს, რომელიც გაზიარებულია ყველა მანიფესტის ფაილში. მანიფესტის ფაილებს შეუძლიათ `import ProjectDescriptionHelpers` ამ დირექტორიაში განსაზღვრული კოდის გამოსაყენებლად. კოდის გაზიარება სასარგებლოა დუბლიკაციების თავიდან ასაცილებლად და პროექტებში თანმიმდევრულობის უზრუნველსაყოფად.
  - **Package.swift:** ეს ფაილი შეიცავს Swift Package დამოკიდებულებებს, რომ Tuist-მა მათი ინტეგრირება შეძლოს Xcode პროექტებისა და target-ების გამოყენებით (როგორიცაა [CocoaPods](https://cocoapods.org)), რომლებიც კონფიგურირებადი და ოპტიმიზირებადია. მეტი ინფორმაცია <.localized_link href="/guides/features/projects/dependencies">აქ</.localized_link>.

- **ფესვის დირექტორია**: თქვენი პროექტის ფესვის დირექტორია, რომელიც ასევე შეიცავს `Tuist` დირექტორიას.
  - <.localized_link href="/guides/features/projects/manifests#tuistswift"><strong>Tuist.swift:</strong></.localized_link> ეს ფაილი შეიცავს Tuist-ის კონფიგურაციას, რომელიც გაზიარებულია ყველა პროექტში, სამუშაო სივრცეში და გარემოში. მაგალითად, ის შეიძლება გამოყენებულ იქნას სქემების ავტომატური გენერაციის გასათიშად ან პროექტების განლაგების სამიზნის განსაზღვრისთვის.
  - <.localized_link href="/guides/features/projects/manifests#workspaceswift"><strong>Workspace.swift:</strong></.localized_link> ეს მანიფესტი წარმოადგენს Xcode სამუშაო სივრცეს. ის გამოიყენება სხვა პროექტების დასაჯგუფებლად და ასევე შეუძლია დამატებითი ფაილებისა და სქემების დამატება.
  - <.localized_link href="/guides/features/projects/manifests#projectswift"><strong>Project.swift:</strong></.localized_link> ეს მანიფესტი წარმოადგენს Xcode პროექტს. ის გამოიყენება პროექტის შემადგენელი target-ებისა და მათი დამოკიდებულებების განსაზღვრისთვის.

ზემოთ აღწერილ პროექტთან ურთიერთობისას, ბრძანებები ელიან, რომ სამუშაო დირექტორიაში ან `--path` ფლაგით მითითებულ დირექტორიაში იპოვონ ან `Workspace.swift`, ან `Project.swift` ფაილი. მანიფესტი უნდა იყოს დირექტორიაში ან იმ დირექტორიის ქვედირექტორიაში, რომელიც შეიცავს `Tuist` დირექტორიას, რაც პროექტის ფესვას წარმოადგენს.

> [!TIP]
> Xcode სამუშაო სივრცეები საშუალებას აძლევდა პროექტების რამდენიმე Xcode პროექტად დაყოფას merge კონფლიქტების ალბათობის შესამცირებლად. თუ სამუშაო სივრცეებს ამ მიზნით იყენებდით, Tuist-ში ისინი არ არის საჭირო. Tuist ავტომატურად გენერირებს სამუშაო სივრცეს, რომელიც შეიცავს პროექტს და მისი დამოკიდებულებების პროექტებს.


## Swift Package <Badge type="warning" text="beta" /> {#swift-package-badge-typewarning-textbeta-}

Tuist ასევე მხარს უჭერს SPM პაკეტის პროექტებს. თუ თქვენ მუშაობთ SPM პაკეტზე, არაფრის განახლება არ უნდა დაგჭირდეთ. Tuist ავტომატურად აღმოაჩენს თქვენს ფესვის `Package.swift` და Tuist-ის ყველა ფუნქცია ისევე მუშაობს, თითქოს ის `Project.swift` მანიფესტი იყოს.

დასაწყებად, გაუშვით `tuist install` და `tuist generate` თქვენს SPM პაკეტში. თქვენს პროექტს ახლა უნდა ჰქონდეს ყველა ის სქემა და ფაილი, რასაც ხედავდით სტანდარტულ Xcode SPM ინტეგრაციაში. თუმცა, ახლა ასევე შეგიძლიათ გაუშვათ <.localized_link href="/guides/features/cache">`tuist cache`</.localized_link> და მიიღოთ თქვენი SPM დამოკიდებულებებისა და მოდულების უმეტესობის წინასწარი კომპილაცია, რაც მომდევნო ბილდებს უკიდურესად სწრაფს ხდის.
