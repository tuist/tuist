# საქაღალდეების სტრუქტურა {#directory-structure}

მიუხედავად იმისა, რომ Tuist-ის პროექტები ხშირად გამოიყენება Xcode-ის პროექტების ჩასანაცვლებლად, მათი გამოყენება ამ შემთხვევით არ არის შეზღუდული. Tuist-ის პროექტები ასევე გამოიყენება სხვა ტიპის პროექტების გენერირებისთვის, როგორიცაა SPM პაკეტები, შაბლონები, პლაგინები და ამოცანები. ეს დოკუმენტი აღწერს Tuist-ის პროექტების სტრუქტურას და მათი ორგანიზების წესებს. მომდევნო განყოფილებებში განვიხილავთ, თუ როგორ უნდა განვსაზღვროთ შაბლონები, პლაგინები და ამოცანები.

## სტანდარტული Tuist-ის პროექტები {#standard-tuist-projects}

Tuist-ის პროექტები **Tuist-ის მიერ გენერირებული პროექტების ყველაზე გავრცელებული ტიპია.** ისინი გამოიყენება აპლიკაციების, ფრეიმვორკების და ბიბლიოთეკების შესაქმნელად. Xcode-ის პროექტებისგან განსხვავებით, Tuist-ის პროექტები განისაზღვრება Swift-ში, რაც მათ უფრო მოქნილს და საპროგრამო უზრუნველყოფის მხრივ ადვილად შესანარჩუნებელს ხდის. Tuist-ის პროექტები ასევე უფრო დეკლარატიულია, რაც მათ გაგებასა და ანალიზს ამარტივებს. ქვემოთ მოცემული სტრუქტურა ასახავს ტიპურ Tuist-ის პროექტს, რომელიც Xcode-ის პროექტს გენერირებს:

```bash
Tuist.swift
Tuist/
  Package.swift
  ProjectDescriptionHelpers/
Projects/
  App/
    Project.swift
  Feature/
    Project.swift
Workspace.swift
```

- **Tuist-ის საქაღალდე:** ამ საქაღალდეს ორი დანიშნულება აქვს. პირველ რიგში, ის მიუთითებს **სად მდებარეობს პროექტის ფესვა**. ეს საშუალებას გვაძლევს ავაგოთ ბილიკები პროექტის ფესვთან მიმართებაში და ასევე გავუშვათ Tuist-ის ბრძანებები პროექტის ნებისმიერი საქაღალდიდან. მეორეც, ის შეიცავს შემდეგ ფაილებს:
  - **ProjectDescriptionHelpers:** ეს საქაღალდე შეიცავს Swift კოდს, რომელიც გაზიარებულია ყველა მანიფესტის ფაილში. მანიფესტის ფაილებს შეუძლიათ `import ProjectDescriptionHelpers` გამოიყენონ ამ საქაღალდეში განსაზღვრული კოდი. კოდის გაზიარება სასარგებლოა დუბლიკატების თავიდან ასაცილებლად და პროექტებში თანმიმდევრულობის უზრუნველსაყოფად.
  - **Package.swift:** ეს ფაილი შეიცავს Swift Package დამოკიდებულებებს, რათა Tuist-მა მათი ინტეგრირება შეძლოს Xcode-ის პროექტებისა და სამიზნეების გამოყენებით (როგორიცაა [CocoaPods](https://cocoapods.org)), რომლებიც კონფიგურირებადი და ოპტიმიზირებადია. ვრცლად იხილეთ <.localized_link href="/guides/features/projects/dependencies">აქ</.localized_link>.

- **ფესვის საქაღალდე**: თქვენი პროექტის ფესვის საქაღალდე, რომელიც ასევე შეიცავს `Tuist` საქაღალდეს.
  - <.localized_link href="/guides/features/projects/manifests#tuistswift"><strong>Tuist.swift:</strong></.localized_link> ეს ფაილი შეიცავს Tuist-ის კონფიგურაციას, რომელიც გაზიარებულია ყველა პროექტში, სამუშაო სივრცეში და გარემოში. მაგალითად, ის შეიძლება გამოყენებულ იქნას სქემების ავტომატური გენერაციის გამოსართავად ან პროექტების განთავსების სამიზნის განსასაზღვრად.
  - <.localized_link href="/guides/features/projects/manifests#workspaceswift"><strong>Workspace.swift:</strong></.localized_link> ეს მანიფესტი წარმოადგენს Xcode-ის სამუშაო სივრცეს. ის გამოიყენება სხვა პროექტების დასაჯგუფებლად და ასევე შეუძლია დამატებითი ფაილებისა და სქემების დამატება.
  - <.localized_link href="/guides/features/projects/manifests#projectswift"><strong>Project.swift:</strong></.localized_link> ეს მანიფესტი წარმოადგენს Xcode-ის პროექტს. ის გამოიყენება პროექტში შემავალი სამიზნეებისა და მათი დამოკიდებულებების განსასაზღვრად.

ზემოთ აღწერილ პროექტთან ურთიერთობისას, ბრძანებები ელიან, რომ სამუშაო საქაღალდეში ან `--path` ფლაგით მითითებულ საქაღალდეში იპოვონ ან `Workspace.swift`, ან `Project.swift` ფაილი. მანიფესტი უნდა იყოს იმ საქაღალდეში ან მის ქვესაქაღალდეში, რომელიც შეიცავს `Tuist` საქაღალდეს, რაც პროექტის ფესვს წარმოადგენს.

> [!TIP]
> Xcode-ის სამუშაო სივრცეები საშუალებას იძლეოდა პროექტები რამდენიმე Xcode-ის პროექტად გაგვეყო, რათა შემცირებულიყო შერწყმის კონფლიქტების ალბათობა. თუ სამუშაო სივრცეებს სწორედ ამ მიზნით იყენებდით, Tuist-ში ისინი არ არის საჭირო. Tuist ავტომატურად გენერირებს სამუშაო სივრცეს, რომელიც შეიცავს პროექტსა და მისი დამოკიდებულებების პროექტებს.


## Swift Package <Badge type="warning" text="beta" /> {#swift-package-badge-typewarning-textbeta-}

Tuist ასევე მხარდაჭერს SPM პაკეტის პროექტებს. თუ SPM პაკეტზე მუშაობთ, არაფრის განახლება არ უნდა დაგჭირდეთ. Tuist ავტომატურად აღიქვამს თქვენს ფესვის `Package.swift` და Tuist-ის ყველა ფუნქცია ისევე მუშაობს, თითქოს ის `Project.swift` მანიფესტი იყოს.

დასაწყებად, გაუშვით `tuist install` და `tuist generate` თქვენს SPM პაკეტში. თქვენს პროექტს ახლა უნდა ჰქონდეს ყველა ის სქემა და ფაილი, რასაც ხედავდით სტანდარტულ Xcode SPM ინტეგრაციაში. თუმცა, ახლა ასევე შეგიძლიათ გაუშვათ <.localized_link href="/guides/features/cache">`tuist cache`</.localized_link> და თქვენი SPM დამოკიდებულებებისა და მოდულების უმეტესობა წინასწარ იქნება კომპილირებული, რაც მომდევნო ბილდებს უკიდურესად სწრაფს გახდის.
