# საქაღალდეების სტრუქტურა {#directory-structure}

მიუხედავად იმისა, რომ Tuist პროექტებს ხშირად Xcode პროექტების ჩასანაცვლებლად იყენებენ, მათი გამოყენება ამით არ შემოიფარგლება. Tuist პროექტები ასევე გამოიყენება სხვა ტიპის პროექტების გენერაციისთვის, როგორიცაა SPM პაკეტები, შაბლონები, პლაგინები და ამოცანები. ეს დოკუმენტი აღწერს Tuist პროექტების სტრუქტურას და მათი ორგანიზების წესებს. მოგვიანებით განვიხილავთ, თუ როგორ უნდა განვსაზღვროთ შაბლონები, პლაგინები და ამოცანები.

## სტანდარტული Tuist პროექტები {#standard-tuist-projects}

Tuist პროექტები **Tuist-ის მიერ გენერირებული ყველაზე გავრცელებული პროექტის ტიპია.** ისინი გამოიყენება აპლიკაციების, ფრეიმვორკების და ბიბლიოთეკების შესაქმნელად. Xcode პროექტებისგან განსხვავებით, Tuist პროექტები Swift-შია განსაზღვრული, რაც მათ უფრო მოქნილს და შენარჩუნებადს ხდის. Tuist პროექტები ასევე უფრო დეკლარატიულია, რაც მათ გაგებასა და ანალიზს ამარტივებს. ქვემოთ მოცემული სტრუქტურა ასახავს ტიპურ Tuist პროექტს, რომელიც Xcode პროექტს გენერირებს:

```bash
Tuist.swift
Tuist/
  Package.swift
  ProjectDescriptionHelpers/
Projects/
  App/
    Project.swift
  Feature/
    Project.swift
Workspace.swift
```

- **Tuist საქაღალდე:** ამ საქაღალდეს ორი დანიშნულება აქვს. პირველ რიგში, ის მიუთითებს **სად მდებარეობს პროექტის ფესვური**. ეს საშუალებას გვაძლევს ავაგოთ გზები პროექტის ფესვთან მიმართებაში და ასევე გავუშვათ Tuist ბრძანებები პროექტის ნებისმიერი საქაღალდიდან. მეორეც, ის არის შემდეგი ფაილების კონტეინერი:
  - **ProjectDescriptionHelpers:** ეს საქაღალდე შეიცავს Swift კოდს, რომელიც საერთოა ყველა მანიფესტის ფაილისთვის. მანიფესტის ფაილებს შეუძლიათ `import ProjectDescriptionHelpers` ამ საქაღალდეში განსაზღვრული კოდის გამოსაყენებლად. კოდის გაზიარება სასარგებლოა დუბლირების თავიდან ასაცილებლად და პროექტებში თანმიმდევრულობის უზრუნველსაყოფად.
  - **Package.swift:** ეს ფაილი შეიცავს Swift Package დამოკიდებულებებს, რომლებიც Tuist ინტეგრირდება Xcode პროექტებისა და სამიზნეების საშუალებით (მაგალითად, [CocoaPods](https://cocoapods.org)), რაც კონფიგურირებადსა და ოპტიმიზირებადს ხდის. მეტი ინფორმაცია <.localized_link href="/guides/features/projects/dependencies">აქ</.localized_link>.

- **ფესვური საქაღალდე**: თქვენი პროექტის ფესვური საქაღალდე, რომელიც ასევე შეიცავს `Tuist` საქაღალდეს.
  - <.localized_link href="/guides/features/projects/manifests#tuistswift"><strong>Tuist.swift:</strong></.localized_link> ეს ფაილი შეიცავს Tuist-ის კონფიგურაციას, რომელიც საერთოა ყველა პროექტის, სამუშაო სივრცისა და გარემოსთვის. მაგალითად, ის შეიძლება გამოყენებულ იქნას სქემების ავტომატური გენერაციის გასათიშად ან პროექტების განთავსების სამიზნის განსასაზღვრად.
  - <.localized_link href="/guides/features/projects/manifests#workspaceswift"><strong>Workspace.swift:</strong></.localized_link> ეს მანიფესტი წარმოადგენს Xcode სამუშაო სივრცეს. ის გამოიყენება სხვა პროექტების დასაჯგუფებლად და ასევე შეუძლია დამატებითი ფაილებისა და სქემების დამატება.
  - <.localized_link href="/guides/features/projects/manifests#projectswift"><strong>Project.swift:</strong></.localized_link> ეს მანიფესტი წარმოადგენს Xcode პროექტს. ის გამოიყენება პროექტში შემავალი სამიზნეებისა და მათი დამოკიდებულებების განსასაზღვრად.

ზემოთ აღწერილ პროექტთან ურთიერთობისას, ბრძანებები ელიან, რომ სამუშაო საქაღალდეში ან `--path` ფლაგით მითითებულ საქაღალდეში იპოვონ ან `Workspace.swift`, ან `Project.swift` ფაილი. მანიფესტი უნდა იყოს ისეთ საქაღალდეში ან მის ქვესაქაღალდეში, რომელიც შეიცავს `Tuist` საქაღალდეს, რაც პროექტის ფესვს წარმოადგენს.

> [!TIP]
> Xcode სამუშაო სივრცეები საშუალებას იძლეოდნენ პროექტების რამდენიმე Xcode პროექტად დაყოფისთვის, რათა შემცირდეს შერწყმის კონფლიქტების ალბათობა. თუ სამუშაო სივრცეებს ამ მიზნით იყენებდით, Tuist-ში ისინი არ არის საჭირო. Tuist ავტომატურად გენერირებს სამუშაო სივრცეს, რომელიც შეიცავს პროექტსა და მისი დამოკიდებულებების პროექტებს.


## Swift Package <Badge type="warning" text="beta" /> {#swift-package-badge-typewarning-textbeta-}

Tuist ასევე მხარს უჭერს SPM პაკეტის პროექტებს. თუ SPM პაკეტზე მუშაობთ, არაფრის განახლება არ დაგჭირდებათ. Tuist ავტომატურად აღიქვამს თქვენს ფესვურ `Package.swift` და Tuist-ის ყველა ფუნქცია ისევე მუშაობს, თითქოს ის `Project.swift` მანიფესტი იყოს.

დასაწყებად, გაუშვით `tuist install` და `tuist generate` თქვენს SPM პაკეტში. თქვენს პროექტს ახლა უნდა ჰქონდეს იგივე სქემები და ფაილები, რასაც ხედავდით სტანდარტულ Xcode SPM ინტეგრაციაში. თუმცა, ახლა ასევე შეგიძლიათ გაუშვათ <.localized_link href="/guides/features/cache">`tuist cache`</.localized_link> და მიიღოთ თქვენი SPM დამოკიდებულებებისა და მოდულების უმეტესობა წინასწარ კომპილირებული, რაც მომდევნო ბილდებს უკიდურესად სწრაფს ხდის.
