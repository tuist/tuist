# საქაღალდეების სტრუქტურა {#directory-structure}

მიუხედავად იმისა, რომ Tuist-ის პროექტები ხშირად გამოიყენება Xcode-ის პროექტების ჩასანაცვლებლად, ისინი არ შემოიფარგლება მხოლოდ ამ გამოყენებით. Tuist-ის პროექტები ასევე გამოიყენება სხვა ტიპის პროექტების გენერაციისთვის, როგორიცაა SPM პაკეტები, შაბლონები, პლაგინები და ამოცანები. ეს დოკუმენტი აღწერს Tuist-ის პროექტების სტრუქტურას და მათ ორგანიზების წესებს. მომდევნო განყოფილებებში განვიხილავთ, თუ როგორ უნდა განვსაზღვროთ შაბლონები, პლაგინები და ამოცანები.

## სტანდარტული Tuist-ის პროექტები {#standard-tuist-projects}

Tuist-ის პროექტები არის **Tuist-ით გენერირებული პროექტების ყველაზე გავრცელებული ტიპი.** ისინი გამოიყენება აპლიკაციების, ფრეიმვორკების და ბიბლიოთეკების შესაქმნელად. Xcode-ის პროექტებისგან განსხვავებით, Tuist-ის პროექტები განისაზღვრება Swift-ში, რაც მათ უფრო მოქნილს და შენარჩუნებადს ხდის. Tuist-ის პროექტები ასევე უფრო დეკლარატიულია, რაც მათ გაგებასა და ანალიზს ამარტივებს. ქვემოთ მოცემული სტრუქტურა ასახავს ტიპურ Tuist-ის პროექტს, რომელიც აგენერირებს Xcode-ის პროექტს:

```bash
Tuist.swift
Tuist/
  Package.swift
  ProjectDescriptionHelpers/
Projects/
  App/
    Project.swift
  Feature/
    Project.swift
Workspace.swift
```

- **Tuist-ის საქაღალდე:** ამ საქაღალდეს ორი დანიშნულება აქვს. პირველ რიგში, ის მიუთითებს **სად მდებარეობს პროექტის ფესვამდე**. ეს საშუალებას იძლევა ავაგოთ ბილიკები პროექტის ფესვთან მიმართებაში და ასევე გავუშვათ Tuist-ის ბრძანებები პროექტის ნებისმიერი საქაღალდიდან. მეორეც, ის არის კონტეინერი შემდეგი ფაილებისთვის:
  - **ProjectDescriptionHelpers:** ეს საქაღალდე შეიცავს Swift-ის კოდს, რომელიც გაზიარებულია ყველა მანიფესტის ფაილში. მანიფესტის ფაილებს შეუძლიათ `import ProjectDescriptionHelpers` ამ საქაღალდეში განსაზღვრული კოდის გამოსაყენებლად. კოდის გაზიარება სასარგებლოა დუბლირების თავიდან ასაცილებლად და პროექტებში თანმიმდევრულობის უზრუნველსაყოფად.
  - **Package.swift:** ეს ფაილი შეიცავს Swift Package-ის დამოკიდებულებებს, რომ Tuist-მა ისინი ინტეგრირდეს Xcode-ის პროექტებისა და სამიზნეების გამოყენებით (როგორიცაა [CocoaPods](https://cococapods)), რომლებიც კონფიგურირებადი და ოპტიმიზირებადია. გაიგეთ მეტი <.localized_link href="/guides/features/projects/dependencies">აქ</.localized_link>.

- **ფესვის საქაღალდე**: თქვენი პროექტის ფესვის საქაღალდე, რომელიც ასევე შეიცავს `Tuist` საქაღალდეს.
  - <.localized_link href="/guides/features/projects/manifests#tuistswift"><bold>Tuist.swift:</bold></.localized_link> ეს ფაილი შეიცავს Tuist-ის კონფიგურაციას, რომელიც გაზიარებულია ყველა პროექტში, სამუშაო სივრცეში და გარემოში. მაგალითად, ის შეიძლება გამოყენებულ იქნას სქემების ავტომატური გენერაციის გასათიშად ან პროექტების განთავსების სამიზნის განსაზღვრისთვის.
  - <.localized_link href="/guides/features/projects/manifests#workspace-swift"><bold>Workspace.swift:</bold></.localized_link> ეს მანიფესტი წარმოადგენს Xcode-ის სამუშაო სივრცეს. ის გამოიყენება სხვა პროექტების დასაჯგუფებლად და ასევე შეუძლია დამატებითი ფაილებისა და სქემების დამატება.
  - <.localized_link href="/guides/features/projects/manifests#project-swift"><bold>Project.swift:</bold></.localized_link> ეს მანიფესტი წარმოადგენს Xcode-ის პროექტს. ის გამოიყენება პროექტის შემადგენელი სამიზნეებისა და მათი დამოკიდებულებების განსაზღვრისთვის.

ზემოთ მოცემულ პროექტთან ურთიერთობისას, ბრძანებები ელიან, რომ იპოვონ ან `Workspace.swift`, ან `Project.swift` ფაილი სამუშაო საქაღალდეში ან `--path` ფლაგით მითითებულ საქაღალდეში. მანიფესტი უნდა იყოს იმ საქაღალდეში ან მის ქვესაქაღალდეში, რომელიც შეიცავს `Tuist` საქაღალდეს, რაც წარმოადგენს პროექტის ფესვს.

> [!TIP]
> Xcode-ის სამუშაო სივრცეები საშუალებას იძლეოდა პროექტების რამდენიმე Xcode-ის პროექტად დაყოფისა, რათა შემცირებულიყო შერწყმის კონფლიქტების ალბათობა. თუ სამუშაო სივრცეებს სწორედ ამ მიზნით იყენებდით, Tuist-ში ისინი არ გჭირდებათ. Tuist ავტომატურად აგენერირებს სამუშაო სივრცეს, რომელიც შეიცავს პროექტს და მისი დამოკიდებულებების პროექტებს.


## Swift Package <Badge type="warning" text="beta" /> {#swift-package-badge-typewarning-textbeta-}

Tuist ასევე მხარს უჭერს SPM პაკეტის პროექტებს. თუ მუშაობთ SPM პაკეტზე, არ უნდა დაგჭირდეთ რაიმეს განახლება. Tuist ავტომატურად აღიქვამს თქვენს ფესვის `Package.swift` და Tuist-ის ყველა ფუნქცია მუშაობს ისე, თითქოს ის იყოს `Project.swift` მანიფესტი.

დასაწყებად, გაუშვით `tuist install` და `tuist generate` თქვენს SPM პაკეტში. თქვენს პროექტს ახლა უნდა ჰქონდეს იგივე სქემები და ფაილები, რასაც ხედავდით სტანდარტულ Xcode SPM ინტეგრაციაში. თუმცა, ახლა ასევე შეგიძლიათ გაუშვათ <.localized_link href="/guides/features/cache">`tuist cache`</.localized_link> და მიიღოთ თქვენი SPM დამოკიდებულებებისა და მოდულების უმეტესობა წინასწარ კომპილირებული, რაც შემდგომ ბილდებს უკიდურესად სწრაფს ხდის.
