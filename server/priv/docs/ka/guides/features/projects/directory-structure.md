# დირექტორიების სტრუქტურა {#directory-structure}

მიუხედავად იმისა, რომ Tuist-ის პროექტები ხშირად გამოიყენება Xcode-ის პროექტების ჩასანაცვლებლად, ისინი არ არის შეზღუდული მხოლოდ ამ გამოყენებით. Tuist-ის პროექტები ასევე გამოიყენება სხვა ტიპის პროექტების გენერაციისთვის, როგორიცაა SPM პაკეტები, შაბლონები, პლაგინები და დავალებები. ეს დოკუმენტი აღწერს Tuist-ის პროექტების სტრუქტურას და მათი ორგანიზების წესებს. შემდგომ თავებში განვიხილავთ, თუ როგორ უნდა განვსაზღვროთ შაბლონები, პლაგინები და დავალებები.

## სტანდარტული Tuist-ის პროექტები {#standard-tuist-projects}

Tuist-ის პროექტები **Tuist-ის მიერ გენერირებული პროექტების ყველაზე გავრცელებული ტიპია.** ისინი გამოიყენება აპლიკაციების, ფრეიმვორკების და ბიბლიოთეკების შესაქმნელად. Xcode-ის პროექტებისგან განსხვავებით, Tuist-ის პროექტები განისაზღვრება Swift-ში, რაც მათ უფრო მოქნილს და მოვლენაში მარტივს ხდის. Tuist-ის პროექტები ასევე უფრო დეკლარატიულია, რაც მათ გაგებასა და ანალიზს ამარტივებს. ქვემოთ მოცემული სტრუქტურა აჩვენებს ტიპურ Tuist-ის პროექტს, რომელიც Xcode-ის პროექტს გენერირებს:

```bash
Tuist.swift
Tuist/
  Package.swift
  ProjectDescriptionHelpers/
Projects/
  App/
    Project.swift
  Feature/
    Project.swift
Workspace.swift
```

- **Tuist-ის დირექტორია:** ამ დირექტორიას ორი დანიშნულება აქვს. პირველ რიგში, ის მიუთითებს **პროექტის ფესვის მდებარეობას**. ეს საშუალებას გვაძლევს ავაგოთ ბილიკები პროექტის ფესვის მიმართ და ასევე გავუშვათ Tuist-ის ბრძანებები პროექტის ნებისმიერი დირექტორიიდან. მეორეც, ის არის შემდეგი ფაილების კონტეინერი:
  - **ProjectDescriptionHelpers:** ეს დირექტორია შეიცავს Swift-ის კოდს, რომელიც გაზიარებულია ყველა მანიფესტის ფაილში. მანიფესტის ფაილებს შეუძლიათ `import ProjectDescriptionHelpers` ამ დირექტორიაში განსაზღვრული კოდის გამოსაყენებლად. კოდის გაზიარება სასარგებლოა დუბლირების თავიდან ასაცილებლად და პროექტებში თანმიმდევრულობის უზრუნველსაყოფად.
  - **Package.swift:** ეს ფაილი შეიცავს Swift Package დამოკიდებულებებს, რომ Tuist-მა მათი ინტეგრირება შეძლოს Xcode-ის პროექტებისა და სამიზნეების გამოყენებით (როგორიცაა [CocoaPods](https://cococapods)), რაც კონფიგურირებადი და ოპტიმიზირებადია. შეიტყვეთ მეტი <.localized_link href="/guides/features/projects/dependencies">აქ</.localized_link>.

- **ფესვის დირექტორია**: თქვენი პროექტის ფესვის დირექტორია, რომელიც ასევე შეიცავს `Tuist` დირექტორიას.
  - <.localized_link href="/guides/features/projects/manifests#tuistswift"><bold>Tuist.swift:</bold></.localized_link> ეს ფაილი შეიცავს Tuist-ის კონფიგურაციას, რომელიც გაზიარებულია ყველა პროექტში, სამუშაო სივრცეში და გარემოში. მაგალითად, ის შეიძლება გამოყენებულ იქნას სქემების ავტომატური გენერაციის გასათიშად ან პროექტების განთავსების სამიზნის განსაზღვრისთვის.
  - <.localized_link href="/guides/features/projects/manifests#workspace-swift"><bold>Workspace.swift:</bold></.localized_link> ეს მანიფესტი წარმოადგენს Xcode-ის სამუშაო სივრცეს. ის გამოიყენება სხვა პროექტების დაჯგუფებისთვის და ასევე შეუძლია დამატებითი ფაილებისა და სქემების დამატება.
  - <.localized_link href="/guides/features/projects/manifests#project-swift"><bold>Project.swift:</bold></.localized_link> ეს მანიფესტი წარმოადგენს Xcode-ის პროექტს. ის გამოიყენება პროექტში შემავალი სამიზნეებისა და მათი დამოკიდებულებების განსაზღვრისთვის.

ზემოთ აღწერილ პროექტთან ურთიერთობისას, ბრძანებები ელიან, რომ სამუშაო დირექტორიაში ან `--path` ფლაგით მითითებულ დირექტორიაში იპოვონ ან `Workspace.swift`, ან `Project.swift` ფაილი. მანიფესტი უნდა იყოს დირექტორიაში ან იმ დირექტორიის ქვედირექტორიაში, რომელიც შეიცავს `Tuist` დირექტორიას, რაც პროექტის ფესვს წარმოადგენს.

> [!TIP]
> Xcode-ის სამუშაო სივრცეები საშუალებას იძლეოდა პროექტების რამდენიმე Xcode-ის პროექტად დაყოფით შერწყმის კონფლიქტების ალბათობის შემცირება. თუ სამუშაო სივრცეებს სწორედ ამ მიზნით იყენებდით, Tuist-ში ისინი არ არის საჭირო. Tuist ავტომატურად გენერირებს სამუშაო სივრცეს, რომელიც შეიცავს პროექტს და მისი დამოკიდებულებების პროექტებს.


## Swift Package <Badge type="warning" text="beta" /> {#swift-package-badge-typewarning-textbeta-}

Tuist ასევე მხარს უჭერს SPM პაკეტის პროექტებს. თუ თქვენ მუშაობთ SPM პაკეტზე, არ უნდა დაგჭირდეთ რაიმეს განახლება. Tuist ავტომატურად აღიქვამს თქვენს ფესვის `Package.swift` და Tuist-ის ყველა ფუნქცია მუშაობს ისე, თითქოს ის `Project.swift` მანიფესტი იყოს.

დასაწყებად, გაუშვით `tuist install` და `tuist generate` თქვენს SPM პაკეტში. თქვენს პროექტს ახლა უნდა ჰქონდეს იგივე სქემები და ფაილები, რასაც ნახავდით სტანდარტულ Xcode SPM ინტეგრაციაში. თუმცა, ახლა ასევე შეგიძლიათ გაუშვათ <.localized_link href="/guides/features/cache">`tuist cache`</.localized_link> და მიიღოთ თქვენი SPM დამოკიდებულებებისა და მოდულების უმეტესობა წინასწარ კომპილირებული, რაც შემდგომ ბილდებს უკიდურესად სწრაფს ხდის.
