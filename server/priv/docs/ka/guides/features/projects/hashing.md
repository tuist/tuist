# ჰეშირება {#hashing}

<.localized_link href="/guides/features/cache">კეშირების</.localized_link> ან შერჩევითი ტესტების შესრულების მსგავს ფუნქციებს სჭირდებათ გზა იმის დასადგენად, შეიცვალა თუ არა სამიზნე. Tuist დამოკიდებულებათა გრაფში თითოეული სამიზნისთვის ითვლის ჰეშს, რათა დაადგინოს, შეიცვალა თუ არა ის. ჰეში გამოითვლება შემდეგი ატრიბუტების მიხედვით:

- სამიზნის ატრიბუტები (მაგ., სახელი, პლატფორმა, პროდუქტი და ა.შ.)
- სამიზნის ფაილები
- სამიზნის დამოკიდებულებების ჰეში

### კეშის ატრიბუტები {#cache-attributes}

დამატებით, <.localized_link href="/guides/features/cache">კეშირების</.localized_link> ჰეშის გამოთვლისას, ჩვენ ასევე ვაჰეშავთ შემდეგ ატრიბუტებს.

#### Swift-ის ვერსია {#swift-version}

ჩვენ ვაჰეშავთ Swift-ის ვერსიას, რომელიც მიღებულია `/usr/bin/xcrun swift --version` ბრძანების გაშვებით, რათა თავიდან ავიცილოთ კომპილაციის შეცდომები სამიზნეებსა და ბინარებს შორის Swift-ის ვერსიების შეუსაბამობის გამო.

> [!NOTE]
> **მოდულის სტაბილურობა**
>
> ბინარული კეშირების წინა ვერსიები ეყრდნობოდა `BUILD_LIBRARY_FOR_DISTRIBUTION` აგების პარამეტრს [მოდულის სტაბილურობის](https://www.swift.org/blog/library-evolution#enabling-library-evolution-support) ჩასართავად და ნებისმიერი კომპილატორის ვერსიით ბინარების გამოყენების შესაძლებლობის მისაცემად. თუმცა, ამან გამოიწვია კომპილაციის პრობლემები პროექტებში, რომლებიც შეიცავდნენ სამიზნეებს მოდულის სტაბილურობის მხარდაჭერის გარეშე. გენერირებული ბინარები მიბმულია მათი კომპილაციისთვის გამოყენებულ Swift-ის ვერსიაზე და Swift-ის ვერსია უნდა ემთხვეოდეს პროექტის კომპილაციისთვის გამოყენებულ ვერსიას.


#### კონფიგურაცია {#configuration}

კეშის ჰეშების გამოთვლისას, Tuist თითოეული პროექტისა და სამიზნის პარამეტრებს ანიჭებს გადაწყვეტილი აგების კონფიგურაციის ფარგლებს. ეს არის ის, რომელიც მითითებულია `--configuration`-ით, წინააღმდეგ შემთხვევაში — პროექტის `defaultConfiguration`, წინააღმდეგ შემთხვევაში — პირველი debug კონფიგურაცია. Tuist აჰეშავს ამ კონფიგურაციის სახელს, ვარიანტს, აგების პარამეტრებსა და კონფიგურაციის ფაილის შინაარსს მასზე მოქმედ საერთო საბაზისო პარამეტრებთან ერთად. სხვა კონფიგურაციის დამატება, წაშლა ან შეცვლა არ მოქმედებს გადაწყვეტილი კონფიგურაციის კეშის ჰეშებზე. რადგან მხოლოდ გადაწყვეტილი კონფიგურაციაა მნიშვნელოვანი, ცხადად მითითებული `--configuration`-ით შევსებული კეში წაკითხვადია ბრძანებისთვის, რომელიც იმავე კონფიგურაციას წყვეტს დროშის გადაცემის გარეშე.

## გამართვა {#debugging}

თუ შენიშნავთ არადეტერმინისტულ ქცევას კეშირების გამოყენებისას სხვადასხვა გარემოში ან გამოძახებისას, ეს შეიძლება იყოს დაკავშირებული გარემოებს შორის განსხვავებებთან ან ჰეშირების ლოგიკაში არსებულ ბაგთან. პრობლემის გამოსასწორებლად გირჩევთ მიჰყვეთ შემდეგ ნაბიჯებს:

1. გაუშვით `tuist hash cache` ან `tuist hash selective-testing` (<.localized_link href="/guides/features/cache">ბინარული კეშირების</.localized_link> ან <.localized_link href="/guides/features/selective-testing">შერჩევითი ტესტირების</.localized_link> ჰეშები), დააკოპირეთ ჰეშები, შეუცვალეთ სახელი პროექტის დირექტორიას და ხელახლა გაუშვით ბრძანება. ჰეშები უნდა ემთხვეოდეს.
2. თუ ჰეშები არ ემთხვევა, სავარაუდოდ, გენერირებული პროექტი დამოკიდებულია გარემოზე. ორივე შემთხვევაში გაუშვით `tuist graph --format json` და შეადარეთ გრაფები. ალტერნატიულად, შექმენით პროექტები და შეადარეთ მათი `project.pbxproj` ფაილები diff-ის ინსტრუმენტით, როგორიცაა [Diffchecker](https://www.diffchecker.com).
3. თუ ჰეშები იდენტურია, მაგრამ განსხვავდება გარემოების მიხედვით (მაგალითად, CI და ლოკალური), დარწმუნდით, რომ ყველგან გამოიყენება ერთი და იგივე [კონფიგურაცია](#configuration) და [Swift-ის ვერსია](#swift-version). Swift-ის ვერსია დაკავშირებულია Xcode-ის ვერსიასთან, ამიტომ დაადასტურეთ, რომ Xcode-ის ვერსიები ემთხვევა.

თუ ჰეშები კვლავ არადეტერმინისტულია, გვაცნობეთ და დაგეხმარებით გამართვაში.


> [!NOTE]
> **გამართვის გაუმჯობესებული გამოცდილება დაგეგმილია**
>
> გამართვის გამოცდილების გაუმჯობესება ჩვენს სამოქმედო გეგმაშია. print-hashes ბრძანება, რომელსაც აკლია კონტექსტი განსხვავებების გასაგებად, შეიცვლება უფრო მოსახერხებელი ბრძანებით, რომელიც ხისებრი სტრუქტურის გამოყენებით აჩვენებს ჰეშებს შორის განსხვავებებს.
