# დინამიური კონფიგურაცია {#dynamic-configuration}

არსებობს სცენარები, სადაც შეიძლება დაგჭირდეთ პროექტის დინამიურად კონფიგურირება გენერაციის დროს. მაგალითად, შეიძლება გსურდეთ შეცვალოთ აპლიკაციის სახელი, ბანდლის იდენტიფიკატორი ან განლაგების სამიზნე იმ გარემოს მიხედვით, სადაც პროექტი გენერირდება. Tuist მხარს უჭერს ამას გარემოს ცვლადების მეშვეობით, რომლებზეც წვდომა შესაძლებელია მანიფესტის ფაილებიდან.

## კონფიგურაცია გარემოს ცვლადების მეშვეობით {#configuration-through-environment-variables}

Tuist საშუალებას გაძლევთ გადასცეთ კონფიგურაცია გარემოს ცვლადების მეშვეობით, რომლებზეც წვდომა შესაძლებელია მანიფესტის ფაილებიდან. მაგალითად:

```bash
TUIST_APP_NAME=MyApp tuist generate
```

თუ გსურთ რამდენიმე გარემოს ცვლადის გადაცემა, უბრალოდ გამოყავით ისინი შუალედით. მაგალითად:

```bash
TUIST_APP_NAME=MyApp TUIST_APP_LOCALE=pl tuist generate
```

## გარემოს ცვლადების წაკითხვა მანიფესტებიდან {#reading-the-environment-variables-from-manifests}

ცვლადებზე წვდომა შესაძლებელია [`Environment`](https://projectdescription.tuist.dev/documentation/projectdescription/environment) ტიპის გამოყენებით. ნებისმიერი ცვლადი, რომელიც ემორჩილება `TUIST_XXX` შეთანხმებას და განსაზღვრულია გარემოში ან გადაეცემა Tuist-ს ბრძანებების შესრულებისას, ხელმისაწვდომი იქნება `Environment` ტიპის გამოყენებით. შემდეგი მაგალითი აჩვენებს, როგორ ვუკეთებთ წვდომას `TUIST_APP_NAME` ცვლადს:

```swift
func appName() -> String {
    if case let .string(environmentAppName) = Environment.appName {
        return environmentAppName
    } else {
        return "MyApp"
    }
}
```

ცვლადებზე წვდომა აბრუნებს `Environment.Value?` ტიპის ინსტანციას, რომელსაც შეიძლება ჰქონდეს შემდეგი მნიშვნელობები:

| შემთხვევა | აღწერა |
| --- | --- |
| `.string(String)` | გამოიყენება, როცა ცვლადი წარმოადგენს სტრიქონს. |

ასევე შეგიძლიათ მიიღოთ სტრიქონული ან ბულის ტიპის `Environment` ცვლადი ქვემოთ განსაზღვრული დამხმარე მეთოდების გამოყენებით. ეს მეთოდები მოითხოვს ნაგულისხმები მნიშვნელობის გადაცემას, რათა მომხმარებელმა ყოველ ჯერზე თანმიმდევრული შედეგები მიიღოს. ეს თავიდან აგაცილებთ ზემოთ განსაზღვრული appName() ფუნქციის განსაზღვრის საჭიროებას.

::: code-group

```swift [String]
Environment.appName.getString(default: "TuistServer")
```

```swift [Boolean]
Environment.isCI.getBoolean(default: false)
```

## დამატებითი გარემოს ცვლადების გადაცემა მანიფესტებზე {#forwarding-additional-environment-variables-to-manifests}

ნაგულისხმევად, მხოლოდ `TUIST_` პრეფიქსით დაწყებული ცვლადები, ასევე `CI` და `DEVELOPER_DIR`, გადაეცემა ქვეპროცესს, რომელიც აფასებს `Project.swift`, `Workspace.swift`, `Package.swift` და პროექტის აღწერის დამხმარეებს. ეს უზრუნველყოფს გენერაციის დეტერმინისტულობას და ხელს უშლის არარელევანტური shell ან CI ცვლადების მიერ მანიფესტის ქეშის გაუქმებას.

როდესაც მანიფესტს სჭირდება ისეთი ცვლადების წაკითხვა, რომლებიც თქვენს კონტროლს არ ექვემდებარება (მაგალითად, მესამე მხარის `Package.swift`, რომელიც უკვე კითხულობს `OPENSWIFTUI_LIBRARY_TYPE`-ს), განაცხადეთ ისინი `Tuist.swift`-ში `manifestEnvironment`-ის მეშვეობით გენერაციის პარამეტრებში. თითოეული ჩანაწერი არის ან ლიტერალური სახელი, ან სახელი, რომელიც მთავრდება `*`-ით პრეფიქსის შესატყვისობისთვის:

```swift
import ProjectDescription

let tuist = Tuist(
    project: .tuist(
        generationOptions: .options(
            manifestEnvironment: [
                "OPENSWIFTUI_*",
                "MY_VAR",
            ]
        )
    )
)
```

ჩამოთვლილი ცვლადები მონაწილეობენ მანიფესტის ქეშის ჰეშში, ამიტომ მათი მნიშვნელობების ცვლილება მოსალოდნელად გააუქმებს ქეშს. ჩამოუთვლელი ცვლადები რჩება დამალული მანიფესტის შეფასებისთვის.
