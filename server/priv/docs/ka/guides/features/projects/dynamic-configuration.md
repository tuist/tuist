# დინამიური კონფიგურაცია {#dynamic-configuration}

არსებობს სცენარები, სადაც შეიძლება დაგჭირდეთ პროექტის დინამიურად კონფიგურირება გენერაციის დროს. მაგალითად, შეიძლება გსურთ შეცვალოთ აპლიკაციის სახელი, ბანდლის იდენტიფიკატორი ან განლაგების სამიზნე იმ გარემოს მიხედვით, სადაც პროექტი გენერირდება. Tuist მხარს უჭერს ამას გარემოს ცვლადების მეშვეობით, რომლებზეც წვდომა შესაძლებელია მანიფესტის ფაილებიდან.

## კონფიგურაცია გარემოს ცვლადების მეშვეობით {#configuration-through-environment-variables}

Tuist საშუალებას გაძლევთ გადასცეთ კონფიგურაცია გარემოს ცვლადების მეშვეობით, რომლებზეც წვდომა შესაძლებელია მანიფესტის ფაილებიდან. მაგალითად:

```bash
TUIST_APP_NAME=MyApp tuist generate
```

თუ გსურთ რამდენიმე გარემოს ცვლადის გადაცემა, უბრალოდ გამოყავით ისინი შუალედით. მაგალითად:

```bash
TUIST_APP_NAME=MyApp TUIST_APP_LOCALE=pl tuist generate
```

## გარემოს ცვლადების წაკითხვა მანიფესტებიდან {#reading-the-environment-variables-from-manifests}

ცვლადებზე წვდომა შესაძლებელია ტიპის [`Environment`](https://projectdescription.tuist.dev/documentation/projectdescription/environment) გამოყენებით. ნებისმიერი ცვლადი, რომელიც ემორჩილება შეთანხმებას `TUIST_XXX` და განსაზღვრულია გარემოში ან გადაეცემა Tuist-ს ბრძანებების შესრულებისას, ხელმისაწვდომი იქნება ტიპის `Environment` მეშვეობით. აქსესორები იყენებენ ცვლადის camelCase სახელს `TUIST_` პრეფიქსის გარეშე, ამიტომ `TUIST_APP_NAME` იკითხება როგორც `Environment.appName`, ხოლო `TUIST_ENABLE_ANALYTICS` როგორც `Environment.enableAnalytics`. იმის შესამოწმებლად, ფასდება თუ არა მანიფესტი CI-ზე, გამოიყენეთ ბულევის ტიპის `Environment.isCI`. შემდეგი მაგალითი კითხულობს `TUIST_APP_NAME`-ს:

```swift
func appName() -> String {
    if case let .string(environmentAppName) = Environment.appName {
        return environmentAppName
    } else {
        return "MyApp"
    }
}
```

ცვლადებზე წვდომა აბრუნებს ტიპის `Environment.Value?` ეგზემპლარს, რომელსაც შეიძლება ჰქონდეს შემდეგი მნიშვნელობები:

| შემთხვევა | აღწერა |
| --- | --- |
| `.string(String)` | გამოიყენება, როდესაც ცვლადი წარმოადგენს სტრიქონს. |

ასევე შეგიძლიათ მიიღოთ სტრიქონის ან ბულევის ტიპის `Environment` ცვლადი ქვემოთ განსაზღვრული დამხმარე მეთოდებიდან ერთ-ერთის გამოყენებით; ეს მეთოდები მოითხოვენ ნაგულისხმევი მნიშვნელობის გადაცემას, რათა მომხმარებელმა ყოველ ჯერზე მიიღოს თანმიმდევრული შედეგები. ეს თავიდან აგაცილებთ ზემოთ განსაზღვრული ფუნქციის appName() განსაზღვრის საჭიროებას.

::: code-group

```swift [String]
Environment.appName.getString(default: "MyApp")
```

```swift [Boolean]
Environment.enableAnalytics.getBoolean(default: false)
```

:::

## დამატებითი გარემოს ცვლადების გადაცემა მანიფესტებზე {#forwarding-additional-environment-variables-to-manifests}

ნაგულისხმევად, მხოლოდ `TUIST_` პრეფიქსის მქონე ცვლადები, ასევე `CI` და `DEVELOPER_DIR`, გადაეცემა ქვეპროცესს, რომელიც აფასებს `Project.swift`-ს, `Workspace.swift`-ს, `Package.swift`-ს და პროექტის აღწერის დამხმარეებს. ეს უზრუნველყოფს გენერაციის დეტერმინისტულობას და ხელს უშლის შეუსაბამო shell ან CI ცვლადების მიერ მანიფესტის ქეშის გაუქმებას.

როდესაც მანიფესტს სჭირდება ისეთი ცვლადების წაკითხვა, რომლებიც თქვენს კონტროლს არ ექვემდებარება (მაგალითად, მესამე მხარის `Package.swift`, რომელიც უკვე კითხულობს `OPENSWIFTUI_LIBRARY_TYPE`-ს), განაცხადეთ ისინი `Tuist.swift`-ში `manifestEnvironment`-ის მეშვეობით გენერაციის პარამეტრებში. თითოეული ჩანაწერი არის ან ლიტერალური სახელი, ან სახელი, რომელიც მთავრდება `*`-ით პრეფიქსით შესატყვისობისთვის:

```swift
import ProjectDescription

let tuist = Tuist(
    project: .tuist(
        generationOptions: .options(
            manifestEnvironment: [
                "OPENSWIFTUI_*",
                "MY_VAR",
            ]
        )
    )
)
```

ჩამოთვლილი ცვლადები მონაწილეობენ მანიფესტის ქეშის ჰეშში, ამიტომ მათი მნიშვნელობების ცვლილება, მოსალოდნელისამებრ, აუქმებს ქეშს. ჩამოუთვლელი ცვლადები რჩება ფარული მანიფესტის შეფასებისთვის.
