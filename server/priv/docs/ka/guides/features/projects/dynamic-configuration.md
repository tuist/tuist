# დინამიური კონფიგურაცია {#dynamic-configuration}

არსებობს სცენარები, როდესაც პროექტის გენერაციის დროს მისი დინამიურად კონფიგურირება შეიძლება დაგჭირდეთ. მაგალითად, შესაძლოა, გსურდეთ აპლიკაციის სახელის, ბანდლის იდენტიფიკატორის ან განთავსების მიზნის (deployment target) შეცვლა იმ გარემოს მიხედვით, სადაც პროექტი გენერირდება. Tuist ამას გარემოს ცვლადების მეშვეობით უზრუნველყოფს, რომლებზეც წვდომა მანიფესტის ფაილებიდან არის შესაძლებელი.

## კონფიგურაცია გარემოს ცვლადების მეშვეობით {#configuration-through-environment-variables}

Tuist საშუალებას გაძლევთ, კონფიგურაცია გადასცეთ გარემოს ცვლადების მეშვეობით, რომლებზეც წვდომა მანიფესტის ფაილებიდან არის შესაძლებელი. მაგალითად:

```bash
TUIST_APP_NAME=MyApp tuist generate
```

თუ რამდენიმე გარემოს ცვლადის გადაცემა გსურთ, უბრალოდ გამოყავით ისინი შუალედით. მაგალითად:

```bash
TUIST_APP_NAME=MyApp TUIST_APP_LOCALE=pl tuist generate
```

## გარემოს ცვლადების წაკითხვა მანიფესტებიდან {#reading-the-environment-variables-from-manifests}

ცვლადებზე წვდომა შესაძლებელია ტიპის [`Environment`](https://projectdescription.tuist.dev/documentation/projectdescription/environment) გამოყენებით. ნებისმიერი ცვლადი, რომელიც ემორჩილება `TUIST_XXX` შეთანხმებას და განსაზღვრულია გარემოში ან გადაეცემა Tuist-ს ბრძანებების შესრულებისას, ხელმისაწვდომი იქნება ტიპის `Environment` მეშვეობით. აქსესორები იყენებენ ცვლადის camelCase სახელს `TUIST_` პრეფიქსის გარეშე, ამიტომ `TUIST_APP_NAME` იკითხება როგორც `Environment.appName`, ხოლო `TUIST_ENABLE_ANALYTICS` — როგორც `Environment.enableAnalytics`. იმის შესამოწმებლად, ხდება თუ არა მანიფესტის შეფასება CI-ზე, გამოიყენეთ ბულეანი `Environment.isCI`. შემდეგი მაგალითი კითხულობს `TUIST_APP_NAME`-ს:

```swift
func appName() -> String {
    if case let .string(environmentAppName) = Environment.appName {
        return environmentAppName
    } else {
        return "MyApp"
    }
}
```

ცვლადებზე წვდომა აბრუნებს ტიპის `Environment.Value?` ეგზემპლარს, რომელსაც შეიძლება ჰქონდეს შემდეგი მნიშვნელობები:

| შემთხვევა | აღწერა |
| --- | --- |
| `.string(String)` | გამოიყენება, როდესაც ცვლადი წარმოადგენს სტრიנגს. |

ასევე შეგიძლიათ მიიღოთ სტრიngის ან ბულეანის ტიპის `Environment` ცვლადი ქვემოთ განსაზღვრული დამხმარე მეთოდების გამოყენებით; ეს მეთოდები მოითხოვენ ნაგულისხმევი მნიშვნელობის გადაცემას, რათა მომხმარებელმა ყოველ ჯერზე თანმიმდევრული შედეგები მიიღოს. ეს თავიდან აგაცილებთ ზემოთ განსაზღვრული appName() ფუნქციის განსაზღვრის საჭიროებას.

::: code-group

```swift [String]
Environment.appName.getString(default: "MyApp")
```

```swift [Boolean]
Environment.enableAnalytics.getBoolean(default: false)
```

:::

## დამატებითი გარემოს ცვლადების გადაცემა მანიფესტებში {#forwarding-additional-environment-variables-to-manifests}

ნაგულისხმევად, მხოლოდ `TUIST_` პრეფიქსის მქონე ცვლადები, ასევე `CI` და `DEVELOPER_DIR`, გადაეცემა ქვეპროცესს, რომელიც აფასებს `Project.swift`-ს, `Workspace.swift`-ს, `Package.swift`-ს და პროექტის აღწერის დამხმარეებს. ეს ინარჩუნებს გენერაციის დეტერმინისტულობას და ხელს უშლის არარელევანტური shell-ის ან CI ცვლადების მიერ მანიფესტის ქეშის გაუქმებას.

როდესაც მანიფესტს სჭირდება ისეთი ცვლადების წაკითხვა, რომლებიც თქვენს კონტროლს არ ექვემდებარება (მაგალითად, მესამე მხარის `Package.swift`, რომელიც უკვე კითხულობს `OPENSWIFTUI_LIBRARY_TYPE`-ს), განაცხადეთ ისინი `Tuist.swift`-ში `manifestEnvironment`-ის მეშვეობით გენერაციის პარამეტრებში. თითოეული ჩანაწერი არის ან ლიტერალური სახელი, ან სახელი, რომელიც ბოლოვდება `*`-ით პრეფიქსის შესაბამისობისთვის:

```swift
import ProjectDescription

let tuist = Tuist(
    project: .tuist(
        generationOptions: .options(
            manifestEnvironment: [
                "OPENSWIFTUI_*",
                "MY_VAR",
            ]
        )
    )
)
```

ჩამოთვლილი ცვლადები მონაწილეობენ მანიფესტის ქეშის ჰეშში, ამიტომ მათი მნიშვნელობების ცვლილება მოსალოდნელად აუქმებს ქეშს. ჩამოუთვლელი ცვლადები რჩება დამალული მანიფესტის შეფასებისთვის.
