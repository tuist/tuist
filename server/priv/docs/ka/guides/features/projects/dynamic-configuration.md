# დინამიური კონფიგურაცია {#dynamic-configuration}

არსებობს სცენარები, როდესაც შეიძლება დაგჭირდეთ პროექტის დინამიურად კონფიგურირება გენერაციის დროს. მაგალითად, შესაძლოა გსურთ შეცვალოთ აპლიკაციის სახელი, ბანდლის იდენტიფიკატორი ან განლაგების მიზანი იმ გარემოდან გამომდინარე, რომელშიც პროექტი გენერირდება. Tuist მხარდაჭერას უწევს ამას გარემოს ცვლადების მეშვეობით, რომლებიც ხელმისაწვდომია მანიფესტის ფაილებიდან.

## კონფიგურაცია გარემოს ცვლადების მეშვეობით {#configuration-through-environment-variables}

Tuist საშუალებას გაძლევთ გადასცეთ კონფიგურაცია გარემოს ცვლადების მეშვეობით, რომლებიც ხელმისაწვდომია მანიფესტის ფაილებიდან. მაგალითად:

```bash
TUIST_APP_NAME=MyApp tuist generate
```

თუ გსურთ რამდენიმე გარემოს ცვლადის გადაცემა, უბრალოდ გამოყავით ისინი შუალედით. მაგალითად:

```bash
TUIST_APP_NAME=MyApp TUIST_APP_LOCALE=pl tuist generate
```

## გარემოს ცვლადების წაკითხვა მანიფესტებიდან {#reading-the-environment-variables-from-manifests}

ცვლადებზე წვდომა შესაძლებელია ტიპის [`Environment`](https://projectdescription.tuist.dev/documentation/projectdescription/environment) გამოყენებით. ნებისმიერი ცვლადი, რომელიც ემორჩილება `TUIST_XXX` შეთანხმებას და განსაზღვრულია გარემოში ან გადაეცემა Tuist-ს ბრძანებების შესრულებისას, ხელმისაწვდომი იქნება `Environment` ტიპის მეშვეობით. შემდეგი მაგალითი გვიჩვენებს, თუ როგორ ვუდგებით `TUIST_APP_NAME` ცვლადს:

```swift
func appName() -> String {
    if case let .string(environmentAppName) = Environment.appName {
        return environmentAppName
    } else {
        return "MyApp"
    }
}
```

ცვლადებზე წვდომა აბრუნებს `Environment.Value?` ტიპის ინსტანციას, რომელსაც შეიძლება ჰქონდეს შემდეგი მნიშვნელობებიდან ერთ-ერთი:

| შემთხვევა | აღწერა |
| --- | --- |
| `.string(String)` | გამოიყენება, როდესაც ცვლადი წარმოადგენს სტრიქონს. |

ასევე შეგიძლიათ მიიღოთ სტრიქონული ან ბულიანი `Environment` ცვლადი ქვემოთ განსაზღვრული დამხმარე მეთოდებიდან ერთ-ერთის გამოყენებით; ეს მეთოდები მოითხოვს ნაგულისხმევი მნიშვნელობის გადაცემას, რათა მომხმარებელმა ყოველ ჯერზე მიიღოს თანმიმდევრული შედეგები. ეს თავიდან აგვაცილებს ზემოთ განსაზღვრული appName() ფუნქციის განსაზღვრის აუცილებლობას.

::: code-group

```swift [String]
Environment.appName.getString(default: "TuistServer")
```

```swift [Boolean]
Environment.isCI.getBoolean(default: false)
```

## დამატებითი გარემოს ცვლადების გადაცემა მანიფესტებისთვის {#forwarding-additional-environment-variables-to-manifests}

ნაგულისხმევად, მხოლოდ `TUIST_` პრეფიქსის მქონე ცვლადები, ასევე `CI` და `DEVELOPER_DIR`, გადაეცემა ქვეპროცესს, რომელიც აფასებს `Project.swift`-ს, `Workspace.swift`-ს, `Package.swift`-ს და პროექტის აღწერის დამხმარეებს. ეს უზრუნველყოფს გენერაციის დეტერმინირებულობას და ხელს უშლის არარელევანტური shell ან CI ცვლადების მიერ მანიფესტის ქეშის გაუქმებას.

როდესაც მანიფესტს სჭირდება თქვენს კონტროლს მიღმა მყოფი ცვლადების წაკითხვა (მაგალითად, მესამე მხარის `Package.swift`, რომელიც უკვე კითხულობს `OPENSWIFTUI_LIBRARY_TYPE`-ს), განაცხადეთ ისინი `Tuist.swift`-ში `manifestEnvironment`-ის მეშვეობით გენერაციის პარამეტრებში. თითოეული ჩანაწერი არის ან ლიტერალური სახელი, ან სახელი, რომელიც ბოლოვდება `*`-ით პრეფიქსის შესატყვისობისთვის:

```swift
import ProjectDescription

let tuist = Tuist(
    project: .tuist(
        generationOptions: .options(
            manifestEnvironment: [
                "OPENSWIFTUI_*",
                "MY_VAR",
            ]
        )
    )
)
```

ჩამოთვლილი ცვლადები მონაწილეობენ მანიფესტის ქეშის ჰეშში, ამიტომ მათი მნიშვნელობების ცვლილება, მოსალოდნელისამებრ, გააუქმებს ქეშს. ჩამოუთვლელი ცვლადები რჩება დამალული მანიფესტის შეფასებისთვის.
