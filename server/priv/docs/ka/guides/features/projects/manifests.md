# მანიფესტები {#manifests}

Tuist პროექტებისა და სამუშაო სივრცეების განსაზღვრისა და გენერაციის პროცესის კონფიგურაციის ძირითად საშუალებად Swift-ფაილებს იყენებს. დოკუმენტაციაში ამ ფაილებს **მანიფესტის ფაილები** ეწოდება.

Swift-ის გამოყენების გადაწყვეტილება შთაგონებული იყო [Swift Package Manager](https://www.swift.org/documentation/package-manager/)-ით, რომელიც ასევე იყენებს Swift-ფაილებს პაკეტების განსაზღვრისთვის. Swift-ის გამოყენების წყალობით შეგვიძლია გამოვიყენოთ კომპილატორი შინაარსის სისწორის ვალიდაციისა და კოდის ხელახლა გამოყენებისთვის სხვადასხვა მანიფესტის ფაილში, ხოლო Xcode უზრუნველყოფს რედაქტირების მაღალი ხარისხის გამოცდილებას სინტაქსის გამოკვეთის, ავტომატური შევსებისა და ვალიდაციის მეშვეობით.

> [!NOTE]
> **ქეშირება**
>
> რადგან მანიფესტის ფაილები არის Swift-ფაილები, რომლებიც კომპილაციას საჭიროებენ, Tuist ინახავს კომპილაციის შედეგებს ქეშში პარსინგის პროცესის დასაჩქარებლად. შესაბამისად, შეამჩნევთ, რომ Tuist-ის პირველი გაშვებისას პროექტის გენერაციას ოდნავ მეტი დრო შეიძლება დასჭირდეს. მომდევნო გაშვებები უფრო სწრაფი იქნება.


## Project.swift {#projectswift}

[`Project.swift`](https://projectdescription.tuist.dev/documentation/projectdescription/project) მანიფესტი აცხადებს Xcode-პროექტს. პროექტი გენერირდება იმავე დირექტორიაში, სადაც მანიფესტის ფაილი მდებარეობს, `name` თვისებაში მითითებული სახელით.

```swift
// Project.swift
let project = Project(
    name: "App",
    targets: [
        // ....
    ]
)
```


> [!WARNING]
> **ფესტივალური ცვლადები**
>
> მანიფესტის ძირში ერთადერთი ცვლადი, რომელიც უნდა იყოს, არის `let project = Project(...)`. თუ გჭირდებათ კოდის ხელახლა გამოყენება მანიფესტის სხვადასხვა ნაწილში, შეგიძლიათ გამოიყენოთ Swift-ფუნქციები.


## Workspace.swift {#workspaceswift}

ნაგულისხმევად, Tuist ქმნის [Xcode Workspace](https://developer.apple.com/documentation/xcode/projects-and-workspaces)-ს, რომელიც შეიცავს გენერირებად პროექტს და მისი დამოკიდებულებების პროექტებს. თუ რაიმე მიზეზის გამო გსურთ სამუშაო სივრცის მორგება დამატებითი პროექტების დასამატებლად ან ფაილებისა და ჯგუფების ჩასართავად, ეს შეგიძლიათ გააკეთოთ [`Workspace.swift`](https://projectdescription.tuist.dev/documentation/projectdescription/workspace) მანიფესტის განსაზღვრით.

```swift
// Workspace.swift
import ProjectDescription

let workspace = Workspace(
    name: "App-Workspace",
    projects: [
        "./App", // Path to directory containing the Project.swift file
    ]
)
```

> [!NOTE]
> Tuist გადაჭრის დამოკიდებულებების გრაფს და ჩართავს დამოკიდებულებების პროექტებს სამუშაო სივრცეში. მათი ხელით ჩართვა არ არის საჭირო. ეს აუცილებელია ბილდის სისტემისთვის დამოკიდებულებების სწორად გადასაჭრელად.


### მულტი ან მონო-პროექტი {#multi-or-monoproject}

ხშირად ისმის კითხვა, უნდა გამოვიყენოთ თუ არა ერთი პროექტი ან რამდენიმე პროექტი სამუშაო სივრცეში. Tuist-ის გარეშე სამყაროში, სადაც მონო-პროექტის კონფიგურაცია ხშირ Git-კონფლიქტებს გამოიწვევდა, სამუშაო სივრცეების გამოყენება რეკომენდებულია. თუმცა, რადგან ჩვენ არ ვუკეთებთ რეკომენდაციას Tuist-ით გენერირებული Xcode-პროექტების Git-რეპოზიტორიაში ჩართვის შესახებ, Git-კონფლიქტები პრობლემა არ არის. შესაბამისად, გადაწყვეტილება ერთი პროექტის ან რამდენიმე პროექტის გამოყენების შესახებ სამუშაო სივრცეში თქვენზეა.

Tuist-ის პროექტში ჩვენ ვეყრდნობით მონო-პროექტებს, რადგან ცივი გენერაციის დრო უფრო სწრაფია (ნაკლები მანიფესტის ფაილია კომპილირებადი) და ჩვენ ვიყენებთ <.localized_link href="/guides/features/projects/code-sharing">პროექტის აღწერის დამხმარე საშუალებებს</.localized_link> როგორც ინკაფსულაციის ერთეულს. თუმცა, შეიძლება გსურდეთ Xcode-პროექტების გამოყენება ინკაფსულაციის ერთეულად თქვენი აპლიკაციის სხვადასხვა დომენის წარმოსადგენად, რაც უფრო ახლოსაა Xcode-ის მიერ რეკომენდებულ პროექტის სტრუქტურასთან.

## Tuist.swift {#tuistswift}

Tuist უზრუნველყოფს <.localized_link href="/contributors/principles#default-to-conventions">გონივრულ ნაგულისხმევ მნიშვნელობებს</.localized_link> პროექტის კონფიგურაციის გასამარტივებლად. თუმცა, შეგიძლიათ მორგოთ კონფიგურაცია პროექტის ძირში [`Tuist.swift`](https://projectdescription.tuist.dev/documentation/projectdescription/tuist)-ის განსაზღვრით, რომელსაც Tuist იყენებს პროექტის ძირის დასადგენად.

```swift
import ProjectDescription

let tuist = Tuist(
    project: .tuist(generationOptions: .options(enforceExplicitDependencies: true))
)
```
