# რედაქტირება {#editing}

განსხვავებით ტრადიციული Xcode პროექტებისა ან Swift პაკეტებისგან, სადაც ცვლილებები ხდება Xcode-ის ინტერფეისის მეშვეობით, Tuist-ით მართული პროექტები განისაზღვრება Swift კოდით, რომელიც შეიცავს **მანიფესტ ფაილებში**. თუ გაქვთ გამოცდილება Swift პაკეტებთან და `Package.swift` ფაილთან, მიდგომა ძალიან მსგავსია.

შეგიძლიათ შეასწოროთ ეს ფაილები ნებისმიერი ტექსტური რედაქტორის გამოყენებით, მაგრამ ჩვენ გირჩევთ გამოიყენოთ Tuist-ის მიერ შემოთავაზებული სამუშაო პროცესი ამისთვის, `tuist edit`. ეს პროცესი ქმნის Xcode პროექტს, რომელიც შეიცავს ყველა მანიფესტ ფაილს და გაძლევთ საშუალებას შეასწოროთ და დააკომპილიროთ ისინი. Xcode-ის გამოყენების წყალობით, იღებთ ყველა უპირატესობას: **კოდის ავტოშევსება, სინტაქსის გამოყოფა და შეცდომების შემოწმება**.

## პროექტის რედაქტირება {#edit-the-project}

პროექტის რედაქტირებისთვის, შეგიძლიათ გაუშვათ შემდეგი ბრძანება Tuist პროექტის დირექტორიაში ან ქვედირექტორიაში:

```bash
tuist edit
```

ბრძანება ქმნის Xcode პროექტს გლობალურ დირექტორიაში და ხსნის მას Xcode-ში. პროექტი შეიცავს `Manifests` დირექტორიას, რომლის აგებაც შეგიძლიათ, რათა დარწმუნდეთ, რომ ყველა თქვენი მანიფესტი ვალიდურია.

> [!NOTE]
> **Glob-ით ამოცნობილი მანიფესტები**
>
> `tuist edit` ადგენს შესაყვან მანიფესტებს glob შაბლონის `**/{Manifest}.swift` გამოყენებით პროექტის ფესვიდან (დირექტორია, რომელიც შეიცავს `Tuist.swift` ფაილს). დარწმუნდით, რომ პროექტის ფესვში არსებობს ვალიდური `Tuist.swift`.


### მანიფესტ ფაილების იგნორირება {#ignoring-manifest-files}

თუ თქვენი პროექტი შეიცავს Swift ფაილებს იგივე სახელით, როგორც მანიფესტ ფაილებს (მაგ., `Project.swift`) ქვედირექტორიებში, რომლებიც არ არის რეალური Tuist მანიფესტები, შეგიძლიათ შექმნათ `.tuistignore` ფაილი პროექტის ფესვში, რათა გამორიცხოთ ისინი რედაქტირების პროექტიდან.

`.tuistignore` ფაილი იყენებს glob შაბლონებს, რათა მიუთითოს, რომელი ფაილები უნდა იქნას იგნორირებული:

```gitignore
# Ignore all Project.swift files in the Sources directory
Sources/**/Project.swift

# Ignore specific subdirectories
Tests/Fixtures/**/Workspace.swift
```

ეს განსაკუთრებით სასარგებლოა, როცა გაქვთ ტესტების ფიქსტურები ან მაგალითის კოდი, რომელიც შემთხვევით იყენებს იგივე სახელდების კონვენციას, როგორც Tuist მანიფესტ ფაილები.

## რედაქტირებისა და გენერაციის სამუშაო პროცესი {#edit-and-generate-workflow}

როგორც შეამჩნიეთ, რედაქტირება ვერ ხდება გენერირებული Xcode პროექტიდან. ეს განზრახვითაა გაკეთებული, რათა გენერირებულ პროექტს არ ჰქონდეს დამოკიდებულება Tuist-ზე, რაც უზრუნველყოფს, რომ მომავალში Tuist-დან გადასვლა მცირე ძალისხმევით შეძლოთ.

პროექტზე მუშაობისას, გირჩევთ გაუშვათ `tuist edit` ტერმინალის სესიიდან, რათა მიიღოთ Xcode პროექტი პროექტის რედაქტირებისთვის, და გამოიყენოთ სხვა ტერმინალის სესია `tuist generate`-ის გასაშვებად.
