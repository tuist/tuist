# რედაქტირება {#editing}

ტრადიციული Xcode პროექტებისგან ან Swift პაკეტებისგან განსხვავებით, სადაც ცვლილებები ხდება Xcode-ის ინტერფეისის მეშვეობით, Tuist-ით მართული პროექტები განისაზღვრება Swift კოდით, რომელიც შეიცავს **მანიფესტ ფაილებში**. თუ გაქვთ გამოცდილება Swift პაკეტებთან და `Package.swift` ფაილთან, მიდგომა ძალიან მსგავსია.

შეგიძლიათ ამ ფაილების რედაქტირება ნებისმიერი ტექსტური რედაქტორით, მაგრამ ჩვენ გირჩევთ გამოიყენოთ Tuist-ის მიერ შემოთავაზებული სამუშაო პროცესი — `tuist edit`. ეს პროცესი ქმნის Xcode პროექტს, რომელიც შეიცავს ყველა მანიფესტ ფაილს და გაძლევთ საშუალებას შეცვალოთ და აკომპილიროთ ისინი. Xcode-ის გამოყენების წყალობით, იღებთ **კოდის ავტოშევსების, სინტაქსის გამოყოფის და შეცდომების შემოწმების** ყველა უპირატესობას.

## პროექტის რედაქტირება {#edit-the-project}

პროექტის რედაქტირებისთვის, შეგიძლიათ გაუშვათ შემდეგი ბრძანება Tuist პროექტის დირექტორიაში ან მის ქვედირექტორიაში:

```bash
tuist edit
```

ბრძანება ქმნის Xcode პროექტს გლობალურ დირექტორიაში და ხსნის მას Xcode-ში. პროექტი შეიცავს `Manifests` დირექტორიას, რომლის აგებაც შეგიძლიათ, რათა დარწმუნდეთ, რომ ყველა თქვენი მანიფესტი ვალიდურია.

> [!NOTE]
> **Glob-ით განსაზღვრული მანიფესტები**
>
> `tuist edit` განსაზღვრავს შესატან მანიფესტებს პროექტის ფესვის დირექტორიიდან (`**/{Manifest}.swift`) glob-ის გამოყენებით (ეს არის დირექტორია, რომელიც შეიცავს `Tuist.swift` ფაილს). დარწმუნდით, რომ პროექტის ფესვში არსებობს ვალიდური `Tuist.swift`.


### მანიფესტ ფაილების იგნორირება {#ignoring-manifest-files}

თუ თქვენი პროექტი შეიცავს Swift ფაილებს იგივე სახელით, როგორც მანიფესტ ფაილებს (მაგ., `Project.swift`), ქვედირექტორიებში, რომლებიც არ არის რეალური Tuist მანიფესტები, შეგიძლიათ შექმნათ `.tuistignore` ფაილი თქვენი პროექტის ფესვში, რათა გამორიცხოთ ისინი რედაქტირების პროექტიდან.

`.tuistignore` ფაილი იყენებს glob შაბლონებს, რათა მიუთითოს, რომელი ფაილები უნდა იყოს იგნორირებული:

```gitignore
# Ignore all Project.swift files in the Sources directory
Sources/**/Project.swift

# Ignore specific subdirectories
Tests/Fixtures/**/Workspace.swift
```

ეს განსაკუთრებით სასარგებლოა, როდესაც გაქვთ ტესტის ფიქსტურები ან მაგალითის კოდი, რომელიც შემთხვევით იყენებს იგივე სახელდების კონვენციას, რასაც Tuist მანიფესტ ფაილები.

## რედაქტირებისა და გენერაციის სამუშაო პროცესი {#edit-and-generate-workflow}

როგორც შეამჩნიეთ, რედაქტირება ვერ ხდება გენერირებული Xcode პროექტიდან. ეს განზრახვით არის გაკეთებული, რათა თავიდან იქნას აცილებული გენერირებულ პროექტში Tuist-ზე დამოკიდებულება, რაც უზრუნველყოფს, რომ მომავალში Tuist-დან გადასვლა მინიმალური ძალისხმევით შეძლოთ.

პროექტზე იტერაციისას, ჩვენ გირჩევთ გაუშვათ `tuist edit` ტერმინალის სესიაში, რათა მიიღოთ Xcode პროექტი პროექტის რედაქტირებისთვის, და გამოიყენოთ სხვა ტერმინალის სესია `tuist generate`-ის გასაშვებად.
