# არაცხადი იმპორტი {#implicit-imports}

Xcode-ის პროექტების გრაფის მართვის სირთულის შესამსუბუქებლად, Apple-მა შექმნა აგების სისტემა ისე, რომ დამოკიდებულებები არაცხადად განისაზღვრება. ეს ნიშნავს, რომ პროდუქტს, მაგალითად აპლიკაციას, შეუძლია დაეყრდნოს ფრეიმვორკს, თუნდაც დამოკიდებულება ცხადად არ იყოს გამოცხადებული. მცირე მასშტაბით ეს პრობლემა არ არის, მაგრამ როცა პროექტის გრაფი რთულდება, არაცხადობამ შეიძლება გამოიწვიოს არასანდო ინკრემენტული ბილდები ან რედაქტორზე დაფუძნებული ფუნქციების, როგორიცაა პრივიუები ან კოდის ავტოშევსება, არასწორი მუშაობა.

პრობლემა ისაა, რომ არაცხადი დამოკიდებულებების წარმოქმნის თავიდან აცილება შეუძლებელია. ნებისმიერ დეველოპერს შეუძლია დაამატოს `import` ოპერატორი თავის Swift კოდში და არაცხადი დამოკიდებულება შეიქმნება. სწორედ აქ შემოდის Tuist. Tuist გთავაზობთ ბრძანებას, რომელიც სტატიკურად აანალიზებს თქვენი პროექტის კოდს და ამოწმებს არაცხად დამოკიდებულებებს. ქვემოთ მოცემული ბრძანება გამოიტანს თქვენი პროექტის არაცხად დამოკიდებულებებს:

```bash
tuist inspect dependencies --only implicit
```

თუ ბრძანება აღმოაჩენს რაიმე არაცხად იმპორტს, ის დასრულდება ნულისგან განსხვავებული გასვლის კოდით.

> [!TIP]
> **ვალიდაცია CI-ში**
>
> ჩვენ მკაცრად გირჩევთ, ეს ბრძანება შეიტანოთ თქვენს <.localized_link href="/guides/integrations/continuous-integration">უწყვეტი ინტეგრაციის</.localized_link> პროცესში ყოველ ჯერზე, როცა ახალი კოდი იგზავნება რეპოზიტორიაში.


> [!WARNING]
> **ყველა არაცხადი შემთხვევა არ აღმოჩნდება**
>
> ვინაიდან Tuist ეყრდნობა სტატიკურ კოდის ანალიზს არაცხადი დამოკიდებულებების აღმოსაჩენად, მან შეიძლება ვერ დაიჭიროს ყველა შემთხვევა. მაგალითად, Tuist ვერ ხვდება პირობით იმპორტებს, რომლებიც კოდში კომპილატორის დირექტივებით არის განსაზღვრული.
