# არაცხადი იმპორტები {#implicit-imports}

Xcode-ის პროექტების გრაფის მართვის სირთულის შესამსუბუქებლად, Apple-მა შექმნა ბილდის სისტემა ისე, რომ დამოკიდებულებები არაცხადად განისაზღვრებოდეს. ეს ნიშნავს, რომ პროდუქტს, მაგალითად აპლიკაციას, შეუძლია დაეყრდნოს ფრეიმვორკს, თუნდაც დამოკიდებულება ცხადად არ იყოს გამოცხადებული. მცირე მასშტაბით ეს პრობლემა არ არის, მაგრამ პროექტის გრაფის სირთულის ზრდასთან ერთად, არაცხადობა შეიძლება გამოიწვიოს არასანდო ინკრემენტულ ბილდებს ან რედაქტორზე დაფუძნებული ფუნქციების, როგორიცაა პრივიუები ან კოდის ავტოშევსება, არასწორ მუშაობას.

პრობლემა ისაა, რომ არაცხადი დამოკიდებულებების წარმოქმნის თავიდან აცილება შეუძლებელია. ნებისმიერ დეველოპერს შეუძლია დაამატოს `import` ოპერატორი თავის Swift კოდში, რითიც არაცხადი დამოკიდებულება შეიქმნება. სწორედ აქ შემოდის Tuist. Tuist გთავაზობთ ბრძანებას, რომელიც სტატიკურად აანალიზებს თქვენი პროექტის კოდს და ამოწმებს არაცხად დამოკიდებულებებს. შემდეგი ბრძანება გამოიტანს თქვენი პროექტის არაცხად დამოკიდებულებებს:

```bash
tuist inspect dependencies --only implicit
```

თუ ბრძანება აღმოაჩენს რაიმე არაცხად იმპორტს, ის დასრულდება ნულისგან განსხვავებული გასვლის კოდით.

> [!TIP]
> **ვალიდაცია CI-ში**
>
> ჩვენ მკაცრად გირჩევთ, ეს ბრძანება შეასრულოთ თქვენი <.localized_link href="/guides/integrations/continuous-integration">უწყვეტი ინტეგრაციის</.localized_link> პროცესის ნაწილად ყოველ ჯერზე, როდესაც ახალი კოდი იგზავნება რეპოზიტორიაში.


> [!WARNING]
> **ყველა არაცხადი შემთხვევა არ ვლინდება**
>
> ვინაიდან Tuist ეყრდნობა სტატიკურ კოდის ანალიზს არაცხადი დამოკიდებულებების აღმოსაჩენად, ის შეიძლება ვერ შეამჩნიოს ყველა შემთხვევას. მაგალითად, Tuist ვერ ხვდება პირობით იმპორტებს კოდში კომპილატორის დირექტივების მეშვეობით.
