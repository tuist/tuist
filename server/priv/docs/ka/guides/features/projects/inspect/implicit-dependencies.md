# არაცხადი იმპორტები {#implicit-imports}

Xcode-ის პროექტების გრაფის მართვის სირთულის შესამსუბუქებლად, Apple-მა შექმნა ბილდის სისტემა ისე, რომ დამოკიდებულებები არაცხადად განისაზღვრება. ეს ნიშნავს, რომ პროდუქტი, მაგალითად აპლიკაცია, შეიძლება იყოს დამოკიდებული ფრეიმვორკზე, თუნდაც დამოკიდებულება ცხადად არ იყოს აღწერილი. მცირე მასშტაბით ეს პრობლემა არ არის, მაგრამ როგორც კი პროექტის გრაფი უფრო რთული ხდება, არაცხადობამ შეიძლება გამოიწვიოს არასანდო ინკრემენტული ბილდები ან რედაქტორზე დაფუძნებული ფუნქციები, როგორიცაა პრივიუები ან კოდის ავტოშევსება.

პრობლემა ისაა, რომ არაცხადი დამოკიდებულებების წარმოქმნას ვერ აიცილებთ თავიდან. ნებისმიერ დეველოპერს შეუძლია დაამატოს `import` ოპერატორი თავის Swift კოდში და არაცხადი დამოკიდებულება შეიქმნება. აქ ერთვება Tuist. Tuist გთავაზობთ ბრძანებას, რომელიც არაცხად დამოკიდებულებებს ამოწმებს პროექტის კოდის სტატიკური ანალიზის მეშვეობით. შემდეგი ბრძანება გამოიტანს თქვენი პროექტის არაცხად დამოკიდებულებებს:

```bash
tuist inspect dependencies --only implicit
```

თუ ბრძანება აღმოაჩენს რაიმე არაცხად იმპორტს, ის დასრულდება ნულისგან განსხვავებული გასვლის კოდით.

> [!TIP]
> **ვალიდაცია CI-ში**
>
> ჩვენ ძლიერ გირჩევთ, რომ ეს ბრძანება გაუშვათ თქვენი <.localized_link href="/guides/integrations/continuous-integration">უწყვეტი ინტეგრაციის</.localized_link> პროცესის ნაწილად ყოველ ჯერზე, როდესაც ახალი კოდი იგზავნება upstream-ში.


> [!WARNING]
> **ყველა არაცხადი შემთხვევა არ აღმოჩნდება**
>
> რადგან Tuist ეყრდნობა სტატიკურ კოდის ანალიზს არაცხადი დამოკიდებულებების აღმოსაჩენად, ის შეიძლება ვერ აღმოაჩინოს ყველა შემთხვევა. მაგალითად, Tuist ვერ ახერხებს პირობითი იმპორტების გაგებას კოდში კომპილატორის დირექტივების მეშვეობით.
