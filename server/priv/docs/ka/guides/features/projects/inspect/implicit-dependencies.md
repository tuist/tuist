# არაცხადი იმპორტები {#implicit-imports}

Xcode-ის პროექტის გრაფის შენარჩუნების სირთულის შესამსუბუქებლად ნედლი Xcode-ის პროექტით, Apple-მა ააგო ბილდის სისტემა ისე, რომ დამოკიდებულებები შეიძლება არაცხადად განისაზღვროს. ეს ნიშნავს, რომ პროდუქტი, მაგალითად აპლიკაცია, შეიძლება იყოს დამოკიდებული ფრეიმვორკზე, თუნდაც დამოკიდებულება ცხადად არ იყოს გამოცხადებული. მცირე მასშტაბით ეს პრობლემა არ არის, მაგრამ როგორც კი პროექტის გრაფი რთულდება, არაცხადობა შეიძლება გამოვლინდეს არასანდო ინკრემენტული ბილდებით ან რედაქტორზე დაფუძნებული ფუნქციებით, როგორიცაა პრივიუები ან კოდის ავტოშევსება.

პრობლემა ის არის, რომ არაცხადი დამოკიდებულებების წარმოქმნას ვერ აღკვეთავთ. ნებისმიერ დეველოპერს შეუძლია დაამატოს `import` ოპერატორი თავის Swift-ის კოდში და არაცხადი დამოკიდებულება შეიქმნება. აქ შემოდის Tuist. Tuist გთავაზობთ ბრძანებას, რომელიც სტატიკურად აანალიზებს თქვენი პროექტის კოდს და ამოწმებს არაცხად დამოკიდებულებებს. ქვემოთ მოცემული ბრძანება გამოიტანს თქვენი პროექტის არაცხად დამოკიდებულებებს:

```bash
tuist inspect dependencies --only implicit
```

თუ ბრძანება აღმოაჩენს რაიმე არაცხად იმპორტს, ის დასრულდება ნულისგან განსხვავებული გასვლის კოდით.

> [!TIP]
> **ვალიდაცია CI-ში**
>
> ჩვენ მკაცრად გირჩევთ, ეს ბრძანება შეასრულოთ თქვენი <.localized_link href="/guides/integrations/continuous-integration">უწყვეტი ინტეგრაციის</.localized_link> პროცესის ნაწილად ყოველ ჯერზე, როდესაც ახალი კოდი იგზავნება upstream-ში.


> [!WARNING]
> **ყველა არაცხადი შემთხვევა არ აღმოჩნდება**
>
> ვინაიდან Tuist ეყრდნობა სტატიკურ კოდის ანალიზს არაცხადი დამოკიდებულებების აღმოსაჩენად, მან შეიძლება ვერ დაიჭიროს ყველა შემთხვევა. მაგალითად, Tuist ვერ ხვდება პირობით იმპორტებს კოდში კომპილატორის დირექტივების მეშვეობით.
