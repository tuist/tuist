# არაცხადი იმპორტი {#implicit-imports}

იმისთვის, რომ შეამციროს Xcode-ის პროექტის გრაფის შენარჩუნების სირთულე ნედლი Xcode პროექტებით, Apple-მა ააგო ბილდის სისტემა ისე, რომ დამოკიდებულებები არაცხადად განისაზღვრება. ეს ნიშნავს, რომ პროდუქტს, მაგალითად აპლიკაციას, შეუძლია დამოკიდებული იყოს ფრეიმვორკზე, თუნდაც დამოკიდებულება ცხადად არ იყოს გამოცხადებული. მცირე მასშტაბით ეს პრობლემა არ არის, მაგრამ რაც უფრო რთული ხდება პროექტის გრაფი, არაცხადობამ შეიძლება გამოიწვიოს არასანდო ინკრემენტული ბილდები ან რედაქტორზე დაფუძნებული ფუნქციები, როგორიცაა პრივიუები ან კოდის ავტოშევსება.

პრობლემა ისაა, რომ არაცხადი დამოკიდებულებების წარმოქმნას ვერ აღკვეთავთ. ნებისმიერ დეველოპერს შეუძლია თავის Swift კოდში დაამატოს `import` ოპერატორი და არაცხადი დამოკიდებულება შეიქმნება. აქ ერთვება Tuist. Tuist გთავაზობთ ბრძანებას, რომელიც არაცხად დამოკიდებულებებს ამოწმებს თქვენი პროექტის კოდის სტატიკური ანალიზით. შემდეგი ბრძანება გამოიტანს თქვენი პროექტის არაცხად დამოკიდებულებებს:

```bash
tuist inspect dependencies --only implicit
```

თუ ბრძანება აღმოაჩენს რაიმე არაცხად იმპორტს, ის დასრულდება ნულისგან განსხვავებული გასვლის კოდით.

> [!TIP]
> **ვალიდაცია CI-ში**
>
> ჩვენ მკაცრად გირჩევთ, ეს ბრძანება გაუშვათ თქვენი <.localized_link href="/guides/integrations/continuous-integration">უწყვეტი ინტეგრაციის</.localized_link> პროცესის ნაწილად ყოველ ჯერზე, როცა ახალი კოდი იგზავნება ზემოთ.


> [!WARNING]
> **ყველა არაცხადი შემთხვევა არ ვლინდება**
>
> ვინაიდან Tuist ეყრდნობა სტატიკურ კოდის ანალიზს არაცხადი დამოკიდებულებების აღმოსაჩენად, შესაძლოა ყველა შემთხვევა არ დაიჭიროს. მაგალითად, Tuist ვერ აღიქვამს პირობით იმპორტებს კოდში კომპილატორის დირექტივების მეშვეობით.
