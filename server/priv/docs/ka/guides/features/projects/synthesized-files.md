# სინთეზირებული ფაილები {#synthesized-files}

Tuist-ს შეუძლია გენერაციის დროს შექმნას ფაილები და კოდი, რაც Xcode პროექტების მართვასა და მუშაობას ამარტივებს. ამ გვერდზე გაეცნობით ამ ფუნქციონალს და იმას, თუ როგორ გამოიყენოთ ის თქვენს პროექტებში.

## მიზნის რესურსები {#target-resources}

Xcode პროექტები მხარდაჭერიან რესურსების დამატებას მიზნებზე. თუმცა, ეს გუნდებს რამდენიმე გამოწვევის წინაშე აყენებს, განსაკუთრებით მაშინ, როდესაც მუშაობთ მოდულურ პროექტთან, სადაც წყაროები და რესურსები ხშირად გადაადგილდება:

- **არათანმიმდევრული წვდომა შესრულების დროს**: სად აღმოჩნდება რესურსები საბოლოო პროდუქტში და როგორ მიუწვდებით მათ, დამოკიდებულია მიზნის პროდუქტის ტიპზე. მაგალითად, თუ თქვენი მიზანი წარმოადგენს აპლიკაციას, რესურსები კოპირდება აპლიკაციის ბანდლში. ეს იწვევს კოდს, რომელიც რესურსებზე წვდომისას ეყრდნობა ბანდლის სტრუქტურის ვარაუდებს, რაც არ არის იდეალური, რადგან ართულებს კოდის გაგებას და რესურსების გადაადგილებას.
- **პროდუქტები, რომლებიც არ მხარდაჭერენ რესურსებს**: არსებობს გარკვეული პროდუქტები, როგორიცაა სტატიკური ბიბლიოთეკები, რომლებიც არ არის ბანდლები და, შესაბამისად, არ მხარდაჭერენ რესურსებს. ამის გამო, თქვენ უნდა მიმართოთ სხვა ტიპის პროდუქტს, მაგალითად ჩარჩოებს (frameworks), რამაც შეიძლება დამატებითი დატვირთვა შეუქმნას თქვენს პროექტს ან აპლიკაციას. მაგალითად, სტატიკური ჩარჩოები სტატიკურად იქნება დაკავშირებული საბოლოო პროდუქტთან და საჭიროა აგების ეტაპი, რათა მხოლოდ რესურსები დაკოპირდეს საბოლოო პროდუქტში. ან დინამიური ჩარჩოები, სადაც Xcode დააკოპირებს როგორც ბინარულ ფაილს, ასევე რესურსებს საბოლოო პროდუქტში, მაგრამ ეს გაზრდის თქვენი აპლიკაციის გაშვების დროს, რადგან ჩარჩო დინამიურად უნდა ჩაიტვირთოს.
- **მიდრეკილება შესრულების დროის შეცდომებისკენ**: რესურსები იდენტიფიცირდება მათი სახელით და გაფართოებით (სტრიქონები). შესაბამისად, ნებისმიერი მათგანის შეცდომა გამოიწვევს შესრულების დროის შეცდომას რესურსზე წვდომის მცდელობისას. ეს არ არის იდეალური, რადგან შეცდომა არ ფიქსირდება კომპილაციის დროს და შეიძლება გამოიწვიოს კრახები რელიზში.

Tuist ზემოაღნიშნულ პრობლემებს წყვეტს **ბანდლებსა და რესურსებზე წვდომის ერთიანი ინტერფეისის სინთეზირებით**, რაც ფარავს იმპლემენტაციის დეტალებს.

> [!WARNING]
> **რეკომენდებულია**
>
> მიუხედავად იმისა, რომ Tuist-ის მიერ სინთეზირებული ინტერფეისის მეშვეობით რესურსებზე წვდომა სავალდებულო არ არის, ჩვენ გირჩევთ მას, რადგან ის ამარტივებს კოდის გაგებას და რესურსების გადაადგილებას.


## რესურსები {#resources}

Tuist უზრუნველყოფს ინტერფეისებს Swift-ში ისეთი ფაილების შინაარსის აღსაწერად, როგორიცაა `Info.plist` ან უფლებამოსილებები (entitlements). ეს სასარგებლოა მიზნებსა და პროექტებში თანმიმდევრულობის უზრუნველსაყოფად და კომპილატორის გამოყენებით პრობლემების კომპილაციის დროს გამოსავლენად. ასევე შეგიძლიათ შექმნათ თქვენი საკუთარი აბსტრაქციები შინაარსის მოდელირებისთვის და მისი გაზიარებისთვის მიზნებსა და პროექტებში.

როდესაც თქვენი პროექტი გენერირდება, Tuist სინთეზირებს ამ ფაილების შინაარსს და ჩაწერს მათ `Derived` დირექტორიაში, პროექტის შემცველი დირექტორიის მიმართებით.

> [!TIP]
> **დაამატეთ Derived დირექტორია .gitignore-ში**
>
> ჩვენ გირჩევთ დაამატოთ `Derived` დირექტორია თქვენი პროექტის `.gitignore` ფაილში.


## ბანდლის აქსესორები {#bundle-accessors}

Tuist სინთეზირებს ინტერფეისს ბანდლზე წვდომისთვის, რომელიც შეიცავს მიზნის რესურსებს.

### Swift {#swift}

მიზანი შეიცავს `Bundle` ტიპის გაფართოებას, რომელიც ავლენს ბანდლს:

```swift
let bundle = Bundle.module
```

### Objective-C {#objectivec}

Objective-C-ში მიიღებთ ინტერფეისს `{Target}Resources` ბანდლზე წვდომისთვის:

```objc
NSBundle *bundle = [MyFeatureResources bundle];
```

> [!WARNING]
> **შეზღუდვა შიდა მიზნებთან**
>
> ამჟამად, Tuist არ ქმნის რესურსების ბანდლის აქსესორებს შიდა მიზნებისთვის, რომლებიც შეიცავენ მხოლოდ Objective-C წყაროებს. ეს ცნობილი შეზღუდვაა, რომელიც აღრიცხულია [საქმე #6456](https://github.com/tuist/tuist/issues/6456)-ში.


> [!TIP]
> **რესურსების მხარდაჭერა ბიბლიოთეკებში ბანდლების მეშვეობით**
>
> თუ მიზნის პროდუქტი, მაგალითად ბიბლიოთეკა, არ მხარდაჭერს რესურსებს, Tuist ჩართავს რესურსებს `bundle` პროდუქტის ტიპის მიზანში, რაც უზრუნველყოფს მათ მოხვედრას საბოლოო პროდუქტში და ინტერფეისის სწორ ბანდლზე მიმართვას. ეს სინთეზირებული ბანდლები ავტომატურად ინიშნება `tuist:synthesized` თეგით და იღებენ ყველა თეგს მშობელი მიზნიდან, რაც საშუალებას გაძლევთ მიმართოთ მათ <.localized_link href="/guides/features/projects/metadata-tags#system-tags">ქეშის პროფილებში</.localized_link>.


## რესურსების აქსესორები {#resource-accessors}

რესურსები იდენტიფიცირდება მათი სახელით და გაფართოებით სტრიქონების გამოყენებით. ეს არ არის იდეალური, რადგან შეცდომა არ ფიქსირდება კომპილაციის დროს და შეიძლება გამოიწვიოს კრახები რელიზში. ამის თავიდან ასაცილებლად, Tuist აერთიანებს [SwiftGen](https://github.com/SwiftGen/SwiftGen)-ს პროექტის გენერაციის პროცესში, რათა სინთეზირდეს ინტერფეისი რესურსებზე წვდომისთვის. ამის წყალობით, შეგიძლიათ დარწმუნებულად მიუწვდეთ რესურსებს, კომპილატორის გამოყენებით ნებისმიერი პრობლემის გამოსავლენად.

Tuist შეიცავს [შაბლონებს](https://github.com/tuist/tuist/tree/main/cli/Sources/TuistGenerator/Templates) შემდეგი ტიპის რესურსებისთვის აქსესორების სინთეზირებისთვის ნაგულისხმევად:

| რესურსის ტიპი | სინთეზირებული ფაილი |
| --- | ---- |
| სურათები და ფერები | `Assets+{Target}.swift` |
| სტრიქონები | `Strings+{Target}.swift` |
| Plist-ები | `{NameOfPlist}.swift` |
| შრიფტები | `Fonts+{Target}.swift` |
| ფაილები | `Files+{Target}.swift` |

> შენიშვნა: შეგიძლიათ გათიშოთ რესურსების აქსესორების სინთეზირება პროექტის დონეზე, პროექტის პარამეტრებში `disableSynthesizedResourceAccessors` ოფციის გადაცემით.

### მორგებული შაბლონები {#custom-templates}

თუ გსურთ შექმნათ თქვენი საკუთარი შაბლონები სხვა ტიპის რესურსებისთვის აქსესორების სინთეზირებისთვის, რაც უნდა იყოს მხარდაჭერილი [SwiftGen](https://github.com/SwiftGen/SwiftGen)-ის მიერ, შეგიძლიათ შექმნათ ისინი `Tuist/ResourceSynthesizers/{name}.stencil` მისამართზე, სადაც სახელი არის რესურსის camel-case ვერსია.

| რესურსი | შაბლონის სახელი |
| --- | --- |
| სტრიქონები | `Strings.stencil` |
| რესურსები | `Assets.stencil` |
| plist-ები | `Plists.stencil` |
| შრიფტები | `Fonts.stencil` |
| coreData | `CoreData.stencil` |
| interfaceBuilder | `InterfaceBuilder.stencil` |
| json | `JSON.stencil` |
| yaml | `YAML.stencil` |
| ფაილები | `Files.stencil` |

თუ გსურთ დააკონფიგურიროთ რესურსების ტიპების სია, რომელთათვისაც უნდა სინთეზირდეს აქსესორები, შეგიძლიათ გამოიყენოთ `Project.resourceSynthesizers` თვისება და გადასცეთ სასურველი რესურსის სინთეზატორების სია:

```swift
let project = Project(name: "App", resourceSynthesizers: [.strings(), .fonts()])
```

> [!NOTE]
> **მითითება**
>
> შეგიძლიათ ნახოთ [ეს მაგალითი](https://github.com/tuist/tuist/tree/main/examples/xcode/generated_ios_app_with_templates), რათა იხილოთ, თუ როგორ გამოვიყენოთ მორგებული შაბლონები რესურსების აქსესორების სინთეზირებისთვის.
