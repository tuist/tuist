# სინთეზირებული ფაილები {#synthesized-files}

Tuist-ს შეუძლია გენერაციის დროს შექმნას ფაილები და კოდი, რაც Xcode პროექტების მართვასა და მუშაობას უფრო მოსახერხებელს ხდის. ამ გვერდზე გაეცნობით ამ ფუნქციონალს და იმას, თუ როგორ გამოიყენოთ ის თქვენს პროექტებში.

## მიზნის რესურსები {#target-resources}

Xcode პროექტები მხარდაჭერიან რესურსების დამატებას მიზნებისთვის. თუმცა, ეს გუნდებს რამდენიმე სირთულეს უქმნის, განსაკუთრებით მაშინ, როდესაც მუშაობთ მოდულურ პროექტთან, სადაც წყაროები და რესურსები ხშირად გადაადგილდება:

- **არათანმიმდევრული წვდომა შესრულების დროს**: სად აღმოჩნდება რესურსები საბოლოო პროდუქტში და როგორ მიუწვდებით მათ, დამოკიდებულია მიზნის პროდუქტის ტიპზე. მაგალითად, თუ თქვენი მიზანი წარმოადგენს აპლიკაციას, რესურსები კოპირდება აპლიკაციის ბანდლში. ეს იწვევს კოდს, რომელიც რესურსებზე წვდომისას ეყრდნობა ბანდლის სტრუქტურის ვარაუდებს, რაც არ არის სასურველი, რადგან ართულებს კოდის გაგებას და რესურსების გადაადგილებას.
- **პროდუქტები, რომლებიც არ მხარდაჭერენ რესურსებს**: არსებობს გარკვეული პროდუქტები, როგორიცაა სტატიკური ბიბლიოთეკები, რომლებიც არ არის ბანდლები და, შესაბამისად, არ მხარდაჭერენ რესურსებს. ამის გამო, თქვენ ან უნდა მიმართოთ სხვა ტიპის პროდუქტს, მაგალითად ფრეიმვორკებს, რამაც შეიძლება დამატებითი დატვირთვა შეუქმნას თქვენს პროექტს ან აპლიკაციას. მაგალითად, სტატიკური ფრეიმვორკები სტატიკურად იქნება დაკავშირებული საბოლოო პროდუქტთან და საჭიროა აგების ეტაპი, რათა მხოლოდ რესურსები დაკოპირდეს საბოლოო პროდუქტში. ან დინამიური ფრეიმვორკები, სადაც Xcode დააკოპირებს როგორც ბინარულ ფაილს, ასევე რესურსებს საბოლოო პროდუქტში, მაგრამ ეს გაზრდის თქვენი აპლიკაციის გაშვების დროს, რადგან ფრეიმვორკი დინამიურად უნდა ჩაიტვირთოს.
- **მიდრეკილება შესრულების დროს შეცდომებისკენ**: რესურსები იდენტიფიცირდება მათი სახელით და გაფართოებით (სტრიנגებით). შესაბამისად, ნებისმიერი მათგანის ბეჭდვითი შეცდომა გამოიწვევს შესრულების დროს შეცდომას რესურსზე წვდომის მცდელობისას. ეს არ არის სასურველი, რადგან შეცდომა არ ვლინდება კომპილაციის დროს და შეიძლება გამოიწვიოს კრახები რელიზის ვერსიაში.

Tuist ზემოთ ჩამოთვლილ პრობლემებს წყვეტს **ბანდლებსა და რესურსებზე წვდომის ერთიანი ინტერფეისის სინთეზირებით**, რაც ფარავს იმპლემენტაციის დეტალებს.

> [!WARNING]
> **რეკომენდებულია**
>
> მიუხედავად იმისა, რომ Tuist-ის მიერ სინთეზირებული ინტერფეისის მეშვეობით რესურსებზე წვდომა არ არის სავალდებულო, ჩვენ გირჩევთ მას, რადგან ის აადვილებს კოდის გაგებას და რესურსების გადაადგილებას.


## რესურსები {#resources}

Tuist უზრუნველყოფს ინტერფეისებს Swift-ში ისეთი ფაილების შინაარსის აღსაწერად, როგორიცაა `Info.plist` ან უფლებები. ეს სასარგებლოა მიზნებსა და პროექტებში თანმიმდევრულობის უზრუნველსაყოფად და კომპილატორის გამოყენებით პრობლემების კომპილაციის დროს აღმოსაჩენად. ასევე შეგიძლიათ შექმნათ თქვენი საკუთარი აბსტრაქციები შინაარსის მოდელირებისთვის და მისი გაზიარებისთვის მიზნებსა და პროექტებში.

როდესაც თქვენი პროექტი გენერირდება, Tuist სინთეზირებს ამ ფაილების შინაარსს და ჩაწერს მათ `Derived` დირექტორიაში, პროექტის შემცველი დირექტორიის მიმართებით.

> [!TIP]
> **დაამატეთ Derived დირექტორია .gitignore-ში**
>
> ჩვენ გირჩევთ დაამატოთ `Derived` დირექტორია თქვენი პროექტის `.gitignore` ფაილში.


## ბანდლის აქსესორები {#bundle-accessors}

Tuist სინთეზირებს ინტერფეისს ბანდლზე წვდომისთვის, რომელიც შეიცავს მიზნის რესურსებს.

### Swift {#swift}

მიზანი შეიცავს `Bundle` ტიპის გაფართოებას, რომელიც აწვდის ბანდლს:

```swift
let bundle = Bundle.module
```

### Objective-C {#objectivec}

Objective-C-ში მიიღებთ ინტერფეისს `{Target}Resources` ბანდლზე წვდომისთვის:

```objc
NSBundle *bundle = [MyFeatureResources bundle];
```

> [!WARNING]
> **შეზღუდვა შიდა მიზნებთან**
>
> ამჟამად, Tuist არ ქმნის რესურსების ბანდლის აქსესორებს შიდა მიზნებისთვის, რომლებიც შეიცავენ მხოლოდ Objective-C წყაროებს. ეს ცნობილი შეზღუდვაა, რომელიც აღრიცხულია [საქმე #6456-ში](https://github.com/tuist/tuist/issues/6456).


> [!TIP]
> **რესურსების მხარდაჭერა ბიბლიოთეკებში ბანდლების მეშვეობით**
>
> თუ მიზნის პროდუქტი, მაგალითად ბიბლიოთეკა, არ მხარდაჭერს რესურსებს, Tuist ჩართავს რესურსებს `bundle` პროდუქტის ტიპის მქონე მიზანში, რაც უზრუნველყოფს მათ საბოლოო პროდუქტში მოხვედრას და ინტერფეისის სწორ ბანდლზე მიმართვას. ეს სინთეზირებული ბანდლები ავტომატურად ინიშნება `tuist:synthesized` თეგით და იღებენ ყველა თეგს მშობელი მიზნიდან, რაც საშუალებას გაძლევთ მიმართოთ მათ <.localized_link href="/guides/features/projects/metadata-tags#system-tags">ქეშის პროფილებში</.localized_link>.


## რესურსების აქსესორები {#resource-accessors}

რესურსები იდენტიფიცირდება მათი სახელით და გაფართოებით სტრიngების გამოყენებით. ეს არ არის სასურველი, რადგან შეცდომა არ ვლინდება კომპილაციის დროს და შეიძლება გამოიწვიოს კრახები რელიზის ვერსიაში. ამის თავიდან ასაცილებლად, Tuist აინტეგრირებს [SwiftGen](https://github.com/SwiftGen/SwiftGen)-ს პროექტის გენერაციის პროცესში, რათა სინთეზირდეს ინტერფეისი რესურსებზე წვდომისთვის. ამის წყალობით, შეგიძლიათ დარწმუნებულად მიუწვდეთ რესურსებს, კომპილატორის გამოყენებით ნებისმიერი პრობლემის აღმოსაჩენად.

Tuist მოიცავს [შაბლონებს](https://github.com/tuist/tuist/tree/main/cli/Sources/TuistGenerator/Templates) შემდეგი ტიპის რესურსებისთვის აქსესორების სინთეზირებისთვის ნაგულისხმევად:

| რესურსის ტიპი | სინთეზირებული ფაილი |
| --- | ---- |
| სურათები და ფერები | `Assets+{Target}.swift` |
| სტრიngები | `Strings+{Target}.swift` |
| Plist-ები | `{NameOfPlist}.swift` |
| შრიფტები | `Fonts+{Target}.swift` |
| ფაილები | `Files+{Target}.swift` |

> შენიშვნა: შეგიძლიათ გათიშოთ რესურსების აქსესორების სინთეზირება პროექტის დონეზე, პროექტის პარამეტრებში `disableSynthesizedResourceAccessors` ოფციის გადაცემით.

#### მორგებული შაბლონები {#custom-templates}

თუ გსურთ უზრუნველყოთ თქვენი საკუთარი შაბლონები სხვა ტიპის რესურსებისთვის აქსესორების სინთეზირებისთვის, რაც უნდა იყოს მხარდაჭერილი [SwiftGen](https://github.com/SwiftGen/SwiftGen)-ის მიერ, შეგიძლიათ შექმნათ ისინი `Tuist/ResourceSynthesizers/{name}.stencil` მისამართზე, სადაც სახელი არის რესურსის camel-case ვერსია.

| რესურსი | შაბლონის სახელი |
| --- | --- |
| strings | `Strings.stencil` |
| assets | `Assets.stencil` |
| plists | `Plists.stencil` |
| fonts | `Fonts.stencil` |
| coreData | `CoreData.stencil` |
| interfaceBuilder | `InterfaceBuilder.stencil` |
| json | `JSON.stencil` |
| yaml | `YAML.stencil` |
| files | `Files.stencil` |

თუ გსურთ დააკონფიგურიროთ რესურსების ტიპების სია, რომელთათვისაც უნდა მოხდეს აქსესორების სინთეზირება, შეგიძლიათ გამოიყენოთ `Project.resourceSynthesizers` თვისება, გადასცეთ იმ რესურსის სინთეზატორების სია, რომელთა გამოყენებაც გსურთ:

```swift
let project = Project(resourceSynthesizers: [.string(), .fonts()])
```

> [!NOTE]
> **წყარო**
>
> შეგიძლიათ ნახოთ [ეს მაგალითი](https://github.com/tuist/tuist/tree/main/examples/xcode/generated_ios_app_with_templates), რათა იხილოთ მაგალითი იმისა, თუ როგორ უნდა გამოიყენოთ მორგებული შაბლონები რესურსებისთვის აქსესორების სინთეზირების მიზნით.
