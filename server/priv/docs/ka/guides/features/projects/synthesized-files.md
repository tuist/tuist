# სინთეზირებული ფაილები {#synthesized-files}

Tuist-ს შეუძლია გენერაციის დროს შექმნას ფაილები და კოდი, რაც Xcode პროექტების მართვასა და მუშაობას ამარტივებს. ამ გვერდზე გაეცნობით ამ ფუნქციონალს და იმას, თუ როგორ გამოიყენოთ ის თქვენს პროექტებში.

## სამიზნე რესურსები {#target-resources}

Xcode პროექტები მხარდაჭერიან რესურსების დამატებას სამიზნეებში (targets). თუმცა, ეს გუნდებს რამდენიმე გამოწვევას უქმნის, განსაკუთრებით მოდულურ პროექტებთან მუშაობისას, სადაც წყაროები და რესურსები ხშირად გადაადგილდება:

- **არათანმიმდევრული წვდომა შესრულების დროს**: სად აღმოჩნდება რესურსები საბოლოო პროდუქტში და როგორ მივმართავთ მათ, დამოკიდებულია სამიზნე პროდუქტზე. მაგალითად, თუ თქვენი სამიზნე აპლიკაციას წარმოადგენს, რესურსები კოპირდება აპლიკაციის ბანდლში. ეს იწვევს კოდს, რომელიც რესურსებზე წვდომისას ვარაუდებს აკეთებს ბანდლის სტრუქტურის შესახებ, რაც არ არის იდეალური, რადგან ართულებს კოდის გაგებას და რესურსების გადაადგილებას.
- **პროდუქტები, რომლებიც არ მხარდაჭერენ რესურსებს**: არსებობს გარკვეული პროდუქტები, როგორიცაა სტატიკური ბიბლიოთეკები, რომლებიც არ არიან ბანდლები და, შესაბამისად, არ მხარდაჭერენ რესურსებს. ამის გამო, თქვენ ან უნდა მიმართოთ სხვა ტიპის პროდუქტს, მაგალითად ფრეიმვორკებს, რამაც შეიძლება ზედმეტი დატვირთვა დაამატოს თქვენს პროექტს ან აპლიკაციას. მაგალითად, სტატიკური ფრეიმვორკები სტატიკურად იქნება დაკავშირებული საბოლოო პროდუქტთან და საჭიროა აწყობის ეტაპი (build phase), რათა მხოლოდ რესურსები დაკოპირდეს საბოლოო პროდუქტში. ან დინამიური ფრეიმვორკები, სადაც Xcode დააკოპირებს როგორც ბინარულ ფაილს, ასევე რესურსებს საბოლოო პროდუქტში, მაგრამ ეს გაზრდის თქვენი აპლიკაციის გაშვების დროს, რადგან ფრეიმვორკი დინამიურად უნდა ჩაიტვირთოს.
- **შეცდომებისადმი მიდრეკილობა შესრულების დროს**: რესურსები იდენტიფიცირდება მათი სახელითა და გაფართოებით (სტრიנגები). შესაბამისად, ნებისმიერი მათგანის შეცდომა გამოიწვევს შესრულების დროის შეცდომას რესურსზე წვდომის მცდელობისას. ეს არ არის იდეალური, რადგან შეცდომა არ ფიქსირდება კომპილაციის დროს და შეიძლება გამოიწვიოს კრახები რელიზში.

Tuist ზემოთ ჩამოთვლილ პრობლემებს წყვეტს **ბანდლებსა და რესურსებზე წვდომის ერთიანი ინტერფეისის სინთეზირებით**, რაც აბსტრაგირებს იმპლემენტაციის დეტალებს.

> [!WARNING]
> **რეკომენდებულია**
>
> მიუხედავად იმისა, რომ Tuist-ის მიერ სინთეზირებული ინტერფეისის მეშვეობით რესურსებზე წვდომა სავალდებულო არ არის, ჩვენ გირჩევთ მას, რადგან ის ამარტივებს კოდის გაგებას და რესურსების გადაადგილებას.


## რესურსები {#resources}

Tuist უზრუნველყოფს ინტერფეისებს ისეთი ფაილების შინაარსის აღსაწერად, როგორიცაა `Info.plist` ან უფლებამოსილებები (entitlements) Swift-ში. ეს სასარგებლოა სამიზნეებსა და პროექტებს შორის თანმიმდევრულობის უზრუნველსაყოფად და კომპილატორის გამოყენებით პრობლემების კომპილაციის დროს აღმოსაჩენად. ასევე შეგიძლიათ შექმნათ საკუთარი აბსტრაქციები შინაარსის მოდელირებისთვის და მისი გაზიარებისთვის სამიზნეებსა და პროექტებს შორის.

როდესაც თქვენი პროექტი გენერირდება, Tuist სინთეზირებს ამ ფაილების შინაარსს და ჩაწერს მათ `Derived` დირექტორიაში, პროექტის შემცველი დირექტორიის მიმართებით.

> [!TIP]
> **Derived დირექტორიის .gitignore-ში დამატება**
>
> ჩვენ გირჩევთ `Derived` დირექტორიის დამატებას თქვენი პროექტის `.gitignore` ფაილში.


## ბანდლის აქსესორები {#bundle-accessors}

Tuist სინთეზირებს ინტერფეისს ბანდლზე წვდომისთვის, რომელიც შეიცავს სამიზნე რესურსებს.

### Swift {#swift}

სამიზნე შეიცავს `Bundle` ტიპის გაფართოებას, რომელიც აწვდის ბანდლს:

```swift
let bundle = Bundle.module
```

### Objective-C {#objectivec}

Objective-C-ში მიიღებთ ინტერფეისს `{Target}Resources` ბანდლზე წვდომისთვის:

```objc
NSBundle *bundle = [MyFeatureResources bundle];
```

> [!WARNING]
> **შეზღუდვა შიდა სამიზნეებთან**
>
> ამჟამად, Tuist არ აგენერირებს რესურსების ბანდლის აქსესორებს შიდა სამიზნეებისთვის, რომლებიც შეიცავენ მხოლოდ Objective-C წყაროებს. ეს ცნობილი შეზღუდვაა, რომელიც ფიქსირდება [საქმე #6456](https://github.com/tuist/tuist/issues/6456)-ში.


> [!TIP]
> **ბიბლიოთეკებში რესურსების მხარდაჭერა ბანდლების მეშვეობით**
>
> თუ სამიზნე პროდუქტი, მაგალითად ბიბლიოთეკა, არ მხარდაჭერს რესურსებს, Tuist ჩართავს რესურსებს `bundle` პროდუქტის ტიპის სამიზნეში, რაც უზრუნველყოფს მათ მოხვედრას საბოლოო პროდუქტში და ინტერფეისის სწორ ბანდლზე მიმართვას. ეს სინთეზირებული ბანდლები ავტომატურად ინიშნება `tuist:synthesized` თეგით და იღებენ ყველა თეგს მშობელი სამიზნიდან, რაც საშუალებას გაძლევთ მიმართოთ მათ <.localized_link href="/guides/features/projects/metadata-tags#system-tags">ქეშის პროფილებში</.localized_link>.


## რესურსების აქსესორები {#resource-accessors}

რესურსები იდენტიფიცირდება მათი სახელითა და გაფართოებით სტრიנגების გამოყენებით. ეს არ არის იდეალური, რადგან შეცდომა არ ფიქსირდება კომპილაციის დროს და შეიძლება გამოიწვიოს კრახები რელიზში. ამის თავიდან ასაცილებლად, Tuist აინტეგრირებს [SwiftGen](https://github.com/SwiftGen/SwiftGen)-ს პროექტის გენერაციის პროცესში, რათა სინთეზირდეს ინტერფეისი რესურსებზე წვდომისთვის. ამის წყალობით, შეგიძლიათ დარწმუნებით მიმართოთ რესურსებს, კომპილატორის გამოყენებით ნებისმიერი პრობლემის აღმოსაჩენად.

Tuist მოიცავს [შაბლონებს](https://github.com/tuist/tuist/tree/main/cli/Sources/TuistGenerator/Templates) შემდეგი ტიპის რესურსების აქსესორების სინთეზირებისთვის ნაგულისხმევად:

| რესურსის ტიპი | სინთეზირებული ფაილი |
| --- | ---- |
| სურათები და ფერები | `Assets+{Target}.swift` |
| სტრიंगები | `Strings+{Target}.swift` |
| Plist-ები | `{NameOfPlist}.swift` |
| შრიფტები | `Fonts+{Target}.swift` |
| ფაილები | `Files+{Target}.swift` |

> შენიშვნა: შეგიძლიათ გათიშოთ რესურსების აქსესორების სინთეზირება პროექტის დონეზე `disableSynthesizedResourceAccessors` ოფციის გადაცემით პროექტის პარამეტრებში.

### მორგებული შაბლონები {#custom-templates}

თუ გსურთ საკუთარი შაბლონების მიწოდება სხვა ტიპის რესურსების აქსესორების სინთეზირებისთვის, რაც უნდა მხარდაჭერილი იყოს [SwiftGen](https://github.com/SwiftGen/SwiftGen)-ის მიერ, შეგიძლიათ შექმნათ ისინი `Tuist/ResourceSynthesizers/{name}.stencil` მისამართზე, სადაც სახელი არის რესურსის camel-case ვერსია.

| რესურსი | შაბლონის სახელი |
| --- | --- |
| სტრიंगები | `Strings.stencil` |
| რესურსები | `Assets.stencil` |
| plist-ები | `Plists.stencil` |
| შრიფტები | `Fonts.stencil` |
| coreData | `CoreData.stencil` |
| interfaceBuilder | `InterfaceBuilder.stencil` |
| json | `JSON.stencil` |
| yaml | `YAML.stencil` |
| ფაილები | `Files.stencil` |

თუ გსურთ დააკონფიგურიროთ რესურსების ტიპების სია, რომელთათვისაც სინთეზირდება აქსესორები, შეგიძლიათ გამოიყენოთ `Project.resourceSynthesizers` თვისება და გადასცეთ სასურველი რესურსის სინთეზატორების სია:

```swift
let project = Project(name: "App", resourceSynthesizers: [.strings(), .fonts()])
```

> [!NOTE]
> **მითითება**
>
> შეგიძლიათ ნახოთ [ეს მაგალითი](https://github.com/tuist/tuist/tree/main/examples/xcode/generated_ios_app_with_templates), რათა იხილოთ, თუ როგორ გამოვიყენოთ მორგებული შაბლონები რესურსების აქსესორების სინთეზირებისთვის.
