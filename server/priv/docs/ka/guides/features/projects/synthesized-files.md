# სინთეზირებული ფაილები {#synthesized-files}

Tuist-ს შეუძლია გენერაციის დროს შექმნას ფაილები და კოდი, რაც Xcode პროექტების მართვასა და მუშაობას უფრო მოსახერხებელს ხდის. ამ გვერდზე გაეცნობით ამ ფუნქციონალს და იმას, თუ როგორ გამოიყენოთ ის თქვენს პროექტებში.

## მიზნის რესურსები {#target-resources}

Xcode პროექტები მხარდაჭერენ რესურსების დამატებას მიზნებში (targets). თუმცა, ეს გუნდებს რამდენიმე სირთულეს უქმნის, განსაკუთრებით მაშინ, როდესაც მუშაობენ მოდულურ პროექტზე, სადაც წყაროები და რესურსები ხშირად გადაადგილდება:

- **არათანმიმდევრული წვდომა შესრულების დროს**: სად აღმოჩნდება რესურსები საბოლოო პროდუქტში და როგორ მიუწვდებით მათ, დამოკიდებულია მიზნის პროდუქტის ტიპზე. მაგალითად, თუ თქვენი მიზანი წარმოადგენს აპლიკაციას, რესურსები კოპირდება აპლიკაციის ბანდლში. ეს იწვევს კოდს, რომელიც რესურსებზე წვდომისას ეყრდნობა ვარაუდებს ბანდლის სტრუქტურის შესახებ, რაც არ არის იდეალური, რადგან ართულებს კოდის გაგებას და რესურსების გადაადგილებას.
- **პროდუქტები, რომლებიც არ მხარდაჭერენ რესურსებს**: არსებობს გარკვეული პროდუქტები, როგორიცაა სტატიკური ბიბლიოთეკები, რომლებიც არ არის ბანდლები და, შესაბამისად, არ მხარდაჭერენ რესურსებს. ამის გამო, თქვენ ან უნდა მიმართოთ სხვა ტიპის პროდუქტს, მაგალითად ფრეიმვორკებს, რამაც შეიძლება დაამატოს ზედმეტი დატვირთვა თქვენს პროექტს ან აპლიკაციას. მაგალითად, სტატიკური ფრეიმვორკები სტატიკურად იქნება დაკავშირებული საბოლოო პროდუქტთან და საჭიროა აწყობის ეტაპი, რათა მხოლოდ რესურსები დაკოპირდეს საბოლოო პროდუქტში. ან დინამიური ფრეიმვორკები, სადაც Xcode დააკოპირებს როგორც ბინარულ ფაილს, ასევე რესურსებს საბოლოო პროდუქტში, მაგრამ ეს გაზრდის თქვენი აპლიკაციის გაშვების დროს, რადგან ფრეიმვორკი დინამიურად უნდა ჩაიტვირთოს.
- **მიდრეკილება შესრულების დროს შეცდომებისკენ**: რესურსები იდენტიფიცირდება მათი სახელითა და გაფართოებით (სტრიנגებით). შესაბამისად, ნებისმიერი მათგანის ბეჭდვითი შეცდომა გამოიწვევს შესრულების დროს შეცდომას რესურსზე წვდომის მცდელობისას. ეს არ არის იდეალური, რადგან შეცდომა არ ვლინდება კომპილაციის დროს და შეიძლება გამოიწვიოს კრაშები რელიზში.

Tuist ზემოაღნიშნულ პრობლემებს ხსნის **ბანდლებსა და რესურსებზე წვდომის ერთიანი ინტერფეისის სინთეზირებით**, რაც აბსტრაგირებს იმპლემენტაციის დეტალებს.

> [!WARNING]
> **რეკომენდებული**
>
> მიუხედავად იმისა, რომ რესურსებზე წვდომა Tuist-ის მიერ სინთეზირებული ინტერფეისის მეშვეობით არ არის სავალდებულო, ჩვენ გირჩევთ მას, რადგან ის აადვილებს კოდის გაგებას და რესურსების გადაადგილებას.


## რესურსები {#resources}

Tuist უზრუნველყოფს ინტერფეისებს ისეთი ფაილების შინაარსის აღსაწერად, როგორიცაა `Info.plist` ან უფლებები (entitlements) Swift-ში. ეს სასარგებლოა მიზნებსა და პროექტებში თანმიმდევრულობის უზრუნველსაყოფად და კომპილატორის გამოყენებით პრობლემების კომპილაციის დროს გამოსავლენად. ასევე შეგიძლიათ შექმნათ თქვენი საკუთარი აბსტრაქციები შინაარსის მოდელირებისთვის და მისი გაზიარებისთვის მიზნებსა და პროექტებს შორის.

როდესაც თქვენი პროექტი გენერირდება, Tuist სინთეზირებს ამ ფაილების შინაარსს და ჩაწერს მათ `Derived` დირექტორიაში, იმ დირექტორიის მიმართებით, რომელიც შეიცავს პროექტს, სადაც ისინი განსაზღვრულია.

> [!TIP]
> **დაამატეთ Derived დირექტორია .gitignore-ში**
>
> ჩვენ გირჩევთ `Derived` დირექტორიის დამატებას თქვენი პროექტის `.gitignore` ფაილში.


## ბანდლის აქსესორები {#bundle-accessors}

Tuist სინთეზირებს ინტერფეისს იმ ბანდლზე წვდომისთვის, რომელიც შეიცავს მიზნის რესურსებს.

### Swift {#swift}

მიზანი შეიცავს `Bundle` ტიპის გაფართოებას, რომელიც ავლენს ბანდლს:

```swift
let bundle = Bundle.module
```

### Objective-C {#objectivec}

Objective-C-ში მიიღებთ `{Target}Resources` ინტერფეისს ბანდლზე წვდომისთვის:

```objc
NSBundle *bundle = [MyFeatureResources bundle];
```

> [!WARNING]
> **შეზღუდვა შიდა მიზნებთან**
>
> ამჟამად, Tuist არ ქმნის რესურსების ბანდლის აქსესორებს შიდა მიზნებისთვის, რომლებიც შეიცავს მხოლოდ Objective-C წყაროებს. ეს არის ცნობილი შეზღუდვა, რომელიც ფიქსირდება [პრობლემა #6456](https://github.com/tuist/tuist/issues/6456)-ში.


> [!TIP]
> **ბიბლიოთეკებში რესურსების მხარდაჭერა ბანდლების მეშვეობით**
>
> თუ მიზნის პროდუქტი, მაგალითად ბიბლიოთეკა, არ მხარდაჭერს რესურსებს, Tuist ჩართავს რესურსებს `bundle` პროდუქტის ტიპის მიზანში, რაც უზრუნველყოფს მათ მოხვედრას საბოლოო პროდუქტში და ინტერფეისის სწორ ბანდლზე მითითებას. ეს სინთეზირებული ბანდლები ავტომატურად ინიშნება `tuist:synthesized` თეგით და იღებენ ყველა თეგს მშობელი მიზნიდან, რაც საშუალებას გაძლევთ მიმართოთ მათ <.localized_link href="/guides/features/projects/metadata-tags#system-tags">ქეშის პროფილებში</.localized_link>.


## რესურსების აქსესორები {#resource-accessors}

რესურსები იდენტიფიცირდება მათი სახელითა და გაფართოებით სტრიngების გამოყენებით. ეს არ არის იდეალური, რადგან შეცდომა არ ვლინდება კომპილაციის დროს და შეიძლება გამოიწვიოს კრაშები რელიზში. ამის თავიდან ასაცილებლად, Tuist აინტეგრირებს [SwiftGen](https://github.com/SwiftGen/SwiftGen)-ს პროექტის გენერაციის პროცესში, რათა სინთეზირდეს ინტერფეისი რესურსებზე წვდომისთვის. ამის წყალობით, შეგიძლიათ დარწმუნებით მიუწვდეთ რესურსებს, კომპილატორის გამოყენებით ნებისმიერი პრობლემის გამოსავლენად.

Tuist შეიცავს [შაბლონებს](https://github.com/tuist/tuist/tree/main/cli/Sources/TuistGenerator/Templates) შემდეგი ტიპის რესურსებისთვის აქსესორების სინთეზირებისთვის ნაგულისხმევად:

| რესურსის ტიპი | სინთეზირებული ფაილი |
| --- | ---- |
| სურათები და ფერები | `Assets+{Target}.swift` |
| სტრიngები | `Strings+{Target}.swift` |
| Plist-ები | `{NameOfPlist}.swift` |
| შრიფტები | `Fonts+{Target}.swift` |
| ფაილები | `Files+{Target}.swift` |

> შენიშვნა: შეგიძლიათ გათიშოთ რესურსების აქსესორების სინთეზირება პროექტის დონეზე `disableSynthesizedResourceAccessors` ოფციის გადაცემით პროექტის პარამეტრებში.

### მორგებული შაბლონები {#custom-templates}

თუ გსურთ უზრუნველყოთ თქვენი საკუთარი შაბლონები სხვა ტიპის რესურსებისთვის აქსესორების სინთეზირებისთვის, რაც უნდა იყოს მხარდაჭერილი [SwiftGen](https://github.com/SwiftGen/SwiftGen)-ის მიერ, შეგიძლიათ შექმნათ ისინი `Tuist/ResourceSynthesizers/{name}.stencil` მისამართზე, სადაც სახელი არის რესურსის camel-case ვერსია.

| რესურსი | შაბლონის სახელი |
| --- | --- |
| სტრიngები | `Strings.stencil` |
| რესურსები | `Assets.stencil` |
| plist-ები | `Plists.stencil` |
| შრიფტები | `Fonts.stencil` |
| coreData | `CoreData.stencil` |
| interfaceBuilder | `InterfaceBuilder.stencil` |
| json | `JSON.stencil` |
| yaml | `YAML.stencil` |
| ფაილები | `Files.stencil` |

თუ გსურთ დააკონფიგურიროთ რესურსების ტიპების სია, რომელთათვისაც უნდა სინთეზირდეს აქსესორები, შეგიძლიათ გამოიყენოთ `Project.resourceSynthesizers` თვისება და გადასცეთ სასურველი რესურსების სინთეზატორების სია:

```swift
let project = Project(name: "App", resourceSynthesizers: [.strings(), .fonts()])
```

> [!NOTE]
> **მითითება**
>
> შეგიძლიათ ნახოთ [ეს მაგალითი](https://github.com/tuist/tuist/tree/main/examples/xcode/generated_ios_app_with_templates), რათა იხილოთ, თუ როგორ გამოიყენოთ მორგებული შაბლონები რესურსების აქსესორების სინთეზირებისთვის.
