# სინთეზირებული ფაილები {#synthesized-files}

Tuist-ს შეუძლია გენერაციის დროს შექმნას ფაილები და კოდი, რაც Xcode პროექტების მართვასა და მუშაობას ამარტივებს. ამ გვერდზე გაეცნობით ამ ფუნქციონალს და მის გამოყენებას თქვენს პროექტებში.

## მიზნის რესურსები {#target-resources}

Xcode პროექტები უჭერენ მხარს რესურსების დამატებას მიზნებში (targets). თუმცა, ეს გუნდებს რამდენიმე სირთულეს უქმნის, განსაკუთრებით მოდულურ პროექტებთან მუშაობისას, სადაც წყაროები და რესურსები ხშირად გადაადგილდება:

- **არათანმიმდევრული წვდომა შესრულების დროს**: რესურსების საბოლოო პროდუქტში განთავსების ადგილი და მათზე წვდომის გზა დამოკიდებულია მიზნის პროდუქტის ტიპზე. მაგალითად, თუ თქვენი მიზანი წარმოადგენს აპლიკაციას, რესურსები კოპირდება აპლიკაციის ბანდლში. ეს იწვევს ისეთ კოდს, რომელიც რესურსებზე წვდომისას ეყრდნობა ბანდლის სტრუქტურის ვარაუდებს, რაც არ არის სასურველი, რადგან ართულებს კოდის გაგებას და რესურსების გადაადგილებას.
- **პროდუქტები, რომლებიც არ უჭერენ მხარს რესურსებს**: არსებობს გარკვეული პროდუქტები, როგორიცაა სტატიკური ბიბლიოთეკები, რომლებიც არ არის ბანდლები და, შესაბამისად, არ უჭერენ მხარს რესურსებს. ამის გამო, თქვენ ან უნდა მიმართოთ სხვა ტიპის პროდუქტს, მაგალითად ჩარჩოებს (frameworks), რამაც შეიძლება გარკვეული ზედმეტი დატვირთვა დაამატოს თქვენს პროექტს ან აპლიკაციას. მაგალითად, სტატიკური ჩარჩოები სტატიკურად დაუკავშირდება საბოლოო პროდუქტს და საჭიროა აგების ფაზა (build phase), რათა მხოლოდ რესურსები დაკოპირდეს საბოლოო პროდუქტში. ან დინამიური ჩარჩოები, სადაც Xcode დააკოპირებს როგორც ბინარულ ფაილს, ასევე რესურსებს საბოლოო პროდუქტში, მაგრამ ეს გაზრდის თქვენი აპლიკაციის გაშვების დროს, რადგან ჩარჩო დინამიურად უნდა ჩაიტვირთოს.
- **მიდრეკილება შესრულების დროის შეცდომებისკენ**: რესურსები იდენტიფიცირდება მათი სახელითა და გაფართოებით (სტრიქონები). შესაბამისად, ნებისმიერი მათგანის ბეჭდვითი შეცდომა გამოიწვევს შესრულების დროის შეცდომას რესურსზე წვდომის მცდელობისას. ეს არ არის სასურველი, რადგან შეცდომა არ ფიქსირდება კომპილაციის დროს და შეიძლება გამოიწვიოს კრაში რელიზ ვერსიაში.

Tuist ზემოთ ჩამოთვლილ პრობლემებს წყვეტს **ბანდლებსა და რესურსებზე წვდომის ერთიანი ინტერფეისის სინთეზირებით**, რაც აბსტრაქციას უკეთებს იმპლემენტაციის დეტალებს.

> [!WARNING]
> **რეკომენდებული**
>
> მიუხედავად იმისა, რომ რესურსებზე წვდომა Tuist-ის მიერ სინთეზირებული ინტერფეისის მეშვეობით არ არის სავალდებულო, ჩვენ გირჩევთ მას, რადგან ის ამარტივებს კოდის გაგებას და რესურსების გადაადგილებას.


## რესურსები {#resources}

Tuist უზრუნველყოფს ინტერფეისებს ისეთი ფაილების შინაარსის აღსაწერად, როგორიცაა `Info.plist` ან უფლებამოსილებები (entitlements) Swift-ში. ეს სასარგებლოა მიზნებსა და პროექტებს შორის თანმიმდევრულობის უზრუნველსაყოფად და კომპილატორის გამოყენებით პრობლემების კომპილაციის დროს გამოსავლენად. ასევე შეგიძლიათ შექმნათ საკუთარი აბსტრაქციები შინაარსის მოდელირებისთვის და მის გასაზიარებლად მიზნებსა და პროექტებს შორის.

როდესაც თქვენი პროექტი გენერირდება, Tuist სინთეზირებს ამ ფაილების შინაარსს და ჩაწერს მათ `Derived` დირექტორიაში, პროექტის შემცველი დირექტორიის მიმართებით.

> [!TIP]
> **დაამატეთ Derived დირექტორია .gitignore-ში**
>
> ჩვენ გირჩევთ, დაამატოთ `Derived` დირექტორია თქვენი პროექტის `.gitignore` ფაილში.


## ბანდლის აქსესორები {#bundle-accessors}

Tuist სინთეზირებს ინტერფეისს ბანდლზე წვდომისთვის, რომელიც შეიცავს მიზნის რესურსებს.

### Swift {#swift}

მიზანი შეიცავს `Bundle` ტიპის გაფართოებას, რომელიც უზრუნველყოფს ბანდლზე წვდომას:

```swift
let bundle = Bundle.module
```

### Objective-C {#objectivec}

Objective-C-ში მიიღებთ ინტერფეისს `{Target}Resources` ბანდლზე წვდომისთვის:

```objc
NSBundle *bundle = [MyFeatureResources bundle];
```

> [!WARNING]
> **შეზღუდვა შიდა მიზნებთან**
>
> ამჟამად, Tuist არ ქმნის რესურსების ბანდლის აქსესორებს შიდა მიზნებისთვის, რომლებიც შეიცავს მხოლოდ Objective-C წყაროებს. ეს ცნობილი შეზღუდვაა, რომელიც ფიქსირდება [საქმე #6456-ში](https://github.com/tuist/tuist/issues/6456).


> [!TIP]
> **ბიბლიოთეკებში რესურსების მხარდაჭერა ბანდლების მეშვეობით**
>
> თუ მიზნის პროდუქტი, მაგალითად ბიბლიოთეკა, არ უჭერს მხარს რესურსებს, Tuist ჩართავს რესურსებს `bundle` პროდუქტის ტიპის მიზანში, რაც უზრუნველყოფს მათ საბოლოო პროდუქტში მოხვედრას და ინტერფეისის სწორ ბანდლზე მიმართვას. ეს სინთეზირებული ბანდლები ავტომატურად ინიშნება `tuist:synthesized` თეგით და მემკვიდრეობით იღებენ ყველა თეგს მშობელი მიზნიდან, რაც საშუალებას გაძლევთ მიმართოთ მათ <.localized_link href="/guides/features/projects/metadata-tags#system-tags">ქეშის პროფილებში</.localized_link>.


## რესურსების აქსესორები {#resource-accessors}

რესურსები იდენტიფიცირდება მათი სახელითა და გაფართოებით სტრიქონების გამოყენებით. ეს არ არის სასურველი, რადგან შეცდომა არ ფიქსირდება კომპილაციის დროს და შეიძლება გამოიწვიოს კრაში რელიზ ვერსიაში. ამის თავიდან ასაცილებლად, Tuist აინტეგრირებს [SwiftGen](https://github.com/SwiftGen/SwiftGen)-ს პროექტის გენერაციის პროცესში, რათა სინთეზირდეს ინტერფეისი რესურსებზე წვდომისთვის. ამის წყალობით, შეგიძლიათ დარწმუნებულად მიმართოთ რესურსებს, კომპილატორის გამოყენებით ნებისმიერი პრობლემის გამოსავლენად.

Tuist მოიცავს [შაბლონებს](https://github.com/tuist/tuist/tree/main/cli/Sources/TuistGenerator/Templates) შემდეგი ტიპის რესურსების აქსესორების სინთეზირებისთვის ნაგულისხმევად:

| რესურსის ტიპი | სინთეზირებული ფაილი |
| --- | ---- |
| სურათები და ფერები | `Assets+{Target}.swift` |
| სტრიქონები | `Strings+{Target}.swift` |
| Plist-ები | `{NameOfPlist}.swift` |
| ფონტები | `Fonts+{Target}.swift` |
| ფაილები | `Files+{Target}.swift` |

> შენიშვნა: შეგიძლიათ გათიშოთ რესურსების აქსესორების სინთეზირება პროექტის დონეზე `disableSynthesizedResourceAccessors` პარამეტრის გადაცემით პროექტის ოფციებში.

#### მორგებული შაბლონები {#custom-templates}

თუ გსურთ საკუთარი შაბლონების მიწოდება სხვა ტიპის რესურსების აქსესორების სინთეზირებისთვის, რაც უნდა იყოს მხარდაჭერილი [SwiftGen](https://github.com/SwiftGen/SwiftGen)-ის მიერ, შეგიძლიათ შექმნათ ისინი `Tuist/ResourceSynthesizers/{name}.stencil` მისამართზე, სადაც სახელი არის რესურსის camel-case ვერსია.

| რესურსი | შაბლონის სახელი |
| --- | --- |
| სტრიქონები | `Strings.stencil` |
| რესურსები | `Assets.stencil` |
| plist-ები | `Plists.stencil` |
| ფონტები | `Fonts.stencil` |
| coreData | `CoreData.stencil` |
| interfaceBuilder | `InterfaceBuilder.stencil` |
| json | `JSON.stencil` |
| yaml | `YAML.stencil` |
| ფაილები | `Files.stencil` |

თუ გსურთ დააკონფიგურიროთ რესურსების ტიპების სია, რომელთათვისაც უნდა სინთეზირდეს აქსესორები, შეგიძლიათ გამოიყენოთ `Project.resourceSynthesizers` თვისება და გადასცეთ სასურველი რესურსის სინთეზატორების სია:

```swift
let project = Project(resourceSynthesizers: [.string(), .fonts()])
```

> [!NOTE]
> **მითითება**
>
> შეგიძლიათ ნახოთ [ეს მაგალითი](https://github.com/tuist/tuist/tree/main/examples/xcode/generated_ios_app_with_templates), რათა იხილოთ, როგორ გამოვიყენოთ მორგებული შაბლონები რესურსებზე წვდომის აქსესორების სინთეზირებისთვის.
