# Swift-პაკეტის მიგრაცია {#migrate-a-swift-package}

Swift Package Manager წარმოიშვა, როგორც Swift-კოდის დამოკიდებულებების მენეჯერი, რომელმაც შემთხვევით აღმოაჩინა, რომ ის ასევე ხსნიდა პროექტების მართვის და სხვა პროგრამირების ენების, მაგალითად Objective-C-ის მხარდაჭერის პრობლემას. ვინაიდან ეს ინსტრუმენტი სხვა მიზნით იყო შექმნილი, მისი გამოყენება პროექტების მასშტაბური მართვისთვის შეიძლება რთული იყოს, რადგან მას აკლია ის მოქნილობა, შესრულება და შესაძლებლობები, რასაც Tuist გთავაზობთ. ეს კარგად არის აღწერილი სტატიაში [Scaling iOS at Bumble](https://medium.com/bumble-tech/scaling-ios-at-bumble-239e0fa009f2), რომელიც შეიცავს ცხრილს, სადაც შედარებულია Swift Package Manager-ის და ნატიური Xcode-პროექტების შესრულება:

<img style="max-width: 400px;" alt="ცხრილი, რომელიც ადარებს შესრულების დეგრადაციას SPM-ის გამოყენებისას ნატიურ Xcode-პროექტებთან შედარებით" src="/images/guides/start/migrate/performance-table.webp">

ხშირად ვხვდებით დეველოპერებს და ორგანიზაციებს, რომლებიც ეჭვქვეშ აყენებენ Tuist-ის საჭიროებას, რადგან Swift Package Manager-ს შეუძლია მსგავსი როლის შესრულება პროექტების მართვაში. ზოგიერთი იწყებს მიგრაციას, რათა მოგვიანებით აღმოაჩინოს, რომ მათი დეველოპერული გამოცდილება მნიშვნელოვნად გაუარესდა. მაგალითად, ფაილის სახელის შეცვლამ შეიძლება 15 წამი დასჭირდეს ხელახალი ინდექსაციისთვის. 15 წამი!

**გაურკვეველია, გახდის თუ არა Apple Swift Package Manager-ს მასშტაბური პროექტების მენეჯერს.** თუმცა, ჩვენ არ ვხედავთ ამის ნიშნებს. სინამდვილეში, საპირისპიროს ვხედავთ. ისინი იღებენ Xcode-ზე დაფუძნებულ გადაწყვეტილებებს, როგორიცაა მოხერხებულობის მიღწევა არაცხადი კონფიგურაციების მეშვეობით, რაც, <.localized_link href="/guides/features/projects/cost-of-convenience">როგორც იცით,</.localized_link> მასშტაბური გართულებების წყაროა. ჩვენ ვფიქრობთ, რომ Apple-მა უნდა დაუბრუნდეს პირველად პრინციპებს და გადახედოს ზოგიერთ გადაწყვეტილებას, რომელიც აზრიანი იყო დამოკიდებულებების მენეჯერისთვის, მაგრამ არა პროექტების მენეჯერისთვის, მაგალითად, კომპილირებადი ენის გამოყენება პროექტების განსაზღვრის ინტერფეისად.

> [!TIP]
> **SwiftPM, როგორც მხოლოდ დამოკიდებულებების მენეჯერი**
>
> Tuist Swift Package Manager-ს განიხილავს, როგორც დამოკიდებულებების მენეჯერს და ეს შესანიშნავი ინსტრუმენტია. ჩვენ ვიყენებთ მას დამოკიდებულებების გადასაწყვეტად და მათ ასაგებად. ჩვენ არ ვიყენებთ მას პროექტების განსაზღვრისთვის, რადგან ის ამისთვის არ არის შექმნილი. პირდაპირი შედარებისთვის იხილეთ [Swift Package Manager vs Tuist](https://tuist.dev/compare/swift-package-manager).


## მიგრაცია Swift Package Manager-დან Tuist-ზე {#migrating-from-swift-package-manager-to-tuist}

მსგავსებები Swift Package Manager-სა და Tuist-ს შორის მიგრაციის პროცესს მარტივს ხდის. მთავარი განსხვავება ის არის, რომ თქვენ განსაზღვრავთ თქვენს პროექტებს Tuist-ის DSL-ის გამოყენებით `Package.swift`-ის ნაცვლად.

ჯერ შექმენით `Project.swift` ფაილი თქვენი `Package.swift` ფაილის გვერდით. `Project.swift` ფაილი შეიცავს თქვენი პროექტის განსაზღვრებას. აქ არის `Project.swift` ფაილის მაგალითი, რომელიც განსაზღვრავს პროექტს ერთი სამიზნით (target):

```swift
import ProjectDescription

let project = Project(
    name: "App",
    targets: [
        .target(
            name: "App",
            destinations: .iOS,
            product: .app,
            bundleId: "dev.tuist.App",
            sources: ["Sources/**/*.swift"]*
        ),
    ]
)
```

რაღაცები, რაც უნდა გაითვალისწინოთ:

- **ProjectDescription**: `PackageDescription`-ის ნაცვლად, გამოიყენებთ `ProjectDescription`-ს.
- **Project:** `package` ინსტანსის ექსპორტის ნაცვლად, თქვენ გაიტანთ `project` ინსტანსს.
- **Xcode-ის ენა:** პრიმიტივები, რომლებსაც თქვენ იყენებთ თქვენი პროექტის განსაზღვრისთვის, ბაძავენ Xcode-ის ენას, ამიტომ თქვენ იპოვით სქემებს, სამიზნეებს (targets) და აგების ფაზებს (build phases) და სხვ.

შემდეგ შექმენით `Tuist.swift` ფაილი შემდეგი შინაარსით:

```swift
import ProjectDescription

let tuist = Tuist()
```

`Tuist.swift` შეიცავს თქვენი პროექტის კონფიგურაციას და მისი გზა (path) ემსახურება როგორც საცნობარო თქვენი პროექტის ფესვის (root) დასადგენად. შეგიძლიათ გადახედოთ დოკუმენტს <.localized_link href="/guides/features/projects/directory-structure">დირექტორიების სტრუქტურა</.localized_link>, რათა მეტი გაიგოთ Tuist-პროექტების სტრუქტურის შესახებ.

## პროექტის რედაქტირება {#editing-the-project}

შეგიძლიათ გამოიყენოთ <.localized_link href="/guides/features/projects/editing">`tuist edit`</.localized_link> პროექტის Xcode-ში რედაქტირებისთვის. ბრძანება შექმნის Xcode-პროექტს, რომლის გახსნაც და მუშაობის დაწყებაც შეგიძლიათ.

```bash
tuist edit
```

პროექტის ზომის მიხედვით, შეგიძლიათ განიხილოთ მისი გამოყენება ერთჯერადად ან ინკრემენტულად. ჩვენ გირჩევთ, დაიწყოთ მცირე პროექტით, რათა გაეცნოთ DSL-ს და სამუშაო პროცესს. ჩვენი რჩევა ყოველთვის არის, დაიწყოთ იმ სამიზნიდან (target), რომელზეც ყველაზე მეტად არიან დამოკიდებულნი, და ასწიოთ ზემოთ ძირითად სამიზნემდე.
