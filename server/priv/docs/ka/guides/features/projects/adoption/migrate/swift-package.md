# Swift პაკეტის მიგრაცია {#migrate-a-swift-package}

Swift Package Manager გამოჩნდა როგორც Swift კოდის დამოკიდებულობების მენეჯერი, რომელმაც შემთხვევით იპოვა თავი პროექტების მართვისა და Objective-C-ის მსგავსი სხვა პროგრამირების ენების მხარდაჭერის პრობლემის გადაჭრაში. ვინაიდან ინსტრუმენტი სხვა მიზნით იყო შექმნილი, მისი გამოყენება პროექტების მასშტაბური მართვისთვის რთულია, რადგან მას აკლია ის მოქნილობა, წარმადობა და შესაძლებლობები, რასაც Tuist გთავაზობთ. ეს კარგად არის აღწერილი [Scaling iOS at Bumble](https://medium.com/bumble-tech/scaling-ios-at-bumble-239e0fa009f2) სტატიაში, რომელიც შეიცავს ქვემოთ მოცემულ ცხრილს Swift Package Manager-ისა და ნატიური Xcode პროექტების წარმადობის შედარებით:

<img style="max-width: 400px;" alt="ცხრილი, რომელიც ადარებს წარმადობის გაუარესებას SPM-ის გამოყენებისას ნატიურ Xcode პროექტებთან შედარებით" src="/images/guides/start/migrate/performance-table.webp">

ხშირად ვხვდებით დეველოპერებსა და ორგანიზაციებს, რომლებიც ეჭვქვეშ აყენებენ Tuist-ის საჭიროებას, რადგან Swift Package Manager-ს შეუძლია პროექტების მართვის მსგავსი როლის შესრულება. ზოგიერთი იწყებს მიგრაციას, მაგრამ მოგვიანებით ხვდება, რომ დეველოპერის გამოცდილება მნიშვნელოვნად გაუარესდა. მაგალითად, ფაილის სახელის შეცვლამ შეიძლება 15 წამამდე დაიკავოს ხელახალი ინდექსაციისთვის. 15 წამი!

**არ არის ცნობილი, შექმნის თუ არა Apple Swift Package Manager-ს მასშტაბური პროექტების მენეჯერად.** თუმცა, ჩვენ არ ვხედავთ ამის ნიშნებს. სინამდვილეში, საპირისპიროს ვაკვირდებით. ისინი იღებენ Xcode-ზე დაფუძნებულ გადაწყვეტილებებს, როგორიცაა მოხერხებულობის მიღწევა არაცხადი კონფიგურაციების მეშვეობით, რაც, <.localized_link href="/guides/features/projects/cost-of-convenience">როგორც იცით,</.localized_link> მასშტაბური პრობლემების წყაროა. ჩვენ ვფიქრობთ, რომ Apple-ს უნდა დაუბრუნდეს პირველად პრინციპებს და გადახედოს ზოგიერთ გადაწყვეტილებას, რომელიც გამართლებული იყო დამოკიდებულობების მენეჯერისთვის, მაგრამ არა პროექტების მენეჯერისთვის, მაგალითად, კომპილირებადი ენის გამოყენება პროექტების განსაზღვრის ინტერფეისად.

> [!TIP]
> **SwiftPM მხოლოდ დამოკიდებულობების მენეჯერად**
>
> Tuist Swift Package Manager-ს განიხილავს როგორც დამოკიდებულობების მენეჯერს და ეს შესანიშნავია. ჩვენ ვიყენებთ მას დამოკიდებულობების გადასაწყვეტად და ასაგებად. ჩვენ არ ვიყენებთ მას პროექტების განსაზღვრისთვის, რადგან ის ამისთვის არ არის შექმნილი. პირდაპირი შედარებისთვის იხილეთ [Swift Package Manager vs Tuist](https://tuist.dev/compare/swift-package-manager).


## მიგრაცია Swift Package Manager-დან Tuist-ზე {#migrating-from-swift-package-manager-to-tuist}

მსგავსებები Swift Package Manager-სა და Tuist-ს შორის მიგრაციის პროცესს მარტივს ხდის. მთავარი განსხვავება ის არის, რომ პროექტებს განსაზღვრავთ Tuist-ის DSL-ის გამოყენებით `Package.swift`-ის ნაცვლად.

ჯერ შექმენით `Project.swift` ფაილი თქვენი `Package.swift` ფაილის გვერდით. `Project.swift` ფაილი შეიცავს თქვენი პროექტის განსაზღვრებას. აქ არის `Project.swift` ფაილის მაგალითი, რომელიც განსაზღვრავს პროექტს ერთი სამიზნით:

```swift
import ProjectDescription

let project = Project(
    name: "App",
    targets: [
        .target(
            name: "App",
            destinations: .iOS,
            product: .app,
            bundleId: "dev.tuist.App",
            sources: ["Sources/**/*.swift"]*
        ),
    ]
)
```

რაღაცები, რაც უნდა გაითვალისწინოთ:

- **ProjectDescription**: `PackageDescription`-ის ნაცვლად გამოიყენებთ `ProjectDescription`-ს.
- **Project:** `package` ინსტანსის ექსპორტის ნაცვლად, თქვენ აექსპორტებთ `project` ინსტანსს.
- **Xcode ენა:** პრიმიტივები, რომლებსაც პროექტის განსაზღვრისთვის იყენებთ, ბაძავენ Xcode-ის ენას, ამიტომ იპოვით სქემებს, სამიზნეებს და აგების ფაზებს, სხვებთან ერთად.

შემდეგ შექმენით `Tuist.swift` ფაილი შემდეგი შინაარსით:

```swift
import ProjectDescription

let tuist = Tuist()
```

`Tuist.swift` შეიცავს თქვენი პროექტის კონფიგურაციას და მისი გზა ემსახურება როგორც მითითება თქვენი პროექტის ფესვის დასადგენად. შეგიძლიათ ნახოთ <.localized_link href="/guides/features/projects/directory-structure">დირექტორიის სტრუქტურა</.localized_link> დოკუმენტი Tuist პროექტების სტრუქტურის შესახებ მეტი ინფორმაციისთვის.

## პროექტის რედაქტირება {#editing-the-project}

შეგიძლიათ გამოიყენოთ <.localized_link href="/guides/features/projects/editing">`tuist edit`</.localized_link> პროექტის Xcode-ში რედაქტირებისთვის. ბრძანება შექმნის Xcode პროექტს, რომლის გახსნაც და მუშაობის დაწყებაც შეგიძლიათ.

```bash
tuist edit
```

პროექტის ზომის მიხედვით, შეიძლება განიხილოთ მისი ერთჯერადი ან ინკრემენტული გამოყენება. ჩვენ გირჩევთ, დაიწყოთ მცირე პროექტით, რათა გაეცნოთ DSL-სა და სამუშაო ნაკადს. ჩვენი რჩევა ყოველთვის არის, დაიწყოთ ყველაზე მეტად დამოკიდებული სამიზნიდან და იმუშაოთ ზედა დონის სამიზნემდე.
