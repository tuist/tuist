# Swift პაკეტის მიგრაცია {#migrate-a-swift-package}

Swift Package Manager წარმოიშვა როგორც Swift კოდის დამოკიდებულობების მენეჯერი, რომელმაც შემთხვევით აღმოაჩინა თავი პროექტების მართვისა და სხვა პროგრამირების ენების, მაგალითად Objective-C-ის, მხარდაჭერის ამოცანის გადაჭრაში. რადგან ინსტრუმენტი სხვა მიზნით იყო შექმნილი, მასშტაბური პროექტების მართვა შეიძლება რთული იყოს, რადგან მას აკლია ის მოქნილობა, შესრულება და სიმძლავრე, რასაც Tuist გთავაზობთ. ეს კარგად არის ასახული [Scaling iOS at Bumble](https://medium.com/bumble-tech/scaling-ios-at-bumble-239e0fa009f2) სტატიაში, რომელიც შეიცავს ქვემოთ მოცემულ ცხრილს Swift Package Manager-ისა და ნატიური Xcode პროექტების შესრულების შედარებით:

<img style="max-width: 400px;" alt="ცხრილი, რომელიც ადარებს შესრულების გაუარესებას SPM-ის გამოყენებისას ნატიურ Xcode პროექტებთან შედარებით" src="/images/guides/start/migrate/performance-table.webp">

ხშირად ვაწყდებით დეველოპერებსა და ორგანიზაციებს, რომლებიც ეჭვქვეშ აყენებენ Tuist-ის საჭიროებას, რადგან Swift Package Manager-ს შეუძლია მსგავსი როლის შესრულება პროექტების მართვაში. ზოგიერთი მიგრაციას იწყებს, რათა მოგვიანებით აღმოაჩინოს, რომ დეველოპერის გამოცდილება მნიშვნელოვნად გაუარესდა. მაგალითად, ფაილის სახელის შეცვლამ შეიძლება 15 წამი დასჭირდეს ხელახლა ინდექსაციისთვის. 15 წამი!

**არ არის ცნობილი, გახდის თუ არა Apple Swift Package Manager-ს მასშტაბებისთვის განკუთვნილ პროექტების მენეჯერად.** თუმცა, ჩვენ არ ვხედავთ ნიშნებს, რომ ეს ხდება. სინამდვილეში, საპირისპიროს ვხედავთ. ისინი იღებენ Xcode-ზე დაფუძნებულ გადაწყვეტილებებს, როგორიცაა მოხერხებულობის მიღწევა იმპლიციტური კონფიგურაციების მეშვეობით, რაც, <.localized_link href="/guides/features/projects/cost-of-convenience">როგორც იცით,</.localized_link> მასშტაბებზე გართულებების წყაროა. ჩვენ ვფიქრობთ, რომ Apple-მა უნდა დაუბრუნდეს პირველად პრინციპებს და გადახედოს ზოგიერთ გადაწყვეტილებას, რომელიც აზრიანი იყო დამოკიდებულობების მენეჯერისთვის, მაგრამ არა პროექტების მენეჯერისთვის, მაგალითად, კომპილირებადი ენის გამოყენება პროექტების განსაზღვრის ინტერფეისად.

> [!TIP]
> **SwiftPM, როგორც მხოლოდ დამოკიდებულობების მენეჯერი**
>
> Tuist Swift Package Manager-ს განიხილავს როგორც დამოკიდებულობების მენეჯერს და ეს შესანიშნავი ინსტრუმენტია. ჩვენ ვიყენებთ მას დამოკიდებულობების ამოსაცნობად და ასაგებად. ჩვენ არ ვიყენებთ მას პროექტების განსაზღვრისთვის, რადგან ის ამისთვის არ არის შექმნილი.


## მიგრაცია Swift Package Manager-დან Tuist-ზე {#migrating-from-swift-package-manager-to-tuist}

მსგავსებები Swift Package Manager-სა და Tuist-ს შორის მიგრაციის პროცესს მარტივს ხდის. მთავარი განსხვავება ის არის, რომ პროექტებს განსაზღვრავთ Tuist-ის DSL-ის გამოყენებით `Package.swift`-ის ნაცვლად.

ჯერ შექმენით `Project.swift` ფაილი თქვენი `Package.swift` ფაილის გვერდით. `Project.swift` ფაილი შეიცავს თქვენი პროექტის განსაზღვრებას. აქ არის `Project.swift` ფაილის მაგალითი, რომელიც განსაზღვრავს პროექტს ერთი სამიზნით:

```swift
import ProjectDescription

let project = Project(
    name: "App",
    targets: [
        .target(
            name: "App",
            destinations: .iOS,
            product: .app,
            bundleId: "dev.tuist.App",
            sources: ["Sources/**/*.swift"]*
        ),
    ]
)
```

რაღაცები, რაც უნდა გაითვალისწინოთ:

- **ProjectDescription**: `PackageDescription`-ის ნაცვლად, გამოიყენებთ `ProjectDescription`-ს.
- **პროექტი:** `package` ეგზემპლარის ექსპორტის ნაცვლად, ექსპორტს გაუკეთებთ `project` ეგზემპლარს.
- **Xcode ენა:** პრიმიტივები, რომლებსაც იყენებთ პროექტის განსაზღვრისთვის, ბაძავენ Xcode-ის ენას, ამიტომ იპოვით სქემებს, სამიზნეებს და აგების ფაზებს, სხვათა შორის.

შემდეგ შექმენით `Tuist.swift` ფაილი შემდეგი შინაარსით:

```swift
import ProjectDescription

let tuist = Tuist()
```

`Tuist.swift` შეიცავს თქვენი პროექტის კონფიგურაციას და მისი გზა ემსახურება როგორც მითითება თქვენი პროექტის ფესვის დასადგენად. შეგიძლიათ ნახოთ <.localized_link href="/guides/features/projects/directory-structure">დირექტორიის სტრუქტურა</.localized_link> დოკუმენტი, რათა მეტი გაიგოთ Tuist პროექტების სტრუქტურის შესახებ.

## პროექტის რედაქტირება {#editing-the-project}

შეგიძლიათ გამოიყენოთ <.localized_link href="/guides/features/projects/editing">`tuist edit`</.localized_link> პროექტის Xcode-ში რედაქტირებისთვის. ბრძანება შექმნის Xcode პროექტს, რომლის გახსნაც და მუშაობის დაწყებაც შეგიძლიათ.

```bash
tuist edit
```

პროექტის ზომის მიხედვით, შეგიძლიათ განიხილოთ მისი გამოყენება ერთჯერადად ან ინკრემენტულად. ჩვენ გირჩევთ, დაიწყოთ მცირე პროექტით, რათა გაეცნოთ DSL-სა და სამუშაო პროცესს. ჩვენი რჩევა ყოველთვის არის, დაიწყოთ ყველაზე მეტად დამოკიდებული სამიზნიდან და იმუშაოთ ზედა დონის სამიზნემდე.
