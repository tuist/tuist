# Swift-პაკეტის მიგრაცია {#migrate-a-swift-package}

Swift Package Manager წარმოიშვა როგორც Swift-კოდის დამოკიდებულებების მენეჯერი, რომელმაც შემთხვევით იპოვა თავი პროექტების მართვისა და სხვა პროგრამირების ენების, მაგალითად Objective-C-ის მხარდაჭერის პრობლემის გადაჭრის პროცესში. რადგან ეს ინსტრუმენტი სხვა მიზნით იყო შექმნილი, მასშტაბური პროექტების მართვა შეიძლება რთული აღმოჩნდეს, რადგან მას აკლია ის მოქნილობა, შესრულება და შესაძლებლობები, რომლებსაც Tuist გთავაზობთ. ეს კარგად არის ასახული სტატიაში [Scaling iOS at Bumble](https://medium.com/bumble-tech/scaling-ios-at-bumble-239e0fa009f2), რომელიც შეიცავს ქვემოთ მოყვანილ ცხრილს Swift Package Manager-ისა და ნატიური Xcode-პროექტების შესრულების შედარებით:

<img style="max-width: 400px;" alt="ცხრილი, რომელიც ადარებს შესრულების დეგრადაციას SPM-ის გამოყენებისას ნატიურ Xcode-პროექტებთან შედარებით" src="/images/guides/start/migrate/performance-table.webp">

ხშირად ვხვდებით დეველოპერებსა და ორგანიზაციებს, რომლებიც ეჭვქვეშ აყენებენ Tuist-ის საჭიროებას, იმის გათვალისწინებით, რომ Swift Package Manager-ს შეუძლია მსგავსი როლის შესრულება პროექტების მართვაში. ზოგიერთი მიგრაციას იწყებს, რათა მოგვიანებით აღმოაჩინოს, რომ მათი დეველოპერული გამოცდილება მნიშვნელოვნად გაუარესდა. მაგალითად, ფაილის სახელის შეცვლამ შეიძლება 15 წამამდე დასჭირდეს ხელახლა ინდექსაციისთვის. 15 წამი!

**გაურკვეველია, შექმნის თუ არა Apple Swift Package Manager-ს მასშტაბური პროექტების მენეჯერად.** თუმცა, ჩვენ არ ვხედავთ ამის ნიშნებს. სინამდვილეში, საპირისპიროს ვხედავთ. ისინი იღებენ Xcode-ზე დაფუძნებულ გადაწყვეტილებებს, მაგალითად, მოხერხებულობის მიღწევას არაცხადი კონფიგურაციების მეშვეობით, რაც, <.localized_link href="/guides/features/projects/cost-of-convenience">როგორც შესაძლოა იცით,</.localized_link> მასშტაბირებისას სირთულეების წყაროა. ჩვენ ვფიქრობთ, რომ Apple-ს დასჭირდება პირველად პრინციპებთან დაბრუნება და ზოგიერთი გადაწყვეტილების გადახედვა, რომლებსაც აზრი ჰქონდა დამოკიდებულებების მენეჯერისთვის, მაგრამ არა პროექტების მენეჯერისთვის, მაგალითად, კომპილირებადი ენის გამოყენება ინტერფეისად პროექტების განსაზღვრისთვის.

> [!TIP]
> **Spm მხოლოდ როგორც დამოკიდებულებების მენეჯერი**
>
> Tuist Swift Package Manager-ს განიხილავს როგორც დამოკიდებულებების მენეჯერს და ეს შესანიშნავი ინსტრუმენტია. ჩვენ ვიყენებთ მას დამოკიდებულებების გადასაწყვეტად და მათ ასაგებად. ჩვენ არ ვიყენებთ მას პროექტების განსაზღვრისთვის, რადგან ის ამისთვის არ არის შექმნილი.


## მიგრაცია Swift Package Manager-დან Tuist-ზე {#migrating-from-swift-package-manager-to-tuist}

მსგავსებები Swift Package Manager-სა და Tuist-ს შორის მიგრაციის პროცესს მარტივს ხდის. მთავარი განსხვავება ის არის, რომ თქვენ განსაზღვრავთ თქვენს პროექტებს Tuist-ის DSL-ის გამოყენებით `Package.swift`-ის ნაცვლად.

ჯერ შექმენით `Project.swift` ფაილი თქვენი `Package.swift` ფაილის გვერდით. `Project.swift` ფაილი შეიცავს თქვენი პროექტის განსაზღვრებას. აქ არის `Project.swift` ფაილის მაგალითი, რომელიც განსაზღვრავს პროექტს ერთი სამიზნით:

```swift
import ProjectDescription

let project = Project(
    name: "App",
    targets: [
        .target(
            name: "App",
            destinations: .iOS,
            product: .app,
            bundleId: "dev.tuist.App",
            sources: ["Sources/**/*.swift"]*
        ),
    ]
)
```

რამდენიმე რამ, რაც უნდა გაითვალისწინოთ:

- **ProjectDescription**: `PackageDescription`-ის გამოყენების ნაცვლად, გამოიყენებთ `ProjectDescription`-ს.
- **Project:** `package` ეგზემპლარის ექსპორტის ნაცვლად, თქვენ ექსპორტს გაუკეთებთ `project` ეგზემპლარს.
- **Xcode-ის ენა:** პრიმიტივები, რომლებსაც თქვენ იყენებთ თქვენი პროექტის განსაზღვრისთვის, ბაძავენ Xcode-ის ენას, ამიტომ თქვენ იპოვით სქემებს, სამიზნეებს და აგების ფაზებს, სხვათა შორის.

შემდეგ შექმენით `Tuist.swift` ფაილი შემდეგი შინაარსით:

```swift
import ProjectDescription

let tuist = Tuist()
```

`Tuist.swift` შეიცავს თქვენი პროექტის კონფიგურაციას და მისი გზა ემსახურება როგორც მითითება თქვენი პროექტის ფესვის დასადგენად. შეგიძლიათ ნახოთ დოკუმენტი <.localized_link href="/guides/features/projects/directory-structure">დირექტორიის სტრუქტურა</.localized_link>, რათა მეტი გაიგოთ Tuist-პროექტების სტრუქტურის შესახებ.

## პროექტის რედაქტირება {#editing-the-project}

შეგიძლიათ გამოიყენოთ <.localized_link href="/guides/features/projects/editing">`tuist edit`</.localized_link> პროექტის Xcode-ში რედაქტირებისთვის. ბრძანება შექმნის Xcode-პროექტს, რომლის გახსნაც და მუშაობის დაწყებაც შეგიძლიათ.

```bash
tuist edit
```

პროექტის ზომის მიხედვით, შეგიძლიათ განიხილოთ მისი გამოყენება ერთჯერადად ან ინკრემენტულად. ჩვენ გირჩევთ დაიწყოთ მცირე პროექტით, რათა გაეცნოთ DSL-ს და სამუშაო პროცესს. ჩვენი რჩევაა ყოველთვის დაიწყოთ ყველაზე მეტად დამოკიდებული სამიზნიდან და იმუშაოთ ზედა დონის სამიზნემდე.
