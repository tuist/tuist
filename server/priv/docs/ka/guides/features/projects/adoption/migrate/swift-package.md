# Swift-პაკეტის მიგრაცია {#migrate-a-swift-package}

Swift Package Manager წარმოიშვა როგორც Swift-კოდის დამოკიდებულებების მენეჯერი, რომელმაც შემთხვევით აღმოაჩინა თავი პროექტების მართვისა და სხვა პროგრამირების ენების, მაგალითად Objective-C-ის მხარდაჭერის ამოცანის გადაჭრაში. ვინაიდან ინსტრუმენტი სხვა მიზნით იყო შექმნილი, მისი გამოყენება პროექტების მასშტაბური მართვისთვის რთული შეიძლება იყოს, რადგან მას აკლია ის მოქნილობა, შესრულება და შესაძლებლობები, რასაც Tuist გთავაზობთ. ეს კარგად არის ასახული სტატიაში [Scaling iOS at Bumble](https://medium.com/bumble-tech/scaling-ios-at-bumble-239e0fa009f2), რომელიც შეიცავს შემდეგ ცხრილს Swift Package Manager-ისა და ნატიური Xcode-პროექტების შესრულების შედარებით:

<img style="max-width: 400px;" alt="ცხრილი, რომელიც ადარებს შესრულების გაუარესებას SPM-ის გამოყენებისას ნატიურ Xcode-პროექტებთან შედარებით" src="/images/guides/start/migrate/performance-table.webp">

ხშირად გვხვდება დეველოპერები და ორგანიზაციები, რომლებიც ეჭვის ქვეშ აყენებენ Tuist-ის საჭიროებას, ვინაიდან Swift Package Manager-ს შეუძლია მსგავსი როლის შესრულება პროექტების მართვაში. ზოგიერთი იწყებს მიგრაციას, რათა მოგვიანებით აღმოაჩინოს, რომ მათი დეველოპერული გამოცდილება მნიშვნელოვნად გაუარესდა. მაგალითად, ფაილის სახელის შეცვლამ შეიძლება 15 წამამდე დაიკავოს ხელახლა ინდექსაციისთვის. 15 წამი!

**გაურკვეველია, შექმნის თუ არა Apple Swift Package Manager-ს მასშტაბური პროექტების მენეჯერად.** თუმცა, ჩვენ არ ვხედავთ რაიმე ნიშანს, რომ ეს ხდება. სინამდვილეში, პირიქით ვხედავთ. ისინი იღებენ Xcode-ზე დაფუძნებულ გადაწყვეტილებებს, როგორიცაა მოხერხებულობის მიღწევა არაცხადი კონფიგურაციების მეშვეობით, რაც, <.localized_link href="/guides/features/projects/cost-of-convenience">როგორც შეიძლება იცოდეთ,</.localized_link> მასშტაბურობისას სირთულეების წყაროა. ჩვენ ვფიქრობთ, რომ Apple-ს დასჭირდება პირველ პრინციპებთან დაბრუნება და ზოგიერთი გადაწყვეტილების გადახედვა, რომლებსაც აზრი ჰქონდა დამოკიდებულებების მენეჯერისთვის, მაგრამ არა პროექტების მენეჯერისთვის, მაგალითად, კომპილირებადი ენის გამოყენება ინტერფეისად პროექტების განსაზღვრისთვის.

> [!TIP]
> **SwiftPM მხოლოდ დამოკიდებულებების მენეჯერად**
>
> Tuist Swift Package Manager-ს განიხილავს როგორც დამოკიდებულებების მენეჯერს და ის შესანიშნავია. ჩვენ ვიყენებთ მას დამოკიდებულებების ამოსაცნობად და მათ ასაგებად. ჩვენ არ ვიყენებთ მას პროექტების განსაზღვრისთვის, რადგან ის ამისთვის არ არის შექმნილი. პირდაპირი შედარებისთვის, იხილეთ [Swift Package Manager vs Tuist](https://tuist.dev/compare/swift-package-manager).


## მიგრაცია Swift Package Manager-დან Tuist-ზე {#migrating-from-swift-package-manager-to-tuist}

მსგავსებები Swift Package Manager-სა და Tuist-ს შორის მიგრაციის პროცესს მარტივს ხდის. მთავარი განსხვავება ის არის, რომ პროექტებს განსაზღვრავთ Tuist-ის DSL-ის გამოყენებით `Package.swift`-ის ნაცვლად.

ჯერ შექმენით `Project.swift` ფაილი თქვენი `Package.swift` ფაილის გვერდით. `Project.swift` ფაილი შეიცავს თქვენი პროექტის განსაზღვრებას. აქ არის `Project.swift` ფაილის მაგალითი, რომელიც განსაზღვრავს პროექტს ერთი სამიზნით:

```swift
import ProjectDescription

let project = Project(
    name: "App",
    targets: [
        .target(
            name: "App",
            destinations: .iOS,
            product: .app,
            bundleId: "dev.tuist.App",
            sources: ["Sources/**/*.swift"]*
        ),
    ]
)
```

რამდენიმე რამ, რაზეც ყურადღება უნდა მიაქციოთ:

- **ProjectDescription**: `PackageDescription`-ის გამოყენების ნაცვლად, გამოიყენებთ `ProjectDescription`-ს.
- **Project:** `package` ეგზემპლარის ექსპორტის ნაცვლად, ექსპორტს გაუკეთებთ `project` ეგზემპლარს.
- **Xcode language:** პრიმიტივები, რომლებსაც იყენებთ პროექტის განსაზღვრისთვის, ბაძავენ Xcode-ის ენას, ამიტომ იპოვით სქემებს, სამიზნეებს და აგების ეტაპებს, სხვებთან ერთად.

შემდეგ შექმენით `Tuist.swift` ფაილი შემდეგი შინაარსით:

```swift
import ProjectDescription

let tuist = Tuist()
```

`Tuist.swift` შეიცავს თქვენი პროექტის კონფიგურაციას და მისი გზა ემსახურება როგორც მითითება თქვენი პროექტის ფესვის დასადგენად. შეგიძლიათ ნახოთ დოკუმენტი <.localized_link href="/guides/features/projects/directory-structure">დირექტორიის სტრუქტურა</.localized_link> Tuist-პროექტების სტრუქტურის შესახებ მეტის გასაგებად.

## პროექტის რედაქტირება {#editing-the-project}

შეგიძლიათ გამოიყენოთ <.localized_link href="/guides/features/projects/editing">`tuist edit`</.localized_link> პროექტის Xcode-ში რედაქტირებისთვის. ბრძანება შექმნის Xcode-პროექტს, რომლის გახსნაც და მუშაობის დაწყებაც შეგიძლიათ.

```bash
tuist edit
```

პროექტის ზომის მიხედვით, შეიძლება განიხილოთ მისი გამოყენება ერთჯერადად ან ინკრემენტულად. ჩვენ გირჩევთ დაიწყოთ მცირე პროექტით, რათა გაეცნოთ DSL-სა და სამუშაო ნაკადს. ჩვენი რჩევა ყოველთვის არის დაიწყოთ ყველაზე მეტად დამოკიდებული სამიზნიდან და იმუშაოთ ზედა დონის სამიზნემდე.
