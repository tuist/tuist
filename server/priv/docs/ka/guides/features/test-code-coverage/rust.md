# Rust-ის კოდის დაფარვა {#rust-code-coverage}

კოდის დაფარვა გაჩვენებთ, თქვენი ტესტების მიერ შესრულებულ კოდის სტრიქონებს. Tuist ზომავს ხაზოვან დაფარვას ყოველი `cargo test` გაშვებისთვის LLVM-ის წყაროზე დაფუძნებული დაფარვის გამოყენებით და აერთიანებს კომიტის გაშვებებს ერთ მაჩვენებლად — პროექტის, თითოეული პაკეტისა და ფაილის მიხედვით. დაშბორდის **კოდის დაფარვა** გვერდი აჩვენებს მას კომიტების მიხედვით და როგორც ტრენდს თითოეული ბრენჩისთვის.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - მიჰყევით <.localized_link href="/guides/get-started/rust-project">Rust-ის პროექტის მოწყობას</.localized_link>
> - თქვენი Rust-ის ინსტრუმენტების ჯაჭვის LLVM-ის ინსტრუმენტები (`llvm-tools`). Tuist ამონტაჟებს მათ rustup-ის მიერ მართულ ინსტრუმენტების ჯაჭვში.
> - თქვენი პროექტი Git-ის რეპოზიტორიაში

## მოწყობა {#setup}

### დაფარვის ჩართვა {#turn-coverage-on}

დაამატეთ ეს სამუშაო სივრცის ძირეულ `Cargo.toml`-ში:

```toml
[workspace.metadata.tuist.test_insights.coverage]
upload = true
```

თუ Tuist-ს ნაცვლად `tuist.toml`-ში აკონფიგურირებთ, იქ დაამატეთ `[test_insights.coverage]`, სადაც `upload = true` იქნება.

შემდეგ გაუშვით ტესტები ჩვეულებრივად:

```sh
tuist cargo test --workspace
```

Tuist აგებს თქვენი რეპოზიტორიის კრეიტებს `-C instrument-coverage` პარამეტრით, უშვებს ტესტებს და ატვირთავს მათ დაფარვას გაშვების ტესტის შედეგებთან ერთად. თქვენი ტესტების გამოსავალი და გასვლის კოდი არ იცვლება. ერთი გაშვებისთვის პარამეტრის გადასაწერად, დააყენეთ `TUIST_COVERAGE_UPLOAD=1` ან `TUIST_COVERAGE_UPLOAD=0`.

დაფარვა ეყრდნობა Git-ის ისტორიას, რომელსაც Tuist ატვირთავს ყოველი გაშვებისას, რომელიც აგროვებს მას, რაც კომიტს ათავსებს მის ბრენჩზე. Git-ის რეპოზიტორიის გარეთ გაშვება ატვირთავს ტესტის შედეგებს, მაგრამ არა დაფარვას.

### დაყოფილი გაშვებები {#sharded-runs}

როდესაც <.localized_link href="/guides/features/test-sharding/rust">ტესტებს ყოფთ</.localized_link>, ყოველი შარდი, რომელიც დაფარვით გადის, ანგარიშდება თავისი მიზნების დაფარვას და Tuist აერთიანებს გაშვების შარდებს ერთ მაჩვენებლად. შარდი განზრახ უშვებს სუიტის ნაწილს, ამიტომ ის არ ხდის კომიტის დაფარვას არასრულს.

### CI-ზე ყოველი კომიტის დასრულება {#complete-each-commit}

კომიტის დაფარვა ხშირად რამდენიმე დავალებისგან მოდის: ერთი შარდის ან ფუნქციების ნაკრების მიხედვით. Tuist-მა არ იცის, როდის მოახსენებს ბოლო მათგანი, ამიტომ უთხარით მას. როდესაც კომიტის ყოველი ტესტის დავალება დასრულდება, გაუშვით ეს დავალებაში, რომელიც ყველა მათგანზეა დამოკიდებული:

```sh
tuist cargo coverage-complete
```

ბრძანება კითხულობს კომიტს checkout-იდან, ან იმას, რომელსაც თქვენი CI პროვაიდერი ანგარიშდება pull request-ზე; სხვის დასახელებად გადაეცით `--commit <sha>`. სანამ კომიტი არ დასრულდება, მისი დაფარვა ჩანს როგორც **მიმდინარე** და არ შედის მისი ბრენჩის ტრენდში.

## როგორ მუშაობს {#how-it-works}

### რას ზომავს Tuist {#what-tuist-measures}

- **პაკეტები.** ყოველი Cargo პაკეტი არის მიზანი დაშბორდზე, თავისი დაფარვით.
- **მხოლოდ პროდუქტის კოდი.** ინტეგრაციის ტესტები, ბენჩმარკები და მაგალითები (`tests/`, `benches/` და `examples/` დირექტორიები და ასეთი ტიპის მიზნები) არის ტესტის კოდი. Tuist ინახავს მათ, მაგრამ ტოვებს ყოველი მაჩვენებლის გარეთ. `#[cfg(test)]` მოდულში არსებული ერთეულოვანი ტესტები არის მათი წყაროს ფაილის ნაწილი, ამიტომ მათი სტრიქონები ითვლება მასთან ერთად, როგორც `cargo llvm-cov`-ში.
- **ფუნქციები.** ყოველი სტრიქონი ეკუთვნის ფუნქციას, რომელიც მასზე ყველაზე ახლოს იწყება. ზოგადი ფუნქცია ითვლება ერთხელ, რამდენი ტიპითაც არ უნდა იყოს ის ინსტანცირებული.
- **Doctests** გადის ჩვეულებრივად, მაგრამ არ იზომება.

Tuist ასევე აღრიცხავს, თუ რომელი კოდი შეასრულა ყოველმა ტესტის ბინარმა, მოგვიანებით დაფარვაზე დაფუძნებული ტესტის შერჩევისთვის. `cargo test` უშვებს ბინარის ტესტებს ერთ პროცესში, ამიტომ ეს ჩანაწერი ეკუთვნის ბინარს მთლიანად და არა მის ცალკეულ ტესტებს.

### გამოტოვებული ტესტები {#skipped-tests}

როდესაც გაშვების საკუთარი არგუმენტები ტოვებს ტესტებს გარეთ, როგორიცაა ტესტის სახელის ფილტრი, `--skip`, `--ignored`, `-p`, `--exclude`, `--lib` ან `--test`, კომიტის დაფარვა არის **არასრული**, თუ არ გაშვებულა კომიტის სხვა გაშვებაც, რომელმაც არაფერი დატოვა გარეთ. შეცდომას, რომელიც აჩერებს `cargo test`-ს სანამ ყოველი ტესტის ბინარი გაშვებულა, აქვს იგივე ეფექტი. დარჩენილი ბინარების გაშვების გასაგრძელებლად დაამატეთ `--no-fail-fast`.

ზოგიერთი ტესტი განზრახ არის გამოტოვებული და არ ხდის კომიტს არასრულს:

- **ტესტები, რომლებსაც <.localized_link href="/guides/features/test-insights/flaky-tests/rust">კარანტინი</.localized_link> ტოვებს.** ისინი გამოტოვებულია, თითქოს წაშლილი იყოს, ამიტომ სტრიქონები, რომლებიც მხოლოდ მათ დაფარეს, ითვლება დაუფარავად.
- **სხვა შარდების მიზნები**, როდესაც ტესტებს ყოფთ.
- **იგნორირებული ტესტები** (`#[ignore]`), რომლებიც ნაგულისხმევად არ გადის.

### სრული და არასრული კომიტები {#commit-status}

დაშბორდზე ყოველ კომიტს აქვს სტატუსი:

| სტატუსი | მნიშვნელობა |
| --- | --- |
| მიმდინარე | გაშვებებმა მოახსენეს დაფარვა, მაგრამ `tuist cargo coverage-complete` ჯერ არ გაშვებულა კომიტისთვის. |
| სრული | კომიტის გაშვებების ყოველი ტესტი გაშვებულა, ან განზრახ იქნა გამოტოვებული. |
| არასრული | ზოგიერთი დაფარვის განსაზღვრა ვერ მოხერხდა, ამიტომ მაჩვენებელი წარმოადგენს ქვედა ზღვარს. |
| არ არის გაზომილი | კომიტისთვის არცერთმა გაშვებამ არ მოახსენა დაფარვა. |

ბრენჩის ტრენდი მოიცავს მხოლოდ სრულ კომიტებს.

## წარმადობაზე გავლენა {#performance-impact}

ინსტრუმენტული კოდი ოდნავ უფრო ნელა მუშაობს. Tuist ინსტრუმენტებს მხოლოდ თქვენი რეპოზიტორის კრეიტებს: დამოკიდებულებები იწყობა ზუსტად ისე, როგორც ჩვეულებრივ ბილდებში და გრძელდება ქეშიდან აღება. Tuist ინახავს თქვენი საკუთარი კრეიტების ორივე ვარიანტს სამიზნე დირექტორიაში, ამიტომ დაფარვით და უდაფარვოდ გაშვებებს შორის გადართვა არ იწვევს მათ ხელახლა აწყობას, თუ მათი კოდი არ შეცვლილა.

## შეზღუდვები {#limitations}

- **მორგებული `rustc-wrapper` მიზნისთვის სპეციფიკური `rustflags`-ით.** როდესაც თქვენი პროექტი აყენებს საკუთარ `rustc-wrapper`-ს, Tuist ნაცვლად ამისა Cargo-ს `build.rustflags`-ში ამატებს `-C instrument-coverage`-ს. Cargo-ს კონფიგურაციის ფაილში `target.<triple>.rustflags` ჩანაწერი ცვლის მათ, ამიტომ თავად დაამატეთ იქ ეს ფლაგი. გაშვება, რომლის ტესტებმაც არ დაწერეს დაფარვა, ამას აცხადებს.
- **კონფიგურირებული მიზნის გამშვებები.** Tuist ტესტის ბინარებს აშვებს საკუთარი გამშვების მეშვეობით. Cargo-ს კონფიგურაციის ფაილში `target.<triple>.runner` იკავებს მის ადგილს: გაშვების დაფარვა მაინც აიტვირთება, მაგრამ Tuist ვერ განსაზღვრავს, რომელმა ტესტის ბინარმა რა შეასრულა. `CARGO_TARGET_<TRIPLE>_RUNNER` გარემოს ცვლადით დაყენებული გამშვები განაგრძობს მუშაობას.
- **დაფარვა არ არის ფორკებიდან გახსნილი პულ-რეკვესტებიდან.** დაფარვა აიტვირთება მხოლოდ იმ გაშვებების მიერ, რომლებიც ავთენტიკაციას გადიან Tuist-თან, ხოლო CI ჩვეულებრივ ფარავს საიდუმლოებსა და იდენტობის ტოკენებს ფორკებიდან გახსნილი პულ-რეკვესტებისგან.

## დაფარვის მოთხოვნა {#querying}

დაშბორდის **კოდის დაფარვა** გვერდი აჩვენებს თითოეული კომიტის მაჩვენებელს, მის პაკეტებსა და ფაილებს, თითოეული ფაილის ფუნქციებთან ერთად. იგივე მონაცემები ხელმისაწვდომია აგენტებისთვის <.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocol სერვერის</.localized_link> მეშვეობით.
