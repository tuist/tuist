# Rust-ის კოდის დაფარვა {#rust-code-coverage}

კოდის დაფარვა გაჩვენებთ, თქვენი ტესტების მიერ შესრულებულ კოდის სტრიქონებს. Tuist ზომავს ხაზოვან დაფარვას ყოველი `cargo test` გაშვებისთვის LLVM-ის წყაროზე დაფუძნებული დაფარვის გამოყენებით და აჯამებს კომიტის გაშვებებს ერთ მაჩვენებლად — პროექტის, თითოეული პაკეტისა და თითოეული ფაილის დონეზე. დაშბორდის **კოდის დაფარვა** გვერდი აჩვენებს მას კომიტების მიხედვით და როგორც ტრენდს თითოეული ბრენჩისთვის.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - მიჰყევით <.localized_link href="/guides/get-started/rust-project">Rust-ის პროექტის მოწყობას</.localized_link>
> - თქვენი Rust-ის ინსტრუმენტების ჯაჭვის LLVM ინსტრუმენტები (`llvm-tools`). Tuist ამონტაჟებს მათ rustup-ის მიერ მართულ ინსტრუმენტების ჯაჭვში.
> - თქვენი პროექტი Git რეპოზიტორიაში

## მოწყობა {#setup}

### დაფარვის ჩართვა {#turn-coverage-on}

დაამატეთ ეს `tuist.toml`-ში თქვენი რეპოზიტორიის ძირში:

```toml
[test_insights.coverage]
upload = true
```

შემდეგ გაუშვით ტესტები ჩვეულებრივად:

```sh
tuist cargo test --workspace
```

Tuist ააგებს თქვენი რეპოზიტორიის კრეიტებს `-C instrument-coverage` ფლაგით, უშვებს ტესტებს და ატვირთავს მათ დაფარვას გაშვების ტესტების შედეგებთან ერთად. თქვენი ტესტების გამომავალი მონაცემები და გასვლის კოდი არ იცვლება. ერთი გაშვებისთვის პარამეტრის გადასაწერად, დააყენეთ `TUIST_COVERAGE_UPLOAD=1` ან `TUIST_COVERAGE_UPLOAD=0`.

დაფარვა ეყრდნობა Git-ის ისტორიას, რომელსაც Tuist ატვირთავს ყოველი გაშვებისას, რომელიც აგროვებს მას, რაც კომიტს ათავსებს მის ბრენჩზე. Git რეპოზიტორიის გარეთ გაშვება ატვირთავს ტესტების შედეგებს, მაგრამ არა დაფარვას.

### დაყოფილი გაშვებები {#sharded-runs}

როდესაც <.localized_link href="/guides/features/test-sharding/rust">ყოფთ ტესტებს</.localized_link>, ყოველი შარდი, რომელიც გაშვებულია დაფარვის ჩართვით, ანგარიშდება თავისი სამიზნეების დაფარვას და Tuist აერთიანებს გაშვების შარდებს ერთ მაჩვენებლად. შარდი განზრახ უშვებს საიტის ნაწილს, ამიტომ ის არ ხდის კომიტის დაფარვას არასრულყოფილს.

### CI-ზე თითოეული კომიტის დასრულება {#complete-each-commit}

კომიტის დაფარვა ხშირად მოდის რამდენიმე სამუშაოდან: ერთი შარდის ან ფუნქციების ნაკრების მიხედვით. Tuist-მა არ იცის, როდის ანგარიშდება ბოლო მათგანი, ამიტომ უთხარით მას. როდესაც კომიტის ყოველი ტესტის სამუშაო დასრულდება, გაუშვით ეს სამუშაოში, რომელიც დამოკიდებულია ყველა მათგანზე:

```sh
tuist cargo coverage-complete
```

ბრძანება კითხულობს კომიტს ჩეკაუტიდან, ან იმას, რომელსაც თქვენი CI პროვაიდერი ანგარიშდება pull request-ზე; გადაეცით `--commit <sha>` სხვის დასახელებლად. სანამ კომიტი არ დასრულდება, მისი დაფარვა ჩანს როგორც **მიმდინარე** და არ შედის მისი ბრენჩის ტრენდში.

## როგორ მუშაობს {#how-it-works}

### რას ზომავს Tuist {#what-tuist-measures}

- **პაკეტები.** თითოეული Cargo პაკეტი არის სამიზნე დაშბორდზე, საკუთარი დაფარვით.
- **მხოლოდ პროდუქციის კოდი.** ინტეგრაციის ტესტები, ბენჩმარკები და მაგალითები (`tests/`, `benches/` და `examples/` დირექტორიები და ასეთი ტიპის სამიზნეები) არის ტესტის კოდი. Tuist ინახავს მათ, მაგრამ ტოვებს მათ ყოველი მაჩვენებლის გარეთ. ერთეულოვანი ტესტები `#[cfg(test)]` მოდულში არის მათი წყაროს ფაილის ნაწილი, ამიტომ მათი სტრიქონები ითვლება მასთან ერთად, როგორც `cargo llvm-cov`-ში.
- **ფუნქციები.** თითოეული სტრიქონი ეკუთვნის ფუნქციას, რომელიც იწყება მასზე ყველაზე ახლოს ზემოთ. ზოგადი ფუნქცია ითვლება ერთხელ, მიუხედავად იმისა, თუ რამდენი ტიპით იქნა ის ინსტანცირებული.
- **Doctests** გაშვებულია ჩვეულებრივად, მაგრამ არ იზომება.

Tuist ასევე აღრიცხავს, თუ რომელი კოდი შეასრულა თითოეულმა ტესტის ბინარმა, მოგვიანებით დაფარვაზე დაფუძნებული ტესტების შერჩევისთვის. `cargo test` უშვებს ბინარის ტესტებს ერთ პროცესში, ამიტომ ეს ჩანაწერი ეკუთვნის ბინარს მთლიანად, არა მის ინდივიდუალურ ტესტებს.

### გამოტოვებული ტესტები {#skipped-tests}

როდესაც გაშვების საკუთარი არგუმენტები ტოვებს ტესტებს გარეთ, როგორიცაა ტესტის სახელის ფილტრი, `--skip`, `--ignored`, `-p`, `--exclude`, `--lib` ან `--test`, კომიტის დაფარვა არის **არასრული**, თუ არ გაშვებულა კომიტის სხვა გაშვებაც, რომელმაც არაფერი დატოვა გარეთ. შეცდომამ, რომელიც აჩერებს `cargo test`-ს სანამ ყოველი ტესტის ბინარი გაშვებული იქნება, აქვს იგივე ეფექტი. დაამატეთ `--no-fail-fast` დარჩენილი ბინარების გაშვების გასაგრძელებლად.

ზოგიერთი ტესტი განზრახ არის გამოტოვებული და არ ხდის კომიტს არასრულს:

- **ტესტები, რომლებსაც <.localized_link href="/guides/features/test-insights/flaky-tests/rust">კარანტინი</.localized_link> ტოვებს.** ისინი გამოტოვებულია ისე, თითქოს წაშლილი იყვნენ, ამიტომ სტრიქონები, რომლებსაც მხოლოდ ისინი ფარავდნენ, ითვლება დაუფარავად.
- **სხვა შარდების სამიზნეები**, როდესაც ყოფთ ტესტებს.
- **იგნორირებული ტესტები** (`#[ignore]`), რომლებიც ჩვეულებრივად არ გაშვებულა.

### სრული და არასრული კომიტები {#commit-status}

თითოეულ კომიტს დაშბორდზე აქვს სტატუსი:

| სტატუსი | მნიშვნელობა |
| --- | --- |
| მიმდინარე | გაშვებებმა ანგარიშდება დაფარვა, მაგრამ `tuist cargo coverage-complete` ჯერ არ გაშვებულა კომიტისთვის. |
| სრული | კომიტის გაშვებების ყოველი ტესტი გაშვებული იყო, ან განზრახ იყო გამოტოვებული. |
| არასრული | ზოგიერთი დაფარვა ვერ განისაზღვრა, ამიტომ მაჩვენებელი არის ქვედა ზღვარი. |
| არ გაზომილა | არცერთმა გაშვებამ არ ანგარიშა დაფარვა კომიტისთვის. |

ბრენჩის ტრენდი მოიცავს მხოლოდ სრულ კომიტებს.

## წარმადობაზე გავლენა {#performance-impact}

ინსტრუმენტული კოდი ოდნავ უფრო ნელა მუშაობს. Tuist ინსტრუმენტაციას უკეთებს მხოლოდ თქვენი რეპოზიტორიის კრეიტებს: დამოკიდებულებები ზუსტად ისევე იწყობა, როგორც ჩვეულებრივ ბილდებში და კეშიდან მოდის. Tuist ინახავს თქვენი საკუთარი კრეიტების ორივე ვარიანტს სამიზნე დირექტორიაში, ამიტომ გაშვებებს შორის გადასვლა დაფარვით და მის გარეშე არ იწვევს მათ ხელახლა აწყობას, თუ მათი კოდი არ შეცვლილა.

## შეზღუდვები {#limitations}

- **მორგებული `rustc-wrapper` სამიზნე-სპეციფიკური `rustflags`-ით.** როდესაც თქვენი პროექტი აყენებს საკუთარ `rustc-wrapper`-ს, Tuist ამის ნაცვლად Cargo-ს `build.rustflags`-ს ამატებს `-C instrument-coverage`-ს. Cargo-ს კონფიგურაციის ფაილში `target.<triple>.rustflags` ჩანაწერი ცვლის მათ, ამიტომ თავად დაამატეთ იქ ეს ფლაგი. გაშვება, რომლის ტესტებმაც არ დაწერეს დაფარვა, ამას აღნიშნავს.
- **კონფიგურირებული სამიზნე რანერები.** Tuist ტესტის ბინარებს აშვებს საკუთარი რანერის მეშვეობით. Cargo-ს კონფიგურაციის ფაილში `target.<triple>.runner` იკავებს მის ადგილს: გაშვების დაფარვა მაინც აიტვირთება, მაგრამ Tuist ვერ განსაზღვრავს, რომელმა ტესტის ბინარმა რა შეასრულა. გარემოს ცვლადით `CARGO_TARGET_<TRIPLE>_RUNNER` დაყენებული რანერი კვლავ მუშაობს.
- **დაფარვა არ არის ფორკებიდან გახსნილი პულ-რეკვესტებიდან.** დაფარვა აიტვირთება მხოლოდ იმ გაშვებების მიერ, რომლებიც ავთენტიკაციას გადიან Tuist-თან, ხოლო CI ჩვეულებრივ ფარავს საიდუმლოებს და იდენტობის ტოკენებს ფორკებიდან გახსნილი პულ-რეკვესტებისგან.

## დაფარვის მოთხოვნა {#querying}

დაშბორდის **კოდის დაფარვა** გვერდი აჩვენებს თითოეული კომიტის მაჩვენებელს, მის პაკეტებს და ფაილებს, თითოეული ფაილის ფუნქციებთან ერთად. იგივე მონაცემები ხელმისაწვდომია აგენტებისთვის <.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocol სერვერის</.localized_link> მეშვეობით.
