# Rust-ის კოდის დაფარვა {#rust-code-coverage}

კოდის დაფარვა გაჩვენებთ, თქვენი ტესტები კოდის რომელ ხაზებს ასრულებენ. Tuist ზომავს ხაზების დაფარვას ყოველი `cargo test` გაშვებისას LLVM-ის წყაროზე დაფუძნებული დაფარვის საშუალებით და აერთიანებს კომიტის გაშვებებს ერთ რიცხვად — პროექტისთვის, თითოეული პაკეტისა და ფაილის მიხედვით. დაფის **Code Coverage** გვერდი აჩვენებს მას კომიტის მიხედვით და როგორც ტრენდს თითოეული ბრენჩისთვის.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - მიჰყევით <.localized_link href="/guides/get-started/rust-project">Rust-ის პროექტის მოწყობას</.localized_link>
> - თქვენი Rust-ის ინსტრუმენტების ჯაჭვის LLVM-ის ინსტრუმენტები (`llvm-tools`). Tuist აყენებს მათ rustup-ის მიერ მართულ ინსტრუმენტების ჯაჭვში.
> - თქვენი პროექტი Git-ის რეპოზიტორიაში

## მოწყობა {#setup}

### დაფარვის ჩართვა {#turn-coverage-on}

დაამატეთ ეს სამუშაო სივრცის ძირითად `Cargo.toml`-ში:

```toml
[workspace.metadata.tuist.test_insights.coverage]
upload = true
```

თუ Tuist-ს `tuist.toml`-ში აკონფიგურირებთ, იქ დაამატეთ `[test_insights.coverage]` `upload = true`-ით.

შემდეგ ჩვეულებრივად გაუშვით ტესტები:

```sh
tuist cargo test --workspace
```

Tuist აგებს თქვენი რეპოზიტორიის კრეიტებს `-C instrument-coverage`-ით, ასრულებს ტესტებს და ატვირთავს მათ დაფარვას გაშვების ტესტების შედეგებთან ერთად. თქვენი ტესტების გამოტანა და გამოსვლის კოდი არ იცვლება. ერთი გაშვებისთვის პარამეტრის გადასაწერად, დააყენეთ `TUIST_COVERAGE_UPLOAD=1` ან `TUIST_COVERAGE_UPLOAD=0`.

დაფარვა ეყრდნობა Git-ის ისტორიას, რომელსაც Tuist ტვირთავს ყოველ გაშვებასთან ერთად, რაც კომიტს განათავსებს მის ბრენჩზე. Git-ის რეპოზიტორიის გარეთ გაშვება ტვირთავს ტესტების შედეგებს, მაგრამ არა დაფარვას.

### დაყოფილი გაშვებები {#sharded-runs}

როდესაც <.localized_link href="/guides/features/test-sharding/rust">ტესტებს ნაწილებად ყოფთ</.localized_link>, ყოველი ნაწილი, რომელიც ჩართული დაფარვით სრულდება, ანგარიშგებს თავისი სამიზნეების დაფარვას და Tuist აერთიანებს გაშვების ნაწილებს ერთ რიცხვად. ნაწილი მიზანმიმართულად ასრულებს სუიტის ნაწილს, ამიტომ ის არ ხდის კომიტის დაფარვას არასრულს.

### CI-ზე ყოველი კომიტის დასრულება {#complete-each-commit}

კომიტის დაფარვა ხშირად რამდენიმე სამუშაოსგან მოდის: ერთი ნაწილის ან ფუნქციების ნაკრების მიხედვით. Tuist-მა არ იცის, როდის ანგარიშგებს ბოლო მათგანი, ამიტომ უთხარით მას. როდესაც კომიტის ყველა ტესტის სამუშაო დასრულდება, გაუშვით ეს სამუშაოში, რომელიც დამოკიდებულია მათ ყველაზე:

```sh
tuist cargo coverage-complete
```

ბრძანება კითხულობს კომიტს ჩექაუთის `HEAD`-დან, კომიტს, რომელზეც თქვენი ტესტები შესრულდა; სხვის დასახელებად გადაეცით `--commit <sha>`. სანამ კომიტი არ დასრულდება, მისი დაფარვა ჩანს როგორც **In progress** და არ შედის მისი ბრენჩის ტრენდში.

## როგორ მუშაობს {#how-it-works}

### რას ზომავს Tuist {#what-tuist-measures}

- **პაკეტები.** თითოეული Cargo-ს პაკეტი არის დაფის სამიზნე, თავისი დაფარვით.
- **მხოლოდ პროდუქციის კოდი.** ინტეგრაციის ტესტები, ბენჩმარკები და მაგალითები (`tests/`, `benches/` და `examples/` დირექტორიები და ამ ტიპის სამიზნეები) არის სატესტო კოდი. Tuist ინახავს მათ, მაგრამ არ შეჰყავს არცერთ რიცხვში. ერთეულოვანი ტესტები `#[cfg(test)]` მოდულში არის მათი წყაროს ფაილის ნაწილი, ამიტომ მათი ხაზები ითვლება მასთან ერთად, როგორც `cargo llvm-cov`-ში.
- **ფუნქციები.** თითოეული ხაზი ეკუთვნის ფუნქციას, რომელიც მასზე ყველაზე ახლოს იწყება. ზოგადი ფუნქცია ერთხელ ითვლება, რამდენი ტიპითაც არ უნდა იყოს ინსტანცირებული.
- **Doctests** სრულდება ჩვეულებრივად, მაგრამ არ იზომება.

Tuist ასევე აღრიცხავს, თუ რომელი კოდი შეასრულა თითოეულმა სატესტო ბინარმა, მოგვიანებით დაფარვაზე დაფუძნებული ტესტების შერჩევისთვის. `cargo test` ასრულებს ბინარის ტესტებს ერთ პროცესში, ამიტომ ეს ჩანაწერი ეკუთვნის ბინარს მთლიანად, არა მის ცალკეულ ტესტებს.

### გამოტოვებული ტესტები {#skipped-tests}

როდესაც გაშვების საკუთარი არგუმენტები ტოვებს ტესტებს გარეთ, როგორიცაა ტესტის სახელის ფილტრი, `--skip`, `--ignored`, `-p`, `--exclude`, `--lib` ან `--test`, კომიტის დაფარვა არის **Incomplete**, თუ არ შესრულდა კომიტის სხვა გაშვებაც, რომელმაც არაფერი გამოტოვა. შეცდომას, რომელიც აჩერებს `cargo test`-ს სანამ ყველა სატესტო ბინარი შესრულდება, იგივე ეფექტი აქვს. დაამატეთ `--no-fail-fast` დარჩენილი ბინარების გასაგრძელებლად.

ზოგიერთი ტესტი მიზანმიმართულად არის გამოტოვებული და არ ხდის კომიტს არასრულს:

- **ტესტები, რომლებსაც <.localized_link href="/guides/features/test-insights/flaky-tests/rust">კარანტინი</.localized_link> ტოვებს.** ისინი გამოტოვებულია, თითქოს წაშლილი იყოს, ამიტომ ხაზები, რომლებიც მხოლოდ მათ ფარავდა, ითვლება დაუფარავად.
- **სხვა ნაწილების სამიზნეები**, როდესაც ტესტებს ნაწილებად ყოფთ.
- **იგნორირებული ტესტები** (`#[ignore]`), რომლებიც ჩვეულებრივად არ სრულდება.

### დაუკომიტებელი ცვლილებები {#uncommitted-changes}

გაშვება ჩექაუთიდან, რომლის თრექინგის ფაილებს აქვს დაუკომიტებელი ცვლილებები, ზომავდა კოდს, რომელიც არ არის კომიტის, ამიტომ მისი დაფარვა არ ითვლება კომიტისთვის. გაშვება აფრთხილებს და ჩამოთვლის შეცვლილ ფაილებს. ფაილები, რომლებსაც თქვენი CI-ის სამუშაო წერს წყაროების გვერდით, როგორიცაა აგების შედეგები ან დაფარვის ანგარიშები, არ ითვლება ცვლილებებად, სანამ Git არ აკონტროლებს მათ. როდესაც მხოლოდ ასეთმა გაშვებებმა გაზომა კომიტი, მისი დაფარვა არის **Incomplete** და `tuist cargo coverage-complete` ამბობს რატომ.

## წარმადობაზე გავლენა {#performance-impact}

ინსტრუმენტალიზებული კოდი ოდნავ ნელა სრულდება. Tuist ინსტრუმენტალიზაციას უკეთებს მხოლოდ თქვენი რეპოზიტორიის კრეიტებს: დამოკიდებულებები იგება ზუსტად ისე, როგორც ჩვეულებრივი აგებისას და კეშიდან მოდის. Tuist ინახავს თქვენი საკუთარი კრეიტების ორივე ვარიანტს სამიზნე დირექტორიაში, ამიტომ დაფარვით და უდაფარვოდ გაშვებებს შორის გადართვა არ იწვევს მათ ხელახლა აგებას, თუ კოდი არ შეცვლილა.

## შეზღუდვები {#limitations}

- **საკუთარი `rustc-wrapper` სამიზნისთვის სპეციფიკური `rustflags`-ით.** როდესაც თქვენი პროექტი აყენებს საკუთარ `rustc-wrapper`-ს, Tuist ამის ნაცვლად Cargo-ს `build.rustflags`-ში ამატებს `-C instrument-coverage`-ს. Cargo-ს კონფიგურაციის ფაილში `target.<triple>.rustflags` ჩანაწერი ცვლის მათ, ამიტომ თავად დაამატეთ ეს ფლაგი იქ. გაშვება, რომლის ტესტებმაც არ ჩაწერეს დაფარვა, ამის შესახებ იტყობინება.
- **კონფიგურირებული სამიზნის გამშვებები.** Tuist ტესტების ბინარებს თავისი გამშვებლის მეშვეობით აშვებს. Cargo-ს კონფიგურაციის ფაილში `target.<triple>.runner` იკავებს მის ადგილს: გაშვების დაფარვა მაინც იტვირთება, მაგრამ Tuist ვერ განსაზღვრავს, რომელი ტესტის ბინარმა რა შეასრულა. `CARGO_TARGET_<TRIPLE>_RUNNER` გარემოს ცვლადით დაყენებული გამშვებელი კვლავ მუშაობს.
- **დაფარვა არ არის ხელმისაწვდომი ფორკებიდან გახსნილი პულ-რეკვესტებისთვის.** დაფარვა იტვირთება მხოლოდ იმ გაშვებების მიერ, რომლებიც Tuist-თან ავთენტიკაციას გადიან, ხოლო CI ჩვეულებრივ ფარავს საიდუმლოებებს და იდენტობის ტოკენებს ფორკებიდან გახსნილი პულ-რეკვესტებისთვის.

## დაფარვის მოთხოვნა {#querying}

დაფის **Code Coverage** გვერდი აჩვენებს თითოეული კომიტის მაჩვენებელს, მის პაკეტებსა და ფაილებს, თითოეული ფაილის ფუნქციების ჩათვლით. იგივე მონაცემები ხელმისაწვდომია აგენტებისთვის <.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocol server</.localized_link>-ის მეშვეობით.
