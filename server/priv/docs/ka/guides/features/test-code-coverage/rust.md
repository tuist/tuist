# Rust-ის კოდის დაფარვა {#rust-code-coverage}

კოდის დაფარვა გაჩვენებთ, თქვენი ტესტები რომელი ხაზები შეასრულეს. Tuist ზომავს ხაზოვან დაფარვას ყოველი `cargo test` გაშვებისთვის LLVM-ის წყაროზე დაფუძნებული დაფარვის საშუალებით და აერთიანებს კომიტის გაშვებებს ერთ რიცხვად პროექტის, თითოეული პაკეტისა და თითოეული ფაილის მიხედვით. დაშბორდის **კოდის დაფარვა** გვერდი აჩვენებს მას კომიტის მიხედვით და როგორც ტრენდს თითოეული ბრენჩისთვის.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - მიჰყევით <.localized_link href="/guides/get-started/rust-project">Rust-ის პროექტის მოწყობას</.localized_link>
> - თქვენი Rust-ის ინსტრუმენტების ჯაჭვის LLVM-ის ინსტრუმენტები (`llvm-tools`). Tuist აყენებს მათ rustup-ის მიერ მართულ ინსტრუმენტების ჯაჭვში.
> - თქვენი პროექტი Git-ის რეპოზიტორიაში

## მოწყობა {#setup}

### დაფარვის ჩართვა {#turn-coverage-on}

დაამატეთ ეს სამუშაო სივრცის ძირითად `Cargo.toml`-ში:

```toml
[workspace.metadata.tuist.test_insights.coverage]
upload = true
```

თუ Tuist-ს ნაცვლად `tuist.toml`-ში აკონფიგურირებთ, იქ დაამატეთ `[test_insights.coverage]` `upload = true`-ით.

შემდეგ გაუშვით თქვენი ტესტები ჩვეულებრივად:

```sh
tuist cargo test --workspace
```

Tuist აგებს თქვენი რეპოზიტორიის კრეიტებს `-C instrument-coverage`-ით, უშვებს ტესტებს და ატვირთავს მათ დაფარვას გაშვების ტესტის შედეგებთან ერთად. თქვენი ტესტების გამოტანა და გასვლის კოდი არ იცვლება. ერთი გაშვებისთვის პარამეტრის გადასაწერად, დააყენეთ `TUIST_COVERAGE_UPLOAD=1` ან `TUIST_COVERAGE_UPLOAD=0`.

დაფარვა ეყრდნობა Git-ის ისტორიას, რომელსაც Tuist ტვირთავს ყოველ გაშვებასთან, რომელიც მას აგროვებს, რაც კომიტს მის ბრენჩზე ათავსებს. Git-ის რეპოზიტორიის გარეთ გაშვება ტვირთავს ტესტის შედეგებს, მაგრამ არა დაფარვას.

### დაშლილი გაშვებები {#sharded-runs}

როდესაც <.localized_link href="/guides/features/test-sharding/rust">ტესტებს ნაწილებად ყოფთ</.localized_link>, ყოველი ნაწილი, რომელიც ჩართული დაფარვით მუშაობს, იტყობინება თავისი სამიზნეების დაფარვას და Tuist აერთიანებს გაშვების ნაწილებს ერთ რიცხვად. ნაწილი განზრახ ასრულებს სუიტის ნაწილს, ამიტომ ის არ ხდის კომიტის დაფარვას არასრულყოფილს.

### CI-ზე ყოველი კომიტის დასრულება {#complete-each-commit}

კომიტის დაფარვა ხშირად რამდენიმე სამუშაოსგან მოდის: ერთი თითოეული ნაწილის ან თვისებების ნაკრებისთვის. Tuist ვერ ხვდება, როდის იტყობინება ბოლო მათგანი, ამიტომ უთხარით მას. როდესაც კომიტის ყოველი ტესტის სამუშაო დასრულდება, გაუშვით ეს სამუშაოში, რომელიც დამოკიდებულია ყველა მათგანზე:

```sh
tuist coverage complete
```

ბრძანება კითხულობს კომიტს ჩეკაუტის `HEAD`-დან, კომიტს, რომელზეც თქვენი ტესტები გაშვებული იყო; გადაეცით `--commit <sha>` სხვის დასახელებლად. სანამ კომიტი არ დასრულდება, მისი დაფარვა ჩანს როგორც **მიმდინარე** და არ შედის მისი ბრენჩის ტრენდში.

## როგორ მუშაობს {#how-it-works}

### რას ზომავს Tuist {#what-tuist-measures}

- **პაკეტები.** ყოველი Cargo პაკეტი არის სამიზნე დაშბორდზე, თავისი დაფარვით.
- **მხოლოდ პროდუქციის კოდი.** ინტეგრაციის ტესტები, ბენჩმარკები და მაგალითები (`tests/`, `benches/` და `examples/` დირექტორიები და ასეთი ტიპის სამიზნეები) არის ტესტის კოდი. Tuist ინახავს მათ, მაგრამ ტოვებს ყოველი რიცხვის გარეთ. ერთეულოვანი ტესტები `#[cfg(test)]` მოდულში არის მათი წყაროს ფაილის ნაწილი, ამიტომ მათი ხაზები ითვლება მასთან ერთად, როგორც `cargo llvm-cov`-ში.
- **ფუნქციები.** ყოველი ხაზი ეკუთვნის ფუნქციას, რომელიც მასზე ყველაზე ახლოს იწყება. ზოგადი ფუნქცია ერთხელ ითვლება, მიუხედავად იმისა, თუ რამდენი ტიპით იქნა ის ინსტანცირებული.
- **Doctests** ჩვეულებრივად მუშაობენ, მაგრამ არ იზომებიან.

Tuist ასევე აღრიცხავს, თუ რომელი კოდი შეასრულა ყოველმა ტესტის ბინარმა, მოგვიანებით დაფარვაზე დაფუძნებული ტესტის შერჩევისთვის. `cargo test` უშვებს ბინარის ტესტებს ერთ პროცესში, ამიტომ ეს ჩანაწერი ეკუთვნის ბინარს მთლიანად, არა მის ცალკეულ ტესტებს.

### გამოტოვებული ტესტები {#skipped-tests}

როდესაც გაშვების საკუთარი არგუმენტები ტოვებს ტესტებს გარეთ, როგორიცაა ტესტის სახელის ფილტრი, `--skip`, `--ignored`, `-p`, `--exclude`, `--lib` ან `--test`, კომიტის დაფარვა არის **არასრული**, თუ არ გაშვებულა კომიტის სხვა გაშვებაც, რომელმაც არაფერი დატოვა გარეთ. შეცდომას, რომელიც აჩერებს `cargo test`-ს სანამ ყოველი ტესტის ბინარი გაშვებული იქნება, აქვს იგივე ეფექტი. დაამატეთ `--no-fail-fast` დარჩენილი ბინარების გაშვების გასაგრძელებლად.

ზოგიერთი ტესტი განზრახ არის გამოტოვებული და არ ხდის კომიტს არასრულს:

- **ტესტები, რომლებსაც <.localized_link href="/guides/features/test-insights/flaky-tests/rust">კარანტინი</.localized_link> ტოვებს.** ისინი გამოტოვებულია ისე, თითქოს წაშლილი იყვნენ, ამიტომ ხაზები, რომლებიც მხოლოდ მათ დაფარეს, ითვლება დაუფარავად.
- **სხვა ნაწილების სამიზნეები**, როდესაც ტესტებს ნაწილებად ყოფთ.
- **იგნორირებული ტესტები** (`#[ignore]`), რომლებიც ნაგულისხმევად არ მუშაობენ.

### დაუფიქსირებელი ცვლილებები {#uncommitted-changes}

ჩეკაუტიდან გაშვება, რომლის თვალყურსადევნ ფაილებს აქვთ დაუფიქსირებელი ცვლილებები, ზომავდა კოდს, რომელიც არ არის კომიტის, ამიტომ მისი დაფარვა არ ითვლება კომიტისთვის. გაშვება აფრთხილებს და ჩამოთვლის შეცვლილ ფაილებს. ფაილები, რომლებსაც თქვენი CI სამუშაო წერს წყაროების გვერდით, როგორიცაა აგების გამომავალი ან დაფარვის ანგარიშები, არ ითვლება ცვლილებებად, სანამ Git მათ არ თვალყურს ადევნებს. როდესაც მხოლოდ ასეთმა გაშვებებმა გაზომა კომიტი, მისი დაფარვა არის **არასრული** და `tuist coverage complete` ამბობს რატომ.

## წარმადობაზე გავლენა {#performance-impact}

ინსტრუმენტალიზებული კოდი ოდნავ ნელა მუშაობს. Tuist აკეთებს ინსტრუმენტალიზაციას მხოლოდ თქვენი რეპოზიტორიის კრეიტებისთვის: დამოკიდებულებები აგდება ისევე, როგორც ჩვეულებრივი აგებების დროს და გრძელდება ქეშიდან მიღება. Tuist ინახავს თქვენი საკუთარი კრეიტების ორივე ვარიანტს სამიზნე დირექტორიაში, ამიტომ დაფარვით და უდაფარვოდ გაშვებებს შორის გადართვა არ იწვევს მათ ხელახლა აგებას, თუ მათი კოდი არ შეცვლილა.

## შეზღუდვები {#limitations}

- **მორგებული `rustc-wrapper` სამიზნე-სპეციფიკური `rustflags`-ით.** როდესაც თქვენი პროექტი აყენებს საკუთარ `rustc-wrapper`, Tuist ნაცვლად ამისა Cargo-ს `build.rustflags`-ში ამატებს `-C instrument-coverage`-ს. Cargo-ს კონფიგურაციის ფაილში `target.<triple>.rustflags` ჩანაწერი ცვლის მათ, ამიტომ დამატეთ ფლაგი იქ თავად. გაშვება, რომლის ტესტებმაც არ დაწერეს დაფარვა, ამბობს ამას.
- **კონფიგურირებული სამიზნე გამშვებები.** Tuist აწყებს სატესტო ბინარებს საკუთარი გამშვებლის მეშვეობით. Cargo-ს კონფიგურაციის ფაილში `target.<triple>.runner` იკავებს მის ადგილს: გაშვების დაფარვა კვლავ იტვირთება, მაგრამ Tuist ვერ განსაზღვრავს, რომელმა სატესტო ბინარმა რა შეასრულა. გარემოს ცვლადის `CARGO_TARGET_<TRIPLE>_RUNNER` მეშვეობით დაყენებული გამშვებელი კვლავ მუშაობს.
- **არ არის დაფარვა ფორკებიდან გახსნილი პულ-რეკვესტებიდან.** დაფარვა იტვირთება მხოლოდ იმ გაშვებების მიერ, რომლებიც ავტორიზდებიან Tuist-თან, ხოლო CI ჩვეულებრივ უკავებს საიდუმლოებს და იდენტობის ტოკენებს ფორკებიდან გახსნილ პულ-რეკვესტებს.

## დაფარვის მოთხოვნა {#querying}

დაშბორდის **კოდის დაფარვა** გვერდი აჩვენებს თითოეული კომიტის მაჩვენებელს, მის პაკეტებს და ფაილებს, თითოეული ფაილის ფუნქციებთან ერთად. იგივე მონაცემები ხელმისაწვდომია აგენტებისთვის <.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocol სერვერის</.localized_link> მეშვეობით.
