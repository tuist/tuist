# Rust-ის კოდის დაფარვა {#rust-code-coverage}

კოდის დაფარვა გეუბნებათ, თქვენი ტესტების მიერ რომელი ხაზები შესრულდა. Tuist ზომავს ყოველი `cargo test` გაშვების ხაზოვან დაფარვას LLVM-ის წყაროზე დაფუძნებული დაფარვის მეშვეობით და აერთიანებს კომიტის გაშვებებს ერთ რიცხვად პროექტის, თითოეული პაკეტისა და ფაილისთვის. დაშბორდის **კოდის დაფარვა** გვერდი აჩვენებს მას კომიტის მიხედვით და როგორც ტენდენციას თითოეული ბრენჩისთვის.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - მიჰყევით <.localized_link href="/guides/get-started/rust-project">Rust-ის პროექტის მოწყობას</.localized_link>
> - თქვენი Rust-ის ინსტრუმენტების ჯაჭვის LLVM ინსტრუმენტები (`llvm-tools`). Tuist აყენებს მათ rustup-ის მიერ მართულ ინსტრუმენტების ჯაჭვზე.
> - თქვენი პროექტი Git-ის რეპოზიტორიაში

## მოწყობა {#setup}

### ჩართეთ დაფარვა {#turn-coverage-on}

დაამატეთ ეს სამუშაო სივრცის ძირითად `Cargo.toml`-ში:

```toml
[workspace.metadata.tuist.test_insights.coverage]
upload = true
```

თუ Tuist-ს `tuist.toml`-ში აკონფიგურირებთ, დაამატეთ `[test_insights.coverage]` `upload = true`-ით.

შემდეგ გაუშვით თქვენი ტესტები ჩვეულებრივად:

```sh
tuist cargo test --workspace
```

Tuist აგებს თქვენი რეპოზიტორიის კრეიტებს `-C instrument-coverage`-ით, უშვებს ტესტებს და ატვირთავს მათ დაფარვას გაშვების ტესტის შედეგებთან ერთად. თქვენი ტესტების გამომავალი მონაცემები და გასვლის კოდი არ იცვლება. ერთი გაშვებისთვის პარამეტრის გადასაწერად, დააყენეთ `TUIST_COVERAGE_UPLOAD=1` ან `TUIST_COVERAGE_UPLOAD=0`.

დაფარვა ეყრდნობა Git-ის ისტორიას, რომელსაც Tuist ტვირთავს ყოველ გაშვებასთან ერთად, რაც კომიტს ათავსებს მის ბრენჩზე. Git-ის რეპოზიტორიის გარეთ გაშვება ტვირთავს ტესტის შედეგებს, მაგრამ არა დაფარვას. კომიტის შემოწმებიდან გაშვებას, ბრენჩის ნაცვლად, არ აქვს ბრენჩი და არ ათავსებს მის კომიტს ბრენჩზე; CI სისტემაზე, რომელსაც Tuist არ ცნობს, დაარქვით ბრენჩს `TUIST_GIT_BRANCH`-ით, როგორც <.localized_link href="/guides/features/test-insights/rust#continuous-integration">უწყვეტი ინტეგრაცია</.localized_link> აღწერს.

### დაყოფილი გაშვებები {#sharded-runs}

როდესაც <.localized_link href="/guides/features/test-sharding/rust">ტესტებს ყოფთ</.localized_link>, ყოველი შარდი, რომელიც ჩართული დაფარვით გადის, აცხობს საკუთარი მიზნების დაფარვას და Tuist აერთიანებს გაშვების შარდებს ერთ რიცხვად. შარდი განზრახ უშვებს სუიტის ნაწილს, ამიტომ ის არ ხდის კომიტის დაფარვას არასრულყოფილს.

### დაასრულეთ ყოველი კომიტი CI-ზე {#complete-each-commit}

კომიტის დაფარვა ხშირად რამდენიმე დავალებისგან მოდის: ერთი შარდის ან ფუნქციების ნაკრების მიხედვით. Tuist-ს არ შეუძლია გაიგოს, როდის მოახსენა ბოლომ, ამიტომ შეატყობინეთ. როდესაც კომიტის ყოველი სატესტო დავალება დასრულდება, გაუშვით ეს დავალებაში, რომელიც დამოკიდებულია ყველა მათგანზე:

```sh
tuist coverage complete
```

ბრძანება კითხულობს კომიტს შემოწმების `HEAD`-დან, კომიტს, რომელზეც თქვენი ტესტები გაუშვით; გადაეცით `--commit <sha>` სხვის დასახელებლად. სანამ კომიტი არ დასრულდება, მისი დაფარვა ჩანს როგორც **მიმდინარე** და არ შედის მისი ბრენჩის ტენდენციაში.

## როგორ მუშაობს {#how-it-works}

### რას ზომავს Tuist {#what-tuist-measures}

- **პაკეტები.** ყოველი Cargo პაკეტი არის მიზანი დაშბორდზე, საკუთარი დაფარვით.
- **მხოლოდ პროდუქციის კოდი.** ინტეგრაციის ტესტები, ბენჩმარკები და მაგალითები (`tests/`, `benches/` და `examples/` დირექტორიები და ასეთი ტიპის მიზნები) არის სატესტო კოდი. Tuist ინახავს მათ, მაგრამ ტოვებს ყოველი რიცხვის გარეთ. ერთეულოვანი ტესტები `#[cfg(test)]` მოდულში არის მათი წყაროს ფაილის ნაწილი, ამიტომ მათი ხაზები ითვლება მასთან ერთად, როგორც `cargo llvm-cov`-ში.
- **ფუნქციები.** ყოველი ხაზი ეკუთვნის ფუნქციას, რომელიც მასზე ზემოთ ყველაზე ახლოს იწყება. ზოგადი ფუნქცია ითვლება ერთხელ, მიუხედავად იმისა, თუ რამდენი ტიპით იქნა ის ინსტანცირებული.
- **Doctests** გადის ჩვეულებრივად, მაგრამ არ იზომება.

Tuist ასევე იწერს, თუ რომელი კოდი შეასრულა ყოველმა სატესტო ბინარმა, მოგვიანებით დაფარვაზე დაფუძნებული ტესტის შერჩევისთვის. `cargo test` უშვებს ბინარის ტესტებს ერთ პროცესში, ამიტომ ეს ჩანაწერი ეკუთვნის ბინარს მთლიანად, არა მის ინდივიდუალურ ტესტებს.

### გამოტოვებული ტესტები {#skipped-tests}

როდესაც გაშვების საკუთარი არგუმენტები ტოვებს ტესტებს გარეთ, როგორიცაა ტესტის სახელის ფილტრი, `--skip`, `--ignored`, `-p`, `--exclude`, `--lib` ან `--test`, კომიტის დაფარვა არის **არასრული**, თუ არ გაუშვა კომიტის სხვა გაშვებამ, რომელმაც არაფერი გამოტოვა. შეცდომას, რომელიც აჩერებს `cargo test`-ს სანამ ყოველი სატესტო ბინარი გაუშვებია, აქვს იგივე ეფექტი. დაამატეთ `--no-fail-fast` დარჩენილი ბინარების გასაგრძელებლად.

ზოგიერთი ტესტი განზრახ არის გამოტოვებული და არ ხდის კომიტს არასრულს:

- **ტესტები, რომლებსაც <.localized_link href="/guides/features/test-insights/flaky-tests/rust">კარანტინი</.localized_link> ტოვებს.** ისინი გამოტოვებულია, თითქოს წაშლილი იყოს, ამიტომ ხაზები, რომლებიც მხოლოდ მათ დაფარეს, ითვლება დაუფარავად.
- **სხვა შარდების მიზნები**, როდესაც ტესტებს ყოფთ.
- **იგნორირებული ტესტები** (`#[ignore]`), რომლებიც ჩვეულებრივად არ გადის.

### დაუკომიტებელი ცვლილებები {#uncommitted-changes}

შემოწმებიდან გაშვება, რომლის თვალყურდევნებადი ფაილებს აქვს დაუკომიტებელი ცვლილებები, ზომავდა კოდს, რომელიც არ არის კომიტის, ამიტომ მისი დაფარვა არ ითვლება კომიტისთვის. გაშვება აფრთხილებს და ჩამოთვლის შეცვლილ ფაილებს. ფაილები, რომლებსაც თქვენი CI დავალება წერს წყაროების გვერდით, როგორიცაა აგების შედეგები ან დაფარვის ანგარიშები, არ ითვლება ცვლილებებად, სანამ Git არ თვალყურს ადევნებს მათ. როდესაც მხოლოდ ასეთმა გაშვებებმა გაზომა კომიტი, მისი დაფარვა არის **არასრული** და `tuist coverage complete` ამბობს რატომ.

## წარმადობაზე გავლენა {#performance-impact}

ინსტრუმენტირებული კოდი ოდნავ ნელა მუშაობს. Tuist ინსტრუმენტირებს მხოლოდ თქვენი რეპოზიტორის კრეიტებს: დამოკიდებულებები იგივენაირად იგება, როგორც ჩვეულებრივი აგებისას და კეშიდან მოდის. Tuist ინახავს თქვენი საკუთარი კრეიტების ორივე ვარიანტს target საქაღალდეში, ამიტომ დაფარვით და უდაფარვოდ გაშვებებს შორის გადართვისას ისინი ხელახლა არ იგება, თუ მათი კოდი არ შეცვლილა.

## შეზღუდვები {#limitations}

- **საკუთარი `rustc-wrapper` სამიზნისთვის სპეციფიკური `rustflags`-ით.** როდესაც თქვენი პროექტი აყენებს საკუთარ `rustc-wrapper`-ს, Tuist ნაცვლად ამისა Cargo-ს `build.rustflags`-ში ამატებს `-C instrument-coverage`-ს. Cargo-ს კონფიგურაციის ფაილში `target.<triple>.rustflags` ჩანაწერი ცვლის მათ, ამიტომ თავად დაამატეთ ეს ფლაგი იქ. გაშვება, რომლის ტესტებმაც არ დაწერეს დაფარვა, ამას აღნიშნავს.
- **კონფიგურირებული სამიზნის გამშვებები.** Tuist ტესტის ბინარებს თავისი გამშვებლის მეშვეობით აშვებს. Cargo-ს კონფიგურაციის ფაილში `target.<triple>.runner` იკავებს მის ადგილს: გაშვების დაფარვა მაინც აიტვირთება, მაგრამ Tuist ვერ განსაზღვრავს, რომელმა ტესტის ბინარმა რა შეასრულა. `CARGO_TARGET_<TRIPLE>_RUNNER` გარემოს ცვლადით დაყენებული გამშვებელი კვლავ მუშაობს.
- **დაფარვა არ არის ფორკებიდან გახსნილი პულ-რეკვესტებიდან.** დაფარვა აიტვირთება მხოლოდ იმ გაშვებების მიერ, რომლებიც Tuist-თან ავთენტიფიცირდებიან, ხოლო CI ჩვეულებრივ ფარავს საიდუმლოებსა და იდენტობის ტოკენებს ფორკებიდან გახსნილი პულ-რეკვესტებისთვის.

## დაფარვის მოთხოვნა {#querying}

დაშბორდის **Code Coverage** გვერდი აჩვენებს თითოეული კომიტის მაჩვენებელს, მის პაკეტებსა და ფაილებს, თითოეული ფაილის ფუნქციებით. იგივე მონაცემები ხელმისაწვდომია აგენტებისთვის <.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocol server</.localized_link>-ის მეშვეობით.
