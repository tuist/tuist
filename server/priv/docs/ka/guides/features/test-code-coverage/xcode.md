# Xcode-ის კოდის დაფარვა {#xcode-code-coverage}

კოდის დაფარვა გაჩვენებთ, თქვენი ტესტები კოდის რომელ ხაზებს ასრულებენ. Tuist ატვირთავს ყოველი ტესტების გაშვების ხაზოვან დაფარვას და ერთიანი რიცხვად აერთიანებს კომიტის ყველა გაშვებას — პროექტის, თითოეული სამიზნისა და თითოეული ფაილის მიხედვით. დაშბორდის **კოდის დაფარვის** გვერდი აჩვენებს მას კომიტების მიხედვით და როგორც ტენდენციას თითოეული შტოსთვის.

<!-- @snippet: ./_xcode-requirements -->

> [!TIP]
> თუ პროექტს Tuist-ით გენერირებთ, მიჰყევით <.localized_link href="/guides/features/test-code-coverage/generated-xcode-project">გენერირებული პროექტის სახელმძღვანელოს</.localized_link>: ის ზომავს ბინარული ქეშიდან მომავალ კოდს და ინარჩუნებს იმ სატესტო სამიზნეების დაფარვას, რომლებსაც შერჩევითი ტესტირება გამოტოვებს.

## მოწყობა {#setup}

### დაფარვის შეგროვება {#collect-coverage}

ჩართეთ დაფარვის ატვირთვა თქვენს `Tuist.swift`-ში. ნაგულისხმევად ის გამორთულია:

```swift
import ProjectDescription

let tuist = Tuist(
    fullHandle: "my-account/my-project",
    testInsights: .testInsights(coverage: .coverage(upload: true)),
    project: .xcode()
)
```

`TUIST_COVERAGE_UPLOAD` გარემოს ცვლადი (`1` ან `0`) უპირატესობას იღებს პარამეტრზე, მაგალითად, ატვირთვის გამოსართავად ჯობებში, რომლებიც ასრულებენ პულ-რეკვესტებს ფორკებიდან.

შემდეგ ჩართეთ **კოდის დაფარვა** სქემის ტესტის ქმედებაში (**Edit Scheme › Test › Options**), ან გადაეცით `-enableCodeCoverage YES` გაშვებას და გაუშვით ტესტები `tuist xcodebuild test`-ის მეშვეობით:

```sh
tuist xcodebuild test \
  -scheme MyScheme \
  -enableCodeCoverage YES
```

Tuist ატვირთავს გაშვების მიერ შეგროვებულ დაფარვას ტესტების შედეგებთან ერთად.

### CI-ზე თითოეული კომიტის დასრულება {#complete-each-commit}

კომიტის დაფარვა ხშირად რამდენიმე ჯობისგან შედგება: ერთი თითოეული სქემის, შარდის ან პლატფორმისთვის. Tuist-მა არ იცის, როდის ანგარიშდება ბოლო მათგანი, ამიტომ მიუთითეთ ეს. როგორც კი კომიტის ყველა სატესტო ჯობა დასრულდება, გაუშვით ეს ჯობაში, რომელიც დამოკიდებულია მათ ყველაზე:

```sh
tuist coverage complete
```

სანამ კომიტი არ დასრულდება, მისი დაფარვა ჩანს როგორც **მიმდინარე** და არ შედის მისი შტოს ტენდენციაში. <.localized_link href="/guides/features/test-code-coverage/generated-xcode-project#commit-status">გენერირებული პროექტის სახელმძღვანელო</.localized_link> აღწერს თითოეულ სტატუსს.

## გამოტოვებული ტესტები {#skipped-tests}

როდესაც გაშვება ტესტებს `-skip-testing`-ით ტოვებს, ის ზომავს ნაკლებს, ვიდრე კომიტის ტესტები ფარავს, და Tuist ვერ გადაიტანს ამ ტესტებს წინა გაშვებიდან. კომიტის დაფარვა არის **არასრული**, თუ კომიტზე სხვა გაშვებამ არ გაუშვა ისინი. კომიტის სრულყოფილობის შესანარჩუნებლად, გაუშვით ყველა ტესტი კომიტზე მინიმუმ ერთ გაშვებაში.

ტესტები, რომლებსაც კარანტინი ტოვებს, საერთოდ არ შედიან დაფარვაში, ამიტომ ისინი არასდროს ხდიან კომიტს **არასრულს**.

## წარმადობაზე გავლენა {#performance-impact}

დაფარვის შეგროვება ზრდის დამატებით დატვირთვას, ძირითადად ტესტების დასრულების შემდეგ, როდესაც Xcode წერს თავის დაფარვის ანგარიშს და Tuist ექსპორტავს დაფარვას. ტესტების აგება და გაშვება დაახლოებით იმდენსვე დროს იღებს, რამდენსაც მის გარეშე.

## დაფარვის მოთხოვნა {#querying}

`tuist coverage` ბრძანებები კითხულობენ იმას, რასაც დაშბორდი აჩვენებს. `--commit`-ის გარეშე, ისინი კითხულობენ `--branch`-ის უახლეს სრულ კომიტს, ან თქვენს ნაგულისხმევ შტოს:

```sh
tuist coverage show                          # the project's coverage and its targets
tuist coverage files --commit <sha>          # files, least covered first
tuist coverage file Sources/Cart.swift --lines  # a file's functions, with per-line counts
```

ყველა მათგანი იღებს `--json`-ს სკრიპტინგისთვის.
