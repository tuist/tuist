# Xcode-ის კოდის დაფარვა {#xcode-code-coverage}

> [!NOTE] EARLY ACCESS
> Xcode-ის პროექტების კოდის დაფარვა ადრეულ წვდომაშია. [დაგვიკავშირდით](mailto:contact@tuist.dev), რომ ჩართოთ ის თქვენს ანგარიშზე. მანამდე Tuist არ ინახავს თქვენი გაშვებების მიერ ატვირთულ დაფარვას.

კოდის დაფარვა გიჩვენებთ, თქვენი ტესტები კოდის რომელ ხაზებს ასრულებენ. Tuist ტვირთავს ყოველი ტესტების გაშვების ხაზობრივ დაფარვას და აერთიანებს ერთი კომიტის გაშვებებს ერთ მაჩვენებლად — პროექტისთვის, თითოეული სამიზნისა და ფაილისთვის. დაფის **კოდის დაფარვის** გვერდი აჩვენებს მას კომიტების მიხედვით და როგორც ტრენდს თითოეული შტოსთვის.

> [!TIP]
> თუ თქვენს პროექტს Tuist-ით აგენერირებთ, ნაცვლად ამისა მიჰყევით <.localized_link href="/guides/features/test-code-coverage/generated-xcode-project">გენერირებული პროექტის სახელმძღვანელოს</.localized_link>: ის ზომავს ბინარული ქეშიდან მომავალ კოდს და ითვალისწინებს იმ სატესტო სამიზნეების დაფარვას, რომლებსაც შერჩევითი ტესტირება გამოტოვებს.

## მოწყობა {#setup}

### დაფარვის შეგროვება {#collect-coverage}

ჩართეთ დაფარვის ატვირთვა თქვენს `Tuist.swift`-ში. ის ნაგულისხმევად გამორთულია:

```swift
import ProjectDescription

let tuist = Tuist(
    fullHandle: "my-account/my-project",
    testInsights: .testInsights(coverage: .coverage(upload: true)),
    project: .xcode()
)
```

`TUIST_COVERAGE_UPLOAD` გარემოს ცვლადი (`1` ან `0`) უპირატესობას იღებს პარამეტრთან შედარებით, მაგალითად, ატვირთვის გამოსართავად ჯობებში, რომლებიც ასრულებენ pull request-ებს fork-ებიდან.

შემდეგ ჩართეთ **კოდის დაფარვა** თქვენი სქემის სატესტო მოქმედებაში (**Edit Scheme › Test › Options**), ან გადაეცით `-enableCodeCoverage YES` გაშვებას და გაუშვით ტესტები `tuist xcodebuild test`-ის მეშვეობით:

```sh
tuist xcodebuild test \
  -scheme MyScheme \
  -enableCodeCoverage YES
```

Tuist ტვირთავს გაშვების მიერ შეგროვებულ დაფარვას მისი ტესტის შედეგებთან ერთად.

### CI-ზე დაასრულეთ თითოეული კომიტი {#complete-each-commit}

კომიტის დაფარვა ხშირად რამდენიმე ჯობისგან შედგება: ერთი თითოეული სქემის, შარდის ან პლატფორმისთვის. Tuist-მა არ იცის, როდის მოახსენებს ბოლო მათგანი, ამიტომ მიუთითეთ ეს. როგორც კი კომიტის ყველა სატესტო ჯობა დასრულდება, გაუშვით ეს ჯობაში, რომელიც დამოკიდებულია ყველა მათგანზე:

```sh
tuist coverage complete
```

სანამ კომიტი არ დასრულდება, მისი დაფარვა ჩანს როგორც **მიმდინარე** და არ შედის მისი შტოს ტრენდში. <.localized_link href="/guides/features/test-code-coverage/generated-xcode-project#commit-status">გენერირებული პროექტის სახელმძღვანელო</.localized_link> აღწერს თითოეულ სტატუსს.

## გამოტოვებული ტესტები {#skipped-tests}

როდესაც გაშვება გამოტოვებს ტესტებს `-skip-testing`-ის მეშვეობით, ის ზომავს ნაკლებს, ვიდრე კომიტის ტესტები ფარავს, და Tuist-ს არ შეუძლია ამ ტესტების გადატანა ადრეული გაშვებიდან. კომიტის დაფარვა არის **არასრული**, თუ კომიტზე სხვა გაშვებამ არ გაუშვა ისინი. კომიტის სისრულის შესანარჩუნებლად, გაუშვით ყველა ტესტი კომიტზე სულ მცირე ერთ გაშვებაში.

ტესტები, რომლებსაც კარანტინი გამოტოვებს, საერთოდ არ შედიან დაფარვაში, ამიტომ ისინი არასდროს ხდიან კომიტს **არასრულად**.

## წარმადობაზე გავლენა {#performance-impact}

დაფარვის შეგროვება მატებს დამატებით დატვირთვას, ძირითადად ტესტების დასრულების შემდეგ, როდესაც Xcode წერს თავის დაფარვის ანგარიშს და Tuist ახდენს დაფარვის ექსპორტს. ტესტების აგება და გაშვება დაახლოებით იმდენსვე დროს მოითხოვს, რამდენსაც მის გარეშე.

## დაფარვის მოთხოვნა {#querying}

`tuist coverage` ბრძანებები კითხულობენ იმას, რასაც დაფა აჩვენებს. `--commit`-ის გარეშე, ისინი კითხულობენ `--branch`-ის უახლეს სრულ კომიტს, ან თქვენს ნაგულისხმევ შტოს:

```sh
tuist coverage show                          # the project's coverage and its targets
tuist coverage files --commit <sha>          # files, least covered first
tuist coverage file Sources/Cart.swift --lines  # a file's functions, with per-line counts
```

ყველა მათგანი იღებს `--json`-ს სკრიპტინგისთვის.
