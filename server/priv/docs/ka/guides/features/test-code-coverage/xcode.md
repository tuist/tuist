# Xcode-ის კოდის დაფარვა {#xcode-code-coverage}

<!-- @snippet: ./_xcode-early-access -->

კოდის დაფარვა გაჩვენებთ, თუ რომელი ხაზები შესრულდა თქვენი ტესტების მიერ. Tuist ატვირთავს ყოველი ტესტების გაშვების ხაზოვან დაფარვას და აერთიანებს ერთი კომიტის გაშვებებს ერთ მაჩვენებლად — პროექტისთვის, თითოეული სამიზნისა და ფაილისთვის. დაფის **კოდის დაფარვის** გვერდი აჩვენებს მას კომიტების მიხედვით და როგორც ტენდენციას თითოეული შტოსთვის.

> [!TIP]
> თუ პროექტს Tuist-ით გენერირებთ, მიჰყევით <.localized_link href="/guides/features/test-code-coverage/generated-xcode-project">გენერირებული პროექტის სახელმძღვანელოს</.localized_link>: ის ზომავს ბინარული ქეშიდან მომავალ კოდს და ინარჩუნებს იმ სატესტო სამიზნეების დაფარვას, რომლებსაც შერჩევითი ტესტირება ტოვებს.

## მოწყობა {#setup}

### დაფარვის შეგროვება {#collect-coverage}

ჩართეთ დაფარვის ატვირთვა თქვენს `Tuist.swift`-ში. ნაგულისხმევად ის გამორთულია:

```swift
import ProjectDescription

let tuist = Tuist(
    fullHandle: "my-account/my-project",
    testInsights: .testInsights(coverage: .coverage(upload: true)),
    project: .xcode()
)
```

`TUIST_COVERAGE_UPLOAD` გარემოს ცვლადი (`1` ან `0`) უპირატესობას იღებს პარამეტრზე, მაგალითად, ატვირთვის გამოსართავად ჯობებში, რომლებიც ასრულებენ pull request-ებს ფორკებიდან.

შემდეგ ჩართეთ **კოდის დაფარვა** თქვენი სქემის სატესტო მოქმედებაში (**Edit Scheme › Test › Options**), ან გადაეცით `-enableCodeCoverage YES` გაშვებას და გაუშვით ტესტები `tuist xcodebuild test`-ის მეშვეობით:

```sh
tuist xcodebuild test \
  -scheme MyScheme \
  -enableCodeCoverage YES
```

Tuist ატვირთავს გაშვების მიერ შეგროვებულ დაფარვას ტესტების შედეგებთან ერთად.

### CI-ზე თითოეული კომიტის დასრულება {#complete-each-commit}

კომიტის დაფარვა ხშირად რამდენიმე ჯობისგან მოდის: ერთი თითოეული სქემის, შარდის ან პლატფორმისთვის. Tuist-მა არ იცის, როდის მოახსენებს ბოლო მათგანი, ამიტომ მიუთითეთ ეს. როგორც კი კომიტის ყველა სატესტო ჯობა დასრულდება, გაუშვით ეს ჯობაში, რომელიც დამოკიდებულია მათ ყველაზე:

```sh
tuist coverage complete
```

სანამ კომიტი არ დასრულდება, მისი დაფარვა ჩანს როგორც **მიმდინარე** და არ შედის მისი შტოს ტენდენციაში. <.localized_link href="/guides/features/test-code-coverage/generated-xcode-project#commit-status">გენერირებული პროექტის სახელმძღვანელო</.localized_link> აღწერს თითოეულ სტატუსს.

## გამოტოვებული ტესტები {#skipped-tests}

როდესაც გაშვება ტესტებს ტოვებს `-skip-testing`-ით, ის ზომავს ნაკლებს, ვიდრე კომიტის ტესტები ფარავს, და Tuist ვერ გადააქვს ეს ტესტები წინა გაშვებიდან. კომიტის დაფარვა არის **არასრული**, თუ კომიტზე სხვა გაშვებამ არ გაუშვა ისინი. კომიტის სისრულის შესანარჩუნებლად, გაუშვით ყველა ტესტი კომიტზე მინიმუმ ერთ გაშვებაში.

ტესტები, რომლებსაც კარანტინი ტოვებს, საერთოდ არ შედიან დაფარვაში, ამიტომ ისინი არასდროს ხდიან კომიტს **არასრულად**.

## წარმადობაზე გავლენა {#performance-impact}

დაფარვის შეგროვება ზრდის დატვირთვას, ძირითადად ტესტების დასრულების შემდეგ, როდესაც Xcode წერს თავის დაფარვის ანგარიშს და Tuist ექსპორტავს დაფარვას. ტესტების აგება და გაშვება დაახლოებით იმდენსვე დროს იღებს, რამდენსაც მის გარეშე.

## დაფარვის მოთხოვნა {#querying}

`tuist coverage` ბრძანებები კითხულობენ იმას, რასაც დაფა აჩვენებს. `--commit`-ის გარეშე, ისინი კითხულობენ `--branch`-ის ან თქვენი ნაგულისხმევი შტოს ბოლო სრულ კომიტს:

```sh
tuist coverage show                          # the project's coverage and its targets
tuist coverage files --commit <sha>          # files, least covered first
tuist coverage file Sources/Cart.swift --lines  # a file's functions, with per-line counts
```

ყველა მათგანი იღებს `--json`-ს სკრიპტინგისთვის.
