# Elixir ტესტების ინსაიტები {#elixir-test-insights}

Tuist-ის Hex პაკეტი ატვირთავს თქვენი Elixir პროექტის ტესტების შედეგებს ყოველი ტესტების გაშვების შემდეგ, რაც საშუალებას გაძლევთ პირდაპირ Tuist დაშბორდზე დაინახოთ ტესტების შესრულება და არასტაბილური ტესტები.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - დაასრულეთ <.localized_link href="/guides/get-started/elixir-project">Elixir-ით დაწყება</.localized_link>

## ტესტების გაშვებების ანგარიშგება {#report-your-test-runs}

ზიარებული კონფიგურაცია აყენებს ტესტების ინტეგრაციას. განაგრძეთ `mix test`-ის გამოყენება იგივე არგუმენტებით, გამომავალი მონაცემებით და გასვლის კოდით:

```bash
mix test test/my_app_test.exs:12 --trace
```

Tuist აგზავნის ანგარიშს გაშვების დასრულებისას; დამატებითი ტესტის ალიასი არ არის საჭირო.

შეგიძლიათ ნახოთ თქვენი ტესტების ინსაიტები Tuist დაშბორდზე და დააკვირდეთ, როგორ იცვლება ისინი დროთა განმავლობაში:

![Phoenix აპლიკაციის ტესტების დაშბორდი](/images/guides/features/elixir/tests-dashboard.png)

## რა ფიქსირდება {#what-is-tracked}

პაკეტი აგროვებს ExUnit-ის შედეგებს, მათ შორის:
- ინდივიდუალური ტესტის წარმატებული/წარუმატებელი სტატუსი და ხანგრძლივობა
- მოდული და `describe` ბლოკი, რომელსაც ეკუთვნის თითოეული ტესტი
- თითოეული შეცდომის შეტყობინება და მდებარეობა
- არასტაბილური ტესტების აღმოჩენა გაშვებებს შორის
- ბრენჩი და კომიტი, ხოლო უწყვეტი ინტეგრაციისას — პროვაიდერი და გაშვება
- უწყვეტი ინტეგრაციისას — ჩეკაუთის [Git ისტორია](#git-history)

Doctests ანგარიშდება, როგორც ნებისმიერი სხვა ტესტი. `--cover`-ით ასევე აიტვირთება გაშვების ხაზოვანი დაფარვა: იხილეთ <.localized_link href="/guides/features/test-code-coverage/elixir">Elixir კოდის დაფარვა</.localized_link>.

> [!NOTE]
> პაკეტი აგზავნის ანგარიშს ExUnit ფორმატერის მეშვეობით, რომელსაც ის ამატებს თქვენს მიერ უკვე გამოყენებულ ფორმატერებთან ერთად. თუ კომანდის ხაზზე გადასცემთ `--formatter`-ს, Mix ცვლის მთელ სიას, ამიტომ გაშვება არ ანგარიშდება და ამოცანა გაფრთხილებთ ამის შესახებ.

### Git ისტორია {#git-history}

უწყვეტი ინტეგრაციისას პაკეტი ასევე ატვირთავს ჩეკაუთის კომიტების ისტორიას: კომიტების SHA-ებს, მათ მშობლებს, კომიტების თარიღებს და ბრენჩს, რომელზეც იყო გაშვება და მისი pull request-ის საბაზისო ბრენჩი. არ აიტვირთება ფაილების შინაარსი, კომიტების შეტყობინებები ან ავტორები. ეს ეუბნება Tuist-ს, რომელი კომიტები მოხვდა თქვენს საწყის ბრენჩზე, მაგალითად, ისინი, რომლებიც merge queue-მ შეამოწმა. პაკეტი კითხულობს ჩეკაუთის უკვე არსებულ ისტორიას და როდესაც ჩეკაუთს არ აქვს საბაზისო ბრენჩი, ითხოვს remote-დან მის უახლეს კომიტს (`git ls-remote`). კოდის დაფარვის (`--cover`) გარეთ ის არ იღებს ისტორიას. კოდის დაფარვისას ზედაპირული ჩეკაუთი ღრმავდება, ფაილების შინაარსის გარეშე, რათა იპოვოს, საიდან გაიყო pull request-ის ბრენჩი და, უწყვეტი ინტეგრაციისას, მიაღწიოს Tuist-ისთვის უკვე ცნობილ კომიტებს, ისე რომ კომიტი არასდროს აიტვირთება მშობლის გარეშე, რომელზეც ის ეყრდნობა.

| ცვლადი | ეფექტი |
| --- | --- |
| `TUIST_GIT_UPLOAD_ENABLED=false` | არ კითხულობს და არ ატვირთავს Git-ის რაიმე ისტორიას. |
| `TUIST_GIT_UNSHALLOW_ENABLED=false` | კითხულობს მხოლოდ ჩეკაუთს, remote-თან დაკავშირების გარეშე. |
| `TUIST_GIT_BRANCH=<branch>` | არქმევს გაშვების ბრენჩის სახელს, CI პროვაიდერისა და ჩეკაუთის წინ. დააყენეთ ის CI სისტემებზე, რომლებსაც Tuist არ ცნობს და რომლებიც ბრენჩის ნაცვლად კომიტს აკეთებენ ჩეკაუთს, რის გამოც მათ გაშვებებს წინააღმდეგ შემთხვევაში არ ექნებათ ბრენჩი. |

## პრობლემების აღმოფხვრა {#troubleshooting}

ანგარიშგება არასდროს ცვლის თქვენი ტესტების შედეგს: თუ ანგარიშის გაგზავნა ვერ ხერხდება, გაშვება სრულდება ისე, როგორც უნდა მომხდარიყო და არაფერი ბეჭდება. იმის სანახავად, რატომ არ გაიგზავნა ანგარიში, დააყენეთ `TUIST_DEBUG=1`:

```bash
TUIST_DEBUG=1 mix test
```
