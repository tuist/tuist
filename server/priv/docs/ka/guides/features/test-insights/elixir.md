# Elixir-ის ტესტების ანალიტიკა {#elixir-test-insights}

Tuist-ის Hex პაკეტი ყოველი ტესტების გაშვების შემდეგ ატვირთავს თქვენი Elixir პროექტის ტესტების შედეგებს, რაც საშუალებას გაძლევთ პირდაპირ Tuist-ის დაფზე ნახოთ ტესტების წარმადობა და არასტაბილური ტესტები.

> [!IMPORTANT] REQUIREMENTS
> - დაასრულეთ <.localized_link href="/guides/get-started/elixir-project">Elixir-ით დაწყება</.localized_link>

## ტესტების გაშვებების ანგარიში {#report-your-test-runs}

საერთო კონფიგურაცია აყენებს ტესტების ინტეგრაციას. განაგრძეთ `mix test`-ის გამოყენება იგივე არგუმენტებით, გამოტანით და გასვლის კოდით:

```bash
mix test test/my_app_test.exs:12 --trace
```

Tuist აგზავნის ანგარიშს გაშვების დასრულებისას; დამატებითი ტესტის ალიასი არ არის საჭირო.

შეგიძლიათ მიუწვდეთ თქვენს ტესტების ანალიტიკას Tuist-ის დაფზე და ნახოთ, როგორ იცვლება ის დროთა განმავლობაში:

![Phoenix აპლიკაციის ტესტების დაფა](/images/guides/features/elixir/tests-dashboard.png)

## რა ფიქსირდება {#what-is-tracked}

პაკეტი აგროვებს ExUnit-ის შედეგებს, მათ შორის:
- ინდივიდუალური ტესტის წარმატებული/ჩავარდნილი სტატუსი და ხანგრძლივობა
- მოდული და `describe` ბლოკი, რომელსაც თითოეული ტესტი ეკუთვნის
- ყოველი ჩავარდნის შეტყობინება და მდებარეობა
- არასტაბილური ტესტების აღმოჩენა გაშვებებს შორის
- ბრენჩი და კომიტი, ხოლო უწყვეტი ინტეგრაციისას — პროვაიდერი და გაშვება
- უწყვეტი ინტეგრაციისას — ჩეკაუტის [Git ისტორია](#git-history)

Doctests ანგარიშდება ნებისმიერ სხვა ტესტთან ერთად. `--cover`-ით ასევე აიტვირთება გაშვების ხაზოვანი დაფარვა: იხილეთ <.localized_link href="/guides/features/test-code-coverage/elixir">Elixir-ის კოდის დაფარვა</.localized_link>.

> [!NOTE]
> პაკეტი ანგარიშგებას ახდენს ExUnit ფორმატერის მეშვეობით, რომელსაც ის უმატებს თქვენს მიერ უკვე გამოყენებულ ფორმატერებს. თუ ბრძანების ხაზზე გადასცემთ `--formatter`-ს, Mix ცვლის მთელ სიას, ამიტომ გაშვება არ ანგარიშდება და ამოცანა გაფრთხილებთ ამის შესახებ.

### Git ისტორია {#git-history}

უწყვეტი ინტეგრაციისას პაკეტი ასევე ატვირთავს ჩეკაუტის კომიტების ისტორიას: კომიტების SHA-ები, მათი მშობლები, კომიტების თარიღები და ბრენჩი, რომელზეც იყო გაშვება და მისი pull request-ის საბაზო ბრენჩი. არ აიტვირთება ფაილების შინაარსი, კომიტების შეტყობინებები ან ავტორები. ეს არის ის, რაც ეუბნება Tuist-ს, რომელი კომიტები მოხვდა თქვენს საწყის ბრენჩზე, მაგალითად, ისინი, რომლებიც merge queue-მ შეამოწმა. პაკეტი კითხულობს ისტორიას, რომელიც ჩეკაუტს უკვე აქვს, და როცა ჩეკაუტს არ აქვს საბაზო ბრენჩი, ითხოვს უახლეს კომიტს remote-დან (`git ls-remote`). კოდის დაფარვის (`--cover`) გარეთ ისტორიას არ იღებს.

| ცვლადი | ეფექტი |
| --- | --- |
| `TUIST_GIT_UPLOAD_ENABLED=false` | არ კითხულობს და არ ატვირთავს Git-ის ისტორიას. |
| `TUIST_GIT_UNSHALLOW_ENABLED=false` | კითხულობს მხოლოდ ჩეკაუტს, remote-თან დაკავშირების გარეშე. |

## პრობლემების გადაჭრა {#troubleshooting}

ანგარიშგება არასდროს ცვლის თქვენი ტესტების შედეგს: თუ ანგარიშის გაგზავნა ვერ ხერხდება, გაშვება სრულდება ისე, როგორც უნდა და არაფერი იბეჭდება. იმის სანახავად, თუ რატომ არ გაიგზავნა ანგარიში, დააყენეთ `TUIST_DEBUG=1`:

```bash
TUIST_DEBUG=1 mix test
```
