# Elixir-ის ტესტების ანალიტიკა {#elixir-test-insights}

Tuist-ის Hex პაკეტი ყოველი ტესტების გაშვების შემდეგ ატვირთავს თქვენი Elixir პროექტის ტესტების შედეგებს, რაც საშუალებას გაძლევთ პირდაპირ Tuist დაფზე ნახოთ ტესტების წარმადობა და არასტაბილური ტესტები.

> [!IMPORTANT] REQUIREMENTS
> - შეასრულეთ <.localized_link href="/guides/get-started/elixir-project">Elixir-ით მუშაობის დაწყება</.localized_link>

## ატვირთეთ ტესტების გაშვებები {#report-your-test-runs}

საერთო კონფიგურაცია აყენებს ტესტების ინტეგრაციას. განაგრძეთ `mix test`-ის გამოყენება იგივე არგუმენტებით, გამომავალი მონაცემებით და გასვლის კოდით:

```bash
mix test test/my_app_test.exs:12 --trace
```

Tuist ატვირთავს გაშვების მონაცემებს მისი დასრულებისას; დამატებითი ტესტების ალიასი არ არის საჭირო.

შეგიძლიათ ნახოთ თქვენი ტესტების ანალიტიკა Tuist დაფზე და დააკვირდეთ, როგორ იცვლება ისინი დროთა განმავლობაში:

![Phoenix აპლიკაციის ტესტების დაფა](/images/guides/features/elixir/tests-dashboard.png)

## რა ფიქსირდება {#what-is-tracked}

პაკეტი აგროვებს ExUnit-ის შედეგებს, მათ შორის:
- ინდივიდუალური ტესტების წარმატებული/წარუმატებელი სტატუსი და ხანგრძლივობა
- მოდული და `describe` ბლოკი, რომელსაც ეკუთვნის თითოეული ტესტი
- თითოეული შეცდომის შეტყობინება და მდებარეობა
- არასტაბილური ტესტების აღმოჩენა გაშვებებს შორის
- ბრენჩი და კომიტი, ხოლო უწყვეტი ინტეგრაციისას — პროვაიდერი და გაშვება
- უწყვეტი ინტეგრაციისას — ჩეკაუტის [Git ისტორია](#git-history)

Doctests ანგარიშდება ნებისმიერი სხვა ტესტის მსგავსად. `--cover`-ის გამოყენებისას ასევე აიტვირთება გაშვების ხაზოვანი დაფარვა: იხილეთ <.localized_link href="/guides/features/test-code-coverage/elixir">Elixir კოდის დაფარვა</.localized_link>.

> [!NOTE]
> პაკეტი ანგარიშდება ExUnit ფორმატერის მეშვეობით, რომელსაც ის ამატებს თქვენს მიერ უკვე გამოყენებულ ფორმატერებთან ერთად. თუ ბრძანების ხაზში გადასცემთ `--formatter`-ს, Mix ცვლის მთელ სიას, ამიტომ გაშვება არ ანგარიშდება და ამოცანა გაფრთხილებთ ამის შესახებ.

### Git ისტორია {#git-history}

უწყვეტი ინტეგრაციისას პაკეტი ასევე ატვირთავს ჩეკაუტის კომიტების ისტორიას: კომიტების SHA-ები, მათი მშობლები, კომიტების თარიღები და ბრენჩი, რომელზეც იყო გაშვება და მისი pull request-ის საბაზო ბრენჩი. არ აიტვირთება ფაილების შინაარსი, კომიტების შეტყობინებები ან ავტორები. ეს არის ინფორმაცია, რომელიც ეუბნება Tuist-ს, რომელი კომიტები მოხვდა თქვენს საბაზო ბრენჩზე, მაგალითად, ისინი, რომლებიც merge queue-მ შეამოწმა. პაკეტი კითხულობს ჩეკაუტში უკვე არსებულ ისტორიას და როდესაც ჩეკაუტს არ აქვს საბაზო ბრენჩი, ითხოვს მის უახლეს კომიტს დაშორებული რეპოზიტორიიდან (`git ls-remote`). კოდის დაფარვის (`--cover`) გარეთ, ისტორიას არ იღებს.

| ცვლადი | ეფექტი |
| --- | --- |
| `TUIST_GIT_UPLOAD_ENABLED=false` | არ კითხულობს და არ ატვირთავს Git-ის ისტორიას. |
| `TUIST_GIT_UNSHALLOW_ENABLED=false` | კითხულობს მხოლოდ ჩეკაუტს, დაშორებულ რეპოზიტორიასთან დაკავშირების გარეშე. |

## პრობლემების გადაჭრა {#troubleshooting}

ანგარიშგება არასდროს ცვლის თქვენი ტესტების შედეგს: თუ ანგარიშის გაგზავნა ვერ ხერხდება, გაშვება სრულდება ისე, როგორც სრულდებოდა და არაფერი იბეჭდება. იმის სანახავად, თუ რატომ არ გაიგზავნა ანგარიში, დააყენეთ `TUIST_DEBUG=1`:

```bash
TUIST_DEBUG=1 mix test
```
