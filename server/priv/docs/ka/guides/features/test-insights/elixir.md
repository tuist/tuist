# Elixir ტესტების ანალიტიკა {#elixir-test-insights}

Tuist-ის Hex პაკეტი ყოველი ტესტის გაშვების შემდეგ ატვირთავს თქვენი Elixir პროექტის ტესტების შედეგებს, რაც საშუალებას გაძლევთ პირდაპირ Tuist დაშბორდზე ნახოთ ტესტების შესრულება და არამდგრადი ტესტები.

> [!IMPORTANT] REQUIREMENTS
> - დაასრულეთ <.localized_link href="/guides/get-started/elixir-project">Elixir-ის დაწყება</.localized_link>

## ტესტების გაშვებების ანგარიში {#report-your-test-runs}

ზოგადი კონფიგურაცია აყენებს ტესტების ინტეგრაციას. განაგრძეთ `mix test`-ის გამოყენება იგივე არგუმენტებით, გამომავალი მონაცემებითა და გასვლის კოდით:

```bash
mix test test/my_app_test.exs:12 --trace
```

Tuist აგზავნის ანგარიშს გაშვების დასრულებისას; დამატებითი ტესტის ალიასი არ არის საჭირო.

შეგიძლიათ მიუწვდეთ თქვენს ტესტების ანალიტიკას Tuist დაშბორდზე და ნახოთ, როგორ იცვლება ისინი დროთა განმავლობაში:

![Phoenix აპლიკაციის ტესტების დაშბორდი](/images/guides/features/elixir/tests-dashboard.png)

## რა ფიქსირდება {#what-is-tracked}

პაკეტი აგროვებს ExUnit-ის შედეგებს, მათ შორის:
- ინდივიდუალური ტესტის წარმატებული/ჩავარდნილი სტატუსი და ხანგრძლივობა
- მოდული და `describe` ბლოკი, რომელსაც თითოეული ტესტი ეკუთვნის
- თითოეული შეცდომის შეტყობინება და მდებარეობა
- არამდგრადი ტესტების აღმოჩენა გაშვებებს შორის
- ბრენჩი და კომიტი, ხოლო უწყვეტი ინტეგრაციისას — პროვაიდერი და გაშვება
- უწყვეტი ინტეგრაციისას — ჩეკაუტის [Git ისტორია](#git-history)

Doctests იგზავნება ისევე, როგორც ნებისმიერი სხვა ტესტი.

> [!NOTE]
> პაკეტი აგზავნის ანგარიშს ExUnit ფორმატერის მეშვეობით, რომელსაც ის ამატებს თქვენს მიერ უკვე გამოყენებულ ფორმატერებთან ერთად. თუ ბრძანების სტრიქონში გადასცემთ `--formatter`-ს, Mix ცვლის მთელ სიას, ამიტომ გაშვება არ იგზავნება და ამოცანა გაფრთხილებთ ამის შესახებ.

### Git ისტორია {#git-history}

უწყვეტი ინტეგრაციისას პაკეტი ასევე ატვირთავს ჩეკაუტის კომიტების ისტორიას: კომიტების SHA-ები, მათი მშობლები, კომიტების თარიღები და ბრენჩი, რომელზეც იყო გაშვება და მისი pull request-ის საბაზო ბრენჩი. არ იტვირთება ფაილების შინაარსი, კომიტების შეტყობინებები ან ავტორები. ეს არის ინფორმაცია, რომელიც ეუბნება Tuist-ს, რომელი კომიტები მოხვდა თქვენს საბაზო ბრენჩზე, მაგალითად, ისინი, რომლებიც merge queue-მ შეამოწმა. პაკეტი კითხულობს ისტორიას, რომელიც ჩეკაუტს უკვე აქვს, და როდესაც ჩეკაუტს არ აქვს საბაზო ბრენჩი, ითხოვს უახლეს კომიტს remote-დან (`git ls-remote`). კოდის დაფარვის გარეთ (`--cover`), ის არ იღებს ისტორიას.

| ცვლადი | ეფექტი |
| --- | --- |
| `TUIST_GIT_UPLOAD_ENABLED=false` | არ კითხულობს და არ ტვირთავს Git-ის ისტორიას. |
| `TUIST_GIT_UNSHALLOW_ENABLED=false` | კითხულობს მხოლოდ ჩეკაუტს, remote-თან დაკავშირების გარეშე. |

## პრობლემების აღმოფხვრა {#troubleshooting}

ანგარიშის გაგზავნა არასდროს ცვლის თქვენი ტესტების შედეგს: თუ ანგარიშის გაგზავნა ვერ ხერხდება, გაშვება სრულდება ისე, როგორც უნდა დასრულებულიყო და არაფერი იბეჭდება. იმის სანახავად, თუ რატომ არ გაიგზავნა ანგარიში, დააყენეთ `TUIST_DEBUG=1`:

```bash
TUIST_DEBUG=1 mix test
```
