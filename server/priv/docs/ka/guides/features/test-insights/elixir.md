# Elixir-ის ტესტების ანალიტიკა {#elixir-test-insights}

Tuist-ის Hex პაკეტი ყოველი ტესტების გაშვების შემდეგ ატვირთავს თქვენი Elixir პროექტის ტესტების შედეგებს, რაც საშუალებას გაძლევთ პირდაპირ Tuist-ის დაფზე ნახოთ ტესტების წარმადობა და არასტაბილური ტესტები.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - დაასრულეთ <.localized_link href="/guides/get-started/elixir-project">Elixir-ით დაწყება</.localized_link>

## ტესტების გაშვებების ანგარიში {#report-your-test-runs}

ზიარებული კონფიგურაცია აყენებს ტესტების ინტეგრაციას. განაგრძეთ `mix test`-ის გამოყენება იგივე არგუმენტებით, გამოტანით და გასვლის კოდით:

```bash
mix test test/my_app_test.exs:12 --trace
```

Tuist აგზავნის ანგარიშს გაშვების დასრულებისას; დამატებითი ტესტების ალიასი არ არის საჭირო.

შეგიძლიათ მიუწვდეთ თქვენს ტესტების ანალიტიკას Tuist-ის დაფზე და ნახოთ, როგორ იცვლება ის დროთა განმავლობაში:

![Phoenix აპლიკაციის ტესტების დაფა](/images/guides/features/elixir/tests-dashboard.png)

## რა ფიქსირდება {#what-is-tracked}

პაკეტი აგროვებს ExUnit-ის შედეგებს, მათ შორის:
- ინდივიდუალური ტესტების წარმატებული/ჩავარდნილი სტატუსი და ხანგრძლივობა
- მოდული და `describe` ბლოკი, რომელსაც თითოეული ტესტი ეკუთვნის
- ყოველი ჩავარდნის შეტყობინება და მდებარეობა
- არასტაბილური ტესტების აღმოჩენა გაშვებებს შორის
- ბრენჩი და კომიტი, ხოლო უწყვეტი ინტეგრაციისას — პროვაიდერი და გაშვება
- უწყვეტი ინტეგრაციისას — შემოწმების [Git ისტორია](#git-history)

Doctests ანგარიშდება როგორც ნებისმიერი სხვა ტესტი. `--cover`-ით ასევე აიტვირთება გაშვების ხაზოვანი დაფარვა: იხილეთ <.localized_link href="/guides/features/test-code-coverage/elixir">Elixir კოდის დაფარვა</.localized_link>.

> [!NOTE]
> პაკეტი აგზავნის ანგარიშს ExUnit ფორმატერის მეშვეობით, რომელსაც ის ამატებს თქვენს მიერ უკვე გამოყენებულ ფორმატერებთან ერთად. თუ ბრძანების ხაზზე გადასცემთ `--formatter`-ს, Mix ცვლის მთელ სიას, ამიტომ გაშვება არ ანგარიშდება და ამოცანა გაფრთხილებთ ამის შესახებ.

### Git ისტორია {#git-history}

უწყვეტი ინტეგრაციისას პაკეტი ასევე ატვირთავს შემოწმების კომიტების ისტორიას: კომიტების SHA-ები, მათი მშობლები, კომიტების თარიღები და ბრენჩი, რომელზეც იყო გაშვება და მისი pull request-ის საბაზო ბრენჩი. არ აიტვირთება ფაილების შინაარსი, კომიტების შეტყობინებები ან ავტორები. ეს არის ის, რაც ეუბნება Tuist-ს, რომელი კომიტები მოხვდა თქვენს საწყის ბრენჩზე, მაგალითად, ისინი, რომლებიც merge queue-მ შეამოწმა. პაკეტი კითხულობს ისტორიას, რომელიც შემოწმებას უკვე აქვს, და როდესაც შემოწმებას არ აქვს საბაზო ბრენჩი, ითხოვს remote-დან მის უახლეს კომიტს (`git ls-remote`). კოდის დაფარვის (`--cover`) გარეთ ის არ იღებს ისტორიას. კოდის დაფარვისას ზედაპირული შემოწმება ღრმავდება, ფაილების შინაარსის გარეშე, რათა იპოვოს, სად გაიყოფა pull request და, უწყვეტი ინტეგრაციისას, მიაღწიოს კომიტებს, რომლებიც Tuist-ს უკვე აქვს, ისე, რომ კომიტი არასდროს აიტვირთოს მშობლის გარეშე, რომელზეც ის ეყრდნობა.

| ცვლადი | ეფექტი |
| --- | --- |
| `TUIST_GIT_UPLOAD_ENABLED=false` | არ კითხულობს და არ ატვირთავს Git-ის ისტორიას. |
| `TUIST_GIT_UNSHALLOW_ENABLED=false` | კითხულობს მხოლოდ შემოწმებას, remote-თან დაკავშირების გარეშე. |

## პრობლემების გადაჭრა {#troubleshooting}

ანგარიშის გაგზავნა არასდროს ცვლის თქვენი ტესტების შედეგს: თუ ანგარიშის გაგზავნა ვერ ხერხდება, გაშვება სრულდება ისე, როგორც უნდა მომხდარიყო და არაფერი ბეჭდება. იმის სანახავად, რატომ არ გაიგზავნა ანგარიში, დააყენეთ `TUIST_DEBUG=1`:

```bash
TUIST_DEBUG=1 mix test
```
