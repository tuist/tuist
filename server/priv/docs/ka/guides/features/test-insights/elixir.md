# Elixir-ის ტესტების ანალიტიკა {#elixir-test-insights}

Tuist-ის Hex პაკეტი ყოველი ტესტების გაშვების შემდეგ ატვირთავს თქვენი Elixir პროექტის ტესტების შედეგებს, რაც საშუალებას გაძლევთ პირდაპირ Tuist-ის დაფაზე დაინახოთ ტესტების შესრულების მაჩვენებლები და არასტაბილური ტესტები.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - დაასრულეთ <.localized_link href="/guides/get-started/elixir-project">Elixir-ით მუშაობის დაწყება</.localized_link>

## ტესტების გაშვებების ანგარიში {#report-your-test-runs}

ზოგადი კონფიგურაცია აყენებს ტესტების ინტეგრაციას. განაგრძეთ `mix test`-ის გამოყენება იგივე არგუმენტებით, გამომავალი მონაცემებითა და გასვლის კოდით:

```bash
mix test test/my_app_test.exs:12 --trace
```

Tuist ანგარიშს აგზავნის გაშვების დასრულებისას; დამატებითი ტესტების ალიასი არ არის საჭირო.

შეგიძლიათ ნახოთ თქვენი ტესტების ანალიტიკა Tuist-ის დაფაზე და დააკვირდეთ, როგორ იცვლება ის დროთა განმავლობაში:

![Phoenix აპლიკაციის ტესტების დაფა](/images/guides/features/elixir/tests-dashboard.png)

## რა ფიქსირდება {#what-is-tracked}

პაკეტი აგროვებს ExUnit-ის შედეგებს, მათ შორის:
- ცალკეული ტესტების წარმატებული/შეცდომის სტატუსი და ხანგრძლივობა
- მოდული და `describe` ბლოკი, რომელსაც თითოეული ტესტი ეკუთვნის
- თითოეული შეცდომის შეტყობინება და მდებარეობა
- არასტაბილური ტესტების აღმოჩენა სხვადასხვა გაშვებებში
- ბრენჩი და კომიტი, ხოლო უწყვეტი ინტეგრაციის დროს — პროვაიდერი და გაშვება
- უწყვეტი ინტეგრაციის დროს — ჩეკაუტის [Git ისტორია](#git-history)

Doctests იგზავნება ნებისმიერი სხვა ტესტის მსგავსად. `--cover`-ის გამოყენებისას ასევე აიტვირთება გაშვების ხაზოვანი დაფარვა: იხილეთ <.localized_link href="/guides/features/test-code-coverage/elixir">Elixir-ის კოდის დაფარვა</.localized_link>.

> [!NOTE]
> პაკეტი ანგარიშს აგზავნის ExUnit ფორმატერის მეშვეობით, რომელსაც ის ამატებს თქვენს მიერ უკვე გამოყენებულ ფორმატერებთან ერთად. თუ ბრძანების სტრიქონში გადასცემთ `--formatter`-ს, Mix ცვლის მთელ სიას, ამიტომ გაშვება არ იგზავნება და ამოცანა გაფრთხილებთ ამის შესახებ.

### Git ისტორია {#git-history}

უწყვეტი ინტეგრაციის დროს პაკეტი ასევე ატვირთავს ჩეკაუტის კომიტების ისტორიას: კომიტების SHA-ები, მათი მშობლები, კომიტების თარიღები და ბრენჩი, რომელზეც იყო გაშვება და მისი pull request-ის საბაზო ბრენჩი. არ აიტვირთება ფაილების შინაარსი, კომიტების შეტყობინებები ან ავტორები. ეს ინფორმაცია ეუბნება Tuist-ს, რომელი კომიტები მოხვდა თქვენს საბაზო ბრენჩზე, მაგალითად, ისინი, რომლებიც merge queue-მ შეამოწმა. პაკეტი კითხულობს ჩეკაუტში უკვე არსებულ ისტორიას და როდესაც ჩეკაუტს არ აქვს საბაზო ბრენჩი, ითხოვს უახლეს კომიტს remote-დან (`git ls-remote`). კოდის დაფარვის (`--cover`) გარეთ ისტორიას არ იტვირთავს. კოდის დაფარვის დროს ზედაპირული ჩეკაუტი ღრმავდება ფაილების შინაარსის გარეშე, რათა დადგინდეს, საიდან გადაიხარა pull request და უწყვეტი ინტეგრაციის დროს მიღწეულ იქნას Tuist-ისთვის უკვე ცნობილი კომიტები, ისე რომ კომიტი არასდროს აიტვირთოს მშობლის გარეშე.

| ცვლადი | ეფექტი |
| --- | --- |
| `TUIST_GIT_UPLOAD_ENABLED=false` | არ კითხულობს და არ ატვირთავს Git-ის ისტორიას. |
| `TUIST_GIT_UNSHALLOW_ENABLED=false` | კითხულობს მხოლოდ ჩეკაუტს, remote-თან დაკავშირების გარეშე. |

## პრობლემების გადაჭრა {#troubleshooting}

ანგარიშის გაგზავნა არასდროს ცვლის თქვენი ტესტების შედეგს: თუ ანგარიშის გაგზავნა ვერ ხერხდება, გაშვება სრულდება ისე, როგორც ჩვეულებრივ და არაფერი ბეჭდება. იმის სანახავად, რატომ არ გაიგზავნა ანგარიში, დააყენეთ `TUIST_DEBUG=1`:

```bash
TUIST_DEBUG=1 mix test
```
