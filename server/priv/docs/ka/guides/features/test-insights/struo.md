# Struo-ს ტესტების ანალიტიკა {#struo-test-insights}

<a id="once-test-insights"></a>

Struo აგზავნის ტესტების შედეგებს Tuist-ში, რათა შეგიძლიათ თვალყური ადევნოთ თქვენს ტესტების ნაკრებს როგორც ლოკალურად, ისე CI-ში, გამოიკვლიოთ შეცდომები და იპოვოთ ნელი ტესტები ცალკეული სამუშაო კვანძებიდან ანგარიშების შეგროვების გარეშე.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - დაასრულეთ <.localized_link href="/guides/get-started/struo-project">Struo-ს დაწყება</.localized_link>.
> - გამოიყენეთ ტესტის სამიზნეები (targets), რომლებიც აწვდიან სტრუქტურირებულ შედეგებს. ხელმისაწვდომი დეტალები დამოკიდებულია სამიზნის ტიპზე და ტესტების გამშვებზე (test runner).

## ტესტების გაშვების ანგარიშგება {#report-your-test-runs}

გაუშვით მთლიანი ნაკრები ან აირჩიეთ კონკრეტული სამიზნე:

```bash
struo test
struo test MyTests
```

Struo ნაკადურად აგზავნის ნატიურ ტესტის მოვლენებს და აქვეყნებს დასრულებულ შედეგებს Tuist-ის საერთო ტესტის მოდელში. **ტესტები** და **ტესტების გაშვებები** აჩვენებენ გაშვებებს; ინდივიდუალურ საქმეებსაც აქვთ საერთო ტესტის ისტორია. <.localized_link href="/guides/features/test-sharding/struo">ჰოსტინგზე განლაგებული დაშლილი გაშვება</.localized_link> აქვეყნებს ერთ ანგარიშს თითოეული სამუშაო კვანძისთვის გაერთიანებულ გაშვებაში, ნაცვლად მისი დიაგნოსტიკური მოვლენების ნაკადის ხელახლა დათვლისა.

## რა ფიქსირდება {#what-is-tracked}

- ანგარიშგებული ტესტის სამიზნეები, ნაკრებები და ინდივიდუალური საქმეები.
- წარმატებული, წარუმატებელი და გამოტოვებული შედეგები, ხანგრძლივობებით, თუ მათ გამშვები აწვდის.
- შეცდომის შეტყობინებები, რომლებიც გამშვებმა მიწოდა ჰოსტინგზე განლაგებულ დაშლილ ანგარიშებში.
- დალაგებული ხელახალი ცდები და არასტაბილური შედეგები, როდესაც ტესტი ჯერ ვერხერხდება, შემდეგ კი წარმატებით სრულდება.
- ბრენჩი, კომიტი და CI კონტექსტი, რომელიც Struo-მ მიწოდა.

ტესტის იდენტიფიკაცია ეფუძნება ნატიურ სამიზნეს, ნაკრებს და საქმის სახელს. დაშლის პაკეტის ID-ები არის დაგეგმვის ერთეულები და არა ტესტის სახელები.

ჩვეულებრივი `struo test` ანგარიშგება ინარჩუნებს შედეგებს და ხელახალი ცდების მცდელობებს, მაგრამ ამჟამად არ მოიცავს შეცდომის შეტყობინებებს საერთო ტესტის ისტორიაში. ჰოსტინგზე განლაგებულ დაშლილ ანგარიშებს შეიძლება ჰქონდეთ შეცდომის შეტყობინებები, მაგრამ არცერთი ანგარიშგების გზა არ აწვდის წყაროს მდებარეობებს. შეინახეთ თქვენი CI ლოგები დიაგნოსტიკისთვის, რომელიც Tuist-ში არ არის ხელმისაწვდომი.

არა ყველა ტესტის სამიზნე უზრუნველყოფს ერთნაირ დეტალიზაციას. ზოგიერთი გამშვები ანგარიშგებს ინდივიდუალურ საქმეებს, სხვები მხოლოდ შეჯამებებს; ზუსტი ფაილის ან საქმის შესრულება ცალკე შესაძლებლობაა. იხილეთ [Struo-ს ტესტების ეკოსისტემის დაფარვა](https://struo.run/docs/guide/graph/testing#understand-current-ecosystem-coverage), სანამ დაეყრდნობოდეთ საქმეების დონის ანალიტიკას ან დახვეწილ დაგეგმვას.

## არასტაბილური ტესტები {#flaky-tests}

Tuist იყენებს ანგარიშგებულ მცდელობებს და CI ისტორიას არათანმიმდევრული შედეგების იდენტიფიცირებისთვის. მცდელობის ანგარიშგება არ ნიშნავს ხელახალი ცდების ჩართვას: დააყენეთ ხელახალი ცდები იმ გამშვებში, რომელიც მათ მხარდაჭერს. იხილეთ <.localized_link href="/guides/features/test-insights/flaky-tests/struo">Struo-ს არასტაბილური ტესტები</.localized_link> აღმოჩენისა და მიმდინარე კარანტინის საზღვრებისთვის.

## შერჩევა და კოდის დაფარვა {#selection-and-code-coverage}

Struo-ს შეუძლია კონსერვატიულად შეარჩიოს ტესტები თავისი ლოკალური გრაფიდან `--changed-path`-ის გამოყენებით. ეს არის Struo-ს საკუთარი შერჩევა და არა Tuist-ის ჰოსტინგზე დაფარვაზე დაფუძნებული ტესტების შერჩევა:

```bash
struo test --changed-path src/library.rs
```

ნატიური Struo ანგარიშგება ამჟამად არ ტვირთავს კოდის დაფარვას Tuist-ში. წარმატებული ტესტის ანგარიში ან დაშლის გეგმა არ ავსებს კოდის დაფარვის დაფას (dashboard).

## პრობლემების გადაჭრა {#troubleshooting}

თუ გაშვება აკლია, შეამოწმეთ, რომ ეფექტური ქეშის პროვაიდერი ასახელებს თქვენს Tuist პროექტს და ხელახლა გაიარეთ ავთენტიკაცია `struo auth login --provider tuist`-ით. ცოცხალი ანგარიშგება ხორციელდება მაქსიმალური ძალისხმევით და არ გარდაქმნის წარმატებულ ტესტის ბრძანებას შეცდომად, როდესაც ანგარიშგების სერვისი მიუწვდომელია.

გაშვების შეჯამებები და სტრუქტურირებული ტესტის შეცდომები არ არის სრული პროცესის ლოგები. ეს სერვერი ამჟამად არ იღებს Struo-ს raw action log stream-ს; შეინახეთ თქვენი CI ლოგები იმ გამოტანისთვის, რომელიც არ არის ჩართული სტრუქტურირებულ შედეგებში.
