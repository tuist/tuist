# Struo-ს ტესტების ანალიტიკა {#struo-test-insights}

<a id="once-test-insights"></a>

Struo აგზავნის ტესტების შედეგებს Tuist-ში, რათა შეძლოთ თქვენი ტესტების ნაკრების თვალყურის დევნება როგორც ლოკალურად, ისე CI-ში, გამოიკვლიოთ შეცდომები და იპოვოთ ნელი ტესტები ცალკეული სამუშაო პროცესების ანგარიშების შეგროვების გარეშე.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - დაასრულეთ <.localized_link href="/guides/get-started/struo-project">Struo-ს გამოყენების დაწყება</.localized_link>.
> - გამოიყენეთ ტესტის მიზნები (targets), რომლებიც აბარებენ სტრუქტურირებულ შედეგებს. ხელმისაწვდომი დეტალები დამოკიდებულია მიზნის ტიპზე და ტესტის გამშვებზე (runner).

## აანგარიშეთ თქვენი ტესტების გაშვებები {#report-your-test-runs}

გაუშვით მთლიანი ნაკრები ან აირჩიეთ კონკრეტული მიზანი:

```bash
struo test
struo test MyTests
```

Struo გადასცემს ნატიურ ტესტის მოვლენებს და აქვეყნებს დასრულებულ შედეგებს Tuist-ის საერთო ტესტის მოდელში. **ტესტები** და **ტესტების გაშვებები** აჩვენებს გაშვებებს; ინდივიდუალურ შემთხვევებსაც აქვთ საერთო ტესტის ისტორია. <.localized_link href="/guides/features/test-sharding/struo">ჰოსტინგზე განთავსებული დაშლილი (sharded) გაშვება</.localized_link> აქვეყნებს ერთ ანგარიშს თითოეული სამუშაო პროცესისთვის გაერთიანებულ გაშვებაში, ნაცვლად მისი დიაგნოსტიკური მოვლენების ნაკადის ხელახლა დათვლისა.

## რა ფიქსირდება {#what-is-tracked}

- აანგარიშებული ტესტის მიზნები, ნაკრებები და ინდივიდუალური შემთხვევები.
- წარმატებული, წარუმატებელი და გამოტოვებული შედეგები, ხანგრძლივობებით, თუ გამშვები (runner) მათ აწვდის.
- შეცდომის შეტყობინებები, რომლებიც გამშვებმა (runner) მოაწოდა ჰოსტინგზე განთავსებულ დაშლილ (sharded) ანგარიშებში.
- დალაგებული ხელახალი ცდის მცდელობები და არასტაბილური შედეგები, როდესაც ტესტი ჯერ ვერ გადის, მაგრამ შემდეგ გადის.
- შტოს (branch), კომიტის და CI კონტექსტი, რომელსაც Struo აწვდის.

ტესტის იდენტურობა ეფუძნება ნატიურ მიზანს, ნაკრებს და შემთხვევის სახელს. დაშლის (sharding) პაკეტის ID-ები არის დაგეგმვის ერთეულები და არა ტესტის სახელები.

ჩვეულებრივი `struo test` ანგარიშგება ინარჩუნებს შედეგებს და ხელახალი ცდის მცდელობებს, მაგრამ ამჟამად არ შეიცავს შეცდომის შეტყობინებებს საერთო ტესტის ისტორიაში. ჰოსტინგზე განთავსებულ დაშლილ (sharded) ანგარიშებში შეიძლება იყოს შეცდომის შეტყობინებები, მაგრამ ანგარიშგების არცერთი გზა არ აწვდის წყაროს მდებარეობებს. შეინახეთ თქვენი CI ლოგები დიაგნოსტიკისთვის, რომელიც Tuist-ში არ არის ხელმისაწვდომი.

არა ყველა ტესტის მიზანი უზრუნველყოფს ერთნაირ დეტალებს. ზოგიერთი გამშვები (runner) აბარებს ინდივიდუალურ შემთხვევებს, სხვები მხოლოდ შეჯამებებს; ზუსტი ფაილის ან შემთხვევის შესრულება ცალკე შესაძლებლობაა. სანამ ეყრდნობოდეთ შემთხვევაზე დაფუძნებულ ანალიტიკას ან დეტალურ დაგეგმვას, იხილეთ [Struo-ს ტესტის ეკოსისტემის დაფარვა](https://struo.run/docs/guide/graph/testing#understand-current-ecosystem-coverage).

## არასტაბილური ტესტები {#flaky-tests}

Tuist იყენებს ანგარიშგებულ მცდელობებს და CI ისტორიას შეუთანხმებელი შედეგების იდენტიფიცირებისთვის. მცდელობის ანგარიშგება არ ნიშნავს ხელახალი ცდების ჩართვას: დააკონფიგურირეთ ხელახალი ცდები იმ გამშვებში (runner), რომელიც მათ მხარდაჭერს. იხილეთ <.localized_link href="/guides/features/test-insights/flaky-tests/struo">Struo-ს არასტაბილური ტესტები</.localized_link> აღმოჩენისა და მიმდინარე კარანტინის ზღვრის შესახებ.

## შერჩევა და კოდის დაფარვა {#selection-and-code-coverage}

Struo-ს შეუძლია კონსერვატიულად შეარჩიოს ტესტები თავისი ლოკალური გრაფიდან `--changed-path`-ის გამოყენებით. ეს არის Struo-ს საკუთარი შერჩევა და არა Tuist-ის ჰოსტინგზე დაფუძნებული დაფარვის ტესტის შერჩევა:

```bash
struo test --changed-path src/library.rs
```

ნატიური Struo ანგარიშგება ამჟამად არ ტვირთავს კოდის დაფარვას Tuist-ში. წარმატებული ტესტის ანგარიში ან დაშლის (shard) გეგმა არ ავსებს კოდის დაფარვის დაფას (dashboard).

## პრობლემების გადაჭრა {#troubleshooting}

თუ გაშვება აკლია, შეამოწმეთ, რომ ეფექტური ქეშის პროვაიდერი ასახელებს თქვენს Tuist პროექტს და ხელახლა გაიარეთ ავთენტიკაცია `struo auth login --provider tuist`-ით. პირდაპირი ანგარიშგება ხორციელდება მაქსიმალური ძალისხმევით და არ აქცევს წარმატებულ ტესტის ბრძანებას შეცდომად, თუ ანგარიშგების სერვისი მიუწვდომელია.

გაშვების შეჯამებები და სტრუქტურირებული ტესტის შეცდომები არ არის სრული პროცესის ლოგები. ეს სერვერი ამჟამად არ იღებს Struo-ს ნედლ მოქმედების ლოგების ნაკადს; შეინახეთ თქვენი CI ლოგები იმ გამოტანისთვის, რომელიც არ არის შეტანილი სტრუქტურირებულ შედეგებში.
