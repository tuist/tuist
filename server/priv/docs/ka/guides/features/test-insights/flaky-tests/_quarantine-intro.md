კარანტინი იზოლირებს არასტაბილურ სატესტო შემთხევას, რათა მან არ დაბლოკოს CI სისტემა მისი გამოსწორების დროს. ნაგულისხმევად ეს არის **ხელით შესრულებული ქმედება**: თქვენ აყენებთ ტესტს კარანტინში, ათავისუფლებთ მას და ცვლით რეჟიმებს დაშბორდის სატესტო შემთხვევის დეტალური გვერდიდან. ასევე შეგიძლიათ ის დააკავშიროთ **ავტომატიზაციის გაფრთხილებასთან** განყოფილებაში **პარამეტრები → ავტომატიზაციები**, რათა ტესტი ავტომატურად დადუმდეს (ან გამოიტოვოს), როცა ის გადალახავს არასტაბილურობის ზღვარს, და გათავისუფლდეს, როცა აღდგება. ყოველი გადასვლა, ხელით თუ ავტომატურად, ფიქსირდება სატესტო შემთხვევის აუდიტის ჟურნალში.

ნაგულისხმევად, აღდგენა ელოდება, სანამ ტრიგერის პირობა აღარ იქნება მოქმედი, ამიტომ ტესტი რჩება კარანტინში, სანამ მისი ძველი არასტაბილური გაშვებები არ დატოვებენ ტრიგერის ფანჯარას. უფრო სწრაფად აღსადგენად, დააყენეთ **აღდგენის პირობა** მნიშვნელობაზე **ახალი არასტაბილური გაშვებების გარეშე**: ტესტი აღდგება, როცა აღდგენის ფანჯარა (დღეები ან გაშვებები) გავა ახალი არასტაბილური გაშვების გარეშე, ყოველი ახალი არასტაბილური გაშვება თავიდან იწყებს ამ ლოდინს და აღდგენის შემდეგ მხოლოდ ახალი არასტაბილური გაშვება კვლავ აყენებს მას კარანტინში.
