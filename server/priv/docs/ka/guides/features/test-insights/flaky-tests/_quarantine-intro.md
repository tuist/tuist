კარანტინი იზოლირებს არასტაბილურ სატესტო შემთხვევას, რათა მან არ დაბლოკოს CI-ს პროცესი მისი გამოსწორების დროს. ნაგულისხმევად ეს არის **ხელით შესრულებული მოქმედება**: თქვენ ათავსებთ ტესტს კარანტინში, ათავისუფლებთ მას და ცვლით რეჟიმებს სატესტო შემთხვევის დეტალური გვერდიდან დაშბორდზე. ასევე შეგიძლიათ ის დააკავშიროთ **ავტომატიზაციის გაფრთხილებასთან** განყოფილებაში **პარამეტრები → ავტომატიზაციები**, რათა ტესტი ავტომატურად ჩაიხშოს (ან გამოიტოვოს), როდესაც ის გადალახავს არასტაბილურობის ზღვარს, და გათავისუფლდეს, როდესაც აღდგება. ყოველი გადასვლა, ხელით თუ ავტომატურად, ფიქსირდება სატესტო შემთხვევის აუდიტის ჟურნალში.

ნაგულისხმევად, აღდგენა ელოდება, სანამ ტრიგერის პირობა აღარ იქნება მოქმედი, ამიტომ ტესტი რჩება კარანტინში, სანამ მისი ძველი არასტაბილური გაშვებები არ დატოვებენ ტრიგერის ფანჯარას. უფრო სწრაფი აღდგენისთვის, დააყენეთ **აღდგენა, როდესაც** მნიშვნელობაზე **არ არის ახალი არასტაბილური გაშვებები**: ტესტი აღდგება მაშინ, როდესაც აღდგენის ფანჯარა (დღეები ან გაშვებები) გაივლის ახალი არასტაბილური გაშვების გარეშე, ყოველი ახალი არასტაბილური გაშვება თავიდან იწყებს ამ ლოდინს და აღდგენის შემდეგ მას კვლავ კარანტინში მხოლოდ ახალი არასტაბილური გაშვება მოათავსებს.
