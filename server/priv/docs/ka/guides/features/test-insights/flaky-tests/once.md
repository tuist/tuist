# Once-ის არასტაბილური ტესტები {#once-flaky-tests}

> [!IMPORTANT]
> **მოთხოვნები**

## როგორ მუშაობს არასტაბილურობის აღმოჩენა {#how-it-works}

### ტესტების ხელახლა გაშვება {#test-retries}

როდესაც გამშვები (runner) იგივე ტესტისთვის რამდენიმე ცდას აფიქსირებს, Tuist ინარჩუნებს მათ. ტესტი, რომელიც ჯერ ვერდება და შემდეგ გადის, აღინიშნება როგორც არასტაბილური; ის კი, რომელიც მუდმივად ვერდება, რჩება ჩავარდნილად. ჩართეთ ხელახლა გაშვება საბაზისო გამშვებში, თუ ის მხარდაჭერილია. Once-ის Tuist-თან დაკავშირება ავტომატურად არ ამატებს ხელახლა გაშვებას ყოველ სატესტო მიზანს (target).

### ჯვარედინი გაშვებების აღმოჩენა {#cross-run-detection}

გაზიარებული ტესტების ისტორია Tuist-ს ასევე საშუალებას აძლევს შეადაროს ერთი და იგივე ტესტის წარმატებული და ჩავარდნილი შედეგები CI-ში ერთსა და იმავე კომიტზე. ამ შედარებისთვის Once-მა უნდა გააგზავნოს კომიტისა და CI-ის კონტექსტი; ლოკალური გაშვებები რჩება ხილული, მაგრამ არ ხდება ავტომატური ჯვარედინი არასტაბილურობის მტკიცებულება.

შემთხვევები იდენტიფიცირდება ნატიური მიზნით (target), საიტით (suite) და შემთხვევის სახელით. შეინარჩუნეთ ეს იდენტობები სტაბილურად მათი ისტორიის შესანახად და გამოიყენეთ სრული თითოეულ-შემთხვევიანი ანგარიშები, ნაცვლად იმისა, რომ სანდოობა გამოიყვანოთ მიზნის საერთო შედეგიდან.

## არასტაბილური ტესტების გამოკვლევა {#investigate-flaky-tests}

გახსენით სატესტო შემთხვევის ისტორია Tuist-ში, რათა შეადაროთ მისი ცდები, ჩავარდნები და დაზარალებული CI კომიტები. გაზიარებული ტესტების მოთხოვნები ასევე ხელმისაწვდომია <.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocol-ის ინსტრუმენტების</.localized_link> მეშვეობით, რაც კოდირების აგენტს საშუალებას აძლევს გამოიკვლიოს იგივე შეტყობინებული შედეგები.

## არასტაბილური ტესტების მართვა {#managing-flaky-tests}

ჩავარდნის გამოკვლევისას შეგიძლიათ მონიშნოთ ან მოხსნათ მონიშვნა ტესტზე, როგორც არასტაბილური, მის დეტალურ გვერდზე. არასტაბილური ტესტების აღმოჩენის ნაგულისხმევი ავტომატიზაცია ასევე ხსნის დროშას აღდგენის ფანჯრის შემდეგ, ჩვეულებრივ 14 დღის განმავლობაში სხვა ტრიგერის გარეშე.

Once-ის პროექტები ამჟამად არ აჩვენებს **Automations** პარამეტრების ჩანართს. აღმოჩენა და შენახული ტესტების მდგომარეობა ხელმისაწვდომია, მაგრამ პარამეტრების სამუშაო პროცესი, რომელიც დოკუმენტირებულია ბილდის სისტემებისთვის კარანტინის აღსრულებით, ჯერ არ არის ხელმისაწვდომი Once-ისთვის.

## კარანტინი {#quarantining}

Tuist-ს შეუძლია შეატყუოს შეტყობინებული შემთხვევები მათ შენახულ კარანტინის მდგომარეობას, მაგრამ ნატიური Once-ის კლიენტი ამჟამად არ იღებს და არ აღასრულებს Tuist-ის **Muted** ან **Skipped** პოლიტიკებს. ამ მდგომარეობის შეცვლა Tuist-ში არ აჩერებს Once-ს ტესტის შესრულებისგან და არ აიძულებს მის ჩავარდნას შეწყვიტოს CI-ის ბლოკირება.

გამოიყენეთ თქვენი გამშვების (runner) საკუთარი ფილტრაციის ან ჩავარდნის პოლიტიკა, როდესაც გჭირდებათ შესრულების დროს კარანტინი. არ ეყრდნობით მხოლოდ დაფის (dashboard) მდგომარეობას ბრძანების გასვლის კოდის (exit code) შესაცვლელად.

## Slack-ის შეტყობინებები {#slack-notifications}

Once-ის პროექტები ამჟამად არ აჩვენებს პროექტის პარამეტრების სამუშაო პროცესს არასტაბილური ტესტების Slack-ის გაფრთხილებების კონფიგურაციისთვის. გამოიყენეთ ქვემოთ მოცემული გაზიარებული ტესტების მოთხოვნები, რათა შეიტანოთ შეტყობინებული არასტაბილური მდგომარეობა თქვენს საკუთარ შეტყობინებებში.
