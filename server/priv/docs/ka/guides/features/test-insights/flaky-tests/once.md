# Once-ის არასტაბილური ტესტები {#once-flaky-tests}

> [!IMPORTANT]
> **მოთხოვნები**
>
> - დააკონფიგურირეთ <.localized_link href="/guides/features/test-insights/once">Once-ის ტესტების ანალიტიკა</.localized_link> სტრუქტურირებული ინდივიდუალური ტესტების შედეგებით.

## როგორ მუშაობს არასტაბილურობის აღმოჩენა {#how-it-works}

### ტესტების ხელახლა გაშვება {#test-retries}

როდესაც გამშვები (runner) იგივე ტესტისთვის რამდენიმე ცდას ანგარიშდება, Tuist ინარჩუნებს მათ. ტესტი, რომელიც ჯერ ვერდება და შემდეგ გადის, აღინიშნება როგორც არასტაბილური; ის კი, რომელიც მუდმივად ვერდება, რჩება ჩავარდნილად. ჩართეთ ხელახლა გაშვებები საბაზისო გამშვებში, თუ ის მხარდაჭერილია. Once-ის Tuist-თან დაკავშირება ავტომატურად არ ამატებს ხელახლა გაშვებებს ყველა სატესტო მიზანზე (target).

### ჯვარედინი გაშვებების აღმოჩენა {#cross-run-detection}

გაზიარებული ტესტების ისტორია ასევე საშუალებას აძლევს Tuist-ს შეადაროს ერთი და იგივე ტესტის წარმატებული და ჩავარდნილი შედეგები CI-ში ერთი და იგივე კომიტისთვის. ამ შედარებისთვის Once-მა უნდა მოახსენოს კომიტი და CI-ს კონტექსტი; ადგილობრივი გაშვებები რჩება ხილული, მაგრამ არ ხდება ავტომატური ჯვარედინი გაშვებების არასტაბილურობის მტკიცებულება.

შემთხვევები იდენტიფიცირდება ნეიტიური მიზნით (target), საიტით (suite) და შემთხვევის სახელით. შეინარჩუნეთ ეს იდენტობები სტაბილური მათი ისტორიის შესანარჩუნებლად და გამოიყენეთ სრული ანგარიშები თითოეული შემთხვევისთვის, ნაცვლად იმისა, რომ სანდოობა გამოიყვანოთ მიზნის ზოგადი შედეგიდან.

## არასტაბილური ტესტების გამოკვლევა {#investigate-flaky-tests}

გახსენით სატესტო შემთხვევის ისტორია Tuist-ში, რათა შეადაროთ მისი ცდები, ჩავარდნები და დაზარალებული CI კომიტები. გაზიარებული ტესტების მოთხოვნები ასევე ხელმისაწვდომია <.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocol-ის ინსტრუმენტების</.localized_link> მეშვეობით, რათა კოდირების აგენტმა შეძლოს იგივე მოხსენებული შედეგების გამოკვლევა.

## არასტაბილური ტესტების მართვა {#managing-flaky-tests}

შეგიძლიათ მონიშნოთ ან მოხსნათ მონიშვნა ტესტის არასტაბილურობის შესახებ მის დეტალურ გვერდზე ჩავარდნის გამოკვლევისას. არასტაბილური ტესტების აღმოჩენის ნაგულისხმევი ავტომატიზაციაც ასუფთავებს დროშას აღდგენის ფანჯრის შემდეგ, ჩვეულებრივ 14 დღის განმავლობაში სხვა ტრიგერის გარეშე.

Once-ის პროექტები ამჟამად არ აჩვენებენ **ავტომატიზაციების** პარამეტრების ჩანართს. აღმოჩენა და შენახული ტესტების მდგომარეობა ხელმისაწვდომია, მაგრამ პარამეტრების სამუშაო ნაკადი, რომელიც დოკუმენტირებულია ბილდის სისტემებისთვის კარანტინის აღსრულებით, ჯერ არ არის ხელმისაწვდომი Once-ისთვის.

## კარანტინი {#quarantining}

Tuist-ს შეუძლია მოხსენებული შემთხვევები მიანიჭოს მათ შენახულ კარანტინის მდგომარეობას, მაგრამ ნეიტიური Once-ის კლიენტი ამჟამად არ იღებს და არ აღასრულებს Tuist-ის **ჩუმად დატოვების** ან **გამოტოვების** პოლიტიკას. ამ მდგომარეობის შეცვლა Tuist-ში არ აჩერებს Once-ს ტესტის შესრულებისგან და არ აიძულებს მის ჩავარდნას შეწყვიტოს CI-ს ბლოკირება.

გამოიყენეთ თქვენი გამშვების (runner) საკუთარი ფილტრაციის ან ჩავარდნის პოლიტიკა, როდესაც გჭირდებათ შესრულების დროს კარანტინი. არ ეყრდნობით მხოლოდ დაფის მდგომარეობას ბრძანების გასასვლელი კოდის შესაცვლელად.

## Slack-ის შეტყობინებები {#slack-notifications}

Once-ის პროექტები ამჟამად არ აჩვენებენ პროექტის პარამეტრების სამუშაო ნაკადს არასტაბილური ტესტების Slack-ის გაფრთხილებების კონფიგურაციისთვის. გამოიყენეთ ქვემოთ მოყვანილი გაზიარებული ტესტების მოთხოვნები, რათა ინტეგრირდეთ მოხსენებული არასტაბილური მდგომარეობა თქვენს საკუთარ შეტყობინებებთან.
