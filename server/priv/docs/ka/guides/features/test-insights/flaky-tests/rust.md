# Rust-ის არასტაბილური ტესტები {#rust-flaky-tests}

Tuist შეუძლია აღმოაჩინოს Cargo-ს ტესტების შეუსაბამო შედეგები და დაგეხმაროთ მათ შესწავლაში **ტესტები → არასტაბილური ტესტები**-ში.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - კონფიგურაცია გაუკეთეთ <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link>-ს.

## როგორ მუშაობს არასტაბილურობის აღმოჩენა {#how-it-works}

Tuist ადარებს CI-ის გაშვებებს იმავე კომიტზე. ტესტი, რომელიც ერთ გაშვებაში გადის, ხოლო მეორეში ვერ გადის, შეიძლება მონიშნულ იქნას როგორც არასტაბილური. თუ Tuist ვერ ცნობს CI სისტემას, დააყენეთ `CI=true`, რათა მისი გაშვებები ჩაითვალოს CI გაშვებებად: იხილეთ <.localized_link href="/guides/features/test-insights/rust#continuous-integration">უწყვეტი ინტეგრაცია</.localized_link>.

ყოველი გაშვება მოახსენეთ ჩვეული ბრძანებით:

```sh
tuist cargo test --workspace
```

Cargo ავტომატურად არ ცდის წარუმატებელ ტესტებს ხელახლა. CI სამუშაოს ხელახლა გაშვება იმავე კომიტზე უზრუნველყოფს დამატებით შედეგს ჯვარედინი აღმოჩენისთვის.

## არასტაბილური ტესტების კარანტინში მოქცევა {#quarantining}

დააყუჩეთ ან გამოტოვეთ ტესტი მისი დეტალური გვერდიდან, ან კონფიგურაცია გაუკეთეთ კარანტინს **პარამეტრები → ავტომატიზაციები**-ში. შემდეგი `tuist cargo test` მიიღებს პროექტის მიმდინარე კარანტინის მდგომარეობას:

- **დაყუჩებული** ტესტები მაინც გაეშვება და მოახსენებს თავიანთ რეალურ შედეგებს, მაგრამ მათი წარუმატებლობა არ აცდენს ბრძანებას. სხვა ტესტების წარუმატებლობები, კომპილაციის შეცდომები, კრახები და არასრული შედეგები მაინც ჩვეულებრივად აცდენენ.
- **გამოტოვებული** ტესტები გამოირიცხება შესრულებიდან და მოიხსენიება როგორც კარანტინში მოქცეული გამოტოვებები. შესაბამისობა მოიცავს პაკეტს, სამიზნეს, Rust-ის მოდულის გზას და ტესტის სახელს, ასე რომ მსგავსად სახელდარქმეული ტესტები დამოუკიდებელი რჩება.

დაყუჩება ინარჩუნებს შერჩეულ workspace-ის პაკეტებსა და ფუნქციებს და აგებს ყველა შერჩეულ სამიზნეს მაშინაც კი, თუ დაყუჩებული სამიზნე ვერ გადის. გამოტოვების კარანტინი მოითხოვს ერთ შერჩეულ პაკეტს: გამოიყენეთ `tuist cargo test -p store` მრავალპაკეტიანი workspace-ის ბრძანების ნაცვლად. Tuist უარყოფს მრავალპაკეტიან გამოტოვებას, რადგან ბრძანების შევიწროვებამ შეიძლება შეცვალოს Cargo-ს გაერთიანებული დამოკიდებულების ფუნქციები.

კარანტინი ვრცელდება ასევე <.localized_link href="/guides/features/test-sharding/rust">დაყოფილ Cargo გაშვებებზე</.localized_link>. თუ Tuist ვერ მიიღებს მდგომარეობას, ის გაფრთხილებას გასცემს და გაეშვება კარანტინის გარეშე; წარუმატებლობები არ იქნება ჩახშობილი. განზრახ კარანტინის გარეშე გასაშვებად:

```sh
TUIST_TEST_SKIP_QUARANTINE=1 tuist cargo test --workspace
```

### შეზღუდვები {#limitations}

- აღსრულება მოითხოვს სტანდარტულ libtest harness-ებს და დაჭერილ ნაგულისხმევ გამონატანს. ბრძანებები ჩუმი, ვრცელი, ალტერნატიული ფორმატის ან დაუჭერი გამონატანით ვერ გადის, როდესაც კარანტინის გამოყენებაა საჭირო.
- აირჩიეთ ზუსტი workspace-ის პაკეტი `-p <package>`-ით, თუ სამიზნის მინიჭება ორაზროვანია. მორგებული harness-ები, პაკეტის/სამიზნის სახელის glob-ები და გადაუჭრელი პაკეტის შერჩევები მხარდაუჭერელია.
- Doctests-ებიც შეიძლება დაყუჩდეს ან გამოიტოვოს, მაგრამ Rustdoc-ის ტესტების ფილტრაციას არ შეუძლია ყოველი შესაძლო მაგალითის სახელთა წყვილის გარჩევა. თუ მაგალითის გამოტოვება ასევე გამოტოვებდა ჩართულ მაგალითს, ან doctest-ის ნაწილობრივი გამორიცხვა იყენებს `--exact`-ს, Tuist ვერ გადის დიაგნოსტიკით იმის ნაცვლად, რომ გამოტოვებული მაგალითი შეასრულოს ან ჩუმად გამოტოვოს ჩართული ტესტები. გამოკვლევისას გამოიყენეთ ზემოთ მოცემული გადაფარვა.

## ახალი ტესტების სტრეს-ტესტირება {#stress-testing-new-tests}

Tuist არ ატარებს ახალი Cargo ტესტების სტრეს-ტესტირებას. გამოიყენეთ Cargo-ს ტესტის ფილტრი წარუმატებელი ტესტის გამეორებისთვის მისი შესწავლისას:

```sh
tuist cargo test -p store rejects_invalid_token
```
