# Rust-ის არასტაბილური ტესტები {#rust-flaky-tests}

Tuist-ს შეუძლია აღმოაჩინოს Cargo-ს ტესტების არათანმიმდევრული შედეგები და დაგეხმაროთ მათ გამოკვლევაში **Tests → Flaky Tests**-ში.

> [!IMPORTANT] Requirements
> - მოაწყვეთ <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link>.

## როგორ მუშაობს არასტაბილურობის აღმოჩენა {#how-it-works}

Tuist ადარებს CI-ის გაშვებებს ერთსა და იმავე კომიტზე. ტესტი, რომელიც ერთ გაშვებაში გადის, ხოლო მეორეში ვერ გადის, შეიძლება მონიშნულ იქნას როგორც არასტაბილური.

ყოველი გაშვების შესახებ ინფორმაცია გადაეცით ჩვეულებრივი ბრძანებით:

```sh
tuist cargo test --workspace
```

Cargo ავტომატურად არ ცდის წარუმატებელი ტესტების ხელახლა გაშვებას. CI სამუშაოს ხელახლა გაშვება იმავე კომიტზე უზრუნველყოფს დამატებით შედეგს ჯვარედინი აღმოჩენისთვის.

## არასტაბილური ტესტების მართვა {#managing-flaky-tests}

### ავტომატური გასუფთავება

აღმოჩენა და აღდგენა ხდება პროექტის „Flaky test detection“ ავტომატიზაციის საშუალებით. ნაგულისხმევად, არასტაბილურობის ნიშანი ქრება 14 დღის შემდეგ, თუ ის ხელახლა არ გამოვლინდა. შეცვალეთ აღდგენის პერიოდი და მოქმედებები **Settings → Automations**-ში.

### ხელით მართვა

გახსენით **Tests → Flaky Tests** ტესტის ისტორიის შესასწავლად. შეგიძლიათ ხელით მონიშნოთ ან მოხსნათ მონიშვნა არასტაბილურად მისი დეტალური გვერდიდან.

## კარანტინი და სტრეს-ტესტირება {#quarantine}

Cargo-ს ინტეგრაცია ჯერ არ იყენებს კარანტინს: დაფაში ჩუმად ჩართული ან გამოტოვებული ტესტები მაინც გაეშვება და მათი წარუმატებლობა მაინც აისახება შედეგზე. ის ასევე არ ატარებს ახალი ტესტების სტრეს-ტესტირებას. გამოიყენეთ Cargo-ს ტესტის ფილტრი წარუმატებელი ტესტის გამოსაკვლევად მისი განმეორებითი გაშვებისთვის:

```sh
tuist cargo test -p store rejects_invalid_token
```
