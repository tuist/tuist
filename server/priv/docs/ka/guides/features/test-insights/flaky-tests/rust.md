# Rust-ის არასტაბილური ტესტები {#rust-flaky-tests}

Tuist შეუძლია აღმოაჩინოს Cargo-ს ტესტების შეუსაბამო შედეგები და დაგეხმაროთ მათ გამოკვლევაში **Tests → Flaky Tests**-ში.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - დააკონფიგურირეთ <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link>.

## როგორ მუშაობს არასტაბილურობის აღმოჩენა {#how-it-works}

Tuist ადარებს CI გაშვებებს ერთსა და იმავე კომიტზე. ტესტი, რომელიც ერთ გაშვებაში გადის, ხოლო მეორეში ვარდება, შეიძლება მონიშნულ იქნას როგორც არასტაბილური.

შეატყობინეთ თითოეული გაშვება ჩვეულებრივი ბრძანებით:

```sh
tuist cargo test --workspace
```

Cargo ავტომატურად არ ცდის თავიდან ჩავარდნილ ტესტებს. CI სამუშაოს ხელახლა გაშვება იმავე კომიტზე იძლევა დამატებით შედეგს გაშვებებს შორის აღმოჩენისთვის.

## არასტაბილური ტესტების კარანტინში მოთავსება {#quarantining}

შეგიძლიათ გააჩუმოთ ან გამოტოვოთ ტესტი მისი დეტალური გვერდიდან, ან დააკონფიგურიროთ კარანტინი **Settings → Automations**-ში. შემდეგი `tuist cargo test` იღებს პროექტის მიმდინარე კარანტინის მდგომარეობას:

- **გაჩუმებული** ტესტები მაინც სრულდება და აწვდიან რეალურ შედეგებს, მაგრამ მათი ჩავარდნები არ ავარდებენ ბრძანებას. სხვა ტესტების ჩავარდნები, კომპილაციის შეცდომები, კრაშები და არასრული შედეგები მაინც იწვევენ ჩავარდნას ჩვეულებრივად.
- **გამოტოვებული** ტესტები გამორიცხულია შესრულებიდან და მოხსენიებულია როგორც კარანტინში მოთავსებული გამოტოვებები. შესაბამისობა მოიცავს პაკეტს, სამიზნეს, Rust-ის მოდულის გზას და ტესტის სახელს, ამიტომ მსგავსად სახელდარქმეული ტესტები დამოუკიდებელი რჩება.

გაჩუმება ინარჩუნებს შერჩეულ workspace პაკეტებსა და ფუნქციებს და ასრულებს ყველა შერჩეულ სამიზნეს მაშინაც კი, თუ გაჩუმებული სამიზნე ჩავარდება. გამოტოვების კარანტინი მოითხოვს ერთ შერჩეულ პაკეტს: გამოიყენეთ `tuist cargo test -p store` მრავალპაკეტიანი workspace ბრძანების ნაცვლად. Tuist უარყოფს მრავალპაკეტიან გამოტოვებას, რადგან ბრძანების შევიწროვებამ შეიძლება შეცვალოს Cargo-ს გაერთიანებული დამოკიდებულების ფუნქციები.

კარანტინი ვრცელდება ასევე <.localized_link href="/guides/features/test-sharding/rust">დაყოფილ Cargo გაშვებებზე</.localized_link>. თუ Tuist ვერ იღებს მდგომარეობას, ის აფრთხილებს და ასრულებს კარანტინის გარეშე; ჩავარდნები არ ითრგუნება. განზრახვითი გაშვებისთვის კარანტინის გარეშე:

```sh
TUIST_TEST_SKIP_QUARANTINE=1 tuist cargo test --workspace
```

### შეზღუდვები {#limitations}

- აღსრულება მოითხოვს სტანდარტულ libtest harness-ებს და გადაღებულ ნაგულისხმევ გამოტანას. ბრძანებები ჩუმი, verbose, ალტერნატიული ფორმატის ან გადაუღებელი გამოტანით ვარდება, როცა კარანტინის გამოყენებაა საჭირო.
- აირჩიეთ ზუსტი workspace პაკეტი `-p <package>`-ით, თუ სამიზნის მიკუთვნება ორაზროვანია. მორგებული harness-ები, პაკეტის/სამიზნის სახელის glob-ები და გადაუწყვეტელი პაკეტის შერჩევები მხარდაუჭერელია.
- Doctests-იც შეიძლება გაჩუმდეს ან გამოიტოვოს, მაგრამ Rustdoc-ის ტესტების ფილტრაციას არ შეუძლია ყველა შესაძლო წყვილის გარჩევა მაგალითების სახელების მიხედვით. თუ მაგალითის გამოტოვება ასევე გამოტოვებდა ჩართულ მაგალითს, ან doctest-ის ნაწილობრივი გამორიცხვა იყენებს `--exact`-ს, Tuist ვარდება დიაგნოსტიკით იმის ნაცვლად, რომ შეასრულოს გამოტოვებული მაგალითი ან ჩუმად გამოტოვოს ჩართული ტესტები. გამოკვლევისას გამოიყენეთ ზემოთ მოცემული გადაფარვა.

## ახალი ტესტების სტრეს-ტესტირება {#stress-testing-new-tests}

Tuist არ აკეთებს ახალი Cargo ტესტების სტრეს-ტესტირებას. გამოიყენეთ Cargo ტესტის ფილტრი ჩავარდნილი ტესტის გასამეორებლად მისი გამოკვლევისას:

```sh
tuist cargo test -p store rejects_invalid_token
```
