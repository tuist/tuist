# Rust-ის არასტაბილური ტესტები {#rust-flaky-tests}

Tuist-ს შეუძლია აღმოაჩინოს Cargo-ს ტესტების არათანმიმდევრული შედეგები და დაგეხმაროთ მათ გამოკვლევაში **Tests → Flaky Tests**-ში.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - დააკონფიგურირეთ <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link>.

## როგორ მუშაობს არასტაბილურობის დეტექცია {#how-it-works}

Tuist ადარებს CI-ს გაშვებებს ერთსა და იმავე კომიტზე. ტესტი, რომელიც ერთ გაშვებაში გადის, ხოლო მეორეში ვერ გადის, შეიძლება მონიშნულ იქნას როგორც არასტაბილური.

ყოველი გაშვება მოახსენეთ ჩვეულებრივი ბრძანებით:

```sh
tuist cargo test --workspace
```

Cargo ავტომატურად არ ცდილობს წარუმატებელი ტესტების ხელახლა გაშვებას. CI-ს სამუშაოს იმავე კომიტზე ხელახლა გაშვება უზრუნველყოფს დამატებით შედეგს ჯვარედინი დეტექციისთვის.

## არასტაბილური ტესტების კარანტინში მოქცევა {#quarantining}

ჩააყუჩეთ ან გამოტოვეთ ტესტი მისი დეტალური გვერდიდან, ან დააკონფიგურირეთ კარანტინი **Settings → Automations**-ში. შემდეგი `tuist cargo test` იღებს პროექტის მიმდინარე კარანტინის მდგომარეობას:

- **ჩაყუჩებული** ტესტები მაინც გადის და აწვდის რეალურ შედეგებს, მაგრამ მათი წარუმატებლობა არ ავარდება ბრძანებას. სხვა ტესტების წარუმატებლობები, კომპილაციის შეცდომები, კრაშები და არასრული შედეგები მაინც ჩვეულებრივად ავარდება.
- **გამოტოვებული** ტესტები გამორიცხულია შესრულებიდან და მოხსენებულია როგორც კარანტინში მოქცეული გამოტოვებები. შესაბამისობა მოიცავს პაკეტს, სამიზნეს, Rust-ის მოდულის გზას და ტესტის სახელს, ამიტომ მსგავსად სახელდარქმეული ტესტები დამოუკიდებელი რჩება.

ჩაყუჩება ინარჩუნებს შერჩეულ workspace-ის პაკეტებსა და ფუნქციებს და ასრულებს ყველა შერჩეულ სამიზნეს მაშინაც კი, თუ ჩაყუჩებული სამიზნე ვერ გადის. გამოტოვების კარანტინი მოითხოვს ერთ შერჩეულ პაკეტს: გამოიყენეთ `tuist cargo test -p store` მრავალპაკეტიანი workspace-ის ბრძანების ნაცვლად. Tuist უარყოფს მრავალპაკეტიან გამოტოვებას, რადგან ბრძანების შევიწროვებამ შეიძლება შეცვალოს Cargo-ს გაერთიანებული დამოკიდებულების ფუნქციები.

კარანტინი ასევე ვრცელდება <.localized_link href="/guides/features/test-sharding/rust">Cargo-ს დაყოფილ გაშვებებზე</.localized_link>. თუ Tuist-ს არ შეუძლია მდგომარეობის მიღება, ის გაფრთხილებას აწვდის და კარანტინის გარეშე ასრულებს; წარუმატებლობები არ ითრგუნება. განზრახ კარანტინის გარეშე გასაშვებად:

```sh
TUIST_TEST_SKIP_QUARANTINE=1 tuist cargo test --workspace
```

### შეზღუდვები {#limitations}

- აღსრულება მოითხოვს სტანდარტულ libtest harness-ებს და დაჭერილ ნაგულისხმევ გამოტანას. ბრძანებები წყნარი, verbose, ალტერნატიული ფორმატის ან დაუჭერელი გამოტანით ვერ გადის, როდესაც კარანტინის გამოყენებაა საჭირო.
- აირჩიეთ ზუსტი workspace-ის პაკეტი `-p <package>`-ით, თუ სამიზნის მინიჭება ორაზროვანია. მორგებული harness-ები, პაკეტის/სამიზნის სახელის გლობები და გადაუწყვეტელი პაკეტის შერჩევები მხარდაუჭერელია.
- Doctests-იც შეიძლება ჩაყუჩდეს ან გამოიტოვოს, მაგრამ Rustdoc-ის ტესტების ფილტრაციას არ შეუძლია ყოველი შესაძლო წყვილის განსხვავება მაგალითების სახელებში. თუ მაგალითის გამოტოვება ასევე გამოტოვებდა ჩართულ მაგალითს, ან doctest-ის ნაწილობრივი გამორიცხვა იყენებს `--exact`-ს, Tuist ავარდება დიაგნოსტიკით იმის ნაცვლად, რომ შეასრულოს გამოტოვებული მაგალითი ან ჩუმად გამოტოვოს ჩართული ტესტები. გამოკვლევისას გამოიყენეთ ზემოთ მოცემული გადაფარვა.

## ახალი ტესტების სტრეს-ტესტირება {#stress-testing-new-tests}

Tuist არ ატარებს ახალი Cargo ტესტების სტრეს-ტესტირებას. გამოიყენეთ Cargo-ს ტესტის ფილტრი წარუმატებელი ტესტის გამოსაკვლევად:

```sh
tuist cargo test -p store rejects_invalid_token
```
