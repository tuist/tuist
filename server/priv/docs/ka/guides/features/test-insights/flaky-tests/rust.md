# Rust-ის არასტაბილური ტესტები {#rust-flaky-tests}

Tuist-ს შეუძლია აღმოაჩინოს Cargo-ს ტესტების არათანმიმდევრული შედეგები და დაგეხმაროთ მათ შესწავლაში **Tests → Flaky Tests**-ში.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - დააკონფიგურირეთ <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link>.

## როგორ მუშაობს არასტაბილურობის აღმოჩენა {#how-it-works}

Tuist ადარებს CI-ის გაშვებებს ერთსა და იმავე კომიტზე. ტესტი, რომელიც ერთ გაშვებაში გადის, ხოლო მეორეში ვერ გადის, შეიძლება მონიშნულ იქნას როგორც არასტაბილური.

ყველა გაშვების შესახებ ინფორმაციის გადაგზავნა ჩვეულებრივი ბრძანებით:

```sh
tuist cargo test --workspace
```

Cargo ავტომატურად არ ცდილობს წარუმატებელი ტესტების ხელახლა გაშვებას. იმავე კომიტზე CI-ის სამუშაოს ხელახლა გაშვება იძლევა დამატებით შედეგს ჯვარედინი გაშვებების აღმოჩენისთვის.

## არასტაბილური ტესტების კარანტინში მოთავსება {#quarantining}

ტესტის დადუმება ან გამოტოვება შესაძლებელია მისი დეტალური გვერდიდან, ან კარანტინის კონფიგურაცია **Settings → Automations**-ში. შემდეგი `tuist cargo test` იღებს პროექტის მიმდინარე კარანტინის მდგომარეობას:

- **დადუმებული** ტესტები მაინც გაეშვება და აჩვენებს რეალურ შედეგებს, მაგრამ მათი წარუმატებლობა არ აწყვეტს ბრძანებას. სხვა ტესტების წარუმატებლობა, კომპილაციის შეცდომები, კრაშები და არასრული შედეგები მაინც იწვევს ჩვეულებრივ წარუმატებლობას.
- **გამოტოვებული** ტესტები გამორიცხულია შესრულებიდან და მოხსენებულია როგორც კარანტინში მოთავსებული გამოტოვებები. შესაბამისობა მოიცავს პაკეტს, სამიზნეს, Rust-ის მოდულის გზას და ტესტის სახელს, ამიტომ მსგავსი სახელების მქონე ტესტები დამოუკიდებელი რჩება.

დადუმება ინარჩუნებს შერჩეულ workspace-ის პაკეტებს და ფუნქციებს, და ასრულებს ყველა შერჩეულ სამიზნეს მაშინაც, თუ დადუმებული სამიზნე ვერ გაივლის. გამოტოვების კარანტინი მოითხოვს ერთ შერჩეულ პაკეტს: გამოიყენეთ `tuist cargo test -p store` მრავალპაკეტიანი workspace-ის ბრძანების ნაცვლად. Tuist უარყოფს მრავალპაკეტიან გამოტოვებას, რადგან ბრძანების შევიწროვებამ შეიძლება შეცვალოს Cargo-ს გაერთიანებული დამოკიდებულების ფუნქციები.

კარანტინი ვრცელდება ასევე <.localized_link href="/guides/features/test-sharding/rust">დაყოფილ Cargo-ს გაშვებებზე</.localized_link>. თუ Tuist-ს არ შეუძლია მდგომარეობის მიღება, ის გასცემს გაფრთხილებას და ასრულებს კარანტინის გარეშე; წარუმატებლობები არ ითრგუნება. განზრახვითი გაშვებისთვის კარანტინის გარეშე:

```sh
TUIST_TEST_SKIP_QUARANTINE=1 tuist cargo test --workspace
```

### შეზღუდვები {#limitations}

- აღსრულება მოითხოვს სტანდარტულ libtest harness-ებს და ჩაჭერილ ნაგულისხმევ გამონატანს. ბრძანებები ჩუმი, ვრცელი, ალტერნატიული ფორმატის ან არაჩაჭერილი გამონატანით ვერ შესრულდება, როდესაც კარანტინის გამოყენებაა საჭირო.
- აირჩიეთ ზუსტი workspace-ის პაკეტი `-p <package>`-ით, თუ სამიზნის მინიჭება ბუნდოვანია. მორგებული harness-ები, პაკეტის/სამიზნის სახელის გლობები და გადაუჭრელი პაკეტის შერჩევები მხარდაუჭერელია.
- Doctests-ებიც შეიძლება დადუმდეს ან გამოიტოვოს, მაგრამ Rustdoc-ის ტესტების ფილტრაციას არ შეუძლია ყველა შესაძლო მაგალითის სახელთა წყვილის გარჩევა. თუ მაგალითის გამოტოვება ასევე გამოტოვებდა ჩართულ მაგალითს, ან doctest-ის ნაწილობრივი გამორიცხვა იყენებს `--exact`-ს, Tuist ვერ შესრულდება დიაგნოსტიკით იმის ნაცვლად, რომ შეასრულოს გამოტოვებული მაგალითი ან ჩუმად გამოტოვოს ჩართული ტესტები. გამოიყენეთ ზემოთ მოცემული გადაფარვა შესწავლის დროს.

## ახალი ტესტების სტრეს-ტესტირება {#stress-testing-new-tests}

Tuist არ ატარებს ახალი Cargo ტესტების სტრეს-ტესტირებას. გამოიყენეთ Cargo-ს ტესტის ფილტრი წარუმატებელი ტესტის გასამეორებლად მისი შესწავლის დროს:

```sh
tuist cargo test -p store rejects_invalid_token
```
