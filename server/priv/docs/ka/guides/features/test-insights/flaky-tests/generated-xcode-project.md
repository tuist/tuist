## როგორ მუშაობს არასტაბილურობის აღმოჩენა {#how-it-works}

Tuist არასტაბილურ ტესტებს ორი გზით ადგენს:

### ტესტების ხელახლა გაშვება {#test-retries}

როდესაც ტესტებს ხელახლა გაშვების ფუნქციით ასრულებთ, Tuist თითოეული ცდის შედეგებს აანალიზებს. თუ ტესტი ზოგიერთ ცდაზე ვერდება, მაგრამ სხვებზე წარმატებით სრულდება, ის არასტაბილურად მონიშნება.

გადაეცით `-retry-tests-on-failure` ან `-test-iterations` `tuist test`-ის მეშვეობით:

```sh
tuist test MyScheme -- -retry-tests-on-failure -test-iterations 3
```

## არასტაბილური ტესტების იზოლირება {#quarantining}

<!-- @snippet: ./_quarantine-intro -->

იზოლირებული ტესტი ერთ-ერთ რეჟიმშია:

- **ჩუმად დატოვებული**: ტესტი მაინც სრულდება, მაგრამ `tuist test` მალავს შეცდომას. შეცდომები კვლავ ეწოდება არასტაბილური ტესტების დეტექტორს, ამიტომ შეგიძლიათ აკვირდეთ ტესტს ბილდის გაწყვეტის გარეშე. აირჩიეთ ეს ვარიანტი ტესტისთვის, რომელსაც აქტიურად იკვლევთ.
- **გამოტოვებული**: xcodebuild იღებს `-skip-testing <identifier>`-ს, ამიტომ ტესტი არასდროს იწყება. ის არ ქმნის ახალ შედეგებს და ქრება არასტაბილური ტესტების დაფიდან მანამ, სანამ ხელახლა არ ჩართავთ. აირჩიეთ ეს, როცა ტესტი გატეხილია, ნელია ან იმდენად მუდმივად არასტაბილურია, რომ მისი გაშვება უბრალოდ CI წუთების ფლანგვაა.

<!-- @snippet: ./_quarantined-passing -->

### ტესტების გაშვება {#running-tests}

`tuist test` ავტომატურად ითვალისწინებს ორივე რეჟიმს:

```sh
tuist test
```

გამოტოვებული ტესტები xcodebuild-ს გადაეცემა როგორც `-skip-testing` და არასდროს იწყება. ჩუმად დატოვებული ტესტები ჩვეულებრივად სრულდება; თუ ისინი ვერდებიან, შეცდომა იმალება მიღებულ ბილდის სტატუსში.

იზოლაციის სრულად გვერდის ავლით ყველაფრის გასაშვებად, ჩუმად დატოვებული და გამოტოვებული ტესტების ჩათვლით:

```sh
tuist test --skip-quarantine
```

## ახალი ტესტების სტრეს-ტესტირება {#stress-testing-new-tests}

<!-- @snippet: ./_stress-intro -->

სატესტო შემთხვევა ახლად ითვლება, თუ ის ბოლო 90 დღის განმავლობაში არ გაშვებულა CI-ზე პროექტის ძირითად შტოზე, ან კომიტზე, რომელიც მას შემდეგ მოხვდა იქ. შერწყმის რიგის გამოყენებისას, სატესტო შემთხვევა, რომელიც რიგმა გაუშვა, ცნობილი ხდება მას შემდეგ, რაც რიგის კომიტი მოხვდება შტოზე, და რჩება ახლად, თუ რიგი მას გამოტოვებს. კომიტები შეესაბამება <.localized_link href="/guides/features/test-insights/xcode#git-history">Git ისტორიას</.localized_link>, რომელსაც Tuist აგროვებს CI-ზე.

<!-- @snippet: ./_stress-modes -->

ორივე რეჟიმში, <.localized_link href="/guides/features/selective-testing/generated-xcode-project">შერჩევითი ტესტირება</.localized_link> არ ტოვებს სატესტო სამიზნეს, რომელსაც აქვს არასტაბილური ახალი სატესტო შემთხვევა, შემდეგ გაშვებაზე. სამიზნე ხელახლა სრულდება და გეიტი კვლავ ატარებს სატესტო შემთხვევის სტრეს-ტესტირებას, სანამ ის ყველა ხელახალ გაშვებას არ გაივლის.

გადაეცით ის პასთროუ არგუმენტებამდე, ან დააყენეთ `TUIST_TEST_STRESS_NEW_TESTS` რეჟიმის შესაცვლელად თითოეული CI არხისთვის:

```sh
tuist test --stress-new-tests report
```
