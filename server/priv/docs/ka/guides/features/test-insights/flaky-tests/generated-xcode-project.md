## როგორ მუშაობს არასტაბილურობის აღმოჩენა {#how-it-works}

Tuist არასტაბილურ ტესტებს ორი გზით აღმოაჩენს:

### ტესტების ხელახლა გაშვება {#test-retries}

როდესაც ტესტებს ხელახლა გაშვების ფუნქციით ასრულებთ, Tuist აანალიზებს თითოეული ცდის შედეგებს. თუ ტესტი ზოგიერთ ცდაზე ვერდება, მაგრამ სხვებზე გადის, ის არასტაბილურად მონიშნება.

გადაეცით `-retry-tests-on-failure` ან `-test-iterations` `tuist test`-ის მეშვეობით:

```sh
tuist test MyScheme -- -retry-tests-on-failure -test-iterations 3
```

## არასტაბილური ტესტების კარანტინში მოქცევა {#quarantining}

<!-- @snippet: ./_quarantine-intro -->

კარანტინში მოქცეული ტესტი ერთ-ერთ რეჟიმშია:

- **დახშული**: ტესტი მაინც გაეშვება, მაგრამ `tuist test` ნიღბავს შეცდომას. შეცდომები მაინც მიეწოდება არასტაბილური ტესტების დეტექტორს, ამიტომ შეგიძლიათ ტესტზე დაკვირვება განაგრძოთ ბილდის გაწყვეტის გარეშე. აირჩიეთ ეს ვარიანტი ტესტისთვის, რომელსაც აქტიურად იკვლევთ.
- **გამოტოვებული**: xcodebuild იღებს `-skip-testing <identifier>`-ს, ამიტომ ტესტი არასდროს იწყება. ის არ წარმოქმნის ახალ შედეგებს და ქრება არასტაბილური ტესტების დაშბორდიდან, სანამ ხელახლა არ ჩართავთ. აირჩიეთ ეს ვარიანტი, როცა ტესტი გაუმართავია, ნელია, ან იმდენად მუდმივად არასტაბილურია, რომ მისი გაშვება უბრალოდ CI-ის წუთების ფლანგვაა.

<!-- @snippet: ./_quarantined-passing -->

### ტესტების გაშვება {#running-tests}

`tuist test` ავტომატურად ითვალისწინებს ორივე რეჟიმს:

```sh
tuist test
```

გამოტოვებული ტესტები xcodebuild-ს გადაეცემა როგორც `-skip-testing` და არასდროს იწყება. დახშული ტესტები ჩვეულებრივად გაეშვება; თუ ისინი ვერდება, შეცდომა ინიღბება მიღებულ ბილდის სტატუსში.

კარანტინის სრულად გვერდის ავლით ყველაფრის, მათ შორის დახშული და გამოტოვებული ტესტების გასაშვებად:

```sh
tuist test --skip-quarantine
```

## ახალი ტესტების სტრეს-ტესტირება {#stress-testing-new-tests}

<!-- @snippet: ./_stress-intro -->

სატესტო შემთხვევა ახლად ითვლება, თუ ის ბოლო 90 დღის განმავლობაში არ გაშვებულა CI-ზე პროექტის ძირითად შტოზე, ან კომიტზე, რომელიც შემდგომში მასში შევიდა. მერჯის რიგის (merge queue) გამოყენებისას, სატესტო შემთხვევა, რომელიც რიგმა გაუშვა, ცნობილი ხდება მას შემდეგ, რაც რიგის კომიტი შევიდება, და რჩება ახლად, თუ რიგი მას გამოტოვებს. კომიტები შეესაბამება <.localized_link href="/guides/features/test-insights/xcode#git-history">Git-ის ისტორიას</.localized_link>, რომელსაც Tuist აგროვებს CI-ზე.

<!-- @snippet: ./_stress-modes -->

ორივე რეჟიმში, <.localized_link href="/guides/features/selective-testing/generated-xcode-project">შერჩევითი ტესტირება</.localized_link> არ გამოტოვებს სატესტო სამიზნეს, რომელსაც აქვს არასტაბილური ახალი სატესტო შემთხვევა, შემდეგ გაშვებაზე. სამიზნე ხელახლა გაეშვება და გეიტი კვლავ ატარებს სატესტო შემთხვევის სტრეს-ტესტირებას, სანამ ის ყველა ხელახლა გაშვებას არ გაივლის.

გადაეცით ის პასთრუ არგუმენტებამდე, ან დააყენეთ `TUIST_TEST_STRESS_NEW_TESTS`, რათა რეჟიმი CI-ის თითოეული არხისთვის შეცვალოთ:

```sh
tuist test --stress-new-tests report
```
