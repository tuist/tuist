## როგორ მუშაობს არასტაბილურობის აღმოჩენა {#how-it-works}

Tuist ორი გზით აღმოაჩენს არასტაბილურ ტესტებს:

### ტესტების ხელახლა გაშვება {#test-retries}

როდესაც ტესტებს აშვებთ ხელახლა გაშვების ფუნქციით, Tuist აანალიზებს თითოეული ცდის შედეგებს. თუ ტესტი ზოგიერთ ცდაზე ვერდება, მაგრამ სხვებზე გადის, ის მონიშნულია როგორც არასტაბილური.

გადაეცით `-retry-tests-on-failure` ან `-test-iterations` `tuist test`-ის მეშვეობით:

```sh
tuist test MyScheme -- -retry-tests-on-failure -test-iterations 3
```

## არასტაბილური ტესტების კარანტინში მოქცევა {#quarantining}

<!-- @snippet: ./_quarantine-intro -->

კარანტინში მოქცეული ტესტი ერთ-ერთ რეჟიმშია:

- **ჩუმად**: ტესტი მაინც ეშვება, მაგრამ `tuist test` ნიღბავს შეცდომას. შეცდომები მაინც კვებავს არასტაბილური ტესტების დეტექტორს, ასე რომ შეგიძლიათ აკვირდეთ ტესტს ბილდის გაწყვეტის გარეშე. აირჩიეთ ეს იმ ტესტისთვის, რომელსაც აქტიურად იკვლევთ.
- **გამოტოვებული**: xcodebuild იღებს `-skip-testing <identifier>`-ს, ამიტომ ტესტი არასდროს იწყება. ის არ წარმოქმნის ახალ შედეგებს და ქრება არასტაბილური ტესტების დაშბორდიდან, სანამ ხელახლა არ ჩართავთ. აირჩიეთ ეს, როდესაც ტესტი გატეხილია, ნელია, ან იმდენად მუდმივად არასტაბილურია, რომ მისი გაშვება უბრალოდ ფუჭად ხარჯავს CI წუთებს.

<!-- @snippet: ./_quarantined-passing -->

### ტესტების გაშვება {#running-tests}

`tuist test` ავტომატურად პატივს სცემს ორივე რეჟიმს:

```sh
tuist test
```

გამოტოვებული ტესტები გადაეცემა xcodebuild-ს როგორც `-skip-testing` და არასდროს იწყება. ჩუმად ტესტები ჩვეულებრივად ეშვება; თუ ისინი ვერდებიან, შეცდომა ინიღბება მიღებულ ბილდის სტატუსში.

კარანტინის სრულად გასაბათილებლად და ყველაფრის გასაშვებად, ჩუმად და გამოტოვებული ტესტების ჩათვლით:

```sh
tuist test --skip-quarantine
```

## ახალი ტესტების სტრეს-ტესტირება {#stress-testing-new-tests}

<!-- @snippet: ./_stress-intro -->

სატესტო შემთხვევა ახლად ითვლება, თუ ის ბოლო 90 დღის განმავლობაში არ გაშვებულა CI-ზე პროექტის ძირითად შტოზე, ან კომიტზე, რომელიც მას შემდეგ ჩაერთო. მერჯის რიგით, ტესტის შემთხვევა, რომელიც რიგმა გაუშვა, ცნობილი ხდება მას შემდეგ, რაც რიგის კომიტი ჩაერთვება, და რჩება ახალი, თუ რიგი მას გამოტოვებს. კომიტები შეესაბამება <.localized_link href="/guides/features/test-insights/xcode#git-history">Git ისტორიის</.localized_link> მეშვეობით, რომელსაც Tuist აგროვებს CI-ზე.

<!-- @snippet: ./_stress-modes -->

ორივე რეჟიმში, <.localized_link href="/guides/features/selective-testing/generated-xcode-project">შერჩევითი ტესტირება</.localized_link> არ გამოტოვებს ტესტის სამიზნეს არასტაბილური ახალი სატესტო შემთხვევით შემდეგ გაშვებაზე. სამიზნე ხელახლა ეშვება, და გეიტი ხელახლა ატესტებს სატესტო შემთხვევას, სანამ ის ყველა ხელახლა გაშვებას არ გაივლის.

გადაეცით ის პასთროუ არგუმენტებამდე, ან დააყენეთ `TUIST_TEST_STRESS_NEW_TESTS` რეჟიმის შესაცვლელად თითოეული CI არხისთვის:

```sh
tuist test --stress-new-tests report
```
