# Once-ის ტესტების ანალიტიკა {#once-test-insights}

Once აგზავნის ტესტების შედეგებს Tuist-ში, რათა შეძლოთ თქვენი ტესტების სუიტის თვალყურის დევნება როგორც ლოკალურად, ისე CI გაშვებებში, გამოიძიოთ შეცდომები და იპოვოთ ნელი ტესტები ცალკეული worker-ების ანგარიშების შეგროვების გარეშე.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - დაასრულეთ <.localized_link href="/guides/get-started/once-project">Once-ით მუშაობის დაწყება</.localized_link>.
> - გამოიყენეთ ტესტის სამიზნეები (targets), რომლებიც აბარებენ სტრუქტურირებულ შედეგებს. ხელმისაწვდომი დეტალები დამოკიდებულია სამიზნის ტიპზე და ტესტის გამშვებზე (test runner).

## ატესტეთ თქვენი ტესტების გაშვებები {#report-your-test-runs}

გაუშვით მთლიანი სუიტა ან აირჩიეთ კონკრეტული სამიზნე:

```bash
once test
once test MyTests
```

Once აგზავნის ნატიურ ტესტის მოვლენებს და აქვეყნებს დასრულებულ შედეგებს Tuist-ის საერთო ტესტის მოდელში. **Tests** და **Test Runs** აჩვენებენ გაშვებებს; ინდივიდუალურ საქმეებსაც (cases) ასევე აქვთ საერთო ტესტის ისტორია. <.localized_link href="/guides/features/test-sharding/once">ჰოსტინგული დაყოფილი გაშვება</.localized_link> აქვეყნებს ერთ ანგარიშს თითოეული worker-ისთვის გაერთიანებულ გაშვებაში, ნაცვლად მისი დიაგნოსტიკური მოვლენების ნაკადის ხელახლა დათვლისა.

## რა ფიქსირდება {#what-is-tracked}

- აბარებული ტესტის სამიზნეები, სუიტები და ინდივიდუალური საქმეები.
- წარმატებული, წარუმატებელი და გამოტოვებული შედეგები, ხანგრძლივობებით, თუ მათ აწვდის გამშვები (runner).
- შეცდომის შეტყობინებები, რომლებსაც აწვდის გამშვები ჰოსტინგულ დაყოფილ ანგარიშებში.
- დალაგებული ხელახალი ცდები და არასტაბილური შედეგები, როდესაც ტესტი ჯერ ვერხერხდება, შემდეგ კი წარმატებით სრულდება.
- ბრენჩის, კომიტის და CI კონტექსტი, რომელსაც აწვდის Once.

ტესტის იდენტურობა ეყრდნობა ნატიურ სამიზნეს, სუიტას და საქმის სახელს. დაყოფის ბატჩის ID-ები არის დაგეგმვის ერთეულები და არა ტესტის სახელები.

ჩვეულებრივი `once test` ანგარიშგება ინარჩუნებს შედეგებს და ხელახალი ცდების მცდელობებს, მაგრამ ამჟამად არ შეიცავს შეცდომის შეტყობინებებს საერთო ტესტის ისტორიაში. ჰოსტინგულ დაყოფილ ანგარიშებს შეიძლება ჰქონდეთ შეცდომის შეტყობინებები, მაგრამ ანგარიშგების არცერთი გზა არ აწვდის წყაროს მდებარეობებს. შეინახეთ თქვენი CI ლოგები დიაგნოსტიკისთვის, რომელიც Tuist-ში არ არის ხელმისაწვდომი.

არა ყოველი ტესტის სამიზნე უზრუნველყოფს ერთნაირ დეტალებს. ზოგიერთი გამშვები აბარებს ინდივიდუალურ საქმეებს, სხვები მხოლოდ შეჯამებებს; ზუსტი ფაილის ან საქმის შესრულება ცალკე შესაძლებლობაა. სანამ დაეყრდნობოდეთ საქმეების მიხედვით ანალიტიკას ან დეტალურ დაგეგმვას, იხილეთ [Once-ის ტესტის ეკოსისტემის დაფარვა](https://buildonce.dev/docs/guide/graph/testing#understand-current-ecosystem-coverage).

## არასტაბილური ტესტები {#flaky-tests}

Tuist იყენებს აბარებულ მცდელობებს და CI ისტორიას არათანმიმდევრული შედეგების იდენტიფიცირებისთვის. მცდელობის აბარება არ ნიშნავს ხელახალი ცდების ჩართვას: დააყენეთ ხელახალი ცდები იმ გამშვებში, რომელიც მათ მხარდაჭერას უწევს. აღმოჩენისა და მიმდინარე კარანტინის საზღვრებისთვის იხილეთ <.localized_link href="/guides/features/test-insights/flaky-tests/once">Once-ის არასტაბილური ტესტები</.localized_link>.

## შერჩევა და კოდის დაფარვა {#selection-and-code-coverage}

Once-ს შეუძლია კონსერვატიულად შეარჩიოს ტესტები თავისი ლოკალური გრაფიდან `--changed-path`-ის გამოყენებით. ეს არის Once-ის საკუთარი შერჩევა და არა Tuist-ის ჰოსტინგული, დაფარვაზე დაფუძნებული ტესტის შერჩევა:

```bash
once test --changed-path src/library.rs
```

ნატიური Once-ის ანგარიშგება ამჟამად არ ტვირთავს კოდის დაფარვას Tuist-ში. წარმატებული ტესტის ანგარიში ან დაყოფის გეგმა არ ავსებს Code Coverage დაფას.

## პრობლემების გადაჭრა {#troubleshooting}

თუ გაშვება აკლია, შეამოწმეთ, რომ ეფექტური ქეშის პროვაიდერი ასახელებს თქვენს Tuist პროექტს და ხელახლა გაიარეთ ავთენტიკაცია `once auth login --provider tuist`-ით. პირდაპირი ანგარიშგება არის მაქსიმალური ძალისხმევის პრინციპზე დაფუძნებული და არ აქცევს წარმატებულ ტესტის ბრძანებას შეცდომად, როდესაც ანგარიშგების სერვისი მიუწვდომელია.

გაშვების შეჯამებები და სტრუქტურირებული ტესტის შეცდომები არ არის სრული პროცესის ლოგები. ეს სერვერი ამჟამად არ იღებს Once-ის raw action log stream-ს; შეინახეთ თქვენი CI ლოგები იმ გამოტანისთვის, რომელიც არ არის შეტანილი სტრუქტურირებულ შედეგებში.
