# Once-ის ტესტების ანალიტიკა {#once-test-insights}

Once აგზავნის ტესტების შედეგებს Tuist-ში, რათა შეძლოთ თქვენი ტესტების ნაკრების თვალყურის დევნება როგორც ლოკალურად, ისე CI-ს გაშვებებისას, გამოიკვლიოთ შეცდომები და აღმოაჩინოთ ნელი ტესტები ინდივიდუალური მუშაკებიდან ანგარიშების შეგროვების გარეშე.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - დაასრულეთ <.localized_link href="/guides/get-started/once-project">Once-ით დაწყება</.localized_link>.
> - გამოიყენეთ ტესტების სამიზნეები (targets), რომლებიც აბარებენ სტრუქტურირებულ შედეგებს. ხელმისაწვდომი დეტალები დამოკიდებულია სამიზნის ტიპზე და ტესტების გამშვებზე (runner).

## აანგარიშეთ თქვენი ტესტების გაშვებები {#report-your-test-runs}

გაუშვით მთლიანი ნაკრები ან აირჩიეთ კონკრეტული სამიზნე:

```bash
once test
once test MyTests
```

Once გადასცემს ნატიურ ტესტების მოვლენებს და აქვეყნებს დასრულებულ შედეგებს Tuist-ის საერთო ტესტების მოდელში. **ტესტები** და **ტესტების გაშვებები** აჩვენებენ გაშვებებს; ინდივიდუალურ შემთხვევებსაც აქვთ საერთო ტესტების ისტორია. <.localized_link href="/guides/features/test-sharding/once">ჰოსტინგზე განლაგებული შარდირებული გაშვება</.localized_link> აქვეყნებს ერთ ანგარიშს თითოეული მუშაკისთვის გაერთიანებულ გაშვებაში, ნაცვლად იმისა, რომ ხელახლა დაითვალოს მისი დიაგნოსტიკური მოვლენების ნაკადი.

## რა ფიქსირდება {#what-is-tracked}

- ანგარიშგებული ტესტების სამიზნეები, ნაკრებები და ინდივიდუალური შემთხვევები.
- გავლილი, ჩავარდნილი და გამოტოვებული შედეგები, ხანგრძლივობებით, თუ გამშვები (runner) მათ აწვდის.
- შეცდომის შეტყობინებები, რომლებიც გამშვებმა (runner) მოგვაწოდა ჰოსტინგზე განლაგებულ შარდირებულ ანგარიშებში.
- დალაგებული ხელახალი ცდები და არასტაბილური შედეგები, როდესაც ტესტი ჯერ ჩავარდება და შემდეგ გაივლის.
- ბრენჩი, კომიტი და CI-ს კონტექსტი, რომელსაც Once აწვდის.

ტესტის იდენტიფიკაცია ეყრდნობა ნატიურ სამიზნის, ნაკრებისა და შემთხვევის სახელებს. შარდირების პაკეტის ID-ები არის დაგეგმვის ერთეულები და არა ტესტების სახელები.

ჩვეულებრივი `once test` ანგარიშგება ინარჩუნებს შედეგებსა და ხელახალი ცდების მცდელობებს, მაგრამ ამჟამად არ შეიცავს შეცდომის შეტყობინებებს საერთო ტესტების ისტორიაში. ჰოსტინგზე განლაგებულ შარდირებულ ანგარიშებს შეიძლება ჰქონდეთ შეცდომის შეტყობინებები, მაგრამ ანგარიშგების არცერთი გზა არ აწვდის წყაროს მდებარეობებს. შეინახეთ თქვენი CI-ს ლოგები იმ დიაგნოსტიკისთვის, რომელიც Tuist-ში არ არის ხელმისაწვდომი.

არა ყველა ტესტის სამიზნე უზრუნველყოფს ერთნაირ დეტალიზაციას. ზოგიერთი გამშვები (runner) აბარებს ინდივიდუალურ შემთხვევებს, სხვები მხოლოდ შეჯამებებს; ზუსტი ფაილის ან შემთხვევის შესრულება ცალკე შესაძლებლობაა. სანამ დაეყრდნობოდეთ შემთხვევების მიხედვით ანალიტიკას ან დეტალურ დაგეგმვას, იხილეთ [Once-ის ტესტების ეკოსისტემის დაფარვა](https://buildonce.dev/docs/guide/graph/testing#understand-current-ecosystem-coverage).

## არასტაბილური ტესტები {#flaky-tests}

Tuist იყენებს ანგარიშგებულ მცდელობებსა და CI-ს ისტორიას არათანმიმდევრული შედეგების იდენტიფიცირებისთვის. მცდელობის ანგარიშგება არ ნიშნავს ხელახალი ცდების ჩართვას: დააყენეთ ხელახალი ცდები იმ გამშვებში (runner), რომელიც მათ მხარდაჭერას უწევს. აღმოჩენისა და მიმდინარე კარანტინის საზღვრებისთვის იხილეთ <.localized_link href="/guides/features/test-insights/flaky-tests/once">Once-ის არასტაბილური ტესტები</.localized_link>.

## შერჩევა და კოდის დაფარვა {#selection-and-code-coverage}

Once-ს შეუძლია კონსერვატიულად შეარჩიოს ტესტები თავისი ლოკალური გრაფიდან `--changed-path`-ის გამოყენებით. ეს არის Once-ის საკუთარი შერჩევა და არა Tuist-ის ჰოსტინგზე განლაგებული დაფარვაზე დაფუძნებული ტესტების შერჩევა:

```bash
once test --changed-path src/library.rs
```

Native Once-ის ანგარიშგება ამჟამად არ ტვირთავს კოდის დაფარვას Tuist-ში. წარმატებული ტესტის ანგარიში ან შარდის გეგმა არ ავსებს კოდის დაფარვის დაფას (dashboard).

## პრობлемების გადაჭრა {#troubleshooting}

თუ გაშვება აკლია, შეამოწმეთ, რომ ეფექტური ქეშის პროვაიდერი ასახელებს თქვენს Tuist-ის პროექტს და ხელახლა გაიარეთ ავთენტიკაცია `once auth login --provider tuist`-ით. პირდაპირი ანგარიშგება ხორციელდება მაქსიმალური ძალისხმევით და არ აქცევს წარმატებულ ტესტის ბრძანებას შეცდომად, როდესაც ანგარიშგების სერვისი მიუწვდომელია.

გაშვების შეჯამებები და სტრუქტურირებული ტესტების შეცდომები არ არის სრული პროცესის ლოგები. ეს სერვერი ამჟამად არ იღებს Once-ის raw action log stream-ს; შეინახეთ თქვენი CI-ს ლოგები იმ გამოტანისთვის, რომელიც არ არის შეტანილი სტრუქტურირებულ შედეგებში.
