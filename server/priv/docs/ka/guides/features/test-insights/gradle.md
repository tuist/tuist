# Gradle-ის ტესტების ანალიტიკა {#gradle-test-insights}

> [!IMPORTANT]
> **მოთხოვნები**
>
> - გამოყენებულია `dev.tuist` Gradle-ის პლაგინი, როგორც აღწერილია <.localized_link href="/guides/get-started/gradle-project">დაიწყეთ Gradle-ის პროექტით</.localized_link>.

Tuist-ის Gradle-ის პლაგინი ავტომატურად ატვირთავს ტესტების შედეგებს ყოველი ტესტის ამოცანის შესრულების შემდეგ, რაც საშუალებას გაძლევთ პირდაპირ Tuist-ის დაფზე ნახოთ ტესტების წარმადობა და არასტაბილური ტესტები.

ტესტების ანალიტიკა ავტომატურად იკრიბება პლაგინის გამოყენებისთანავე. დამატებითი კონფიგურაცია არ არის საჭირო.

შეგიძლიათ მიუწვდეთ თქვენს ტესტების ანალიტიკას Tuist-ის დაფზე და ნახოთ, როგორ იცვლება ის დროთა განმავლობაში:

![დაფა ტესტების ანალიტიკით](/images/guides/features/build-insights/tests-dashboard.png)

## რა ფიქსირდება {#what-is-tracked}

პლაგინი აგროვებს შედეგებს ყველა Gradle-ის `Test` ამოცანიდან, მათ შორის:
- ინდივიდუალური სატესტო შემთხვევის წარმატება/ჩავარდნის სტატუსი და ხანგრძლივობა
- ტესტების სიუიტისა და კლასის სტრუქტურა
- არასტაბილური ტესტების აღმოჩენა გაშვებების მიხედვით

## ატვირთვის ქცევის კონფიგურაცია {#configure-upload-behavior}

ნაგულისხმევად:
- ლოკალური ბილდებისთვის ტესტების შედეგები ფონურად აიტვირთება.
- CI-ის გაშვებებისთვის ტესტების შედეგები წინა პლანზე აიტვირთება, რათა თავიდან ავიცილოთ ტელემეტრიის დაკარგვა მოკლე სიცოცხლის მქონე აგენტებზე.

შეგიძლიათ გადაწეროთ ეს ქცევა `uploadInBackground`-ის გამოყენებით `tuist` ბლოკში თქვენს `settings.gradle.kts`-ში:

```kotlin
tuist {
    uploadInBackground = false // always upload in the foreground
}
```

### Git-ის ისტორია {#git-history}

CI-ზე პლაგინი ასევე ატვირთავს ჩეკაუტის კომიტების ისტორიას, როდესაც იტყობინება ტესტების გაშვების შესახებ: კომიტების SHA-ები, მათი მშობლები, კომიტების თარიღები და დარტი, რომელზეც იყო გაშვება და მისი pull request-ის საბაზო დარტი. არ აიტვირთება ფაილების შინაარსი, კომიტების შეტყობინებები ან ავტორები. ეს ინფორმაცია ეუბნება Tuist-ს, რომელი კომიტები მოხვდა თქვენს ნაგულისხმევ დარტზე, მაგალითად, ისინი, რომლებიც merge queue-მ შეამოწმა. პლაგინი კითხულობს ისტორიას, რომელიც ჩეკაუტს უკვე აქვს, და როდესაც ჩეკაუტს არ აქვს საბაზო დარტი, ითხოვს რემოტიდან მის უახლეს კომიტს (`git ls-remote`). ის არ იწერს ისტორიას.

| ცვლადი | ეფექტი |
| --- | --- |
| `TUIST_GIT_UPLOAD_ENABLED=false` | არ კითხულობს და არ ატვირთავს Git-ის ისტორიას. |
| `TUIST_GIT_UNSHALLOW_ENABLED=false` | კითხულობს მხოლოდ ჩეკაუტს, რემოტთან დაკავშირების გარეშე. |
