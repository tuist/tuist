# Gradle ტესტების ანალიტიკა {#gradle-test-insights}

> [!IMPORTANT]
> **მოთხოვნები**
>
> - გამოყენებულია `dev.tuist` Gradle პლაგინი, როგორც აღწერილია <.localized_link href="/guides/get-started/gradle-project">დაწყება Gradle პროექტით</.localized_link>.

Tuist-ის Gradle პლაგინი ავტომატურად ატვირთავს ტესტების შედეგებს ყოველი სატესტო ამოცანის შესრულების შემდეგ, რაც საშუალებას გაძლევთ პირდაპირ Tuist დაფზე ნახოთ ტესტების წარმადობა და არასტაბილური ტესტები.

ტესტების ანალიტიკა ავტომატურად იკრიბება პლაგინის გამოყენებისთანავე. დამატებითი კონფიგურაცია არ არის საჭირო.

შეგიძლიათ მიუწვდეთ თქვენს ტესტების ანალიტიკას Tuist დაფზე და ნახოთ, როგორ იცვლება ის დროთა განმავლობაში:

![დაფა ტესტების ანალიტიკით](/images/guides/features/build-insights/tests-dashboard.png)

## რა ფიქსირდება {#what-is-tracked}

პლაგინი აგროვებს შედეგებს ყველა Gradle `Test` ამოცანიდან, მათ შორის:
- ინდივიდუალური სატესტო შემთხვევის წარმატების/ჩავარდნის სტატუსი და ხანგრძლივობა
- სატესტო სუიტისა და კლასის სტრუქტურა
- არასტაბილური ტესტების აღმოჩენა სხვადასხვა გაშვებებში

ჩართეთ <.localized_link href="/guides/features/test-code-coverage/gradle">კოდის დაფარვა</.localized_link>, რათა ასევე ატვირთოთ ინფორმაცია იმ კოდზე, რომელიც თქვენმა ტესტებმა შეასრულეს.

## ატვირთვის ქცევის კონფიგურაცია {#configure-upload-behavior}

ნაგულისხმევად:
- ტესტების შედეგები აიტირთება ფონურ რეჟიმში ლოკალური ბილდებისთვის.
- ტესტების შედეგები აიტირთება წინა პლანზე CI გაშვებებისთვის, რათა თავიდან აიცილოთ ტელემეტრიის დაკარგვა მოკლევადიან აგენტებზე.

შეგიძლიათ გადაწეროთ ეს ქცევა `uploadInBackground`-ის გამოყენებით `tuist` ბლოკში თქვენს `settings.gradle.kts`-ში:

```kotlin
tuist {
    uploadInBackground = false // always upload in the foreground
}
```

### Git ისტორია {#git-history}

CI-ზე პლაგინი ასევე ატვირთავს ჩექაუთის კომიტების ისტორიას, როდესაც იტყობინება ტესტების გაშვების შესახებ: კომიტების SHA-ები, მათი მშობლები, კომიტების თარიღები და შტო, რომელზეც იყო გაშვება და მისი pull request-ის საბაზისო შტო. არ აიტვირთება ფაილების შინაარსი, კომიტების შეტყობინებები ან ავტორები. ეს არის ის, რაც ეუბნება Tuist-ს, რომელი კომიტები მოხვდა თქვენს საბაზისო შტოზე, მაგალითად ისინი, რომლებიც merge queue-მ შეამოწმა. პლაგინი კითხულობს ისტორიას, რომელიც ჩექაუთს უკვე აქვს, და როდესაც ჩექაუთს არ აქვს საბაზისო შტო, ითხოვს remote-დან მის უახლეს კომიტს (`git ls-remote`). ის არ იწერს ისტორიას.

| ცვლადი | ეფექტი |
| --- | --- |
| `TUIST_GIT_UPLOAD_ENABLED=false` | არ კითხულობს და არ ატვირთავს Git-ის ისტორიას. |
| `TUIST_GIT_UNSHALLOW_ENABLED=false` | კითხულობს მხოლოდ ჩექაუთს, remote-თან დაკავშირების გარეშე. |
