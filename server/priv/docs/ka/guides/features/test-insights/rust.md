# Rust-ის ტესტების ანალიტიკა {#rust-test-insights}

Tuist იუწყება ინდივიდუალურ ტესტების შედეგებს `cargo test`-დან, მათ შორის ერთეულოვანი ტესტები, ინტეგრაციული ტესტები და doctests. Rust-ის დამატებითი დამოკიდებულება ან სხვა ტესტების გამშვები არ არის საჭირო.

> [!IMPORTANT] Requirements
> - მიჰყევით <.localized_link href="/guides/get-started/rust-project">Rust-ის პროექტის კონფიგურაციას</.localized_link>.

## ტესტების გაშვების შესახებ ინფორმაციის გაგზავნა {#report-your-test-runs}

```sh
tuist cargo test --workspace
```

mise Cargo-ს გარსაცმის კონფიგურირების შემდეგ, შეგიძლიათ განაგრძოთ `cargo test`-ის ბეჭდვა. Cargo კვლავ აკომპილირებს და ასრულებს თქვენს ტესტებს ჩვეულებრივი არგუმენტებით, გამოტანით და გასვლის კოდით. ანგარიშგების შეცდომები არ ცვლის თქვენი ტესტების შედეგს.

შეგიძლიათ აირჩიოთ პაკეტი ან გაფილტროთ ტესტები ჩვეულებრივად:

```sh
tuist cargo test -p store
tuist cargo test authentication
```

## რაზე აკეთებს Tuist დაკვირვებას {#what-is-tracked}

- წარმატებული, წარუმატებელი და იგნორირებული ტესტები დასრულებული ტესტების ნაკრებებიდან.
- ერთეულოვანი ტესტები, ინტეგრაციული ტესტები და doctests.
- მთლიანი ნაკრების ხანგრძლივობა.
- ხელმისაწვდომი მეტამონაცემები ბრენჩის, კომიტის, CI-ის და გამშვების შესახებ.

გაფილტრული ტესტები და ტესტები, რომლებიც შეცდომის შემდეგ არ შესრულდა, არასდროს მოიხსენიება როგორც წარმატებული. შედეგები ჩანსახავს **ტესტები** განყოფილებაში დაფაზე.

## პაკეტები, მოდულები და ტესტების საქმეები {#test-hierarchy}

Tuist აჯგუფებს შედეგებს Cargo-ს პაკეტისა და სამიზნის მიხედვით. Rust-ის მოდულების გზები აჯგუფებს ინდივიდუალურ ტესტებს სამიზნის ფარგლებში:

| დაფის ეტიკეტი | Rust-ის მნიშვნელობა | მაგალითი |
| --- | --- | --- |
| მოდულები | Cargo-ს პაკეტი და სამიზნე | `store::api` |
| ტესტების ნაკრებები | Rust-ის მოდულების გზები | `api::authentication` |
| ტესტების საქმეები | ინდივიდუალური ტესტები | `rejects_invalid_token` |

Doctests იყენებენ ცალკე მოდულს, მაგალითად `store::doctest/store`. მათ სახელებში შედის წყაროს მდებარეობა, ამიტომ მაგალითის გადატანამ შეიძლება შეცვალოს მისი იდენტურობა.

## Doctests და ხანგრძლივობა {#cargo-test}

Doctests სრულდება თქვენი ჩვეულებრივი ტესტების ბრძანებით, მათ შორის `compile_fail`, `should_panic` და `no_run` მაგალითებით. მხოლოდ doctests-ის გასაშვებად:

```sh
tuist cargo test --doc
```

Stable libtest იუწყება მთლიანი ნაკრების დროს, მაგრამ არა ინდივიდუალური ტესტების ხანგრძლივობას. ხელმიუწვდომელი დროის ნიშნები გამორიცხულია თითოეული საქმის ხანგრძლივობის ისტორიიდან და ანალიტიკიდან, ხოლო ტესტების შედეგები კვლავ მონაწილეობენ სანდოობისა და გაშვებების რაოდენობის გამოთვლაში.

## ანგარიშგების ლიმიტები {#reporting-limits}

ინდივიდუალური შედეგები იკრიბება Cargo/libtest-ის ნაგულისხმევი გამოტანიდან. ბრძანებები, რომლებიც იყენებენ `--no-run`, `--list`, ჩუმ ან Cargo-ს ვრცელ გამოტანას, ალტერნატიულ ფორმატებს ან დაუჭერელ ტესტების გამოტანას, სრულდება ჩვეულებრივად ინდივიდუალური ტესტების ანგარიშგების გარეშე. მორგებული harness-ები, არასრული შეჯამებები, სამიზნის გაურკვეველი მიკუთვნება და ზედმეტად დიდი ანგარიშები არ იტვირთება.

თუ workspace-ის პაკეტებს აქვთ იდენტურად სახელდარქმეული ინტეგრაციული სამიზნეები, აირჩიეთ ერთ-ერთი `-p <package>`-ით. ანგარიშგება მხარს უჭერს workspace-ის ზუსტ პაკეტის სახელებს; დამოკიდებულების პაკეტები, ვერსიით კვალიფიცირებული სელექტორები და globs სრულდება ჩვეულებრივად, მაგრამ არ ანგარიშდება. აბსოლუტური doctest გზები გამოტოვებულია, რათა checkout-ის გზები არ მოხვდნენ ტესტების იდენტურობაში.

Tuist ნაკადურად გასცემს გამოტანას შედეგების შეგროვებისას. ეს შეიძლება გავლენა იქონიოს ავტომატურ ფერების აღმოჩენაზე. ფონურმა პროცესებმა, რომლებიც Cargo-ს გასვლის შემდეგაც ღიად ტოვებენ გამოტანის მილებს, შეიძლება გამოიწვიონ ანგარიშის გამოტოვება, მაგრამ არ ცვლიან Cargo-ს გასვლის სტატუსს.

## სანდოობა და შერჩევა {#reliability-and-selection}

გამოიყენეთ <.localized_link href="/guides/features/test-insights/flaky-tests/rust">არასტაბილური ტესტების აღმოჩენა და კარანტინი</.localized_link> არასტაბილური ტესტების შესასწავლად და მათ ჩუმად დასატოვებლად ან გამოსატოვებლად. <.localized_link href="/guides/features/test-sharding/rust">ტესტების დაყოფა</.localized_link> ანაწილებს მთლიან Cargo-ს სამიზნეებს CI-ის მუშაკებზე. დაფარვის შეტანა, დაფარვაზე დაფუძნებული ტესტების შერჩევა და ერთხელ აგების განაწილება არ არის ხელმისაწვდომი ჩვეულებრივი Cargo-ს ტესტების გაშვებისთვის.

## პრობლემების გადაჭრა {#troubleshooting}

თუ ტესტების გაშვება არ ჩანსახავს დაფაზე, ჩართეთ debug გამოტანა, რათა ნახოთ, რატომ არ გაიგზავნა მისი ანგარიში:

```sh
TUIST_DEBUG=1 tuist cargo test --workspace
```
