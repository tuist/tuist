# Rust ტესტების ინსაიტები {#rust-test-insights}

Tuist აგზავნის ცალკეულ ტესტების შედეგებს `cargo test`-დან, მათ შორის იუნიტ ტესტებს, ინტეგრაციულ ტესტებს და დოქტესტებს. Rust დამოკიდებულება ან დამატებითი ტესტების გამშვები არ არის საჭირო.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - მიჰყევით <.localized_link href="/guides/get-started/rust-project">Rust პროექტის კონფიგურაციას</.localized_link>.

## აგზავნეთ თქვენი ტესტების გაშვებები {#report-your-test-runs}

```sh
tuist cargo test --workspace
```

mise Cargo wrapper-ის კონფიგურირების შემდეგ, შეგიძლიათ განაგრძოთ `cargo test`-ის აკრეფა. Cargo კვლავ ახდენს თქვენი ტესტების კომპილაციას და გაშვებას ჩვეული არგუმენტებით, გამოტანით და გასვლის კოდით. ანგარიშგების შეცდომები არ ცვლის თქვენი ტესტების შედეგს.

შეგიძლიათ აირჩიოთ პაკეტი ან გაფილტროთ ტესტები ჩვეულებრივად:

```sh
tuist cargo test -p store
tuist cargo test authentication
```

## რას აკვირდება Tuist {#what-is-tracked}

- წარმატებული, წარუმატებელი და იგნორირებული ტესტები დასრულებული ტესტების ნაკრებებიდან.
- იუნიტ ტესტები, ინტეგრაციული ტესტები და დოქტესტები.
- მთლიანი ნაკრების ხანგრძლივობა.
- ხელმისაწვდომი ბრენჩის, კომიტის, CI-ის და გამშვების მეტამონაცემები.

ფილტრაციის შედეგად გამოტოვებული ტესტები და წარუმატებლობის შემდეგ არ შესრულებული ტესტები არასდროს მონიშნება როგორც წარმატებული. შედეგები ჩანს დაფაზე **Tests** განყოფილებაში.

## პაკეტები, მოდულები და ტესტების საქმეები {#test-hierarchy}

Tuist აჯგუფებს შედეგებს Cargo პაკეტისა და სამიზნის მიხედვით. Rust მოდულის გზები აჯგუფებს ცალკეულ ტესტებს ერთი სამიზნის ფარგლებში:

| დაფის ლეიბლი | Rust მნიშვნელობა | მაგალითი |
| --- | --- | --- |
| მოდულები | Cargo პაკეტი და სამიზნე | `store::api` |
| ტესტების ნაკრებები | Rust მოდულის გზები | `api::authentication` |
| ტესტების საქმეები | ცალკეული ტესტები | `rejects_invalid_token` |

დოქტესტები იყენებენ ცალკე მოდულს, როგორიცაა `store::doctest/store`. მათი სახელები შეიცავს წყაროს მდებარეობას, ამიტომ მაგალითის გადატანამ შეიძლება შეცვალოს მისი იდენტობა.

## დოქტესტები და ხანგრძლივობა {#cargo-test}

დოქტესტები ეშვება თქვენი ჩვეული ტესტის ბრძანებით, მათ შორის `compile_fail`, `should_panic` და `no_run` მაგალითებით. მხოლოდ დოქტესტების გასაშვებად:

```sh
tuist cargo test --doc
```

სტაბილური libtest აგზავნის მთლიანი ნაკრების დროს, მაგრამ არა ცალკეული ტესტების ხანგრძლივობას. ხელმიუწვდომელი დროები გამოირიცხება თითოეული საქმის ხანგრძლივობის ისტორიიდან და ანალიტიკიდან, თუმცა ტესტების შედეგები მაინც მონაწილეობენ სანდოობისა და გაშვებების რაოდენობაში.

## ანგარიშგების ლიმიტები {#reporting-limits}

ცალკეული შედეგები იკრიბება Cargo/libtest-ის ნაგულისხმევი გამოტანიდან. ბრძანებები, რომლებიც იყენებენ `--no-run`, `--list`, ჩუმ ან Cargo-verbose გამოტანას, ალტერნატიულ ფორმატებს ან დაუჭერელ ტესტების გამოტანას, ჩვეულებრივად ეშვებიან ცალკეული ტესტების ანგარიშგების გარეშე. მორგებული harness-ები, არასრული შეჯამებები, ორაზროვანი სამიზნის მიკუთვნება და ზედმეტად დიდი ანგარიშები არ იტვირთება.

თუ workspace პაკეტებს აქვთ იდენტური სახელის მქონე ინტეგრაციული სამიზნეები, აირჩიეთ ერთ-ერთი `-p <package>`-ით. ანგარიშგება მხარს უჭერს ზუსტ workspace პაკეტის სახელებს; დამოკიდებულების პაკეტები, ვერსიით კვალიფიცირებული სელექტორები და globs ჩვეულებრივად ეშვებიან, მაგრამ არ ანგარიშდებიან. აბსოლუტური დოქტესტის გზები გამოტოვებულია, რათა checkout გზები არ მოხვდეს ტესტების იდენტობებში.

Tuist აგზავნის გამოტანას შედეგების შეგროვებისას. ეს შეიძლება გავლენა იქონიოს ავტომატურ ფერის აღმოჩენაზე. ფონური პროცესები, რომლებიც ტოვებენ გამოტანის მილებს ღიად Cargo-ს გასვლის შემდეგ, შეიძლება გამოიწვიოს ანგარიშის გამოტოვება, მაგრამ არ ცვლიან Cargo-ს გასვლის სტატუსს.

## სანდოობა და შერჩევა {#reliability-and-selection}

გამოიყენეთ <.localized_link href="/guides/features/test-insights/flaky-tests/rust">არასტაბილური ტესტების აღმოჩენა და კარანტინი</.localized_link> არასტაბილური ტესტების შესასწავლად და მათ დასაჩუმებლად ან გამოსატოვებლად. <.localized_link href="/guides/features/test-sharding/rust">ტესტების დაყოფა</.localized_link> ანაწილებს მთლიან Cargo სამიზნეებს CI მუშაკებზე. ჩართეთ <.localized_link href="/guides/features/test-code-coverage/rust">კოდის დაფარვა</.localized_link>, რათა დააკვირდეთ თქვენი ტესტების გაშვებების ხაზოვან დაფარვას. დაფარვაზე დაფუძნებული ტესტების შერჩევა და ერთხელ აგებული განაწილება არ არის ხელმისაწვდომი ჩვეულებრივი Cargo ტესტების გაშვებებისთვის.

## პრობლემების გადაჭრა {#troubleshooting}

თუ ტესტების გაშვება არ ჩანს დაფაზე, ჩართეთ debug გამოტანა, რათა ნახოთ, რატომ არ გაიგზავნა მისი ანგარიში:

```sh
TUIST_DEBUG=1 tuist cargo test --workspace
```
