# Rust ტესტების ანალიტიკა {#rust-test-insights}

Tuist იუწყება ინდივიდუალური ტესტების შედეგებს `cargo test`-დან, მათ შორის ერთეულურ ტესტებს, ინტეგრაციულ ტესტებს და doctests-ებს. Rust დამოკიდებულება ან დამატებითი ტესტების გამშვები არ არის საჭირო.

> [!IMPORTANT] Requirements
> - მიჰყევით <.localized_link href="/guides/get-started/rust-project">Rust პროექტის კონფიგურაციას</.localized_link>.

## ტესტების გაშვების ანგარიში {#report-your-test-runs}

```sh
tuist cargo test --workspace
```

mise Cargo wrapper-ის კონფიგურაციით, შეგიძლიათ განაგრძოთ `cargo test`-ის ბეჭდვა. Cargo კვლავ აკომპილირებს და ასრულებს თქვენს ტესტებს ჩვეული არგუმენტებით, გამოტანით და გასვლის კოდით. ანგარიშის წარუმატებლობა არ ცვლის თქვენი ტესტების შედეგს.

შეგიძლიათ აირჩიოთ პაკეტი ან გაფილტროთ ტესტები ჩვეულებრივად:

```sh
tuist cargo test -p store
tuist cargo test authentication
```

## რა აკონტროლებს Tuist {#what-is-tracked}

- წარმატებული, წარუმატებელი და იგნორირებული ტესტები დასრულებული ტესტების სუიტებიდან.
- ერთეულური ტესტები, ინტეგრაციული ტესტები და doctests-ები.
- მთლიანი სუიტის ხანგრძლივობა.
- ხელმისაწვდომი ბრენჩის, კომიტის, CI-ის და გამშვების მეტამონაცემები.

გაფილტრული ტესტები და ტესტები, რომლებიც არ შესრულდა შეცდომის შემდეგ, არასდროს იუწყება როგორც წარმატებული. შედეგები ჩანსახულია დაფბორდზე \*\***Tests**\*\* ქვეშ.

## პაკეტები, მოდულები და ტესტის შემთხვევები {#test-hierarchy}

Tuist აჯგუფებს შედეგებს Cargo პაკეტისა და სამიზნის მიხედვით. Rust მოდულის გზები აჯგუფებს ინდივიდუალურ ტესტებს სამიზნის ფარგლებში:

| დაფბორდის ეტიკეტი | Rust მნიშვნელობა | მაგალითი |
| --- | --- | --- |
| მოდულები | Cargo პაკეტი და სამიზნე | `store::api` |
| ტესტების სუიტები | Rust მოდულის გზები | `api::authentication` |
| ტესტის შემთხვევები | ინდივიდუალური ტესტები | `rejects_invalid_token` |

Doctests-ები იყენებენ ცალკეულ მოდულს, როგორიცაა `store::doctest/store`. მათი სახელები შეიცავს წყაროს მდებარეობას, ამიტომ მაგალითის გადატანამ შეიძლება შეცვალოს მისი იდენტობა.

## Doctests-ები და ხანგრძლივობა {#cargo-test}

Doctests-ები სრულდება თქვენი ჩვეულებრივი ტესტის ბრძანებით, მათ შორის `compile_fail`, `should_panic` და `no_run` მაგალითებით. მხოლოდ doctests-ების გასაშვებად:

```sh
tuist cargo test --doc
```

Stable libtest იუწყება მთლიანი სუიტის დროს, მაგრამ არა ინდივიდუალური ტესტების ხანგრძლივობას. ხელმიუწვდომელი დროები გამოირიცხება თითოეული შემთხვევის ხანგრძლივობის ისტორიიდან და ანალიტიკიდან, ხოლო ტესტის შედეგები კვლავ მონაწილეობენ სანდოობისა და გაშვების რაოდენობაში.

## ანგარიშის ლიმიტები {#reporting-limits}

ინდივიდუალური შედეგები იკრიბება Cargo/libtest-ის ნაგულისხმევი გამოტანიდან. ბრძანებები, რომლებიც იყენებენ `--no-run`, `--list`, ჩუმ ან Cargo-verbose გამოტანას, ალტერნატიულ ფორმატებს ან დაუჭერელ ტესტის გამოტანას, სრულდება ჩვეულებრივად ინდივიდუალური ტესტების ანგარიშის გარეშე. მორგებული harness-ები, არასრული შეჯამებები, გაურკვეველი სამიზნის მიკუთვნება და ზედმეტად დიდი ანგარიშები არ იტვირთება.

თუ workspace პაკეტებს აქვთ იდენტურად სახელდარქმეული ინტეგრაციის სამიზნეები, აირჩიეთ ერთ-ერთი `-p <package>`-ით. ანგარიში მხარდაჭერს workspace პაკეტების ზუსტ სახელებს; დამოკიდებულების პაკეტები, ვერსიით კვალიფიცირებული სელექტორები და globs სრულდება ჩვეულებრივად, მაგრამ არ იუწყება. აბსოლუტური doctest გზები გამოირიცხება, რათა checkout გზები არ მოხვდნენ ტესტის იდენტობებში.

Tuist აწვდის გამოტანას შედეგების შეგროვებისას. ეს შეიძლება გავლენა იქონიოს ავტომატურ ფერის აღმოჩენაზე. ფონური პროცესები, რომლებიც ტოვებენ გამოტანის მილებს ღიად Cargo-ს გასვლის შემდეგ, შეიძლება გამოიწვიოს ანგარიშის გამოტოვება, მაგრამ არ ცვლიან Cargo-ს გასვლის სტატუსს.

## სანდოობა და შერჩევა {#reliability-and-selection}

გამოიყენეთ <.localized_link href="/guides/features/test-insights/flaky-tests/rust">არასტაბილური ტესტების აღმოჩენა</.localized_link> არასტაბილური ტესტების შესასწავლად. დაფბორდის კარანტინი ამჟამად არ აჩუმებს ან არ ტოვებს Cargo ტესტებს. დაფარვის შეტანა, დაფარვაზე დაფუძნებული ტესტის შერჩევა და ერთჯერადი აგების შარდინგი არ არის ხელმისაწვდომი ჩვეულებრივი Cargo ტესტების გაშვებისთვის.

## პრობლემების გადაჭრა {#troubleshooting}

თუ ტესტის გაშვება არ ჩანსახულია დაფბორდზე, ჩართეთ debug გამოტანა, რათა ნახოთ, რატომ არ გაიგზავნა მისი ანგარიში:

```sh
TUIST_DEBUG=1 tuist cargo test --workspace
```
