# Rust-ის ტესტების ანალიტიკა {#rust-test-insights}

Tuist იუწყება ინდივიდუალური ტესტების შედეგებს `cargo test`-დან, მათ შორის ერთეული ტესტები, ინტეგრაციული ტესტები და doctests. Rust-ის დამატებითი დამოკიდებულება ან სხვა ტესტების გამშვები არ არის საჭირო.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - მიჰყევით <.localized_link href="/guides/get-started/rust-project">Rust პროექტის კონფიგურაციას</.localized_link>.

## შეატყობინეთ თქვენი ტესტების გაშვებები {#report-your-test-runs}

```sh
tuist cargo test --workspace
```

mise-ის Cargo wrapper-ის კონფიგურაციის შემდეგ, შეგიძლიათ განაგრძოთ `cargo test`-ის შეყვანა. Cargo კვლავ აკომპილირებს და ასრულებს თქვენს ტესტებს ჩვეულებრივი არგუმენტებით, გამოტანით და გასვლის კოდით. შეტყობინების შეცდომები არ ცვლის თქვენი ტესტების შედეგს.

შეგიძლიათ აირჩიოთ პაკეტი ან გაფილტროთ ტესტები ჩვეულებრივად:

```sh
tuist cargo test -p store
tuist cargo test authentication
```

## რას აკონტროლებს Tuist {#what-is-tracked}

- წარმატებული, წარუმატებელი და იგნორირებული ტესტები დასრულებული ტესტების ნაკრებიდან.
- ერთეული ტესტები, ინტეგრაციული ტესტები და doctests.
- მთლიანი ნაკრების ხანგრძლივობა.
- ხელმისაწვდომი მონაცემები ბრენჩის, კომიტის, CI-ის და გამშვების შესახებ.

ფილტრული ტესტები და შეცდომის შემდეგ არ გაშვებული ტესტები არასდროს მონიშნება როგორც წარმატებული. შედეგები ჩანს სადაშბორდზე **Tests**-ის ქვეშ.

## პაკეტები, მოდულები და ტესტების საქმეები {#test-hierarchy}

Tuist აჯგუფებს შედეგებს Cargo პაკეტისა და მიზნის მიხედვით. Rust-ის მოდულების გზები აჯგუფებს ინდივიდუალურ ტესტებს მიზნის ფარგლებში:

| დაფის ეტიკეტი | Rust-ის მნიშვნელობა | მაგალითი |
| --- | --- | --- |
| მოდულები | Cargo პაკეტი და მიზანი | `store::api` |
| ტესტების ნაკრებები | Rust-ის მოდულების გზები | `api::authentication` |
| ტესტების საქმეები | ინდივიდუალური ტესტები | `rejects_invalid_token` |

Doctests იყენებენ ცალკე მოდულს, მაგალითად `store::doctest/store`. მათ სახელებში შედის წყაროს მდებარეობა, ამიტომ მაგალითის გადატანამ შეიძლება შეცვალოს მისი იდენტობა.

## Doctests და ხანგრძლივობა {#cargo-test}

Doctests სრულდება თქვენი ჩვეულებრივი ტესტის ბრძანებით, მათ შორის `compile_fail`, `should_panic` და `no_run` მაგალითები. მხოლოდ doctests-ის გასაშვებად:

```sh
tuist cargo test --doc
```

სტაბილური libtest იუწყება მთლიანი ნაკრების დროს, მაგრამ არა ინდივიდუალური ტესტების ხანგრძლივობას. მიუწვდომელი დროის ნიშნები გამოირიცხება თითოეული საქმის ხანგრძლივობის ისტორიიდან და ანალიტიკიდან, ხოლო ტესტების შედეგები კვლავ მონაწილეობენ სანდოობისა და გაშვებების რაოდენობაში.

## შეტყობინების ლიმიტები {#reporting-limits}

ინდივიდუალური შედეგები იკრიბება Cargo/libtest-ის ნაგულისხმევი გამოტანიდან. ბრძანებები, რომლებიც იყენებენ `--no-run`, `--list`, ჩუმ ან Cargo-verbose გამოტანას, ალტერნატიულ ფორმატებს ან დაუჭერელ ტესტის გამოტანას, სრულდება ჩვეულებრივად ინდივიდუალური ტესტების შეტყობინების გარეშე. მორგებული harness-ები, არასრული შეჯამებები, გაურკვეველი მიზნის მინიჭება და ზედმეტად დიდი ანგარიშები არ იტვირთება.

თუ workspace პაკეტებს აქვთ იდენტურად სახელდარქმეული ინტეგრაციული მიზნები, აირჩიეთ ერთ-ერთი `-p <package>`-ით. შეტყობინება უჭერს მხარს workspace პაკეტების ზუსტ სახელებს; დამოკიდებულების პაკეტები, ვერსიით კვალიფიცირებული სელექტორები და globs სრულდება ჩვეულებრივად, მაგრამ არ იუწყება. აბსოლუტური doctest გზები გამოირიცხება, რათა checkout გზები არ მოხვდეს ტესტების იდენტობაში.

Tuist აკეთებს ნაკადს გამოტანისა შედეგების შეგროვებისას. ეს შეიძლება გავლენა იქონიოს ავტომატურ ფერის აღმოჩენაზე. ფონური პროცესები, რომლებიც ტოვებენ გამოტანის მილებს გახსნილს Cargo-ს გასვლის შემდეგ, შეიძლება გამოიწვიოს ანგარიშის გამოტოვება, მაგრამ არ ცვლიან Cargo-ს გასვლის სტატუსს.

## სანდოობა და შერჩევა {#reliability-and-selection}

გამოიყენეთ <.localized_link href="/guides/features/test-insights/flaky-tests/rust">არასტაბილური ტესტების აღმოჩენა და კარანტინი</.localized_link> არასტაბილური ტესტების შესასწავლად და მათ დასამუნჯებლად ან გამოსატოვებლად. <.localized_link href="/guides/features/test-sharding/rust">ტესტების დაყოფა</.localized_link> ანაწილებს მთლიან Cargo მიზნებს CI მუშაკებზე. დაფარვის შეტანა, დაფარვაზე დაფუძნებული ტესტების შერჩევა და ერთხელ აგების განაწილება არ არის ხელმისაწვდომი ჩვეულებრივი Cargo ტესტების გაშვებისთვის.

## პრობлемების გადაჭრა {#troubleshooting}

თუ ტესტების გაშვება არ ჩანს დაფაზე, ჩართეთ debug გამოტანა, რათა ნახოთ, რატომ არ გაიგზავნა მისი ანგარიში:

```sh
TUIST_DEBUG=1 tuist cargo test --workspace
```
