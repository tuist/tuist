# Rust-ის ტესტების ანალიტიკა {#rust-test-insights}

Tuist იწერს ინდივიდუალურ ტესტების შედეგებს `cargo test`-დან, მათ შორის ერთეულოვან ტესტებს, ინტეგრაციულ ტესტებს და doctests-ებს. Rust-ის დამატებითი დამოკიდებულება ან ტესტების გამშვები არ არის საჭირო.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - მიჰყევით <.localized_link href="/guides/get-started/rust-project">Rust-ის პროექტის კონფიგურაციას</.localized_link>.

## გააგზავნეთ თქვენი ტესტების გაშვებები {#report-your-test-runs}

```sh
tuist cargo test --workspace
```

mise-ის Cargo wrapper-ის კონფიგურაციის შემდეგ, შეგიძლიათ განაგრძოთ `cargo test`-ის აკრეფა. Cargo კვლავ ახდენს თქვენი ტესტების კომპილაციას და გაშვებას ჩვეული არგუმენტებით, გამოტანით და გასვლის კოდით. შეტყობინებების გაგზავნის შეცდომები არ ცვლის თქვენი ტესტების შედეგს.

შეგიძლიათ აირჩიოთ პაკეტი ან გაფილტროთ ტესტები ჩვეულებრივად:

```sh
tuist cargo test -p store
tuist cargo test authentication
```

## რაზე აკეთებს Tuist დაკვირვებას {#what-is-tracked}

- გავლილი, ჩავარდნილი და იგნორირებული ტესტები დასრულებული ტესტების ნაკრებიდან.
- ერთეულოვანი ტესტები, ინტეგრაციული ტესტები და doctests-ები.
- მთლიანი ნაკრების ხანგრძლივობა.
- ხელმისაწვდომი მეტამონაცემები ბრენჩის, კომიტის, CI-ის და გამშვების შესახებ.

გაფილტრული ტესტები და ტესტები, რომლებიც არ შესრულებულა ჩავარდნის შემდეგ, არასდროს იწერება როგორც გავლილი. შედეგები ჩანს დაფის **Tests** განყოფილებაში.

## პაკეტები, მოდულები და ტესტის შემთხვევები {#test-hierarchy}

Tuist აჯგუფებს შედეგებს Cargo პაკეტისა და სამიზნის მიხედვით. Rust-ის მოდულების გზები აჯგუფებს ინდივიდუალურ ტესტებს სამიზნის ფარგლებში:

| დაფის ეტიკეტი | Rust-ის მნიშვნელობა | მაგალითი |
| --- | --- | --- |
| მოდულები | Cargo პაკეტი და სამიზნე | `store::api` |
| ტესტების ნაკრებები | Rust-ის მოდულების გზები | `api::authentication` |
| ტესტის შემთხვევები | ინდივიდუალური ტესტები | `rejects_invalid_token` |

Doctests-ები იყენებენ ცალკე მოდულს, მაგალითად `store::doctest/store`. მათი სახელები შეიცავს წყაროს მდებარეობას, ამიტომ მაგალითის გადატანამ შეიძლება შეცვალოს მისი იდენტურობა.

## Doctests-ები და ხანგრძლივობა {#cargo-test}

Doctests-ები ეშვება თქვენი ჩვეული ტესტების ბრძანებით, მათ შორის `compile_fail`, `should_panic` და `no_run` მაგალითებით. მხოლოდ doctests-ების გასაშვებად:

```sh
tuist cargo test --doc
```

Stable libtest იწერს მთლიანი ნაკრების დროს, მაგრამ არა ინდივიდუალური ტესტების ხანგრძლივობას. მიუწვდომელი დროის მონაცემები გამოირიცხება თითოეული შემთხვევის ხანგრძლივობის ისტორიიდან და ანალიტიკიდან, თუმცა ტესტების შედეგები კვლავ მონაწილეობენ სანდოობისა და გაშვებების რაოდენობის დათვლაში.

## შეტყობინებების ლიმიტები {#reporting-limits}

ინდივიდუალური შედეგები იკრიბება Cargo/libtest-ის ნაგულისხმევი გამოტანიდან. ბრძანებები, რომლებიც იყენებენ `--no-run`, `--list`, ჩუმ ან Cargo-verbose გამოტანას, ალტერნატიულ ფორმატებს ან დაუჭერელ ტესტების გამოტანას, ჩვეულებრივად ეშვებიან ინდივიდუალური ტესტების შეტყობინების გარეშე. მორგებული harness-ები, არასრული შეჯამებები, გაურკვეველი სამიზნის მიკუთვნება და ზედმეტად დიდი ანგარიშები არ იტვირთება.

თუ workspace-ის პაკეტებს აქვთ იდენტურად სახელდარქმეული ინტეგრაციის სამიზნეები, აირჩიეთ ერთ-ერთი `-p <package>`-ით. შეტყობინებები მხარდაჭერილია workspace-ის ზუსტი პაკეტის სახელებისთვის; დამოკიდებულების პაკეტები, ვერსიით კვალიფიცირებული სელექტორები და globs ჩვეულებრივად ეშვებიან, მაგრამ არ იწერებიან. აბსოლუტური doctest გზები გამოირიცხება, რათა checkout-ის გზები არ მოხვდეს ტესტების იდენტურობაში.

Tuist აწვდის გამოტანას შედეგების შეგროვებისას. ეს შეიძლება გავლენა იქონიოს ავტომატურ ფერების აღმოჩენაზე. ფონური პროცესები, რომლებიც ტოვებენ გამოტანის მილებს გახსნილს Cargo-ს გასვლის შემდეგ, შეიძლება გამოიწვიონ ანგარიშის გამოტოვება, მაგრამ არ ცვლიან Cargo-ს გასვლის სტატუსს.

## სანდოობა და შერჩევა {#reliability-and-selection}

გამოიყენეთ <.localized_link href="/guides/features/test-insights/flaky-tests/rust">არასტაბილური ტესტების აღმოჩენა და კარანტინი</.localized_link> არასტაბილური ტესტების შესასწავლად და მათ დასადუმებლად ან გამოსატოვებლად. <.localized_link href="/guides/features/test-sharding/rust">ტესტების დაშლა</.localized_link> ანაწილებს მთლიან Cargo სამიზნეებს CI მუშაკებზე. ჩართეთ <.localized_link href="/guides/features/test-code-coverage/rust">კოდის დაფარვა</.localized_link>, რათა დააკვირდეთ თქვენი ტესტების გაშვებების ხაზოვან დაფარვას. დაფარვაზე დაფუძნებული ტესტების შერჩევა და ერთხელ აგების განაწილება არ არის ხელმისაწვდომი ჩვეულებრივი Cargo ტესტების გაშვებისთვის.

## პრობლემების მოგვარება {#troubleshooting}

თუ ტესტების გაშვება არ ჩანს დაფაზე, ჩართეთ debug გამოტანა, რათა ნახოთ, რატომ არ გაიგზავნა მისი ანგარიში:

```sh
TUIST_DEBUG=1 tuist cargo test --workspace
```
