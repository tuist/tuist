# Rust ტესტების ანალიტიკა {#rust-test-insights}

Tuist იუწყება ცალკეული ტესტების შედეგებს `cargo test`-დან, მათ შორის ერთეულოვანი ტესტები, ინტეგრაციული ტესტები და doctests. არ არის საჭირო Rust დამოკიდებულება ან დამატებითი ტესტების გამშვები.

> [!IMPORTANT]
> **მოთხოვნები**
>
> - მიჰყევით <.localized_link href="/guides/get-started/rust-project">Rust პროექტის კონფიგურაციას</.localized_link>.

## გააგზავნეთ თქვენი ტესტების გაშვებები {#report-your-test-runs}

```sh
tuist cargo test --workspace
```

mise Cargo wrapper-ის კონფიგურაციით, შეგიძლიათ განაგრძოთ `cargo test`-ის აკრეფა. Cargo კვლავ აკომპილირებს და უშვებს თქვენს ტესტებს ჩვეულებრივი არგუმენტებით, გამოტანით და გასვლის კოდით. ანგარიშგების შეცდომები არ ცვლის თქვენი ტესტების შედეგს.

შეგიძლიათ აირჩიოთ პაკეტი ან გაფილტროთ ტესტები ჩვეულებრივად:

```sh
tuist cargo test -p store
tuist cargo test authentication
```

## რა თვალყურს ადევნებს Tuist {#what-is-tracked}

- წარმატებული, წარუმატებელი და იგნორირებული ტესტები დასრულებული ტესტების ნაკრებიდან.
- ერთეულოვანი ტესტები, ინტეგრაციული ტესტები და doctests.
- მთლიანი ნაკრების ხანგრძლივობა.
- ხელმისაწვდომი ბრენჩის, კომიტის, CI და გამშვების მეტამონაცემები.

გაფილტრული ტესტები და ტესტები, რომლებიც არ შესრულდა შეცდომის შემდეგ, არასდროს იუწყება როგორც წარმატებული. შედეგები ჩანს **Tests**-ის ქვეშ დაფაზე.

## პაკეტები, მოდულები და ტესტის შემთხვევები {#test-hierarchy}

Tuist აჯგუფებს შედეგებს Cargo პაკეტისა და მიზნის მიხედვით. Rust მოდულის გზები აჯგუფებს ცალკეულ ტესტებს მიზნის ფარგლებში:

| დაფის ჭდე | Rust მნიშვნელობა | მაგალითი |
| --- | --- | --- |
| მოდულები | Cargo პაკეტი და მიზანი | `store::api` |
| ტესტების ნაკრებები | Rust მოდულის გზები | `api::authentication` |
| ტესტის შემთხვევები | ცალკეული ტესტები | `rejects_invalid_token` |

Doctests იყენებენ ცალკე მოდულს, მაგალითად `store::doctest/store`. მათი სახელები შეიცავს წყაროს მდებარეობას, ამიტომ მაგალითის გადატანამ შეიძლება შეცვალოს მისი იდენტურობა.

## Doctests და ხანგრძლივობა {#cargo-test}

Doctests ეშვება თქვენი ჩვეულებრივი ტესტის ბრძანებით, მათ შორის `compile_fail`, `should_panic` და `no_run` მაგალითებით. მხოლოდ doctests-ის გასაშვებად:

```sh
tuist cargo test --doc
```

Stable libtest იუწყება მთლიანი ნაკრების დროს, მაგრამ არა ცალკეული ტესტების ხანგრძლივობას. მიუწვდომელი დროის მონაცემები გამორიცხულია თითოეული შემთხვევის ხანგრძლივობის ისტორიიდან და ანალიტიკიდან, ხოლო ტესტის შედეგები კვლავ მონაწილეობენ სანდოობისა და გაშვებების რაოდენობაში.

## ანგარიშგების ლიმიტები {#reporting-limits}

ცალკეული შედეგები იკრიბება Cargo/libtest-ის ნაგულისხმევი გამოტანიდან. ბრძანებები, რომლებიც იყენებენ `--no-run`, `--list`, ჩუმ ან Cargo-verbose გამოტანას, ალტერნატიულ ფორმატებს ან დაუჭერელ ტესტის გამოტანას, ეშვებიან ჩვეულებრივად ცალკეული ტესტების ანგარიშგების გარეშე. მორგებული harness-ები, არასრული შეჯამებები, გაურკვეველი მიზნის მიკუთვნება და ზედმეტად დიდი ანგარიშები არ იტვირთება.

თუ სამუშაო სივრცის პაკეტებს აქვთ იდენტური სახელის მქონე ინტეგრაციული მიზნები, აირჩიეთ ერთ-ერთი `-p <package>`-ით. ანგარიშგება მხარს უჭერს სამუშაო სივრცის ზუსტ პაკეტის სახელებს; დამოკიდებულების პაკეტები, ვერსიით კვალიფიცირებული სელექტორები და globs ეშვებიან ჩვეულებრივად, მაგრამ არ იუწყებიან. აბსოლუტური doctest გზები გამოტოვებულია, რათა checkout გზები არ მოხვდეს ტესტის იდენტურობებში.

Tuist აწვდის გამოტანას შედეგების შეგროვებისას. ეს შეიძლება გავლენა იქონიოს ავტომატურ ფერის აღმოჩენაზე. ფონურ პროცესებს, რომლებიც ტოვებენ გამოტანის მილებს გახსნილს Cargo-ს გასვლის შემდეგ, შეუძლიათ გამოიწვიონ ანგარიშის გამოტოვება, მაგრამ არ ცვლიან Cargo-ს გასვლის სტატუსს.

## სანდოობა და შერჩევა {#reliability-and-selection}

გამოიყენეთ <.localized_link href="/guides/features/test-insights/flaky-tests/rust">არასტაბილური ტესტების აღმოჩენა და კარანტინი</.localized_link> არასტაბილური ტესტების შესასწავლად და მათ დასამუნჯად ან გამოსატოვებლად. <.localized_link href="/guides/features/test-sharding/rust">ტესტების დაყოფა</.localized_link> ანაწილებს მთლიან Cargo მიზნებს CI მუშაკებზე. ჩართეთ <.localized_link href="/guides/features/test-code-coverage/rust">კოდის დაფარვა</.localized_link>, რათა მიჰყვეთ თქვენი ტესტების გაშვებების ხაზოვან დაფარვას. დაფარვაზე დაფუძნებული ტესტების შერჩევა და ერთხელ აგების განაწილება არ არის ხელმისაწვდომი ჩვეულებრივი Cargo ტესტების გაშვებებისთვის.

## პრობლემების მოგვარება {#troubleshooting}

თუ ტესტის გაშვება არ ჩანს დაფაზე, ჩართეთ debug გამოტანა, რათა ნახოთ, რატომ არ გაიგზავნა მისი ანგარიში:

```sh
TUIST_DEBUG=1 tuist cargo test --workspace
```
