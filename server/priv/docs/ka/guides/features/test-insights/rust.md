# Rust-ის ტესტების ანალიტიკა {#rust-test-insights}

Tuist იუწყება ინდივიდუალურ ტესტების შედეგებს `cargo test`-დან, მათ შორის ერთეულოვანი ტესტები, ინტეგრაციული ტესტები და doctests. Rust-ის დამოკიდებულება ან დამატებითი ტესტების გამშვები არ არის საჭირო.

> [!IMPORTANT] Requirements
> - მიჰყევით <.localized_link href="/guides/get-started/rust-project">Rust პროექტის კონფიგურაციას</.localized_link>.

## გააგზავნეთ თქვენი ტესტების გაშვებები {#report-your-test-runs}

```sh
tuist cargo test --workspace
```

mise Cargo wrapper-ის კონფიგურაციით, შეგიძლიათ განაგრძოთ `cargo test`-ის შეყვანა. Cargo კვლავ აკომპილირებს და ასრულებს თქვენს ტესტებს ჩვეულებრივი არგუმენტებით, გამოტანით და გასვლის კოდით. გაგზავნის შეცდომები არ ცვლის თქვენი ტესტების შედეგს.

შეგიძლიათ აირჩიოთ პაკეტი ან გაფილტროთ ტესტები ჩვეულებრივად:

```sh
tuist cargo test -p store
tuist cargo test authentication
```

## რაზე აკვირდება Tuist {#what-is-tracked}

- გავლილი, ჩავარდნილი და უგულებელყოფილი ტესტები დასრულებული ტესტების ნაკრებიდან.
- ერთეულოვანი ტესტები, ინტეგრაციული ტესტები და doctests.
- მთლიანი ნაკრების ხანგრძლივობა.
- ხელმისაწვდომი მეტამონაცემები branch-ის, commit-ის, CI-ის და runner-ის შესახებ.

გაფილტრული ტესტები და ტესტები, რომლებიც ვერ შესრულდა ჩავარდნის შემდეგ, არასდროს იუწყებიან როგორც გავლილი. შედეგები ჩანს **Tests**-ში დაფაზე.

## პაკეტები, მოდულები და ტესტების საქმეები {#test-hierarchy}

Tuist აჯგუფებს შედეგებს Cargo პაკეტისა და target-ის მიხედვით. Rust-ის მოდულის გზები აჯგუფებს ინდივიდუალურ ტესტებს target-ის ფარგლებში:

| დაფის ეტიკეტი | Rust-ის მნიშვნელობა | მაგალითი |
| --- | --- | --- |
| მოდულები | Cargo პაკეტი და target | `store::api` |
| ტესტების ნაკრებები | Rust-ის მოდულის გზები | `api::authentication` |
| ტესტების საქმეები | ინდივიდუალური ტესტები | `rejects_invalid_token` |

Doctests იყენებენ ცალკე მოდულს, მაგალითად `store::doctest/store`. მათი სახელები მოიცავს წყაროს მდებარეობას, ამიტომ მაგალითის გადატანამ შეიძლება შეცვალოს მისი იდენტურობა.

## Doctests და ხანგრძლივობა {#cargo-test}

Doctests სრულდება თქვენი ჩვეულებრივი ტესტების ბრძანებით, მათ შორის `compile_fail`, `should_panic` და `no_run` მაგალითებით. მხოლოდ doctests-ის გასაშვებად:

```sh
tuist cargo test --doc
```

სტაბილური libtest იუწყება მთლიანი ნაკრების დროს, მაგრამ არა ინდივიდუალური ტესტების ხანგრძლივობას. ხელმიუწვდომელი დროები გამოირიცხება თითოეული საქმის ხანგრძლივობის ისტორიებიდან და ხანგრძლივობის ანალიტიკიდან, ხოლო ტესტების შედეგები კვლავ მონაწილეობენ საიმედოობისა და გაშვებების რაოდენობაში.

## გაგზავნის ლიმიტები {#reporting-limits}

ინდივიდუალური შედეგები იკრიბება Cargo/libtest-ის ნაგულისხმევი გამოტანიდან. ბრძანებები, რომლებიც იყენებენ `--no-run`, `--list`, ჩუმ ან Cargo-verbose გამოტანას, ალტერნატიულ ფორმატებს ან დაუჭერელ ტესტების გამოტანას, სრულდება ჩვეულებრივად ინდივიდუალური ტესტების გაგზავნის გარეშე. მორგებული harness-ები, არასრული შეჯამებები, გაურკვეველი target-ის მიკუთვნება და ზედმეტად დიდი ანგარიშები არ იტვირთება.

თუ workspace პაკეტებს აქვთ იდენტურად სახელდარქმეული ინტეგრაციული target-ები, აირჩიეთ ერთ-ერთი `-p <package>`-ით. გაგზავნა მხარდაჭერს workspace პაკეტების ზუსტ სახელებს; დამოკიდებულების პაკეტები, ვერსიით კვალიფიცირებული სელექტორები და globs სრულდება ჩვეულებრივად, მაგრამ არ იგზავნება. აბსოლუტური doctest გზები გამოირიცხება, რათა checkout გზები არ მოხვდნენ ტესტების იდენტურობაში.

Tuist ნაკადავებს გამოტანას შედეგების შეგროვებისას. ეს შეიძლება გავლენა მოახდინოს ავტომატურ ფერის აღმოჩენაზე. ფონური პროცესები, რომლებიც ტოვებენ გამოტანის მილებს ღიად Cargo-ს გასვლის შემდეგ, შეიძლება გამოიწვიონ ანგარიშის გამოტოვება, მაგრამ არ ცვლიან Cargo-ს გასვლის სტატუსს.

## საიმედოობა და შერჩევა {#reliability-and-selection}

გამოიყენეთ <.localized_link href="/guides/features/test-insights/flaky-tests/rust">არასტაბილური ტესტების აღმოჩენა და კარანტინი</.localized_link> არასტაბილური ტესტების შესასწავლად და მათ დასადუმებლად ან გამოსატოვებლად. <.localized_link href="/guides/features/test-sharding/rust">ტესტების გადანაწილება</.localized_link> ანაწილებს მთლიან Cargo target-ებს CI worker-ებზე. დაფარვის შეტანა, დაფარვაზე დაფუძნებული ტესტების შერჩევა და ერთხელ აგების განაწილება არ არის ხელმისაწვდომი ჩვეულებრივი Cargo ტესტების გაშვებისთვის.

## პრობლემების გადაჭრა {#troubleshooting}

თუ ტესტების გაშვება არ ჩანს დაფაზე, ჩართეთ debug გამოტანა, რათა ნახოთ, რატომ არ გაიგზავნა მისი ანგარიში:

```sh
TUIST_DEBUG=1 tuist cargo test --workspace
```
