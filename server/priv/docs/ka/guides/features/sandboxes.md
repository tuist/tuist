# სენდბოქსები {#sandboxes}

> [!IMPORTANT]
> **მხოლოდ მოწვევით**
>
> Tuist Sandboxes, როგორც Linux-ზე, ისე macOS-ზე, ამჟამად მხოლოდ მოწვევითაა ხელმისაწვდომი, სანამ შესაძლებლობებს გავზრდით. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [კომუნიტის Slack-ში](https://slack.tuist.dev), რათა თქვენი ანგარიშისთვის წვდომა მოითხოვოთ. ფასები გამოცხადდება, როდესაც Sandboxes ზოგად ხელმისაწვდომობას მიიღებს.

სენდბოქსი არის ვირტუალური მანქანა, სადაც კოდირების აგენტი ასრულებს ბრძანებებს და არედაქტირებს ფაილებს. თითოეულ აგენტის სესიას ეკუთვნის საკუთარი სენდბოქსი, რომელიც ინარჩუნებს მის checkout-ს, აწყობის პროდუქტებს და დაინსტალირებულ ხელსაწყოებს სესიის განმავლობაში. როდესაც აგენტი უმოქმედო ხდება, სენდბოქსი ჩერდება; შემდეგი შეტყობინება აღადგენს მას იქიდან, სადაც გაჩერდა.

სენდბოქსები მუშაობენ იმავე ფლოტზე, რაზეც <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link>, თქვენი გუნდის <.localized_link href="/guides/features/cache">ქეშის</.localized_link> გვერდით, ასე რომ აგენტის აწყობებს შეუძლიათ გამოიყენონ იგივე ქეშირებული არტიფაქტები, რაც თქვენს CI-სა და ადგილობრივ მანქანებს.

სენდბოქსების გამოყენება შეგიძლიათ:

- **<.localized_link href="/guides/features/sandboxes/amp">Amp</.localized_link>**: გაუშვით თქვენი Amp სამუშაო სივრცის orbs Tuist-ზე, ან ნებისმიერ Amp ძაფს მიანიჭეთ Mac Xcode-ის აწყობებისთვის <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინის</.localized_link> მეშვეობით.
- **<.localized_link href="/guides/features/sandboxes/claude">Claude</.localized_link>**: გაუშვით Claude Managed Agents სესიები და Claude Code ღრუბლოვანი სესიები (claude.ai, დესკტოპისა და მობილურის აპები და `claude --cloud`) Tuist-ზე.
- **[Tuist CLI](#cli)**: შექმენით სენდბოქსები და გაუშვით მათში ბრძანებები თქვენი ტერმინალიდან, ან თქვენი საკუთარი ხელსაწყოებიდან API-ს მეშვეობით.

## CLI-ს დაწყება {#cli}

შექმენით სენდბოქსი და გაუშვით მასში ბრძანებები თქვენი ტერმინალიდან `tuist sandbox`-ის მეშვეობით.

### 1. შესვლა {#cli-log-in}

ანგარიშის ნებისმიერ წევრს შეუძლია შექმნას და მართოს მისი სენდბოქსები:

```bash
tuist auth login
```

### 2. სენდბოქსის შექმნა {#cli-create}

```bash
tuist sandbox create --platform macos
```

გამოტოვეთ `--platform` Linux-ისთვის. გადაეცით `--xcode` ვერსიით, მაგალითად `--xcode 26.1.1`, Mac-ისთვის იმ [Xcode](#xcode)-ით; ეს გულისხმობს `--platform macos`-ს. გადაეცით `--vcpus` `--memory-gb`-თან ერთად უფრო დიდი [კონფიგურაციისთვის](#platforms), `--guaranteed-vcpus` Linux სენდბოქსისთვის მეტი [CPU](#guaranteed-cpu)-ის გარანტიის მისაღებად, და `--workspace-gb` უფრო დიდი დისკისთვის. სენდბოქსი მუშაობს შექმნიდან ორი საათის განმავლობაში და ხელახლა ყოველი აღდგენიდან; გადაეცით `--lifetime-minutes` 5 წუთიდან ერთ დღემდე შუალედისთვის. როდესაც მისი სიცოცხლის ხანგრძლივობა მთავრდება, მისი მიმდინარე ბრძანებები იუქმდება და ის ჩერდება და არქივირდება, ფაილების შენარჩუნებით, ასე რომ დაუვიწყებელი სენდბოქსი წყვეტს თქვენი ანგარიშის შესაძლებლობების გამოყენებას. ბრძანება ბრუნდება, როდესაც სენდბოქსი მუშაობს და ბეჭდავს მის დეტალებს, მათ შორის ID-ს. როდესაც ყველა ჰოსტი დაკავებულია, მაგალითად, როდესაც CI დავალებები იკავებენ საერთო Mac-ებს, სერვერი ელოდება 25 წამს ერთ-ერთისთვის, სანამ შექმნა ჩავარდება `fleet_busy`-ით; გადაეცით `--wait-timeout 5m` ცდის გასაგრძელებლად 5 წუთამდე (მაქსიმუმ საათამდე), მიზეზის stderr-ზე დაახლოებით წუთში ერთხელ გამეორებით. ის იყენებს მიმდინარე დირექტორიაში არსებული Tuist პროექტის ანგარიშს; გადაეცით `--account` სხვის არჩევას.

### 3. ბრძანებების გაშვება {#cli-exec}

```bash
tuist sandbox exec <sandbox-id> -- xcodebuild -version
```

ბრძანება მუშაობს `bash -l`-ით სენდბოქსში, რომელიც ჯერ აღდგება, თუ ჩერებულია. `tuist` აწვდის მის გამონატანს, რამდენი ხანიც არ უნდა მუშაობდეს და გადის ბრძანების სტატუსით; Ctrl-C აუქმებს მას სენდბოქსში. გადაეცით `--cwd`, `--env NAME=VALUE` და `--timeout` (ექვს საათამდე) საჭიროებისამებრ.

ბრძანება მუშაობს `tuist`-გან დამოუკიდებლად, ასე რომ უძლებს კავშირის გაწყვეტას. ხანგრძლივი აწყობის ჩასასმელად დროის ლიმიტით ინსტრუმენტის გამოძახებაში, მაგალითად აგენტის, გადაეცით `--wait <seconds>`: როდესაც ისინი ჯერ გაივლიან, `tuist` ტოვებს ბრძანებას მუშა მდგომარეობაში, გადის 75-ით და ბეჭდავს `tuist sandbox exec <sandbox-id> --attach <command-id> --stdout-offset … --stderr-offset …` ბრძანებას, რომელიც აგრძელებს მის გამონატანს იქიდან, სადაც გაჩერდა და გადის ბრძანების სტატუსით.

### ჩვეულებრივი ამოცანები {#cli-tasks}

| ამოცანა | ბრძანება |
| --- | --- |
| სენდბოქსების ჩამოთვლა | `tuist sandbox list` |
| ერთის ჩვენება | `tuist sandbox show <id>` |
| შეჩერება ან აღდგენა | `tuist sandbox pause <id>`, `tuist sandbox resume <id>` |
| მუშაობის გაგრძელება ვადის გასვლის შემდეგ | `tuist sandbox extend <id> --lifetime-minutes 240` |
| ადგილობრივი Git worktree-ის ფაილების ასახვა მასში | `tuist sandbox sync <id>` |
| ფაილების კოპირება გარეთ ან შიგნით | `tuist sandbox cp <id>:<path> <local-path>`, `tuist sandbox cp <local-path> <id>:<path>` |
| წაშლა | `tuist sandbox delete <id> --yes` |
| გამოყენების ნახვა | `tuist sandbox analytics` |

დაამატეთ `--json` მანქანისთვის წასაკითხი გამონატანისთვის. იხილეთ <.localized_link href="/cli/sandbox">CLI-ს ცნობარი</.localized_link> ყველა პარამეტრისთვის. სენდბოქსების კოდიდან მართვის ნაცვლად, გამოიყენეთ იგივე ოპერაციები [Tuist API](https://tuist.dev/api/docs)-ს მეშვეობით `/api/accounts/{account_handle}/sandboxes`-ქვეშ, ან მიეცით აგენტს მათი გამოყენება <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>-ს მეშვეობით.

ხელსაწყოები, რომლებსაც არ შეუძლიათ ინტერაქტიული შესვლა, მაგალითად აგენტის პლაგინი, რომელიც აწყობს macOS სენდბოქსში, შეუძლიათ ავთენტიკაცია <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენით</.localized_link> `account:sandboxes:write` სკოპით. მას შეუძლია გააკეთოს ის, რაც ანგარიშის წევრს: შექმნას სენდბოქსები, გაუშვას მათში ბრძანებები და შეაჩეროს, აღადგინოს, დააარქივოს და წაშალოს ისინი. ინტეგრაციის პარამეტრები და ინტეგრაციის მომსახურე სენდბოქსებში ბრძანებების გაშვება რჩება ანგარიშის ადმინისტრატორებთან.

### Tuist სენდბოქსის შიგნით {#tuist-in-sandbox}

macOS სენდბოქსები მოდიან Tuist CLI-ით. როდესაც თქვენი პროექტი ამაგრებს Tuist-ს mise-ის მეშვეობით (`mise.toml` ან `.tool-versions`), `tuist` ასრულებს იმ ვერსიას, რომელიც ინსტალირდება პირველად, როდესაც ბრძანებას დასჭირდება. ყოველი ბრძანება, რომელსაც იწყებთ `tuist sandbox exec`-ით, აქვს mise-ის shims (`$HOME/.local/share/mise/shims`) პირველად `PATH`-ზე და გამოსახულების Tuist ბოლოს, ასე რომ `tuist` და თქვენი სხვა mise ხელსაწყოები მუშაობენ თქვენს ბრძანებებში და Xcode აწყობის ფაზებში, მაგალითად სქემის post-actions-ში. თითოეულ Mac-ს ასევე აქვს გზამკვლევი კოდირების აგენტებისთვის `/opt/tuist/agent-guide.md`-ზე, გენერირებული მისი გამოსახულებიდან: მისი Xcode და სიმულატორები, სად არის რეპოზიტორია და რას შეიცავს მზად snapshot. Claude Code, Codex და Amp, რომლებიც მუშაობენ Mac-ზე, პოულობენ მას მათი ინსტრუქციის ფაილებიდან.

ყოველი ბრძანება, რომელსაც იწყებთ `tuist sandbox exec`-ით, ასევე იღებს იმას, რასაც Tuist runner იღებს, ასე რომ სენდბოქსში აწყობები იყენებენ თქვენი ანგარიშის <.localized_link href="/guides/features/cache">ქეშს</.localized_link> თქვენი მონაცემების გადაცემის გარეშე:

- `TUIST_URL` და, სადაც სენდბოქსის ჰოსტი აღწევს მას, მაგალითად macOS-ზე, იმავე რაკში არსებული ქეშის `TUIST_CACHE_ENDPOINT`.
- `TUIST_OIDC_TOKEN`, მოკლევადიანი იდენტობის ტოკენი იმ ბრძანებისთვის. Tuist CLI 4.218.0 და ზემოთ ავტომატურად შედის მით; 4.215.0-დან 4.217.x-მდე, ჯერ გაუშვით `tuist auth login` იმავე ბრძანებაში.

ტოკენი იჭედება ყოველი ბრძანებისთვის და შეიძლება გაცვლილ იქნას Tuist ტოკენზე მხოლოდ მაშინ, როდესაც ეს ბრძანება მუშაობს, ასე რომ სენდბოქსი არასდროს ინახავს ხანგრძლივად მოქმედ მონაცემებს. ის არასდროს ანიჭებს იმაზე მეტს, ვიდრე პირს ან ტოკენს, რომელმაც დაიწყო ბრძანება, შეუძლია გააკეთოს ქეშთან: ანგარიშის წევრებს, რომელთა ქეშის ტოკენებს მხოლოდ ჩაწერა შეუძლიათ, ეძლევათ წაკითხვის წვდომა, და ანგარიშის ტოკენს სჭირდება ქეშის სკოპები, მაგალითად `ci`, `account:sandboxes:write`-თან ერთად, რათა სენდბოქსმა საერთოდ გამოიყენოს ქეში. ცვლადები, რომლებსაც გადასცემთ `--env`-ით, აქვთ უპირატესობა.

## აწყობა Mac-ზე კოდირების აგენტიდან {#coding-agents}

კოდირების აგენტი, რომელიც მუშაობს Linux-ზე, მაგალითად ღრუბლოვანი აგენტის სესია, შეუძლია ააწყოს, შეამოწმოს და გაუშვას Apple-პლატფორმის კოდი macOS სენდბოქსზე, სანამ ის აგრძელებს ფაილების რედაქტირებას იქ, სადაც მუშაობს. Amp-ში, დააინსტალირეთ <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინი</.localized_link>. სხვა აგენტებისთვის, მაგალითად Claude Code ან Cursor:

1. დააკავშირეთ აგენტი Tuist <.localized_link href="/guides/features/agentic-coding/mcp">MCP სერვერთან</.localized_link>. მისი `create_sandbox` ხელსაწყო ეუბნება აგენტს, თუ როგორ მართოს Mac.
2. დააინსტალირეთ Tuist CLI იქ, სადაც აგენტი მუშაობს, მაგალითად გარემოს კონფიგურაციის სკრიპტში: `mise use -g tuist@latest`, ან `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist` (`tuist-linux-aarch64` ARM-ზე).
3. მოახდინეთ CLI-ის ავტორიზაცია. MCP სერვერის შესვლა არ გადაეცემა მას, ამიტომ ან გაუშვით `tuist auth login` როგორც ანგარიშის წევრმა, ან დააყენეთ `TUIST_TOKEN` <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენზე</.localized_link> `account:sandboxes:write` სკოპით.
4. თუ გარემო ზღუდავს ქსელურ წვდომას, ნება დართეთ `tuist.dev`. CLI ატვირთავს ფაილებს Mac-ზე მისი მეშვეობით, ამიტომ სხვა დომენი არ სჭირდება.
5. სურვილისამებრ, მიეცით აგენტს Mac-ების შექმნისა და წაშლის უფლება ყოველ ჯერზე კითხვის გარეშე. აგენტები იკითხავენ `create_sandbox`-ის გამოძახებამდე, რადგან Mac ითვლება თქვენი ანგარიშის ლიმიტებში, და `delete_sandbox`-მდე, რადგან მისი გაუქმება შეუძლებელია. Claude Code-ში, ნება დართეთ ორივე `.claude/settings.json`-ში, MCP სერვერის რეგისტრაციის სახელის გამოყენებით (აქ `tuist`):

   ```json
   {
     "permissions": {
       "allow": ["mcp__tuist__create_sandbox", "mcp__tuist__delete_sandbox"]
     }
   }
   ```

იმისთვის, რომ აგენტმა მოახდინოს კონფიგურაცია, მიაწოდეთ ეს პრომპტი:

```text
Set up this environment so you can build and test this project on a Tuist macOS sandbox.

Read https://tuist.dev/en/docs/guides/features/sandboxes#coding-agents and follow its "Build on a Mac from a coding agent" section. It's the current Tuist guide for this, so prefer it over anything you remember about Tuist.

You're done when you have created a Mac with create_sandbox, synced this repository to it with tuist sandbox sync, run the project's build there with tuist sandbox exec, and deleted the Mac.

Ask me before anything that needs my login or approval, such as tuist auth login. If a step fails or is blocked, stop and tell me which step you reached and the exact error, without secrets.
```

აგენტი ქმნის ერთ Mac-ს თითოეული ამოცანისთვის, პროექტის მიერ მიბმული [Xcode](#xcode)-ით: `create_sandbox` ჩამოთვლის ხელმისაწვდომ Xcode-ებს და ეუბნება აგენტს, წაიკითხოს პროექტის მიბმა, მაგალითად `.xcode-version`. ყოველი ბრძანების წინ ის ასრულებს `tuist sandbox sync`. ის აკოპირებს ფაილებს, რომლებსაც Git არ იგნორებს, დაკომიტებული იქნება თუ არა, ხოლო შემდეგ მხოლოდ შეცვლილ ფაილებს. Mac-ს უკვე აქვს [Tuist](#tuist-in-sandbox), პროექტის მიერ მიბმული ვერსია, თუ ასეთი არსებობს, შესული თქვენი ანგარიშის ქეშში, და აგენტი ერთხელ კითხულობს Mac-ის სახელმძღვანელოს. შემდეგ აგენტი ასრულებს ბრძანებებს, როგორიცაა `xcodebuild`, `tuist sandbox exec`-ის მეშვეობით, აკოპირებს შედეგებს, როგორიცაა სქრინშოტები ან აწყობილი აპლიკაცია, უკან `tuist sandbox cp`-ით, და შლის Mac-ს, როცა ამოცანა დასრულდება. Mac რჩება გაშვებული 10 წუთის განმავლობაში ბოლო ბრძანების შემდეგ, რათა შემდეგი დაუყოვნებლივ დაიწყოს; `tuist sandbox pause` აბრუნებს მას უფრო ადრე. მიტოვებული Mac ჯერ ჩერდება, არქივირდება მისი ორსაათიანი სიცოცხლის ციკლის დასრულებისას და იშლება 14 დღის შემდეგ; აგენტი აგრძელებს სიცოცხლის ციკლს ხანგრძლივი აწყობის წინ.

## Linux და macOS {#platforms}

**Linux** სენდბოქსები მუშაობენ Ubuntu 24.04-ზე. ყოველ Linux სენდბოქსს აქვს 16 vCPU და იყენებს მანქანის თავისუფალ ბირთვებს, ამიტომ მისი კონფიგურაცია განსაზღვრავს მეხსიერებას:

- 2 GiB RAM (`--vcpus 1 --memory-gb 2`)
- 4 GiB RAM (`--vcpus 2 --memory-gb 4`, ნაგულისხმევი)
- 8 GiB RAM (`--vcpus 4 --memory-gb 8`)
- 16 GiB RAM (`--vcpus 8 --memory-gb 16`)
- 32 GiB RAM (`--vcpus 16 --memory-gb 32`)
- 44 GiB RAM (`--vcpus 16 --memory-gb 44`)

**macOS** სენდბოქსები მუშაობენ Apple სილიკონზე Xcode-ით:

- 8 vCPU, 8 GiB RAM (ნაგულისხმევი)
- 8 vCPU, 16 GiB RAM
- 8 vCPU, 24 GiB RAM

### გარანტირებული CPU {#guaranteed-cpu}

Linux სენდბოქსს გარანტირებული აქვს vCPU-ის მეოთხედი მეხსიერების ყოველ GiB-ზე, მაგალითად 2 vCPU 8 GiB-ისთვის, და იყენებს დამატებით რესურსებს, რამდენსაც მანქანა თავისუფალს ტოვებს, 16 vCPU-მდე. ეს შეესაბამება აგენტს, რომელიც ძირითადად ელოდება და შემდეგ აწყობს პაკეტურად. როდესაც აწყობას სჭირდება უფრო სტაბილური CPU დატვირთული მანქანის პირობებშიც კი, შეუქმენით გარანტია 1, 2, 4 ან 8 vCPU სენდბოქსის შექმნისას; ის მიიღებს უფრო დიდს ამ რიცხვსა და მეხსიერების გარანტიას შორის:

| სად | როგორ |
| --- | --- |
| CLI | `tuist sandbox create --guaranteed-vcpus 4` |
| API და MCP `create_sandbox` | `"guaranteed_vcpus": 4` |

- **გარანტია არის მინიმუმი, არა მაქსიმუმი.** სენდბოქსი 4 გარანტირებული vCPU-ით მაინც აღწევს 16-ს, როცა ბირთვები თავისუფალია. კონკურენციის პირობებში, ყოველი სენდბოქსი იღებს CPU-ს თავისი გარანტიის პროპორციულად.
- **ბილინგი ხდება მინიმუმის მიხედვით.** მოქმედი სენდბოქსისთვის გადაიხდით გამოყენებული CPU-ისთვის, მაგრამ არასდროს ნაკლებს, ვიდრე მისი გარანტია.
- **სენდბოქსი ინარჩუნებს გარანტიას მთელი სიცოცხლის განმავლობაში.** შესაცვლელად, შექმენით ახალი სენდბოქსი.
- **macOS სენდბოქსებს ყოველთვის აქვთ მთლიანი კონფიგურაცია**, ამიტომ ისინი არ იღებენ გარანტიას.

### აირჩიეთ Xcode {#xcode}

ყოველი macOS სენდბოქსი აწარმოებს ერთ Xcode-ს, რომელსაც თქვენ ირჩევთ შექმნისას. ის იტვირთება იმავე იმიჯით, რაც <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link>-ის პროფილი ამ Xcode-ისთვის, ამიტომ აგენტი აწყობს იმავე ინსტრუმენტებითა და სიმულატორებით, რაც თქვენი CI. tuist.dev-ზე, macOS სენდბოქსები ამჟამად სთავაზობენ:

- `26.6` (ნაგულისხმევი)
- `26.1.1`
- `27.0`
- `27.1`
- `27.2`

აირჩიეთ ერთი `xcode_version`-ით (`--xcode` CLI-ში), ზუსტი ვერსიის გამოყენებით, როგორც ეს რანერის პროფილებშია:

| სად | როგორ |
| --- | --- |
| CLI | `tuist sandbox create --xcode 26.1.1` |
| API და MCP `create_sandbox` | `"xcode_version": "26.1.1"` |
| Tuist Mac პლაგინი Amp-ისთვის | `tuist_mac_start` `xcode`-ით |
| Amp orbs | Orb-ის ტიპი `macos-xcode-26-1-1` (იხილეთ <.localized_link href="/guides/features/sandboxes/amp#xcode">Amp</.localized_link>) |
| Claude Code და Claude Managed Agents | `xcode_version` გარემოში, ან თითოეული Managed Agents სესიისთვის (იხილეთ <.localized_link href="/guides/features/sandboxes/claude#xcode">Claude</.localized_link>) |

- **ვერსიის მითითების გარეშე**, Mac იღებს ნაგულისხმევ ვერსიას.
- **Tuist-ის მიერ შეუთავაზებელი ვერსია უარყოფილი იქნება**, ხოლო შეცდომა ჩამოთვლის ხელმისაწვდომ ვერსიებს, რათა იცოდეთ, რა არის ამჟამად ხელმისაწვდომი.
- **Tuist არ კითხულობს თქვენი რეპოზიტორიის `.xcode-version`-ს.** ვერსიას თქვენ ან აგენტი, რომელიც Mac-ს ითხოვს, ირჩევთ. MCP ინსტრუმენტი და Tuist Mac პლაგინი აგენტებს ეუბნებიან, რომ დაემთხვეს პროექტის მიერ მიმაგრებულ ვერსიას.
- **სენდბოქსი ინარჩუნებს თავის Xcode-ს მთელი სიცოცხლის განმავლობაში.** სხვა Xcode-ით ასაწყობად, შექმენით ახალი სენდბოქსი. `xcodebuild -version` აჩვენებს, თუ რომელ Xcode-ს აწარმოებს Mac.

## უსაფრთხოება {#security}

- ყოველი სენდბოქსი არის დამოუკიდებელი ვირტუალური მანქანა. სენდბოქსები ერთმანეთთან ან CI დავალებებთან არ იზიარებენ ფაილურ სისტემას, მეხსიერებას ან პროცესებს.
- სენდბოქსები ეკუთვნის ანგარიშს და მისი ნებისმიერი წევრი შეუძლია მათი გამოყენება და მართვა. სენდბოქსები, რომლებიც ემსახურებიან ინტეგრაციას, მაგალითად Amp orb-ს ან Claude Code სესიას, ინახავენ ამ სესიის სამუშაოს და სერთიფიკატებს: წევრებს შეუძლიათ მათი ნახვა, შეჩერება, აღდგენა, არქივირება და წაშლა, მაგრამ მათში ბრძანებების გაშვება ან ფაილების ატვირთვა მხოლოდ ადმინისტრატორებს შეუძლიათ. ინტეგრაციებს მხოლოდ ადმინისტრატორები აკავშირებენ. ინტეგრაციიდან წამოსული სესიები მხოლოდ იმ ანგარიშის სენდბოქსებს აღწევენ, რომელთანაც ინტეგრაციაა დაკავშირებული.
- სერთიფიკატები, რომლებსაც Tuist-ს აწვდით ინტეგრაციის დასაკავშირებლად, მაგალითად Amp პროვაიდერის ტოკენი ან Claude გარემოს გასაღები, ინახება დაშიფრული სახით და აღარასდროს ჩანს.
- სენდბოქსს შეუძლია ინტერნეტთან წვდომა. მოეპყარით იმას, რასაც აგენტი მისგან წვდება ისე, როგორც CI დავალებას.
