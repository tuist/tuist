# სენდბოქსები {#sandboxes}

> [!IMPORTANT]
> **მხოლოდ მოწვევით**
>
> Tuist სენდბოქსები, როგორც Linux-ზე, ისე macOS-ზე, ამჟამად მხოლოდ მოწვევითაა ხელმისაწვდომი, სანამ ტევადობას გავზრდით. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [საზოგადოების Slack-ში](https://slack.tuist.dev), რათა თქვენს ანგარიშზე წვდომა მოითხოვოთ. ფასები გამოცხადდება, როდესაც სენდბოქსები ზოგად ხელმისაწვდომობას მიიღებენ.

სენდბოქსი არის ვირტუალური მანქანა, სადაც კოდირების აგენტი ასრულებს ბრძანებებს და არედაქტირებს ფაილებს. თითოეულ აგენტის სესიას ენიჭება საკუთარი სენდბოქსი, რომელიც ინახავს მის ჩეკაუთს, ბილდის პროდუქტებს და დაინსტალირებულ ინსტრუმენტებს სესიის განმავლობაში. როდესაც აგენტი უმოქმედო ხდება, სენდბოქსი იყურება; შემდეგი შეტყობინება აღადგენს მას იქიდან, სადაც გაჩერდა.

სენდბოქსები მუშაობენ იმავე ფლოტზე, რაზეც <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link>, თქვენი გუნდის <.localized_link href="/guides/features/cache">ქეშის</.localized_link> გვერდით, რათა აგენტის ბილდებმა შეძლონ იმავე ქეშირებული არტეფაქტების გამოყენება, რასაც თქვენი CI და ადგილობრივი მანქანები იყენებენ.

სენდბოქსების გამოყენება შეგიძლიათ შემდეგიდან:

- **<.localized_link href="/guides/features/sandboxes/amp">Amp</.localized_link>**: გაუშვით თქვენი Amp სამუშაო სივრცის ორბები Tuist-ზე, ან მიანიჭეთ ნებისმიერ Amp ნაკადს Mac Xcode ბილდებისთვის <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინის</.localized_link> მეშვეობით.
- **<.localized_link href="/guides/features/sandboxes/claude">Claude</.localized_link>**: გაუშვით Claude Managed Agents სესიები და Claude Code ღრუბლოვანი სესიები (claude.ai, დესკტოპისა და მობილური აპლიკაციები და `claude --cloud`) Tuist-ზე.
- **[Tuist CLI](#cli)**: შექმენით სენდბოქსები და გაუშვით მათში ბრძანებები თქვენი ტერმინალიდან, ან თქვენი საკუთარი ინსტრუმენტებიდან API-ს მეშვეობით.

## დაიწყეთ CLI-ით {#cli}

შექმენით სენდბოქსი და გაუშვით მასში ბრძანებები თქვენი ტერმინალიდან `tuist sandbox`-ის მეშვეობით.

### 1. შესვლა {#cli-log-in}

სენდბოქსების მართვა მოითხოვს ანგარიშის ადმინისტრატორს:

```bash
tuist auth login
```

### 2. სენდბოქსის შექმნა {#cli-create}

```bash
tuist sandbox create --platform macos
```

Linux-ისთვის გამოტოვეთ `--platform`. გადაეცით `--xcode` ვერსიით, მაგალითად `--xcode 26.1.1`, Mac-ისთვის იმ [Xcode](#xcode)-ით; ეს გულისხმობს `--platform macos`-ს. გადაეცით `--vcpus` `--memory-gb`-თან ერთად უფრო დიდი [კონფიგურაციისთვის](#platforms), და `--workspace-gb` უფრო დიდი დისკისთვის. ბრძანება ბრუნდება, როდესაც სენდბოქსი გაშვებულია და ბეჭდავს მის დეტალებს, მათ შორის ID-ს. ის იყენებს მიმდინარე დირექტორიაში არსებული Tuist პროექტის ანგარიშს; გადაეცით `--account` სხვის არჩევას.

### 3. ბრძანებების გაშვება {#cli-exec}

```bash
tuist sandbox exec <sandbox-id> -- xcodebuild -version
```

ბრძანება სრულდება `bash -l`-ით სენდბოქსში, რომელიც ჯერ აღდგება, თუ ის შეჩერებულია. `tuist` აწვდის მის გამონატანს, რამდენი ხანიც არ უნდა გაგრძელდეს და სრულდება ბრძანების სტატუსით; Ctrl-C აუქმებს მას სენდბოქსში. გადაეცით `--cwd`, `--env NAME=VALUE` და `--timeout` (ექვს საათამდე) საჭიროებისამებრ.

### ჩვეულებრივი ამოცანები {#cli-tasks}

| ამოცანა | ბრძანება |
| --- | --- |
| სენდბოქსების ჩამონათვალი | `tuist sandbox list` |
| ერთის ჩვენება | `tuist sandbox show <id>` |
| შეჩერება ან აღდგენა | `tuist sandbox pause <id>`, `tuist sandbox resume <id>` |
| ადგილობრივი Git worktree-ის ფაილების ასახვა მასში | `tuist sandbox sync <id>` |
| ფაილების კოპირება გარეთ ან შიგნით | `tuist sandbox cp <id>:<path> <local-path>`, `tuist sandbox cp <local-path> <id>:<path>` |
| წაშლა | `tuist sandbox delete <id> --yes` |
| გამოყენების ნახვა | `tuist sandbox analytics` |

დაამატეთ `--json` მანქანისთვის წასაკითხი გამონატანისთვის. ყველა პარამეტრისთვის იხილეთ <.localized_link href="/cli/sandbox">CLI-ის ცნობარი</.localized_link>. სენდბოქსების კოდიდან მართვისთვის, გამოიყენეთ იგივე ოპერაციები [Tuist API](https://tuist.dev/api/docs)-ს მეშვეობით `/api/accounts/{account_handle}/sandboxes`-ის ქვეშ, ან მიეცით აგენტს მათი გამოყენების საშუალება <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>-ის მეშვეობით.

ინსტრუმენტებს, რომლებსაც ინტერაქტიული შესვლა არ შეუძლიათ, მაგალითად აგენტის პლაგინს, რომელიც macOS სენდბოქსში აწყობს, შეუძლია ავთენტიკაცია <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენით</.localized_link> `account:sandboxes:write` სკოუპით. მას შეუძლია შექმნას სენდბოქსები, გაუშვას მათში ბრძანებები, შეაჩეროს, აღადგინოს და წაშალოს ისინი, როგორც ანგარიშის წევრს. სენდბოქსები, რომლებიც Amp ან Claude ინტეგრაციას ემსახურებიან, ანალიტიკა და ინტეგრაციის პარამეტრები რჩება ანგარიშის ადმინისტრატორებთან.

### Tuist სენდბოქსის შიგნით {#tuist-in-sandbox}

სენდბოქსის გამოსახულებები არ შეიცავენ Tuist CLI-ს, ამიტომ მუშაობს თქვენი პროექტის მიერ მიმაგრებული ვერსია. პირველი `tuist sandbox sync`-ის შემდეგ, გაუშვით `mise install` რეპოზიტორიის ფესვში სენდბოქსზე (`mise` და `brew` დაინსტალირებულია), შემდეგ გაუშვით `tuist` mise-ის მეშვეობით, მაგალითად `$HOME/.local/share/mise/shims`-ით `PATH`-ზე.

ყოველი ბრძანება, რომელსაც `tuist sandbox exec`-ით იწყებთ, ასევე იღებს იმას, რასაც Tuist runner იღებს, ამიტომ სენდბოქსში ბილდები იყენებენ თქვენი ანგარიშის <.localized_link href="/guides/features/cache">ქეშს</.localized_link> თქვენს მიერ რწმუნებების გადაცემის გარეშე:

- `TUIST_URL` და, სადაც სენდბოქსის ჰოსტი მას წვდება, მაგალითად macOS-ზე, იმავე რაკში არსებული ქეშის `TUIST_CACHE_ENDPOINT`.
- `TUIST_OIDC_TOKEN`, მოკლე ვადიანი იდენტობის ტოკენი იმ ბრძანებისთვის. Tuist CLI 4.218.0 და უფრო ახალი ვერსიები თავად შედიან მისით; 4.215.0-დან 4.217.x-მდე, ჯერ გაუშვით `tuist auth login` იმავე ბრძანებაში.

ტოკენი იქმნება ყოველი ბრძანებისთვის და შეიძლება გაცვლილ იქნას Tuist ტოკენზე მხოლოდ მაშინ, როდესაც ეს ბრძანება მუშაობს, ამიტომ სენდბოქსი არასდროს ინახავს ხანგრძლივი ვადის რწმუნებას. ის არასდროს ანიჭებს იმაზე მეტს, ვიდრე ბრძანების დამწყებ პირს ან ტოკენს შეუძლია ქეშთან: ანგარიშის წევრებს, რომელთა ქეშის ტოკენებს მხოლოდ ჩაწერა შეუძლიათ, ენიჭებათ წაკითხვის წვდომა, და ანგარიშის ტოკენს სჭირდება ქეშის სკოუპები, მაგალითად `ci`, `account:sandboxes:write`-თან ერთად, რათა სენდბოქსმა საერთოდ გამოიყენოს ქეში. ცვლადები, რომლებსაც `--env`-ით გადასცემთ, აქვთ უპირატესობა.

## აწყობა Mac-ზე კოდირების აგენტიდან {#coding-agents}

კოდირების აგენტი, რომელიც მუშაობს Linux-ზე, მაგალითად ღრუბლოვანი აგენტის სესია, შეუძლია ააწყოს, შეამოწმოს და გაუშვას Apple-პლატფორმის კოდი macOS სენდბოქსზე, სანამ ის აგრძელებს ფაილების რედაქტირებას იქ, სადაც მუშაობს. Amp-ში, დააინსტალირეთ <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინი</.localized_link>. სხვა აგენტებისთვის, მაგალითად Claude Code ან Cursor:

1. დააკავშირეთ აგენტი Tuist <.localized_link href="/guides/features/agentic-coding/mcp">MCP სერვერთან</.localized_link>. მისი `create_sandbox` ინსტრუმენტი ეუბნება აგენტს, თუ როგორ უმართოს Mac-ს.
2. დააინსტალირეთ Tuist CLI იქ, სადაც აგენტი მუშაობს, მაგალითად გარემოს setup სკრიპტში: `mise use -g tuist@latest`, ან `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist` (`tuist-linux-aarch64` ARM-ზე).
3. მოახდინეთ CLI-ის ავთენტიკაცია. MCP სერვერის შესვლა არ გადაეცემა მას, ამიტომ ან გაუშვით `tuist auth login` როგორც ანგარიშის წევრმა, ან დააყენეთ `TUIST_TOKEN` <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენზე</.localized_link> `account:sandboxes:write` სკოუპით.
4. თუ გარემო ზღუდავს ქსელურ წვდომას, დაუშვით `tuist.dev`. CLI ამ საშუალებით ატვირთავს ფაილებს Mac-ზე, ამიტომ სხვა დომენი არ სჭირდება.

აგენტი თითოეული ამოცანისთვის ქმნის ერთ Mac-ს, პროექტის მიერ მინიშნებული [Xcode](#xcode)-ით: `create_sandbox` ჩამოთვლის ხელმისაწვდომ Xcode-ებს და ეუბნება აგენტს, წაიკითხოს პროექტის მინიშნება, მაგალითად `.xcode-version`. ყოველი ბრძანების შესრულებამდე ის ასრულებს `tuist sandbox sync`-ს. ის აკოპირებს ფაილებს, რომლებსაც Git არ იგნორირებს (მიუხედავად იმისა, არის თუ არა ისინი კომიტებული), ხოლო შემდეგ მხოლოდ შეცვლილ ფაილებს. პირველი სინქრონიზაციის შემდეგ ის ასრულებს `mise install`-ს Mac-ზე რეპოზიტორიის ძირში, რათა [პროექტის მიერ მინიშნებული Tuist](#tuist-in-sandbox) იყოს იქ და ავტორიზებული იყოს თქვენი ანგარიშის ქეშთან. შემდეგ აგენტი ასრულებს ბრძანებებს, როგორიცაა `xcodebuild`, `tuist sandbox exec`-ის საშუალებით, აკოპირებს შედეგებს, როგორიცაა სკრინშოტები ან აწყობილი აპლიკაცია, უკან `tuist sandbox cp`-ის საშუალებით და შლის Mac-ს, როცა ამოცანა დასრულდება. Mac რჩება გაშვებული ბოლო ბრძანების შემდეგ 10 წუთის განმავლობაში, რათა შემდეგი დაუყოვნებლივ დაიწყოს; `tuist sandbox pause` უფრო ადრე აბრუნებს მას. მიტოვებული Mac შეჩერდება და წაიშლება 14 დღის შეჩერების შემდეგ.

## Linux და macOS {#platforms}

**Linux** სენდბოქსები მუშაობენ Ubuntu 24.04-ზე:

- 2 vCPU, 4 GiB RAM (ნაგულისხმევი)
- 4 vCPU, 8 GiB RAM
- 8 vCPU, 16 GiB RAM

**macOS** სენდბოქსები მუშაობენ Apple silicon-ზე Xcode-ით:

- 8 vCPU, 8 GiB RAM (ნაგულისხმევი)
- 8 vCPU, 16 GiB RAM
- 8 vCPU, 24 GiB RAM

### Xcode-ის არჩევა {#xcode}

ყოველი macOS სენდბოქსი აწარმოებს ერთ Xcode-ს, რომელსაც თქვენ ირჩევთ მისი შექმნისას. ის ტვირთავს იმავე იმიჯს, რასაც <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link>-ის პროფილი ამ Xcode-ისთვის, ამიტომ აგენტი აწყობს იმავე ინსტრუმენტებითა და სიმულატორებით, რასაც თქვენი CI. tuist.dev-ზე macOS სენდბოქსები ამჟამად გთავაზობთ:

- `26.6` (ნაგულისხმევი)
- `26.1.1`
- `27.0`
- `27.1`
- `27.2`

აირჩიეთ ერთ-ერთი `xcode_version`-ით (`--xcode` CLI-ში), ზუსტი ვერსიის გამოყენებით, როგორც ეს runner-ების პროფილებში ხდება:

| სად | როგორ |
| --- | --- |
| CLI | `tuist sandbox create --xcode 26.1.1` |
| API და MCP `create_sandbox` | `"xcode_version": "26.1.1"` |
| Tuist Mac პლაგინი Amp-ისთვის | `tuist_mac_start` `xcode`-ით |
| Amp orbs | Orb-ის ტიპი `macos-xcode-26-1-1` (იხილეთ <.localized_link href="/guides/features/sandboxes/amp#xcode">Amp</.localized_link>) |
| Claude Code და Claude Managed Agents | `xcode_version` გარემოზე, ან Managed Agents-ის სესიის მიხედვით (იხილეთ <.localized_link href="/guides/features/sandboxes/claude#xcode">Claude</.localized_link>) |

- **ვერსიის მითითების გარეშე**, Mac იღებს ნაგულისხმევს.
- **Tuist-ის მიერ შეუთავაზებელი ვერსია უარყოფილი იქნება**, და შეცდომა ჩამოთვლის ხელმისაწვდომ ვერსიებს, რათა იცოდეთ, რა არის ხელმისაწვდომი ამჟამად.
- **Tuist არ კითხულობს თქვენი რეპოზიტორიის `.xcode-version`-ს.** თქვენ, ან აგენტი, რომელიც ითხოვს Mac-ს, ირჩევთ ვერსიას. MCP ინსტრუმენტი და Tuist Mac პლაგინი ეუბნებიან აგენტებს, შეუსაბამონ პროექტის მიერ მინიშნებული ვერსია.
- **სენდბოქსი ინარჩუნებს თავის Xcode-ს მთელი სიცოცხლის განმავლობაში.** სხვა Xcode-ით აწყობისთვის, შექმენით ახალი სენდბოქსი. `xcodebuild -version` აჩვენებს, თუ რომელ Xcode-ს აწარმოებს Mac.

## უსაფრთხოება {#security}

- ყოველი სენდბოქსი არის ცალკეული ვირტუალური მანქანა. სენდბოქსები არ იზიარებენ ფაილურ სისტემას, მეხსიერებას ან პროცესებს ერთმანეთთან ან CI სამუშაოებთან.
- სენდბოქსები ეკუთვნის ანგარიშს და მხოლოდ მის ადმინისტრატორებს შეუძლიათ მათი მართვა. ინტეგრაციიდან მომავალი სესიები მხოლოდ იმ ანგარიშის სენდბოქსებს აღწევენ, რომელთანაც ინტეგრაციაა დაკავშირებული.
- მონაცემები, რომლებსაც თქვენ აწვდით Tuist-ს ინტეგრაციის დასაკავშირებლად, როგორიცაა Amp პროვაიდერის ტოკენი ან Claude გარემოს გასაღები, ინახება დაშიფრული და აღარასდროს ჩანს.
- სენდბოქსს შეუძლია ინტერნეტთან წვდომა. მოეპყარით იმას, რასაც აგენტი მისგან წვდება, ისე, როგორც მოეპყრებოდით CI სამუშაოს.
