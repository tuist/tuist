# სენდბოქსები {#sandboxes}

> [!IMPORTANT]
> **მხოლოდ მოწვევით**
>
> Tuist-ის სენდბოქსები, როგორც Linux-ზე, ისე macOS-ზე, ამჟამად მხოლოდ მოწვევითაა ხელმისაწვდომი, სანამ ტევადობას გავზრდით. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [საზოგადოების Slack-ში](https://slack.tuist.dev), რათა თქვენი ანგარიშისთვის წვდომა მოითხოვოთ. ფასები გამოცხადდება, როდესაც სენდბოქსები ზოგად ხელმისაწვდომობას მიიღებენ.

სენდბოქსი არის ვირტუალური მანქანა, სადაც კოდირების აგენტი ასრულებს ბრძანებებს და არედაქტირებს ფაილებს. აგენტის თითოეულ სესიას ეკუთვნის საკუთარი სენდბოქსი, რომელიც ინახავს ჩეკაუტს, ბილდის პროდუქტებს და დაყენებულ ხელსაწყოებს სესიის განმავლობაში. როდესაც აგენტი უმოქმედო ხდება, სენდბოქსი ჩერდება; შემდეგი შეტყობინება აღადგენს მას იქიდან, სადაც გაჩერდა.

სენდბოქსები მუშაობენ იმავე ინფრასტრუქტურაზე, რაზეც <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link>, თქვენი გუნდის <.localized_link href="/guides/features/cache">ქეშის</.localized_link> გვერდით, რათა აგენტის ბილდებმა შეძლონ იმავე ქეშირებული არტეფაქტების გამოყენება, რასაც თქვენი CI და ლოკალური მანქანები იყენებენ.

სენდბოქსების გამოყენება შესაძლებელია:

- **<.localized_link href="/guides/features/sandboxes/amp">Amp</.localized_link>**: გაუშვით თქვენი Amp სამუშაო სივრცის ორბები Tuist-ზე, ან მიანიჭეთ ნებისმიერ Amp ძაფს Mac Xcode ბილდებისთვის <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინის</.localized_link> მეშვეობით.
- **<.localized_link href="/guides/features/sandboxes/claude">Claude</.localized_link>**: გაუშვით Claude Managed Agents სესიები და Claude Code cloud სესიები (claude.ai, დესკტოპ და მობილური აპლიკაციები, და `claude --cloud`) Tuist-ზე.
- **[Tuist CLI](#cli)**: შექმენით სენდბოქსები და გაუშვით ბრძანებები მათში თქვენი ტერმინალიდან, ან თქვენი საკუთარი ხელსაწყოებიდან API-ს მეშვეობით.

## CLI-ს გამოყენების დაწყება {#cli}

შექმენით სენდბოქსი და გაუშვით ბრძანებები მასში თქვენი ტერმინალიდან `tuist sandbox`-ის მეშვეობით.

### 1. შესვლა {#cli-log-in}

ანგარიშის ნებისმიერ წევრს შეუძლია შექმნას და მართოს მისი სენდბოქსები:

```bash
tuist auth login
```

### 2. სენდბოქსის შექმნა {#cli-create}

```bash
tuist sandbox create --platform macos
```

Linux-ისთვის გამოტოვეთ `--platform`. გადაეცით `--xcode` ვერსიით, მაგალითად `--xcode 26.1.1`, Mac-ისთვის იმ [Xcode](#xcode)-ით; ეს გულისხმობს `--platform macos`-ს. გადაეცით `--vcpus` `--memory-gb`-თან ერთად უფრო დიდი [კონფიგურაციისთვის](#platforms), `--guaranteed-vcpus` Linux სენდბოქსისთვის მეტი [CPU](#guaranteed-cpu)-ს გარანტიისთვის, და `--workspace-gb` უფრო დიდი დისკისთვის. ბრძანება ბრუნდება, როდესაც სენდბოქსი გაშვებულია და ბეჭდავს მის დეტალებს, მათ შორის ID-ს. ის იყენებს მიმდინარე დირექტორიაში არსებული Tuist პროექტის ანგარიშს; გადაეცით `--account` სხვის არჩევას.

### 3. ბრძანებების გაშვება {#cli-exec}

```bash
tuist sandbox exec <sandbox-id> -- xcodebuild -version
```

ბრძანება სრულდება `bash -l`-ით სენდბოქსში, რომელიც ჯერ აღდგება, თუ შეჩერებულია. `tuist` ატარებს მის გამონატანს მთელი გაშვების განმავლობაში და გადის ბრძანების სტატუსით; Ctrl-C აუქმებს მას სენდბოქსში. გადაეცით `--cwd`, `--env NAME=VALUE` და `--timeout` (ექვს საათამდე) საჭიროების შემთხვევაში.

### ჩვეულებრივი ამოცანები {#cli-tasks}

| ამოცანა | ბრძანება |
| --- | --- |
| სენდბოქსების ჩამონათვალი | `tuist sandbox list` |
| ერთის ჩვენება | `tuist sandbox show <id>` |
| შეჩერება ან აღდგენა | `tuist sandbox pause <id>`, `tuist sandbox resume <id>` |
| ლოკალური Git worktree-ის ფაილების ასახვა მასში | `tuist sandbox sync <id>` |
| ფაილების კოპირება გარეთ ან შიგნით | `tuist sandbox cp <id>:<path> <local-path>`, `tuist sandbox cp <local-path> <id>:<path>` |
| წაშლა | `tuist sandbox delete <id> --yes` |
| გამოყენების ნახვა | `tuist sandbox analytics` |

დაამატეთ `--json` მანქანისთვის წასაკითხი გამონატანისთვის. ყველა პარამეტრისთვის იხილეთ <.localized_link href="/cli/sandbox">CLI-ს ცნობარი</.localized_link>. სენდბოქსების კოდიდან მართვისთვის, გამოიყენეთ იგივე ოპერაციები [Tuist API](https://tuist.dev/api/docs)-ს მეშვეობით `/api/accounts/{account_handle}/sandboxes`-ის ქვეშ, ან მიეცით აგენტს მათი გამოყენება <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>-ის მეშვეობით.

ხელსაწყოები, რომლებსაც ინტერაქტიული შესვლა არ შეუძლიათ, მაგალითად აგენტის პლაგინი, რომელიც ბილდს macOS სენდბოქსში, შეუძლიათ ავთენტიკაცია <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენით</.localized_link> `account:sandboxes:write` სკოუპით. მას შეუძლია გააკეთოს ის, რაც ანგარიშის წევრს: შექმნას სენდბოქსები, გაუშვას მათში ბრძანებები, და შეაჩეროს, აღადგინოს, დაარქივოს და წაშალოს ისინი. ინტეგრაციის პარამეტრები რჩება ანგარიშის ადმინისტრატორებთან.

### Tuist სენდბოქსის შიგნით {#tuist-in-sandbox}

სენდბოქსის იმიჯები არ შეიცავენ Tuist CLI-ს, ამიტომ თქვენი პროექტის მიერ მიმაგრებული ვერსია არის ის, რომელიც გაეშვება. პირველი `tuist sandbox sync`-ის შემდეგ, გაუშვით `mise install` რეპოზიტორიის ფესვში სენდბოქსზე (`mise` და `brew` დაყენებულია). ყოველი ბრძანება, რომელსაც `tuist sandbox exec`-ით იწყებთ, აქვს mise-ის shims (`$HOME/.local/share/mise/shims`) პირველად `PATH`-ზე, ამიტომ `tuist` და სხვა mise ხელსაწყოები სრულდება თქვენს ბრძანებებში და Xcode ბილდის ფაზებში, მაგალითად სქემის post-actions-ში.

ყოველი ბრძანება, რომელსაც `tuist sandbox exec`-ით იწყებთ, ასევე იღებს იმას, რასაც Tuist runner იღებს, ამიტომ სენდბოქსში ბილდები იყენებენ თქვენი ანგარიშის <.localized_link href="/guides/features/cache">ქეშს</.localized_link> თქვენს მიერ რწმუნებების გადაცემის გარეშე:

- `TUIST_URL` და, სადაც სენდბოქსის ჰოსტი აღწევს მას, მაგალითად macOS-ზე, `TUIST_CACHE_ENDPOINT` იმავე რეკში არსებული ქეშის.
- `TUIST_OIDC_TOKEN`, მოკლე ვადიანი იდენტობის ტოკენი იმ ბრძანებისთვის. Tuist CLI 4.218.0 და უფრო ახალი ვერსიები თავად შედიან მისით; 4.215.0-დან 4.217.x-მდე, ჯერ გაუშვით `tuist auth login` იმავე ბრძანებაში.

ტოკენი იჭედება ყოველი ბრძანებისთვის და შეიძლება გაცვლილ იქნას Tuist ტოკენზე მხოლოდ იმ ბრძანების გაშვებისას, ამიტომ სენდბოქსი არასდროს ინახავს ხანგრძლივი ვადის რწმუნებას. ის არასდროს ანიჭებს უფრო მეტს, ვიდრე პირს ან ტოკენს, რომელმაც ბრძანება დაიწყო, შეუძლია გააკეთოს ქეშთან: ანგარიშის წევრები, რომელთა ქეშის ტოკენებს მხოლოდ ჩაწერა შეუძლიათ, იღებენ წაკითხვის წვდომას, და ანგარიშის ტოკენს სჭირდება ქეშის სკოუპები, მაგალითად `ci`, `account:sandboxes:write`-თან ერთად, რათა სენდბოქსმა საერთოდ გამოიყენოს ქეში. ცვლადები, რომლებსაც `--env`-ით გადასცემთ, აქვთ უპირატესობა.

## Mac-ზე ბილდი კოდირების აგენტიდან {#coding-agents}

კოდირების აგენტი, რომელიც მუშაობს Linux-ზე, მაგალითად cloud აგენტის სესია, შეუძლია ააშენოს, შეამოწმოს და გაუშვას Apple პლატფორმის კოდი macOS სენდბოქსზე, სანამ ის აგრძელებს ფაილების რედაქტირებას იქ, სადაც მუშაობს. Amp-ში, დააყენეთ <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინი</.localized_link>. სხვა აგენტებისთვის, მაგალითად Claude Code ან Cursor:

1. დააკავშირეთ აგენტი Tuist <.localized_link href="/guides/features/agentic-coding/mcp">MCP სერვერთან</.localized_link>. მისი `create_sandbox` ხელსაწყო ეუბნება აგენტს, თუ როგორ მართოს Mac.
2. დააყენეთ Tuist CLI იქ, სადაც აგენტი მუშაობს, მაგალითად გარემოს setup სკრიპტში: `mise use -g tuist@latest`, ან `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist` (`tuist-linux-aarch64` ARM-ზე).
3. აავთენტიკეთ CLI. MCP სერვერის შესვლა არ გადაეცემა მას, ამიტომ ან გაუშვით `tuist auth login` ანგარიშის წევრად, ან დააყენეთ `TUIST_TOKEN` <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენზე</.localized_link> `account:sandboxes:write` სკოუპით.
4. თუ გარემო ზღუდავს ქსელურ წვდომას, დაუშვით `tuist.dev`. CLI ატვირთავს ფაილებს Mac-ზე მისი საშუალებით, ამიტომ სხვა დომენი არ სჭირდება.

აგენტი ქმნის ერთ Mac-ს თითოეული ამოცანისთვის, პროექტის მიერ მიმაგრებული [Xcode](#xcode)-ით: `create_sandbox` ჩამოთვლის Xcode-ების ვერსიებს, რომელთა შორისაც შეუძლია არჩევანი და ეუბნება აგენტს, წაიკითხოს პროექტის მიმაგრება, მაგალითად `.xcode-version`. ყოველი ბრძანების შესრულებამდე ის ასრულებს `tuist sandbox sync`. ის აკოპირებს ფაილებს, რომლებსაც Git არ იგნორირებს (მიუხედავად იმისა, არიან თუ არა ისინი კომიტში), ხოლო შემდეგ მხოლოდ შეცვლილ ფაილებს. პირველი სინქრონიზაციის შემდეგ ის ასრულებს `mise install` რეპოზიტორიის root-ში Mac-ზე, რათა [პროექტის მიერ მიმაგრებული Tuist](#tuist-in-sandbox) იყოს ხელმისაწვდომი და ავთენტიკირებული თქვენი ანგარიშის cache-ში. შემდეგ აგენტი ასრულებს ისეთ ბრძანებებს, როგორიცაა `xcodebuild`, `tuist sandbox exec`-ის საშუალებით, აკოპირებს შედეგებს, მაგალითად სკრინშოტებს ან აწყობილ აპლიკაციას უკან `tuist sandbox cp`-ის საშუალებით და შლის Mac-ს, როდესაც ამოცანა დასრულდება. Mac მუშაობას აგრძელებს ბოლო ბრძანებიდან 10 წუთის განმავლობაში, რათა შემდეგი დაუყოვნებლივ დაიწყოს; `tuist sandbox pause` უფრო ადრე აბრუნებს რესურსს. დატოვებული Mac გადადის pause-რეჟიმში და იშლება 14 დღის pause-ში ყოფნის შემდეგ.

## Linux და macOS {#platforms}

**Linux** სენდბოქსები მუშაობენ Ubuntu 24.04-ზე. ყოველ Linux სენდბოქსს აქვს 16 vCPU და იყენებს მასზე მუშაობისას თავისუფალ ბირთვებს, ამიტომ მისი კონფიგურაცია განსაზღვრავს მეხსიერებას:

- 2 GiB RAM (`--vcpus 1 --memory-gb 2`)
- 4 GiB RAM (`--vcpus 2 --memory-gb 4`, ნაგულისხმევი)
- 8 GiB RAM (`--vcpus 4 --memory-gb 8`)
- 16 GiB RAM (`--vcpus 8 --memory-gb 16`)
- 32 GiB RAM (`--vcpus 16 --memory-gb 32`)
- 44 GiB RAM (`--vcpus 16 --memory-gb 44`)

**macOS** სენდბოქსები მუშაობენ Apple silicon-ზე Xcode-ით:

- 8 vCPU, 8 GiB RAM (ნაგულისხმევი)
- 8 vCPU, 16 GiB RAM
- 8 vCPU, 24 GiB RAM

### გარანტირებული CPU {#guaranteed-cpu}

Linux სენდბოქსს გარანტირებული აქვს vCPU-ის მეოთხედი მეხსიერების თითოეულ GiB-ზე, მაგალითად 2 vCPU 8 GiB-ისთვის, და იყენებს დამატებით რესურსებს, რამდენსაც მისი მანქანა თავისუფალს ტოვებს, 16 vCPU-მდე. ეს შეესაბამება აგენტის მუშაობის სტილს, რომელიც ძირითადად ელოდება და შემდეგ ასრულებს ბილდებს მოკლე დროში. როდესაც ბილდს სჭირდება უფრო სტაბილური CPU მაშინაც კი, როცა მანქანა დატვირთულია, შექმნისას დაუნიშნეთ მას 1, 2, 4 ან 8 გარანტირებული vCPU; ის მიიღებს უფრო დიდ მნიშვნელობას ამ რიცხვსა და მეხსიერების გარანტიას შორის:

| სად | როგორ |
| --- | --- |
| CLI | `tuist sandbox create --guaranteed-vcpus 4` |
| API და MCP `create_sandbox` | `"guaranteed_vcpus": 4` |

- **გარანტია არის მინიმუმი, არა ზღვარი.** სენდბოქსს, რომელსაც აქვს 4 გარანტირებული vCPU, მაინც შეუძლია გაზრდა 16-მდე, როცა ბირთვები თავისუფალია. კონკურენციის პირობებში, თითოეული სენდბოქსი იღებს CPU-ს თავისი გარანტიის პროპორციულად.
- **გადასახადი ირიცხება მინიმუმის მიხედვით.** მომუშავე სენდბოქსისთვის გადასახადი ირიცხება გამოყენებული CPU-ს მიხედვით, მაგრამ არასდროს ნაკლები, ვიდრე მისი გარანტია.
- **სენდბოქსი ინარჩუნებს თავის გარანტიას სიცოცხლის ბოლომდე.** მის შესაცვლელად, შექმენით ახალი სენდბოქსი.
- **macOS სენდბოქსებს ყოველთვის აქვთ მთლიანი კონფიგურაცია**, ამიტომ ისინი არ იღებენ ცალკე გარანტიას.

### აირჩიეთ Xcode {#xcode}

ყოველი macOS სენდბოქსი მუშაობს ერთი Xcode-ით, რომელსაც თქვენ ირჩევთ შექმნისას. ის იტვირთება იმავე იმიჯით, რაც <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link>-ის პროფილი იმ Xcode-ისთვის, ამიტომ აგენტი აშენებს იმავე toolchain-ით და სიმულატორებით, რაც თქვენი CI. tuist.dev-ზე, macOS სენდბოქსები ამჟამად გვთავაზობენ:

- `26.6` (ნაგულისხმევი)
- `26.1.1`
- `27.0`
- `27.1`
- `27.2`

აირჩიეთ ერთ-ერთი `xcode_version`-ით (`--xcode` CLI-ში), ზუსტი ვერსიის მითითებით, როგორც ეს runner პროფილებშია:

| სად | როგორ |
| --- | --- |
| CLI | `tuist sandbox create --xcode 26.1.1` |
| API და MCP `create_sandbox` | `"xcode_version": "26.1.1"` |
| Tuist Mac პლაგინი Amp-ისთვის | `tuist_mac_start` `xcode`-ით |
| Amp orbs | orb-ის ტიპი `macos-xcode-26-1-1` (იხილეთ <.localized_link href="/guides/features/sandboxes/amp#xcode">Amp</.localized_link>) |
| Claude Code და Claude Managed Agents | `xcode_version` გარემოში, ან თითოეული Managed Agents სესიისთვის (იხილეთ <.localized_link href="/guides/features/sandboxes/claude#xcode">Claude</.localized_link>) |

- **ვერსიის მითითების გარეშე**, Mac იღებს ნაგულისხმევს.
- **Tuist-ის მიერ შეუთავაზებელი ვერსია უარყოფილი იქნება**, და შეცდომა ჩამოთვლის ვერსიებს, რომელთა შორისაც შეგიძლიათ არჩევანი, რათა იცოდეთ, რაა ხელმისაწვდომი ამჟამად.
- **Tuist არ კითხულობს თქვენი რეპოზიტორიის `.xcode-version`-ს.** ვერსიას ირჩევთ თქვენ, ან აგენტი, რომელიც Mac-ს ითხოვს. MCP ინსტრუმენტი და Tuist Mac პლაგინი აგენტებს ეუბნებიან, რომ შეუსაბამონ ვერსია, რომელსაც პროექტი იყენებს.
- **სენდბოქსი ინარჩუნებს თავის Xcode-ს სიცოცხლის ბოლომდე.** სხვა Xcode-ით ასაშენებლად, შექმენით ახალი სენდბოქსი. `xcodebuild -version` აჩვენებს, თუ რომელ Xcode-ს მუშაობს Mac.

## უსაფრთხოება {#security}

- ყოველი სენდბოქსი არის საკუთარი ვირტუალური მანქანა. სენდბოქსები არ იზიარებენ ფაილურ სისტემას, მეხსიერებას ან პროცესებს ერთმანეთთან ან CI დავალებებთან.
- სენდბოქსები ეკუთვნის ანგარიშს და მისი ნებისმიერი წევრი შეუძლია მათი გამოყენება და მართვა, ინტეგრაციისთვის განკუთვნილი სენდბოქსების ჩათვლით. ინტეგრაციებს მხოლოდ ადმინისტრატორები აკავშირებენ. ინტეგრაციიდან მომავალი სესიები მხოლოდ იმ ანგარიშის სენდბოქსებს აღწევენ, რომელსაც ინტეგრაცია მიერთებულია.
- მონაცემები, რომლებსაც თქვენ აწვდით Tuist-ს ინტეგრაციის დასაკავშირებლად, როგორიცაა Amp პროვაიდერის ტოკენი ან Claude გარემოს გასაღები, ინახება დაშიფრული და აღარასდროს ჩანს.
- სენდბოქსს შეუძლია ინტერნეტთან წვდომა. მოეპყარით იმას, რასაც აგენტი оттуда შეუძლია წვდომა, ისე, როგორც მოეპყრებოდით CI დავალებას.
