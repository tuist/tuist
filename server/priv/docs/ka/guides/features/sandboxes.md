# სენდბოქსები {#sandboxes}

> [!IMPORTANT]
> **მხოლოდ მოწვევით**
>
> Tuist სენდბოქსები, როგორც Linux-ის, ისე macOS-ის, ამჟამად მხოლოდ მოწვევითაა ხელმისაწვდომი, სანამ შესაძლებლობებს გავზრდით. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [კომუნიკაციის Slack-ზე](https://slack.tuist.dev), რათა თქვენი ანგარიშისთვის წვდომა მოითხოვოთ. ფასები გამოცხადდება, როდესაც სენდბოქსები ზოგადი ხელმისაწვდომობის ეტაპზე გადავა.

სენდბოქსი არის ვირტუალური მანქანა, სადაც კოდირების აგენტი ასრულებს ბრძანებებს და არედაქტირებს ფაილებს. აგენტის თითოეულ სესიას ეკუთვნის საკუთარი სენდბოქსი, რომელიც ინახავს რეპოზიტორიის ჩეკაუთს, ბილდის პროდუქტებსა და დაინსტალირებულ ხელსაწყოებს სესიის განმავლობაში. როდესაც აგენტი უმოქმედო ხდება, სენდბოქსი იყურება; შემდეგი შეტყობინება აღადგენს მას იქიდან, სადაც გაჩერდა.

სენდბოქსები მუშაობენ იმავე ინფრასტრუქტურაზე, რაზეც <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link>, თქვენი გუნდის <.localized_link href="/guides/features/cache">ქეშთან</.localized_link> ერთად, ამიტომ აგენტის ბილდებს შეუძლიათ გამოიყენონ იგივე ქეშირებული არტიფაქტები, რაც თქვენს CI-სა და ლოკალურ მანქანებს.

სენდბოქსების გამოყენება შეგიძლიათ შემდეგი საშუალებებით:

- **<.localized_link href="/guides/features/sandboxes/amp">Amp</.localized_link>**: გაუშვით თქვენი Amp სამუშაო სივრცის ორბები Tuist-ზე, ან ნებისმიერ Amp ძაფს მიანიჭეთ Mac Xcode-ის ბილდებისთვის <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინის</.localized_link> მეშვეობით.
- **<.localized_link href="/guides/features/sandboxes/claude">Claude</.localized_link>**: გაუშვით Claude Managed Agents სესიები და Claude Code-ის ღრუბლოვანი სესიები (claude.ai, დესკტოპისა და მობილური აპლიკაციები და `claude --cloud`) Tuist-ზე.
- **[Tuist CLI](#cli)**: შექმენით სენდბოქსები და გაუშვით მათში ბრძანებები თქვენი ტერმინალიდან, ან თქვენი საკუთარი ხელსაწყოებიდან API-ის მეშვეობით.

## CLI-ით დაწყება {#cli}

შექმენით სენდბოქსი და გაუშვით მასში ბრძანებები თქვენი ტერმინალიდან `tuist sandbox`-ის მეშვეობით.

### 1. შესვლა {#cli-log-in}

ანგარიშის ნებისმიერ წევრს შეუძლია შექმნას და მართოს მისი სენდბოქსები:

```bash
tuist auth login
```

### 2. სენდბოქსის შექმნა {#cli-create}

```bash
tuist sandbox create --platform macos
```

Linux-ისთვის გამოტოვეთ `--platform`. Mac-ისთვის, რომელსაც ექნება ის [Xcode](#xcode), გადაეცით `--xcode` ვერსიით, მაგალითად `--xcode 26.1.1`; ეს გულისხმობს `--platform macos`-ს. უფრო დიდი [კონფიგურაციისთვის](#platforms) გადაეცით `--vcpus` `--memory-gb`-თან ერთად, ხოლო უფრო დიდი დისკისთვის — `--workspace-gb`. ბრძანება ბრუნდება მას შემდეგ, რაც სენდბოქსი გაეშვება და ბეჭდავს მის დეტალებს, მათ შორის ID-ს. ის იყენებს მიმდინარე დირექტორიაში არსებული Tuist პროექტის ანგარიშს; სხვის არჩევით გადაეცით `--account`.

### 3. ბრძანებების გაშვება {#cli-exec}

```bash
tuist sandbox exec <sandbox-id> -- xcodebuild -version
```

ბრძანება სენდბოქსში სრულდება `bash -l`-ით, რომელიც ჯერ აღადგენს მას, თუ ის შეჩერებულია. `tuist` აწვდის მის გამონატანს, რამდენი ხანიც არ უნდა სრულდებოდეს, და სრულდება ბრძანების სტატუსით; Ctrl-C აუქმებს მას სენდბოქსში. საჭიროების შემთხვევაში გადაეცით `--cwd`, `--env NAME=VALUE` და `--timeout` (ექვს საათამდე).

### ჩვეულებრივი ამოცანები {#cli-tasks}

| ამოცანა | ბრძანება |
| --- | --- |
| სენდბოქსების სია | `tuist sandbox list` |
| ერთის ჩვენება | `tuist sandbox show <id>` |
| შეჩერება ან აღდგენა | `tuist sandbox pause <id>`, `tuist sandbox resume <id>` |
| ლოკალური Git worktree-ის ფაილების ასახვა მასში | `tuist sandbox sync <id>` |
| ფაილების კოპირება გარეთ ან შიგნით | `tuist sandbox cp <id>:<path> <local-path>`, `tuist sandbox cp <local-path> <id>:<path>` |
| წაშლა | `tuist sandbox delete <id> --yes` |
| გამოყენების ნახვა | `tuist sandbox analytics` |

მანქანისთვის წასაკითხი გამონატანისთვის დაამატეთ `--json`. ყველა პარამეტრის სანახავად იხილეთ <.localized_link href="/cli/sandbox">CLI-ის ცნობარი</.localized_link>. სენდბოქსების კოდიდან მართვისთვის, გამოიყენეთ იგივე ოპერაციები [Tuist API](https://tuist.dev/api/docs)-ის მეშვეობით `/api/accounts/{account_handle}/sandboxes` ქვეშ, ან მიეცით აგენტს მათი გამოყენების საშუალება <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>-ის მეშვეობით.

ხელსაწყოები, რომლებსაც ინტერაქტიული შესვლა არ შეუძლიათ, მაგალითად აგენტის პლაგინი, რომელიც macOS სენდბოქსში აწყობს, შეუძლიათ ავთენტიკაცია <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენით</.localized_link> `account:sandboxes:write` სკოპით. მას შეუძლია გააკეთოს ის, რაც ანგარიშის წევრს: შექმნას სენდბოქსები, გაუშვას მათში ბრძანებები, შეაჩეროს, აღადგინოს, დააარქივოს და წაშალოს ისინი. ინტეგრაციის პარამეტრები რჩება ანგარიშის ადმინისტრატორებთან.

### Tuist სენდბოქსის შიგნით {#tuist-in-sandbox}

სენდბოქსის იმიჯები არ შეიცავენ Tuist CLI-ს, ამიტომ სრულდება თქვენი პროექტის მიერ მიმაგრებული ვერსია. პირველი `tuist sandbox sync`-ის შემდეგ, გაუშვით `mise install` რეპოზიტორიის ფესვში სენდბოქსზე (`mise` და `brew` დაინსტალირებულია). ყოველი ბრძანება, რომელსაც `tuist sandbox exec`-ით იწყებთ, mise-ის shim-ებს (`$HOME/.local/share/mise/shims`) აქვს პირველად `PATH`-ზე, ამიტომ `tuist` და სხვა mise ხელსაწყოები სრულდება თქვენს ბრძანებებში და Xcode-ის ბილდის ფაზებში, მაგალითად სქემის post-actions-ში.

ყოველი ბრძანება, რომელსაც `tuist sandbox exec`-ით იწყებთ, ასევე იღებს იმას, რასაც Tuist runner იღებს, ამიტომ სენდბოქსში ბილდები იყენებენ თქვენი ანგარიშის <.localized_link href="/guides/features/cache">ქეშს</.localized_link> თქვენს მიერ რწმუნებების გადაცემის გარეშე:

- `TUIST_URL` და, იქ, სადაც სენდბოქსის ჰოსტი მას სწვდება, მაგალითად macOS-ზე, იმავე რაკში არსებული ქეშის `TUIST_CACHE_ENDPOINT`.
- `TUIST_OIDC_TOKEN`, მოკლევადიანი იდენტობის ტოკენი იმ ბრძანებისთვის. Tuist CLI 4.218.0 და ზემოთ ვერსიები თავისთავად შედიან მით; 4.215.0-დან 4.217.x-მდე ვერსიებში, ჯერ გაუშვით `tuist auth login` იმავე ბრძანებაში.

ტოკენი იქმნება ყოველი ბრძანებისთვის და შეიძლება გაცვლილი იქნას Tuist ტოკენზე მხოლოდ მაშინ, როცა ეს ბრძანება სრულდება, ამიტომ სენდბოქსი არასდროს ინახავს ხანგრძლივი მოქმედების რწმუნებას. ის არასდროს ანიჭებს იმაზე მეტს, ვიდრე პირს ან ტოკენს, რომელმაც ბრძანება დაიწყო, შეუძლია გააკეთოს ქეშთან: ანგარიშის წევრებს, რომელთა ქეშის ტოკენებს მხოლოდ ჩაწერა შეუძლიათ, ენიჭებათ წაკითხვის წვდომა, ხოლო ანგარიშის ტოკენს სჭირდება ქეშის სკოპები, მაგალითად `ci`, `account:sandboxes:write`-თან ერთად, რათა სენდბოქსმა საერთოდ გამოიყენოს ქეში. ცვლადები, რომლებსაც `--env`-ით გადასცემთ, აქვთ უპირატესობა.

## Mac-ზე აწყობა კოდირების აგენტიდან {#coding-agents}

კოდირების აგენტი, რომელიც Linux-ზე მუშაობს, მაგალითად ღრუბლოვანი აგენტის სესია, შეუძლია ააწყოს, შეამოწმოს და გაუშვას Apple-პლატფორმის კოდი macOS სენდბოქსზე, სანამ ის აგრძელებს ფაილების რედაქტირებას იქ, სადაც მუშაობს. Amp-ში, დააინსტალირეთ <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინი</.localized_link>. სხვა აგენტებისთვის, მაგალითად Claude Code ან Cursor:

1. დააკავშირეთ აგენტი Tuist <.localized_link href="/guides/features/agentic-coding/mcp">MCP სერვერთან</.localized_link>. მისი `create_sandbox` ხელსაწყო ეუბნება აგენტს, თუ როგორ მართოს Mac.
2. დააინსტალირეთ Tuist CLI იქ, სადაც აგენტი მუშაობს, მაგალითად გარემოს setup სკრიპტში: `mise use -g tuist@latest`, ან `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist` (`tuist-linux-aarch64` ARM-ზე).
3. აავთენტიკეთ CLI. MCP სერვერის შესვლა მასზე არ ვრცელდება, ამიტომ ან გაუშვით `tuist auth login` როგორც ანგარიშის წევრმა, ან დააყენეთ `TUIST_TOKEN` <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენზე</.localized_link> `account:sandboxes:write` სკოპით.
4. თუ გარემო ზღუდავს ქსელურ წვდომას, დაუშვით `tuist.dev`. CLI ამის საშუალებით ატვირთავს ფაილებს Mac-ზე, ამიტომ სხვა დომენი არ სჭირდება.

აგენტი ქმნის ერთ Mac-ს თითოეული ამოცანისთვის, პროექტის მიერ მითითებული [Xcode](#xcode)-ით: `create_sandbox` ჩამოთვლის ხელმისაწვდომ Xcode-ებს და ეუბნება აგენტს, წაიკითხოს პროექტის ვერსია, მაგალითად `.xcode-version`. ყოველი ბრძანების შესრულებამდე ის ასრულებს `tuist sandbox sync`. ის აკოპირებს ფაილებს, რომლებსაც Git არ იგნორირებს — როგორც დაკომიტებულს, ისე დაუკომიტებელს, შემდეგ კი მხოლოდ შეცვლილ ფაილებს. პირველი სინქრონიზაციის შემდეგ ის ასრულებს `mise install` რეპოზიტორიის ძირში Mac-ზე, რათა [პროექტის მიერ მითითებული Tuist](#tuist-in-sandbox) იყოს ხელმისაწვდომი და ავტორიზებული თქვენი ანგარიშის ქეშთან. შემდეგ აგენტი ასრულებს ბრძანებებს, როგორიცაა `xcodebuild`, `tuist sandbox exec`-ის გამოყენებით, აკოპირებს შედეგებს, მაგალითად სკრინშოტებს ან აწყობილ აპლიკაციას, უკან `tuist sandbox cp`-ით და შლის Mac-ს, როცა ამოცანა დასრულდება. Mac რჩება გაშვებული ბოლო ბრძანებიდან 10 წუთის განმავლობაში, რათა შემდეგი ბრძანება დაუყოვნებლივ დაიწყოს; `tuist sandbox pause` კი უფრო ადრე აბრუნებს რესურსს. მიტოვებული Mac ჯერ პაუზდება და 14 დღის შემდეგ იშლება.

## Linux და macOS {#platforms}

**Linux** სენდბოქსები მუშაობენ Ubuntu 24.04-ზე:

- 2 vCPU, 4 GiB RAM (ნაგულისხმევი)
- 4 vCPU, 8 GiB RAM
- 8 vCPU, 16 GiB RAM

**macOS** სენდბოქსები მუშაობენ Apple silicon-ზე Xcode-ით:

- 8 vCPU, 8 GiB RAM (ნაგულისხმევი)
- 8 vCPU, 16 GiB RAM
- 8 vCPU, 24 GiB RAM

### აირჩიეთ Xcode {#xcode}

თითოეული macOS სენდბოქსი ერთ Xcode-ს ატარებს, რომელსაც მისი შექმნისას ირჩევთ. ის ტვირთავს იმავე იმიჯს, რაც <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link> პროფილი იმ Xcode-ისთვის, ამიტომ აგენტი იყენებს იმავე ინსტრუმენტთა ნაკრებს და სიმულატორებს, რაც თქვენი CI. tuist.dev-ზე macOS სენდბოქსები ამჟამად გთავაზობთ:

- `26.6` (ნაგულისხმევი)
- `26.1.1`
- `27.0`
- `27.1`
- `27.2`

აირჩიეთ ერთ-ერთი `xcode_version`-ით (`--xcode` CLI-ში), ზუსტი ვერსიის გამოყენებით, როგორც ეს runner პროფილებში ხდება:

| სად | როგორ |
| --- | --- |
| CLI | `tuist sandbox create --xcode 26.1.1` |
| API და MCP `create_sandbox` | `"xcode_version": "26.1.1"` |
| Tuist Mac პლაგინი Amp-ისთვის | `tuist_mac_start` `xcode`-ით |
| Amp orbs | Orb-ის ტიპი `macos-xcode-26-1-1` (იხ. <.localized_link href="/guides/features/sandboxes/amp#xcode">Amp</.localized_link>) |
| Claude Code და Claude Managed Agents | `xcode_version` გარემოზე, ან თითოეული Managed Agents სესიისთვის (იხ. <.localized_link href="/guides/features/sandboxes/claude#xcode">Claude</.localized_link>) |

- **ვერსიის მითითების გარეშე**, Mac იღებს ნაგულისხმევს.
- **ვერსია, რომელსაც Tuist არ გთავაზობთ, უარყოფილი იქნება** და შეცდომა ჩამოთვლის ვერსიებს, რომელთა არჩევაც შეგიძლიათ, რათა იცოდეთ, რაა ხელმისაწვდომი ამჟამად.
- **Tuist არ კითხულობს თქვენი რეპოზიტორიის `.xcode-version`-ს.** ვერსიას თქვენ, ან Mac-ის მომთხოვნი აგენტი ირჩევთ. MCP ხელსაწყო და Tuist Mac პლაგინი ეუბნებიან აგენტებს, დაემთხვეს პროექტის მიერ მინიჭებულ ვერსიას.
- **სენდბოქსი ინარჩუნებს თავის Xcode-ს მთელი სიცოცხლის განმავლობაში.** სხვა Xcode-ით აწყობისთვის, შექმენით ახალი სენდბოქსი. `xcodebuild -version` აჩვენებს, თუ რომელ Xcode-ს ატარებს Mac.

## უსაფრთხოება {#security}

- თითოეული სენდბოქსი საკუთარი ვირტუალური მანქანაა. სენდბოქსები არ იზიარებენ ფაილურ სისტემას, მეხსიერებას ან პროცესებს ერთმანეთთან ან CI სამუშაოებთან.
- სენდბოქსები ეკუთვნიან ანგარიშს და მისი ნებისმიერი წევრი შეუძლია მათი გამოყენება და მართვა, ინტეგრაციის მომსახურე სენდბოქსების ჩათვლით. ინტეგრაციებს მხოლოდ ადმინისტრატორები აკავშირებენ. ინტეგრაციიდან მომავალი სესიები მხოლოდ იმ ანგარიშის სენდბოქსებს აღწევენ, რომელთანაც ინტეგრაციაა დაკავშირებული.
- მოწმობები, რომლებსაც Tuist-ს აძლევთ ინტეგრაციის დასაკავშირებლად, მაგალითად Amp პროვაიდერის ტოკენი ან Claude გარემოს გასაღები, ინახება დაშიფრული და აღარასდროს ჩანს.
- სენდბოქსს შეუძლია ინტერნეტთან წვდომა. მოეპყარით იმას, რასაც აგენტი მისგან წვდება ისე, როგორც CI სამუშაოს.
