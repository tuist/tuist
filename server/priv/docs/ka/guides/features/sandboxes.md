# სენდბოქსები {#sandboxes}

> [!IMPORTANT]
> **მხოლოდ მოწვევით**
>
> Tuist Sandboxes, როგორც Linux-ის, ისე macOS-ის ვერსიები, ამჟამად მხოლოდ მოწვევითაა ხელმისაწვდომი, სანამ შესაძლებლობებს გავზრდით. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [საზოგადოების Slack-ში](https://slack.tuist.dev), რათა თქვენი ანგარიშისთვის წვდომა მოითხოვოთ. ფასები გამოცხადდება, როდესაც Sandboxes ზოგად ხელმისაწვდომობას მიიღებს.

სენდბოქსი არის ვირტუალური მანქანა, სადაც კოდირების აგენტი ასრულებს ბრძანებებს და არედაქტირებს ფაილებს. თითოეულ აგენტის სესიას ენიჭება საკუთარი სენდბოქსი, რომელიც ინარჩუნებს კოდის ჩექაუთს, ბილდის პროდუქტებსა და ინსტალირებულ ინსტრუმენტებს სესიის განმავლობაში. როდესაც აგენტი უმოქმედოა, სენდბოქსი ჩერდება; შემდეგი შეტყობინება აღადგენს მას იქიდან, სადაც გაჩერდა.

სენდბოქსები მუშაობენ იმავე ინფრასტრუქტურაზე, რაზეც <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link>, თქვენი გუნდის <.localized_link href="/guides/features/cache">ქეშის</.localized_link> გვერდით, რითაც აგენტის ბილდებს შეუძლიათ გამოიყენონ იგივე ქეშირებული არტეფაქტები, რასაც თქვენი CI და ლოკალური მანქანები.

სენდბოქსების გამოყენება შეგიძლიათ:

- **<.localized_link href="/guides/features/sandboxes/amp">Amp</.localized_link>**: გაუშვით თქვენი Amp სამუშაო სივრცის ორბები Tuist-ზე, ან ნებისმიერ Amp ნაკადს მიაწოდეთ Mac Xcode ბილდებისთვის <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინის</.localized_link> საშუალებით.
- **<.localized_link href="/guides/features/sandboxes/claude">Claude</.localized_link>**: გაუშვით Claude Managed Agents სესიები და Claude Code ღრუბლოვანი სესიები (claude.ai, დესკტოპისა და მობილური აპლიკაციები და `claude --cloud`) Tuist-ზე.
- **[Tuist CLI](#cli)**: შექმენით სენდბოქსები და გაუშვით ბრძანებები მათში თქვენი ტერმინალიდან, ან თქვენი საკუთარი ინსტრუმენტებიდან API-ს მეშვეობით.

## დაიწყეთ CLI-ით {#cli}

შექმენით სენდბოქსი და გაუშვით ბრძანებები მასში თქვენი ტერმინალიდან `tuist sandbox`-ის საშუალებით.

### 1. შესვლა {#cli-log-in}

ანგარიშის ნებისმიერ წევრს შეუძლია შექმნას და მართოს მისი სენდბოქსები:

```bash
tuist auth login
```

### 2. სენდბოქსის შექმნა {#cli-create}

```bash
tuist sandbox create --platform macos
```

გამოტოვეთ `--platform` Linux-ისთვის. გადაეცით `--xcode` ვერსიით, მაგალითად `--xcode 26.1.1`, Mac-ისთვის იმ [Xcode](#xcode)-ით; ეს გულისხმობს `--platform macos`-ს. გადაეცით `--vcpus` `--memory-gb`-თან ერთად უფრო დიდი [კონფიგურაციისთვის](#platforms) და `--workspace-gb` უფრო დიდი დისკისთვის. ბრძანება ბრუნდება, როგორც კი სენდბოქსი გაეშვება და ბეჭდავს მის დეტალებს, მათ შორის ID-ს. ის იყენებს მიმდინარე დირექტორიაში არსებული Tuist პროექტის ანგარიშს; გადაეცით `--account` სხვის არჩევას.

### 3. ბრძანებების გაშვება {#cli-exec}

```bash
tuist sandbox exec <sandbox-id> -- xcodebuild -version
```

ბრძანება სრულდება `bash -l`-ით სენდბოქსში, რომელიც ჯერ აღდგება, თუ შეჩერებულია. `tuist` აგზავნის მის გამონატანს, რამდენი ხანიც არ უნდა გაგრძელდეს და სრულდება ბრძანების სტატუსით; Ctrl-C აუქმებს მას სენდბოქსში. გადაეცით `--cwd`, `--env NAME=VALUE` და `--timeout` (ექვს საათამდე) საჭიროების შემთხვევაში.

### ჩვეულებრივი ამოცანები {#cli-tasks}

| ამოცანა | ბრძანება |
| --- | --- |
| სენდბოქსების ჩამონათვალი | `tuist sandbox list` |
| ერთის ჩვენება | `tuist sandbox show <id>` |
| შეჩერება ან აღდგენა | `tuist sandbox pause <id>`, `tuist sandbox resume <id>` |
| ლოკალური Git worktree-ის ფაილების ასახვა მასში | `tuist sandbox sync <id>` |
| ფაილების კოპირება გარეთ ან შიგნით | `tuist sandbox cp <id>:<path> <local-path>`, `tuist sandbox cp <local-path> <id>:<path>` |
| წაშლა | `tuist sandbox delete <id> --yes` |
| გამოყენების ნახვა | `tuist sandbox analytics` |

დაამატეთ `--json` მანქანისთვის წასაკითხი გამონატანისთვის. ყველა პარამეტრისთვის იხილეთ <.localized_link href="/cli/sandbox">CLI ცნობარი</.localized_link>. სენდბოქსების კოდიდან მართვისთვის, გამოიყენეთ იგივე ოპერაციები [Tuist API](https://tuist.dev/api/docs)-ს მეშვეობით `/api/accounts/{account_handle}/sandboxes`-ქვეშ, ან მიეცით აგენტს მათი გამოყენების საშუალება <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>-ს მეშვეობით.

ინსტრუმენტები, რომლებსაც ინტერაქტიული შესვლა არ შეუძლიათ, მაგალითად აგენტის პლაგინი, რომელიც macOS სენდბოქსში აწყობს, შეუძლიათ ავთენტიკაცია <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენით</.localized_link> `account:sandboxes:write` სკოუპით. მას შეუძლია გააკეთოს ის, რაც ანგარიშის წევრს: შექმნას სენდბოქსები, გაუშვას მათში ბრძანებები, შეაჩეროს, აღადგინოს, დაარქივოს და წაშალოს ისინი. ინტეგრაციის პარამეტრები რჩება ანგარიშის ადმინისტრატორებთან.

### Tuist სენდბოქსის შიგნით {#tuist-in-sandbox}

სენდბოქსის იმიჯები არ შეიცავენ Tuist CLI-ს, ამიტომ მუშაობს თქვენი პროექტის მიერ მიმაგრებული ვერსია. პირველი `tuist sandbox sync`-ის შემდეგ, გაუშვით `mise install` რეპოზიტორიის ძირში სენდბოქსზე (`mise` და `brew` ინსტალირებულია). ყოველი ბრძანება, რომელსაც `tuist sandbox exec`-ით იწყებთ, mise-ის shims-ებს (`$HOME/.local/share/mise/shims`) პირველად აყენებს `PATH`-ზე, რითაც `tuist` და სხვა mise ინსტრუმენტები მუშაობენ თქვენს ბრძანებებში და Xcode ბილდის ფაზებში, მაგალითად სქემის post-actions-ში.

ყოველი ბრძანება, რომელსაც `tuist sandbox exec`-ით იწყებთ, ასევე იღებს იმას, რასაც Tuist runner იღებს, ამიტომ სენდბოქსში ბილდები იყენებენ თქვენი ანგარიშის <.localized_link href="/guides/features/cache">ქეშს</.localized_link> თქვენს მიერ კრედენშალების გადაცემის გარეშე:

- `TUIST_URL` და, იქ, სადაც სენდბოქსის ჰოსტი მას აღწევს, მაგალითად macOS-ზე, იმავე რაკში არსებული ქეშის `TUIST_CACHE_ENDPOINT`.
- `TUIST_OIDC_TOKEN`, მოკლე ვადიანი იდენტობის ტოკენი იმ ბრძანებისთვის. Tuist CLI 4.218.0 და ზემოთ ვერსიები თავისით შედიან მით; 4.215.0-დან 4.217.x-მდე, ჯერ გაუშვით `tuist auth login` იმავე ბრძანებაში.

ტოკენი იქმნება ყოველი ბრძანებისთვის და შეიძლება გაცვლილი იქნას Tuist ტოკენზე მხოლოდ მაშინ, როდესაც ეს ბრძანება მუშაობს, ამიტომ სენდბოქსი არასდროს ინახავს ხანგრძლივი ვადის კრედენშალს. ის არასდროს ანიჭებს იმაზე მეტს, ვიდრე ბრძანების დამწყებ პირს ან ტოკენს შეუძლია ქეშთან: ანგარიშის წევრებს, რომელთა ქეშის ტოკენებს მხოლოდ ჩაწერა შეუძლიათ, ენიჭებათ წაკითხვის წვდომა, და ანგარიშის ტოკენს სჭირდება ქეშის სკოუპები, მაგალითად `ci`, `account:sandboxes:write`-თან ერთად, რათა სენდბოქსმა საერთოდ გამოიყენოს ქეში. `--env`-ით გადაცემული ცვლადები აქვთ უპირატესობა.

## აწყობა Mac-ზე კოდირების აგენტიდან {#coding-agents}

კოდირების აგენტს, რომელიც მუშაობს Linux-ზე, მაგალითად ღრუბლოვანი აგენტის სესიას, შეუძლია ააწყოს, გატესტოს და გაუშვას Apple-პლატფორმის კოდი macOS სენდბოქსზე, სანამ ის აგრძელებს ფაილების რედაქტირებას იქ, სადაც მუშაობს. Amp-ში, დააინსტალირეთ <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინი</.localized_link>. სხვა აგენტებისთვის, მაგალითად Claude Code ან Cursor:

1. დააკავშირეთ აგენტი Tuist <.localized_link href="/guides/features/agentic-coding/mcp">MCP სერვერთან</.localized_link>. მისი `create_sandbox` ინსტრუმენტი ეუბნება აგენტს, თუ როგორ მართოს Mac.
2. დააინსტალირეთ Tuist CLI იქ, სადაც აგენტი მუშაობს, მაგალითად გარემოს setup სკრიპტში: `mise use -g tuist@latest`, ან `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist` (`tuist-linux-aarch64` ARM-ზე).
3. ავთენტიკაცია CLI-სთვის. MCP სერვერის შესვლა არ გადაეცემა მას, ამიტომ ან გაუშვით `tuist auth login` როგორც ანგარიშის წევრმა, ან დააყენეთ `TUIST_TOKEN` <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენზე</.localized_link> `account:sandboxes:write` სკოუპით.
4. თუ გარემო ზღუდავს ქსელურ წვდომას, დაუშვით `tuist.dev`. CLI ატვირთავს ფაილებს Mac-ზე მისი საშუალებით, ამიტომ სხვა დომენი არ სჭირდება.

აგენტი ქმნის ერთ Mac-ს თითოეული ამოცანისთვის, პროექტის მიერ მიმაგრებული [Xcode](#xcode)-ით: `create_sandbox` ჩამოთვლის ხელმისაწვდომ Xcode-ებს და ეუბნება აგენტს, წაიკითხოს პროექტის მიმაგრება, მაგალითად `.xcode-version`. ყოველი ბრძანების შესრულებამდე ის ასრულებს `tuist sandbox sync`. ის აკოპირებს ფაილებს, რომლებსაც Git არ იგნორირებს (ჩაკომიტებულს თუ არა), ხოლო შემდეგ მხოლოდ შეცვლილ ფაილებს. პირველი სინქრონიზაციის შემდეგ ის ასრულებს `mise install` რეპოზიტორიის ძირში Mac-ზე, რათა [პროექტის მიმაგრებული Tuist](#tuist-in-sandbox) იყოს იქ, შესული თქვენი ანგარიშის ქეშში. შემდეგ აგენტი ასრულებს ბრძანებებს, როგორიცაა `xcodebuild`, `tuist sandbox exec`-ის საშუალებით, აკოპირებს შედეგებს, როგორიცაა სკრინშოტები ან აწყობილი აპლიკაცია, უკან `tuist sandbox cp`-ით და შლის Mac-ს, როცა ამოცანა დასრულდება. Mac რჩება გაშვებული ბოლო ბრძანებიდან 10 წუთის განმავლობაში, რათა შემდეგი დაუყოვნებლივ დაიწყოს; `tuist sandbox pause` უფრო სწრაფად აბრუნებს მას. მიტოვებული Mac იყინება და იშლება 14 დღიანი გაყინვის შემდეგ.

## Linux და macOS {#platforms}

**Linux** სენდბოქსები მუშაობენ Ubuntu 24.04-ზე:

- 2 vCPU, 4 GiB RAM (ნაგულისხმევი)
- 4 vCPU, 8 GiB RAM
- 8 vCPU, 16 GiB RAM

**macOS** სენდბოქსები მუშაობენ Apple silicon-ზე Xcode-ით:

- 8 vCPU, 8 GiB RAM (ნაგულისხმევი)
- 8 vCPU, 16 GiB RAM
- 8 vCPU, 24 GiB RAM

### აირჩიეთ Xcode {#xcode}

ყოველი macOS სენდბოქსი აწარმოებს ერთ Xcode-ს, რომელსაც თქვენ ირჩევთ მისი შექმნისას. ის იტვირთება იმავე იმიჯით, რაც <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link> პროფილი ამ Xcode-ისთვის, ამიტომ აგენტი აწყობს იმავე ინსტრუმენტებითა და სიმულატორებით, რაც თქვენი CI. tuist.dev-ზე, macOS სენდბოქსები ამჟამად გთავაზობთ:

- `26.6` (ნაგულისხმევი)
- `26.1.1`
- `27.0`
- `27.1`
- `27.2`

აირჩიეთ ერთ-ერთი `xcode_version`-ით (`--xcode` CLI-ში), ზუსტი ვერსიის გამოყენებით, როგორც ეს runner პროფილებში კეთდება:

| სად | როგორ |
| --- | --- |
| CLI | `tuist sandbox create --xcode 26.1.1` |
| API და MCP `create_sandbox` | `"xcode_version": "26.1.1"` |
| Tuist Mac პლაგინი Amp-ისთვის | `tuist_mac_start` `xcode`-ით |
| Amp orbs | Orb-ის ტიპი `macos-xcode-26-1-1` (იხილეთ <.localized_link href="/guides/features/sandboxes/amp#xcode">Amp</.localized_link>) |
| Claude Code და Claude Managed Agents | `xcode_version` გარემოზე, ან თითოეული Managed Agents სესიისთვის (იხილეთ <.localized_link href="/guides/features/sandboxes/claude#xcode">Claude</.localized_link>) |

- **ვერსიის მითითების გარეშე**, Mac იღებს ნაგულისხმევს.
- **Tuist-ის მიერ შეუთავაზებელი ვერსია უარყოფილია**, ხოლო შეცდომა ჩამოთვლის ვერსიებს, რომელთა არჩევაც შეგიძლიათ, რათა იცოდეთ, რაა ხელმისაწვდომი ამჟამად.
- **Tuist არ კითხულობს თქვენი რეპოზიტორიის `.xcode-version`-ს.** თქვენ, ან აგენტი, რომელიც ითხოვს Mac-ს, ირჩევთ ვერსიას. MCP ინსტრუმენტი და Tuist Mac პლაგინი ეუბნებიან აგენტებს, დაემთხვნენ პროექტის მიერ მიმაგრებულ ვერსიას.
- **სენდბოქსი ინარჩუნებს თავის Xcode-ს სიცოცხლის ბოლომდე.** სხვა Xcode-ით აწყობისთვის, შექმენით ახალი სენდბოქსი. `xcodebuild -version` აჩვენებს, თუ რომელ Xcode-ს აწარმოებს Mac.

## უსაფრთხოება {#security}

- ყოველი სენდბოქსი არის ცალკეული ვირტუალური მანქანა. სენდბოქსები არ იზიარებენ ფაილურ სისტემას, მეხსიერებას ან პროცესებს ერთმანეთთან ან CI სამუშაოებთან.
- სენდბოქსები ეკუთვნის ანგარიშს და მისი ნებისმიერი წევრი შეუძლია მათი გამოყენება და მართვა, მათ შორის იმ სენდბოქსების, რომლებიც ემსახურებიან ინტეგრაციას. მხოლოდ ადმინისტრატორები აკავშირებენ ინტეგრაციებს. ინტეგრაციიდან მომავალი სესიები მხოლოდ იმ ანგარიშის სენდბოქსებს აღწევენ, რომელთანაც ინტეგრაციაა დაკავშირებული.
- მონაცემები, რომლებსაც თქვენ აწვდით Tuist-ს ინტეგრაციის დასაკავშირებლად, როგორიცაა Amp პროვაიდერის ტოკენი ან Claude გარემოს გასაღები, ინახება დაშიფრული და აღარასდროს ჩანს.
- სენდბოქსს შეუძლია ინტერნეტთან წვდომა. მოეპყარით იმას, რასაც აგენტი შეუძლია მიუწვდეს მისგან, ისე, როგორც მოეპყრებოდით CI სამუშაოს.
