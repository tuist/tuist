# სენდბოქსები {#sandboxes}

> [!IMPORTANT]
> **მხოლოდ მოწვევით**
>
> Tuist Sandboxes, როგორც Linux-ის, ისე macOS-ის ვერსიები, ამჟამად ხელმისაწვდომია მხოლოდ მოწვევით, სანამ ჩვენ გავზრდით შესაძლებლობებს. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [კომუნური Slack-ის](https://slack.tuist.dev) საშუალებით, რათა მოითხოვოთ თქვენი ანგარიშისთვის წვდომა. ფასები გამოცხადდება, როდესაც Sandboxes ზოგადი ხელმისაწვდომობის ეტაპზე გადავა.

სენდბოქსი არის ვირტუალური მანქანა, სადაც კოდინგის აგენტი ასრულებს ბრძანებებს და არედაქტირებს ფაილებს. თითოეული აგენტის სესია იღებს საკუთარ სენდბოქსს, რომელიც ინახავს მის კოდის ასლს, ბილდის პროდუქტებს და დაინსტალირებულ ინსტრუმენტებს სესიის განმავლობაში. როდესაც აგენტი უმოქმედო ხდება, სენდბოქსი ჩერდება; შემდეგი შეტყობინება აღადგენს მას იქიდან, სადაც გაჩერდა.

სენდბოქსები მუშაობენ იმავე ინფრასტრუქტურაზე, რაზეც <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link>, თქვენი გუნდის <.localized_link href="/guides/features/cache">ქეშთან</.localized_link> ერთად, რათა აგენტის ბილდებმა შეძლონ იმავე ქეშირებული არტიფაქტების გამოყენება, რასაც თქვენი CI და ლოკალური მანქანები იყენებენ.

სენდბოქსების გამოყენება შეგიძლიათ:

- **<.localized_link href="/guides/features/sandboxes/amp">Amp</.localized_link>**: გაუშვით თქვენი Amp სამუშაო სივრცის orbs Tuist-ზე, ან მიანიჭეთ ნებისმიერ Amp ნაკადს Mac Xcode ბილდებისთვის <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინის</.localized_link> საშუალებით.
- **<.localized_link href="/guides/features/sandboxes/claude">Claude</.localized_link>**: გაუშვით Claude Managed Agents სესიები და Claude Code ღრუბლოვანი სესიები (claude.ai, დესკტოპ და მობილური აპლიკაციები, და `claude --cloud`) Tuist-ზე.
- **[Tuist CLI](#cli)**: შექმენით სენდბოქსები და გაუშვით ბრძანებები მათში თქვენი ტერმინალიდან, ან თქვენი საკუთარი ინსტრუმენტებიდან API-ის საშუალებით.

## დაიწყეთ CLI-ით {#cli}

შექმენით სენდბოქსი და გაუშვით ბრძანებები მასში თქვენი ტერმინალიდან `tuist sandbox`-ის საშუალებით.

### 1. შესვლა {#cli-log-in}

ანგარიშის ნებისმიერ წევრს შეუძლია შექმნას და მართოს მისი სენდბოქსები:

```bash
tuist auth login
```

### 2. სენდბოქსის შექმნა {#cli-create}

```bash
tuist sandbox create --platform macos
```

გამოტოვეთ `--platform` Linux-ისთვის. გადაეცით `--xcode` ვერსიასთან ერთად, მაგალითად `--xcode 26.1.1`, Mac-ისთვის იმ [Xcode](#xcode)-ით; ეს გულისხმობს `--platform macos`-ს. გადაეცით `--vcpus` `--memory-gb`-თან ერთად უფრო დიდი [კონფიგურაციისთვის](#platforms), `--guaranteed-vcpus` Linux სენდბოქსისთვის მეტი [CPU](#guaranteed-cpu)-ის გარანტიისთვის, და `--workspace-gb` უფრო დიდი დისკისთვის. ბრძანება ბრუნდება, როდესაც სენდბოქსი გაშვებულია და ბეჭდავს მის დეტალებს, მათ შორის მის ID-ს. ის იყენებს მიმდინარე დირექტორიაში არსებული Tuist პროექტის ანგარიშს; გადაეცით `--account` სხვის არჩევას.

### 3. ბრძანებების გაშვება {#cli-exec}

```bash
tuist sandbox exec <sandbox-id> -- xcodebuild -version
```

ბრძანება სრულდება `bash -l`-ით სენდბოქსში, რომელიც ჯერ აღდგება, თუ ის შეჩერებულია. `tuist` აგზავნის მის გამონატანს, რამდენი ხანიც არ უნდა გაგრძელდეს და გამოდის ბრძანების სტატუსით; Ctrl-C აუქმებს მას სენდბოქსში. გადაეცით `--cwd`, `--env NAME=VALUE` და `--timeout` (ექვს საათამდე) საჭიროების შემთხვევაში.

ბრძანება სრულდება `tuist`-გან დამოუკიდებლად, რათა გადარჩეს კავშირის გაწყვეტის შემთხვევაში. ხანგრძლივი ბილდის ჩასასმელად ინსტრუმენტის გამოძახებაში დროის ლიმიტით, მაგალითად აგენტის, გადაეცით `--wait <seconds>`: როდესაც ისინი ჯერ გაივლიან, `tuist` ტოვებს ბრძანებას გაშვებულს, გამოდის 75-ით და ბეჭდავს `tuist sandbox exec <sandbox-id> --attach <command-id> --stdout-offset … --stderr-offset …` ბრძანებას, რომელიც აგრძელებს მის გამონატანს იქიდან, სადაც გაჩერდა და გამოდის ბრძანების სტატუსით.

### ჩვეულებრივი ამოცანები {#cli-tasks}

| ამოცანა | ბრძანება |
| --- | --- |
| სენდბოქსების სია | `tuist sandbox list` |
| ერთის ჩვენება | `tuist sandbox show <id>` |
| შეჩერება ან აღდგენა | `tuist sandbox pause <id>`, `tuist sandbox resume <id>` |
| ლოკალური Git სამუშაო ხის ფაილების ასახვა მასში | `tuist sandbox sync <id>` |
| ფაილების კოპირება გარეთ ან შიგნით | `tuist sandbox cp <id>:<path> <local-path>`, `tuist sandbox cp <local-path> <id>:<path>` |
| წაშლა | `tuist sandbox delete <id> --yes` |
| გამოყენების ნახვა | `tuist sandbox analytics` |

დაამატეთ `--json` მანქანისთვის წასაკითხი გამონატანისთვის. იხილეთ <.localized_link href="/cli/sandbox">CLI ცნობარი</.localized_link> ყველა ოფციისთვის. სენდბოქსების კოდიდან მართვის ნაცვლად, გამოიყენეთ იგივე ოპერაციები [Tuist API](https://tuist.dev/api/docs)-ის საშუალებით `/api/accounts/{account_handle}/sandboxes`-ქვეშ, ან მიეცით აგენტს მათი გამოყენების საშუალება <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>-ის საშუალებით.

ინსტრუმენტები, რომლებსაც არ შეუძლიათ ინტერაქტიული შესვლა, მაგალითად აგენტის პლაგინი, რომელიც ბილდს აკეთებს macOS სენდბოქსში, შეუძლიათ ავთენტიკაცია <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენით</.localized_link> `account:sandboxes:write` სკოუპით. მას შეუძლია გააკეთოს ის, რაც ანგარიშის წევრს შეუძლია: შექმნას სენდბოქსები, გაუშვას მათში ბრძანებები, და შეაჩეროს, აღადგინოს, დაარქივოს და წაშალოს ისინი. ინტეგრაციის პარამეტრები რჩება ანგარიშის ადმინისტრატორებთან.

### Tuist სენდბოქსის შიგნით {#tuist-in-sandbox}

macOS სენდბოქსები მოდიან Tuist CLI-ით. როდესაც თქვენი პროექტი ამაგრებს Tuist-ს mise-ის საშუალებით (`mise.toml` ან `.tool-versions`), `tuist` ასრულებს იმ ვერსიას, რომელიც ინსტალირდება პირველად, როდესაც ბრძანებას დასჭირდება. ყოველი ბრძანება, რომელსაც იწყებთ `tuist sandbox exec`-ით, აქვს mise-ის shims (`$HOME/.local/share/mise/shims`) პირველ ადგილზე `PATH`-ზე და გამოსახულების Tuist ბოლოს, რათა `tuist` და თქვენი სხვა mise ინსტრუმენტები იმუშაონ თქვენს ბრძანებებში და Xcode ბილდის ფაზებში, მაგალითად სქემის post-actions-ში. თითოეულ Mac-ს ასევე აქვს გზამკვლევი კოდინგის აგენტებისთვის `/opt/tuist/agent-guide.md`-ზე, გენერირებული მისი გამოსახულებიდან: მისი Xcode და სიმულატორები, სად არის რეპოზიტორია და რას შეიცავს მზადყოფნის სნეპშოტი. Claude Code, Codex და Amp, რომლებიც მუშაობენ Mac-ზე, პოულობენ მას მათი ინსტრუქციის ფაილებიდან.

ყოველი ბრძანება, რომელსაც იწყებთ `tuist sandbox exec`-ით, ასევე იღებს იმას, რასაც Tuist runner იღებს, რათა სენდბოქსში ბილდებმა გამოიყენონ თქვენი ანგარიშის <.localized_link href="/guides/features/cache">ქეში</.localized_link> თქვენი კრედენციალების გადაცემის გარეშე:

- `TUIST_URL` და, სადაც სენდბოქსის ჰოსტი აღწევს მას, მაგალითად macOS-ზე, `TUIST_CACHE_ENDPOINT` იმავე რაკში არსებული ქეშის.
- `TUIST_OIDC_TOKEN`, მოკლევადიანი იდენტობის ტოკენი იმ ბრძანებისთვის. Tuist CLI 4.218.0 და უფრო ახალი ვერსიები ავთენტიკაციას აკეთებენ მისი საშუალებით თავისთავად; 4.215.0-დან 4.217.x-მდე, გაუშვით `tuist auth login` ჯერ იმავე ბრძანებაში.

ტოკენი იჭრება ყოველი ბრძანებისთვის და შეიძლება გაცვლილ იქნას Tuist ტოკენზე მხოლოდ იმ ბრძანების შესრულების დროს, რათა სენდბოქსმა არასდროს შეინახოს ხანგრძლივი კრედენციალი. ის არასდროს ანიჭებს უფრო მეტს, ვიდრე პირს ან ტოკენს, რომელმაც დაიწყო ბრძანება, შეუძლია გააკეთოს ქეშთან: ანგარიშის წევრები, რომელთა ქეშის ტოკენებს მხოლოდ ჩაწერა შეუძლიათ, იღებენ წაკითხვის წვდომას, და ანგარიშის ტოკენს სჭირდება ქეშის სკოუპები, მაგალითად `ci`, `account:sandboxes:write`-თან ერთად, რათა სენდბოქსმა საერთოდ გამოიყენოს ქეში. ცვლადები, რომლებსაც გადასცემთ `--env`-ით, აქვთ უპირატესობა.

## აშენება Mac-ზე კოდინგის აგენტიდან {#coding-agents}

კოდინგის აგენტი, რომელიც მუშაობს Linux-ზე, მაგალითად ღრუბლოვანი აგენტის სესია, შეუძლია ააშენოს, გატესტოს და გაუშვას Apple-პლატფორმის კოდი macOS სენდბოქსზე, სანამ ის აგრძელებს ფაილების რედაქტირებას იქ, სადაც მუშაობს. Amp-ში, დააინსტალირეთ <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინი</.localized_link>. სხვა აგენტებისთვის, მაგალითად Claude Code ან Cursor:

1. დააკავშირეთ აგენტი Tuist <.localized_link href="/guides/features/agentic-coding/mcp">MCP სერვერთან</.localized_link>. მისი `create_sandbox` ინსტრუმენტი ეუბნება აგენტს, თუ როგორ მართოს Mac.
2. დააინსტალირეთ Tuist CLI იქ, სადაც აგენტი მუშაობს, მაგალითად გარემოს setup სკრიპტში: `mise use -g tuist@latest`, ან `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist` (`tuist-linux-aarch64` ARM-ზე).
3. აუთენტიფიცირეთ CLI. MCP სერვერის შესვლა არ გადადის მასზე, ამიტომ ან გაუშვით `tuist auth login` როგორც ანგარიშის წევრი, ან დააყენეთ `TUIST_TOKEN` <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენზე</.localized_link> `account:sandboxes:write` სკოუპით.
4. თუ გარემო ზღუდავს ქსელურ წვდომას, დაუშვით `tuist.dev`. CLI ატვირთავს ფაილებს Mac-ზე მისი საშუალებით, ამიტომ სხვა დომენი არ სჭირდება.

აგენტი ქმნის ერთ Mac-ს თითოეული ამოცანისთვის, პროექტის მიერ მიბმული [Xcode](#xcode)-ით: `create_sandbox` ჩამოთვლის Xcode-ებს, რომელთა არჩევაც შეუძლია და ეუბნება აგენტს, წაიკითხოს პროექტის მიბმა, მაგალითად `.xcode-version`. ყოველი ბრძანების წინ ის ასრულებს `tuist sandbox sync`-ს. ის აკოპირებს ფაილებს, რომლებსაც Git არ იგნორირებს, დაკომიტული იქნება თუ არა, ხოლო შემდეგ მხოლოდ იმ ფაილებს, რომლებიც შეიცვალა. Mac-ზე უკვე არის [Tuist](#tuist-in-sandbox), პროექტის მიერ მიბმული ვერსია, თუ ის მიბმულია, შესული თქვენი ანგარიშის ქეშში, და აგენტი კითხულობს Mac-ის გზამკვლევს ერთხელ. შემდეგ აგენტი ასრულებს ბრძანებებს, როგორიცაა `xcodebuild`, `tuist sandbox exec`-ის საშუალებით, აკოპირებს შედეგებს, როგორიცაა სკრინშოტები ან აწყობილი აპლიკაცია, უკან `tuist sandbox cp`-ის საშუალებით და შლის Mac-ს, როდესაც ამოცანა დასრულდება. Mac რჩება გაშვებული 10 წუთის განმავლობაში ბოლო ბრძანების შემდეგ, რათა შემდეგი დაიწყოს მაშინვე; `tuist sandbox pause` აბრუნებს მას უფრო ადრე. მიტოვებული Mac შემდეგ ჩერდება და იშლება 14 დღის შეჩერების შემდეგ.

## Linux და macOS {#platforms}

**Linux** სენდბოქსები მუშაობენ Ubuntu 24.04-ზე. ყოველ Linux სენდბოქსს აქვს 16 vCPU და იყენებს მასზე გაშვებული მანქანის თავისუფალ ბირთვებს, ამიტომ მისი ფორმა განსაზღვრავს მეხსიერებას:

- 2 GiB RAM (`--vcpus 1 --memory-gb 2`)
- 4 GiB RAM (`--vcpus 2 --memory-gb 4`, ნაგულისხმევი)
- 8 GiB RAM (`--vcpus 4 --memory-gb 8`)
- 16 GiB RAM (`--vcpus 8 --memory-gb 16`)
- 32 GiB RAM (`--vcpus 16 --memory-gb 32`)
- 44 GiB RAM (`--vcpus 16 --memory-gb 44`)

**macOS** სენდბოქსები მუშაობენ Apple სილიკონზე Xcode-ით:

- 8 vCPU, 8 GiB RAM (ნაგულისხმევი)
- 8 vCPU, 16 GiB RAM
- 8 vCPU, 24 GiB RAM

### გარანტირებული CPU {#guaranteed-cpu}

Linux სენდბოქსს გარანტირებული აქვს vCPU-ის მეოთხედი მეხსიერების თითოეულ GiB-ზე, მაგალითად 2 vCPU 8 GiB-ისთვის, და იყენებს იმდენს, რამდენიც თავისუფალია მის მანქანაზე, 16 vCPU-მდე. ეს შეესაბამება აგენტს, რომელიც ძირითადად ელოდება და შემდეგ აშენებს პაკეტურად. როდესაც აშენებას სჭირდება უფრო სტაბილური CPU დატვირთული მანქანის დროსაც კი, შეუქმენით გარანტია 1, 2, 4 ან 8 vCPU სენდბოქსის შექმნისას; ის იღებს უფრო დიდს ამ გარანტიასა და მეხსიერების გარანტიას შორის:

| სად | როგორ |
| --- | --- |
| CLI | `tuist sandbox create --guaranteed-vcpus 4` |
| API და MCP `create_sandbox` | `"guaranteed_vcpus": 4` |

- **გარანტია არის მინიმუმი, არა ლიმიტი.** სენდბოქსი 4 გარანტირებული vCPU-ით მაინც აღწევს 16-ს, როდესაც ბირთვები თავისუფალია. კონკურენციის პირობებში, თითოეული სენდბოქსი იღებს CPU-ს თავისი გარანტიის პროპორციულად.
- **ბილინგი ხდება მინიმუმის მიხედვით.** მოქმედი სენდბოქსისთვის ბილინგი ხდება გამოყენებული CPU-ს მიხედვით, მაგრამ არასდროს ნაკლები, ვიდრე მისი გარანტია.
- **სენდბოქსი ინარჩუნებს თავის გარანტიას სიცოცხლის განმავლობაში.** მის შესაცვლელად, შექმენით ახალი სენდბოქსი.
- **macOS სენდბოქსებს ყოველთვის აქვთ მთლიანი ფორმა**, ამიტომ ისინი არ იღებენ გარანტიას.

### აირჩიეთ Xcode {#xcode}

ყოველი macOS სენდბოქსი აშენებს ერთ Xcode-ს, რომელსაც თქვენ ირჩევთ შექმნისას. ის იტვირთება იმავე იმიჯით, რაც <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link> პროფილი ამ Xcode-ისთვის, ამიტომ აგენტი აშენებს იმავე ინსტრუმენტებითა და სიმულატორებით, რაც თქვენი CI. tuist.dev-ზე, macOS სენდბოქსები ამჟამად სთავაზობენ:

- `26.6` (ნაგულისხმევი)
- `26.1.1`
- `27.0`
- `27.1`
- `27.2`

აირჩიეთ ერთი `xcode_version`-ით (`--xcode` CLI-ში), ზუსტი ვერსიის გამოყენებით, როგორც ეს runner პროფილები აკეთებენ:

| სად | როგორ |
| --- | --- |
| CLI | `tuist sandbox create --xcode 26.1.1` |
| API და MCP `create_sandbox` | `"xcode_version": "26.1.1"` |
| Tuist Mac პლაგინი Amp-ისთვის | `tuist_mac_start` `xcode`-ით |
| Amp orbs | orb-ის ტიპი `macos-xcode-26-1-1` (იხილეთ <.localized_link href="/guides/features/sandboxes/amp#xcode">Amp</.localized_link>) |
| Claude Code და Claude Managed Agents | `xcode_version` გარემოზე, ან თითოეული Managed Agents სესიისთვის (იხილეთ <.localized_link href="/guides/features/sandboxes/claude#xcode">Claude</.localized_link>) |

- **ვერსიის გარეშე**, Mac იღებს ნაგულისხმევს.
- **ვერსია, რომელსაც Tuist არ სთავაზობს, უარყოფილია**, ხოლო შეცდომაში ჩამოთვლილია ვერსიები, რომელთა არჩევაც შეგიძლიათ, რათა იცოდეთ, რა არის ხელმისაწვდომი ამჟამად.
- **Tuist არ კითხულობს თქვენი რეპოზიტორიის `.xcode-version`-ს.** ვერსიას თქვენ ან Mac-ის მომთხოვნი აგენტი ირჩევთ. MCP ინსტრუმენტი და Tuist Mac პლაგინი აგენტებს ეუბნებიან, რომ დაემთხვნენ პროექტის მიერ მიმაგრებულ ვერსიას.
- **სენდბოქსი ინარჩუნებს თავის Xcode-ს სიცოცხლის განმავლობაში.** სხვა Xcode-ით აშენებისთვის, შექმენით ახალი სენდბოქსი. `xcodebuild -version` აჩვენებს, თუ რომელ Xcode-ს აშენებს Mac.

## უსაფრთხოება {#security}

- ყოველი სენდბოქსი არის საკუთარი ვირტუალური მანქანა. სენდბოქსები ერთმანეთთან ან CI დავალებებთან არ იზიარებენ ფაილურ სისტემას, მეხსიერებას ან პროცესებს.
- სენდბოქსები ეკუთვნის ანგარიშს და მისი ნებისმიერი წევრი შეუძლია მათი გამოყენება და მართვა, ინტეგრაციის მომსახურე სენდბოქსების ჩათვლით. ინტეგრაციებს მხოლოდ ადმინისტრატორები აკავშირებენ. ინტეგრაციიდან წამოსული სესიები მხოლოდ იმ ანგარიშის სენდბოქსებს აღწევენ, რომელთანაც ინტეგრაციაა დაკავშირებული.
- მონაცემები, რომლებსაც Tuist-ს აწვდით ინტეგრაციის დასაკავშირებლად, როგორიცაა Amp პროვაიდერის ტოკენი ან Claude გარემოს გასაღები, ინახება დაშიფრული და აღარასდროს ჩანდება.
- სენდბოქსს შეუძლია ინტერნეტთან წვდომა. მოეპყარით იმას, რასაც აგენტი მისგან წვდება ისე, როგორც CI დავალებას.
