# სენდბოქსები {#sandboxes}

> [!IMPORTANT]
> **მხოლოდ მოწვევით**
>
> Tuist Sandboxes, როგორც Linux-ზე, ისე macOS-ზე, ამჟამად ხელმისაწვდომია მხოლოდ მოწვევით, სანამ ჩვენ გავზრდით სიმძლავრეს. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [საზოგადოების Slack-ში](https://slack.tuist.dev), რათა მოითხოვოთ წვდომა თქვენი ანგარიშისთვის. ფასები გამოცხადდება, როდესაც Sandboxes ზოგად ხელმისაწვდომობას მიიღებს.

სენდბოქსი არის ვირტუალური მანქანა, სადაც კოდირების აგენტი ასრულებს ბრძანებებს და არედაქტირებს ფაილებს. აგენტის თითოეულ სესიას ენიჭება საკუთარი სენდბოქსი, რომელიც ინახავს მის გადმოწერილ კოდს, აწყობის პროდუქტებსა და დაინსტალირებულ ინსტრუმენტებს სესიის განმავლობაში. როდესაც აგენტი უმოქმედო ხდება, სენდბოქსი ჩერდება; შემდეგი შეტყობინება აღადგენს მას იქიდან, სადაც შეჩერდა.

სენდბოქსები მუშაობენ იმავე ინფრასტრუქტურაზე, რაზეც <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link>, თქვენი გუნდის <.localized_link href="/guides/features/cache">ქეშთან</.localized_link> ერთად, რათა აგენტის აწყობებმა შეძლოს იმავე ქეშირებული არტიფაქტების გამოყენება, რასაც თქვენი CI და ადგილობრივი მანქანები იყენებენ.

შეგიძლიათ გამოიყენოთ სენდბოქსები:

- **<.localized_link href="/guides/features/sandboxes/amp">Amp</.localized_link>**: გაუშვით თქვენი Amp სამუშაო სივრცის orbs Tuist-ზე, ან მიანიჭეთ ნებისმიერ Amp ძაფს Mac Xcode აწყობებისთვის <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინის</.localized_link> საშუალებით.
- **<.localized_link href="/guides/features/sandboxes/claude">Claude</.localized_link>**: გაუშვით Claude Managed Agents სესიები და Claude Code ღრუბლოვანი სესიები (claude.ai, დესკტოპისა და მობილური აპლიკაციები, და `claude --cloud`) Tuist-ზე.
- **[Tuist CLI](#cli)**: შექმენით სენდბოქსები და გაუშვით ბრძანებები მათში თქვენი ტერმინალიდან, ან თქვენი საკუთარი ინსტრუმენტებიდან API-ის საშუალებით.

## დაიწყეთ CLI-ით {#cli}

შექმენით სენდბოქსი და გაუშვით ბრძანებები მასში თქვენი ტერმინალიდან `tuist sandbox`-ის საშუალებით.

### 1. შესვლა {#cli-log-in}

სენდბოქსების მართვა მოითხოვს ანგარიშის ადმინისტრატორს:

```bash
tuist auth login
```

### 2. სენდბოქსის შექმნა {#cli-create}

```bash
tuist sandbox create --platform macos
```

გამოტოვეთ `--platform` Linux-ისთვის. გადაეცით `--vcpus` `--memory-gb`-თან ერთად უფრო დიდი [კონფიგურაციისთვის](#platforms), და `--workspace-gb` უფრო დიდი დისკისთვის. ბრძანება ბრუნდება, როდესაც სენდბოქსი გაშვებულია და ბეჭდავს მის დეტალებს, მათ შორის ID-ს. ის იყენებს მიმდინარე დირექტორიაში არსებული Tuist პროექტის ანგარიშს; გადაეცით `--account` სხვის არჩევას.

### 3. ბრძანებების გაშვება {#cli-exec}

```bash
tuist sandbox exec <sandbox-id> -- xcodebuild -version
```

ბრძანება სრულდება `bash -l`-ით სენდბოქსში, რომელიც ჯერ აღდგება, თუ შეჩერებულია. `tuist` აწვდის მის გამოსავალს, რამდენი ხანიც არ უნდა გაგრძელდეს და სრულდება ბრძანების სტატუსით; Ctrl-C აუქმებს მას სენდბოქსში. გადაეცით `--cwd`, `--env NAME=VALUE` და `--timeout` (ექვს საათამდე) საჭიროების შემთხვევაში.

### ჩვეულებრივი ამოცანები {#cli-tasks}

| ამოცანა | ბრძანება |
| --- | --- |
| სენდბოქსების სია | `tuist sandbox list` |
| ერთის ჩვენება | `tuist sandbox show <id>` |
| შეჩერება ან აღდგენა | `tuist sandbox pause <id>`, `tuist sandbox resume <id>` |
| ადგილობრივი Git worktree-ის ფაილების ასახვა მასში | `tuist sandbox sync <id>` |
| ფაილების კოპირება გარეთ ან შიგნით | `tuist sandbox cp <id>:<path> <local-path>`, `tuist sandbox cp <local-path> <id>:<path>` |
| წაშლა | `tuist sandbox delete <id> --yes` |
| გამოყენების ნახვა | `tuist sandbox analytics` |

დაამატეთ `--json` მანქანისთვის წაკითხვადი გამოსავლისთვის. იხილეთ <.localized_link href="/cli/sandbox">CLI ცნობარი</.localized_link> ყველა პარამეტრისთვის. სენდბოქსების კოდიდან მართვის ნაცვლად, გამოიყენეთ იგივე ოპერაციები [Tuist API](https://tuist.dev/api/docs)-ის საშუალებით `/api/accounts/{account_handle}/sandboxes`-ის ქვეშ, ან მიეცით აგენტს მათი გამოყენების საშუალება <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>-ის საშუალებით.

ინსტრუმენტებს, რომლებსაც არ შეუძლიათ ინტერაქტიული შესვლა, მაგალითად აგენტის პლაგინს, რომელიც აწყობს macOS სენდბოქსში, შეუძლია ავთენტიკაცია <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენით</.localized_link> `account:sandboxes:write` სკოპით. მას შეუძლია შექმნას სენდბოქსები, გაუშვას მათში ბრძანებები, შეაჩეროს, აღადგინოს და წაშალოს ისინი, როგორც ანგარიშის წევრს. სენდბოქსები, რომლებიც ემსახურებიან Amp ან Claude ინტეგრაციას, ანალიტიკას და ინტეგრაციის პარამეტრებს, რჩებიან ანგარიშის ადმინისტრატორებთან.

### Tuist სენდბოქსის შიგნით {#tuist-in-sandbox}

სენდბოქსის გამოსახულებები არ შეიცავს Tuist CLI-ს, ამიტომ გაშვებულია თქვენი პროექტის საკუთარი მიმაგრებული ვერსია. პირველი `tuist sandbox sync`-ის შემდეგ, გაუშვით `mise install` რეპოზიტორიის ფესვში სენდბოქსზე (`mise` და `brew` დაინსტალირებულია), შემდეგ გაუშვით `tuist` mise-ის საშუალებით, მაგალითად `$HOME/.local/share/mise/shims`-ით `PATH`-ზე.

ყოველ ბრძანებას, რომელსაც იწყებთ `tuist sandbox exec`-ით, ასევე აქვს ის, რაც Tuist runner-ს აქვს, ამიტომ სენდბოქსში აწყობები იყენებენ თქვენი ანგარიშის <.localized_link href="/guides/features/cache">ქეშს</.localized_link> თქვენს მიერ რწმუნებების გადაცემის გარეშე:

- `TUIST_URL` და, იქ, სადაც სენდბოქსის ჰოსტი აღწევს მას, მაგალითად macOS-ზე, `TUIST_CACHE_ENDPOINT` იმავე რაკში არსებული ქეშის.
- `TUIST_OIDC_TOKEN`, მოკლე ვადიანი იდენტობის ტოკენი ამ ბრძანებისთვის. Tuist CLI 4.218.0 და უფრო ახალი ვერსიები თავისთავად შედიან მისით; 4.215.0-დან 4.217.x-მდე ვერსიებში, ჯერ გაუშვით `tuist auth login` იმავე ბრძანებაში.

ტოკენი იქმნება ყოველი ბრძანებისთვის და შეიძლება გაცვლილ იქნას Tuist ტოკენზე მხოლოდ მაშინ, როდესაც ეს ბრძანება სრულდება, ამიტომ სენდბოქსი არასდროს ინახავს ხანგრძლივი ვადის რწმუნებას. ის არასდროს ანიჭებს მეტს, ვიდრე პირს ან ტოკენს, რომელმაც დაიწყო ბრძანება, შეუძლია გააკეთოს ქეშთან: ანგარიშის წევრებს, რომელთა ქეშის ტოკენებსაც მხოლოდ ჩაწერა შეუძლიათ, ენიჭებათ წაკითხვის წვდომა, და ანგარიშის ტოკენს სჭირდება ქეშის სკოპები, როგორიცაა `ci`, `account:sandboxes:write`-თან ერთად, რათა სენდბოქსმა საერთოდ გამოიყენოს ქეში. ცვლადები, რომლებსაც გადასცემთ `--env`-ით, აქვთ უპირატესობა.

## აწყობა Mac-ზე კოდირების აგენტიდან {#coding-agents}

კოდირების აგენტს, რომელიც მუშაობს Linux-ზე, მაგალითად ღრუბლოვანი აგენტის სესიას, შეუძლია ააწყოს, შეამოწმოს და გაუშვას Apple პლატფორმის კოდი macOS სენდბოქსზე, სანამ ის აგრძელებს ფაილების რედაქტირებას იქ, სადაც მუშაობს. Amp-ში, დააინსტალირეთ <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინი</.localized_link>. სხვა აგენტებისთვის, როგორიცაა Claude Code ან Cursor:

1. დააკავშირეთ აგენტი Tuist <.localized_link href="/guides/features/agentic-coding/mcp">MCP სერვერთან</.localized_link>. მისი `create_sandbox` ინსტრუმენტი ეუბნება აგენტს, თუ როგორ მართოს Mac.
2. დააინსტალირეთ Tuist CLI იქ, სადაც აგენტი მუშაობს, მაგალითად გარემოს setup სკრიპტში: `mise use -g tuist@latest`, ან `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist` (`tuist-linux-aarch64` ARM-ზე).
3. მოახდინეთ CLI-ის ავთენტიკაცია. MCP სერვერის შესვლა არ გადადის მასზე, ამიტომ ან გაუშვით `tuist auth login` როგორც ანგარიშის წევრმა, ან დააყენეთ `TUIST_TOKEN` <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენზე</.localized_link> `account:sandboxes:write` სკოპით.
4. თუ გარემო ზღუდავს ქსელურ წვდომას, დაუშვით `tuist.dev`. CLI ამის საშუალებით ატვირთავს ფაილებს Mac-ზე, ამიტომ სხვა დომენი არ სჭირდება.

აგენტი თითოეული ამოცანისთვის ქმნის ერთ Mac-ს და ყოველი ბრძანების შესრულებამდე ასრულებს `tuist sandbox sync`-ს. ის აკოპირებს ფაილებს, რომლებსაც Git არ იგნორირებს (მიუხედავად იმისა, არის თუ არა ისინი კომიტებული), ხოლო შემდეგ მხოლოდ შეცვლილ ფაილებს. პირველი სინქრონიზაციის შემდეგ ის ასრულებს `mise install`-ს რეპოზიტორიის ძირში Mac-ზე, რათა [პროექტის მიმაგრებული Tuist](#tuist-in-sandbox) იყოს იქ, შესული თქვენი ანგარიშის ქეშში. შემდეგ აგენტი ასრულებს ისეთ ბრძანებებს, როგორიცაა `xcodebuild`, `tuist sandbox exec`-ის საშუალებით, აკოპირებს შედეგებს, როგორიცაა ეკრანის ანაბეჭდები ან აწყობილი აპლიკაცია, უკან `tuist sandbox cp`-ის საშუალებით და შლის Mac-ს, როდესაც ამოცანა დასრულდება. Mac მუშაობას აგრძელებს ბოლო ბრძანებიდან 10 წუთის განმავლობაში, რათა შემდეგი მაშინვე დაიწყოს; `tuist sandbox pause` უფრო სწრაფად აბრუნებს მას. მიტოვებული Mac ჩერდება და იშლება 14 დღის გაჩერების შემდეგ.

## Linux და macOS {#platforms}

**Linux** სენდბოქსები მუშაობენ Ubuntu 24.04-ზე:

- 2 vCPU, 4 GiB RAM (ნაგულისხმევი)
- 4 vCPU, 8 GiB RAM
- 8 vCPU, 16 GiB RAM

## უსაფრთხოება {#security}

- ყოველი სენდბოქსი არის ცალკეული ვირტუალური მანქანა. სენდბოქსები არ იზიარებენ ფაილურ სისტემას, მეხსიერებას ან პროცესებს ერთმანეთთან ან CI სამუშაოებთან.
- სენდბოქსები ეკუთვნის ანგარიშს და მათ მართვა მხოლოდ მის ადმინისტრატორებს შეუძლიათ. ინტეგრაციიდან მომავალი სესიები მხოლოდ იმ ანგარიშის სენდბოქსებს აღწევს, რომელთანაც ინტეგრაციაა დაკავშირებული.
- მონაცემები, რომლებსაც Tuist-ს აწვდით ინტეგრაციის დასაკავშირებლად, როგორიცაა Amp პროვაიდერის ტოკენი ან Claude გარემოს გასაღები, ინახება დაშიფრული და აღარასდროს გამოჩნდება.
- სენდბოქსს შეუძლია ინტერნეტთან წვდომა. მოეპყარით იმას, რასაც აგენტს შეუძლია იქიდან წვდომა, ისე, როგორც მოეპყრებოდით CI სამუშაოს.
