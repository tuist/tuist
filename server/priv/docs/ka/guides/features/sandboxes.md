# სენდბოქსები {#sandboxes}

> [!IMPORTANT]
> **მხოლოდ მოწვევით**
>
> Tuist Sandboxes, როგორც Linux-ის, ისე macOS-ის ვერსიები, ამჟამად ხელმისაწვდომია მხოლოდ მოწვევით, სანამ ჩვენ გავზრდით შესაძლებლობებს. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [საზოგადოების Slack-ში](https://slack.tuist.dev), რათა მოითხოვოთ წვდომა თქვენი ანგარიშისთვის. ფასები გამოცხადდება, როდესაც Sandboxes ზოგადი ხელმისაწვდომობის ეტაპზე გადავა.

სენდბოქსი არის ვირტუალური მანქანა, სადაც კოდირების აგენტი ასრულებს ბრძანებებს და არედაქტირებს ფაილებს. აგენტის თითოეულ სესიას ენიჭება საკუთარი სენდბოქსი, რომელიც ინახავს მის checkout-ს, აგების პროდუქტებსა და დაინსტალირებულ ინსტრუმენტებს სესიის განმავლობაში. როდესაც აგენტი უმოქმედო მდგომარეობაში გადადის, სენდბოქსი ჩერდება; შემდეგი შეტყობინება აღადგენს მას იქიდან, სადაც გაჩერდა.

სენდბოქსები მუშაობენ იმავე ინფრასტრუქტურაზე, რაზეც <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link>, თქვენი გუნდის <.localized_link href="/guides/features/cache">ქეშთან</.localized_link> ერთად, რათა აგენტის აგებებმა შეძლონ იმავე ქეშირებული არტეფაქტების გამოყენება, რასაც თქვენი CI და ლოკალური მანქანები იყენებენ.

სენდბოქსების გამოყენება შეგიძლიათ:

- **<.localized_link href="/guides/features/sandboxes/amp">Amp</.localized_link>**: გაუშვით თქვენი Amp სამუშაო სივრცის orbs Tuist-ზე, ან მიანიჭეთ ნებისმიერ Amp ძაფს Mac Xcode-ის აგებებისთვის <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინის</.localized_link> მეშვეობით.
- **<.localized_link href="/guides/features/sandboxes/claude">Claude</.localized_link>**: გაუშვით Claude Managed Agents სესიები და Claude Code ღრუბლოვანი სესიები (claude.ai, დესკტოპისა და მობილური აპლიკაციები და `claude --cloud`) Tuist-ზე.
- **[Tuist CLI](#cli)**: შექმენით სენდბოქსები და გაუშვით ბრძანებები მათში თქვენი ტერმინალიდან ან თქვენი საკუთარი ინსტრუმენტებიდან API-ს მეშვეობით.

## დაიწყეთ CLI-ით {#cli}

შექმენით სენდბოქსი და გაუშვით ბრძანებები მასში თქვენი ტერმინალიდან `tuist sandbox`-ის მეშვეობით.

### 1. შესვლა {#cli-log-in}

ანგარიშის ნებისმიერ წევრს შეუძლია შექმნას და მართოს მისი სენდბოქსები:

```bash
tuist auth login
```

### 2. სენდბოქსის შექმნა {#cli-create}

```bash
tuist sandbox create --platform macos
```

გამოტოვეთ `--platform` Linux-ისთვის. გადაეცით `--xcode` ვერსიით, მაგალითად `--xcode 26.1.1`, Mac-ისთვის იმავე [Xcode](#xcode)-ით; ეს გულისხმობს `--platform macos`-ს. გადაეცით `--vcpus` `--memory-gb`-თან ერთად უფრო დიდი [კონფიგურაციისთვის](#platforms), `--guaranteed-vcpus` Linux სენდბოქსისთვის მეტი [CPU](#guaranteed-cpu)-ის გარანტიის მისაღებად და `--workspace-gb` უფრო დიდი დისკისთვის. სენდბოქსი მუშაობს ორი საათის განმავლობაში შექმნიდან და ასევე თითოეული აღდგენიდან; გადაეცით `--lifetime-minutes` 5 წუთიდან ერთ დღემდე დიაპაზონისთვის. როდესაც მისი სიცოცხლის ხანგრძლივობა იწურება, მისი შესრულებადი ბრძანებები წყდება და ის ჩერდება და არქივირდება, ფაილების შენარჩუნებით, რათა მივიწყებულმა სენდბოქსმა შეწყვიტოს თქვენი ანგარიშის რესურსების გამოყენება. ბრძანება ბრუნდება, როდესაც სენდბოქსი გაშვებულია და ბეჭდავს მის დეტალებს, მათ შორის მის ID-ს. როდესაც ყველა ჰოსტი დაკავებულია, მაგალითად, როდესაც CI დავალებები იკავებენ გაზიარებულ Mac-ებს, სერვერი ელოდება 25 წამს ერთ-ერთის გათავისუფლებას, სანამ შექმნა ჩავარდება `fleet_busy`-ით; გადაეცით `--wait-timeout 5m` ცდების გასაგრძელებლად 5 წუთის განმავლობაში (მაქსიმუმ ერთი საათი), მიზეზის stderr-ზე დაახლოებით წუთში ერთხელ გამეორებით. ის იყენებს მიმდინარე დირექტორიაში არსებული Tuist პროექტის ანგარიშს; გადაეცით `--account` სხვის არჩევას.

### 3. ბრძანებების შესრულება {#cli-exec}

```bash
tuist sandbox exec <sandbox-id> -- xcodebuild -version
```

ბრძანება სრულდება `bash -l`-ით სენდბოქსში, რომელიც ჯერ აღდგება, თუ ის შეჩერებულია. `tuist` აგზავნის მის გამომავალ მონაცემებს მთელი შესრულების განმავლობაში და სრულდება ბრძანების სტატუსით; Ctrl-C აუქმებს მას სენდბოქსში. გადაეცით `--cwd`, `--env NAME=VALUE` და `--timeout` (ექვს საათამდე) საჭიროების შემთხვევაში.

ბრძანება სრულდება `tuist`-გან დამოუკიდებლად, რითაც ის უძლებს კავშირის გაწყვეტას. ხანგრძლივი აგების ჩასატევად დროის ლიმიტიანი ინსტრუმენტის გამოძახებაში, მაგალითად აგენტის, გადაეცით `--wait <seconds>`: როდესაც ისინი ჯერ გაივლიან, `tuist` ტოვებს ბრძანებას შესრულებადს, სრულდება 75 კოდით და ბეჭდავს `tuist sandbox exec <sandbox-id> --attach <command-id> --stdout-offset … --stderr-offset …` ბრძანებას, რომელიც აგრძელებს მის გამომავალ მონაცემებს იქიდან, სადაც გაჩერდა და სრულდება ბრძანების სტატუსით.

### ჩვეულებრივი ამოცანები {#cli-tasks}

| ამოცანა | ბრძანება |
| --- | --- |
| სენდბოქსების სია | `tuist sandbox list` |
| ერთის ჩვენება | `tuist sandbox show <id>` |
| შეჩერება ან აღდგენა | `tuist sandbox pause <id>`, `tuist sandbox resume <id>` |
| შეინარჩუნეთ შესრულება ვადის გასვლის შემდეგ | `tuist sandbox extend <id> --lifetime-minutes 240` |
| ლოკალური Git worktree-ის ფაილების ასახვა მასში | `tuist sandbox sync <id>` |
| გაშვებული iOS Simulator-ის ან macOS სენდბოქსის მთელი ეკრანის სქრინშოტი | `tuist sandbox screenshot <id> --out shot.png`, `tuist sandbox screenshot <id> --screen --out screen.png` |
| ფაილების კოპირება გარეთ ან შიგნით | `tuist sandbox cp <id>:<path> <local-path>`, `tuist sandbox cp <local-path> <id>:<path>` |
| წაშლა | `tuist sandbox delete <id> --yes` |
| გამოყენების ნახვა | `tuist sandbox analytics` |

დაამატეთ `--json` მანქანისთვის წასაკითხი გამომავალი მონაცემებისთვის. იხილეთ <.localized_link href="/cli/sandbox">CLI-ის ცნობარი</.localized_link> ყველა პარამეტრისთვის. სენდბოქსების კოდიდან მართვისთვის, გამოიყენეთ იგივე ოპერაციები [Tuist API](https://tuist.dev/api/docs)-ს მეშვეობით `/api/accounts/{account_handle}/sandboxes`-ქვეშ, ან მიეცით აგენტს მათი გამოყენების საშუალება <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>-ის მეშვეობით.

ინსტრუმენტებს, რომლებსაც არ შეუძლიათ ინტერაქტიული შესვლა, მაგალითად აგენტის პლაგინს, რომელიც აგებს macOS სენდბოქსში, შეუძლიათ ავთენტიკაცია <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენით</.localized_link> `account:sandboxes:write` სკოუპით. მას შეუძლია გააკეთოს ის, რაც ანგარიშის წევრს: შექმნას სენდბოქსები, გაუშვას ბრძანებები მათში და შეაჩეროს, აღადგინოს, დააარქივოს და წაშალოს ისინი. ინტეგრაციის პარამეტრები და ბრძანებების შესრულება ინტეგრაციის მსახურე სენდბოქსებში რჩება ანგარიშის ადმინისტრატორების პრეროგატივა.

### Tuist სენდბოქსის შიგნით {#tuist-in-sandbox}

macOS სენდბოქსები მოყვება Tuist CLI-ით. როდესაც თქვენი პროექტი ამაგრებს Tuist-ს mise-ის მეშვეობით (`mise.toml` ან `.tool-versions`), `tuist` ასრულებს იმ ვერსიას, რომელიც ინსტალირდება პირველად, როდესაც ბრძანებას დასჭირდება. ყველა ბრძანება, რომელსაც იწყებთ `tuist sandbox exec`-ით, აქვს mise-ის shims (`$HOME/.local/share/mise/shims`) პირველ ადგილზე `PATH`-ში და გამოსახულების Tuist ბოლოს, რათა `tuist` და თქვენი სხვა mise ინსტრუმენტები შესრულდნენ თქვენს ბრძანებებში და Xcode აგების ეტაპებში, მაგალითად სქემის post-actions-ში. თითოეულ Mac-ს ასევე აქვს გზამკვლევი კოდირების აგენტებისთვის `/opt/tuist/agent-guide.md`-ზე, გენერირებული მისი გამოსახულებიდან: მისი Xcode და სიმულატორები, სად არის რეპოზიტორია და რას შეიცავს მზადყოფნის სნეპშოტი. Claude Code, Codex და Amp, რომლებიც მუშაობენ Mac-ზე, პოულობენ მას მათი ინსტრუქციის ფაილებიდან.

ყველა ბრძანება, რომელსაც იწყებთ `tuist sandbox exec`-ით, ასევე იღებს იმას, რასაც Tuist runner იღებს, რითაც სენდბოქსში აგებები იყენებენ თქვენი ანგარიშის <.localized_link href="/guides/features/cache">ქეშს</.localized_link> თქვენი მხრიდან სერთიფიკატების გადაცემის გარეშე:

- `TUIST_URL` და, სადაც სენდბოქსის ჰოსტი აღწევს მას, მაგალითად macOS-ზე, იმავე რეკში არსებული ქეშის `TUIST_CACHE_ENDPOINT`.
- `TUIST_OIDC_TOKEN`, მოკლევადიანი იდენტობის ტოკენი იმ ბრძანებისთვის. Tuist CLI 4.218.0 და უფრო ახალი ვერსიები თავისთავად ავთენტიკაციას აკეთებენ მისით; 4.215.0-დან 4.217.x-მდე ვერსიებში, ჯერ გაუშვით `tuist auth login` იმავე ბრძანებაში.

ტოკენი იჭედება თითოეული ბრძანებისთვის და შეიძლება გაცვლილი იქნას Tuist ტოკენზე მხოლოდ იმ ბრძანების შესრულებისას, რითაც სენდბოქსი არასდროს ინახავს ხანგრძლივი ვადის სერთიფიკატს. ის არასდროს ანიჭებს იმაზე მეტს, ვიდრე პირს ან ტოკენს, რომელმაც დაიწყო ბრძანება, შეუძლია გააკეთოს ქეშთან: ანგარიშის წევრები, რომელთა ქეშის ტოკენებსაც მხოლოდ ჩაწერა შეუძლიათ, იღებენ წაკითხვის წვდომას, და ანგარიშის ტოკენს სჭირდება ქეშის სკოუპები, მაგალითად `ci`, `account:sandboxes:write`-თან ერთად, რათა სენდბოქსმა საერთოდ გამოიყენოს ქეში. ცვლადები, რომლებსაც გადასცემთ `--env`-ით, აქვთ უპირატესობა.

## აგება Mac-ზე კოდირების აგენტიდან {#coding-agents}

კოდირების აგენტს, რომელიც მუშაობს Linux-ზე, მაგალითად ღრუბლოვანი აგენტის სესიას, შეუძლია ააგოს, შეამოწმოს და გაუშვას Apple-პლატფორმის კოდი macOS სენდბოქსზე, სანამ ის აგრძელებს ფაილების რედაქტირებას იქ, სადაც მუშაობს. Amp-ში, დააინსტალირეთ <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინი</.localized_link>. სხვა აგენტებისთვის, მაგალითად Claude Code ან Cursor:

1. დააკავშირეთ აგენტი Tuist-ის <.localized_link href="/guides/features/agentic-coding/mcp">MCP სერვერთან</.localized_link>. მისი `create_sandbox` ინსტრუმენტი ეუბნება აგენტს, თუ როგორ უმართოს Mac-ს.
2. დააინსტალირეთ Tuist CLI იქ, სადაც აგენტი მუშაობს, მაგალითად, გარემოს დაყენების სკრიპტში: `mise use -g tuist@latest`, ან `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist` (`tuist-linux-aarch64` ARM-ზე).
3. მოახდინეთ CLI-ის ავთენტიკაცია. MCP სერვერის შესვლა არ გადაეცემა მას, ამიტომ ან გაუშვით `tuist auth login` როგორც ანგარიშის წევრმა, ან დააყენეთ `TUIST_TOKEN` <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენზე</.localized_link> `account:sandboxes:write` სკოუპით.
4. თუ გარემო ზღუდავს ქსელურ წვდომას, ნება დართეთ `tuist.dev`. CLI მის საშუალებით ატვირთავს ფაილებს Mac-ზე, ამიტომ სხვა დომენი არ სჭირდება.
5. სურვილისამებრ, ნება დართეთ აგენტს შექმნას და წაშალოს Mac-ები ყოველ ჯერზე კითხვის გარეშე. აგენტები იკითხავენ `create_sandbox`-ის გამოძახებამდე, რადგან Mac ითვლება თქვენი ანგარიშის ლიმიტებში, და `delete_sandbox`-მდე, რადგან მისი გაუქმება შეუძლებელია. Claude Code-ში, ნება დართეთ ორივე `.claude/settings.json`-ში, MCP სერვერის რეგისტრაციის სახელის გამოყენებით (აქ `tuist`):

   ```json
   {
     "permissions": {
       "allow": ["mcp__tuist__create_sandbox", "mcp__tuist__delete_sandbox"]
     }
   }
   ```

იმისთვის, რომ აგენტმა მოახდინოს დაყენება, მიეცით მას ეს მოთხოვნა:

```text
Set up this environment so you can build and test this project on a Tuist macOS sandbox.

Read https://tuist.dev/en/docs/guides/features/sandboxes#coding-agents and follow its "Build on a Mac from a coding agent" section. It's the current Tuist guide for this, so prefer it over anything you remember about Tuist.

You're done when you have created a Mac with create_sandbox, synced this repository to it with tuist sandbox sync, run the project's build there with tuist sandbox exec, and deleted the Mac.

Ask me before anything that needs my login or approval, such as tuist auth login. If a step fails or is blocked, stop and tell me which step you reached and the exact error, without secrets.
```

აგენტი ქმნის ერთ Mac-ს თითოეული ამოცანისთვის, პროექტის მიერ მიბმული [Xcode](#xcode)-ით: `create_sandbox` ჩამოთვლის ხელმისაწვდომ Xcode-ებს და ეუბნება აგენტს, წაიკითხოს პროექტის მიბმა, მაგალითად `.xcode-version`. ყოველი ბრძანების წინ ის ასრულებს `tuist sandbox sync`. ის აკოპირებს ფაილებს, რომლებსაც Git არ იგნორირებს, ჩაკომიტებულს თუ არა, ხოლო შემდეგ მხოლოდ შეცვლილებს. Mac-ს უკვე აქვს [Tuist](#tuist-in-sandbox), პროექტის მიბმული ვერსია, თუ ასეთი არსებობს, შესული თქვენი ანგარიშის ქეშში, და აგენტი ერთხელ კითხულობს Mac-ის სახელმძღვანელოს. შემდეგ აგენტი ასრულებს ბრძანებებს, როგორიცაა `xcodebuild`, `tuist sandbox exec`-ის საშუალებით, აშვებს აპლიკაციას Simulator-ში და გაჩვენებთ მას MCP სერვერის `get_sandbox_screenshot` ან `tuist sandbox screenshot`-ის საშუალებით, აკოპირებს შედეგებს, როგორიცაა აგებული აპლიკაცია, უკან `tuist sandbox cp`-ით და შლის Mac-ს, როცა ამოცანა დასრულდება. Mac მუშაობას აგრძელებს 10 წუთის განმავლობაში ბოლო ბრძანების შემდეგ, რათა შემდეგი მაშინვე დაიწყოს; `tuist sandbox pause` უფრო სწრაფად აბრუნებს მას. დარჩენილი Mac იყინება, არქივირდება მისი ორსაათიანი სიცოცხლის ციკლის დასრულებისას და იშლება 14 დღის შემდეგ; აგენტი აგრძელებს სიცოცხლის ციკლს გრძელი აგებამდე.

## Linux და macOS {#platforms}

**Linux** სენდბოქსები მუშაობენ Ubuntu 24.04-ზე. ყოველ Linux სენდბოქსს აქვს 16 vCPU და იყენებს მასპინძელი მანქანის თავისუფალ ბირთვებს, ამიტომ მისი ფორმა განსაზღვრავს მეხსიერებას:

- 2 GiB RAM (`--vcpus 1 --memory-gb 2`)
- 4 GiB RAM (`--vcpus 2 --memory-gb 4`, ნაგულისხმევი)
- 8 GiB RAM (`--vcpus 4 --memory-gb 8`)
- 16 GiB RAM (`--vcpus 8 --memory-gb 16`)
- 32 GiB RAM (`--vcpus 16 --memory-gb 32`)
- 44 GiB RAM (`--vcpus 16 --memory-gb 44`)

**macOS** სენდბოქსები მუშაობენ Apple silicon-ზე Xcode-ით:

- 8 vCPU, 8 GiB RAM (ნაგულისხმევი)
- 8 vCPU, 16 GiB RAM
- 8 vCPU, 24 GiB RAM

### გარანტირებული CPU {#guaranteed-cpu}

Linux სენდბოქსს გარანტირებული აქვს vCPU-ის მეოთხედი მეხსიერების ყოველ GiB-ზე, მაგალითად 2 vCPU 8 GiB-ისთვის, და იყენებს დამატებით რესურსებს, რამდენიც თავისუფალია მასპინძელ მანქანაზე, 16 vCPU-მდე. ეს შეესაბამება აგენტს, რომელიც ძირითადად ელოდება და შემდეგ აგებს პიკურ რეჟიმში. როდესაც აგებას სჭირდება უფრო სტაბილური CPU მაშინაც კი, როცა მანქანა დატვირთულია, შეუქმენით მას გარანტია 1, 2, 4 ან 8 vCPU სენდბოქსის შექმნისას; ის მიიღებს უფრო დიდს ამ გარანტიასა და მეხსიერების გარანტიას შორის:

| სად | როგორ |
| --- | --- |
| CLI | `tuist sandbox create --guaranteed-vcpus 4` |
| API და MCP `create_sandbox` | `"guaranteed_vcpus": 4` |

- **გარანტია არის მინიმუმი, არა მაქსიმუმი.** სენდბოქსს 4 გარანტირებული vCPU-ით მაინც შეუძლია ავიდეს 16-მდე, როცა ბირთვები თავისუფალია. კონკურენციის პირობებში, ყოველი სენდბოქსი იღებს CPU-ს თავისი გარანტიის პროპორციულად.
- **ის ირიცხება როგორც მინიმუმი.** მომუშავე სენდბოქსი ირიცხება გამოყენებული CPU-სთვის, მაგრამ არასდროს ნაკლებად, ვიდრე მისი გარანტია.
- **სენდბოქსი ინარჩუნებს თავის გარანტიას სიცოცხლის ბოლომდე.** მის შესაცვლელად, შექმენით ახალი სენდბოქსი.
- **macOS სენდბოქსებს ყოველთვის აქვთ მთლიანი ფორმა**, ამიტომ ისინი არ იღებენ გარანტიას.

### აირჩიეთ Xcode {#xcode}

ყოველი macOS სენდბოქსი აშვებს ერთ Xcode-ს, რომელსაც თქვენ ირჩევთ მისი შექმნისას. ის იტვირთება იმავე იმიჯით, რაც <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link>-ის პროფილი ამ Xcode-ისთვის, ამიტომ აგენტი აგებს იმავე ინსტრუმენტების ნაკრებით და სიმულატორებით, რაც თქვენი CI. tuist.dev-ზე, macOS სენდბოქსები ამჟამად გთავაზობენ:

- `26.6` (ნაგულისხმევი)
- `26.1.1`
- `27.0`
- `27.1`
- `27.2`

აირჩიეთ ერთი `xcode_version`-ით (`--xcode` CLI-ში), ზუსტი ვერსიის გამოყენებით, როგორც ეს აკეთებს რანერის პროფილები:

| სად | როგორ |
| --- | --- |
| CLI | `tuist sandbox create --xcode 26.1.1` |
| API და MCP `create_sandbox` | `"xcode_version": "26.1.1"` |
| Tuist Mac პლაგინი Amp-ისთვის | `tuist_mac_start` `xcode`-ით |
| Amp orbs | orb-ის ტიპი `macos-xcode-26-1-1` (იხილეთ <.localized_link href="/guides/features/sandboxes/amp#xcode">Amp</.localized_link>) |
| Claude Code და Claude Managed Agents | `xcode_version` გარემოზე, ან თითოეული Managed Agents სესიისთვის (იხილეთ <.localized_link href="/guides/features/sandboxes/claude#xcode">Claude</.localized_link>) |

- **ვერსიის მითითების გარეშე**, Mac იღებს ნაგულისხმევს.
- **Tuist-ის მიერ შეუთავაზებელი ვერსია უარყოფილია**, ხოლო შეცდომაში ჩამოთვლილია ვერსიები, რომელთა არჩევაც შეგიძლიათ, რათა იცოდეთ, რაა ხელმისაწვდომი ამჟამად.
- **Tuist არ კითხულობს თქვენი რეპოზიტორიის `.xcode-version`-ს.** ვერსიას თქვენ, ან აგენტი, რომელიც Mac-ს ითხოვს, ირჩევს. MCP ინსტრუმენტი და Tuist Mac პლაგინი ეუბნებიან აგენტებს, შეუსაბამონ პროექტის მიერ მიმაგრებული ვერსია.
- **სენდბოქსი ინარჩუნებს თავის Xcode-ს სიცოცხლის ბოლომდე.** სხვა Xcode-ით ასაწყობად, შექმენით ახალი სენდბოქსი. `xcodebuild -version` აჩვენებს, თუ რომელ Xcode-ს აშვებს Mac.

## უსაფრთხოება {#security}

- ყოველი სენდბოქსი არის საკუთარი ვირტუალური მანქანა. სენდბოქსები არ იზიარებენ ფაილურ სისტემას, მეხსიერებას ან პროცესებს ერთმანეთთან ან CI სამუშაოებთან.
- სენდბოქსები ეკუთვნის ანგარიშს და მისი ნებისმიერი წევრი შეუძლია მათი გამოყენება და მართვა. სენდბოქსები, რომლებიც ემსახურებიან ინტეგრაციას, მაგალითად Amp orb-ს ან Claude Code სესიას, ინახავენ ამ სესიის სამუშაოს და სერთიფიკატებს: წევრებს შეუძლიათ მათი ნახვა, შეჩერება, განახლება, არქივირება და წაშლა, მაგრამ მხოლოდ ადმინისტრატორებს შეუძლიათ მათში ბრძანებების გაშვება ან ფაილების ატვირთვა. ინტეგრაციებს მხოლოდ ადმინისტრატორები აკავშირებენ. ინტეგრაციიდან მომავალი სესიები მხოლოდ იმ ანგარიშის სენდბოქსებს აღწევენ, რომელთანაც ინტეგრაციაა დაკავშირებული.
- სერთიფიკატები, რომლებსაც Tuist-ს აწვდით ინტეგრაციის დასაკავშირებლად, მაგალითად Amp პროვაიდერის ტოკენი ან Claude გარემოს გასაღები, ინახება დაშიფრულად და აღარასდროს ჩანდება.
- სენდბოქსს შეუძლია ინტერნეტთან წვდომა. მოეპყარით იმას, რასაც აგენტს შეუძლია მისგან წვდომა, ისე, როგორც მოეპყრებოდით CI სამუშაოს.
