# სენდბოქსები {#sandboxes}

> [!IMPORTANT]
> **მხოლოდ მიწვევით**
>
> Tuist Sandboxes, როგორც Linux-ის, ისე macOS-ის ვერსიები, ამჟამად ხელმისაწვდომია მხოლოდ მიწვევით, სანამ ჩვენ გავზრდით შესაძლებლობებს. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [საზოგადოების Slack-ში](https://slack.tuist.dev), რათა მოითხოვოთ წვდომა თქვენი ანგარიშისთვის. ფასები გამოცხადდება, როდესაც Sandboxes ზოგად ხელმისაწვდომობას მიიღებს.

სენდბოქსი არის ვირტუალური მანქანა, სადაც კოდირების აგენტი ასრულებს ბრძანებებს და არედაქტირებს ფაილებს. თითოეულ აგენტის სესიას ენიჭება საკუთარი სენდბოქსი, რომელიც ინახავს მის ჩექაუთს, ბილდის პროდუქტებს და დაინსტალირებულ ინსტრუმენტებს სესიის განმავლობაში. როდესაც აგენტი უმოქმედო ხდება, სენდბოქსი ჩერდება; შემდეგი შეტყობინება აღადგენს მას იქიდან, სადაც გაჩერდა.

სენდბოქსები მუშაობენ იმავე ფლოტზე, რაზეც <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link>, თქვენი გუნდის <.localized_link href="/guides/features/cache">ქეშის</.localized_link> გვერდით, ასე რომ აგენტის ბილდებს შეუძლიათ გამოიყენონ იგივე ქეშირებული არტიფაქტები, რასაც თქვენი CI და ლოკალური მანქანები.

შეგიძლიათ გამოიყენოთ სენდბოქსები შემდეგიდან:

- **<.localized_link href="/guides/features/sandboxes/amp">Amp</.localized_link>**: გაუშვით თქვენი Amp სამუშაო სივრცის ორბები Tuist-ზე, ან მიანიჭეთ ნებისმიერ Amp ნაკადს Mac Xcode ბილდებისთვის <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინის</.localized_link> მეშვეობით.
- **<.localized_link href="/guides/features/sandboxes/claude">Claude</.localized_link>**: გაუშვით Claude Managed Agents სესიები და Claude Code ღრუბლოვანი სესიები (claude.ai, დესკტოპისა და მობილური აპები, და `claude --cloud`) Tuist-ზე.
- **[Tuist CLI](#cli)**: შექმენით სენდბოქსები და გაუშვით ბრძანებები მათში თქვენი ტერმინალიდან, ან თქვენი საკუთარი ინსტრუმენტებიდან API-ს მეშვეობით.

## დაიწყეთ CLI-ით {#cli}

შექმენით სენდბოქსი და გაუშვით ბრძანებები მასში თქვენი ტერმინალიდან `tuist sandbox`-ის მეშვეობით.

### 1. შესვლა {#cli-log-in}

ანგარიშის ნებისმიერ წევრს შეუძლია შექმნას და მართოს მისი სენდბოქსები:

```bash
tuist auth login
```

### 2. სენდბოქსის შექმნა {#cli-create}

```bash
tuist sandbox create --platform macos
```

გამოტოვეთ `--platform` Linux-ისთვის. გადაეცით `--xcode` ვერსიით, მაგალითად `--xcode 26.1.1`, Mac-ისთვის იმ [Xcode](#xcode)-ით; ეს გულისხმობს `--platform macos`-ს. გადაეცით `--vcpus` `--memory-gb`-თან ერთად უფრო დიდი [ფორმისთვის](#platforms), `--guaranteed-vcpus` Linux სენდბოქსისთვის მეტი [CPU](#guaranteed-cpu)-ის გარანტიისთვის, და `--workspace-gb` უფრო დიდი დისკისთვის. სენდბოქსი მუშაობს ორი საათის განმავლობაში შექმნიდან, და ასევე ყოველი აღდგენიდან; გადაეცით `--lifetime-minutes` 5 წუთიდან ერთ დღემდე შუალედისთვის. როდესაც მისი სიცოცხლის ხანგრძლივობა მთავრდება, მისი შემსრულებელი ბრძანებები იუქმდება და ის ჩერდება და არქივირდება, ფაილების შენარჩუნებით, ასე რომ მივიწყებული სენდბოქსი წყვეტს თქვენი ანგარიშის რესურსების გამოყენებას. ბრძანება ბრუნდება, როდესაც სენდბოქსი მუშაობს და ბეჭდავს მის დეტალებს, მათ შორის მის ID-ს. ის იყენებს მიმდინარე დირექტორიაში არსებული Tuist პროექტის ანგარიშს; გადაეცით `--account` სხვის არჩევისთვის.

### 3. ბრძანებების გაშვება {#cli-exec}

```bash
tuist sandbox exec <sandbox-id> -- xcodebuild -version
```

ბრძანება მუშაობს `bash -l`-ით სენდბოქსში, რომელიც ჯერ აღდგება, თუ ის გაჩერებულია. `tuist` აგზავნის მის გამონატანს, რამდენი ხანიც არ უნდა მუშაობდეს და გადის ბრძანების სტატუსით; Ctrl-C აუქმებს მას სენდბოქსში. გადაეცით `--cwd`, `--env NAME=VALUE` და `--timeout` (ექვს საათამდე) საჭიროებისამებრ.

ბრძანება მუშაობს `tuist`-ისგან დამოუკიდებლად, ასე რომ ის გადაიტანს კავშირის გაწყვეტას. ხანგრძლივი ბილდის ჩასასმელად ინსტრუმენტის გამოძახებაში დროის ლიმიტით, როგორიცაა აგენტის, გადაეცით `--wait <seconds>`: როდესაც ისინი ჯერ გაივლიან, `tuist` ტოვებს ბრძანებას შესრულების პროცესში, გადის 75-ით და ბეჭდავს `tuist sandbox exec <sandbox-id> --attach <command-id> --stdout-offset … --stderr-offset …` ბრძანებას, რომელიც აგრძელებს მის გამონატანს იქიდან, სადაც გაჩერდა და გადის ბრძანების სტატუსით.

### ჩვეულებრივი ამოცანები {#cli-tasks}

| ამოცანა | ბრძანება |
| --- | --- |
| სენდბოქსების ჩამოთვლა | `tuist sandbox list` |
| ერთის ჩვენება | `tuist sandbox show <id>` |
| შეჩერება ან აღდგენა | `tuist sandbox pause <id>`, `tuist sandbox resume <id>` |
| მუშაობის გაგრძელება ვადის გასვლის შემდეგ | `tuist sandbox extend <id> --lifetime-minutes 240` |
| ლოკალური Git worktree-ის ფაილების ასახვა მასში | `tuist sandbox sync <id>` |
| ფაილების კოპირება გარეთ ან შიგნით | `tuist sandbox cp <id>:<path> <local-path>`, `tuist sandbox cp <local-path> <id>:<path>` |
| წაშლა | `tuist sandbox delete <id> --yes` |
| გამოყენების ნახვა | `tuist sandbox analytics` |

დაამატეთ `--json` მანქანისთვის წასაკითხი გამონატანისთვის. იხილეთ <.localized_link href="/cli/sandbox">CLI ცნობარი</.localized_link> ყველა პარამეტრისთვის. სენდბოქსების კოდიდან მართვის ნაცვლად, გამოიყენეთ იგივე ოპერაციები [Tuist API](https://tuist.dev/api/docs)-ს მეშვეობით `/api/accounts/{account_handle}/sandboxes`-ის ქვეშ, ან მიეცით აგენტს მათი გამოყენება <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>-ის მეშვეობით.

ინსტრუმენტები, რომლებსაც არ შეუძლიათ ინტერაქტიული შესვლა, როგორიცაა აგენტის პლაგინი, რომელიც აწყობს macOS სენდბოქსში, შეუძლიათ ავთენტიკაცია <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენით</.localized_link> `account:sandboxes:write` სკოუპით. მას შეუძლია გააკეთოს ის, რაც ანგარიშის წევრს: შექმნას სენდბოქსები, გაუშვას ბრძანებები მათში, და შეაჩეროს, აღადგინოს, დააარქივოს და წაშალოს ისინი. ინტეგრაციის პარამეტრები რჩება ანგარიშის ადმინისტრატორებთან.

### Tuist სენდბოქსის შიგნით {#tuist-in-sandbox}

macOS სენდბოქსები მოდიან Tuist CLI-ით. როდესაც თქვენი პროექტი ამაგრებს Tuist-ს mise-ის მეშვეობით (`mise.toml` ან `.tool-versions`), `tuist` აწარმოებს იმ ვერსიას, რომელიც ინსტალირდება პირველად, როდესაც ბრძანებას დასჭირდება. ყოველი ბრძანება, რომელსაც იწყებთ `tuist sandbox exec`-ით, აქვს mise-ის shim-ები (`$HOME/.local/share/mise/shims`) პირველად `PATH`-ზე და გამოსახულების Tuist ბოლოს, ასე რომ `tuist` და თქვენი სხვა mise ინსტრუმენტები მუშაობენ თქვენს ბრძანებებში და Xcode ბილდის ფაზებში, როგორიცაა სქემის post-actions. თითოეულ Mac-ს ასევე აქვს გიდი კოდირების აგენტებისთვის `/opt/tuist/agent-guide.md`-ზე, რომელიც გენერირდება მისი გამოსახულებიდან: მისი Xcode და სიმულატორები, სად არის რეპოზიტორია და რას შეიცავს მზადყოფნის სნეპშოტი. Claude Code, Codex და Amp, რომლებიც მუშაობენ Mac-ზე, პოულობენ მას მათი ინსტრუქციის ფაილებიდან.

ყოველი ბრძანება, რომელსაც იწყებთ `tuist sandbox exec`-ით, ასევე იღებს იმას, რასაც Tuist runner იღებს, ასე რომ სენდბოქსში ბილდები იყენებენ თქვენი ანგარიშის <.localized_link href="/guides/features/cache">ქეშს</.localized_link> თქვენი მონაცემების გადაცემის გარეშე:

- `TUIST_URL` და, სადაც სენდბოქსის ჰოსტი აღწევს მას, როგორიცაა macOS-ზე, `TUIST_CACHE_ENDPOINT` იმავე რაკში არსებული ქეშის.
- `TUIST_OIDC_TOKEN`, მოკლევადიანი იდენტობის ტოკენი იმ ბრძანებისთვის. Tuist CLI 4.218.0 და მოგვიანო ვერსიები ავთენტიკაციას აკეთებენ მისით თავისთავად; 4.215.0-დან 4.217.x-მდე, გაუშვით `tuist auth login` ჯერ იმავე ბრძანებაში.

ტოკენი იჭედება ყოველი ბრძანებისთვის და შეიძლება გაცვლილ იქნას Tuist ტოკენზე მხოლოდ მაშინ, როდესაც იმ ბრძანება მუშაობს, ასე რომ სენდბოქსი არასდროს ინახავს ხანგრძლივად მოქმედ მონაცემებს. ის არასდროს ანიჭებს უფრო მეტს, ვიდრე პირს ან ტოკენს, რომელმაც დაიწყო ბრძანება, შეუძლია გააკეთოს ქეშთან: ანგარიშის წევრები, რომელთა ქეშის ტოკენებსაც მხოლოდ ჩაწერა შეუძლიათ, იღებენ წაკითხვის წვდომას, და ანგარიშის ტოკენს სჭირდება ქეშის სკოუპები, როგორიცაა `ci`, `account:sandboxes:write`-თან ერთად, რათა სენდბოქსმა საერთოდ გამოიყენოს ქეში. ცვლადები, რომლებსაც გადასცემთ `--env`-ით, აქვთ უპირატესობა.

## აწყობა Mac-ზე კოდირების აგენტიდან {#coding-agents}

კოდირების აგენტი, რომელიც მუშაობს Linux-ზე, როგორიცაა ღრუბლოვანი აგენტის სესია, შეუძლია ააწყოს, შეამოწმოს და გაუშვას Apple-პლატფორმის კოდი macOS სენდბოქსზე, სანამ ის აგრძელებს ფაილების რედაქტირებას იქ, სადაც მუშაობს. Amp-ში, დააინსტალირეთ <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინი</.localized_link>. სხვა აგენტებისთვის, როგორიცაა Claude Code ან Cursor:

1. დააკავშირეთ აგენტი Tuist <.localized_link href="/guides/features/agentic-coding/mcp">MCP სერვერთან</.localized_link>. მისი `create_sandbox` ინსტრუმენტი ეუბნება აგენტს, თუ როგორ მართოს Mac.
2. დააინსტალირეთ Tuist CLI იქ, სადაც აგენტი მუშაობს, მაგალითად, გარემოს დაყენების სკრიპტში: `mise use -g tuist@latest`, ან `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist` (`tuist-linux-aarch64` ARM-ზე).
3. მოახდინეთ CLI-ის ავტორიზაცია. MCP სერვერზე შესვლა მასზე არ ვრცელდება, ამიტომ ან გაუშვით `tuist auth login` როგორც ანგარიშის წევრმა, ან დააყენეთ `TUIST_TOKEN` <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენზე</.localized_link> `account:sandboxes:write` სკოუპით.
4. თუ გარემო ზღუდავს ქსელურ წვდომას, ნება დართეთ `tuist.dev`. CLI ამ გზით ატვირთავს ფაილებს Mac-ზე, ამიტომ სხვა დომენი არ სჭირდება.
5. სურვილისამებრ, მიეცით აგენტს Mac-ების შექმნისა და წაშლის უფლება ყოველ ჯერზე კითხვის გარეშე. აგენტები იკითხავენ `create_sandbox`-ის გამოძახებამდე, რადგან Mac ითვლება თქვენი ანგარიშის ლიმიტებში, და `delete_sandbox`-მდე, რადგან ეს მოქმედება შეუქცევადია. Claude Code-ში, ნება დართეთ ორივეს `.claude/settings.json`-ში, MCP სერვერის რეგისტრაციის სახელის გამოყენებით (აქ `tuist`):

   ```json
   {
     "permissions": {
       "allow": ["mcp__tuist__create_sandbox", "mcp__tuist__delete_sandbox"]
     }
   }
   ```

იმისთვის, რომ აგენტმა თავად მოახდინოს დაყენება, მიაწოდეთ ეს მოთხოვნა:

```text
Set up this environment so you can build and test this project on a Tuist macOS sandbox.

Read https://tuist.dev/en/docs/guides/features/sandboxes#coding-agents and follow its "Build on a Mac from a coding agent" section. It's the current Tuist guide for this, so prefer it over anything you remember about Tuist.

You're done when you have created a Mac with create_sandbox, synced this repository to it with tuist sandbox sync, run the project's build there with tuist sandbox exec, and deleted the Mac.

Ask me before anything that needs my login or approval, such as tuist auth login. If a step fails or is blocked, stop and tell me which step you reached and the exact error, without secrets.
```

აგენტი ქმნის ერთ Mac-ს თითოეული ამოცანისთვის, პროექტის მიერ მითითებული [Xcode](#xcode)-ით: `create_sandbox` ჩამოთვლის ხელმისაწვდომ Xcode-ებს და ეუბნება აგენტს, წაიკითხოს პროექტის მითითება, მაგალითად, `.xcode-version`. ყოველი ბრძანების წინ ის ასრულებს `tuist sandbox sync`. ის აკოპირებს ფაილებს, რომლებსაც Git არ იგნორებს, დაკომიტულს თუ არა, ხოლო შემდეგ მხოლოდ შეცვლილ ფაილებს. Mac-ს უკვე აქვს [Tuist](#tuist-in-sandbox), პროექტის მიერ მითითებული ვერსია, თუ ასეთი არსებობს, შესული თქვენი ანგარიშის ქეშში, და აგენტი ერთხელ კითხულობს Mac-ის სახელმძღვანელოს. შემდეგ აგენტი ასრულებს ბრძანებებს, როგორიცაა `xcodebuild`, `tuist sandbox exec`-ის მეშვეობით, აკოპირებს შედეგებს, როგორიცაა სქრინშოტები ან აწყობილი აპლიკაცია, უკან `tuist sandbox cp`-ის მეშვეობით და შლის Mac-ს, როცა ამოცანა დასრულდება. Mac მუშაობას აგრძელებს ბოლო ბრძანებიდან 10 წუთის განმავლობაში, რათა შემდეგი დაუყოვნებლივ დაიწყოს; `tuist sandbox pause` მას უფრო ადრე აბრუნებს. მიტოვებული Mac იყინება, არქივირდება მისი ორსაათიანი სიცოცხლის ხანგრძლივობის დასრულებისას და იშლება 14 დღის შემდეგ; აგენტი აგრძელებს სიცოცხლის ხანგრძლივობას ხანგრძლივი აწყობის წინ.

## Linux და macOS {#platforms}

**Linux** სენდბოქსები მუშაობენ Ubuntu 24.04-ზე. ყოველ Linux სენდბოქსს აქვს 16 vCPU და იყენებს მასპინძელი მანქანის თავისუფალ ბირთვებს, ამიტომ მისი ფორმა განსაზღვრავს მეხსიერებას:

- 2 GiB RAM (`--vcpus 1 --memory-gb 2`)
- 4 GiB RAM (`--vcpus 2 --memory-gb 4`, ნაგულისხმევი)
- 8 GiB RAM (`--vcpus 4 --memory-gb 8`)
- 16 GiB RAM (`--vcpus 8 --memory-gb 16`)
- 32 GiB RAM (`--vcpus 16 --memory-gb 32`)
- 44 GiB RAM (`--vcpus 16 --memory-gb 44`)

**macOS** სენდბოქსები მუშაობენ Apple silicon-ზე Xcode-ით:

- 8 vCPU, 8 GiB RAM (ნაგულისხმევი)
- 8 vCPU, 16 GiB RAM
- 8 vCPU, 24 GiB RAM

### გარანტირებული CPU {#guaranteed-cpu}

Linux სენდბოქსს გარანტირებული აქვს vCPU-ის მეოთხედი თითოეულ GiB მეხსიერებაზე, მაგალითად, 2 vCPU 8 GiB-ისთვის, და იყენებს დამატებით რესურსებს, რამდენიც თავისუფალია მასპინძელ მანქანაზე, 16 vCPU-მდე. ეს შეესაბამება აგენტს, რომელიც ძირითადად ელოდება და შემდეგ აწყობს ნაკადებად. როდესაც აწყობას სჭირდება უფრო სტაბილური CPU მაშინაც კი, როცა მანქანა დატვირთულია, შეუქმენით გარანტია 1, 2, 4 ან 8 vCPU-ზე სენდბოქსის შექმნისას; ის მიიღებს უფრო დიდს ამ რიცხვსა და მეხსიერების გარანტიას შორის:

| სად | როგორ |
| --- | --- |
| CLI | `tuist sandbox create --guaranteed-vcpus 4` |
| API და MCP `create_sandbox` | `"guaranteed_vcpus": 4` |

- **გარანტია არის მინიმუმი, არა ზღვარი.** სენდბოქსი 4 გარანტირებული vCPU-ით მაინც აღწევს 16-ს, როცა ბირთვები თავისუფალია. კონკურენციის პირობებში, თითოეული სენდბოქსი იღებს CPU-ს თავისი გარანტიის პროპორციულად.
- **გადახდა ხდება მინიმუმის მიხედვით.** მომუშავე სენდბოქსისთვის გადახდა ხდება გამოყენებული CPU-ს მიხედვით, მაგრამ არასდროს ნაკლები, ვიდრე მისი გარანტია.
- **სენდბოქსი ინარჩუნებს გარანტიას სიცოცხლის ბოლომდე.** მის შესაცვლელად, შექმენით ახალი სენდბოქსი.
- **macOS სენდბოქსებს ყოველთვის აქვთ მთლიანი ფორმა**, ამიტომ ისინი არ იღებენ გარანტიას.

### აირჩიეთ Xcode {#xcode}

ყოველი macOS სენდბოქსი მუშაობს ერთ Xcode-ზე, რომელსაც თქვენ ირჩევთ შექმნისას. ის იტვირთება იმავე იმიჯით, რაც <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link>-ის პროფილი ამ Xcode-ისთვის, ამიტომ აგენტი აწყობს იმავე ინსტრუმენტებითა და სიმულატორებით, რაც თქვენი CI. tuist.dev-ზე, macOS სენდბოქსები ამჟამად გთავაზობთ:

- `26.6` (ნაგულისხმევი)
- `26.1.1`
- `27.0`
- `27.1`
- `27.2`

აირჩიეთ ერთ-ერთი `xcode_version`-ით (`--xcode` CLI-ში), ზუსტი ვერსიის მითითებით, როგორც ეს runner პროფილებში ხდება:

| სად | როგორ |
| --- | --- |
| CLI | `tuist sandbox create --xcode 26.1.1` |
| API და MCP `create_sandbox` | `"xcode_version": "26.1.1"` |
| Tuist Mac პლაგინი Amp-ისთვის | `tuist_mac_start` `xcode`-ით |
| Amp orbs | Orb-ის ტიპი `macos-xcode-26-1-1` (იხილეთ <.localized_link href="/guides/features/sandboxes/amp#xcode">Amp</.localized_link>) |
| Claude Code და Claude Managed Agents | `xcode_version` გარემოში, ან თითოეული Managed Agents სესიისთვის (იხილეთ <.localized_link href="/guides/features/sandboxes/claude#xcode">Claude</.localized_link>) |

- **ვერსიის მითითების გარეშე**, Mac იღებს ნაგულისხმევ ვერსიას.
- **Tuist-ის მიერ შეუთავაზებელი ვერსია უარყოფილია**, ხოლო შეცდომაში ჩამოთვლილია ხელმისაწვდომი ვერსიები, რათა იცოდეთ, რა არის ამჟამად ხელმისაწვდომი.
- **Tuist არ კითხულობს თქვენი რეპოზიტორიის `.xcode-version`-ს.** ვერსიას თქვენ ან Mac-ის მომთხოვნი აგენტი ირჩევთ. MCP ინსტრუმენტი და Tuist Mac პლაგინი აგენტებს აცნობებენ, რომ დაემთხვიონ პროექტის მიერ მიბმულ ვერსიას.
- **სენდბოქსი ინარჩუნებს თავის Xcode-ს სიცოცხლის ბოლომდე.** სხვა Xcode-ით ასაწყობად, შექმენით ახალი სენდბოქსი. `xcodebuild -version` აჩვენებს, თუ რომელ Xcode-ს იყენებს Mac.

## უსაფრთხოება {#security}

- ყოველი სენდბოქსი არის დამოუკიდებელი ვირტუალური მანქანა. სენდბოქსები არ იზიარებენ ფაილურ სისტემას, მეხსიერებას ან პროცესებს ერთმანეთთან ან CI სამუშაოებთან.
- სენდბოქსები ეკუთვნის ანგარიშს და მისი ნებისმიერი წევრი შეუძლია მათი გამოყენება და მართვა, ინტეგრაციის მომსახურე სენდბოქსების ჩათვლით. ინტეგრაციებს მხოლოდ ადმინისტრატორები აკავშირებენ. ინტეგრაციიდან წამოსული სესიები მხოლოდ იმ ანგარიშის სენდბოქსებს აღწევენ, რომელთანაც ინტეგრაციაა დაკავშირებული.
- მოწმობები, რომლებსაც თქვენ აწვდით Tuist-ს ინტეგრაციის დასაკავშირებლად, მაგალითად Amp პროვაიდერის ტოკენი ან Claude გარემოს გასაღები, ინახება დაშიფრული სახით და აღარასდროს ჩანს.
- სენდბოქსს შეუძლია ინტერნეტთან წვდომა. მოეპყარით იმას, რასაც აგენტს შეუძლია იქიდან წვდომა, ისე, როგორც მოეპყრობოდით CI სამუშაოს.
