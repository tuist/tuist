# სენდბოქსები {#sandboxes}

> [!IMPORTANT]
> **მხოლოდ მიწვევით**
>
> Tuist-ის სენდბოქსები, როგორც Linux-ზე, ისე macOS-ზე, ამჟამად მხოლოდ მიწვევითაა ხელმისაწვდომი, სანამ ტევადობას გავზრდით. [დაგვიკავშირდით](mailto:contact@tuist.dev) ან მოგვწერეთ [საზოგადოების Slack-ში](https://slack.tuist.dev), რათა თქვენი ანგარიშისთვის წვდომა მოითხოვოთ. ფასები გამოცხადდება, როდესაც სენდბოქსები საყოველთაოდ გახდება ხელმისაწვდომი.

სენდბოქსი არის ვირტუალური მანქანა, სადაც კოდირების აგენტი ასრულებს ბრძანებებს და არედაქტირებს ფაილებს. აგენტის თითოეულ სესიას ეკუთვნის საკუთარი სენდბოქსი, რომელიც ინარჩუნებს კოდის ჩექაუთს, ბილდის პროდუქტებსა და დაინსტალირებულ ხელსაწყოებს სესიის განმავლობაში. როდესაც აგენტი უმოქმედოა, სენდბოქსი იყურება; შემდეგი შეტყობინება აღადგენს მას იქიდან, სადაც შეჩერდა.

სენდბოქსები მუშაობენ იმავე ფლოტზე, რაზეც <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link>, თქვენი გუნდის <.localized_link href="/guides/features/cache">ქეშთან</.localized_link> ერთად, რათა აგენტის ბილდებმა შეძლონ იმავე ქეშირებული არტიფაქტების გამოყენება, რასაც თქვენი CI და ლოკალური მანქანები იყენებენ.

სენდბოქსების გამოყენება შესაძლებელია შემდეგიდან:

- **<.localized_link href="/guides/features/sandboxes/amp">Amp</.localized_link>**: გაუშვით თქვენი Amp სამუშაო სივრცის ორბები Tuist-ზე, ან ნებისმიერ Amp ნაკადს მიაწოდეთ Mac Xcode-ის ბილდებისთვის <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინის</.localized_link> საშუალებით.
- **<.localized_link href="/guides/features/sandboxes/claude">Claude</.localized_link>**: გაუშვით Claude Managed Agents-ის სესიები და Claude Code-ის ღრუბლოვანი სესიები (claude.ai, დესკტოპ და მობილური აპლიკაციები, და `claude --cloud`) Tuist-ზე.
- **[Tuist CLI](#cli)**: შექმენით სენდბოქსები და გაუშვით ბრძანებები მათში თქვენი ტერმინალიდან, ან თქვენი საკუთარი ხელსაწყოებიდან API-ის საშუალებით.

## CLI-ით დაწყება {#cli}

შექმენით სენდბოქსი და გაუშვით მასში ბრძანებები თქვენი ტერმინალიდან `tuist sandbox`-ის საშუალებით.

### 1. შესვლა {#cli-log-in}

სენდბოქსების მართვა მოითხოვს ანგარიშის ადმინისტრატორს:

```bash
tuist auth login
```

### 2. სენდბოქსის შექმნა {#cli-create}

```bash
tuist sandbox create --platform macos
```

Linux-ისთვის გამოტოვეთ `--platform`. გადაეცით `--vcpus` `--memory-gb`-თან ერთად უფრო დიდი [კონფიგურაციისთვის](#platforms), და `--workspace-gb` უფრო დიდი დისკისთვის. ბრძანება ბრუნდება, როდესაც სენდბოქსი გაშვებულია და ბეჭდავს მის დეტალებს, მათ შორის ID-ს. ის იყენებს მიმდინარე დირექტორიაში არსებული Tuist პროექტის ანგარიშს; გადაეცით `--account` სხვის არჩევას.

### 3. ბრძანებების გაშვება {#cli-exec}

```bash
tuist sandbox exec <sandbox-id> -- xcodebuild -version
```

ბრძანება სრულდება `bash -l`-ით სენდბოქსში, რომელიც ჯერ აღდგება, თუ შეჩერებულია. `tuist` ატარებს მის გამონატანს მთელი გაშვების განმავლობაში და სრულდება ბრძანების სტატუსით; Ctrl-C აუქმებს მას სენდბოქსში. საჭიროების შემთხვევაში გადაეცით `--cwd`, `--env NAME=VALUE` და `--timeout` (ექვს საათამდე).

### ჩვეულებრივი ამოცანები {#cli-tasks}

| ამოცანა | ბრძანება |
| --- | --- |
| სენდბოქსების ჩამონათვალი | `tuist sandbox list` |
| ერთის ჩვენება | `tuist sandbox show <id>` |
| შეჩერება ან აღდგენა | `tuist sandbox pause <id>`, `tuist sandbox resume <id>` |
| ლოკალური Git worktree-ის ფაილების ასახვა მასში | `tuist sandbox sync <id>` |
| ფაილების კოპირება გარეთ ან შიგნით | `tuist sandbox cp <id>:<path> <local-path>`, `tuist sandbox cp <local-path> <id>:<path>` |
| წაშლა | `tuist sandbox delete <id> --yes` |
| გამოყენების ნახვა | `tuist sandbox analytics` |

დაამატეთ `--json` მანქანური წაკითხვისთვის შესაფერისი გამონატანისთვის. ყველა პარამეტრისთვის იხილეთ <.localized_link href="/cli/sandbox">CLI-ის ცნობარი</.localized_link>. სენდბოქსების კოდიდან მართვისთვის, გამოიყენეთ იგივე ოპერაციები [Tuist API-ის](https://tuist.dev/api/docs) საშუალებით `/api/accounts/{account_handle}/sandboxes` ქვეშ, ან მიეცით აგენტს მათი გამოყენების საშუალება <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>-ის მეშვეობით.

ხელსაწყოები, რომლებსაც ინტერაქტიული შესვლა არ შეუძლიათ, მაგალითად აგენტის პლაგინი, რომელიც macOS სენდბოქსში ახდენს ბილდს, შეუძლიათ ავთენტიკაცია <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენით</.localized_link> `account:sandboxes:write` სკოპით. მას შეუძლია შექმნას სენდბოქსები, გაუშვას მათში ბრძანებები, და შეაჩეროს, აღადგინოს და წაშალოს ისინი, ანგარიშის წევრის მსგავსად. სენდბოქსები, რომლებიც Amp-ის ან Claude-ის ინტეგრაციას, ანალიტიკას და ინტეგრაციის პარამეტრებს ემსახურებიან, ანგარიშის ადმინისტრატორებთან რჩება.

## Mac-ზე ბილდი კოდირების აგენტიდან {#coding-agents}

კოდირების აგენტი, რომელიც მუშაობს Linux-ზე, მაგალითად ღრუბლოვანი აგენტის სესია, შეუძლია ააწყოს, შეამოწმოს და გაუშვას Apple-პლატფორმის კოდი macOS სენდბოქსზე, სანამ ის აგრძელებს ფაილების რედაქტირებას იქ, სადაც მუშაობს. Amp-ში დააინსტალირეთ <.localized_link href="/guides/features/sandboxes/amp#remote-mac">Tuist Mac პლაგინი</.localized_link>. სხვა აგენტებისთვის, როგორიცაა Claude Code ან Cursor:

1. დააკავშირეთ აგენტი Tuist-ის <.localized_link href="/guides/features/agentic-coding/mcp">MCP სერვერთან</.localized_link>. მისი `create_sandbox` ხელსაწყო ეუბნება აგენტს, თუ როგორ უმართოს Mac-ს.
2. დააინსტალირეთ Tuist CLI იქ, სადაც აგენტი მუშაობს, მაგალითად გარემოს setup სკრიპტში: `mise use -g tuist@latest`, ან `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist` (`tuist-linux-aarch64` ARM-ზე).
3. ავთენტიკაცია CLI-ისთვის. MCP სერვერის შესვლა მასზე არ ვრცელდება, ამიტომ ან გაუშვით `tuist auth login` ანგარიშის წევრად, ან დააყენეთ `TUIST_TOKEN` <.localized_link href="/guides/server/authentication#account-tokens">ანგარიშის ტოკენზე</.localized_link> `account:sandboxes:write` სკოპით.
4. თუ გარემო ზღუდავს ქსელურ წვდომას, დაუშვით `tuist.dev`. CLI ატვირთავს ფაილებს Mac-ზე მისი საშუალებით, ამიტომ სხვა დომენი არ სჭირდება.

აგენტი ქმნის ერთ Mac-ს თითოეული ამოცანისთვის და, ყოველ ბრძანებამდე, ასრულებს `tuist sandbox sync`-ს. ის აკოპირებს ფაილებს, რომლებსაც Git არ იგნორირებს, ჩაკომიტირებულს თუ არა, და შემდეგ მხოლოდ იმას, რაც შეიცვალა. შემდეგ აგენტი ასრულებს ბრძანებებს, როგორიცაა `xcodebuild`, `tuist sandbox exec`-ის საშუალებით, აკოპირებს შედეგებს, როგორიცაა სკრინშოტები ან აწყობილი აპლიკაცია, უკან `tuist sandbox cp`-ით, და შლის Mac-ს, როდესაც ამოცანა დასრულდება. Mac რჩება გაშვებული 10 წუთის განმავლობაში ბოლო ბრძანების შემდეგ, ამიტომ შემდეგი მაშინვე იწყება; `tuist sandbox pause` უფრო ადრე აბრუნებს მას. დატოვებული Mac შემდეგ იყურება და იშლება 14 დღის შეჩერების შემდეგ.

## Linux და macOS {#platforms}

**Linux** სენდბოქსები მუშაობენ Ubuntu 24.04-ზე:

- 2 vCPU, 4 GiB RAM (ნაგულისხმევი)
- 4 vCPU, 8 GiB RAM
- 8 vCPU, 16 GiB RAM

**macOS** სენდბოქსები მუშაობენ Apple silicon-ზე Xcode-ით:

- 8 vCPU, 8 GiB RAM (ნაგულისხმევი)
- 8 vCPU, 16 GiB RAM
- 8 vCPU, 24 GiB RAM

## უსაფრთხოება {#security}

- ყოველი სენდბოქსი საკუთარი ვირტუალური მანქანაა. სენდბოქსები არ იზიარებენ ფაილურ სისტემას, მეხსიერებას ან პროცესებს ერთმანეთთან ან CI სამუშაოებთან.
- სენდბოქსები ეკუთვნის ანგარიშს და მათ მართვა მხოლოდ მის ადმინისტრატორებს შეუძლიათ. ინტეგრაციის სესიები მხოლოდ იმ ანგარიშის სენდბოქსებთან ახდენენ კავშირს, რომელთანაც ინტეგრაციაა მიერთებული.
- მონაცემები, რომლებსაც Tuist-ს აწვდით ინტეგრაციის დასაკავშირებლად, როგორიცაა Amp პროვაიდერის ტოკენი ან Claude გარემოს გასაღები, ინახება დაშიფრული და აღარასდროს ჩანდება.
- სენდბოქსს შეუძლია ინტერნეტთან წვდომა. მოეპყარით იმას, რასაც აგენტი მისგან წვდება ისე, როგორც CI სამუშაოს.
