## ტრეკები tuist share-ით {#share-tracks}

სამუშაო პროცესებისთვის, რომლებიც აქვეყნებენ `tuist share`-ის საშუალებით, გამოიყენეთ `--track` ტრეკის არჩევას:

```bash
tuist share App --track beta
tuist share App --track nightly
```

## გამოშვების შენიშვნები {#release-notes}

გამოიყენეთ ტრეკები გარემოს ჯგუფებისთვის და გამოშვების შენიშვნები ცალკეული ბილდის მიზნებისთვის:

```bash
tuist share App --track QA --release-notes "Fix sign-in and improve the checkout flow"
```

ჩაანაცვლეთ `App` თქვენი აპლიკაციის სახელით, აპლიკაციის ფაილის გზით ან შესრულებადი დისტრიბუციით და მისი `--executable` ოფციით. გამოშვების შენიშვნები არის სურვილისამებრ ჩვეულებრივი ტექსტი, 10 000 სიმბოლომდე. პირველი არაცარიელი ხაზი ჩანს ერთხაზიან ფრაგმენტად გადახედვების სიაში, ასე რომ ბილდის ნომრები და სხვა იდენტიფიცირების ინფორმაცია ერთი შეხედვით ჩანს. გრძელი ხაზები იკვეცება; სრული შენიშვნები ჩანს დეტალურ გვერდებზე. ძებნა ემთხვევა საჩვენებელ სახელებს და სრულ გამოშვების შენიშვნებს, მათ შორის ხაზებს, რომლებიც არ ჩანს ფრაგმენტში. მრავალხაზიანი შენიშვნები მხარდაჭერილია, მაგალითად `--release-notes "$(< release-notes.txt)"`. ისინი არ ცვლიან აპლიკაციის საჩვენებელ სახელს ან მის ტრეკს.

### თავსებადობა {#preview-metadata-compatibility}

გამოშვების შენიშვნები არ ცვლიან, თუ რომელ გადახედვას ეკუთვნის ბილდი. პირველი შენიშვნები, რომელსაც გადახედვა იღებს, ინახება: მოგვიანებით ატვირთვას შეუძლია დაამატოს შენიშვნები გადახედვას, რომელსაც არ აქვს, მაგრამ ვერ გადაწერს ან წაშლის არსებულს. გადახედვები, რომლებიც აიტვირთა გამოშვების შენიშვნების არსებობამდე, რჩება ვალიდური მათ გარეშე.

თვითმასპინძელ განლაგებებს სჭირდებათ სერვერის ვერსია, რომელიც მხარს უჭერს გამოშვების შენიშვნებს და ტრეკის ფილტრაციას, განახლებულ კლიენტთან ერთად. ძველი სერვერები იგნორირებენ შენიშვნებს. სიის endpoint-ების ტრეკისა და ძებნის ფილტრებისთვის, იხილეთ [API-ის ცნობარი](https://tuist.dev/api/docs).

> ავტომატური pull/merge request კომენტარების მისაღებად, დააკავშირეთ თქვენი <.localized_link href="/guides/server/accounts-and-projects">დაშორებული პროექტი</.localized_link> <.localized_link href="/guides/integrations/gitforge/github">Git forge</.localized_link>-თან.

## ავტომატიზაციები {#automations}

გამოიყენეთ `--json` JSON გამოტანის მისაღებად `tuist share`-დან:

```bash
tuist share --json
```

გამოიყენეთ შედეგი მორგებული ავტომატიზაციებისთვის, როგორიცაა Slack-ის შეტყობინების გამოქვეყნება CI-დან. `url` გასაღები შეიცავს სრულ გადახედვის ბმულს; `qrCodeURL` მიუთითებს QR კოდის გამოსახულებაზე გადახედვის მოწყობილობაზე გასახსნელად:

```json
{
  "id": 1234567890,
  "url": "https://tuist.dev/preview/1234567890",
  "qrCodeURL": "https://tuist.dev/preview/1234567890/qr-code.svg"
}
```
