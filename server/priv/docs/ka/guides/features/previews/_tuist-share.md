## ტრეკები tuist share-ით {#share-tracks}

სამუშაო პროცესებისთვის, რომლებიც აქვეყნებენ `tuist share`-ის საშუალებით, გამოიყენეთ `--track` ტრეკის შესარჩევად:

```bash
tuist share App --track beta
tuist share App --track nightly
```

## გამოშვების შენიშვნები {#release-notes}

გამოიყენეთ ტრეკები გარემოს ჯგუფებისთვის და გამოშვების შენიშვნები ცალკეული ბილდის მიზნით:

```bash
tuist share App --track QA --release-notes "Fix sign-in and improve the checkout flow"
```

ჩაანაცვლეთ `App` თქვენი აპლიკაციის სახელით, აპლიკაციის ფაილის გზით ან შესრულებადი დისტრიბუციით და მისი `--executable` ოფციით. გამოშვების შენიშვნები არის არასავალდებულო ჩვეულებრივი ტექსტი, 10,000 სიმბოლომდე. პირველი არაცარიელი ხაზი ჩანს ერთხაზიან ფრაგმენტად გადახედვების სიაში, ასე რომ ბილდის ნომრები და სხვა იდენტიფიცირების ინფორმაცია ერთი შეხედვით ჩანს. გრძელი ხაზები იკვეცება; სრული შენიშვნები ჩანს დეტალურ გვერდებზე. ძებნა ემთხვევა საჩვენებელ სახელებს და სრულ გამოშვების შენიშვნებს, მათ შორის ხაზებს, რომლებიც არ ჩანს ფრაგმენტში. მრავალხაზიანი შენიშვნები მხარდაჭერილია, მაგალითად `--release-notes "$(< release-notes.txt)"`. ისინი არ ცვლიან აპლიკაციის საჩვენებელ სახელს ან მის ტრეკს.

### თავსებადობა {#preview-metadata-compatibility}

გამოშვების შენიშვნები არის დამატებითი მეტამონაცემები, არა გადახედვის იდენტობის ნაწილი. ატვირთვები ძველი და ახალი კლიენტებისგან კვლავ ჯგუფდება ერთსა და იმავე გადახედვაში პლატფორმების მიხედვით. პირველი არაცარიელი შენიშვნები ინახება: მოგვიანებით ატვირთვამ შეიძლება შეავსოს შენიშვნები, რომლებიც ადრე არ იყო, მაგრამ ვერ გადაწერს არსებულ შენიშვნებს. `release_notes`-ის გამოტოვება, `null`-ის გაგზავნა ან ცარიელი ან მხოლოდ თეთრი სივრცის შემცველი სტრიქონის გაგზავნა არასდროს ასუფთავებს შენიშვნებს. არსებული გადახედვები არ ივსება უკან და რჩება ვალიდური შენიშვნების გარეშე.

სიის API-ის არასავალდებულო `track` კითხვის პარამეტრი ემთხვევა მთელ ტრეკის სახელს, დიდ-პატარა ასოების განუსხვავებლად, რაც თავსებადია არსებულ ტრეკის შენახვასთან. გამოტოვეთ ის ან გააგზავნეთ ცარიელი მნიშვნელობა (`?track=`) ყველა ტრეკის ჩამოსათვლელად. ტრეკის სახელები რჩება ღია სტრიქონებად, არა ფიქსირებული მნიშვნელობების სიად. `GET /api/projects/:account_handle/:project_handle/previews/tracks` აბრუნებს `{total_count, tracks: [{name, count}]}` დალაგებული, დიდ-პატარა ასოების განუსხვავებლად დაჯგუფებული სახელიანი ტრეკებით, იმავე გადახედვის-წაკითხვის ავტორიზაციის ქვეშ, რაც ბილდების ჩამოთვლისას. რაოდენობები მოიცავს მთელ პროექტს დამოუკიდებლად დაჯგუფების, ძებნისა და შერჩეული ტრეკისგან; ჯამი მოიცავს არატრეკირებულ გადახედვებს. ითვლება მხოლოდ ჩამოსათვლელი გადახედვები bundle identifier-ით. სიის API ასევე იღებს არასავალდებულო `search` საჩვენებელი სახელის ან სრული გამოშვების შენიშვნების ლიტერალური, დიდ-პატარა ასოების განუსხვავებელი ქვესტრიქონისთვის, გაერთიანებული ტრეკთან დაჯგუფებამდე. არსებული `display_name` ფილტრაცია რჩება ზუსტი.

ძველ კლიენტებს შეუძლიათ განაგრძონ გადახედვების ატვირთვა და ჩამოთვლა ამ ორი ველის გაგზავნის გარეშე. ახალი კლიენტები იღებენ უფრო ძველ პასუხებს, რომლებიც გამორიცხავენ ტრეკს ან შენიშვნებს, და იგნორირებენ უცნობ პასუხის თვისებებს, რომლებიც დაემატა მომავალ სერვერებმა. API ინტეგრაციებმაც ასევე უნდა დაიგნორონ უცნობი პასუხის თვისებები, რათა დამატებითი მეტამონაცემები დარჩეს თავსებადი.

თვითმასპინძელ განლაგებებს სჭირდებათ სერვერის ვერსია, რომელიც მხარს უჭერს გამოშვების შენიშვნებსა და ტრეკის ფილტრაციას, განახლებულ კლიენტთან ერთად, ამ ფუნქციების გამოყენებისთვის. უფრო ძველმა სერვერებმა შეიძლება დაიგნორონ შენიშვნები ან უცნობი კითხვის პარამეტრები.

## ავტომატიზაციები {#automations}

გამოიყენეთ `--json` JSON გამოსავლის მისაღებად `tuist share`-დან:

```bash
tuist share --json
```

გამოიყენეთ შედეგი მორგებული ავტომატიზაციებისთვის, როგორიცაა Slack შეტყობინების გამოქვეყნება CI-დან. `url` გასაღები შეიცავს სრულ გადახედვის ბმულს; `qrCodeURL` მიუთითებს QR კოდის გამოსახულებაზე გადახედვის მოწყობილობაზე გასახსნელად:

```json
{
  "id": 1234567890,
  "url": "https://cloud.tuist.io/preview/1234567890",
  "qrCodeURL": "https://cloud.tuist.io/preview/1234567890/qr-code.svg"
}
```
