# Bazel-ის პრევიუები

გამოაქვეყნეთ Android APK-ები, Apple სიმულატორის და macOS აპლიკაციები, ასევე კომანდური ხაზის ინსტრუმენტები თქვენი არსებული Bazel სამიზნეებიდან. დაამატეთ პრევიუს სამიზნე ყოველი იმ შედეგისთვის, რომლის გაზიარებაც გსურთ; თქვენი ჩვეულებრივი ბილდები უცვლელი დარჩება.

## მოწყობა

დაამატეთ [`rules_tuist` Tuist-ის რეპოზიტორიიდან](https://github.com/tuist/tuist/tree/main/bazel) ფაილში `MODULE.bazel`, მიუთითეთ ის კომიტი, რომლის გამოყენებაც გსურთ:

```starlark
bazel_dep(name = "rules_tuist")

git_override(
    module_name = "rules_tuist",
    remote = "https://github.com/tuist/tuist.git",
    commit = "FULL_COMMIT_SHA",
    strip_prefix = "bazel",
)
```

შეინარჩუნეთ თქვენი არსებული აპლიკაციის სამიზნეები, ნეიტიური SDK-ები და ხელმოწერის კონფიგურაცია. Bazel უზრუნველყოფს გამოქვეყნების ინსტრუმენტებს.

შედით პირდაპირ Bazel-იდან:

```bash
bazel run @rules_tuist//:login
```

ეს აზიარებს მონაცემებს Tuist CLI-სა და Gradle პლაგინთან; არსებული შესვლაც მუშაობს. CI-ზე გამოიყენეთ `TUIST_TOKEN` ან გაუშვით შესვლის სამიზნე Tuist-ის <.localized_link href="/guides/integrations/continuous-integration">OIDC აუთენტიკაციით</.localized_link>. არასდროს ჩადოთ მონაცემები BUILD ფაილებში ან წესების ატრიბუტებში. გადაეცით `-- --url https://tuist.example.com` საკუთარ ჰოსტინგზე განთავსებულ ეგზემპლარში შესასვლელად.

ჩატვირთეთ მხოლოდ ის ადაპტერი, რომელიც გჭირდებათ თქვენს `BUILD.bazel` ფაილში:

```starlark
load("@rules_tuist//:android.bzl", "android_preview")

android_preview(name = "preview_android", app = ":android_app")
```

Apple აპლიკაციებისთვის:

```starlark
load("@rules_tuist//:apple.bzl", "apple_preview")

apple_preview(name = "preview_ios", app = ":ios_app")
apple_preview(name = "preview_macos", app = ":macos_app")
```

შესრულებადი სამიზნეებისთვის, როგორიცაა `cc_binary`:

```starlark
load("@rules_tuist//:executable.bzl", "executable_preview")

executable_preview(name = "preview_cli", binary = ":my_tool")
```

შესრულებადი პრევიუ მოიცავს სამიზნის მიერ განცხადებულ runtime ფაილებს. განაცხადეთ ბიბლიოთეკები და რესურსები, რომლებიც თქვენს ინსტრუმენტს სჭირდება მის Bazel სამიზნეში, და გამოიყენეთ ისეთი გზები, რომლებიც მუშაობს თქვენი ბილდის დირექტორიის გარეთ.

## აგება და გამოქვეყნება

```bash
bazel run //:preview_android -- \
  --publish --project acme/app --track review
bazel run //:preview_ios --platforms=//platforms:ios_simulator -- \
  --publish --project acme/app --track review
bazel run //:preview_macos -- --publish --project acme/app --track review
bazel run //:preview_cli -- --publish --project acme/app --track review
```

ჩაანაცვლეთ აპლიკაციისა და სიმულატორის პლატფორმის ლეიბლები თქვენი საკუთარი მნიშვნელობებით. გადაეცით `--url` საკუთარ ჰოსტინგზე განთავსებული Tuist წყაროსთვის და `--revision` Git კომიტის ასოცირებისთვის.

გადაეცით `--publish --project account/project` წარმატებული ბილდის გასაზიარებლად. `--publish`-ის გარეშე, ან `--no-publish`-ით, არაფერი აიტვირთება და შესვლა არ არის საჭირო. ჩვეულებრივი `bazel build` არასდროს აქვეყნებს, მათ შორის ქეშის მოხვედრის შემთხვევაშიც. `tuist bazel setup` ააქტიურებს ქეშირებას და ინსაიტებს, არა გამოქვეყნებას.

## მხარდაჭერილი შედეგები

- **Android:** ხელმოწერილი აპლიკაციის APK-ები, დებაგ ბილდების ჩათვლით. დააინსტალირეთ Android SDK build-tools და კომანდური ხაზის ინსტრუმენტები, და დააყენეთ `ANDROID_HOME` ან `ANDROID_SDK_ROOT`. ტესტის APK-ები და Android App Bundles არ არის მხარდაჭერილი.
- **Apple:** ad-hoc-ით ხელმოწერილი სიმულატორისა და macOS აპლიკაციები, აგებული და ვერიფიცირებული macOS-ზე. ფიზიკურ მოწყობილობებზე აგება, ფრეიმვორქები, გაფართოებები და ტესტები არ არის მხარდაჭერილი. გამოიყენეთ არქივის შედეგი ექსპერიმენტული tree არქივების ნაცვლად.
- **კომანდური ხაზის ინსტრუმენტები:** macOS ან Linux შესრულებადი ფაილები arm64 ან x86_64 არქიტექტურისთვის, უნივერსალური macOS ბინარების ჩათვლით. სკრიპტებს სჭირდებათ shebang და ინტერპრეტატორი მიმღების სისტემაზე. განაცხადეთ runtime დამოკიდებულებები თქვენს სამიზნეში; Tuist არ აინსტალირებს დაკარგულ ბიბლიოთეკებს ან ენის რანთაიმებს.

## ქეშის გამეორება, შეცდომები და შენახვა

იგივე გამოქვეყნების გამეორება იყენებს არსებულ პრევიუს ხელახლა ატვირთვის გარეშე, მაშინაც კი, როცა Bazel აღადგენს ბილდს ქეშიდან. შედეგის, ტრეკის ან რევიზიის ცვლილება ქმნის ახალ გამოქვეყნებას. ატვირთვის შეცდომა აფუჭებს კომანდას; შეგიძლიათ ხელახლა გაუშვათ იმის შესამოწმებლად, დასრულდა თუ არა გამოქვეყნება სანამ კიდევ ერთხელ სცადოთ.

კომანდა ბმავს თქვენი პროექტის პრევიუებზე, სადაც დამუშავებას შეიძლება რამდენიმე წამი დასჭირდეს. პრევიუები იყენებენ პროექტის ნაგულისხმევ ხილვადობას.

არტეფაქტების გამოქვეყნებები იწურება 30 დღის შემდეგ ჰოსტინგზე განთავსებულ Tuist-ზე. საკუთარ ჰოსტინგზე განთავსებული ეგზემპლარები იყენებენ `TUIST_APP_PREVIEW_RETENTION_DAYS`; მისი დაყენების გარეშე ამ ოჯახისთვის ვადა არ იწურება. ვადაგასული გამოქვეყნების ჩანაწერების აღდგენა იგივე მოქმედების გამეორებით შეუძლებელია.

იხილეთ <.localized_link href="/guides/features/previews#run-a-preview">პრევიუს გაშვება</.localized_link> გამოქვეყნებული ბილდების გასაშვებად, წვდომის, ტრეკების და README ბეიჯების შესახებ.

## Apple პრევიუები

Apple სიმულატორისა და macOS პრევიუებისთვის, იხილეთ <.localized_link href="/guides/features/previews/run/macos">Tuist macOS კომპანიონი აპის ინსტრუქციები</.localized_link>. ეს არ ცვლის Bazel-ის აპლიკაციის შესაბამისობის ან ხელმოწერის მოთხოვნებს.
