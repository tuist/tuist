# Bazel-ის პრივიუები

გამოაქვეყნეთ Android APK-ები, Apple სიმულატორისა და macOS აპლიკაციები და კომანდური ხაზის ინსტრუმენტები თქვენი არსებული Bazel სამიზნეებიდან. დაამატეთ პრივიუს სამიზნე ყოველი გამოსავლისთვის, რომლის გაზიარებაც გსურთ; თქვენი ჩვეულებრივი ბილდები უცვლელი რჩება.

## მოწყობა

დაამატეთ [`rules_tuist` Tuist-ის რეპოზიტორიიდან](https://github.com/tuist/tuist/tree/main/bazel) ფაილში `MODULE.bazel`, მიუბმით ის კომიტი, რომლის გამოყენებაც გსურთ:

```starlark
bazel_dep(name = "rules_tuist")

git_override(
    module_name = "rules_tuist",
    remote = "https://github.com/tuist/tuist.git",
    commit = "FULL_COMMIT_SHA",
    strip_prefix = "bazel",
)
```

შეინარჩუნეთ თქვენი არსებული აპლიკაციის სამიზნეები, ნატიური SDK-ები და ხელმოწერის კონფიგურაცია. Bazel უზრუნველყოფს გამოქვეყნების ინსტრუმენტებს.

შედით პირდაპირ Bazel-იდან:

```bash
bazel run @rules_tuist//:login
```

ეს იზიარებს მონაცემებს Tuist CLI-თან და Gradle პლაგინთან; არსებული შესვლაც მუშაობს. CI-ზე გამოიყენეთ `TUIST_TOKEN` ან გაუშვით შესვლის სამიზნე Tuist-ის <.localized_link href="/guides/integrations/continuous-integration">OIDC ავთენტიკაციით</.localized_link>. არასდროს მოათავსოთ მონაცემები BUILD ფაილებში ან წესების ატრიბუტებში. გადაეცით `-- --url https://tuist.example.com` საკუთარ სერვერზე განთავსებულ ეგზემპლარში შესასვლელად.

ჩატვირთეთ მხოლოდ საჭირო ადაპტერი თქვენს `BUILD.bazel` ფაილში:

```starlark
load("@rules_tuist//:android.bzl", "android_preview")

android_preview(name = "preview_android", app = ":android_app")
```

Apple აპლიკაციებისთვის:

```starlark
load("@rules_tuist//:apple.bzl", "apple_preview")

apple_preview(name = "preview_ios", app = ":ios_app")
apple_preview(name = "preview_macos", app = ":macos_app")
```

შესრულებადი სამიზნეებისთვის, როგორიცაა `cc_binary`:

```starlark
load("@rules_tuist//:executable.bzl", "executable_preview")

executable_preview(name = "preview_cli", binary = ":my_tool")
```

შესრულებადი პრივიუ შეიცავს სამიზნის მიერ განცხადებულ დროის შესრულების ფაილებს. განაცხადეთ ბიბლიოთეკები და რესურსები, რომლებიც თქვენს ინსტრუმენტს სჭირდება, მის Bazel სამიზნეში და გამოიყენეთ გზები, რომლებიც მუშაობენ თქვენი ბილდის დირექტორიის გარეთ.

## აგება და გამოქვეყნება

```bash
bazel run //:preview_android -- \
  --publish --project acme/app --track review
bazel run //:preview_ios --platforms=//platforms:ios_simulator -- \
  --publish --project acme/app --track review
bazel run //:preview_macos -- --publish --project acme/app --track review
bazel run //:preview_cli -- --publish --project acme/app --track review
```

ჩაანაცვლეთ აპლიკაციისა და სიმულატორის პლატფორმის ლეიბლები თქვენი საკუთარი მნიშვნელობებით. გადაეცით `--url` საკუთარ სერვერზე განთავსებული Tuist წყაროსთვის და `--revision` Git კომიტთან ასოცირებისთვის.

გადაეცით `--publish --project account/project` წარმატებული ბილდის გასაზიარებლად. `--publish`-ის გარეშე, ან `--no-publish`-ით, არაფერი აიტვირთება და შესვლა არ არის საჭირო. ჩვეულებრივი `bazel build` არასდროს აქვეყნებს, მათ შორის ქეშის მოხვედრის შემთხვევაშიც. `tuist bazel setup` ააქტიურებს ქეშირებას და ანალიტიკას, არა გამოქვეყნებას.

## მხარდაჭერილი გამოსავლები

- **Android:** ხელმოწერილი აპლიკაციის APK-ები, დებაგ ბილდების ჩათვლით. დააინსტალირეთ Android SDK build-tools და კომანდური ხაზის ინსტრუმენტები და დააყენეთ `ANDROID_HOME` ან `ANDROID_SDK_ROOT`. ტესტური APK-ები და Android App Bundles არ არის მხარდაჭერილი.
- **Apple:** ad-hoc ხელმოწერილი სიმულატორისა და macOS აპლიკაციები, აგებული და ვერიფიცირებული macOS-ზე. ფიზიკური მოწყობილობის ბილდები, ფრეიმვორქები, გაფართოებები და ტესტები არ არის მხარდაჭერილი. გამოიყენეთ არქივის გამოსავალი ექსპერიმენტული ხის არქივების ნაცვლად.
- **კომანდური ხაზის ინსტრუმენტები:** macOS ან Linux შესრულებადი ფაილები arm64 ან x86_64 არქიტექტურისთვის, უნივერსალური macOS ბინარების ჩათვლით. სკრიპტებს სჭირდებათ shebang და ინტერპრეტატორი მიმღების სისტემაზე. განაცხადეთ დროის შესრულების დამოკიდებულებები თქვენს სამიზნეში; Tuist არ აინსტალირებს დაკარგულ ბიბლიოთეკებს ან ენის გარემოებს.

## ქეშის განმეორება, შეცდომები და შენახვა

იგივე გამოქვეყნების განმეორება იყენებს არსებულ პრივიუს ხელახლა ატვირთვის გარეშე, მაშინაც კი, როცა Bazel აღადგენს ბილდს ქეშიდან. გამოსავლის, ტრეკის ან რევიზიის ცვლილება ქმნის ახალ გამოქვეყნებას. ატვირთვის შეცდომა აფერხებს კომანდას; შეგიძლიათ ხელახლა გაუშვათ იმის შესამოწმებლად, დასრულდა თუ არა გამოქვეყნება, სანამ კიდევ სცადით.

კომანდა ბმავს თქვენი პროექტის პრივიუებზე, სადაც დამუშავებას შეიძლება დრო დასჭირდეს. პრივიუები იყენებენ პროექტის ნაგულისხმევ ხილვადობას.

არტეფაქტების გამოქვეყნებები იწურება 30 დღის შემდეგ hosted Tuist-ზე. საკუთარ სერვერზე განთავსებული ეგზემპლარები იყენებენ `TUIST_APP_PREVIEW_RETENTION_DAYS`; მისი დაუყენებლობა თიშავს ვადას ამ ოჯახისთვის. ვადაგასული გამოქვეყნების ჩანაწერების აღდგენა იგივე მოქმედების განმეორებით შეუძლებელია.

იხილეთ <.localized_link href="/guides/features/previews#run-a-preview">პრივიუს გაშვება</.localized_link> გამოქვეყნებული ბილდების გასაშვებად, წვდომისთვის, ტრეკებისა და README ბეჯებისთვის.

## Apple პრივიუები

Apple სიმულატორისა და macOS პრივიუებისთვის, იხილეთ <.localized_link href="/guides/features/previews/run/macos">Tuist macOS კომპანიონი აპის ინსტრუქციები</.localized_link>. ეს არ ცვლის Bazel-ის აპლიკაციის შესაბამისობის ან ხელმოწერის მოთხოვნებს.
