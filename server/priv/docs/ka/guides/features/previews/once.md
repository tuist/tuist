# Once-ის არტიფაქტების გამოქვეყნება

[Once](https://buildonce.dev/docs/guide/infrastructure/tuist#publish-application-previews)-ს შეუძლია გამოაქვეყნოს უცვლელი არტიფაქტები არსებული Tuist აუთენტიკაციის გამოყენებით. ამისთვის საჭიროა Once 0.74.0+ და Tuist სერვერი არტიფაქტების მიმღებით. Once 0.73.x იყენებს მემკვიდრეობით ერთ-პეილოდიან ადაპტერს.

## დანიშნულების კონფიგურაცია

სამუშაო სივრცის `once.toml` ფაილში:

```toml
[infrastructures.tuist]
kind = "tuist"
account = "acme"
project = "app"

[infrastructure.artifacts]
name = "tuist"
```

```bash
once auth login --provider tuist
once artifact publish MyApplication --track review
```

მიმღები ინახავს სრულ ნაკრებს, წევრების მანიფესტებსა და პეილოადებს, უცნობი ინტერფეისების ჩათვლით. მხარდაჭერილი ნატიური ინტერფეისები ასინქრონულად პროეცირდება პრევიუებში პროექტის ნაგულისხმევი ხილვადობის, წვდომისა და გავრცელების პარამეტრების გამოყენებით. ზოგადი არტიფაქტების შემცველობა რჩება კონფიდენციალურად, მაშინაც კი, თუ პროექტი საჯაროა. ქვითარი ადასტურებს არტიფაქტის შენახვას და არა პრევიუს დამუშავების დასრულებას; მისი URL ხსნის პროექტის პრევიუების სიას.

## შესაბამისი აპლიკაციები

Apple-ის პროექცია იღებს `dev.once.apple-install.v2` მეტამონაცემებს macOS-ზე ექსპორტირებული ad-hoc ხელმოწერილი macOS და სიმულატორის აპლიკაციებისთვის. ფიზიკურ მოწყობილობაზე გათვლილი აპლიკაციები არ არის შესაბამისი. Android-ის პროექცია იღებს `dev.once.android-install.v1` მეტამონაცემებს ვერიფიცირებული ხელმოწერით. Once ამტკიცებს ავტომატურ გამოქვეყნებას მხოლოდ debug-ხელმოწერილი, არა-ინსტრუმენტული APK-ებისთვის. უცნობი ინტერფეისები რჩება ჩამოსატვირთად როგორც არტიფაქტები პრევიუების შექმნის გარეშე. Android-ის ინსტალაციის ბმულები ინარჩუნებენ `.apk` ფაილის სახელს, მიუხედავად იმისა, რომ პეილოადები ინახება შინაარსის დაიჯესტების ქვეშ.

## აირჩიეთ გამოქვეყნება ბილდების შემდეგ

```toml
[infrastructure]
publish_on_build = ["MyApplication"]
```

```bash
once artifact publish MyApplication --allow-on-build
once build MyApplication
```

ყველა მოთხოვნილი ბილდი უნდა დასრულდეს წარმატებით. ავტომატური გამოქვეყნება ასევე მოითხოვს პროდიუსერის მიერ მთლიანი დახურვის (closure) დამტკიცებას და ლოკალურ ავტორიზაციას ამ მანქანის, სამუშაო სივრცის, ზუსტი ბოლოწერტილის, სამიზნისა და სტაბილური Tuist პროექტის დანიშნულებისთვის. პოლიტიკის ან ავტორიზაციის გარეშე არტიფაქტების გამოქვეყნების ქსელური მოთხოვნები არ ხორციელდება. ჩვეულებრივი Once ბილდები რჩება იმპლიციტური გამოქვეყნების გვერდითი ეფექტების გარეშე.

იგივე შენახული გამოქვეყნების განმეორებითი შესრულება ამოწმებს დისტანციურ ქვითარს და თავს არიდებს კიდევ ერთ ატვირთვას. ეს განსხვავდება `tuist share`-ის დუბლიკატური ბილდის ქცევისგან.

## შენახვა

არტიფაქტების გამოქვეყნებები იწურება 30 დღის შემდეგ hosted Tuist-ზე. Self-hosted ინსტანციები იყენებენ `TUIST_APP_PREVIEW_RETENTION_DAYS`-ს; მისი დაუყენებლობა თიშავს ვადას ამ ოჯახისთვის. ვადაგასული ჩანაწერები რჩებიან როგორც „საფლავის ქვები“ (tombstones) და მათი გააქტიურება იგივე განზრახვის განმეორებითი შესრულებით შეუძლებელია. არსებული `tuist share` ხელმოწერის, ხილვადობისა და გავრცელების სამუშაო ნაკადები უცვლელი რჩება.

იხილეთ <.localized_link href="/guides/features/previews#run-a-preview">პრევიუს გაშვება</.localized_link> გამოქვეყნებული ბილდების გასაშვებად, წვდომის, ტრეკებისა და README ბეჯებისთვის.

შესაბამისი Apple სიმულატორისა და macOS პრევიუებისთვის, იხილეთ <.localized_link href="/guides/features/previews/run/macos">Tuist macOS companion აპის ინსტრუქციები</.localized_link>. ფიზიკურ მოწყობილობაზე გათვლილი აპლიკაციები რჩებიან შეუფერებლად Once-ით გამოქვეყნებისთვის.
