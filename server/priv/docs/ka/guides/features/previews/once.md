# Once-ის პრევიუები {#once-previews}

[Once](https://buildonce.dev/docs/guide/infrastructure/tuist#publish-application-previews)-ს შეუძლია გამოაქვეყნოს აპლიკაციის არტეფაქტები Tuist-ზე, რათა გუნდის წევრებმა შეძლონ ბილდის ტესტირება მისი ლოკალურად ხელახლა აგების გარეშე. ამისთვის საჭიროა Once 0.74.0+ და Tuist სერვერი არტეფაქტების მიმღებით. Once 0.73.x იყენებს ძველ ერთჯერადი პეილოადის ადაპტერს.

## დანიშნულების კონფიგურაცია

დაასრულეთ <.localized_link href="/guides/get-started/once-project">Once-ის დაწყება</.localized_link>, შემდეგ დაამატეთ არტეფაქტის ბმული სამუშაო სივრცის `once.toml` ფაილში. ხელახლა გამოიყენეთ პროვაიდერი, თუ ის უკვე კონფიგურირებულია ქეშირებისთვის:

```toml
[infrastructures.tuist]
kind = "tuist"
account = "acme"
project = "app"

[infrastructure.artifacts]
name = "tuist"
```

```bash
once auth login --provider tuist
once artifact publish MyApplication --track review
```

მიმღები ინახავს სრულ ნაკრებს, წევრთა მანიფესტებს და პეილოადებს, უცნობი ინტერფეისების ჩათვლით. მხარდაჭერილი ნატიური ინტერფეისები ასინქრონულად გადაიყვანება პრევიუებში პროექტის ნაგულისხმევი ხილვადობის, წვდომის და დისტრიბუციის პარამეტრების გამოყენებით. ზოგადი არტეფაქტების შიგთავსი რჩება კონფიდენციალური, მაშინაც კი, თუ პროექტი საჯაროა. ქვითარი ადასტურებს არტეფაქტის შენახვას და არა პრევიუს დამუშავების დასრულებას; მისი URL ხსნის პროექტის პრევიუების სიას.

## შესაბამისი აპლიკაციები

Apple-ის პროექცია იღებს `dev.once.apple-install.v2` მეტამონაცემებს ad-hoc ხელმოწერილი macOS და სიმულატორის აპლიკაციებისთვის, რომლებიც ექსპორტირებულია macOS-ზე. ფიზიკურ მოწყობილობებზე განკუთვნილი აპლიკაციები არ არის შესაბამისი. Android-ის პროექცია იღებს `dev.once.android-install.v1` მეტამონაცემებს ვერიფიცირებული ხელმოწერით. Once ავტომატურ გამოქვეყნებას ამტკიცებს მხოლოდ debug-ხელმოწერილი, არა-ინსტრუმენტაციული APK-ებისთვის. უცნობი ინტერფეისები რჩება ჩამოსატვირთად როგორც არტეფაქტები პრევიუების შექმნის გარეშე. Android-ის ინსტალაციის ბმულები ინარჩუნებენ `.apk` ფაილის სახელს, მიუხედავად იმისა, რომ პეილოადები ინახება კონტენტის დაიჯესტების ქვეშ.

## აირჩიეთ გამოქვეყნება ბილდების შემდეგ

```toml
[infrastructure]
publish_on_build = ["MyApplication"]
```

```bash
once artifact publish MyApplication --allow-on-build
once build MyApplication
```

ყველა მოთხოვნილი ბილდი უნდა წარმატებით დასრულდეს. ავტომატური გამოქვეყნება ასევე მოითხოვს მწარმოებლის მიერ მთელი დახურვის (closure) დამტკიცებას და ლოკალურ ავტორიზაციას ამ მანქანის, სამუშაო სივრცის, ზუსტი ბოლოწერტილის, სამიზნის და სტაბილური Tuist პროექტის დანიშნულებისთვის. პოლიტიკის ან ავტორიზაციის გარეშე არ ხდება არტეფაქტების გამოქვეყნების ქსელური მოთხოვნები. ჩვეულებრივი Once ბილდები რჩებიან თავისუფალი იმპლიციური გამოქვეყნების გვერდითი ეფექტებისგან.

იგივე შენახული გამოქვეყნების გამეორება ამოწმებს დისტანციურ ქვითარს და თავს არიდებს ხელახლა ატვირთვას. ეს განსხვავდება `tuist share`-ის ორმაგი ბილდის ქცევისგან.

## შენახვა

არტეფაქტების გამოქვეყნებები იწურება 30 დღის შემდეგ Tuist-ის ჰოსტინგზე. თვითჰოსტინგული ინსტანციები იყენებენ `TUIST_APP_PREVIEW_RETENTION_DAYS`-ს; მისი დაუყენებლობა თიშავს ვადას ამ ოჯახისთვის. ვადაგასული ჩანაწერები რჩებიან როგორც საფლავის ქვები და ვერ გააქტიურდება იგივე განზრახვის გამეორებით. არსებული `tuist share` ხელმოწერის, ხილვადობის და დისტრიბუციის სამუშაო პროცესები უცვლელი რჩება.

იხილეთ <.localized_link href="/guides/features/previews#run-a-preview">პრევიუს გაშვება</.localized_link> გამოქვეყნებული ბილდების გაშვების, წვდომის, ტრეკების და README ბეჯების შესახებ.

## Apple-ის პრევიუები

შესაბამისი Apple სიმულატორის და macOS პრევიუებისთვის, იხილეთ <.localized_link href="/guides/features/previews/run/macos">Tuist macOS კომპანიონის აპლიკაციის ინსტრუქციები</.localized_link>. ფიზიკურ მოწყობილობებზე განკუთვნილი აპლიკაციები კვლავ არ არის შესაბამისი Once-ით გამოქვეყნებისთვის.
