# Once-ის პრივიუები {#once-previews}

[Once](https://buildonce.dev/docs/guide/infrastructure/tuist#publish-application-previews)-ს შეუძლია გამოაქვეყნოს აპლიკაციის არტეფაქტები Tuist-ზე, რათა გუნდის წევრებმა შეძლონ ბილდის ტესტირება მისი ლოკალურად ხელახლა აგების გარეშე. ამისთვის საჭიროა Once 0.74.0+ და Tuist სერვერი არტეფაქტების მიმღებით. Once 0.73.x იყენებს ძველ ერთიანი პეილოადის ადაპტერს.

## დანიშნულების კონფიგურაცია

დაასრულეთ <.localized_link href="/guides/get-started/once-project">Once-ით დაწყება</.localized_link>, შემდეგ დაამატეთ არტეფაქტის ბმული სამუშაო სივრცის `once.toml` ფაილში. ხელახლა გამოიყენეთ პროვაიდერი, თუ ის უკვე კონფიგურირებულია ქეშირებისთვის:

```toml
[infrastructures.tuist]
kind = "tuist"
account = "acme"
project = "app"

[infrastructure.artifacts]
name = "tuist"
```

```bash
once auth login --provider tuist
once artifact publish MyApplication --track review
```

მიმღები ინარჩუნებს სრულ ნაკრებს, წევრთა მანიფესტებს და პეილოადებს, უცნობი ინტერფეისების ჩათვლით. მხარდაჭერილი ნატიური ინტერფეისები ასინქრონულად გადაიყვანება პრივიუებში პროექტის ნაგულისხმევი ხილვადობის, წვდომისა და განაწილების პარამეტრების გამოყენებით. ზოგადი არტეფაქტის შინაარსი რჩება კონფიდენციალური, მაშინაც კი, თუ პროექტი საჯაროა. მიღების ქვითარი ადასტურებს არტეფაქტის შენახვას და არა პრივიუს დამუშავების დასრულებას; მისი URL ხსნის პროექტის პრივიუების სიას.

## შესაბამისი აპლიკაციები

Apple-ის პროექცია იღებს `dev.once.apple-install.v2` მეტამონაცემებს ad-hoc ხელმოწერილი macOS და სიმულატორის აპლიკაციებისთვის, რომლებიც ექსპორტირებულია macOS-ზე. ფიზიკური მოწყობილობის აპლიკაციები არ არის შესაბამისი. Android-ის პროექცია იღებს `dev.once.android-install.v1` მეტამონაცემებს ვერიფიცირებული ხელმოწერით. Once ავტომატურ გამოქვეყნებას ამტკიცებს მხოლოდ debug-ხელმოწერილი, არა-ინსტრუმენტული APK-ებისთვის. უცნობი ინტერფეისები რჩება ჩამოსატვირთად არტეფაქტების სახით პრივიუების შექმნის გარეშე. Android-ის ინსტალაციის ბმულები ინარჩუნებენ `.apk` ფაილის სახელს, მიუხედავად იმისა, რომ პეილოადები ინახება შინაარსის დაიჯესტების ქვეშ.

## აირჩიეთ გამოქვეყნება ბილდების შემდეგ

```toml
[infrastructure]
publish_on_build = ["MyApplication"]
```

```bash
once artifact publish MyApplication --allow-on-build
once build MyApplication
```

ყველა მოთხოვნილი ბილდი უნდა წარმატებით დასრულდეს. ავტომატური გამოქვეყნება ასევე მოითხოვს პროდიუსერის მიერ მთლიანი დახურვის (closure) დამტკიცებას და ლოკალურ ავტორიზაციას ამ მანქანის, სამუშაო სივრცის, ზუსტი ბოლოწერტილის, სამიზნის და სტაბილური Tuist პროექტის დანიშნულებისთვის. პოლიტიკის ან ავტორიზაციის გარეშე არ ხდება არტეფაქტების გამოქვეყნების ქსელური მოთხოვნები. ჩვეულებრივი Once ბილდები რჩებიან იმპლიციური გამოქვეყნების გვერდითი ეფექტების გარეშე.

იგივე შენახული გამოქვეყნების გამეორება ამოწმებს დისტანციურ ქვითარს და თავს არიდებს კიდევ ერთ ატვირთვას. ეს განსხვავდება `tuist share`-ის ორმაგი ბილდის ქცევისგან.

## შენახვა

არტეფაქტების გამოქვეყნებები იწურება 30 დღის შემდეგ Tuist-ის ჰოსტინგზე. თვითმასპინძელი ინსტანციები იყენებენ `TUIST_APP_PREVIEW_RETENTION_DAYS`-ს; მისი დაუყენებლობა თიშავს ვადას ამ ოჯახისთვის. ვადაგასული ჩანაწერები რჩებიან როგორც „საფლავები“ და მათი გააქტიურება იგივე განზრახვის გამეორებით შეუძლებელია. არსებული `tuist share` ხელმოწერის, ხილვადობისა და განაწილების სამუშაო პროცესები უცვლელი რჩება.

იხილეთ <.localized_link href="/guides/features/previews#run-a-preview">პრივიუს გაშვება</.localized_link> გამოქვეყნებული ბილდების გასაშვებად, წვდომის, ტრეკების და README ბეჯებისთვის.

## Apple-ის პრივიუები

შესაბამისი Apple სიმულატორისა და macOS პრივიუებისთვის, იხილეთ <.localized_link href="/guides/features/previews/run/macos">Tuist macOS დამხმარე აპლიკაციის ინსტრუქციები</.localized_link>. ფიზიკური მოწყობილობის აპლიკაციები კვლავ არ არის შესაბამისი Once-ით გამოქვეყნებისთვის.
