# მხარდაჭერილი პრივიუს ტიპები

პრივიუს ტიპი განსაზღვრავს, რას აფუთავთ და სად შეუძლია მას გაშვება, დამოუკიდებლად იმ ბილდ სისტემისგან, რომელიც მას ქმნის. თითოეულ გამოქვეყნების სამუშაო ნაკადს აქვს თავისი ხელმოწერისა და შესაბამისობის მოთხოვნები.

## მობილური აპლიკაციები {#mobile-apps}

- **Android:** ხელმოწერილი აპლიკაციის APK. მიმღებებს სჭირდებათ თავსებადი Android მოწყობილობა ან ემულატორი. Android App Bundles (`.aab`) არ არის პრივიუს ინსტალაციის პაკეტები.
- **Apple:** აპლიკაციის ბანდლი სიმულატორისთვის, ან ექსპორტირებული IPA ფიზიკური მოწყობილობებისთვის. მოწყობილობის ბილდებს სჭირდებათ პროვიზიონირების პროფილი, რომელიც ნებართვას აძლევს ინსტალაციას მიმღების მოწყობილობაზე.

<.localized_link href="/guides/features/previews/xcode">Xcode</.localized_link>, <.localized_link href="/guides/features/previews/gradle">Gradle</.localized_link> და <.localized_link href="/guides/features/previews/bazel">Bazel</.localized_link> სახელმძღვანელოები აღწერენ, თუ რომელი გამოსავლების გამოქვეყნება შეუძლია თითოეულ სამუშაო ნაკადს. მაგალითად, Bazel და Once გამოქვეყნება მხარს უჭერს შესაბამის Apple სიმულატორისა და macOS აპლიკაციებს, არა ფიზიკური მოწყობილობის ბილდებს.

## დესკტოპ აპლიკაციები {#desktop-apps}

გაუზიარეთ აწყობილი macOS აპლიკაციის ბანდლი:

```bash
tuist share path/to/MyApp.app
```

ხელმოწერისა და ნოტარიზაციის მოთხოვნები კვლავ მოქმედებს. დესკტოპ აპლიკაციის ბანდლი განსხვავდება Tuist macOS აპლიკაციისგან, რომლის გამოყენებაც მიმღებებს შეუძლიათ პრივიუსების გასაშვებად.

## კომანდური ხაზის ინსტრუმენტები {#command-line-tools}

გაუზიარეთ დამოუკიდებელი შესრულებადი ფაილი macOS-ზე ან Linux-ზე:

```bash
tuist share path/to/my-tool
```

თუ CLI-ს სჭირდება რესურსების ბანდლები, დინამიური ბიბლიოთეკები ან დამხმარე შესრულებადი ფაილები, შეადგინეთ დისტრიბუციის დირექტორია და მიუთითეთ მისი შესვლის წერტილი ამ დირექტორიის მიმართებაში:

```bash
tuist share path/to/distribution --executable bin/my-tool
```

იტვირთება მთლიანი დისტრიბუციის დირექტორია. ჩართეთ ბიბლიოთეკები, რესურსები და დამხმარე ფაილები, რომლებიც თქვენს ინსტრუმენტს სჭირდება, და დარწმუნდით, რომ მას შეუძლია გაშვება თქვენი ბილდის დირექტორიის გარეთ. სკრიპტებს სჭირდებათ shebang და ინტერპრეტატორი, რომელიც ინსტალირებულია მიმღების სისტემაზე.

## რამდენიმე CLI სამიზნე {#multiple-cli-targets}

პრივიუ აჯგუფებს ერთი და იგივე CLI-ის ბილდებს ერთი კომიტისთვის; თითოეული ბილდი შეიცავს დისტრიბუციას ერთი ოპერაციული სისტემისა და ერთი ან მეტი CPU არქიტექტურისთვის. მაგალითად, ერთ პრივიუში შეიძლება იყოს macOS arm64, macOS x86_64 და Linux x86_64 დისტრიბუციები. უნივერსალური macOS შესრულებადი ფაილი ფარავს ორივე Mac არქიტექტურას ერთ ბილდში.

ააწყვეთ თითოეული სამიზნე ცალ-ცალკე, შემდეგ გამოაქვეყნეთ დისტრიბუციები თანმიმდევრულად იგივე Git checkout-დან, იგივე შესვლის წერტილის საბაზისო სახელითა და ტრეკით:

```bash
tuist share dist/macos-arm64 --executable bin/tuist --track pr
tuist share dist/macos-x86_64 --executable bin/tuist --track pr
tuist share dist/linux-x86_64 --executable bin/tuist --track pr
```

ეს ატვირთვები ამატებს ბილდებს იგივე პრივიუს ბმულს. შეინარჩუნეთ პროექტი, კომიტი, გამომქვეყნებელი ანგარიში, CLI-ის სახელი და ტრეკი იდენტური ყველა ატვირთვისას. Tuist ირჩევს ბილდს, რომელიც შეესაბამება მიმღების ოპერაციულ სისტემასა და CPU არქიტექტურას.

## კლიენტისა და სერვერის თავსებადობა {#client-and-server-compatibility}

გამოიყენეთ განახლებული Tuist CLI დესკტოპისა და კომანდური ხაზის პრივიუსების გასაშვებად. თუ Tuist-ს თვითონ ჰოსტავთ, განაახლეთ თქვენი სერვერი ამ ტიპების გამოქვეყნებამდე. მობილური პრივიუები კვლავ მუშაობს ძველ კლიენტებთან.

ააწყვეთ თქვენი მიმღებების ოპერაციული სისტემებისა და CPU არქიტექტურებისთვის. Tuist არ აკეთებს თქვენი აპლიკაციის ჯვარედინ კომპილაციას ან მისი დამოკიდებულებების ინსტალაციას; Linux ინსტრუმენტებს ასევე სჭირდებათ თავსებადი სისტემური ბიბლიოთეკები.

პრივიუები გაშვებულია თქვენი მომხმარებლის ანგარიშის ნებართვებით, არა სენდბოქსში. გაუშვით მხოლოდ ის ბილდები, რომლებიც ეკუთვნის ავტორებსა და pull request-ებს, რომლებსაც ენდობით.
