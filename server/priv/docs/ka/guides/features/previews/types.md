# მხარდაჭერილი პრივიუსების ტიპები

პრივიუსის ტიპი განსაზღვრავს, რას აკეთებთ პაკეტად და სად შეუძლია მას გაშვება, დამოუკიდებლად იმ ბილდის სისტემისგან, რომელიც მას ქმნის. თითოეულ გამოქვეყნების სამუშაო ნაკადს აქვს თავისი ხელმოწერისა და შესაბამისობის მოთხოვნები.

## მობილური აპლიკაციები {#mobile-apps}

- **Android:** ხელმოწერილი აპლიკაციის APK. მიმღებებს სჭირდებათ თავსებადი Android მოწყობილობა ან ემულატორი. Android App Bundles (`.aab`) არ არის პრივიუსის ინსტალაციის პაკეტები.
- **Apple:** აპლიკაციის ბანდლი სიმულატორისთვის ან ექსპორტირებული IPA ფიზიკური მოწყობილობებისთვის. მოწყობილობის ბილდებს სჭირდებათ პროვიზიონინგის პროფილი, რომელიც იძლევა ინსტალაციის უფლებას მიმღების მოწყობილობაზე.

<.localized_link href="/guides/features/previews/xcode">Xcode</.localized_link>, <.localized_link href="/guides/features/previews/gradle">Gradle</.localized_link> და <.localized_link href="/guides/features/previews/bazel">Bazel</.localized_link> სახელმძღვანელოები აღწერენ, თუ რომელ გამომავალ ფაილებს შეუძლია თითოეული სამუშაო ნაკადის გამოქვეყნება. მაგალითად, Bazel და Once გამოქვეყნება მხარს უჭერს შესაბამის Apple სიმულატორისა და macOS აპლიკაციებს, არა ფიზიკური მოწყობილობის ბილდებს.

## დესკტოპის აპლიკაციები {#desktop-apps}

გააზიარეთ აწყობილი macOS აპლიკაციის ბანდლი:

```bash
tuist share path/to/MyApp.app
```

ხელმოწერისა და ნოტარიზაციის მოთხოვნები კვლავ მოქმედებს. დესკტოპის აპლიკაციის ბანდლი განსხვავდება Tuist macOS აპლიკაციისგან, რომლის გამოყენებაც მიმღებებს შეუძლიათ პრივიუსების გასაშვებად.

## კომანდური ხაზის ინსტრუმენტები {#command-line-tools}

გააზიარეთ დამოუკიდებელი შესრულებადი ფაილი macOS-ზე ან Linux-ზე:

```bash
tuist share path/to/my-tool
```

თუ CLI-ს სჭირდება რესურსების ბანდლები, დინამიური ბიბლიოთეკები ან დამხმარე შესრულებადი ფაილები, შეადგინეთ დისტრიბუციის დირექტორია და მიუთითეთ მისი შესვლის წერტილი ამ დირექტორიის მიმართ:

```bash
tuist share path/to/distribution --executable bin/my-tool
```

იტვირთება მთლიანი დისტრიბუციის დირექტორია. ჩართეთ ბიბლიოთეკები, რესურსები და დამხმარე ფაილები, რომლებიც თქვენს ინსტრუმენტს სჭირდება, და დარწმუნდით, რომ მას შეუძლია გაშვება თქვენი ბილდის დირექტორიის გარეთ. სკრიპტებს სჭირდებათ shebang და ინტერპრეტატორი, რომელიც ინსტალირებულია მიმღების სისტემაში.

## რამდენიმე CLI სამიზნე {#multiple-cli-targets}

პრივიუსი აჯგუფებს ერთი და იგივე CLI-ის ბილდებს ერთი კომიტისთვის; თითოეული ბილდი შეიცავს დისტრიბუციას ერთი ოპერაციული სისტემისა და ერთი ან მეტი CPU არქიტექტურისთვის. მაგალითად, ერთ პრივიუსში შეიძლება იყოს macOS arm64, macOS x86_64 და Linux x86_64 დისტრიბუციები. უნივერსალური macOS შესრულებადი ფაილი ფარავს ორივე Mac არქიტექტურას ერთ ბილდში.

ააწყვეთ თითოეული სამიზნე ცალ-ცალკე, შემდეგ გამოაქვეყნეთ დისტრიბუციები თანმიმდევრულად ერთი და იგივე Git ჩეკაუთიდან, იგივე შესვლის წერტილის ბაზური სახელითა და ტრეკით:

```bash
tuist share dist/macos-arm64 --executable bin/tuist --track pr
tuist share dist/macos-x86_64 --executable bin/tuist --track pr
tuist share dist/linux-x86_64 --executable bin/tuist --track pr
```

ეს ატვირთვები ამატებს ბილდებს იმავე პრივიუსის ბმულზე. შეინახეთ პროექტი, კომიტი, გამომქვეყნებელი ანგარიში, CLI-ის სახელი და ტრეკი იდენტური ყველა ატვირთვისას. Tuist ირჩევს ბილდს, რომელიც შეესაბამება მიმღების ოპერაციულ სისტემასა და CPU არქიტექტურას.

## კლიენტისა და სერვერის თავსებადობა {#client-and-server-compatibility}

გამოიყენეთ განახლებული Tuist CLI დესკტოპისა და კომანდური ხაზის პრივიუსების გასაშვებად. თუ Tuist-ს თვითონ ჰოსტავთ, განაახლეთ თქვენი სერვერი ამ ტიპების გამოქვეყნებამდე. მობილური პრივიუსები კვლავ მუშაობს ძველ კლიენტებთან.

ააწყვეთ თქვენი მიმღებების ოპერაციული სისტემებისა და CPU არქიტექტურებისთვის. Tuist არ აკეთებს თქვენი აპლიკაციის ჯვარედინ კომპილაციას ან არ აყენებს მის დამოკიდებულებებს; Linux ინსტრუმენტებს ასევე სჭირდებათ თავსებადი სისტემური ბიბლიოთეკები.

პრივიუსები გაშვებულია თქვენი მომხმარებლის ანგარიშის უფლებებით, არა სენდბოქსში. გაუშვით მხოლოდ ის ბილდები, რომელთა ავტორებსა და pull request-ებსაც ენდობით.
