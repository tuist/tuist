# მხარდაჭერილი პრივიუს ტიპები

პრივიუს ტიპი განსაზღვრავს, რას აკეთებთ პაკეტად და სად შეუძლია მას გაშვება, დამოუკიდებლად იმ ბილდ სისტემისგან, რომელიც მას ქმნის. თითოეულ გამოქვეყნების ნაკადს აქვს თავისი ხელმოწერისა და შესაბამისობის მოთხოვნები.

## მობილური აპლიკაციები {#mobile-apps}

- **Android:** ხელმოწერილი აპლიკაციის APK. მიმღებებს სჭირდებათ თავსებადი Android მოწყობილობა ან ემულატორი. Android App Bundles (`.aab`) არ არის პრივიუს ინსტალაციის პაკეტები.
- **Apple:** აპლიკაციის ბანდლი სიმულატორისთვის ან ექსპორტირებული IPA ფიზიკური მოწყობილობებისთვის. მოწყობილობის ბილდებს სჭირდებათ პროვიზიონინგის პროფილი, რომელიც უშვებს ინსტალაციას მიმღების მოწყობილობაზე.

<.localized_link href="/guides/features/previews/xcode">Xcode</.localized_link>-ის, <.localized_link href="/guides/features/previews/gradle">Gradle</.localized_link>-ისა და <.localized_link href="/guides/features/previews/bazel">Bazel</.localized_link>-ის სახელმძღვანელოები აღწერენ, თუ რომელ გამოსავლებს შეუძლია თითოეული ნაკადის გამოქვეყნება. მაგალითად, Bazel-ისა და Struo-ს გამოქვეყნება მხარს უჭერს შესაბამის Apple სიმულატორისა და macOS აპლიკაციებს, არა ფიზიკური მოწყობილობის ბილდებს.

## დესკტოპ აპლიკაციები {#desktop-apps}

გააზიარეთ აგებული macOS აპლიკაციის ბანდლი:

```bash
tuist share path/to/MyApp.app
```

ხელმოწერისა და ნოტარიზაციის მოთხოვნები კვლავ მოქმედებს. დესკტოპ აპლიკაციის ბანდლი განსხვავდება Tuist macOS აპლიკაციისგან, რომლის გამოყენებაც მიმღებებს შეუძლიათ პრივიუსების გასაშვებად.

## კომანდური ხაზის ინსტრუმენტები {#command-line-tools}

გააზიარეთ დამოუკიდებელი შესრულებადი ფაილი macOS-ზე ან Linux-ზე:

```bash
tuist share path/to/my-tool
```

თუ CLI-ს სჭირდება რესურსების ბანდლები, დინამიური ბიბლიოთეკები ან დამხმარე შესრულებადი ფაილები, შეადგინეთ დისტრიბუციის დირექტორია და მიუთითეთ მისი შესვლის წერტილი ამ დირექტორიასთან მიმართებაში:

```bash
tuist share path/to/distribution --executable bin/my-tool
```

იტვირთება მთლიანი დისტრიბუციის დირექტორია. ჩართეთ ბიბლიოთეკები, რესურსები და დამხმარე ფაილები, რომლებიც თქვენს ინსტრუმენტს სჭირდება, და დარწმუნდით, რომ მას შეუძლია გაშვება თქვენი ბილდის დირექტორიის გარეთ. სკრიპტებს სჭირდებათ shebang და ინტერპრეტატორი, რომელიც ინსტალირებულია მიმღების სისტემაზე.

შესრულებად ფაილებს არ აქვთ საკუთარი ხატულა. გადაეცით PNG `--icon`-ით, რათა ის გამოჩნდეს პრივიუზე, მაგალითად, Linux დესკტოპ აპლიკაციისთვის:

```bash
tuist share path/to/distribution --executable bin/my-app --icon path/to/icon.png
```

## რამდენიმე CLI სამიზნე {#multiple-cli-targets}

პრივიუ აჯგუფებს ერთი და იგივე CLI-ის ბილდებს ერთი კომიტისთვის; თითოეული ბილდი შეიცავს დისტრიბუციას ერთი ოპერაციული სისტემისა და ერთი ან მეტი CPU არქიტექტურისთვის. მაგალითად, ერთ პრივიუში შეიძლება იყოს macOS arm64, macOS x86_64 და Linux x86_64 დისტრიბუციები. უნივერსალური macOS შესრულებადი ფაილი ფარავს ორივე Mac არქიტექტურას ერთ ბილდში.

ააგეთ თითოეული სამიზნე ცალ-ცალკე, შემდეგ გამოაქვეყნეთ დისტრიბუციები თანმიმდევრულად იგივე Git ჩეკაუტიდან, იგივე შესვლის წერტილის საბაზისო სახელითა და ტრეკით:

```bash
tuist share dist/macos-arm64 --executable bin/tuist --track pr
tuist share dist/macos-x86_64 --executable bin/tuist --track pr
tuist share dist/linux-x86_64 --executable bin/tuist --track pr
```

ეს ატვირთვები ამატებს ბილდებს იგივე პრივიუს ლინკზე. შეინახეთ პროექტი, კომიტი, გამომქვეყნებელი ანგარიში, CLI-ის სახელი და ტრეკი იდენტური ყველა ატვირთვისთვის. Tuist ირჩევს ბილდს, რომელიც შეესაბამება მიმღების ოპერაციულ სისტემასა და CPU არქიტექტურას.

## კლიენტისა და სერვერის თავსებადობა {#client-and-server-compatibility}

გამოიყენეთ უახლესი Tuist CLI დესკტოპისა და კომანდური ხაზის პრივიუსების გასაშვებად. თუ Tuist-ს თვითონ ჰოსტავთ, განაახლეთ თქვენი სერვერი ამ ტიპების გამოქვეყნებამდე. მობილური პრივიუები კვლავ მუშაობენ ძველ კლიენტებთან.

ააგეთ თქვენი მიმღებების ოპერაციული სისტემებისა და CPU არქიტექტურებისთვის. Tuist არ აკეთებს თქვენი აპლიკაციის ჯვარედინ კომპილაციას ან არ აყენებს მის დამოკიდებულებებს; Linux ინსტრუმენტებს ასევე სჭირდებათ თავსებადი სისტემური ბიბლიოთეკები.

პრივიუები გაშვებულია თქვენი მომხმარებლის ანგარიშის უფლებებით, არა სენდბოქსში. გაუშვით მხოლოდ ის ბილდები, რომელთა ავტორებსა და pull request-ებს ენდობით.
