# Gradle-ის პრევიუები

ააწყვეთ და გააზიარეთ Android აპლიკაციები და ნატიური კომანდური ხაზის ინსტრუმენტები პირდაპირ Gradle-დან. დაიწყეთ <.localized_link href="/guides/get-started/gradle-project">Gradle-ის პროექტის სახელმძღვანელო</.localized_link> პროექტის დასაკავშირებლად და ავტორიზაციისთვის.

## Android აპლიკაციები

```bash
./gradlew :app:tuistShareDebug
```

`dev.tuist` პარამეტრების პლაგინი რეგისტრირებს `tuistShare<Variant>` ამოცანას Android Gradle Plugin-ის (8.8.2 ან უფრო გვიანი ვერსია) თითოეული აპლიკაციის ვარიანტისთვის. შეცვალეთ `app` და `Debug` თქვენი აპლიკაციის მოდულითა და ვარიანტით, მაგალითად, `:app:tuistShareDemoDebug` პროდუქტის ფლეივორისთვის. ამოცანა ააწყობს APK-ს Gradle-ის გამოცხადებული არტიფაქტის დამოკიდებულებების მეშვეობით მის გამოქვეყნებამდე. ის ასევე მუშაობს, როცა ბილდის შედეგები განახლებულია ან აღდგენილია ბილდის ქეშიდან.

მხარდაჭერილია მხოლოდ ერთი, ხელმოწერილი, უნივერსალური აპლიკაციის APK. Android-ის debug ვარიანტი ჩვეულებრივ იყენებს debug ხელმოწერის გასაღებს; release ვარიანტებს სჭირდებათ თქვენი საკუთარი ხელმოწერის კონფიგურაცია. ამოცანა ამოწმებს APK ხელმოწერას ავტორიზაციამდე ან ატვირთვამდე. ხელმოუწერილი, არასწორი, ინსტრუმენტული და გაყოფილი APK-ები უარყოფილია. ბიბლიოთეკის მოდულები, ტესტის APK-ები და Android App Bundles (`.aab`) არ არიან გამოქვეყნების სამიზნეები.

## ნატიური კომანდური ხაზის ინსტრუმენტები

პროექტები, რომლებიც იყენებენ Gradle-ის `cpp-application` ან `swift-application` პლაგინს, იღებენ გაზიარების ამოცანას თითოეული ნატიური ბინარისთვის:

```bash
./gradlew :app:tuistShareMainDebug
```

ამოცანა ააწყობს და აფორმებს ინსტალირებულ დისტრიბუციას, მისი გამშვებისა და შესრულების დროის ბიბლიოთეკების ჩათვლით. გამოიყენეთ `tuistShareMainRelease` release ბინარისთვის. პროექტებს, რომლებიც მიზნად ისახავენ მრავალ მანქანას, აქვთ ამოცანა თითოეული ბინარისთვის; გაუშვით `./gradlew :app:tasks --all` მათი სახელების საპოვნელად.

მხარდაჭერილია ნატიური macOS და Linux შესრულებადი ფაილები arm64 ან x86_64 არქიტექტურისთვის. ააწყვეთ სამიზნე პლატფორმაზე თქვენი Gradle პლაგინისთვის საჭირო ინსტრუმენტთა ჯაჭვის გამოყენებით. JVM აპლიკაციები და მათი გენერირებული გამშვების სკრიპტები არ არის მხარდაჭერილი ამ ინტეგრაციით.

## გამოქვეყნების ქცევა

გაზიარების ამოცანები აქვეყნებენ პლაგინის არსებული Tuist სერთიფიკატების გამოყენებით, Tuist CLI-ის გამოძახების გარეშე. ჩვეულებრივი `assemble`, `build` და ტესტის ამოცანები არასდროს აქვეყნებენ პრევიუებს.

გაზიარების შემდეგ, გახსენით **პრევიუები** თქვენს პროექტში ბმულის დასაკოპირებლად. იგივე ბილდისა და ტრეკის გაზიარების განმეორება ხელახლა იყენებს მის გამოქვეყნებას, ბილდის ქეშში მოხვედრის შემდეგაც კი. წარუმატებელი ან დაუდასტურებელი ატვირთვები აფერხებენ გაზიარების ამოცანას; ისინი არ არის მოხსენიებული, როგორც წარმატებული პრევიუები.

## CI და ტრეკები

დააკონფიგურირეთ <.localized_link href="/guides/integrations/continuous-integration">CI ავტორიზაცია</.localized_link> იმავე სერთიფიკატებით, რომლებსაც იყენებთ პლაგინის სხვა ავტორიზებულ ფუნქციებში, შემდეგ მოითხოვეთ გამოქვეყნება ცალსახად:

```bash
./gradlew :app:tuistShareDebug --track nightly
```

დაამატეთ `--track nightly` ნატიური გაზიარების ამოცანას იგივე გზით. ამოცანები იყენებენ კონფიგურირებულ Tuist პროექტს, სერვერის URL-ს და პროქსის პარამეტრებს. პრევიუს გამოქვეყნება ყოველთვის მოითხოვს ავტორიზაციას. Git რევიზიის მეტამონაცემები, რელიზის შენიშვნები და ავტომატური pull-request კომენტარები არ არის მიმაგრებული ამ ამოცანების მიერ.

არტიფაქტის გამოქვეყნებები იწურება 30 დღის შემდეგ hosted Tuist-ზე. Self-hosted ინსტანციები იყენებენ `TUIST_APP_PREVIEW_RETENTION_DAYS`; მისი დაუყენებლობა თიშავს ვადაგასვლას ამ ოჯახისთვის. ვადაგასული გამოქვეყნებები ვერ აღდგება იგივე მოქმედების განმეორებით.

## არსებული APK-ს გაზიარება

APK-სთვის, რომელიც აწყობილია ამ სამუშაო ნაკადის გარეთ, ან რელიზის შენიშვნების ჩასართავად ძველი ატვირთვის ნაკადთან ერთად, CLI კვლავ ხელმისაწვდომია:

```bash
tuist share app/build/outputs/apk/debug/app-debug.apk \
  --track nightly --release-notes "Improve checkout"
```
