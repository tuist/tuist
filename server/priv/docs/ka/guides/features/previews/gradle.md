# Gradle-ის პრევიუები

ააწყვეთ და გააზიარეთ Android აპლიკაციები და ნეიტიური კომანდური ხაზის ინსტრუმენტები პირდაპირ Gradle-დან. დაიწყეთ <.localized_link href="/guides/get-started/gradle-project">Gradle პროექტის სახელმძღვანელოთი</.localized_link> პროექტის დასაკავშირებლად და ავტორიზაციისთვის.

## Android აპლიკაციები

```bash
./gradlew :app:tuistShareDebug
```

`dev.tuist` პარამეტრების პლაგინი რეგისტრირებს `tuistShare<Variant>` ამოცანას თითოეული აპლიკაციის ვარიანტისთვის Android Gradle Plugin-იდან (8.8.2 ან უფრო გვიანი). შეცვალეთ `app` და `Debug` თქვენი აპლიკაციის მოდულითა და ვარიანტით, მაგალითად `:app:tuistShareDemoDebug` პროდუქტის ფლეივორისთვის. ამოცანა ააწყობს APK-ს Gradle-ის მიერ განაცხადებული არტეფაქტის დამოკიდებულებების მეშვეობით მის გამოქვეყნებამდე. ის ასევე მუშაობს, როდესაც ბილდის გამოსავალი აქტუალურია ან აღდგენილია ბილდის ქეშიდან.

მხარდაჭერილია მხოლოდ ერთი, ხელმოწერილი, უნივერსალური აპლიკაციის APK. Android-ის debug ვარიანტი ჩვეულებრივ იყენებს debug ხელმოწერის გასაღებს; release ვარიანტებს სჭირდებათ თქვენი საკუთარი ხელმოწერის კონფიგურაცია. ამოცანა ამოწმებს APK ხელმოწერას ავტორიზაციამდე ან ატვირთვამდე. ხელმოუწერელი, არასწორი, ინსტრუმენტული და გაყოფილი APK უარყოფილია. ბიბლიოთეკის მოდულები, ტესტის APK და Android App Bundles (`.aab`) არ არის გამოქვეყნების სამიზნეები.

## ნეიტიური კომანდური ხაზის ინსტრუმენტები

პროექტები, რომლებიც იყენებენ Gradle-ის `cpp-application` ან `swift-application` პლაგინს, იღებენ გაზიარების ამოცანას თითოეული ნეიტიური ბინარისთვის:

```bash
./gradlew :app:tuistShareMainDebug
```

ამოცანა ააწყობს და აფუთავს ინსტალირებულ დისტრიბუციას, მისი გამშვებისა და შესრულების ბიბლიოთეკების ჩათვლით. გამოიყენეთ `tuistShareMainRelease` release ბინარისთვის. პროექტებს, რომლებიც რამდენიმე მანქანას ემიზნებიან, აქვთ ამოცანა თითოეული ბინარისთვის; გაუშვით `./gradlew :app:tasks --all` მათი სახელების საპოვნელად.

მხარდაჭერილია ნეიტიური macOS და Linux შესრულებადი ფაილები arm64 ან x86_64-ისთვის. ააწყვეთ სამიზნე პლატფორმაზე თქვენი Gradle პლაგინისთვის საჭირო ინსტრუმენტთა ჯაჭვით. JVM აპლიკაციები და მათი გენერირებული გამშვები სკრიპტები არ არის მხარდაჭერილი ამ ინტეგრაციით.

## გამოქვეყნების ქცევა

გაზიარების ამოცანები აქვეყნებენ პლაგინის არსებული Tuist სერთიფიკატების გამოყენებით, Tuist CLI-ის გამოძახების გარეშე. ჩვეულებრივი `assemble`, `build` და ტესტის ამოცანები არასდროს აქვეყნებენ პრევიუებს.

გაზიარების შემდეგ, გახსენით **Previews** თქვენს პროექტში ბმულის დასაკოპირებლად. იგივე ბილდისა და ტრეკის გაზიარების განმეორება ხელახლა იყენებს მის გამოქვეყნებას, ბილდის ქეშში მოხვედრის შემდეგაც კი. წარუმატებელი ან დაუდასტურებელი ატვირთვები აფრუშებენ გაზიარების ამოცანას; ისინი არ არის მოხსენიებული, როგორც წარმატებული პრევიუები.

## CI და ტრეკები

კონფიგურირება <.localized_link href="/guides/integrations/continuous-integration">CI ავტორიზაცია</.localized_link> იმავე სერთიფიკატებით, რომლებსაც იყენებთ პლაგინის სხვა ავტორიზებულ ფუნქციებისთვის, შემდეგ მოითხოვეთ გამოქვეყნება ცალსახად:

```bash
./gradlew :app:tuistShareDebug --track nightly
```

დაამატეთ `--track nightly` ნეიტიურ გაზიარების ამოცანას იმავე გზით. ამოცანები იყენებენ კონფიგურირებულ Tuist პროექტს, სერვერის URL-ს და პროქსის პარამეტრებს. პრევიუს გამოქვეყნება ყოველთვის მოითხოვს ავტორიზაციას. Git რევიზიის მეტამონაცემები, გამოშვების შენიშვნები და ავტომატური pull-request კომენტარები არ არის მიმაგრებული ამ ამოცანების მიერ.

არტეფაქტის გამოქვეყნებები იწურება 30 დღის შემდეგ hosted Tuist-ზე. Self-hosted ინსტანციები იყენებენ `TUIST_APP_PREVIEW_RETENTION_DAYS`; მისი დაუყენებლობა თიშავს ვადას ამ ოჯახისთვის. ვადაგასული გამოქვეყნებების აღდგენა შეუძლებელია იმავე ქმედების განმეორებით.

## არსებული APK-ს გაზიარება

APK-სთვის, რომელიც აწყობილია ამ სამუშაო პროცესის გარეთ, ან რათა ჩართოთ გამოშვების შენიშვნები ძველი ატვირთვის ნაკადთან, CLI რჩება ხელმისაწვდომი:

```bash
tuist share app/build/outputs/apk/debug/app-debug.apk \
  --track nightly --release-notes "Improve checkout"
```

იხილეთ <.localized_link href="/guides/features/previews#run-a-preview">Run a preview</.localized_link> გამოქვეყნებული ბილდების გასაშვებად, წვდომისთვის, ტრეკებისთვის და README ბეჯებისთვის.
