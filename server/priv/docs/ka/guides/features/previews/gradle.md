# Gradle-ის პრევიუები

ააწყვეთ და გააზიარეთ Android აპლიკაციები და ნატიური კომანდური ხაზის ინსტრუმენტები პირდაპირ Gradle-დან. დაიწყეთ <.localized_link href="/guides/get-started/gradle-project">Gradle პროექტის სახელმძღვანელოთი</.localized_link> პროექტის დასაკავშირებლად და ავტორიზაციისთვის.

## Android აპლიკაციები

```bash
./gradlew :app:tuistShareDebug
```

`dev.tuist` პარამეტრების პლაგინი რეგისტრირებს `tuistShare<Variant>` ამოცანას თითოეული აპლიკაციის ვარიანტისთვის Android Gradle Plugin-დან (8.8.2 ან უფრო გვიანი). შეცვალეთ `app` და `Debug` თქვენი აპლიკაციის მოდულითა და ვარიანტით, მაგალითად `:app:tuistShareDemoDebug` პროდუქტის ფლეივორისთვის. ამოცანა ქმნის APK-ს Gradle-ის მიერ განცხადებული არტეფაქტის დამოკიდებულებების მეშვეობით მის გამოქვეყნებამდე. ის ასევე მუშაობს, როდესაც ბილდის გამონატანები აქტუალურია ან აღდგენილია ბილდის ქეშიდან.

მხარდაჭერილია მხოლოდ ერთი, ხელმოწერილი, უნივერსალური აპლიკაციის APK. Android-ის debug ვარიანტი ჩვეულებრივ იყენებს debug ხელმოწერის გასაღებს; release ვარიანტებს სჭირდებათ თქვენი საკუთარი ხელმოწერის კონფიგურაცია. ამოცანა ამოწმებს APK ხელმოწერას ავტორიზაციამდე ან ატვირთვამდე. ხელმოუწერელი, არასწორი, ინსტრუმენტული და გაყოფილი APK-ები უარყოფილია. ბიბლიოთეკის მოდულები, ტესტის APK-ები და Android App Bundles (`.aab`) არ არის გამოქვეყნების სამიზნეები.

## ნატიური კომანდური ხაზის ინსტრუმენტები

პროექტები, რომლებიც იყენებენ Gradle-ის `cpp-application` ან `swift-application` პლაგინს, იღებენ გაზიარების ამოცანას თითოეული ნატიური ბინარისთვის:

```bash
./gradlew :app:tuistShareMainDebug
```

ამოცანა ქმნის და აფუთებს დაინსტალირებულ დისტრიბუციას, მათ შორის მის ლაუნჩერსა და შესრულების ბიბლიოთეკებს. გამოიყენეთ `tuistShareMainRelease` release ბინარისთვის. პროექტებს, რომლებიც რამდენიმე მანქანას ემიზნებიან, აქვთ ამოცანა თითოეული ბინარისთვის; გაუშვით `./gradlew :app:tasks --all` მათი სახელების საპოვნელად.

მხარდაჭერილია ნატიური macOS და Linux შესრულებადი ფაილები arm64 ან x86_64-ისთვის. ააწყვეთ სამიზნე პლატფორმაზე თქვენი Gradle პლაგინისთვის საჭირო ინსტრუმენტთა ჯაჭვით. JVM აპლიკაციები და მათი გენერირებული ლაუნჩერის სკრიპტები არ არის მხარდაჭერილი ამ ინტეგრაციის მიერ.

## გამოქვეყნების ქცევა

გაზიარების ამოცანები აქვეყნებენ პლაგინის არსებული Tuist კრედენციალების გამოყენებით, Tuist CLI-ის გამოძახების გარეშე. ჩვეულებრივი `assemble`, `build` და ტესტის ამოცანები არასდროს აქვეყნებენ პრევიუებს.

გაზიარების შემდეგ, გახსენით **პრევიუები** თქვენს პროექტში ბმულის დასაკოპირებლად. იგივე ბილდისა და ტრეკის გაზიარების განმეორება ხელახლა იყენებს მის გამოქვეყნებას, მათ შორის ბილდ-ქეშში მოხვედრის შემდეგაც. წარუმატებელი ან დაუდასტურებელი ატვირთვები აფრთხობენ გაზიარების ამოცანას; ისინი არ იუწყებიან როგორც წარმატებული პრევიუები.

## CI და ტრეკები

დააკონფიგურირეთ <.localized_link href="/guides/integrations/continuous-integration">CI ავტორიზაცია</.localized_link> იმავე კრედენციალებით, რომლებსაც იყენებთ პლაგინის სხვა ავტორიზებულ ფუნქციებისთვის, შემდეგ მოითხოვეთ გამოქვეყნება ცალსახად:

```bash
./gradlew :app:tuistShareDebug --track nightly
```

დაამატეთ `--track nightly` ნატიურ გაზიარების ამოცანას იმავე გზით. ამოცანები იყენებენ კონფიგურირებულ Tuist პროექტს, სერვერის URL-სა და პროქსის პარამეტრებს. პრევიუს გამოქვეყნება ყოველთვის მოითხოვს ავტორიზაციას. Git რევიზიის მეტამონაცემები, გამოშვების შენიშვნები და ავტომატური pull-request კომენტარები არ არის მიმაგრებული ამ ამოცანების მიერ.

არტეფაქტების გამოქვეყნებები იწურება 30 დღის შემდეგ hosted Tuist-ზე. Self-hosted ინსტანციები იყენებენ `TUIST_APP_PREVIEW_RETENTION_DAYS`; მისი დაუყენებლობა თიშავს ვადას ამ ოჯახისთვის. ვადაგასული გამოქვეყნებები ვერ აღდგება იმავე განზრახვის განმეორებით.

## არსებული APK-ის გაზიარება

APK-ისთვის, რომელიც აწყობილია ამ სამუშაო ნაკადის გარეთ, ან legacy ატვირთვის ნაკადთან გამოშვების შენიშვნების ჩასართავად, CLI კვლავ ხელმისაწვდომია:

```bash
tuist share app/build/outputs/apk/debug/app-debug.apk \
  --track nightly --release-notes "Improve checkout"
```
