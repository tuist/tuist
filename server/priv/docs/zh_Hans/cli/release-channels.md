# 发布渠道 {#release-channels}

Tuist CLI 通过三个渠道发布，各自提供不同的稳定性保障。推荐安装的是 **稳定版**，更新节奏较慢：它不会在每次功能合并时都前进，因此升级不再意味着要吸收一批无关的变更。早期采用者仍可以在 **金丝雀版** 上运行每次提交的构建，而 **候选发布版** 渠道则让团队在某个版本线变为稳定之前先行试用。

## 各渠道 {#the-channels}

| 渠道 | 版本格式 | 发布频率 | 默认解析？ |
| --- | --- | --- | --- |
| 金丝雀版 | `X.Y.0-canary.N`（例如 `4.201.0-canary.42`） | 每次提交到 `main` | 否——需显式选择 |
| 候选发布版 | `X.Y.0-rc.N`（例如 `4.200.0-rc.1`） | 每周一从 `main` 切出，试用约 1 周 | 否——需显式选择 |
| 稳定版 | `X.Y.Z`（例如 `4.200.0`、`4.200.1`） | 在顺利试用后，每周一晋升为稳定版 | **是** |

金丝雀版和候选发布版的构建会以预发布形式发布。Mise 和 Homebrew 等工具在解析 `latest`、裸安装或固定版本线时会排除预发布版本，因此只有在你显式请求时才会使用它们。

### 金丝雀版 {#canary}

每次提交到 `main` 都会发布一个金丝雀版本。金丝雀版始终代表 **下一个未发布的小版本**：一旦某个版本线被切出用于发布，`main` 就会前进到下一个小版本（例如，从 `4.200.0-canary.42` 到 `4.201.0-canary.1`）。如果你希望尽早获得信号，或者想在修复进入稳定版之前验证你报告或贡献的修复是否按预期工作，金丝雀版是合适的渠道。

### 候选发布版 {#release-candidate}

当一个小版本准备发布时，其版本线会被冻结到一个受保护的 `releases/<major>.<minor>.x` 分支，并以 `X.Y.0-rc.1` 的形式发布。该版本线处于功能冻结状态；只会挑选关键修复和回归修复，并且每接受一个修复就会递增 RC 版本号（`-rc.2`、`-rc.3`、…）。在顺利度过试用期后，该版本线会晋升为稳定版。

### 稳定版 {#stable}

稳定版是推荐的渠道，也是所有文档指向的版本。只有在候选发布版顺利试用后，才会发布稳定版的小版本（`X.Y.0`），并且当新功能合并到 `main` 时，它 **不会** 前进。稳定版本线上的补丁版本（`X.Y.1`、`X.Y.2`、…）仅包含回溯修复，绝不会包含新功能。

## 选择版本 {#choosing-a-version}

使用 [Mise](/en/guides/install-tuist)（推荐）：

```bash
mise use tuist@latest              # Latest stable (recommended)
mise use tuist@4.200               # Pin to a stable line; receives backported fixes only
mise use tuist@4.200.1             # Pin to an exact stable patch
mise use tuist@4.201.0-rc.1        # Opt into a release candidate to soak it
mise use tuist@4.201.0-canary.42   # Opt into a specific canary build
```

使用 Homebrew 时，`brew install --formula tuist` 始终安装最新的稳定版；预发布版本不会通过该公式分发。

## 推荐策略 {#recommended-strategy}

1. **固定到一个稳定版本线**，例如 `tuist@4.200`。该版本线仅接收回溯修复，从不引入新功能，因此日常升级风险较低。
2. **有计划地采用新功能。** 当你准备好使用下一个小版本时，先在候选发布版渠道上试用，然后将你的固定版本切换到新的稳定版本线。
3. 如果你是希望尽早获得信号的早期采用者，可以在非关键环境中 **试用金丝雀版**。

## 支持与回溯修复 {#support-and-backports}

任何时候都有两个稳定版本线处于积极维护状态：

| 版本线 | 接收内容 |
| --- | --- |
| 当前版本线（`X.Y.x`） | 回归修复和安全修复 |
| 上一个版本线（`X.(Y-1).x`） | 仅限关键修复和安全修复 |
| 更早的版本线 | 无 — 请升级到受维护的版本线 |

修复首先合并到 `main`（金丝雀版）。回归修复和安全修复会回溯到当前稳定版本线，而上一个版本线仅接收关键修复和安全修复。其他错误修复不会回溯；它们将随下一个小版本发布。当新版本线晋升为稳定版时，原来的当前版本线变为“上一个”，而原来的“上一个”版本线则停止接收回溯修复。

无论使用哪个渠道，Tuist 服务器都保持与过去 3 个月内发布的任何 CLI [兼容](/en/cli/compatibility)，因此只要你在此期间进行升级，固定到稳定版本线就不会使你超出支持范围。
