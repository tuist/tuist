Quarantining isolates a flaky test so it doesn't block CI while you fix it. By default it's a **manual action**: you quarantine a test, release it, and switch modes from the test case detail page in the dashboard. You can also wire it into an **automation alert** under **Settings → Automations** so a test is automatically muted (or skipped) when it crosses a flakiness threshold, and released when it recovers. Every transition, manual or automated, is recorded on the test case's audit log.

By default, recovery waits until the trigger condition no longer holds, so a test stays quarantined until its old flaky runs leave the trigger window. To recover sooner, set **Recover when** to **No new flaky runs**: the test recovers once the recovery window (days or runs) passes without a new flaky run, every new flaky run restarts that wait, and after recovering only a new flaky run quarantines it again.
