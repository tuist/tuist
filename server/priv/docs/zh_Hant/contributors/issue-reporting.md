# 問題回報 {#issue-reporting}

作為 Tuist 使用者，你可能會遇到錯誤或意外行為。如果發生這種情況，我們鼓勵你回報這些問題，以便我們修復。

## GitHub Issues 是我們的工單平台 {#github-issues-is-our-ticketing-platform}

問題應在 GitHub 上以 [GitHub issues](https://github.com/tuist/tuist/issues) 的形式回報，而不是在 Slack 或其他平台上。GitHub 更適合追蹤和管理問題，更接近程式碼庫，並讓我們能追蹤問題的進展。此外，它鼓勵對問題進行詳細描述，這促使回報者深入思考問題並提供更多背景資訊。

## 背景資訊至關重要 {#context-is-crucial}

缺乏足夠背景資訊的問題將被視為不完整，作者會被要求提供更多背景資訊。如果未提供，該問題將會被關閉。你可以這樣想：你提供的背景資訊越多，我們就越容易理解問題並修復它。因此，如果你希望問題得到修復，請盡可能提供詳細的背景資訊。試著回答以下問題：

- 你當時試圖做什麼？
- 你的專案圖結構看起來如何？
- 你使用的是哪個版本的 Tuist？
- 這是否阻礙了你的工作？

我們也要求你提供一個最小的 **可重現專案**。

## 可重現專案 {#reproducible-project}

### 什麼是可重現專案？ {#what-is-a-reproducible-project}

可重現專案是一個小型的 Tuist 專案，用於示範問題——通常這個問題是由 Tuist 中的錯誤引起的。你的可重現專案應包含清楚示範該錯誤所需的最少功能。

### 為什麼你應該建立可重現的測試案例？ {#why-should-you-create-a-reproducible-test-case}

可重現專案讓我們能夠隔離問題的原因，這是修復問題的第一步！任何錯誤回報中最重要的部分是描述重現該錯誤所需的確切步驟。

可重現專案是分享導致錯誤的特定環境的絕佳方式。你的可重現專案是幫助那些想協助你的人的最佳方法。

### 建立可重現專案的步驟 {#steps-to-create-a-reproducible-project}

- 建立新的 git 儲存庫。
- 在儲存庫目錄中使用 `tuist init` 初始化專案。
- 新增重現你所見錯誤所需的程式碼。
- 發布程式碼（你的 GitHub 帳號是執行此操作的好去處），然後在建立問題時連結到它。

### 可重現專案的好處 {#benefits-of-reproducible-projects}

- **縮小影響範圍：** 透過移除除錯誤以外的所有內容，你無需費力尋找錯誤。
- **無需發布機密程式碼：** 你可能無法發布你的主要專案（出於多種原因）。將其一小部分重新製作成可重現的測試案例，讓你能公開示範問題，而不會洩露任何機密程式碼。
- **證明錯誤存在：** 有時錯誤是由你機器上的某些設定組合引起的。可重現的測試案例讓貢獻者能夠下載你的建置並在他們的機器上進行測試。這有助於驗證並縮小問題的原因範圍。
- **獲得修復錯誤的協助：** 如果其他人能夠重現你的問題，他們通常有很大機會修復該問題。若無法先重現錯誤，幾乎不可能修復它。
