# 데이터 보관 {#data-retention}

Tuist는 업로드된 아티팩트 파일과 대시보드 및 인사이트에 사용되는 기록에 대해 별도의 보관 정책을 적용합니다. 만료된 아티팩트 파일을 삭제해도 해당 인사이트 기록은 삭제되지 않습니다.

아티팩트 파일의 경우, 호스팅된 Tuist 서버는 최대 30일로 제한된 플랜 기반 보관 기간을 사용합니다. 자체 호스팅 인스턴스에서는 아티팩트 정리가 기본적으로 비활성화되어 있으며, 운영자는 각 지원되는 아티팩트 유형에 대해 별도의 보관 기간을 설정하도록 선택할 수 있습니다.

## 아티팩트 파일 {#artifact-files}

### 호스팅된 Tuist 서버 {#hosted-artifact-files}

이러한 보관 기간은 호스팅된 Tuist 서버에서 아티팩트 파일이 얼마나 오랫동안 사용 가능한지를 정의합니다.

| 아티팩트 | Air 및 오픈 소스 | Pro | Enterprise |
| --- | --- | --- | --- |
| 캐시 아티팩트(Xcode 캐시, 모듈 캐시, Gradle 캐시, Bazel 원격 캐시 파일 및 Tuist Runners의 GitLab CI 캐시 아카이브 포함) | 14일 | 30일 | 30일 |
| 앱 미리보기 빌드 및 아이콘 | 30일 | 30일 | 30일 |
| 빌드 아카이브 | 7일 | 30일 | 30일 |
| 실행 아티팩트(결과 번들 및 세션 아카이브 포함) | 7일 | 30일 | 30일 |
| 테스트 실행 첨부 파일 | 30일 | 30일 | 30일 |
| 샤드 번들 | 7일 | 14일 | 30일 |

활성 계정 플랜이 호스팅 보관 기간을 결정합니다. 계정에 활성 구독이 없는 경우 Tuist는 Air 보관 기간을 사용합니다. 일부 아티팩트 유형은 재생성될 것으로 예상되므로 더 짧은 보관 기간을 사용합니다.

Tuist가 테스트 실행 식별자를 기록하기 전에 생성된 테스트 첨부 파일은 자동 삭제에서 제외됩니다. Tuist는 보관 정리 중에 무제한적인 과거 소유권 조회를 피하면서 이러한 파일을 계속 사용할 수 있게 유지합니다.

### 자체 호스팅 인스턴스 {#self-hosted-artifact-files}

자체 호스팅 아티팩트 정리는 선택 사항이며, 각 아티팩트 유형별로 별도로 구성할 수 있고 30일로 제한되지 않습니다. 지원되는 아티팩트 유형 및 배포 옵션은 <.localized_link href="/guides/server/self-host/server#artifact-retention">자체 호스팅 아티팩트 보관 구성</.localized_link>을 참조하세요.

## 대시보드 및 활동 데이터 {#dashboard-and-activity-data}

대시보드 및 활동 기록은 아티팩트 파일 정리와 독립적인 보관 정책을 가집니다. 아래 보관 기간은 Enterprise를 포함한 호스팅 플랜에 따라 달라지지 않습니다.

### Xcode 빌드 및 테스트 인사이트 {#xcode-build-and-test-insights}

핵심 Xcode 빌드 및 테스트 기록은 현재 고정된 시간 기반 삭제 일정이 없습니다. 타임라인 단계 및 머신 메트릭과 같은 기타 보고서 데이터는 별도로 만료됩니다:

| 데이터 | 보관 기간 |
| --- | --- |
| 빌드 요약, 파일별 및 타겟별 빌드 기록, 빌드 이슈 | 고정된 시간 기반 삭제 일정 없음 |
| 테스트 실행, 모듈 및 스위트 결과, 개별 테스트 결과 | 고정된 시간 기반 삭제 일정 없음 |
| 빌드 타임라인 단계와 캡처된 로그 | 90일 |
| 빌드 머신 메트릭 | 90일 |
| Xcode 프로젝트 그래프 기록 | 30일 |

이러한 기록은 [아티팩트 파일 보관 기간](#hosted-artifact-files)에 포함되는 다운로드 가능한 빌드 아카이브, 결과 번들 및 테스트 첨부 파일과 별개입니다. Enterprise에서는 해당 파일이 30일간 보관되며, 관련 빌드 및 테스트 기록은 파일이 만료된 후에도 계속 사용할 수 있습니다. 고정된 시간 기반 삭제 일정이 없는 기록이 영구적으로 사용 가능함을 보장하는 것은 아닙니다.

### 기타 대시보드 및 활동 데이터 {#other-dashboard-and-activity-data}

| 데이터 | 보관 기간 |
| --- | --- |
| Gradle 빌드 기록, 작업 기록, 캐시 이벤트 기록, Mix 빌드 기록, 컴파일된 파일 기록, 빌드 단계 기록 및 진단, Cargo 빌드 기록(집계 컴파일 캐시 측정치 포함) 및 컴파일러 관찰, Bazel 호출, Bazel 트레이스 프로파일, 인덱싱된 프로파일 단계 및 작업 진단, 대기 중인 Bazel 프로파일 및 테스트 수집 기록, Bazel 호출 로그, Bazel 원격 작업 캐시 관찰 | 90일 |
| 지속적 모듈 상세 페이지의 Xcode 모듈 컴파일 및 캐시 기록 | 30일 |
| 지속적 상세 페이지의 작업, 선언된 Once 작업, Bazel BEP 작업, 컴파일된 파일 및 모듈 관찰 | 90일(위의 Xcode 모듈 제외) |
| 지속적 작업/작업/모듈/파일 식별 메타데이터 | 관찰 없이 365일 |
| 러너 작업 로그, 아카이브된 러너 로그, 러너 작업 머신 메트릭 | 90일 |
| 웹훅 전달 이력 | 고정된 삭제 일정 없음 |

지속적 상세 URL은 특정 빌드가 계속 사용 가능한지에 의존하지 않습니다. 식별 메타데이터는 개별 관찰보다 더 오래 유지될 수 있으므로, 선택된 기간 동안 상세 페이지에 이력이 없을 수 있습니다. 새로운 이력은 기능이 배포된 후 수신된 보고서에서 인덱싱되며, 기존 실행 수준 이력은 소급하여 복사되지 않습니다.

ClickHouse의 내부 `system.*` 운영 로그 테이블은 Tuist의 제품 데이터 보관 정책이 아닌 ClickHouse 계층에서 구성됩니다. 기본적으로 제한이 없으며, 번들된 자체 호스팅 Docker Compose 및 내장 Helm ClickHouse 구성으로 이를 제한할 수 있습니다. 자세한 내용은 <.localized_link href="/guides/server/self-host/server#capping-operational-log-retention">운영 로그 보관 제한</.localized_link>을 참조하세요.
