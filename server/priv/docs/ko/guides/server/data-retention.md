# 데이터 보관 {#data-retention}

Tuist는 업로드된 아티팩트 파일과 대시보드 및 인사이트에 사용되는 레코드에 대해 각각 다른 보관 정책을 적용합니다. 만료된 아티팩트 파일을 삭제해도 연결된 인사이트 레코드는 삭제되지 않습니다.

아티팩트 파일의 경우, 호스팅된 Tuist 서버는 최대 30일로 제한된 요금제 기반 기간을 사용합니다. 자체 호스팅 인스턴스에서는 아티팩트 정리가 기본적으로 비활성화되어 있으며, 운영자가 각 지원 아티팩트 유형별로 별도의 기간을 설정하도록 선택할 수 있습니다.

## 아티팩트 파일 {#artifact-files}

### 호스팅된 Tuist 서버 {#hosted-artifact-files}

이러한 기간은 호스팅된 Tuist 서버에서 아티팩트 파일이 얼마나 오랫동안 사용 가능한지를 정의합니다.

| 아티팩트 | Air 및 오픈 소스 | Pro | Enterprise |
| --- | --- | --- | --- |
| 캐시 아티팩트(Xcode 캐시, 모듈 캐시, Gradle 캐시, Bazel 원격 캐시 파일 및 Tuist Runners의 GitLab CI 캐시 아카이브 포함) | 14일 | 30일 | 30일 |
| 앱 미리보기 빌드 및 아이콘 | 30일 | 30일 | 30일 |
| 빌드 아카이브 | 7일 | 30일 | 30일 |
| 실행 아티팩트(결과 번들 및 세션 아카이브 포함) | 7일 | 30일 | 30일 |
| 테스트 실행 첨부 파일 | 30일 | 30일 | 30일 |
| 샤드 번들 | 7일 | 14일 | 30일 |

활성 계정 요금제가 호스팅 보관 기간을 결정합니다. 계정에 활성 구독이 없으면 Tuist는 Air 보관 기간을 사용합니다. 일부 아티팩트 유형은 재생성될 것으로 예상되므로 더 짧은 기간을 사용합니다.

Tuist가 테스트 실행 식별자를 기록하기 전에 생성된 테스트 첨부 파일은 자동 삭제에서 제외됩니다. 이러한 파일은 Tuist가 보관 정리 중에 무제한적인 과거 소유권 조회를 피하는 동안 계속 사용 가능합니다.

### 자체 호스팅 인스턴스 {#self-hosted-artifact-files}

자체 호스팅 아티팩트 정리는 선택 사항이며, 각 아티팩트 유형별로 별도로 구성할 수 있고 30일로 제한되지 않습니다. 지원되는 아티팩트 유형 및 배포 옵션은 <.localized_link href="/guides/server/self-host/server#artifact-retention">자체 호스팅 아티팩트 보관 구성</.localized_link>을 참조하세요.

## 대시보드 및 활동 데이터 {#dashboard-and-activity-data}

대시보드 및 활동 레코드는 아티팩트 파일 정리와 독립적인 보관 정책을 가집니다. 아래 기간은 Enterprise를 포함한 호스팅 요금제에 따라 달라지지 않습니다.

### Xcode 빌드 및 테스트 인사이트 {#xcode-build-and-test-insights}

핵심 Xcode 빌드 및 테스트 레코드는 현재 고정된 시간 기반 삭제 일정이 없습니다. 타임라인 단계 및 머신 메트릭과 같은 기타 보고서 데이터는 별도로 만료됩니다.

| 데이터 | 보관 기간 |
| --- | --- |
| 빌드 요약, 파일별 및 타겟별 빌드 레코드, 빌드 이슈 | 고정된 시간 기반 삭제 일정 없음 |
| 테스트 실행, 모듈 및 스위트 결과, 개별 테스트 결과 | 고정된 시간 기반 삭제 일정 없음 |
| 빌드 타임라인 단계 및 캡처된 로그 | 90일 |
| 빌드 머신 메트릭 | 90일 |
| Xcode 프로젝트 그래프 레코드 | 30일 |

이러한 레코드는 [아티팩트 파일 보관 기간](#hosted-artifact-files)에 해당하는 다운로드 가능한 빌드 아카이브, 결과 번들 및 테스트 첨부 파일과 분리되어 있습니다. Enterprise에서는 해당 파일이 30일간 보관되며, 파일이 만료된 후에도 관련 빌드 및 테스트 레코드는 계속 사용 가능합니다. 고정된 시간 기반 삭제 일정이 없는 레코드가 영구적으로 사용 가능함을 보장하는 것은 아닙니다.

### 기타 대시보드 및 활동 데이터 {#other-dashboard-and-activity-data}

Bazel 인덱싱된 프로파일 단계에는 작업과 안전하게 연결할 수 있는 경우 nullable한 작업별 원격 큐, 입력 가져오기, 실행 및 출력 업로드 타이밍이 포함됩니다. 이러한 데이터는 캐시된 아티팩트 및 청구 레코드와 독립적으로 프로파일의 90일 보관 기간을 공유합니다.

| 데이터 | 보관 기간 |
| --- | --- |
| Gradle 빌드 레코드, 작업 레코드 및 실패한 작업과 구성 단계의 실패 메시지, 캐시 이벤트 레코드, Mix 빌드 레코드, 컴파일된 파일 레코드, 빌드 단계 레코드 및 진단, Cargo 빌드 레코드(집계 컴파일 캐시 측정값 포함) 및 컴파일러 관찰 결과, Bazel 호출, Bazel 트레이스 프로파일, 인덱싱된 프로파일 단계 및 작업 진단, 대기 중인 Bazel 프로파일 및 테스트 수집 레코드, Bazel 호출 로그, Bazel 원격 작업 캐시 관찰 결과 | 90일 |
| 지속적 모듈 상세 페이지의 Xcode 모듈 컴파일 및 캐시 기록 | 30일 |
| 지속적 상세 페이지의 작업, 선언된 Once 작업, Bazel BEP 작업, 컴파일된 파일 및 모듈 관찰 결과 | 위의 Xcode 모듈 제외 90일 |
| 지속적 작업/작업/모듈/파일 식별 메타데이터 | 관찰 결과 없이 365일 |
| 러너 작업 로그, 아카이브된 러너 로그 및 러너 작업 머신 메트릭 | 90일 |
| 코드 커버리지 줄 세부 정보(각 테스트 실행의 줄별 및 함수별 커버리지, 파일의 커버리지 페이지에 표시) | 31일 |
| 각 테스트 실행의 코드 커버리지 합계 | 365일 |
| 커밋의 코드 커버리지(합계, 타겟 및 파일별 수치) | 3년; 풀 리퀘스트에서만 추가된 커밋의 경우 90일 |
| 웹훅 전달 기록 | 고정된 삭제 일정 없음 |

지속적 상세 URL은 특정 빌드가 계속 사용 가능한지에 의존하지 않습니다. 식별 메타데이터는 개별 관찰 결과보다 더 오래 유지될 수 있으므로, 선택한 기간 동안 상세 페이지에 기록이 없을 수 있습니다. 새로운 기록은 기능이 배포된 후 수신된 보고서에서 인덱싱되며, 기존 실행 수준 기록은 소급하여 복사되지 않습니다.

ClickHouse의 내부 `system.*` 운영 로그 테이블은 Tuist의 제품 데이터 보관 정책이 아닌 ClickHouse 계층에서 구성됩니다. 기본적으로 무제한이며, 번들된 자체 호스팅 Docker Compose 및 내장 Helm ClickHouse 구성으로 이를 제한할 수 있습니다. 자세한 내용은 <.localized_link href="/guides/server/self-host/server#capping-operational-log-retention">운영 로그 보관 제한</.localized_link>을 참조하세요.
