## 개인 네트워크에서 자격 증명 없이 리포트 전송하기 {#network-trusted-publishing}

셀프 호스팅 배포는 개발자가 로그인하지 않고도 완료된 리포트를 게시할 수 있도록 허용합니다. 운영자는 인스턴스에 `TUIST_NETWORK_TRUSTED_INSIGHTS_ACCESS=true`를 구성하고 <.localized_link href="/guides/server/self-host/server#network-trusted-access">셀프 호스팅 가이드</.localized_link>에 설명된 대로 인스턴스를 재시작해야 합니다. 이는 지원되는 모든 프로젝트에 적용되며 대시보드 설정은 없습니다. 스키마의 사후 작업이나 터미널에서 사용하는 환경에 셀프 호스팅 URL과 프로젝트를 구성하세요. CLI는 자격 증명이 없을 때 인스턴스 정책을 자동으로 검색합니다.

```sh
export TUIST_URL="https://tuist.internal.example"
tuist inspect build
# To publish local test results:
tuist inspect test
```

자격 증명이 실제로 없는 경우, 활동 로그와 XCResult 번들이 로컬에서 파싱되어 구조화된 리포트로 전송됩니다. 원본 아카이브, 첨부 파일, 커버리지/히스토리 업로드, 원격 프로세서, 샤드 참조 또는 선택적 실행 증거는 제출되지 않습니다. 리포트는 계속 표시되지만 인증된 테스트 케이스 상태를 업데이트하거나 격리/실패 자동화를 트리거할 수는 없습니다. 대시보드 및 기타 권한이 필요한 명령어는 여전히 로그인이 필요합니다. 인스턴스에서 별도로 네트워크 신뢰 캐시 접근을 활성화하거나 자격 증명이 제공되지 않는 한 캐시 통합은 비활성화 상태로 유지하세요.

현재 자격 증명은 인증된 상태로 유지됩니다. 유효하지 않거나 손상되었거나 비어 있거나 갱신이 거부된 자격 증명은 차단되고 디스크에 남아 있으므로 이후 명령어가 자동으로 비인증 상태가 되지 않습니다. 의도적인 복구 조치로 다시 로그인하거나 명시적으로 로그아웃하세요. 자격 증명 없는 클라이언트를 업그레이드하기 전에 모든 서버 복제본을 검색 기능이 있는 버전으로 업그레이드하고 리디렉션 없이 최종 서버 URL을 구성하세요. 검색 기능이 없는 이전 서버, 비활성화된 인스턴스 및 검색 실패 시에는 여전히 인증이 필요합니다. 클라이언트 측 옵트인은 필요하지 않습니다. 구성된 액터 클레임을 생략하려면 `TUIST_ACTOR_ID=""`를 독립적으로 설정하세요. 검증된 자격 증명 신원에는 영향을 주지 않습니다.
