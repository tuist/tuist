## 보고서 작성자 클레임 {#report-actor-claim}

보고서 생성 요청은 `TUIST_ACTOR_ID`를 조직 범위 라벨로 명시적으로 설정한 경우에만 선택적 `x-tuist-actor-id` 헤더를 포함합니다. 예를 들어 `TUIST_ACTOR_ID=employee-123 tuist inspect build`와 같이 설정할 수 있습니다. 기본적으로 라벨은 전송되지 않으며, Tuist는 운영 체제 사용자 이름을 감지하지 않습니다. 빈 `TUIST_ACTOR_ID`는 보고된 식별자를 생략하지만 자격 증명 기반의 검증된 신원을 제거하지는 않습니다. 식별자는 공백이 없는 인쇄 가능한 ASCII 문자 1~128바이트여야 하며, 잘못된 재정의 값은 대체 없이 생략됩니다. 커스텀 프록시가 익숙하지 않은 헤더를 거부하는 경우, 빈 환경 변수 재정의 값을 사용하여 옵트아웃하세요.

검증된 개별 자격 증명이 우선하며, 그렇지 않은 경우 클라이언트가 보고한 식별자는 **검증되지 않음**으로 표시되며 권한을 부여하거나 사용자와 자동으로 연결되지 않습니다. 식별자는 프로젝트 보고서를 볼 수 있는 모든 사람에게 공개되며, 프로젝트가 공개된 경우 공개 뷰어에게도 보이고 데이터 내보내기에 포함되므로 비밀 정보를 포함하지 마세요. 이는 빌드, 테스트 및 명령 이벤트 보고서에 적용됩니다. 이전 서버는 선택적 헤더를 무시하며, 새로운 서버는 해당 헤더가 없는 이전 클라이언트를 허용합니다. 식별자가 없는 새로운 공유 토큰 보고서는 게시 조직 대신 **알 수 없음**으로 표시됩니다. 기존 보고서는 이전 속성 정보를 유지합니다. 빌드 및 테스트 목록에서는 검증된 사용자와 검증되지 않은 보고 식별자를 구분합니다. 자체 호스팅 인스턴스가 자격 증명 없는 보고를 명시적으로 활성화하고 클라이언트가 해당 정책을 발견하지 않는 한 인증은 여전히 필요합니다.

### 스킴 사후 작업 {#actor-claim-post-actions}

작성자 클레임은 기본적으로 비활성화되어 있습니다. 스킴 사후 작업을 구성하려면 셸 내보내기에 의존하지 않고 해당 스크립트에서 `TUIST_ACTOR_ID`를 설정하세요. Dock에서 실행된 Xcode는 `~/.zshrc`의 변수를 상속하지 않습니다. Homebrew를 사용하여 구성된 클레임을 명시적으로 억제하려면 다음을 사용하세요:

```sh
export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"
export TUIST_ACTOR_ID=""
tuist inspect build
```

Mise를 사용하는 경우, Mise가 환경을 로드한 후 값을 재정의하세요:

```sh
$HOME/.local/bin/mise x -C "$SRCROOT" -- env TUIST_ACTOR_ID="" tuist inspect build
```

빈 값 대신 명시적 라벨을 사용하여 옵트인하세요.
