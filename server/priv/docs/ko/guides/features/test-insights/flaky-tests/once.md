# Once 불안정한 테스트 {#once-flaky-tests}

> [!IMPORTANT]
> **요구 사항**
>
> - 구조화된 개별 테스트 결과와 함께 <.localized_link href="/guides/features/test-insights/once">Once 테스트 인사이트</.localized_link>를 구성하세요.

<!-- @snippet: ./_intro -->

## 불안정성 감지 방식 {#how-it-works}

### 테스트 재시도 {#test-retries}

러너가 동일한 테스트에 대한 여러 시도를 보고하면 Tuist는 이를 보존합니다. 실패한 후 통과하는 테스트는 불안정한 것으로 보고되며, 계속 실패하는 테스트는 실패로 남습니다. 지원되는 경우 기본 러너에서 재시도를 활성화하세요. Once를 Tuist에 연결한다고 해서 모든 테스트 타겟에 재시도가 자동으로 추가되지는 않습니다.

### 실행 간 감지 {#cross-run-detection}

공유된 테스트 이력을 통해 Tuist는 CI에서 동일한 테스트와 커밋에 대한 통과 및 실패 결과를 비교할 수 있습니다. 이러한 비교를 위해 Once는 커밋과 CI 컨텍스트를 보고해야 합니다. 로컬 실행은 가시성을 유지하지만 자동 교차 실행 불안정성 증거가 되지는 않습니다.

케이스는 네이티브 타겟, 스위트 및 케이스 이름으로 식별됩니다. 이력을 보존하려면 이러한 식별자를 안정적으로 유지하고, 타겟의 전체 결과로부터 신뢰성을 추론하기보다 완전한 케이스별 보고서를 사용하세요.

## 불안정한 테스트 조사 {#investigate-flaky-tests}

Tuist에서 테스트 케이스의 이력을 열어 시도, 실패 및 영향받은 CI 커밋을 비교하세요. 공유 테스트 쿼리는 <.localized_link href="/guides/features/agentic-coding/mcp">Model Context Protocol 도구</.localized_link>를 통해서도 사용할 수 있으므로 코딩 에이전트가 동일한 보고 결과를 조사할 수 있습니다.

## 불안정한 테스트 관리 {#managing-flaky-tests}

실패를 조사하는 동안 상세 페이지에서 테스트를 불안정한 것으로 표시하거나 표시를 해제할 수 있습니다. 기본 불안정한 테스트 감지 자동화는 또한 복구 기간(일반적으로 다른 트리거 없이 14일) 후에 플래그를 지웁니다.

Once 프로젝트는 현재 **Automations** 설정 탭을 노출하지 않습니다. 감지 및 저장된 테스트 상태는 사용할 수 있지만 격리 강제 기능이 있는 빌드 시스템을 위해 문서화된 설정 워크플로는 아직 Once에서 노출되지 않았습니다.

## 격리 {#quarantining}

Tuist는 보고된 케이스를 저장된 격리 상태에 귀속시킬 수 있지만, 네이티브 Once 클라이언트는 현재 Tuist의 **Muted** 또는 **Skipped** 정책을 가져오고 적용하지 않습니다. Tuist에서 해당 상태를 변경해도 Once가 테스트를 실행하는 것을 막거나 실패로 인해 CI가 차단되는 것을 방지하지는 않습니다.

실행 시간 격리가 필요한 경우 러너 자체의 필터링 또는 실패 정책을 사용하세요. 명령의 종료 코드를 변경하기 위해 대시보드 상태에만 의존하지 마세요.

## Slack 알림 {#slack-notifications}

Once 프로젝트는 현재 불안정한 테스트 Slack 알림을 구성하기 위한 프로젝트 설정 워크플로를 노출하지 않습니다. 아래 공유 테스트 쿼리를 사용하여 보고된 불안정 상태를 자체 알림과 통합하세요.
