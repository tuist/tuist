# 릴리스 채널 {#release-channels}

Tuist CLI는 안정성 보장 수준이 다른 세 가지 채널을 통해 배포됩니다. 권장 설치 방식은 **안정(stable)** 채널로, 변경 속도가 느립니다. 기능이 병합될 때마다 버전이 올라가지 않으므로 업그레이드 시 관련 없는 변경 사항을 일괄 적용할 필요가 없습니다. 얼리 어답터는 **카나리(canary)** 에서 커밋 단위 빌드를 실행할 수 있으며, **릴리스 후보(release candidate)** 채널을 사용하면 팀이 upcoming 라인이 안정화되기 전에 충분히 검증할 수 있습니다.

## 채널 {#the-channels}

| 채널 | 버전 형식 | 배포 주기 | 기본적으로 선택되나요? |
| --- | --- | --- | --- |
| 카나리 | `X.Y.0-canary.N` (예: `4.201.0-canary.42`) | `main`에 대한 모든 커밋 | 아니요 — 명시적 옵트인 필요 |
| 릴리스 후보 | `X.Y.0-rc.N` (예: `4.200.0-rc.1`) | 매주 월요일 `main`에서 분기, 약 1주간 검증 | 아니요 — 명시적 옵트인 필요 |
| 안정 | `X.Y.Z` (예: `4.200.0`, `4.200.1`) | 검증이 완료되면 매주 월요일 승격 | **예** |

카나리와 릴리스 후보 빌드는 프리릴리스로 게시됩니다. Mise와 Homebrew 같은 도구는 `latest`, 기본 설치 또는 라인 고정 시 프리릴리스를 제외하므로, 명시적으로 요청하지 않는 한 이러한 버전에 도달하지 않습니다.

### 카나리 {#canary}

`main`에 대한 모든 커밋은 카나리를 게시합니다. 카나리는 항상 **다음 출시 예정 마이너 버전**을 나타냅니다. 릴리스용 라인이 분기되면 `main`는 다음 마이너 버전으로 이동합니다(예: `4.200.0-canary.42`에서 `4.201.0-canary.1`로). 카나리는 가장 빠른 신호를 원하는 얼리 어답터나, 보고하거나 기여한 수정 사항이 안정 채널에 도달하기 전에 예상대로 동작하는지 검증하려는 경우에 적합한 채널입니다.

### 릴리스 후보 {#release-candidate}

마이너 버전 출시 준비가 되면 해당 라인은 보호된 `releases/<major>.<minor>.x` 브랜치로 고정되고 `X.Y.0-rc.1`로 게시됩니다. 이 라인은 기능 추가가 중단되며, 중요한 수정 사항과 회귀 문제만 체리픽됩니다. 각 수용된 수정 사항은 RC 버전을 증가시킵니다(`-rc.2`, `-rc.3`, …). 검증 기간이 문제 없이 종료되면 해당 라인은 안정 채널로 승격됩니다.

### 안정 {#stable}

안정 채널은 권장 채널이며 모든 문서가 지칭하는 채널입니다. 안정 마이너 버전(`X.Y.0`)은 릴리스 후보가 문제 없이 검증을 마친 경우에만 게시되며, 새로운 기능이 `main`에 병합되더라도 **업데이트되지 않습니다**. 안정 라인의 패치 버전(`X.Y.1`, `X.Y.2`, …)에는 백포트된 수정 사항만 포함되며, 새로운 기능은 절대 포함되지 않습니다.

## 버전 선택 {#choosing-a-version}

[Mise](/en/guides/install-tuist) 사용(권장):

```bash
mise use tuist@latest              # Latest stable (recommended)
mise use tuist@4.200               # Pin to a stable line; receives backported fixes only
mise use tuist@4.200.1             # Pin to an exact stable patch
mise use tuist@4.201.0-rc.1        # Opt into a release candidate to soak it
mise use tuist@4.201.0-canary.42   # Opt into a specific canary build
```

Homebrew의 경우, `brew install --formula tuist`는 항상 최신 안정 버전을 설치하며, 프리릴리스는 포뮬러를 통해 배포되지 않습니다.

## 권장 전략 {#recommended-strategy}

1. **안정 라인에 고정**하세요. 예를 들어 `tuist@4.200`와 같이 지정합니다. 해당 라인은 백포트된 수정 사항만 받고 새로운 기능은 포함되지 않으므로 일상적인 업그레이드의 위험이 낮습니다.
2. **새로운 기능을 의도적으로 도입하세요.** 다음 마이너 버전 준비가 되면 릴리스 후보 채널에서 검증한 후, 고정을 새로운 안정 라인으로 이동하세요.
3. 가장 빠른 신호를 원하는 얼리 어답터라면 중요하지 않은 환경에서 **카나리를 시험**해 보세요.

## 지원 및 백포트 {#support-and-backports}

언제나 두 개의 안정 라인이 적극적으로 유지 관리됩니다:

| 라인 | 받는 수정 사항 |
| --- | --- |
| 현재 (`X.Y.x`) | 회귀 문제 및 보안 수정 사항 |
| 이전 (`X.(Y-1).x`) | 중요 및 보안 수정 사항만 |
| 이전 버전 | 없음 — 유지 관리 중인 라인으로 업그레이드 |

수정 사항은 먼저 `main`(카나리)에 적용됩니다. 회귀 문제와 보안 수정 사항은 현재 안정 라인에 백포트되며, 이전 라인은 중요 및 보안 수정 사항만 받습니다. 다른 버그 수정 사항은 백포트되지 않으며 다음 마이너 버전과 함께 출시됩니다. 새로운 라인이 안정 채널로 승격되면 기존 현재 라인은 "이전" 라인이 되고, 기존 "이전" 라인은 백포트를 받지 않게 됩니다.

채널과 무관하게 Tuist 서버는 지난 3개월 이내에 출시된 모든 CLI와 [호환](/en/cli/compatibility) 상태를 유지하므로, 해당 기간 내에 업그레이드하는 한 안정 라인에 고정해도 지원 범위에서 벗어나지 않습니다.
