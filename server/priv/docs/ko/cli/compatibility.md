# 호환성 {#compatibility}

Tuist CLI는 캐시, 빌드 및 테스트 인사이트, 프리뷰, 레지스트리와 같은 기능을 위해 Tuist 서버와 통신합니다. 서버는 CLI 업그레이드 시기와 무관하게 지속적으로 배포되므로, 서버 변경 사항이 실행 중인 CLI 버전을 중단시켜서는 안 됩니다. 이를 보장하기 위해 서버는 정의된 기간 동안 최근 CLI 릴리스와 호환성을 유지합니다.

## 지원 기간 {#support-window}

Tuist 서버는 **지난 3개월** 동안 출시된 CLI 릴리스를 지원합니다. 이 기간 동안 서버는 하위 호환성을 유지합니다. 지난 3개월 내에 출시된 모든 CLI는 서버를 대상으로 빌드, 캐싱 및 테스트 실행을 계속할 수 있으며, 서버 변경으로 인해 문제가 발생하지 않도록 자신의 일정에 따라 CLI를 업그레이드할 수 있습니다.

CLI는 [시맨틱 버전 관리](https://semver.org)를 따릅니다. 지난 3개월 이내에 게시된 모든 릴리스가 지원됩니다.

## 지원 기간 외 {#outside-the-window}

지원 기간보다 오래된 CLI 릴리스는 사용 중단(deprecated)으로 간주됩니다. 서버는 여전히 응답하지만 다음과 같은 제한이 있을 수 있습니다.

- 최신 서버 측 기능이 해당 버전에서 작동하지 않을 수 있습니다.
- 서버 기반 명령어가 업그레이드를 요청하는 경고를 출력할 수 있습니다.

사용 중단된 버전에서의 동작은 보장되지 않습니다. 해당 버전을 사용 중이라면 지원 기간 내의 릴리스로 업그레이드하세요.

## 약속을 지키는 방법 {#how-we-keep-the-promise}

하위 호환성은 가정하는 것이 아니라 검증합니다. 모든 서버 배포는 **지원 기간 내에 있는 가장 오래된 CLI 릴리스**(현재 `{{minimum_supported_cli_version}}`)를 대상으로 자동화된 인수 테스트를 실행하여 캐시 풀 경로를 종단 간(end-to-end)으로 검사합니다. 변경 사항이 해당 버전을 중단시킬 경우, 배포는 프로덕션에 도달하기 전에 차단됩니다. 이는 최신 CLI를 대상으로 한 테스트와 함께 실행되므로, 구형 클라이언트의 회귀 문제는 최신 클라이언트의 회귀 문제와 동일한 방식으로 발견됩니다.

## 권장 사항 {#recommendation}

지원되는 기간 내에 머물기 위해 최소 3개월마다 CLI를 업그레이드하세요. CI에서 CLI 버전을 고정하고 정기적으로 업데이트하면 팀이 일관되고 지원되는 릴리스를 사용할 수 있습니다.
