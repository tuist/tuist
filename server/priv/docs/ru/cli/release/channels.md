# Каналы релизов {#release-channels}

CLI Tuist поставляется через три канала с разными гарантиями стабильности. Рекомендуемая установка — **стабильная**, и обновления выходят нечасто: версия не меняется при каждом слиянии новой возможности, поэтому обновление больше не означает поглощение пакета несвязанных изменений. Ранние пользователи по-прежнему могут запускать сборки для каждого коммита на канале **canary**, а канал **release candidate** позволяет командам предварительно тестировать будущую ветку до её перехода в стабильную.

## Текущие релизы {#live-release-status}

Перевод в стабильный канал запланирован на понедельники в 06:00 UTC. После успешного планового перевода следующий кандидат в релизы создаётся из `main`, а последующие canary-сборки переходят к следующей минорной версии. См. <.localized_link href="/cli/release/calendar">календарь релизов</.localized_link> для информации о предстоящих окнах и недавних выпусках, включая патчи и бэкпорты.

## Каналы {#the-channels}

| Канал | Формат версии | Частота | Разрешается по умолчанию? |
| --- | --- | --- | --- |
| Canary | `X.Y.0-canary.N` (например, `4.201.0-canary.42`) | Каждый коммит в `main` | Нет — требуется явное подключение |
| Release candidate | `X.Y.0-rc.N` (например, `4.200.0-rc.1`) | Создаётся из `main` каждый понедельник, тестируется ~1 неделю | Нет — требуется явное подключение |
| Stable | `X.Y.Z` (например, `4.200.0`, `4.200.1`) | Переводится в стабильный канал каждый понедельник после успешного тестирования | **Да** |

Сборки Canary и Release Candidate публикуются как предварительные релизы. Такие инструменты, как Mise и Homebrew, исключают предварительные релизы при разрешении `latest`, чистой установке или привязке к ветке, поэтому вы попадёте на одну из них только при явном запросе.

### Canary {#canary}

Каждый коммит в `main` публикует canary-сборку. Canary всегда представляет **следующую невыпущенную минорную версию**: как только ветка выделяется для релиза, `main` переходит к следующей минорной версии (например, с `4.200.0-canary.42` на `4.201.0-canary.1`). Canary — правильный канал для ранних пользователей, которые хотят получить сигнал как можно раньше или проверить, что исправление, которое вы сообщили или внесли, работает так, как ожидается, до попадания в стабильную версию.

### Release candidate {#release-candidate}

Когда минорная версия готова к выпуску, её ветка замораживается на защищённой ветке `releases/<major>.<minor>.x` и публикуется как `X.Y.0-rc.1`. Ветка заморожена по возможностям; принимаются только критические исправления и исправления регрессий, и каждое принятое исправление увеличивает номер RC (`-rc.2`, `-rc.3`, …). После успешного завершения периода тестирования ветка переводится в стабильный канал.

### Stable {#stable}

Stable — рекомендуемый канал, на который ссылается вся документация. Стабильная минорная версия (`X.Y.0`) публикуется только после успешного тестирования кандидата в релизы и **не** обновляется при слиянии новых возможностей в `main`. Патчи (`X.Y.1`, `X.Y.2`, …) в стабильной ветке содержат только бэкпортированные исправления, никогда — новые возможности.

## Выбор версии {#choosing-a-version}

С помощью <.localized_link href="/guides/install-tuist">Mise</.localized_link> (рекомендуется):

```bash
mise use tuist@latest              # Latest stable (recommended)
mise use tuist@4.200               # Pin to a stable line; receives backported fixes only
mise use tuist@4.200.1             # Pin to an exact stable patch
mise use tuist@4.201.0-rc.1        # Opt into a release candidate to soak it
mise use tuist@4.201.0-canary.42   # Opt into a specific canary build
```

С Homebrew команда `brew install --formula tuist` всегда устанавливает последнюю стабильную версию; предварительные релизы не распространяются через формулу.

## Рекомендуемая стратегия {#recommended-strategy}

1. **Зафиксируйте стабильную ветку**, например `tuist@4.200`. Эта ветка получает только бэкпортированные исправления, никогда — новые возможности, поэтому повседневные обновления остаются низко рискованными.
2. **Осознанно внедряйте новые возможности.** Когда вы будете готовы к следующей минорной версии, протестируйте её на канале release candidate, затем перенесите фиксацию на новую стабильную ветку.
3. **Попробуйте canary** в некритичной среде, если вы ранний пользователь и хотите получить сигнал как можно раньше.

## Поддержка и бэкпорты {#support-and-backports}

В любой момент активно поддерживаются две стабильные ветки:

| Ветка | Получает |
| --- | --- |
| Текущая (`X.Y.x`) | Регрессии и исправления безопасности |
| Предыдущая (`X.(Y-1).x`) | Только критические исправления и исправления безопасности |
| Более старые | Нет — обновитесь до поддерживаемой ветки |

Исправления сначала попадают в `main` (canary). Регрессии и исправления безопасности бэкпортируются в текущую стабильную ветку, а предыдущая ветка получает только критические исправления и исправления безопасности. Другие исправления ошибок не бэкпортируются; они выходят со следующей минорной версией. Когда новая ветка переводится в статус stable, бывшая текущая становится «previous», а бывшая «previous» перестаёт получать бэкпорты.

Независимо от канала, сервер Tuist остаётся <.localized_link href="/cli/compatibility">совместимым</.localized_link> с любым CLI, выпущенным за последние 3 месяца, поэтому фиксация на стабильной ветке никогда не выведет вас за пределы поддерживаемого окна, если вы обновляетесь в течение этого периода.
