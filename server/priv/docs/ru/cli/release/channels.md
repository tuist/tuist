# Каналы релизов {#release-channels}

CLI Tuist распространяется через три канала с разными гарантиями стабильности. Рекомендуемый вариант установки — **stable**; он обновляется медленно: версия не меняется при каждом слиянии новой возможности, поэтому обновление больше не означает получение пакета несвязанных изменений. Ранние пользователи могут запускать сборки по каждому коммиту на канале **canary**, а канал **release candidate** позволяет командам предварительно тестировать будущую ветку до её перевода в статус stable.

## Текущие релизы {#live-release-status}

Перевод в stable запланирован на понедельники в 06:00 UTC. После успешного планового перевода следующий релиз-кандидат создаётся из `main`, а последующие canary-сборки переходят к следующей минорной версии. См. <.localized_link href="/cli/release/calendar">календарь релизов</.localized_link> для просмотра предстоящих окон и недавних выпусков, включая патчи и бэкпорты.

## Каналы {#the-channels}

| Канал | Формат версии | Частота | Разрешается по умолчанию? |
| --- | --- | --- | --- |
| Canary | `X.Y.0-canary.N` (например, `4.201.0-canary.42`) | Каждый коммит в `main` | Нет — требуется явное подключение |
| Release candidate | `X.Y.0-rc.N` (например, `4.200.0-rc.1`) | Создаётся из `main` каждый понедельник, тестируется ~1 неделю | Нет — требуется явное подключение |
| Stable | `X.Y.Z` (например, `4.200.0`, `4.200.1`) | Переводится в stable каждый понедельник после чистого тестирования | **Да** |

Сборки Canary и Release Candidate публикуются как предварительные релизы. Инструменты вроде Mise и Homebrew исключают предварительные релизы при разрешении `latest`, установке без указания версии или фиксации ветки, поэтому вы попадёте на один из них только при явном запросе.

### Canary {#canary}

Каждый коммит в `main` публикует canary-сборку. Canary всегда соответствует **следующей невыпущенной минорной версии**: когда ветка выделяется для релиза, `main` переходит к следующей минорной версии (например, с `4.200.0-canary.42` на `4.201.0-canary.1`). Canary — правильный канал для ранних пользователей, которым нужен самый ранний сигнал, или чтобы убедиться, что исправление, которое вы сообщили или внесли, работает ожидаемым образом до попадания в stable.

### Release candidate {#release-candidate}

Когда минорная версия готова к выпуску, её ветка замораживается на защищённой ветке `releases/<major>.<minor>.x` и публикуется как `X.Y.0-rc.1`. Ветка заморожена по функциональности; в неё попадают только критические исправления и исправления регрессий, и каждое принятое исправление увеличивает номер RC (`-rc.2`, `-rc.3`, …). После чистого завершения периода тестирования ветка переводится в stable.

### Stable {#stable}

Stable — рекомендуемый канал, на который ссылается вся документация. Стабильная минорная версия (`X.Y.0`) публикуется только после чистого тестирования релиз-кандидата и **не** обновляется при слиянии новых возможностей в `main`. Патчи (`X.Y.1`, `X.Y.2`, …) в стабильной ветке содержат только бэкпортированные исправления, никогда — новые возможности.

## Выбор версии {#choosing-a-version}

С помощью <.localized_link href="/guides/install-tuist">Mise</.localized_link> (рекомендуется):

```bash
mise use tuist@latest              # Latest stable (recommended)
mise use tuist@4.200               # Pin to a stable line; receives backported fixes only
mise use tuist@4.200.1             # Pin to an exact stable patch
mise use tuist@4.201.0-rc.1        # Opt into a release candidate to soak it
mise use tuist@4.201.0-canary.42   # Opt into a specific canary build
```

В Homebrew `brew install --formula tuist` всегда устанавливает последнюю стабильную версию; предварительные релизы не распространяются через формулу.

## Рекомендуемая стратегия {#recommended-strategy}

1. **Зафиксируйте стабильную ветку**, например `tuist@4.200`. Эта ветка получает только бэкпортированные исправления, без новых возможностей, поэтому ежедневные обновления остаются низко рискованными.
2. **Осознанно внедряйте новые возможности.** Когда вы готовы к следующей минорной версии, протестируйте её на канале release candidate, затем перенесите фиксацию на новую стабильную ветку.
3. **Попробуйте canary** в некритичной среде, если вы ранний пользователь и хотите получать самый ранний сигнал.

## Поддержка и бэкпорты {#support-and-backports}

В любой момент активно поддерживаются две стабильные ветки:

| Ветка | Получает |
| --- | --- |
| Текущая (`X.Y.x`) | Регрессии и исправления безопасности |
| Предыдущая (`X.(Y-1).x`) | Только критические исправления и исправления безопасности |
| Более старые | Нет — обновитесь до поддерживаемой ветки |

Исправления сначала попадают в `main` (canary). Регрессии и исправления безопасности бэкпортируются в текущую стабильную ветку, а предыдущая ветка получает только критические исправления и исправления безопасности. Другие исправления ошибок не бэкпортируются; они выходят со следующей минорной версией. Когда новая ветка переводится в статус stable, ветка, которая была текущей, становится «предыдущей», а ветка, которая была «предыдущей», перестаёт получать бэкпорты.

Независимо от канала, сервер Tuist остаётся <.localized_link href="/cli/compatibility">совместимым</.localized_link> с любым CLI, выпущенным за последние 3 месяца, поэтому фиксация на стабильной ветке никогда не выведет вас за пределы окна поддержки, если вы обновляетесь в течение этого периода.
