# Каналы релизов {#release-channels}

CLI Tuist распространяется через три канала с разными гарантиями стабильности. Рекомендуемый вариант установки — **stable**, который обновляется медленно: он не продвигается при каждом слиянии новой возможности, поэтому обновление больше не означает получение пакета несвязанных изменений. Ранние пользователи по-прежнему могут запускать сборки для каждого коммита в канале **canary**, а канал **release candidate** позволяет командам предварительно тестировать будущую ветку перед её переходом в стабильную.

## Текущие релизы {#live-release-status}

Перевод в статус stable запланирован на понедельники в 06:00 UTC. После успешного планового перевода следующий кандидат в релизы создаётся из `main`, а последующие canary-сборки переходят к следующей минорной версии. Смотрите <.localized_link href="/cli/release/calendar">календарь релизов</.localized_link>, чтобы узнать о предстоящих окнах и недавних выпусках, включая патчи и бэкпорты.

## Каналы {#the-channels}

| Канал | Формат версии | Частота обновлений | Выбирается по умолчанию? |
| --- | --- | --- | --- |
| Canary | `X.Y.0-canary.N` (например, `4.201.0-canary.42`) | Каждый коммит в `main` | Нет — требуется явное подключение |
| Release candidate | `X.Y.0-rc.N` (например, `4.200.0-rc.1`) | Создаётся из `main` каждый понедельник, тестируется ~1 неделю | Нет — требуется явное подключение |
| Stable | `X.Y.Z` (например, `4.200.0`, `4.200.1`) | Переводится в статус stable каждый понедельник после успешного тестирования | **Да** |

Сборки Canary и Release Candidate публикуются как предварительные релизы. Такие инструменты, как Mise и Homebrew, исключают предварительные релизы при разрешении `latest`, установке без указания версии или привязке к ветке, поэтому вы попадёте на них только при явном запросе.

### Canary {#canary}

Каждый коммит в `main` публикует canary-сборку. Canary всегда представляет **следующую невыпущенную минорную версию**: как только ветка создаётся для релиза, `main` переходит к следующей минорной версии (например, с `4.200.0-canary.42` на `4.201.0-canary.1`). Canary — правильный канал для ранних пользователей, которые хотят получить сигнал как можно раньше или проверить, что исправление, которое вы сообщили или внесли, работает должным образом до попадания в stable.

### Release candidate {#release-candidate}

Когда минорная версия готова к выпуску, её ветка замораживается на защищённой ветке `releases/<major>.<minor>.x` и публикуется как `X.Y.0-rc.1`. Ветка заморожена по функциональности; в неё попадают только критические исправления и исправления регрессий, а каждое принятое исправление увеличивает номер RC (`-rc.2`, `-rc.3`, …). После успешного завершения периода тестирования ветка переводится в статус stable.

### Stable {#stable}

Stable — рекомендуемый канал, на который ссылается вся документация. Стабильная минорная версия (`X.Y.0`) публикуется только после успешного тестирования кандидата в релизы и **не** продвигается при слиянии новых возможностей в `main`. Патчи (`X.Y.1`, `X.Y.2`, …) в стабильной ветке содержат только бэкпортированные исправления, никогда — новые возможности.

## Выбор версии {#choosing-a-version}

С помощью <.localized_link href="/guides/install-tuist">Mise</.localized_link> (рекомендуется):

```bash
mise use tuist@latest              # Latest stable (recommended)
mise use tuist@4.200               # Pin to a stable line; receives backported fixes only
mise use tuist@4.200.1             # Pin to an exact stable patch
mise use tuist@4.201.0-rc.1        # Opt into a release candidate to soak it
mise use tuist@4.201.0-canary.42   # Opt into a specific canary build
```

При использовании Homebrew команда `brew install --formula tuist` всегда устанавливает последнюю стабильную версию; предварительные релизы не распространяются через формулу.

## Рекомендуемая стратегия {#recommended-strategy}

1. **Зафиксируйте стабильную ветку**, например `tuist@4.200`. Эта ветка получает только бэкпортированные исправления, но не новые возможности, поэтому ежедневные обновления остаются безопасными.
2. **Внедряйте новые возможности осознанно.** Когда вы будете готовы к следующей минорной версии, протестируйте её в канале release candidate, а затем перенесите фиксацию на новую стабильную ветку.
3. **Попробуйте canary** в некритичной среде, если вы ранний пользователь и хотите получать сигналы как можно раньше.

## Поддержка и бэкпорты {#support-and-backports}

В любой момент активно поддерживаются две стабильные ветки:

| Ветка | Получает |
| --- | --- |
| Текущая (`X.Y.x`) | Регрессии и исправления безопасности |
| Предыдущая (`X.(Y-1).x`) | Только критические исправления и исправления безопасности |
| Более старые | Нет — обновитесь до поддерживаемой ветки |

Исправления сначала попадают в `main` (canary). Регрессии и исправления безопасности бэкпортируются в текущую стабильную ветку, а предыдущая ветка получает только критические исправления и исправления безопасности. Другие исправления ошибок не бэкпортируются; они выпускаются со следующей минорной версией. Когда новая ветка переводится в статус stable, текущая ветка становится «previous», а ветка, которая была «previous», перестаёт получать бэкпорты.

Независимо от канала, сервер Tuist остаётся <.localized_link href="/cli/compatibility">совместимым</.localized_link> с любым CLI, выпущенным за последние 3 месяца, поэтому фиксация на стабильной ветке не выведет вас за пределы поддерживаемого периода, если вы будете обновляться в течение этого срока.
