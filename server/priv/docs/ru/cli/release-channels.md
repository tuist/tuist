# Каналы релизов {#release-channels}

CLI Tuist распространяется через три канала с разными гарантиями стабильности. Рекомендуемая установка — **stable**, которая обновляется медленно: она не продвигается при каждом слиянии новой возможности, поэтому обновление больше не означает поглощение пакета несвязанных изменений. Ранние пользователи по-прежнему могут запускать сборки для каждого коммита в канале **canary**, а канал **release candidate** позволяет командам тщательно тестировать предстоящую ветку до её перевода в статус стабильной.

## Каналы {#the-channels}

| Канал | Формат версии | Частота обновлений | Выбирается по умолчанию? |
| --- | --- | --- | --- |
| Canary | `X.Y.0-canary.N` (например, `4.201.0-canary.42`) | Каждый коммит в `main` | Нет — требуется явное согласие |
| Release candidate | `X.Y.0-rc.N` (например, `4.200.0-rc.1`) | Отделяется от `main` каждый понедельник, тестируется ~1 неделю | Нет — требуется явное согласие |
| Stable | `X.Y.Z` (например, `4.200.0`, `4.200.1`) | Повышается до стабильного каждый понедельник после успешного тестирования | **Да** |

Сборки Canary и Release Candidate публикуются как предварительные релизы. Такие инструменты, как Mise и Homebrew, исключают предварительные релизы при разрешении `latest`, установке без указания версии или привязке к ветке, поэтому вы попадёте на них только при явном запросе.

### Canary {#canary}

Каждый коммит в `main` публикует версию canary. Canary всегда представляет собой **следующую невыпущенную минорную версию**: как только ветка отделяется для релиза, `main` переходит к следующей минорной версии (например, с `4.200.0-canary.42` на `4.201.0-canary.1`). Canary — правильный выбор для ранних пользователей, которые хотят получить сигнал как можно раньше или проверить, что исправление, которое вы сообщили или внесли, работает должным образом до попадания в стабильный канал.

### Release candidate {#release-candidate}

Когда минорная версия готова к выпуску, её ветка замораживается на защищённой ветке `releases/<major>.<minor>.x` и публикуется как `X.Y.0-rc.1`. Ветка заморожена по функциональности; в неё включаются только критические исправления и исправления регрессий, и каждое принятое исправление увеличивает номер RC (`-rc.2`, `-rc.3`, …). После успешного завершения периода тестирования ветка повышается до стабильной.

### Stable {#stable}

Stable — рекомендуемый канал, на который ссылается вся документация. Стабильная минорная версия (`X.Y.0`) публикуется только после успешного тестирования кандидата в релизы и **не** продвигается при слиянии новых возможностей в `main`. Патчи (`X.Y.1`, `X.Y.2`, …) в стабильной ветке содержат только обратно портированные исправления, никогда — новые возможности.

## Выбор версии {#choosing-a-version}

С помощью <.localized_link href="/guides/install-tuist">Mise</.localized_link> (рекомендуется):

```bash
mise use tuist@latest              # Latest stable (recommended)
mise use tuist@4.200               # Pin to a stable line; receives backported fixes only
mise use tuist@4.200.1             # Pin to an exact stable patch
mise use tuist@4.201.0-rc.1        # Opt into a release candidate to soak it
mise use tuist@4.201.0-canary.42   # Opt into a specific canary build
```

С Homebrew команда `brew install --formula tuist` всегда устанавливает последнюю стабильную версию; предварительные релизы не распространяются через формулу.

## Рекомендуемая стратегия {#recommended-strategy}

1. **Зафиксируйте стабильную ветку**, например `tuist@4.200`. Эта ветка получает только обратно портированные исправления, никогда — новые возможности, поэтому ежедневные обновления остаются низко рискованными.
2. **Осознанно внедряйте новые возможности.** Когда вы будете готовы к следующей минорной версии, протестируйте её в канале release candidate, затем перенесите фиксацию на новую стабильную ветку.
3. **Попробуйте canary** в некритичной среде, если вы ранний пользователь и хотите получать сигналы как можно раньше.

## Поддержка и обратное портирование {#support-and-backports}

В любой момент активно поддерживаются две стабильные ветки:

| Ветка | Получает |
| --- | --- |
| Текущая (`X.Y.x`) | Исправления регрессий и уязвимостей безопасности |
| Предыдущая (`X.(Y-1).x`) | Только критические исправления и исправления уязвимостей безопасности |
| Более старые | Нет — обновитесь до поддерживаемой ветки |

Исправления сначала попадают в `main` (canary). Исправления регрессий и уязвимостей безопасности обратно портируются в текущую стабильную ветку, а предыдущая ветка получает только критические исправления и исправления уязвимостей безопасности. Другие исправления ошибок не обратно портируются; они выпускаются со следующей минорной версией. Когда новая ветка переводится в статус stable, текущая ветка становится «previous», а ветка, которая была «previous», перестаёт получать обратное портирование.

Независимо от канала, сервер Tuist остаётся <.localized_link href="/cli/compatibility">совместимым</.localized_link> с любым CLI, выпущенным за последние 3 месяца, поэтому фиксация на стабильной ветке никогда не выведет вас за пределы окна поддержки, если вы обновляетесь в течение этого периода.
