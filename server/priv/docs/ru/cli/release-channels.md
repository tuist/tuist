# Каналы релизов {#release-channels}

CLI Tuist распространяется через три канала с разными гарантиями стабильности. Рекомендуемый вариант установки — **stable**, обновления в котором выходят нечасто: версия не меняется при каждом слиянии новой возможности, поэтому обновление больше не означает получение пакета несвязанных изменений. Ранние пользователи по-прежнему могут запускать сборки для каждого коммита в канале **canary**, а канал **release candidate** позволяет командам предварительно тестировать будущую ветку до её перевода в статус stable.

## Каналы {#the-channels}

| Канал | Формат версии | Частота обновлений | Выбирается по умолчанию? |
| --- | --- | --- | --- |
| Canary | `X.Y.0-canary.N` (например, `4.201.0-canary.42`) | Каждый коммит в `main` | Нет — требуется явное подключение |
| Release candidate | `X.Y.0-rc.N` (например, `4.200.0-rc.1`) | Создаётся из `main` каждый понедельник, тестируется ~1 неделю | Нет — требуется явное подключение |
| Stable | `X.Y.Z` (например, `4.200.0`, `4.200.1`) | Переводится в stable каждый понедельник после успешного тестирования | **Да** |

Сборки Canary и Release Candidate публикуются как предварительные релизы. Инструменты вроде Mise и Homebrew исключают предварительные релизы при разрешении `latest`, установке без указания версии или привязке к ветке, поэтому вы попадёте на них только при явном запросе.

### Canary {#canary}

Каждый коммит в `main` публикует версию canary. Canary всегда соответствует **следующей невыпущенной минорной версии**: после создания ветки для релиза `main` переходит к следующей минорной версии (например, с `4.200.0-canary.42` на `4.201.0-canary.1`). Canary — подходящий канал для ранних пользователей, которым нужна самая ранняя обратная связь, или для проверки того, что исправление, которое вы сообщили или внесли, работает ожидаемым образом до попадания в stable.

### Release candidate {#release-candidate}

Когда минорная версия готова к выпуску, её ветка замораживается в защищённой ветке `releases/<major>.<minor>.x` и публикуется как `X.Y.0-rc.1`. Ветка заморожена по функциональности; в неё включаются только критические исправления и исправления регрессий, и каждое принятое исправление увеличивает номер RC (`-rc.2`, `-rc.3`, …). После успешного завершения периода тестирования ветка переводится в stable.

### Stable {#stable}

Stable — рекомендуемый канал, на который ссылается вся документация. Стабильная минорная версия (`X.Y.0`) публикуется только после успешного тестирования release candidate и **не** обновляется при слиянии новых возможностей в `main`. Патчи (`X.Y.1`, `X.Y.2`, …) в стабильной ветке содержат только обратно портированные исправления, но никогда — новые возможности.

## Выбор версии {#choosing-a-version}

С помощью [Mise](/en/guides/install-tuist) (рекомендуется):

```bash
mise use tuist@latest              # Latest stable (recommended)
mise use tuist@4.200               # Pin to a stable line; receives backported fixes only
mise use tuist@4.200.1             # Pin to an exact stable patch
mise use tuist@4.201.0-rc.1        # Opt into a release candidate to soak it
mise use tuist@4.201.0-canary.42   # Opt into a specific canary build
```

В Homebrew `brew install --formula tuist` всегда устанавливает последнюю стабильную версию; предварительные релизы не распространяются через формулу.

## Рекомендуемая стратегия {#recommended-strategy}

1. **Зафиксируйте стабильную ветку**, например `tuist@4.200`. Эта ветка получает только обратно портированные исправления, но не новые возможности, поэтому ежедневные обновления остаются безопасными.
2. **Осознанно внедряйте новые возможности.** Когда будете готовы к следующей минорной версии, протестируйте её в канале release candidate, затем перенесите фиксацию на новую стабильную ветку.
3. **Попробуйте canary** в некритичной среде, если вы ранний пользователь и хотите получать самую раннюю обратную связь.

## Поддержка и обратное портирование {#support-and-backports}

В любой момент активно поддерживаются две стабильные ветки:

| Ветка | Получает |
| --- | --- |
| Текущая (`X.Y.x`) | Исправления регрессий и уязвимостей безопасности |
| Предыдущая (`X.(Y-1).x`) | Только критические исправления и исправления уязвимостей безопасности |
| Более старые | Нет — обновитесь до поддерживаемой ветки |

Исправления сначала попадают в `main` (canary). Исправления регрессий и уязвимостей безопасности обратно портируются в текущую стабильную ветку, а предыдущая ветка получает только критические исправления и исправления уязвимостей безопасности. Другие исправления ошибок не обратно портируются; они выпускаются со следующей минорной версией. Когда новая ветка переводится в статус стабильной, та, что была текущей, становится «предыдущей», а та, что была «предыдущей», перестает получать обратно портированные исправления.

Независимо от канала, сервер Tuist остается [совместимым](/en/cli/compatibility) с любым CLI, выпущенным за последние 3 месяца, поэтому фиксация на стабильной ветке никогда не выведет вас за рамки поддерживаемого периода, если вы будете обновляться в течение этого срока.
