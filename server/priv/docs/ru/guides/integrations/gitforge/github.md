# Интеграция с GitHub {#github}

Git-репозитории — основа подавляющего большинства программных проектов. Мы интегрируемся с GitHub, чтобы предоставлять аналитику Tuist прямо в ваших пул-реквестах и избавить вас от части настройки, например синхронизации ветки по умолчанию.

## Настройка {#setup}

Вам нужно установить приложение Tuist для GitHub во вкладке `Integrations` вашей организации: ![Изображение, показывающее вкладку интеграций](/images/guides/integrations/gitforge/github/integrations.png)

Вы также можете установить приложение напрямую из GitHub. При необходимости войдите в Tuist, авторизуйте приложение GitHub, чтобы Tuist мог подтвердить ваш доступ к установке, и выберите организацию Tuist для подключения. Вы должны владеть организацией GitHub (или личным аккаунтом GitHub), куда устанавливается приложение. Доступны только организации Tuist, которыми вы управляете, и ваш личный аккаунт Tuist. Tuist пропускает выбор только тогда, когда приложение установлено в вашем личном аккаунте GitHub и ваш личный аккаунт Tuist — единственный вариант. Для организаций GitHub Tuist всегда запрашивает выбор, даже если ваш личный аккаунт — единственный вариант. Если организация Tuist вашей команды не отображается в списке, выберите **Создать организацию** или попросите одного из её администраторов назначить вас администратором. Список обновляется, пока страница открыта, поэтому организация появится без необходимости начинать заново, если вы выберете её в течение десяти минут после возвращения в Tuist. Если вы начинаете процесс из Tuist, организация уже выбрана, и этот шаг пропускается.

После этого вы можете добавить подключение проекта между вашим репозиторием GitHub и проектом Tuist:

![Изображение, показывающее добавление подключения проекта](/images/guides/integrations/gitforge/github/add-project-connection.png)

После установки приложения вы также можете связать проект без использования панели управления:

- **CLI:** `tuist project repository connect owner/name`, и `tuist project repository disconnect` для удаления связи.
- **REST API:** `PUT` и `DELETE` на `/api/projects/{account_handle}/{project_handle}/vcs-connection`.
- **Model Context Protocol:** инструменты `connect_project_repository` и `disconnect_project_repository`.

Репозиторий должен быть доступен установке приложения GitHub, а проект использует ветку по умолчанию этого репозитория. Токенам аккаунта требуется область видимости `project:admin:write`.

> [!TIP]
> **Разрешение IP-адресов**
>
> Если ваша организация GitHub использует [списки разрешённых IP-адресов](https://docs.github.com/en/organizations/keeping-your-organization-secure/managing-security-settings-for-your-organization/managing-allowed-ip-addresses-for-your-organization) или ваш экземпляр GitHub находится за межсетевым экраном, обязательно добавьте исходящие IP-адреса Tuist <.localized_link href="/guides/server/network#outbound-ip-addresses">в список разрешённых</.localized_link>, чтобы интеграция могла взаимодействовать с вашим репозиторием.

### GitHub Enterprise Server {#github-enterprise-server}

Tuist также интегрируется с самостоятельно размещаемыми экземплярами GitHub Enterprise Server (GHES). На карточке интеграции с GitHub переключитесь на вкладку **Enterprise server**, введите базовый URL вашего GHES (например, `https://github.example.com`) и нажмите «Установить».

Поскольку приложения GitHub привязаны к одному экземпляру GitHub, Tuist не может повторно использовать своё приложение с github.com на вашем GHES — вместо этого кнопка установки направляет вас через [поток манифеста приложения](https://docs.github.com/en/apps/sharing-github-apps/registering-a-github-app-from-a-manifest) GitHub: GHES помогает вашему администратору зарегистрировать новое приложение Tuist на экземпляре, а затем передаёт учётные данные нового приложения обратно в Tuist. Tuist хранит эти учётные данные в зашифрованном виде для каждой установки и использует их для каждого вызова API, подписи вебхука и ссылки на ваши репозитории в дальнейшем.

Дополнительная настройка сервера Tuist не требуется; поток манифеста автоматически генерирует и настраивает всё необходимое.

#### Разрешения приложения и события вебхуков {#github-app-permissions}

Для комментариев к пул-реквестам и проверок размера бандла Tuist требуются следующие **разрешения репозитория**:

| Разрешение | Доступ | Используется для |
|---|---|---|
| Метаданные (`metadata`) | Только чтение | Базовые метаданные репозитория; требуются GitHub для каждого приложения |
| Пул-реквесты (`pull_requests`) | Чтение и запись | Чтение пул-реквестов, включая SHA коммита head, а также перечисление, публикация и обновление комментариев к пул-реквестам |
| Проверки (`checks`) | Чтение и запись | Создание и обновление запусков проверок, включая проверки прохождения/неудачи размера бандла |

Tuist использует событие вебхука `check_run` для обработки действий проверки размера бандла. Поток манифеста настраивает эту подписку автоматически.

Для ручной настройки приложения на github.com с самостоятельно размещаемым сервером Tuist см. <.localized_link href="/guides/server/self-host/server#platform-github-registering-the-app">руководство по самостоятельному размещению</.localized_link>.

#### Отдельные URL браузера и API {#separate-browser-and-api-urls}

Если инженеры получают доступ к GitHub Enterprise через внутренний хостнейм, а сторонние сервисы используют внешний прокси, настройте оба адреса перед нажатием кнопки установки:

| Поле | Пример | Используется |
|---|---|---|
| **Server URL** | `https://github.internal.company.com` | Ваш браузер, для регистрации и установки приложения, а также ссылки на GitHub из Tuist |
| **API URL** | `https://github-proxy.company.com/api/v3` | Серверы Tuist, для обмена кодом манифеста, получения токенов доступа, доступа к репозиториям, комментариев к пул-реквестам и проверок |

API URL — это полный базовый URL REST API, включая `/api/v3` или эквивалентный путь, предоставляемый вашим прокси. Tuist не добавляет `/api/v3` к явно указанному API URL. Оставьте поле пустым, если один хостнейм работает как для вашего браузера, так и для Tuist; существующие подключения продолжат использовать `<Server URL>/api/v3`.

Оба адреса должны маршрутизироваться к **одному и тому же экземпляру GitHub Enterprise**. Вашему браузеру нужно достигать только Server URL, а не API-прокси. Серверам Tuist нужно достигать только API URL, а не внутреннего хостнейма браузера.

Для внешнего прокси:

- Используйте HTTPS с сертификатом, которому доверяют серверы Tuist, и публичным DNS, разрешающимся в публичные IP-адреса. Переопределения API URL не обходят защиты Tuist от частных IP/SSRF. Переопределение должно указывать на ваш экземпляр Enterprise, а не на `github.com` или конечную точку `*.github.com`.
- Добавьте в белый список каждый <.localized_link href="/guides/server/network#outbound-ip-addresses">исходящий IP-адрес</.localized_link> Tuist.
- Перенаправляйте конечные точки REST API, которые использует Tuist, включая `POST /api/v3/app-manifests/{code}/conversions`, `POST /api/v3/app/installations/{installation_id}/access_tokens`, а также конечные точки API репозитория для комментариев и проверок. Это восходящие пути GitHub; переведите их, если ваш прокси предоставляет другой префикс.
- Перенаправляйте запросы к GitHub без HTTP-редиректов или интерактивной страницы входа. Tuist не следует автоматически за редиректами API Enterprise, поэтому они не могут обойти проверки публичных IP. Конечная точка преобразования манифеста должна быть доступна во время настройки, до того как у Tuist появятся учетные данные приложения. Загрузка логов GitHub Actions является исключением: Tuist следует за редиректами подписанных архивов только по HTTPS, проверяет и привязывает каждое назначение к публичному IP и не пересылает токен установки.

GitHub может возвращать ссылки пагинации, используя свой внутренний хостнейм. Tuist перебазирует ссылки от настроенного экземпляра GitHub на API URL, сохраняя префикс пути вашего прокси; ссылки на нерелевантные источники отвергаются.

Отдельно, GitHub должен иметь возможность доставлять вебхуки на `https://tuist.dev/webhooks/github` (или `/webhooks/github` на вашем самостоятельно размещаемом сервере Tuist). Инженеры должны иметь возможность вернуться в Tuist для завершения обратных вызовов браузера. API URL не меняет ни одно из этих назначений.

Администраторы организации также могут изменить или очистить API URL в существующей интеграции Enterprise, используя **Save API URL** в карточке интеграции. Повторная установка приложения или повторное подключение проекта не требуются. Очистка восстанавливает `<Server URL>/api/v3`. Сохранение проверяет формат URL, а не连通ность прокси. Обработка вебхуков может занять до одной минуты для использования измененного адреса, поскольку поиски установки кэшируются; запросы, уже находящиеся в процессе выполнения, могут все еще использовать предыдущий адрес.

> [!NOTE]
> **Только план Enterprise на размещенном сервере Tuist**
>
> На размещенном сервере Tuist (`https://tuist.dev`), интеграция с GitHub Enterprise Server доступна исключительно организациям на плане **Enterprise**. Самостоятельно размещаемые развертывания Tuist могут использовать её на любом плане.

## Комментарии к пул-реквестам/запросам на слияние {#pull-merge-request-comments}

Приложение GitHub публикует отчет о запуске Tuist, который включает сводку по пул-реквесту, в том числе ссылки на последние <.localized_link href="/guides/features/previews/xcode#pullmerge-request-comments">превью</.localized_link> или <.localized_link href="/guides/features/selective-testing/generated-xcode-project#pullmerge-request-comments">тесты</.localized_link>:

Tuist обновляет один комментарий по мере поступления результатов. Сборки Gradle отображаются отдельно для каждого корневого проекта и набора запрошенных задач; повторный запуск тех же задач заменяет предыдущий результат этого вызова. Полная история сборок остается доступной в Tuist.

Комментарии включены по умолчанию, сохраняя отчетность для существующих интеграций. Чтобы отключить или снова включить их для проекта, откройте **Project Settings → Integrations** и переключите **GitHub → Run report comments**. У каждого проекта своя настройка; подключения репозиториев остаются управляемыми в настройках организации.

Отключение комментариев не отключает загрузку сборок или тестов, сводки заданий GitHub Actions, подключения репозиториев или другие функции интеграции с GitHub. Существующие комментарии не удаляются.

![Изображение, показывающее комментарий к пул-реквесту](/images/guides/integrations/gitforge/github/pull-request-comment.png)

> [!NOTE]
> **Требования**
>
> Комментарий публикуется только тогда, когда ваши запуски CI <.localized_link href="/guides/server/authentication#continuous-integration">аутентифицированы</.localized_link>.

> [!NOTE]
> **`GITHUB_REF`**
>
> Если у вас есть пользовательский рабочий процесс, который не запускается коммитом пул-реквеста, а, например, комментарием GitHub, вам может потребоваться убедиться, что переменная `GITHUB_REF` установлена либо в `refs/pull/<PR_NUMBER>/merge`, либо в `refs/pull/<PR_NUMBER>/head`.
>
> Вы можете запустить соответствующую команду, например `tuist share`, с префиксом переменной окружения `GITHUB_REF`: <code v-pre>GITHUB_REF="refs/pull/${{ github.event.issue.number }}/head" tuist share</code>

## Сводка задания GitHub Actions {#github-actions-job-summary}

CLI Tuist и плагин Gradle записывают результаты тестов и сборок в [сводку задания](https://github.blog/news-insights/product-news/supercharging-github-actions-with-job-summaries/) в GitHub Actions. Сводка содержит ссылку на полный отчет в Tuist, где доступны более подробные данные, такие как нестабильные тесты и дельты размера бандла.

Для Gradle каждый успешно загруженный отчет о сборке или тесте добавляет свою собственную сводку, сохраняя другой контент, записанный такими инструментами, как `gradle/actions/setup-gradle`. Для этого требуется версия плагина, поддерживающая сводки заданий; старые версии плагина Gradle сообщают только через комментарий к пул-реквесту приложения GitHub. Приложение GitHub не нужно подключать для сводок заданий, и отключение **Run report comments** не влияет на них.

Когда доступно назначение для сводки GitHub Actions, Gradle ожидает завершения загрузок и формирования сводок перед выходом, даже если включено `uploadInBackground`. GitHub фиксирует сводку по завершении шага рабочего процесса.

![Изображение, показывающее отчет о запуске Tuist в сводке задания GitHub Actions](/images/guides/integrations/gitforge/github/github-actions-job-summary.png)

Это особенно полезно при использовании [очередей слияния](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue). Запуск очереди слияния не привязан к пул-реквесту, поэтому комментарий не публикуется, но сводка задания все равно отображает результаты.

> [!NOTE]
> **Требования**
>
> Сводки заданий требуют успешной загрузки отчета. На размещенном сервере Tuist ваши запуски CI должны быть <.localized_link href="/guides/server/authentication#continuous-integration">аутентифицированы</.localized_link>. Самостоятельно размещаемые экземпляры также могут принимать отчеты без учетных данных, если включена публикация отчетов, доверенных сети.
