# Интеграция с GitHub {#github}

Git-репозитории — основа подавляющего большинства программных проектов. Мы интегрируемся с GitHub, чтобы предоставлять аналитику Tuist прямо в ваших пул-реквестах и избавлять от части настройки, например синхронизации ветки по умолчанию.

## Настройка {#setup}

Вам нужно установить приложение Tuist для GitHub во вкладке `Integrations` вашей организации: ![Изображение, показывающее вкладку интеграций](/images/guides/integrations/gitforge/github/integrations.png)

Вы также можете установить приложение напрямую из GitHub. При необходимости войдите в Tuist, авторизуйте приложение GitHub, чтобы Tuist мог подтвердить ваш доступ к установке, и выберите организацию Tuist для подключения. Вы должны владеть организацией GitHub (или личным аккаунтом GitHub), куда устанавливается приложение. Доступны только организации Tuist, которыми вы управляете, и ваш личный аккаунт Tuist. Если доступен только один аккаунт, Tuist подключает его автоматически, не показывая выбор. При начале работы из Tuist организация уже выбрана, и этот шаг пропускается.

После этого вы можете добавить связь проекта между вашим репозиторием GitHub и проектом Tuist:

![Изображение, показывающее добавление связи проекта](/images/guides/integrations/gitforge/github/add-project-connection.png)

После установки приложения вы также можете связать проект без использования дашборда:

- **CLI:** `tuist project repository connect owner/name`, и `tuist project repository disconnect` для удаления связи.
- **REST API:** `PUT` и `DELETE` на `/api/projects/{account_handle}/{project_handle}/vcs-connection`.
- **Model Context Protocol:** инструменты `connect_project_repository` и `disconnect_project_repository`.

Репозиторий должен быть доступен установке приложения GitHub, а проект использует ветку по умолчанию репозитория. Токены аккаунта требуют область видимости `project:admin:write`.

> [!TIP]
> **Белый список IP-адресов**
>
> Если ваша организация GitHub использует [списки разрешённых IP-адресов](https://docs.github.com/en/organizations/keeping-your-organization-secure/managing-security-settings-for-your-organization/managing-allowed-ip-addresses-for-your-organization) или ваш экземпляр GitHub находится за файрволом, обязательно добавьте исходящие IP-адреса Tuist <.localized_link href="/guides/server/network#outbound-ip-addresses">в белый список</.localized_link>, чтобы интеграция могла взаимодействовать с вашим репозиторием.

### GitHub Enterprise Server {#github-enterprise-server}

Tuist также интегрируется с самостоятельно размещёнными экземплярами GitHub Enterprise Server (GHES). На карточке интеграции с GitHub переключитесь на вкладку **Сервер предприятия**, введите базовый URL вашего GHES (например, `https://github.example.com`) и нажмите «Установить».

Поскольку приложения GitHub привязаны к одному экземпляру GitHub, Tuist не может повторно использовать своё приложение с github.com на вашем GHES — вместо этого кнопка установки проводит вас через [поток манифеста приложения](https://docs.github.com/en/apps/sharing-github-apps/registering-a-github-app-from-a-manifest) GitHub: GHES помогает вашему администратору зарегистрировать новое приложение Tuist на экземпляре, а затем передаёт учётные данные нового приложения обратно в Tuist. Tuist хранит эти учётные данные в зашифрованном виде для каждой установки и использует их для каждого вызова API, подписи вебхуков и ссылок на ваши репозитории.

Дополнительная настройка сервера Tuist не требуется; поток манифеста автоматически генерирует и настраивает всё необходимое.

#### Разрешения приложения и события вебхуков {#github-app-permissions}

Для комментариев к пул-реквестам и проверок размера бандла Tuist требует следующие **разрешения репозитория**:

| Разрешение | Доступ | Используется для |
|---|---|---|
| Метаданные (`metadata`) | Только чтение | Базовые метаданные репозитория; требуются GitHub для каждого приложения |
| Пул-реквесты (`pull_requests`) | Чтение и запись | Чтение пул-реквестов, включая SHA коммита head, а также получение списка, публикация и обновление комментариев к пул-реквестам |
| Проверки (`checks`) | Чтение и запись | Создание и обновление запусков проверок, включая проверки прохождения/непрохождения по размеру бандла |

Tuist использует событие вебхука `check_run` для обработки действий проверки размера бандла. Поток манифеста настраивает эту подписку автоматически.

Для ручной настройки приложения на github.com с самостоятельно размещённым сервером Tuist см. <.localized_link href="/guides/server/self-host/server#platform-github-registering-the-app">руководство по самостоятельному размещению</.localized_link>.

#### Отдельные URL браузера и API {#separate-browser-and-api-urls}

Если инженеры обращаются к GitHub Enterprise через внутренний хостнейм, а сторонние сервисы используют внешний прокси, настройте оба адреса перед нажатием кнопки установки:

| Поле | Пример | Используется |
|---|---|---|
| **URL сервера** | `https://github.internal.company.com` | Ваш браузер — для регистрации и установки приложения, а также для ссылок на GitHub из Tuist |
| **URL API** | `https://github-proxy.company.com/api/v3` | Серверы Tuist — для обмена кодом манифеста, получения токенов доступа, доступа к репозиториям, комментариев к пул-реквестам и проверок |

URL API — это полный базовый URL REST API, включая `/api/v3` или эквивалентный путь, предоставляемый вашим прокси. Tuist не добавляет `/api/v3` к явно указанному URL API. Оставьте поле пустым, если один хостнейм работает и для вашего браузера, и для Tuist; существующие подключения продолжат использовать `<Server URL>/api/v3`.

Оба адреса должны вести на **один и тот же экземпляр GitHub Enterprise**. Вашему браузеру нужно достигать только URL сервера, а не прокси API. Серверам Tuist нужно достигать только URL API, а не внутреннего хостнейма браузера.

Для внешнего прокси:

- Используйте HTTPS с сертификатом, которому доверяют серверы Tuist, и публичный DNS, разрешающийся в публичные IP-адреса. Переопределения URL API не обходят защиты Tuist от частных IP-адресов и SSRF. Переопределение должно указывать на ваш экземпляр Enterprise, а не на `github.com` или конечную точку `*.github.com`.
- Добавьте в белый список каждый <.localized_link href="/guides/server/network#outbound-ip-addresses">исходящий IP-адрес</.localized_link> Tuist.
- Перенаправляйте конечные точки REST API, которые использует Tuist, включая `POST /api/v3/app-manifests/{code}/conversions`, `POST /api/v3/app/installations/{installation_id}/access_tokens` и конечные точки API репозитория для комментариев и проверок. Это upstream-пути GitHub; переведите их, если ваш прокси предоставляет другой префикс.
- Перенаправляйте запросы к GitHub без HTTP-редиректов или интерактивной страницы входа. Tuist не следует автоматически за редиректами API Enterprise, поэтому они не могут обойти проверки публичных IP-адресов. Конечная точка преобразования манифеста должна быть доступна во время настройки, до того как у Tuist появятся учетные данные приложения. Загрузки логов GitHub Actions являются исключением: Tuist следует за редиректами подписанных архивов только по HTTPS, проверяет и привязывает каждое назначение к публичному IP-адресу и не пересылает токен установки.

GitHub может возвращать ссылки пагинации, используя свой внутренний хостнейм. Tuist перебазирует ссылки с настроенного экземпляра GitHub на URL API, сохраняя префикс пути вашего прокси; ссылки на нерелевантные источники отвергаются.

Отдельно, GitHub должен иметь возможность доставлять вебхуки на `https://tuist.dev/webhooks/github` (или `/webhooks/github` на вашем самостоятельно размещённом сервере Tuist). Инженеры должны иметь возможность вернуться в Tuist для завершения обратных вызовов браузера. URL API не меняет ни одно из этих назначений.

Администраторы организации также могут изменить или очистить URL API в существующей интеграции Enterprise, используя **Сохранить URL API** в карточке интеграции. Повторная установка приложения или повторное подключение проекта не требуются. Очистка восстанавливает `<Server URL>/api/v3`. При сохранении проверяется формат URL, а не связность прокси. Обработка вебхуков может занять до одной минуты для использования изменённого адреса, поскольку поиски установки кэшируются; запросы, уже находящиеся в процессе выполнения, могут всё ещё использовать предыдущий адрес.

> [!NOTE]
> **Только план Enterprise на размещённом сервере Tuist**
>
> На размещённом сервере Tuist (`https://tuist.dev`) интеграция с GitHub Enterprise Server доступна исключительно организациям на плане **Enterprise**. Самостоятельно размещённые развертывания Tuist могут использовать её на любом плане.

## Комментарии к пул-/мерж-реквестам {#pull-merge-request-comments}

Приложение GitHub публикует отчёт о запуске Tuist, который включает сводку по пул-реквесту, в том числе ссылки на последние <.localized_link href="/guides/features/previews#pullmerge-request-comments">превью</.localized_link> или <.localized_link href="/guides/features/selective-testing#pullmerge-request-comments">тесты</.localized_link>:

Tuist обновляет один комментарий по мере поступления результатов. Сборки Gradle отображаются отдельно для каждого корневого проекта и набора запрошенных задач; повторный запуск тех же задач заменяет предыдущий результат этого вызова. Полная история сборок остаётся доступной в Tuist.

Комментарии включены по умолчанию, что сохраняет отчётность для существующих интеграций. Чтобы отключить или снова включить их для проекта, откройте **Настройки проекта → Интеграции** и переключите **GitHub → Комментарии к отчётам о запусках**. У каждого проекта своя настройка; подключения репозиториев по-прежнему управляются в настройках организации.

Отключение комментариев не отключает выгрузку сборок или тестов, сводки заданий GitHub Actions, подключения репозиториев или другие функции интеграции с GitHub. Существующие комментарии не удаляются.

![Изображение, показывающее комментарий к пул-реквесту](/images/guides/integrations/gitforge/github/pull-request-comment.png)

> [!NOTE]
> **Требования**
>
> Комментарий публикуется только тогда, когда ваши запуски CI <.localized_link href="/guides/integrations/continuous-integration#authentication">аутентифицированы</.localized_link>.

> [!NOTE]
> **Github_ref**
>
> Если у вас есть пользовательский рабочий процесс, который запускается не коммитом пул-реквеста, а, например, комментарием GitHub, вам может потребоваться убедиться, что переменная `GITHUB_REF` установлена либо в `refs/pull/<PR_NUMBER>/merge`, либо в `refs/pull/<PR_NUMBER>/head`.
>
> Вы можете выполнить соответствующую команду, например `tuist share`, с префиксом переменной окружения `GITHUB_REF`: <code v-pre>GITHUB_REF="refs/pull/${{ github.event.issue.number }}/head" tuist share</code>

## Сводка задания GitHub Actions {#github-actions-job-summary}

CLI Tuist и плагин Gradle записывают результаты тестов и сборок в [сводку задания](https://github.blog/news-insights/product-news/supercharging-github-actions-with-job-summaries/) в GitHub Actions. Сводка содержит ссылку на полный отчёт в Tuist, где доступны более подробные сведения, такие как нестабильные тесты и изменения размера бандла.

Для Gradle каждый успешно загруженный отчёт о сборке или тесте добавляет свою собственную сводку, сохраняя другой контент, созданный такими инструментами, как `gradle/actions/setup-gradle`. Для этого требуется версия плагина, включающая поддержку сводки задания; более старые версии плагина Gradle сообщают результаты только через комментарий приложения GitHub к пул-реквесту. Приложение GitHub не нужно подключать для сводок заданий, и отключение **Комментариев к отчётам о запусках** не влияет на них.

Когда доступно назначение для сводки GitHub Actions, Gradle ожидает завершения выгрузок и формирования сводок перед выходом, даже если включено `uploadInBackground`. GitHub фиксирует сводку по завершении шага рабочего процесса.

![Изображение, показывающее отчёт о запуске Tuist в сводке задания GitHub Actions](/images/guides/integrations/gitforge/github/github-actions-job-summary.png)

Это особенно полезно при использовании [очередей слияния](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue). Запуск очереди слияния не привязан к пул-реквесту, поэтому комментарий не публикуется, но сводка задания всё равно отображает результаты.

> [!NOTE]
> **Требования**
>
> Сводки заданий требуют успешной выгрузки отчёта. На размещённом сервере Tuist ваши запуски CI должны быть <.localized_link href="/guides/integrations/continuous-integration#authentication">аутентифицированы</.localized_link>. Самостоятельно размещённые экземпляры также могут принимать отчёты без учётных данных, если включена публикация отчётов с доверием к сети.
