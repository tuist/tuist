# Интеграция с Entire {#entire}

Tuist может публиковать данные о сборках, тестах, превью и бандлах для открытых и черновых [Trails](https://docs.entire.com/guides/trails/overview) в репозиториях [Entire](https://entire.com). Каждый Trail получает гейт Tuist с отчётом о запуске, находками по всем изменениям для упавших и нестабильных тестов, а также сводным комментарием, который Tuist обновляет по мере поступления новых данных вместо публикации нового комментария при каждой выгрузке.

Установка плагина не запускает сборки или тесты. Ваши существующие рабочие процессы продолжают выгружать результаты в Tuist, а интеграция переносит эти результаты в ваши Trails.

## Настройка {#setup}

Администратор аккаунта Tuist устанавливает плагин, затем подключает репозитории к проектам Tuist, как в интеграциях с <.localized_link href="/guides/integrations/gitforge/github">GitHub</.localized_link> и <.localized_link href="/guides/integrations/gitforge/origin">Origin</.localized_link>.

1. Откройте раздел **Settings → Integrations** вашего аккаунта.
2. В карточке Entire выберите **Install Entire plugin**. Выберите проект Entire и репозитории, которыми хотите поделиться с Tuist.

   ![Установите плагин Entire из раздела интеграций аккаунта](/images/guides/integrations/gitforge/entire/integrations.png)

3. Вернитесь в Tuist и выберите **Add new project connection**. В разделе **Choose repository to connect to** выберите свой проект Tuist и репозиторий Entire, затем нажмите **Create Connection**. Если доступен только один проект Tuist, он будет выбран автоматически.

   ![Подключите проект Tuist к репозиторию Entire](/images/guides/integrations/gitforge/entire/add-project-connection.png)

4. Продолжайте выгружать результаты из CI с помощью ваших существующих аутентифицированных команд Tuist, например используя <.localized_link href="/guides/server/authentication#account-tokens">токен аккаунта</.localized_link>. Tuist сопоставляет результаты с текущим головным коммитом каждого Trail, поэтому флаги, специфичные для Entire, не нужны.

Проект Tuist может сохранять подключение к GitHub и одновременно публиковать данные в Entire, что полезно, когда репозиторий Entire является зеркалом репозитория GitHub. Интеграция не требует использования исполнителя CI от Tuist и не меняет вашего провайдера CI.

## Отчёты и разрешения {#reports-and-permissions}

При установке плагина вы предоставляете разрешения, необходимые для поиска Trails и публикации отчётов:

| Разрешение | Для чего используется |
| --- | --- |
| Содержимое репозитория: чтение | Получение событий Trail и поиск открытых и черновых Trails с их головными коммитами. |
| Проверки: запись | Публикация гейта Tuist на головном коммите Trail. |
| Находки: запись | Публикация упавших и нестабильных тестов в виде находок и закрытие находок, заменяемых новым отчётом. |
| Обсуждения: запись | Публикация и обновление сводного комментария. Без этого разрешения Tuist всё равно публикует гейт и находки. |

Tuist не нуждается в доступе на запись к вашему исходному коду или разрешении на слияние Trails.

Tuist публикует три элемента для каждого Trail:

- **Гейт:** проверка Tuist появляется в разделе **Gates** с отчётом о запуске и ссылкой на проект в Tuist. Она отображается под плагином Tuist, отдельно от гейта **Checks** зеркала GitHub. Завершается со статусом `neutral`, который Entire отображает как пройденный, поскольку выгруженные результаты не сообщают Tuist, завершились ли все ожидаемые задания CI. Гейт не блокирует слияние, даже если есть находки, поэтому сохраняйте обязательные проверки вашего провайдера CI для обеспечения прохождения/падения.
- **Находки:** упавшие и нестабильные тесты отображаются как находки по всем изменениям со ссылками на тест-кейсы в Tuist. Находки не влияют на гейт обзора Agent в Entire.
- **Сводный комментарий:** как и комментарий к пул-реквесту в GitHub и Origin, для каждого проекта сохраняется один комментарий Tuist Run Report на каждый Trail. Если вы удалите его, следующий отчёт опубликует его снова.

По мере поступления новых результатов Tuist публикует обновлённый отчёт для текущего головного коммита Trail и закрывает находки, которые он заменяет. Повторные попытки не создают дублирующих обзоров, находок или комментариев, включая случаи, когда ответ Entire на публикацию теряется. При открытии или повторном открытии Trail подхватываются результаты, уже выгруженные для его головного коммита. Если для текущего головного коммита нет результатов, Tuist ничего не публикует, поэтому гейт старого коммита не может удовлетворить требования для нового головного коммита. Закрытые и слитые Trails не обновляются.

Карточка Entire перечисляет подключения проектов к репозиториям. Выберите **Manage → Remove connection** для подключения проекта, чтобы остановить его отчётность без удаления плагина. Уже опубликованные отчёты остаются в Entire, а повторное подключение начинает публикацию новых отчётов. Чтобы изменить доступ плагина к репозиториям или удалить его, используйте настройки **Plugins** проекта в Entire.

## Самостоятельно размещаемые серверы {#server-configuration}

Если вы размещаете собственный сервер Tuist, сначала зарегистрируйте и настройте плагин Entire для вашего развёртывания. Следуйте <.localized_link href="/guides/server/self-host/server#platform-entire">инструкциям по самостоятельному размещению Entire</.localized_link>, затем вернитесь к шагам настройки выше, чтобы подключить аккаунты и проекты.
