# SCIM-синхронизация {#scim-provisioning}

Tuist поддерживает синхронизацию по протоколу SCIM 2.0, чтобы поставщик удостоверений мог автоматически создавать, обновлять и удалять учётные записи участников организации.

Настройка SCIM выполняется на вкладке **Authentication** в параметрах вашей организации. Токен SCIM — это токен учётной записи организации с правами доступа только к SCIM; он отображается один раз при создании.

> [!NOTE]
> SCIM управляет членством и жизненным циклом учётных записей. Он не заменяет <.localized_link href="/guides/integrations/authentication/sso">Single Sign-On</.localized_link>. Если пользователи должны также входить через вашего поставщика удостоверений, настройте SSO отдельно.

Синхронизированные пользователи уже являются участниками организации. При входе с тем же адресом электронной почты это членство может подтвердить доверие для связывания их идентичности у поставщика. <.localized_link href="/guides/integrations/authentication/sso#verify-a-login-email-domain">Проверенный домен адреса электронной почты для входа</.localized_link> и <.localized_link href="/guides/integrations/authentication/sso#choose-an-enrollment-policy">политика регистрации</.localized_link> определяют поведение пользователей, которые ещё не были синхронизированы или добавлены в организацию.

## Okta {#okta}

Для работы с Tuist Okta использует два отдельных приложения:

- **OIDC Web Application** — для входа в Tuist.
- **SCIM 2.0 Test App (Header Auth)** — для синхронизации пользователей и групп в Tuist.

Если пользователи должны входить через Okta, сначала настройте <.localized_link href="/guides/integrations/authentication/sso#okta">Okta SSO</.localized_link>, а затем выполните шаги ниже для настройки синхронизации SCIM.

### Шаг 1. Создайте токен SCIM для Tuist {#okta-step-1}

1. В Tuist перейдите на вкладку параметров **Authentication** вашей организации.
2. В разделе **SCIM provisioning** скопируйте **URL-адрес конечной точки SCIM**. Он должен заканчиваться на `/scim/v2`.
3. Нажмите **Generate token**.
4. Укажите имя токена (например, `Okta`).
5. Скопируйте созданный токен. Tuist показывает токен только один раз.

### Шаг 2. Добавьте приложение Okta для SCIM {#okta-step-2}

1. В панели администратора Okta перейдите в **Applications > Applications > Browse App Catalog**.
2. Найдите и добавьте **SCIM 2.0 Test App (Header Auth)**.
3. Задайте узнаваемое имя, например `Tuist SCIM`.
4. Завершите настройку параметров входа для тестового приложения SCIM. Tuist не использует это приложение для входа; вход обрабатывается OIDC-приложением из руководства по SSO.

### Шаг 3. Настройте интеграцию API {#okta-step-3}

1. Откройте вкладку **Provisioning** приложения SCIM.
2. В разделе **Settings > Integration** нажмите **Configure API Integration** или **Edit**.
3. Включите опцию **Enable API integration**.
4. Вставьте **URL-адрес конечной точки SCIM** из Tuist в поле Okta **Base URL**.
5. Вставьте токен SCIM из Tuist в поле **API Token**, добавив префикс `Bearer `. Например, `Bearer tuist_scim_...`. Okta отправляет это значение в заголовке `Authorization`, а Tuist ожидает bearer-токен.
6. Включите **Import Groups**, если хотите, чтобы Okta читал группы SCIM из Tuist.
7. Нажмите **Test API Credentials**. Okta должна сообщить об успешной проверке интеграции.
8. Нажмите **Save**.

### Шаг 4. Включите действия синхронизации {#okta-step-4}

1. На вкладке **Provisioning** приложения SCIM откройте раздел **Settings > To App**.
2. Нажмите **Edit**.
3. Включите:
   - **Create Users**
   - **Update User Attributes**
   - **Deactivate Users**
4. Нажмите **Save**.

### Шаг 5. Назначьте пользователей или группы {#okta-step-5}

1. Откройте вкладку **Assignments** приложения SCIM.
2. Назначьте пользователей или группы, которые должны быть синхронизированы в Tuist.
3. Назначьте тех же пользователей или группы приложению Okta OIDC, если они также должны иметь возможность входа через SSO.
4. Проверьте вкладку **Members** в Tuist, чтобы убедиться, что назначенные пользователи отображаются в организации.

Чтобы протестировать удаление из организации, отмените назначение или деактивируйте пользователя в Okta и убедитесь, что он исчезнет с вкладки **Members** организации Tuist.

### Назначение ролей {#okta-assigning-roles}

В Tuist есть три <.localized_link href="/guides/server/accounts-and-projects#roles">роли</.localized_link>: `admin`, `user` и `viewer`. Для каждой роли Tuist предоставляет одну группу SCIM: `Tuist Admins`, `Tuist Users` и `Tuist Viewers`. Свяжите группы Okta с ними с помощью функции **Group Push**:

1. Выберите или создайте группу Okta для каждой назначаемой роли и назначьте эти группы на вкладке **Assignments** приложения SCIM.
2. Убедитесь, что опция **Import Groups** включена в интеграции API, затем откройте вкладку **Import** приложения SCIM и нажмите **Import Now**, чтобы Okta узнал о группах Tuist.
3. Откройте вкладку **Push Groups** приложения SCIM и нажмите **Push Groups > Find groups by name**.
4. Выберите группу Okta, выберите действие **Link Group** и укажите соответствующую группу Tuist. Tuist не поддерживает создание групп через SCIM, поэтому свяжите существующую группу вместо создания новой.
5. Нажмите **Save** и повторите для остальных ролей.

Добавление пользователя в связанную группу назначает ему эту роль. Удаление пользователя из группы возвращает ему роль, которая используется организацией по умолчанию для участников единого входа, то есть `user`, если администратор не изменил её в разделе **Settings > Authentication**. Пользователи, не входящие ни в одну связанную группу, также получают эту роль. Удаление пользователя из группы не удаляет его из организации; для этого отмените назначение или деактивируйте его в Okta.

## Microsoft Entra ID {#microsoft-entra-id}

Entra ID синхронизирует данные в Tuist через корпоративное приложение, не входящее в галерею. Сначала настройте <.localized_link href="/guides/integrations/authentication/sso#microsoft-entra-id">Microsoft Entra ID SSO</.localized_link>, если пользователи также должны входить через Entra ID.

Приложение, которое вы регистрируете для единого входа, и корпоративное приложение, используемое для синхронизации, могут быть одним и тем же. Синхронизация настраивается в параметрах корпоративного приложения.

### Шаг 1. Создайте токен SCIM для Tuist {#entra-step-1}

1. В Tuist перейдите на вкладку настроек **Authentication** вашей организации.
2. В разделе **SCIM provisioning** скопируйте **URL-адрес конечной точки SCIM**. Он должен заканчиваться на `/scim/v2`.
3. Нажмите **Generate token**.
4. Укажите имя токена (например, `Entra ID`).
5. Скопируйте созданный токен. Tuist показывает токен только один раз.

### Шаг 2. Настройте синхронизацию {#entra-step-2}

1. В центре администрирования Microsoft Entra перейдите в раздел **Identity > Applications > Enterprise applications** и откройте приложение Tuist.
2. Откройте раздел **Provisioning** и установите для параметра **Provisioning Mode** значение **Automatic**.
3. Установите для параметра **Tenant URL** URL-адрес конечной точки SCIM из Tuist.
4. Установите для параметра **Secret Token** токен SCIM из Tuist. Введите токен отдельно, без префикса `Bearer `; Entra ID добавляет схему самостоятельно.
5. Нажмите **Test Connection**. Entra ID должна сообщить, что предоставленные учетные данные авторизованы.
6. Сохраните конфигурацию.

### Шаг 3. Установите атрибут сопоставления {#entra-step-3}

1. В разделе **Mappings** откройте пункт **Provision Microsoft Entra ID Users**.
2. Убедитесь, что `userPrincipalName` или `mail` сопоставляется с атрибутом SCIM `userName` и что этот атрибут используется для **Matching precedence 1**.
3. Удалите `externalId` из атрибутов сопоставления, если он присутствует.

Tuist сопоставляет синхронизированных пользователей по `userName`. Он не хранит идентификатор объекта каталога, который Entra ID отправляет как `externalId`, поэтому фильтр по этому атрибуту не найдет существующего участника, и циклы синхронизации могут работать непредсказуемо.

### Шаг 4. Отключите синхронизацию групп {#entra-step-4}

В разделе **Mappings** отключите параметр **Provision Microsoft Entra ID Groups**.

Группы SCIM в Tuist — это фиксированные группы для каждой роли организации, а не группы каталога, которые можно создавать, поэтому попытка синхронизировать группу каталога завершится ошибкой. Вместо этого назначайте роли, как описано ниже.

### Шаг 5. Назначьте пользователей и запустите синхронизацию {#entra-step-5}

1. Откройте вкладку **Users and groups** приложения и назначьте пользователей или группы, которые должны быть синхронизированы в Tuist.
2. Вернитесь в раздел **Provisioning** и запустите синхронизацию.
3. Проверьте вкладку **Members** в Tuist, чтобы убедиться, что назначенные пользователи отображаются в организации.

Entra ID выполняет синхронизацию по собственному расписанию, обычно каждые 40 минут, поэтому участники не появляются мгновенно. Используйте **Provision on demand**, чтобы немедленно протестировать синхронизацию одного пользователя.

Чтобы протестировать удаление из организации, отмените назначение или отключите пользователя в Entra ID и убедитесь, что он исчезнет с вкладки **Members** организации Tuist.

Если позже вы измените область синхронизации, например с **Sync all users and groups** на **Sync only assigned users and groups**, нажмите **Restart provisioning**. Entra ID применит новую область, включая удаление пользователей, которые больше в нее не входят, только после перезапуска.

### Назначение ролей {#entra-assigning-administrators}

В Tuist есть три <.localized_link href="/guides/server/accounts-and-projects#roles">роли</.localized_link>: `admin`, `user` и `viewer`. Чтобы настроить их из Entra ID:

1. В разделе **App registrations** откройте приложение Tuist и добавьте роль приложения для каждой роли Tuist, которую вы хотите назначить. Установите **Allowed member types** в значение **Users/Groups**, а **Value** — в `admin`, `user` или `viewer`.
2. На вкладке **Users and groups** корпоративного приложения назначьте каждому пользователю или группе одну из этих ролей приложения. Пользователь может иметь несколько ролей приложения. Tuist применяет наиболее привилегированную роль, где `admin` имеет приоритет над `user`, а `user` — над `viewer`, поэтому пользователь, состоящий в группах, сопоставленных с разными ролями, получит самую высокую из них.
3. В разделе **Provisioning > Mappings** откройте выпадающий список **Advanced Options** и выберите **Edit target User attributes**. Добавьте атрибут с именем `roles`, установите для **Type** значение `String` и отметьте пункт **Multi-Value**.
4. В разделе **Provisioning > Mappings > Provision Microsoft Entra ID Users** нажмите **Add New Mapping**. Установите **Mapping type** в значение **Expression**, **Expression** в значение `AssertiveAppRoleAssignmentsComplex([appRoleAssignments])`, а **Target attribute** — в добавленный вами атрибут `roles`.
5. Оставьте область синхронизации установленной в значение **Sync only assigned users and groups**. `AssertiveAppRoleAssignmentsComplex` несовместим с **Sync all users and groups**.

`AssertiveAppRoleAssignmentsComplex` отправляет все роли приложения, которые есть у пользователя, а также сообщения об удалении, поэтому снятие роли в Entra ID понижает пользователя до самой привилегированной роли, которая у него остается. `SingleAppRoleAssignment([appRoleAssignments])`, сопоставленный с `roles[primary eq "True"].value`, также работает, но он отправляет только одну роль, и Entra ID не гарантирует, какую именно выберет, если у пользователя их несколько.

Изменение ролей приложения пользователя в Entra ID обновляет его роль в Tuist при следующем цикле синхронизации. Пользователь, синхронизированный без роли приложения или со значениями, отличными от `admin`, `user` или `viewer`, получает роль, по которой организация регистрирует участников единого входа, то есть `user`, если администратор не изменил ее в разделе **Settings > Authentication**.

## Поведение жизненного цикла {#lifecycle-behavior}

Когда ваш поставщик удостоверений назначает пользователя приложению синхронизации, Tuist создает пользователя, если этот адрес электронной почты еще не известен Tuist, а затем добавляет его в организацию. Если адрес электронной почты уже принадлежит существующему пользователю Tuist вне организации, Tuist добавляет этого пользователя и отправляет ему уведомление, если только учетная запись не была создана через интеграцию SCIM другой организации. В этом случае Tuist отклоняет запрос с кодом `409`, чтобы поставщик удостоверений не мог захватить учетную запись, управляемую другой организацией.

Ваш поставщик удостоверений может изменить адрес электронной почты пользователя (`userName`), только пока ваша организация управляет учетной записью самостоятельно. Это означает, что Tuist создал учетную запись через вашу интеграцию SCIM, и с тех пор пользователь не устанавливал пароль, не входил через поставщика, отличного от единого входа вашей организации, не регистрировал агента и не присоединился к другой организации. Для любого другого пользователя Tuist отклоняет изменение с кодом `400` и типом ошибки SCIM `mutability`. При этом деактивация, отправленная в том же запросе, все равно применяется. Tuist также отказывается создавать пользователей или переименовывать их в домен входа, проверенный другой организацией, а также в собственный домен Tuist на tuist.dev. Переименование очищает запись о том, что пользователь подтвердил контроль над старым адресом.

Когда ваш поставщик удостоверений отменяет назначение или деактивирует пользователя, Tuist удаляет его роль в организации, сохраняя запись пользователя и любые принадлежащие ему работы. Удаление из организации не отключает пользователя глобально, так как один и тот же пользователь Tuist может принадлежать другим организациям.

Tuist предоставляет три синтетические группы SCIM: `Tuist Admins`, `Tuist Users` и `Tuist Viewers`. Добавление участника в группу устанавливает его роль в организации. Удаление участника из группы, соответствующей его текущей роли, возвращает его к роли регистрации, а само членство прекращается только тогда, когда пользователь отменяется назначение или деактивируется. Поставщики удостоверений также могут устанавливать роль через атрибут SCIM `roles` у пользователя со значением `admin`, `user` или `viewer`. Поставщик удостоверений, отправляющий несколько значений, применяет наиболее привилегированное из них, где `admin` имеет приоритет над `user`, а `user` — над `viewer`.

## Поддерживаемые функции SCIM {#supported-scim-features}

Tuist поддерживает конечные точки SCIM 2.0, необходимые поставщикам удостоверений для управления жизненным циклом:

- `POST`, `GET`, `PUT`, `PATCH` и `DELETE` для `/Users`.
- `GET` и `PATCH` для `/Groups`.
- Конечные точки обнаружения SCIM для `/ServiceProviderConfig`, `/ResourceTypes` и `/Schemas`.
