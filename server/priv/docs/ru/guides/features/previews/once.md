# Публикация артефактов Once

[Once](https://buildonce.dev/docs/guide/infrastructure/tuist#publish-application-previews) может публиковать неизменяемые артефакты, используя существующую аутентификацию Tuist. Для этого требуется Once версии 0.74.0+ и сервер Tuist с приемником артефактов. Вместо этого Once версии 0.73.x использует устаревший адаптер для одиночной полезной нагрузки.

## Настройка назначения

В файле `once.toml` рабочего пространства:

```toml
[infrastructures.tuist]
kind = "tuist"
account = "acme"
project = "app"

[infrastructure.artifacts]
name = "tuist"
```

```bash
once auth login --provider tuist
once artifact publish MyApplication --track review
```

Приемник сохраняет полный набор, манифесты участников и полезные нагрузки, включая неизвестные интерфейсы. Поддерживаемые нативные интерфейсы асинхронно преобразуются в превью с использованием настроек видимости, доступа и распространения проекта по умолчанию. Содержимое общих артефактов остается приватным, даже в публичных проектах. Квитанция подтверждает хранение артефакта, а не завершение обработки превью; ее URL открывает список превью проекта.

## Поддерживаемые приложения

Проекция Apple принимает метаданные `dev.once.apple-install.v2` для приложений macOS и симулятора, подписанных ad-hoc и экспортированных на macOS. Приложения для физических устройств не поддерживаются. Проекция Android принимает метаданные `dev.once.android-install.v1` с проверенной подписью. Once одобряет автоматическую публикацию только для APK, подписанных отладочным ключом и не содержащих инструменты инструментации. Неизвестные интерфейсы остаются доступными для скачивания как артефакты без создания превью. Ссылки для установки Android сохраняют имя файла `.apk`, хотя полезные нагрузки хранятся под хешами содержимого.

## Автоматическая публикация после сборок

```toml
[infrastructure]
publish_on_build = ["MyApplication"]
```

```bash
once artifact publish MyApplication --allow-on-build
once build MyApplication
```

Все запрошенные сборки должны успешно завершиться. Автоматическая публикация также требует одобрения производителем всего замыкания и локальной авторизации для этой машины, рабочего пространства, точной конечной точки, цели и стабильного назначения проекта Tuist. Без политики или авторизации сетевые запросы на публикацию артефактов не выполняются. Обычные сборки Once не имеют побочных эффектов неявной публикации.

Повторное выполнение той же сохраненной публикации проверяет удаленную квитанцию и избегает повторной загрузки. Это отличается от поведения дублирования сборок в `tuist share`.

## Хранение

Публикации артефактов истекают через 30 дней в размещенном Tuist. Самостоятельно размещенные экземпляры используют `TUIST_APP_PREVIEW_RETENTION_DAYS`; если переменная не установлена, срок действия для этого семейства отключается. Истекшие записи остаются как надгробия и не могут быть реактивированы путем повторного выполнения того же намерения. Существующие рабочие процессы подписи, видимости и распространения `tuist share` остаются без изменений.

См. <.localized_link href="/guides/features/previews#run-a-preview">Запуск превью</.localized_link> для информации о запуске опубликованных сборок, доступе, треках и бейджах README.

## Превью Apple

Для поддерживаемых превью симулятора Apple и macOS см. <.localized_link href="/guides/features/previews/run/macos">инструкции по приложению-компаньону Tuist для macOS</.localized_link>. Приложения для физических устройств по-прежнему не поддерживаются для публикации через Once.
