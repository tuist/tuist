# Превью Struo {#struo-previews}

<a id="once-previews"></a>

[Struo](https://struo.run/docs/guide/infrastructure/tuist#publish-application-previews) может публиковать артефакты приложений в Tuist, чтобы коллеги могли протестировать сборку без её локальной пересборки. Используйте [Struo 1.0.0](https://github.com/tuist/struo/releases/tag/1.0.0) или более позднюю версию и сервер Tuist с приёмником артефактов.

## Настройка назначения

Выполните шаги из раздела <.localized_link href="/guides/get-started/struo-project">Начало работы со Struo</.localized_link>, затем добавьте привязку артефактов в файл `struo.toml` рабочего пространства. Повторно используйте провайдер, если он уже настроен для кэширования:

```toml
[infrastructures.tuist]
kind = "tuist"
account = "acme"
project = "app"

[infrastructure.artifacts]
name = "tuist"
```

```bash
struo auth login --provider tuist
struo artifact publish MyApplication --track review
```

Приёмник сохраняет полный набор, манифесты участников и полезные нагрузки, включая неизвестные интерфейсы. Поддерживаемые нативные интерфейсы асинхронно преобразуются в превью с использованием настроек видимости, доступа и распространения проекта по умолчанию. Содержимое обычных артефактов остаётся закрытым, даже в публичных проектах. Квитанция подтверждает хранение артефакта, а не завершение обработки превью; её URL открывает список превью проекта.

## Поддерживаемые приложения

Проекция Apple принимает метаданные `dev.struo.apple-install.v2` для macOS-приложений и приложений для симулятора с ad-hoc подписью, экспортированных на macOS. Приложения для физических устройств не поддерживаются. Проекция Android принимает метаданные `dev.struo.android-install.v1` с проверенной подписью. Struo одобряет автоматическую публикацию только для APK с отладочной подписью и без инструментации. Неизвестные интерфейсы остаются доступными для скачивания как артефакты без создания превью. Ссылки для установки Android сохраняют имя файла с расширением `.apk`, хотя полезные нагрузки хранятся под хешами содержимого.

## Автоматическая публикация после сборок

```toml
[infrastructure]
publish_on_build = ["MyApplication"]
```

```bash
struo artifact publish MyApplication --allow-on-build
struo build MyApplication
```

Все запрошенные сборки должны завершиться успешно. Автоматическая публикация также требует одобрения производителем всего замыкания и локальной авторизации для этой машины, рабочего пространства, конкретного эндпоинта, цели и стабильного назначения проекта Tuist. Без политики или авторизации сетевые запросы на публикацию артефактов не выполняются. Обычные сборки Struo не имеют побочных эффектов неявной публикации.

Повторное выполнение той же сохранённой публикации проверяет удалённую квитанцию и избегает повторной загрузки. Это отличается от поведения при дублировании сборок в `tuist share`.

## Хранение

Публикации артефактов истекают через 30 дней на хостинге Tuist. В самостоятельно размещённых экземплярах используется переменная `TUIST_APP_PREVIEW_RETENTION_DAYS`; если она не установлена, срок действия для этого семейства отключается. Истёкшие записи остаются как надгробия и не могут быть реактивированы повторным выполнением того же действия. Существующие рабочие процессы подписи, видимости и распространения `tuist share` остаются без изменений.

См. раздел <.localized_link href="/guides/features/previews#run-a-preview">Запуск превью</.localized_link> для информации о запуске опубликованных сборок, доступе, треках и бейджах README.

## Превью Apple

Для поддерживаемых превью симулятора Apple и macOS см. <.localized_link href="/guides/features/previews/run/macos">инструкции по сопутствующему приложению Tuist для macOS</.localized_link>. Приложения для физических устройств по-прежнему не поддерживаются для публикации через Struo.
