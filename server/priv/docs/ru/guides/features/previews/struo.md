# Предпросмотры Struo {#struo-previews}

<a id="once-previews"></a>

[Struo](https://struo.run/docs/guide/infrastructure/tuist#publish-application-previews) может публиковать артефакты приложений в Tuist, чтобы коллеги могли опробовать сборку без её локальной пересборки. Используйте [Struo 1.0.0](https://github.com/tuist/struo/releases/tag/1.0.0) или более позднюю версию и сервер Tuist с приёмником артефактов.

## Настройте назначение

Выполните шаги из <.localized_link href="/guides/get-started/struo-project">Начало работы со Struo</.localized_link>, затем добавьте привязку артефактов в файл `struo.toml` рабочего пространства. Повторно используйте провайдер, если он уже настроен для кэширования:

```toml
[infrastructures.tuist]
kind = "tuist"
account = "acme"
project = "app"

[infrastructure.artifacts]
name = "tuist"
```

```bash
struo auth login --provider tuist
struo artifact publish MyApplication --track review
```

Приёмник сохраняет полный набор, манифесты участников и полезные нагрузки, включая неизвестные интерфейсы. Поддерживаемые нативные интерфейсы асинхронно проецируются в предпросмотры с использованием настроек видимости, доступа и распространения проекта по умолчанию. Содержимое обычных артефактов остаётся приватным, даже в публичных проектах. Квитанция подтверждает хранение артефакта, а не завершение обработки предпросмотра; её URL открывает список предпросмотров проекта.

## Поддерживаемые приложения

Проекция Apple принимает метаданные `dev.struo.apple-install.v2` для приложений macOS и симулятора, подписанных ad-hoc и экспортированных на macOS. Приложения для физических устройств не поддерживаются. Проекция Android принимает метаданные `dev.struo.android-install.v1` с проверенной подписью. Struo одобряет автоматическую публикацию только для APK, подписанных отладочным ключом и не являющихся инструментарием. Неизвестные интерфейсы остаются доступными для скачивания как артефакты без создания предпросмотров. Ссылки на установку Android сохраняют имя файла `.apk`, хотя полезные нагрузки хранятся под хешами содержимого.

## Включите публикацию после сборок

```toml
[infrastructure]
publish_on_build = ["MyApplication"]
```

```bash
struo artifact publish MyApplication --allow-on-build
struo build MyApplication
```

Все запрошенные сборки должны успешно завершиться. Автоматическая публикация также требует одобрения производителем всего замыкания и локальной авторизации для этой машины, рабочего пространства, точной конечной точки, цели и стабильного назначения проекта Tuist. Без политики или авторизации сетевые запросы на публикацию артефактов не выполняются. Обычные сборки Struo остаются без неявных побочных эффектов публикации.

Повторное выполнение той же сохранённой публикации проверяет удалённую квитанцию и избегает повторной загрузки. Это отличается от поведения дублирования сборок в `tuist share`.

## Хранение

Публикации артефактов истекают через 30 дней на размещённом Tuist. Самостоятельно размещённые экземпляры используют `TUIST_APP_PREVIEW_RETENTION_DAYS`; если переменная не установлена, срок действия для этого семейства отключён. Истёкшие записи остаются как надгробия и не могут быть реактивированы повторным выполнением того же намерения. Существующие рабочие процессы подписи, видимости и распространения `tuist share` остаются неизменными.

См. <.localized_link href="/guides/features/previews#run-a-preview">Запуск предпросмотра</.localized_link> для информации о запуске опубликованных сборок, доступе, треках и бейджах README.

Для поддерживаемых предпросмотров симулятора Apple и macOS см. <.localized_link href="/guides/features/previews/run/macos">инструкции по приложению-компаньону Tuist для macOS</.localized_link>. Приложения для физических устройств по-прежнему не поддерживаются для публикации через Struo.
