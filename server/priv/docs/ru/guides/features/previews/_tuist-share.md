## Треки с tuist share {#share-tracks}

Для рабочих процессов, которые публикуются с помощью `tuist share`, используйте `--track` для выбора трека:

```bash
tuist share App --track beta
tuist share App --track nightly
```

## Примечания к релизу {#release-notes}

Используйте треки для групп окружений и примечания к релизу для отдельной сборки:

```bash
tuist share App --track QA --release-notes "Fix sign-in and improve the checkout flow"
```

Замените `App` на имя вашего приложения, путь к файлу приложения или исполняемую дистрибуцию и её опцию `--executable`. Примечания к релизу — это необязательный текст в формате plain text длиной до 10 000 символов. Первая непустая строка отображается как однострочный фрагмент в списках превью, поэтому номера сборок и другая идентифицирующая информация видны сразу. Длинные строки обрезаются; полные примечания отображаются на страницах с деталями. Поиск сопоставляет отображаемые имена и полные примечания к релизу, включая строки, не показанные во фрагменте. Поддерживаются многострочные примечания, например `--release-notes "$(< release-notes.txt)"`. Они не изменяют отображаемое имя приложения или его трек.

### Совместимость {#preview-metadata-compatibility}

Примечания к релизу не меняют принадлежность сборки к превью. Сохраняются первые примечания, полученные превью: последующая загрузка может добавить примечания к превью, у которого их нет, но не может перезаписать или очистить существующие. Превью, загруженные до появления примечаний к релизу, остаются действительными без них.

Развёртывания на собственных серверах требуют версию сервера, поддерживающую примечания к релизу и фильтрацию по трекам, а также обновлённый клиент. Старые серверы игнорируют примечания. Информацию о фильтрах треков и поиска для конечных точек списков см. в [справочнике API](https://tuist.dev/api/docs).

## Комментарии к pull/merge-запросам {#pullmerge-request-comments}

> [!WARNING]
> **Требуется интеграция с Git-форжем**
>
> Чтобы получать автоматические комментарии к pull/merge-запросам, интегрируйте ваш <.localized_link href="/guides/server/accounts-and-projects">удалённый проект</.localized_link> с <.localized_link href="/guides/integrations/gitforge/github">Git-форжем</.localized_link>.

После подключения вашего проекта Tuist к вашей Git-платформе добавьте <.localized_link href="/cli/share">`tuist share`</.localized_link> после успешной сборки приложения в CI. Tuist опубликует ссылку на превью прямо в ваших pull/merge-запросах, чтобы ревьюеры могли тестировать без локальной сборки:

## Автоматизации {#automations}

Используйте `--json`, чтобы получить JSON-вывод от `tuist share`:

```bash
tuist share --json
```

Используйте результат для пользовательских автоматизаций, например для отправки сообщения в Slack из CI. Ключ `url` содержит полную ссылку на превью; `qrCodeURL` указывает на изображение QR-кода для открытия превью на устройстве:

```json
{
  "id": 1234567890,
  "url": "https://tuist.dev/preview/1234567890",
  "qrCodeURL": "https://tuist.dev/preview/1234567890/qr-code.svg"
}
```
