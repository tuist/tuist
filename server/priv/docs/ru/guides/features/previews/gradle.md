# Превью Gradle

Собирайте и делитесь Android-приложениями и нативными утилитами командной строки прямо из Gradle. Начните с <.localized_link href="/guides/get-started/gradle-project">руководства по проекту Gradle</.localized_link>, чтобы подключить проект и пройти аутентификацию.

## Android-приложения

```bash
./gradlew :app:tuistShareDebug
```

Плагин настроек `dev.tuist` регистрирует задачу `tuistShare<Variant>` для каждого варианта приложения из Android Gradle Plugin (версии 8.8.2 или новее). Замените `app` и `Debug` на ваш модуль приложения и вариант, например `:app:tuistShareDemoDebug` для продуктового флейвора. Задача собирает APK через объявленные в Gradle зависимости артефактов перед его публикацией. Она также работает, когда выходные данные сборки актуальны или восстановлены из кэша сборки.

Поддерживается только один подписанный универсальный APK приложения. Вариант отладки в Android обычно использует ключ отладочной подписи; для релизных вариантов нужна ваша собственная конфигурация подписи. Задача проверяет подпись APK перед аутентификацией или загрузкой. Неподписанные, недействительные, инструментальные и разделённые APK отклоняются. Библиотечные модули, тестовые APK и пакеты Android App Bundle (`.aab`) не являются целями публикации.

## Нативные утилиты командной строки

Проекты, использующие плагин Gradle `cpp-application` или `swift-application`, получают задачу обмена для каждого нативного бинарного файла:

```bash
./gradlew :app:tuistShareMainDebug
```

Задача собирает и упаковывает установленную дистрибуцию, включая её лаунчер и библиотеки времени выполнения. Используйте `tuistShareMainRelease` для релизного бинарного файла. В проектах, ориентированных на несколько машин, есть отдельная задача для каждого бинарного файла; выполните `./gradlew :app:tasks --all`, чтобы узнать их имена.

Поддерживаются нативные исполняемые файлы macOS и Linux для архитектур arm64 или x86_64. Выполняйте сборку на целевой платформе с набором инструментов, требуемым вашим плагином Gradle. JVM-приложения и создаваемые для них скрипты запуска не поддерживаются этой интеграцией.

## Поведение при публикации

Задачи обмена публикуют данные, используя существующие учётные данные Tuist плагина, без вызова CLI Tuist. Обычные задачи `assemble`, `build` и тестирования никогда не публикуют превью.

После обмена откройте раздел **Previews** в вашем проекте, чтобы скопировать ссылку. Повторный обмен той же сборкой и треком повторно использует её публикацию, в том числе после попадания в кэш сборки. Неудачные или неподтверждённые загрузки приводят к сбою задачи обмена; они не отображаются как успешные превью.

## CI и треки

Настройте <.localized_link href="/guides/integrations/continuous-integration">аутентификацию в CI</.localized_link>, используя те же учётные данные, что и для других аутентифицированных возможностей плагина, затем явно запросите публикацию:

```bash
./gradlew :app:tuistShareDebug --track nightly
```

Добавьте `--track nightly` к задаче обмена нативным бинарным файлом аналогичным образом. Задачи используют настроенный проект Tuist, URL сервера и параметры прокси. Публикация превью всегда требует аутентификации. Метаданные ревизии Git, примечания к выпуску и автоматические комментарии к pull-запросам этими задачами не добавляются.

Публикации артефактов истекают через 30 дней на хостинге Tuist. В самостоятельно размещённых экземплярах используется переменная `TUIST_APP_PREVIEW_RETENTION_DAYS`; если она не установлена, срок действия для этого семейства отключён. Истёкшие публикации нельзя восстановить, повторив ту же операцию.

## Поделиться существующим APK

Для APK, собранного вне этого рабочего процесса, или чтобы добавить примечания к выпуску при использовании устаревшего потока загрузки, доступен CLI:

```bash
tuist share app/build/outputs/apk/debug/app-debug.apk \
  --track nightly --release-notes "Improve checkout"
```

См. <.localized_link href="/guides/features/previews#run-a-preview">Запуск превью</.localized_link> для информации о запуске опубликованных сборок, доступе, треках и бейджах для README.
