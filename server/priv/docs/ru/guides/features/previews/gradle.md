# Превью Gradle

Собирайте и делитесь приложениями для Android и нативными консольными утилитами напрямую из Gradle. Начните с <.localized_link href="/guides/get-started/gradle-project">руководства по проекту Gradle</.localized_link>, чтобы подключить проект и пройти аутентификацию.

## Приложения для Android

```bash
./gradlew :app:tuistShareDebug
```

Плагин настроек `dev.tuist` регистрирует задачу `tuistShare<Variant>` для каждого варианта сборки приложения из Android Gradle Plugin (версии 8.8.2 или новее). Замените `app` и `Debug` на ваш модуль приложения и вариант, например `:app:tuistShareDemoDebug` для продуктового флейвора. Задача собирает APK через объявленные в Gradle зависимости артефактов перед его публикацией. Она также работает, когда выходные данные сборки актуальны или восстановлены из кэша сборки.

Поддерживается только один подписанный универсальный APK приложения. Вариант отладки в Android обычно использует ключ отладочной подписи; для релизных вариантов нужна ваша собственная конфигурация подписи. Задача проверяет подпись APK перед аутентификацией или загрузкой. Неподписанные, недействительные APK, APK для инструментационных тестов и разделенные APK отклоняются. Библиотечные модули, тестовые APK и пакеты приложений Android (`.aab`) не являются целями публикации.

## Нативные консольные утилиты

Проекты, использующие плагин Gradle `cpp-application` или `swift-application`, получают задачу шеринга для каждого нативного бинарного файла:

```bash
./gradlew :app:tuistShareMainDebug
```

Задача собирает и упаковывает установленную дистрибуцию, включая её лаунчер и библиотеки времени выполнения. Используйте `tuistShareMainRelease` для релизного бинарного файла. В проектах, ориентированных на несколько машин, есть задача для каждого бинарного файла; выполните `./gradlew :app:tasks --all`, чтобы найти их имена.

Поддерживаются нативные исполняемые файлы macOS и Linux для arm64 или x86_64. Выполняйте сборку на целевой платформе с использованием тулчейна, требуемого вашим плагином Gradle. JVM-приложения и генерируемые ими скрипты запуска не поддерживаются этой интеграцией.

## Поведение при публикации

Задачи шеринга публикуют материалы, используя существующие учетные данные Tuist плагина, без вызова CLI Tuist. Обычные задачи `assemble`, `build` и тестирования никогда не публикуют превью.

После шеринга откройте **Превью** в вашем проекте, чтобы скопировать ссылку. Повторный шеринг той же сборки и трека повторно использует её публикацию, в том числе после попадания в кэш сборки. Неудачные или неподтвержденные загрузки приводят к сбою задачи шеринга; они не отображаются как успешные превью.

## CI и треки

Настройте <.localized_link href="/guides/integrations/continuous-integration">аутентификацию CI</.localized_link> с теми же учетными данными, которые вы используете для других аутентифицированных функций плагина, затем явно запросите публикацию:

```bash
./gradlew :app:tuistShareDebug --track nightly
```

Добавьте `--track nightly` к задаче шеринга нативного кода аналогичным образом. Задачи используют настроенный проект Tuist, URL сервера и настройки прокси. Публикация превью всегда требует аутентификации. Метаданные ревизии Git, примечания к выпуску и автоматические комментарии к пул-реквестам не прикрепляются этими задачами.

Публикации артефактов истекают через 30 дней на хостинге Tuist. Самостоятельно размещаемые экземпляры используют `TUIST_APP_PREVIEW_RETENTION_DAYS`; если оставить его неустановленным, истечение срока действия для этого семейства отключается. Истекшие публикации нельзя восстановить, повторив ту же операцию.

## Поделиться существующим APK

Для APK, собранного вне этого рабочего процесса, или для включения примечаний к выпуску через устаревший поток загрузки, CLI остается доступным:

```bash
tuist share app/build/outputs/apk/debug/app-debug.apk \
  --track nightly --release-notes "Improve checkout"
```

См. <.localized_link href="/guides/features/previews#run-a-preview">Запуск превью</.localized_link> для информации о запуске опубликованных сборок, доступе, треках и бейджах для README.
