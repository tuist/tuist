# Поддерживаемые типы превью

Тип превью определяет, что именно упаковывается и где может выполняться приложение, независимо от системы сборки, которая его создала. Каждый рабочий процесс публикации имеет собственные требования к подписи и условиям допуска.

## Мобильные приложения {#mobile-apps}

- **Android:** подписанный APK-файл приложения. Получателям потребуется совместимое Android-устройство или эмулятор. Пакеты Android App Bundles (`.aab`) не являются пакетами для установки превью.
- **Apple:** пакет приложения для симулятора или экспортированный IPA-файл для физических устройств. Для сборок под устройство необходим профиль обеспечения (provisioning profile), разрешающий установку на устройство получателя.

Руководства по <.localized_link href="/guides/features/previews/xcode">Xcode</.localized_link>, <.localized_link href="/guides/features/previews/gradle">Gradle</.localized_link> и <.localized_link href="/guides/features/previews/bazel">Bazel</.localized_link> описывают, какие артефакты может публиковать каждый рабочий процесс. Например, публикация через Bazel и Once поддерживает подходящие приложения для симуляторов Apple и macOS, но не сборки для физических устройств.

## Настольные приложения {#desktop-apps}

Поделитесь собранным пакетом приложения macOS:

```bash
tuist share path/to/MyApp.app
```

Требования к подписи и нотариализации по-прежнему применяются. Пакет настольного приложения отличается от приложения Tuist для macOS, которое получатели могут использовать для запуска превью.

## Инструменты командной строки {#command-line-tools}

Поделитесь автономным исполняемым файлом на macOS или Linux:

```bash
tuist share path/to/my-tool
```

Если инструменту CLI требуются пакеты ресурсов, динамические библиотеки или вспомогательные исполняемые файлы, соберите директорию дистрибутива и укажите точку входа относительно этой директории:

```bash
tuist share path/to/distribution --executable bin/my-tool
```

Загружается вся директория дистрибутива. Включите библиотеки, ресурсы и вспомогательные файлы, необходимые вашему инструменту, и убедитесь, что он может работать вне директории сборки. Скриптам требуются shebang и интерпретатор, установленные в системе получателя.

## Несколько целей CLI {#multiple-cli-targets}

Превью объединяет сборки одного и того же CLI для одного коммита; каждая сборка содержит дистрибутив для одной операционной системы и одной или нескольких архитектур ЦПУ. Например, одно превью может содержать дистрибутивы для macOS arm64, macOS x86_64 и Linux x86_64. Универсальный исполняемый файл macOS покрывает обе архитектуры Mac в одной сборке.

Соберите каждую цель отдельно, затем публикуйте дистрибутивы последовательно из одного и того же рабочего каталога Git, используя одно и то же базовое имя точки входа и трек:

```bash
tuist share dist/macos-arm64 --executable bin/tuist --track pr
tuist share dist/macos-x86_64 --executable bin/tuist --track pr
tuist share dist/linux-x86_64 --executable bin/tuist --track pr
```

Эти загрузки добавляют сборки к одной и той же ссылке превью. Убедитесь, что проект, коммит, учетная запись публикации, имя CLI и трек идентичны во всех загрузках. Tuist выбирает сборку, соответствующую операционной системе и архитектуре ЦПУ получателя.

## Совместимость клиента и сервера {#client-and-server-compatibility}

Используйте актуальную версию CLI Tuist для запуска превью настольных приложений и инструментов командной строки. Если вы размещаете Tuist самостоятельно, обновите сервер перед публикацией этих типов. Превью для мобильных устройств продолжают работать со старыми версиями клиентов.

Выполняйте сборку под операционные системы и архитектуры ЦПУ ваших получателей. Tuist не выполняет кросс-компиляцию вашего приложения и не устанавливает его зависимости; инструментам для Linux также требуются совместимые системные библиотеки.

Превью выполняются с правами вашей пользовательской учетной записи, а не в песочнице. Запускайте только те сборки, авторам и пул-реквестам которых вы доверяете.
