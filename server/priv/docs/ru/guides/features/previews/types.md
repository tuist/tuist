# Поддерживаемые типы превью

Тип превью определяет, что именно вы упаковываете и где это может запускаться, независимо от системы сборки, которая его создает. Каждый рабочий процесс публикации имеет собственные требования к подписи и условиям допуска.

## Мобильные приложения {#mobile-apps}

- **Android:** подписанный APK-файл приложения. Получателям потребуется совместимое Android-устройство или эмулятор. Пакеты Android App Bundles (`.aab`) не являются пакетами для установки превью.
- **Apple:** пакет приложения для симулятора или экспортированный IPA-файл для физических устройств. Для сборок под устройства необходим профиль обеспечения, разрешающий установку на устройство получателя.

Руководства по <.localized_link href="/guides/features/previews/xcode">Xcode</.localized_link>, <.localized_link href="/guides/features/previews/gradle">Gradle</.localized_link> и <.localized_link href="/guides/features/previews/bazel">Bazel</.localized_link> описывают, какие артефакты может публиковать каждый рабочий процесс. Например, публикация через Bazel и Once поддерживает подходящие приложения для симуляторов Apple и macOS, но не сборки для физических устройств.

## Десктопные приложения {#desktop-apps}

Поделитесь собранным пакетом приложения macOS:

```bash
tuist share path/to/MyApp.app
```

Требования к подписи и нотариализации по-прежнему применяются. Пакет десктопного приложения отличается от приложения Tuist для macOS, которое получатели могут использовать для запуска превью.

## Инструменты командной строки {#command-line-tools}

Поделитесь автономным исполняемым файлом на macOS или Linux:

```bash
tuist share path/to/my-tool
```

Если инструменту CLI требуются пакеты ресурсов, динамические библиотеки или вспомогательные исполняемые файлы, соберите директорию дистрибутива и укажите точку входа относительно этой директории:

```bash
tuist share path/to/distribution --executable bin/my-tool
```

Загружается вся директория дистрибутива. Включите библиотеки, ресурсы и вспомогательные файлы, необходимые вашему инструменту, и убедитесь, что он может работать вне вашей директории сборки. Скриптам требуется shebang и установленный интерпретатор в системе получателя.

## Несколько целей CLI {#multiple-cli-targets}

Превью группирует сборки одного и того же CLI для одного коммита; каждая сборка содержит дистрибутив для одной операционной системы и одной или нескольких архитектур CPU. Например, одно превью может содержать дистрибутивы для macOS arm64, macOS x86_64 и Linux x86_64. Универсальный исполняемый файл macOS покрывает обе архитектуры Mac в одной сборке.

Соберите каждую цель отдельно, затем публикуйте дистрибутивы последовательно из одного и того же рабочего каталога Git, используя одно и то же базовое имя точки входа и трек:

```bash
tuist share dist/macos-arm64 --executable bin/tuist --track pr
tuist share dist/macos-x86_64 --executable bin/tuist --track pr
tuist share dist/linux-x86_64 --executable bin/tuist --track pr
```

Эти загрузки добавляют сборки к одной и той же ссылке на превью. Сохраняйте идентичными проект, коммит, учетную запись публикации, имя CLI и трек во всех загрузках. Tuist выбирает сборку, соответствующую операционной системе и архитектуре CPU получателя.

## Совместимость клиента и сервера {#client-and-server-compatibility}

Используйте актуальную версию Tuist CLI для запуска десктопных превью и превью инструментов командной строки. Если вы самостоятельно размещаете Tuist, обновите свой сервер перед публикацией этих типов. Мобильные превью продолжают работать со старыми версиями клиентов.

Выполняйте сборку для операционных систем и архитектур CPU ваших получателей. Tuist не выполняет кросс-компиляцию вашего приложения и не устанавливает его зависимости; инструментам для Linux также требуются совместимые системные библиотеки.

Превью запускаются с правами вашей пользовательской учетной записи, а не в песочнице. Запускайте только те сборки, авторам и pull-запросам которых вы доверяете.
