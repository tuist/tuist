# Кэш {#cache}

Артефакты сборки не разделяются между окружениями, из-за чего приходится многократно пересобирать один и тот же код. Функция кэширования Tuist позволяет удалённо обмениваться артефактами, чтобы ваша команда и CI получали более быстрые сборки без повторной компиляции уже готового. О том, как работают локальные и удалённые кэши сборок в разных системах сборки и что представляют собой собственные кэши Xcode, читайте в <.localized_link href="/references/concepts/build-cache">Что такое кэш сборки?</.localized_link>. Чтобы понять причины медленных сборок перед выбором кэша, см. [Медленные сборки](https://tuist.dev/solutions/slow-builds).

> [!TIP]
> **Максимальная скорость на Tuist Runners**
>
> На <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link> кэш расположен в частной сети раннера и использует тот же кэш, что и машины разработчиков, поэтому задачи CI сразу получают «тёплые» попадания без необходимости отдельного прогрева кэша для CI.


## Ограничить загрузку только для CI {#restrict-uploads-to-ci}

Администраторы аккаунта могут сделать доступ разработчиков только для чтения, разрешив CI загружать артефакты кэша. Откройте настройки **Кэш** аккаунта в Tuist и установите **Доступ на загрузку в кэш** в значение **Только CI и токены аккаунта**. После этого участники, аутентифицированные через сеансы входа, всё ещё смогут скачивать данные из кэша, но для загрузки потребуется OIDC-аутентификация CI или токен аккаунта с правами на запись в кэш, например `project:cache:write` или `ci`.

Используйте эту настройку, когда CI является доверенным источником кэша, а локальные машины должны только потреблять кэш. Настройка влияет только на авторизацию загрузки в кэш.
