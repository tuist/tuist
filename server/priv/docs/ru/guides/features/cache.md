# Кэш {#cache}

Артефакты сборки не передаются между окружениями, из-за чего приходится многократно пересобирать один и тот же код. Функция кэширования Tuist обменивается артефактами удалённо, чтобы ваша команда и CI получали более быстрые сборки без повторной компиляции уже собранного. О том, как работают локальные и удалённые кэши сборок в разных системах сборки и что представляют собой собственные кэши Xcode, см. <.localized_link href="/references/concepts/build-cache">Что такое кэш сборки?</.localized_link>. Чтобы понять причины медленных сборок до выбора кэша, см. [Медленные сборки](https://tuist.dev/solutions/slow-builds).

> [!TIP]
> **Максимальная скорость на Tuist Runners**
>
> На <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link> кэш расположен в частной сети раннера и использует тот же кэш, что и машины разработчиков, поэтому задачи CI сразу получают «тёплые» попадания без необходимости отдельно прогревать кэш CI.


## Ограничить загрузку только для CI {#restrict-uploads-to-ci}

Администраторы аккаунта могут предоставить разработчикам доступ только для чтения, разрешив CI загружать артефакты кэша. Откройте настройки **Кэш** аккаунта в Tuist и установите для параметра **Доступ на загрузку в кэш** значение **Только CI и токены аккаунта**. После этого участники, аутентифицированные через сеансы входа, по-прежнему смогут скачивать данные из кэша, но для загрузки потребуется аутентификация CI через OIDC или токен аккаунта с правами на запись в кэш, например `project:cache:write` или `ci`.

Используйте этот режим, когда CI выступает доверенным источником кэша, а локальные машины должны только потреблять кэш. Настройка влияет только на авторизацию загрузки в кэш.
