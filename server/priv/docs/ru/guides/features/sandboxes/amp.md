# Amp {#amp}

> [!IMPORTANT]
> **Только по приглашениям**
>
> Песочницы Tuist для Linux и macOS сейчас доступны только по приглашениям. [Напишите нам](mailto:contact@tuist.dev) или обратитесь в [Slack‑сообществе](https://slack.tuist.dev), чтобы запросить доступ для вашего аккаунта.

[Amp](https://ampcode.com) запускает инструменты каждого потока в [орбе](https://ampcode.com/docs/orbs) — машине с клонированным репозиторием потока. Tuist может стать [собственным провайдером орбов](https://ampcode.com/docs/orbs/self-hosted) для вашего рабочего пространства Amp: каждый поток, который его выбирает, работает в собственной <.localized_link href="/guides/features/sandboxes">песочнице</.localized_link> Tuist на Linux или macOS. Вам не нужно ничего запускать или хостить самостоятельно.

## Подключить Amp {#connect}

Вы должны быть администратором как рабочего пространства Amp, так и аккаунта Tuist.

1. В Amp откройте **Settings → Orbs** рабочего пространства, нажмите **Add Orb Provider** и задайте имя, например `tuist`. Участники выбирают провайдера по этому имени. Скопируйте токен `aop_live_…`; Amp показывает его только один раз.
2. В диалоге **Edit** провайдера в Amp добавьте эти **Orb types** и выберите значение по умолчанию:

   | Тип | Платформа | Конфигурация |
   | --- | --- | --- |
   | `linux` | Linux | 2 vCPU, 4 GiB RAM, 10 GB workspace |
   | `macos` | macOS with Xcode | 8 vCPU, 8 GiB RAM, 10 GB workspace |

3. В Tuist откройте **Sandboxes** в панели управления аккаунтом, нажмите **Connect** на карточке Amp и вставьте токен.

Карточка покажет **Connected**, когда Tuist начнёт обслуживать провайдера. Один аккаунт Tuist обслуживает одного провайдера. Любой, кто может использовать провайдера в Amp, запускает орбы от имени подключённого аккаунта Tuist, и расходы списываются с него. Чтобы остановить, нажмите **Disconnect** на карточке или отключите провайдера в Amp.

## Запустить поток {#start-a-thread}

В интерфейсе создания нового потока в Amp нажмите **Orb**, выберите провайдера Tuist в разделе **Self-Hosted** и укажите `linux` или `macos`. Из CLI Amp:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos
```

Поток сохраняет тип орба на протяжении всей жизни. Если тип не указан, используется значение по умолчанию провайдера. Чтобы для каждого нового потока использовать одну платформу, выберите провайдера и его тип в разделе **Default Orb** в **Settings → Orbs** Amp.

Amp клонирует репозиторий, запускает ваш скрипт `.agents/setup` и настраивает учётные данные Git, как это делается для любого орба. Каждый орб также может читать <.localized_link href="/guides/features/cache">кэш</.localized_link> Tuist вашего аккаунта.

## Приостановка и хранение {#retention}

Когда поток переходит в режим ожидания, Amp приостанавливает его орб. Следующее сообщение возобновляет работу с сохранением файлов.

- **Linux:** Запущенные процессы сохраняются при паузе. Орб, который долго находился в паузе, перемещается в архивное хранилище и восстанавливается при следующем сообщении без своих процессов. Орбы Linux хранят файлы до тех пор, пока Amp не удалит орб потока.
- **macOS:** Орб, находящийся в паузе или в состоянии ошибки в течение 7 дней, удаляется. Следующее сообщение потока создаёт новый орб, и Amp снова запускает `.agents/setup`. Первый орб macOS на машине устанавливает CLI Amp, поэтому запуск может занять до двух минут.

Орб, который остаётся в режиме ожидания без приостановки со стороны Amp (например, потому что сигнал паузы не поступил), приостанавливается через десять минут практически без использования CPU.
