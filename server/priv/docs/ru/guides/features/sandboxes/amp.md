# Amp {#amp}

> [!IMPORTANT]
> **Только по приглашениям**
>
> Песочницы Tuist, как для Linux, так и для macOS, сейчас доступны только по приглашениям. [Свяжитесь с нами](mailto:contact@tuist.dev) или напишите нам в [Slack-сообществе](https://slack.tuist.dev), чтобы запросить доступ для вашего аккаунта.

[Amp](https://ampcode.com) запускает инструменты каждого потока в [орбе](https://ampcode.com/docs/orbs) — машине с клонированным репозиторием потока. Tuist может выступать в роли [собственного провайдера орбов](https://ampcode.com/docs/orbs/self-hosted) для вашего рабочего пространства Amp: каждый поток, который его выбирает, работает в собственной <.localized_link href="/guides/features/sandboxes">песочнице</.localized_link> Tuist на Linux или macOS. Вам не нужно самостоятельно запускать или размещать что-либо.

Чтобы ваши потоки оставались на текущих орбах и собирали, тестировали и запускали код для платформ Apple только на Mac, используйте вместо этого [плагин Tuist Mac](#remote-mac).

## Подключение Amp {#connect}

Вы должны быть администратором как рабочего пространства Amp, так и аккаунта Tuist.

1. В Amp откройте раздел **Settings → Orbs** вашего рабочего пространства, нажмите **Add Orb Provider** и задайте имя, например `tuist`. Участники выбирают провайдера по этому имени. Скопируйте токен `aop_live_…`; Amp показывает его только один раз.
2. В диалоге **Edit** провайдера в Amp добавьте **типы орбов**, которые хотите предложить, и выберите тип по умолчанию. Типы Linux соответствуют размерам [собственных орбов Amp](https://ampcode.com/docs/orbs/sizes-and-costs):

   | Тип | Платформа | Конфигурация |
   | --- | --- | --- |
   | `linux` | Linux | 4 vCPU, 8 GiB RAM, 10 GB рабочего пространства |
   | `linux-tiny` | Linux | 1 vCPU, 2 GiB RAM, 10 GB рабочего пространства |
   | `linux-small` | Linux | 2 vCPU, 4 GiB RAM, 10 GB рабочего пространства |
   | `linux-medium` | Linux | 4 vCPU, 8 GiB RAM, 10 GB рабочего пространства (то же, что `linux`) |
   | `linux-large` | Linux | 8 vCPU, 16 GiB RAM, 10 GB рабочего пространства |
   | `linux-xxlarge` | Linux | 16 vCPU, 32 GiB RAM, 10 GB рабочего пространства |
   | `linux-3xlarge` | Linux | 16 vCPU, 44 GiB RAM, 10 GB рабочего пространства |
   | `macos` | macOS с Xcode по умолчанию | 8 vCPU, 8 GiB RAM, 10 GB рабочего пространства |
   | `macos-xcode-<version>` | macOS с указанной версией Xcode, например `macos-xcode-26-1-1` для Xcode 26.1.1 | 8 vCPU, 8 GiB RAM, 10 GB рабочего пространства |

3. В Tuist откройте раздел **Sandboxes** в панели управления вашего аккаунта, нажмите **Connect** на карточке Amp и вставьте токен.

На карточке появится статус **Connected**, когда Tuist начнет обслуживать провайдера. Один аккаунт Tuist обслуживает одного провайдера. Любой пользователь, который может использовать провайдера в Amp, запускает орбы от имени подключенного аккаунта Tuist, и расходы списываются с него. Чтобы остановить, нажмите **Disconnect** на карточке или отключите провайдера в Amp.

## Запуск потока {#start-a-thread}

В интерфейсе создания нового потока в Amp нажмите **Orb**, выберите провайдера Tuist в разделе **Self-Hosted** и укажите тип, например `linux-small` для репозитория, которому требуется меньше ресурсов, чем `linux`, или `linux-large` для того, которому нужно больше. Из CLI Amp:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos
```

Поток сохраняет свой тип орба на протяжении всего жизненного цикла. Если тип не указан, используется тип по умолчанию провайдера. Чтобы использовать один тип для всех новых потоков, выберите провайдера и его тип в разделе **Default Orb** настроек Amp **Settings → Orbs**.

### Выбор версии Xcode {#xcode}

`macos` использует <.localized_link href="/guides/features/sandboxes#xcode">Xcode</.localized_link> по умолчанию. Чтобы выбрать другую версию, добавьте тип орба, названный в её честь, заменив точки дефисами: `macos-xcode-26-1-1` запускает Xcode 26.1.1, `macos-xcode-27-0` — Xcode 27.0. Добавьте тип для каждой версии Xcode, закрепленной в ваших репозиториях, и выбирайте его для каждого потока, как любой другой тип:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos-xcode-26-1-1
```

Тип для версии Xcode, которую Tuist не предоставляет, завершится ошибкой при запуске нового орба. Орб, уже запущенный на такой версии, продолжит работу даже после того, как Tuist перестанет предоставлять эту версию Xcode.

Amp клонирует репозиторий, выполняет ваш скрипт `.agents/setup` и настраивает учетные данные Git, как это делается для любого орба. Каждый орб также может читать <.localized_link href="/guides/features/cache">кэш</.localized_link> Tuist вашего аккаунта.

## Приостановка и хранение {#retention}

Когда поток переходит в режим ожидания, Amp приостанавливает его орб. Следующее сообщение возобновляет работу с сохранением всех файлов.

- **Linux:** Запущенные процессы сохраняются при приостановке. Орб, который долго находился в приостановленном состоянии, перемещается в архивное хранилище и восстанавливается при следующем сообщении, но без процессов. Орбы Linux хранят файлы до тех пор, пока Amp не удалит орб потока.
- **macOS:** Орб, находящийся в приостановленном состоянии или в состоянии ошибки в течение 7 дней, удаляется. Следующее сообщение потока запускает новый орб, и Amp снова выполняет `.agents/setup`. Первый орб macOS на машине устанавливает CLI Amp, поэтому запуск может занять до двух минут.

Орб, который остается в режиме ожидания без приостановки со стороны Amp (например, если сигнал приостановки не поступил), приостанавливается через десять минут с почти нулевым использованием ЦП.

## Использование Mac из любого потока Amp {#remote-mac}

Плагин Tuist Mac предоставляет потоку Amp песочницу macOS с Xcode, симуляторами iOS и Homebrew, пока поток продолжает работать там, где он запущен, например на одном из собственных орбов Linux в Amp. Попросите Amp выполнить задачу, и он запустит Mac, когда это потребуется:

> Добавь переключатель темного режима на экран настроек, запусти приложение в симуляторе iOS и покажи мне скриншот.

Amp продолжает редактировать код там, где он выполняется. Перед каждой командой на Mac плагин запускает `tuist sandbox sync`, который копирует файлы, не игнорируемые Git (закоммиченные или нет), а впоследствии — только измененные. Артефакты сборки и другие игнорируемые файлы, созданные на Mac, остаются там, поэтому сборки остаются инкрементальными. Плагин добавляет эти инструменты и навык `remote-mac`, который сообщает Amp, когда и как их использовать:

| Инструмент | Что делает |
| --- | --- |
| `tuist_mac_start` | Создает Mac для потока или повторно использует существующий и синхронизирует файлы |
| `tuist_mac_shell` | Синхронизирует файлы, затем выполняет команду на Mac |
| `tuist_mac_screenshot` | Показывает симулятор или экран в потоке |
| `tuist_mac_download` | Копирует файл обратно, например собранный `.app` |
| `tuist_mac_stop` | Удаляет Mac потока |

На Mac нет собственного CLI Tuist: после первой синхронизации Amp выполняет `mise install` в корне репозитория, чтобы установить закрепленную версию Tuist проекта, а `tuist_mac_shell` добавляет shim-скрипты mise в `PATH`. Каждая команда на Mac самостоятельно <.localized_link href="/guides/features/sandboxes#tuist-in-sandbox">авторизуется для доступа к кэшу вашего аккаунта</.localized_link> с помощью Tuist 4.218.0 или новее; в версиях с 4.215.0 по 4.217.x Amp сначала выполняет `tuist auth login`.

Поток использует один Mac. Amp передает `tuist_mac_start` версию <.localized_link href="/guides/features/sandboxes#xcode">Xcode</.localized_link>, закрепленную в репозитории (например, в `.xcode-version`), или вы можете запросить конкретную версию («используй Xcode 26.1.1»); если версия не указана, Mac использует версию по умолчанию. Mac сохраняет свою версию Xcode, поэтому переключение означает остановку текущего Mac и запуск другого. Tuist приостанавливает его в режиме ожидания, а следующая команда возобновляет работу. Amp удаляет Mac после завершения задачи; оставленный без дела Mac удаляется после 14 дней приостановки. Mac учитываются в вашем аккаунте Tuist так же, как и любые другие песочницы.

### Настройка {#remote-mac-setup}

1. **Установите плагин.** Это один файл: [`tuist-mac.ts`](https://github.com/tuist/tuist/blob/main/.amp/plugins/tuist-mac.ts). Чтобы сделать его доступным для всех в вашем рабочем пространстве Amp, администратор рабочего пространства просит Amp в потоке:

   > Добавь https://raw.githubusercontent.com/tuist/tuist/main/.amp/plugins/tuist-mac.ts в плагины нашего рабочего пространства.

   Amp фиксирует его в [репозитории плагинов](https://ampcode.com/docs/customize/global-plugins-and-skills) рабочего пространства и запрашивает подтверждение перед отправкой. Вместо этого попросите «мои личные плагины», чтобы установить его только для себя, или сохраните файл как `.amp/plugins/tuist-mac.ts` в репозитории, чтобы использовать его только там. Плагин является копией: чтобы обновить его, попросите Amp заменить его последней версией по тому же URL.
2. **Установите CLI Tuist** там, где работает Amp. На орбах добавьте его в скрипт репозитория [`.agents/setup`](https://ampcode.com/docs/orbs/customizing), например `mise use -g tuist@latest`, или `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist`.
3. **Разрешите CLI использовать песочницы вашего аккаунта.** На орбах подключите рабочее пространство Amp к вашему аккаунту Tuist, как описано в разделе <.localized_link href="/guides/server/authentication#amp-orbs">орбы Amp</.localized_link>. Затем орбы самостоятельно авторизуются и получают доступ к песочницам. В других местах, например при использовании CLI Amp на машине Linux, выполните `tuist auth login` от имени участника аккаунта или установите `TUIST_MAC_TOKEN` в значение <.localized_link href="/guides/server/authentication#account-tokens">токена аккаунта</.localized_link> с областью действия `account:sandboxes:write`, а также добавьте `ci`, чтобы Mac мог использовать кэш. Плагин передает `TUIST_MAC_TOKEN` в CLI вместо `TUIST_TOKEN`, поэтому установите его также, если ваши орбы уже имеют `TUIST_TOKEN` без этой области действия.
4. **Укажите, какой аккаунт использовать**, если в репозитории нет `tuist.toml` с `project = "<account>/<project>"`. В Linux CLI не может прочитать аккаунт из `Tuist.swift`. Установите `TUIST_MAC_ACCOUNT` в значение хэндла вашего аккаунта в переменных окружения проекта Amp. Без этого Amp передает аккаунт из `Tuist.swift` через `fullHandle` в `tuist_mac_start`.

CLI достигает Mac только через `tuist.dev`, поэтому среда с ограниченным сетевым доступом должна разрешать только этот домен. Чтобы использовать CLI, которого нет в `PATH`, установите `TUIST_MAC_CLI` в путь к нему.

Агенты, которые не поддерживают плагины Amp, такие как Claude Code или Cursor, могут делать то же самое через сервер Tuist MCP и CLI, как описано в разделе <.localized_link href="/guides/features/sandboxes#coding-agents">Сборка на Mac из агента для написания кода</.localized_link>.

### Использование Mac от Tuist вместо спутников macOS от Amp {#remote-mac-satellites}

У Amp также есть собственные облачные Mac, [спутники macOS](https://ampcode.com/docs/orbs/mac), которые находятся в бета-версии для рабочих пространств, присоединившихся к списку ожидания. Когда поток может запустить оба варианта, встроенные инструкции Amp направляют задачи macOS на свои спутники, поэтому плагин выбирается редко. Чтобы потоки использовали Mac от Tuist, выполните одно из следующих действий:

- **Отключите спутники macOS для себя.** Каждый участник отключает их в разделе **Mac Satellites** настроек Amp [Settings → Experimental Features](https://ampcode.com/settings/experimental-features).
- **Отключите их для рабочего пространства.** Когда орбы вашего рабочего пространства [работают на Tuist](#connect), администратор рабочего пространства может установить параметр **Where Orbs Run** в значение **Self-Hosted Only** в настройках рабочего пространства Amp в разделе **Orbs**. Тогда агенты не смогут запускать спутники, размещенные Amp, но участники также не смогут использовать встроенные орбы Amp, поэтому делайте это только тогда, когда все ваши потоки работают на ваших собственных провайдерах орбов.
- **Запрашивайте Mac от Tuist.** Добавьте «Используй инструменты `tuist_mac_*` для задач macOS, а не спутники macOS.» в подсказку или в рекомендации для агентов в настройках рабочего пространства Amp, чтобы каждый поток следовал этому правилу.
