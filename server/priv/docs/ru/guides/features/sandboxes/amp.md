# Amp {#amp}

> [!IMPORTANT]
> **Только по приглашениям**
>
> Песочницы Tuist, как для Linux, так и для macOS, сейчас доступны только по приглашениям. [Свяжитесь с нами](mailto:contact@tuist.dev) или напишите нам в [Slack-сообществе](https://slack.tuist.dev), чтобы запросить доступ для вашей учётной записи.

[Amp](https://ampcode.com) запускает инструменты каждого потока в [орбе](https://ampcode.com/docs/orbs) — машине с клонированным репозиторием потока. Tuist может стать [собственным провайдером орбов](https://ampcode.com/docs/orbs/self-hosted) для вашего рабочего пространства Amp: каждый поток, который его выбирает, работает в собственной <.localized_link href="/guides/features/sandboxes">песочнице</.localized_link> Tuist на Linux или macOS. Вам не нужно ничего запускать или хостить самостоятельно.

Чтобы потоки оставались на своих текущих орбах и собирали, тестировали и запускали код для платформ Apple только на Mac, используйте вместо этого [плагин Tuist Mac](#remote-mac).

## Подключение Amp {#connect}

Вы должны быть администратором как рабочего пространства Amp, так и учётной записи Tuist.

1. В Amp откройте **Settings → Orbs** вашего рабочего пространства, нажмите **Add Orb Provider** и задайте имя, например `tuist`. Участники выбирают провайдера по этому имени. Скопируйте токен `aop_live_…`; Amp показывает его только один раз.
2. В диалоге **Edit** провайдера в Amp добавьте **типы орбов**, которые хотите предложить, и выберите тип по умолчанию. Типы Linux соответствуют размерам [собственных орбов Amp](https://ampcode.com/docs/orbs/sizes-and-costs):

   | Тип | Платформа | Конфигурация |
   | --- | --- | --- |
   | `linux` | Linux | 4 vCPU, 8 GiB RAM, рабочее пространство 10 ГБ |
   | `linux-tiny` | Linux | 1 vCPU, 2 GiB RAM, рабочее пространство 10 ГБ |
   | `linux-small` | Linux | 2 vCPU, 4 GiB RAM, рабочее пространство 10 ГБ |
   | `linux-medium` | Linux | 4 vCPU, 8 GiB RAM, рабочее пространство 10 ГБ (то же, что `linux`) |
   | `linux-large` | Linux | 8 vCPU, 16 GiB RAM, рабочее пространство 10 ГБ |
   | `linux-xxlarge` | Linux | 16 vCPU, 32 GiB RAM, рабочее пространство 10 ГБ |
   | `linux-3xlarge` | Linux | 16 vCPU, 44 GiB RAM, рабочее пространство 10 ГБ |
   | `macos` | macOS с Xcode по умолчанию | 8 vCPU, 8 GiB RAM, рабочее пространство 30 ГБ |
   | `macos-xcode-<version>` | macOS с указанной версией Xcode, например `macos-xcode-26-1-1` для Xcode 26.1.1 | 8 vCPU, 8 GiB RAM, рабочее пространство 30 ГБ |

3. В Tuist откройте раздел **Sandboxes** в панели управления вашей учётной записи, нажмите **Connect** на карточке Amp и вставьте токен.

На карточке отобразится **Connected**, когда Tuist начнёт обслуживать провайдера. Одна учётная запись Tuist обслуживает одного провайдера. Любой, кто может использовать провайдера в Amp, запускает орбы от имени подключённой учётной записи Tuist, и расходы списываются с неё. Чтобы остановить, нажмите **Disconnect** на карточке или отключите провайдера в Amp.

## Запуск потока {#start-a-thread}

В редакторе нового потока Amp нажмите **Orb**, выберите провайдера Tuist в разделе **Self-Hosted** и укажите тип, например `linux-small` для репозитория, которому требуется меньше ресурсов, чем `linux`, или `linux-large` для более требовательного. Из CLI Amp:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos
```

Поток сохраняет тип орба на всём протяжении жизни. Без указания типа используется тип по умолчанию провайдера. Чтобы использовать один тип для всех новых потоков, выберите провайдера и его тип в разделе **Default Orb** настроек Amp **Settings → Orbs**.

### Выбор версии Xcode {#xcode}

`macos` запускает <.localized_link href="/guides/features/sandboxes#xcode">Xcode</.localized_link> по умолчанию. Для другой версии добавьте тип орба с её именем, заменив точки на дефисы: `macos-xcode-26-1-1` запускает Xcode 26.1.1, `macos-xcode-27-0` — Xcode 27.0. Добавьте тип для каждой версии Xcode, закреплённой в ваших репозиториях, и выбирайте его для каждого потока, как любой другой тип:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos-xcode-26-1-1
```

Тип для версии Xcode, которую Tuist не предоставляет, приведёт к ошибке при запуске нового орба. Орб, уже запущенный на такой версии, продолжит работу даже после того, как Tuist перестанет предоставлять эту версию Xcode.

Amp клонирует репозиторий, запускает ваш скрипт `.agents/setup` и настраивает учётные данные Git, как для любого орба. Каждый орб также может читать <.localized_link href="/guides/features/cache">кэш</.localized_link> Tuist вашей учётной записи.

## Приостановка и хранение {#retention}

Когда поток переходит в режим простоя, Amp приостанавливает его орб. Следующее сообщение возобновляет работу с сохранением всех файлов.

- **Linux:** Запущенные процессы сохраняются при приостановке. Орб, находящийся в приостановленном состоянии длительное время, перемещается в архивное хранилище и восстанавливается при следующем сообщении, но без процессов. Орбы Linux хранят файлы до тех пор, пока Amp не удалит орб потока.
- **macOS:** Орб, находящийся в приостановленном состоянии или в состоянии ошибки в течение 7 дней, удаляется. Следующее сообщение потока запускает новый орб, и Amp повторно выполняет `.agents/setup`. Первый орб macOS на машине устанавливает CLI Amp, поэтому запуск может занять до двух минут.

Орб, остающийся в режиме простоя без приостановки со стороны Amp (например, если сигнал приостановки не поступил), приостанавливается через десять минут практически без использования ЦП.

## Использование Mac из любого потока Amp {#remote-mac}

Плагин Tuist Mac предоставляет потоку Amp песочницу macOS с Xcode, симуляторами iOS и Homebrew, при этом поток продолжает выполняться там, где он запущен, например на одном из собственных Linux-орбов Amp. Попросите Amp выполнить задачу, и он запустит Mac, когда это потребуется:

> Добавь переключатель тёмного режима на экран настроек, запусти приложение в симуляторе iOS и покажи скриншот.

Amp продолжает редактировать код там, где он выполняется. Перед каждой командой на Mac плагин запускает `tuist sandbox sync`, который копирует файлы, не игнорируемые Git (закоммиченные или нет), а впоследствии — только изменённые. Артефакты сборки и другие игнорируемые файлы, созданные на Mac, остаются там, поэтому сборки остаются инкрементальными. Плагин добавляет эти инструменты и навык `remote-mac`, который сообщает Amp, когда и как их использовать:

| Инструмент | Что делает |
| --- | --- |
| `tuist_mac_start` | Создаёт Mac для потока или повторно использует существующий и выполняет синхронизацию |
| `tuist_mac_shell` | Выполняет синхронизацию, затем запускает команду на Mac |
| `tuist_mac_screenshot` | Показывает симулятор или экран в потоке |
| `tuist_mac_download` | Копирует файл обратно, например собранный `.app` |
| `tuist_mac_stop` | Удаляет Mac потока |

На Mac нет собственного CLI Tuist: после первой синхронизации Amp запускает `mise install` в корне репозитория, чтобы установить закреплённую версию Tuist проекта, а `tuist_mac_shell` добавляет shim’ы mise в `PATH`. Каждая команда на Mac самостоятельно <.localized_link href="/guides/features/sandboxes#tuist-in-sandbox">авторизуется в кэше вашей учётной записи</.localized_link> с помощью Tuist 4.218.0 или новее; для версий 4.215.0–4.217.x Amp сначала запускает `tuist auth login`.

Поток использует один Mac. Amp передаёт в `tuist_mac_start` версию <.localized_link href="/guides/features/sandboxes#xcode">Xcode</.localized_link>, закреплённую в репозитории (например, в `.xcode-version`), или вы можете запросить конкретную («используй Xcode 26.1.1»); без указания версии Mac использует версию по умолчанию. Mac сохраняет свою версию Xcode, поэтому переключение означает остановку текущего и запуск другого. Tuist приостанавливает его в режиме простоя, а следующая команда возобновляет работу. Amp удаляет Mac после завершения задачи; оставленный без внимания Mac удаляется после 14 дней приостановки. Mac учитываются в лимитах вашей учётной записи Tuist так же, как и другие песочницы.

### Настройка {#remote-mac-setup}

1. **Установите плагин.** Это один файл: [`tuist-mac.ts`](https://github.com/tuist/tuist/blob/main/.amp/plugins/tuist-mac.ts). Чтобы сделать его доступным для всех участников рабочего пространства Amp, администратор просит Amp в потоке:

   > Добавь https://raw.githubusercontent.com/tuist/tuist/main/.amp/plugins/tuist-mac.ts в плагины нашего рабочего пространства.

   Amp фиксирует его в [репозитории плагинов](https://ampcode.com/docs/customize/global-plugins-and-skills) рабочего пространства и запрашивает подтверждение перед отправкой. Чтобы установить плагин только для себя, попросите «my personal plugins» или сохраните файл как `.amp/plugins/tuist-mac.ts` в репозитории для использования только там. Плагин является копией: для обновления попросите Amp заменить его последней версией по тому же URL.
2. **Установите CLI Tuist** там, где выполняется Amp. На орбах добавьте его в скрипт репозитория [`.agents/setup`](https://ampcode.com/docs/orbs/customizing), например `mise use -g tuist@latest`, или `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist`.
3. **Разрешите CLI использовать песочницы вашей учётной записи.** На орбах подключите рабочее пространство Amp к вашей учётной записи Tuist, как описано в разделе <.localized_link href="/guides/server/authentication#amp-orbs">Amp orbs</.localized_link>. После этого орбы авторизуются самостоятельно и получают доступ к песочницам. В других местах, например при использовании CLI Amp на машине Linux, выполните `tuist auth login` от имени участника учётной записи или установите для `TUIST_MAC_TOKEN` значение <.localized_link href="/guides/server/authentication#account-tokens">токена учётной записи</.localized_link> с областью действия `account:sandboxes:write`, а также добавьте `ci`, чтобы Mac мог использовать кэш. Плагин передаёт в CLI `TUIST_MAC_TOKEN` вместо `TUIST_TOKEN`, поэтому установите его также, если у ваших орбов уже есть `TUIST_TOKEN` без этой области действия.
4. **Укажите, какую учётную запись использовать**, если в репозитории нет `tuist.toml` с `project = "<account>/<project>"`. В Linux CLI не может прочитать учётную запись из `Tuist.swift`. Установите для `TUIST_MAC_ACCOUNT` значение хэндла вашей учётной записи в переменных окружения проекта Amp. Без этого Amp передаёт учётную запись из `Tuist.swift` (`fullHandle`) в `tuist_mac_start`.

CLI обращается к Mac только через `tuist.dev`, поэтому среда с ограниченным сетевым доступом должна разрешать только этот домен. Чтобы использовать CLI, которого нет в `PATH`, установите для `TUIST_MAC_CLI` путь к нему.

Агенты, не поддерживающие плагины Amp, такие как Claude Code или Cursor, могут делать то же самое через сервер Tuist MCP и CLI, как описано в разделе <.localized_link href="/guides/features/sandboxes#coding-agents">Сборка на Mac от агента для написания кода</.localized_link>.

### Использование Tuist Mac вместо macOS Satellites от Amp {#remote-mac-satellites}

У Amp также есть собственные облачные Mac, [macOS Satellites](https://ampcode.com/docs/orbs/mac), доступные в бета-версии для рабочих пространств, добавленных в лист ожидания. Когда поток может запустить оба варианта, встроенные инструкции Amp направляют задачи macOS на свои спутники, поэтому плагин выбирается редко. Чтобы потоки использовали Tuist Macs, выполните одно из следующих действий:

- **Отключите macOS Satellites для себя.** Каждый участник отключает их в разделе **Mac Satellites** настроек Amp [Settings → Experimental Features](https://ampcode.com/settings/experimental-features).
- **Отключите их для рабочего пространства.** Когда орбы вашего рабочего пространства [работают на Tuist](#connect), администратор может установить параметр **Where Orbs Run** в значение **Self-Hosted Only** в настройках рабочего пространства Amp в разделе **Orbs**. После этого агенты не смогут запускать спутники, размещённые Amp, но участники также не смогут использовать встроенные орбы Amp, поэтому применяйте эту настройку только если все ваши потоки работают на ваших собственных провайдерах орбов.
- **Запрашивайте Tuist Macs.** Добавьте в подсказку или в рекомендации для агентов в настройках рабочего пространства Amp фразу «Use the `tuist_mac_*` tools for macOS work, not macOS Satellites.», чтобы каждый поток следовал ей.
