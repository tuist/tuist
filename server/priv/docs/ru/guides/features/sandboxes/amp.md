# Amp {#amp}

> [!IMPORTANT]
> **Только по приглашениям**
>
> Песочницы Tuist, как для Linux, так и для macOS, сейчас доступны только по приглашениям. [Свяжитесь с нами](mailto:contact@tuist.dev) или напишите нам в [Slack-сообществе](https://slack.tuist.dev), чтобы запросить доступ для вашего аккаунта.

[Amp](https://ampcode.com) запускает инструменты каждого потока в [орбе](https://ampcode.com/docs/orbs) — машине с клонированным репозиторием потока. Tuist может стать [собственным провайдером орбов](https://ampcode.com/docs/orbs/self-hosted) для вашего рабочего пространства Amp: каждый поток, который его выбирает, работает в собственной <.localized_link href="/guides/features/sandboxes">песочнице</.localized_link> Tuist на Linux или macOS. Вам не нужно самостоятельно запускать или хостить что-либо.

Чтобы ваши потоки оставались на своих текущих орбах и собирали, тестировали и запускали код для платформ Apple только на Mac, используйте вместо этого [плагин Tuist Mac](#remote-mac).

## Подключение Amp {#connect}

Вы должны быть администратором как рабочего пространства Amp, так и аккаунта Tuist.

1. В Amp откройте **Settings → Orbs** вашего рабочего пространства, нажмите **Add Orb Provider** и задайте имя, например `tuist`. Участники выбирают провайдера по этому имени. Скопируйте токен `aop_live_…`; Amp показывает его только один раз.
2. В диалоге **Edit** провайдера в Amp добавьте **типы орбов**, которые хотите предлагать, и выберите тип по умолчанию. Типы Linux соответствуют памяти [собственных орбов Amp](https://ampcode.com/docs/orbs/sizes-and-costs). Каждому гарантируется четверть виртуального ядра на гигабайт памяти, а при наличии свободных ядер на машине он может кратковременно использовать до 16 виртуальных ядер (см. <.localized_link href="/guides/features/sandboxes#guaranteed-cpu">Гарантированные CPU</.localized_link>):

   | Тип | Конфигурация |
   | --- | --- |
   | `linux` | Linux, 8 ГБ ОЗУ, 2 гарантированных виртуальных ядра |
   | `linux-tiny` | Linux, 2 ГБ ОЗУ, 0,5 гарантированного виртуального ядра |
   | `linux-small` | Linux, 4 ГБ ОЗУ, 1 гарантированное виртуальное ядро |
   | `linux-medium` | То же, что и `linux` |
   | `linux-large` | Linux, 16 ГБ ОЗУ, 4 гарантированных виртуальных ядра |
   | `linux-xxlarge` | Linux, 32 ГБ ОЗУ, 8 гарантированных виртуальных ядер |
   | `linux-3xlarge` | Linux, 44 ГБ ОЗУ, 11 гарантированных виртуальных ядер |
   | `macos` | macOS с Xcode по умолчанию, 8 виртуальных ядер, 8 ГБ ОЗУ |
   | `macos-xcode-<version>` | macOS с этим [Xcode](#xcode), 8 виртуальных ядер, 8 ГБ ОЗУ |

   Для типов Linux рабочее пространство составляет 10 ГБ, для типов macOS — 30 ГБ.

3. В Tuist откройте **Sandboxes** на панели управления вашего аккаунта, нажмите **Connect** на карточке Amp и вставьте токен.

На карточке появится статус **Connected**, когда Tuist начнёт обслуживать провайдера. Один аккаунт Tuist обслуживает одного провайдера. Любой, кто может использовать провайдера в Amp, запускает орбы от имени подключённого аккаунта Tuist, и расходы списываются с него. Чтобы остановить, нажмите **Disconnect** на карточке или отключите провайдера в Amp.

## Запуск потока {#start-a-thread}

В редакторе нового потока Amp нажмите **Orb**, выберите провайдера Tuist в разделе **Self-Hosted** и укажите тип, например `linux-small`, если репозиторию нужно меньше ресурсов, чем `linux`, или `linux-large`, если нужно больше. Из CLI Amp:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos
```

Поток сохраняет свой тип орба на протяжении всей жизни. Если тип не указан, используется тип по умолчанию провайдера. Чтобы для каждого нового потока использовался один тип, выберите провайдера и его тип в разделе **Default Orb** настроек Amp **Settings → Orbs**.

### Выбор Xcode {#xcode}

`macos` запускает <.localized_link href="/guides/features/sandboxes#xcode">Xcode</.localized_link> по умолчанию. Чтобы использовать другой, добавьте тип орба, названный в его честь, заменив точки на дефисы: `macos-xcode-26-1-1` запускает Xcode 26.1.1, `macos-xcode-27-0` — Xcode 27.0. Добавьте тип для каждой версии Xcode, которую фиксируют ваши репозитории, и выбирайте его для каждого потока, как любой другой тип:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos-xcode-26-1-1
```

Тип для версии Xcode, которую Tuist не предлагает, завершается ошибкой при запуске нового орба. Орб, уже запущенный на такой версии, продолжает возобновлять работу даже после того, как Tuist перестаёт предлагать эту версию Xcode.

Amp клонирует репозиторий, запускает ваш скрипт `.agents/setup` и настраивает учётные данные Git, как для любого орба. Каждый орб также может читать <.localized_link href="/guides/features/cache">кэш</.localized_link> Tuist вашего аккаунта.

## Приостановка и хранение {#retention}

Когда поток переходит в режим ожидания, Amp приостанавливает его орб. Следующее сообщение возобновляет работу орба с сохранением всех файлов.

- **Linux:** Выполняемые процессы сохраняются при приостановке. Орб, который долго находился в приостановленном состоянии, перемещается в архивное хранилище и восстанавливается при следующем сообщении, но без своих процессов. Орбы Linux хранят файлы до тех пор, пока Amp не удалит орб потока.
- **macOS:** Орб, находящийся в приостановленном состоянии или в состоянии ошибки в течение 7 дней, удаляется. Следующее сообщение потока запускает новый орб, и Amp снова выполняет `.agents/setup`. Первый орб macOS на машине устанавливает CLI Amp, поэтому его запуск может занять до двух минут.

Орб, который остаётся в режиме ожидания без приостановки со стороны Amp, например потому что сигнал приостановки не поступил, приостанавливается через десять минут с почти нулевым использованием CPU.

## Использование Mac из любого потока Amp {#remote-mac}

Плагин Tuist Mac предоставляет потоку Amp песочницу macOS с Xcode, симуляторами iOS и Homebrew, пока поток продолжает работать там, где он был запущен, например на одном из собственных орбов Linux Amp. Попросите Amp выполнить задачу, и он запустит Mac, когда это потребуется:

> Добавь переключатель тёмного режима на экран настроек, запусти приложение в симуляторе iOS и покажи скриншот.

Amp продолжает редактировать код там, где он выполняется. Перед каждой командой на Mac плагин запускает `tuist sandbox sync`, который копирует файлы, не игнорируемые Git, независимо от того, закоммичены они или нет, а затем только те, что изменились. Артефакты сборки и другие игнорируемые файлы, созданные на Mac, остаются там, поэтому сборки остаются инкрементальными. Плагин добавляет эти инструменты и навык `remote-mac`, который сообщает Amp, когда и как их использовать:

| Инструмент | Что делает |
| --- | --- |
| `tuist_mac_start` | Создаёт Mac для потока или повторно использует существующий и синхронизирует файлы |
| `tuist_mac_shell` | Синхронизирует файлы, затем выполняет команду на Mac |
| `tuist_mac_screenshot` | Показывает симулятор или экран в потоке |
| `tuist_mac_download` | Копирует файл обратно, например собранный `.app` |
| `tuist_mac_stop` | Удаляет Mac потока |

На Mac установлен CLI Tuist, и он запускает версию проекта, если она закреплена через mise; `tuist_mac_shell` добавляет shims mise в начало `PATH`. Каждая команда на Mac <.localized_link href="/guides/features/sandboxes#tuist-in-sandbox">авторизуется в кэше вашего аккаунта</.localized_link> самостоятельно при использовании Tuist 4.218.0 или новее; с версиями от 4.215.0 до 4.217.x Amp сначала выполняет `tuist auth login`.

Поток использует один Mac. Amp передаёт в `tuist_mac_start` ту версию <.localized_link href="/guides/features/sandboxes#xcode">Xcode</.localized_link>, которая закреплена в репозитории, например в `.xcode-version`, или вы можете запросить конкретную версию («используй Xcode 26.1.1»); без указания версии Mac использует стандартную. Mac сохраняет установленный Xcode, поэтому переключение означает остановку текущего Mac и запуск другого. Tuist приостанавливает его в режиме ожидания, а следующая команда возобновляет работу. Amp удаляет Mac после завершения задачи; оставленный без присмотра Mac удаляется после 14 дней в приостановленном состоянии. Mac учитываются в квотах вашего аккаунта Tuist так же, как и другие песочницы.

### Настройка {#remote-mac-setup}

1. **Установите плагин.** Это один файл: [`tuist-mac.ts`](https://github.com/tuist/tuist/blob/main/.amp/plugins/tuist-mac.ts). Чтобы сделать его доступным для всех участников рабочего пространства Amp, администратор рабочего пространства запрашивает у Amp в потоке:

   > Добавь https://raw.githubusercontent.com/tuist/tuist/main/.amp/plugins/tuist-mac.ts в плагины нашего рабочего пространства.

   Amp фиксирует файл в [репозитории плагинов](https://ampcode.com/docs/customize/global-plugins-and-skills) рабочего пространства и запрашивает подтверждение перед отправкой. Вместо этого можно запросить «мои личные плагины», чтобы установить его только для себя, или сохранить файл как `.amp/plugins/tuist-mac.ts` в репозитории, чтобы использовать его только там. Плагин является копией: для обновления попросите Amp заменить его последней версией по тому же URL.
2. **Установите CLI Tuist** там, где работает Amp. На орбах добавьте его в скрипт репозитория [`.agents/setup`](https://ampcode.com/docs/orbs/customizing), например `mise use -g tuist@latest`, или `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist`.
3. **Разрешите CLI использовать песочницы вашего аккаунта.** На орбах подключите рабочее пространство Amp к вашему аккаунту Tuist, как описано в разделе <.localized_link href="/guides/server/authentication#amp-orbs">Орбы Amp</.localized_link>. После этого орбы авторизуются самостоятельно и получают доступ к песочницам. В других случаях, например при использовании CLI Amp на машине Linux, выполните `tuist auth login` от имени участника аккаунта или установите `TUIST_MAC_TOKEN` в значение <.localized_link href="/guides/server/authentication#account-tokens">токена аккаунта</.localized_link> с областью доступа `account:sandboxes:write`, а также добавьте `ci`, чтобы Mac мог использовать кэш. Плагин передаёт в CLI `TUIST_MAC_TOKEN` вместо `TUIST_TOKEN`, поэтому установите его, даже если ваши орбы уже имеют `TUIST_TOKEN` без этой области доступа.
4. **Укажите, какой аккаунт использовать**, если в репозитории нет файла `tuist.toml` с параметром `project = "<account>/<project>"`. В Linux CLI не может прочитать аккаунт из `Tuist.swift`. Установите `TUIST_MAC_ACCOUNT` в значение хэндла вашего аккаунта в переменных окружения проекта Amp. Без этого Amp передаёт аккаунт из поля `fullHandle` файла `Tuist.swift` в `tuist_mac_start`.

CLI обращается к Mac только через `tuist.dev`, поэтому среда с ограниченным сетевым доступом должна разрешать только этот домен. Чтобы использовать CLI, который не находится в `PATH`, установите `TUIST_MAC_CLI` в путь к нему.

Агенты, не поддерживающие плагины Amp, такие как Claude Code или Cursor, могут делать то же самое через сервер Tuist MCP и CLI, как описано в разделе <.localized_link href="/guides/features/sandboxes#coding-agents">Сборка на Mac от агента кодирования</.localized_link>.

### Использование Mac Tuist вместо macOS Satellites от Amp {#remote-mac-satellites}

У Amp также есть собственные облачные Mac, [macOS Satellites](https://ampcode.com/docs/orbs/mac), доступные в бета-версии для рабочих пространств, добавленных в лист ожидания. Когда поток может запустить оба варианта, встроенные инструкции Amp направляют задачи macOS на свои спутники, поэтому плагин выбирается редко. Чтобы потоки использовали Mac Tuist, выполните одно из следующих действий:

- **Отключите macOS Satellites для себя.** Каждый участник отключает их в разделе **Mac Satellites** настроек Amp [Settings → Experimental Features](https://ampcode.com/settings/experimental-features).
- **Отключите их для рабочего пространства.** Когда орбы вашего рабочего пространства [работают на Tuist](#connect), администратор рабочего пространства может установить параметр **Where Orbs Run** в значение **Self-Hosted Only** в настройках рабочего пространства Amp в разделе **Orbs**. После этого агенты не смогут запускать спутники, размещённые Amp, но участники также не смогут использовать встроенные орбы Amp, поэтому делайте это только тогда, когда все ваши потоки работают на ваших собственных провайдерах орбов.
- **Запрашивайте Mac Tuist.** Добавьте в подсказку или в рекомендации для агентов рабочего пространства в настройках Amp фразу «Используй инструменты `tuist_mac_*` для задач macOS, а не macOS Satellites», чтобы каждый поток следовал этому правилу.
