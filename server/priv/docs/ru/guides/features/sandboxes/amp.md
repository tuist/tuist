# Amp {#amp}

> [!IMPORTANT]
> **Только по приглашению**
>
> Песочницы Tuist для Linux и macOS сейчас доступны только по приглашению. [Напишите нам](mailto:contact@tuist.dev) или свяжитесь с нами в [Slack-сообществе](https://slack.tuist.dev), чтобы запросить доступ для вашего аккаунта.

[Amp](https://ampcode.com) запускает инструменты каждого потока в [орбе](https://ampcode.com/docs/orbs) — машине, на которой клонирован репозиторий потока. Tuist может стать [провайдером собственных орбов](https://ampcode.com/docs/orbs/self-hosted) для вашего рабочего пространства Amp: каждый поток, который его выбирает, работает в собственной <.localized_link href="/guides/features/sandboxes">песочнице</.localized_link> Tuist на Linux или macOS. Вам не нужно ничего запускать или хостить самостоятельно.

Чтобы потоки оставались на текущих орбах и собирали, тестировали и запускали код для платформ Apple только на Mac, используйте вместо этого [плагин Tuist Mac](#remote-mac).

## Подключить Amp {#connect}

Вы должны быть администратором как рабочего пространства Amp, так и аккаунта Tuist.

1. В Amp откройте **Settings → Orbs** вашего рабочего пространства, нажмите **Add Orb Provider** и задайте имя, например `tuist`. Участники выбирают провайдера по этому имени. Скопируйте токен `aop_live_…`; Amp показывает его только один раз.
2. В диалоге **Edit** провайдера в Amp добавьте **типы орбов**, которые хотите предложить, и выберите тип по умолчанию. Типы Linux соответствуют памяти [собственных орбов Amp](https://ampcode.com/docs/orbs/sizes-and-costs). Каждому гарантируется четверть виртуального ядра на гигабайт памяти, а при наличии свободных ядер на машине он может кратковременно использовать до 16 vCPU (см. <.localized_link href="/guides/features/sandboxes#guaranteed-cpu">Гарантированное процессорное время</.localized_link>):

   | Тип | Конфигурация |
   | --- | --- |
   | `linux` | Linux, 8 ГБ ОЗУ, 2 гарантированных vCPU |
   | `linux-tiny` | Linux, 2 ГБ ОЗУ, 0.5 гарантированного vCPU |
   | `linux-small` | Linux, 4 ГБ ОЗУ, 1 гарантированный vCPU |
   | `linux-medium` | Как у `linux` |
   | `linux-large` | Linux, 16 ГБ ОЗУ, 4 гарантированных vCPU |
   | `linux-xxlarge` | Linux, 32 ГБ ОЗУ, 8 гарантированных vCPUs |
   | `linux-3xlarge` | Linux, 44 ГБ ОЗУ, 11 гарантированных vCPU |
   | `macos` | macOS с Xcode по умолчанию, 8 vCPU, 8 ГБ ОЗУ |
   | `macos-xcode-<version>` | macOS с этим [Xcode](#xcode), 8 vCPU, 8 ГБ ОЗУ |

   Для типов Linux рабочее пространство составляет 10 ГБ, для типов macOS — 30 ГБ.

3. В Tuist откройте **Sandboxes** в панели управления вашего аккаунта, нажмите **Connect** на карточке Amp и вставьте токен.

На карточке появится статус **Connected**, когда Tuist начнёт обслуживать провайдера. Один аккаунт Tuist обслуживает одного провайдера. Любой, кто может использовать провайдера в Amp, запускает орбы от имени подключённого аккаунта Tuist, и расходы списываются с него. Чтобы остановить, нажмите **Disconnect** на карточке или отключите провайдера в Amp.

## Запустить поток {#start-a-thread}

В редакторе нового потока Amp нажмите **Orb**, выберите провайдера Tuist в разделе **Self-Hosted** и укажите тип, например `linux-small`, если репозиторию нужно меньше ресурсов, чем `linux`, или `linux-large`, если нужно больше. Из CLI Amp:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos
```

Поток сохраняет свой тип орба на протяжении всей жизни. Если тип не указан, используется тип по умолчанию провайдера. Чтобы для каждого нового потока использовался один и тот же тип, выберите провайдера и его тип в разделе **Default Orb** настроек Amp **Settings → Orbs**.

### Выбрать Xcode {#xcode}

`macos` запускает <.localized_link href="/guides/features/sandboxes#xcode">Xcode</.localized_link> по умолчанию. Чтобы использовать другой, добавьте тип орба, названный в его честь, заменив точки дефисами: `macos-xcode-26-1-1` запустит Xcode 26.1.1, `macos-xcode-27-0` — Xcode 27.0. Добавьте тип для каждого Xcode, который закрепляют ваши репозитории, и выбирайте его для потока так же, как любой другой тип:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos-xcode-26-1-1
```

Если Tuist не предлагает тип для указанного Xcode, запуск нового орба завершится ошибкой. Орб, который уже был запущен с этим Xcode, продолжит работу даже после того, как Tuist перестанет предлагать эту версию.

Amp клонирует репозиторий, выполняет ваш скрипт `.agents/setup` и настраивает учётные данные Git, как для любого орба. Каждый орб также может читать <.localized_link href="/guides/features/cache">кэш</.localized_link> Tuist вашего аккаунта.

## Приостановка и хранение {#retention}

Когда поток переходит в режим ожидания, Amp приостанавливает его орб. Следующее сообщение возобновляет работу с сохранением всех файлов.

- **Linux:** Запущенные процессы сохраняются при приостановке. Орб, который долго находился в приостановленном состоянии, перемещается в архивное хранилище и восстанавливается при следующем сообщении, но без процессов. Орбы Linux хранят файлы до тех пор, пока Amp не удалит орб потока.
- **macOS:** Орб, находящийся в приостановленном состоянии или в состоянии ошибки в течение 7 дней, удаляется. Следующее сообщение потока создаёт новый орб, и Amp снова запускает `.agents/setup`. Первый орб macOS на машине устанавливает CLI Amp, поэтому запуск может занять до двух минут.

Орб, который остаётся в режиме ожидания без приостановки со стороны Amp (например, потому что сигнал паузы не поступил), приостанавливается через десять минут практически без использования CPU.

## Использовать Mac из любого потока Amp {#remote-mac}

Плагин Tuist Mac предоставляет потоку Amp песочницу macOS с Xcode, симуляторами iOS и Homebrew, пока поток продолжает работать там, где он был запущен, например на одном из собственных орбов Linux в Amp. Поручите задачу Amp, и он запустит Mac, когда это потребуется:

> Добавьте переключатель тёмного режима на экран настроек, запустите приложение в симуляторе iOS и покажите скриншот.

Amp продолжает редактировать код там, где он выполняется. Перед каждой командой на Mac плагин запускает `tuist sandbox sync`, который копирует файлы, не игнорируемые Git (как закоммиченные, так и нет), а затем только изменённые. Артефакты сборки и другие игнорируемые файлы, созданные на Mac, остаются там, поэтому сборки остаются инкрементальными. Плагин добавляет эти инструменты и навык `remote-mac`, который подсказывает Amp, когда и как их использовать:

| Инструмент | Что делает |
| --- | --- |
| `tuist_mac_start` | Создаёт Mac для потока или повторно использует существующий и выполняет синхронизацию |
| `tuist_mac_shell` | Выполняет синхронизацию, затем запускает команду на Mac |
| `tuist_mac_screenshot` | Показывает симулятор или экран в потоке |
| `tuist_mac_download` | Копирует файл обратно, например собранный `.app` |
| `tuist_mac_stop` | Удаляет Mac потока |

На Mac нет собственного CLI Tuist: после первой синхронизации Amp запускает `mise install` в корне репозитория, чтобы установить закреплённую версию Tuist проекта, а `tuist_mac_shell` добавляет shim-скрипты mise в `PATH`. Каждая команда на Mac самостоятельно <.localized_link href="/guides/features/sandboxes#tuist-in-sandbox">авторизуется в кэше вашего аккаунта</.localized_link> с помощью Tuist 4.218.0 или новее; для версий с 4.215.0 по 4.217.x Amp сначала запускает `tuist auth login`.

Поток использует один Mac. Amp передаёт в `tuist_mac_start` ту версию <.localized_link href="/guides/features/sandboxes#xcode">Xcode</.localized_link>, которая закреплена в репозитории (например, в `.xcode-version`), либо вы можете запросить конкретную версию («используй Xcode 26.1.1»); если версия не указана, Mac использует стандартную. Mac сохраняет установленный Xcode, поэтому переключение означает остановку текущего Mac и запуск другого. Tuist приостанавливает Mac в режиме ожидания, а следующая команда возобновляет его работу. Amp удаляет Mac после завершения задачи; оставленный без внимания Mac удаляется после 14 дней в приостановленном состоянии. Mac учитываются в лимитах вашего аккаунта Tuist так же, как и другие песочницы.

### Настройка {#remote-mac-setup}

1. **Установите плагин.** Это один файл: [`tuist-mac.ts`](https://github.com/tuist/tuist/blob/main/.amp/plugins/tuist-mac.ts). Чтобы сделать его доступным для всех участников рабочего пространства Amp, администратор рабочего пространства запрашивает у Amp в потоке:

   > Добавь https://raw.githubusercontent.com/tuist/tuist/main/.amp/plugins/tuist-mac.ts в плагины нашего рабочего пространства.

   Amp фиксирует его в [репозитории плагинов](https://ampcode.com/docs/customize/global-plugins-and-skills) рабочего пространства и запрашивает подтверждение перед отправкой. Вместо этого можно запросить «мои личные плагины», чтобы установить его только для себя, или сохранить файл как `.amp/plugins/tuist-mac.ts` в репозитории, чтобы использовать его только там. Плагин является копией: для обновления попросите Amp заменить его на последнюю версию по тому же URL.
2. **Установите CLI Tuist** там, где работает Amp. На орбах добавьте его в скрипт [`.agents/setup`](https://ampcode.com/docs/orbs/customizing) репозитория, например `mise use -g tuist@latest`, или `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist`.
3. **Разрешите CLI использовать песочницы вашего аккаунта.** На орбах подключите рабочее пространство Amp к вашему аккаунту Tuist, как описано в разделе <.localized_link href="/guides/server/authentication#amp-orbs">орбы Amp</.localized_link>. Тогда орбы будут самостоятельно авторизовываться с доступом к песочницам. В других случаях, например при использовании CLI Amp на машине Linux, выполните `tuist auth login` от имени участника аккаунта или установите для `TUIST_MAC_TOKEN` значение <.localized_link href="/guides/server/authentication#account-tokens">токена аккаунта</.localized_link> с областью действия `account:sandboxes:write`, а также добавьте `ci`, чтобы Mac мог использовать кэш. Плагин передаёт в CLI `TUIST_MAC_TOKEN` вместо `TUIST_TOKEN`, поэтому установите его и в том случае, когда ваши орбы уже имеют `TUIST_TOKEN` без этой области действия.
4. **Укажите, какой аккаунт использовать**, если в репозитории нет `tuist.toml` с `project = "<account>/<project>"`. В Linux CLI не может прочитать аккаунт из `Tuist.swift`. Установите для `TUIST_MAC_ACCOUNT` значение хендла вашего аккаунта в переменных окружения проекта Amp. Без этого Amp передаёт аккаунт из `Tuist.swift` через `fullHandle` в `tuist_mac_start`.

CLI обращается к Mac только через `tuist.dev`, поэтому в среде с ограниченным сетевым доступом необходимо разрешить только этот домен. Чтобы использовать CLI, который не находится в `PATH`, установите для `TUIST_MAC_CLI` путь к нему.

Агенты, не поддерживающие плагины Amp, такие как Claude Code или Cursor, могут делать то же самое через сервер Tuist MCP и CLI, как описано в разделе <.localized_link href="/guides/features/sandboxes#coding-agents">сборка на Mac из агента для написания кода</.localized_link>.

### Использовать Mac от Tuist вместо macOS Satellites от Amp {#remote-mac-satellites}

У Amp также есть собственные облачные Mac — [macOS Satellites](https://ampcode.com/docs/orbs/mac), которые находятся в бета-версии для рабочих пространств, добавленных в список ожидания. Когда поток может запустить оба варианта, встроенные инструкции Amp направляют задачи macOS на свои спутники, поэтому плагин выбирается редко. Чтобы потоки использовали Mac от Tuist, выполните одно из следующих действий:

- **Отключите macOS Satellites для себя.** Каждый участник отключает их в разделе **Mac Satellites** в настройках Amp [Settings → Experimental Features](https://ampcode.com/settings/experimental-features).
- **Отключите их для рабочего пространства.** Если орбы вашего рабочего пространства [работают на Tuist](#connect), администратор рабочего пространства может установить в настройках Amp для рабочего пространства, в разделе **Orbs**, параметр **Where Orbs Run** в значение **Self-Hosted Only**. Тогда агенты не смогут запускать спутники, размещённые Amp, но участники также не смогут использовать встроенные орбы Amp, поэтому делайте это только тогда, когда все ваши потоки работают на ваших собственных провайдерах орбов.
- **Запросите Mac от Tuist.** Добавьте в подсказку или в рекомендации для агентов рабочего пространства в настройках Amp фразу «Используй инструменты `tuist_mac_*` для задач macOS, а не macOS Satellites», чтобы каждый поток следовал этому правилу.
