# Amp {#amp}

> [!IMPORTANT]
> **Только по приглашению**
>
> Песочницы Tuist для Linux и macOS сейчас доступны только по приглашению. [Напишите нам](mailto:contact@tuist.dev) или обратитесь в [Slack-сообщество](https://slack.tuist.dev), чтобы запросить доступ для вашего аккаунта.

[Amp](https://ampcode.com) запускает инструменты каждого треда в [орбе](https://ampcode.com/docs/orbs) — машине, на которой клонирован репозиторий треда. Tuist может выступать [провайдером орбов с собственным хостингом](https://ampcode.com/docs/orbs/self-hosted) для вашего рабочего пространства Amp: каждый тред, который его выбирает, работает в собственной <.localized_link href="/guides/features/sandboxes">песочнице</.localized_link> Tuist на Linux или macOS. Вам не нужно самостоятельно запускать или хостить что-либо.

Чтобы оставить треды на текущих орбах и собирать, тестировать и запускать код для платформ Apple только на Mac, используйте вместо этого [плагин Tuist Mac](#remote-mac).

## Подключить Amp {#connect}

Вы должны быть администратором как рабочего пространства Amp, так и аккаунта Tuist.

1. В Amp откройте **Settings → Orbs** вашего рабочего пространства, нажмите **Add Orb Provider** и задайте имя, например `tuist`. Участники выбирают провайдера по этому имени. Скопируйте токен `aop_live_…`; Amp показывает его только один раз.
2. В диалоге **Edit** провайдера в Amp добавьте **типы орбов**, которые хотите предложить, и выберите тип по умолчанию. Типы Linux соответствуют размерам [собственных орбов Amp](https://ampcode.com/docs/orbs/sizes-and-costs):

   | Тип | Платформа | Конфигурация |
   | --- | --- | --- |
   | `linux` | Linux | 4 vCPU, 8 GiB RAM, рабочее пространство 10 ГБ |
   | `linux-tiny` | Linux | 1 vCPU, 2 GiB RAM, рабочее пространство 10 ГБ |
   | `linux-small` | Linux | 2 vCPU, 4 GiB RAM, рабочее пространство 10 ГБ |
   | `linux-medium` | Linux | 4 vCPU, 8 GiB RAM, рабочее пространство 10 ГБ (то же, что `linux`) |
   | `linux-large` | Linux | 8 vCPU, 16 GiB RAM, рабочее пространство 10 ГБ |
   | `linux-xxlarge` | Linux | 16 vCPU, 32 GiB RAM, рабочее пространство 10 ГБ |
   | `linux-3xlarge` | Linux | 16 vCPU, 44 GiB RAM, рабочее пространство 10 ГБ |
   | `macos` | macOS с Xcode | 8 vCPU, 8 GiB RAM, рабочее пространство 10 ГБ |

3. В Tuist откройте раздел **Sandboxes** в панели управления аккаунтом, нажмите **Connect** на карточке Amp и вставьте токен.

Карточка покажет статус **Connected**, когда Tuist начнёт обслуживать провайдера. Один аккаунт Tuist обслуживает одного провайдера. Любой пользователь, который может использовать провайдера в Amp, запускает орбы от имени подключённого аккаунта Tuist, и расходы списываются с него. Чтобы остановить, нажмите **Disconnect** на карточке или отключите провайдера в Amp.

## Начать тред {#start-a-thread}

В редакторе нового треда Amp нажмите **Orb**, выберите провайдера Tuist в разделе **Self-Hosted** и укажите тип, например `linux-small` для репозитория, которому нужно меньше ресурсов, чем `linux`, или `linux-large` для более требовательного. Из CLI Amp:

```bash
amp -ox "Fix the failing snapshot tests" --orb-provider tuist --orb-size macos
```

Тред сохраняет тип орба на протяжении всей жизни. Если тип не указан, используется значение по умолчанию провайдера. Чтобы для каждого нового треда использовался один тип, выберите провайдера и его тип в разделе **Default Orb** настроек Amp **Settings → Orbs**.

Amp клонирует репозиторий, запускает ваш скрипт `.agents/setup` и настраивает учётные данные Git, как это делается для любого орба. Каждый орб также может читать <.localized_link href="/guides/features/cache">кэш</.localized_link> Tuist вашего аккаунта.

## Приостановка и хранение {#retention}

Когда тред переходит в режим ожидания, Amp приостанавливает его орб. Следующее сообщение возобновляет работу с сохранением файлов.

- **Linux:** Работающие процессы сохраняются при приостановке. Орб, который долго находился в приостановленном состоянии, перемещается в архивное хранилище и восстанавливается при следующем сообщении без своих процессов. Орбы Linux хранят файлы до тех пор, пока Amp не удалит орб треда.
- **macOS:** Орб, находящийся в приостановленном состоянии или в состоянии ошибки в течение 7 дней, удаляется. Следующее сообщение треда создаёт новый орб, и Amp снова запускает `.agents/setup`. Первый орб macOS на машине устанавливает CLI Amp, поэтому запуск может занять до двух минут.

Орб, который остаётся в режиме ожидания без приостановки со стороны Amp, например потому что сигнал паузы не поступил, приостанавливается через десять минут с почти нулевым использованием CPU.

## Использовать Mac из любого треда Amp {#remote-mac}

Плагин Tuist Mac предоставляет треду Amp песочницу macOS с Xcode, симуляторами iOS и Homebrew, при этом тред продолжает работать там, где он запущен, например на одном из собственных Linux-орбов Amp. Попросите Amp выполнить задачу, и он запустит Mac, когда это потребуется:

> Добавь переключатель тёмного режима на экран настроек, запусти приложение в симуляторе iOS и покажи мне скриншот.

Amp продолжает редактировать код там, где он выполняется. Перед каждой командой на Mac плагин запускает `tuist sandbox sync`, который копирует файлы, не игнорируемые Git (закоммиченные или нет), а впоследствии — только изменённые файлы. Артефакты сборки и другие игнорируемые файлы, созданные на Mac, остаются там, поэтому сборки остаются инкрементальными. Плагин добавляет эти инструменты и навык `remote-mac`, который сообщает Amp, когда и как их использовать:

| Инструмент | Что делает |
| --- | --- |
| `tuist_mac_start` | Создаёт Mac для треда или повторно использует существующий и выполняет синхронизацию |
| `tuist_mac_shell` | Выполняет синхронизацию, затем запускает команду на Mac |
| `tuist_mac_screenshot` | Показывает симулятор или экран в треде |
| `tuist_mac_download` | Копирует файл обратно, например собранный `.app` |
| `tuist_mac_stop` | Удаляет Mac треда |

На Mac нет собственного CLI Tuist: после первой синхронизации Amp запускает `mise install` в корне репозитория, чтобы установить зафиксированную версию Tuist проекта, а `tuist_mac_shell` добавляет shim-скрипты mise в `PATH`. Каждая команда на Mac самостоятельно <.localized_link href="/guides/features/sandboxes#tuist-in-sandbox">авторизуется в кэше вашего аккаунта</.localized_link> с помощью Tuist 4.218.0 или новее; в версиях с 4.215.0 по 4.217.x Amp сначала запускает `tuist auth login`.

Тред использует один Mac. Tuist приостанавливает его в режиме ожидания, а следующая команда возобновляет работу. Amp удаляет Mac после завершения задачи; оставленный без внимания Mac удаляется после 14 дней в приостановленном состоянии. Mac учитываются в вашем аккаунте Tuist так же, как и любые другие песочницы.

### Настройка {#remote-mac-setup}

1. **Установите плагин.** Это один файл: [`tuist-mac.ts`](https://github.com/tuist/tuist/blob/main/.amp/plugins/tuist-mac.ts). Чтобы сделать его доступным для всех участников рабочего пространства Amp, администратор рабочего пространства просит Amp в треде:

   > Добавь https://raw.githubusercontent.com/tuist/tuist/main/.amp/plugins/tuist-mac.ts в плагины нашего рабочего пространства.

   Amp фиксирует его в [репозитории плагинов](https://ampcode.com/docs/customize/global-plugins-and-skills) рабочего пространства и запрашивает подтверждение перед отправкой. Вместо этого попросите «my personal plugins», чтобы установить плагин только для себя, или сохраните файл как `.amp/plugins/tuist-mac.ts` в репозитории, чтобы использовать его только там. Плагин является копией: для обновления попросите Amp заменить его последней версией по тому же URL.
2. **Установите CLI Tuist** там, где работает Amp. На орбах добавьте его в скрипт репозитория [`.agents/setup`](https://ampcode.com/docs/orbs/customizing), например `mise use -g tuist@latest`, или `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist`.
3. **Разрешите CLI использовать песочницы вашего аккаунта.** На орбах подключите рабочее пространство Amp к вашему аккаунту Tuist, как описано в разделе <.localized_link href="/guides/server/authentication#amp-orbs">Amp orbs</.localized_link>. После этого орбы самостоятельно выполняют вход и получают доступ к песочницам. В других местах, например при использовании CLI Amp на машине Linux, выполните `tuist auth login` от имени участника аккаунта или установите для `TUIST_MAC_TOKEN` значение <.localized_link href="/guides/server/authentication#account-tokens">токена аккаунта</.localized_link> со scope `account:sandboxes:write`, а также добавьте `ci`, чтобы Mac мог использовать кэш. Плагин передаёт `TUIST_MAC_TOKEN` в CLI вместо `TUIST_TOKEN`, поэтому установите его, даже если ваши орбы уже имеют `TUIST_TOKEN` без этого scope.
4. **Укажите, какой аккаунт использовать**, если в репозитории отсутствует `tuist.toml` с `project = "<account>/<project>"`. В Linux CLI не может прочитать аккаунт из `Tuist.swift`. Установите для `TUIST_MAC_ACCOUNT` значение хэндла вашего аккаунта в переменных окружения проекта Amp. Без этого Amp передаёт аккаунт из `Tuist.swift` (`fullHandle`) в `tuist_mac_start`.

CLI обращается к Mac только через `tuist.dev`, поэтому среда с ограниченным сетевым доступом должна разрешать только этот домен. Чтобы использовать CLI, которого нет в `PATH`, установите для `TUIST_MAC_CLI` путь к нему.

Агенты, не поддерживающие плагины Amp, такие как Claude Code или Cursor, могут делать то же самое через сервер Tuist MCP и CLI, как описано в разделе <.localized_link href="/guides/features/sandboxes#coding-agents">Сборка на Mac от агента для написания кода</.localized_link>.

### Использовать Tuist Mac вместо macOS Satellites от Amp {#remote-mac-satellites}

У Amp также есть собственные облачные Mac, [macOS Satellites](https://ampcode.com/docs/orbs/mac), находящиеся в бета-версии для рабочих пространств, присоединившихся к списку ожидания. Когда тред может запустить оба варианта, встроенные инструкции Amp направляют задачи macOS на свои спутники, поэтому плагин выбирается редко. Чтобы треды использовали Tuist Macs, выполните одно из следующих действий:

- **Отключите macOS Satellites для себя.** Каждый участник отключает их в разделе **Mac Satellites** настроек Amp [Settings → Experimental Features](https://ampcode.com/settings/experimental-features).
- **Отключите их для рабочего пространства.** Когда орбы вашего рабочего пространства [работают на Tuist](#connect), администратор рабочего пространства может установить параметр **Where Orbs Run** в значение **Self-Hosted Only** в настройках рабочего пространства Amp в разделе **Orbs**. После этого агенты не смогут запускать спутники, размещённые Amp, но участники также не смогут использовать встроенные орбы Amp, поэтому делайте это только тогда, когда все ваши треды работают на ваших собственных провайдерах орбов.
- **Запросите Tuist Macs.** Добавьте «Use the `tuist_mac_*` tools for macOS work, not macOS Satellites.» в запрос или в руководство для агентов вашего рабочего пространства в настройках рабочего пространства Amp, чтобы каждый тред следовал этому правилу.
