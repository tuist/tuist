# Покрытие кода в Xcode {#xcode-code-coverage}

Покрытие кода показывает, какие строки вашего кода выполнялись тестами. Tuist загружает покрытие по строкам для каждого запуска тестов и объединяет результаты всех запусков одного коммита в одну метрику — для проекта, каждой цели и каждого файла. На странице **Покрытие кода** в дашборде эти данные отображаются по коммитам и в виде тренда для каждой ветки.

> [!TIP]
> Если вы генерируете проект с помощью Tuist, вместо этого следуйте <.localized_link href="/guides/features/test-code-coverage/generated-xcode-project">руководству по сгенерированным проектам</.localized_link>: оно измеряет код, поступающий из бинарного кэша, и учитывает покрытие тех целей тестирования, которые пропускаются при выборочном тестировании.

## Настройка {#setup}

### Сбор покрытия {#collect-coverage}

Включите загрузку покрытия в вашем файле `Tuist.swift`. По умолчанию она отключена:

```swift
import ProjectDescription

let tuist = Tuist(
    fullHandle: "my-account/my-project",
    testInsights: .testInsights(coverage: .coverage(upload: true)),
    project: .xcode()
)
```

Переменная окружения `TUIST_COVERAGE_UPLOAD` (`1` или `0`) имеет приоритет над настройкой, например, чтобы отключить загрузку в задачах, обрабатывающих пул-реквесты из форков.

Затем включите **Покрытие кода** в действии тестирования вашей схемы (**Edit Scheme › Test › Options**) или передайте флаг `-enableCodeCoverage YES` при запуске и выполните тесты через `tuist xcodebuild test`:

```sh
tuist xcodebuild test \
  -scheme MyScheme \
  -enableCodeCoverage YES
```

Tuist загружает собранное покрытие вместе с результатами тестов.

### Завершение каждого коммита в CI {#complete-each-commit}

Покрытие коммита часто формируется несколькими задачами: по одной на схему, шард или платформу. Tuist не может самостоятельно определить, когда последняя из них завершилась, поэтому сообщите ему об этом. Когда все задачи тестирования для коммита завершатся, выполните эту команду в задаче, зависящей от всех них:

```sh
tuist coverage complete
```

До завершения коммита его покрытие отображается как **В процессе** и не учитывается в тренде ветки. В <.localized_link href="/guides/features/test-code-coverage/generated-xcode-project#commit-status">руководстве по сгенерированным проектам</.localized_link> описан каждый статус.

## Пропущенные тесты {#skipped-tests}

Когда запуск пропускает тесты с помощью флага `-skip-testing`, измеряется меньшая часть кода, чем покрывают тесты коммита, и Tuist не может перенести результаты этих тестов из предыдущего запуска. Покрытие коммита будет **Неполным**, если только другой запуск этого же коммита не выполнил их. Чтобы коммит считался полным, выполните все тесты хотя бы в одном запуске для каждого коммита.

Тесты, пропущенные карантином, вообще не входят в покрытие, поэтому они никогда не делают коммит **Неполным**.

## Влияние на производительность {#performance-impact}

Сбор покрытия добавляет накладные расходы, преимущественно после завершения тестов, пока Xcode формирует отчет о покрытии, а Tuist экспортирует данные. Сборка и выполнение тестов занимают примерно столько же времени, как и без сбора покрытия.

## Запрос покрытия {#querying}

Команды `tuist coverage` читают данные, которые отображает дашборд. Без указания `--commit` они считывают последний завершенный коммит ветки `--branch` или вашей ветки по умолчанию:

```sh
tuist coverage show                          # the project's coverage and its targets
tuist coverage files --commit <sha>          # files, least covered first
tuist coverage file Sources/Cart.swift --lines  # a file's functions, with per-line counts
```

Все команды поддерживают флаг `--json` для использования в скриптах.
