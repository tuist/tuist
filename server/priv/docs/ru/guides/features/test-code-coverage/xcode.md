# Покрытие кода в Xcode {#xcode-code-coverage}

<!-- @snippet: ./_xcode-early-access -->

Покрытие кода показывает, какие строки вашего кода выполнили тесты. Tuist загружает покрытие по строкам для каждого запуска тестов и объединяет запуски одного коммита в одну метрику для проекта, каждой цели и каждого файла. На странице **Покрытие кода** в дашборде эти данные отображаются по коммитам и в виде тренда для каждой ветки.

> [!TIP]
> Если вы генерируете проект с помощью Tuist, следуйте <.localized_link href="/guides/features/test-code-coverage/generated-xcode-project">руководству по сгенерированным проектам</.localized_link>: оно измеряет код, поступающий из бинарного кэша, и учитывает покрытие целей тестов, которые пропускает выборочное тестирование.

## Настройка {#setup}

### Сбор покрытия {#collect-coverage}

Включите загрузку покрытия в вашем `Tuist.swift`. По умолчанию она отключена:

```swift
import ProjectDescription

let tuist = Tuist(
    fullHandle: "my-account/my-project",
    testInsights: .testInsights(coverage: .coverage(upload: true)),
    project: .xcode()
)
```

Переменная окружения `TUIST_COVERAGE_UPLOAD` (`1` или `0`) имеет приоритет над настройкой, например, чтобы отключить загрузку в задачах, выполняющих pull-запросы из форков.

Затем включите **Покрытие кода** в действии тестирования вашей схемы (**Edit Scheme › Test › Options**) или передайте `-enableCodeCoverage YES` при запуске и выполните тесты через `tuist xcodebuild test`:

```sh
tuist xcodebuild test \
  -scheme MyScheme \
  -enableCodeCoverage YES
```

Tuist загружает собранное покрытием вместе с результатами тестов.

### Завершение каждого коммита в CI {#complete-each-commit}

Покрытие коммита часто формируется несколькими задачами: по одной на схему, шард или платформу. Tuist не может определить, когда последняя из них завершилась, поэтому сообщите ему об этом. Когда все задачи тестирования для коммита завершены, выполните эту команду в задаче, зависящей от всех них:

```sh
tuist coverage complete
```

Пока коммит не завершён, его покрытие отображается как **В процессе** и не учитывается в тренде ветки. <.localized_link href="/guides/features/test-code-coverage/generated-xcode-project#commit-status">Руководство по сгенерированным проектам</.localized_link> описывает каждый статус.

## Пропущенные тесты {#skipped-tests}

Когда запуск пропускает тесты с помощью `-skip-testing`, он измеряет меньше, чем покрывают тесты коммита, и Tuist не может перенести эти тесты из предыдущего запуска. Покрытие коммита будет **Неполным**, если другой запуск этого коммита не выполнил их. Чтобы коммит оставался полным, выполните все тесты хотя бы в одном запуске для каждого коммита.

Тесты, пропущенные карантином, вообще не участвуют в покрытии, поэтому они никогда не делают коммит **Неполным**.

## Влияние на производительность {#performance-impact}

Сбор покрытия добавляет накладные расходы, в основном после завершения тестов, пока Xcode записывает отчёт о покрытии, а Tuist экспортирует данные. Сборка и выполнение тестов занимают примерно столько же времени, сколько и без покрытия.

## Запрос покрытия {#querying}

Команды `tuist coverage` читают данные, которые отображает дашборд. Без `--commit` они читают последний завершённый коммит из `--branch` или из вашей ветки по умолчанию:

```sh
tuist coverage show                          # the project's coverage and its targets
tuist coverage files --commit <sha>          # files, least covered first
tuist coverage file Sources/Cart.swift --lines  # a file's functions, with per-line counts
```

Все они поддерживают `--json` для скриптов.
