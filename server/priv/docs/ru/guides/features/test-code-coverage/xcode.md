# Покрытие кода в Xcode {#xcode-code-coverage}

> [!NOTE] EARLY ACCESS
> Покрытие кода для проектов Xcode находится на стадии раннего доступа. [Свяжитесь с нами](mailto:contact@tuist.dev), чтобы включить его для вашего аккаунта. До этого момента Tuist не сохраняет данные о покрытии, загружаемые вашими запусками.

Покрытие кода показывает, какие строки вашего кода были выполнены тестами. Tuist загружает покрытие по строкам для каждого запуска тестов и объединяет данные всех запусков одного коммита в единую метрику для проекта, каждой цели и каждого файла. На странице **Code Coverage** дашборда эти данные отображаются по коммитам и в виде тренда для каждой ветки.

> [!TIP]
> Если вы генерируете проект с помощью Tuist, следуйте <.localized_link href="/guides/features/test-code-coverage/generated-xcode-project">руководству по сгенерированным проектам</.localized_link>: оно измеряет код, поступающий из бинарного кэша, и учитывает покрытие тех целей тестирования, которые пропускаются при выборочном тестировании.

## Настройка {#setup}

### Сбор данных о покрытии {#collect-coverage}

Включите загрузку данных о покрытии в файле `Tuist.swift`. По умолчанию эта функция отключена:

```swift
import ProjectDescription

let tuist = Tuist(
    fullHandle: "my-account/my-project",
    testInsights: .testInsights(coverage: .coverage(upload: true)),
    project: .xcode()
)
```

Переменная окружения `TUIST_COVERAGE_UPLOAD` (`1` или `0`) имеет приоритет над настройкой, например, чтобы отключить загрузку в задачах, выполняющих pull-requests из форков.

Затем включите **Code Coverage** в действии тестирования вашей схемы (**Edit Scheme › Test › Options**) или передайте флаг `-enableCodeCoverage YES` при запуске и выполните тесты через `tuist xcodebuild test`:

```sh
tuist xcodebuild test \
  -scheme MyScheme \
  -enableCodeCoverage YES
```

Tuist загружает данные о покрытии, собранные во время запуска, вместе с результатами тестов.

### Завершение каждого коммита в CI {#complete-each-commit}

Данные о покрытии коммита часто поступают из нескольких задач: по одной на схему, шард или платформу. Tuist не может определить, когда последняя из них завершила отчет, поэтому укажите это явно. После завершения всех задач тестирования для коммита выполните следующую команду в задаче, зависящей от всех них:

```sh
tuist coverage complete
```

Пока коммит не завершен, его покрытие отображается как **In progress** и не учитывается в тренде ветки. <.localized_link href="/guides/features/test-code-coverage/generated-xcode-project#commit-status">Руководство по сгенерированным проектам</.localized_link> описывает каждый статус.

## Пропущенные тесты {#skipped-tests}

Когда запуск пропускает тесты с помощью флага `-skip-testing`, он измеряет меньшую часть кода, чем покрывают все тесты коммита, и Tuist не может перенести данные этих тестов из предыдущего запуска. Покрытие коммита помечается как **Incomplete**, если только другой запуск этого же коммита не выполнил эти тесты. Чтобы коммит считался завершенным, выполните все тесты хотя бы в одном запуске для каждого коммита.

Тесты, пропущенные из-за карантина, вообще не входят в расчет покрытия, поэтому они никогда не делают коммит **Incomplete**.

## Влияние на производительность {#performance-impact}

Сбор данных о покрытии добавляет накладные расходы, преимущественно после завершения тестов, пока Xcode формирует отчет о покрытии, а Tuist экспортирует данные. Сборка и выполнение тестов занимают примерно столько же времени, сколько и без сбора покрытия.

## Получение данных о покрытии {#querying}

Команды `tuist coverage` читают данные, отображаемые в дашборде. Без указания `--commit` они считывают данные последнего завершенного коммита ветки `--branch` или вашей ветки по умолчанию:

```sh
tuist coverage show                          # the project's coverage and its targets
tuist coverage files --commit <sha>          # files, least covered first
tuist coverage file Sources/Cart.swift --lines  # a file's functions, with per-line counts
```

Все команды поддерживают флаг `--json` для использования в скриптах.
