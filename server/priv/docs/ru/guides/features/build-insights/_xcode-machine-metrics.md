## Метрики машины {#machine-metrics}

Аналитика сборок может включать метрики производительности на уровне машины (загрузка процессора, памяти, сети и диска), собираемые во время сборки. Чтобы включить эту функцию, настройте лёгкий фоновый демон, который постоянно опрашивает системные метрики:

```bash
tuist setup insights
```

Это запускает локальный демон, который в фоне опрашивает метрики. Данные автоматически подхватываются командой `tuist inspect build` и загружаются вместе с отчётом о сборке.

Метрики диска включают активность чтения/записи, а при использовании совместимого CLI и сервера — общий и доступный объём на томе данных системы macOS (`/System/Volumes/Data`). Доступное пространство не учитывает очищаемое место. Диаграмма использования диска показывает занятое место (общее минус доступное) вместе с общей ёмкостью за время сборки, а не только на момент загрузки. Она не измеряет отдельные внешние тома, используемые для клонирования репозитория или DerivedData.

После обновления CLI перезапустите существующий сборщик метрик, выполнив `tuist teardown insights`, а затем `tuist setup insights`. Сбор метрик должен работать во время сборки; старые отчёты и неудачные измерения не содержат значений использования диска и не отображаются как нулевые. Данные об использовании диска хранятся в соответствии с существующим 90-дневным сроком хранения машинных метрик.

> [!TIP]
> **CI**
>
> Выполните `tuist setup insights` на ваших CI-машинах перед сборкой, чтобы также собирать там машинные метрики.

Чтобы прекратить сбор машинных метрик, выполните:

```bash
tuist teardown insights
```

Это выгружает LaunchAgent демона, удаляет его plist-файл и стирает собранные метрики и логи демона из `~/.local/state`, поэтому в фоне ничего не остаётся работать.
