## Метрики машины {#machine-metrics}

Аналитика сборок может включать метрики производительности на уровне машины (ЦП, память, сеть и использование диска), собираемые во время сборки. Чтобы включить эту функцию, настройте легковесный фоновый демон, который постоянно опрашивает системные метрики:

```bash
tuist setup insights
```

Это запускает локальный демон, который опрашивает метрики в фоне. Данные автоматически подхватываются командой `tuist inspect build` и загружаются вместе с отчётом о сборке.

Метрики диска включают активность чтения/записи и, при использовании совместимых CLI и сервера, общий и доступный объём на томе данных системы macOS (`/System/Volumes/Data`). Доступное пространство не учитывает очищаемое место. График использования диска показывает занятое пространство (общее минус доступное) вместе с общей ёмкостью в течение всей сборки, а не только на момент загрузки. Он не измеряет отдельные внешние тома, используемые для checkout или DerivedData.

После обновления CLI перезапустите существующий сборщик метрик, выполнив `tuist teardown insights`, а затем `tuist setup insights`. Сбор метрик должен работать во время сборки; старые отчёты и неудачные измерения не содержат значений использования диска и не отображаются как нулевые. Данные об использовании диска хранятся в соответствии с существующим 90-дневным сроком хранения метрик машины.

> [!TIP]
> **CI**
>
> Выполните `tuist setup insights` на ваших CI-машинах перед сборкой, чтобы также собирать там метрики машины.

Чтобы прекратить сбор метрик машины, выполните:

```bash
tuist teardown insights
```

Это выгружает LaunchAgent демона, удаляет его plist-файл и стирает собранные метрики и логи демона из `~/.local/state`, поэтому в фоне ничего не остаётся работать.
