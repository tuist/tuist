## Метрики машины {#machine-metrics}

Аналитика сборок может включать метрики производительности на уровне машины (ЦП, память, сеть и использование диска), собранные во время сборки. Чтобы включить эту функцию, настройте легковесный фоновый демон, который постоянно опрашивает системные метрики:

```bash
tuist setup insights
```

Это запускает локальный демон, который опрашивает метрики в фоновом режиме. Данные автоматически собираются `tuist inspect build` и загружаются вместе с отчетом о сборке.

Метрики диска включают активность чтения/записи и, при использовании совместимого CLI и сервера, общий объем и доступное пространство на томе данных системы macOS (`/System/Volumes/Data`). Доступное пространство не включает очищаемое место. Диаграмма использования диска показывает занятое пространство (общее минус доступное) вместе с общей емкостью за время сборки, а не только на момент загрузки. Она не измеряет отдельные внешние тома, используемые для клонирования репозитория или DerivedData.

После обновления CLI перезапустите существующий сборщик метрик с помощью `tuist teardown insights`, а затем `tuist setup insights`. Сбор метрик должен работать во время сборки; старые отчеты и неудачные измерения не содержат значений использования диска и не отображаются как нулевые. Выборки использования диска подчиняются существующему правилу хранения метрик машины в течение 90 дней.

> [!TIP]
> **CI**
>
> Выполните `tuist setup insights` на ваших CI-машинах перед сборкой, чтобы собирать метрики машины и там.

Чтобы прекратить сбор метрик машины, выполните:

```bash
tuist teardown insights
```

Это выгружает LaunchAgent демона, удаляет его plist и удаляет собранные метрики и логи демона из `~/.local/state`, поэтому в фоновом режиме ничего не остается работать.
