# Аналитика сборок Once {#once-build-insights}

Once отправляет данные о запусках в Tuist во время их выполнения, чтобы вы могли отслеживать прогресс, не дожидаясь финального лога CI. Откройте ссылку на дашборд, которая выводится в начале запуска, чтобы просмотреть граф зависимостей, статус действий и решения кэширования.

> [!IMPORTANT]
> **Требования**
>
> - Выполните шаги из руководства <.localized_link href="/guides/get-started/once-project">Начало работы с Once</.localized_link> и выполните аутентификацию машины, на которой работает Once.

## Отправка данных о сборках {#report-your-builds}

Продолжайте использовать команды Once:

```bash
once build MyApplication
```

Отправка данных в реальном времени выполняется по принципу «best-effort». Недоступность конечной точки отправки или истечение срока действия сессии не приводят к сбою сборки. Если сессия истекла, войдите снова с помощью `once auth login --provider tuist`.

## Что показывает дашборд {#what-the-dashboard-shows}

Используйте разделы **Сборки** и **Запуски сборок**, чтобы сравнивать запуски по времени, веткам и окружениям (локальным или CI). Каждый запуск может включать:

- Запрошенную команду, статус, время начала и длительность.
- Версию Once и информацию о хосте.
- Действия, их зависимости, статус, длительность и результаты кэширования.
- Ошибки действий.
- Ветку Git, коммит и контекст CI, если они переданы клиентом.

Ищите и фильтруйте действия, чтобы найти неудачные или медленные задачи. Имена действий и исходные файлы помогают связать работу с кодом; старые версии клиентов могут предоставлять меньше деталей. Кэшированные или пропущенные действия не являются выполненной работой, а отсутствие данных о времени не означает выполнение нулевой длительности.

Tuist в настоящее время не получает необработанный поток логов действий Once. Сохраняйте логи CI для полного вывода процесса; сводки запусков и структурированные ошибки не заменяют эти логи.

Раздел **Кэш** разделяет решения по действиям и передачу объектов контента. См. <.localized_link href="/guides/features/cache/once">Кэш Once</.localized_link> для интерпретации активности кэша.

## Тесты {#tests}

Команды тестирования также создают запуски Once. Их отчеты по наборам и кейсам отображаются в разделе **Тесты**; размещенные шарды дополнительно публикуют объединенный запуск тестов. См. <.localized_link href="/guides/features/test-insights/once">Аналитика тестов Once</.localized_link>.

## Агенты кодирования и Grafana {#coding-agents-and-grafana}

<.localized_link href="/guides/features/agentic-coding/mcp#once-runs">Инструменты Model Context Protocol</.localized_link> позволяют агенту получать список запусков Once и считывать итоги по действиям и кэшу для конкретного запуска. Те же данные доступны через HTTP API.

Используйте <.localized_link href="/guides/integrations/grafana">интеграцию с Grafana</.localized_link> для финальных метрик здоровья сборок Once. Once в настоящее время не сообщает об экономии времени благодаря кэшу, поэтому эта метрика остается недоступной, а не равной нулю.
