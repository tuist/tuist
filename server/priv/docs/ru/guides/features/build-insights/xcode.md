# Аналитика сборок Xcode {#xcode-build-insights}

Работа над крупными проектами не должна требовать многократной пересборки одного и того же кода. Tuist Build Insights позволяет отслеживать аналитику сборок, чтобы выявлять тенденции до того, как время локальных сборок и сборок в CI станет узким местом.

Аналитика сборок формируется командой `tuist inspect build`, которую обычно добавляют в пост-действие схемы.

Чтобы начать отслеживать время локальных сборок, используйте команду `tuist inspect build`, добавив её в пост-действие схемы:

![Пост-действие для анализа сборок](/images/guides/features/build-insights/inspect-build-scheme-post-action.png)

> [!NOTE]
> Установите поле «Provide build settings from» на исполняемый файл или основной таргет сборки, чтобы захватить конфигурацию сборки.


> [!NOTE]
> Пост-действие схемы не выполняется, если сборка завершилась ошибкой.

>
> В этом случае вы можете выполнить его, установив `runPostActionsOnFailure` в значение `YES` в соответствующем разделе `project.pbxproj` `BuildAction`:
>
> ```diff
> <BuildAction
>    buildImplicitDependencies="YES"
>    parallelizeBuildables="YES"
> +  runPostActionsOnFailure="YES">
> ```

Для [Mise](https://mise.jdx.dev/) активируйте `tuist` в окружении пост-действия:

```sh
# -C ensures that Mise loads the configuration from the Mise configuration
# file in the project's root directory.
$HOME/.local/bin/mise x -C $SRCROOT -- tuist inspect build
```

> [!TIP]
> **Разрешение путей Mise**
>
> Переменная `PATH` вашего окружения не наследуется пост-действием схемы, поэтому используйте абсолютный путь к Mise. Он зависит от способа установки Mise. Настройки сборки должны наследоваться из таргета, чтобы `mise` мог запускаться из `$SRCROOT`.

Для [Homebrew](https://brew.sh/) добавьте пути Homebrew в окружение пост-действия:

```sh
export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"
tuist inspect build
```

Заявки актора по умолчанию отключены. Чтобы настроить их для пост-действия схемы, задайте `TUIST_ACTOR_ID` непосредственно в этом скрипте, а не полагайтесь на экспорт переменных оболочки. Xcode, запущенный из Dock, не наследует переменные из `~/.zshrc`. Чтобы явно подавить настроенную заявку при использовании Homebrew, выполните:

```sh
export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"
export TUIST_ACTOR_ID=""
tuist inspect build
```

При использовании Mise переопределите значение после загрузки окружения Mise:

```sh
$HOME/.local/bin/mise x -C "$SRCROOT" -- env TUIST_ACTOR_ID="" tuist inspect build
```

Используйте явную метку вместо пустого значения, чтобы включить отправку.

После входа в систему локальные сборки отслеживаются и становятся доступны в панели управления Tuist:

> [!TIP]
> Чтобы быстро открыть панель управления, выполните `tuist project show --web` из командной строки.


![Панель управления с аналитикой сборок](/images/guides/features/build-insights/builds-dashboard.png)

## Аналитика сборок в CI {#continuous-integration}

Чтобы отслеживать аналитику сборок в CI, убедитесь, что CI <.localized_link href="/guides/integrations/continuous-integration#authentication">аутентифицирован</.localized_link>.

Для CI на базе xcodebuild необходимо:
- Использовать <.localized_link href="/cli/xcodebuild#tuist-xcodebuild">`tuist xcodebuild`</.localized_link> при вызове действий `xcodebuild`.
- Добавьте `-resultBundlePath` в команду `xcodebuild`.

Без `-resultBundlePath` необходимые журналы активности и пакеты результатов не создаются, и `tuist inspect build` не может проанализировать сборку.

## Отправка отчётов без учётных данных в частной сети {#network-trusted-publishing}

Развёртывание на собственном сервере может позволить разработчикам публиковать готовые отчёты без входа в систему. Оператор должен настроить `TUIST_NETWORK_TRUSTED_INSIGHTS_ACCESS=true` на экземпляре и перезапустить его, как описано в <.localized_link href="/guides/server/self-host/server#network-trusted-access">руководстве по самостоятельному размещению</.localized_link>. Это применяется ко всем поддерживаемым проектам; отдельной настройки в панели управления нет. Настройте URL-адрес самостоятельного размещения и проект в окружении, используемом вашим пост-действием схемы или терминалом. CLI автоматически определяет политику экземпляра, когда учётные данные отсутствуют:

```sh
export TUIST_URL="https://tuist.internal.example"
tuist inspect build
# To publish local test results:
tuist inspect test
```

При полном отсутствии учётных данных журналы активности и пакеты XCResult анализируются локально и отправляются в виде структурированных отчётов. Не передаются необработанные архивы, вложения, данные покрытия/истории, удалённые процессоры, ссылки на шарды или доказательства выборочного выполнения. Отчёты остаются видимыми, но не могут обновлять состояние тест-кейсов для аутентифицированных пользователей или запускать автоматизацию карантина/сбоев. Для доступа к панелям управления и другим привилегированным командам всё ещё требуется вход в систему. Оставьте интеграцию кэша отключённой, если экземпляр отдельно не включает доступ к кэшу с доверием к сети или не предоставлены учётные данные.

Текущие учётные данные остаются аутентифицированными. Недействительные, повреждённые, пустые или отклонённые при обновлении учётные данные приводят к безопасному отказу и сохраняются на диске, поэтому последующие команды не становятся не подписанными незаметно. Войдите в систему заново или явно выйдите из неё как осознанное действие восстановления. Обновите каждую реплику сервера до версии с поддержкой обнаружения перед обновлением клиентов, работающих без учётных данных, и настройте финальный URL сервера без перенаправлений. Старые серверы без поддержки обнаружения, отключённые экземпляры и сбои обнаружения по‑прежнему требуют аутентификации. Дополнительное согласие на стороне клиента не требуется. Установите `TUIST_ACTOR_ID=""` отдельно, чтобы исключить настроенную заявку актора; это не влияет на проверенную идентичность учётных данных.

## Метрики машины {#machine-metrics}

Аналитика сборок может включать метрики производительности на уровне машины (ЦП, память, сеть и использование диска), собираемые во время сборки. Чтобы включить эту функцию, настройте лёгкий фоновый демон, который постоянно снимает системные метрики:

```bash
tuist setup insights
```

Это запускает локальный демон, который в фоне снимает метрики. Данные автоматически подхватываются командой `tuist inspect build` и загружаются вместе с отчётом о сборке.

> [!TIP]
> **CI**
>
> Выполните `tuist setup insights` на ваших машинах CI перед сборкой, чтобы также собирать машинные метрики.

Чтобы прекратить сбор машинных метрик, выполните:

```bash
tuist teardown insights
```

Это выгружает LaunchAgent демона, удаляет его plist и стирает собранные метрики и логи демона из `~/.local/state`, поэтому в фоне ничего не остаётся работать.


## Заявка актора отчёта {#report-actor-claim}

Запросы на создание отчёта включают опциональный заголовок `x-tuist-actor-id` только если вы явно установили `TUIST_ACTOR_ID` в метку в области организации, например `TUIST_ACTOR_ID=employee-123 tuist inspect build`. По умолчанию метка не отправляется, и Tuist не определяет имена пользователей операционной системы. Пустое значение `TUIST_ACTOR_ID` исключает отправляемый идентификатор, но не удаляет проверенную идентичность на основе учётных данных. Идентификаторы должны состоять из 1–128 байт печатных символов ASCII, кроме пробела; недопустимые переопределения опускаются без возврата к значению по умолчанию. Если пользовательский прокси отклоняет неизвестные заголовки, откажитесь от отправки, установив пустое переопределение в окружении.

Проверенные индивидуальные учётные данные имеют приоритет; иначе идентификаторы, сообщённые клиентом, отображаются как **Непроверенные** и никогда не предоставляют права или не связываются с пользователями автоматически. Идентификаторы видны всем, кто может просматривать отчёты проекта, включая публичных зрителей, если проект публичный, и включаются в экспорты данных, поэтому не включайте в них секреты. Это относится к отчётам о сборках, тестах и событиях команд. Старые серверы игнорируют опциональный заголовок, а новые серверы принимают старых клиентов без него. Новые отчёты с общим токеном без идентификатора показывают **Неизвестно**, а не публикующую организацию; исторические отчёты сохраняют прежнюю атрибуцию. В списках сборок и тестов проверяемые пользователи отделяются от непроверенных сообщённых идентификаторов. Аутентификация по‑прежнему требуется, если только самохостинговый экземпляр явно не включает отчётность без учётных данных и клиент не обнаруживает эту политику.

## Пользовательские метаданные {#custom-metadata}

Вы можете прикреплять метаданные к сборкам с помощью переменных окружения, чтобы улучшить фильтрацию.

### Переменные окружения

| Переменная | Формат | Описание |
|----------|--------|-------------|
| `TUIST_BUILD_TAGS` | Разделённые запятыми | Несколько тегов в одной переменной. |
| `TUIST_BUILD_VALUE_*` | Одно значение | Пара ключ-значение, где суффикс является ключом. |

### Примеры

Установите эти значения в CI или в вашей оболочке перед запуском сборки:

```sh
export TUIST_BUILD_TAGS="nightly,ios-team,release-candidate"
```

```sh
export TUIST_BUILD_VALUE_TICKET="PROJ-1234"
export TUIST_BUILD_VALUE_PR_URL="https://github.com/myorg/myrepo/pull/123"
```
