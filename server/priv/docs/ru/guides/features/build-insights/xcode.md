# Аналитика сборок Xcode {#xcode-build-insights}

Работа над крупными проектами не должна требовать многократной пересборки одного и того же кода. Тулза Tuist Build Insights позволяет отслеживать аналитику сборок, чтобы вы могли выявлять тенденции до того, как время локальных сборок и сборок в CI станет узким местом.

Аналитика сборок формируется командой `tuist inspect build`, которую обычно добавляют в пост-действие схемы.

Чтобы начать отслеживать время локальных сборок, используйте команду `tuist inspect build`, добавив её в пост-действие схемы:

![Пост-действие для анализа сборок](/images/guides/features/build-insights/inspect-build-scheme-post-action.png)

> [!NOTE]
> Установите поле «Provide build settings from» на исполняемый файл или вашу основную цель сборки, чтобы захватить конфигурацию сборки.


> [!NOTE]
> Пост-действие схемы не выполняется, если сборка завершилась ошибкой.

>
> В этом случае вы можете выполнить его, установив `runPostActionsOnFailure` в значение `YES` в соответствующем `project.pbxproj` `BuildAction`:
>
> ```diff
> <BuildAction
>    buildImplicitDependencies="YES"
>    parallelizeBuildables="YES"
> +  runPostActionsOnFailure="YES">
> ```

Для [Mise](https://mise.jdx.dev/) активируйте `tuist` в окружении пост-действия:

```sh
# -C ensures that Mise loads the configuration from the Mise configuration
# file in the project's root directory.
$HOME/.local/bin/mise x -C $SRCROOT -- tuist inspect build
```

> [!TIP]
> **Разрешение путей Mise**
>
> Переменная `PATH` вашего окружения не наследуется пост-действием схемы, поэтому используйте абсолютный путь к Mise. Это зависит от способа установки Mise. Настройки сборки должны наследоваться от цели, чтобы `mise` мог запускаться из `$SRCROOT`.

Для [Homebrew](https://brew.sh/) добавьте пути Homebrew в окружение пост-действия:

```sh
export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"
tuist inspect build
```

Заявки актора по умолчанию отключены. Чтобы настроить заявку для пост-действия схемы, задайте `TUIST_ACTOR_ID` прямо в этом скрипте, а не полагайтесь на экспорт переменных оболочки. Xcode, запущенный из Dock, не наследует переменные из `~/.zshrc`. Чтобы явно подавить настроенную заявку при использовании Homebrew, используйте:

```sh
export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"
export TUIST_ACTOR_ID=""
tuist inspect build
```

При использовании Mise переопределите значение после загрузки окружения Mise:

```sh
$HOME/.local/bin/mise x -C "$SRCROOT" -- env TUIST_ACTOR_ID="" tuist inspect build
```

Используйте явную метку вместо пустого значения, чтобы активировать функцию.

После входа в систему локальные сборки отслеживаются и становятся доступны в панели управления Tuist:

> [!TIP]
> Чтобы быстро открыть панель управления, выполните `tuist project show --web` из CLI.


![Панель управления с аналитикой сборок](/images/guides/features/build-insights/builds-dashboard.png)

## Аналитика сборок в CI {#continuous-integration}

Чтобы отслеживать аналитику сборок в CI, убедитесь, что CI <.localized_link href="/guides/integrations/continuous-integration#authentication">аутентифицирован</.localized_link>.

Для CI на базе xcodebuild необходимо:
- Использовать <.localized_link href="/cli/xcodebuild#tuist-xcodebuild">`tuist xcodebuild`</.localized_link> при вызове действий `xcodebuild`.
- Добавить `-resultBundlePath` к вашей команде `xcodebuild`.

Без `-resultBundlePath` необходимые журналы активности и пакеты результатов не создаются, и `tuist inspect build` не может проанализировать сборку.

## Отправка отчётов без учётных данных в частной сети {#network-trusted-publishing}

Развёртывание на собственном сервере позволяет разработчикам публиковать готовые отчёты без входа в систему. Оператор должен настроить `TUIST_NETWORK_TRUSTED_INSIGHTS_ACCESS=true` на экземпляре и перезапустить его, как описано в <.localized_link href="/guides/server/self-host/server#network-trusted-access">руководстве по самостоятельному размещению</.localized_link>. Это относится ко всем поддерживаемым проектам; отдельной настройки в панели управления нет. Настройте URL-адрес собственного сервера и проект в окружении, которое используется пост-действием схемы или терминалом. CLI автоматически обнаруживает политику экземпляра, если учётные данные отсутствуют:

```sh
export TUIST_URL="https://tuist.internal.example"
tuist inspect build
# To publish local test results:
tuist inspect test
```

При полном отсутствии учётных данных журналы активности и пакеты XCResult анализируются локально и отправляются в виде структурированных отчётов. Не передаются необработанные архивы, вложения, данные покрытия/истории, удалённые процессоры, ссылки на шарды или доказательства выборочного выполнения. Отчёты остаются видимыми, но не могут обновлять состояние аутентифицированных тестовых случаев или запускать автоматизацию карантина/ошибок. Панели управления и другие привилегированные команды всё ещё требуют входа в систему. Оставьте интеграцию кэша отключённой, если экземпляр отдельно не включает доступ к кэшу с доверием к сети или не предоставлены учётные данные.

Текущие учётные данные остаются аутентифицированными. Недействительные, повреждённые, пустые или отклонённые при обновлении учётные данные приводят к отказу и остаются на диске, поэтому последующие команды не становятся неявно неаутентифицированными. Войдите в систему снова или явно выйдите из неё как осознанное действие восстановления. Обновите каждую реплику сервера до версии с поддержкой обнаружения перед обновлением клиентов без учётных данных и настройте финальный URL сервера без перенаправлений. Старые серверы без обнаружения, отключённые экземпляры и сбои обнаружения всё ещё требуют аутентификации. Опция на стороне клиента не нужна. Установите `TUIST_ACTOR_ID=""` независимо, чтобы исключить настроенную заявку актора; это не влияет на проверенную личность учётных данных.

## Метрики машины {#machine-metrics}

Аналитика сборок может включать метрики производительности на уровне машины (ЦП, память, сеть и использование диска), собираемые во время сборки. Чтобы включить эту функцию, настройте лёгкий фоновый демон, который постоянно снимает системные метрики:

```bash
tuist setup insights
```

Это запускает локальный демон, который снимает метрики в фоновом режиме. Данные автоматически подхватываются командой `tuist inspect build` и загружаются вместе с отчётом о сборке.

> [!TIP]
> **CI**
>
> Выполните `tuist setup insights` на ваших машинах CI перед сборкой, чтобы также собирать метрики машины.

Чтобы прекратить сбор метрик машины, выполните:

```bash
tuist teardown insights
```

Это выгружает LaunchAgent демона, удаляет его plist и стирает собранные метрики и логи демона из `~/.local/state`, поэтому в фоне ничего не остаётся работать.


## Заявка актора в отчёте {#report-actor-claim}

Запросы на создание отчёта включают необязательный заголовок `x-tuist-actor-id` только тогда, когда вы явно устанавливаете `TUIST_ACTOR_ID` в метку, ограниченную организацией, например `TUIST_ACTOR_ID=employee-123 tuist inspect build`. По умолчанию метка не отправляется, и Tuist не определяет имена пользователей операционной системы. Пустое значение `TUIST_ACTOR_ID` исключает отправляемый идентификатор, но не удаляет проверенную личность на основе учётных данных. Идентификаторы должны состоять из 1–128 байт печатных символов ASCII, кроме пробела; недействительные переопределения опускаются без возврата к значению по умолчанию. Если пользовательский прокси отвергает неизвестные заголовки, откажитесь от функции с помощью пустого переопределения в окружении.

Проверенные индивидуальные учётные данные имеют приоритет; иначе идентификаторы, сообщённые клиентом, отображаются как **Непроверенные** и никогда не предоставляют права доступа и не связываются с пользователями автоматически. Идентификаторы видны всем, кто может просматривать отчёты проекта, включая публичных зрителей, если проект публичный, и включаются в экспорты данных, поэтому не включайте секреты. Это относится к отчётам о сборках, тестах и событиях команд. Старые серверы игнорируют необязательный заголовок, а новые серверы принимают старых клиентов без него. Новые отчёты с общим токеном без идентификатора показывают **Неизвестно**, а не публикующую организацию; исторические отчёты сохраняют прежнюю атрибуцию. В списках сборок и тестов различаются проверенные пользователи и непроверенные сообщённые идентификаторы. Аутентификация остаётся обязательной, если экземпляр на собственном сервере явно не включает отчётность без учётных данных и клиент не обнаруживает эту политику.

## Пользовательские метаданные {#custom-metadata}

Вы можете прикреплять метаданные к сборкам с помощью переменных окружения, чтобы улучшить фильтрацию.

### Переменные окружения

| Переменная | Формат | Описание |
|----------|--------|-------------|
| `TUIST_BUILD_TAGS` | Разделённые запятыми | Несколько тегов в одной переменной. |
| `TUIST_BUILD_VALUE_*` | Одно значение | Пара ключ-значение, где суффикс является ключом. |

### Примеры

Установите эти значения в CI или в вашей оболочке перед запуском сборки:

```sh
export TUIST_BUILD_TAGS="nightly,ios-team,release-candidate"
```

```sh
export TUIST_BUILD_VALUE_TICKET="PROJ-1234"
export TUIST_BUILD_VALUE_PR_URL="https://github.com/myorg/myrepo/pull/123"
```
