# Аналитика сборок Elixir {#elixir-build-insights}

Hex-пакет Tuist может отправлять аналитику сборок в Tuist. Время сборки, граф зависимостей между файлами и их изменение со временем дают всё необходимое для оптимизации графа сборки и максимального использования всех ядер, доступных в среде компиляции.

> [!IMPORTANT] REQUIREMENTS
> - Пройдите <.localized_link href="/guides/get-started/elixir-project">Руководство по началу работы с Elixir</.localized_link>

## Отправка отчётов о сборках {#report-your-builds}

Общая настройка устанавливает интеграцию компиляции. Продолжайте использовать привычные команды:

```bash
mix compile
```

Интеграция охватывает `mix compile` и каждую компиляцию, которую запускают другие задачи, например `mix test` или `mix phx.server`. Компиляция, которая не находит работы, не отправляется в отчёт, поэтому на панели отображаются только выполненные сборки.

## Передача идентификатора актора {#report-actor-claim}

Запросы на отправку отчётов о сборках и тестах Mix включают необязательный заголовок `x-tuist-actor-id` только если вы явно настроили метку. Установите `TUIST_ACTOR_ID` в метку в рамках организации или добавьте `actor_id: "developer-label"` в конфигурацию `tuist` проекта. Приоритет имеет переменная окружения, затем параметры времени выполнения `:actor_id`, затем конфигурация проекта. По умолчанию метка не отправляется, и пакет не определяет имена пользователей операционной системы. Фиксированная метка проекта применяется ко всем, кто использует эту конфигурацию. Пустые или некорректные переопределения опускают передачу идентификатора вместо отката; это не удаляет проверенную идентификацию на основе учётных данных. Если пользовательский прокси отвергает неизвестные заголовки, откажитесь от передачи, установив `TUIST_ACTOR_ID=""`.

Идентификаторы должны состоять из 1–128 байт печатных символов ASCII без пробелов. Некорректные переопределения пропускаются без отката. Проверенные индивидуальные учётные данные имеют приоритет; другие идентификаторы, сообщаемые клиентом, отображаются как **Непроверено**, никогда не предоставляют доступ и никогда не связываются с пользователями автоматически. Эти идентификаторы видны всем, кто может просматривать отчёты проекта, включая публичных зрителей, если проект открыт, и они включаются в экспорт данных, поэтому не добавляйте секреты. Старые серверы игнорируют необязательный заголовок, а новые принимают старых клиентов без него. Новые отчёты с общим токеном без идентификатора показывают **Неизвестно** вместо публикующей организации; исторические отчёты сохраняют прежнюю атрибуцию. Отправка отчётов о сборках и тестах по умолчанию требует аутентификации. Самостоятельно размещённые установки могут явно включить отправку без учётных данных, как описано ниже.

## Отправка без учётных данных в частной сети {#network-trusted-publishing}

После того как оператор настроит `TUIST_NETWORK_TRUSTED_INSIGHTS_ACCESS=true` на экземпляре и перезапустит его, как описано в <.localized_link href="/guides/server/self-host/server#network-trusted-access">руководстве по самостоятельному размещению</.localized_link>, настройте пункт назначения. SDK автоматически определяет, разрешает ли экземпляр отправку данных без учетных данных, когда они отсутствуют. Настройка экземпляра применяется ко всем поддерживаемым проектам и не имеет переключателя в панели управления:

```elixir
tuist: [
  url: "https://tuist.internal.example",
  project: "account/project"
]
```

`mix tuist.compile` и `mix tuist.test` публикуют структурированные отчёты без входа, когда учётные данные действительно отсутствуют и обнаружение подтверждает, что сервер это разрешает. Никаких клиентских флагов или включения в проекте не требуется. Предоставленные учётные данные, включая переданный идентификатор CI OIDC, используются или отклоняются, но никогда не игнорируются для перехода к неподписанной отправке. `TUIST_TOKEN` только с пробельными символами является ошибкой. Пустой `TUIST_TOKEN` может выполнить откат к действительным сохранённым учётным данным или переданному OIDC, а устаревшие сохранённые учётные данные могут выполнить откат к переданному OIDC; оба пути остаются аутентифицированными и никогда не включают неподписанную отправку. Непригодные учётные данные сохраняются и приводят к ошибке, если ни один аутентифицированный вариант отката не сработал. Обновите каждую реплику сервера до версии с поддержкой обнаружения перед обновлением клиентов для отправки без учётных данных; старые серверы без обнаружения, отключённые экземпляры и сбои обнаружения по‑прежнему требуют аутентификации.

Неподписанные прогоны — это телеметрия, а не доверенные данные о нестабильности тестов, карантине, покрытии или избирательном выполнении. Планирование шардов, архивы сборок и эндпоинты покрытия/артефактов по‑прежнему требуют учётных данных. Установите `TUIST_ACTOR_ID=""` отдельно, чтобы опустить настроенный идентификатор актора; проверенная идентификация по учётным данным не затрагивается.

## Что отслеживается {#what-is-tracked}

Для каждой сборки пакет собирает:
- Её длительность, результат (успех/неудача) и среду Elixir, Erlang/OTP и Mix, в которой она выполнялась
- Каждое предупреждение и ошибку с указанием файла и строки
- Время компиляции каждого файла и модули, которые он определяет
- Файлы, от которых зависит каждый файл, и нужны ли они во время компиляции или только во время выполнения
- Действия сборки помимо компиляции файлов, такие как проверка типов, запись на диск и работа других компиляторов Mix
- Использование процессора, памяти, сети и диска машиной во время сборки
- Ветку и коммит, а при непрерывной интеграции — провайдера и прогон

## Поиск причин замедления сборки {#find-what-slows-a-build-down}

Откройте сборку в разделе **Сборки → Запуски сборок** на панели управления. Сведения о сборках, количестве диагностических сообщений и сводках кэша зависимостей также доступны через `tuist build mix list` и `tuist build mix show`, `GET /api/projects/{account_handle}/{project_handle}/mix/builds`, а также инструменты `list_mix_builds` и `get_mix_build` <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>.

На вкладке **Обзор** перечислены файлы, скомпилированные сборкой. Их можно группировать по модулям, искать и сортировать по:
- **Длительности компиляции**, чтобы найти файлы, которые сами по себе медленные.
- **Зависимым при компиляции** — количеству файлов, которые не могут скомпилироваться, пока не скомпилируется этот. Медленный файл с большим количеством зависимых тормозит остальную часть сборки, а его изменение приводит к перекомпиляции всех них.
- **Зависимостям при компиляции** — количеству файлов, которых ожидает этот файл.

![Обзор сборки Mix приложения Phoenix](/images/guides/features/elixir/build.png)

Вкладка **Временная шкала** показывает ту же сборку во времени: какие файлы компилировались параллельно, где выполнялась проверка типов и запись на диск, и какова была нагрузка машины в каждый момент. Участок с одной полосой означает период, когда сборка не могла использовать имеющиеся ядра.

![Временная шкала полной сборки Mix приложения Phoenix](/images/guides/features/elixir/build-timeline.png)

Вкладки **Предупреждения** и **Ошибки** перечисляют диагностики сборки.

## Пользовательские метаданные {#custom-metadata}

Добавляйте теги и данные в формате «ключ–значение» к сборкам Mix, чтобы различать прогоны разных команд, оборудования или рабочих процессов. Оба вида отображаются на странице деталей каждой сборки.

Установите метаданные через переменные окружения:

```sh
export TUIST_TAGS="nightly,release"
export TUIST_VALUES="ticket=TUIST-123,runner=linux-arm64"
```

Метаданные также можно настроить в `mix.exs`:

```elixir
tuist: [
  project: "account/project",
  tags: ["nightly", "release"],
  values: %{"ticket" => "TUIST-123", "runner" => "linux-arm64"}
]
```

Теги из обоих источников объединяются. Если один и тот же ключ настроен в обоих местах, приоритет имеет значение из переменной окружения.

Теги могут содержать только буквы, цифры, дефисы и знаки подчеркивания. Сборка может иметь до 50 тегов, каждый тег — до 50 символов. Сборка может иметь до 20 записей «ключ–значение», каждый ключ — до 50 символов, каждое значение — до 500 символов. Это те же серверные ограничения, что и для метаданных сборок Xcode. Пакет пропускает недопустимые теги и слишком большие или пустые записи метаданных перед отправкой отчета, поэтому неверная конфигурация не помешает сохранить остальную часть отчета аналитики сборки. Используйте метаданные «ключ–значение» для значений, которые не соответствуют ограничениям для тегов.

Пользовательские метаданные прикрепляются к сборкам, а не к прогонам тестов.

Пользовательские метаданные видны участникам проекта в панели управления. Не используйте их для учетных данных, токенов доступа или других конфиденциальных данных. Tuist хранит данные сборок Mix, включая эти метаданные, в течение 90 дней. Подробнее см. в <.localized_link href="/guides/server/data-retention">политике хранения данных</.localized_link>.

## Устранение неполадок {#troubleshooting}

Отправка отчетов никогда не меняет результат вашей сборки: если отчет не удается отправить, сборка завершается как обычно и ничего не выводится. Чтобы узнать, почему отчет не был отправлен, установите `TUIST_DEBUG=1`:

```bash
TUIST_DEBUG=1 mix compile --force
```
