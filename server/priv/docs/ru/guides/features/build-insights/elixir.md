# Аналитика сборок Elixir {#elixir-build-insights}

Hex-пакет Tuist может отправлять аналитику сборок в Tuist. Время сборки, граф зависимостей между вашими файлами и то, как они меняются со временем, дают вам всё необходимое для оптимизации графа сборки и максимального использования всех ядер, доступных в среде компиляции.

> [!IMPORTANT] REQUIREMENTS
> - Завершите <.localized_link href="/guides/get-started/elixir-project">Начало работы с Elixir</.localized_link>

## Отправка отчётов о сборках {#report-your-builds}

Общая настройка устанавливает интеграцию компиляции. Продолжайте использовать ваши обычные команды:

```bash
mix compile
```

Интеграция охватывает `mix compile` и каждую компиляцию, которую запускает другая задача, например `mix test` или `mix phx.server`. Компиляция, которая не находит работы, не отправляется в отчёт, поэтому на панели отображаются только выполненные сборки.

## Отправка утверждения об акторе {#report-actor-claim}

Запросы отчётов о сборке и тестировании Mix включают необязательный заголовок `x-tuist-actor-id` только если вы явно настроили метку. Установите `TUIST_ACTOR_ID` в метку, ограниченную организацией, или добавьте `actor_id: "developer-label"` в конфигурацию `tuist` проекта. При разрешении приоритет отдаётся переменной окружения, затем параметрам времени выполнения `:actor_id`, затем конфигурации проекта. По умолчанию метка не отправляется, и пакет не определяет имена пользователей операционной системы. Фиксированная метка проекта применяется ко всем, кто использует эту конфигурацию. Пустые или недопустимые переопределения пропускают утверждение вместо отката; это не удаляет проверенную идентификацию на основе учётных данных. Если пользовательский прокси отклоняет неизвестные заголовки, откажитесь от отправки с помощью `TUIST_ACTOR_ID=""` .

Идентификаторы должны состоять из 1–128 байт печатных символов ASCII, кроме пробела. Недопустимые переопределения пропускаются без отката. Проверенные индивидуальные учётные данные имеют приоритет; другие идентификаторы, сообщаемые клиентом, отображаются как **Непроверено**, никогда не авторизуют доступ и никогда не связываются с пользователями автоматически. Любой, кто может просматривать отчёты проекта, видит эти идентификаторы, включая публичных зрителей, если проект публичный, и они включаются в экспорт данных, поэтому не включайте секреты. Старые серверы игнорируют необязательный заголовок, а новые серверы принимают старых клиентов без него. Новые отчёты с общим токеном без идентификатора показывают **Неизвестно** вместо публикующей организации; исторические отчёты сохраняют прежнюю атрибуцию. Отчётность о сборках и тестах по умолчанию требует аутентификации. Самостоятельно размещённые установки могут явно включить отчётность без учётных данных, как описано ниже.

## Отчётность без учётных данных в частной сети {#network-trusted-publishing}

После того как оператор настроит `TUIST_NETWORK_TRUSTED_REPORT_PUBLISHING=true` на экземпляре и перезапустит его, как описано в <.localized_link href="/guides/server/self-host/server#network-trusted-report-publishing">руководстве по самостоятельному размещению</.localized_link>, настройте ваше назначение. SDK автоматически определяет, разрешает ли экземпляр отчётность без учётных данных, когда учётные данные отсутствуют. Настройка экземпляра охватывает все поддерживаемые проекты и не имеет переключателя на панели:

```elixir
tuist: [
  url: "https://tuist.internal.example",
  project: "account/project"
]
```

`mix tuist.compile` и `mix tuist.test` публикуют структурированные отчёты без входа в систему, когда учётные данные действительно отсутствуют и обнаружение подтверждает, что сервер это разрешает. Никакой флаг клиента или согласие проекта не требуется. Предоставленные учётные данные, включая предоставленную идентичность CI OIDC, используются или отклоняются, но никогда не игнорируются для перехода к неподписанной отчётности. `TUIST_TOKEN` , состоящий только из пробельных символов, является ошибкой. Пустой `TUIST_TOKEN` может откатиться к действительным сохранённым учётным данным или предоставленному OIDC, а устаревшие сохранённые учётные данные могут откатиться к предоставленному OIDC; оба пути остаются аутентифицированными и никогда не включают неподписанную отчётность. Непригодные учётные данные сохраняются и приводят к ошибке, если ни один аутентифицированный вариант отката не succeeds. Обновите каждую реплику сервера до версии с поддержкой обнаружения перед обновлением клиентов без учётных данных; старые серверы без обнаружения, отключённые экземпляры и сбои обнаружения всё ещё требуют аутентификации.

Неподписанные запуски являются телеметрией, а не доверенными доказательствами нестабильности, карантина, покрытия или выборочного выполнения. Планирование шардов, архивы сборок и конечные точки покрытия/артефактов всё ещё требуют учётных данных. Установите `TUIST_ACTOR_ID=""` независимо, чтобы пропустить настроенное утверждение об акторе; проверенная идентичность учётных данных не затрагивается.

## Что отслеживается {#what-is-tracked}

Для каждой сборки пакет собирает:
- Её продолжительность, успешность и среду Elixir, Erlang/OTP и Mix, в которой она выполнялась
- Каждое предупреждение и ошибку с указанием файла и строки
- Время компиляции каждого файла и модули, которые он определяет
- Файлы, от которых зависит каждый файл, и нужны ли они во время компиляции или только во время выполнения
- Что делала сборка помимо компиляции файлов, например проверка типов, запись на диск и другие компиляторы Mix
- Использование процессора, памяти, сети и диска машины во время сборки
- Ветку и коммит, а при непрерывной интеграции — провайдера и запуск

## Поиск причин замедления сборки {#find-what-slows-a-build-down}

Откройте сборку из раздела **Сборки → Запуски сборок** на панели. Сборки, количество их диагностик и сводки кэша зависимостей также доступны через `tuist build mix list` и `tuist build mix show`, `GET /api/projects/{account_handle}/{project_handle}/mix/builds`, а также инструменты `list_mix_builds` и `get_mix_build` <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link> .

На вкладке **Обзор** перечислены файлы, скомпилированные сборкой. Вы можете группировать их по модулям, искать и сортировать по:
- **Продолжительности компиляции**, чтобы найти файлы, которые сами по себе медленные.
- **Зависимым во время компиляции** — количеству файлов, которые не могут быть скомпилированы, пока не будет скомпилирован этот. Медленный файл с большим количеством зависимых задерживает остальную часть сборки, а его изменение приводит к перекомпиляции всех них.
- **Зависимостям во время компиляции** — количеству файлов, которых ожидает этот файл.

![Обзор сборки Mix приложения Phoenix](/images/guides/features/elixir/build.png)

На вкладке **Временная шкала** показана та же сборка во времени: какие файлы компилировались параллельно, где сборка выполняла проверку типов и запись на диск, и какова была нагрузка на машину в каждый момент. Участок с одной полосой означает период, когда сборка не могла использовать имеющиеся ядра.

![Временная шкала полной сборки Mix приложения Phoenix](/images/guides/features/elixir/build-timeline.png)

На вкладках **Предупреждения** и **Ошибки** перечислены диагностики сборки.

## Пользовательские метаданные {#custom-metadata}

Добавляйте теги и данные в формате ключ-значение к сборкам Mix, чтобы различать запуски разных команд, оборудования или рабочих процессов. Оба вида данных отображаются на странице деталей каждой сборки.

Установите метаданные с помощью переменных окружения:

```sh
export TUIST_TAGS="nightly,release"
export TUIST_VALUES="ticket=TUIST-123,runner=linux-arm64"
```

Вы также можете настроить метаданные в `mix.exs`:

```elixir
tuist: [
  project: "account/project",
  tags: ["nightly", "release"],
  values: %{"ticket" => "TUIST-123", "runner" => "linux-arm64"}
]
```

Теги из обоих источников объединяются. Если один и тот же ключ настроен в обоих местах, приоритет имеет значение из переменной окружения.

Теги могут содержать только буквы, цифры, дефисы и знаки подчеркивания. Сборка может иметь до 50 тегов, каждый из которых может содержать до 50 символов. Сборка может иметь до 20 записей в формате ключ-значение, каждый ключ может содержать до 50 символов, а каждое значение — до 500 символов. Это те же ограничения на стороне сервера, что и для метаданных сборок Xcode. Пакет пропускает недопустимые теги и слишком большие или пустые записи метаданных перед отправкой отчета, поэтому неверная конфигурация не помешает сохранению остальной части отчета о сборке. Используйте метаданные в формате ключ-значение для значений, которые не соответствуют ограничениям для тегов.

Пользовательские метаданные прикрепляются к сборкам, а не к запускам тестов.

Пользовательские метаданные видны участникам проекта в панели управления. Не используйте их для учетных данных, токенов доступа или других конфиденциальных данных. Tuist хранит данные сборок Mix, включая эти метаданные, в течение 90 дней. Подробнее см. в <.localized_link href="/guides/server/data-retention">политике хранения данных</.localized_link>.

## Устранение неполадок {#troubleshooting}

Отправка отчетов никогда не изменяет результат вашей сборки: если отчет не может быть отправлен, сборка завершается так, как должна была, и ничего не выводится. Чтобы узнать, почему отчет не был отправлен, установите `TUIST_DEBUG=1`:

```bash
TUIST_DEBUG=1 mix compile --force
```
