# Аналитика сборок Elixir {#elixir-build-insights}

Пакет Tuist для Hex может отправлять аналитику сборок в Tuist. Время сборки, граф зависимостей между вашими файлами и то, как они меняются со временем, дают вам информацию, необходимую для оптимизации графа сборки и максимального использования всех ядер, доступных в среде, где происходит компиляция.

> [!IMPORTANT] REQUIREMENTS
> - Завершите <.localized_link href="/guides/get-started/elixir-project">Начало работы с Elixir</.localized_link>

## Отправка отчетов о сборках {#report-your-builds}

Общая настройка устанавливает интеграцию компиляции. Продолжайте использовать ваши обычные команды:

```bash
mix compile
```

Интеграция охватывает `mix compile` и каждую компиляцию, которую запускает другая задача, например `mix test` или `mix phx.server`. Компиляция, которая не находит работы, не отправляется в отчет, поэтому панель управления показывает только сборки, которые выполнили работу.

## Отправка информации об акторе {#report-actor-claim}

Запросы на отправку отчетов о сборке и тестировании Mix включают необязательный заголовок `x-tuist-actor-id` только тогда, когда вы явно настроите метку. Установите `TUIST_ACTOR_ID` в метку, ограниченную организацией, или добавьте `actor_id: "developer-label"` в конфигурацию `tuist` проекта. При разрешении приоритет отдается переменной окружения, затем параметрам времени выполнения `:actor_id`, затем конфигурации проекта. По умолчанию метка не отправляется, и пакет не определяет имена пользователей операционной системы. Фиксированная метка проекта применяется ко всем, кто использует эту конфигурацию. Пустые или недопустимые переопределения пропускают утверждение вместо возврата к предыдущему значению; это не удаляет проверенную идентификацию на основе учетных данных. Если пользовательский прокси отклоняет неизвестные заголовки, откажитесь от отправки с помощью `TUIST_ACTOR_ID=""`.

Идентификаторы должны состоять из 1–128 байт печатных символов ASCII, исключая пробелы. Недопустимые переопределения пропускаются без возврата к предыдущему значению. Проверенные индивидуальные учетные данные имеют приоритет; другие идентификаторы, сообщаемые клиентом, отображаются как **Непроверено**, никогда не авторизуют доступ и никогда не связываются автоматически с пользователями. Любой, кто может просматривать отчеты проекта, видит эти идентификаторы, включая публичных зрителей, если проект общедоступен, и они включаются в экспорт данных, поэтому не включайте секретные данные. Старые серверы игнорируют необязательный заголовок, а новые серверы принимают старых клиентов без него. Новые отчеты с общим токеном без идентификатора показывают **Неизвестно**, а не публикующую организацию; исторические отчеты сохраняют свою предыдущую атрибуцию. Отчетность о сборках и тестах по умолчанию требует аутентификации. Самостоятельно размещенные установки могут явно включить отчетность без учетных данных, как описано ниже.

## Отчетность без учетных данных в частной сети {#network-trusted-publishing}

После того как оператор настроит `TUIST_NETWORK_TRUSTED_INSIGHTS_ACCESS=true` на экземпляре и перезапустит его, как описано в <.localized_link href="/guides/server/self-host/server#network-trusted-access">руководстве по самостоятельному размещению</.localized_link>, настройте ваше назначение. SDK автоматически обнаруживает, разрешает ли экземпляр отчетность без учетных данных, когда учетные данные отсутствуют. Настройка экземпляра охватывает каждый поддерживаемый проект и не имеет переключателя на панели управления:

```elixir
tuist: [
  url: "https://tuist.internal.example",
  project: "account/project"
]
```

`mix tuist.compile` и `mix tuist.test` публикуют структурированные отчеты без входа в систему, когда учетные данные действительно отсутствуют и обнаружение подтверждает, что сервер это разрешает. Никакой флаг клиента или согласие проекта не требуется. Предоставленные учетные данные, включая предоставленную идентификацию CI OIDC, используются или отклоняются, но никогда не игнорируются для перехода к неподписанной отчетности. `TUIST_TOKEN`, содержащий только пробельные символы, является ошибкой. Пустой `TUIST_TOKEN` может вернуться к действительным сохраненным учетным данным или предоставленному OIDC, а устаревшие сохраненные учетные данные могут вернуться к предоставленному OIDC; оба пути остаются аутентифицированными и никогда не включают неподписанную отчетность. Непригодные учетные данные сохраняются и приводят к ошибке, если ни один аутентифицированный вариант возврата не succeeds. Обновите каждую реплику сервера до версии, поддерживающей обнаружение, перед обновлением клиентов, работающих без учетных данных; старые серверы без обнаружения, отключенные экземпляры и сбои обнаружения все еще требуют аутентификации.

Неподписанные запуски являются телеметрией, а не доверенными доказательствами нестабильности, карантина, покрытия или выборочного выполнения. Планирование шардов, архивы сборок и конечные точки покрытия/артефактов все еще требуют учетных данных. Установите `TUIST_ACTOR_ID=""` независимо, чтобы пропустить настроенное утверждение об акторе; проверенная идентификация учетных данных не затрагивается.

## Что отслеживается {#what-is-tracked}

Для каждой сборки пакет собирает:
- Ее продолжительность, успешность, а также среду Elixir, Erlang/OTP и Mix, в которой она выполнялась
- Каждое предупреждение и ошибку, с указанием файла и строки
- Сколько времени заняла компиляция каждого файла и какие модули он определяет
- Файлы, от которых зависит каждый файл, и нужны ли они во время компиляции или только во время выполнения
- Что делала сборка помимо компиляции файлов, например, проверка типов, запись на диск и другие компиляторы Mix
- Использование процессора, памяти, сети и диска машиной во время сборки
- Ветку и коммит, а при непрерывной интеграции — провайдера и запуск

## Поиск причин замедления сборки {#find-what-slows-a-build-down}

Откройте сборку из раздела **Сборки → Запуски сборок** на панели управления. Сборки, количество их диагностик и сводки кэша зависимостей также доступны через `tuist build mix list` и `tuist build mix show`, `GET /api/projects/{account_handle}/{project_handle}/mix/builds`, а также инструменты `list_mix_builds` и `get_mix_build` <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>.

На вкладке **Обзор** перечислены файлы, которые были скомпилированы сборкой. Вы можете группировать их по модулям, искать и сортировать по:
- **Продолжительности компиляции**, чтобы найти файлы, которые сами по себе медленные.
- **Зависимым во время компиляции**, количеству файлов, которые не могут быть скомпилированы, пока не будет скомпилирован этот. Медленный файл с большим количеством зависимых файлов задерживает остальную часть сборки, а его изменение приводит к перекомпиляции всех них.
- **Зависимостям во время компиляции**, количеству файлов, которых ожидает этот файл.

![Обзор сборки Mix приложения Phoenix](/images/guides/features/elixir/build.png)

Вкладка **Временная шкала** показывает ту же сборку во времени: какие файлы компилировались параллельно, где сборка выполняла проверку типов и запись на диск, и как работала машина в каждый момент. Участок с одной полосой — это период, когда сборка не могла использовать имеющиеся ядра.

![Временная шкала полной сборки Mix приложения Phoenix](/images/guides/features/elixir/build-timeline.png)

Вкладки **Предупреждения** и **Ошибки** перечисляют диагностики сборки.

## Пользовательские метаданные {#custom-metadata}

Прикрепляйте теги и данные типа «ключ-значение» к сборкам Mix, чтобы различать запуски от разных команд, оборудования или рабочих процессов. И то, и другое отображается на странице деталей каждой сборки.

Установите метаданные с помощью переменных окружения:

```sh
export TUIST_TAGS="nightly,release"
export TUIST_VALUES="ticket=TUIST-123,runner=linux-arm64"
```

Вы также можете настроить метаданные в `mix.exs`:

```elixir
tuist: [
  project: "account/project",
  tags: ["nightly", "release"],
  values: %{"ticket" => "TUIST-123", "runner" => "linux-arm64"}
]
```

Теги из обоих источников объединяются. Если один и тот же ключ настроен в обоих местах, приоритет имеет значение из переменной окружения.

Теги должны содержать только буквы, цифры, дефисы и знаки подчеркивания. Сборка может иметь до 50 тегов, каждый тег может содержать до 50 символов. Сборка может иметь до 20 записей типа «ключ-значение», каждый ключ может содержать до 50 символов, а каждое значение — до 500 символов. Это те же ограничения на стороне сервера, что и для метаданных сборки Xcode. Пакет пропускает недопустимые теги и слишком большие или пустые записи метаданных перед отправкой отчета, поэтому неверная конфигурация не помешает сохранению остальной части отчета с аналитикой сборки. Используйте метаданные типа «ключ-значение» для значений, которые не соответствуют ограничениям для тегов.

Пользовательские метаданные прикрепляются к сборкам, а не к запускам тестов.

Пользовательские метаданные видны участникам проекта в панели управления. Не используйте их для учетных данных, токенов доступа или других конфиденциальных данных. Tuist хранит данные сборок Mix, включая эти метаданные, в течение 90 дней. Подробнее см. в <.localized_link href="/guides/server/data-retention">политике хранения данных</.localized_link>.

## Устранение неполадок {#troubleshooting}

Отправка отчетов никогда не влияет на результат вашей сборки: если отчет не удается отправить, сборка завершается так, как должна была, и ничего не выводится. Чтобы узнать, почему отчет не был отправлен, установите `TUIST_DEBUG=1`:

```bash
TUIST_DEBUG=1 mix compile --force
```
