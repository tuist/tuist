## Публикация отчётов без учётных данных в частной сети {#network-trusted-publishing}

Развёртывание на собственном сервере позволяет разработчикам публиковать готовые отчёты без входа в систему. Оператор должен настроить `TUIST_NETWORK_TRUSTED_INSIGHTS_ACCESS=true` на экземпляре и перезапустить его, как описано в <.localized_link href="/guides/server/self-host/server#network-trusted-access">руководстве по самостоятельному размещению</.localized_link>. Это относится ко всем поддерживаемым проектам; отдельной настройки в панели управления нет. Настройте URL-адрес собственного сервера и проект в окружении, используемом пост-действием вашей схемы или терминалом. CLI автоматически определяет политику экземпляра, если учётные данные отсутствуют:

```sh
export TUIST_URL="https://tuist.internal.example"
tuist inspect build
# To publish local test results:
tuist inspect test
```

При полном отсутствии учётных данных журналы активности и пакеты XCResult анализируются локально и отправляются в виде структурированных отчётов. Не передаются необработанные архивы, вложения, данные покрытия/истории, удалённые процессоры, ссылки на шарды или доказательства выборочного выполнения. Отчёты остаются видимыми, но не могут обновлять состояние аутентифицированных тестовых случаев или запускать автоматизацию карантина/сбоев. Для доступа к панелям управления и другим привилегированным командам всё ещё требуется вход в систему. Оставьте интеграцию кэша отключённой, если экземпляр отдельно не включает доверенный сетевой доступ к кэшу или не предоставлены учётные данные.

Текущие учётные данные остаются аутентифицированными. Недействительные, повреждённые, пустые или отклонённые при обновлении учётные данные приводят к отказу в доступе и сохраняются на диске, поэтому последующие команды не становятся неавторизованными незаметно. Войдите в систему снова или явно выйдите из неё как осознанное действие восстановления. Обновите каждую реплику сервера до версии с поддержкой обнаружения перед обновлением клиентов, работающих без учётных данных, и настройте конечный URL-адрес сервера без перенаправлений. Старые серверы без поддержки обнаружения, отключённые экземпляры и сбои обнаружения по-прежнему требуют аутентификации. Опциональное включение на стороне клиента не требуется. Установите `TUIST_ACTOR_ID=""` отдельно, чтобы исключить настроенное утверждение об акторе; проверенная идентичность учётных данных не затрагивается.
