# Аналитика сборок Rust {#rust-build-insights}

Build Insights помогает найти, что замедляет ваши сборки Cargo, и выявить регрессии до того, как они повлияют на всю команду. Вы можете сравнивать локальные сборки со сборками в CI, отслеживать изменения времени сборки и анализировать крейты, скомпилированные в каждой сборке.

> [!IMPORTANT] Requirements
> - Следуйте <.localized_link href="/guides/get-started/rust-project">настройке проекта Rust</.localized_link>, чтобы подключить свой проект и пройти аутентификацию.

## Отправка отчетов о сборках {#report-your-builds}

Выполняйте обычные команды Cargo через Tuist:

```sh
tuist cargo build --workspace
tuist cargo check --all-targets
tuist cargo +nightly build --features tracing
```

Если вы используете mise, <.localized_link href="/guides/get-started/rust-project#keep-typing-cargo">настройте обёртку для Cargo</.localized_link>, чтобы продолжать использовать обычные команды `cargo`. Ваши аргументы, выбор инструментария, вывод и код завершения останутся прежними.

## Поиск причин замедления сборки {#explore-your-builds}

Откройте сборку из раздела **Сборки → Запуски сборок** на панели управления. Используйте фильтры по дате, окружению и версии Rust, чтобы сравнивать похожие сборки. Сборки и их счётчики кэша также доступны через `tuist build cargo list` и `tuist build cargo show`, `GET /api/projects/{account_handle}/{project_handle}/cargo/builds`, а также через `list_cargo_builds` и `get_cargo_build` <.localized_link href="/guides/features/agentic-coding/mcp">инструменты MCP</.localized_link>.

На вкладке **Обзор** используйте раздел **Задачи компилятора**, чтобы найти медленные крейты. Сортируйте по **Длительности** или **Начато после** (время с момента запуска команды Cargo) или выполняйте поиск по имени крейта или корневому исходному файлу.

Каждая строка представляет один вызов `rustc` для крейта, который может содержать множество исходных файлов. **Корень крейта** указывает на его корневой исходный файл; длительность относится ко всей задаче компилятора, а не только к этому файлу. Крейт может встречаться более одного раза для разных целей или конфигураций. Сообщения компилятора группируются в разделах **Предупреждения** и **Ошибки**.

## Чтение временных меток {#timing-boundaries}

Длительность сборки — это время, затраченное на выполнение всей команды Cargo. Задачи компилятора могут выполняться параллельно, поэтому их длительность не суммируется в общую длительность сборки.

Cargo компилирует только те крейты, которые требуют пересборки. Крейты, которые уже актуальны, не отображаются в списке компилятора. При использовании кэша компиляции Tuist восстановленные задачи отображаются в измерениях кэша, а не как выполнения компилятора.

Tuist не измеряет скрипты сборки отдельно и не показывает временную шкалу сборки. Для больших сборок отображаются первые 500 задач компилятора с уведомлением, если было записано больше.

## Чтение измерений кэша {#cache-measurements}

`tuist cargo` включает экспериментальный кэш компиляции, реализованный в CLI Tuist. Следуйте <.localized_link href="/guides/features/cache/rust">руководству по кэшированию для Rust</.localized_link> для настройки, удалённого чтения и записи через Kura, поддерживаемых компиляций и устранения неполадок.

Откройте раздел **Cargo Cache** на боковой панели проекта, чтобы отслеживать процент попаданий в кэш, а также зафиксированные показатели передачи, задержки и пропускной способности across сборок. Фильтруйте по дате или окружению, переключайтесь между дневными трендами и процентом попаданий для отдельных сборок или откройте недавнюю сборку для анализа активности кэша. Сборки без измерений кэша остаются недоступными, а не учитываются как нулевые.

Откройте вкладку **Кэш** сборки, чтобы увидеть попадания задач, промахи, процент попаданий, а также объем загруженных и выгруженных данных. Вкладка появляется, когда сборка сообщает данные кэша.

- Раздел **Задачи, поддающиеся кэшированию** показывает, какие задачи компилятора и скриптов сборки повторно использовали кэшированные результаты. Выполняйте поиск или фильтрацию задач, анализируйте задержки чтения/записи кэша и разверните строку, чтобы увидеть ее выходные данные.
- Раздел **Выходы CAS** показывает загрузки и выгрузки артефактов с указанием их размеров, длительности и пропускной способности. Диаграмма учитывает завершенные передачи; уже присутствующие артефакты и неудачные попытки остаются в таблице.

**Попадание** означает, что кэшированные результаты были повторно использованы. **Промах** означает, что задача была скомпилирована заново. Попадания не разделяются на локальные и удаленные; раздел Выходы CAS показывает зафиксированные операции с артефактами.

Если подробные записи отсутствуют или неполны, на странице отображается уведомление. Сводка все равно охватывает всю сборку. Оцененная избегнутая работа компилятора — это **не сэкономленное время сборки**.

> [!WARNING] Experimental compilation cache
> Первая версия кэширует только библиотеки листьев реестра с проверенными входами и выходами. Крейты рабочего пространства, скрипты сборки, процедурные макросы, зависимости от других крейтов, инкрементальная компиляция, нативное линкование и исполняемые файлы собираются обычным образом. Ключи кэша сохраняют абсолютные пути, поэтому повторное использование при разных путях checkout пока не поддерживается.

### Сборки, запускающие тесты {#builds-that-run-tests}

`tuist cargo test` сообщает длительность всей команды, включая её тесты. Также сообщаются результаты отдельных тестов, включая doctests, через <.localized_link href="/guides/features/test-insights/rust">аналитику тестов Rust</.localized_link>. Результаты отдельных тестов отображаются в разделе **Тесты**; длительность команды отображается в аналитике сборок.

## Другие инструменты компилятора {#other-compiler-tools}

Tuist сохраняет существующие обертки компилятора, настроенные через `RUSTC_WRAPPER`, `CARGO_BUILD_RUSTC_WRAPPER` или конфигурацию Cargo, и оставляет `RUSTC_WORKSPACE_WRAPPER` без изменений. Существующая глобальная обертка отключает кэш Tuist и наблюдатель компилятора: Tuist не может определить, действительно ли эта обертка запускала rustc. Пользовательские обертки рабочего пространства также могут привести к меньшему количеству задач компилятора в отчете.

Tuist находит Cargo через rustup. Если вы используете нестандартную установку, установите `TUIST_CARGO_EXECUTABLE` равным пути к исполняемому файлу. Вызов Cargo по прямому пути инструментария обходит обертку mise. Алиас Cargo не может заменить встроенную команду, такую как `build`.

Если вы используете ночную опцию Cargo `-C`, сначала перейдите в рабочее пространство: Tuist передает команды `-C`, но не собирает их временные метки сборки.

## Устранение неполадок {#troubleshooting}

Если сборка не отображается на панели управления, включите отладочный вывод, чтобы узнать, почему отчет не был отправлен:

```sh
TUIST_DEBUG=1 tuist cargo build --workspace
```

Отчетность не влияет на результат вашей сборки.
