# Аналитика сборок Rust {#rust-build-insights}

Build Insights помогает найти, что замедляет ваши сборки Cargo, и обнаружить регрессии до того, как они повлияют на всю команду. Вы можете сравнивать локальные сборки со сборками в CI, отслеживать изменения времени сборки и изучать крейты, скомпилированные в каждой сборке.

> [!IMPORTANT] Requirements
> - Следуйте <.localized_link href="/guides/get-started/rust-project">настройке проекта Rust</.localized_link>, чтобы подключить проект и пройти аутентификацию.

## Отправляйте отчеты о сборках {#report-your-builds}

Запускайте обычные команды Cargo через Tuist:

```sh
tuist cargo build --workspace
tuist cargo check --all-targets
tuist cargo +nightly build --features tracing
```

Если вы используете mise, <.localized_link href="/guides/get-started/rust-project#keep-typing-cargo">настройте обёртку для Cargo</.localized_link>, чтобы продолжать использовать обычные команды `cargo`. Ваши аргументы, выбор тулчейна, вывод и код завершения останутся прежними.

## Найдите причину замедления сборки {#explore-your-builds}

Откройте сборку в разделе **Сборки → Запуски сборок** на панели управления. Используйте фильтры по дате, окружению и версии Rust, чтобы сравнивать похожие сборки. Данные о сборках и их счётчиках кэша также доступны через `tuist build cargo list` и `tuist build cargo show`, `GET /api/projects/{account_handle}/{project_handle}/cargo/builds`, а также через инструменты `list_cargo_builds` и `get_cargo_build` <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>.

На вкладке **Обзор** используйте раздел **Задачи компилятора**, чтобы найти медленные крейты. Сортируйте по **Длительности** или **Началу после** (время с момента запуска команды Cargo) или выполняйте поиск по имени крейта или корневому исходному файлу.

Каждая строка представляет один вызов `rustc` для крейта, который может содержать множество исходных файлов. **Корень крейта** указывает его корневой исходный файл; длительность относится ко всей задаче компилятора, а не только к этому файлу. Крейт может встречаться несколько раз для разных целей или конфигураций. Сообщения компилятора сгруппированы в разделах **Предупреждения** и **Ошибки**.

### Отслеживайте крейты между сборками {#crate-history}

Для проектов, подключенных к поэтапному внедрению истории крейтов, раздел **Сборки → Крейты** показывает наблюдаемые крейты и историю их компиляции. Откройте крейт, чтобы сравнить зафиксированные длительности и результаты между сборками, а затем перейдите от компиляции к соответствующей сборке Cargo. Тот же инвентарь доступен через `/cargo/crates` в API проекта и общие инструменты сущностей сборки MCP с параметром `kind: cargo_crates`.

Крейты группируются по точному записанному корневому пути, имени и типу. Изменение путей 체크아웃 может разделить историю; профили, функции и тройки целей не различаются. Это инвентарь наблюдаемых задач компилятора, а не всех крейтов в вашем рабочем пространстве. Кэшированные или актуальные крейты не создают образцы компиляции.

### Атрибуция отчетов о сборках {#report-attribution}

Аутентифицированные отчеты идентифицируют пользователя, использующего личные учетные данные. Общие учетные данные могут не указывать конкретного пользователя. При необходимости установите для `TUIST_ACTOR_ID` стабильный непрозрачный идентификатор на машине, отправляющей отчет; по умолчанию эта функция отключена, и значение отображается как непроверенное утверждение, которое никогда не используется для авторизации. Старые серверы могут игнорировать это утверждение. Не помещайте в него секреты.

## Анализ временных показателей {#timing-boundaries}

Длительность сборки — это время, затраченное на выполнение всей команды Cargo. Задачи компилятора могут выполняться параллельно, поэтому их длительности не суммируются в общую длительность сборки.

Cargo компилирует только те крейты, которые требуют пересборки. Крейты, которые уже актуальны, не появятся в списке компилятора. При использовании кэша компиляции Tuist восстановленные задачи отображаются в измерениях кэша, а не как выполнения компилятора.

Tuist не измеряет скрипты сборки отдельно и не показывает временную шкалу сборки. В большой сборке отображаются первые 500 задач компилятора с уведомлением, если было записано больше.

## Анализ измерений кэша {#cache-measurements}

`tuist cargo` включает экспериментальный кэш компиляции, реализованный в CLI Tuist. Следуйте <.localized_link href="/guides/features/cache/rust">руководству по кэшированию для Rust</.localized_link> для настройки, удалённого чтения и записи через Kura, поддерживаемых компиляций и устранения неполадок.

Откройте раздел **Cargo Cache** на боковой панели проекта, чтобы отслеживать процент попаданий в кэш и зафиксированные показатели передачи, задержки и пропускной способности между сборками. Фильтруйте по дате или окружению, переключайтесь между дневными трендами и процентом попаданий для отдельных сборок или откройте недавнюю сборку, чтобы изучить активность кэша. Сборки без измерений кэша остаются недоступными, а не учитываются как нулевые.

Откройте вкладку **Кэш** сборки, чтобы увидеть попадания задач, промахи задач, процент попаданий, а также объем загруженных и выгруженных данных. Вкладка появляется, когда сборка сообщает данные кэша.

- Раздел **Задачи, поддающиеся кэшированию** показывает, какие задачи компилятора и скриптов сборки повторно использовали кэшированные выходные данные. Ищите или фильтруйте задачи, изучайте задержку чтения/записи кэша и разверните строку, чтобы увидеть ее выходные данные.
- Раздел **Выходные данные CAS** показывает загрузки и выгрузки артефактов с указанием их размеров, длительности и пропускной способности. Диаграмма учитывает завершенные передачи; уже присутствующие артефакты и неудачные попытки остаются в таблице.

**Попадание** означает, что кэшированные выходные данные были повторно использованы. **Промах** означает, что задача была скомпилирована заново. Попадания не разделяются на локальные и удаленные; раздел «Выходные данные CAS» показывает записанные операции с артефактами.

Если подробные записи отсутствуют или неполны, страница показывает уведомление. Сводка все равно охватывает всю сборку. Оцененная избежанная работа компилятора **не равна сэкономленному времени сборки**.

> [!WARNING] Experimental compilation cache
> Первая версия кэширует только библиотечные конечные узлы реестра с проверенными входными и выходными данными. Крейты рабочего пространства, скрипты сборки, процедурные макросы, зависимости от других крейтов, инкрементальная компиляция, нативная линковка и исполняемые файлы собираются обычным образом. Ключи кэша сохраняют абсолютные пути, поэтому повторное использование при разных путях 체크아웃 пока не поддерживается.

### Сборки, запускающие тесты {#builds-that-run-tests}

`tuist cargo test` сообщает длительность выполнения всей команды, включая её тесты. Также он передаёт результаты отдельных тестов, включая doctests, через <.localized_link href="/guides/features/test-insights/rust">аналитику тестов Rust</.localized_link>. Результаты отдельных тестов отображаются в разделе **Тесты**; длительность команды — в аналитике сборок.

## Другие инструменты компилятора {#other-compiler-tools}

Tuist сохраняет существующие обертки компилятора, настроенные через `RUSTC_WRAPPER`, `CARGO_BUILD_RUSTC_WRAPPER` или конфигурацию Cargo, и оставляет `RUSTC_WORKSPACE_WRAPPER` без изменений. Существующая глобальная обертка отключает кэш Tuist и наблюдатель компилятора: Tuist не может установить, действительно ли эта обертка запускала rustc. Пользовательские обертки рабочего пространства также могут привести к меньшему количеству задач компилятора в отчете.

Tuist находит Cargo через rustup. Если вы используете пользовательскую установку, установите для `TUIST_CARGO_EXECUTABLE` путь к исполняемому файлу. Вызов Cargo по прямому пути инструментария обходит обертку mise. Алиас Cargo не может заменить встроенную команду, такую как `build`.

Если вы используете ночную опцию Cargo `-C`, сначала перейдите в рабочее пространство: Tuist перенаправляет команды `-C`, но не собирает данные о времени их выполнения.

## Устранение неполадок {#troubleshooting}

Если сборка не отображается на панели управления, включите отладочный вывод, чтобы узнать, почему её отчет не был отправлен:

```sh
TUIST_DEBUG=1 tuist cargo build --workspace
```

Отправка отчета не влияет на результат вашей сборки.
