# Аналитика сборок Rust {#rust-build-insights}

Build Insights помогает определить, что замедляет ваши сборки Cargo, и выявить регрессии до того, как они повлияют на всю команду. Вы можете сравнивать локальные сборки со сборками в CI, отслеживать изменения времени сборки и анализировать крейты, скомпилированные в каждой сборке.

> [!IMPORTANT]
> **Требования**
>
> - Выполните <.localized_link href="/guides/get-started/rust-project">настройку проекта Rust</.localized_link>, чтобы подключить проект и пройти аутентификацию.

## Отправка отчётов о сборках {#report-your-builds}

Запускайте обычные команды Cargo через Tuist:

```sh
tuist cargo build --workspace
tuist cargo check --all-targets
tuist cargo +nightly build --features tracing
```

Если вы используете mise, <.localized_link href="/guides/get-started/rust-project#keep-typing-cargo">настройте обёртку для Cargo</.localized_link>, чтобы продолжать использовать обычные команды `cargo`. Ваши аргументы, выбор инструментария, вывод и код завершения останутся прежними.

## Поиск причин замедления сборки {#explore-your-builds}

Откройте сборку в разделе **Сборки → Запуски сборок** на панели управления. Используйте фильтры по дате, окружению и версии Rust, чтобы сравнивать похожие сборки. Данные о сборках и их счётчиках кэша также доступны через `tuist build cargo list` и `tuist build cargo show`, `GET /api/projects/{account_handle}/{project_handle}/cargo/builds`, а также инструменты `list_cargo_builds` и `get_cargo_build` <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>.

На вкладке **Обзор** используйте раздел **Задачи компилятора**, чтобы найти медленные крейты. Сортируйте по **Длительности** или **Началу после** (время с момента запуска команды Cargo) или выполняйте поиск по имени крейта или корневому исходному файлу.

Каждая строка соответствует одному вызову `rustc` для крейта, который может содержать множество исходных файлов. **Корень крейта** указывает его корневой исходный файл; длительность относится ко всей задаче компилятора, а не только к этому файлу. Один и тот же крейт может встречаться несколько раз для разных целей или конфигураций. Сообщения компилятора сгруппированы в разделах **Предупреждения** и **Ошибки**.

### Отслеживание крейтов между сборками {#crate-history}

Когда эта функция доступна для вашего проекта, раздел **Сборки → Крейты** показывает обнаруженные крейты и историю их компиляции. Откройте крейт, чтобы сравнить зафиксированные длительности и результаты между сборками, а затем перейдите от компиляции к соответствующей сборке Cargo. Тот же инвентарь доступен через `/cargo/crates` в API проекта и общие инструменты MCP для сущностей сборки с параметром `kind: cargo_crates`.

Крейты группируются по точно зафиксированному корневому пути, имени и типу. Изменение путей 체크아웃 может разделять истории; профили, функции и тройки целей не различаются. Это инвентарь наблюдаемых задач компилятора, а не всех крейтов в вашем рабочем пространстве. Кэшированные или актуальные крейты не создают образцы компиляции.

### Атрибуция отчётов о сборках {#report-attribution}

Аутентифицированные отчёты идентифицируют пользователя, использующего личные учётные данные. Общие учётные данные могут не указывать конкретного пользователя. При необходимости установите `TUIST_ACTOR_ID` в стабильный непрозрачный идентификатор на машине, отправляющей отчёт; по умолчанию эта функция отключена, значение отображается как непроверенное утверждение и никогда не используется для авторизации. Старые серверы могут игнорировать это утверждение. Не помещайте туда секреты.

## Чтение данных о времени выполнения {#timing-boundaries}

Длительность сборки — это время выполнения всей команды Cargo. Задачи компилятора могут выполняться параллельно, поэтому их длительности не суммируются в общую длительность сборки.

Cargo компилирует только те крейты, которые требуют пересборки. Крейты, которые уже актуальны, не появляются в списке компилятора. При использовании кэша компиляции Tuist восстановленные задачи отображаются в измерениях кэша, а не как выполнения компилятора.

Tuist не измеряет скрипты сборки отдельно и не показывает временную шкалу сборки. В большой сборке отображаются первые 500 задач компилятора с уведомлением, если было записано больше.

## Чтение измерений кэша {#cache-measurements}

`tuist cargo` включает экспериментальный кэш компиляции, реализованный в CLI Tuist. Следуйте <.localized_link href="/guides/features/cache/rust">руководству по кэшу для Rust</.localized_link> для настройки, удалённого чтения и записи через Kura, информации о поддерживаемых компиляциях и устранения неполадок.

Откройте раздел **Кэш Cargo** на боковой панели проекта, чтобы отслеживать процент попаданий в кэш и зафиксированные показатели передачи, задержки и пропускной способности между сборками. Фильтруйте по дате или окружению, переключайтесь между дневными трендами и процентом попаданий для отдельных сборок или откройте недавнюю сборку, чтобы изучить её активность кэша. Сборки без измерений кэша остаются недоступными, а не учитываются как нулевые.

Откройте вкладку **Кэш** сборки, чтобы увидеть попадания задач, промахи задач, процент попаданий, а также объём загруженных и выгруженных байтов. Вкладка появляется, когда сборка сообщает данные кэша.

- Раздел **Задачи, поддающиеся кэшированию** показывает, какие задачи компилятора и скриптов сборки повторно использовали кэшированные выходные данные. Ищите или фильтруйте задачи, изучайте задержку чтения/записи кэша и раскрывайте строку, чтобы увидеть её выходные данные.
- Раздел **Выходные данные CAS** показывает загрузки и выгрузки артефактов с указанием их размеров, длительности и пропускной способности. Диаграмма учитывает завершённые передачи; уже присутствующие артефакты и неудачные попытки остаются в таблице.

**Попадание** означает, что кэшированные выходные данные были повторно использованы. **Промах** означает, что задача была скомпилирована заново. Попадания не разделяются на локальные и удалённые; раздел «Выходные данные CAS» показывает зафиксированные операции с артефактами.

Если подробные записи отсутствуют или неполны, страница показывает уведомление. Сводка всё равно охватывает всю сборку. Оценённый объём избежанной работы компилятора **не равен сэкономленному времени сборки**.

Инкрементальные компиляции выполняются обычным образом.

### Сборки, выполняющие тесты {#builds-that-run-tests}

`tuist cargo test` сообщает длительность всей команды, включая её тесты. Также сообщаются результаты отдельных тестов, включая doctests, через <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link>. Результаты отдельных тестов отображаются в разделе **Тесты**; длительность команды отображается в аналитике сборок.

## Другие инструменты компилятора {#other-compiler-tools}

Tuist сохраняет существующие обёртки компилятора, настроенные через `RUSTC_WRAPPER`, `CARGO_BUILD_RUSTC_WRAPPER` или конфигурацию Cargo, и оставляет `RUSTC_WORKSPACE_WRAPPER` без изменений. Существующая глобальная обёртка отключает кэш Tuist и наблюдатель компилятора: Tuist не может установить, действительно ли эта обёртка запускала rustc. Пользовательские обёртки рабочего пространства также могут приводить к меньшему количеству задач компилятора в отчёте.

Tuist находит Cargo через rustup. Если вы используете пользовательскую установку, установите `TUIST_CARGO_EXECUTABLE` в путь к исполняемому файлу. Вызов Cargo по прямому пути инструментария обходит обёртку mise. Алиас Cargo не может заменить встроенную команду, такую как `build`.

Если вы используете ночную опцию Cargo `-C`, сначала перейдите в рабочее пространство: Tuist передаёт команды `-C`, но не собирает данные о времени их выполнения.

## Устранение неполадок {#troubleshooting}

Если сборка не отображается на панели управления, включите отладочный вывод, чтобы узнать, почему её отчёт не был отправлен:

```sh
TUIST_DEBUG=1 tuist cargo build --workspace
```

Отправка отчётов не изменяет результат вашей сборки.
