# Аналитика сборок Rust {#rust-build-insights}

Аналитика сборок помогает найти, что замедляет ваши сборки Cargo, и выявить регрессии до того, как они повлияют на всю команду. Вы можете сравнивать локальные сборки со сборками в CI, отслеживать изменения времени сборки и анализировать крейты, скомпилированные в каждой сборке.

> [!IMPORTANT]
> **Требования**
>
> - Следуйте инструкциям по <.localized_link href="/guides/get-started/rust-project">настройке проекта Rust</.localized_link>, чтобы подключить проект и пройти аутентификацию.

## Отправляйте отчеты о сборках {#report-your-builds}

Запускайте обычные команды Cargo через Tuist:

```sh
tuist cargo build --workspace
tuist cargo check --all-targets
tuist cargo +nightly build --features tracing
```

Если вы используете mise, <.localized_link href="/guides/get-started/rust-project#keep-typing-cargo">настройте обертку для Cargo</.localized_link>, чтобы продолжать использовать обычные команды `cargo`. Ваши аргументы, выбор тулчейна, вывод и код завершения останутся прежними.

## Найдите, что замедляет сборку {#explore-your-builds}

Откройте сборку из раздела **Builds → Build Runs** на дашборде. Используйте фильтры по дате, окружению и версии Rust, чтобы сравнивать похожие сборки. Данные о сборках и счетчики кэша также доступны через `tuist build cargo list` и `tuist build cargo show`, `GET /api/projects/{account_handle}/{project_handle}/cargo/builds`, а также инструменты `list_cargo_builds` и `get_cargo_build` <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>.

На вкладке **Overview** используйте раздел **Compiler jobs**, чтобы найти медленные крейты. Сортируйте по **Duration** или **Started after** (время с момента запуска команды Cargo) или выполняйте поиск по имени крейта или корневому исходному файлу.

Каждая строка соответствует одному вызову `rustc` для крейта, который может содержать множество исходных файлов. **Crate root** указывает на его корневой исходный файл; длительность относится ко всей задаче компилятора, а не только к этому файлу. Крейт может встречаться несколько раз для разных таргетов или конфигураций. Сообщения компилятора сгруппированы в разделах **Warnings** и **Errors**.

### Отслеживайте крейты между сборками {#crate-history}

Когда эта функция доступна для вашего проекта, раздел **Builds → Crates** показывает наблюдаемые крейты и историю их компиляции. Откройте крейт, чтобы сравнить записанные длительности и результаты между сборками, а затем перейдите от компиляции к соответствующей сборке Cargo. Тот же инвентарь доступен через `/cargo/crates` в API проекта и общие инструменты MCP для сущностей сборки с параметром `kind: cargo_crates`.

Крейты группируются по точному записанному корневому пути, имени и типу. Изменение путей 체크아웃 может разделить истории; профили, фичи и тройки таргетов не различаются. Это инвентарь наблюдаемых задач компилятора, а не всех крейтов в вашем воркспейсе. Закэшированные или актуальные крейты не создают образцы компиляции.

### Атрибуция отчетов о сборках {#report-attribution}

Аутентифицированные отчеты идентифицируют человека, использующего личные учетные данные. Общие учетные данные не обязаны указывать конкретного человека. При желании установите для `TUIST_ACTOR_ID` стабильный непрозрачный идентификатор на машине, отправляющей отчет; по умолчанию эта функция отключена, значение отображается как непроверенное утверждение и никогда не используется для авторизации. Старые серверы могут игнорировать это утверждение. Не помещайте в него секреты.

## Чтение временных метрик {#timing-boundaries}

Длительность сборки — это время выполнения всей команды Cargo. Задачи компилятора могут выполняться параллельно, поэтому их длительности не суммируются в общую длительность сборки.

Cargo компилирует только те крейты, которые требуют пересборки. Крейты, которые уже актуальны, не появятся в списке компилятора. При использовании кэша компиляции Tuist восстановленные задачи отображаются в измерениях кэша, а не как выполнения компилятора.

Tuist не измеряет скрипты сборки отдельно и не показывает временную шкалу сборки. В большой сборке отображаются первые 500 задач компилятора с уведомлением, если было записано больше.

## Чтение метрик кэша {#cache-measurements}

`tuist cargo` включает экспериментальный кэш компиляции, реализованный в CLI Tuist. Следуйте <.localized_link href="/guides/features/cache/rust">руководству по кэшу для Rust</.localized_link> для настройки, удаленного чтения и записи через Kura, поддерживаемых компиляций и устранения неполадок.

Откройте раздел **Cargo Cache** на боковой панели проекта, чтобы отслеживать процент попаданий в кэш, а также записанные измерения передачи, задержки и пропускной способности между сборками. Фильтруйте по дате или окружению, переключайтесь между дневными трендами и процентом попаданий для отдельных сборок или откройте недавнюю сборку, чтобы изучить активность кэша. Сборки без измерений кэша остаются недоступными, а не учитываются как нулевые.

Откройте вкладку **Cache** сборки, чтобы увидеть попадания задач, промахи задач, процент попаданий, а также объем загруженных и выгруженных байт. Вкладка появляется, когда сборка сообщает данные кэша.

- Раздел **Cacheable Tasks** показывает, какие задачи компилятора и скриптов сборки повторно использовали закэшированные выходные данные. Ищите или фильтруйте задачи, изучайте задержку чтения/записи кэша и разверните строку, чтобы увидеть ее выходные данные.
- Раздел **CAS Outputs** показывает загрузки и выгрузки артефактов с указанием их размеров, длительности и пропускной способности. Диаграмма учитывает завершенные передачи; уже присутствующие артефакты и неудачные попытки остаются в таблице.

**Hit** означает, что закэшированные выходные данные были повторно использованы. **Missed** означает, что задача была скомпилирована заново. Попадания не разделяются на локальные и удаленные; раздел CAS Outputs показывает записанные операции с артефактами.

Если подробные записи отсутствуют или неполны, страница показывает уведомление. Сводка все равно охватывает всю сборку. Оцененный объем избежанной работы компилятора **не равен сэкономленному времени сборки**.

### Сборки, запускающие тесты {#builds-that-run-tests}

`tuist cargo test` сообщает длительность всей команды, включая ее тесты. Также сообщаются результаты отдельных тестов, включая doctests, через <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link>. Результаты отдельных тестов отображаются в разделе **Tests**; длительность команды отображается в аналитике сборок.

## Другие инструменты компилятора {#other-compiler-tools}

Tuist сохраняет существующие обертки компилятора, настроенные через `RUSTC_WRAPPER`, `CARGO_BUILD_RUSTC_WRAPPER` или конфигурацию Cargo, и оставляет `RUSTC_WORKSPACE_WRAPPER` без изменений. Существующая глобальная обертка отключает кэш Tuist и наблюдатель компилятора: Tuist не может установить, действительно ли эта обертка запускала rustc. Пользовательские обертки воркспейса также могут привести к тому, что в отчете будет меньше задач компилятора.

Tuist находит Cargo через rustup. Если вы используете пользовательскую установку, установите для `TUIST_CARGO_EXECUTABLE` путь к исполняемому файлу. Вызов Cargo по прямому пути тулчейна обходит обертку mise. Алиас Cargo не может заменить встроенную команду, такую как `build`.

Если вы используете ночную опцию Cargo `-C`, сначала перейдите в воркспейс: Tuist передает команды `-C`, но не собирает их временные метрики сборки.

## Устранение неполадок {#troubleshooting}

Если сборка не отображается на дашборде, включите отладочный вывод, чтобы узнать, почему ее отчет не был отправлен:

```sh
TUIST_DEBUG=1 tuist cargo build --workspace
```

Отчетность не изменяет результат вашей сборки.
