# Аналитика сборок Struo {#struo-build-insights}

<a id="once-build-insights"></a>

Struo передаёт данные о запусках в Tuist во время их выполнения, поэтому вы можете отслеживать прогресс, не дожидаясь финального лога CI. Откройте ссылку на дашборд, которая выводится в начале запуска, чтобы просмотреть граф, статус действий и решения кэширования.

> [!IMPORTANT]
> **Требования**
>
> - Пройдите <.localized_link href="/guides/get-started/struo-project">Начало работы со Struo</.localized_link> и выполните аутентификацию машины, на которой работает Struo.

## Отправляйте данные о сборках {#report-your-builds}

Продолжайте использовать команды Struo:

```bash
struo build MyApplication
```

Живая отчётность работает по принципу best-effort. Недоступность конечной точки отчётности или истечение срока действия сессии не приводят к сбою сборки. Войдите снова с помощью `struo auth login --provider tuist`, если сессия истекла.

## Что показывает дашборд {#what-the-dashboard-shows}

Используйте разделы **Сборки** и **Запуски сборок** для сравнения запусков во времени, по веткам и в локальных или CI-средах. Каждый запуск может включать:

- Запрошенную команду, статус, время начала и длительность.
- Версию Struo и информацию о хосте.
- Действия и их зависимости, статус, длительность и результаты кэширования.
- Сообщённые ошибки действий.
- Ветку Git, коммит и контекст CI, если они переданы клиентом.

Ищите и фильтруйте действия, чтобы найти неудачные или медленные задачи. Имена действий и исходные файлы помогают связать работу с кодом; старые клиенты могут предоставлять меньше деталей. Кэшированные или пропущенные действия не являются выполненной работой, а отсутствие данных о времени не означает выполнение с нулевой длительностью.

Tuist в настоящее время не принимает необработанный поток логов действий Struo. Сохраняйте логи CI для полного вывода процесса; сводки запусков и структурированные ошибки не заменяют эти логи.

Представление **Кэш** разделяет решения по действиям и передачу объектов контента. См. <.localized_link href="/guides/features/cache/struo">Кэш Struo</.localized_link> для интерпретации активности кэша.

## Тесты {#tests}

Команды тестирования также создают запуски Struo. Их сообщённые наборы и кейсы отображаются в разделе **Тесты**; размещённые шарды дополнительно публикуют объединённый запуск тестов. См. <.localized_link href="/guides/features/test-insights/struo">Аналитика тестов Struo</.localized_link>.

## Агенты кодирования и Grafana {#coding-agents-and-grafana}

Инструменты <.localized_link href="/guides/features/agentic-coding/mcp#struo-runs">Model Context Protocol</.localized_link> позволяют агенту получать список запусков Struo и читать итоги по действиям и кэшу для конкретного запуска. Те же данные доступны через HTTP API.

Используйте <.localized_link href="/guides/integrations/grafana">интеграцию с Grafana</.localized_link> для финальных метрик здоровья сборок Struo. Struo в настоящее время не сообщает об экономии времени кэша, поэтому эта метрика остаётся недоступной, а не равной нулю.
