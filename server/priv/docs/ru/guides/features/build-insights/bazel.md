# Аналитика сборок Bazel {#bazel-build-insights}

Каждое завершённое выполнение `build`, `test` и других команд Bazel отображается на панели \*\***Invocations**\*\* проекта: тип команды, код выхода, время начала и окончания, длительность, а также попадания в кэш, промахи, загрузки и выгрузки, которые Bazel отнёс к этому же выполнению.

Данные о выполнении передаются через [Build Event Protocol](https://bazel.build/remote/bep) Bazel. Настройка подключает его автоматически при запуске `tuist bazel setup`; дополнительные флаги не требуются, чтобы начать видеть выполнения.

## Что показывает панель {#what-the-dashboard-shows}

Каждое выполнение записывает:

- Команду, которую запустил Bazel, её код выхода, время начала и окончания, а также общую длительность.
- Количество действий, целей и пакетов.
- Ограниченную временную шкалу сборки и сводку критического пути.
- Попадания в кэш, промахи, загрузки и выгрузки, отнесённые к выполнению.
- Строки журнала прогресса, захваченные во время выполнения, в порядке исполнения.
- Версию Bazel, ветку git и коммит, когда Bazel их сообщает, а также то, было ли выполнение запущено в CI.

Активность кэша, которую Bazel не может отнести к завершённому выполнению, например, когда команда прерывается в процессе выполнения, всё равно отображается в разделе проекта **Overview** как необработанное наблюдение удалённого кэша. Это не считается доказательством успешности команды, её длительности или результатов тестов.

## Пользовательские метаданные {#custom-metadata}

Привязывайте данные в формате «ключ-значение» к выполнениям, чтобы сравнивать запуски из разных команд, на разном оборудовании или в разных рабочих процессах. Значения отображаются на странице деталей каждого выполнения, а также через интерфейс прикладного программирования и инструменты Model Context Protocol.

Установите метаданные с помощью встроенного флага Bazel `--build_metadata`:

```bash
bazel build --build_metadata=TICKET=TUIST-123 --build_metadata=RUNNER=macos-14 //...
```

Или установите их один раз для каждого профиля в вашем `.bazelrc`:

```text
build:ci --build_metadata=RUNNER=macos-14
```

Каждое выполнение может содержать до 20 пользовательских записей. Ключи могут содержать до 50 символов, а значения — до 500 символов. Записи, превышающие эти ограничения, отбрасываются перед сохранением выполнения, поэтому недопустимая запись не препятствует сохранению остальной части отчёта.

Контекстные ключи, которые Tuist получает из среды сборки, такие как `CI`, `GIT_BRANCH` и `GIT_COMMIT`, не сохраняются как пользовательские значения, поскольку они уже заполняют основные поля выполнения.

Пользовательские метаданные видны участникам проекта на панели управления, а также через интерфейс прикладного программирования и инструменты Model Context Protocol. Не используйте их для учётных данных, токенов доступа или других конфиденциальных данных.

## Отказ от участия {#opting-out}

Поток Build Event Protocol передаёт аргументы командной строки, значения переменных окружения и вывод команд. Tuist сохраняет только перечисленные выше поля завершённых команд и отбрасывает остальные, но если вы предпочитаете вообще не отправлять поток событий, повторно запустите настройку с помощью:

```bash
tuist bazel setup --no-build-insights
```

Сгенерированный файл `.bazelrc.tuist` затем настраивает только удалённый кэш. Выполнения перестают отображаться на панели управления, а наблюдения кэша остаются на странице **Overview**.

## Хранение данных {#data-retention}

Tuist хранит выполнения Bazel и их журналы в течение 90 дней. См. <.localized_link href="/guides/server/data-retention">хранение данных</.localized_link> для получения полной информации о политике.
