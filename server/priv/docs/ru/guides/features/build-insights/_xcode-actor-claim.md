## Указание идентификатора актора {#report-actor-claim}

Запросы на создание отчётов включают необязательный заголовок `x-tuist-actor-id` только если вы явно зададите `TUIST_ACTOR_ID` в виде метки, привязанной к организации, например `TUIST_ACTOR_ID=employee-123 tuist inspect build`. По умолчанию метка не отправляется, и Tuist не определяет имена пользователей операционной системы. Пустое значение `TUIST_ACTOR_ID` исключает передачу идентификатора, но не удаляет верифицированную личность, подтверждённую учётными данными. Идентификаторы должны состоять из 1–128 байт печатных символов ASCII, кроме пробела; недопустимые переопределения игнорируются без возврата к предыдущему значению. Если пользовательский прокси отвергает неизвестные заголовки, откажитесь от передачи, установив пустое переопределение в переменных окружения.

Верифицированные индивидуальные учётные данные имеют приоритет; в остальных случаях идентификаторы, сообщённые клиентом, отображаются как **Неверифицировано** и никогда не предоставляют права доступа и не связываются с пользователями автоматически. Идентификаторы видны всем, кто может просматривать отчёты проекта, включая публичных зрителей, если проект общедоступен, и включаются в экспорт данных, поэтому не добавляйте в них секреты. Это относится к отчётам о сборках, тестах и событиях команд. Старые серверы игнорируют необязательный заголовок, а новые серверы принимают старые клиенты без него. Новые отчёты по общим токенам без идентификатора показывают **Неизвестно** вместо публикующей организации; исторические отчёты сохраняют прежнюю атрибуцию. В списках сборок и тестов верифицированные пользователи отделяются от неверифицированных идентификаторов, сообщённых клиентом. Аутентификация остаётся обязательной, если только self-hosted инстанс явно не включает отчётность без учётных данных и клиент не обнаруживает эту политику.

### Пост-действия схемы {#actor-claim-post-actions}

По умолчанию указание идентификатора актора отключено. Чтобы настроить его для пост-действия схемы, задайте `TUIST_ACTOR_ID` непосредственно в этом скрипте, а не полагайтесь на экспорт переменных оболочки. Xcode, запущенный из Dock, не наследует переменные из `~/.zshrc`. Чтобы явно отключить настроенное указание при использовании Homebrew, выполните:

```sh
export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"
export TUIST_ACTOR_ID=""
tuist inspect build
```

При использовании Mise переопределите значение после загрузки окружения Mise:

```sh
$HOME/.local/bin/mise x -C "$SRCROOT" -- env TUIST_ACTOR_ID="" tuist inspect build
```

Чтобы включить передачу, используйте явную метку вместо пустого значения.
