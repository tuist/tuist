## Заявление об акторе отчёта {#report-actor-claim}

Запросы на создание отчётов включают необязательный заголовок `x-tuist-actor-id` только тогда, когда вы явно устанавливаете `TUIST_ACTOR_ID` в метку, ограниченную организацией, например `TUIST_ACTOR_ID=employee-123 tuist inspect build`. По умолчанию метка не отправляется, и Tuist не определяет имена пользователей операционной системы. Пустое значение `TUIST_ACTOR_ID` исключает сообщаемый идентификатор, но не удаляет проверенную личность на основе учётных данных. Идентификаторы должны состоять из 1–128 байт печатных символов ASCII, кроме пробела; недопустимые переопределения пропускаются без возврата к предыдущему значению. Если пользовательский прокси-сервер отклоняет неизвестные заголовки, откажитесь от этой функции, установив пустое переопределение в переменных окружения.

Проверенные индивидуальные учётные данные имеют приоритет; в противном случае идентификаторы, сообщённые клиентом, отображаются как **Непроверенные** и никогда не предоставляют разрешения и не связываются с пользователями автоматически. Идентификаторы видны всем, кто может просматривать отчёты проекта, включая публичных зрителей, если проект общедоступен, и включаются в экспорт данных, поэтому не включайте в них секреты. Это относится к отчётам о сборках, тестах и событиях команд. Старые серверы игнорируют необязательный заголовок, а новые серверы принимают старых клиентов без него. Новые отчёты с общим токеном без идентификатора показывают **Неизвестно**, а не публикующую организацию; исторические отчёты сохраняют свою предыдущую атрибуцию. В списках сборок и тестов проверенные пользователи отделяются от непроверенных сообщаемых идентификаторов. Аутентификация остаётся обязательной, если только самостоятельно размещённый экземпляр явно не включает отчётность без учётных данных и клиент не обнаруживает эту политику.

### Пост-действия схемы {#actor-claim-post-actions}

Заявления об акторах по умолчанию отключены. Чтобы настроить такое заявление для пост-действия схемы, установите `TUIST_ACTOR_ID` непосредственно в этом скрипте, а не полагайтесь на экспорт переменных оболочки. Xcode, запущенный из Dock, не наследует переменные из `~/.zshrc`. Чтобы явно подавить настроенное заявление при использовании Homebrew, выполните:

```sh
export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"
export TUIST_ACTOR_ID=""
tuist inspect build
```

При использовании Mise переопределите значение после загрузки среды Mise:

```sh
$HOME/.local/bin/mise x -C "$SRCROOT" -- env TUIST_ACTOR_ID="" tuist inspect build
```

Используйте явную метку вместо пустого значения, чтобы активировать функцию.
