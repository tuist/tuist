## Заявление об акторе отчёта {#report-actor-claim}

Запросы на создание отчётов включают необязательный заголовок `x-tuist-actor-id` только в том случае, если вы явно задаёте `TUIST_ACTOR_ID` в виде метки, ограниченной организацией, например `TUIST_ACTOR_ID=employee-123 tuist inspect build`. По умолчанию метка не отправляется, и Tuist не определяет имена пользователей операционной системы. Пустое значение `TUIST_ACTOR_ID` исключает передаваемый идентификатор, но не удаляет верифицированную личность на основе учётных данных. Идентификаторы должны состоять из 1–128 байт печатных символов ASCII, кроме пробела; недопустимые переопределения игнорируются без возврата к предыдущему значению. Если пользовательский прокси отклоняет неизвестные заголовки, откажитесь от передачи, установив пустое переопределение через переменную окружения.

Верифицированные индивидуальные учётные данные имеют приоритет; идентификаторы, переданные клиентом, в остальных случаях отображаются как **Неверифицировано** и никогда не предоставляют права доступа и не связываются с пользователями автоматически. Идентификаторы видны всем, кто может просматривать отчёты проекта, включая публичных зрителей, если проект публичный, и включаются в экспорт данных, поэтому не добавляйте в них секреты. Это относится к отчётам о сборках, тестах и событиях команд. Старые серверы игнорируют этот необязательный заголовок, а новые серверы принимают старых клиентов без него. Новые отчёты с общим токеном без идентификатора показывают **Неизвестно**, а не публикующую организацию; исторические отчёты сохраняют прежнюю атрибуцию. В списках сборок и тестов верифицированные пользователи отделены от неверифицированных переданных идентификаторов. Аутентификация остаётся обязательной, если только саморазвёрнутый экземпляр явно не включает отчётность без учётных данных и клиент не обнаруживает эту политику.

### Пост-действия схемы {#actor-claim-post-actions}

Заявления об акторах по умолчанию отключены. Чтобы настроить такое заявление для пост-действия схемы, задайте `TUIST_ACTOR_ID` непосредственно в этом скрипте, а не полагайтесь на экспорт переменных оболочки. Xcode, запущенный из Dock, не наследует переменные из `~/.zshrc`. Чтобы явно подавить настроенное заявление при использовании Homebrew, выполните:

```sh
export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"
export TUIST_ACTOR_ID=""
tuist inspect build
```

При использовании Mise переопределите значение после загрузки окружения Mise:

```sh
$HOME/.local/bin/mise x -C "$SRCROOT" -- env TUIST_ACTOR_ID="" tuist inspect build
```

Чтобы включить передачу, используйте явную метку вместо пустого значения.
