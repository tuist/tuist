# Удалённое выполнение Struo {#struo-remote-execution}

<a id="once-remote-execution"></a>

Общий кэш позволяет избежать повторного выполнения работы, которую уже завершил другой компьютер. Удалённое выполнение также переносит подходящие промахи кэша с вашего компьютера: Struo планирует действия команд графа на одноразовых Linux-воркерах Tuist и получает их результаты через тот же кэш проекта.

> [!NOTE]
> Удалённое выполнение сейчас доступно только по приглашению. [Свяжитесь с нами](mailto:contact@tuist.dev), чтобы запросить доступ для вашего аккаунта.

> [!IMPORTANT]
> **Требования**
>
> - Аккаунт Tuist с включённым удалённым выполнением и доступной вычислительной ёмкостью.
> - Версия Struo с поддержкой удалённого выполнения Tuist.
> - Совместимый сервер, который объявляет образ воркера, конечную точку кэша, уровень параллелизма и абсолютный каталог выполнения. Серверы, не указывающие каталог, несовместимы с текущим клиентом Struo; Struo останавливается до загрузки работы.
> - Команды и тулчейны, которые могут выполняться на `linux/amd64` внутри объявленного образа воркера.

Это запускает действия графа, а не всю CI-задачу целиком. Настройка Struo не устанавливает оркестрацию рабочих процессов GitHub или GitLab.

## Настройка {#setup}

Пройдите <.localized_link href="/guides/get-started/struo-project">Начало работы со Struo</.localized_link>. Выберите одного и того же провайдера Tuist для кэширования и выполнения и зафиксируйте образ воркера, объявленный сервисом:

```toml
[infrastructures.tuist]
kind = "tuist"
account = "acme"
project = "app"
execution_image = "sha-REPLACE_WITH_THE_IMAGE_TAG"

[infrastructure.cache]
provider = "tuist"

[infrastructure.execution]
provider = "tuist"
```

Выполните аутентификацию с учётными данными, которые могут читать и записывать кэш проекта, затем запросите удалённое выполнение:

```bash
struo build --remote MyTarget
```

Замените цель и тег образа на свои. Struo проверяет объявленный образ, каталог выполнения, назначение кэша и ёмкость аккаунта перед загрузкой работы. Кэш и выполнение должны указывать на один и тот же проект.

## Подготовка действий для воркеров {#prepare-actions-for-workers}

- Объявите входные и выходные данные. Выходные данные должны оставаться в пределах рабочего каталога действия.
- Разрешайте инструменты внутри образа воркера, а не по абсолютным путям на инициирующем компьютере.
- Используйте действия, безопасные для повторного выполнения: сбой воркера или перезапуск сервиса могут привести к ещё одному запуску.
- Укладывайте таймауты в десятиминутный лимит действия сервиса. Неподдерживаемые требования, включая запрет сети, приводят к ошибке, а не к тихому локальному запуску.

Struo учитывает объявленную параллельность действий аккаунта и снижает нагрузку, когда очередь сервиса заполнена. Смена образа разделяет конфигурацию сборки и закэшированные результаты, предотвращая повторное использование между несовместимыми образами воркеров.

## Просмотр удалённого выполнения {#inspect-remote-execution}

В боковой панели проекта есть страница **Удалённое выполнение**. Её карточка **Аналитика** показывает количество выполнений и общее время выполнения за выбранный период, как описано в разделе <.localized_link href="/guides/features/cache/bazel-cache#running-actions-and-usage">Запуск действий и использование</.localized_link>. Телеметрия запусков Struo пока не различает удалённое выполнение и локальные действия, поэтому на странице нет данных о времени удалённого выполнения для каждого запуска или списка выполняющихся запусков. Здесь объясняется этот пробел и даётся ссылка на **Запуски сборки** для просмотра записанных деталей действий. Текущие выполняющиеся и поставленные в очередь удалённые действия доступны через MCP-инструмент `get_remote_execution_activity` и его REST-эндпоинт. Оба источника относятся к сервису выполнения, а не к каналам воркеров.

См. [Руководство по удалённому выполнению Struo](https://struo.run/docs/guide/infrastructure/tuist#run-actions-on-tuist-workers) по вопросам постановки в очередь, обновления аутентификации и переопределения конечных точек кэша. Перейдите к <.localized_link href="/guides/features/build-insights/struo">Аналитике сборок Struo</.localized_link>, чтобы просмотреть полученные запуски.
