# Удалённое выполнение Struo {#struo-remote-execution}

<a id="once-remote-execution"></a>

Общий кэш позволяет не повторять работу, которую уже выполнила другая машина. Удалённое выполнение также переносит подходящие промахи кэша с вашего компьютера: Struo планирует действия команд графа на одноразовых Linux-воркерах Tuist и получает их результаты через тот же кэш проекта.

> [!NOTE]
> Удалённое выполнение сейчас доступно только по приглашению. [Свяжитесь с нами](mailto:contact@tuist.dev), чтобы запросить доступ для вашей учётной записи.

> [!IMPORTANT]
> **Требования**
>
> - Учётная запись Tuist с включённым удалённым выполнением и доступной вычислительной ёмкостью.
> - Версия Struo с поддержкой удалённого выполнения Tuist.
> - Совместимый сервер, который объявляет образ воркера, конечную точку кэша, уровень параллелизма и абсолютный каталог выполнения. Серверы, не указывающие каталог, несовместимы с текущим клиентом Struo; Struo останавливается до начала загрузки работы.
> - Команды и тулчейны, которые могут выполняться на `linux/amd64` внутри объявленного образа воркера.

Так выполняются действия графа, а не вся задача CI. Настройка Struo не устанавливает оркестрацию рабочих процессов GitHub или GitLab.

## Настройка {#setup}

Выполните шаги из раздела <.localized_link href="/guides/get-started/struo-project">Начало работы со Struo</.localized_link>. Выберите одного и того же провайдера Tuist для кэширования и выполнения и зафиксируйте образ воркера, объявленный сервисом:

```toml
[infrastructures.tuist]
kind = "tuist"
account = "acme"
project = "app"
execution_image = "sha-REPLACE_WITH_THE_IMAGE_TAG"

[infrastructure.cache]
provider = "tuist"

[infrastructure.execution]
provider = "tuist"
```

Аутентифицируйтесь с учётными данными, имеющими права на чтение и запись кэша проекта, затем запросите удалённое выполнение:

```bash
struo build --remote MyTarget
```

Замените цель и тег образа на свои. Перед загрузкой работы Struo проверяет объявленный образ, каталог выполнения, назначение кэша и ёмкость учётной записи. Кэш и выполнение должны указывать на один и тот же проект.

## Подготовка действий для воркеров {#prepare-actions-for-workers}

- Объявите входные и выходные данные. Выходные данные должны оставаться внутри рабочего каталога действия.
- Разрешайте инструменты внутри образа воркера, а не по абсолютным путям на инициирующем компьютере.
- Используйте действия, безопасные для повторного выполнения: сбой воркера или перезапуск сервиса могут привести к ещё одному запуску.
- Укладывайте таймауты в десятиминутный лимит на действие сервиса. Неподдерживаемые требования, включая запрет сетевого доступа, приводят к ошибке, а не к незаметному локальному запуску.

Struo учитывает объявленную параллельность действий учётной записи и снижает нагрузку, когда очередь сервиса заполнена. Смена образа разделяет конфигурацию сборки и кэшированные результаты, предотвращая повторное использование между несовместимыми образами воркеров.

## Просмотр удалённого выполнения {#inspect-remote-execution}

В боковой панели проекта есть страница **Удалённое выполнение**. Карточка **Аналитика** показывает количество выполнений и общее время выполнения за выбранный период, как описано в разделе <.localized_link href="/guides/features/cache/bazel-cache#running-actions-and-usage">Выполнение действий и использование</.localized_link>. В релизах Struo новее 2.19.0 каждое удалённое действие указывает принадлежность к запуску Struo, поэтому страница также отображает графики времени ожидания в очереди и выполнения, а также список запусков с их удалёнными действиями, результатами и временными метриками, начиная с активных. Запуск открывает свою страницу в разделе **Запуски сборки**. Запуски от старых клиентов и действия, обслуженные из удалённого кэша, там не учитываются. Текущие выполняемые и поставленные в очередь удалённые действия доступны через инструмент MCP `get_remote_execution_activity` и его REST-эндпоинт. Оба источника данных относятся к сервису выполнения, а не к каналам воркеров.

См. [Руководство по удалённому выполнению Struo](https://struo.run/docs/guide/infrastructure/tuist#run-actions-on-tuist-workers) по вопросам постановки в очередь, обновления аутентификации и переопределения конечных точек кэша. Следуйте разделу <.localized_link href="/guides/features/build-insights/struo">Аналитика сборок Struo</.localized_link>, чтобы просмотреть получившиеся запуски.
