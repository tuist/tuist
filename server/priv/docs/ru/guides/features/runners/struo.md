# Удалённое выполнение Struo {#struo-remote-execution}

<a id="once-remote-execution"></a>

Общий кэш позволяет не повторять работу, которую уже выполнила другая машина. Удалённое выполнение также переносит подходящие промахи кэша с вашего компьютера: Struo планирует действия команд графа на одноразовых Linux-воркерах Tuist и получает их результаты через тот же кэш проекта.

> [!NOTE]
> Удалённое выполнение сейчас доступно только по приглашению. [Свяжитесь с нами](mailto:contact@tuist.dev), чтобы запросить доступ для вашей учётной записи.

> [!IMPORTANT]
> **Требования**
>
> - Учётная запись Tuist с включённым удалённым выполнением и доступной ёмкостью для выполнения.
> - Версия Struo с поддержкой удалённого выполнения через Tuist.
> - Совместимый сервер, который объявляет образ воркера, конечную точку кэша, уровень параллелизма и абсолютный каталог выполнения. Серверы, которые не указывают каталог, несовместимы с текущим клиентом Struo; Struo останавливается до загрузки работы.
> - Команды и тулчейны, которые могут выполняться на `linux/amd64` внутри объявленного образа воркера.

Это запускает действия графа, а не весь CI-задание. Настройка Struo не устанавливает оркестрацию рабочих процессов GitHub или GitLab.

## Настройка {#setup}

Пройдите <.localized_link href="/guides/get-started/struo-project">Начало работы со Struo</.localized_link>. Выберите одного и того же провайдера Tuist для кэширования и выполнения и зафиксируйте образ воркера, объявленный сервисом:

```toml
[infrastructures.tuist]
kind = "tuist"
account = "acme"
project = "app"
execution_image = "sha-REPLACE_WITH_THE_IMAGE_TAG"

[infrastructure.cache]
provider = "tuist"

[infrastructure.execution]
provider = "tuist"
```

Аутентифицируйтесь с учётными данными, которые могут читать и записывать кэш проекта, затем запросите удалённое выполнение:

```bash
struo build --remote MyTarget
```

Замените цель и тег образа на свои. Struo проверяет объявленный образ, каталог выполнения, назначение кэша и ёмкость учётной записи перед загрузкой работы. Кэш и выполнение должны указывать на один и тот же проект.

## Подготовка действий для воркеров {#prepare-actions-for-workers}

- Объявите входные и выходные данные. Выходные данные должны оставаться внутри рабочего каталога действия.
- Разрешайте инструменты внутри образа воркера, а не по абсолютным путям на инициирующем компьютере.
- Используйте действия, безопасные для повторного выполнения: сбой воркера или перезапуск сервиса может привести к ещё одному выполнению.
- Укладывайте таймауты в десятиминутный лимит действия сервиса. Неподдерживаемые требования, включая запрет сети, приводят к ошибке, а не к незаметному локальному запуску.

Struo учитывает объявленную параллельность действий учётной записи и снижает нагрузку, когда очередь сервиса заполнена. Смена образа разделяет конфигурацию сборки и кэшированные результаты, предотвращая повторное использование между несовместимыми образами воркеров.

## Просмотр удалённого выполнения {#inspect-remote-execution}

В боковой панели проекта есть страница **Удалённое выполнение**. Её карточка **Аналитика** показывает выполнения и общее время выполнения за выбранный период, как описано в <.localized_link href="/guides/features/cache/bazel-cache#running-actions-and-usage">Выполнение действий и использование</.localized_link>. Телеметрия запусков Struo пока не различает удалённое выполнение и локальные действия, поэтому на странице нет временных метрик удалённого выполнения по каждому запуску или списка активных запусков. Здесь объясняется этот пробел и даётся ссылка на **Запуски сборки** для просмотра записанных деталей действий. Текущие выполняемые и поставленные в очередь удалённые действия доступны через MCP-инструмент `get_remote_execution_activity` и его REST-конечную точку. Оба источника данных поступают от сервиса выполнения, а не от каналов воркеров.

См. [Руководство по удалённому выполнению Struo](https://struo.run/docs/guide/infrastructure/tuist#run-actions-on-tuist-workers) для информации об очереди, обновлении аутентификации и переопределении конечной точки кэша. Следуйте <.localized_link href="/guides/features/build-insights/struo">Инсайты сборки Struo</.localized_link>, чтобы просмотреть полученные запуски.
