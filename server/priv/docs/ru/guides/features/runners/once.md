# Удалённое выполнение Once {#once-remote-execution}

Общий кэш позволяет не повторять работу, которую уже выполнила другая машина. Удалённое выполнение также переносит подходящие промахи кэша с вашего компьютера: Once планирует действия команд графа на одноразовых Linux-воркерах Tuist и получает их результаты через тот же кэш проекта.

> [!NOTE]
> Удалённое выполнение сейчас доступно только по приглашению. [Свяжитесь с нами](mailto:contact@tuist.dev), чтобы запросить доступ для вашей учётной записи.

> [!IMPORTANT]
> **Требования**
>
> - Учётная запись Tuist с включённым удалённым выполнением и доступной ёмкостью для выполнения.
> - Версия Once с поддержкой удалённого выполнения Tuist.
> - Совместимый сервер, который объявляет образ воркера, конечную точку кэша, уровень параллелизма и абсолютный каталог выполнения. Серверы, не указывающие каталог, несовместимы с текущим клиентом Once; Once останавливается до начала загрузки работы.
> - Команды и тулчейны, которые могут выполняться на `linux/amd64` внутри объявленного образа воркера.

Это запускает действия графа, а не весь CI-задачу. Настройка Once не устанавливает оркестрацию рабочих процессов GitHub или GitLab.

## Настройка {#setup}

Пройдите <.localized_link href="/guides/get-started/once-project">Начало работы с Once</.localized_link>. Выберите одного и того же провайдера Tuist для кэширования и выполнения и зафиксируйте образ воркера, объявленный сервисом:

```toml
[infrastructures.tuist]
kind = "tuist"
account = "acme"
project = "app"
execution_image = "sha-REPLACE_WITH_THE_IMAGE_TAG"

[infrastructure.cache]
provider = "tuist"

[infrastructure.execution]
provider = "tuist"
```

Аутентифицируйтесь с учётными данными, которые могут читать и записывать кэш проекта, затем запросите удалённое выполнение:

```bash
once build --remote MyTarget
```

Замените цель и тег образа на свои. Once проверяет объявленный образ, каталог выполнения, назначение кэша и ёмкость учётной записи перед загрузкой работы. Кэш и выполнение должны указывать на один и тот же проект.

## Подготовка действий для воркеров {#prepare-actions-for-workers}

- Объявите входные и выходные данные. Выходные данные должны оставаться в пределах рабочего каталога действия.
- Разрешайте инструменты внутри образа воркера, а не по абсолютным путям на инициирующем компьютере.
- Используйте действия, безопасные для повторного выполнения: сбой воркера или перезапуск сервиса могут привести к ещё одному выполнению.
- Удерживайте таймауты в пределах десятиминутного лимита на действие сервиса. Неподдерживаемые требования, включая запрет сети, приводят к ошибке, а не к тихому локальному выполнению.

Once учитывает объявленную параллельность действий учётной записи и применяет отсрочку, когда очередь сервиса заполнена. Смена образа разделяет конфигурацию сборки и закэшированные результаты, предотвращая повторное использование между несовместимыми образами воркеров.

## Просмотр удалённого выполнения {#inspect-remote-execution}

В боковой панели проекта есть страница **Удалённое выполнение**, но телеметрия запусков Once пока не различает удалённое выполнение и локальные действия. На странице объясняется этот пробел и даётся ссылка на **Запуски сборок** для просмотра деталей записанных действий; она не выводит удалённую активность из каналов воркеров и не показывает эти действия как удалённое использование.

См. [Руководство по удалённому выполнению Once](https://buildonce.dev/docs/guide/infrastructure/tuist#run-actions-on-tuist-workers) по вопросам очереди, обновления аутентификации и переопределения конечных точек кэша. Следуйте <.localized_link href="/guides/features/build-insights/once">Аналитике сборок Once</.localized_link>, чтобы просмотреть полученные запуски.
