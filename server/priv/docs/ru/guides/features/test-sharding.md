# Параллельное выполнение тестов {#test-sharding}

Современные CI-хосты предоставляют многоядерные среды, позволяющие в некоторой степени параллелизовать выполнение тестов. Однако бывают ситуации, когда возможностей одного хоста недостаточно — например, когда вы ограничены количеством симуляторов, которые можно запускать одновременно, или когда ваш набор тестов просто перерастает возможности одной машины.

В таких случаях нужна система, которая распределяет тесты по нескольким CI-раннерам и объединяет результаты в единое представление. Именно этим занимается шардирование тестов.

Tuist использует исторические данные о времени выполнения тестов, чтобы интеллектуально балансировать нагрузку между шардами с помощью [алгоритма упаковки в контейнеры](https://en.wikipedia.org/wiki/Bin_packing_problem), благодаря чему каждый раннер завершает работу примерно в одно и то же время. Результаты со всех шардов автоматически агрегируются в разделе <.localized_link href="/guides/features/test-insights">Аналитика тестов</.localized_link>, предоставляя единое представление о вашем наборе тестов по всем шардам. Шардирование сокращает реальное время выполнения, но может увеличить машинное время; статьи [Медленные тесты](https://tuist.dev/solutions/slow-tests) и [Затраты на CI](https://tuist.dev/solutions/ci-costs) объясняют, как взвешивать эти два фактора.
