## Понимание размеров бандлов {#understanding-sizes}

Для каждого проанализированного бандла Tuist сообщает два значения:

- **Размер при установке**: место, которое приложение занимает после установки на устройство.
- **Размер загрузки**: сжатый размер, который скачивают пользователи. Для бандлов Apple это значение доступно только для `.ipa` (размер архива); для входных данных `.xcarchive` или `.app` оно недоступно.

Размеры хранятся в байтах и отображаются в десятичной системе, где 1 МБ равен 1 000 000 байт, а 1 ГБ — 1 000 000 000 байт — та же система, которую Apple использует для указания ёмкости хранилища и размеров приложений (см. [Как измеряется ёмкость хранилища на устройствах Apple](https://support.apple.com/en-us/102119)). Размер при установке 733 446 863 байт отображается как 733,4 МБ.

## Непрерывная интеграция {#continuous-integration}

Чтобы отслеживать размер бандла со временем, анализируйте его в CI. Сначала убедитесь, что ваш CI <.localized_link href="/guides/integrations/continuous-integration#authentication">аутентифицирован</.localized_link>.

Tuist также должен знать, к какому проекту относить бандл. Если вы ещё не подключили проект, выполните `tuist init` или укажите идентификатор вручную:

::: code-group
```swift [Tuist.swift]
let tuist = Tuist(fullHandle: "my-account/my-project")
```
```toml [tuist.toml]
project = "my-account/my-project"
```
<!-- -->
:::

Используйте <.localized_link href="/references/tuist-toml">`tuist.toml`</.localized_link> для проектов без манифеста Swift, например проектов Gradle. Если присутствуют оба файла, приоритет имеет `Tuist.swift`.

Пример рабочего процесса GitHub Actions:

::: code-group
```yaml [Apple]
name: Build

jobs:
  build:
    steps:
      - # Build your app
      - name: Analyze bundle
        run: tuist inspect bundle App.ipa
        env:
          TUIST_TOKEN: ${{ secrets.TUIST_TOKEN }}
```
```yaml [Android]
name: Build

jobs:
  build:
    steps:
      - # Build your app
      - name: Analyze bundle
        # .aab is recommended over .apk for more accurate size analysis
        run: tuist inspect bundle App.aab
        env:
          TUIST_TOKEN: ${{ secrets.TUIST_TOKEN }}
```
<!-- -->
:::

## Комментарии к pull/merge-запросам {#pullmerge-request-comments}

> [!WARNING]
> **Требуется интеграция с Git-платформой**
>
> Чтобы получать автоматические комментарии к pull/merge-запросам, интегрируйте ваш <.localized_link href="/guides/server/accounts-and-projects">проект Tuist</.localized_link> с <.localized_link href="/guides/server/authentication">Git-платформой</.localized_link>.

Когда ваш проект Tuist подключён к Git-платформе, например [GitHub](https://github.com), Tuist будет оставлять комментарий непосредственно в ваших pull/merge-запросах каждый раз, когда вы выполняете `tuist inspect bundle`:

## Пороги размера {#size-thresholds}

> [!WARNING]
> **Требуется интеграция с Git-форжем**
>
> Чтобы использовать пороги размера, подключите [Tuist GitHub App](https://github.com/apps/tuist) к вашему проекту. Это можно сделать на странице интеграций проекта.

Пороги размера позволяют блокировать pull-запросы, когда размер бандла превышает настроенный процент или абсолютное значение по сравнению с базовой веткой. При нарушении порога Tuist создаёт проверку GitHub Check Run для коммита PR, блокируя слияние до устранения увеличения размера:

![Проверка статуса PR, показывающая превышение порога размера бандла](/images/guides/features/bundle-size/github-pr-check-status.png)

Результат проверки показывает базовый размер, текущий размер и изменение в выбранной единице измерения. Если увеличение преднамеренное, вы можете принять его прямо в интерфейсе GitHub, нажав кнопку **Принять**:

![Проверка GitHub, показывающая нарушение порога](/images/guides/features/bundle-size/github-check-run-threshold.png)

### Настройка {#size-thresholds-configuration}

Чтобы настроить пороги, перейдите на вкладку **Настройки > Бандлы** вашего проекта:

![Настройки порогов размера бандла](/images/guides/features/bundle-size/bundle-size-thresholds.png)

Выберите **Размер при установке** или **Размер загрузки**, затем выберите **Тип порога**:

- **Процент (%)**: ограничивает рост относительно базового размера. Поддерживаются дробные проценты, например `0.47`. Существующие процентные пороги сохраняют свои настроенные значения и поведение.
- **Абсолютный размер (МБ)**: ограничивает рост на фиксированную величину, независимо от базового размера. Введите `1.5`, чтобы разрешить рост до 1,5 МБ. МБ использует десятичные единицы: 1 МБ = 1 000 000 байт. Значения должны приводиться к положительному целому числу байт.

![Настройка порога абсолютного роста размера бандла](/images/guides/features/bundle-size/absolute-size-threshold.png)

Оба типа сравниваются с последним бандлом на настроенной **базовой ветке** с тем же именем, тем же типом бандла (например, `.app` или `.ipa`) и хотя бы одной общей платформой, поэтому симуляторный `.app` сравнивается только с загрузками симуляторного `.app`. Необязательное поле **Имя бандла** ограничивает правило этим бандлом. Проверка завершается неудачей только если рост **превышает** лимит; равный рост, неизменные размеры и уменьшения проходят успешно. Без подходящей базы или записанного размера для выбранной метрики правило пропускается. Нулевой базовый размер поддерживается для абсолютных лимитов; процентные лимиты продолжают его пропускать, так как процентный рост не определён.

### Ограничение тех, кто может принимать {#size-thresholds-approvals}

По умолчанию любой пользователь с правами на запись в репозиторий может принять увеличение размера, потому что именно ему GitHub показывает кнопку. Чтобы сузить круг, настройте **Кто может принимать** в разделе **Настройки > Бандлы**:

- **Все**: по умолчанию. Любой пользователь с правами на запись в репозиторий.
- **Выбранные пользователи GitHub**: только указанные вами имена пользователей GitHub.

Если пользователя нет в списке, проверка остаётся неуспешной с пояснением, а кнопка остаётся доступной для тех, кто может её использовать.
