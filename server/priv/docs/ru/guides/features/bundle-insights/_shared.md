## Понимание размеров пакетов {#understanding-sizes}

Для каждого проанализированного пакета Tuist сообщает два значения:

- **Размер установки**: место, которое приложение занимает после установки на устройство.
- **Размер загрузки**: сжатый размер, который скачивают пользователи. Для пакетов Apple это значение сообщается только для `.ipa` (размер архива); для входных данных `.xcarchive` или `.app` оно недоступно.

Размеры хранятся в байтах и отображаются в десятичной системе, где 1 МБ равен 1 000 000 байт, а 1 ГБ — 1 000 000 000 байт, — та же система, которую Apple использует для отчётов о ёмкости хранилища и размерах приложений (см. [Как измеряется ёмкость хранилища на устройствах Apple](https://support.apple.com/en-us/102119)). Размер установки 733 446 863 байт отображается как 733,4 МБ.

## Непрерывная интеграция {#continuous-integration}

Чтобы отслеживать размер пакета со временем, анализируйте его в CI. Сначала убедитесь, что ваш CI <.localized_link href="/guides/integrations/continuous-integration#authentication">аутентифицирован</.localized_link>.

Tuist также должен знать, к какому проекту относить пакет. Если вы ещё не подключили проект, выполните `tuist init` или укажите handle самостоятельно:

::: code-group
```swift [Tuist.swift]
let tuist = Tuist(fullHandle: "my-account/my-project")
```
```toml [tuist.toml]
project = "my-account/my-project"
```
<!-- -->
:::

Используйте <.localized_link href="/references/tuist-toml">`tuist.toml`</.localized_link> для проектов без манифеста Swift, например проектов Gradle. Если присутствуют оба файла, приоритет имеет `Tuist.swift`.

Пример рабочего процесса GitHub Actions:

::: code-group
```yaml [Apple]
name: Build

jobs:
  build:
    steps:
      - # Build your app
      - name: Analyze bundle
        run: tuist inspect bundle App.ipa
        env:
          TUIST_TOKEN: ${{ secrets.TUIST_TOKEN }}
```
```yaml [Android]
name: Build

jobs:
  build:
    steps:
      - # Build your app
      - name: Analyze bundle
        # .aab is recommended over .apk for more accurate size analysis
        run: tuist inspect bundle App.aab
        env:
          TUIST_TOKEN: ${{ secrets.TUIST_TOKEN }}
```
<!-- -->
:::

После настройки вы сможете видеть, как меняется размер вашего пакета со временем:

## Комментарии к pull/merge-запросам {#pullmerge-request-comments}

> [!WARNING]
> **Требуется интеграция с Git-платформой**
>
> Чтобы получать автоматические комментарии к pull/merge-запросам, интегрируйте свой <.localized_link href="/guides/server/accounts-and-projects">проект Tuist</.localized_link> с <.localized_link href="/guides/server/authentication">Git-платформой</.localized_link>.

После подключения проекта Tuist к вашей Git-платформе, такой как [GitHub](https://github.com), Tuist будет оставлять комментарий непосредственно в ваших pull/merge-запросах каждый раз, когда вы запускаете `tuist inspect bundle`:

## Пороговые значения размера {#size-thresholds}

> [!WARNING]
> **Требуется интеграция с Git-форжем**
>
> Чтобы использовать пороговые значения размера, подключите [приложение Tuist для GitHub](https://github.com/apps/tuist) к своему проекту. Это можно сделать на странице интеграций проекта.

Пороговые значения размера позволяют блокировать pull-запросы, когда размер пакета превышает настроенный процент или абсолютное значение по сравнению с базовой веткой. При нарушении порога Tuist создаёт проверку GitHub Check Run для коммита PR, блокируя слияние до устранения увеличения размера:

![Проверка статуса PR, показывающая превышение порога размера пакета](/images/guides/features/bundle-size/github-pr-check-status.png)

Результат проверки показывает базовый размер, текущий размер и изменение в выбранной единице измерения. Если увеличение преднамеренное, вы можете принять его прямо в интерфейсе GitHub, нажав кнопку **Принять**:

![Проверка GitHub, показывающая нарушение порога](/images/guides/features/bundle-size/github-check-run-threshold.png)

### Настройка {#size-thresholds-configuration}

Чтобы настроить пороги, перейдите на вкладку **Settings > Bundles** вашего проекта:

![Настройки пороговых значений размера пакета](/images/guides/features/bundle-size/bundle-size-thresholds.png)

Выберите **Размер установки** или **Размер загрузки**, затем выберите **Тип порога**:

- **Процент (%)**: ограничивает рост относительно базового размера. Поддерживаются дробные проценты, такие как `0.47`. Существующие процентные пороги сохраняют свои настроенные значения и поведение.
- **Абсолютный размер (МБ)**: ограничивает рост на фиксированную величину, независимо от базового размера. Введите `1.5`, чтобы разрешить рост до 1,5 МБ. МБ использует десятичные единицы: 1 МБ = 1 000 000 байт. Значения должны приводиться к положительному целому числу байт.

![Настройка порога абсолютного роста размера пакета](/images/guides/features/bundle-size/absolute-size-threshold.png)

Оба типа сравниваются с последним пакетом на настроенной **базовой ветке** с тем же именем, тем же типом пакета (например, `.app` или `.ipa`) и хотя бы одной общей платформой, поэтому симуляторный `.app` сравнивается только с загрузками симуляторных `.app`. Необязательное поле **Имя пакета** ограничивает правило этим пакетом. Проверка завершается ошибкой только если рост **превышает** лимит; равный рост, неизменные размеры и уменьшения проходят. Без подходящей базы или записанного размера для выбранной метрики правило пропускается. Базовый размер нуля поддерживается для абсолютных лимитов; процентные лимиты продолжают пропускать его, так как процентный рост не определён.

### Ограничение тех, кто может принимать {#size-thresholds-approvals}

По умолчанию любой пользователь с правами на запись в репозиторий может принять увеличение размера, потому что именно им GitHub показывает кнопку. Чтобы сузить круг, настройте параметр **Кто может принимать** в разделе **Settings > Bundles**:

- **Все**: по умолчанию. Любой пользователь с правами на запись в репозиторий.
- **Выбранные пользователи GitHub**: только указанные вами имена пользователей GitHub.

Если пользователя нет в списке, проверка остаётся неудачной с пояснением, а кнопка остаётся доступной для тех, кто может её использовать.
