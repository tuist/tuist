# Песочницы {#sandboxes}

> [!IMPORTANT]
> **Только по приглашению**
>
> Tuist Sandboxes для Linux и macOS сейчас доступны только по приглашению, пока мы масштабируем мощности. [Свяжитесь с нами](mailto:contact@tuist.dev) или напишите нам в [Slack-сообществе](https://slack.tuist.dev), чтобы запросить доступ для вашего аккаунта. Цены будут объявлены, когда песочницы станут общедоступными.

Песочница — это виртуальная машина, на которой агент для написания кода выполняет команды и редактирует файлы. Каждая сессия агента получает собственную песочницу, которая хранит клон репозитория, артефакты сборки и установленные инструменты на протяжении всей сессии. Когда агент переходит в режим ожидания, песочница ставится на паузу; следующее сообщение возобновляет работу с того места, где она остановилась.

Песочницы работают на том же парке машин, что и <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link>, рядом с <.localized_link href="/guides/features/cache">кэшем</.localized_link> вашей команды, поэтому сборки агента могут использовать те же кэшированные артефакты, что и ваши CI-системы и локальные машины.

Вы можете использовать песочницы из:

- **<.localized_link href="/guides/features/sandboxes/amp">Amp</.localized_link>**: запускайте орбы рабочего пространства Amp на Tuist или предоставьте любому треду Amp Mac для сборок Xcode с помощью <.localized_link href="/guides/features/sandboxes/amp#remote-mac">плагина Tuist Mac</.localized_link>.
- **<.localized_link href="/guides/features/sandboxes/claude">Claude</.localized_link>**: запускайте сессии Claude Managed Agents и облачные сессии Claude Code (claude.ai, десктопные и мобильные приложения и `claude --cloud`) на Tuist.
- **[The Tuist CLI](#cli)**: создавайте песочницы и выполняйте в них команды из терминала или из собственных инструментов через API.

## Начало работы с CLI {#cli}

Создайте песочницу и выполняйте в ней команды из терминала с помощью `tuist sandbox`.

### 1. Войти {#cli-log-in}

Любой участник аккаунта может создавать песочницы и управлять ими:

```bash
tuist auth login
```

### 2. Создать песочницу {#cli-create}

```bash
tuist sandbox create --platform macos
```

Опустите `--platform` для Linux. Передайте `--xcode` с версией, например `--xcode 26.1.1`, для Mac с этим [Xcode](#xcode); это подразумевает `--platform macos`. Передайте `--vcpus` вместе с `--memory-gb` для большего [формата](#platforms), `--guaranteed-vcpus` чтобы гарантировать песочнице Linux больше [CPU](#guaranteed-cpu), и `--workspace-gb` для большего диска. Команда завершится, когда песочница запустится, и выведет её детали, включая ID. Она использует аккаунт проекта Tuist в текущей директории; передайте `--account`, чтобы выбрать другой.

### 3. Выполнять команды {#cli-exec}

```bash
tuist sandbox exec <sandbox-id> -- xcodebuild -version
```

Команда выполняется с `bash -l` в песочнице, которая сначала возобновляется, если была на паузе. `tuist` передаёт вывод столько, сколько выполняется команда, и завершается со статусом команды; Ctrl-C отменяет выполнение в песочнице. При необходимости передайте `--cwd`, `--env NAME=VALUE` и `--timeout` (до шести часов).

Команда выполняется независимо от `tuist`, поэтому переживает обрыв соединения. Чтобы уместить долгую сборку в вызов инструмента с ограничением по времени, например у агента, передайте `--wait <seconds>`: когда время истекает раньше, `tuist` оставляет команду работающей, завершается с кодом 75 и выводит команду `tuist sandbox exec <sandbox-id> --attach <command-id> --stdout-offset … --stderr-offset …`, которая продолжает вывод с места остановки и завершается со статусом команды.

### Частые задачи {#cli-tasks}

| Задача | Команда |
| --- | --- |
| Список песочниц | `tuist sandbox list` |
| Показать одну | `tuist sandbox show <id>` |
| Пауза или возобновление | `tuist sandbox pause <id>`, `tuist sandbox resume <id>` |
| Синхронизировать файлы локального Git-дерева в песочницу | `tuist sandbox sync <id>` |
| Копировать файлы внутрь или наружу | `tuist sandbox cp <id>:<path> <local-path>`, `tuist sandbox cp <local-path> <id>:<path>` |
| Удалить | `tuist sandbox delete <id> --yes` |
| Посмотреть использование | `tuist sandbox analytics` |

Добавьте `--json` для машиночитаемого вывода. Все опции описаны в <.localized_link href="/cli/sandbox">справочнике CLI</.localized_link>. Чтобы управлять песочницами из кода, используйте те же операции через [Tuist API](https://tuist.dev/api/docs) по пути `/api/accounts/{account_handle}/sandboxes` или позвольте агенту использовать их через <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>.

Инструменты, которые не могут войти интерактивно, например плагин агента, собирающий проект в песочнице macOS, могут аутентифицироваться с помощью <.localized_link href="/guides/server/authentication#account-tokens">токена аккаунта</.localized_link> со скоупом `account:sandboxes:write`. Он позволяет делать то же, что и участник аккаунта: создавать песочницы, выполнять в них команды, ставить на паузу, возобновлять, архивировать и удалять их. Настройки интеграций остаются у администраторов аккаунта.

### Tuist внутри песочницы {#tuist-in-sandbox}

Песочницы macOS поставляются с CLI Tuist. Когда ваш проект фиксирует версию Tuist через mise (`mise.toml` или `.tool-versions`), `tuist` запускает именно эту версию, устанавливая её при первом запуске команды, которой она нужна. Каждая команда, которую вы запускаете через `tuist sandbox exec`, имеет шимы mise (`$HOME/.local/share/mise/shims`) первыми в `PATH`, а Tuist из образа — последним, поэтому `tuist` и другие инструменты mise работают в ваших командах и в фазах сборки Xcode, например в post-actions схемы. На каждом Mac также есть руководство для агентов по адресу `/opt/tuist/agent-guide.md`, сгенерированное из его образа: версии Xcode и симуляторы, расположение репозитория и содержимое готового снапшота. Claude Code, Codex и Amp, работающие на Mac, находят его по своим файлам инструкций.

Каждая команда, запущенная через `tuist sandbox exec`, также получает то, что получает раннер Tuist, поэтому сборки в песочнице используют <.localized_link href="/guides/features/cache">кэш</.localized_link> вашего аккаунта без передачи учётных данных:

- `TUIST_URL` и, там, где хост песочницы имеет к нему доступ, например на macOS, `TUIST_CACHE_ENDPOINT` кэша в той же стойке.
- `TUIST_OIDC_TOKEN` — краткосрочный токен идентичности для этой команды. Туист CLI 4.218.0 и новее входят с ним автоматически; для версий с 4.215.0 по 4.217.x сначала выполните `tuist auth login` в той же команде.

Токен выпускается для каждой команды и может быть обменен на токен Tuist только пока эта команда выполняется, поэтому песочница никогда не хранит долгосрочные учётные данные. Он никогда не предоставляет больше прав, чем есть у человека или токена, запустившего команду, для работы с кэшем: участники аккаунта, чьи токены кэша имеют право только на запись, получают доступ на чтение, а токен аккаунта нуждается в скоупах кэша, таких как `ci`, вместе с `account:sandboxes:write`, чтобы песочница вообще могла использовать кэш. Переменные, переданные через `--env`, имеют приоритет.

## Сборка на Mac из агента для написания кода {#coding-agents}

Агент для написания кода, работающий на Linux, например облачная сессия агента, может собирать, тестировать и запускать код для платформ Apple в песочнице macOS, продолжая редактировать файлы там, где он работает. В Amp установите <.localized_link href="/guides/features/sandboxes/amp#remote-mac">плагин Tuist Mac</.localized_link>. Для других агентов, таких как Claude Code или Cursor:

1. Подключите агента к <.localized_link href="/guides/features/agentic-coding/mcp">MCP-серверу</.localized_link> Tuist. Его инструмент `create_sandbox` сообщает агенту, как управлять Mac.
2. Установите CLI Tuist там, где работает агент, например в скрипте настройки окружения: `mise use -g tuist@latest` или `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist` (`tuist-linux-aarch64` на ARM).
3. Аутентифицируйте CLI. Вход на MCP-сервере не переносится в него, поэтому либо выполните `tuist auth login` как участник аккаунта, либо установите для `TUIST_TOKEN` значение <.localized_link href="/guides/server/authentication#account-tokens">токена аккаунта</.localized_link> со скоупом `account:sandboxes:write`.
4. Если окружение ограничивает сетевой доступ, разрешите доступ к `tuist.dev`. CLI загружает файлы на Mac через него, поэтому другие домены не требуются.

Агент создаёт один Mac для каждой задачи с той версией [Xcode](#xcode), которую закрепляет проект: `create_sandbox` перечисляет доступные версии Xcode и указывает агенту прочитать закреплённую версию проекта, например `.xcode-version`. Перед каждой командой он выполняет `tuist sandbox sync`. Он копирует файлы, которые Git не игнорирует (независимо от того, закоммичены они или нет), а впоследствии — только изменившиеся. На Mac уже установлен [Tuist](#tuist-in-sandbox) (закреплённая версия проекта, если она закреплена), выполнен вход в кэш вашего аккаунта, и агент единожды читает руководство по Mac. Затем агент запускает команды, такие как `xcodebuild`, с помощью `tuist sandbox exec`, копирует результаты, такие как скриншоты или собранное приложение, обратно с помощью `tuist sandbox cp`, и удаляет Mac после завершения задачи. Mac остаётся работающим в течение 10 минут после последней команды, поэтому следующая команда начинается сразу; `tuist sandbox pause` позволяет вернуть его раньше. Оставленный без присмотра Mac переходит в режим паузы и удаляется после 14 дней в режиме паузы.

## Linux и macOS {#platforms}

Песочницы **Linux** работают на Ubuntu 24.04. Каждая песочница Linux имеет 16 виртуальных процессоров и использует простаивающие ядра машины, на которой она работает, поэтому её конфигурация определяет объём памяти:

- 2 ГБ ОЗУ (`--vcpus 1 --memory-gb 2`)
- 4 ГБ ОЗУ (`--vcpus 2 --memory-gb 4`, по умолчанию)
- 8 ГБ ОЗУ (`--vcpus 4 --memory-gb 8`)
- 16 ГБ ОЗУ (`--vcpus 8 --memory-gb 16`)
- 32 ГБ ОЗУ (`--vcpus 16 --memory-gb 32`)
- 44 ГБ ОЗУ (`--vcpus 16 --memory-gb 44`)

Песочницы **macOS** работают на Apple Silicon с Xcode:

- 8 виртуальных процессоров, 8 ГБ ОЗУ (по умолчанию)
- 8 виртуальных процессоров, 16 ГБ ОЗУ
- 8 виртуальных процессоров, 24 ГБ ОЗУ

### Гарантированные процессоры {#guaranteed-cpu}

Песочнице Linux гарантируется четверть виртуального процессора на каждый гигабайт памяти, например 2 виртуальных процессора для 8 ГБ, и она использует столько дополнительных ресурсов, сколько доступно на машине, вплоть до своих 16 виртуальных процессоров. Это подходит для агента, который большую часть времени ожидает, а затем выполняет сборку всплесками. Если сборке требуется более стабильная производительность процессора даже на загруженной машине, при создании песочницы гарантируйте ей 1, 2, 4 или 8 виртуальных процессоров; она получит большее из этого значения и гарантии, определяемой памятью:

| Где | Как |
| --- | --- |
| CLI | `tuist sandbox create --guaranteed-vcpus 4` |
| API и MCP `create_sandbox` | `"guaranteed_vcpus": 4` |

- **Гарантия — это минимум, а не максимум.** Песочница с 4 гарантированными виртуальными процессорами всё равно может использовать до 16, когда ядра свободны. При конкуренции за ресурсы каждая песочница получает процессорное время пропорционально своей гарантии.
- **Оплата взимается исходя из минимума.** Работающая песочница оплачивается за фактически использованные процессоры, но не менее гарантированного количества.
- **Песочница сохраняет свою гарантию на весь срок жизни.** Чтобы изменить её, создайте новую песочницу.
- **Песочницы macOS всегда имеют полную конфигурацию**, поэтому для них не применяется отдельная гарантия.

### Выбор версии Xcode {#xcode}

Каждая песочница macOS запускает одну версию Xcode, которую вы выбираете при её создании. Она загружает тот же образ, что и профиль <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link> для этой версии Xcode, поэтому агент собирает проект с тем же набором инструментов и симуляторами, что и ваш CI. На tuist.dev песочницы macOS в настоящее время предлагают:

- `26.6` (по умолчанию)
- `26.1.1`
- `27.0`
- `27.1`
- `27.2`

Выберите версию с помощью `xcode_version` (`--xcode` в CLI), указывая точную версию, как это делается в профилях раннеров:

| Где | Как |
| --- | --- |
| CLI | `tuist sandbox create --xcode 26.1.1` |
| API и MCP `create_sandbox` | `"xcode_version": "26.1.1"` |
| Плагин Tuist Mac для Amp | `tuist_mac_start` с параметром `xcode` |
| Orbs для Amp | Тип орба `macos-xcode-26-1-1` (см. <.localized_link href="/guides/features/sandboxes/amp#xcode">Amp</.localized_link>) |
| Claude Code и Claude Managed Agents | `xcode_version` в окружении или для каждой сессии Managed Agents (см. <.localized_link href="/guides/features/sandboxes/claude#xcode">Claude</.localized_link>) |

- **Без указания версии** Mac получает версию по умолчанию.
- **Версия, которую Tuist не предлагает, отклоняется**, а в сообщении об ошибке перечисляются доступные для выбора версии, чтобы вы знали, что доступно прямо сейчас.
- **Tuist не читает файл `.xcode-version` вашего репозитория.** Версию выбираете вы или агент, запрашивающий Mac. Инструмент MCP и плагин Tuist Mac instruct агентов использовать версию, зафиксированную в проекте.
- **Песочница сохраняет свою версию Xcode на весь срок жизни.** Чтобы собирать проект с другой версией Xcode, создайте новую песочницу. `xcodebuild -version` показывает, какая версия Xcode запущена на Mac.

## Безопасность {#security}

- Каждая песочница — это отдельная виртуальная машина. Песочницы не разделяют файловую систему, память или процессы друг с другом или с задачами CI.
- Песочницы принадлежат аккаунту, и любой его участник может использовать и управлять ими, включая песочницы, обслуживающие интеграции. Подключать интеграции могут только администраторы. Сессии от интеграции имеют доступ только к песочницам того аккаунта, к которому подключена интеграция.
- Учетные данные, которые вы предоставляете Tuist для подключения интеграции, такие как токен провайдера Amp или ключ окружения Claude, хранятся в зашифрованном виде и больше никогда не отображаются.
- Песочница имеет доступ к интернету. Относитесь к тому, к чему агент может получить доступ из неё, так же, как к задаче CI.
