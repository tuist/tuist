# Песочницы {#sandboxes}

> [!IMPORTANT]
> **Только по приглашению**
>
> Песочницы Tuist, как для Linux, так и для macOS, сейчас доступны только по приглашениям, пока мы увеличиваем мощность. [Свяжитесь с нами](mailto:contact@tuist.dev) или напишите нам в [Slack-сообществе](https://slack.tuist.dev), чтобы запросить доступ для вашего аккаунта. Цены будут объявлены, когда песочницы станут общедоступными.

Песочница — это виртуальная машина, где агент для написания кода выполняет свои команды и редактирует файлы. Каждая сессия агента получает собственную песочницу, которая хранит его репозиторий, артефакты сборки и установленные инструменты на протяжении всей сессии. Когда агент переходит в режим ожидания, песочница приостанавливается; следующее сообщение возобновляет работу с того места, где она остановилась.

Песочницы работают на том же парке машин, что и <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link>, рядом с <.localized_link href="/guides/features/cache">кешем</.localized_link> вашей команды, поэтому сборки агента могут использовать те же кэшированные артефакты, что и ваши CI-системы и локальные машины.

Вы можете использовать песочницы через:

- **<.localized_link href="/guides/features/sandboxes/amp">Amp</.localized_link>**: запускайте орбы вашего рабочего пространства Amp на Tuist или предоставьте любому потоку Amp Mac для сборок Xcode с помощью <.localized_link href="/guides/features/sandboxes/amp#remote-mac">плагина Tuist Mac</.localized_link>.
- **<.localized_link href="/guides/features/sandboxes/claude">Claude</.localized_link>**: запускайте сессии Claude Managed Agents и облачные сессии Claude Code (claude.ai, десктопные и мобильные приложения, а также `claude --cloud`) на Tuist.
- **[CLI Tuist](#cli)**: создавайте песочницы и выполняйте в них команды из терминала или из ваших собственных инструментов через API.

## Начало работы с CLI {#cli}

Создайте песочницу и выполняйте в ней команды из терминала с помощью `tuist sandbox`.

### 1. Вход в систему {#cli-log-in}

Для управления песочницами требуется администратор аккаунта:

```bash
tuist auth login
```

### 2. Создание песочницы {#cli-create}

```bash
tuist sandbox create --platform macos
```

Опустите `--platform` для Linux. Укажите `--vcpus` вместе с `--memory-gb` для большей [конфигурации](#platforms) и `--workspace-gb` для большего диска. Команда завершается, когда песочница запущена, и выводит её детали, включая ID. Она использует аккаунт проекта Tuist в текущей директории; укажите `--account`, чтобы выбрать другой.

### 3. Выполнение команд {#cli-exec}

```bash
tuist sandbox exec <sandbox-id> -- xcodebuild -version
```

Команда выполняется через `bash -l` в песочнице, которая сначала возобновляется, если была приостановлена. `tuist` передаёт вывод столько, сколько выполняется команда, и завершается со статусом команды; Ctrl-C отменяет её выполнение в песочнице. При необходимости указывайте `--cwd`, `--env NAME=VALUE` и `--timeout` (до шести часов).

### Частые задачи {#cli-tasks}

| Задача | Команда |
| --- | --- |
| Список песочниц | `tuist sandbox list` |
| Показать одну | `tuist sandbox show <id>` |
| Приостановить или возобновить | `tuist sandbox pause <id>`, `tuist sandbox resume <id>` |
| Синхронизировать файлы локального Git-репозитория в песочницу | `tuist sandbox sync <id>` |
| Копировать файлы внутрь или наружу | `tuist sandbox cp <id>:<path> <local-path>`, `tuist sandbox cp <local-path> <id>:<path>` |
| Удалить | `tuist sandbox delete <id> --yes` |
| Посмотреть использование | `tuist sandbox analytics` |

Добавьте `--json` для вывода в машиночитаемом формате. См. <.localized_link href="/cli/sandbox">справочник CLI</.localized_link> для всех опций. Чтобы управлять песочницами из кода, используйте те же операции через [Tuist API](https://tuist.dev/api/docs) по пути `/api/accounts/{account_handle}/sandboxes` или позвольте агенту использовать их через <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>.

Инструменты, которые не могут войти в систему интерактивно, например плагин агента, выполняющий сборку в песочнице macOS, могут аутентифицироваться с помощью <.localized_link href="/guides/server/authentication#account-tokens">токена аккаунта</.localized_link> с областью прав `account:sandboxes:write`. Он может создавать песочницы, выполнять в них команды, а также приостанавливать, возобновлять и удалять их, как участник аккаунта. Песочницы, обслуживающие интеграцию Amp или Claude, аналитику и настройки интеграции, остаются под управлением администраторов аккаунта.

### Tuist внутри песочницы {#tuist-in-sandbox}

Образы песочниц не включают CLI Tuist, поэтому используется версия, закреплённая в вашем проекте. После первой `tuist sandbox sync` выполните `mise install` в корне репозитория на песочнице (`mise` и `brew` установлены), затем запускайте `tuist` через mise, например, добавив `$HOME/.local/share/mise/shims` в `PATH`.

Каждая команда, запущенная через `tuist sandbox exec`, получает то же, что и раннер Tuist, поэтому сборки в песочнице используют <.localized_link href="/guides/features/cache">кеш</.localized_link> вашего аккаунта без необходимости передавать учётные данные:

- `TUIST_URL` и, если хост песочницы имеет к нему доступ, например на macOS, `TUIST_CACHE_ENDPOINT` кеша в той же стойке.
- `TUIST_OIDC_TOKEN`, краткосрочный токен идентификации для этой команды. Туист CLI версии 4.218.0 и новее входят в систему с его помощью автоматически; для версий с 4.215.0 по 4.217.x сначала выполните `tuist auth login` в той же команде.

Токен выпускается для каждой команды и может быть обменен на токен Tuist только пока эта команда выполняется, поэтому песочница никогда не хранит долгосрочные учётные данные. Он никогда не предоставляет больше прав, чем есть у человека или токена, запустившего команду, для работы с кешем: участники аккаунта, чьи токены кеша имеют права только на запись, получают доступ на чтение, а токен аккаунта требует областей прав кеша, таких как `ci`, вместе с `account:sandboxes:write`, чтобы песочница вообще могла использовать кеш. Переменные, переданные через `--env`, имеют приоритет.

## Сборка на Mac от агента для написания кода {#coding-agents}

Агент для написания кода, работающий на Linux, например облачная сессия агента, может собирать, тестировать и запускать код для платформ Apple на песочнице macOS, продолжая редактировать файлы там, где он работает. В Amp установите <.localized_link href="/guides/features/sandboxes/amp#remote-mac">плагин Tuist Mac</.localized_link>. Для других агентов, таких как Claude Code или Cursor:

1. Подключите агента к <.localized_link href="/guides/features/agentic-coding/mcp">MCP-серверу</.localized_link> Tuist. Его инструмент `create_sandbox` сообщает агенту, как управлять Mac.
2. Установите CLI Tuist там, где работает агент, например в скрипте настройки окружения: `mise use -g tuist@latest` или `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist` (`tuist-linux-aarch64` на ARM).
3. Аутентифицируйте CLI. Вход на MCP-сервере не распространяется на него, поэтому либо выполните `tuist auth login` как участник аккаунта, либо установите `TUIST_TOKEN` в значение <.localized_link href="/guides/server/authentication#account-tokens">токена аккаунта</.localized_link> с областью прав `account:sandboxes:write`.
4. Если окружение ограничивает сетевой доступ, разрешите доступ к `tuist.dev`. CLI загружает файлы на Mac через него, поэтому другие домены не требуются.

Агент создает один Mac для каждой задачи и перед каждой командой выполняет `tuist sandbox sync`. Он копирует файлы, которые Git не игнорирует (закоммиченные или нет), а впоследствии — только изменившиеся. После первой синхронизации он запускает `mise install` в корне репозитория на Mac, чтобы там оказался [закрепленный в проекте Tuist](#tuist-in-sandbox), авторизованный в кеше вашего аккаунта. Затем агент выполняет команды, такие как `xcodebuild`, с помощью `tuist sandbox exec`, копирует результаты, например скриншоты или собранное приложение, обратно с помощью `tuist sandbox cp` и удаляет Mac по завершении задачи. Mac остается запущенным в течение 10 минут после последней команды, поэтому следующая команда начинается немедленно; `tuist sandbox pause` позволяет освободить его раньше. Оставленный без внимания Mac переходит в режим паузы и удаляется после 14 дней в состоянии паузы.

## Linux и macOS {#platforms}

Песочницы **Linux** работают на Ubuntu 24.04:

- 2 vCPU, 4 ГБ ОЗУ (по умолчанию)
- 4 vCPU, 8 ГБ ОЗУ
- 8 vCPU, 16 ГБ ОЗУ

Песочницы **macOS** работают на Apple Silicon с Xcode:

- 8 vCPU, 8 ГБ ОЗУ (по умолчанию)
- 8 vCPU, 16 ГБ ОЗУ
- 8 vCPU, 24 ГБ ОЗУ

## Безопасность {#security}

- Каждая песочница является отдельной виртуальной машиной. Песочницы не разделяют файловую систему, память или процессы друг с другом или с задачами CI.
- Песочницы принадлежат аккаунту, и управлять ими могут только его администраторы. Сессии из интеграции имеют доступ только к песочницам того аккаунта, к которому подключена интеграция.
- Учетные данные, которые вы предоставляете Tuist для подключения интеграции, такие как токен провайдера Amp или ключ окружения Claude, хранятся в зашифрованном виде и больше никогда не отображаются.
- Песочница имеет доступ к интернету. Относитесь к тому, что агент может получить из нее, так же, как к задаче CI.
