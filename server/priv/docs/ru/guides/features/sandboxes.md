# Песочницы {#sandboxes}

> [!IMPORTANT]
> **Только по приглашениям**
>
> Песочницы Tuist, как для Linux, так и для macOS, сейчас доступны только по приглашениям, пока мы масштабируем мощности. [Свяжитесь с нами](mailto:contact@tuist.dev) или напишите нам в [Slack-сообществе](https://slack.tuist.dev), чтобы запросить доступ для вашего аккаунта. Цены будут объявлены, когда песочницы станут общедоступными.

Песочница — это виртуальная машина, где агент для написания кода выполняет свои команды и редактирует файлы. Каждая сессия агента получает собственную песочницу, которая хранит её клон репозитория, артефакты сборки и установленные инструменты на протяжении всей сессии. Когда агент переходит в режим ожидания, песочница приостанавливается; следующее сообщение возобновляет работу с того места, где она остановилась.

Песочницы работают на том же парке машин, что и <.localized_link href="/guides/features/runners">раннеры Tuist</.localized_link>, рядом с <.localized_link href="/guides/features/cache">кэшем</.localized_link> вашей команды, поэтому сборки агента могут использовать те же кэшированные артефакты, что и ваш CI и локальные машины.

Вы можете использовать песочницы через:

- **<.localized_link href="/guides/features/sandboxes/amp">Amp</.localized_link>**: запускайте орбы вашего рабочего пространства Amp в Tuist или предоставьте любому потоку Amp Mac для сборок Xcode с помощью <.localized_link href="/guides/features/sandboxes/amp#remote-mac">плагина Tuist Mac</.localized_link>.
- **<.localized_link href="/guides/features/sandboxes/claude">Claude</.localized_link>**: запускайте сессии Claude Managed Agents и облачные сессии Claude Code (claude.ai, десктопные и мобильные приложения и `claude --cloud`) в Tuist.
- **[CLI Tuist](#cli)**: создавайте песочницы и выполняйте в них команды из терминала или из ваших собственных инструментов через API.

## Начало работы с CLI {#cli}

Создайте песочницу и выполняйте в ней команды из терминала с помощью `tuist sandbox`.

### 1. Войти {#cli-log-in}

Любой участник аккаунта может создавать песочницы и управлять ими:

```bash
tuist auth login
```

### 2. Создать песочницу {#cli-create}

```bash
tuist sandbox create --platform macos
```

Опустите `--platform` для Linux. Передайте `--xcode` с версией, например `--xcode 26.1.1`, для Mac с этой версией [Xcode](#xcode); это подразумевает `--platform macos`. Передайте `--vcpus` вместе с `--memory-gb` для большей [конфигурации](#platforms) и `--workspace-gb` для большего диска. Команда завершается, когда песочница запущена, и выводит её детали, включая ID. Она использует аккаунт проекта Tuist в текущей директории; передайте `--account`, чтобы выбрать другой.

### 3. Выполнять команды {#cli-exec}

```bash
tuist sandbox exec <sandbox-id> -- xcodebuild -version
```

Команда выполняется через `bash -l` в песочнице, которая сначала возобновляется, если была приостановлена. `tuist` транслирует её вывод столько, сколько она работает, и завершается со статусом команды; Ctrl-C отменяет выполнение в песочнице. При необходимости передайте `--cwd`, `--env NAME=VALUE` и `--timeout` (до шести часов).

### Частые задачи {#cli-tasks}

| Задача | Команда |
| --- | --- |
| Список песочниц | `tuist sandbox list` |
| Показать одну | `tuist sandbox show <id>` |
| Приостановить или возобновить | `tuist sandbox pause <id>`, `tuist sandbox resume <id>` |
| Синхронизировать файлы локального рабочего дерева Git в песочницу | `tuist sandbox sync <id>` |
| Копировать файлы из песочницы или в неё | `tuist sandbox cp <id>:<path> <local-path>`, `tuist sandbox cp <local-path> <id>:<path>` |
| Удалить | `tuist sandbox delete <id> --yes` |
| Посмотреть использование | `tuist sandbox analytics` |

Добавьте `--json` для вывода в машиночитаемом формате. См. <.localized_link href="/cli/sandbox">справочник CLI</.localized_link> для всех опций. Чтобы управлять песочницами из кода, используйте те же операции через [Tuist API](https://tuist.dev/api/docs) по пути `/api/accounts/{account_handle}/sandboxes` или позвольте агенту использовать их через <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>.

Инструменты, которые не могут выполнять интерактивный вход, например плагин агента, выполняющий сборку в песочнице macOS, могут аутентифицироваться с помощью <.localized_link href="/guides/server/authentication#account-tokens">токена аккаунта</.localized_link> с областью прав `account:sandboxes:write`. Он может делать всё то же, что и участник аккаунта: создавать песочницы, выполнять в них команды, а также приостанавливать, возобновлять, архивировать и удалять их. Настройки интеграций остаются у администраторов аккаунта.

### Tuist внутри песочницы {#tuist-in-sandbox}

Образы песочниц не включают CLI Tuist, поэтому используется версия, закреплённая в вашем проекте. После первой синхронизации `tuist sandbox sync` выполните `mise install` в корне репозитория на песочнице (`mise` и `brew` установлены). Каждая команда, запускаемая через `tuist sandbox exec`, имеет shim’ы mise (`$HOME/.local/share/mise/shims`) первыми в `PATH`, поэтому `tuist` и другие инструменты mise выполняются в ваших командах и в фазах сборки Xcode, например в post-actions схемы.

Каждая команда, запускаемая через `tuist sandbox exec`, также получает то, что получает раннер Tuist, поэтому сборки в песочнице используют <.localized_link href="/guides/features/cache">кэш</.localized_link> вашего аккаунта без передачи учётных данных:

- `TUIST_URL` и, там, где хост песочницы имеет к нему доступ, например на macOS, `TUIST_CACHE_ENDPOINT` кэша в той же стойке.
- `TUIST_OIDC_TOKEN` — краткосрочный токен идентичности для этой команды. Tuist CLI версии 4.218.0 и новее входят с его помощью автоматически; для версий с 4.215.0 по 4.217.x сначала выполните `tuist auth login` в той же команде.

Токен выпускается для каждой команды и может быть обменен на токен Tuist только пока эта команда выполняется, поэтому песочница никогда не хранит долгосрочные учётные данные. Он никогда не предоставляет больше прав, чем есть у человека или токена, запустившего команду, для работы с кэшем: участники аккаунта, чьи токены кэша имеют права только на запись, получают доступ на чтение, а токену аккаунта нужны области прав кэша, такие как `ci`, вместе с `account:sandboxes:write`, чтобы песочница вообще могла использовать кэш. Переменные, переданные через `--env`, имеют приоритет.

## Сборка на Mac из агента для написания кода {#coding-agents}

Агент для написания кода, работающий на Linux, например облачная сессия агента, может собирать, тестировать и запускать код для платформ Apple в песочнице macOS, продолжая редактировать файлы там, где он работает. В Amp установите <.localized_link href="/guides/features/sandboxes/amp#remote-mac">плагин Tuist Mac</.localized_link>. Для других агентов, таких как Claude Code или Cursor:

1. Подключите агента к <.localized_link href="/guides/features/agentic-coding/mcp">MCP-серверу</.localized_link> Tuist. Его инструмент `create_sandbox` сообщает агенту, как управлять Mac.
2. Установите CLI Tuist там, где работает агент, например в скрипте настройки окружения: `mise use -g tuist@latest` или `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist` (`tuist-linux-aarch64` на ARM).
3. Аутентифицируйте CLI. Вход на MCP-сервере не переносится в него, поэтому либо выполните `tuist auth login` как участник аккаунта, либо установите `TUIST_TOKEN` в значение <.localized_link href="/guides/server/authentication#account-tokens">токена аккаунта</.localized_link> с областью прав `account:sandboxes:write`.
4. Если окружение ограничивает сетевой доступ, разрешите `tuist.dev`. CLI загружает файлы на Mac через него, поэтому другие домены не требуются.

Агент создает один Mac для каждой задачи с той версией [Xcode](#xcode), которая закреплена в проекте: `create_sandbox` перечисляет доступные версии Xcode и указывает агенту прочитать закрепленную версию проекта, например `.xcode-version`. Перед каждой командой он выполняет `tuist sandbox sync`. Он копирует файлы, которые Git не игнорирует (закоммиченные или нет), а затем — только измененные. После первой синхронизации он запускает `mise install` в корне репозитория на Mac, чтобы там оказался [закрепленный в проекте Tuist](#tuist-in-sandbox), авторизованный в кэше вашего аккаунта. Затем агент выполняет команды, такие как `xcodebuild`, с помощью `tuist sandbox exec`, копирует результаты, например скриншоты или собранное приложение, обратно через `tuist sandbox cp` и удаляет Mac после завершения задачи. Mac остается запущенным в течение 10 минут после последней команды, поэтому следующая команда начинается сразу; `tuist sandbox pause` позволяет освободить его раньше. Оставленный без присмотра Mac переходит в режим паузы и удаляется после 14 дней в режиме паузы.

## Linux и macOS {#platforms}

Песочницы **Linux** работают на Ubuntu 24.04:

- 2 vCPU, 4 ГБ ОЗУ (по умолчанию)
- 4 vCPU, 8 ГБ ОЗУ
- 8 vCPU, 16 ГБ ОЗУ

Песочницы **macOS** работают на Apple Silicon с Xcode:

- 8 vCPU, 8 ГБ ОЗУ (по умолчанию)
- 8 vCPU, 16 ГБ ОЗУ
- 8 vCPU, 24 ГБ ОЗУ

### Выбор Xcode {#xcode}

Каждая песочница macOS запускает одну версию Xcode, которую вы выбираете при её создании. Она загружает тот же образ, что и профиль <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link> для этой версии Xcode, поэтому агент собирает проект с тем же набором инструментов и симуляторами, что и ваш CI. На tuist.dev песочницы macOS сейчас предлагают:

- `26.6` (по умолчанию)
- `26.1.1`
- `27.0`
- `27.1`
- `27.2`

Выберите версию с помощью `xcode_version` (`--xcode` в CLI), указывая точную версию, как это делается в профилях раннеров:

| Где | Как |
| --- | --- |
| CLI | `tuist sandbox create --xcode 26.1.1` |
| API и MCP `create_sandbox` | `"xcode_version": "26.1.1"` |
| Плагин Tuist Mac для Amp | `tuist_mac_start` с `xcode` |
| Orbs Amp | Тип орба `macos-xcode-26-1-1` (см. <.localized_link href="/guides/features/sandboxes/amp#xcode">Amp</.localized_link>) |
| Claude Code и Claude Managed Agents | `xcode_version` в окружении или для каждой сессии Managed Agents (см. <.localized_link href="/guides/features/sandboxes/claude#xcode">Claude</.localized_link>) |

- **Без указания версии** Mac получает версию по умолчанию.
- **Версия, которую Tuist не предлагает, будет отклонена**, а в ошибке будет перечислен список доступных для выбора версий, чтобы вы знали, что доступно прямо сейчас.
- **Tuist не читает файл `.xcode-version` вашего репозитория.** Версию выбираете вы или агент, запрашивающий Mac. Инструмент MCP и плагин Tuist Mac указывают агентам использовать версию, закрепленную в проекте.
- **Песочница сохраняет свою версию Xcode на весь срок жизни.** Чтобы собрать проект с другой версией Xcode, создайте новую песочницу. `xcodebuild -version` показывает, какая версия Xcode запущена на Mac.

## Безопасность {#security}

- Каждая песочница является отдельной виртуальной машиной. Песочницы не разделяют файловую систему, память или процессы друг с другом или с задачами CI.
- Песочницы принадлежат аккаунту, и любой его участник может использовать и управлять ими, включая песочницы, обслуживающие интеграцию. Подключать интеграции могут только администраторы. Сессии из интеграции имеют доступ только к песочницам того аккаунта, к которому подключена интеграция.
- Учетные данные, которые вы предоставляете Tuist для подключения интеграции, такие как токен провайдера Amp или ключ окружения Claude, хранятся в зашифрованном виде и больше никогда не отображаются.
- Песочница имеет доступ к интернету. Относитесь к тому, к чему агент может получить доступ из неё, так же, как к задаче CI.
