# Песочницы {#sandboxes}

> [!IMPORTANT]
> **Только по приглашению**
>
> Песочницы Tuist, как для Linux, так и для macOS, сейчас доступны только по приглашению, пока мы масштабируем мощности. [Свяжитесь с нами](mailto:contact@tuist.dev) или напишите нам в [Slack-сообществе](https://slack.tuist.dev), чтобы запросить доступ для вашего аккаунта. Информация о ценах будет опубликована, когда песочницы станут общедоступными.

Песочница — это виртуальная машина, где агент для написания кода выполняет свои команды и редактирует файлы. Каждая сессия агента получает собственную песочницу, которая хранит его рабочую копию, артефакты сборки и установленные инструменты на протяжении всей сессии. Когда агент переходит в режим ожидания, песочница приостанавливается; следующее сообщение возобновляет работу с того места, где она остановилась.

Песочницы работают на том же парке машин, что и <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link>, рядом с <.localized_link href="/guides/features/cache">кэшем</.localized_link> вашей команды, поэтому сборки агента могут использовать те же кэшированные артефакты, что и ваши CI-системы и локальные машины.

Вы можете использовать песочницы через:

- **<.localized_link href="/guides/features/sandboxes/amp">Amp</.localized_link>**: запускайте орбы вашего рабочего пространства Amp на Tuist или предоставьте любому потоку Amp Mac для сборок Xcode с помощью <.localized_link href="/guides/features/sandboxes/amp#remote-mac">плагина Tuist Mac</.localized_link>.
- **<.localized_link href="/guides/features/sandboxes/claude">Claude</.localized_link>**: запускайте сессии Claude Managed Agents и облачные сессии Claude Code (claude.ai, десктопные и мобильные приложения, а также `claude --cloud`) на Tuist.
- **[The Tuist CLI](#cli)**: создавайте песочницы и выполняйте в них команды из терминала или из ваших собственных инструментов через API.

## Начало работы с CLI {#cli}

Создайте песочницу и выполняйте в ней команды из терминала с помощью `tuist sandbox`.

### 1. Вход в систему {#cli-log-in}

Для управления песочницами требуется администратор аккаунта:

```bash
tuist auth login
```

### 2. Создание песочницы {#cli-create}

```bash
tuist sandbox create --platform macos
```

Опустите `--platform` для Linux. Укажите `--vcpus` вместе с `--memory-gb` для выбора большей [конфигурации](#platforms) и `--workspace-gb` для увеличения диска. Команда завершается, когда песочница запущена, и выводит её детали, включая ID. Она использует аккаунт проекта Tuist в текущей директории; укажите `--account`, чтобы выбрать другой.

### 3. Выполнение команд {#cli-exec}

```bash
tuist sandbox exec <sandbox-id> -- xcodebuild -version
```

Команда выполняется через `bash -l` в песочнице, которая сначала возобновляется, если была приостановлена. `tuist` передаёт вывод столько, сколько выполняется команда, и завершается со статусом команды; Ctrl-C отменяет её выполнение в песочнице. При необходимости передавайте `--cwd`, `--env NAME=VALUE` и `--timeout` (до шести часов).

### Частые задачи {#cli-tasks}

| Задача | Команда |
| --- | --- |
| Список песочниц | `tuist sandbox list` |
| Показать одну | `tuist sandbox show <id>` |
| Приостановить или возобновить | `tuist sandbox pause <id>`, `tuist sandbox resume <id>` |
| Синхронизировать файлы локального рабочего дерева Git в песочницу | `tuist sandbox sync <id>` |
| Копировать файлы внутрь или наружу | `tuist sandbox cp <id>:<path> <local-path>`, `tuist sandbox cp <local-path> <id>:<path>` |
| Удалить | `tuist sandbox delete <id> --yes` |
| Посмотреть использование | `tuist sandbox analytics` |

Добавьте `--json` для вывода в машиночитаемом формате. См. <.localized_link href="/cli/sandbox">справочник CLI</.localized_link> для всех опций. Чтобы управлять песочницами из кода, используйте те же операции через [Tuist API](https://tuist.dev/api/docs) по пути `/api/accounts/{account_handle}/sandboxes` или позвольте агенту использовать их через <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>.

Инструменты, которые не могут выполнять интерактивный вход, например плагин агента, выполняющий сборку в песочнице macOS, могут аутентифицироваться с помощью <.localized_link href="/guides/server/authentication#account-tokens">токена аккаунта</.localized_link> со скоупом `account:sandboxes:write`. Он может создавать песочницы, выполнять в них команды, а также приостанавливать, возобновлять и удалять их, как участник аккаунта. Песочницы, обслуживающие интеграции Amp или Claude, а также настройки аналитики и интеграций, остаются под управлением администраторов аккаунта.

## Сборка на Mac из агента для написания кода {#coding-agents}

Агент для написания кода, работающий на Linux, например облачная сессия агента, может собирать, тестировать и запускать код для платформ Apple в песочнице macOS, продолжая редактировать файлы там, где он работает. В Amp установите <.localized_link href="/guides/features/sandboxes/amp#remote-mac">плагин Tuist Mac</.localized_link>. Для других агентов, таких как Claude Code или Cursor:

1. Подключите агента к <.localized_link href="/guides/features/agentic-coding/mcp">MCP-серверу</.localized_link> Tuist. Его инструмент `create_sandbox` сообщает агенту, как управлять Mac.
2. Установите Tuist CLI там, где работает агент, например в скрипте настройки окружения: `mise use -g tuist@latest` или `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist` (`tuist-linux-aarch64` на ARM).
3. Выполните аутентификацию CLI. Вход на MCP-сервере не распространяется на него, поэтому либо выполните `tuist auth login` как участник аккаунта, либо установите `TUIST_TOKEN` в значение <.localized_link href="/guides/server/authentication#account-tokens">токена аккаунта</.localized_link> со скоупом `account:sandboxes:write`.
4. Если окружение ограничивает сетевой доступ, разрешите доступ к `tuist.dev`. CLI загружает файлы на Mac через этот домен, поэтому другие домены не требуются.

Агент создаёт один Mac на задачу и перед каждой командой выполняет `tuist sandbox sync`. Он копирует файлы, которые Git не игнорирует (закоммиченные или нет), а затем только изменённые. Затем агент выполняет команды, такие как `xcodebuild`, с помощью `tuist sandbox exec`, копирует результаты, например скриншоты или собранное приложение, обратно с помощью `tuist sandbox cp` и удаляет Mac после завершения задачи. Mac остаётся запущенным в течение 10 минут после последней команды, поэтому следующая команда начинается немедленно; `tuist sandbox pause` позволяет освободить его раньше. Оставленный без внимания Mac затем приостанавливается и удаляется после 14 дней в приостановленном состоянии.

## Linux и macOS {#platforms}

Песочницы **Linux** работают на Ubuntu 24.04:

- 2 vCPU, 4 GiB RAM (по умолчанию)
- 4 vCPU, 8 GiB RAM
- 8 vCPU, 16 GiB RAM

Песочницы **macOS** работают на Apple silicon с Xcode:

- 8 vCPU, 8 GiB RAM (по умолчанию)
- 8 vCPU, 16 GiB RAM
- 8 vCPU, 24 GiB RAM

## Безопасность {#security}

- Каждая песочница — это отдельная виртуальная машина. Песочницы не разделяют файловую систему, память или процессы друг с другом или с задачами CI.
- Песочницы принадлежат аккаунту, и управлять ими могут только его администраторы. Сессии из интеграции имеют доступ только к песочницам аккаунта, к которому подключена интеграция.
- Учётные данные, которые вы предоставляете Tuist для подключения интеграции, такие как токен провайдера Amp или ключ окружения Claude, хранятся в зашифрованном виде и больше не отображаются.
- Песочница имеет доступ к интернету. Относитесь к тому, что агент может получить из неё, так же, как к задаче CI.
