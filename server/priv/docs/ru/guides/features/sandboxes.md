# Песочницы {#sandboxes}

> [!IMPORTANT]
> **Только по приглашению**
>
> Tuist Sandboxes для Linux и macOS сейчас доступны только по приглашениям, пока мы масштабируем мощности. [Свяжитесь с нами](mailto:contact@tuist.dev) или напишите нам в [Slack-сообществе](https://slack.tuist.dev), чтобы запросить доступ для вашего аккаунта. Цены будут объявлены, когда Sandboxes станут общедоступными.

Песочница — это виртуальная машина, на которой агент программирования выполняет команды и редактирует файлы. Каждой сессии агента выделяется собственная песочница, которая хранит клон репозитория, артефакты сборки и установленные инструменты на протяжении всей сессии. Когда агент простаивает, песочница приостанавливается; следующее сообщение возобновляет работу с того места, где она остановилась.

Песочницы работают на том же парке машин, что и <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link>, рядом с <.localized_link href="/guides/features/cache">кешем</.localized_link> вашей команды, поэтому сборки агента могут использовать те же кешированные артефакты, что и ваши CI-системы и локальные машины.

Вы можете использовать песочницы через:

- **<.localized_link href="/guides/features/sandboxes/amp">Amp</.localized_link>**: запускайте орбы вашего рабочего пространства Amp на Tuist или предоставляйте любому треку Amp Mac для сборок Xcode с помощью <.localized_link href="/guides/features/sandboxes/amp#remote-mac">плагина Tuist Mac</.localized_link>.
- **<.localized_link href="/guides/features/sandboxes/claude">Claude</.localized_link>**: запускайте сессии Claude Managed Agents и облачные сессии Claude Code (claude.ai, десктопные и мобильные приложения, а также `claude --cloud`) на Tuist.
- **[CLI Tuist](#cli)**: создавайте песочницы и выполняйте в них команды из терминала или из ваших собственных инструментов через API.

## Начало работы с CLI {#cli}

Создайте песочницу и выполняйте в ней команды из терминала с помощью `tuist sandbox`.

### 1. Вход в систему {#cli-log-in}

Любой участник аккаунта может создавать песочницы и управлять ими:

```bash
tuist auth login
```

### 2. Создание песочницы {#cli-create}

```bash
tuist sandbox create --platform macos
```

Опустите `--platform` для Linux. Укажите `--xcode` с версией, например `--xcode 26.1.1`, чтобы получить Mac с этой версией [Xcode](#xcode); это автоматически подразумевает `--platform macos`. Укажите `--vcpus` вместе с `--memory-gb` для выбора большей [конфигурации](#platforms), `--guaranteed-vcpus` для гарантированного выделения большего количества [процессорных ядер](#guaranteed-cpu) в песочнице Linux и `--workspace-gb` для увеличения диска. Команда завершится, когда песочница запустится, и выведет её параметры, включая ID. Она использует аккаунт проекта Tuist в текущей директории; укажите `--account`, чтобы выбрать другой.

### 3. Выполнение команд {#cli-exec}

```bash
tuist sandbox exec <sandbox-id> -- xcodebuild -version
```

Команда выполняется через `bash -l` в песочнице, которая сначала возобновляется, если была приостановлена. `tuist` передаёт вывод команды столько, сколько она выполняется, и завершается со статусом команды; Ctrl-C отменяет выполнение в песочнице. При необходимости укажите `--cwd`, `--env NAME=VALUE` и `--timeout` (до шести часов).

### Частые задачи {#cli-tasks}

| Задача | Команда |
| --- | --- |
| Список песочниц | `tuist sandbox list` |
| Показать одну | `tuist sandbox show <id>` |
| Приостановить или возобновить | `tuist sandbox pause <id>`, `tuist sandbox resume <id>` |
| Синхронизировать файлы локального Git-рабочего дерева в песочницу | `tuist sandbox sync <id>` |
| Копировать файлы из песочницы или в неё | `tuist sandbox cp <id>:<path> <local-path>`, `tuist sandbox cp <local-path> <id>:<path>` |
| Удалить | `tuist sandbox delete <id> --yes` |
| Посмотреть использование | `tuist sandbox analytics` |

Добавьте `--json` для вывода в машиночитаемом формате. Все опции описаны в <.localized_link href="/cli/sandbox">справочнике CLI</.localized_link>. Чтобы управлять песочницами из кода, используйте те же операции через [Tuist API](https://tuist.dev/api/docs) по пути `/api/accounts/{account_handle}/sandboxes` или позвольте агенту работать с ними через <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>.

Инструменты, которые не могут проходить интерактивную аутентификацию, например плагин агента, выполняющий сборку в песочнице macOS, могут аутентифицироваться с помощью <.localized_link href="/guides/server/authentication#account-tokens">токена аккаунта</.localized_link> со скоупом `account:sandboxes:write`. Такой токен позволяет делать всё, что может участник аккаунта: создавать песочницы, выполнять в них команды, приостанавливать, возобновлять, архивировать и удалять их. Настройки интеграций остаются у администраторов аккаунта.

### Tuist внутри песочницы {#tuist-in-sandbox}

Образы песочниц не включают CLI Tuist, поэтому используется версия, закреплённая в вашем проекте. После первой синхронизации `tuist sandbox sync` выполните `mise install` в корне репозитория на песочнице (установлены `mise` и `brew`). Каждая команда, запускаемая через `tuist sandbox exec`, получает приоритет shims mise (`$HOME/.local/share/mise/shims`) в переменной `PATH`, поэтому `tuist` и другие инструменты mise выполняются в ваших командах и на этапах сборки Xcode, например в post-actions схемы.

Каждая команда, запускаемая через `tuist sandbox exec`, также получает возможности Tuist runner, поэтому сборки в песочнице используют <.localized_link href="/guides/features/cache">кеш</.localized_link> вашего аккаунта без передачи учётных данных:

- `TUIST_URL` и, если хост песочницы имеет к нему доступ (например, на macOS), `TUIST_CACHE_ENDPOINT` кеша в той же стойке.
- `TUIST_OIDC_TOKEN` — кратковременный токен идентичности для этой команды. Туист CLI версии 4.218.0 и новее входит в систему с его помощью автоматически; для версий с 4.215.0 по 4.217.x сначала выполните `tuist auth login` в той же команде.

Токен выпускается для каждой команды и может быть обменен на токен Tuist только во время выполнения этой команды, поэтому песочница никогда не хранит долгоживущие учётные данные. Он никогда не предоставляет больше прав, чем есть у пользователя или токена, запустившего команду, для работы с кешем: участники аккаунта, чьи токены кеша имеют права только на запись, получают доступ на чтение, а токен аккаунта должен иметь скоупы кеша, такие как `ci`, вместе с `account:sandboxes:write`, чтобы песочница вообще могла использовать кеш. Переменные, переданные через `--env`, имеют приоритет.

## Сборка на Mac от агента программирования {#coding-agents}

Агент программирования, работающий на Linux, например облачная сессия агента, может собирать, тестировать и запускать код для платформ Apple в песочнице macOS, продолжая редактировать файлы там, где он работает. В Amp установите <.localized_link href="/guides/features/sandboxes/amp#remote-mac">плагин Tuist Mac</.localized_link>. Для других агентов, таких как Claude Code или Cursor:

1. Подключите агента к <.localized_link href="/guides/features/agentic-coding/mcp">MCP-серверу</.localized_link> Tuist. Его инструмент `create_sandbox` сообщает агенту, как управлять Mac.
2. Установите CLI Tuist там, где работает агент, например в скрипте настройки окружения: `mise use -g tuist@latest` или `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist` (`tuist-linux-aarch64` для ARM).
3. Аутентифицируйте CLI. Вход на MCP-сервере не распространяется на него, поэтому либо выполните `tuist auth login` как участник аккаунта, либо установите `TUIST_TOKEN` в значение <.localized_link href="/guides/server/authentication#account-tokens">токена аккаунта</.localized_link> со скоупом `account:sandboxes:write`.
4. Если окружение ограничивает сетевой доступ, разрешите `tuist.dev`. CLI загружает файлы на Mac через него, поэтому другие домены не требуются.

Агент создает один Mac для каждой задачи с версией [Xcode](#xcode), закрепленной в проекте: `create_sandbox` перечисляет доступные версии Xcode и указывает агенту прочитать закрепленную версию проекта, например `.xcode-version`. Перед каждой командой он выполняет `tuist sandbox sync`. Он копирует файлы, которые Git не игнорирует (как закоммиченные, так и нет), а затем — только измененные. После первой синхронизации он запускает `mise install` в корне репозитория на Mac, чтобы там оказалась [закрепленная версия Tuist проекта](#tuist-in-sandbox), авторизованная в кеше вашего аккаунта. Затем агент выполняет такие команды, как `xcodebuild`, с помощью `tuist sandbox exec`, копирует результаты, такие как скриншоты или собранное приложение, обратно с помощью `tuist sandbox cp` и удаляет Mac после завершения задачи. Mac остается работающим в течение 10 минут после последней команды, чтобы следующая запустилась мгновенно; `tuist sandbox pause` позволяет освободить его раньше. Оставленный без присмотра Mac переходит в режим паузы и удаляется после 14 дней в этом состоянии.

## Linux и macOS {#platforms}

Песочницы **Linux** работают на Ubuntu 24.04. Каждая песочница Linux имеет 16 виртуальных процессоров (vCPU) и использует свободные ядра машины, на которой она запущена, поэтому конфигурация определяет объем памяти:

- 2 ГБ ОЗУ (`--vcpus 1 --memory-gb 2`)
- 4 ГБ ОЗУ (`--vcpus 2 --memory-gb 4`, по умолчанию)
- 8 ГБ ОЗУ (`--vcpus 4 --memory-gb 8`)
- 16 ГБ ОЗУ (`--vcpus 8 --memory-gb 16`)
- 32 ГБ ОЗУ (`--vcpus 16 --memory-gb 32`)
- 44 ГБ ОЗУ (`--vcpus 16 --memory-gb 44`)

Песочницы **macOS** работают на Apple Silicon с Xcode:

- 8 vCPU, 8 ГБ ОЗУ (по умолчанию)
- 8 vCPU, 16 ГБ ОЗУ
- 8 vCPU, 24 ГБ ОЗУ

### Гарантированные процессоры {#guaranteed-cpu}

Песочнице Linux гарантируется четверть vCPU на каждый ГБ памяти, например 2 vCPU для 8 ГБ, и она использует дополнительные ресурсы, если машина простаивает, вплоть до своих 16 vCPU. Это подходит для агента, который большую часть времени ожидает, а затем выполняет сборку рывками. Если сборке требуется более стабильная производительность CPU даже на загруженной машине, при создании песочницы гарантируйте ей 1, 2, 4 или 8 vCPU; она получит большее значение между этой гарантией и гарантией, зависящей от памяти:

| Где | Как |
| --- | --- |
| CLI | `tuist sandbox create --guaranteed-vcpus 4` |
| API и MCP `create_sandbox` | `"guaranteed_vcpus": 4` |

- **Гарантия — это минимум, а не предел.** Песочница с 4 гарантированными vCPU все равно может использовать до 16, когда ядра свободны. При конкуренции за ресурсы каждая песочница получает долю CPU пропорционально своей гарантии.
- **Оплата взимается исходя из минимума.** За работающую песочницу взимается плата за используемые ею процессоры, но не менее гарантированного минимума.
- **Песочница сохраняет свою гарантию на весь срок жизни.** Чтобы изменить её, создайте новую песочницу.
- **Песочницы macOS всегда имеют полную конфигурацию**, поэтому для них не применяется отдельная гарантия.

### Выбор версии Xcode {#xcode}

Каждая песочница macOS запускает одну версию Xcode, которую вы выбираете при её создании. Она загружает тот же образ, что и профиль <.localized_link href="/guides/features/runners">Tuist Runners</.localized_link> для этой версии Xcode, поэтому агент собирает проект с тем же набором инструментов и симуляторами, что и ваш CI. На tuist.dev песочницы macOS в настоящее время предлагают:

- `26.6` (по умолчанию)
- `26.1.1`
- `27.0`
- `27.1`
- `27.2`

Выберите версию с помощью `xcode_version` (`--xcode` в CLI), указывая точную версию, как это делают профили раннеров:

| Где | Как |
| --- | --- |
| CLI | `tuist sandbox create --xcode 26.1.1` |
| API и MCP `create_sandbox` | `"xcode_version": "26.1.1"` |
| Плагин Tuist Mac для Amp | `tuist_mac_start` с параметром `xcode` |
| Orbs в Amp | Тип орба `macos-xcode-26-1-1` (см. <.localized_link href="/guides/features/sandboxes/amp#xcode">Amp</.localized_link>) |
| Claude Code и Claude Managed Agents | `xcode_version` в настройках окружения или для каждой сессии Managed Agents (см. <.localized_link href="/guides/features/sandboxes/claude#xcode">Claude</.localized_link>) |

- **Без указания версии** Mac получит версию по умолчанию.
- **Версия, которую Tuist не предлагает, будет отклонена**, а в сообщении об ошибке будут перечислены доступные для выбора версии, чтобы вы знали, что доступно прямо сейчас.
- **Tuist не считывает `.xcode-version` вашего репозитория.** Версию выбираете вы или агент, запрашивающий Mac. Инструмент MCP и плагин Tuist Mac instruct агентов использовать версию, зафиксированную в проекте.
- **Песочница сохраняет свою версию Xcode на весь срок жизни.** Чтобы собирать проект с другой версией Xcode, создайте новую песочницу. `xcodebuild -version` показывает, какая версия Xcode запущена на Mac.

## Безопасность {#security}

- Каждая песочница — это отдельная виртуальная машина. Песочницы не разделяют файловую систему, память или процессы друг с другом или с задачами CI.
- Песочницы принадлежат аккаунту, и любой его участник может использовать и управлять ими, включая песочницы, обслуживающие интеграцию. Подключать интеграции могут только администраторы. Сессии от интеграции имеют доступ только к песочницам того аккаунта, к которому подключена интеграция.
- Учетные данные, которые вы предоставляете Tuist для подключения интеграции, такие как токен провайдера Amp или ключ окружения Claude, хранятся в зашифрованном виде и больше никогда не отображаются.
- Песочница имеет доступ к интернету. Относитесь к тому, что агент может получить из неё, так же, как к задаче CI.
