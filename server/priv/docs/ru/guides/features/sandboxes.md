# Песочницы {#sandboxes}

> [!IMPORTANT]
> **Только по приглашению**
>
> Песочницы Tuist, как для Linux, так и для macOS, сейчас доступны только по приглашению, пока мы наращиваем мощности. [Свяжитесь с нами](mailto:contact@tuist.dev) или напишите нам в [Slack сообщества](https://slack.tuist.dev), чтобы запросить доступ для вашего аккаунта. Цены будут объявлены, когда песочницы станут общедоступными.

Песочница — это виртуальная машина, где агент для написания кода выполняет свои команды и редактирует файлы. Каждая сессия агента получает собственную песочницу, которая хранит его рабочую копию, артефакты сборки и установленные инструменты на протяжении всей сессии. Когда агент переходит в режим ожидания, песочница приостанавливается; следующее сообщение возобновляет работу с того места, где она остановилась.

Песочницы работают на том же парке машин, что и <.localized_link href="/guides/features/runners">раннеры Tuist</.localized_link>, рядом с <.localized_link href="/guides/features/cache">кешем</.localized_link> вашей команды, поэтому сборки агента могут использовать те же кешированные артефакты, что и ваши CI-системы и локальные машины.

Вы можете использовать песочницы через:

- **<.localized_link href="/guides/features/sandboxes/amp">Amp</.localized_link>**: запускайте орбы вашего рабочего пространства Amp в Tuist или предоставьте любому потоку Amp Mac для сборок Xcode с помощью <.localized_link href="/guides/features/sandboxes/amp#remote-mac">плагина Tuist Mac</.localized_link>.
- **<.localized_link href="/guides/features/sandboxes/claude">Claude</.localized_link>**: запускайте сессии Claude Managed Agents и облачные сессии Claude Code (claude.ai, десктопные и мобильные приложения, а также `claude --cloud`) в Tuist.
- **[CLI Tuist](#cli)**: создавайте песочницы и выполняйте в них команды из терминала или из ваших собственных инструментов через API.

## Начало работы с CLI {#cli}

Создайте песочницу и выполняйте в ней команды из терминала с помощью `tuist sandbox`.

### 1. Вход в систему {#cli-log-in}

Любой участник аккаунта может создавать песочницы и управлять ими:

```bash
tuist auth login
```

### 2. Создание песочницы {#cli-create}

```bash
tuist sandbox create --platform macos
```

Опустите `--platform` для Linux. Передайте `--xcode` с версией, например `--xcode 26.1.1`, для Mac с этой [Xcode](#xcode); это подразумевает `--platform macos`. Передайте `--vcpus` вместе с `--memory-gb` для выбора большего [типа машины](#platforms), `--guaranteed-vcpus` для гарантированного выделения большего количества [процессорных ядер](#guaranteed-cpu) для песочницы Linux и `--workspace-gb` для увеличения диска. Песочница работает два часа с момента создания и два часа после каждого возобновления; передайте `--lifetime-minutes` для установки времени от 5 минут до суток. Когда срок жизни истекает, выполняемые команды отменяются, а песочница приостанавливается и архивируется с сохранением файлов, чтобы забытая песочница перестала потреблять ресурсы вашего аккаунта. Команда завершается, когда песочница запущена, и выводит её детали, включая ID. Если все хосты заняты, например, когда задачи CI удерживают общие Mac, сервер ждет 25 секунд, прежде чем создание завершится ошибкой `fleet_busy`; передайте `--wait-timeout 5m`, чтобы продолжать попытки до 5 минут (максимум час), при этом причина будет повторяться в stderr примерно раз в минуту. Используется аккаунт проекта Tuist в текущей директории; передайте `--account`, чтобы выбрать другой.

### 3. Выполнение команд {#cli-exec}

```bash
tuist sandbox exec <sandbox-id> -- xcodebuild -version
```

Команда выполняется через `bash -l` в песочнице, которая сначала возобновляется, если была приостановлена. `tuist` передает вывод столько, сколько выполняется команда, и завершается со статусом команды; Ctrl-C отменяет выполнение в песочнице. При необходимости передайте `--cwd`, `--env NAME=VALUE` и `--timeout` (до шести часов).

Команда выполняется отдельно от `tuist`, поэтому она переживает разрыв соединения. Чтобы вписать долгую сборку в вызов инструмента с ограничением по времени, например, для агента, передайте `--wait <seconds>`: когда время истекает, `tuist` оставляет команду выполняться, завершается со статусом 75 и выводит команду `tuist sandbox exec <sandbox-id> --attach <command-id> --stdout-offset … --stderr-offset …`, которая продолжает вывод с места остановки и завершается со статусом исходной команды.

### Частые задачи {#cli-tasks}

| Задача | Команда |
| --- | --- |
| Список песочниц | `tuist sandbox list` |
| Показать одну | `tuist sandbox show <id>` |
| Приостановить или возобновить | `tuist sandbox pause <id>`, `tuist sandbox resume <id>` |
| Продлить работу после истечения срока | `tuist sandbox extend <id> --lifetime-minutes 240` |
| Синхронизировать файлы локального Git-дерева | `tuist sandbox sync <id>` |
| Копировать файлы внутрь или наружу | `tuist sandbox cp <id>:<path> <local-path>`, `tuist sandbox cp <local-path> <id>:<path>` |
| Удалить | `tuist sandbox delete <id> --yes` |
| Посмотреть использование | `tuist sandbox analytics` |

Добавьте `--json` для вывода в машиночитаемом формате. См. <.localized_link href="/cli/sandbox">справочник CLI</.localized_link> для всех опций. Чтобы управлять песочницами из кода, используйте те же операции через [Tuist API](https://tuist.dev/api/docs) по пути `/api/accounts/{account_handle}/sandboxes` или позвольте агенту использовать их через <.localized_link href="/guides/features/agentic-coding/mcp">MCP</.localized_link>.

Инструменты, которые не могут войти в систему интерактивно, например плагин агента, выполняющий сборку в песочнице macOS, могут аутентифицироваться с помощью <.localized_link href="/guides/server/authentication#account-tokens">токена аккаунта</.localized_link> со скоупом `account:sandboxes:write`. Он может делать всё то же, что и участник аккаунта: создавать песочницы, выполнять в них команды, а также приостанавливать, возобновлять, архивировать и удалять их. Настройки интеграций и выполнение команд в песочницах, обслуживающих интеграцию, остаются за администраторами аккаунта.

### Tuist внутри песочницы {#tuist-in-sandbox}

Песочницы macOS поставляются с CLI Tuist. Когда ваш проект фиксирует версию Tuist через mise (`mise.toml` или `.tool-versions`), `tuist` запускает именно эту версию, устанавливая её при первом запросе. Каждая команда, запущенная через `tuist sandbox exec`, имеет шимы mise (`$HOME/.local/share/mise/shims`) первыми в `PATH`, а системный Tuist образа — последним, поэтому `tuist` и другие инструменты mise работают в ваших командах и в фазах сборки Xcode, таких как post-actions схемы. Каждый Mac также содержит руководство для агентов по адресу `/opt/tuist/agent-guide.md`, сгенерированное на основе образа: информация об Xcode и симуляторах, расположение репозитория и содержимое готового снимка. Claude Code, Codex и Amp, работающие на Mac, находят его через свои файлы инструкций.

Каждая команда, запущенная через `tuist sandbox exec`, также получает доступ к ресурсам раннера Tuist, поэтому сборки в песочнице используют <.localized_link href="/guides/features/cache">кеш</.localized_link> вашего аккаунта без передачи учетных данных:

- `TUIST_URL` и, если хост песочницы имеет к нему доступ (например, на macOS), `TUIST_CACHE_ENDPOINT` кеша в той же стойке.
- `TUIST_OIDC_TOKEN`, краткосрочный токен идентичности для этой команды. Tuist CLI версии 4.218.0 и новее входят с его помощью автоматически; для версий с 4.215.0 по 4.217.x сначала выполните `tuist auth login` в той же команде.

Токен выпускается для каждой команды и может быть обменен на токен Tuist только во время её выполнения, поэтому песочница никогда не хранит долгосрочные учетные данные. Он не предоставляет больше прав, чем есть у пользователя или токена, запустившего команду, для работы с кешем: участники аккаунта, чьи токены кеша имеют права только на запись, получают доступ на чтение, а токен аккаунта требует скоупов кеша, таких как `ci`, вместе с `account:sandboxes:write` для использования кеша песочницей. Переменные, переданные через `--env`, имеют приоритет.

## Сборка на Mac из агента для написания кода {#coding-agents}

Агент для написания кода, работающий на Linux, например облачная сессия агента, может собирать, тестировать и запускать код для платформ Apple в песочнице macOS, продолжая редактировать файлы в месте своего запуска. В Amp установите <.localized_link href="/guides/features/sandboxes/amp#remote-mac">плагин Tuist Mac</.localized_link>. Для других агентов, таких как Claude Code или Cursor:

1. Подключите агента к <.localized_link href="/guides/features/agentic-coding/mcp">MCP-серверу</.localized_link> Tuist. Его инструмент `create_sandbox` сообщает агенту, как управлять Mac.
2. Установите CLI Tuist там, где работает агент, например в скрипте настройки окружения: `mise use -g tuist@latest`, или `curl -fsSL https://github.com/tuist/tuist/releases/download/<version>/tuist-linux-x86_64.tar.gz | tar -xz -C /usr/local/bin tuist` (`tuist-linux-aarch64` на ARM).
3. Выполните аутентификацию CLI. Вход на MCP-сервере не распространяется на него, поэтому либо выполните `tuist auth login` как участник аккаунта, либо установите для `TUIST_TOKEN` значение <.localized_link href="/guides/server/authentication#account-tokens">токена аккаунта</.localized_link> со скоупом `account:sandboxes:write`.
4. Если окружение ограничивает сетевой доступ, разрешите доступ к `tuist.dev`. CLI загружает файлы на Mac через этот домен, поэтому другие домены не требуются.
5. По желанию разрешите агенту создавать и удалять Mac без запроса каждый раз. Агенты запрашивают подтверждение перед вызовом `create_sandbox`, так как Mac учитывается в лимитах вашего аккаунта, и перед `delete_sandbox`, так как это действие необратимо. В Claude Code разрешите оба действия в `.claude/settings.json`, используя имя, под которым вы зарегистрировали MCP-сервер (здесь `tuist`):

   ```json
   {
     "permissions": {
       "allow": ["mcp__tuist__create_sandbox", "mcp__tuist__delete_sandbox"]
     }
   }
   ```

Чтобы агент выполнил настройку, передайте ему следующий промпт:

```text
Set up this environment so you can build and test this project on a Tuist macOS sandbox.

Read https://tuist.dev/en/docs/guides/features/sandboxes#coding-agents and follow its "Build on a Mac from a coding agent" section. It's the current Tuist guide for this, so prefer it over anything you remember about Tuist.

You're done when you have created a Mac with create_sandbox, synced this repository to it with tuist sandbox sync, run the project's build there with tuist sandbox exec, and deleted the Mac.

Ask me before anything that needs my login or approval, such as tuist auth login. If a step fails or is blocked, stop and tell me which step you reached and the exact error, without secrets.
```

Агент создает один Mac для каждой задачи с версией [Xcode](#xcode), закрепленной в проекте: `create_sandbox` перечисляет доступные версии Xcode и указывает агенту прочитать закрепленную версию проекта, например `.xcode-version`. Перед каждой командой он выполняет `tuist sandbox sync`. Он копирует файлы, которые Git не игнорирует (закоммиченные или нет), а затем только измененные файлы. На Mac уже установлен [Tuist](#tuist-in-sandbox) (закрепленная версия проекта, если она есть), выполнен вход в кеш вашего аккаунта, и агент один раз читает руководство по Mac. Затем агент запускает команды, такие как `xcodebuild`, через `tuist sandbox exec`, копирует результаты, такие как скриншоты или собранное приложение, обратно через `tuist sandbox cp` и удаляет Mac после завершения задачи. Mac остается работающим в течение 10 минут после последней команды, поэтому следующая команда запускается сразу; `tuist sandbox pause` позволяет освободить его раньше. Оставленный без присмотра Mac переходит в режим паузы, архивируется по истечении двухчасового срока жизни и удаляется через 14 дней; агент продлевает срок жизни перед длительной сборкой.

## Linux и macOS {#platforms}

Песочницы **Linux** работают на Ubuntu 24.04. Каждая песочница Linux имеет 16 vCPU и использует свободные ядра машины, на которой она запущена, поэтому её конфигурация определяет объем памяти:

- 2 ГБ ОЗУ (`--vcpus 1 --memory-gb 2`)
- 4 ГБ ОЗУ (`--vcpus 2 --memory-gb 4`, по умолчанию)
- 8 ГБ ОЗУ (`--vcpus 4 --memory-gb 8`)
- 16 ГБ ОЗУ (`--vcpus 8 --memory-gb 16`)
- 32 ГБ ОЗУ (`--vcpus 16 --memory-gb 32`)
- 44 ГБ ОЗУ (`--vcpus 16 --memory-gb 44`)

Песочницы **macOS** работают на Apple Silicon с Xcode:

- 8 vCPU, 8 ГБ ОЗУ (по умолчанию)
- 8 vCPU, 16 ГБ ОЗУ
- 8 vCPU, 24 ГБ ОЗУ

### Гарантированное CPU {#guaranteed-cpu}

Песочнице Linux гарантируется четверть vCPU на каждый ГБ памяти, например 2 vCPU для 8 ГБ, и она использует дополнительные ресурсы, если машина простаивает, вплоть до своих 16 vCPU. Это подходит для агента, который большую часть времени ожидает, а затем выполняет сборки всплесками. Если сборке требуется более стабильный доступ к CPU даже на загруженной машине, при создании песочницы гарантируйте ей 1, 2, 4 или 8 vCPU; она получит большее значение из этого числа и гарантии, зависящей от памяти:

| Где | Как |
| --- | --- |
| CLI | `tuist sandbox create --guaranteed-vcpus 4` |
| API и MCP `create_sandbox` | `"guaranteed_vcpus": 4` |

- **Гарантия — это минимум, а не предел.** Песочница с 4 гарантированными vCPU все равно может использовать до 16, когда ядра свободны. При конкуренции за ресурсы каждая песочница получает CPU пропорционально своей гарантии.
- **Оплата взимается за минимум.** За работающую песочницу взимается плата за используемое CPU, но не менее гарантированного объема.
- **Песочница сохраняет свою гарантию на весь срок жизни.** Чтобы изменить её, создайте новую песочницу.
- **Песочницы macOS всегда имеют полную конфигурацию**, поэтому они не используют гарантии.

### Выбор версии Xcode {#xcode}

Каждая песочница macOS запускает одну версию Xcode, которую вы выбираете при её создании. Она загружает тот же образ, что и профиль <.localized_link href="/guides/features/runners">раннеров Tuist</.localized_link> для этой версии Xcode, поэтому агент собирает проект с тем же набором инструментов и симуляторами, что и ваш CI. На tuist.dev песочницы macOS в настоящее время предлагают:

- `26.6` (по умолчанию)
- `26.1.1`
- `27.0`
- `27.1`
- `27.2`

Выберите версию через `xcode_version` (`--xcode` в CLI), указав точную версию, как это делается в профилях раннеров:

| Где | Как |
| --- | --- |
| CLI | `tuist sandbox create --xcode 26.1.1` |
| API и MCP `create_sandbox` | `"xcode_version": "26.1.1"` |
| Плагин Tuist Mac для Amp | `tuist_mac_start` с параметром `xcode` |
| Orbs в Amp | Тип орба `macos-xcode-26-1-1` (см. <.localized_link href="/guides/features/sandboxes/amp#xcode">Amp</.localized_link>) |
| Claude Code и Claude Managed Agents | `xcode_version` в окружении или для каждой сессии Managed Agents (см. <.localized_link href="/guides/features/sandboxes/claude#xcode">Claude</.localized_link>) |

- **Без указания версии** Mac получит версию по умолчанию.
- **Запрос на версию, которую Tuist не предлагает, будет отклонен**, а в сообщении об ошибке будут перечислены доступные для выбора версии, чтобы вы знали, что доступно прямо сейчас.
- **Tuist не читает файл `.xcode-version` вашего репозитория.** Версию выбираете вы или агент, запрашивающий Mac. Инструмент MCP и плагин Tuist Mac подсказывают агентам использовать версию, закрепленную в проекте.
- **Песочница сохраняет выбранную версию Xcode на весь срок жизни.** Чтобы собрать проект с другой версией Xcode, создайте новую песочницу. `xcodebuild -version` показывает, какая версия Xcode запущена на Mac.

## Безопасность {#security}

- Каждая песочница — это отдельная виртуальная машина. Песочницы не разделяют файловую систему, память или процессы друг с другом или с задачами CI.
- Песочницы принадлежат аккаунту, и любой его участник может использовать и управлять ими. Песочницы, обслуживающие интеграцию, например орб Amp или сессию Claude Code, хранят данные и учетные данные этой сессии: участники могут просматривать их, ставить на паузу, возобновлять, архивировать и удалять, но только администраторы могут выполнять в них команды или загружать файлы. Только администраторы подключают интеграции. Сессии из интеграции имеют доступ только к песочницам того аккаунта, к которому подключена интеграция.
- Учетные данные, которые вы предоставляете Tuist для подключения интеграции, такие как токен провайдера Amp или ключ окружения Claude, хранятся в зашифрованном виде и больше никогда не отображаются.
- Песочница имеет доступ к интернету. Относитесь к тому, к чему агент может получить доступ из неё, так же, как к задаче CI.
