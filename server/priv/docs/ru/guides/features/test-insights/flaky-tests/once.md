# Нестабильные тесты Once {#once-flaky-tests}

> [!IMPORTANT]
> **Требования**
>
> - Настройте <.localized_link href="/guides/features/test-insights/once">аналитику тестов Once</.localized_link> со структурированными результатами отдельных тестов.

<!-- @snippet: ./_intro -->

## Как работает обнаружение нестабильности {#how-it-works}

### Повторные запуски тестов {#test-retries}

Когда раннер сообщает несколько попыток для одного и того же теста, Tuist сохраняет их. Тест, который сначала завершился с ошибкой, а затем прошёл, помечается как нестабильный; тест, который продолжает завершаться с ошибкой, остаётся неудачным. Включите повторные запуски в используемом раннере, если это поддерживается. Подключение Once к Tuist не добавляет автоматически повторные запуски ко всем целям тестирования.

### Обнаружение между запусками {#cross-run-detection}

Общая история тестов также позволяет Tuist сравнивать успешные и неудачные результаты для одного и того же теста и коммита в CI. Для такого сравнения Once должен передавать информацию о коммите и контексте CI; локальные запуски остаются видимыми, но не становятся автоматическими доказательствами нестабильности между запусками.

Тест-кейсы идентифицируются по нативной цели, набору тестов и имени кейса. Сохраняйте эти идентификаторы неизменными, чтобы сохранить историю, и используйте полные отчёты по каждому кейсу вместо вывода надёжности из общего результата цели.

## Исследование нестабильных тестов {#investigate-flaky-tests}

Откройте историю тест-кейса в Tuist, чтобы сравнить его попытки, сбои и затронутые коммиты в CI. Общие запросы к тестам также доступны через <.localized_link href="/guides/features/agentic-coding/mcp">инструменты Model Context Protocol</.localized_link>, поэтому агент написания кода может исследовать те же сообщённые результаты.

## Управление нестабильными тестами {#managing-flaky-tests}

Вы можете отметить или снять отметку о нестабильности теста на странице его деталей во время расследования сбоя. Автоматизация обнаружения нестабильных тестов по умолчанию также снимает флаг после окна восстановления, обычно 14 дней без нового триггера.

В проектах Once сейчас нет вкладки настроек **Automations**. Обнаружение и сохранённое состояние тестов доступны, но рабочий процесс настроек, документированный для систем сборки с принудительным карантином, пока не представлен для Once.

## Карантин {#quarantining}

Tuist может сопоставлять сообщённые кейсы с их сохранённым состоянием карантина, но нативный клиент Once сейчас не получает и не применяет политики Tuist **Muted** или **Skipped**. Изменение этого состояния в Tuist не останавливает выполнение теста в Once и не делает так, чтобы его сбой перестал блокировать CI.

Используйте собственную политику фильтрации или обработки сбоев вашего раннера, когда нужен карантин на этапе выполнения. Не полагайтесь только на состояние в панели управления для изменения кода завершения команды.
