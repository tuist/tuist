Карантин изолирует нестабильный тест, чтобы он не блокировал CI, пока вы его исправляете. По умолчанию это **ручное действие**: вы помещаете тест в карантин, выводите его из карантина и переключаете режимы на странице деталей тест-кейса в дашборде. Также можно настроить **автоматическое оповещение** в разделе **Settings → Automations**, чтобы тест автоматически игнорировался (или пропускался) при превышении порога нестабильности и выводился из карантина после восстановления. Каждый переход, ручной или автоматический, записывается в журнал аудита тест-кейса.

По умолчанию восстановление ожидает, пока условие срабатывания перестанет выполняться, поэтому тест остается в карантине, пока старые нестабильные запуски не выйдут из окна срабатывания. Чтобы ускорить восстановление, установите для **Recover when** значение **No new flaky runs**: тест восстановится, если в течение окна восстановления (в днях или запускаx) не будет новых нестабильных запусков; каждый новый нестабильный запуск сбрасывает этот таймер ожидания, а после восстановления только новый нестабильный запуск снова поместит тест в карантин.
