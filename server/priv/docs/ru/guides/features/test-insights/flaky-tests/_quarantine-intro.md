Карантин изолирует нестабильный тест, чтобы он не блокировал CI, пока вы его исправляете. По умолчанию это **ручное действие**: вы помещаете тест в карантин, выводите его из карантина и переключаете режимы на странице деталей тест-кейса в дашборде. Вы также можете настроить **автоматическое оповещение** в разделе **Settings → Automations**, чтобы тест автоматически игнорировался (или пропускался) при превышении порога нестабильности и выводился из карантина после восстановления. Каждый переход, ручной или автоматический, записывается в журнал аудита тест-кейса.

По умолчанию восстановление происходит только после того, как условие срабатывания перестает выполняться, поэтому тест остается в карантине, пока старые нестабильные запуски не выйдут за пределы окна срабатывания. Чтобы ускорить восстановление, установите для параметра **Recover when** значение **No new flaky runs**: тест восстановится, если в течение окна восстановления (в днях или запусках) не будет новых нестабильных запусков; каждый новый нестабильный запуск перезапускает ожидание, а после восстановления тест снова попадет в карантин только при появлении нового нестабильного запуска.
