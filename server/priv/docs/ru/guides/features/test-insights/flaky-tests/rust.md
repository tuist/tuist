# Нестабильные тесты в Rust {#rust-flaky-tests}

Tuist может обнаруживать несогласованные результаты тестов Cargo и помогать исследовать их в разделе **Tests → Flaky Tests**.

> [!IMPORTANT]
> **Требования**
>
> - Настройте <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link>.

## Как работает обнаружение нестабильных тестов {#how-it-works}

Tuist сравнивает запуски CI для одного и того же коммита. Тест, который проходит в одном запуске и падает в другом, можно пометить как нестабильный.

Отправляйте данные каждого запуска с помощью обычной команды:

```sh
tuist cargo test --workspace
```

Cargo не повторяет упавшие тесты автоматически. Повторный запуск задачи CI на том же коммите даст ещё один результат для обнаружения между запусками.

## Карантин нестабильных тестов {#quarantining}

Заглушите или пропустите тест на странице его деталей либо настройте карантин в разделе **Settings → Automations**. Следующий вызов `tuist cargo test` получит текущее состояние карантина проекта:

- **Заглушённые** тесты всё равно выполняются и сообщают фактические результаты, но их сбои не приводят к падению команды. Другие сбои тестов, ошибки компиляции, краши и неполные результаты по-прежнему приводят к обычному падению.
- **Пропущенные** тесты исключаются из выполнения и отчитываются как пропуски из-за карантина. Сопоставление учитывает пакет, таргет, путь модуля Rust и имя теста, поэтому тесты с похожими именами остаются независимыми.

При заглушении сохраняются выбранные пакеты рабочего пространства и возможности, а также выполняются все выбранные таргеты, даже если заглушённый таргет упадёт. Пропуск по карантину требует выбора одного пакета: используйте `tuist cargo test -p store` вместо команды для многопакетного рабочего пространства. Tuist отклоняет пропуск нескольких пакетов, потому что сужение команды может изменить объединённые возможности зависимостей Cargo.

Карантин также применяется к <.localized_link href="/guides/features/test-sharding/rust">шардированным запускам Cargo</.localized_link>. Если Tuist не может получить состояние, он выдаёт предупреждение и выполняет запуск без карантина; сбои не подавляются. Чтобы намеренно запустить без карантина:

```sh
TUIST_TEST_SKIP_QUARANTINE=1 tuist cargo test --workspace
```

### Ограничения {#limitations}

- Для применения требуется стандартный harness libtest и захват вывода по умолчанию. Команды с тихим, подробным, альтернативным форматом или без захвата вывода завершаются ошибкой, когда нужно применить карантин.
- Выберите точный пакет рабочего пространства с помощью `-p <package>`, если привязка к таргету неоднозначна. Пользовательские harnesses, шаблоны имён пакетов/таргетов и неразрешённые выборы пакетов не поддерживаются.
- Doctests тоже можно заглушить или пропустить, но фильтрация тестов Rustdoc не всегда может различить каждую возможную пару имён примеров. Если пропуск примера также пропустит включённый пример или частичное исключение doctest использует `--exact`, Tuist завершается с диагностикой вместо выполнения пропущенного примера или молчаливого исключения включённых тестов. Используйте приведённое выше переопределение во время расследования.

## Стресс-тестирование новых тестов {#stress-testing-new-tests}

Tuist не выполняет стресс-тестирование новых тестов Cargo. Используйте фильтр тестов Cargo, чтобы повторить падающий тест во время расследования:

```sh
tuist cargo test -p store rejects_invalid_token
```
