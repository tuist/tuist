# Нестабильные тесты Rust {#rust-flaky-tests}

Tuist может обнаруживать противоречивые результаты тестов Cargo и помогать вам исследовать их в разделе **Тесты → Нестабильные тесты**.

> [!IMPORTANT] Requirements
> - Настройте <.localized_link href="/guides/features/test-insights/rust">аналитику тестов Rust</.localized_link>.

## Как работает обнаружение нестабильности {#how-it-works}

Tuist сравнивает запуски CI для одного и того же коммита. Тест, который проходит в одном запуске и падает в другом, может быть помечен как нестабильный.

Отправляйте отчет о каждом запуске с помощью обычной команды:

```sh
tuist cargo test --workspace
```

Cargo не повторяет упавшие тесты автоматически. Повторный запуск задачи CI для того же коммита предоставляет еще один результат для межзапускового обнаружения.

## Управление нестабильными тестами {#managing-flaky-tests}

### Автоматическая очистка

Обнаружение и восстановление выполняются через автоматизацию проекта «Обнаружение нестабильных тестов». По умолчанию флаг нестабильности снимается через 14 дней без повторного срабатывания. Измените окно восстановления и действия в разделе **Настройки → Автоматизации**.

### Ручное управление

Откройте **Тесты → Нестабильные тесты**, чтобы просмотреть историю теста. Вы можете вручную пометить или снять пометку о нестабильности на странице сведений о тесте.

## Карантин и стресс-тестирование {#quarantine}

Интеграция с Cargo пока не применяет карантин: тесты, отключенные или пропущенные в панели управления, все равно запускаются, и их сбои по-прежнему влияют на результат. Она также не выполняет стресс-тестирование новых тестов. Используйте фильтр тестов Cargo, чтобы повторить падающий тест во время его исследования:

```sh
tuist cargo test -p store rejects_invalid_token
```
