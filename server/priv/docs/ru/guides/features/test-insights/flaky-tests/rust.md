# Нестабильные тесты в Rust {#rust-flaky-tests}

Tuist может обнаруживать несогласованные результаты тестов Cargo и помогать исследовать их в разделе **Тесты → Нестабильные тесты**.

> [!IMPORTANT]
> **Требования**
>
> - Настройте <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link>.

## Как работает обнаружение нестабильности {#how-it-works}

Tuist сравнивает запуски CI на одном и том же коммите. Тест, который проходит в одном запуске и падает в другом, может быть помечен как нестабильный.

Отправляйте данные каждого запуска с помощью обычной команды:

```sh
tuist cargo test --workspace
```

Cargo не повторяет упавшие тесты автоматически. Повторный запуск задачи CI на том же коммите дает еще один результат для межзапускового обнаружения.

## Карантин нестабильных тестов {#quarantining}

Включите игнорирование сбоев или пропуск теста на странице его деталей либо настройте карантин в разделе **Настройки → Автоматизации**. Следующий вызов `tuist cargo test` получает текущее состояние карантина проекта:

- Тесты со **статусом «Сбои игнорируются»** все равно выполняются и сообщают фактические результаты, но их сбои не приводят к падению команды. Другие сбои тестов, ошибки компиляции, падения и неполные результаты по-прежнему приводят к ошибке.
- **Пропущенные** тесты исключаются из выполнения и отображаются как пропуски из-за карантина. Сопоставление учитывает пакет, цель, путь модуля Rust и имя теста, поэтому тесты с похожими именами остаются независимыми.

Игнорирование сбоев сохраняет выбранные пакеты рабочего пространства и возможности, а также запускает все выбранные цели, даже если одна из целей со включенным игнорированием сбоев упадет. Пропуск по карантину требует выбора одного пакета: используйте `tuist cargo test -p store`, а не команду для многопакетного рабочего пространства. Tuist отклоняет пропуск нескольких пакетов, потому что сужение команды может изменить объединенные возможности зависимостей Cargo.

Карантин также применяется к <.localized_link href="/guides/features/test-sharding/rust">разделенным запускам Cargo</.localized_link>. Если Tuist не может получить состояние, он выводит предупреждение и выполняет запуск без карантина; сбои не подавляются. Чтобы намеренно запустить без карантина:

```sh
TUIST_TEST_SKIP_QUARANTINE=1 tuist cargo test --workspace
```

### Ограничения {#limitations}

- Принудительное применение требует стандартных harness-библиотек libtest и захвата вывода по умолчанию. Команды с тихим, подробным, альтернативным форматом или без захвата вывода завершаются ошибкой, когда необходимо применить карантин.
- Выберите точный пакет рабочего пространства с помощью `-p <package>`, если привязка к цели неоднозначна. Пользовательские harness-библиотеки, шаблоны имен пакетов/целей и неразрешенные выборы пакетов не поддерживаются.
- Doctests также можно перевести в режим игнорирования сбоев или пропустить, но фильтрация тестов Rustdoc не может различить каждую возможную пару имен примеров. Если пропуск примера также пропустит включенный пример или частичное исключение doctest использует `--exact`, Tuist завершится с диагностикой вместо выполнения пропущенного примера или молчаливого пропуска включенных тестов. Используйте указанное выше переопределение во время исследования.

## Стресс-тестирование новых тестов {#stress-testing-new-tests}

Tuist не выполняет стресс-тестирование новых тестов Cargo. Используйте фильтр тестов Cargo, чтобы повторить падающий тест во время его исследования:

```sh
tuist cargo test -p store rejects_invalid_token
```
