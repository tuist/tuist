# Нестабильные тесты в Rust {#rust-flaky-tests}

Tuist может обнаруживать несогласованные результаты тестов Cargo и помогать вам исследовать их в разделе **Тесты → Нестабильные тесты**.

> [!IMPORTANT]
> **Требования**
>
> - Настройте <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link>.

## Как работает обнаружение нестабильных тестов {#how-it-works}

Tuist сравнивает запуски CI для одного и того же коммита. Тест, который проходит в одном запуске и падает в другом, может быть помечен как нестабильный.

Отправляйте данные каждого запуска с помощью обычной команды:

```sh
tuist cargo test --workspace
```

Cargo не повторяет упавшие тесты автоматически. Повторный запуск задачи CI для того же коммита дает еще один результат для межзапускового обнаружения.

## Карантин для нестабильных тестов {#quarantining}

Игнорируйте или пропускайте тест на странице его деталей либо настройте карантин в разделе **Настройки → Автоматизации**. Следующий вызов `tuist cargo test` получает текущее состояние карантина проекта:

- **Игнорируемые** тесты по-прежнему выполняются и сообщают свои фактические результаты, но их сбои не приводят к падению команды. Другие сбои тестов, ошибки компиляции, падения и неполные результаты по-прежнему приводят к обычному завершению с ошибкой.
- **Пропускаемые** тесты исключаются из выполнения и отмечаются как пропущенные из-за карантина. Сопоставление учитывает пакет, таргет, путь модуля Rust и имя теста, поэтому тесты с похожими именами остаются независимыми.

Игнорирование сохраняет выбранные пакеты рабочего пространства и возможности (features) и выполняет все выбранные таргеты даже после сбоя игнорируемого таргета. Пропуск по карантину требует выбора одного пакета: используйте `tuist cargo test -p store`, а не команду для многопакетного рабочего пространства. Tuist отклоняет пропуск нескольких пакетов, потому что сужение команды может изменить унифицированные возможности зависимостей Cargo.

Карантин также применяется к <.localized_link href="/guides/features/test-sharding/rust">разделенным запускам Cargo</.localized_link>. Если Tuist не может получить состояние, он выводит предупреждение и выполняет запуск без карантина; сбои не подавляются. Чтобы намеренно запустить без карантина:

```sh
TUIST_TEST_SKIP_QUARANTINE=1 tuist cargo test --workspace
```

### Ограничения {#limitations}

- Принудительное применение требует стандартных harness-ов libtest и захвата вывода по умолчанию. Команды с тихим, подробным, альтернативным форматом или незахваченным выводом завершаются с ошибкой, когда нужно применить карантин.
- Выбирайте точный пакет рабочего пространства с помощью `-p <package>`, если атрибуция таргета неоднозначна. Пользовательские harness-ы, глобы для имен пакетов/таргетов и неразрешенные выборы пакетов не поддерживаются.
- Doctests тоже можно игнорировать или пропускать, но фильтрация тестов Rustdoc не всегда может различить каждую возможную пару имен примеров. Если пропуск примера также пропустит включенный пример или частичное исключение doctest использует `--exact`, Tuist завершается с диагностикой вместо выполнения пропущенного примера или молчаливого пропуска включенных тестов. Используйте приведенное выше переопределение во время расследования.

## Стресс-тестирование новых тестов {#stress-testing-new-tests}

Tuist не выполняет стресс-тестирование новых тестов Cargo. Используйте фильтр тестов Cargo, чтобы повторить падающий тест во время его исследования:

```sh
tuist cargo test -p store rejects_invalid_token
```
