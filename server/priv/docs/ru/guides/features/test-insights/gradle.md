# Аналитика тестов Gradle {#gradle-test-insights}

> [!IMPORTANT]
> **Требования**
>
> - Подключён плагин Gradle `dev.tuist`, как описано в разделе <.localized_link href="/guides/get-started/gradle-project">Начало работы с проектом Gradle</.localized_link>.

Плагин Gradle от Tuist автоматически загружает результаты тестов после каждого выполнения задачи тестирования, предоставляя вам видимость производительности тестов и нестабильных тестов непосредственно в панели управления Tuist.

Аналитика тестов собирается автоматически после подключения плагина. Дополнительная настройка не требуется.

Вы можете получить доступ к аналитике тестов в панели управления Tuist и отслеживать её изменения со временем:

![Панель управления с аналитикой тестов](/images/guides/features/build-insights/tests-dashboard.png)

## Что отслеживается {#what-is-tracked}

Плагин собирает результаты всех задач Gradle `Test`, включая:
- Статус прохождения/сбоя и длительность каждого отдельного тест-кейса
- Структуру наборов тестов и классов
- Обнаружение нестабильных тестов across запусков

Включите <.localized_link href="/guides/features/test-code-coverage/gradle">покрытие кода</.localized_link>, чтобы также загружать информацию о том, какой код выполняли ваши тесты.

## Настройка поведения загрузки {#configure-upload-behavior}

По умолчанию:
- Результаты тестов загружаются в фоновом режиме для локальных сборок.
- Результаты тестов загружаются в основном потоке для запусков в CI, чтобы избежать потери телеметрии на кратковременно существующих агентах.

Вы можете переопределить это поведение, используя `uploadInBackground` в блоке `tuist` в файле `settings.gradle.kts`:

```kotlin
tuist {
    uploadInBackground = false // always upload in the foreground
}
```

### История Git {#git-history}

В CI плагин также загружает историю коммитов 체크아웃a при отчёте о запуске тестов: SHA коммитов, их родителей, даты коммитов и ветку, в которой находился запуск и базовая ветка его pull request’а. Содержимое файлов, сообщения коммитов или авторы не загружаются. Это позволяет Tuist определять, какие коммиты попали в вашу основную ветку, например те, которые тестировала очередь слияния. Плагин читает историю, уже имеющуюся в 체크아웃е, а если в 체크아웃е нет базовой ветки, запрашивает у удалённого репозитория последний коммит (`git ls-remote`). Он не загружает историю.

| Переменная | Эффект |
| --- | --- |
| `TUIST_GIT_UPLOAD_ENABLED=false` | Не читает и не загружает историю Git. |
| `TUIST_GIT_UNSHALLOW_ENABLED=false` | Читает только содержимое 체크아웃а, не обращаясь к удалённому репозиторию. |
