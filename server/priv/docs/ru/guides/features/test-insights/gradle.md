# Аналитика тестов Gradle {#gradle-test-insights}

> [!IMPORTANT]
> **Требования**
>
> - Применён плагин Gradle `dev.tuist`, как описано в разделе <.localized_link href="/guides/get-started/gradle-project">Начало работы с проектом Gradle</.localized_link>.

Плагин Gradle от Tuist автоматически загружает результаты тестов после каждого запуска тестовой задачи, предоставляя вам видимость производительности тестов и нестабильных тестов прямо в панели управления Tuist.

Аналитика тестов собирается автоматически после применения плагина. Дополнительная настройка не требуется.

Вы можете получить доступ к аналитике тестов в панели управления Tuist и увидеть, как она меняется со временем:

![Панель управления с аналитикой тестов](/images/guides/features/build-insights/tests-dashboard.png)

## Что отслеживается {#what-is-tracked}

Плагин собирает результаты всех задач `Test` Gradle, включая:
- Статус прохождения/сбоя и длительность каждого тест-кейса
- Структура тестовых наборов и классов
- Обнаружение нестабильных тестов across запусков

Включите <.localized_link href="/guides/features/test-code-coverage/gradle">покрытие кода</.localized_link>, чтобы также загружать данные о том, какой код выполняли ваши тесты.

## Настройка поведения загрузки {#configure-upload-behavior}

По умолчанию:
- Результаты тестов загружаются в фоновом режиме для локальных сборок.
- Результаты тестов загружаются в активном режиме для запусков в CI, чтобы избежать потери телеметрии на краткоживущих агентах.

Вы можете переопределить это поведение, используя `uploadInBackground` в блоке `tuist` в вашем файле `settings.gradle.kts`:

```kotlin
tuist {
    uploadInBackground = false // always upload in the foreground
}
```

### История Git {#git-history}

В CI плагин также загружает историю коммитов 체크아웃 при отчёте о запуске тестов: SHA коммитов, их родителей, даты коммитов и ветку, в которой находился запуск и базовая ветка его пул-реквеста. Содержимое файлов, сообщения коммитов или авторы не загружаются. Это позволяет Tuist определить, какие коммиты попали в вашу основную ветку, например, те, которые тестировала очередь слияния. Плагин читает историю, которая уже есть в 체크아웃е, и если в 체크아웃е нет базовой ветки, запрашивает у удалённого репозитория её последний коммит (`git ls-remote`). Вне контекста покрытия кода история не загружается. При включённом покрытии кода поверхностный checkout углубляется без загрузки содержимого файлов, чтобы найти точку ответвления пул-реквеста и достичь коммитов, которые уже есть у Tuist, так что коммит никогда не загружается без своего родителя.

| Переменная | Эффект |
| --- | --- |
| `TUIST_GIT_UPLOAD_ENABLED=false` | Не читает и не загружает историю Git. |
| `TUIST_GIT_UNSHALLOW_ENABLED=false` | Читает только локальный checkout, не обращаясь к удалённому репозиторию. |
