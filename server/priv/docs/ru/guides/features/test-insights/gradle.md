# Аналитика тестов Gradle {#gradle-test-insights}

> [!IMPORTANT]
> **Требования**
>
> - Подключен плагин Gradle `dev.tuist`, как описано в разделе <.localized_link href="/guides/get-started/gradle-project">Начало работы с проектом Gradle</.localized_link>.

Плагин Gradle от Tuist автоматически загружает результаты тестов после каждого выполнения задачи тестирования, предоставляя видимость производительности тестов и нестабильных тестов прямо в панели управления Tuist.

Аналитика тестов собирается автоматически после подключения плагина. Дополнительная настройка не требуется.

Вы можете получить доступ к аналитике тестов в панели управления Tuist и отслеживать её изменения со временем:

![Панель управления с аналитикой тестов](/images/guides/features/build-insights/tests-dashboard.png)

## Что отслеживается {#what-is-tracked}

Плагин собирает результаты всех задач `Test` Gradle, включая:
- Статус прохождения/сбоя и длительность каждого отдельного тест-кейса
- Структура наборов тестов и классов
- Обнаружение нестабильных тестов across запусков

Включите <.localized_link href="/guides/features/test-code-coverage/gradle">покрытие кода</.localized_link>, чтобы также загружать информацию о том, какой код выполняли ваши тесты.

## Настройка поведения загрузки {#configure-upload-behavior}

По умолчанию:
- Результаты тестов загружаются в фоновом режиме для локальных сборок.
- Результаты тестов загружаются в активном режиме для запусков в CI, чтобы избежать потери телеметрии на кратковременно существующих агентах.

Вы можете переопределить это поведение, используя `uploadInBackground` в блоке `tuist` в вашем файле `settings.gradle.kts`:

```kotlin
tuist {
    uploadInBackground = false // always upload in the foreground
}
```

### История Git {#git-history}

В CI плагин также загружает историю коммитов извлеченной версии при отчете о запуске тестов: SHA коммитов, их родительские коммиты, даты коммитов и ветку, в которой находился запуск и базовая ветка его pull request’а. Содержимое файлов, сообщения коммитов и авторы не загружаются. Это позволяет Tuist определить, какие коммиты попали в вашу основную ветку, например те, которые проверяла очередь слияний. Плагин читает историю, которая уже есть в извлеченной версии, а если в ней нет базовой ветки, запрашивает у удаленного репозитория последний коммит (`git ls-remote`). История не выгружается.

| Переменная | Эффект |
| --- | --- |
| `TUIST_GIT_UPLOAD_ENABLED=false` | Не читает и не загружает историю Git. |
| `TUIST_GIT_UNSHALLOW_ENABLED=false` | Читает только извлеченную версию, без обращения к удаленному репозиторию. |
