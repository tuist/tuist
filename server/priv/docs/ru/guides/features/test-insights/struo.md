# Аналитика тестов Struo {#struo-test-insights}

<a id="once-test-insights"></a>

Struo отправляет результаты тестов в Tuist, чтобы вы могли отслеживать выполнение наборов тестов локально и в CI, исследовать сбои и находить медленные тесты без сбора отчётов от отдельных воркеров.

> [!IMPORTANT]
> **Требования**
>
> - Пройдите <.localized_link href="/guides/get-started/struo-project">начало работы со Struo</.localized_link>.
> - Используйте тестовые цели, которые предоставляют структурированные результаты. Доступная детализация зависит от типа цели и тестового раннера.

## Отправляйте результаты запусков тестов {#report-your-test-runs}

Запустите весь набор тестов или выберите конкретную цель:

```bash
struo test
struo test MyTests
```

Struo передаёт нативные события тестирования и публикует завершённые результаты в общую модель тестов Tuist. Разделы **Тесты** и **Запуски тестов** отображают запуски; отдельные тест-кейсы также имеют общую историю тестирования. <.localized_link href="/guides/features/test-sharding/struo">Запуск с шардированием на хосте</.localized_link> публикует один отчёт от каждого воркера в объединённый запуск вместо повторного подсчёта его потока диагностических событий.

## Что отслеживается {#what-is-tracked}

- Отправленные тестовые цели, наборы тестов и отдельные тест-кейсы.
- Результаты прохождения, сбоев и пропусков, с указанием длительности, если она предоставляется раннером.
- Сообщения об ошибках, предоставляемые раннером в отчётах о шардированных запусках на хосте.
- Упорядоченные попытки повторного запуска и результаты нестабильных тестов, когда тест сначала падает, а затем проходит.
- Контекст ветки, коммита и CI, предоставляемый Struo.

Идентификация теста использует нативные имена цели, набора тестов и тест-кейса. Идентификаторы пакетов шардирования являются единицами планирования, а не именами тестов.

Обычная отправка отчётов `struo test` сохраняет результаты и попытки повторного запуска, но в настоящее время не включает сообщения об ошибках в общую историю тестов. Отчёты о шардированных запусках на хосте могут включать сообщения об ошибках, но ни один из способов отправки не предоставляет информацию о расположении в исходном коде. Сохраняйте логи CI для диагностики, которая недоступна в Tuist.

Не каждая тестовая цель предоставляет одинаковую детализацию. Некоторые раннеры сообщают об отдельных тест-кейсах, другие — только сводки; точное выполнение файла или кейса является отдельной возможностью. Ознакомьтесь с [покрытием экосистемы тестирования Struo](https://struo.run/docs/guide/graph/testing#understand-current-ecosystem-coverage), прежде чем полагаться на аналитику по отдельным кейсам или тонкогранулярное планирование.

## Нестабильные тесты {#flaky-tests}

Tuist использует данные о попытках запуска и историю CI для выявления несогласованных результатов. Отправка данных о попытке не равнозначна включению повторных запусков: настройте повторные запуски в раннере, который их поддерживает. См. раздел <.localized_link href="/guides/features/test-insights/flaky-tests/struo">Нестабильные тесты Struo</.localized_link> для получения информации об обнаружении и текущих границах карантина.

## Выбор тестов и покрытие кода {#selection-and-code-coverage}

Struo может консервативно выбирать тесты из своего локального графа с помощью `--changed-path`. Это собственный механизм выбора Struo, а не выбор тестов на основе покрытия, предоставляемый Tuist:

```bash
struo test --changed-path src/library.rs
```

Нативная отправка отчётов Struo в настоящее время не загружает данные о покрытии кода в Tuist. Успешный отчёт о тестировании или план шардирования не заполняет панель «Покрытие кода».

## Устранение неполадок {#troubleshooting}

Если запуск отсутствует, убедитесь, что активный провайдер кэша указывает на ваш проект Tuist, и повторно выполните аутентификацию с помощью `struo auth login --provider tuist`. Отправка отчётов в реальном времени выполняется по принципу «best-effort» и не приводит к ошибке успешно выполненной команды тестирования, если сервис отправки отчётов недоступен.

Сводки запусков и структурированные данные о сбоях тестов не являются полными логами процессов. Этот сервер в настоящее время не принимает необработанный поток логов действий Struo; сохраняйте логи CI для вывода, который не включён в структурированные результаты.
