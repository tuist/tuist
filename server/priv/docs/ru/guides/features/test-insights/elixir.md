# Аналитика тестов Elixir {#elixir-test-insights}

Hex-пакет Tuist загружает результаты тестов вашего проекта на Elixir после каждого запуска, обеспечивая видимость производительности тестов и нестабильных тестов непосредственно в панели управления Tuist.

> [!IMPORTANT] REQUIREMENTS
> - Выполните <.localized_link href="/guides/get-started/elixir-project">Начало работы с Elixir</.localized_link>

## Отчет о запусках тестов {#report-your-test-runs}

Общая настройка устанавливает интеграцию тестирования. Продолжайте использовать `mix test`, с теми же аргументами, выводом и кодом выхода:

```bash
mix test test/my_app_test.exs:12 --trace
```

Tuist сообщает о запуске по его завершении; дополнительный алиас для тестов не требуется.

Вы можете получить доступ к аналитике тестов в панели управления Tuist и увидеть, как они меняются со временем:

![Панель тестов приложения Phoenix](/images/guides/features/elixir/tests-dashboard.png)

## Что отслеживается {#what-is-tracked}

Пакет собирает результаты из ExUnit, включая:
- Статус прохождения/неудачи и длительность каждого отдельного теста
- Модуль и блок `describe`, к которому относится каждый тест
- Сообщение и местоположение каждой ошибки
- Обнаружение нестабильных тестов между запусками
- Ветка и коммит, а при непрерывной интеграции — провайдер и запуск
- При непрерывной интеграции также загружается [история Git](#git-history) клонированного репозитория

Doctests报告方式与其他测试相同。使用 `--cover` 时，还会上传运行的行覆盖率：请参阅 <.localized_link href="/guides/features/test-code-coverage/elixir">Покрытие кода Elixir</.localized_link>。

> [!NOTE]
> Пакет отправляет отчеты через форматтер ExUnit, который добавляется к уже используемым вами. Если вы передаете `--formatter` в командной строке, Mix заменяет весь список, поэтому запуск не отчетится, и задача предупреждает вас об этом.

### История Git {#git-history}

При непрерывной интеграции пакет также загружает историю коммитов клонированного репозитория: SHA коммитов, их родителей, даты коммитов и ветку, в которой находился запуск и базовая ветка его pull request'а. Содержимое файлов, сообщения коммитов или авторы не загружаются. Это позволяет Tuist определить, какие коммиты попали в вашу основную ветку, например, те, которые проверила очередь слияния. Пакет читает историю, которая уже есть в клонированном репозитории, и если в нем нет базовой ветки, запрашивает у удаленного репозитория последний коммит (`git ls-remote`). Вне покрытия кода (`--cover`) история не загружается.

| Переменная | Эффект |
| --- | --- |
| `TUIST_GIT_UPLOAD_ENABLED=false` | Не читает и не загружает никакую историю Git. |
| `TUIST_GIT_UNSHALLOW_ENABLED=false` | Читает только клонированный репозиторий, не обращаясь к удаленному. |

## Устранение неполадок {#troubleshooting}

Отчетность никогда не изменяет результат ваших тестов: если отчет не может быть отправлен, запуск завершается так, как это произошло бы, и ничего не выводится. Чтобы узнать, почему отчет не был отправлен, установите `TUIST_DEBUG=1`:

```bash
TUIST_DEBUG=1 mix test
```
