# Аналитика тестов Elixir {#elixir-test-insights}

Hex-пакет Tuist загружает результаты тестов вашего проекта на Elixir после каждого запуска, предоставляя вам видимость производительности тестов и нестабильных тестов непосредственно в панели управления Tuist.

> [!IMPORTANT] REQUIREMENTS
> - Завершите <.localized_link href="/guides/get-started/elixir-project">Начало работы с Elixir</.localized_link>

## Отчет о запусках тестов {#report-your-test-runs}

Общая настройка устанавливает интеграцию тестирования. Продолжайте использовать `mix test`, с теми же аргументами, выводом и кодом выхода:

```bash
mix test test/my_app_test.exs:12 --trace
```

Tuist сообщает о запуске по его завершении; дополнительный алиас для тестов не требуется.

Вы можете получить доступ к аналитике ваших тестов в панели управления Tuist и увидеть, как они изменяются со временем:

![Панель тестов приложения Phoenix](/images/guides/features/elixir/tests-dashboard.png)

## Что отслеживается {#what-is-tracked}

Пакет собирает результаты из ExUnit, включая:
- Статус прохождения/сбоя отдельного теста и его длительность
- Модуль и блок `describe`, к которому относится каждый тест
- Сообщение и местоположение каждой ошибки
- Обнаружение нестабильных тестов между запусками
- Ветка и коммит, а при непрерывной интеграции — провайдер и запуск
- При непрерывной интеграции — [история Git](#git-history) клонированного репозитория

Doctests сообщаются так же, как и любые другие тесты.

> [!NOTE]
> Пакет отправляет отчеты через форматтер ExUnit, который он добавляет к уже используемым вами. Если вы передаете `--formatter` в командной строке, Mix заменяет весь список, поэтому запуск не报告ируется, и задача предупреждает вас об этом.

### История Git {#git-history}

При непрерывной интеграции пакет также загружает историю коммитов клонированного репозитория: SHA коммитов, их родителей, даты коммитов и ветку, в которой выполнялся запуск, а также базовую ветку pull request'а. Содержимое файлов, сообщения коммитов или авторы не загружаются. Это позволяет Tuist определить, какие коммиты попали в вашу основную ветку, например, те, которые были протестированы очередью слияния. Пакет читает историю, которая уже есть в клонированном репозитории, а если в нем нет базовой ветки, запрашивает у удаленного репозитория последний коммит (`git ls-remote`). Вне покрытия кода (`--cover`) история не загружается.

| Переменная | Эффект |
| --- | --- |
| `TUIST_GIT_UPLOAD_ENABLED=false` | Не читает и не загружает никакую историю Git. |
| `TUIST_GIT_UNSHALLOW_ENABLED=false` | Читает только клонированный репозиторий, без обращения к удаленному. |

## Устранение неполадок {#troubleshooting}

Отчетность никогда не меняет результат ваших тестов: если отчет не может быть отправлен, запуск завершается так, как если бы отчета не было, и ничего не выводится. Чтобы узнать, почему отчет не был отправлен, установите `TUIST_DEBUG=1`:

```bash
TUIST_DEBUG=1 mix test
```
