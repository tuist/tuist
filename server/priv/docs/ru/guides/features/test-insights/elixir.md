# Аналитика тестов Elixir {#elixir-test-insights}

Hex-пакет Tuist загружает результаты тестов вашего проекта на Elixir после каждого запуска тестов, предоставляя видимость производительности тестов и нестабильных тестов прямо в панели управления Tuist.

> [!IMPORTANT]
> **Требования**
>
> - Завершите <.localized_link href="/guides/get-started/elixir-project">Начало работы с Elixir</.localized_link>

## Отправка результатов запусков тестов {#report-your-test-runs}

Общая настройка устанавливает интеграцию тестирования. Продолжайте использовать `mix test`, с теми же аргументами, выводом и кодом выхода:

```bash
mix test test/my_app_test.exs:12 --trace
```

Tuist отправляет отчет о запуске по его завершении; дополнительный алиас для тестов не требуется.

Вы можете получить доступ к аналитике тестов в панели управления Tuist и видеть, как они изменяются со временем:

![Панель тестов приложения Phoenix](/images/guides/features/elixir/tests-dashboard.png)

## Что отслеживается {#what-is-tracked}

Пакет собирает результаты из ExUnit, включая:
- Статус прохождения/сбоя и длительность каждого отдельного теста
- Модуль и блок `describe`, к которому относится каждый тест
- Сообщение и местоположение каждого сбоя
- Обнаружение нестабильных тестов между запусками
- Ветка и коммит, а при непрерывной интеграции — провайдер и запуск
- При непрерывной интеграции — [история Git](#git-history) клонированного репозитория

Doctests отправляются так же, как и любые другие тесты. С опцией `--cover` также загружается покрытие строк кода запуска: см. <.localized_link href="/guides/features/test-code-coverage/elixir">Покрытие кода Elixir</.localized_link>.

> [!NOTE]
> Пакет отправляет отчеты через форматтер ExUnit, который добавляется к уже используемым вами форматтерам. Если вы передаете `--formatter` в командной строке, Mix заменяет весь список, поэтому запуск не отправляется, и задача предупреждает вас об этом.

### История Git {#git-history}

При непрерывной интеграции пакет также загружает историю коммитов клонированного репозитория: SHA коммитов, их родительские коммиты, даты коммитов и ветку, в которой выполнялся запуск, а также базовую ветку pull request'а. Содержимое файлов, сообщения коммитов или авторы не загружаются. Это позволяет Tuist определить, какие коммиты попали в вашу основную ветку, например, те, которые тестировала очередь слияния. Пакет читает историю, которая уже есть в клонированном репозитории, а если базовой ветки нет, запрашивает у удаленного репозитория последний коммит (`git ls-remote`). Вне покрытия кода (`--cover`) история не загружается. При включенном покрытии кода поверхностный клон углубляется без загрузки содержимого файлов, чтобы найти точку ответвления pull request'а и, при непрерывной интеграции, достичь коммитов, которые уже есть у Tuist, поэтому коммит никогда не загружается без своего родительского коммита.

| Переменная | Эффект |
| --- | --- |
| `TUIST_GIT_UPLOAD_ENABLED=false` | Не читает и не загружает историю Git. |
| `TUIST_GIT_UNSHALLOW_ENABLED=false` | Читает только клонированный репозиторий, не обращаясь к удаленному серверу. |

## Устранение неполадок {#troubleshooting}

Отправка отчетов никогда не меняет результат ваших тестов: если отчет не может быть отправлен, запуск завершается так, как завершился бы иначе, и ничего не выводится. Чтобы увидеть причину, по которой отчет не был отправлен, установите `TUIST_DEBUG=1`:

```bash
TUIST_DEBUG=1 mix test
```
