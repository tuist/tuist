# Аналитика тестов Elixir {#elixir-test-insights}

Hex-пакет Tuist загружает результаты тестирования вашего проекта на Elixir после каждого запуска тестов, предоставляя видимость производительности тестов и нестабильных тестов прямо в панели управления Tuist.

> [!IMPORTANT]
> **Требования**
>
> - Выполните <.localized_link href="/guides/get-started/elixir-project">Начало работы с Elixir</.localized_link>

## Отправка результатов запусков тестов {#report-your-test-runs}

Общая настройка устанавливает интеграцию для тестирования. Продолжайте использовать `mix test`, с теми же аргументами, выводом и кодом выхода:

```bash
mix test test/my_app_test.exs:12 --trace
```

Tuist отправляет отчет о запуске по его завершении; дополнительный алиас для тестов не требуется.

Вы можете получить доступ к аналитике тестов в панели управления Tuist и увидеть, как она меняется со временем:

![Панель тестов приложения Phoenix](/images/guides/features/elixir/tests-dashboard.png)

## Что отслеживается {#what-is-tracked}

Пакет собирает результаты из ExUnit, включая:
- Статус прохождения/сбоя отдельного теста и его длительность
- Модуль и блок `describe`, к которому относится каждый тест
- Сообщение и местоположение каждого сбоя
- Обнаружение нестабильных тестов между запусками
- Ветка и коммит, а при непрерывной интеграции — провайдер и запуск
- При непрерывной интеграции — [история Git](#git-history) 체크아웃a

Doctests отправляются так же, как и любые другие тесты. С опцией `--cover` также загружается покрытие строк кода запуска: см. <.localized_link href="/guides/features/test-code-coverage/elixir">Покрытие кода Elixir</.localized_link>.

> [!NOTE]
> Пакет отправляет отчеты через форматтер ExUnit, который он добавляет к уже используемым вами. Если вы передаете `--formatter` в командной строке, Mix заменяет весь список, поэтому запуск не отправляется, и задача предупреждает вас об этом.

### История Git {#git-history}

При непрерывной интеграции пакет также загружает историю коммитов 체크아웃a: SHA коммитов, их родителей, даты коммитов и ветку, в которой находился запуск и базовая ветка pull request'а. Содержимое файлов, сообщения коммитов или авторы не загружаются. Это позволяет Tuist определить, какие коммиты попали в вашу основную ветку, например, те, которые тестировала очередь слияния. Пакет читает историю, которая уже есть в 체크아웃е, и если в 체크아웃е нет базовой ветки, запрашивает у удаленного репозитория последний коммит (`git ls-remote`). Вне покрытия кода (`--cover`) история не загружается. При наличии покрытия кода поверхностный 체크아웃 углубляется без содержимого файлов, чтобы найти точку ответвления pull request'а и, при непрерывной интеграции, добраться до коммитов, которые уже есть в Tuist, чтобы коммит никогда не загружался без родительского коммита, на котором он основан.

| Переменная | Эффект |
| --- | --- |
| `TUIST_GIT_UPLOAD_ENABLED=false` | Не читает и не загружает историю Git. |
| `TUIST_GIT_UNSHALLOW_ENABLED=false` | Читает только текущий 체크아웃, не обращаясь к удаленному репозиторию. |

## Устранение неполадок {#troubleshooting}

Отправка отчетов никогда не меняет результат ваших тестов: если отчет не может быть отправлен, запуск завершается так, как должен был, и ничего не выводится. Чтобы узнать, почему отчет не был отправлен, установите `TUIST_DEBUG=1`:

```bash
TUIST_DEBUG=1 mix test
```
