# Аналитика тестов Rust {#rust-test-insights}

Tuist сообщает результаты отдельных тестов из `cargo test`, включая юнит-тесты, интеграционные тесты и doctests. Никаких зависимостей Rust или дополнительных раннеров тестов не требуется.

> [!IMPORTANT]
> **Требования**
>
> - Следуйте инструкциям по <.localized_link href="/guides/get-started/rust-project">настройке проекта Rust</.localized_link>.

## Отправка результатов запусков тестов {#report-your-test-runs}

```sh
tuist cargo test --workspace
```

При настроенной обёртке mise для Cargo вы можете продолжать вводить `cargo test`. Cargo по-прежнему компилирует и запускает ваши тесты с обычными аргументами, выводом и кодом выхода. Сбои отправки отчётов не влияют на результат ваших тестов.

Вы можете выбрать пакет или отфильтровать тесты как обычно:

```sh
tuist cargo test -p store
tuist cargo test authentication
```

## Что отслеживает Tuist {#what-is-tracked}

- Пройденные, упавшие и проигнорированные тесты из завершённых наборов тестов.
- Юнит-тесты, интеграционные тесты и doctests.
- Длительность выполнения всего набора тестов.
- Доступные метаданные ветки, коммита, CI и раннера.

Отфильтрованные тесты и тесты, не выполненные после сбоя, никогда не отмечаются как пройденные. Результаты отображаются в разделе **Тесты** в дашборде.

## Пакеты, модули и тест-кейсы {#test-hierarchy}

Tuist группирует результаты по пакетам и таргетам Cargo. Пути модулей Rust группируют отдельные тесты внутри таргета:

| Метка в дашборде | Значение в Rust | Пример |
| --- | --- | --- |
| Модули | Пакет и таргет Cargo | `store::api` |
| Наборы тестов | Пути модулей Rust | `api::authentication` |
| Тест-кейсы | Отдельные тесты | `rejects_invalid_token` |

Doctests используют отдельный модуль, например `store::doctest/store`. Их имена включают путь к исходному файлу, поэтому перемещение примера может изменить его идентификатор.

## Doctests и длительность выполнения {#cargo-test}

Doctests запускаются вашей обычной командой тестирования, включая примеры `compile_fail`, `should_panic` и `no_run`. Чтобы запустить только doctests:

```sh
tuist cargo test --doc
```

Стабильная версия libtest сообщает время выполнения всего набора, но не длительность отдельных тестов. Недоступные данные о времени исключаются из истории длительности по каждому кейсу и аналитики длительности, при этом результаты тестов всё ещё учитываются в показателях надёжности и количества запусков.

## Ограничения отправки отчётов {#reporting-limits}

Отдельные результаты собираются из стандартного вывода Cargo/libtest. Команды с использованием `--no-run`, `--list`, тихого или подробного вывода Cargo, альтернативных форматов или неперехваченного вывода тестов выполняются нормально, но без отправки отчётов по отдельным тестам. Пользовательские harness, неполные сводки, неоднозначное определение таргета и слишком большие отчёты не загружаются.

Если пакеты рабочего пространства имеют интеграционные таргеты с одинаковыми именами, выберите один из них с помощью `-p <package>`. Отправка отчётов поддерживает точные имена пакетов рабочего пространства; пакеты зависимостей, селекторы с указанием версии и шаблоны выполняются нормально, но не отправляются. Абсолютные пути doctests опускаются, чтобы пути 체크아웃 не попадали в идентификаторы тестов.

Tuist передаёт вывод в потоковом режиме во время сбора результатов. Это может повлиять на автоматическое определение цвета. Фоновые процессы, которые оставляют каналы вывода открытыми после завершения Cargo, могут привести к пропуску отчёта, но не изменяют код выхода Cargo.

## Надёжность и выборка {#reliability-and-selection}

Используйте <.localized_link href="/guides/features/test-insights/flaky-tests/rust">обнаружение нестабильных тестов и карантин</.localized_link>, чтобы исследовать нестабильные тесты и игнорировать или пропускать их. <.localized_link href="/guides/features/test-sharding/rust">Распределение тестов</.localized_link> распределяет целые таргеты Cargo между воркерами CI. Импорт покрытия, выборка тестов на основе покрытия и распределение с однократной сборкой недоступны для обычных запусков тестов Cargo.

## Устранение неполадок {#troubleshooting}

Если запуск тестов не отображается в дашборде, включите отладочный вывод, чтобы узнать, почему отчёт не был отправлен:

```sh
TUIST_DEBUG=1 tuist cargo test --workspace
```
