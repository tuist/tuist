# Аналитика тестов Rust {#rust-test-insights}

Tuist сообщает результаты отдельных тестов из `cargo test`, включая модульные тесты, интеграционные тесты и doctests. Зависимости Rust или дополнительный тестовый раннер не требуются.

> [!IMPORTANT] Requirements
> - Следуйте <.localized_link href="/guides/get-started/rust-project">инструкциям по настройке проекта Rust</.localized_link>.

## Отчет о запусках тестов {#report-your-test-runs}

```sh
tuist cargo test --workspace
```

При настроенной обертке mise для Cargo вы можете продолжать вводить `cargo test`. Cargo по-прежнему компилирует и запускает ваши тесты со своими обычными аргументами, выводом и кодом выхода. Сбои при отправке отчетов не влияют на результат ваших тестов.

Вы можете выбрать пакет или отфильтровать тесты как обычно:

```sh
tuist cargo test -p store
tuist cargo test authentication
```

## Что отслеживает Tuist {#what-is-tracked}

- Пройденные, проваленные и проигнорированные тесты из завершенных наборов тестов.
- Модульные тесты, интеграционные тесты и doctests.
- Общее время выполнения набора тестов.
- Доступные метаданные ветки, коммита, CI и раннера.

Отфильтрованные тесты и тесты, не выполненные после сбоя, никогда не отмечаются как пройденные. Результаты отображаются в разделе **Тесты** панели управления.

## Пакеты, модули и тестовые случаи {#test-hierarchy}

Tuist группирует результаты по пакету и цели Cargo. Пути модулей Rust группируют отдельные тесты внутри цели:

| Метка в панели управления | Значение в Rust | Пример |
| --- | --- | --- |
| Модули | Пакет и цель Cargo | `store::api` |
| Наборы тестов | Пути модулей Rust | `api::authentication` |
| Тестовые случаи | Отдельные тесты | `rejects_invalid_token` |

Doctests используют отдельный модуль, например `store::doctest/store`. Их имена включают расположение в исходном коде, поэтому перемещение примера может изменить его идентификатор.

## Doctests и длительность {#cargo-test}

Doctests запускаются с вашей обычной командой тестирования, включая примеры `compile_fail`, `should_panic` и `no_run`. Чтобы запустить только doctests:

```sh
tuist cargo test --doc
```

Стабильная libtest сообщает общее время набора тестов, но не длительность отдельных тестов. Недоступные данные о времени исключаются из историй длительности по каждому случаю и аналитики длительности, при этом результаты тестов по-прежнему учитываются при расчете надежности и количества запусков.

## Ограничения отчетности {#reporting-limits}

Отдельные результаты собираются из стандартного вывода Cargo/libtest. Команды, использующие `--no-run`, `--list`, тихий или подробный вывод Cargo, альтернативные форматы или незахваченный вывод тестов, выполняются нормально без отчетности по отдельным тестам. Пользовательские harnesses, неполные сводки, неоднозначная атрибуция целей и отчеты чрезмерного размера не загружаются.

Если пакеты рабочего пространства имеют интеграционные цели с одинаковыми именами, выберите одну из них с помощью `-p <package>`. Отчетность поддерживает точные имена пакетов рабочего пространства; пакеты зависимостей, селекторы с указанием версии и шаблоны выполняются нормально, но не отчетятся. Абсолютные пути doctest опускаются, чтобы пути 체크아웃 не попадали в идентификаторы тестов.

Tuist передает вывод в потоковом режиме во время сбора результатов. Это может повлиять на автоматическое определение цвета. Фоновые процессы, которые держат каналы вывода открытыми после завершения Cargo, могут привести к тому, что отчет не будет отправлен, но это не изменяет код выхода Cargo.

## Надежность и выбор {#reliability-and-selection}

Используйте <.localized_link href="/guides/features/test-insights/flaky-tests/rust">обнаружение нестабильных тестов</.localized_link> для исследования нестабильных тестов. Карантин в панели управления в настоящее время не отключает и не пропускает тесты Cargo. Импорт данных покрытия, выбор тестов на основе покрытия и шардинг с однократной сборкой недоступны для обычных запусков тестов Cargo.

## Устранение неполадок {#troubleshooting}

Если запуск теста не отображается в панели управления, включите отладочный вывод, чтобы узнать, почему его отчет не был отправлен:

```sh
TUIST_DEBUG=1 tuist cargo test --workspace
```
