# Аналитика тестов Rust {#rust-test-insights}

Tuist отправляет отдельные результаты тестов из `cargo test`, включая модульные тесты, интеграционные тесты и doctests. Зависимости от Rust или дополнительный тестовый раннер не требуются.

> [!IMPORTANT] Requirements
> - Следуйте инструкциям по <.localized_link href="/guides/get-started/rust-project">настройке проекта Rust</.localized_link>.

## Отправка результатов тестовых запусков {#report-your-test-runs}

```sh
tuist cargo test --workspace
```

При настроенной обертке mise для Cargo вы можете продолжать вводить `cargo test`. Cargo по-прежнему компилирует и запускает ваши тесты с обычными аргументами, выводом и кодом выхода. Ошибки отправки отчетов не влияют на результат ваших тестов.

Вы можете выбрать пакет или отфильтровать тесты как обычно:

```sh
tuist cargo test -p store
tuist cargo test authentication
```

## Что отслеживает Tuist {#what-is-tracked}

- Пройденные, проваленные и проигнорированные тесты из завершенных тестовых наборов.
- Модульные тесты, интеграционные тесты и doctests.
- Общее время выполнения наборов тестов.
- Доступные метаданные ветки, коммита, CI и раннера.

Отфильтрованные тесты и тесты, не выполненные после сбоя, никогда не отмечаются как пройденные. Результаты отображаются в разделе **Тесты** панели управления.

## Пакеты, модули и тестовые случаи {#test-hierarchy}

Tuist группирует результаты по пакетам и целям Cargo. Пути модулей Rust группируют отдельные тесты внутри цели:

| Метка в панели управления | Значение в Rust | Пример |
| --- | --- | --- |
| Модули | Пакет и цель Cargo | `store::api` |
| Тестовые наборы | Пути модулей Rust | `api::authentication` |
| Тестовые случаи | Отдельные тесты | `rejects_invalid_token` |

Doctests используют отдельный модуль, например `store::doctest/store`. Их имена включают путь к исходному файлу, поэтому перемещение примера может изменить его идентификатор.

## Doctests и длительность выполнения {#cargo-test}

Doctests запускаются с вашей обычной командой тестирования, включая примеры `compile_fail`, `should_panic` и `no_run`. Чтобы запустить только doctests:

```sh
tuist cargo test --doc
```

Стабильная библиотека libtest сообщает общее время набора, но не длительность отдельных тестов. Недоступные данные о времени исключаются из истории длительности по случаям и аналитики длительности, при этом результаты тестов по-прежнему учитываются в показателях надежности и количества запусков.

## Ограничения отчетности {#reporting-limits}

Отдельные результаты собираются из стандартного вывода Cargo/libtest. Команды, использующие `--no-run`, `--list`, тихий или подробный вывод Cargo, альтернативные форматы или неперехваченный вывод тестов, выполняются нормально без отчетности по отдельным тестам. Пользовательские harnesses, неполные сводки, неоднозначная привязка к целям и отчеты чрезмерного размера не загружаются.

Если пакеты рабочего пространства имеют интеграционные цели с одинаковыми именами, выберите одну из них с помощью `-p <package>`. Отчетность поддерживает точные имена пакетов рабочего пространства; пакеты зависимостей, селекторы с указанием версии и шаблоны выполняются нормально, но не отчетятся. Абсолютные пути doctest опускаются, чтобы пути checkout не попадали в идентификаторы тестов.

Tuist потоково передает вывод во время сбора результатов. Это может повлиять на автоматическое определение цвета. Фоновые процессы, которые держат каналы вывода открытыми после завершения работы Cargo, могут привести к тому, что отчет не будет отправлен, но не изменят код выхода Cargo.

## Надежность и выборка {#reliability-and-selection}

Используйте <.localized_link href="/guides/features/test-insights/flaky-tests/rust">обнаружение нестабильных тестов и их изоляцию</.localized_link> для исследования нестабильных тестов и их отключения или пропуска. <.localized_link href="/guides/features/test-sharding/rust">Распараллеливание тестов</.localized_link> распределяет целые цели Cargo между работниками CI. Импорт покрытия, выборка тестов на основе покрытия и распределение с однократной сборкой недоступны для обычных запусков тестов Cargo.

## Устранение неполадок {#troubleshooting}

Если запуск теста не отображается в панели управления, включите режим отладки, чтобы узнать, почему его отчет не был отправлен:

```sh
TUIST_DEBUG=1 tuist cargo test --workspace
```
