# Аналитика тестов Rust {#rust-test-insights}

Tuist отправляет результаты отдельных тестов из `cargo test`, включая юнит-тесты, интеграционные тесты и doctests. Зависимости от Rust или дополнительный тестовый раннер не требуются.

> [!IMPORTANT]
> **Требования**
>
> - Следуйте инструкциям по <.localized_link href="/guides/get-started/rust-project">настройке проекта Rust</.localized_link>.

## Отправка результатов запусков тестов {#report-your-test-runs}

```sh
tuist cargo test --workspace
```

При настроенной обёртке mise для Cargo вы можете продолжать вводить `cargo test`. Cargo по-прежнему компилирует и запускает ваши тесты с обычными аргументами, выводом и кодом выхода. Ошибки отправки отчётов не влияют на результат ваших тестов.

Вы можете выбрать пакет или отфильтровать тесты как обычно:

```sh
tuist cargo test -p store
tuist cargo test authentication
```

## Что отслеживает Tuist {#what-is-tracked}

- Прошедшие, упавшие и проигнорированные тесты из завершённых наборов тестов.
- Юнит-тесты, интеграционные тесты и doctests.
- Длительность выполнения всего набора тестов.
- Доступные метаданные ветки, коммита, CI и раннера.

Отфильтрованные тесты и тесты, не выполненные после сбоя, никогда не отмечаются как прошедшие. Результаты отображаются в разделе **Тесты** панели управления.

## Пакеты, модули и тестовые случаи {#test-hierarchy}

Tuist группирует результаты по пакетам и целям Cargo. Пути модулей Rust группируют отдельные тесты внутри цели:

| Метка в панели управления | Значение в Rust | Пример |
| --- | --- | --- |
| Модули | Пакет и цель Cargo | `store::api` |
| Наборы тестов | Пути модулей Rust | `api::authentication` |
| Тестовые случаи | Отдельные тесты | `rejects_invalid_token` |

Doctests используют отдельный модуль, например `store::doctest/store`. Их имена включают путь к исходному файлу, поэтому перемещение примера может изменить его идентификатор.

## Doctests и длительность выполнения {#cargo-test}

Doctests запускаются вашей обычной командой тестирования, включая примеры `compile_fail`, `should_panic` и `no_run`. Чтобы запустить только doctests:

```sh
tuist cargo test --doc
```

Стабильная библиотека libtest сообщает время выполнения всего набора, но не длительность отдельных тестов. Недоступные значения времени исключаются из истории длительности по каждому случаю и аналитики длительности, при этом результаты тестов всё ещё учитываются в показателях надёжности и количества запусков.

## Ограничения отчётности {#reporting-limits}

Отдельные результаты собираются из стандартного вывода Cargo/libtest. Команды с использованием `--no-run`, `--list`, тихого или подробного вывода Cargo, альтернативных форматов или неперехваченного вывода тестов выполняются нормально, но без отправки отчётов по отдельным тестам. Пользовательские harness‑системы, неполные сводки, неоднозначная привязка к целям и слишком большие отчёты не загружаются.

Если пакеты рабочего пространства имеют интеграционные цели с одинаковыми именами, выберите одну из них с помощью `-p <package>`. Отчётность поддерживает точные имена пакетов рабочего пространства; пакеты зависимостей, селекторы с указанием версии и шаблоны выполняются нормально, но не попадают в отчёты. Абсолютные пути doctest опускаются, чтобы пути 체크아웃 не попадали в идентификаторы тестов.

Tuist передаёт вывод в потоковом режиме во время сбора результатов. Это может повлиять на автоматическое определение цвета. Фоновые процессы, которые оставляют каналы вывода открытыми после завершения Cargo, могут привести к пропуску отчёта, но не меняют код выхода Cargo.

## Надёжность и выборка {#reliability-and-selection}

Используйте <.localized_link href="/guides/features/test-insights/flaky-tests/rust">обнаружение нестабильных тестов и их карантин</.localized_link>, чтобы исследовать нестабильные тесты и игнорировать или пропускать их. <.localized_link href="/guides/features/test-sharding/rust">Распараллеливание тестов</.localized_link> распределяет целые цели Cargo между воркерами CI. Включите <.localized_link href="/guides/features/test-code-coverage/rust">покрытие кода</.localized_link>, чтобы отслеживать покрытие строк в ваших запусках тестов. Выборка тестов на основе покрытия и распределение с однократной сборкой недоступны для обычных запусков тестов Cargo.

## Устранение неполадок {#troubleshooting}

Если запуск тестов не отображается в панели управления, включите отладочный вывод, чтобы узнать, почему отчёт не был отправлен:

```sh
TUIST_DEBUG=1 tuist cargo test --workspace
```
