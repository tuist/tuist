# Аналитика тестов Once {#once-test-insights}

Once отправляет результаты тестов в Tuist, чтобы вы могли отслеживать выполнение набора тестов как локально, так и в CI, исследовать сбои и находить медленные тесты без сбора отчётов с отдельных воркеров.

> [!IMPORTANT]
> **Требования**
>
> - Выполните <.localized_link href="/guides/get-started/once-project">Начало работы с Once</.localized_link>.
> - Используйте тестовые цели, которые предоставляют структурированные результаты. Доступная детализация зависит от типа цели и тестового раннера.

## Отправка результатов тестовых запусков {#report-your-test-runs}

Запустите весь набор тестов или выберите конкретную цель:

```bash
once test
once test MyTests
```

Once передаёт нативные события тестирования и публикует завершённые результаты в общую модель тестов Tuist. Разделы **Тесты** и **Запуски тестов** отображают запуски; отдельные тест-кейсы также имеют общую историю тестирования. <.localized_link href="/guides/features/test-sharding/once">Запуск с шардированием на хосте</.localized_link> публикует один отчёт от каждого воркера в объединённый запуск, вместо повторного подсчёта его потока диагностических событий.

## Что отслеживается {#what-is-tracked}

- Отправленные тестовые цели, наборы тестов и отдельные тест-кейсы.
- Результаты прохождения, сбоя и пропуска, с указанием длительности, если она предоставляется раннером.
- Сообщения об ошибках, предоставляемые раннером в отчётах о запусках с шардированием на хосте.
- Упорядоченные попытки повторного запуска и результаты нестабильных тестов, когда тест сначала падает, а затем проходит.
- Контекст ветки, коммита и CI, предоставляемый Once.

Идентификация теста использует нативные имена цели, набора тестов и тест-кейса. Идентификаторы пакетов шардирования являются единицами планирования, а не именами тестов.

Обычная отправка отчётов `once test` сохраняет результаты и попытки повторного запуска, но в настоящее время не включает сообщения об ошибках в общую историю тестов. Отчёты о запусках с шардированием на хосте могут включать сообщения об ошибках, но ни один из способов отправки не предоставляет информацию о расположении исходного кода. Сохраняйте логи CI для диагностики данных, которые недоступны в Tuist.

Не каждая тестовая цель предоставляет одинаковый уровень детализации. Некоторые раннеры сообщают о отдельных тест-кейсах, другие — только сводные данные; точное определение выполняемого файла или кейса является отдельной возможностью. Ознакомьтесь с [покрытием тестовой экосистемы Once](https://buildonce.dev/docs/guide/graph/testing#understand-current-ecosystem-coverage), прежде чем полагаться на аналитику по отдельным кейсам или тонкозернистое планирование.

## Нестабильные тесты {#flaky-tests}

Tuist использует данные о попытках запуска и историю CI для выявления непоследовательных результатов. Отправка данных о попытке не равносильна включению повторных запусков: настройте повторные запуски в раннере, который их поддерживает. См. раздел <.localized_link href="/guides/features/test-insights/flaky-tests/once">Нестабильные тесты в Once</.localized_link> для получения информации об обнаружении и текущих правилах карантина.

## Выбор тестов и покрытие кода {#selection-and-code-coverage}

Once может консервативно выбирать тесты из своего локального графа с помощью `--changed-path`. Это собственный механизм выбора Once, а не выбор тестов на основе покрытия, предоставляемый Tuist:

```bash
once test --changed-path src/library.rs
```

Нативная отправка отчётов Once в настоящее время не загружает данные о покрытии кода в Tuist. Успешный отчёт о тестировании или план шардирования не заполняют панель «Покрытие кода».

## Устранение неполадок {#troubleshooting}

Если запуск отсутствует, убедитесь, что активный провайдер кэша указывает на ваш проект Tuist, и повторно выполните аутентификацию с помощью `once auth login --provider tuist`. Отправка отчётов в реальном времени работает по принципу «best-effort» и не приводит к сбою успешно выполненной команды тестирования, если сервис отправки отчётов недоступен.

Сводки запусков и структурированные данные о сбоях тестов не являются полными логами процессов. Этот сервер в настоящее время не принимает необработанный поток логов действий Once; сохраняйте логи CI для вывода, который не включён в структурированные результаты.
