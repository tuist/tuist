# Аналитика тестов Once {#once-test-insights}

Once отправляет результаты тестов в Tuist, чтобы вы могли отслеживать выполнение набора тестов как локально, так и в CI, исследовать сбои и находить медленные тесты без сбора отчётов от отдельных воркеров.

> [!IMPORTANT]
> **Требования**
>
> - Выполните шаги из руководства <.localized_link href="/guides/get-started/once-project">Начало работы с Once</.localized_link>.
> - Используйте цели тестирования, которые предоставляют структурированные результаты. Доступный уровень детализации зависит от типа цели и тестового раннера.

## Отправка результатов прогонов тестов {#report-your-test-runs}

Запустите весь набор тестов или выберите конкретную цель:

```bash
once test
once test MyTests
```

Once передаёт нативные события тестирования и публикует завершённые результаты в общую модель тестов Tuist. Разделы **Тесты** и **Прогоны тестов** отображают запуски; отдельные тест-кейсы также имеют общую историю тестирования. <.localized_link href="/guides/features/test-sharding/once">Запуск с шардированием на хосте</.localized_link> публикует один отчёт от каждого воркера в объединённый прогон, вместо того чтобы повторно учитывать поток диагностических событий.

## Что отслеживается {#what-is-tracked}

- Цели тестирования, тестовые наборы (suites) и отдельные тест-кейсы.
- Результаты выполнения (успешные, неудачные и пропущенные), включая длительность, если она предоставляется раннером.
- Сообщения об ошибках, предоставляемые раннером в отчётах о шардированных запусках на хосте.
- Упорядоченные попытки повторного запуска и результаты нестабильных тестов, когда тест сначала падает, а затем проходит.
- Контекст ветки, коммита и CI, предоставляемый Once.

Идентификация теста использует нативные имена цели, набора и кейса. Идентификаторы пакетов шардирования являются единицами планирования, а не именами тестов.

Обычная отправка отчётов через `once test` сохраняет результаты и попытки повторного запуска, но в настоящее время не включает сообщения об ошибках в общую историю тестов. Отчёты о шардированных запусках на хосте могут включать сообщения об ошибках, но ни один из способов отправки не предоставляет информацию о расположении исходного кода. Сохраняйте логи CI для диагностики данных, которые недоступны в Tuist.

Не все цели тестирования предоставляют одинаковый уровень детализации. Некоторые раннеры сообщают о отдельных кейсах, другие — только сводные данные; точное определение выполненных файлов или кейсов является отдельной возможностью. Ознакомьтесь с [покрытием экосистемы тестирования Once](https://buildonce.dev/docs/guide/graph/testing#understand-current-ecosystem-coverage), прежде чем полагаться на аналитику по отдельным кейсам или тонко настроенное планирование.

## Нестабильные тесты {#flaky-tests}

Tuist использует данные о попытках запуска и историю CI для выявления непоследовательных результатов. Отправка данных о попытке не равносильна включению повторных запусков: настройте повторные запуски в раннере, который их поддерживает. См. раздел <.localized_link href="/guides/features/test-insights/flaky-tests/once">Нестабильные тесты в Once</.localized_link> для получения информации об обнаружении и текущих границах карантина.

## Выбор тестов и покрытие кода {#selection-and-code-coverage}

Once может консервативно выбирать тесты из своего локального графа с помощью `--changed-path`. Это собственный механизм выбора Once, а не выбор тестов на основе покрытия, предоставляемый Tuist:

```bash
once test --changed-path src/library.rs
```

Нативная отправка отчётов Once в настоящее время не загружает данные о покрытии кода в Tuist. Успешный отчёт о тестировании или план шардирования не заполняет панель «Покрытие кода».

## Устранение неполадок {#troubleshooting}

Если прогон отсутствует, проверьте, что активный провайдер кэша указывает на ваш проект Tuist, и повторно выполните аутентификацию с помощью `once auth login --provider tuist`. Отправка отчётов в реальном времени работает по принципу best-effort и не приводит к ошибке успешно выполненной команды тестирования, если сервис отправки отчётов недоступен.

Сводки прогонов и структурированные данные о сбоях тестов не являются полными логами процессов. Этот сервер в настоящее время не собирает необработанный поток логов действий Once; сохраняйте логи CI для вывода, который не включён в структурированные результаты.
