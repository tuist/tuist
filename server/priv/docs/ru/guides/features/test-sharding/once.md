# Шардирование тестов Once {#once-test-sharding}

Когда ваш набор тестов перерастает возможности одной машины, Once может попросить Tuist распределить обнаруженные пакеты тестов между CI-воркерами. Воркеры выполняют свои задачи через Once, а Tuist объединяет их отчёты в один запуск тестов.

> [!IMPORTANT]
> **Требования**
>
> - Завершите настройку: <.localized_link href="/guides/get-started/once-project">Начало работы с Once</.localized_link>.
> - Используйте релиз Once, который поддерживает команды `once query test-plan --shards` и `once test --shard-plan`. Версия Once 0.71.0 поддерживает только портативные планы, но не этот хостинговый workflow.
> - Обеспечьте полное обнаружение для выбранных целей тестирования, а также наличие одинакового состояния репозитория и тестовой среды на воркерах.

Обёртка для CLI Tuist не требуется. Once использует свой нативный провайдер Tuist и учётные данные.

## Обнаружение ваших тестов {#discover-your-tests}

Запустите выбранные тесты, чтобы выполнить обнаружение перед планированием:

```bash
once test MyTests --format json
```

Доступная гранулярность пакетов зависит от раннера. Некоторые цели тестирования поддерживают пакеты по файлам или тест-кейсам; другие остаются на уровне целей. Следуйте [руководству по тестированию Once](https://buildonce.dev/docs/guide/graph/testing), чтобы узнать о возможностях обнаружения и пакетирования.

## Создание хостингового плана {#create-a-hosted-plan}

В задаче планирования используйте ссылку, общую для этого выполнения CI:

```bash
once query test-plan --shards 4 --reference "$CI_EXECUTION_ID" --format json
```

Ответ содержит ID хостингового плана и фактические индексы воркеров:

```json
{"shard_plan_id":"<UUID>","shards":[0,1,2,3]}
```

Стройте матрицу CI на основе `shards`, а не предполагайте, что она всегда содержит четыре элемента. Пустой план возвращает пустой ID и массив, поэтому запускать воркеры не нужно. Передайте `--target`, чтобы сузить план, или повторите `--changed-path`, чтобы использовать выбор на основе графа Once.

По умолчанию ссылка берётся из `TUIST_SHARD_REFERENCE` или определяется из запуска CI. Передавайте её явно, если в среде нет поддерживаемого идентификатора CI.

## Выполнение каждого шарда {#execute-each-shard}

Передайте каждому воркеру полученный ID плана и его собственный индекс:

```bash
once test --shard-plan "$SHARD_PLAN_ID" --shard-index "$SHARD_INDEX" --jobs 4
```

Альтернативно, установите `TUIST_SHARD_PLAN_ID` и `TUIST_SHARD_INDEX`. Воркеры скачивают план, привязанный к конкретному UUID, и выполняют только назначенные им пакеты. Пустое назначение ничего не запускает; отсутствующие результаты, упавшие процессы и прерванная работа не могут пройти через партицию.

Это распределяет план тестирования, а не предварительно собранный архив с тестами. Подготовьте необходимые исходники, инструменты и данные обнаружения на воркерах; общее кэширование может избежать повторного выполнения подходящих задач сборки.

## Повторные запуски и результаты {#reruns-and-results}

Для повторного запуска увеличьте значение `--shard-attempt` или установите `TUIST_SHARD_ATTEMPT`. В остальных случаях Once использует номер попытки запуска GitHub, по умолчанию равный 1. Значение `--shard-report-revision` по умолчанию равно 0 и может увеличиваться при исправлении отчёта в рамках той же попытки. Эти счётчики не связаны с повторными попытками отдельных тестов.

Откройте раздел **Tests → Shards**, чтобы проверить план, балансировку и отчитавшиеся воркеры, затем откройте объединённый запуск тестов для просмотра индивидуальных результатов. Единицы планирования Once обозначены как **Batches**; кейсы сохраняют свои исходные названия целей, наборов и тестов.

Смотрите <.localized_link href="/guides/features/test-insights/once">Аналитика тестов Once</.localized_link> для получения подробностей об отчётности и ограничениях покрытия.
