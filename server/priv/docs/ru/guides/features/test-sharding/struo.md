# Шардирование тестов Struo {#struo-test-sharding}

<a id="once-test-sharding"></a>

Когда набор тестов перерастает возможности одной машины, Struo может попросить Tuist распределить обнаруженные пакеты тестов между воркерами CI. Воркеры выполняют свои задания через Struo, а Tuist объединяет их отчёты в один запуск тестов.

> [!IMPORTANT]
> **Требования**
>
> - Завершите <.localized_link href="/guides/get-started/struo-project">Начало работы со Struo</.localized_link>.
> - Используйте [Struo 1.0.0](https://github.com/tuist/struo/releases/tag/1.0.0) или более позднюю версию с `struo query test-plan --shards` и `struo test --shard-plan`.
> - Обеспечьте полное обнаружение для выбранных целей тестирования и наличие одинакового 체크아웃а и тестовой среды на воркерах.

Обёртка Tuist CLI не требуется. Struo использует свой нативный провайдер Tuist и учётные данные.

## Обнаружение ваших тестов {#discover-your-tests}

Запустите выбранные тесты, чтобы выполнить обнаружение перед планированием:

```bash
struo test MyTests --format json
```

Доступная гранулярность пакетов зависит от раннера. Некоторые цели тестирования поддерживают пакеты по файлам или тест-кейсам; другие остаются на уровне целей. Следуйте [руководству по тестированию Struo](https://struo.run/docs/guide/graph/testing), чтобы узнать о возможностях обнаружения и пакетирования.

## Создание размещённого плана {#create-a-hosted-plan}

В задаче планирования используйте ссылку, общую для этого выполнения CI:

```bash
struo query test-plan --shards 4 --reference "$CI_EXECUTION_ID" --format json
```

Ответ содержит ID размещённого плана и фактические индексы воркеров:

```json
{"shard_plan_id":"<UUID>","shards":[0,1,2,3]}
```

Стройте матрицу CI на основе `shards`, а не предполагайте, что она содержит четыре элемента. Пустой план возвращает пустой ID и массив, поэтому запускать воркеры не нужно. Передайте `--target`, чтобы сузить план, или повторите `--changed-path`, чтобы использовать выбор на основе графа Struo.

По умолчанию ссылка берётся из `TUIST_SHARD_REFERENCE` или обнаруженного запуска CI. Указывайте её явно, если в среде нет поддерживаемого идентификатора CI.

## Выполнение каждого шарда {#execute-each-shard}

Передайте каждому воркеру полученный ID плана и его собственный индекс:

```bash
struo test --shard-plan "$SHARD_PLAN_ID" --shard-index "$SHARD_INDEX" --jobs 4
```

В качестве альтернативы установите `TUIST_SHARD_PLAN_ID` и `TUIST_SHARD_INDEX`. Воркеры скачивают план, привязанный к конкретному UUID, и выполняют только назначенные им пакеты. Пустое назначение ничего не запускает; отсутствующие результаты, сбои процессов и прерванная работа не могут пройти через раздел.

Это распределяет план тестирования, а не предварительно собранный архив сборки тестов. Подготовьте необходимые исходники, инструменты и обнаружение на воркерах; общее кэширование может избежать повторения подходящей работы по сборке.

## Повторные запуски и результаты {#reruns-and-results}

Для повторного запуска увеличьте `--shard-attempt` или установите `TUIST_SHARD_ATTEMPT`. В противном случае Struo использует номер попытки запуска GitHub, по умолчанию равный 1. `--shard-report-revision` по умолчанию равен 0 и может увеличиваться при исправлении отчёта в рамках той же попытки. Эти счётчики отделены от повторных попыток самого теста.

Откройте **Тесты → Шарды**, чтобы проверить план, баланс и отчитавшиеся воркеры, затем откройте объединённый запуск тестов для просмотра индивидуальных результатов. Единицы планирования Struo помечены как **Пакеты**; кейсы сохраняют свои родные названия целей, наборов и тестов.

См. <.localized_link href="/guides/features/test-insights/struo">Аналитика тестов Struo</.localized_link> для получения подробностей об отчётности и ограничениях покрытия.
