# Шардирование тестов Struo {#struo-test-sharding}

<a id="once-test-sharding"></a>

Когда ваш набор тестов перерастает возможности одной машины, Struo может попросить Tuist распределить обнаруженные пакеты тестов между CI-воркерами. Воркеры выполняют свои задачи через Struo, а Tuist объединяет их отчёты в один запуск тестов.

> [!IMPORTANT]
> **Требования**
>
> - Пройдите <.localized_link href="/guides/get-started/struo-project">Начало работы со Struo</.localized_link>.
> - Используйте [Struo 1.0.0](https://github.com/tuist/struo/releases/tag/1.0.0) или новее с командами `struo query test-plan --shards` и `struo test --shard-plan`.
> - Обеспечьте полное обнаружение для выбранных целей тестирования, а также наличие одинакового состояния репозитория и тестовой среды на воркерах.

Обёртка для Tuist CLI не требуется. Struo использует свой встроенный провайдер Tuist и учётные данные.

## Обнаружение ваших тестов {#discover-your-tests}

Запустите выбранные тесты, чтобы выполнить обнаружение перед планированием:

```bash
struo test MyTests --format json
```

Доступная гранулярность пакетов зависит от раннера. Некоторые цели тестирования поддерживают пакетирование по файлам или отдельным тест-кейсам; другие остаются на уровне целей. Следуйте [руководству по тестированию Struo](https://struo.run/docs/guide/graph/testing), чтобы узнать о возможностях обнаружения и пакетирования.

## Создание размещённого плана {#create-a-hosted-plan}

В задаче планирования используйте ссылку, общую для этого выполнения CI:

```bash
struo query test-plan --shards 4 --reference "$CI_EXECUTION_ID" --format json
```

Ответ содержит ID размещённого плана и фактические индексы воркеров:

```json
{"shard_plan_id":"<UUID>","shards":[0,1,2,3]}
```

Стройте матрицу CI на основе `shards`, а не предполагайте, что она всегда содержит четыре элемента. Пустой план возвращает пустой ID и массив, поэтому запускать воркеры не нужно. Передайте `--target`, чтобы сузить план, или повторяйте `--changed-path`, чтобы использовать выбор на основе графа Struo.

По умолчанию ссылка берётся из `TUIST_SHARD_REFERENCE` или определяется автоматически из запуска CI. Указывайте её явно, если в среде нет поддерживаемого идентификатора CI.

## Выполнение каждого шарда {#execute-each-shard}

Передайте каждому воркеру полученный ID плана и его собственный индекс:

```bash
struo test --shard-plan "$SHARD_PLAN_ID" --shard-index "$SHARD_INDEX" --jobs 4
```

Альтернативно, установите переменные `TUIST_SHARD_PLAN_ID` и `TUIST_SHARD_INDEX`. Воркеры скачивают план, привязанный к конкретному UUID, и выполняют только назначенные им пакеты. Пустое назначение ничего не запускает; отсутствующие результаты, сбои процессов и прерванная работа не могут пройти проверку раздела.

Это распределяет план тестирования, а не предварительно собранный архив тестовой сборки. Подготовьте необходимые исходные коды, инструменты и этап обнаружения на воркерах; общее кэширование может избежать повторного выполнения подходящих задач сборки.

## Повторные запуски и результаты {#reruns-and-results}

Для повторного запуска увеличьте значение `--shard-attempt` или установите `TUIST_SHARD_ATTEMPT`. В противном случае Struo использует номер попытки запуска GitHub, по умолчанию равный 1. `--shard-report-revision` по умолчанию равен 0 и может увеличиваться при исправлении отчёта в рамках той же попытки. Эти счётчики не связаны с повторными попытками отдельных тестов.

Откройте раздел **Tests → Shards**, чтобы проверить план, балансировку и зарегистрированные воркеры, затем откройте объединённый запуск тестов для просмотра индивидуальных результатов. Единицы планирования Struo обозначены как **Batches**; тест-кейсы сохраняют свои исходные названия целей, наборов и тестов.

См. <.localized_link href="/guides/features/test-insights/struo">Аналитика тестов Struo</.localized_link> для получения подробностей об отчётности и ограничениях покрытия.
