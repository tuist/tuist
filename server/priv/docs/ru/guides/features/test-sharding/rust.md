# Шардирование тестов Rust {#rust-test-sharding}

Tuist распределяет цели тестирования Cargo по рабочим узлам CI, используя исторические данные о длительности целей. Цели модульных тестов, интеграционных тестов и doctests каждой библиотеки являются отдельными модулями. Тесты внутри одной цели выполняются вместе.

> [!IMPORTANT]
> **Требования**
>
> - Настройте <.localized_link href="/guides/features/test-insights/rust">Rust Test Insights</.localized_link> и выполните аутентификацию CLI в задаче планирования и на рабочих узлах.
> - Выберите один пакет, используя `-p <package>` в воркспейсе. Шардирование нескольких пакетов не поддерживается.
> - Используйте одинаковую ревизию, инструментарий Rust, выбор пакета, функции и фильтры тестов в каждой задаче.

## Создание плана {#create-a-plan}

Добавьте количество шардов к `--no-run`, чтобы скомпилировать и перечислить цели без выполнения тестов:

```sh
TUIST_SHARD_REFERENCE=my-ci-run tuist cargo test -p store --no-run --shard-max 4
```

Команда выводит JSON, содержащий `shard_plan_id` и массив `shards` с нулевой индексацией. В GitHub Actions она также записывает `shard-plan-id` и `shards` в `GITHUB_OUTPUT`. Без явной ссылки Tuist формирует её на основе поддерживаемой среды CI.

| Опция | Описание |
| --- | --- |
| `--shard-max N` | Максимальное количество шардов |
| `--shard-min N` | Минимальное количество шардов |
| `--shard-total N` | Точное количество, вплоть до доступных целей |
| `--shard-max-duration N` | Целевая максимальная длительность шарда в миллисекундах |

Используйте только `--shard-total` или комбинируйте `--shard-min` и `--shard-max`. Без исторических данных о длительности планировщик использует оценки целей по умолчанию. Обычный `--no-run` без опций шардирования остаётся командой только для сборки.

## Выполнение каждого шарда {#execute-each-shard}

Установите ID плана и индекс шарда на каждом рабочем узле, затем используйте те же аргументы тестирования Cargo:

```sh
TUIST_SHARD_PLAN_ID=<plan-id> TUIST_SHARD_INDEX=0 tuist cargo test -p store
```

В качестве альтернативы установите `TUIST_SHARD_REFERENCE` в значение ссылки задачи планирования вместо передачи ID плана. Tuist получает назначение и просит Cargo выполнить только эти цели. Недействительные или несовместимые назначения приводят к ошибке команды, а не к запуску всех тестов. Пустые назначения не выполняют тесты. Результаты с рабочих узлов связываются с планом в Test Insights, и <.localized_link href="/guides/features/test-insights/flaky-tests/rust#quarantining">карантин</.localized_link> применяется внутри каждого шарда.

## Ограничения {#limits}

Это шардирование на уровне целей, а не распределение с однократной сборкой. Каждому рабочему узлу требуется клон исходного кода и сборка своих целей; <.localized_link href="/guides/features/cache/rust">кэш компиляции Cargo</.localized_link> может повторно использовать подходящие результаты компиляции. Tuist не загружает исполняемые файлы тестов и не требует другого средства запуска тестов Rust.

Для шардирования требуется выбрать один пакет. Сужение команды для нескольких пакетов может изменить объединённые функции зависимостей Cargo, поэтому Tuist отклоняет её вместо запуска тестов с другим графом функций. Планируйте каждый пакет отдельно, пока не будет добавлена поддержка шардирования нескольких пакетов.

Шардирование требует стандартных harness-сред libtest и захвата вывода по умолчанию. Команды с тихим режимом, подробным выводом, альтернативным форматом, без захвата вывода и с пользовательским harness отклоняются. Если Cargo не может однозначно идентифицировать цель, выберите точный пакет воркспейса с помощью `-p <package>`. Пакеты зависимостей, селекторы с указанием версии, глобальные шаблоны имён пакетов/целей и ночная опция Cargo `-C` не поддерживаются для шардирования. Сохраняйте идентичный выбор тестов при планировании и выполнении.
