# Model Context Protocol

[Model Context Protocol (MCP)](https://modelcontextprotocol.io/docs/getting-started/intro) — это открытый стандарт, позволяющий агентам искусственного интеллекта взаимодействовать с внешними сервисами и источниками данных. Он обеспечивает совместимость таких приложений, как [Claude](https://claude.ai/), [Claude Code](https://docs.anthropic.com/en/docs/claude-code), [Codex](https://developers.openai.com/codex/), и редакторов, таких как [Zed](https://zed.dev), [Cursor](https://www.cursor.com) или [Visual Studio Code](https://code.visualstudio.com), с Tuist.

Tuist размещает серверную точку входа Model Context Protocol по адресу `https://tuist.dev/mcp`. Подключив к ней свой клиент, агенты смогут получать доступ к данным вашего проекта в Tuist, включая аналитику тестов, анализ нестабильных тестов и многое другое. Большинство инструментов работают только на чтение и ограничены данными проектов Tuist, прошедших аутентификацию. Инструменты настройки аккаунта могут перечислять аккаунты, создавать организации, создавать проекты и добавлять существующих пользователей в организации, если у аутентифицированного пользователя есть необходимые разрешения. Каждый инструмент предоставляет аннотации, указывающие, работает ли он только на чтение, может ли он вызвать трудно обратимые изменения и может ли он изменить состояние в публичном интернете. Инструменты настройки аккаунта требуют аутентификации пользователя. Они недоступны для токенов проектов или обычных токенов аккаунтов. Когда пользователь авторизует клиент в браузере или подтверждает регистрацию `auth.md`, Tuist связывает эти учетные данные с пользователем только в точке входа Model Context Protocol, чтобы инструменты настройки могли завершить запрошенный рабочий процесс.

Tuist реализует [протокол версии 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http). Запросы не сохраняют состояние: клиенты отправляют метаданные протокола с каждым запросом и могут вызывать инструменты напрямую без инициализации. `server/discover` возвращает идентификатор сервера, возможности, поддерживаемые версии и инструкции. Идентификаторы сессий или независимые потоки событий отсутствуют. Клиенты, использующие поток инициализации 2025-06-18 или 2025-03-26, по-прежнему поддерживаются; они также работают без сессий на стороне сервера.

## Model Context Protocol против навыков

Функциональность инструментов Model Context Protocol и <.localized_link href="/guides/features/agentic-coding/skills">навыков</.localized_link> может пересекаться. Учитывая текущее перекрытие между ними, выбирайте один подход для каждого рабочего процесса и используйте его последовательно, вместо того чтобы смешивать оба в одном потоке.

Для клиентов, поддерживающих установку плагинов, используйте <.localized_link href="/guides/features/agentic-coding/plugins">плагины Tuist</.localized_link>, чтобы установить их вместе.

## Настройка

Добавьте `https://tuist.dev/mcp` в качестве удаленного сервера Model Context Protocol в вашем клиенте. Инструкции по инициализации сервера и публичная карточка сервера описывают OAuth 2.0 с динамической регистрацией клиента и стандартный поток авторизации через браузер встроенным образом, не требуя от агентов загружать или следовать внешним документам аутентификации. Эти общесерверные инструкции оставляют рекомендации по рабочему процессу общими: аутентификация инструментов не аутентифицирует локальные инструменты командной строки или интеграции со сборочными системами, и агенты должны проверять запрашиваемые изменения через соответствующие инструменты Tuist. Настройка и проверки аутентификации, специфичные для сборочной системы, документированы в руководствах по интеграции и подсказках. Tuist по-прежнему предоставляет метаданные обнаружения [Open Authorization](https://oauth.net/2/) и текущий [протокол auth.md](https://workos.com/auth-md) отдельно по адресу `https://tuist.dev/auth.md`.

Точка входа принимает жизненный цикл запроса Model Context Protocol без сохранения состояния `2026-07-28`, включая `server/discover`, наряду со старым жизненным циклом на основе сессий. Существующие клиенты могут продолжать использовать свой текущий метод подключения.

Клиенты, поддерживающие события Model Context Protocol, могут подписываться на события проекта. См. раздел [События](#events) для получения информации о доступных событиях и требованиях к доставке.

Клиенты, которые уже поддерживают удаленную аутентификацию через браузер, могут продолжать аутентифицироваться в браузере. Клиенты и агенты, поддерживающие `auth.md`, могут регистрироваться анонимно, предоставлять утверждение идентичности доверенного провайдера или начинать процесс подтверждения адреса электронной почты с аутентификацией сервиса. Регистрация возвращает утверждение идентичности, подписанное Tuist, которое агент обменивает на стандартной конечной точке токена на токен доступа сроком на один час. Tuist публикует свой открытый ключ подписи и поддерживает стандартное отзывание токенов и доставку событий безопасности от провайдера.

Неаутентифицированный агент должен прочитать заголовок `WWW-Authenticate`, возвращаемый точкой входа Model Context Protocol, получить метаданные защищенного ресурса, получить метаданные сервера авторизации и перейти по его URL `agent_auth.skill`. Tuist также возвращает тот же локальный URL `auth_md` в теле ответа об отказе в доступе, чтобы клиенты, управляемые языковыми моделями, могли обнаружить этот поток без reliance на нативную интеграцию клиента. Локальный для развертывания документ является источником истины для имен конечных точек, тел запросов, опроса подтверждения и обмена утверждениями.

Прежде чем агент начнет процесс подтверждения адреса электронной почты, он должен попросить пользователя подтвердить адрес электронной почты для его аккаунта Tuist. Он не должен выводить этот адрес из профиля провайдера, конфигурации Git, переменной окружения или метаданных сессии.

Точка входа использует группу областей видимости `mcp`. Анонимные учетные данные до подтверждения могут обнаруживать возможности и читать публичные руководства по интеграции, но они не рассматриваются как вошедший в систему пользователь. После авторизации в браузере или подтверждения учетные данные привязываются к пользователю, и каждый инструмент применяет те же проверки авторизации, что и панель управления. Подробнее см. в <.localized_link href="/guides/server/authentication#scope-groups">документации по группам областей видимости</.localized_link>.

Инструменты разрешаются к проектам, которые аутентифицированный пользователь уже может читать. Инструменты сборки Xcode и Gradle принимают UUID сборки или URL панели управления. UUID должен идентифицировать ровно один проект; если он встречается в нескольких проектах, инструмент возвращает ошибку «не найдено» вместо выбора отчета другого проекта. Чтение данных панели управления и API в рамках проекта остается доступным. Сообщаемые идентификаторы действующих лиц являются непроверенными метками, а не учетными данными или дополнительными правами доступа.

Инструменты списка сборок и детальной информации предоставляют необязательные метаданные `tuist_version`: версия CLI Tuist для Xcode и Cargo, плагин Tuist Gradle для Gradle и библиотека `tuist_ex` для Mix. Xcode также предоставляет `tuist_generation_version` из связанного события генерации проекта, которое может отличаться от версии загружающего CLI. Отсутствующие значения равны null, они не выводятся из данных сервера или другого отчета. Bazel использует существующий `bazel_version`; детали запуска Once предоставляют `once_version`. Эти поля описывают сообщаемые версии, а не проверенную идентичность или версии контракта взаимодействия. REST-эндпоинты сборок предоставляют те же метаданные. Существующие навыки интеграции и работы с нестабильными тестами не зависят от полей версий и не требуют изменений в рабочем процессе.

Операторы Tuist, исследующие аккаунт клиента, делают это через внутренние инструменты операций Tuist, которые записывают каждый вызов; прямое подключение к этой точке входа не дает доступа beyond членства самого пользователя.

<details>
<summary>Claude Code</summary>

Выполните:

```bash
claude mcp add --transport http tuist https://tuist.dev/mcp
```

Если безголовый клиент Claude Code не сообщает модели о неудачном подключении к нативному серверу, потребуйте от агента проверить неаутентифицированный ответ [протокола передачи гипертекста](https://developer.mozilla.org/en-US/docs/Web/HTTP) настроенной точки входа перед поиском в размещенной документации или редактированием проекта. Ответ направляет модель к локальному документу `auth.md`, даже если аутентификация в браузере недоступна.

</details>


<details>
<summary>Codex</summary>

Выполните:

```bash
codex mcp add tuist --url https://tuist.dev/mcp
codex mcp login tuist
```

Завершите вход в браузере перед началом нового запуска `codex exec`. Codex считывает инструкции сервера Tuist во время инициализации, поэтому запросы оптимизации Gradle автоматически получают рабочий процесс аутентификации и проверки.

</details>

<summary>Claude Desktop</summary>

- **Name:** `tuist`
- **URL:** `https://tuist.dev/mcp`

При появлении запроса завершите [Open Authorization](https://oauth.net/2/) в браузере.

<details>
<summary>Pi</summary>

Pi не включает клиент Model Context Protocol. Вы можете установить стороннее расширение [`pi-mcp-adapter`](https://pi.dev/packages/pi-mcp-adapter), предварительно изучив его исходный код и последствия для безопасности:

```bash
pi install npm:pi-mcp-adapter
```

Добавьте файл `.mcp.json` на уровне проекта:

```json
{
  "mcpServers": {
    "tuist": {
      "url": "https://tuist.dev/mcp",
      "auth": false
    }
  }
}
```

Установка `auth` в значение `false` предотвращает скрытие неавторизованного ответа Tuist обработчиком аутентификации браузера адаптера. После этого безголовый агент может прочитать возвращенный URL `auth_md` и следовать процессу регистрации Tuist, обмена утверждениями идентичности и опроса подтверждения. Настройте полученный токен доступа как bearer-токен или позвольте агенту выполнять аутентифицированные вызовы Model Context Protocol напрямую.

Если вы предпочитаете аутентификацию в браузере, установите `auth` в значение `"oauth"`. Для этого потока держите один процесс активным с использованием [режима удаленного вызова процедур](https://pi.dev/docs/latest/rpc) Pi, пока аутентификация не завершится:

```bash
pi --mode rpc
```

Не разделяйте ожидающую аутентификацию в браузере между отдельными вызовами `pi --print`, так как процесс, владеющий состоянием обратного вызова, уже завершился.

</details>

Если ваш агент поддерживает `auth.md`, он может начать работу анонимно без открытия браузера. Доверенная идентичность провайдера также может завершить процесс без браузера, если идентичность провайдера уже связана. Для электронной почты с аутентификацией службы, анонимного подтверждения или первой связи с провайдером агент показывает вам ссылку на проверку Tuist и шестизначный код. Откройте ссылку, войдите в систему и введите код агента на странице Tuist. Никогда не отправляйте код обратно агенту. Метаданные сервера авторизации Tuist указывают непосредственно на собственный `/auth.md` развертывания, который содержит точные форматы запросов и опроса.

## Интеграции систем сборки используют два набора учетных данных

Учетные данные, используемые для инструментов Model Context Protocol, не аутентифицируют плагин Gradle или удаленные сервисы Bazel. Прежде чем агент изменит или проверит интеграцию Gradle или Bazel, он должен выполнить:

```bash
tuist auth whoami --url https://tuist.dev
```

Если эта команда не аутентифицирована, агент должен остановиться и попросить пользователя выполнить:

```bash
tuist auth login --url https://tuist.dev
```

Для локального или самостоятельно размещенного развертывания замените URL в обеих командах и в `tuist.toml`. Сохраняйте одинаковое написание имени хоста везде. Например, `localhost` и `127.0.0.1` используют отдельные сохраненные учетные данные.


## Возможности

### Инструменты

Следующие инструменты доступны через сервер Tuist Model Context Protocol:

Каждый инструмент предоставляет понятное описание вместе с явными схемами ввода и вывода. Успешные вызовы возвращают структурированный контент, соответствующий заявленной схеме вывода, а также тот же результат, сериализованный в виде текста для клиентов, которые еще не потребляют структурированный контент.

Инструменты, принимающие идентификатор отдельной записи, такой как `build_run_id`, `test_run_id`, `test_case_id`, `bundle_id`, `run_id`, `generation_id` или `cache_run_id`, также принимают URL-адрес этой записи в панели управления Tuist. Вставьте URL-адрес прямо из браузера вместо того, чтобы извлекать из него идентификатор.

#### Поиск по документации и сообществу

Этот инструмент только для чтения выполняет поиск по документации Tuist, справочнику [application programming interface](https://en.wikipedia.org/wiki/API), релизам GitHub, форуму сообщества и задачам GitHub через тот же поисковый движок, который работает на сайте документации. Результаты поиска по релизам включают продукт, версию, дату публикации и статус предварительного выпуска. По умолчанию выполняется поиск по стабильным релизам, предварительные релизы можно включить с помощью `include_prereleases`. Инструмент доступен только на сервере, размещенном Tuist, по адресу `https://tuist.dev/mcp`.

| Инструмент | Описание | Обязательные параметры |
|------|-------------|---------------------|
| `search_tuist` | Поиск по публичной документации Tuist, справочнику application programming interface, релизам GitHub, обсуждениям сообщества и задачам GitHub. При необходимости ограничьте поиск одним `source` (`docs`, `api_reference`, `releases`, `forum`, `issues`). | `query` |

#### Ответы на основе исходного кода

Эти инструменты только для чтения позволяют агентам использовать точную публичную ревизию исходного кода Tuist, развернутую вместе с размещенным сервером, в качестве источника истины для ответов, зависящих от текущего поведения. Они доступны только по адресу `https://tuist.dev/mcp`.

Совместимые клиенты получают фактические описания ревизии исходного кода инструментов, ссылки и ограничения результатов во время инициализации вместе с информацией об inline OAuth-аутентификации. Эти описания не предписывают стиль ответа или рабочий процесс проверки. Пользователи могут задать вопрос напрямую, не вызывая сначала подсказку `ask_tuist`; подсказка остается доступной для явного рабочего процесса на основе исходного кода.

Каждая операция имеет фиксированные ограничения на параллелизм, длительность, обход, количество прочитанных байтов и размер ответа. Результаты поиска и списков включают поля `truncated` и `truncation_reason`. Если результат усечен, сузьте путь, шаблон файла или поисковый запрос вместо того, чтобы считать результат исчерпывающим.

| Инструмент | Описание | Обязательные параметры |
|------|-------------|---------------------|
| `search_tuist_code` | Отвечайте на вопросы о текущем поведении, значениях по умолчанию, конфигурации, фича-флагах, обработке ошибок или недокументированных деталях, выполняя поиск по исходным файлам. Результаты включают окружающие строки, ссылки на исходный код с привязкой к ревизии и статистику сканирования. | `pattern` |
| `list_tuist_files` | Обнаруживайте подсистему исходного кода или nearby тесты, когда соответствующий путь неизвестен. Списки имеют ограниченную глубину и количество результатов. | Нет |
| `read_tuist_file` | Изучайте определенный диапазон строк в файле реализации, месте вызова или тесте после нахождения соответствующего пути. Усеченные ответы предоставляют `next_start_line` для продолжения. | `path` |

#### Сборки Xcode

Инструменты детализации сборок для Xcode, Gradle, Bazel, Mix и Cargo предоставляют данные в существующем формате `custom_metadata: {tags, values}`, включая наблюдения за инфраструктурой, если они сообщаются. Значения остаются строками, а неизвестные ключи сохраняются. Например, `tuist.cpu.available_processors` описывает доступные во время выполнения логические процессоры, тогда как `tuist.gradle.max_workers` — это ограничение на количество воркеров Gradle, а `tuist.jvm.max_heap_bytes` — ограничение кучи JVM, а не память хоста. Это ненадежные наблюдения клиента, а не проверенные идентификаторы раннеров. Отсутствующие наблюдения остаются отсутствующими; импортированные логи и старые клиенты могут не иметь метаданных инфраструктуры. Обновление метаданных Once ожидает согласованного обновления клиента/протокола.

| Инструмент | Описание | Обязательные параметры |
|------|-------------|---------------------|
| `list_xcode_builds` | Список запусков сборок Xcode для проекта. | `account_handle`, `project_handle` |

| `list_xcode_build_files` | Список скомпилированных файлов для конкретного запуска сборки Xcode. | `build_run_id` |
| `list_xcode_build_steps` | Список записанных шагов сборки с указанием времени и результатов, без текста логов. | `build_run_id` |
| `get_xcode_build_step` | Получить один записанный шаг сборки, включая его лог и флаг усечения. | `build_run_id`, `step_id` |

`list_xcode_build_steps` по умолчанию возвращает страницы по 20 шагов (максимум 100 через `page_size`), с `page` и `pagination_metadata` для навигации. Используйте `search` для поиска по заголовкам, проектам или целям, либо фильтруйте по точному совпадению `project`, `target`, `category` (например, `swiftCompilation`) и `status` (`success` или `failure`). Сортируйте по `duration_ms` для отображения самых медленных первыми (по умолчанию) или по `start_ms` для хронологического порядка. ID шагов разрешают неоднозначности и возвращаются в виде десятичных строк для сохранения полной 64-битной точности. ID привязаны к сборке и не должны сопоставляться между разными сборками.

Опциональные `start_ms` и `end_ms` выбирают шаги, пересекающиеся с временным диапазоном в миллисекундах от начала сборки; конец диапазона исключается. Оба инструмента принимают UUID сборки или URL панели управления в качестве `build_run_id`. Передайте полученный `id` шага без изменений в качестве `step_id` для получения его лога. Логи хранят до 64 КиБ на шаг, при этом `log_truncated` указывает на пропущенный вывод.

Шаги собираются по умолчанию при обработке сборок Xcode. Записанные данные шагов хранятся 90 дней. Ответ списка включает `availability`: `available`, если записанные шаги существуют, даже если фильтры ничего не нашли; `processing`, если сборка все еще обрабатывается и шагов пока нет; или `unavailable`, если шаги не были записаны или срок их хранения истек.

Те же операции доступны через HTTP API по адресам `GET /api/projects/{account_handle}/{project_handle}/xcode/builds/{build_id}/steps` и `GET /api/projects/{account_handle}/{project_handle}/xcode/builds/{build_id}/steps/{step_id}`, с теми же фильтрами и пагинацией. Для обоих требуется доступ на чтение к проекту сборки.

ID шагов Bazel, возвращаемые из сохраненных сводок, остаются читаемыми, если полный профиль поступает между списком и выборкой шага. Индексированный профиль, данные шагов которого истекли, сообщает о недоступности. Списки шагов Gradle включают кэшированные и пропущенные операции с нулевой длительностью.

#### Задачи, действия, модули и файлы

Эти инструменты, работающие в контексте проекта, проверяют постоянные идентификаторы сборок across запусков. Начните с `list_build_entities`, затем передайте полученный стабильный `id` с тем же `kind` в `get_build_entity` или `list_build_entity_history` вместе с `account_handle` и `project_handle`. Идентификатор сборки или вызова не требуется.

| Инструмент | Описание | Обязательные параметры |
| --- | --- | --- |
| `list_build_entities` | Список задач, модулей, действий или файлов одного типа, обнаруженных в сборках проекта. | `account_handle`, `project_handle`, `kind` |
| `get_build_entity` | Получить одну сущность сборки с ее нативным идентификатором и аналитикой за выбранный период. | `account_handle`, `project_handle`, `kind`, `id` |
| `list_build_entity_history` | Список записанных выполнений, компиляций или событий кэша для одной сущности сборки, от новых к старым. | `account_handle`, `project_handle`, `kind`, `id` |

| `kind` | Инструментарий | Списки истории |
| --- | --- | --- |
| `bazel_actions` | Действия Bazel | Выполнения действий, сообщенные через BEP |
| `gradle_tasks` | Задачи Gradle | Выполнения задач |
| `xcode_modules` | Модули Xcode | Компиляции и события кэша модулей |
| `once_actions` | Действия Once | Выполнения |
| `mix_files` | Компилированные файлы Mix | Компиляции |
| `mix_modules` | Компилированные модули Mix | Компиляции |

Эти инструменты внедряются постепенно и возвращают данные только для проектов, где они включены; для остальных проектов возвращается ошибка вместо пустого результата. Тип доступен только для проектов, использующих соответствующий инструментарий сборки. Инструменты принимают ограниченные фильтры `start_at`/`end_at`, `environment` (`any`, `ci` или `local`) и точное значение `branch`. `list_build_entities` принимает `q`; `list_build_entity_history` поддерживает непрозрачные курсоры `after`/`before`. Неизвестные данные о времени выполнения или наблюдения кэша остаются недоступными, а не превращаются в нули или промахи. История ссылается на записанного родителя и нативное выполнение для детализации с помощью существующих инструментов запусков.

Метрики `get_build_entity` включают `duration_samples` — количество наблюдений с записанным временем: реальные нулевые длительности учитываются, отсутствующие данные о времени — нет. Это число может быть меньше количества наблюдений; недоступная статистика длительности остается null.

Длительности модулей Xcode берутся из измеренных компиляций целей в логах сборки. Разрешения кэша модулей и цели без работы компиляции не вносят вклад в выборки длительности. Наблюдения компиляции относятся к сборке Xcode; события кэша относятся к команде генерации или кэширования.

Действия Bazel идентифицируются по метке цели, мнемонике и настроенному первичному выходу, что позволяет различать отдельные действия и конфигурации без опоры на зависящие от входных данных дайджесты кэша. История записывает выполнения, сообщенные через BEP, а не поиски в кэше или фазы трассировки профиля. Полное покрытие выполнения требует `--build_event_publish_all_actions`; доставка артефактов осуществляется по принципу best effort, поэтому отсутствие наблюдений не является доказательством того, что работа не выполнялась. Старые полезные нагрузки Kura без стабильной идентичности или начала выполнения по-прежнему принимаются, но не индексируются. Отсутствующие измерения времени окончания остаются недоступными, а реальные нулевые длительности учитываются.

Длительности модулей Mix измеряют компиляцию содержащего файла, а не независимо измеренную работу модуля. Действия Once используют объявленные слоты target/capability/index, когда клиент сообщил сопоставления целей; одни лишь диагностические метки не являются стабильными идентификаторами. Существующие клиенты и инструменты уровня запуска по-прежнему поддерживаются без изменений.

Чтение аналитики имеет ограничения по памяти и времени выполнения. Если запрос превышает эти лимиты, инструмент возвращает ошибку вместо создания пустого результата.

Новые наблюдения индексируются после развертывания; эта функция не заполняет ретроспективно существующую телеметрию запусков. Метаданные идентичности хранятся дольше отдельных наблюдений в соответствии с <.localized_link href="/guides/server/data-retention">политикой хранения данных</.localized_link>.

### События

Клиенты, использующие жизненный цикл Model Context Protocol `2026-07-28` без состояния, могут вызывать `events/list` для обнаружения событий и их схем полезной нагрузки:

| Событие | Когда отправляется | Фильтр подписки |
|-------|-----------------|---------------------|
| `test_case.marked_flaky` | Тест-кейс меняется с нестабильного на стабильный или наоборот (становится нестабильным). | `account_handle`, `project_handle` |
| `build.failed` | Локальная сборка или сборка в непрерывной интеграции Xcode, Gradle или Bazel завершается с ошибкой. | `account_handle`, `project_handle` |
| `test_run.failed` | Локальный запуск тестов или запуск в непрерывной интеграции завершается с ошибкой, включая объединенный шардированный запуск или прерванный запуск. | `account_handle`, `project_handle` |
| `ci_job.failed` | Задача раннера Tuist завершается с ошибкой. | `account_handle` |

Для подписки клиент вызывает `events/subscribe` с именем события, идентификаторами, указанными выше в `arguments`, и доставкой `webhook`, содержащей URL-адрес обратного вызова `https://` и секрет подписи `whsec_`. События проекта требуют членства в аккаунте и права на чтение соответствующих данных тестов или сборок; события задач раннера требуют членства в аккаунте и права на чтение данных раннера. Подписки можно создавать с помощью заявленных токенов доступа [`auth.md`](https://workos.com/auth-md), заявленных токенов аккаунта и разрешений авторизации браузера; доставка прекращается, когда связанные учетные данные становятся неактивными. Каждый пользователь может иметь до 25 активных подписок. Перед сохранением подписки Tuist отправляет проверочный запрос на обратный вызов. Обратный вызов должен вернуть объект, содержащий то же значение `challenge`. Подписка действует семь дней по умолчанию, может быть обновлена путем повторной подписки и прекращает доставку при удалении доступа или учетных данных пользователя. Необязательный параметр `ttlMs` ограничен диапазоном от одного часа до 30 дней. Tuist повторяет попытки вызова тайм-аута и отменяет подписку после как минимум трех последовательных тайм-аутов в течение пяти минут; подпишитесь снова после восстановления обратного вызова.

При возникновении события Tuist отправляет его идентификатор ресурса и URL-адрес дашборда на обратный вызов. Ошибки сборки и запуска тестов также включают `is_ci` и `git_branch`, поэтому клиенты могут игнорировать локальные ошибки или фильтровать по ветке. События сборки включают `build_system`; события задач раннера включают как `workflow_job_id`, так и `workflow_run_id`. Запрос включает идентификатор подписки и заголовки подписи [Standard Webhooks](https://www.standardwebhooks.com/), чтобы клиент мог проверить источник. Tuist повторяет неудачные доставки, поэтому клиентам следует использовать стабильный `eventId` для отклонения дубликатов. Полезная нагрузка не содержит имен тестов, логов и сообщений об ошибках; клиент может получить эти детали через инструменты, описанные выше, и решить, уведомлять ли команду или начинать отладку. Клиенты могут остановить доставку с помощью `events/unsubscribe`.

Промпты с данными проекта принимают `account_handle` и `project_handle` для ограничения исследования конкретным проектом. Промпты сравнения также принимают аргументы `base` и `head` для указания двух сравниваемых элементов (по ID, URL-адресу дашборда или имени ветки). `ask_tuist` принимает `question` вместо параметров проекта. `integrate_gradle_project` также принимает `features` — список интеграций Gradle через запятую: `remote_cache`, `build_insights`, `test_insights`, `flaky_tests` и `test_sharding`. `integrate_bazel_project` принимает необязательный `server_url` для самостоятельно размещенных или локальных установок. `integrate_xcode_project` принимает `features` с `xcode_cache`, `build_insights`, `test_insights` и `test_sharding`.

#### Возможности промпта интеграции Gradle

Промпт `integrate_gradle_project` и инструмент `get_gradle_integration_guide` документируют полный рабочий процесс настройки. Инструмент также упоминается в инструкциях инициализации сервера, что делает его обнаруживаемым для агентов, которые не перечисляют промпты.

| Возможность | Что настраивает агент |
|---------|---------------------------|
| `remote_cache` | Включает кэш сборки Gradle, настраивает политику загрузки удаленного кэша Tuist и рекомендует загружать данные только с раннеров непрерывной интеграции с локальным доступом только для чтения. |
| `build_insights` | Применяет плагин Tuist Gradle и при необходимости настраивает поведение загрузки аналитики сборки. |
| `test_insights` | Применяет плагин Tuist Gradle, чтобы результаты задач Gradle `Test` автоматически загружались. |
| `flaky_tests` | Помогает настроить обнаружение нестабильных тестов, опциональное использование плагина Gradle Test Retry и конфигурацию карантина тестов. |
| `test_sharding` | Добавляет рабочий процесс непрерывной интеграции для `tuistPrepareTestShards`, генерации матрицы шардов и выполнения тестов на основе `TUIST_SHARD_INDEX`. |

Если `features` опущен, промпт просит агента уточнить, какие интеграции нужны пользователю, или вывести минимально полезный набор из запроса перед редактированием проекта Gradle.

#### Возможности промпта интеграции Xcode

Промпт `integrate_xcode_project` документирует каждую интеграцию Xcode, которую поддерживает Tuist:

| Возможность | Что настраивает агент |
|---------|---------------------------|
| `xcode_cache` | Настраивает `tuist setup cache`, параметры кэша сгенерированного проекта, ручные настройки сборки кэша Xcode и политику загрузки, ограниченную раннерами непрерывной интеграции. |
| `build_insights` | Настраивает `tuist inspect build`, `tuist xcodebuild`, `-resultBundlePath` и опциональные метрики машины через `tuist setup insights`. |
| `test_insights` | Настраивает `tuist inspect test`, пост-действия тестов схемы и генерацию бандла результатов для запусков тестов в непрерывной интеграции. |
| `test_sharding` | Добавляет планирование шардов для Xcode или сгенерированного проекта и рабочий процесс выполнения шардов с `TUIST_SHARD_INDEX`. |

Если `features` опущен, промпт просит агента уточнить, какие интеграции нужны пользователю, или вывести минимально полезный набор из запроса перед редактированием проекта Xcode.
