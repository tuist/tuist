# Протокол Model Context Protocol

[Model Context Protocol (MCP)](https://modelcontextprotocol.io/docs/getting-started/intro) — это открытый стандарт, позволяющий агентам искусственного интеллекта взаимодействовать с внешними сервисами и источниками данных. Он обеспечивает совместимость таких приложений, как [Claude](https://claude.ai/), [Claude Code](https://docs.anthropic.com/en/docs/claude-code), [Codex](https://developers.openai.com/codex/), и редакторов, таких как [Zed](https://zed.dev), [Cursor](https://www.cursor.com) или [Visual Studio Code](https://code.visualstudio.com), с Tuist.

Tuist размещает серверную точку входа Model Context Protocol по адресу `https://tuist.dev/mcp`. Подключив к ней ваш клиент, агенты смогут получать доступ к данным ваших проектов Tuist, включая аналитику тестов, анализ нестабильных тестов и многое другое. Большинство инструментов работают только в режиме чтения и имеют доступ исключительно к данным проектов Tuist после аутентификации. Инструменты настройки аккаунта могут перечислять аккаунты, создавать организации, создавать проекты и добавлять существующих пользователей в организации, если у аутентифицированного пользователя есть необходимые разрешения. Каждый инструмент предоставляет аннотации, указывающие, работает ли он только в режиме чтения, может ли он вызвать изменения, которые трудно отменить, и может ли он изменять состояние публичного интернета. Инструменты настройки аккаунта требуют аутентификации пользователя. Они недоступны для токенов проектов или обычных токенов аккаунтов. Когда пользователь авторизует клиент в браузере или подтверждает регистрацию через `auth.md`, Tuist связывает эти учетные данные с пользователем только в точке входа Model Context Protocol, чтобы инструменты настройки могли завершить запрошенный рабочий процесс.

Tuist реализует [протокол версии 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http). Запросы являются безсостоятельными: клиенты отправляют метаданные протокола с каждым запросом и могут вызывать инструменты напрямую без инициализации. `server/discover` возвращает идентификатор сервера, его возможности, поддерживаемые версии и инструкции. Идентификаторы сессий или независимые потоки событий отсутствуют. Клиенты, использующие поток инициализации версий 2025-06-18 или 2025-03-26, по-прежнему поддерживаются; они также работают без серверных сессий.

## Model Context Protocol против навыков (skills)

Инструменты Model Context Protocol и <.localized_link href="/guides/features/agentic-coding/skills">навыки</.localized_link> могут пересекаться по функциональности. Учитывая текущее перекрытие между ними, выбирайте один подход для каждого рабочего процесса и используйте его последовательно, вместо того чтобы смешивать оба в одном потоке.

Для клиентов, поддерживающих установку плагинов, используйте <.localized_link href="/guides/features/agentic-coding/plugins">плагины Tuist</.localized_link>, чтобы установить их вместе.

## Конфигурация

Добавьте `https://tuist.dev/mcp` в качестве удаленного сервера Model Context Protocol в вашем клиенте. Инструкции по инициализации сервера и публичная карточка сервера описывают OAuth 2.0 с динамической регистрацией клиента и стандартный поток авторизации через браузер непосредственно в тексте, не требуя от агентов загружать или следовать внешним документам аутентификации. Эти общесерверные инструкции сохраняют рекомендации по рабочему процессу общими: аутентификация инструментов не аутентифицирует локальные инструменты командной строки или интеграции с системами сборки, и агенты должны проверять запрашиваемые изменения через соответствующие инструменты Tuist. Настройка и проверки аутентификации, специфичные для системы сборки, документированы в руководствах по интеграции и подсказках. Tuist по-прежнему предоставляет как метаданные обнаружения [Open Authorization](https://oauth.net/2/), так и текущий [протокол auth.md](https://workos.com/auth-md) по адресу `https://tuist.dev/auth.md` отдельно.

Точка входа принимает безсостоятельный жизненный цикл запросов Model Context Protocol версии `2026-07-28`, включая `server/discover`, наряду со старым жизненным циклом на основе сессий. Существующие клиенты могут продолжать использовать свой текущий метод подключения.

Клиенты, поддерживающие события Model Context Protocol, могут подписываться на события проекта. См. раздел [События](#events) для получения информации о доступных событиях и требованиях к доставке.

Клиенты, которые уже поддерживают удаленную аутентификацию через браузер, могут продолжать аутентифицироваться в браузере. Клиенты и агенты, поддерживающие `auth.md`, могут регистрироваться анонимно, предоставлять доверенное утверждение идентичности провайдера или начинать процесс подтверждения электронной почты с аутентификацией сервиса. Регистрация возвращает утверждение идентичности, подписанное Tuist, которое агент обменивает на стандартной конечной точке токенов на часовой токен доступа. Tuist публикует свой открытый ключ подписи и поддерживает стандартное отзывание токенов и доставку событий безопасности от провайдера.

Неаутентифицированный агент должен прочитать заголовок `WWW-Authenticate`, возвращаемый точкой входа Model Context Protocol, получить метаданные защищенного ресурса, получить метаданные сервера авторизации и перейти по URL-адресу `agent_auth.skill`. Tuist также возвращает тот же локальный URL-адрес `auth_md` в теле ответа об отказе в доступе, чтобы клиенты, управляемые языковыми моделями, могли обнаружить этот поток без reliance на нативную интеграцию клиента. Локальный для развертывания документ является источником истины для имен конечных точек, тел запросов, опроса подтверждений и обмена утверждениями.

Прежде чем агент начнет процесс подтверждения электронной почты, он должен попросить пользователя подтвердить адрес электронной почты для своего аккаунта Tuist. Он не должен определять этот адрес из профиля провайдера, конфигурации Git, переменной окружения или метаданных сессии.

Точка входа использует группу областей видимости `mcp`. Анонимные учетные данные до подтверждения могут обнаруживать возможности и читать публичные руководства по интеграции, но они не рассматриваются как вошедшие в систему пользователи. После авторизации через браузер или подтверждения, учетные данные получают область видимости пользователя, и каждый инструмент применяет те же проверки авторизации, что и панель управления. Подробности см. в <.localized_link href="/guides/server/authentication#scope-groups">документации по группам областей видимости</.localized_link>.

Инструменты работают с проектами, к которым у аутентифицированного пользователя уже есть доступ. Инструменты сборки для Xcode и Gradle принимают UUID сборки или URL-адрес дашборда. UUID должен однозначно идентифицировать один проект; если он встречается в нескольких проектах, инструмент возвращает ошибку «не найдено», вместо того чтобы выбирать отчёт другого проекта. Чтение данных через дашборд и API в рамках проекта остаётся доступным. Идентификаторы действующих лиц — это непроверенные метки, а не учётные данные или дополнительные права доступа.

Инструменты списка сборок и детализации предоставляют необязательные метаданные `tuist_version`: CLI Tuist для Xcode и Cargo, плагин Tuist Gradle для Gradle и библиотека `tuist_ex` для Mix. Xcode также предоставляет `tuist_generation_version` из связанного события генерации проекта, которое может отличаться от версии CLI, выполнившего загрузку. Отсутствующие значения равны null и не выводятся из данных сервера или другого отчёта. Bazel использует свой существующий `bazel_version`; детали запуска Once предоставляют `once_version`. Эти поля описывают сообщаемые версии, а не проверенную идентификацию или версии контракта взаимодействия. REST-эндпоинты сборок предоставляют те же метаданные. Существующие интеграции и навыки работы с нестабильными тестами не зависят от полей версий и не требуют изменений в рабочем процессе.

Операторы Tuist, исследующие аккаунт клиента, делают это через внутренние инструменты операций Tuist, которые записывают каждый вызов; прямое подключение к этой точке входа не даёт доступа сверх членства самого пользователя.

Pi не включает клиент Model Context Protocol. Вы можете установить стороннее расширение [`pi-mcp-adapter`](https://pi.dev/packages/pi-mcp-adapter) после изучения его исходного кода и последствий для безопасности:

После этого безголовый агент может прочитать возвращённый URL `auth_md` и следовать процессу регистрации Tuist, обмена утверждением идентичности и опроса подтверждения. Если вы предпочитаете аутентификацию через браузер, установите `auth` в значение `"oauth"`. Для этого потока держите один процесс активным с помощью [режима удалённого вызова процедур](https://pi.dev/docs/latest/rpc) Pi до завершения аутентификации:

```bash
pi --mode rpc
```

Не разделяйте ожидающую аутентификацию браузера между отдельными вызовами `pi --print`, так как процесс, владеющий состоянием обратного вызова, уже завершился.

Метаданные сервера авторизации Tuist указывают непосредственно на собственный `/auth.md` развёртывания, который содержит точные формы запросов и опроса.

## Интеграции систем сборки используют два набора учётных данных

Учётные данные, используемые для инструментов Model Context Protocol, не аутентифицируют плагин Gradle или удалённые сервисы Bazel. Перед тем как агент изменит или проверит интеграцию Gradle или Bazel, он должен выполнить:

```bash
tuist auth whoami --url https://tuist.dev
```

Если эта команда не аутентифицирована, агент должен остановиться и попросить пользователя выполнить:

```bash
tuist auth login --url https://tuist.dev
```

Для локального или самостоятельно размещённого развёртывания замените URL в обеих командах и в `tuist.toml`. Сохраняйте одинаковое написание имени хоста везде. Например, `localhost` и `127.0.0.1` используют отдельные сохранённые учётные данные.


## Возможности

### Инструменты

Следующие инструменты доступны через сервер Tuist Model Context Protocol:

Каждый инструмент публикует понятное человеку описание вместе с явными схемами ввода и вывода. Успешные вызовы возвращают структурированный контент, соответствующий заявленной схеме вывода, а также тот же результат, сериализованный в виде текста для клиентов, которые ещё не потребляют структурированный контент.

Инструменты, принимающие идентификатор одной записи, такой как `build_run_id`, `test_run_id`, `test_case_id`, `bundle_id`, `run_id`, `generation_id` или `cache_run_id`, также принимают URL-адрес этой записи из панели управления Tuist. Вставьте URL прямо из браузера вместо того, чтобы извлекать из него идентификатор.

#### Поиск по документации и сообществу

Этот инструмент только для чтения выполняет поиск по документации Tuist, справочнику [прикладного программного интерфейса](https://en.wikipedia.org/wiki/API), релизам на GitHub, форуму сообщества и задачам на GitHub через тот же поисковый движок, который работает на сайте документации. Результаты поиска по релизам включают продукт, версию, дату публикации и статус предварительной версии. По умолчанию выполняется поиск по стабильным релизам, предварительные релизы можно включить с помощью `include_prereleases`. Инструмент доступен только на сервере, размещённом Tuist, по адресу `https://tuist.dev/mcp`.

| Инструмент | Описание | Обязательные параметры |
|------|-------------|---------------------|
| `search_tuist` | Поиск по публичной документации Tuist, справочнику прикладного программного интерфейса, релизам на GitHub, обсуждениям в сообществе и задачам на GitHub. При необходимости ограничьте поиск одним `source` (`docs`, `api_reference`, `releases`, `forum`, `issues`). | `query` |

#### Обратная связь

Агенты могут сообщить команде Tuist, если инструмент или подсказка Tuist не сработали так, как они ожидали, например, выдали непонятный результат, ошибку, отсутствующие данные или недостающую возможность. Агентам предлагается предложить отчёт и отправить его только после вашего согласия. Каждый отчёт открывает диалог со службой поддержки Tuist, которая может ответить вам по электронной почте. Отчёт включает то, что ожидал агент, что произошло, необязательное предложение, ваш идентификатор пользователя Tuist, имя пользователя и электронную почту, а также организации, к которым вы принадлежите. Агенты также могут указать аккаунт и проект, в которых возникла проблема, чтобы команда знала, с какой организацией связаться; принимаются только аккаунты, к которым вы имеете доступ. Отчёты могут отправлять только агенты, вошедшие в систему как пользователь Tuist, и каждый пользователь может открывать до 10 отчётов в час. Инструмент доступен только на сервере, размещённом Tuist, по адресу `https://tuist.dev/mcp`.

| Инструмент | Описание | Обязательные параметры |
|------|-------------|---------------------|
| `report_feedback` | Сообщить о проблеме с инструментом или подсказкой Tuist. При необходимости укажите `tool_name`, `account_handle` и `project_handle`, в которых это произошло, и добавьте `suggestion`. | `category`, `expected`, `actual` |

#### Ответы на основе исходного кода

Эти инструменты только для чтения позволяют агентам использовать точную публичную ревизию исходного кода Tuist, развёрнутую вместе с размещённым сервером, в качестве источника истины для ответов, зависящих от текущего поведения. Они доступны только по адресу `https://tuist.dev/mcp`.

Совместимые клиенты получают фактические описания ревизии исходного кода инструментов, ссылки и ограничения результатов во время инициализации вместе с информацией об аутентификации OAuth. Эти описания не предписывают стиль ответа или рабочий процесс проверки. Пользователи могут задать вопрос напрямую, не вызывая сначала подсказку `ask_tuist`; подсказка остаётся доступной для явного рабочего процесса на основе исходного кода.

Каждая операция имеет фиксированные ограничения на параллелизм, длительность, обход, количество прочитанных байтов и размер ответа. #### Сборки Xcode

Инструменты детализации сборок для Xcode, Gradle, Bazel, Mix и Cargo предоставляют существующую структуру `custom_metadata: {tags, values}`, включая данные об инфраструктуре, если они сообщаются. Значения остаются строками, а неизвестные ключи сохраняются. Например, `tuist.cpu.available_processors` описывает доступные во время выполнения логические процессоры, тогда как `tuist.gradle.max_workers` — это ограничение на количество рабочих процессов Gradle, а `tuist.jvm.max_heap_bytes` — ограничение кучи JVM, а не объем памяти хоста. Это ненадежные наблюдения клиента, а не проверенные идентификаторы раннеров. Отсутствующие наблюдения остаются отсутствующими; импортированные логи и старые клиенты могут не иметь метаданных инфраструктуры. Обновление метаданных ожидает согласованного обновления клиента/протокола.

| Инструмент | Описание | Обязательные параметры |

| `get_xcode_build` | Получить подробную информацию о конкретном запуске сборки Xcode, включая временный URL-адрес для скачивания архива с исходным файлом `.xcactivitylog`. | `build_run_id` |
| `list_xcode_build_targets` | Список целей сборки для конкретного запуска сборки Xcode. | `build_run_id` |
| `list_xcode_build_files` | Список скомпилированных файлов для конкретного запуска сборки Xcode. | `build_run_id` |
| `list_xcode_build_steps` | Список записанных шагов сборки с указанием времени и результатов, без текста логов. | `build_run_id` |

`list_xcode_build_steps` по умолчанию возвращает страницы по 20 шагов (максимум 100 через `page_size`), с параметрами `page` и `pagination_metadata` для навигации. Используйте `search` для поиска по заголовкам, проектам или целям, либо фильтруйте по точному совпадению `project`, `target`, `category` (например, `swiftCompilation`) и `status` (`success` или `failure`). Сортируйте по `duration_ms` для отображения самых медленных сначала (по умолчанию) или по `start_ms` для хронологического порядка. ID шагов используются для разрешения ничьих и возвращаются в виде десятичных строк для сохранения полной 64-битной точности. ID привязаны к сборке и не должны сопоставляться между разными сборками.

Необязательные параметры `start_ms` и `end_ms` выбирают шаги, попадающие в диапазон времени в миллисекундах от начала сборки; конец диапазона исключается. Оба инструмента принимают UUID сборки или URL панели управления в качестве `build_run_id`. Передайте полученный `id` шага без изменений в качестве `step_id` для получения его лога. Логи хранят до 64 КиБ на шаг, при этом `log_truncated` указывает на усеченный вывод.

Шаги собираются по умолчанию при обработке сборок Xcode. Записанные данные шагов хранятся 90 дней. Ответ списка включает поле `availability`: `available`, если записанные шаги существуют, даже если фильтры ничего не находят; `processing`, если сборка еще обрабатывается и шагов пока нет; или `unavailable`, если шаги не были записаны или срок их хранения истек.

Те же операции доступны через HTTP API по адресам `GET /api/projects/{account_handle}/{project_handle}/xcode/builds/{build_id}/steps` и `GET /api/projects/{account_handle}/{project_handle}/xcode/builds/{build_id}/steps/{step_id}`, с теми же фильтрами и пагинацией. Для обоих требуется доступ на чтение к проекту сборки.

Списки шагов Gradle и Bazel по умолчанию возвращают 20 результатов (максимум 100), поддерживают `search`, точное совпадение `project`, `target`, `category` и `status`, фильтры по пересекающимся интервалам `start_ms` / `end_ms` (конец исключается) и сортировку по `duration_ms` или `start_ms`. ID шагов Bazel, возвращаемые из сохраненных сводок, остаются читаемыми, если полный профиль поступает в промежуток между получением списка и запросом шага. Индексированный профиль, данные шагов которого истекли, сообщает о недоступности. Списки шагов Gradle включают кэшированные и пропущенные операции с нулевой длительностью.

#### Задачи, действия, модули и файлы

Эти инструменты, работающие в контексте проекта, исследуют постоянные идентификаторы сборок across запусков. Начните с `list_build_entities`, затем передайте полученный стабильный `id` с тем же `kind` в `get_build_entity` или `list_build_entity_history` вместе с `account_handle` и `project_handle`. Идентификатор сборки или вызова не требуется.

| Инструмент | Описание | Обязательные параметры |
| --- | --- | --- |
| `list_build_entities` | Список задач, модулей, действий или файлов одного типа, обнаруженных в сборках проекта. | `account_handle`, `project_handle`, `kind` |
| `get_build_entity` | Получить одну сущность сборки с её нативным идентификатором и аналитикой за выбранный период. | `account_handle`, `project_handle`, `kind`, `id` |
| `list_build_entity_history` | Список записанных выполнений, компиляций или событий кэша для одной сущности сборки, от новых к старым. | `account_handle`, `project_handle`, `kind`, `id` |

| `kind` | Инструментарий | Списки истории |
| --- | --- | --- |
| `bazel_actions` | Действия Bazel | Выполнения действий, сообщённые через BEP |
| `gradle_tasks` | Задачи Gradle | Выполнения задач |
| `xcode_modules` | Модули Xcode | Компиляции и события кэша модулей |
| `once_actions` | Действия Once | Выполнения |
| `mix_files` | Скомпилированные файлы Mix | Компиляции |
| `mix_modules` | Скомпилированные модули Mix | Компиляции |
| `cargo_crates` | Крейты Cargo | Записанные вызовы rustc |

Эти инструменты внедряются постепенно и возвращают данные только для проектов, где они включены; для остальных проектов возвращается ошибка вместо пустого результата. Тип доступен только для проектов, использующих соответствующий инструментарий сборки. Инструменты принимают ограниченные фильтры `start_at`/`end_at`, `environment` (`any`, `ci` или `local`) и точный `branch`. `list_build_entities` принимает `q`; `list_build_entity_history` поддерживает непрозрачные курсоры `after`/`before`. Неизвестные наблюдения времени или кэша остаются недоступными, а не превращаются в нули или промахи. История ссылается на записанного родителя и нативное выполнение для детализации с использованием существующих инструментов запусков.

Метрики `get_build_entity` включают `duration_samples` — количество наблюдений с записанным временем: подлинные нулевые длительности учитываются, отсутствующее время — нет. Это количество может быть меньше количества наблюдений; недоступная статистика длительности остаётся null.

Длительности модулей Xcode получены из измеренных компиляций целей в логах сборки. Разрешения кэша модулей и цели без работы по компиляции не вносят вклад в выборки длительности. Наблюдения компиляции ссылается на сборку Xcode; события кэша — на команду генерации или кэша.

Действия Bazel идентифицируются по метке цели, мнемонике и настроенному первичному выводу, сохраняя раздельные действия и конфигурации различными без опоры на зависящие от ввода дайджесты кэша. История записывает выполнения, сообщённые через BEP, а не поиски в кэше или фазы трассировки. Полное покрытие выполнения требует `--build_event_publish_all_actions`; доставка артефактов выполняется по принципу best effort, поэтому отсутствующие наблюдения не являются доказательством того, что работа не выполнялась. Старые payloads Kura без стабильной идентичности или начала выполнения всё ещё принимаются, но не индексируются. Отсутствующие измерения времени окончания остаются недоступными, а подлинные нулевые длительности учитываются.

Длительности модулей Mix измеряют компиляцию содержащего файла, а не независимо измеренную работу модуля. Действия Once используют объявленные слоты target/capability/index, когда клиент сообщил сопоставления целей; одни лишь диагностические метки не являются стабильными идентификаторами. Существующие клиенты и инструменты уровня запуска поддерживаются без изменений.

Крейты Cargo группируются по точно записанному корню крейта, имени и типу. Изменения пути checkout могут разделять истории, а профили сборки, возможности и тройки целей не различаются. История измеряет вызовы rustc, а не работу по файлам или попадания в кэш; отсутствующие задания не устанавливают удаления или полную инвентаризацию рабочего пространства.

Чтения аналитики имеют ограниченное потребление памяти и времени выполнения. Если запрос превышает эти лимиты, инструмент возвращает ошибку вместо создания пустого результата.

Новые наблюдения индексируются после развертывания; эта функция не заполняет ретроспективно существующую телеметрию запусков. Метаданные идентичности хранятся дольше отдельных наблюдений в соответствии с <.localized_link href="/guides/server/data-retention">политикой хранения данных</.localized_link>.

### События

Клиенты, использующие жизненный цикл Model Context Protocol без сохранения состояния `2026-07-28`, могут вызывать `events/list` для обнаружения событий и их схем полезной нагрузки:

| Событие | Когда отправляется | Фильтр подписки |
|-------|-----------------|---------------------|
| `test_case.marked_flaky` | Тест-кейс меняется с нестабильного на стабильный или наоборот. | `account_handle`, `project_handle` |
| `build.failed` | Локальная сборка или сборка в системе непрерывной интеграции Xcode, Gradle или Bazel завершается с ошибкой. | `account_handle`, `project_handle` |
| `test_run.failed` | Локальный запуск тестов или запуск тестов в системе непрерывной интеграции завершается с ошибкой, включая объединенный шардированный запуск или заброшенный запуск. | `account_handle`, `project_handle` |
| `ci_job.failed` | Задача раннера Tuist завершается с ошибкой. | `account_handle` |

Для подписки клиент вызывает `events/subscribe` с именем события, хэндлами, указанными выше в `arguments`, и доставкой `webhook`, содержащей URL обратного вызова `https://` и секрет подписи `whsec_`. События проекта требуют членства в аккаунте и доступа на чтение к соответствующим данным тестов или сборок; события задач раннера требуют членства в аккаунте и доступа на чтение к раннеру. Заявленные токены доступа [`auth.md`](https://workos.com/auth-md), заявленные токены аккаунта и гранты авторизации браузера могут создавать подписки; доставка останавливается, когда связанные учетные данные больше не активны. Каждый пользователь может иметь до 25 активных подписок. Tuist отправляет проверочный запрос на обратный вызов перед сохранением подписки. Обратный вызов должен вернуть объект, содержащий то же значение `challenge`. Подписка действует семь дней по умолчанию, может быть обновлена путем повторной подписки и прекращает доставку при удалении доступа или учетных данных пользователя. Необязательный параметр `ttlMs` ограничен диапазоном от одного часа до 30 дней. Tuist повторяет попытки вызова тайм-аута и отменяет подписку после как минимум трех последовательных тайм-аутов в течение пяти минут; подпишитесь снова после восстановления обратного вызова.

При возникновении события Tuist отправляет его идентификатор ресурса и URL дашборда на обратный вызов. Ошибки сборки и запуска тестов также включают `is_ci` и `git_branch`, поэтому клиенты могут игнорировать локальные ошибки или фильтровать по ветке. События сборки включают `build_system`; события задач раннера включают как `workflow_job_id`, так и `workflow_run_id`. Запрос включает идентификатор подписки и заголовки подписи [Standard Webhooks](https://www.standardwebhooks.com/), чтобы клиент мог проверить его происхождение. Tuist повторяет неудачные доставки, поэтому клиентам следует использовать стабильный `eventId` для отбрасывания дубликатов. Полезная нагрузка не содержит имен тестов, логов и сообщений об ошибках; клиент может получить эти детали через инструменты выше и решить, уведомлять ли команду или начать отладку. Клиенты могут остановить доставку с помощью `events/unsubscribe`.

### Подсказки

| Подсказка | Описание |
|--------|-------------|
| `fix_flaky_test` | Направляет вас через процесс исправления нестабильного теста, анализируя шаблоны сбоев, выявляя первопричину и применяя целенаправленное исправление. |
| `compare_builds` | Направляет вас через процесс сравнения сборок для выявления регрессий производительности, изменений кэша и проблем сборки. Использует нативные инструменты для проектов Xcode, Gradle, Bazel и Cargo. Сравнения Cargo сохраняют частичное покрытие компилятора и различают оценочную работу компилятора от сэкономленного времени. |
| `compare_test_runs` | Направляет вас через процесс сравнения двух запусков тестов для выявления регрессий, новых сбоев и нестабильных тестов. |
| `compare_bundles` | Направляет вас через процесс сравнения двух бандлов для выявления изменений размера по всему дереву артефактов. |
| `compare_test_case` | Направляет вас через процесс сравнения поведения тест-кейса в двух ветках или временных периодах. |
| `compare_generations` | Направляет вас через процесс сравнения двух запусков генераций для выявления регрессий производительности и изменений кэша модулей. |
| `compare_cache_runs` | Направляет вас через процесс сравнения двух запусков кэша для выявления изменений эффективности кэша и регрессий на уровне целей. |
| `integrate_gradle_project` | Направляет вас через процесс интеграции Tuist в существующий проект Gradle. Включает отдельную аутентификацию инструмента и Gradle, обнаружение аккаунта, создание проекта, политику удаленного кэша, аналитику сборки и проверку считыванием. |
| `integrate_bazel_project` | Направляет вас через процесс создания или выбора проекта Bazel, аутентификации командной строки, настройки удаленного кэша и аналитики сборки, а также проверки интеграции через данные сборки Tuist. |
| `integrate_xcode_project` | Направляет вас через процесс интеграции Tuist в существующий проект Xcode. Поддерживает кэш Xcode, аналитику сборки, аналитику тестов и шардирование тестов. |
| `ask_tuist` | Отвечает на вопрос о Tuist, используя общедоступные материалы для контекста и сфокусированные доказательства реализации и тестирования как источник истины для текущего поведения. Требуется `question` и ссылается на доказательства, привязанные к ревизии. |

Подсказки с данными проекта принимают `account_handle` и `project_handle` для ограничения исследования конкретным проектом. Подсказки сравнения также принимают аргументы `base` и `head` для указания двух сравниваемых элементов (по ID, URL дашборда или имени ветки). `ask_tuist` принимает `question` вместо параметров проекта. `integrate_gradle_project` также принимает `features`, список интеграций Gradle через запятую: `remote_cache`, `build_insights`, `test_insights`, `flaky_tests` и `test_sharding`. `integrate_bazel_project` принимает необязательный `server_url` для самостоятельного размещения или локальных установок. `integrate_xcode_project` принимает `features` с `xcode_cache`, `build_insights`, `test_insights` и `test_sharding`.

#### Возможности подсказки интеграции Gradle

Подсказка `integrate_gradle_project` и инструмент `get_gradle_integration_guide` документируют полный рабочий процесс настройки. Инструмент также упоминается в инструкциях инициализации сервера, что делает его обнаруживаемым агентами, которые не перечисляют подсказки.

| Возможность | Что настраивает агент |
|---------|---------------------------|
| `remote_cache` | Включает кэш сборки Gradle, настраивает политику загрузки удаленного кэша Tuist и рекомендует загружать только с раннеров непрерывной интеграции с локальным доступом только для чтения. |
| `build_insights` | Применяет плагин Tuist Gradle и при необходимости настраивает поведение загрузки аналитики сборки. |
| `test_insights` | Применяет плагин Tuist Gradle, чтобы результаты задачи Gradle `Test` автоматически загружались. |
| `flaky_tests` | Руководит настройкой обнаружения нестабильных тестов, опционального использования плагина Gradle Test Retry и конфигурации карантина тестов. |
| `test_sharding` | Добавляет рабочий процесс непрерывной интеграции для `tuistPrepareTestShards`, генерации матрицы шардов и выполнения тестов на основе `TUIST_SHARD_INDEX`. |

Когда `features` пропущен, подсказка просит агента уточнить, какие интеграции хочет пользователь, или определить минимально полезный набор из запроса перед редактированием проекта Gradle.

#### Возможности подсказки интеграции Xcode

Подсказка `integrate_xcode_project` документирует все интеграции с Xcode, которые поддерживает Tuist:

| Возможность | Что настраивает агент |
|---------|---------------------------|
| `xcode_cache` | Настраивает `tuist setup cache`, параметры кэша сгенерированного проекта, ручные настройки сборки кэша Xcode и политику загрузки, ограниченную раннерами непрерывной интеграции. |
| `build_insights` | Настраивает `tuist inspect build`, `tuist xcodebuild`, `-resultBundlePath` и опциональные метрики машины через `tuist setup insights`. |
| `test_insights` | Настраивает `tuist inspect test`, пост-действия тестирования схем и генерацию бандлов результатов для запусков тестов в непрерывной интеграции. |
| `test_sharding` | Добавляет рабочий процесс планирования шардов для Xcode или сгенерированного проекта и выполнения шардов с `TUIST_SHARD_INDEX`. |

Если `features` не указан, подсказка просит агента уточнить, какие интеграции нужны пользователю, или вывести минимально полезный набор из запроса перед редактированием проекта Xcode.
