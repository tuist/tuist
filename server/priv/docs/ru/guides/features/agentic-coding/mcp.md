# Model Context Protocol

[Model Context Protocol (MCP)](https://modelcontextprotocol.io/docs/getting-started/intro) — это открытый стандарт, позволяющий агентам искусственного интеллекта взаимодействовать с внешними сервисами и источниками данных. Он обеспечивает совместимость таких приложений, как [Claude](https://claude.ai/), [Claude Code](https://docs.anthropic.com/en/docs/claude-code), [Codex](https://developers.openai.com/codex/), и редакторов, таких как [Zed](https://zed.dev), [Cursor](https://www.cursor.com) или [Visual Studio Code](https://code.visualstudio.com), с Tuist.

Tuist размещает серверную точку входа Model Context Protocol по адресу `https://tuist.dev/mcp`. Подключив к ней свой клиент, агенты смогут получать доступ к данным вашего проекта Tuist, включая аналитику тестов, анализ нестабильных тестов и многое другое. Большинство инструментов работают только в режиме чтения и ограничены данными проектов Tuist, прошедших аутентификацию. Инструменты настройки аккаунта могут перечислять аккаунты, создавать организации, создавать проекты и добавлять существующих пользователей в организации, если у аутентифицированного пользователя есть необходимые права. Каждый инструмент предоставляет аннотации, указывающие, работает ли он только в режиме чтения, может ли он вызвать изменения, которые трудно отменить, и может ли он изменить состояние в публичном интернете. Инструменты настройки аккаунта требуют аутентификации пользователя. Они недоступны для токенов проектов или обычных токенов аккаунтов. Когда пользователь авторизует клиент в браузере или подтверждает регистрацию `auth.md`, Tuist связывает эти учетные данные с пользователем только на точке входа Model Context Protocol, чтобы инструменты настройки могли завершить запрошенный рабочий процесс.

Tuist реализует [протокол версии 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http). Запросы не имеют состояния: клиенты отправляют метаданные протокола с каждым запросом и могут вызывать инструменты напрямую без инициализации. `server/discover` возвращает идентификатор сервера, возможности, поддерживаемые версии и инструкции. Идентификаторы сессий или независимые потоки событий отсутствуют. Клиенты, использующие поток инициализации версий 2025-06-18 или 2025-03-26, по-прежнему поддерживаются; они также работают без серверных сессий.

## Model Context Protocol против навыков

Функциональность инструментов Model Context Protocol и <.localized_link href="/guides/features/agentic-coding/skills">навыков</.localized_link> может пересекаться. Учитывая текущее перекрытие между ними, выбирайте один подход для каждого рабочего процесса и используйте его последовательно, вместо того чтобы смешивать оба в одном потоке.

Для клиентов, поддерживающих установку плагинов, используйте <.localized_link href="/guides/features/agentic-coding/plugins">плагины Tuist</.localized_link> для одновременной установки обоих компонентов.

## Конфигурация

Добавьте `https://tuist.dev/mcp` как удаленный сервер Model Context Protocol в вашем клиенте. Инструкции по инициализации сервера и публичная карточка сервера описывают OAuth 2.0 с динамической регистрацией клиента и стандартный поток авторизации через браузер непосредственно в тексте, не требуя от агентов загружать или следовать внешним документам аутентификации. Эти общесерверные инструкции сохраняют общие рекомендации по рабочему процессу: аутентификация инструментов не аутентифицирует локальные инструменты командной строки или интеграции со системами сборки, и агенты должны проверять запрашиваемые изменения через соответствующие инструменты Tuist. Настройка и проверки аутентификации, специфичные для системы сборки, документированы в руководствах по интеграции и подсказках. Tuist по-прежнему отдельно предоставляет метаданные обнаружения [Open Authorization](https://oauth.net/2/) и текущий [протокол auth.md](https://workos.com/auth-md) по адресу `https://tuist.dev/auth.md`.

Если одна из ваших организаций требует единого входа (SSO), авторизация клиента в браузере требует сессии, выполненной через эту организацию, и при необходимости Tuist сначала перенаправляет вас к провайдеру. См. <.localized_link href="/guides/integrations/authentication/sso#choose-an-enrollment-policy">единый вход</.localized_link>.

Точка входа принимает жизненный цикл запросов Model Context Protocol без состояния `2026-07-28`, включая `server/discover`, наряду со старым жизненным циклом на основе сессий. Существующие клиенты могут продолжать использовать свой текущий метод подключения.

Клиенты, поддерживающие события Model Context Protocol, могут подписываться на события проекта. См. раздел [События](#events) для получения информации о доступных событиях и требованиях к доставке.

Клиенты, которые уже поддерживают удаленную аутентификацию через браузер, могут продолжать аутентифицироваться в браузере. Клиенты и агенты, поддерживающие `auth.md`, могут регистрироваться анонимно, предоставлять доверенное утверждение идентичности провайдера или начинать запрос на подтверждение электронной почты с аутентификацией сервиса. Регистрация возвращает утверждение идентичности, подписанное Tuist, которое агент обменивает на стандартной конечной точке токенов на токен доступа сроком на один час. Tuist публикует свой публичный ключ подписи и поддерживает стандартное отзывание токенов и доставку событий безопасности от провайдера.

Неаутентифицированный агент должен прочитать заголовок `WWW-Authenticate`, возвращаемый точкой входа Model Context Protocol, получить метаданные защищенного ресурса, получить метаданные сервера авторизации и перейти по его URL `agent_auth.skill`. Tuist также возвращает тот же локальный URL `auth_md` в теле ответа об отсутствии авторизации, чтобы клиенты, управляемые языковыми моделями, могли обнаружить этот поток без reliance на нативную интеграцию клиента. Локальный для развертывания документ является источником истины для имен конечных точек, тел запросов, опроса подтверждений и обмена утверждениями.

Прежде чем агент начнет запрос на подтверждение электронной почты, он должен попросить пользователя подтвердить адрес электронной почты для его аккаунта Tuist. Он не должен выводить этот адрес из профиля провайдера, конфигурации Git, переменной окружения или метаданных сессии.

Точка входа использует группу областей видимости `mcp`. Анонимные учетные данные до подтверждения могут обнаруживать возможности и читать публичные руководства по интеграции, но они не рассматриваются как вошедший в систему пользователь. После авторизации в браузере или подтверждения, учетные данные получают область видимости пользователя, и каждый инструмент применяет те же проверки авторизации, что и панель управления. Подробности см. в <.localized_link href="/guides/server/authentication#scope-groups">документации по группам областей видимости</.localized_link>.

Инструменты разрешаются к проектам, которые аутентифицированный пользователь уже может читать. Инструменты сборки Xcode и Gradle принимают UUID сборки или URL панели управления. UUID должен идентифицировать ровно один проект; если он встречается в нескольких проектах, инструмент возвращает «не найдено» вместо выбора отчета другого проекта. Чтения панели управления и API в рамках проекта остаются доступными. Сообщаемые идентификаторы действующих лиц являются непроверенными метками, а не учетными данными или дополнительными правами доступа.

Инструменты списка сборок и детальной информации предоставляют дополнительные метаданные `tuist_version`: версию CLI Tuist для Xcode и Cargo, плагин Tuist Gradle для Gradle и библиотеку `tuist_ex` для Mix. Xcode также предоставляет `tuist_generation_version` из связанного события генерации проекта, которое может отличаться от версии загружающего CLI. Отсутствующие значения равны null, а не выводятся из сервера или другого отчета. Bazel использует существующий `bazel_version`; детали запуска Once предоставляют `once_version`. Эти поля описывают сообщаемые версии, а не проверенную идентификацию или версии сетевого протокола. Конечные точки REST API для сборок предоставляют те же метаданные. Существующие интеграции и навыки работы с нестабильными тестами не зависят от полей версий и не требуют изменений в рабочих процессах.

Операторы Tuist, исследующие аккаунт клиента, делают это через внутренние операционные инструменты Tuist, которые записывают каждый вызов; прямое подключение к этой конечной точке не дает доступа beyond членства самого пользователя.

<summary>Pi</summary>

Pi не включает клиент Model Context Protocol. Вы можете установить стороннее расширение [`pi-mcp-adapter`](https://pi.dev/packages/pi-mcp-adapter) после изучения его исходного кода и последствий для безопасности:

Добавьте файл `.mcp.json` на уровне проекта:

```json
{

    }
  }
}
```

Установка `auth` в значение `false` предотвращает скрытие неавторизованного ответа Tuist обработчиком аутентификации браузера адаптера. Безголовый агент сможет прочитать возвращенный URL `auth_md` и следовать процессу регистрации Tuist, обмена утверждениями идентичности и опроса заявок. Настройте полученный токен доступа как bearer-токен или позвольте агенту выполнять аутентифицированные вызовы Model Context Protocol напрямую.

Если вы предпочитаете аутентификацию через браузер, установите `auth` в значение `"oauth"`. Для этого потока держите один процесс активным с использованием [remote procedure call mode](https://pi.dev/docs/latest/rpc) Pi, пока аутентификация не завершится:

```bash
pi --mode rpc
```

Не разделяйте ожидающую аутентификацию в браузере между отдельными вызовами `pi --print`, так как процесс, владеющий состоянием обратного вызова, уже завершился.

Метаданные сервера авторизации Tuist указывают непосредственно на собственный `/auth.md` развертывания, который содержит точные форматы запросов и опроса.

## WebMCP

В браузерах, поддерживающих [WebMCP](https://webmachinelearning.github.io/webmcp), страницы Tuist регистрируют инструменты через `document.modelContext`, поэтому агенты, встроенные в браузер, могут вызывать их без дополнительной настройки. Вызовы выполняются на сервере Tuist.

- **Страницы веб-сайта и документации** регистрируют инструменты документации и исходного кода (`search_tuist`, `search_tuist_code`, `list_tuist_files` и `read_tuist_file`). Вход в систему не требуется.
- **Страницы панели управления аккаунта**, когда вы вошли в систему, регистрируют инструменты Tuist только для чтения для этого аккаунта. Каждая страница регистрирует только инструменты для того, что она отображает, для системы сборки проекта: страница сборок проекта Gradle получает инструменты сборки Gradle, страницы тестов — инструменты тестирования и покрытия, а страницы раннеров — инструменты раннеров. Страница настроек подписок на ИИ вашего личного аккаунта получает `list_ai_subscriptions`, который отвечает только для вашего собственного аккаунта. Каждая страница также получает инструменты документации, `list_projects` и `get_project`. Инструменты выполняются от имени вошедшего пользователя, поэтому они имеют доступ только к данным, которые вы можете читать в панели управления, и только к тому аккаунту, который вы просматриваете. При переходе на другую страницу или аккаунт инструменты заменяются инструментами этой страницы.

Инструменты, создающие, изменяющие или удаляющие данные, недоступны через WebMCP, поскольку браузерный агент получает инструменты без вашего добавления и читает контент, создаваемый сборками и тестами. Подключите клиент MCP к конечной точке `/mcp`, чтобы использовать эти инструменты.

Если организация требует единый вход, войдите в панель управления через её провайдера, чтобы использовать её инструменты.

## Интеграции с системами сборки используют два набора учетных данных

Учетные данные, используемые для инструментов Model Context Protocol, не аутентифицируют плагин Gradle или удаленные сервисы Bazel. Прежде чем агент изменит или проверит интеграцию с Gradle или Bazel, он должен выполнить:

```bash
tuist auth whoami --url https://tuist.dev
```

Если эта команда не прошла аутентификацию, агент должен остановиться и попросить пользователя выполнить:

```bash
tuist auth login --url https://tuist.dev
```

Для локального или самостоятельно размещенного развертывания замените URL-адрес в обеих командах и в `tuist.toml`. Сохраняйте написание хоста идентичным везде. Например, `localhost` и `127.0.0.1` используют отдельные сохраненные учетные данные.


## Возможности

### Инструменты

Следующие инструменты доступны через сервер Tuist Model Context Protocol:

Каждый инструмент публикует понятное человеку описание вместе с явными схемами ввода и вывода. Успешные вызовы возвращают структурированный контент, соответствующий заявленной схеме вывода, а также тот же результат, сериализованный в виде текста для клиентов, которые еще не потребляют структурированный контент.

Инструменты, принимающие идентификатор одной записи, такие как `build_run_id`, `test_run_id`, `test_case_id`, `bundle_id`, `run_id`, `generation_id` или `cache_run_id`, также принимают URL-адрес панели управления Tuist для этой записи. Вставьте URL-адрес прямо из браузера вместо того, чтобы извлекать из него идентификатор.

#### Поиск по документации и сообществу

Этот инструмент только для чтения выполняет поиск в документации Tuist, справочнике [программного интерфейса приложения](https://en.wikipedia.org/wiki/API), релизах GitHub, форуме сообщества и задачах GitHub через тот же поисковый движок, который работает на сайте документации. Результаты поиска по релизам включают продукт, версию, дату публикации и статус предварительного релиза. По умолчанию поиск выполняется по стабильным релизам, предварительные релизы можно включить с помощью `include_prereleases`. Инструмент доступен только на сервере, размещенном Tuist, по адресу `https://tuist.dev/mcp`.

| Инструмент | Описание | Обязательные параметры |
|------|-------------|---------------------|
| `search_tuist` | Поиск в публичной документации Tuist, справочнике программного интерфейса приложения, релизах GitHub, обсуждениях сообщества и задачах GitHub. При необходимости ограничьте поиск одним `source` (`docs`, `api_reference`, `releases`, `forum`, `issues`). | `query` |

#### Обратная связь

Агенты могут сообщить команде Tuist, если инструмент или подсказка Tuist работали не так, как ожидалось, например, выдали непонятный результат, ошибку, недостающие данные или отсутствующую возможность. Агентам предлагается предложить отчет и отправить его только после вашего согласия. Каждый отчет открывает диалог с поддержкой Tuist, которая может ответить вам по электронной почте. Отчет включает то, что ожидал агент, что произошло, необязательное предложение, ваш идентификатор пользователя Tuist, имя пользователя и электронную почту, а также организации, к которым вы принадлежите. Агенты также могут указать аккаунт и проект, в которых возникла проблема, чтобы команда знала, с какой организацией связаться; принимаются только аккаунты, к которым вы имеете доступ. Отчеты могут отправлять только агенты, вошедшие в систему как пользователь Tuist, и каждый пользователь может открыть до 10 отчетов в час. Инструмент доступен только на сервере, размещенном Tuist, по адресу `https://tuist.dev/mcp`.

| Инструмент | Описание | Обязательные параметры |
|------|-------------|---------------------|
| `report_feedback` | Сообщить о проблеме с инструментом или подсказкой Tuist. При необходимости укажите `tool_name`, `account_handle` и `project_handle`, в которых это произошло, и добавьте `suggestion`. | `category`, `expected`, `actual` |

#### Ответы на основе исходного кода

Эти инструменты только для чтения позволяют агентам использовать точную публичную ревизию исходного кода Tuist, развернутую вместе с размещенным сервером, в качестве источника истины для ответов, зависящих от текущего поведения. Они доступны только по адресу `https://tuist.dev/mcp`.

Совместимые клиенты получают фактические описания ревизии исходного кода инструментов, ссылки и ограничения результатов во время инициализации, вместе с информацией об аутентификации OAuth в строке. Эти описания не предписывают стиль ответа или рабочий процесс проверки. Пользователи могут задать вопрос напрямую, не вызывая сначала подсказку `ask_tuist`; подсказка остается доступной для явного рабочего процесса на основе исходного кода.

Каждая операция имеет фиксированные ограничения на параллелизм, длительность, обход, количество прочитанных байтов и размер ответа. #### Сборки Xcode

Инструменты детализации сборок для Xcode, Gradle, Bazel, Mix и Cargo предоставляют существующую структуру `custom_metadata: {tags, values}`, включая наблюдения за инфраструктурой, если они сообщаются. Значения остаются строками, а неизвестные ключи сохраняются. Например, `tuist.cpu.available_processors` описывает логические процессоры, доступные во время выполнения, тогда как `tuist.gradle.max_workers` — это лимит рабочих процессов Gradle, а `tuist.jvm.max_heap_bytes` — лимит кучи JVM, а не память хоста. Это ненадежные наблюдения клиента, а не проверенные идентификаторы раннеров. Отсутствующие наблюдения остаются отсутствующими; импортированные журналы и старые клиенты могут не иметь метаданных инфраструктуры. Обновление метаданных ожидает согласованного обновления клиента/протокола.

| Инструмент | Описание | Обязательные параметры |

| `list_xcode_build_targets` | Перечислите цели сборки для конкретного запуска сборки Xcode. | `build_run_id` |
| `list_xcode_build_files` | Перечислите скомпилированные файлы для конкретного запуска сборки Xcode. | `build_run_id` |

`list_xcode_build_steps` по умолчанию возвращает страницы по 20 шагов (максимум 100 через `page_size`), с `page` и `pagination_metadata` для навигации. Используйте `search` для поиска по заголовкам, проектам или целям, либо фильтруйте по точным `project`, `target`, `category` (например, `swiftCompilation`) и `status` (`success` или `failure`). Сортируйте по `duration_ms` для отображения самых медленных сначала (по умолчанию) или по `start_ms` для хронологического порядка. ID шагов разрывают связи и возвращаются в виде десятичных строк для сохранения полной 64-битной точности. ID привязаны к сборке и не должны сопоставляться между разными сборками.

Необязательные `start_ms` и `end_ms` выбирают шаги, попадающие в диапазон времени в миллисекундах от начала сборки; конечная граница не включается. Оба инструмента принимают UUID сборки или URL-адрес панели управления как `build_run_id`. Передайте полученный ID шага `id` без изменений как `step_id`, чтобы получить его журнал. Журналы хранят до 64 КиБ на шаг, при этом `log_truncated` указывает на пропущенный вывод.

Шаги собираются по умолчанию при обработке сборок Xcode. Записанные данные о шагах сохраняются в течение 90 дней. Ответ списка включает `availability`: `available`, если записанные шаги существуют, даже если фильтры ничего не нашли; `processing`, если сборка всё ещё обрабатывается и шагов пока нет; или `unavailable`, если шаги не были записаны или срок их хранения истёк.

Те же операции доступны через HTTP API по адресам `GET /api/projects/{account_handle}/{project_handle}/xcode/builds/{build_id}/steps` и `GET /api/projects/{account_handle}/{project_handle}/xcode/builds/{build_id}/steps/{step_id}`, с теми же фильтрами и пагинацией. Для обоих требуется доступ на чтение к проекту сборки.

Списки шагов Gradle и Bazel по умолчанию возвращают 20 результатов (максимум 100), поддерживают `search`, точные `project`, `target`, `category` и `status`, фильтры по пересекающемуся времени `start_ms` / `end_ms` (конечная граница не включается) и сортировку по `duration_ms` или `start_ms`. Передавайте полученные ID без изменений; они привязаны к своей сборке. Списки содержат `time_origin` и `coverage`. Старые отчёты Gradle используют `first_recorded_timestamp`, так как время начала сборки не было загружено. Профили Bazel предоставляют все записанные интервалы с покрытием `trace_profile` и `profile_start` в качестве начала отсчёта времени. Для старых сборок используются сохранённые сводки BEP. Исходные записи истекают через 90 дней. Детали Bazel включают очищенные журналы действий, если они опубликованы; деталь `log` для Gradle равна null. Подсказка `compare_builds` использует это покрытие, чтобы отличить полные трассировки Bazel от сохранённых сводок, и направляет агентов к деталям шагов для получения результатов действий и журналов перед проверкой общего вывода вызова.

ID шагов Bazel, возвращаемые из сохранённых сводок, остаются читаемыми, если полный профиль поступает между получением списка и запросом шага. Индексированный профиль, данные шагов которого истекли, сообщает о недоступности. Списки шагов Gradle включают кэшированные и пропущенные операции с нулевой длительностью.

#### Задачи, действия, модули и файлы

Эти инструменты уровня проекта анализируют постоянные идентификаторы сборок across запусков. Начните с `list_build_entities`, затем передайте возвращённый стабильный `id` с тем же `kind` в `get_build_entity` или `list_build_entity_history` вместе с `account_handle` и `project_handle`. Идентификатор сборки или вызова не требуется.

Эти инструменты внедряются постепенно и возвращают данные только для проектов, в которых они включены; для остальных проектов возвращается ошибка вместо пустого результата. Тип доступен только для проектов, использующих соответствующий инструментарий сборки. Инструменты принимают ограниченные фильтры `start_at`/`end_at`, `environment` (`any`, `ci` или `local`) и точное значение `branch`. `list_build_entities` принимает `q`; `list_build_entity_history` поддерживает непрозрачные курсоры `after`/`before`. Неизвестные данные о времени выполнения или кэше остаются недоступными, а не превращаются в нули или промахи. История ссылается на записанного родителя и нативное выполнение для детализации с помощью существующих инструментов запуска.

Метрики `get_build_entity` включают `duration_samples` — количество наблюдений с записанным временем: подлинные нулевые длительности учитываются, отсутствующие данные о времени — нет. Это число может быть меньше количества наблюдений; недоступная статистика длительности остаётся равной null.

Длительность модулей Xcode определяется по измеренным компиляциям целей в логах сборки. Разрешения кэша модулей и цели без работы по компиляции не вносят вклад в выборку длительностей. Наблюдения за компиляцией относятся к сборке Xcode; события кэша относятся к команде генерации или кэширования.

Действия Bazel идентифицируются по метке цели, мнемонике и настроенному основному выходному файлу, что позволяет разделять действия и конфигурации без опоры на зависящие от входных данных дайджесты кэша. История записывает выполнения, сообщённые через BEP, а не обращения к кэшу или этапы профилирования трассировки. Полное покрытие выполнения требует `--build_event_publish_all_actions`; доставка артефактов выполняется по принципу «best effort», поэтому отсутствие наблюдений не является доказательством того, что работа не выполнялась. Старые полезные нагрузки Kura без стабильного идентификатора или начала выполнения по-прежнему принимаются, но не индексируются. Отсутствующие измерения времени окончания остаются недоступными, а подлинные нулевые длительности учитываются.

Длительность модулей Mix измеряет компиляцию содержащего файла, а не независимо измеренную работу модуля. Действия Once используют объявленные слоты цель/возможность/индекс, когда клиент сообщил сопоставления целей; одни лишь диагностические метки не являются стабильными идентификаторами. Существующие клиенты и инструменты уровня запуска поддерживаются без изменений.

Крейты Cargo группируются по точно записанному корню крейта, имени и типу. Изменения пути checkout могут разделять истории, при этом профили сборки, возможности и тройки целей не различаются. История измеряет вызовы rustc, а не работу по отдельным файлам или попадания в кэш; отсутствующие задачи не свидетельствуют об удалениях или полной инвентаризации рабочего пространства.

Чтение аналитики имеет ограничения по памяти и времени выполнения. Если запрос превышает эти лимиты, инструмент возвращает ошибку вместо создания пустого результата.

Новые наблюдения индексируются после развертывания; эта функция не заполняет ретроспективно существующую телеметрию запусков. Метаданные идентификаторов хранятся дольше отдельных наблюдений в соответствии с <.localized_link href="/guides/server/data-retention">политикой хранения данных</.localized_link>.

### События

Клиенты, использующие жизненный цикл Model Context Protocol без сохранения состояния `2026-07-28`, могут вызвать `events/list` для обнаружения событий и их схем полезной нагрузки:

| Событие | Когда отправляется | Фильтр подписки |
|-------|-----------------|---------------------|
| `test_case.marked_flaky` | Тест-кейс меняется с нестабильного на стабильный. | `account_handle`, `project_handle` |
| `build.failed` | Локальная сборка или сборка в непрерывной интеграции Xcode, Gradle или Bazel завершается с ошибкой. | `account_handle`, `project_handle` |
| `test_run.failed` | Локальный запуск тестов или запуск тестов в непрерывной интеграции завершается с ошибкой, включая объединённый шардированный запуск или отменённый запуск. | `account_handle`, `project_handle` |
| `ci_job.failed` | Задача раннера Tuist завершается с ошибкой. | `account_handle` |

Для подписки клиент вызывает `events/subscribe` с именем события, идентификаторами, перечисленными выше в `arguments`, и доставкой `webhook`, содержащей URL-адрес обратного вызова `https://` и секрет подписи `whsec_`. События проекта требуют членства в аккаунте и доступа на чтение к соответствующим данным тестов или сборок; события задач раннера требуют членства в аккаунте и доступа на чтение к раннеру. Заявленные токены доступа [`auth.md`](https://workos.com/auth-md), заявленные токены аккаунта и разрешения авторизации браузера могут создавать подписки; доставка останавливается, когда связанная учётная запись больше не активна. Каждый пользователь может иметь до 25 активных подписок. Tuist отправляет проверочный запрос на обратный вызов перед сохранением подписки. Обратный вызов должен вернуть объект, содержащий то же значение `challenge`. Подписка действует семь дней по умолчанию, может быть обновлена путём повторной подписки и прекращает доставку, когда доступ пользователя или учётная запись удаляются. Необязательный параметр `ttlMs` ограничен диапазоном от одного часа до 30 дней. Tuist повторяет попытку вызова тайм-аута обратного вызова и отменяет подписку после как минимум трёх последовательных тайм-аутов в течение пяти минут; подпишитесь снова после восстановления обратного вызова.

При возникновении события Tuist отправляет его идентификатор ресурса и URL-адрес панели управления на обратный вызов. Ошибки сборки и запуска тестов также включают `is_ci` и `git_branch`, поэтому клиенты могут игнорировать локальные ошибки или фильтровать по ветке. События сборки включают `build_system`; события задач раннера включают как `workflow_job_id`, так и `workflow_run_id`. Запрос включает идентификатор подписки и заголовки подписи [Standard Webhooks](https://www.standardwebhooks.com/), чтобы клиент мог проверить её источник. Tuist повторяет неудачные доставки, поэтому клиентам следует использовать стабильный `eventId` для отбрасывания дубликатов. Полезная нагрузка не содержит имен тестов, логов и сообщений об ошибках; клиент может получить эти детали через инструменты выше и решить, уведомлять ли команду или начать отладку. Клиенты могут остановить доставку с помощью `events/unsubscribe`.

### Подсказки

| Подсказка | Описание |
|--------|-------------|
| `fix_flaky_test` | Помогает исправить нестабильный тест, анализируя шаблоны сбоев, выявляя первопричину и применяя целенаправленное исправление. |
| `compare_builds` | Помогает сравнить сборки, чтобы выявить регрессии производительности, изменения в кэше и проблемы сборки. Использует нативные инструменты для проектов Xcode, Gradle, Bazel и Cargo. При сравнении Cargo сохраняется частичное покрытие компилятора, а оценочная работа компилятора отделяется от фактической экономии времени. |
| `compare_test_runs` | Помогает сравнить два запуска тестов, чтобы выявить регрессии, новые сбои и нестабильные тесты. |
| `compare_bundles` | Помогает сравнить два бандла, чтобы выявить изменения размера в дереве артефактов. |
| `compare_test_case` | Помогает сравнить поведение тест-кейса в двух ветках или за разные периоды времени. |
| `compare_generations` | Помогает сравнить два запуска генерации, чтобы выявить регрессии производительности и изменения в кэше модулей. |
| `compare_cache_runs` | Помогает сравнить два запуска кэширования, чтобы выявить изменения эффективности кэша и регрессии на уровне таргетов. |
| `integrate_gradle_project` | Помогает интегрировать Tuist в существующий проект Gradle. Включает отдельную аутентификацию инструмента и Gradle, обнаружение аккаунта, создание проекта, политику удаленного кэша, аналитику сборки и проверку считыванием данных. |
| `integrate_bazel_project` | Помогает создать или выбрать проект Bazel, аутентифицировать командную строку, настроить удаленный кэш и аналитику сборки, а также проверить интеграцию через данные сборки Tuist. |
| `integrate_xcode_project` | Помогает интегрировать Tuist в существующий проект Xcode. Поддерживает кэш Xcode, аналитику сборки, аналитику тестов и шардирование тестов. |
| `ask_tuist` | Отвечает на вопрос по Tuist, используя общедоступные материалы для контекста и сфокусированные данные реализации и тестирования как источник истины для текущего поведения. Требуется `question` и приводятся доказательства, привязанные к ревизии. |

Подсказки для данных проекта принимают `account_handle` и `project_handle`, чтобы ограничить исследование конкретным проектом. Подсказки для сравнения также принимают аргументы `base` и `head`, чтобы указать два сравниваемых элемента (по ID, URL панели управления или имени ветки). `ask_tuist` принимает `question` вместо параметров проекта. `integrate_gradle_project` также принимает `features` — список интеграций Gradle через запятую: `remote_cache`, `build_insights`, `test_insights`, `flaky_tests` и `test_sharding`. `integrate_bazel_project` принимает необязательный `server_url` для самостоятельного хостинга или локальных установок. `integrate_xcode_project` принимает `features` со значениями `xcode_cache`, `build_insights`, `test_insights` и `test_sharding`.

#### Возможности подсказки интеграции Gradle

Подсказка `integrate_gradle_project` и инструмент `get_gradle_integration_guide` документируют полный процесс настройки. Инструмент также упоминается в инструкциях инициализации сервера, что делает его обнаруживаемым для агентов, которые не перечисляют подсказки.

| Возможность | Что настраивает агент |
|---------|---------------------------|
| `remote_cache` | Включает кэш сборки Gradle, настраивает политику загрузки удаленного кэша Tuist и рекомендует загружать данные только с раннеров непрерывной интеграции с локальным доступом только для чтения. |
| `build_insights` | Применяет плагин Tuist Gradle и при необходимости настраивает поведение загрузки аналитики сборки. |
| `test_insights` | Применяет плагин Tuist Gradle, чтобы результаты задач Gradle `Test` автоматически загружались. |
| `flaky_tests` | Помогает настроить обнаружение нестабильных тестов, опциональное использование плагина Gradle Test Retry и конфигурацию карантина тестов. |
| `test_sharding` | Добавляет рабочий процесс непрерывной интеграции для `tuistPrepareTestShards`, генерации матрицы шардов и выполнения тестов на основе `TUIST_SHARD_INDEX`. |

Если `features` пропущен, подсказка просит агента уточнить, какие интеграции нужны пользователю, или вывести минимально полезный набор из запроса перед редактированием проекта Gradle.

#### Возможности подсказки интеграции Xcode

Подсказка `integrate_xcode_project` документирует каждую интеграцию Xcode, которую поддерживает Tuist:

| Возможность | Что настраивает агент |
|---------|---------------------------|
| `xcode_cache` | Настраивает `tuist setup cache`, параметры кэша сгенерированного проекта, ручные настройки сборки кэша Xcode и политику загрузки, ограниченную раннерами непрерывной интеграции. |
| `build_insights` | Настраивает `tuist inspect build`, `tuist xcodebuild`, `-resultBundlePath` и опциональные метрики машины через `tuist setup insights`. |
| `test_insights` | Настраивает `tuist inspect test`, пост-действия тестирования схем и генерацию бандла результатов для запусков тестов в непрерывной интеграции. |
| `test_sharding` | Добавляет планирование шардов для Xcode или сгенерированного проекта и рабочий процесс выполнения шардов с `TUIST_SHARD_INDEX`. |

Если `features` пропущен, подсказка просит агента уточнить, какие интеграции нужны пользователю, или вывести минимально полезный набор из запроса перед редактированием проекта Xcode.
