# Model Context Protocol

[Model Context Protocol (MCP)](https://modelcontextprotocol.io/docs/getting-started/intro) — это открытый стандарт, позволяющий агентам искусственного интеллекта взаимодействовать с внешними сервисами и источниками данных. Он обеспечивает совместимость таких приложений, как [Claude](https://claude.ai/), [Claude Code](https://docs.anthropic.com/en/docs/claude-code), [Codex](https://developers.openai.com/codex/), и редакторов, таких как [Zed](https://zed.dev), [Cursor](https://www.cursor.com) или [Visual Studio Code](https://code.visualstudio.com), с Tuist.

Tuist размещает серверную конечную точку Model Context Protocol по адресу `https://tuist.dev/mcp`. Подключив к ней свой клиент, вы позволяете агентам получать доступ к данным вашего проекта в Tuist, включая аналитику тестов, анализ нестабильных тестов и многое другое. Большинство инструментов работают только на чтение и имеют доступ только к аутентифицированным данным проекта Tuist. Инструменты настройки аккаунта могут перечислять аккаунты, создавать организации, создавать проекты и добавлять существующих пользователей в организации, если у аутентифицированного пользователя есть необходимые разрешения. Каждый инструмент предоставляет аннотации, указывающие, работает ли он только на чтение, может ли он вызвать трудно обратимые изменения и может ли он изменить состояние в публичном интернете. Инструменты настройки аккаунта требуют аутентификации пользователя. Они недоступны для токенов проектов или обычных токенов аккаунтов. Когда пользователь авторизует клиент в браузере или подтверждает регистрацию `auth.md`, Tuist связывает эти учетные данные с пользователем только на конечной точке Model Context Protocol, чтобы инструменты настройки могли завершить запрошенный рабочий процесс.

Tuist реализует [протокол версии 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http). Запросы являются stateless: клиенты отправляют метаданные протокола с каждым запросом и могут вызывать инструменты напрямую без инициализации. `server/discover` возвращает идентификатор сервера, его возможности, поддерживаемые версии и инструкции. Идентификаторы сессий или независимые потоки событий отсутствуют. Клиенты, использующие поток инициализации 2025-06-18 или 2025-03-26, по-прежнему поддерживаются; они также работают без серверных сессий.

## Model Context Protocol против навыков (skills)

Функциональность инструментов Model Context Protocol и <.localized_link href="/guides/features/agentic-coding/skills">навыков (skills)</.localized_link> может пересекаться. Учитывая текущее перекрытие между ними, выбирайте один подход для каждого рабочего процесса и используйте его последовательно, вместо того чтобы смешивать оба подхода в одном потоке.

Для клиентов, поддерживающих установку плагинов, используйте <.localized_link href="/guides/features/agentic-coding/plugins">плагины Tuist</.localized_link> для установки обоих компонентов вместе.

## Конфигурация

Добавьте `https://tuist.dev/mcp` в качестве удаленного сервера Model Context Protocol в вашем клиенте. Инструкции по инициализации сервера и публичная карточка сервера описывают OAuth 2.0 с динамической регистрацией клиента и стандартный поток авторизации через браузер встроенными средствами, не требуя от агентов загружать или следовать внешним документам по аутентификации. Эти общесерверные инструкции оставляют рекомендации по рабочему процессу универсальными: аутентификация инструментов не аутентифицирует локальные инструменты командной строки или интеграции с системами сборки, и агенты должны проверять запрашиваемые изменения через соответствующие инструменты Tuist. Настройка и проверки аутентификации, специфичные для системы сборки, документированы в руководствах по интеграции и подсказках. Tuist по-прежнему предоставляет отдельно метаданные обнаружения [Open Authorization](https://oauth.net/2/) и текущий [протокол auth.md](https://workos.com/auth-md) по адресу `https://tuist.dev/auth.md`.

Если одна из ваших организаций требует единого входа (SSO), авторизация клиента в браузере требует сессии, выполненной через эту организацию, и при необходимости Tuist сначала перенаправляет вас к провайдеру. См. <.localized_link href="/guides/integrations/authentication/sso#choose-an-enrollment-policy">единый вход (SSO)</.localized_link>.

Конечная точка принимает stateless жизненный цикл запросов Model Context Protocol `2026-07-28`, включая `server/discover`, наряду со старым жизненным циклом на основе сессий. Существующие клиенты могут продолжать использовать свой текущий метод подключения.

Клиенты, поддерживающие события Model Context Protocol, могут подписываться на события проекта. См. раздел [События](#events) для получения информации о доступных событиях и требованиях к доставке.

Клиенты, которые уже поддерживают удаленную аутентификацию через браузер, могут продолжать аутентифицироваться в браузере. Клиенты и агенты, поддерживающие `auth.md`, могут регистрироваться анонимно, предоставлять доверенное утверждение идентичности провайдера или начинать запрос на подтверждение электронной почты с аутентификацией сервиса. Регистрация возвращает утверждение идентичности, подписанное Tuist, которое агент обменивает на стандартной конечной точке токенов на токен доступа сроком на один час. Tuist публикует свой публичный ключ подписи и поддерживает стандартное отзывание токенов и доставку событий безопасности от провайдера.

Неаутентифицированный агент должен прочитать заголовок `WWW-Authenticate`, возвращаемый конечной точкой Model Context Protocol, получить метаданные защищенного ресурса, получить метаданные сервера авторизации и перейти по его URL `agent_auth.skill`. Tuist также возвращает тот же локальный URL `auth_md` в теле ответа об отказе в доступе, чтобы клиенты, управляемые языковыми моделями, могли обнаружить этот поток без reliance на нативную интеграцию клиента. Локальный для развертывания документ является источником истины для имен конечных точек, тел запросов, опроса подтверждения и обмена утверждениями.

Прежде чем агент начнет запрос на подтверждение электронной почты, он должен попросить пользователя подтвердить адрес электронной почты для его аккаунта Tuist. Он не должен определять этот адрес из профиля провайдера, конфигурации Git, переменной окружения или метаданных сессии.

Конечная точка использует группу областей видимости `mcp`. Анонимные учетные данные до подтверждения могут обнаруживать возможности и читать публичные руководства по интеграции, но они не рассматриваются как вошедшие в систему пользователи. После авторизации в браузере или подтверждения, учетные данные привязываются к пользователю, и каждый инструмент применяет те же проверки авторизации, что и панель управления. Подробнее см. в <.localized_link href="/guides/server/authentication#scope-groups">документации по группам областей видимости</.localized_link>.

Инструменты разрешаются к проектам, к которым аутентифицированный пользователь уже имеет доступ на чтение. Инструменты сборки Xcode и Gradle принимают UUID сборки или URL панели управления. UUID должен идентифицировать ровно один проект; если он встречается в нескольких проектах, инструмент возвращает «не найдено» вместо выбора отчета другого проекта. Чтение данных панели управления и API в рамках проекта остается доступным. Сообщаемые идентификаторы акторов являются непроверенными метками, а не учетными данными или дополнительными правами доступа.

Инструменты списка сборок и деталей предоставляют необязательные метаданные `tuist_version`: версию CLI Tuist для Xcode и Cargo, плагин Tuist Gradle для Gradle и библиотеку `tuist_ex` для Mix. Xcode также предоставляет `tuist_generation_version` из связанного события генерации проекта, которое может отличаться от версии загружающего CLI. Отсутствующие значения равны null, а не выводятся из данных сервера или другого отчета. Bazel использует свой существующий `bazel_version`; детали запуска Once предоставляют `once_version`. Эти поля описывают сообщаемые версии, а не проверенную идентичность или версии сетевого контракта. Конечные точки REST API для сборок предоставляют те же метаданные. Существующие навыки интеграции и работы с нестабильными тестами не зависят от полей версий и не требуют изменений в рабочем процессе.

Операторы Tuist, исследующие аккаунт клиента, делают это через внутренние инструменты эксплуатации Tuist, которые записывают каждый вызов; прямое подключение к этой конечной точке не дает доступа beyond членства самого пользователя.

<summary>Pi</summary>

Pi не включает клиент Model Context Protocol. Вы можете установить стороннее расширение [`pi-mcp-adapter`](https://pi.dev/packages/pi-mcp-adapter) после изучения его исходного кода и последствий для безопасности:

Добавьте файл `.mcp.json` на уровне проекта:

```json
    }

```

Установка `auth` в значение `false` предотвращает скрытие обработчиком аутентификации адаптера в браузере ответа об отсутствии авторизации от Tuist. Безголовый агент сможет затем прочитать возвращенный URL `auth_md` и следовать процессу регистрации Tuist, обмена утверждениями идентичности и опроса заявок. Настройте полученный токен доступа как bearer-токен или позвольте агенту выполнять аутентифицированные вызовы Model Context Protocol напрямую.

Если вы предпочитаете аутентификацию в браузере, установите `auth` в значение `"oauth"`. Для этого потока держите один процесс активным с использованием [режима удаленного вызова процедур](https://pi.dev/docs/latest/rpc) Pi, пока аутентификация не завершится:

```bash
pi --mode rpc
```

Не разделяйте ожидающую аутентификацию в браузере между отдельными вызовами `pi --print`, так как процесс, владеющий состоянием обратного вызова, уже завершился.

## WebMCP

В браузерах, поддерживающих [WebMCP](https://webmachinelearning.github.io/webmcp), страницы Tuist регистрируют инструменты через `document.modelContext`, поэтому агенты, встроенные в браузер, могут вызывать их без дополнительной настройки. Вызовы выполняются на сервере Tuist.

- **Страницы веб-сайта и документации** регистрируют инструменты документации и исходного кода (`search_tuist`, `search_tuist_code`, `list_tuist_files` и `read_tuist_file`). Им не требуется вход в систему.
- **Страницы панели управления аккаунта**, когда вы вошли в систему, регистрируют инструменты Tuist только для чтения для этого аккаунта. Каждая страница регистрирует только инструменты для того, что она отображает, для системы сборки проекта: страница сборок проекта Gradle получает инструменты сборки Gradle, страницы тестов — инструменты тестирования и покрытия, страницы раннеров — инструменты раннеров, а страницы песочниц — инструменты песочниц. Раздел «Подписки» на странице настроек ИИ вашего личного аккаунта получает `list_ai_subscriptions`, который отвечает только по вашему собственному аккаунту. Каждая страница также получает инструменты документации, `list_projects` и `get_project`. Инструменты выполняются от имени вошедшего в систему пользователя, поэтому они имеют доступ только к данным, которые вы можете читать в панели управления, и только к аккаунту, который вы просматриваете. При переходе на другую страницу или аккаунт инструменты заменяются на инструменты этой страницы.

Инструменты, создающие, изменяющие или удаляющие данные, недоступны через WebMCP, поскольку браузерный агент получает инструменты без вашего добавления и читает контент, создаваемый сборками и тестами. Подключите клиент MCP к конечной точке `/mcp`, чтобы использовать эти инструменты.

Если организация использует единый вход (SSO), войдите в панель управления через её провайдера, чтобы использовать её инструменты.

## Интеграции с системами сборки используют два набора учётных данных

Учётные данные, используемые для инструментов Model Context Protocol, не аутентифицируют плагин Gradle или удалённые сервисы Bazel. Прежде чем агент начнёт редактировать или проверять интеграцию с Gradle или Bazel, он должен выполнить:

```bash
tuist auth whoami --url https://tuist.dev
```

Если эта команда не прошла аутентификацию, агент должен остановиться и попросить пользователя выполнить:

```bash
tuist auth login --url https://tuist.dev
```

Для локального или самостоятельно размещённого развёртывания замените URL в обеих командах и в `tuist.toml`. Сохраняйте написание имени хоста одинаковым везде. Например, `localhost` и `127.0.0.1` используют разные сохранённые учётные данные.


## Возможности

### Инструменты

Следующие инструменты доступны через сервер Tuist Model Context Protocol:

Каждый инструмент публикует понятное человеку описание вместе с явными схемами ввода и вывода. Успешные вызовы возвращают структурированный контент, соответствующий заявленной схеме вывода, а также тот же результат, сериализованный в виде текста для клиентов, которые ещё не потребляют структурированный контент.

Инструменты, принимающие идентификатор отдельной записи, такой как `build_run_id`, `test_run_id`, `test_case_id`, `bundle_id`, `run_id`, `generation_id` или `cache_run_id`, также принимают URL-адрес этой записи в панели управления Tuist. Вставьте URL прямо из браузера вместо того, чтобы извлекать из него идентификатор.

#### Поиск по документации и сообществу

Этот инструмент только для чтения выполняет поиск по документации Tuist, справочнику [программного интерфейса приложения](https://en.wikipedia.org/wiki/API), релизам на GitHub, форуму сообщества и задачам на GitHub через тот же поисковый движок, что используется на сайте документации. Результаты поиска по релизам включают продукт, версию, дату публикации и статус предварительного выпуска. По умолчанию поиск выполняется по стабильным релизам, предварительные релизы можно включить с помощью `include_prereleases`. Инструмент доступен только на сервере, размещённом Tuist, по адресу `https://tuist.dev/mcp`.

| Инструмент | Описание | Обязательные параметры |
|------|-------------|---------------------|
| `search_tuist` | Поиск по общедоступной документации Tuist, справочнику программного интерфейса приложения, релизам на GitHub, обсуждениям в сообществе и задачам на GitHub. При необходимости ограничьте поиск одним `source` (`docs`, `api_reference`, `releases`, `forum`, `issues`). | `query` |

#### Обратная связь

Агенты могут сообщить команде Tuist, если инструмент или подсказка Tuist сработали не так, как ожидалось, например, выдали непонятный результат, ошибку, недостающие данные или отсутствующую возможность. Агентам предлагается составить отчёт и отправить его только после вашего согласия. Каждый отчёт открывает диалог со службой поддержки Tuist, которая может ответить вам по электронной почте. Отчёт включает то, что ожидал агент, что произошло, необязательное предложение, ваш идентификатор пользователя Tuist, имя пользователя и адрес электронной почты, а также организации, к которым вы принадлежите. Агенты также могут указать аккаунт и проект, в которых возникла проблема, чтобы команда знала, с какой организацией связаться; принимаются только аккаунты, к которым вы имеете доступ. Только агенты, вошедшие в систему как пользователь Tuist, могут отправлять отчёты, и каждый пользователь может создавать до 10 отчётов в час. Инструмент доступен только на сервере, размещённом Tuist, по адресу `https://tuist.dev/mcp`.

| Инструмент | Описание | Обязательные параметры |
|------|-------------|---------------------|
| `report_feedback` | Сообщить о проблеме с инструментом или подсказкой Tuist. При необходимости укажите `tool_name`, `account_handle` и `project_handle`, в которых это произошло, и добавьте `suggestion`. | `category`, `expected`, `actual` |

#### Ответы на основе исходного кода

Эти инструменты только для чтения позволяют агентам использовать точную общедоступную ревизию исходного кода Tuist, развёрнутую вместе с размещённым сервером, в качестве источника истины для ответов, зависящих от текущего поведения. Они доступны только по адресу `https://tuist.dev/mcp`.

Совместимые клиенты получают фактические описания ревизии исходного кода инструментов, ссылки и ограничения результатов при инициализации, вместе с информацией об inline-аутентификации OAuth. #### Сборки Xcode

Инструменты детальной информации о сборках для Xcode, Gradle, Bazel, Mix и Cargo предоставляют существующую структуру `custom_metadata: {tags, values}`, включая наблюдения за инфраструктурой, если они сообщаются. Значения остаются строками, а неизвестные ключи сохраняются. Отсутствующие наблюдения остаются отсутствующими; импортированные логи и старые клиенты могут не иметь метаданных инфраструктуры. | `list_xcode_build_steps` | Список записанных шагов сборки с указанием времени и результатов, без текста логов. | `build_run_id` |
| `get_xcode_build_step` | Получить один записанный шаг сборки, включая его лог и флаг усечения. | `build_run_id`, `step_id` |
| `list_xcode_build_issues` | Список проблем сборки (предупреждения и ошибки) для конкретного запуска сборки. | `build_run_id` |
| `list_xcode_build_cache_tasks` | Список задач, подлежащих кэшированию (попадания/промахи кэша), для конкретного запуска сборки Xcode. | `build_run_id` |
| `list_xcode_build_cas_outputs` | Список выходов [хранилища с адресацией по содержимому](https://en.wikipedia.org/wiki/Content-addressable_storage) для конкретного запуска сборки Xcode. | `build_run_id` |

`list_xcode_build_steps` по умолчанию возвращает страницы по 20 шагов (максимум 100 через `page_size`), с `page` и `pagination_metadata` для навигации. Используйте `search` для поиска по названиям, проектам или целям, либо фильтруйте по точному совпадению `project`, `target`, `category` (например, `swiftCompilation`) и `status` (`success` или `failure`). Сортируйте по `duration_ms` для отображения самых медленных сначала (по умолчанию) или по `start_ms` для хронологического порядка. ID шагов используются для разрешения ничьих и возвращаются в виде десятичных строк для сохранения полной 64-битной точности. ID привязаны к конкретной сборке и не должны сопоставляться между разными сборками.

Необязательные параметры `start_ms` и `end_ms` выбирают шаги, пересекающиеся с временным диапазоном в миллисекундах от начала сборки; конец диапазона исключается. Оба инструмента принимают UUID сборки или URL панели управления в качестве `build_run_id`. Передайте полученный `id` шага без изменений в качестве `step_id` для получения его лога. Логи хранят до 64 КиБ на шаг, при этом `log_truncated` указывает на усеченный вывод.

Шаги собираются по умолчанию при обработке сборок Xcode. Записанные данные шагов хранятся 90 дней. Ответ списка включает `availability`: `available`, если записанные шаги существуют, даже если фильтры ничего не находят; `processing`, если сборка все еще обрабатывается и шагов пока нет; или `unavailable`, если шаги не были записаны или срок их хранения истек.

Те же операции доступны через HTTP API по адресам `GET /api/projects/{account_handle}/{project_handle}/xcode/builds/{build_id}/steps` и `GET /api/projects/{account_handle}/{project_handle}/xcode/builds/{build_id}/steps/{step_id}`, с теми же фильтрами и пагинацией. Для обоих требуется доступ на чтение к проекту сборки.

ID шагов Bazel, возвращаемые из сохраненных сводок, остаются доступными для чтения, если полный профиль поступает в период между получением списка и запросом шага. Индексированный профиль, данные шагов которого истекли, сообщает о недоступности. Списки шагов Gradle включают кэшированные и пропущенные операции с нулевой длительностью.

#### Задачи, действия, модули и файлы

Эти инструменты уровня проекта анализируют постоянные идентификаторы сборок across запусков. Начните с `list_build_entities`, затем передайте полученный стабильный `id` с тем же `kind` в `get_build_entity` или `list_build_entity_history` вместе с `account_handle` и `project_handle`. Идентификатор сборки или вызова не требуется.

| Инструмент | Описание | Обязательные параметры |
| --- | --- | --- |
| `list_build_entities` | Список задач, модулей, действий или файлов одного типа, обнаруженных в сборках проекта. | `account_handle`, `project_handle`, `kind` |
| `get_build_entity` | Получить одну сущность сборки с ее нативным идентификатором и аналитикой за выбранный период. | `account_handle`, `project_handle`, `kind`, `id` |
| `list_build_entity_history` | Список записанных выполнений, компиляций или событий кэша для одной сущности сборки, сначала новые. | `account_handle`, `project_handle`, `kind`, `id` |

| `kind` | Инструментарий | Списки истории |
| --- | --- | --- |
| `bazel_actions` | Действия Bazel | Выполнения действий, сообщенные через BEP |
| `gradle_tasks` | Задачи Gradle | Выполнения задач |
| `xcode_modules` | Модули Xcode | Компиляции и события кэша модулей |
| `once_actions` | Действия Once | Выполнения |
| `mix_files` | Компилируемые файлы Mix | Компиляции |
| `mix_modules` | Компилируемые модули Mix | Компиляции |
| `cargo_crates` | Крейты Cargo | Записанные вызовы rustc |

Эти инструменты внедряются постепенно и возвращают данные только для проектов, где они включены; для других проектов они возвращают ошибку вместо пустого результата. Тип доступен только для проектов, использующих соответствующий инструментарий сборки. Инструменты принимают ограниченные фильтры `start_at`/`end_at`, `environment` (`any`, `ci` или `local`) и точное значение `branch`. `list_build_entities` принимает `q`; `list_build_entity_history` поддерживает непрозрачные курсоры `after`/`before`. Неизвестные данные о времени или наблюдения кэша остаются недоступными, а не превращаются в нули или промахи. История ссылается на записанного родителя и нативное выполнение для детализации с использованием существующих инструментов запуска.

Метрики `get_build_entity` включают `duration_samples` — количество наблюдений с записанным временем: подлинные нулевые длительности учитываются, отсутствующие данные о времени — нет. Это количество может быть меньше количества наблюдений; недоступная статистика длительности остается null.

Длительности модулей Xcode получены из измеренных компиляций целей в логах сборки. Разрешения кэша модулей и цели без работы по компиляции не вносят вклад в выборки длительности. Наблюдения компиляции ссылается на сборку Xcode; события кэша — на команду генерации или кэширования.

Действия Bazel идентифицируются по метке цели, мнемонике и настроенному основному выходному файлу, что позволяет различать отдельные действия и конфигурации без опоры на зависящие от входных данных дайджесты кэша. История записывает выполнения, сообщенные через BEP, а не поиски в кэше или этапы профилирования трассировки. Полное покрытие выполнений требует `--build_event_publish_all_actions`; доставка артефактов осуществляется по принципу best effort, поэтому отсутствие наблюдений не является доказательством того, что работа не выполнялась. Старые полезные нагрузки Kura без стабильного идентификатора или начала выполнения по-прежнему принимаются, но не индексируются. Отсутствующие измерения времени окончания остаются недоступными, а подлинные нулевые длительности учитываются.

Длительности модулей Mix измеряют компиляцию содержащего файла, а не независимо измеренную работу модуля. Действия Once используют объявленные слоты target/capability/index, когда клиент сообщил сопоставления целей; одни лишь диагностические метки не являются стабильными идентификаторами. Существующие клиенты и инструменты уровня запуска поддерживаются без изменений.

Крейты Cargo группируются по точно записанному корню крейта, имени и типу. Изменения пути checkout могут разделять истории, а профили сборки, функции и тройки целей не различаются. История измеряет вызовы rustc, а не работу по файлам или попадания в кэш; отсутствующие задачи не свидетельствуют об удалениях или полной инвентаризации рабочего пространства.

Чтение аналитики имеет ограничения по памяти и времени выполнения. Если запрос превышает эти лимиты, инструмент возвращает ошибку вместо создания пустого результата.

Новые наблюдения индексируются после развертывания; эта функция не заполняет ретроспективно существующую телеметрию запусков. Метаданные идентификаторов хранятся дольше отдельных наблюдений в соответствии с <.localized_link href="/guides/server/data-retention">политикой хранения данных</.localized_link>.

### События

Клиенты, использующие жизненный цикл Model Context Protocol без сохранения состояния `2026-07-28`, могут вызвать `events/list` для обнаружения событий и их схем полезной нагрузки:

| Событие | Когда отправляется | Фильтр подписки |
|-------|-----------------|---------------------|
| `test_case.marked_flaky` | Тест-кейс меняется с не нестабильного на нестабильный. | `account_handle`, `project_handle` |
| `build.failed` | Локальная или сборка непрерывной интеграции Xcode, Gradle или Bazel завершается с ошибкой. | `account_handle`, `project_handle` |
| `test_run.failed` | Локальный или запуск тестов непрерывной интеграции завершается с ошибкой, включая объединенный шардированный запуск или отмененный запуск. | `account_handle`, `project_handle` |
| `ci_job.failed` | Задача раннера Tuist завершается с ошибкой. | `account_handle` |

Для подписки клиент вызывает `events/subscribe` с именем события, хэндлами, указанными выше в `arguments`, и доставкой `webhook`, содержащей URL-адрес обратного вызова `https://` и секрет подписи `whsec_`. События проекта требуют членства в аккаунте и доступа на чтение к соответствующим данным тестов или сборок; события задач раннера требуют членства в аккаунте и доступа на чтение к раннеру. Заявленные токены доступа [`auth.md`](https://workos.com/auth-md), заявленные токены аккаунта и гранты авторизации браузера могут создавать подписки; доставка прекращается, когда связанные учетные данные больше не активны. Каждый пользователь может иметь до 25 активных подписок. Tuist отправляет проверочный запрос обратному вызову перед сохранением подписки. Обратный вызов должен вернуть объект, содержащий то же значение `challenge`. Подписка действует семь дней по умолчанию, может быть обновлена путем повторной подписки и прекращает доставку при удалении доступа или учетных данных пользователя. Необязательный параметр `ttlMs` ограничен диапазоном от одного часа до 30 дней. Tuist повторяет попытку вызова тайм-аута и отменяет подписку после как минимум трех последовательных тайм-аутов в течение пяти минут; подпишитесь снова после восстановления обратного вызова.

При возникновении события Tuist отправляет его идентификатор ресурса и URL-адрес панели управления на обратный вызов. Ошибки сборки и запуска тестов также включают `is_ci` и `git_branch`, поэтому клиенты могут игнорировать локальные ошибки или фильтровать по ветке. События сборки включают `build_system`; события задач раннера включают как `workflow_job_id`, так и `workflow_run_id`. Запрос включает идентификатор подписки и заголовки подписи [Standard Webhooks](https://www.standardwebhooks.com/), чтобы клиент мог проверить его источник. Tuist повторяет неудачные доставки, поэтому клиентам следует использовать стабильный `eventId` для отклонения дубликатов. Полезная нагрузка не содержит имен тестов, логов и сообщений об ошибках; клиент может получить эти детали через инструменты выше и решить, уведомлять ли команду или начать отладку. Клиенты могут остановить доставку с помощью `events/unsubscribe`.

### Подсказки

| Подсказка | Описание |
|--------|-------------|
| `fix_flaky_test` | Направляет вас через исправление нестабильного теста, анализируя шаблоны ошибок, выявляя первопричину и применяя целевое исправление. |
| `compare_builds` | Направляет вас через сравнение сборок для выявления регрессий производительности, изменений кэша и проблем сборки. Использует нативные инструменты для проектов Xcode, Gradle, Bazel и Cargo. Сравнения Cargo сохраняют частичное покрытие компилятора и различают оценочную работу компилятора от сэкономленного времени. |
| `compare_test_runs` | Направляет вас через сравнение двух запусков тестов для выявления регрессий, новых ошибок и нестабильных тестов. |
| `compare_bundles` | Направляет вас через сравнение двух бандлов для выявления изменений размера по всему дереву артефактов. |
| `compare_test_case` | Направляет вас через сравнение поведения тест-кейса между двумя ветками или периодами времени. |
| `compare_generations` | Направляет вас через сравнение двух запусков поколений для выявления регрессий производительности и изменений кэша модулей. |
| `compare_cache_runs` | Направляет вас через сравнение двух запусков кэша для выявления изменений эффективности кэша и регрессий на уровне целей. |
| `integrate_gradle_project` | Направляет вас через интеграцию Tuist в существующий проект Gradle. Включает отдельную аутентификацию инструмента и Gradle, обнаружение аккаунта, создание проекта, политику удаленного кэша, аналитику сборки и проверку чтения обратно. |
| `integrate_bazel_project` | Направляет вас через создание или выбор проекта Bazel, аутентификацию командной строки, настройку удаленного кэша и аналитики сборки, а также проверку интеграции через данные сборки Tuist. |
| `integrate_xcode_project` | Направляет вас через интеграцию Tuist в существующий проект Xcode. Поддерживает кэш Xcode, аналитику сборки, аналитику тестов и шардирование тестов. |
| `ask_tuist` | Отвечает на вопрос о Tuist, используя публичные материалы для контекста и сфокусированные доказательства реализации и тестирования как источник истины для текущего поведения. Требуется `question` и цитируются доказательства, привязанные к ревизии. |

Подсказки с данными проекта принимают `account_handle` и `project_handle` для ограничения исследования конкретным проектом. Подсказки сравнения также принимают аргументы `base` и `head` для указания двух элементов для сравнения (по ID, URL-адресу панели управления или имени ветки). `ask_tuist` принимает `question` вместо параметров проекта. `integrate_gradle_project` также принимает `features`, список интеграций Gradle через запятую для применения: `remote_cache`, `build_insights`, `test_insights`, `flaky_tests` и `test_sharding`. `integrate_bazel_project` принимает необязательный `server_url` для самостоятельного размещения или локальных установок. `integrate_xcode_project` принимает `features` с `xcode_cache`, `build_insights`, `test_insights` и `test_sharding`.

#### Возможности подсказки интеграции Gradle

Подсказка `integrate_gradle_project` и инструмент `get_gradle_integration_guide` документируют полный рабочий процесс настройки. Инструмент также упоминается в инструкциях инициализации сервера, что делает его обнаруживаемым для агентов, которые не перечисляют подсказки.

| Возможность | Что настраивает агент |
|---------|---------------------------|
| `remote_cache` | Включает кэш сборки Gradle, настраивает политику загрузки удаленного кэша Tuist и рекомендует загружать данные только с раннеров непрерывной интеграции с локальным доступом только для чтения. |
| `build_insights` | Применяет плагин Tuist для Gradle и при необходимости настраивает поведение загрузки аналитики сборки. |
| `test_insights` | Применяет плагин Tuist для Gradle, чтобы результаты задач Gradle `Test` автоматически загружались. |
| `flaky_tests` | Направляет настройку обнаружения нестабильных тестов, опционального использования плагина Gradle Test Retry и конфигурации карантина тестов. |
| `test_sharding` | Добавляет рабочий процесс непрерывной интеграции для `tuistPrepareTestShards`, генерации матрицы шардов и выполнения тестов на основе `TUIST_SHARD_INDEX`. |

Если `features` опущен, подсказка просит агента уточнить, какие интеграции нужны пользователю, или вывести минимально полезный набор из запроса перед редактированием проекта Gradle.

#### Возможности подсказки интеграции Xcode

Подсказка `integrate_xcode_project` документирует каждую интеграцию Xcode, которую поддерживает Tuist:

| Возможность | Что настраивает агент |
|---------|---------------------------|
| `xcode_cache` | Настраивает `tuist setup cache`, параметры кэша сгенерированного проекта, ручные настройки сборки кэша Xcode и политику загрузки, ограниченную раннерами непрерывной интеграции. |

Если `features` опущен, подсказка просит агента уточнить, какие интеграции нужны пользователю, или вывести минимально полезный набор из запроса перед редактированием проекта Xcode.
