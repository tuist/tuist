# Протокол Model Context

[Model Context Protocol (MCP)](https://modelcontextprotocol.io/docs/getting-started/intro) — это открытый стандарт, позволяющий агентам искусственного интеллекта взаимодействовать с внешними сервисами и источниками данных. Он обеспечивает совместимость таких приложений, как [Claude](https://claude.ai/), [Claude Code](https://docs.anthropic.com/en/docs/claude-code), [Codex](https://developers.openai.com/codex/), и редакторов, таких как [Zed](https://zed.dev), [Cursor](https://www.cursor.com) или [Visual Studio Code](https://code.visualstudio.com), с Tuist.

Tuist размещает серверную конечную точку протокола Model Context по адресу `https://tuist.dev/mcp`. Подключив к ней свой клиент, агенты смогут получать доступ к данным вашего проекта Tuist, включая аналитику тестов, анализ нестабильных тестов и многое другое. Большинство инструментов работают только в режиме чтения и ограничены данными проектов Tuist, прошедших аутентификацию. Инструменты настройки аккаунта могут перечислять аккаунты, создавать организации, создавать проекты и добавлять существующих пользователей в организации, если у аутентифицированного пользователя есть необходимые разрешения. Каждый инструмент предоставляет аннотации, указывающие, работает ли он только в режиме чтения, может ли он вызвать труднообратимые изменения и может ли он изменять состояние в публичном интернете. Инструменты настройки аккаунта требуют аутентификации пользователя. Они недоступны для токенов проектов или обычных токенов аккаунтов. Когда пользователь авторизует клиент в браузере или подтверждает регистрацию `auth.md`, Tuist связывает эти учетные данные с пользователем только на конечной точке протокола Model Context, чтобы инструменты настройки могли завершить запрошенный рабочий процесс.

Tuist реализует [протокол версии 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http). Запросы являются stateless: клиенты отправляют метаданные протокола с каждым запросом и могут вызывать инструменты напрямую без инициализации. `server/discover` возвращает идентификатор сервера, возможности, поддерживаемые версии и инструкции. Идентификаторы сессий или независимые потоки событий отсутствуют. Клиенты, использующие поток инициализации версий 2025-06-18 или 2025-03-26, по-прежнему поддерживаются; они также работают без сессий на стороне сервера.

## Протокол Model Context против навыков (skills)

Функциональность инструментов протокола Model Context и <.localized_link href="/guides/features/agentic-coding/skills">навыков</.localized_link> может пересекаться. Учитывая текущее перекрытие между ними, выбирайте один подход для каждого рабочего процесса и используйте его последовательно, вместо того чтобы смешивать оба в одном потоке.

Для клиентов, поддерживающих установку плагинов, используйте <.localized_link href="/guides/features/agentic-coding/plugins">плагины Tuist</.localized_link>, чтобы установить их вместе.

## Настройка

Добавьте `https://tuist.dev/mcp` в качестве удаленного сервера протокола Model Context в вашем клиенте. Инструкции по инициализации сервера и публичная карточка сервера описывают OAuth 2.0 с динамической регистрацией клиента и стандартный поток авторизации через браузер встроенным образом, не требуя от агентов загружать или следовать внешним документам аутентификации. Эти общесерверные инструкции сохраняют общие рекомендации по рабочему процессу: аутентификация инструментов не аутентифицирует локальные инструменты командной строки или интеграции с системами сборки, и агенты должны проверять запрашиваемые изменения через соответствующие инструменты Tuist. Настройка и проверки аутентификации, специфичные для системы сборки, документированы в руководствах по интеграции и подсказках. Tuist по-прежнему предоставляет метаданные обнаружения [Open Authorization](https://oauth.net/2/) и текущий [протокол auth.md](https://workos.com/auth-md) по адресу `https://tuist.dev/auth.md` отдельно.

Конечная точка принимает stateless жизненный цикл запросов протокола Model Context `2026-07-28`, включая `server/discover`, наряду со старым жизненным циклом на основе сессий. Существующие клиенты могут продолжать использовать свой текущий метод подключения.

Клиенты, поддерживающие события протокола Model Context, могут подписываться на события проекта. См. раздел [События](#events) для получения информации о доступных событиях и требованиях к доставке.

Клиенты, которые уже поддерживают удаленную аутентификацию через браузер, могут продолжать аутентифицироваться в браузере. Клиенты и агенты, поддерживающие `auth.md`, могут регистрироваться анонимно, предоставлять утверждение идентичности доверенного провайдера или начинать процесс подтверждения электронной почты с аутентификацией сервиса. Регистрация возвращает утверждение идентичности, подписанное Tuist, которое агент обменивает на стандартной конечной точке токенов на токен доступа сроком на один час. Tuist публикует свой публичный ключ подписи и поддерживает стандартное отзывание токенов и доставку событий безопасности от провайдера.

Неаутентифицированный агент должен прочитать заголовок `WWW-Authenticate`, возвращаемый конечной точкой протокола Model Context, получить метаданные защищенного ресурса, получить метаданные сервера авторизации и перейти по его URL `agent_auth.skill`. Tuist также возвращает тот же локальный URL `auth_md` в теле ответа об отказе в доступе, чтобы клиенты, управляемые языковыми моделями, могли обнаружить этот поток, не полагаясь на нативную интеграцию клиента. Документ, локальный для развертывания, является источником истины для имен конечных точек, тел запросов, опроса подтверждения и обмена утверждениями.

Прежде чем агент начнет процесс подтверждения электронной почты, он должен попросить пользователя подтвердить адрес электронной почты для его аккаунта Tuist. Он не должен выводить этот адрес из профиля провайдера, конфигурации Git, переменной окружения или метаданных сессии.

Конечная точка использует группу областей видимости `mcp`. Анонимные учетные данные до подтверждения могут обнаруживать возможности и читать публичные руководства по интеграции, но они не рассматриваются как вошедшие в систему пользователи. После авторизации в браузере или подтверждения учетные данные ограничены пользователем, и каждый инструмент применяет те же проверки авторизации, что и панель управления. Подробности см. в <.localized_link href="/guides/server/authentication#scope-groups">документации по группам областей видимости</.localized_link>.

Инструменты разрешаются к проектам, которые аутентифицированный пользователь уже может читать. Инструменты сборки Xcode и Gradle принимают UUID сборки или URL панели управления. UUID должен идентифицировать ровно один проект; если он встречается в нескольких проектах, инструмент возвращает ошибку «не найдено» вместо выбора отчета другого проекта. Чтение данных панели управления и API в рамках проекта остается доступным. Сообщаемые идентификаторы действующих лиц являются непроверенными метками, а не учетными данными или дополнительными правами доступа.

Операторы Tuist, исследующие аккаунт клиента, делают это через внутренние операционные инструменты Tuist, которые записывают каждый вызов; прямое подключение к этой конечной точке не дает доступа beyond собственных членств пользователя.

<summary>Claude Code</summary>

Выполните:

```bash
claude mcp add --transport http tuist https://tuist.dev/mcp
```

Если автономный клиент Claude Code не передает модели информацию о неудачном подключении к нативному серверу, потребуйте от агента проверить неаутентифицированный ответ [протокола передачи гипертекста](https://developer.mozilla.org/en-US/docs/Web/HTTP) настроенной конечной точки перед поиском в размещенной документации или редактированием проекта. Ответ направит модель к локальному документу развертывания `auth.md`, даже если аутентификация в браузере недоступна.

</details>


<details>
<summary>Codex</summary>

Выполните:

```bash
codex mcp add tuist --url https://tuist.dev/mcp
```

Завершите вход через браузер перед запуском нового `codex exec`. Codex считывает инструкции сервера Tuist во время инициализации, поэтому запросы на оптимизацию Gradle автоматически получают рабочий процесс аутентификации и проверки.

</details>

<details>
<summary>Pi</summary>

Pi не включает клиент Model Context Protocol. Вы можете установить стороннее расширение [`pi-mcp-adapter`](https://pi.dev/packages/pi-mcp-adapter) после изучения его исходного кода и последствий для безопасности:

```bash
pi install npm:pi-mcp-adapter
```

Добавьте файл `.mcp.json` на уровне проекта:

```json
{
  "mcpServers": {
    "tuist": {
      "url": "https://tuist.dev/mcp",
      "auth": false
    }
  }
}
```

Установка значения `auth` в `false` предотвращает скрытие неавторизованного ответа Tuist обработчиком аутентификации браузера адаптера. После этого автономный агент может прочитать возвращенный URL `auth_md` и следовать процессу регистрации Tuist, обмена утверждениями идентичности и опроса подтверждений. Настройте полученный токен доступа как bearer-токен или позвольте агенту выполнять аутентифицированные вызовы Model Context Protocol напрямую.

Если вы предпочитаете аутентификацию через браузер, установите `auth` в `"oauth"`. Для этого потока держите один процесс активным с использованием [режима удаленного вызова процедур](https://pi.dev/docs/latest/rpc) Pi до завершения аутентификации:

```bash
pi --mode rpc
```

Не разделяйте ожидающую аутентификацию в браузере между отдельными вызовами `pi --print`, так как процесс, владеющий состоянием обратного вызова, уже завершился.

</details>

Если ваш агент поддерживает `auth.md`, он может начать работу анонимно без открытия браузера. Доверенная идентичность провайдера также может завершить процесс без браузера, если идентичность провайдера уже связана. Для электронной почты с аутентификацией службы, анонимного подтверждения или первой ссылки на провайдера агент покажет вам ссылку на проверку Tuist и шестизначный код. Откройте ссылку, войдите в систему и введите код агента на странице Tuist. Никогда не отправляйте код обратно агенту. Метаданные сервера авторизации Tuist указывают непосредственно на собственный `/auth.md` развертывания, который содержит точные форматы запросов и опроса.

## Интеграции систем сборки используют два набора учетных данных

Учетные данные, используемые для инструментов Model Context Protocol, не аутентифицируют плагин Gradle или удаленные сервисы Bazel. Перед тем как агент изменит или проверит интеграцию Gradle или Bazel, он должен выполнить:

```bash
tuist auth whoami --url https://tuist.dev
```

Если эта команда не аутентифицирована, агент должен остановиться и попросить пользователя выполнить:

```bash
tuist auth login --url https://tuist.dev
```

Для локального или самостоятельно размещенного развертывания замените URL в обеих командах и в `tuist.toml`. Сохраняйте одинаковое написание имени хоста везде. Например, `localhost` и `127.0.0.1` используют отдельные сохраненные учетные данные.


## Возможности

### Инструменты

Следующие инструменты доступны через сервер Tuist Model Context Protocol:

Каждый инструмент публикует понятное человеку описание вместе с явными схемами ввода и вывода. Успешные вызовы возвращают структурированное содержимое, соответствующее заявленной схеме вывода, а также тот же результат, сериализованный в виде текста для клиентов, которые еще не потребляют структурированное содержимое.

Инструменты, принимающие идентификатор одной записи, такие как `build_run_id`, `test_run_id`, `test_case_id`, `bundle_id`, `run_id`, `generation_id` или `cache_run_id`, также принимают URL панели управления Tuist для этой записи. Вставьте URL прямо из браузера вместо извлечения из него идентификатора.

#### Поиск по документации и сообществу

Этот инструмент только для чтения выполняет поиск в документации Tuist, справочнике [программного интерфейса приложения](https://en.wikipedia.org/wiki/API), релизах GitHub, на форуме сообщества и в задачах GitHub через тот же поисковый движок, что используется на сайте документации. Результаты поиска по релизам включают продукт, версию, дату публикации и статус предварительной версии. По умолчанию выполняется поиск по стабильным релизам; предварительные версии можно включить с помощью `include_prereleases`. Инструмент доступен только на сервере, размещенном Tuist, по адресу `https://tuist.dev/mcp`.

| Инструмент | Описание | Обязательные параметры |
|------|-------------|---------------------|
| `search_tuist` | Поиск в публичной документации Tuist, справочнике программного интерфейса приложения, релизах GitHub, обсуждениях сообщества и задачах GitHub. При необходимости можно ограничить поиск одним `source` (`docs`, `api_reference`, `releases`, `forum`, `issues`). | `query` |

#### Ответы с опорой на исходный код

Эти инструменты только для чтения позволяют агентам использовать точную публичную ревизию исходного кода Tuist, развернутую вместе с хостинговым сервером, как источник истины для ответов, зависящих от текущего поведения. Они доступны только по адресу `https://tuist.dev/mcp`.

Совместимые клиенты получают фактические описания ревизии исходного кода инструментов, ссылки и ограничения результатов во время инициализации вместе со встроенной информацией об аутентификации OAuth. Эти описания не предписывают стиль ответа или рабочий процесс проверки. Пользователи могут задать вопрос напрямую, не вызывая сначала подсказку `ask_tuist`; подсказка остается доступной для явного рабочего процесса с опорой на исходный код.

Каждая операция имеет фиксированные ограничения на параллельность, длительность, глубину обхода, объем прочитанных байтов и размер ответа. Результаты поиска и списков включают поля `truncated` и `truncation_reason`. Если результат усечен, сузьте путь, шаблон файла или поисковый запрос вместо того, чтобы считать результат исчерпывающим.

| Инструмент | Описание | Обязательные параметры |
|------|-------------|---------------------|
| `search_tuist_code` | Отвечайте на вопросы о текущем поведении, значениях по умолчанию, конфигурации, флагах функций, обработке ошибок или недокументированных деталях, выполняя поиск по исходным файлам. Результаты включают окружающие строки, ссылки на исходный код с привязкой к ревизии и статистику сканирования. | `pattern` |
| `list_tuist_files` | Обнаруживайте подсистему исходного кода или близлежащие тесты, когда соответствующий путь неизвестен. Списки имеют ограниченную глубину и количество результатов. | Нет |
| `read_tuist_file` | Просматривайте определенный диапазон строк в файле реализации, месте вызова или тесте после нахождения соответствующего пути. Усеченные ответы предоставляют `next_start_line` для продолжения. | `path` |

#### Проекты

| Инструмент | Описание | Обязательные параметры |
|------|-------------|---------------------|
| `list_accounts` | Перечисляет хэндлы личных аккаунтов и аккаунтов организаций, доступные аутентифицированному пользователю, включая возможность создания проектов для каждого аккаунта. | Нет |
| `get_organization` | Получает список участников организации. Ожидающие приглашения требуют тех же прав администратора, что и панель управления; токены принятия приглашений никогда не возвращаются. | `account_handle` |
| `create_organization` | Создает организацию Tuist для аутентифицированного пользователя. | `handle` |
| `create_project` | Создает проект Tuist в аккаунте, к которому у аутентифицированного пользователя есть доступ. | `account_handle`, `project_handle` |

#### Сборки Xcode

Инструменты детализации сборок для Xcode, Gradle, Bazel, Mix и Cargo предоставляют существующую структуру `custom_metadata: {tags, values}`, включая наблюдения за инфраструктурой, если они сообщаются. Значения остаются строками, а неизвестные ключи сохраняются. Например, `tuist.cpu.available_processors` описывает логические процессоры, доступные во время выполнения, тогда как `tuist.gradle.max_workers` — это лимит рабочих процессов Gradle, а `tuist.jvm.max_heap_bytes` — лимит кучи JVM, а не память хоста. Это ненадежные наблюдения клиента, а не проверенные идентификаторы раннеров. Отсутствующие наблюдения остаются отсутствующими; импортированные логи и старые клиенты могут не иметь метаданных инфраструктуры. Формат метаданных ожидает согласованного обновления клиента/протокола.

| Инструмент | Описание | Обязательные параметры |
|------|-------------|---------------------|
| `list_xcode_builds` | Перечисляет запуски сборок Xcode для проекта. | `account_handle`, `project_handle` |
| `get_xcode_build` | Получает подробную информацию о конкретном запуске сборки Xcode, включая временный URL-адрес для скачивания архива с исходным файлом `.xcactivitylog`. | `build_run_id` |
| `list_xcode_build_targets` | Перечисляет цели сборки для конкретного запуска сборки Xcode. | `build_run_id` |
| `list_xcode_build_files` | Перечисляет скомпилированные файлы для конкретного запуска сборки Xcode. | `build_run_id` |
| `list_xcode_build_steps` | Перечисляет записанные шаги сборки с указанием времени и результатов, без текста логов. | `build_run_id` |
| `get_xcode_build_step` | Получает один записанный шаг сборки, включая его лог и флаг усечения. | `build_run_id`, `step_id` |
| `list_xcode_build_issues` | Перечисляет проблемы сборки (предупреждения и ошибки) для конкретного запуска сборки. | `build_run_id` |
| `list_xcode_build_cache_tasks` | Перечисляет кэшируемые задачи (попадания/промахи кэша) для конкретного запуска сборки Xcode. | `build_run_id` |
| `list_xcode_build_cas_outputs` | Перечисляет выходные данные [хранилища с адресацией по содержимому](https://en.wikipedia.org/wiki/Content-addressable_storage) для конкретного запуска сборки Xcode. | `build_run_id` |

`list_xcode_build_steps` по умолчанию возвращает страницы по 20 шагов (максимум 100 через `page_size`), с `page` и `pagination_metadata` для навигации. Используйте `search` для поиска по заголовкам, проектам или целям, либо фильтруйте по точному совпадению `project`, `target`, `category` (например, `swiftCompilation`) и `status` (`success` или `failure`). Сортируйте по `duration_ms` для отображения самых медленных сначала (по умолчанию) или по `start_ms` для хронологического порядка. Идентификаторы шагов разрывают равенство и возвращаются в виде десятичных строк для сохранения полной 64-битной точности. Идентификаторы привязаны к сборке и не должны сопоставляться между разными сборками.

Необязательные параметры `start_ms` и `end_ms` выбирают шаги, пересекающиеся с временным диапазоном в миллисекундах от начала сборки; конец диапазона исключается. Оба инструмента принимают UUID сборки или URL панели управления в качестве `build_run_id`. Передавайте полученный идентификатор шага `id` без изменений в качестве `step_id` для получения его лога. Логи хранят до 64 КиБ на шаг, при этом `log_truncated` указывает на пропущенный вывод.

Шаги собираются по умолчанию при обработке сборок Xcode. Записанные данные шагов сохраняются в течение 90 дней. Ответ списка включает поле `availability`: `available`, если записанные шаги существуют, даже если фильтры ничего не нашли; `processing`, если сборка все еще обрабатывается и шагов пока нет; или `unavailable`, если шаги не были записаны или срок их хранения истек.

Те же операции доступны через HTTP API по адресам `GET /api/projects/{account_handle}/{project_handle}/xcode/builds/{build_id}/steps` и `GET /api/projects/{account_handle}/{project_handle}/xcode/builds/{build_id}/steps/{step_id}`, с теми же фильтрами и пагинацией. Для обоих требуется доступ на чтение к проекту сборки.

Исходные записи истекают через 90 дней. Детали Bazel включают очищенные логи действий, если они опубликованы; поле `log` в деталях Gradle равно null. Подсказка `compare_builds` использует это покрытие для различения полных трассировок Bazel и сохраненных сводок, направляя агентов к деталям шагов для получения результатов действий и логов перед проверкой более широкого вывода вызова.

Идентификаторы шагов Bazel, возвращаемые из сохраненных сводок, остаются читаемыми, если полный профиль поступает в промежутке между перечислением и получением шага. Индексированный профиль, данные шагов которого истекли, сообщает о недоступности. Списки шагов Gradle включают кэшированные и пропущенные операции с нулевой длительностью.

| `list_build_entities` | Перечисляет задачи, модули, действия или файлы одного вида, обнаруженные в сборках проекта. | `account_handle`, `project_handle`, `kind` |
| `get_build_entity` | Получает одну сущность сборки с ее нативным идентификатором и аналитикой за выбранный период. | `account_handle`, `project_handle`, `kind`, `id` |
| `list_build_entity_history` | Перечисляет записанные выполнения, компиляции или события кэша одной сущности сборки, начиная с самых новых. | `account_handle`, `project_handle`, `kind`, `id` |

| `kind` | Инструментарий | Списки истории |
| --- | --- | --- |
| `bazel_actions` | Действия Bazel | Выполнения действий, сообщенные через BEP |
| `gradle_tasks` | Задачи Gradle | Выполнения задач |
| `xcode_modules` | Модули Xcode | Компиляции и события кэша модулей |
| `once_actions` | Действия Once | Выполнения |
| `mix_files` | Компилированные файлы Mix | Компиляции |
| `mix_modules` | Компилированные модули Mix | Компиляции |

Эти инструменты внедряются постепенно и возвращают данные только для проектов, где они включены; для остальных проектов возвращается ошибка вместо пустого результата. Вид доступен только для проектов, использующих соответствующий инструментарий сборки. Инструменты принимают ограниченные фильтры `start_at`/`end_at`, `environment` (`any`, `ci` или `local`) и точное значение `branch`. `list_build_entities` принимает `q`; `list_build_entity_history` поддерживает непрозрачные курсоры `after`/`before`. Неизвестные данные о времени выполнения или наблюдения кэша остаются недоступными, а не превращаются в нули или промахи. История ссылается на записанного родителя и нативное выполнение для детализации с использованием существующих инструментов запусков.

Метрики `get_build_entity` включают `duration_samples` — количество наблюдений с записанным временем: подлинные нулевые длительности учитываются, отсутствующее время — нет. Это число может быть меньше количества наблюдений; недоступная статистика длительности остается равной null.

Длительности модулей Xcode берутся из измеренных компиляций целей в журналах сборки. Разрешения кэша модулей и цели без работы по компиляции не вносят вклад в выборки длительности. Наблюдения компиляции ссылаются на сборку Xcode; события кэша ссылаются на команду генерации или кэша.

Действия Bazel идентифицируются по метке цели, мнемонике и настроенному первичному выводу, сохраняя отдельные действия и конфигурации различными без опоры на зависящие от ввода дайджесты кэша. История записывает выполнения, сообщенные через BEP, а не поиски в кэше или этапы трассировки. Полное покрытие выполнения требует `--build_event_publish_all_actions`; доставка артефактов выполняется по мере возможностей, поэтому отсутствующие наблюдения не являются доказательством того, что работа не выполнялась. Старые полезные нагрузки Kura без стабильного идентификатора или начала выполнения по-прежнему принимаются, но не индексируются. Отсутствующие измерения времени окончания остаются недоступными, а подлинные нулевые длительности учитываются.

Длительности модулей Mix измеряют компиляцию содержащего файла, а не независимо измеренную работу модуля. Действия Once используют объявленные слоты цель/возможность/индекс, когда клиент сообщил сопоставления целей; одни лишь диагностические метки не являются стабильными идентификаторами. Существующие клиенты и инструменты уровня запуска поддерживаются без изменений.

Чтения аналитики имеют ограниченные память и время выполнения. Если запрос превышает эти лимиты, инструмент возвращает ошибку вместо создания пустого результата.

Новые наблюдения индексируются после развертывания; эта функция не заполняет ретроспективно существующую телеметрию запусков. Метаданные идентификатора хранятся дольше отдельных наблюдений согласно <.localized_link href="/guides/server/data-retention">политике хранения данных</.localized_link>.

### События

Клиенты, использующие жизненный цикл Model Context Protocol без состояния `2026-07-28`, могут вызывать `events/list` для обнаружения событий и их схем полезной нагрузки:

| Событие | Когда отправляется | Фильтр подписки |
|-------|-----------------|---------------------|
| `test_case.marked_flaky` | Тест-кейс меняется с не нестабильного на нестабильный. | `account_handle`, `project_handle` |
| `build.failed` | Локальная сборка Xcode, Gradle или Bazel или сборка в непрерывной интеграции завершается с ошибкой. | `account_handle`, `project_handle` |
| `test_run.failed` | Локальный запуск тестов или запуск тестов в непрерывной интеграции завершается с ошибкой, включая объединенный шардированный запуск или прерванный запуск. | `account_handle`, `project_handle` |
| `ci_job.failed` | Задание раннера Tuist завершается с ошибкой. | `account_handle` |

Чтобы подписаться, клиент вызывает `events/subscribe` с именем события, идентификаторами, указанными выше в `arguments`, и доставкой `webhook`, содержащей URL-адрес обратного вызова `https://` и секрет подписи `whsec_`. События проекта требуют членства в аккаунте и доступа на чтение к соответствующим данным тестов или сборок; события заданий раннера требуют членства в аккаунте и доступа на чтение к раннеру. Заявленные токены доступа [`auth.md`](https://workos.com/auth-md), заявленные токены аккаунта и разрешения авторизации браузера могут создавать подписки; доставка прекращается, когда связанная учетная запись больше не активна. Каждый пользователь может иметь до 25 активных подписок. Tuist отправляет проверочный запрос на обратный вызов перед сохранением подписки. Обратный вызов должен вернуть объект, содержащий то же значение `challenge`. Подписка действует семь дней по умолчанию, может быть обновлена путем повторной подписки и прекращает доставку при удалении доступа пользователя или учетных данных. Необязательный параметр `ttlMs` ограничен от одного часа до 30 дней. Tuist повторяет попытку вызова обратного вызова при тайм-ауте и отменяет подписку после как минимум трех последовательных тайм-аутов в течение пяти минут; подпишитесь снова после восстановления обратного вызова.

При возникновении события Tuist отправляет его идентификатор ресурса и URL-адрес панели управления на обратный вызов. Ошибки сборки и запуска тестов также включают `is_ci` и `git_branch`, поэтому клиенты могут игнорировать локальные ошибки или фильтровать по ветви. События сборки включают `build_system`; события заданий раннера включают как `workflow_job_id`, так и `workflow_run_id`. Запрос включает идентификатор подписки и заголовки подписи [Standard Webhooks](https://www.standardwebhooks.com/), чтобы клиент мог проверить его источник. Tuist повторяет неудачные доставки, поэтому клиентам следует использовать стабильный `eventId` для отклонения дубликатов. Полезная нагрузка не содержит имен тестов, журналов и сообщений об ошибках; клиент может получить эти детали через инструменты выше и решить, уведомлять ли команду или начать отладку. Клиенты могут остановить доставку с помощью `events/unsubscribe`.

Подсказки с данными проекта принимают `account_handle` и `project_handle`, чтобы ограничить исследование конкретным проектом. Подсказки сравнения также принимают аргументы `base` и `head`, чтобы указать два элемента для сравнения (по ID, URL-адресу панели управления или имени ветви). `ask_tuist` принимает `question` вместо параметров проекта. `integrate_gradle_project` также принимает `features` — список интеграций Gradle через запятую: `remote_cache`, `build_insights`, `test_insights`, `flaky_tests` и `test_sharding`. `integrate_bazel_project` принимает необязательный `server_url` для самостоятельного развертывания или локальных установок. `integrate_xcode_project` принимает `features` с `xcode_cache`, `build_insights`, `test_insights` и `test_sharding`.

#### Возможности подсказки интеграции Gradle

Подсказка `integrate_gradle_project` и инструмент `get_gradle_integration_guide` документируют полный рабочий процесс настройки. Инструмент также упоминается в инструкциях инициализации сервера, что делает его обнаруживаемым агентами, которые не перечисляют подсказки.

| Возможность | Что настраивает агент |
|---------|---------------------------|
| `remote_cache` | Включает кэш сборки Gradle, настраивает политику загрузки удаленного кэша Tuist и рекомендует загружать данные только с раннеров непрерывной интеграции с локальным доступом только для чтения. |
| `build_insights` | Применяет плагин Tuist Gradle и при необходимости настраивает поведение загрузки аналитики сборки. |
| `test_insights` | Применяет плагин Tuist Gradle, чтобы результаты задач Gradle `Test` автоматически загружались. |
| `flaky_tests` | Помогает настроить обнаружение нестабильных тестов, опциональное использование плагина Gradle Test Retry и конфигурацию карантина тестов. |

| `build_insights` | Настраивает `tuist inspect build`, `tuist xcodebuild`, `-resultBundlePath` и опциональные метрики машины через `tuist setup insights`. |
| `test_insights` | Настраивает `tuist inspect test`, пост-действия тестирования схем и генерацию бандлов результатов для запусков тестов непрерывной интеграции. |
| `test_sharding` | Добавляет планирование шардов для Xcode или сгенерированного проекта и рабочий процесс выполнения шардов с `TUIST_SHARD_INDEX`. |

Если `features` пропущен, подсказка просит агента уточнить, какие интеграции нужны пользователю, или вывести минимально полезный набор из запроса перед редактированием проекта Xcode.
