# Хеширование {#hashing}

Такие возможности, как <.localized_link href="/guides/features/cache">кэширование</.localized_link> или выборочное тестирование, требуют способа определить, изменилась ли цель. Tuist вычисляет хеш для каждой цели в графе зависимостей, чтобы понять, была ли она изменена. Хеш рассчитывается на основе следующих атрибутов:

- Атрибуты цели (например, имя, платформа, продукт и т. д.)
- Файлы цели
- Хеш зависимостей цели

### Атрибуты кэша {#cache-attributes}

Кроме того, при вычислении хеша для <.localized_link href="/guides/features/cache">кэширования</.localized_link> мы также хешируем следующие атрибуты.

#### Версия Swift {#swift-version}

Мы хешируем версию Swift, полученную при выполнении команды `/usr/bin/xcrun swift --version`, чтобы избежать ошибок компиляции из-за несоответствия версий Swift между целями и бинарными файлами.

> [!NOTE]
> **Стабильность модулей**
>
> Предыдущие версии бинарного кэширования опирались на параметр сборки `BUILD_LIBRARY_FOR_DISTRIBUTION` для включения [стабильности модулей](https://www.swift.org/blog/library-evolution#enabling-library-evolution-support) и использования бинарных файлов с любой версией компилятора. Однако это вызывало проблемы компиляции в проектах с целями, которые не поддерживают стабильность модулей. Сгенерированные бинарные файлы привязаны к версии Swift, использованной для их компиляции, и эта версия должна совпадать с той, что используется для компиляции проекта.


#### Конфигурация {#configuration}

При вычислении хешей кэша Tuist применяет настройки каждого проекта и цели к разрешённой конфигурации сборки. Это конфигурация, указанная через `--configuration`, иначе — `defaultConfiguration` проекта, иначе — первая отладочная конфигурация. Tuist хеширует имя этой конфигурации, вариант, параметры сборки и содержимое файла конфигурации вместе с общими базовыми настройками, которые к ней применяются. Добавление, удаление или изменение другой конфигурации не влияет на хеши кэша разрешённой конфигурации. Поскольку важна только разрешённая конфигурация, кэш, заполненный с явным указанием `--configuration`, доступен команде, которая разрешает ту же конфигурацию без передачи этого флага.

## Отладка {#debugging}

Если вы замечаете недетерминированное поведение при использовании кэширования в разных окружениях или запусках, это может быть связано с различиями между окружениями или ошибкой в логике хеширования. Рекомендуем выполнить следующие шаги для отладки проблемы:

1. Выполните `tuist hash cache` или `tuist hash selective-testing` (хеши для <.localized_link href="/guides/features/cache">бинарного кэширования</.localized_link> или <.localized_link href="/guides/features/selective-testing">выборочного тестирования</.localized_link>), скопируйте хеши, переименуйте директорию проекта и снова выполните команду. Хеши должны совпасть.
2. Если хеши не совпадают, скорее всего, сгенерированный проект зависит от окружения. Выполните `tuist graph --format json` в обоих случаях и сравните графы. Альтернативно, сгенерируйте проекты и сравните их файлы `project.pbxproj` с помощью инструмента diff, например [Diffchecker](https://www.diffchecker.com).
3. Если хеши одинаковы, но различаются между окружениями (например, CI и локальное), убедитесь, что везде используется одна и та же [конфигурация](#configuration) и одна и та же [версия Swift](#swift-version). Версия Swift привязана к версии Xcode, поэтому проверьте, что версии Xcode совпадают.

Если хеши по-прежнему недетерминированы, сообщите нам об этом, и мы поможем с отладкой.


> [!NOTE]
> **Планируется улучшение опыта отладки**
>
> Улучшение опыта отладки входит в наш план развития. Команда print-hashes, которой не хватает контекста для понимания различий, будет заменена более удобной командой, использующей древовидную структуру для отображения различий между хешами.
