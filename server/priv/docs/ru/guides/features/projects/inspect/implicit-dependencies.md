# Неявные импорты {#implicit-imports}

Чтобы упростить поддержку графа проектов Xcode при работе с «сырыми» проектами Xcode, Apple спроектировала систему сборки так, чтобы зависимости можно было определять неявно. Это означает, что продукт, например приложение, может зависеть от фреймворка даже без явного объявления этой зависимости. В небольших проектах это нормально, но по мере усложнения графа проекта неявность может проявляться в виде ненадёжных инкрементальных сборок или проблем с функциями редактора, такими как предпросмотры или автодополнение кода.

Проблема в том, что вы не можете предотвратить возникновение неявных зависимостей. Любой разработчик может добавить оператор `import` в свой код на Swift, и неявная зависимость будет создана. Здесь на помощь приходит Tuist. Tuist предоставляет команду для проверки неявных зависимостей путём статического анализа кода вашего проекта. Следующая команда выведет список неявных зависимостей вашего проекта:

```bash
tuist inspect dependencies --only implicit
```

Если команда обнаруживает какие-либо неявные импорты, она завершается с кодом выхода, отличным от нуля.

> [!TIP]
> **Проверка в CI**
>
> Мы настоятельно рекомендуем запускать эту команду как часть вашего процесса <.localized_link href="/guides/integrations/continuous-integration">непрерывной интеграции</.localized_link> каждый раз, когда новый код отправляется в репозиторий.


> [!WARNING]
> **Обнаруживаются не все неявные случаи**
>
> Поскольку Tuist полагается на статический анализ кода для обнаружения неявных зависимостей, он может пропустить некоторые случаи. Например, Tuist не способен распознать условные импорты через директивы компилятора в коде.
