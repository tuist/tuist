# Неявные импорты {#implicit-imports}

Чтобы упростить поддержку графа проектов Xcode на основе обычных файлов проектов, Apple спроектировала систему сборки так, чтобы зависимости можно было определять неявно. Это означает, что продукт, например приложение, может зависеть от фреймворка, даже если зависимость не объявлена явно. В небольших проектах это допустимо, но по мере усложнения графа проекта неявность может проявляться в виде ненадёжных инкрементальных сборок или функций редактора, таких как предварительный просмотр или автодополнение кода.

Проблема в том, что нельзя предотвратить появление неявных зависимостей. Любой разработчик может добавить оператор `import` в свой код на Swift, и неявная зависимость будет создана. Здесь на помощь приходит Tuist. Tuist предоставляет команду для проверки неявных зависимостей путём статического анализа кода вашего проекта. Следующая команда выведет список неявных зависимостей вашего проекта:

```bash
tuist inspect dependencies --only implicit
```

Если команда обнаруживает какие-либо неявные импорты, она завершается с кодом выхода, отличным от нуля.

> [!TIP]
> **Проверять в CI**
>
> Мы настоятельно рекомендуем запускать эту команду в составе процесса <.localized_link href="/guides/integrations/continuous-integration">непрерывной интеграции</.localized_link> каждый раз, когда новый код отправляется в репозиторий.


> [!WARNING]
> **Не все случаи неявных зависимостей обнаруживаются**
>
> Поскольку Tuist опирается на статический анализ кода для выявления неявных зависимостей, он может пропустить некоторые случаи. Например, Tuist не способен распознать условные импорты через директивы компилятора в коде.
