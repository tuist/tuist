# Неявные импорты {#implicit-imports}

Чтобы снизить сложность поддержки графа проектов Xcode в «сырых» проектах, Apple спроектировала систему сборки так, чтобы зависимости могли определяться неявно. Это означает, что продукт, например приложение, может зависеть от фреймворка, даже если зависимость не объявлена явно. В небольших масштабах это нормально, но по мере усложнения графа проекта неявность может приводить к нестабильным инкрементальным сборкам или проблемам с функциями редактора, такими как предварительный просмотр и автодополнение кода.

Проблема в том, что вы не можете предотвратить появление неявных зависимостей. Любой разработчик может добавить оператор `import` в свой код на Swift, и неявная зависимость будет создана. Здесь на помощь приходит Tuist. Tuist предоставляет команду для проверки неявных зависимостей путем статического анализа кода вашего проекта. Следующая команда выведет список неявных зависимостей вашего проекта:

```bash
tuist inspect dependencies --only implicit
```

Если команда обнаружит какие-либо неявные импорты, она завершится с кодом выхода, отличным от нуля.

> [!TIP]
> **Проверка в CI**
>
> Мы настоятельно рекомендуем запускать эту команду в рамках процесса <.localized_link href="/guides/integrations/continuous-integration">непрерывной интеграции</.localized_link> каждый раз, когда новый код отправляется в репозиторий.


> [!WARNING]
> **Обнаруживаются не все неявные случаи**
>
> Поскольку Tuist полагается на статический анализ кода для выявления неявных зависимостей, он может пропустить некоторые случаи. Например, Tuist не способен обрабатывать условные импорты через директивы компилятора в коде.
