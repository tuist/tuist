# Сгенерированные файлы {#synthesized-files}

Tuist может генерировать файлы и код на этапе генерации проекта, чтобы упростить управление и работу с проектами Xcode. На этой странице вы узнаете об этой функциональности и о том, как использовать её в своих проектах.

## Ресурсы таргетов {#target-resources}

Проекты Xcode поддерживают добавление ресурсов к таргетам. Однако это создаёт для команд ряд сложностей, особенно при работе с модульным проектом, где исходный код и ресурсы часто перемещаются:

- **Несогласованный доступ во время выполнения**: место размещения ресурсов в конечном продукте и способ доступа к ним зависят от типа продукта таргета. Например, если ваш таргет представляет собой приложение, ресурсы копируются в бандл приложения. Это приводит к тому, что код, обращающийся к ресурсам, делает предположения о структуре бандла, что нежелательно, так как усложняет понимание кода и перемещение ресурсов.
- **Продукты, не поддерживающие ресурсы**: некоторые типы продуктов, такие как статические библиотеки, не являются бандлами и поэтому не поддерживают ресурсы. Из-за этого приходится использовать другой тип продукта, например фреймворки, что может добавить накладные расходы вашему проекту или приложению. Например, статические фреймворки линкуются статически к конечному продукту, и требуется этап сборки, чтобы скопировать только ресурсы в конечный продукт. Или динамические фреймворки, где Xcode копирует и бинарный файл, и ресурсы в конечный продукт, но это увеличивает время запуска приложения, поскольку фреймворк нужно загружать динамически.
- **Склонность к ошибкам времени выполнения**: ресурсы идентифицируются по имени и расширению (строкам). Поэтому опечатка в любом из них приведёт к ошибке времени выполнения при попытке доступа к ресурсу. Это нежелательно, потому что ошибка не обнаруживается на этапе компиляции и может привести к сбоям в релизной сборке.

Tuist решает указанные выше проблемы, **синтезируя единый интерфейс для доступа к бандлам и ресурсам**, который абстрагирует детали реализации.

> [!WARNING]
> **Рекомендуется**
>
> Хотя доступ к ресурсам через синтезированный Tuist интерфейс не является обязательным, мы рекомендуем его, потому что это упрощает понимание кода и перемещение ресурсов.


## Ресурсы {#resources}

Tuist предоставляет интерфейсы для объявления содержимого файлов, таких как `Info.plist` или entitlements, на Swift. Это полезно для обеспечения согласованности между таргетами и проектами и позволяет компилятору выявлять проблемы на этапе компиляции. Вы также можете создать собственные абстракции для моделирования содержимого и использовать их в разных таргетах и проектах.

При генерации вашего проекта Tuist синтезирует содержимое этих файлов и записывает их в директорию `Derived` относительно директории, содержащей проект, который их определяет.

> [!TIP]
> **Добавьте директорию Derived в .gitignore**
>
> Мы рекомендуем добавить директорию `Derived` в файл `.gitignore` вашего проекта.


## Аксессоры бандлов {#bundle-accessors}

Tuist синтезирует интерфейс для доступа к бандлу, содержащему ресурсы таргета.

### Swift {#swift}

Таргет будет содержать расширение типа `Bundle`, которое предоставляет доступ к бандлу:

```swift
let bundle = Bundle.module
```

### Objective-C {#objectivec}

В Objective-C вы получите интерфейс `{Target}Resources` для доступа к бандлу:

```objc
NSBundle *bundle = [MyFeatureResources bundle];
```

> [!WARNING]
> **Ограничение для внутренних таргетов**
>
> В настоящее время Tuist не генерирует аксессоры бандлов ресурсов для внутренних таргетов, содержащих только исходный код на Objective-C. Это известное ограничение, отслеживаемое в [issue #6456](https://github.com/tuist/tuist/issues/6456).


> [!TIP]
> **Поддержка ресурсов в библиотеках через бандлы**
>
> Если продукт таргета, например библиотека, не поддерживает ресурсы, Tuist включит ресурсы в таргет с типом продукта `bundle`, гарантируя, что они попадут в конечный продукт и что интерфейс будет указывать на правильный бандл. Эти синтезированные бандлы автоматически помечаются тегом `tuist:synthesized` и наследуют все теги от родительского таргета, что позволяет целевым образом использовать их в <.localized_link href="/guides/features/projects/metadata-tags#system-tags">профилях кэша</.localized_link>.


## Аксессоры ресурсов {#resource-accessors}

Ресурсы идентифицируются по имени и расширению с помощью строк. Это нежелательно, потому что ошибки не обнаруживаются на этапе компиляции и могут привести к сбоям в релизной сборке. Чтобы предотвратить это, Tuist интегрирует [SwiftGen](https://github.com/SwiftGen/SwiftGen) в процесс генерации проекта для синтеза интерфейса доступа к ресурсам. Благодаря этому вы можете уверенно обращаться к ресурсам, используя компилятор для выявления любых проблем.

Tuist включает [шаблоны](https://github.com/tuist/tuist/tree/main/cli/Sources/TuistGenerator/Templates) для синтеза аксессоров следующих типов ресурсов по умолчанию:

| Тип ресурса | Сгенерированный файл |
| --- | ---- |
| Изображения и цвета | `Assets+{Target}.swift` |
| Строки | `Strings+{Target}.swift` |
| Plist-файлы | `{NameOfPlist}.swift` |
| Шрифты | `Fonts+{Target}.swift` |
| Файлы | `Files+{Target}.swift` |

> Примечание: вы можете отключить синтез аксессоров ресурсов для конкретного проекта, передав опцию `disableSynthesizedResourceAccessors` в настройки проекта.

### Пользовательские шаблоны {#custom-templates}

Если вы хотите предоставить собственные шаблоны для синтеза аксессоров к другим типам ресурсов, которые должны поддерживаться [SwiftGen](https://github.com/SwiftGen/SwiftGen), вы можете создать их по пути `Tuist/ResourceSynthesizers/{name}.stencil`, где имя — это версия названия ресурса в camelCase.

| Ресурс | Имя шаблона |
| --- | --- |
| строки | `Strings.stencil` |
| ресурсы | `Assets.stencil` |
| plist-файлы | `Plists.stencil` |
| шрифты | `Fonts.stencil` |
| coreData | `CoreData.stencil` |
| interfaceBuilder | `InterfaceBuilder.stencil` |
| json | `JSON.stencil` |
| yaml | `YAML.stencil` |
| файлы | `Files.stencil` |

Если вы хотите настроить список типов ресурсов, для которых нужно синтезировать аксессоры, используйте свойство `Project.resourceSynthesizers`, передав список нужных синтезаторов ресурсов:

```swift
let project = Project(name: "App", resourceSynthesizers: [.strings(), .fonts()])
```

> [!NOTE]
> **Справочник**
>
> Вы можете посмотреть [этот пример](https://github.com/tuist/tuist/tree/main/examples/xcode/generated_ios_app_with_templates), чтобы увидеть, как использовать пользовательские шаблоны для синтеза аксессоров к ресурсам.
