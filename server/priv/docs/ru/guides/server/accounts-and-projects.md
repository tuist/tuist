# Аккаунты и проекты {#accounts-and-projects}

Некоторые возможности Tuist требуют сервера, который обеспечивает сохранение данных и может взаимодействовать с другими сервисами. Для работы с сервером вам нужен аккаунт и проект, который вы подключите к своему локальному проекту.

## Аккаунты {#accounts}

Чтобы использовать сервер, вам понадобится аккаунт. Существует два типа аккаунтов:

- **Личный аккаунт:** такие аккаунты создаются автоматически при регистрации и идентифицируются по хендлу, который получается либо от провайдера идентификации (например, GitHub), либо из первой части адреса электронной почты.
- **Аккаунт организации:** такие аккаунты создаются вручную и идентифицируются по хендлу, который задаёт разработчик. Организации позволяют приглашать других участников для совместной работы над проектами.

Если вы знакомы с [GitHub](https://github.com), концепция похожа: у вас могут быть личные аккаунты и аккаунты организаций, и они идентифицируются *хендлом*, который используется при формировании URL-адресов.

Вы можете управлять организацией через подкоманды раздела <.localized_link href="/cli/organization">`tuist organization`</.localized_link>. Чтобы создать новый аккаунт организации, выполните:
```bash
tuist organization create {account-handle}
```

### Членство в организации {#organization-membership}

Пользователи могут стать участниками организации по приглашению, через автоматическую регистрацию по единому входу или через <.localized_link href="/guides/integrations/authentication/scim">предоставление доступа по протоколу SCIM</.localized_link>.

Аутентификация через провайдер идентификации организации сама по себе не даёт членства. <.localized_link href="/guides/integrations/authentication/sso#choose-an-enrollment-policy">Политика регистрации по единому входу</.localized_link> организации определяет, нужно ли пользователю из доверенного домена приглашение или он может присоединиться автоматически.

Администраторы могут пригласить участника из панели управления или с помощью <.localized_link href="/cli/organization/invite">`tuist organization invite`</.localized_link>. Передайте `--role admin` или `--role viewer`, чтобы назначить приглашённому роль, отличную от `user`, когда он примет приглашение.

### Роли {#roles}

Каждый участник организации имеет одну из трёх ролей:

| Роль | Что она предоставляет |
| --- | --- |
| **Администратор** | Всё, что может делать пользователь, плюс управление организацией: участниками и приглашениями, проектами, биллингом, токенами, вебхуками и настройками. |
| **Пользователь** | Чтение и выполнение действий в рамках работы организации: запуск сборок и тестов, запись в кэш, создание и удаление превью, а также изменение состояния тест-кейса. |
| **Наблюдатель** | Только чтение работы организации без внесения изменений. Доступны для чтения панели управления, сборки, прогоны тестов, нестабильные и помещённые в карантин тесты, превью, бандлы и активность раннеров. Подключение интерактивной оболочки или VNC-сессии к раннеру недоступно, потому что это выполняет команды на машине. |

Выберите роль при приглашении пользователя и измените её позже в разделе **Участники** панели управления. Роль, заданная таким образом, никогда не перезаписывается при последующем входе.

## Проекты {#projects}

Ваши проекты необходимо интегрировать с вашим аккаунтом через удалённый проект. Продолжая сравнение с GitHub, это похоже на наличие локального и удалённого репозиториев, куда вы отправляете свои изменения. Вы можете использовать <.localized_link href="/cli/project">`tuist project`</.localized_link> для создания и управления проектами.

Проекты идентифицируются полным хендлом, который получается объединением хендла организации и хендла проекта. Например, если у вас есть организация с хендлом `tuist` и проект с хендлом `tuist`, полный хендл будет `tuist/tuist`.

Связь между локальным и удалённым проектом выполняется через файл конфигурации. Если его нет, создайте файл `Tuist.swift` и добавьте следующее содержимое:

```swift
let tuist = Tuist(fullHandle: "{account-handle}/{project-handle}") // e.g. tuist/tuist
```

> [!WARNING]
> **Возможности, доступные только для проектов Tuist**
>
> Обратите внимание, что некоторые возможности, например <.localized_link href="/guides/features/cache/module-cache">кэширование модулей</.localized_link>, требуют проекта, управляемого Tuist. Если вы не используете Tuist для управления своим проектом, эти возможности будут недоступны.


URL-адрес вашего проекта формируется с использованием полного хендла. Например, публичная панель управления Tuist доступна по адресу [tuist.dev/tuist/tuist](https://tuist.dev/tuist/tuist), где `tuist/tuist` — полный хендл проекта.
