# Аккаунты и проекты {#accounts-and-projects}

Некоторые функции Tuist требуют сервера, который обеспечивает сохранение данных и может взаимодействовать с другими сервисами. Для взаимодействия с сервером вам нужен аккаунт и проект, который вы подключите к своему локальному проекту.

## Аккаунты {#accounts}

Чтобы использовать сервер, вам понадобится аккаунт. Существует два типа аккаунтов:

- **Личный аккаунт:** Эти аккаунты создаются автоматически при регистрации и идентифицируются по хендлу, который получается либо от провайдера идентификации (например, GitHub), либо из первой части адреса электронной почты.
- **Организационный аккаунт:** Эти аккаунты создаются вручную и идентифицируются по хендлу, который определяется разработчиком. Организации позволяют приглашать других участников для совместной работы над проектами.

Если вы знакомы с [GitHub](https://github.com), концепция аналогична их: у вас могут быть личные и организационные аккаунты, и они идентифицируются по *хендлу*, который используется при формировании URL-адресов.

> [!NOTE]
> **Сначала CLI**
>
> Большинство операций по управлению аккаунтами и проектами выполняется через CLI. Мы работаем над веб-интерфейсом, который упростит управление аккаунтами и проектами.


Вы можете управлять организацией с помощью подкоманд раздела <.localized_link href="/cli/organization">`tuist organization`</.localized_link>. Чтобы создать новый организационный аккаунт, выполните:
```bash
tuist organization create {account-handle}
```

### Членство в организации {#organization-membership}

Пользователи могут стать членами организации по приглашению, через автоматическую регистрацию единого входа или <.localized_link href="/guides/integrations/authentication/scim">предоставление доступа через System for Cross-domain Identity Management</.localized_link>.

Аутентификация через провайдера идентификации организации сама по себе не предоставляет членство. <.localized_link href="/guides/integrations/authentication/sso#choose-an-enrollment-policy">политика регистрации единого входа</.localized_link> организации определяет, нужно ли пользователю из доверенного домена приглашение или он может присоединиться автоматически.

Администраторы могут пригласить участника из панели управления или с помощью <.localized_link href="/cli/organization/invite">`tuist organization invite`</.localized_link>. Передайте `--role admin` или `--role viewer`, чтобы назначить приглашенному роль, отличную от `user`, когда он примет приглашение.

### Роли {#roles}

Каждый участник организации имеет одну из трех ролей:

| Роль | Что она дает |
| --- | --- |
| **Администратор** | Все, что может делать пользователь, плюс управление организацией: участниками и приглашениями, проектами, биллингом, токенами, вебхуками и настройками. |
| **Пользователь** | Чтение и выполнение действий с работой организации: запуск сборок и тестов, запись в кэш, создание и удаление превью, а также изменение состояния тестового случая. |
| **Наблюдатель** | Чтение работы организации без возможности ее изменения. Панели управления, сборки, запуски тестов, нестабильные и помещенные в карантин тесты, превью, бандлы и активность раннеров доступны только для чтения. Подключение интерактивной оболочки или сеанса VNC к раннеру недоступно, так как это выполняет команды на машине. |

Выберите роль при приглашении кого-либо и измените ее позже в разделе **Участники** в панели управления. Роль, установленная таким образом, никогда не перезаписывается при последующем входе в систему.

## Проекты {#projects}

Ваши проекты должны быть интегрированы с вашим аккаунтом через удаленный проект. Продолжая сравнение с GitHub, это похоже на наличие локального и удаленного репозитория, куда вы отправляете свои изменения. Вы можете использовать <.localized_link href="/cli/project">`tuist project`</.localized_link> для создания и управления проектами.

Проекты идентифицируются полным хендлом, который является результатом объединения хендла организации и хендла проекта. Например, если у вас есть организация с хендлом `tuist` и проект с хендлом `tuist`, полный хендл будет `tuist/tuist`.

Связь между локальным и удаленным проектом осуществляется через файл конфигурации. Если у вас его нет, создайте его по пути `Tuist.swift` и добавьте следующее содержимое:

```swift
let tuist = Tuist(fullHandle: "{account-handle}/{project-handle}") // e.g. tuist/tuist
```

> [!WARNING]
> **Функции, доступные только для проектов Tuist**
>
> Обратите внимание, что некоторые функции, такие как <.localized_link href="/guides/features/cache/module-cache">кэширование модулей</.localized_link>, требуют проекта, управляемого Tuist. Если вы не используете Tuist для управления своим проектом, вы не сможете использовать эти функции.


URL-адрес вашего проекта формируется с использованием полного хендла. Например, панель управления Tuist, которая является публичной, доступна по адресу [tuist.dev/tuist/tuist](https://tuist.dev/tuist/tuist), где `tuist/tuist` — полный хендл проекта.
