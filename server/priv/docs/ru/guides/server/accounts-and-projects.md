# Аккаунты и проекты {#accounts-and-projects}

Некоторые возможности Tuist требуют сервера, который обеспечивает сохранение данных и может взаимодействовать с другими сервисами. Для работы с сервером вам нужен аккаунт и проект, который вы подключите к своему локальному проекту.

## Аккаунты {#accounts}

Чтобы использовать сервер, вам понадобится аккаунт. Есть два типа аккаунтов:

- **Личный аккаунт:** такие аккаунты создаются автоматически при регистрации и идентифицируются по хэндлу, который получается либо от провайдера идентификации (например, GitHub), либо из первой части адреса электронной почты.
- **Аккаунт организации:** такие аккаунты создаются вручную и идентифицируются по хэндлу, который задаёт разработчик. Организации позволяют приглашать других участников для совместной работы над проектами.

Если вы знакомы с [GitHub](https://github.com), концепция похожа: у вас могут быть личные аккаунты и аккаунты организаций, и они идентифицируются по *хэндлу*, который используется при формировании URL-адресов.

Вы можете управлять организацией через подкоманды раздела <.localized_link href="/cli/organization">`tuist organization`</.localized_link>. Чтобы создать новый аккаунт организации, выполните:
```bash
tuist organization create {account-handle}
```

### Членство в организации {#organization-membership}

Пользователи могут стать членами организации по приглашению, через автоматическую регистрацию по единому входу (SSO) или через <.localized_link href="/guides/integrations/authentication/scim">предоставление доступа по протоколу System for Cross-domain Identity Management (SCIM)</.localized_link>.

Аутентификация через провайдера идентификации организации сама по себе не даёт членства. <.localized_link href="/guides/integrations/authentication/sso#choose-an-enrollment-policy">Политика регистрации по единому входу (SSO)</.localized_link> организации определяет, нужен ли пользователю из доверенного домена приглашение или он может присоединиться автоматически.

Администраторы могут пригласить участника из дашборда или с помощью <.localized_link href="/cli/organization/invite">`tuist organization invite`</.localized_link>. Передайте `--role admin` или `--role viewer`, чтобы назначить приглашённому роль, отличную от `user`, когда он примет приглашение.

### Роли {#roles}

Каждый участник организации имеет одну из трёх ролей:

| Роль | Что она предоставляет |
| --- | --- |
| **Администратор** | Всё, что доступно пользователю, плюс управление организацией: участниками и приглашениями, проектами, биллингом, токенами, вебхуками и настройками. |
| **Пользователь** | Чтение и выполнение действий в рамках организации: запуск сборок и тестов, запись в кэш, создание и удаление превью, а также изменение состояния тест-кейса. |
| **Наблюдатель** | Только чтение данных организации без возможности их изменения. Дашборды, сборки, прогоны тестов, нестабильные и помещённые в карантин тесты, превью, бандлы и активность раннеров доступны для просмотра. Подключение интерактивной оболочки или VNC-сессии к раннеру недоступно, потому что это выполняет команды на машине. |

Выберите роль при приглашении пользователя и измените её позже в разделе **Участники** дашборда. Роль, заданная таким образом, никогда не перезаписывается при последующем входе.

## Проекты {#projects}

Ваши проекты нужно интегрировать с аккаунтом через удалённый проект. Продолжая аналогию с GitHub, это похоже на наличие локального и удалённого репозиториев, куда вы отправляете свои изменения. Для создания и управления проектами используйте <.localized_link href="/cli/project">`tuist project`</.localized_link>.

Проекты идентифицируются полным хэндлом, который образуется путём объединения хэндла организации и хэндла проекта. Например, если у вас есть организация с хэндлом `tuist` и проект с хэндлом `tuist`, полный хэндл будет `tuist/tuist`.

Связь между локальным и удалённым проектом настраивается через файл конфигурации. Если его нет, создайте файл `Tuist.swift` и добавьте следующее содержимое:

```swift
let tuist = Tuist(fullHandle: "{account-handle}/{project-handle}") // e.g. tuist/tuist
```

> [!WARNING]
> **Возможности, доступные только для проектов Tuist**
>
> Обратите внимание, что некоторые возможности, такие как <.localized_link href="/guides/features/cache/module-cache">кэширование модулей</.localized_link>, требуют проекта, управляемого Tuist. Если вы не используете Tuist для управления проектом, эти возможности будут недоступны.


URL-адрес вашего проекта формируется с использованием полного хэндла. Например, публичный дашборд Tuist доступен по адресу [tuist.dev/tuist/tuist](https://tuist.dev/tuist/tuist), где `tuist/tuist` — полный хэндл проекта.
