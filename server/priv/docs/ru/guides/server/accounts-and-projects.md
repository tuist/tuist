# Аккаунты и проекты {#accounts-and-projects}

Некоторые возможности Tuist требуют сервера, который обеспечивает сохранение данных и может взаимодействовать с другими сервисами. Для взаимодействия с сервером вам нужен аккаунт и проект, который вы подключите к своему локальному проекту.

## Аккаунты {#accounts}

Чтобы использовать сервер, вам понадобится аккаунт. Есть два типа аккаунтов:

- **Личный аккаунт:** такие аккаунты создаются автоматически при регистрации и идентифицируются по хэндлу, который получается либо от провайдера идентификации (например, GitHub), либо из первой части адреса электронной почты.
- **Организационный аккаунт:** такие аккаунты создаются вручную и идентифицируются по хэндлу, который определяет разработчик. Организации позволяют приглашать других участников для совместной работы над проектами.

Если вы знакомы с [GitHub](https://github.com), концепция похожа: у вас могут быть личные и организационные аккаунты, и они идентифицируются по *хэндлу*, который используется при формировании URL-адресов.

> [!NOTE]
> **Сначала CLI**
>
> Большинство операций по управлению аккаунтами и проектами выполняется через CLI. Мы работаем над веб-интерфейсом, который упростит управление аккаунтами и проектами.


Вы можете управлять организацией через подкоманды в разделе <.localized_link href="/cli/organization">`tuist organization`</.localized_link>. Чтобы создать новый организационный аккаунт, выполните:
```bash
tuist organization create {account-handle}
```

### Членство в организации {#organization-membership}

Пользователи могут стать участниками организации по приглашению, через автоматическую регистрацию по единому входу (SSO) или через <.localized_link href="/guides/integrations/authentication/scim">предоставление доступа по протоколу SCIM</.localized_link>.

Аутентификация через поставщик удостоверений организации сама по себе не предоставляет членство. <.localized_link href="/guides/integrations/authentication/sso#choose-an-enrollment-policy">Политика регистрации единого входа</.localized_link> организации определяет, требуется ли пользователю из доверенного домена приглашение или он может присоединиться автоматически.

Администраторы могут пригласить участника из панели управления или с помощью <.localized_link href="/cli/organization/invite">`tuist organization invite`</.localized_link>. Передайте `--role admin` или `--role viewer`, чтобы назначить приглашенному роль, отличную от `user`, когда он примет приглашение.

### Роли {#roles}

Каждый участник организации имеет одну из трех ролей:

| Роль | Что дает |
| --- | --- |
| **Администратор** | Все, что может делать пользователь, плюс управление организацией: участниками и приглашениями, проектами, биллингом, токенами, вебхуками и настройками. |
| **Пользователь** | Чтение и выполнение действий с работой организации: запуск сборок и тестов, запись в кэш, создание и удаление превью, а также изменение состояния тест-кейса. |
| **Наблюдатель** | Только чтение работы организации без внесения изменений. Панели управления, сборки, прогоны тестов, нестабильные и помещенные в карантин тесты, превью, бандлы и активность раннеров доступны для чтения. Подключение интерактивной оболочки или сеанса VNC к раннеру недоступно, потому что это выполняет команды на машине. |

Выберите роль при приглашении пользователя и измените ее позже в разделе **Участники** панели управления. Роль, заданная таким образом, никогда не перезаписывается при последующем входе.

## Проекты {#projects}

Ваши проекты необходимо интегрировать с вашим аккаунтом через удаленный проект. Продолжая сравнение с GitHub, это похоже на наличие локального и удаленного репозиториев, куда вы отправляете свои изменения. Вы можете использовать <.localized_link href="/cli/project">`tuist project`</.localized_link> для создания и управления проектами.

Проекты идентифицируются полным хэндлом, который образуется путем объединения хэндла организации и хэндла проекта. Например, если у вас есть организация с хэндлом `tuist` и проект с хэндлом `tuist`, полный хэндл будет `tuist/tuist`.

Связь между локальным и удаленным проектом устанавливается через файл конфигурации. Если его нет, создайте файл `Tuist.swift` и добавьте следующее содержимое:

```swift
let tuist = Tuist(fullHandle: "{account-handle}/{project-handle}") // e.g. tuist/tuist
```

> [!WARNING]
> **Возможности только для проектов Tuist**
>
> Обратите внимание, что некоторые возможности, такие как <.localized_link href="/guides/features/cache/module-cache">кэширование модулей</.localized_link>, требуют проекта, управляемого Tuist. Если вы не используете Tuist для управления своим проектом, эти возможности будут недоступны.


URL-адрес вашего проекта формируется с использованием полного хэндла. Например, публичная панель управления Tuist доступна по адресу [tuist.dev/tuist/tuist](https://tuist.dev/tuist/tuist), где `tuist/tuist` — полный хэндл проекта.
