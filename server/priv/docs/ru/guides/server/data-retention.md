# Хранение данных {#data-retention}

Tuist применяет отдельные политики хранения для загруженных файлов артефактов и записей, используемых в панелях мониторинга и аналитике. Удаление файла артефакта с истёкшим сроком не приводит к удалению связанных с ним записей аналитики.

Для файлов артефактов размещённый сервер Tuist использует периоды хранения, зависящие от тарифного плана, с ограничением до 30 дней. Очистка артефактов по умолчанию отключена на самостоятельно размещаемых экземплярах, где администраторы могут включить её и настроить отдельный период для каждого поддерживаемого типа артефактов.

## Файлы артефактов {#artifact-files}

### Размещённый сервер Tuist {#hosted-artifact-files}

Эти периоды определяют, как долго файлы артефактов остаются доступными на размещённом сервере Tuist.

| Артефакт | Air и Open Source | Pro | Enterprise |
| --- | --- | --- | --- |
| Артефакты кэша, включая кэш Xcode, кэш модулей, кэш Gradle, файлы удалённого кэша Bazel и архивы кэша GitLab CI от Tuist Runners | 14 дней | 30 дней | 30 дней |
| Сборки предварительного просмотра приложений и значки | 30 дней | 30 дней | 30 дней |
| Архивы сборок | 7 дней | 30 дней | 30 дней |
| Артефакты запуска, включая пакеты результатов и архивы сессий | 7 дней | 30 дней | 30 дней |
| Вложения запусков тестов | 30 дней | 30 дней | 30 дней |
| Пакеты шардов | 7 дней | 14 дней | 30 дней |

Активный тарифный план аккаунта определяет период хранения на размещённом сервере. Если у аккаунта нет активной подписки, Tuist использует период хранения тарифа Air. Для некоторых типов артефактов применяются более короткие периоды, поскольку они предполагаются к повторной генерации.

Вложения тестов, созданные до того, как Tuist зафиксировал идентификатор запуска теста, исключаются из автоматического удаления. Их файлы остаются доступными, пока Tuist избегает неограниченного поиска исторических данных о владельцах во время очистки хранения.

### Самостоятельно размещаемые экземпляры {#self-hosted-artifact-files}

Очистка артефактов на самостоятельно размещаемых экземплярах включается опционально, настраивается отдельно для каждого типа артефактов и не ограничена 30 днями. См. <.localized_link href="/guides/server/self-host/server#artifact-retention">конфигурацию хранения артефактов для самостоятельного размещения</.localized_link>, чтобы узнать о поддерживаемых типах артефактов и вариантах развёртывания.

## Данные панели мониторинга и активности {#dashboard-and-activity-data}

Записи панели мониторинга и активности имеют политики хранения, независимые от очистки файлов артефактов. Периоды ниже не зависят от размещённого тарифного плана, включая Enterprise.

### Аналитика сборок и тестов Xcode {#xcode-build-and-test-insights}

Основные записи сборок и тестов Xcode в настоящее время не имеют фиксированного расписания удаления по времени. Другие данные отчётов, такие как шаги временной шкалы и метрики машин, истекают отдельно:

| Данные | Хранение |
| --- | --- |
| Сводки сборок, записи сборок по файлам и целям, а также проблемы сборки | Нет фиксированного расписания удаления по времени |
| Запуски тестов, результаты модулей и наборов, а также результаты отдельных тестов | Нет фиксированного расписания удаления по времени |
| Шаги временной шкалы сборки и их захваченные логи | 90 дней |
| Метрики машины сборки | 90 дней |
| Записи графа проекта Xcode | 30 дней |

Эти записи отделены от загружаемых архивов сборок, пакетов результатов и вложений тестов, на которые распространяются [периоды хранения файлов артефактов](#hosted-artifact-files). На тарифе Enterprise эти файлы хранятся 30 дней; связанные записи сборок и тестов остаются доступными после истечения срока хранения файлов. Отсутствие фиксированного расписания удаления по времени не гарантирует постоянного доступа.

### Другие данные панели мониторинга и активности {#other-dashboard-and-activity-data}

Индексированные шаги профиля Bazel включают необязательные времена ожидания в удалённой очереди, получения входных данных, выполнения и выгрузки результатов для каждого действия, когда их можно безопасно связать с действием. Они разделяют 90-дневный период хранения профиля, независимо от кэшированных артефактов и записей биллинга.

| Данные | Хранение |
| --- | --- |
| Записи сборок Gradle, записи задач и сообщения об ошибках неудавшихся задач и шагов конфигурации, записи событий кэша, записи сборок Mix, записи скомпилированных файлов, записи шагов сборки и диагностика, записи сборок Cargo (включая агрегированные измерения кэша компиляции) и наблюдения компилятора, вызовы Bazel, профили трассировки Bazel, индексированные шаги профиля и диагностика действий, ожидающие обработки записи профилей и тестов Bazel, логи вызовов Bazel и наблюдения удалённого кэша действий Bazel | 90 дней |
| Начала вызовов Bazel, которые отображают их как выполняющиеся до завершения | 2 дня |
| История компиляции модулей Xcode и кэша на постоянных страницах деталей модулей | 30 дней |
| Наблюдения за задачами, объявленными действиями Struo, действиями Bazel BEP, скомпилированными файлами и модулями на постоянных страницах деталей | 90 дней, кроме модулей Xcode выше |
| Постоянные метаданные идентичности задач/действий/модулей/файлов | 365 дней без наблюдений |
| Логи заданий раннера, архивные логи раннера и метрики машин заданий раннера | 90 дней |
| Детализация покрытия кода по строкам (покрытие каждой строки и функции каждого запуска теста, отображаемое на странице покрытия файла) | 31 день |
| Общие показатели покрытия кода каждого запуска теста | 365 дней |
| Покрытие кода коммита (его общие показатели, цели и показатели по файлам) | 3 года; 90 дней для коммитов, добавленных только пул-реквестом |
| История доставки вебхуков | Нет фиксированного расписания удаления |

Постоянные URL-адреса деталей не зависят от доступности конкретной сборки. Их метаданные идентичности могут сохраняться дольше отдельных наблюдений, поэтому на странице деталей может отсутствовать история за выбранный период. Новая история индексируется из отчётов, полученных после развёртывания функции; существующая история на уровне запусков не копируется ретроспективно.

Внутренние таблицы журналов операций ClickHouse `system.*` настраиваются на уровне ClickHouse, а не политикой хранения данных продукта Tuist. По умолчанию они не имеют ограничений; конфигурации Docker Compose для самостоятельного размещения и встроенные конфигурации Helm для ClickHouse могут устанавливать для них лимиты, как описано в разделе <.localized_link href="/guides/server/self-host/server#capping-operational-log-retention">ограничение срока хранения журналов операций</.localized_link>.
