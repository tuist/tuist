# Установите пакет Hex {#install-the-hex-package}

Tuist предоставляет пакет [Hex](https://hex.pm/packages/tuist_ex) — `tuist_ex`, который интегрируется с вашим проектом на Elixir и открывает доступ к таким возможностям, как <.localized_link href="/guides/features/build-insights/elixir">анализ сборок</.localized_link> и <.localized_link href="/guides/features/test-insights/elixir">анализ тестов</.localized_link>. В этом руководстве показано, как установить и настроить его.

Пакет требует Elixir версии 1.18 или новее. Интерфейс командной строки Tuist не нужен.

## 1. Создайте проект {#create-the-project}

Создайте проект в панели управления Tuist и выберите **Mix (Elixir)** в качестве системы сборки. Его идентификатор `account/project` связывает ваш Mix-проект с ним.

В разделах ниже описаны аутентификация и детали конфигурации.

## 3. Аутентифицируйте команду и непрерывную интеграцию {#authenticate}

Каждый участник команды выполняет следующую команду, чтобы получить доступ к функциям Tuist на своём компьютере:

```bash
mix tuist.login
```

Она выводит короткий код для входа, открывает браузер, куда нужно ввести этот код, и ожидает авторизации. Чтобы войти без браузера, передайте учётные данные:

```bash
mix tuist.login --email person@example.com --password secret
```

Если вы используете самостоятельно размещённый или локальный сервер Tuist, укажите его базовый URL в `mix.exs` или передайте через `--url`:

```bash
mix tuist.login --url http://localhost:8080
```

Сохраняйте единообразие в написании хоста. Например, вход, сохранённый для `localhost`, отличается от входа, сохранённого для `127.0.0.1`.

В GitHub Actions, CircleCI и Bitrise этап входа для непрерывной интеграции не требуется. При первой отправке отчёта задачей токен OpenID Connect провайдера обменивается на токен Tuist. <.localized_link href="/guides/integrations/gitforge/github">Подключите репозиторий GitHub</.localized_link> к проекту Tuist и предоставьте задаче в GitHub Actions разрешение `id-token: write`:

```yaml
jobs:
  test:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      id-token: write
    steps:
      - uses: actions/checkout@v4
      - uses: erlef/setup-beam@v1
        with:
          elixir-version: '1.18'
          otp-version: '27'
      - run: mix deps.get
      - run: mix test
```

Для любого другого поставщика удостоверений OpenID Connect, например Fly.io Machines, настройте политику доверия рабочей нагрузки в разделе **Рабочие удостоверения** на странице **Настройки → Аутентификация** вашего аккаунта. Это даст CI доступ ко всем текущим и будущим проектам, принадлежащим этому аккаунту. Установите `TUIST_OIDC_ACCOUNT` в аккаунт Tuist, которому принадлежит проект, и передайте свежесгенерированный токен удостоверения с аудиторией политики через `TUIST_OIDC_TOKEN`. Интеграция автоматически выполнит обмен, если нет токена аккаунта или действительного сохранённого входа; `mix tuist.login` также принимает его вне CI. Автоматический обмен повторно использует действующую сессию только для того же сервера, аккаунта и переданного токена удостоверения. Смена этого удостоверения запускает новый обмен, а пустой токен приводит к ошибке вместо повторного использования предыдущей сессии. Сессии Tuist действуют один час без токенов обновления, поэтому для долгоживущих задач сгенерируйте новый токен удостоверения и снова выполните `mix tuist.login` до истечения срока сессии. Следуйте инструкциям по <.localized_link href="/guides/server/authentication#workload-identity-trust-policies">настройке рабочих удостоверений</.localized_link> и <.localized_link href="/guides/server/authentication#flyio-machines">примеру для Fly.io</.localized_link>.

Запросы на слияние из форков не получают токен OpenID Connect, поэтому их запуски не отчитываются и завершаются успехом или неудачей как обычно. На других провайдерах установите переменную окружения `TUIST_TOKEN` в токен аккаунта. Следуйте <.localized_link href="/guides/server/authentication#continuous-integration">руководству по аутентификации непрерывной интеграции</.localized_link>, чтобы создать его.

## 4. Продолжайте использовать `mix test` и `mix compile` {#aliases}

<.localized_link href="/guides/get-started/elixir-project#set-up-tuist">Общая настройка</.localized_link> устанавливает для вас алиасы компиляции и тестирования. `mix test test/my_app_test.exs:12 --trace` отчитывается о запуске с тем же выводом и кодом выхода, а интеграция компиляции охватывает сборки, запускаемые через `mix test` или `mix phx.server`. Компиляция, которая не находит работы, не отчитывается.

Задачи также работают при вызове по их собственному имени. Mix запускает задачу, набранную таким образом, в окружении `dev`, поэтому для тестового окружения задача должна перезапуститься во втором процессе. Добавьте задачи в предпочтительные окружения, чтобы избежать этого:

```elixir
def cli do
  [preferred_envs: ["tuist.test": :test, "tuist.test.build": :test]]
end
```

## Справочник по конфигурации {#configuration-reference}

Следующие параметры доступны в разделе `tuist` настроек проекта в файле `mix.exs`:

| Параметр | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `project` | `String` | нет (обязательно) | Идентификатор проекта в формате `account/project`. |
| `url` | `String` | `"https://tuist.dev"` | Базовый URL сервера Tuist. |
| `cache` | `boolean` или список ключевых слов | отключено | Настройка включает кэширование зависимостей. См. <.localized_link href="/guides/features/cache/elixir">кэш Elixir</.localized_link> для исключений и дополнительных входных данных. |
| `test_retries` | `integer` | `0` | Сколько раз повторять упавшие тесты; см. <.localized_link href="/guides/features/test-insights/flaky-tests/elixir#test-retries">повторные запуски тестов</.localized_link>. |
| `tags` | список `String` | `[]` | Теги, прикрепляемые к каждой сборке; см. <.localized_link href="/guides/features/build-insights/elixir#custom-metadata">пользовательские метаданные</.localized_link>. |
| `values` | карта | `%{}` | Данные в виде пар «ключ–значение», прикрепляемые к каждой сборке. |

Переменные окружения имеют приоритет над `mix.exs`:

| Переменная | Описание |
| --- | --- |
| `TUIST_PROJECT` | Идентификатор проекта в формате `account/project`. |
| `TUIST_URL` | Базовый URL сервера Tuist. |
| `TUIST_TOKEN` | Токен для аутентификации вместо сохранённых учётных данных. |
| `TUIST_OIDC_TOKEN` | Недавно выпущенный токен удостоверения OpenID Connect, обмениваемый на токен Tuist. Его аудитория должна быть `tuist` для GitHub Actions и Bitrise или соответствовать рабочей идентичности аккаунта для других провайдеров. Используется `mix tuist.login` или как запасной вариант, когда нет токена аккаунта или действительных сохранённых учётных данных. |
| `TUIST_OIDC_ACCOUNT` | Идентификатор аккаунта Tuist, которому принадлежит проект. Требуется при обмене токена через рабочую идентичность аккаунта. Он выбирает среди существующих рабочих идентичностей и сам по себе не предоставляет доступ. |
| `TUIST_TEST_RETRIES` | Сколько раз повторять упавшие тесты. |
| `TUIST_TAGS` | Теги через запятую, прикрепляемые к сборке. |
| `TUIST_VALUES` | Пары `key=value` через запятую, прикрепляемые к сборке. |
| `TUIST_DEBUG` | Установите значение `1`, чтобы вывести причину, по которой отчёт не удалось отправить. |

Отправка отчётов никогда не меняет код выхода `mix test` или `mix compile`. Если отчёт не удалось отправить, задача ничего не выводит, если не установлен `TUIST_DEBUG=1`.
