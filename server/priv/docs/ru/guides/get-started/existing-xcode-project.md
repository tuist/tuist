# Проект Xcode {#existing-xcode-project}

::: code-group

```text [Agent prompt]
Help me get started with Tuist. Follow the setup at:
https://tuist.dev/en/docs/guides/get-started/existing-xcode-project
```

:::

Выбирайте этот путь, если хотите сохранить `.xcodeproj` и `.xcworkspace` в неизменном виде и подключить возможности Tuist без перехода на генерацию проектов. В каждом разделе ниже сначала описывается, чего сейчас не хватает, а затем показано, какая функция закрывает этот пробел.

## Предварительные требования

- macOS с **Xcode 26 или новее** (кэш компиляции и современные инструменты аналитики зависят от него).
- <.localized_link href="/guides/install-tuist">Интерфейс командной строки Tuist</.localized_link>.

## Подключение проекта

Запустите `tuist init` в корне репозитория. Когда Tuist обнаружит ваше рабочее пространство, выберите **Интегрировать `<YourApp>`**, затем выполните аутентификацию в браузере и выберите аккаунт, которому должен принадлежать проект. Tuist создаст файл `Tuist.swift` в корне, который закрепляет идентификатор проекта, чтобы ваши коллеги и CI использовали одно и то же подключение. Зафиксируйте его в Git.

Если вы запускаете это из агента для написания кода или скрипта, сначала выполните `tuist auth login` (браузерный поток ждет, пока вы нажмете Enter), затем используйте неинтерактивную форму:

```bash
tuist init --build-system xcode --name <project-handle> --account <account>
```

Все нижеперечисленное является опциональным и независимым.

## Кэш компиляции Xcode

Xcode 26 поставляется с кэшем компиляции для каждого файла, но его хранилище находится внутри `DerivedData` машины. Чистая сборка заполняет его локально; коллеги и раннеры CI пересобирают все с нуля, потому что не видят это хранилище.

`tuist setup cache` направляет кэш компиляции Xcode в общую сеть кэша Tuist. Попадание в кэш на любой машине разработчика или в любом запуске CI затем приносит пользу всем остальным машинам, собирающим ту же ревизию.

```bash
tuist setup cache
```

Выполните сборку в Xcode. Очистите Derived Data, запустите сборку еще раз на второй машине или на раннере CI. Вторая сборка завершится за долю времени, а отчет о сборке Xcode покажет попадания в кэш компиляции.

## Аналитика сборок

Xcode записывает длительность сборки для каждой цели в журнал и в отчет о сборке. Эти данные не агрегируются по запускам или по машинам. Регрессия времени сборки, попавшая в один PR, обычно проявляется только как общее замедление CI, без явного сигнала о том, какая цель вызвала это и когда.

Аналитика сборок записывает длительность каждой сборки и время выполнения этапов, чтобы тренд был виден на панели управления. Это одна строка пост-действия в вашей схеме:

1. В Xcode: **Product → Scheme → Edit Scheme…**
2. Разверните **Build → Post-actions**, нажмите **+**, выберите **New Run Script Action**.
3. В разделе **Provide build settings from** выберите целевой объект вашего приложения.
4. Вставьте строку, соответствующую способу установки Tuist: ::: code-group
   ```bash [Mise]
   $HOME/.local/bin/mise x -C $SRCROOT -- tuist inspect build
   ```
   ```bash [Homebrew]
   tuist inspect build
   ```
   <!-- -->
   :::

   Скрипты схем Xcode не наследуют `PATH` вашей оболочки, поэтому shim mise не находится автоматически. Строка Mise выше вызывает mise по абсолютному пути и просит его загрузить конфигурацию из `$SRCROOT`, чтобы выбрать версию, закрепленную в вашем проекте.
5. Выполните сборку один раз. Сборка появится на вкладке **Builds** панели управления в течение нескольких секунд.

## Аналитика тестов

Журнал тестов Xcode перечисляет результаты по каждому тесту по одному запуску за раз. Он не агрегирует межзапусковые сигналы, которые вам действительно нужны: как часто падает тест, насколько медленнее он стал за последнюю неделю, падает ли он только на определенных симуляторах. Тест, который за десять запусков CI дрейфует от надежного к нестабильному, выглядит так же, как один неудачный запуск.

Аналитика тестов записывает результат и длительность каждого теста и коррелирует результаты между запусками. Медленные тесты, сбои и нестабильные тесты отображаются на вкладке **Tests** панели управления.

1. **Product → Scheme → Edit Scheme…**
2. **Test → Post-actions → +** → **New Run Script Action**.
3. **Provide build settings from** вашего целевого объекта приложения.
4. Вставьте: ::: code-group
   ```bash [Mise]
   $HOME/.local/bin/mise x -C $SRCROOT -- tuist inspect test
   ```
   ```bash [Homebrew]
   tuist inspect test
   ```
   <!-- -->
   :::
5. Запустите действие тестирования один раз. Результаты появятся на вкладке **Tests** панели управления.

## Аналитика бандлов

Размер установки и загрузки IPA меняется с каждым добавленным ресурсом и каждым связанным символом. Xcode сообщает размеры по запросу в **Product → Show Archive**, а не в виде серии. PR, добавляющий большой ресурс, неотличим от любого другого PR в очереди на слияние.

Аналитика бандлов записывает размеры установки и загрузки для каждой проанализированной сборки и может отклонять проверку PR, если превышен порог для ветки. Добавьте это в свой CI сразу после шага сборки:

```bash
tuist inspect bundle App.ipa
```

Откройте **Bundle insights** на панели управления, чтобы увидеть тренд и настроить пороги.

## Previews

TestFlight добавляет цикл сборки и проверки при каждом обмене. Отправка подписанного `.ipa` напрямую требует UDID получателя в профиле обеспечения. Ни то, ни другое не удобно для дизайнера или специалиста по QA, который просто хочет попробовать текущую ветку.

Previews превращает сборку в ссылку для общего доступа, которая запускается на симуляторе или устройстве одной командой:

```bash
tuist xcodebuild build -scheme App -workspace App.xcworkspace -configuration Debug -sdk iphonesimulator
tuist share App
```

Отправьте ссылку. Получатели запускают ее с помощью `tuist run <url>` или приложения Tuist для macOS.

## Подключите команду

Эффект от кэша и аналитики усиливается с ростом числа участников проекта. Пригласите коллег в организацию через настройки аккаунта на панели управления и настройте <.localized_link href="/guides/integrations/authentication/sso">Single Sign-On</.localized_link> (Google, Okta, Microsoft), чтобы подключение занимало один клик вместо индивидуального `tuist auth login`.
