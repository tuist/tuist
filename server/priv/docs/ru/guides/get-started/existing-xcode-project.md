::: code-group

Help me get started with Tuist. Follow the setup at:

Выбирайте этот путь, если хотите сохранить `.xcodeproj` или `.xcworkspace` без изменений и подключить возможности Tuist, не переходя на генерацию проектов. Каждый раздел ниже начинается с описания того, чего сейчас не хватает, а затем показывает функцию, которая закрывает этот пробел.

## Предварительные требования

- macOS с **Xcode 26 или новее** (кэш компиляции и современные метрики зависят от него).
- <.localized_link href="/guides/install-tuist">Интерфейс командной строки Tuist</.localized_link>.

## Подключение проекта

Запустите `tuist init` в корне репозитория. Когда Tuist обнаружит ваше рабочее пространство, выберите **Интегрировать `<YourApp>`**, затем пройдите аутентификацию в браузере и выберите аккаунт, которому должен принадлежать проект. Tuist создаст в корне файл `Tuist.swift`, который закрепляет идентификатор проекта, чтобы ваши коллеги и CI использовали одно и то же подключение. Зафиксируйте его в системе контроля версий.

Если вы управляете этим процессом через агента кодирования или скрипт, сначала запустите `tuist auth login` (браузерный поток ждет, пока вы нажмете Enter), затем используйте неинтерактивную форму:

```bash
tuist init --build-system xcode --name <project-handle> --account <account>
```

Все нижеперечисленное является необязательным и независимым.

## Кэш компиляции Xcode

Xcode 26 поставляется с кэшем компиляции для каждого файла, но его хранилище находится внутри `DerivedData` машины. Чистая сборка заполняет его локально; коллеги и раннеры CI пересобирают все с нуля, потому что не видят это хранилище.

`tuist setup cache` направляет кэш компиляции Xcode в общую сеть кэша Tuist. Попадание в кэш на любом компьютере разработчика или в задаче CI затем ускоряет сборку той же ревизии на всех остальных машинах.

```bash
tuist setup cache
```

Выполните сборку в Xcode. Очистите Derived Data, выполните сборку еще раз на втором компьютере или раннере CI. Вторая сборка завершится за долю времени, а отчет о сборке Xcode покажет попадания в кэш компиляции.

## Метрики сборки

Xcode записывает длительность сборки для каждой цели в журнал и в отчет о сборке. Эти данные не агрегируются по нескольким запускам или машинам. Регрессия времени сборки, попавшая в один PR, обычно проявляется только как общее замедление CI, без явного сигнала о том, какая цель вызвала ее и когда.

Метрики сборки записывают длительность каждой сборки и время выполнения этапов, чтобы тренд был виден на панели управления. Это одна строка пост-действия в вашей схеме:

1. В Xcode: **Product → Scheme → Edit Scheme…**
2. Разверните **Build → Post-actions**, нажмите **+**, выберите **New Run Script Action**.
3. В разделе **Provide build settings from** выберите цель вашего приложения.
4. Вставьте строку, соответствующую способу установки Tuist: ::: code-group
   ```bash [Mise]
   $HOME/.local/bin/mise x -C $SRCROOT -- tuist inspect build
   ```
   ```bash [Homebrew]
   tuist inspect build
   ```
   <!-- -->
   :::

   Скрипты схем Xcode не наследуют `PATH` вашей оболочки, поэтому shim mise не находится автоматически. Строка Mise выше вызывает mise по абсолютному пути и просит его загрузить конфигурацию из `$SRCROOT`, чтобы выбрать версию, закрепленную в вашем проекте.
5. Выполните сборку один раз. Сборка появится на вкладке **Сборки** панели управления в течение нескольких секунд.

## Метрики тестов

Журнал тестов Xcode перечисляет результаты по каждому тесту для одного запуска за раз. Он не агрегирует межзапусковые сигналы, которые вам действительно нужны: как часто падает тест, насколько он замедлился за последнюю неделю, падает ли он только на определенных симуляторах. Тест, который за десять запусков CI дрейфует от надежного к нестабильному, выглядит так же, как один неудачный запуск.

Метрики тестов записывают результат и длительность каждого теста и коррелируют результаты между запусками. Медленные тесты, сбои и нестабильности отображаются на вкладке **Тесты** панели управления.

1. **Product → Scheme → Edit Scheme…**
2. **Test → Post-actions → +** → **New Run Script Action**.
3. **Provide build settings from** цель вашего приложения.
4. Вставьте: ::: code-group
   ```bash [Mise]
   $HOME/.local/bin/mise x -C $SRCROOT -- tuist inspect test
   ```
   ```bash [Homebrew]
   tuist inspect test
   ```
   <!-- -->
   :::
5. Запустите действие тестирования один раз. Результаты появятся на вкладке **Тесты** панели управления.

## Метрики бандла

Размер установки и загрузки IPA меняется с каждым добавленным ассетом и каждым связанным символом. Xcode сообщает размеры по запросу в **Product → Show Archive**, а не в виде серии. PR, добавляющий большой ассет, неотличим от любого другого PR в очереди на слияние.

Метрики бандла записывают размеры установки и загрузки для каждой анализируемой сборки и могут завершать проверку PR ошибкой при превышении порога для ветки. Добавьте это в ваш CI сразу после шага сборки:

```bash
tuist inspect bundle App.ipa
```

Откройте **Метрики бандла** на панели управления, чтобы увидеть тренд и настроить пороги.

## Превью

TestFlight добавляет цикл сборки и проверки при каждом обмене. Отправка подписанного `.ipa` напрямую требует UDID получателя в профиле обеспечения. Ни то, ни другое неудобно для дизайнера или QA, который просто хочет попробовать текущую ветку.

Превью превращает сборку в ссылку для общего доступа, которая запускается на симуляторе или устройстве одной командой:

```bash
tuist xcodebuild build -scheme App -workspace App.xcworkspace -configuration Debug -sdk iphonesimulator
tuist share App
```

Отправьте ссылку. Получатели запускают ее с помощью `tuist run <url>` или приложения Tuist для macOS.

## Подключите команду

Преимущества кэша и метрик растут с увеличением числа участников проекта. Пригласите коллег в организацию через настройки аккаунта на панели управления и настройте <.localized_link href="/guides/integrations/authentication/sso">единый вход (SSO)</.localized_link> (Google, Okta, Microsoft), чтобы подключение занимало один клик вместо индивидуального выполнения `tuist auth login` для каждого пользователя.

## Что дальше

Если вы перерастете этот подход, следующим большим шагом станут проекты, генерируемые Tuist. Это серьезное изменение (цели описываются в манифестах Swift вместо `.xcodeproj`), но именно оно открывает доступ к кэшу модулей и выборочному тестированию.
