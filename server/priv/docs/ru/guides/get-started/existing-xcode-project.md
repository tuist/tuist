# Проект Xcode {#existing-xcode-project}

::: code-group

```text [Agent prompt]
Help me get started with Tuist. Follow the setup at:
https://tuist.dev/en/docs/guides/get-started/existing-xcode-project
```

:::

Выберите этот путь, если вы хотите сохранить свой `.xcodeproj` или `.xcworkspace` без изменений и использовать возможности Tuist, не переходя на генерацию проектов. Каждый раздел ниже начинается с описания того, чего сейчас не хватает, а затем показывает функцию, которая заполняет этот пробел.

## Предварительные требования

- macOS с **Xcode 26 или новее** (кэш компиляции и современные аналитические данные зависят от него).
- <.localized_link href="/guides/install-tuist">Интерфейс командной строки Tuist</.localized_link>.

## Подключение проекта

Выполните `tuist init` в корне репозитория. Когда Tuist обнаружит ваше рабочее пространство, выберите **Интегрировать `<YourApp>`**, затем выполните аутентификацию в браузере и выберите аккаунт, которому должен принадлежать проект. Tuist создаст файл `Tuist.swift` в корне, который закрепляет идентификатор проекта, чтобы ваши коллеги и CI использовали одно и то же подключение. Зафиксируйте его в системе контроля версий.

Если вы выполняете это через агента кодирования или скрипт, сначала запустите `tuist auth login` (браузерный поток ожидает, пока вы нажмете Enter), затем используйте неинтерактивную форму:

```bash
tuist init --build-system xcode --name <project-handle> --account <account>
```

Все нижеперечисленное является необязательным и независимым.

## Кэш компиляции Xcode

Xcode 26 поставляется с кэшем компиляции для каждого файла, но его хранилище находится внутри `DerivedData` машины. Чистая сборка заполняет его локально; коллеги и исполнители CI перестраивают все с нуля, потому что не видят это хранилище.

`tuist setup cache` направляет кэш компиляции Xcode в общую сеть кэша Tuist. Попадание в кэш на любом компьютере разработчика или при запуске CI затем приносит пользу всем другим машинам, собирающим ту же ревизию.

```bash
tuist setup cache
```

Соберите проект в Xcode. Очистите Derived Data, соберите снова на втором компьютере или исполнителе CI. Вторая сборка завершится за долю времени, а отчет о сборке Xcode покажет попадания в кэш компиляции.

## Аналитика сборок

Xcode записывает длительность сборки для каждой цели в журнал и в отчет о сборке. Эти данные не агрегируются по запускам или по машинам. Регрессия времени сборки, попавшая в один PR, обычно проявляется только как общее замедление CI, без очевидного сигнала о том, какая цель вызвала это или когда.

Аналитика сборок записывает длительность каждой сборки и время выполнения этапов, так что тренд виден на панели управления. Это однострочное пост-действие в вашей схеме:

1. В Xcode: **Product → Scheme → Edit Scheme…**
2. Разверните **Build → Post-actions**, нажмите **+**, выберите **New Run Script Action**.
3. В разделе **Provide build settings from** выберите целевой объект вашего приложения.
4. Вставьте строку, соответствующую способу установки Tuist: ::: code-group
   ```bash [Mise]
   $HOME/.local/bin/mise x -C $SRCROOT -- tuist inspect build
   ```
   ```bash [Homebrew]
   tuist inspect build
   ```
   <!-- -->
   :::

   Скрипты схем Xcode не наследуют `PATH` вашей оболочки, поэтому shim mise не находится автоматически. Строка Mise выше вызывает mise по абсолютному пути и просит его загрузить конфигурацию из `$SRCROOT`, чтобы он выбрал версию, закрепленную в вашем проекте.
5. Выполните сборку один раз. Сборка появится на вкладке **Builds** панели управления в течение нескольких секунд.

## Аналитика тестов

Журнал тестов Xcode перечисляет результаты каждого теста по одному запуску за раз. Он не агрегирует межзапусковый сигнал, который вам действительно нужен: как часто тест падает, насколько медленнее он стал на прошлой неделе, падает ли он только на определенных симуляторах. Тест, дрейфующий от надежного к нестабильному в течение десяти запусков CI, выглядит так же, как один неудачный запуск.

Аналитика тестов записывает результат и длительность каждого теста и коррелирует результаты между запусками. Медленные тесты, сбои и нестабильности отображаются на вкладке **Tests** панели управления.

1. **Product → Scheme → Edit Scheme…**
2. **Test → Post-actions → +** → **New Run Script Action**.
3. **Provide build settings from** целевого объекта вашего приложения.
4. Вставьте: ::: code-group
   ```bash [Mise]
   $HOME/.local/bin/mise x -C $SRCROOT -- tuist inspect test
   ```
   ```bash [Homebrew]
   tuist inspect test
   ```
   <!-- -->
   :::
5. Запустите действие теста один раз. Результаты появятся на вкладке **Tests** панели управления.

## Аналитика пакетов

Размер установки и загрузки IPA изменяется с каждым добавленным ресурсом и каждым связанным символом. Xcode сообщает размеры по запросу в **Product → Show Archive**, а не в виде серии. PR, добавляющий большой ресурс, неотличим от любого другого PR в очереди на слияние.

Аналитика пакетов записывает размеры установки и загрузки для каждой проанализированной сборки и может завершить проверку PR ошибкой, если превышен порог для ветки. Добавьте это в свой CI сразу после шага сборки:

```bash
tuist inspect bundle App.ipa
```

Откройте **Bundle insights** на панели управления, чтобы увидеть тренд и настроить пороги.

## Предпросмотры

TestFlight добавляет цикл сборки и проверки при каждом обмене. Отправка подписанного `.ipa` напрямую требует UDID получателя в профиле обеспечения. Ни то, ни другое не удобно для дизайнера или QA, которые просто хотят попробовать текущую ветку.

Previews превращает сборку в ссылку для общего доступа, которая запускается на симуляторе или устройстве одной командой:

```bash
tuist xcodebuild build -scheme App -workspace App.xcworkspace -configuration Debug -sdk iphonesimulator
tuist share App
```

Отправьте ссылку. Получатели запускают ее с помощью `tuist run <url>` или приложения Tuist для macOS.

## Подключите команду

Кэш и аналитика становятся эффективнее по мере увеличения числа людей, подключенных к проекту. Пригласите своих коллег в организацию через настройки аккаунта на панели управления и настройте <.localized_link href="/guides/integrations/authentication/sso">Single Sign-On</.localized_link> (Google, Okta, Microsoft), чтобы процесс подключения был простым кликом, а не требовал индивидуального `tuist auth login` для каждого пользователя.

## Что делать дальше

Если вы перерастете этот подход, следующим важным шагом станут проекты, генерируемые Tuist. Это серьезное изменение (цели описываются в манифестах Swift вместо `.xcodeproj`), но именно оно открывает доступ к кэшу модулей и выборочному тестированию. Полностью описано в руководстве <.localized_link href="/guides/get-started/generated-xcode-project">Generated Xcode project</.localized_link>.
