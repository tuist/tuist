Следуйте этому пути, чтобы подключить существующий проект Gradle к Tuist. Плагин Gradle `dev.tuist` связывает локальный кэш сборок Gradle с удалённым кэшем Tuist и загружает данные о сборках и тестах в панель управления, не изменяя ни одной команды `./gradlew`.

Каждый раздел ниже начинается с того, чего сейчас не хватает, а затем показывает функцию, которая заполняет этот пробел.

## Предварительные требования

- Проект Gradle с файлом `settings.gradle.kts` (или `settings.gradle`).
- <.localized_link href="/guides/install-tuist">Интерфейс командной строки Tuist</.localized_link>.

## Подключение проекта

В корневой директории проекта Gradle выполните `tuist init`. Выберите **Интеграция проекта Gradle**, затем пройдите аутентификацию в браузере и выберите аккаунт, которому должен принадлежать проект.

```bash
tuist init
```

Если вы выполняете это из агента для написания кода или скрипта, сначала запустите `tuist auth login` (браузерный поток ожидает нажатия Enter), затем используйте неинтерактивную форму:

```bash
tuist init --build-system gradle --name <project-handle> --account <account>
```

Tuist создаёт файл `tuist.toml` в корне репозитория с идентификатором проекта и выводит блок `plugins { ... }`. Вставьте его в начало файла `settings.gradle.kts`:

<!-- @snippet: ../_gradle-plugin-block -->

Проверьте работоспособность с помощью `./gradlew help`. Gradle должен загрузиться без ошибок. Если плагин не найден, убедитесь, что блок находится в `settings.gradle.kts`, а не в `build.gradle.kts`.

Всё нижеперечисленное является опциональным и независимым.

## Удалённый кэш сборок

Локальный кэш сборок Gradle хранит результаты задач на машине, которая их произвела. Два разработчика на одной ветке используют кэш в своих собственных директориях `~/.gradle`, а не общих, а CI каждый раз работает с новым пустым кэшем.

Удалённый кэш Tuist расширяет тот же протокол ключ/значение, который Gradle уже использует между машинами. Результаты задачи загружаются на машине, которая первой её выполнила, и скачиваются всеми остальными, кто сталкивается с теми же входными данными. Включите его в `gradle.properties`:

```properties
org.gradle.caching=true
```

Затем выполните сборку в двух средах:

```bash
./gradlew clean build --build-cache --info
```

Задачи, поддерживающие кэширование, сообщают `FROM-CACHE` при втором запуске. Откройте раздел **Кэш** на панели управления, чтобы увидеть коэффициент попаданий в кэш со временем.

## Аналитика сборок

Gradle выводит время выполнения задач в конце сборки, а с флагом `--profile` создаёт HTML-отчёт для каждой сборки. Ни один из этих методов не агрегирует данные по нескольким запускам. Задача, которая замедлилась в серии коммитов, выглядит в отчёте любой отдельной сборки так же, как и всегда.

Плагин `dev.tuist` автоматически загружает время выполнения задач для каждой сборки на панель управления после применения плагина. Дополнительная настройка не требуется. Откройте раздел **Сборки** на панели управления после следующего `./gradlew build`, чтобы увидеть тенденцию.

## Аналитика тестов

Отчёты о тестах Gradle находятся для каждой сборки в директории `build/reports/tests/`. Тест, который периодически падает в десяти запусках CI, в любом отдельном отчёте выглядит как стабильный тест, который однажды случайно упал.

Аналитика тестов записывает результат и длительность каждой задачи для каждого запуска `./gradlew test` и сопоставляет результаты между запусками. Нестабильные тесты, медленные тесты и сбои отображаются на вкладке **Тесты** панели управления. Когда количество нестабильных тестов накапливается, изолируйте их через панель управления, чтобы они перестали блокировать слияния.

Плагин также поддерживает **режим стресс-тестирования**, который повторно запускает тесты, добавленные сборкой, и помечает те, которые оказываются нестабильными, до их попадания в основную ветку. Добавьте это в расширение `tuist` в файле `settings.gradle.kts`:

```kotlin
tuist {
    stressNewTests {
        mode = "report" // or "enforce"
    }
}
```

## Аналитика бандлов

Android Gradle Plugin сообщает размер созданного `.aab` в выводе сборки. Это число исчезает вместе с веткой, а сравнение размеров между релизами требует ручного учёта. Play Console сообщает те же числа, но только после загрузки артефакта.

Аналитика бандлов записывает размеры установки и скачивания для каждого `.aab` (рекомендуется) или `.apk` и может отклонять проверку PR, если превышен порог для ветки. Добавьте это в ваш CI сразу после шага сборки:

```bash
tuist inspect bundle App.aab
```

Откройте раздел **Аналитика бандлов → Android** на панели управления, чтобы увидеть тенденцию и настроить пороги.

## Превью

Внутренний тестовый трек Play Console добавляет задержку на проверку и распространение при каждом partage. Отправка сырого `.apk` через Slack или электронную почту быстрее, но теряется связь с тем, к какой конкретной сборке относится сообщение.

Плагин может собирать и публиковать вариант приложения напрямую, без отдельной загрузки через CLI:

```bash
./gradlew :app:tuistShareDebug --track nightly
```

Запрос задачи `tuistShare<Variant>` включает публикацию для этого вызова; обычные сборки никогда не загружают превью. См. <.localized_link href="/guides/features/previews/gradle">Превью для Gradle</.localized_link> для информации о поддерживаемых APK, подписании и установке.

## Подключение команды

Попадания в кэш, аналитика и стресс-тестирование усиливаются с увеличением числа людей, подключённых к проекту. Пригласите коллег в организацию из настроек аккаунта на панели управления и настройте <.localized_link href="/guides/integrations/authentication/sso">Единый вход (SSO)</.localized_link> (Google, Okta, Microsoft), чтобы онбординг происходил в один клик, а не требовал индивидуального `tuist auth login` для каждого человека.

Для CI не используйте личный логин. Аутентифицируйтесь через OIDC-идентичность вашего CI-провайдера или создайте токен аккаунта с пресетом **CI** на панели управления и установите его как `TUIST_TOKEN`. См. <.localized_link href="/guides/server/authentication#gradle-plugin-authentication">Аутентификация плагина Gradle</.localized_link>.
