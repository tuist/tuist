Следуйте этому пути, чтобы подключить существующее рабочее пространство Bazel к Tuist. Tuist предоставляет кэш на основе [Remote Execution API](https://github.com/bazelbuild/remote-apis), к которому Bazel подключается как к удаленному кэшу, а также поток Build Event Service, который превращает каждую сборку и тест в видимые данные на панели управления. Обзор того, что Tuist добавляет к Bazel, см. в статье [Bazel with Tuist](https://tuist.dev/build-systems/bazel). Если вы переходите от другого провайдера для Bazel, сравнения с [BuildBuddy](https://tuist.dev/compare/buildbuddy) и [EngFlow](https://tuist.dev/compare/engflow) описывают изменения.

Каждый раздел ниже начинается с описания недостающих сегодня возможностей, а затем пошагово объясняет функцию, которая заполняет этот пробел.

## Предварительные требования

- Рабочее пространство Bazel (файл `WORKSPACE` или `MODULE.bazel` в его корне) и Bazel, доступный в переменной окружения `PATH`.
- <.localized_link href="/guides/install-tuist">Интерфейс командной строки Tuist</.localized_link>.

## Подключение рабочего пространства

Из корня рабочего пространства Bazel выполните команду `tuist init`. Tuist обнаруживает файл `WORKSPACE` или `MODULE.bazel` и предлагает опцию **Integrate a Bazel workspace**. Пройдите аутентификацию в браузере и выберите аккаунт, которому должен принадлежать проект.

```bash
tuist init
```

Если вы выполняете это действие через агент написания кода или скрипт, сначала запустите `tuist auth login` (браузерный процесс ожидает нажатия Enter), затем используйте неинтерактивную форму:

```bash
tuist init --build-system bazel --name <project-handle> --account <account>
```

После завершения инициализации Tuist:

1. Создает файл `tuist.toml` в корне рабочего пространства с идентификатором проекта.
2. Создает файл `.bazelrc.tuist` рядом с вашим `.bazelrc`, настроенный на ближайший регион кэша Tuist и аутентифицированный через вспомогательный инструмент учетных данных для каждого рабочего пространства.
3. Добавляет строку `try-import %workspace%/.bazelrc.tuist` в ваш файл `.bazelrc`.

Зафиксируйте строку `try-import` в репозитории. Она одинакова на всех машинах. Добавьте `.bazelrc.tuist` в ваш `.gitignore`. Путь к вспомогательному инструменту учетных данных зависит от пользователя, а регион кэша — от местоположения, поэтому их не следует передавать другим.

Все описанное ниже включается автоматически после подключения рабочего пространства.

## Удаленный кэш

Локальный дисковый кэш Bazel находится в директории `~/.cache/bazel` (или там, куда указывает параметр `--disk_cache`). Попадание в кэш на машине одного разработчика недоступно другим, а контейнеры задач CI каждый раз запускаются с пустым кэшем.

[Remote Execution API](https://github.com/bazelbuild/remote-apis) от Bazel — это протокол для расширения этого же кэша до общей конечной точки. Tuist поддерживает этот протокол. Как только файл `.bazelrc.tuist` настроен, Bazel пропускает действия, результаты которых уже есть в общем кэше, и загружает их вместо выполнения. Работа одной машины приносит пользу всем остальным машинам, собирающим ту же ревизию.

Проверьте, выполнив две чистые сборки для одной и той же ревизии (локально или одна локальная + одна в CI):

```bash
bazel clean
bazel build //...
```

В отчете второго запуска должны быть указаны попадания в кэш. Откройте раздел **Cache** на панели управления, чтобы увидеть динамику процента попаданий.

## Аналитика сборок и тестов

Поток событий сборки Bazel и XML-отчеты по каждому тесту генерируются при каждом вызове. Сравнение длительности выполнения целей в течение недели или выявление теста, ставшего нестабильным за несколько запусков в CI, требует сбора и агрегации этих событий в одном месте.

Протокол Build Event Service, который уже генерирует Bazel, предназначен именно для этого. Файл `.bazelrc.tuist`, созданный командой `tuist init`, настраивает поток BES для отправки данных в Tuist, поэтому аналитика сборок и тестов начинает поступать при следующем выполнении `bazel build` и `bazel test`. Дополнительная настройка не требуется. Откройте разделы **Builds** и **Tests** на панели управления, чтобы просмотреть данные.

## Подключите команду

Попадания в кэш и аналитика становятся ценнее с увеличением числа участников проекта. Пригласите коллег в организацию через настройки аккаунта на панели управления и настройте <.localized_link href="/guides/integrations/authentication/sso">Single Sign-On</.localized_link> (Google, Okta, Microsoft), чтобы подключение новых участников происходило в один клик, а не требовало индивидуального выполнения `tuist auth login` для каждого человека.
