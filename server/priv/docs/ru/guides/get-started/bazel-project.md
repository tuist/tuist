# Проект Bazel {#bazel-project}

::: code-group

Следуйте этому пути, чтобы подключить существующее рабочее пространство Bazel к Tuist. Tuist предоставляет кэш [Remote Execution API](https://github.com/bazelbuild/remote-apis), к которому Bazel подключается как к удалённому кэшу, а также поток Build Event Service, который превращает каждую сборку и тест в видимые данные на панели управления. Обзор того, что Tuist добавляет к Bazel, см. в статье [Bazel with Tuist](https://tuist.dev/build-systems/bazel). Если вы переходите от другого провайдера для Bazel, сравнения [BuildBuddy](https://tuist.dev/compare/buildbuddy) и [EngFlow](https://tuist.dev/compare/engflow) описывают изменения.

Каждый раздел ниже начинается с описания недостающих возможностей, а затем показывает функцию, которая закрывает этот пробел.

## Предварительные требования

- Рабочее пространство Bazel (файл `WORKSPACE` или `MODULE.bazel` в его корне) и Bazel, доступный в `PATH`.
- <.localized_link href="/guides/install-tuist">Интерфейс командной строки Tuist</.localized_link>.

## Подключение рабочего пространства

В корне рабочего пространства Bazel выполните `tuist init`. Tuist обнаруживает `WORKSPACE` / `MODULE.bazel` и предлагает **Integrate a Bazel workspace**. Пройдите аутентификацию в браузере и выберите аккаунт, которому должен принадлежать проект.

```bash
tuist init
```

Если вы запускаете это через агент написания кода или скрипт, сначала выполните `tuist auth login` (браузерный поток ожидает нажатия Enter), затем используйте неинтерактивную форму:

```bash
tuist init --build-system bazel --name <project-handle> --account <account>
```

После завершения init Tuist:

1. Создаёт файл `tuist.toml` в корне рабочего пространства с идентификатором проекта.
2. Создаёт файл `.bazelrc.tuist` рядом с вашим `.bazelrc`, настроенный на ближайший регион кэша Tuist и аутентифицированный через вспомогательный инструмент учётных данных для каждого рабочего пространства.
3. Добавляет строку `try-import %workspace%/.bazelrc.tuist` в ваш `.bazelrc`.

Зафиксируйте строку `try-import`. Она одинакова на каждой машине. Добавьте `.bazelrc.tuist` в ваш `.gitignore`. Путь к вспомогательному инструменту учётных данных зависит от пользователя, а регион кэша — от местоположения, поэтому их не следует передавать другим.

Все функции ниже включаются автоматически после подключения рабочего пространства.

## Удалённый кэш

Локальный дисковый кэш Bazel находится в `~/.cache/bazel` (или там, куда указывает `--disk_cache`). Попадание в кэш на машине одного разработчика не доступно другим, а контейнеры задач CI каждый раз запускаются с пустым кэшем.

[Remote Execution API](https://github.com/bazelbuild/remote-apis) от Bazel — это протокол для расширения этого кэша до общего конечного пункта. Tuist поддерживает его. Как только `.bazelrc.tuist` настроен, Bazel пропускает действия, результаты которых уже есть в общем кэше, и загружает их вместо выполнения. Работа одной машины приносит пользу всем остальным машинам, собирающим ту же ревизию.

Проверьте двумя чистыми сборками для одной и той же ревизии (локально или одна локальная + одна в CI):

```bash
bazel clean
bazel build //...
```

Отчёт второй сборки должен показать попадания в кэш. Откройте раздел **Cache** на панели управления, чтобы увидеть коэффициент попаданий со временем.

## Аналитика сборок и тестов

Поток событий сборки Bazel и XML-отчёты по каждому тесту генерируются при каждом запуске. Сравнение длительностей на уровне целей в течение недели или выявление теста, ставшего нестабильным за несколько запусков в CI, требует сбора и агрегации этих событий.

Протокол Build Event Service, который уже выдаёт Bazel, предназначен именно для этого. Файл `.bazelrc.tuist`, созданный `tuist init`, настраивает поток BES для Tuist, поэтому аналитика сборок и тестов начинает поступать при следующем `bazel build` и `bazel test`. Дополнительная настройка не требуется. Откройте разделы **Builds** и **Tests** на панели управления, чтобы увидеть данные.

## Подключите команду

Попадания в кэш и аналитика усиливаются с ростом числа людей, подключённых к проекту. Пригласите коллег в организацию через настройки аккаунта на панели управления и настройте <.localized_link href="/guides/integrations/authentication/sso">Single Sign-On</.localized_link> (Google, Okta, Microsoft), чтобы подключение происходило в один клик, а не требовало индивидуального `tuist auth login` для каждого.
