# Проект Bazel {#bazel-project}

::: code-group

```text [Agent prompt]
Help me get started with Tuist. Follow the setup at:
https://tuist.dev/en/docs/guides/get-started/bazel-project
```

:::

Следуйте этому пути, чтобы подключить существующее рабочее пространство Bazel к Tuist. Tuist предоставляет кэш [Remote Execution API](https://github.com/bazelbuild/remote-apis), к которому Bazel подключается как к удалённому кэшу, а также поток Build Event Service, который превращает каждую сборку и тест в видимые данные на панели управления.

Каждый раздел ниже начинается с описания того, чего не хватает сегодня, а затем показывает функцию, которая заполняет этот пробел.

## Предварительные требования

- Рабочее пространство Bazel (файл `WORKSPACE` или `MODULE.bazel` в его корне) и Bazel, доступный в `PATH`.
- <.localized_link href="/guides/install-tuist">Интерфейс командной строки Tuist</.localized_link>.

## Подключение рабочего пространства

> [!NOTE]
> Рабочий процесс Bazel внутри `tuist init` требует версии CLI Tuist, которая поставляется вместе с ним. В более ранних версиях `tuist init` не будет предлагать вариант «Integrate a Bazel workspace». В качестве альтернативы выполните `tuist auth login`, а затем `tuist bazel setup` из корня рабочего пространства, что проведёт вас через те же шаги, что описаны ниже.

Из корня рабочего пространства Bazel выполните `tuist init`. Tuist обнаруживает `WORKSPACE` / `MODULE.bazel` и предлагает **Integrate a Bazel workspace**. Пройдите аутентификацию в браузере и выберите учётную запись, которой должен принадлежать проект.

```bash
tuist init
```

Если вы запускаете это из агента для написания кода или скрипта, сначала выполните `tuist auth login` (браузерный поток ждёт, пока вы нажмёте Enter), затем используйте неинтерактивную форму:

```bash
tuist init --build-system bazel --name <project-handle> --account <account>
```

Когда инициализация завершится, Tuist:

1. Создаёт файл `tuist.toml` в корне рабочего пространства с идентификатором проекта.
2. Создаёт файл `.bazelrc.tuist` рядом с вашим `.bazelrc`, настроенный на ближайший регион кэша Tuist и аутентифицированный через вспомогательный инструмент учётных данных для каждого рабочего пространства.
3. Добавляет строку `try-import %workspace%/.bazelrc.tuist` в ваш `.bazelrc`.

Зафиксируйте строку `try-import`. Она одинакова на каждом компьютере. Добавьте `.bazelrc.tuist` в ваш `.gitignore`. Путь к вспомогательному инструменту учётных данных зависит от пользователя, а регион кэша — от местоположения, поэтому их не следует передавать другим.

Всё описанное ниже включается автоматически после подключения рабочего пространства.

## Удалённый кэш

Локальный дисковый кэш Bazel находится в `~/.cache/bazel` (или там, куда указывает `--disk_cache`). Попадание в кэш на машине одного разработчика не доступно другим, а контейнеры задач CI каждый раз запускаются с пустым кэшем.

[Remote Execution API](https://github.com/bazelbuild/remote-apis) от Bazel — это протокол для расширения этого же кэша до общей конечной точки. Tuist поддерживает его. Как только `.bazelrc.tuist` настроен, Bazel пропускает действия, результаты которых уже есть в общем кэше, и загружает их вместо выполнения. Работа одной машины приносит пользу всем остальным машинам, собирающим ту же ревизию.

Проверьте, выполнив две чистые сборки для одной и той же ревизии (локально или одну локальную и одну в CI):

```bash
bazel clean
bazel build //...
```

В отчёте второго запуска должны быть указаны попадания в кэш. Откройте раздел **Cache** на панели управления, чтобы увидеть динамику попаданий.

## Аналитика сборок и тестов

Поток событий сборки Bazel и XML-отчёты по каждому тесту генерируются при каждом вызове. Сравнение длительности на уровне целей в течение недели или выявление теста, который стал нестабильным за несколько запусков в CI, означает необходимость сбора и агрегации этих событий где-то.

Протокол Build Event Service, который уже генерирует Bazel, предназначен именно для этого. Файл `.bazelrc.tuist`, созданный `tuist init`, настраивает поток BES для работы с Tuist, поэтому аналитика сборок и тестов начинает поступать при следующем выполнении `bazel build` и `bazel test`. Ничего дополнительно настраивать не нужно. Откройте разделы **Builds** и **Tests** на панели управления, чтобы увидеть данные.

## Подключите команду

Попадания в кэш и аналитика накапливаются с увеличением числа людей, подключённых к проекту. Пригласите коллег в организацию через настройки учётной записи на панели управления и настройте <.localized_link href="/guides/integrations/authentication/sso">Single Sign-On</.localized_link> (Google, Okta, Microsoft), чтобы подключение занимало один клик, а не требовало индивидуального выполнения `tuist auth login` для каждого человека.
