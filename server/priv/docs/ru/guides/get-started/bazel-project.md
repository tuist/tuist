Следуйте этому пути, чтобы подключить существующее рабочее пространство Bazel к Tuist. Tuist предоставляет кэш [Remote Execution API](https://github.com/bazelbuild/remote-apis), к которому Bazel подключается как к удаленному кэшу, а также поток Build Event Service, который превращает каждую сборку и тест в видимые данные на панели управления. Обзор того, что Tuist добавляет к Bazel, см. в статье [Bazel с Tuist](https://tuist.dev/build-systems/bazel). Если вы переходите от другого провайдера для Bazel, сравнения [BuildBuddy](https://tuist.dev/compare/buildbuddy) и [EngFlow](https://tuist.dev/compare/engflow) описывают изменения.

Каждый раздел ниже начинается с описания того, чего не хватает сегодня, а затем проводит вас через функцию, которая заполняет этот пробел.

## Предварительные требования

- Рабочее пространство Bazel (файл `WORKSPACE` или `MODULE.bazel` в его корне) и Bazel, доступный в `PATH`.
- <.localized_link href="/guides/install-tuist">Интерфейс командной строки Tuist</.localized_link>.

## Подключение рабочего пространства

Из корня рабочего пространства Bazel выполните `tuist init`. Tuist обнаруживает `WORKSPACE` / `MODULE.bazel` и предлагает **Интегрировать рабочее пространство Bazel**. Пройдите аутентификацию в браузере и выберите учетную запись, которой должен принадлежать проект.

```bash
tuist init
```

Если вы выполняете это из агента кодирования или скрипта, сначала запустите `tuist auth login` (браузерный поток ожидает нажатия Enter), затем используйте неинтерактивную форму:

```bash
tuist init --build-system bazel --name <project-handle> --account <account>
```

По завершении init Tuist:

1. Записывает `tuist.toml` в корень рабочего пространства с идентификатором проекта.
2. Записывает `.bazelrc.tuist` рядом с вашим `.bazelrc`, настроенный на ближайший регион кэша Tuist и аутентифицированный через вспомогательный инструмент учетных данных для каждого рабочего пространства.
3. Добавляет строку `try-import %workspace%/.bazelrc.tuist` в ваш `.bazelrc`.

Зафиксируйте строку `try-import`. Она одинакова на каждой машине. Добавьте `.bazelrc.tuist` в ваш `.gitignore`. Путь к вспомогательному инструменту учетных данных зависит от пользователя, а регион кэша — от местоположения, поэтому их не следует передавать другим.

Все нижеперечисленное включается автоматически после подключения рабочего пространства.

## Удаленный кэш

Собственный локальный дисковый кэш Bazel находится в `~/.cache/bazel` (или там, куда указывает `--disk_cache`). Попадание в кэш на машине одного разработчика не доступно другим, а контейнеры заданий CI каждый раз запускаются с пустым кэшем.

[Remote Execution API](https://github.com/bazelbuild/remote-apis) от Bazel — это протокол для расширения этого же кэша до общей конечной точки. Tuist поддерживает его. Как только `.bazelrc.tuist` настроен, Bazel пропускает действия, результаты которых уже есть в общем кэше, и загружает их вместо выполнения. Работа одной машины приносит пользу всем остальным машинам, собирающим ту же ревизию.

Проверьте, выполнив две чистые сборки для одной и той же ревизии (локально или одну локальную и одну в CI):

```bash
bazel clean
bazel build //...
```

Сводка второго запуска должна сообщать о попаданиях в кэш. Откройте раздел **Кэш** на панели управления, чтобы увидеть динамику коэффициента попаданий.

## Аналитика сборок и тестов

Поток событий сборки Bazel и XML-отчеты по каждому тесту генерируются при каждом вызове. Сравнение длительности на уровне целей в течение недели или выявление теста, ставшего нестабильным за несколько прогонов в CI, означает необходимость сбора и агрегации этих событий где-то.

Протокол Build Event Service, который уже генерирует Bazel, предназначен именно для этого. `.bazelrc.tuist`, созданный `tuist init`, настраивает поток BES для Tuist, поэтому аналитика сборок и тестов начинает поступать при следующем `bazel build` и `bazel test`. Дополнительная настройка не требуется. Откройте разделы **Сборки** и **Тесты** на панели управления, чтобы увидеть данные.

## Подключите команду

Попадания в кэш и аналитика накапливаются с увеличением числа людей, подключенных к проекту. Пригласите коллег в организацию через настройки учетной записи на панели управления и настройте <.localized_link href="/guides/integrations/authentication/sso">Единый вход (SSO)</.localized_link> (Google, Okta, Microsoft), чтобы подключение происходило в один клик, а не требовало индивидуального `tuist auth login` для каждого человека.
