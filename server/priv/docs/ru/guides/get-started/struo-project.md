# Проект Struo {#struo-project}

<a id="once-project"></a>

::: code-group

Help me get started with Tuist. Follow the setup at:
https://tuist.dev/en/docs/guides/get-started/struo-project

:::

[Struo](https://struo.run) выполняет кешируемые скрипты и графы сборки. Подключите его к Tuist, чтобы делиться результатами кеша между машинами, отслеживать запуски в реальном времени и публиковать приложения для тестирования вашей командой. Сохраните существующие исходные файлы проекта и определения сборки; интеграция настраивается в `struo.toml`.

## Предварительные требования

- Установлен [Struo 1.0.0](https://github.com/tuist/struo/releases/tag/1.0.0) или более поздняя версия, а также есть рабочее пространство или кешируемый скрипт. Следуйте [руководству по установке](https://struo.run/docs/guide/getting-started) или закрепите версию через mise:

  ```bash
  mise use -g github:tuist/struo@1.0.0
  ```

- Аккаунт Tuist. Для интеграции со Struo CLI Tuist не требуется.

## Обновление с Once {#upgrading-from-once}

Struo — новое название Once. Переименуйте файлы `once.toml` в `struo.toml`, обновите закрепления mise с `github:tuist/once` на `github:tuist/struo` и замените команды `once` на `struo`. Обновите заголовки скриптов с `# once` на `# struo` и shebang на `#!/usr/bin/env -S struo exec -- bash`. Переименуйте переменные окружения `ONCE_*` в `STRUO_*`, например `STRUO_CACHE_PROVIDER`; учетные данные Tuist по-прежнему используют `TUIST_TOKEN`.

Замените записи `.once/` в файлах игнорирования на `.struo/`. Результаты теперь сохраняются в `.struo/out/`, а общий локальный кеш контента использует `$XDG_CACHE_HOME/struo/cas` (по умолчанию `~/.cache/struo/cas`). Ключи кеша и локальное хранилище используют новое имя, поэтому после обновления ожидайте холодный локальный кеш вместо переноса старых записей. Войдите снова с помощью `struo auth login --provider tuist`.

Переименование не меняет точки совместимости Tuist: отчетность в реальном времени по-прежнему использует `once.events.v1`, а существующие маршруты `/api/.../once` остаются поддерживаемыми. См. [руководство по переименованию в upstream](https://struo.run/changelog/2026-11-18-once-is-now-struo).

## Подключение проекта {#connect-the-project}

Из корня вашего репозитория выполните:

```bash
struo connect --provider tuist --create
```

При необходимости Struo выполнит вход, создаст проект Tuist в вашем личном аккаунте и запишет привязку провайдера в `struo.toml`. См. [Подключение проекта](https://struo.run/docs/guide/infrastructure/connect), чтобы выбрать другой аккаунт или существующий проект.

Для существующего проекта Tuist настройте провайдера и привязку кеша самостоятельно:

```toml
[infrastructures.tuist]
kind = "tuist"
account = "acme"
project = "app"
# url = "https://your-tuist-server.example.com"

[infrastructure.cache]
provider = "tuist"
```

Замените `acme` и `app` на идентификаторы вашего аккаунта и проекта, затем выполните аутентификацию:

```bash
struo auth login --provider tuist
```

Зафиксируйте `struo.toml` в репозитории, чтобы коллеги и CI использовали назначение, а не ваши учетные данные. Каждый разработчик входит в систему на своей машине.

## Общий кеш

Локальный кеш помогает только той машине, которая его заполнила. При настроенном Tuist Struo может восстановить совпадающие результаты, созданные другим разработчиком или CI, вместо повторного выполнения той же работы.

Запустите ваш кешируемый скрипт или цель графа как обычно:

```bash
struo build MyApplication
```

Откройте **Struo Cache** в панели управления, чтобы просмотреть активность удаленного кеша. См. <.localized_link href="/guides/features/cache/struo">Кеш Struo</.localized_link> для настройки и проверки повторного использования между машинами.

## Аналитика сборок

Struo выводит ссылку на панель управления при начале запуска. Откройте ее, чтобы следить за графом, статусом действий и решениями кеша по мере выполнения. Используйте раздел **Сборки**, чтобы сравнить производительность локально и в CI, а также исследовать неудачные действия. Сохраняйте логи CI для полного вывода процесса; ingest необработанных логов действий сейчас недоступен.

См. <.localized_link href="/guides/features/build-insights/struo">Аналитика сборок Struo</.localized_link>, чтобы узнать, что записывается и как получить доступ из агентов кодирования или Grafana.

## Аналитика тестов и шардирование

Запустите цели тестов Struo:

```bash
struo test
```

Откройте раздел **Тесты**, чтобы просмотреть отчеты по наборам, случаям, длительности и сбоям. Результаты зависят от возможностей отчетности целевого теста; действие, запускающее процесс теста, не автоматически формирует отчет по каждому случаю.

Когда набор тестов становится слишком большим для одной машины, создайте план шардирования и распределите его пакеты по рабочим узлам CI. См. <.localized_link href="/guides/features/test-insights/struo">Аналитика тестов Struo</.localized_link> и <.localized_link href="/guides/features/test-sharding/struo">Шардирование тестов Struo</.localized_link>.

## Превью и размер бандла

Добавьте привязку артефактов к тому же провайдеру, чтобы публиковать поддерживаемые приложения для Android, симулятора Apple и macOS:

```toml
[infrastructure.artifacts]
name = "tuist"
```

```bash
struo artifact publish MyApplication --track review
```

Возвращенная ссылка открывает превью вашего проекта; обработка может занять некоторое время. См. <.localized_link href="/guides/features/previews/struo">Превью Struo</.localized_link> для требований к подписи и опциональной публикации после сборок.

Чтобы отслеживать размер бандла, используйте CLI Tuist отдельно для собранного `.app`, `.ipa`, `.xcarchive`, `.apk` или `.aab`. Следуйте <.localized_link href="/guides/features/bundle-insights">руководству по аналитике бандлов Apple или Android</.localized_link>; публикация артефакта Struo не загружает отчет о размере бандла автоматически.

## Непрерывная интеграция

Используйте токен аккаунта, авторизованный для операций проекта, в `TUIST_TOKEN`, или аутентифицируйтесь через OpenID Connect поддерживаемого провайдера CI:

```bash
struo auth login --provider tuist --no-browser
struo build MyApplication
struo test
```

В GitHub Actions предоставьте задаче права `id-token: write` и `contents: read`. См. пример в <.localized_link href="/guides/integrations/continuous-integration#struo">Struo в непрерывной интеграции</.localized_link>. Личный вход разработчика не является учетными данными для CI.

## Удаленное выполнение

Аккаунты с включенным удаленным выполнением могут также запускать подходящие действия команд графа на Linux-воркерах Tuist. Это отдельно от обмена результатами кеша и от запуска всего рабочего процесса CI. См. <.localized_link href="/guides/features/runners/struo">Удаленное выполнение Struo</.localized_link> для требований к воркерам и настройки.
