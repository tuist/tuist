# Проект Once {#once-project}

::: code-group

```text [Agent prompt]
Help me get started with Tuist. Follow the setup at:
https://tuist.dev/en/docs/guides/get-started/once-project
```

:::

[Once](https://buildonce.dev) запускает кешируемые скрипты и графы сборки. Подключите его к Tuist, чтобы делиться результатами кеша между машинами, отслеживать запуски в реальном времени и публиковать приложения для тестирования вашей командой. Сохраните существующие исходные коды проекта и определения сборки; интеграция настраивается в файле `once.toml`.

## Предварительные требования

- Установлен [Once](https://buildonce.dev/docs/guide/getting-started), а также есть рабочее пространство или кешируемый скрипт.
- Аккаунт Tuist. CLI Tuist не требуется для интеграции с Once.

## Подключение проекта {#connect-the-project}

В корневом каталоге репозитория выполните:

```bash
once connect --provider tuist --create
```

При необходимости Once выполнит вход, создаст проект Tuist в вашем личном аккаунте и запишет привязку провайдера в файл `once.toml`. См. [Подключение проекта](https://buildonce.dev/docs/guide/infrastructure/connect), чтобы выбрать другой аккаунт или существующий проект.

Для существующего проекта Tuist настройте провайдер и привязку кеша самостоятельно:

```toml
[infrastructures.tuist]
kind = "tuist"
account = "acme"
project = "app"
# url = "https://your-tuist-server.example.com"

[infrastructure.cache]
provider = "tuist"
```

Замените `acme` и `app` на идентификаторы вашего аккаунта и проекта, затем выполните аутентификацию:

```bash
once auth login --provider tuist
```

Зафиксируйте файл `once.toml` в системе контроля версий, чтобы ваши коллеги и CI использовали общее назначение, а не ваши учетные данные. Каждый разработчик входит в систему на своей машине.

## Общий кеш

Локальный кеш полезен только для машины, которая его заполнила. При настроенном Tuist Once может восстанавливать совпадающие результаты, созданные другим разработчиком или CI, вместо повторного выполнения той же работы.

Запустите ваш кешируемый скрипт или цель графа как обычно:

```bash
once build MyApplication
```

Откройте раздел **Кеш Once** в панели управления, чтобы просмотреть активность удаленного кеша. См. <.localized_link href="/guides/features/cache/once">Кеш Once</.localized_link> для настройки и проверки повторного использования между машинами.

## Аналитика сборок

Once выводит ссылку на панель управления при начале запуска. Откройте ее, чтобы отслеживать граф, статус действий и решения кеша по мере выполнения запуска. Используйте раздел **Сборки** для сравнения производительности локально и в CI, а также для анализа неудачных действий. Сохраняйте логи CI для полного вывода процесса; ingest необработанных логов действий в настоящее время недоступен.

См. <.localized_link href="/guides/features/build-insights/once">Аналитика сборок Once</.localized_link>, чтобы узнать, что записывается и как получить доступ к этим данным из агентов кодирования или Grafana.

## Аналитика тестов и шардирование

Запустите цели тестирования Once:

```bash
once test
```

Откройте раздел **Тесты**, чтобы просмотреть отчеты по наборам, случаям, длительности и сбоям. Результаты зависят от возможностей отчетности целевого теста; действие, запускающее процесс теста, не автоматически формирует отчет по каждому случаю.

Когда набор тестов становится слишком большим для одной машины, создайте план шардирования и распределите его пакеты между работниками CI. См. <.localized_link href="/guides/features/test-insights/once">Аналитика тестов Once</.localized_link> и <.localized_link href="/guides/features/test-sharding/once">Шардирование тестов Once</.localized_link>.

## Превью и размер бандла

Добавьте привязку артефактов к тому же провайдеру, чтобы публиковать поддерживаемые приложения для Android, симулятора Apple и macOS:

```toml
[infrastructure.artifacts]
name = "tuist"
```

```bash
once artifact publish MyApplication --track review
```

Полученная ссылка открывает превью вашего проекта; обработка может занять некоторое время. См. <.localized_link href="/guides/features/previews/once">Превью Once</.localized_link> для требований к подписи и возможности публикации после сборок.

Чтобы отслеживать размер бандла, используйте CLI Tuist отдельно для собранного `.app`, `.ipa`, `.xcarchive`, `.apk` или `.aab`. Следуйте <.localized_link href="/guides/features/bundle-insights">руководству по аналитике бандлов Apple или Android</.localized_link>; публикация артефакта Once не приводит к автоматической загрузке отчета о размере бандла.

## Непрерывная интеграция

Используйте токен аккаунта, авторизованный для операций проекта, в переменной `TUIST_TOKEN`, или выполните аутентификацию через идентификатор OpenID Connect поддерживаемого провайдера CI:

```bash
once auth login --provider tuist --no-browser
once build MyApplication
once test
```

В GitHub Actions предоставьте задаче права `id-token: write` и `contents: read`. См. пример в разделе <.localized_link href="/guides/integrations/continuous-integration#once">Once в непрерывной интеграции</.localized_link>. Личный вход разработчика не является учетными данными для CI.

## Удаленное выполнение

Аккаунты с включенным удаленным выполнением также могут запускать подходящие действия команд графа на Linux-воркерах Tuist. Это отличается от обмена результатами кеша и от запуска всего рабочего процесса CI. См. <.localized_link href="/guides/features/runners/once">Удаленное выполнение Once</.localized_link> для требований к воркерам и настройки.
