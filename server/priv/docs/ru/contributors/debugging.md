# Отладка {#debugging}

Открытость — это практическое преимущество: код доступен, его можно запустить локально, а также использовать AI-агенты для программирования, чтобы быстрее получать ответы и отлаживать возможные ошибки в кодовой базе.

Если во время отладки вы обнаружите отсутствующую или неполную документацию, обновите англоязычные документы в каталоге `server/priv/docs/en` и создайте PR.

## Снимок стека потоков в CI {#thread-dump-ci}

Когда CLI периодически зависает, можно сделать снимок стека потоков без остановки процесса. Включите обработчик сигналов и отправьте сигнал `SIGUSR1` работающему процессу `tuist`.

```bash
export TUIST_THREAD_DUMP_SIGNAL=1
export TUIST_THREAD_DUMP_SAMPLE=1 # macOS only, captures all threads via /usr/bin/sample
tuist generate &
TUIST_PID=$!
sleep 600
kill -USR1 "$TUIST_PID"
wait "$TUIST_PID"
```

Если переменная `TUIST_THREAD_DUMP_SAMPLE` не установлена, обработчик выводит стек текущего потока. Вывод записывается в stderr, поэтому он отображается в логах CI.

## Использование AI-агентов для программирования {#use-coding-agents}

AI-агенты для программирования полезны для:

- Поиска в кодовой базе мест, где реализовано определённое поведение.
- Воспроизведения проблем локально и быстрой итерации.
- Отслеживания потока входных данных через Tuist для поиска первопричины.

Предоставляйте минимально возможный пример воспроизведения и направляйте агента на конкретный компонент (CLI, сервер, кэш, документация или handbook). Чем уже область исследования, тем быстрее и точнее проходит отладка.

### Часто используемые промпты (FNP) {#frequently-needed-prompts}

#### Неожиданный результат генерации проекта {#unexpected-project-generation}

Генерация проекта выдаёт неожиданный результат. Запустите Tuist CLI для моего проекта по пути `/path/to/project`, чтобы понять причину. Проследите конвейер генератора и укажите участки кода, ответственные за полученный вывод.

#### Воспроизводимая ошибка в сгенерированных проектах {#reproducible-bug-in-generated-projects}

Похоже, это ошибка в сгенерированных проектах. Создайте воспроизводимый проект в каталоге `examples/`, используя существующие примеры как образец. Добавьте падающий приёмочный тест, запустите его через `xcodebuild`, выбрав только этот тест, исправьте проблему, повторно запустите тест для подтверждения успеха и создайте PR.
