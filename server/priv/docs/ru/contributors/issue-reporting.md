# Сообщение об ошибках {#issue-reporting}

Как пользователь Tuist, вы можете столкнуться с ошибками или неожиданным поведением. Если это произойдет, мы рекомендуем сообщить о них, чтобы мы могли их исправить.

## GitHub Issues — наша платформа для обработки заявок {#github-issues-is-our-ticketing-platform}

Ошибки следует сообщать на GitHub в виде [задач GitHub](https://github.com/tuist/tuist/issues), а не в Slack или на других платформах. GitHub лучше подходит для отслеживания и управления ошибками, ближе к кодовой базе и позволяет нам следить за прогрессом решения проблемы. Кроме того, он стимулирует подробное описание проблемы, что заставляет автора задуматься о ней и предоставить больше контекста.

## Контекст имеет решающее значение {#context-is-crucial}

Задача без достаточного контекста будет считаться неполной, и у автора запросят дополнительную информацию. Если она не будет предоставлена, задача будет закрыта. Думайте об этом так: чем больше контекста вы предоставите, тем легче нам будет понять проблему и исправить ее. Поэтому, если вы хотите, чтобы ваша ошибка была исправлена, предоставьте как можно больше контекста. Постарайтесь ответить на следующие вопросы:

- Что вы пытались сделать?
- Как выглядит ваш граф зависимостей?
- Какую версию Tuist вы используете?
- Блокирует ли это вашу работу?

Мы также требуем предоставить минимальный **воспроизводимый проект**.

## Воспроизводимый проект {#reproducible-project}

### Что такое воспроизводимый проект? {#what-is-a-reproducible-project}

Воспроизводимый проект — это небольшой проект Tuist, демонстрирующий проблему — часто эта проблема вызвана ошибкой в Tuist. Ваш воспроизводимый проект должен содержать минимально необходимые возможности для четкой демонстрации ошибки.

### Зачем создавать воспроизводимый тест-кейс? {#why-should-you-create-a-reproducible-test-case}

Воспроизводимый проект позволяет нам изолировать причину проблемы, что является первым шагом к ее исправлению! Самая важная часть любого отчета об ошибке — описание точных шагов, необходимых для воспроизведения ошибки.

Воспроизводимый проект — отличный способ поделиться конкретной средой, вызывающей ошибку. Ваш воспроизводимый проект — лучший способ помочь людям, которые хотят вам помочь.

### Шаги по созданию воспроизводимого проекта {#steps-to-create-a-reproducible-project}

- Создайте новый git-репозиторий.
- Инициализируйте проект с помощью `tuist init` в директории репозитория.
- Добавьте код, необходимый для воспроизведения увиденной ошибки.
- Опубликуйте код (ваш аккаунт GitHub хорошо подходит для этого), а затем добавьте ссылку на него при создании задачи.

### Преимущества воспроизводимых проектов {#benefits-of-reproducible-projects}

- **Меньшая площадь поиска:** Удалив все лишнее, кроме ошибки, вам не придется копаться в коде, чтобы найти баг.
- **Не нужно публиковать секретный код:** Вы можете не иметь возможности опубликовать свой основной проект (по многим причинам). Создание небольшой его части в виде воспроизводимого тест-кейса позволяет публично продемонстрировать проблему, не раскрывая секретный код.
- **Доказательство наличия ошибки:** Иногда ошибка вызвана некоторой комбинацией настроек на вашей машине. Воспроизводимый тест-кейс позволяет участникам скачать вашу сборку и протестировать ее на своих машинах. Это помогает проверить и сузить круг причин проблемы.
- **Получите помощь в исправлении ошибки:** Если кто-то другой может воспроизвести вашу проблему, у него часто есть хорошие шансы исправить ее. Практически невозможно исправить ошибку, не имея возможности сначала ее воспроизвести.
