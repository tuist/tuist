# Отчёт об ошибках {#issue-reporting}

При использовании Tuist вы можете столкнуться с ошибками или неожиданным поведением. Если это произойдёт, сообщите нам о них, чтобы мы могли их исправить.

## GitHub Issues — наша система отслеживания задач {#github-issues-is-our-ticketing-platform}

Ошибки следует регистрировать на GitHub в виде [GitHub issues](https://github.com/tuist/tuist/issues), а не в Slack или на других платформах. GitHub лучше подходит для отслеживания и управления задачами, ближе к кодовой базе и позволяет следить за прогрессом решения проблемы. Кроме того, он стимулирует подробное описание проблемы, что заставляет автора глубже разобраться в ней и предоставить больше контекста.

## Контекст имеет решающее значение {#context-is-crucial}

Задача без достаточного контекста будет считаться неполной, и автору будет предложено добавить дополнительную информацию. Если контекст не будет предоставлен, задача будет закрыта. Помните: чем больше контекста вы дадите, тем проще нам понять проблему и исправить её. Поэтому, если хотите, чтобы вашу ошибку исправили, предоставьте как можно больше информации. Постарайтесь ответить на следующие вопросы:

- Что вы пытались сделать?
- Как выглядит ваш граф зависимостей?
- Какую версию Tuist вы используете?
- Это блокирует вашу работу?

Также требуется предоставить минимальный **воспроизводимый проект**.

## Воспроизводимый проект {#reproducible-project}

### Что такое воспроизводимый проект? {#what-is-a-reproducible-project}

Воспроизводимый проект — это небольшой проект Tuist, демонстрирующий проблему; часто эта проблема вызвана ошибкой в Tuist. Ваш воспроизводимый проект должен содержать только те возможности, которые необходимы для чёткой демонстрации ошибки.

### Зачем создавать воспроизводимый тест-кейс? {#why-should-you-create-a-reproducible-test-case}

Воспроизводимый проект позволяет изолировать причину проблемы, что является первым шагом к её исправлению! Самая важная часть любого отчёта об ошибке — точное описание шагов, необходимых для воспроизведения бага.

Воспроизводимый проект — отличный способ поделиться конкретной средой, вызывающей ошибку. Такой проект — лучший способ помочь тем, кто хочет вам помочь.

### Шаги по созданию воспроизводимого проекта {#steps-to-create-a-reproducible-project}

- Создайте новый Git-репозиторий.
- Инициализируйте проект с помощью `tuist init` в директории репозитория.
- Добавьте код, необходимый для воспроизведения наблюдаемой ошибки.
- Опубликуйте код (ваш аккаунт на GitHub хорошо подходит для этого) и добавьте ссылку на него при создании задачи.

### Преимущества воспроизводимых проектов {#benefits-of-reproducible-projects}

- **Меньшая площадь поиска:** Убрав всё лишнее, кроме самой ошибки, вам не придётся копаться в коде, чтобы найти баг.
- **Не нужно публиковать конфиденциальный код:** Вы можете не иметь возможности опубликовать основной проект (по разным причинам). Создание небольшой его части в виде воспроизводимого тест-кейса позволяет публично продемонстрировать проблему, не раскрывая секретный код.
- **Доказательство наличия ошибки:** Иногда ошибка возникает из-за определённой комбинации настроек на вашем компьютере. Воспроизводимый тест-кейс позволяет другим участникам скачать вашу сборку и протестировать её на своих машинах. Это помогает подтвердить и сузить круг возможных причин проблемы.
- **Получите помощь в исправлении ошибки:** Если кто-то ещё может воспроизвести вашу проблему, у него есть хорошие шансы её исправить. Исправить баг практически невозможно, пока его не удалось воспроизвести.
