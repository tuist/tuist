# Отчёты об ошибках {#issue-reporting}

При использовании Tuist вы можете столкнуться с ошибками или неожиданным поведением. Если это произойдёт, пожалуйста, сообщите о них, чтобы мы могли их исправить.

## GitHub Issues — наша платформа для отслеживания задач {#github-issues-is-our-ticketing-platform}

Сообщения об ошибках следует создавать на GitHub в виде [GitHub issues](https://github.com/tuist/tuist/issues), а не в Slack или на других платформах. GitHub лучше подходит для отслеживания и управления ошибками, ближе к кодовой базе и позволяет следить за прогрессом решения. Кроме того, он стимулирует подробное описание проблемы, что заставляет автора глубже продумать её и предоставить больше контекста.

## Контекст имеет решающее значение {#context-is-crucial}

Сообщение без достаточного контекста будет считаться неполным, и у автора запросят дополнительную информацию. Если она не будет предоставлена, сообщение закроют. Помните: чем больше контекста вы дадите, тем проще нам понять проблему и исправить её. Поэтому, если хотите, чтобы вашу ошибку исправили, предоставьте как можно больше контекста. Постарайтесь ответить на следующие вопросы:

- Что вы пытались сделать?
- Как выглядит ваш граф зависимостей?
- Какую версию Tuist вы используете?
- Это блокирует вашу работу?

Также необходимо предоставить минимальный **воспроизводимый проект**.

## Воспроизводимый проект {#reproducible-project}

### Что такое воспроизводимый проект? {#what-is-a-reproducible-project}

Воспроизводимый проект — это небольшой проект Tuist, демонстрирующий проблему; часто эта проблема вызвана ошибкой в Tuist. Ваш воспроизводимый проект должен содержать лишь минимально необходимые возможности для чёткой демонстрации ошибки.

### Зачем создавать воспроизводимый тест-кейс? {#why-should-you-create-a-reproducible-test-case}

Воспроизводимый проект позволяет изолировать причину проблемы, что является первым шагом к её исправлению! Самая важная часть любого отчёта об ошибке — описание точных шагов для её воспроизведения.

Воспроизводимый проект — отличный способ поделиться конкретной средой, вызывающей ошибку. Такой проект лучше всего помогает тем, кто хочет вам помочь.

### Шаги по созданию воспроизводимого проекта {#steps-to-create-a-reproducible-project}

- Создайте новый Git-репозиторий.
- Инициализируйте проект с помощью `tuist init` в директории репозитория.
- Добавьте код, необходимый для воспроизведения наблюдаемой ошибки.
- Опубликуйте код (ваш аккаунт на GitHub хорошо подходит для этого) и добавьте ссылку на него при создании сообщения об ошибке.

### Преимущества воспроизводимых проектов {#benefits-of-reproducible-projects}

- **Меньшая площадь поиска:** Убрав всё лишнее, кроме самой ошибки, вам не придётся долго искать её причину.
- **Не нужно публиковать конфиденциальный код:** Возможно, вы не можете опубликовать основной проект (по разным причинам). Создание небольшой его части в виде воспроизводимого тест-кейса позволяет публично продемонстрировать проблему, не раскрывая секретный код.
- **Доказательство наличия ошибки:** Иногда ошибка возникает из-за определённой комбинации настроек на вашем компьютере. Воспроизводимый тест-кейс позволяет другим участникам скачать вашу сборку и протестировать её на своих машинах. Это помогает подтвердить и сузить круг возможных причин проблемы.
- **Получите помощь в исправлении ошибки:** Если кто-то другой сможет воспроизвести вашу проблему, у него высоки шансы её исправить. Исправить ошибку практически невозможно, пока её нельзя воспроизвести.
