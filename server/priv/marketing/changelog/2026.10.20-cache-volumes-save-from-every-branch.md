---
title: Cache volumes now save from every branch
description: "Successful jobs from any branch of your repository, including pull requests, now save their cache volume changes. You can still limit saving to specific branches on the runner profile."
category: "Product"
pull_request: 14422
---

Cache volumes keep dependency directories between CI jobs. Until now, only successful jobs on the default branch saved their changes, so pull requests kept starting from whatever the default branch last saved.

With GitHub Actions, every successful job from your repository now saves its changes, including pull requests from the same repository. Pull requests from forks and `pull_request_target` jobs never save. A job that doesn't change a volume leaves the saved version in place.

![The new runner profile form with the Save cache from section expanded and Limit to specific branches turned off](/marketing/images/changelog/2026.10.20-cache-volumes-save-from-every-branch.png)

To save only from some branches, open **Runners → Profiles**, edit the profile your workflows use in `runs-on:`, expand **Save cache from**, and turn on **Limit to specific branches**. You can then keep the default branch and add branch names or patterns such as `release/*`. Profiles that already limit saving to specific branches keep their settings. Buildkite and GitLab CI keep saving from the default branch. See the [cache volumes guide](https://tuist.dev/en/docs/guides/features/runners/cache-volumes#choose-which-branches-save) for details.
