---
title: Test reliability automations now measure your default branch
description: "Reliability alerts stop counting pull-request runs, so uploading pre-commit test results no longer moves the numbers that quarantine your tests."
category: "Product"
pull_request: 12461
---

A reliability automation used to measure every run of a test, whichever branch it came from. That made uploading pre-commit results a trade: you either kept those runs out of Tuist and lost the failure reports with them, or you let a work-in-progress failure on someone's branch move the same number that decides whether an established test gets quarantined.

Reliability automations now measure runs on your project's default branch. There is nothing to configure: existing alerts pick it up, and the branch they use is the one set in your project settings. Send your pre-commit runs to Tuist and you get the reports, the failure detail and the history, while the reliability figure keeps describing your trunk.

Flakiness automations are unchanged and still measure every branch, because a test that flakes on pull requests is wasting time whether or not your trunk is clean.

Recovery follows the same scope. A quarantined test that stops running on your default branch is no longer treated as having recovered just because there is nothing left to measure, so it stays quarantined until real trunk runs prove it healthy again.
