Cache volumes keep dependency directories between CI jobs. Until now, only successful jobs on the default branch saved their changes, so teams that don't run CI on the default branch after every merge saw their caches fall behind during the day.

You can now choose which branches save. Open **Runners → Profiles**, edit the profile your workflows use in `runs-on:`, and expand **Save cache from**. Jobs on each repository's default branch keep saving, and you can add branch names or patterns such as `release/*`, or `*` to let every branch in the repository save. To save only from the branches you add, turn off **Default branch**. The settings apply to every cache volume used by jobs on that profile, including the new volumes you get when your cache key changes.

![The runner profile form with the Save cache from section expanded, with Default branch turned on and develop and release/* added as additional branches](/marketing/images/changelog/2026.10.15-cache-volume-branches.png)

Existing workflows keep working as before. Pull requests from forks never save. See the [cache volumes guide](https://tuist.dev/en/docs/guides/features/runners/cache-volumes#choose-which-branches-save) for details.
