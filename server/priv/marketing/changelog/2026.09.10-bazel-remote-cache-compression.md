---
title: Move Bazel remote-cache traffic with less bandwidth
description: "The Tuist remote cache now negotiates zstd wire compression with Bazel, shrinking cache upload and download bytes without changing what the cache stores."
category: "Product"
---

Bazel's client turns on wire compression by default when the remote cache advertises support. The Tuist cache now negotiates the [zstd compressor](https://facebook.github.io/zstd/) on both `ByteStream` transfers and `BatchUpdateBlobs`/`BatchReadBlobs`, so cache uploads and downloads from Bazel move meaningfully fewer bytes over the network on typical action outputs.

Cache contents on disk are unchanged: compression is a wire-only concern, verified against the same content digest Bazel already sends, so cache accounting and deduplication behave exactly as before. Existing Bazel projects pick this up automatically once they run against an updated Tuist cache; older clients keep working with uncompressed transfers.
