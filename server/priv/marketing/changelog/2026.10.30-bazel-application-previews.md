Getting feedback on a change shouldn't require everyone to build it themselves. Bazel and Gradle projects can now share apps and native command-line tools directly through **Tuist Previews**, so teammates can try a build without setting up the project.

With Gradle, run `./gradlew :app:tuistShareDebug --track nightly` for an Android app, or `./gradlew :app:tuistShareMainDebug` for a native C++ or Swift application. With Bazel, add a preview target alongside your Android app, Apple simulator or macOS app, or executable, then run it with `--publish --project account/project`.

Native command-line previews include their declared runtime dependencies, so recipients can run the packaged tool outside your build directory. Both workflows use your existing Tuist authentication and project access, without a separate CLI upload step.

You stay in control of what reaches your team: ordinary builds never publish previews. When you do share a build, it appears alongside your project's other previews, with the same visibility and distribution settings.

Get started with the [Gradle preview guide](/en/docs/guides/features/previews/gradle) or [Bazel preview guide](/en/docs/guides/features/previews/bazel), then share a link so teammates can [run the preview](/en/docs/guides/features/previews/run/cli).
