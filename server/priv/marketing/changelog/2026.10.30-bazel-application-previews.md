Bazel projects can now publish applications through Tuist's existing **Previews** experience. Add an `android_preview` or `apple_preview` target, then run it with `--publish --project account/project` to share a verified signed APK or an ad-hoc signed Apple simulator or macOS application.

Publication uses your existing Tuist authentication, project visibility, and distribution. It runs after a successful build, outside cached actions. Ordinary builds and runs without publication consent make no publication requests; replaying an identical retained publication does not upload or create another preview.

The companion rules are available in the repository's `bazel/` module, not yet in the Bazel Central Registry. Physical-device Apple archives and unsigned applications are not supported by this flow.

The preview documentation now has dedicated Xcode, Gradle, and Bazel guides. See the [Bazel preview guide](/en/docs/guides/features/previews/bazel) for setup, eligible outputs, and retention.
