title: Single sign-on enforcement now covers the Tuist CLI, app and MCP clients
description: "When an organization enforces single sign-on, its members now have to sign in with its provider before Tuist connects the CLI, the Tuist app or an MCP client."
category: "Product"
pull_request: 15168
---

Organizations that enforce [single sign-on](/en/guides/integrations/authentication/sso#choose-an-enrollment-policy) already required it on their dashboard. Signing in to the Tuist CLI, the Tuist app, an MCP client or the API reference creates a credential that acts for you in every organization you belong to, so that now requires it too: if you signed in another way, Tuist sends you to your organization's provider first, and sign-in with an email and password or with Apple is refused.

Credentials issued earlier keep working until they expire. If you belong to several organizations that enforce single sign-on, one session can't satisfy all of them, so ask an organization admin for help.
