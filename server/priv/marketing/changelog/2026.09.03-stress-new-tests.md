A flaky test is cheapest to fix while its author still holds the context that produced it. Tuist can now rerun the test cases a branch adds, several times each in a fresh process, and flag any that pass and fail on the same commit before the change merges.

Every stressed test case is badged in the run's test case list, with the number of repetitions it earned and how many of them failed. A test case that disagreed with itself is flaky rather than failed, so it appears with the run's flaky tests, expandable to each repetition and the failure it produced.

![A test run's test case list, with new test cases badged by the number of repetitions they were rerun and one showing that 3 of 10 failed](/marketing/images/changelog/2026.09.03-stress-new-tests.png)

The gate is off unless you enable it, and it takes a mode rather than a switch, so anyone reading the pipeline can see whether the job can fail on flakiness. Start with `report`, which prints a warning for each disagreement and leaves the run's own result alone, then move to `enforce` once you trust what it finds:

```sh
tuist xcodebuild test --stress-new-tests report -scheme MyScheme
```

Gradle takes the same modes through a `stressNewTests` block in `settings.gradle.kts`, and both read the `TUIST_TEST_STRESS_NEW_TESTS` environment variable so you can vary the mode per matrix lane.

Each test case is rerun according to its own duration, so a fast test earns ten repetitions and a slow one earns two. The pass reuses what the first pass built, stops at 200 test cases and ten minutes of wall-clock time, and says so whenever a bound bites. Those parameters live on your project and are tuned from telemetry, so they never wait on a release.

Repetitions the gate solicits are recorded apart from your organic flakiness data. They never mark a test flaky, never trigger alerts, and never quarantine anything, so turning the gate on cannot move the numbers you already act on.

Learn more in the [flaky tests documentation](https://tuist.dev/en/docs/guides/features/test-insights/flaky-tests/xcode#stress-testing-new-tests).
