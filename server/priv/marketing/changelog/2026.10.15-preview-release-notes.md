---
title: Add build context to app previews
description: "Attach release notes to preview builds and filter previews by track in the iOS app."
category: "Product"
---

App previews now support optional release notes, so testers can understand what changed in a build without opening its commit. Add them when sharing an app:

```bash
tuist share App --track QA --release-notes "Fix sign-in and improve checkout"
```

Web and iOS preview lists show the first release-notes line, so build numbers and other identifying information are visible at a glance. Long lines are truncated, with full notes on the detail pages. Search on both platforms matches app names and full release notes. Tracks remain independent groups for environments such as QA, beta, or nightly. The iOS app now shows each preview's track beside its commit hash and offers searchable previews with track pills below the project selector. Each pill shows its full-project build count, and the selected track is highlighted in purple. Search and track filtering apply across all pages; choose All to return to every track without a separate Clear button or text-entry dialog.

The macOS app also discovers previews from every branch, rather than only the project's default branch, and launches the app selected in its menu.

Self-hosted deployments need an updated server, CLI, and companion app to use release notes and track filtering.
