---
title: Give the wider team read-only access with the viewer role
description: "Organizations can now add members who read dashboards, builds, and test insights without being able to change anything."
category: "Product"
pull_request: 12641
---

Organizations had two roles, admin and user, and both could act on what they saw. Muting or skipping a flaky test case, deleting a preview, writing to the cache: a user could do all of it. Opening your build and test insights to the wider engineering team therefore meant handing every one of them the ability to quarantine a test.

Members can now be added as **viewers**. A viewer reads projects, builds, test runs, flaky and quarantined tests, previews, bundles, and runner activity, and cannot change any of it. Where a control would mutate something, a viewer sees the current value instead: a quarantined test case still shows that it is muted, it just cannot be un-muted from that page.

Set the role when you invite someone from **Members**, or change an existing member's role from the same page. Organizations using single sign-on can also pick which role automatic enrollment grants, so opening sign-in to everyone in the directory no longer implies giving everyone write access.

Whether a viewer counts towards a paid seat has not changed with this release.
