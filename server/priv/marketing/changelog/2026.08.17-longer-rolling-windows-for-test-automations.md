---
title: Set test automation rolling windows up to 1000 runs
description: "Rolling windows on test automation triggers now go up to 1000 runs, matching what recovery windows already allowed."
category: "Product"
pull_request: 12420
---

A test automation with a rolling window measures the last N runs of each test case. The "Last N runs" field on a trigger accepted at most 75, while the matching field on a recovery rule already accepted up to 1000. Both now accept up to 1000.

The gap made one useful shape impossible to express: quarantine a test that turns flaky, then only un-quarantine it once it has passed a few hundred consecutive runs. That rule needs the trigger window and the recovery window to be the same size, so the trigger's lower limit capped both.

A rolling window above 75 runs starts measuring once the test case has accumulated that many runs. Until then the automation stays quiet rather than judging a 500-run rule against the handful of runs recorded so far. Automations using windows of 75 runs or fewer are unaffected and keep evaluating exactly as before.
