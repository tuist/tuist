# Cargo insights

The Tuist CLI decorates Cargo. Builds and compiler invocations are retained for 90 days in ClickHouse; tests use shared test ingestion with `build_system: cargo`.

- A compilation is a rustc invocation. Never describe its duration as per-source-file timing, Cargo scheduling time, or cache-hit time.
- Scope every read to the selected project. Parent build authorization must precede child reads.
- Exclude legacy `nextest` command reports from all build lists, options and analytics; nextest execution belongs in Tests, not build-duration measurements. Explicit `test-build` reports remain builds.
- Overview and Builds home analytics reuse the shared schema-parameterized analytics engine with a project-scoped build cohort. The Builds home applies Rust-version/environment filters to counts, success rates and duration percentiles. Configuration groups are allowlisted and capped at 100; scatter reads are capped at 10,000 with explicit truncation. Recent builds are bounded, ordered newest-first, and respect the selected cohort and date range. Keep both dashboards separate from the Build Runs history, whose cursor ordering includes the build UUID to stabilize equal timestamps/durations.
- Bound reports and diagnostics before buffering. Do not store arbitrary compiler arguments or environment variables.
- `CacheMetrics` validates optional wire version 1 with an exact allowlist of nonnegative bounded counters and stores it in `cargo_builds.cache_metrics` as JSON. Blank/malformed legacy values do not invent measurements. Preserve distinct lookup-miss, unconsulted and verification counters on the wire and in storage. The task-reuse presentation groups all three as task misses (compiled rather than reused); `task_misses/1` and `hit_rate/1` use aggregate counters independently of partial task records. Speculative prefetches never count as task hits or misses; downloaded bytes do not establish per-action remote-hit provenance. Estimated avoided compiler work is not wall-clock savings. Credentials, arbitrary compiler arguments and private agent events never enter cache metrics.
- `CacheDetails` validates the optional version-1 inspection object nested in the existing `cache_metrics` JSON: up to 2,000 task decisions, 5,000 SHA-256 CAS operations, 128 references per task and 4 MB total. Reject unknown/private fields, invalid tagged identities, contradictory operation/outcome pairs and unbounded durations. Legacy/corrupt details must leave valid aggregates available without invented rows. Export/retention/authorization follow the parent Cargo build.
- `Cache` powers the project cache dashboard with ClickHouse-side per-build average/percentile reuse rates, preceding equal-length period trends, daily series, lazy 10,000-point scatter and at most 50 recent builds with batched reporter preloads. Recent rows omit the potentially 4 MB inspection JSON and batch scalar cache availability/rates in ClickHouse instead. Deduplicate report retries using their first-seen row within a bounded 24-hour lookback before applying period boundaries, and share project, half-open date, environment and non-nextest scopes across every read. Extract raw top-level JSON fields and inspection arrays before per-field validation/aggregation so large inspection documents are not reparsed for every counter. Aggregate counters supply hit rates and transfer bytes even when inspection is partial; task index timings supply latency, and only successful positive-duration CAS operations supply time-weighted throughput. Missing telemetry remains unavailable, distinct from measured zero. Never infer hit origin or elapsed savings.
- Keep the CLI wire contract, API schema, migrations, documentation and data-export inventory aligned.
