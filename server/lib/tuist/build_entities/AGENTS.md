# Persistent build inventories

## Boundary
- `Tuist.BuildEntities` owns run-independent identities and bounded cross-run observation queries. Native facts remain authoritative for execution details.
- Supported storage and REST/MCP resources: Gradle tasks, Xcode modules, declared Once action slots, Bazel BEP actions, Mix files and Mix modules. `Resources.dashboard_resources/0` excludes Mix files; hiding that dashboard must not remove its descriptor, native ingestion or public tools/endpoints. Xcode compilation-cache keys and Bazel digests are not stable logical identities; preserve their native run/cache routes.
- Identities use versioned length-prefixed encoding and deterministic project/system/kind and observation UUIDs. Preserve field order and collision fixtures. Gradle includes root project/build/task paths and type; Xcode includes project/target; Once requires declared target/capability/index mappings; Mix uses reported paths or qualified module names. Bazel uses exact target label, mnemonic and configured primary output: never truncate fields or substitute cache/action digests. BEP start time distinguishes attempts. Older incomplete payloads remain accepted but unindexed.

## Rollout and writes
- `FeatureFlags.build_entities_enabled?/1` requires project `:build_entities` enrollment and an inactive `:build_entities_kill_switch` in every environment. Check before producer mapping, Once mapping persistence and new public surfaces. Native ingestion/legacy pages continue while disabled. Tests enroll their own project, never globally in async tests.
- Batch through `Observation.Buffer`; never query/upsert the catalog during ingestion. The materialized view derives duplicate-insensitive identity/min/max/name states. Evaluate flags once per distinct project per batch.
- Once publication uses synchronous `record/2`, a PostgreSQL run lock and `build_entities_published_at`. Mark only after ClickHouse acknowledges the whole batch. Replayed completion/recovery skips published runs. A crash between acknowledgement and commit can replay; deterministic IDs and replacement-safe reads remain mandatory. See [../once_events/AGENTS.md](../once_events/AGENTS.md).
- Missing trustworthy identity skips derivation, not previously accepted reports. Retry invariance requires the same native parent/event identity; a new build ID denotes a new execution.

## Replacement and query invariants
- Observations use `ReplacingMergeTree(inserted_at)` with stable `(project_id, system, kind, entity_id, id)` sorting, independent of mutable observed time. Versions can span insertion-month partitions.
- Resolve the whole latest row with `FINAL` before time/cohort/table/execution predicates, retaining NULL clears. `bounded_query/3` adds non-overridable `do_not_merge_across_partitions_select_final: 0`, `optimize_move_to_prewhere_if_final: 0`, and `use_skip_indexes_if_final: 0`.
- Explicit `PREWHERE` selects only whole replacement groups by project/system/kind/entity ID, never mutable time, partition or evidence. Catalog range/search candidates safely overapproximate IDs; exact membership/counts use latest observations.
- Preserve bounded windows, thread/memory/spill/deadline budgets, page sizes, 100-parent batches and the 10,000-plus-one scatter cap. Query-limit failures are errors, never empty facts/not-found responses.
- Count-plus-page uses windows with an empty-page fallback; history totals precede cursor filtering. Unfiltered inventory membership stays catalog-only; optional internal/legacy Branch/Status/Cache predicates match the same latest observation before metrics/sort/pagination. Allowlist operators/fields and parameterize values. Dashboard inventories do not expose those filters.
- Inventory analytics use kind-scan budgets and whole selected cohorts, independent of table search/sort/pagination. `GROUPING SETS` combines period/daily aggregates. Period and daily distinct active entities are separate and nonadditive. Explicit success/failure counts distinguish unknown outcomes from measured zero failures.
- Gradle/Once/Bazel `executions` require uncached explicit success/failure, independently of optional timing; hits/skipped/up-to-date/no-source/cancelled/unknown do not qualify. Mix counts reported compilations, including untimed records. `executions_only: true` applies this evidence (or measured Xcode compilation evidence) to detail analytics/history/scatter after replacement resolution; default public history remains unchanged.
- Dashboard inventory reads use `execution_durations_only: true`: duration aggregates and scatter exclude timed cache hits and unexecuted actions without losing catalog membership. Real executed zero remains zero. Public/default reads retain their existing semantics. Scatter carries identity/name from the same latest observation, with no per-point lookups. Legacy Mix module scatter deduplicates parent/file executions before the cap; missing references never collapse unrelated observations.

## Default-branch Xcode module state
- Capture server-attributed `xcode_graphs.project_id` and nullable `modules_count` from distinct reported project/module-name pairs, including noncacheable modules, in the native graph header. This is a reported workspace snapshot, not proof that every workspace in a repository was included. An explicitly empty graph is zero; old uncounted graphs remain NULL. Do not backfill counts from cache/execution observations or partly flushed target rows.
- `default_branch_module_counts/3` requires matching project scope on both graph headers and command events, even when client event IDs collide across tenants. Legacy unscoped headers cannot supply a count. Resolve the latest whole event tuple before branch/time predicates so metadata corrections cannot resurrect an old cohort; retained scoped graph IDs bound candidates. A project-leading projection indexes new headers, without materializing/backfilling historical parts. Use the latest graph before the selected period end, with a preperiod state and daily carry-forward. A newer NULL invalidates older known counts. No configured branch or retained snapshot means unavailable, not zero. This state is independent of environment, search and execution filters.
- Bound graph insertion pruning, event lookback and the selected period; use kind-scan budgets. Deterministic version ties include event time, graph insertion time and graph ID. Tuple-wrapped nullable aggregation must retain clears. The source retains graphs for 30 days; older chart portions can be unavailable. Snapshot errors must not hide execution analytics or the table.

## Evidence and presentation
- Bazel observations come only from signed BEP diagnostics, never trace phases/REAPI traffic. Require all-actions publication for complete coverage; retain best-effort/drop semantics. Do not claim a complete target inventory. Measured BEP zero remains zero; absent/invalid end times stay untimed. Resolve string invocation IDs in one project-scoped latest-row batch, without inferred actors. Native diagnostics/cache pages remain compatible while collection is off.
- Never invent timing, outcome, cache, environment or actor evidence. Cache writes are not misses. Missing differs from measured zero.
- Xcode graph/cache and activity-log records share project/target identity. Graph observations have no compilation timing/outcome. Build observations require positive native `compilation_duration`; zero means no work and is omitted. Use discriminator `compilation:<ordinal>`, execution reference `build_target:<ordinal>` and native build parent; graph parents stay command events. Resolve parent context in bounded native batches and link compilation history/scatter to Build Runs.
- Mix module timings remain shared containing-file measurements in storage/public interfaces, not additive independent module work. The module dashboard hides duration widgets/columns/sorting/scatter. Once capability/index remain identity fields even though hidden in dashboard presentation; task type/Bazel mnemonic use type badges without identity changes.
- Inventory Last status/Last ran at use the existing aggregate scan and deterministic observed-time/ID recency after replacement/cohort predicates. Cache hits never qualify; Xcode needs measured work, Gradle/Once/Bazel explicit executed outcomes, and Mix a compilation report. Unknown latest outcomes never fall back to older success. Missing execution is NULL, never catalog Last seen. Nulls sort last both directions before pagination. `include_metrics: false` preserves metadata-only public shapes.
- Aggregate duration samples/average/p50/p90/p99 before sorting/paging. Missing durations sort last both ways; executed zero stays numeric. Timed dashboards default to descending p90, Mix modules to descending Last ran at; API ordering is unchanged.
- Parent metadata is optional and project-scoped: one native-parent batch and one recorded-user batch. Missing/deleted/org actors remain unknown, never inferred from viewer/project owner. Explicit provenance verifies only `actor_account_id`; opaque claims stay unverified. Empty-provenance parents retain historical publisher attribution. Latest nullable native metadata uses `argMax(tuple(value), version).1` to preserve clears.
