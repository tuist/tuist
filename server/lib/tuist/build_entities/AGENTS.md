# Persistent Build Entities

This boundary owns deterministic cross-run identities, the slim ClickHouse observation index, native ingestion adapters and shared bounded filter parsing. Public dashboard, API and MCP resources use Tasks, Actions, Modules or Files, never generic entity terminology.

## Contracts
- Identity contracts are versioned and length-prefixed. Project, toolchain, kind and every declared identity field contribute to the stable ID. Display names, branches, dates and individual run IDs do not.
- Gradle tasks include root project/build/task paths and type. Generated Xcode modules include project and target. Xcode/Bazel cache actions identify exact keys/digests, not logical operations across changing inputs. Once actions require declared target/capability/index mappings. Mix files use reported paths and modules use qualified names.
- Older reports remain valid. Missing native identity mappings skip only the new derived observation; never reject a previously accepted report. Unknown telemetry must not become success, a cache miss, or zero duration.
- `record/1` never performs catalog lookups. Use `Observation.Buffer` and deterministic observation IDs; native facts remain authoritative for execution detail. Submit a report's observations as a batch, not one insert per entity. ClickHouse's `build_entities_mv` populates the catalog automatically from flushed observation batches. Once's run-local target mappings are idempotent PostgreSQL projections, not per-action catalog upserts; resolve them in one run-scoped join at finalization. Replay invariance requires the same native parent/event identity, not a newly minted build ID.

## Storage and Reads
- `build_entity_observations` is sorted by `(project_id, system, kind, entity_id, id)` and replacement-versioned by `inserted_at`. Observed time is not a replacement key: a correction may move it. Prototype databases with the earlier entity/time/id key must be recreated in isolation before using the new reader. Deduplicate observations before counts, averages or percentiles, including before time/cohort filtering when replayed records can change those fields. Do not add replay-sensitive daily distribution materialized views.
- `build_entities` stores immutable identity plus duplicate-insensitive first/last-seen and observed-time latest-name state. Read merged aggregate states without assuming background merges completed.
- Keep duration and execution outcome separate from cache outcome. Executed work distributions exclude Gradle hit/skip/up-to-date/no-source timings. Cache-operation timing is not compilation duration; Mix module timing is its containing file's compilation.
- Observation retention is 30 days for generated Xcode modules and 90 days otherwise. Catalog metadata expires after 365 days of inactivity. No deployment-time unbounded backfill.
- Observation reads use `FINAL` to resolve the whole latest row (NULL corrections included) before time/cohort filters. Pin `do_not_merge_across_partitions_select_final: 0`, `optimize_move_to_prewhere_if_final: 0` and `use_skip_indexes_if_final: 0`; never add insertion-time partition pruning or non-key PREWHERE. Explicit PREWHERE is restricted to project/system/kind/entity-ID key predicates, selecting whole replacement groups before payload reads. Native parent reads still use `argMax` tuples because some tables are plain MergeTree. Use in-order catalog aggregation, two threads, bounded blocks/streams and external group/sort spill thresholds. Entity/page reads have a 256 MiB/20-second ceiling; kind-wide catalog and membership scans have a 512 MiB/30-second ceiling. Client timeouts allow five extra seconds. Time/memory limit codes raise `QueryLimitError`; REST returns 503, MCP returns a normal tool error, and async cards retain their error state rather than fabricated empty results.
- Older Kura events without a producer `event_id` remain accepted in native ingestion but do not create derived observations. Content hashing would conflate distinct identical lookups. Once history references the project-scoped client run ID used by its native route; unstorable target mappings are skipped without truncating identity or rejecting an event stream.
- `Params` accepts fixed environment values, half-open ranges within 90 days and bounded pagination/cursors without creating atoms from input. API/MCP share it; dashboard preserves its selected period across navigation.
- Dashboard activity searches branch, commit and native run/execution references after latest-row resolution. Only Branch, Outcome and Cache filters with fixed operators and parameterized values are supported. Timestamp/duration sorting happens before pagination, keeps missing durations last and breaks ties deterministically. Default newest-first reads retain opaque time cursors; alternative sorts use numbered pages bounded to 10,000 with the same read/spill limits.
- Duration sample counts are `count(duration_ms)`, never `observations`: hits, skips and missing native timings have no duration. `duration_scatter/5` resolves the latest row before period/environment/branch/cache filters, drops missing durations only after that, orders newest first by time and ID, and caps at 10,000 rows (fetching one more to report truncation honestly). It returns raw observations; series, grouping and native links belong to the surface.
- `parent_actor_names/4` is optional dashboard metadata for at most 100 parents per call: one bounded lookup per source (ClickHouse under entity read limits, then one Postgres batch), never per row, and no catalog, ingestion or schema change. It reports the attribution the native parent recorded, the same as native build run pages, including a personal project's owner when that account was recorded. Only user accounts are named; zero, missing, deleted or organization actors stay absent. Never derive an actor when attribution is missing (no project-account or viewer fallback, no recovery of credential details old reports never stored). The latest parent version decides, so lookups use `argMax(tuple(value), version).1`: plain `argMax` skips NULL and would resurrect a cleared actor. Bazel has no trustworthy actor and returns `%{}`.
- `parent_contexts/4` is the dashboard's single parent lookup per history page: one bounded query against the native parent (Gradle `gradle_builds`, Xcode `build_runs` or `command_events`, Mix `mix_builds`, Once `once_runs`, Bazel `bazel_invocations`) plus one name batch. Contexts exist only for parents in the project. Labels are the native human-readable names (Gradle root project with tags, Xcode scheme, raw Xcode or Bazel command, literal `mix compile`, Once `command_display`); a missing label stays `nil` and is never replaced by an ID or a guess. Labels stay raw; Xcode commands also carry the recorded `command_arguments` and Bazel invocations the recorded `target_patterns`, read in the same query, so surfaces can reuse native command rendering. Bazel `ran_by_name` is always `nil`. `parent_actor_names/4` delegates to it and still returns `%{}` for Bazel without querying.

## Validation
- Cover identity fixtures and collisions, cross-project/kind isolation, replay invariance, cross-month replacement (assert both physical partitions), delayed older writes, cleared NULLs, latest-name ordering, cache hit cohorts and unknown telemetry, cursor boundaries and native old/new producers. Run the isolated volume gates in `priv/benchmarks/` when changing SQL/storage. Inventory/history count-plus-page uses windows with an empty-page count fallback; history totals precede cursor filters. Filtered inventories join counts from one FINAL pass, restricted by catalog range/search candidates (an overapproximation across all versions). Keep time/cohort filters after FINAL and leave unfiltered inventories on their catalog-only membership path. Assert one query for a populated filtered page, exact filtered observation counts, false-positive catalog ranges and out-of-range totals. Analytics combines period and daily aggregates with GROUPING SETS, preserving nullable duration/sample semantics.
- Migrations follow repository ClickHouse engine policy. Update `server/data-export.md` and English retention docs when stored fields or TTLs change.
