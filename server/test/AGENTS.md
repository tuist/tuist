# Server Tests

This directory contains ExUnit tests for the Tuist Server.

## Testing Guidelines
- HTML assertions must not depend on serialized attribute order. Check portal-template event wiring with `Floki` selectors when LiveView's `element/2` cannot reach the portal content; retain the separate event-driven behavior assertions.
- Provider-initiated installation tests cover signed-out return paths, exact Origin receipt state/audience/expiry checks, GitHub App OAuth code exchange and exact installation access with bounded pagination/timeouts and cross-host conflict diagnostics, receipt-safe Origin setup failure logging, user/session expiry and state rejection, administrator-only selection with submission reauthorization, automatic attachment for a sole eligible account with the same authorization and provider-proof checks, idempotency, ownership-transfer denial, cancellation, and unchanged Tuist/GHES organization-state flows. Never treat an installation callback ID alone as proof.
- Release-environment regressions source the real shell template in subprocesses with process-local environment overrides, never mutate test-process System configuration, and cover private-cookie/listener guards plus non-colliding remote commands. Runtime child specs must retain DNS-discovered connections on failed/partial answers while preserving unrelated strategies. Isolated VM probes distinguish real node-monitor events from libcluster's misleading successful-disconnect log after a no-op callback; they do not prove enforced Kubernetes policies or physical-partition recovery.
- OAuth regressions exercise upstream client/token/code/scope stores after earlier lookups, then edit rows directly to prove authoritative reads. Seed unique entries in the real legacy cache and prove they remain ignored even after no-op invalidations. Reject replicated-cache calls at both default and explicit-options arities, preserve upstream return shapes for all token types and nil refresh keys, and require revocation to commit without cache availability. Scope-list keys are global: use a synchronous test and restore prior entries. Cover access/refresh revocation, expiry, code value/value+redirect lookups, client metadata/grants, deleted entities, database errors and routed denial. Code-ID lookups are database-path parity, not a cache discriminator; Boruta revocation does not establish issued-JWT revocation. Keep upstream adapters and avoid global configuration changes. Manual multi-instance checks must mix authoritative-reading compatibility and no-invalidation replicas, then exercise replacement, rollback to compatibility, cache loss, partitions and database-pool loss. A cache-reading legacy joiner is an explicitly unsupported negative control, not a supported rollback target. Mutating delete back into a replicated call must fail the no-cache-dependency checks. The existing refresh-token index remains unchanged.
- Endpoint privacy coverage must verify credentials, operator grants, and `x-tuist-actor-id` are absent both from the header scrubber output and the actual Sentry request-interface data, while ordinary headers remain.
- Persistent build identity coverage lives in `tuist/build_entities*`, native API/MCP tool tests and `tuist_web/live/build_entity_live_test.exs`, with `BuildEntitiesFixtures` for cross-surface records. Cover the five supported native kinds, explicit per-project `:build_entities` enrollment (never global enrollment in async tests), disabled/kill-switch native compatibility, durable Once publication and transient failure retries, FINAL/replacement safety settings, old/new producers, replay/time/cohort correction, stable cursors, tenant/toolchain isolation, optional measurements, bounded query errors and LiveView filter/retry/reuse behavior. Exact-key Xcode/Bazel action inventories are intentionally absent. Activity coverage checks latest-row search/outcome/cache filtering, full-cohort sorting before stable pages, missing durations last, safe sort allowlists, retained controls on history failure, and table-only analytics reuse. For inventories, Recent activity and History, assert that search/filter controls and the table share one white card section with no nested table section; functional search checks alone do not catch split-surface layout regressions. Cover aligned No data widget states for empty cohorts across native kinds, distinct metric-specific unavailability for populated cohorts, and genuine zero durations/hit rates. Assert native human-readable Project/Scheme/Command/Run context (including Gradle tags and recorded command inputs) as the first Recent activity/History column, Build Runs column order and shared Passed/Failed and Built by CI/user/Unknown cells. Parent IDs stay in tooltips/navigation, not displayed UUID text. Cover one project-scoped parent-context batch for labels/actors/Bazel link availability, historical recorded personal owners, explicit verified versus claimed actors without publisher inference, missing/deleted/org actors, latest-version label/argument/actor clearing, nullable environment and optional metadata query limits without hiding facts. Shared badge tests live in `tuist_web/components/runs/ran_by_badge_test.exs`; keep one module covering both legacy and explicit report actors. Keep entity outcomes/durations/cache results distinct from parent aggregates. Assert native inventory columns, root-build formatting, missing scope versus zero indices, and nonduplicated primary identifiers with differing names preserved as sublabels. Cover lazy duration scatter, grouping/table-patch reuse, independent query errors and Line recovery, truthful cap-plus-one truncation, native links, duration-sample tooltips, rate denominators/gaps, and omission of unsupported timing. Give real async reads an explicit timeout rather than relying on the default 100ms. Copy BuildEntities centrally in `test_helper.exs` for mocks, not in individual tests.
- Agent-marketing coverage checks authored landing-page inventory and docs links, original policy wording and statement access, bounded directory links, cookie-free explicit routes, alternate discovery, quality-aware negotiation, unchanged redirect/error responses, Cloudflare cache bypass only on converted marketing/docs Markdown responses (including HEAD), and unchanged CDN policy for HTML, errors, redirects, and unconverted bodies.
- Problem/comparison-guide coverage checks explicit Markdown-only delivery, English-only content, exclusion from browser routes/navigation and sitemap, `/llms.txt` inventory, robots.txt content usage for Markdown URLs, excluded intent files, review/source sections, agent-tool names, and documented feature limitations. The comparison overview must link to all 15 provider guides; recommendations and experiments remain Tuist-first without competitor-selection sections. Source contracts preserve researched cache mechanisms, MCP/analytics overlaps, and toolchain-specific restrictions rather than generic feature checkmarks. Cover project-first/environment-second ordering, non-mobile engineering examples, sourced billing units and exceptions, Namespace's standalone Bazel service, CircleCI OAuth restrictions, Buildkite macOS plan requirements, and configuration/telemetry qualifications. These assertions prevent copy regressions; they do not verify live vendor claims.
- Search-indexing coverage verifies crawlable public project overview HTML, noindex for every deeper dashboard route and failed response, query-free canonical URLs, and bounded public-only overview sitemaps. Keep private-project authorization and deep-dashboard challenges unchanged.
- Build-system-guide coverage distinguishes native toolchain capabilities from Tuist infrastructure, checks all five guides plus the index through decision-guide discovery, and keeps Once's canary status and upcoming remote execution explicit. Cover later-shard raw retry flakiness when duplicate identities collapse. Test write-through buffering does not establish production buffer durability or capacity.

Local Valkey/replica probes do not establish production capacity or a strict global quota under partitions/restarts.
