# Activity log parser

- This Swift package builds a standalone executable, despite the historical `nif` directory name. Parser crashes must remain isolated from the BEAM.
- The executable receives five paths: activity log, CAS database, legacy CAS metadata directory, summary JSON, and step JSONL. Write each step through the parser callback, leaving `BuildData.build_steps` empty in the production summary. The default array result remains available to library callers and tests.
- The CAS database is an immutable, checkpointed snapshot from the build archive, not the proxy's live database. Open it with SQLite's `immutable` URI option: on macOS, a read-only WAL-mode database without its `-wal`/`-shm` sidecars opened successfully but failed metadata queries. This failure was reproduced on macOS; production Linux already reads these archives, so the immutable option is portability hardening rather than a requirement for the production analytics fix. Keep the sidecar-free WAL regression and the compiler analytics ShellSpec in `kura/spec/e2e/xcode_analytics_spec.sh`.
- `BuildStepLog` normalizes at most the retained prefix/suffix and caps each step independently at 64 KiB. Retain the end of oversized output for diagnostics; never introduce a shared budget that starves later steps.
- Elixir consumes the sidecar within the parser callback and cleans up both output files on success or failure. Coordinate protocol changes with `lib/tuist/processor/xcactivitylog_parser.ex`.
- Validate this standalone server package with `swift test --replace-scm-with-registry` and `swift build -c release --replace-scm-with-registry`. The CLI's Xcode-only workflow does not apply to this package.
- Cacheable tasks follow Xcode's own `N hits / M cacheable tasks` report. When caching steps run, that is one task per cache key. Swift caching step titles wrap the key in a JSON array; Xcode 27 clang titles carry it bare (`Clang caching query key 0~…`) and mark the query with `cache hit` / `cache miss` notes. A queried hit is `hit_remote`, a key materialized without a query is `hit_local`. `xcode_27_clang_cache_hits` was recorded against a local Kura through the CAS plugin; reconcile new fixtures against the report line.
- A local-only cache (plugin enabled, no `COMPILATION_CACHE_REMOTE_SERVICE_PATH`) runs no caching steps. With `COMPILATION_CACHE_ENABLE_DIAGNOSTIC_REMARKS=YES`, each compile step carries hit notes (`Local cache found for key:` from Swift, `local cache found for key:` from clang modules, `replayed cache hit:` from clang compiles) or miss notes (`Local cache miss for key:`, `cache miss:`). Without remarks there are no notes and no tasks. Xcode counts one task per compile step, not per key: a batch-mode Swift job lists one `Local cache found` note per file and still counts once. Its single miss note makes the whole step a miss. Steps whose keys already have caching steps are skipped. `xcode_27_local_cache_misses` is a rebuild of a toy package (`-driver-batch-count 2`, private `COMPILATION_CACHE_CAS_PATH`) after editing one Swift and one C file.
