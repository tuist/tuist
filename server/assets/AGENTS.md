# Server Assets (JS/CSS)

This directory contains frontend assets for the Phoenix app (LiveView, marketing, apidocs).

## Responsibilities

- Build-detail infrastructure and custom metadata tables share the existing metadata typography, link treatment and 35% property column across Xcode, Gradle, Bazel, Mix and Cargo. Keep `#build-environment-table` and `#custom-metadata-table` aligned in page styles. `components/build_metadata.css` keeps the separate Infrastructure and runner Noora card compact and initially collapsed, hides its content before JavaScript mounts, and preserves a single-row header on narrow screens. Custom metadata stays inside Build Details.

- `app/css/pages/auth.css` includes the shared integration organization chooser, reusing login's logo, dots, gradients and frame. Organization rows use Noora avatars, keyboard focus states, wrapping labels and a bounded scrolling list with inset padding to preserve row borders and shadows, with a Cancel action below. Keep both provider flows visually identical and support light/dark themes and narrow viewports.

- `app/css/pages/build_entity.css` scopes the shared native task/action/module/file detail layout. Match test-case analytics spacing, wrap identity badges and controls, stack widgets on small screens, and let Noora tables own horizontal scrolling. Charts explicitly fill their section; table search/sort/filter controls and active chips use Test Case Runs spacing inside the same white card section as the table, never a separate bordered toolbar section. Header identity explanations use the shared regular small body font, secondary label color and zero paragraph margins; don't leave them as browser-default serif text. It is imported through `pages.css`.

- Expanded Xcode cache task rows append CAS outputs with a Noora Load more button; the build-run stylesheet adds spacing around the control. Loading and pagination are managed by LiveView; output IDs are not embedded in the initial table.

- Timeline summary values (elapsed time, step count and target count) use small decorative separator dots.
- Timeline metrics use a responsive 2×2 grid with independent 120px plots and subtle 2px card corners; the build-step viewport stays 600px tall. Search and the step legend sit above the step lanes below the metric grid, outside chart gesture handling, with a time ruler for each section.
- The inspector and its resize divider align with the top of the step chart section (including search and legend) and span that section only, keeping details below the metric grid. Step and metric charts share the same Noora border with a 2px radius.
- `BuildTimelineMetrics.mjs` renders CPU, memory, network and disk tracks using the same time range as build steps; each plot has its own time ruler, synchronized cursor and range-selection overlay, with coordinates scaled to its own width. Noora-styled chart cards use taller line plots, horizontal gridlines, and purple/blue series. Metric hover values appear only in each chart’s top-right readout, including both network/disk directions; floating tooltips are reserved for build steps. The initial and maximum zoom-out both show the entire build. Failed hook initialization cleans up listeners and indicators and hides partially mounted content. Samples are loaded once, culled by binary search, and keep stable scales across zooms; missing samples and collection gaps are not shown as zero readings.

- Bundle threshold modals keep controls aligned in a shared desktop grid, stack labels above controls on narrow screens, and stay within the viewport with vertical scrolling. Decimal MB help belongs below the input, not in its label; keep these styles scoped to threshold modals.

Never derive or randomly allocate reported live origins in the browser, and never increment measured live totals from arc arrivals (demo arrivals remain illustrative). `/globe` explicitly opts into a separate illustrative animation layer: fixed global city coordinates feed only regions with recent measured downloads, supplementing reported arcs to a three-arcs-per-second baseline while data is fresh and available.
