# Atlas deployment

- `values.yaml` is the standalone contract: external PostgreSQL and an operator-provided application Secret. It must render without organization destinations, custom resource definitions, or projected Tuist server credentials.
- `values-managed-production.yaml` preserves Tuist's deployment and is passed explicitly by the managed release workflow. `.helmignore` excludes it from published archives. Standalone and managed production explicitly set `ATLAS_DEMO_MODE=false`, taking precedence over Secret-sourced environment values. Rendering rejects any mismatch between `demo.enabled` and `env.ATLAS_DEMO_MODE` in either direction, so the runtime bypass cannot be enabled without the demo deployment barriers.
- `values-demo.yaml` is a separate public demo deployment layered only over standalone defaults, never the managed overlay. It requires an isolated external `atlas_demo` database, a SELECT-only application role, independent keys, and a distinct `migrationJob.appSecretName`. Its migration init container also runs operator-only fictional seeds; its NetworkPolicy permits only DNS and the explicitly selected demo PostgreSQL pods. See `atlas/deploy/demo.md`. No production connector tokens or integrations may be mounted. `test-demo-boundary.sh` verifies this rendering contract without contacting a cluster.
- Managed production enables the native iOS association for the existing `U6LC622NKF.dev.tuist.atlas` identity. Android association remains disabled until the operator sets `ATLAS_ANDROID_APP_LINK_SHA256` to the stable distribution certificate, matching the protected native-publication configuration. Never add an ephemeral CI debug fingerprint. See `atlas/deploy/AGENTS.md#native-app-links` for rollout checks.
- Managed production sources `ATLAS_CHATGPT_CLIENT_ID` from `atlas-chatgpt-oauth/client_id` in the `atlas-k8s-production` 1Password vault through the existing `onepassword` ClusterSecretStore and `atlas-app` ExternalSecret. The server and migration init container inherit the Secret via `envFrom`; do not add an explicit `env` value that would shadow it. Create the item before deploying the mapping, or reconciliation of the shared application Secret will fail. ESO refreshes hourly; changing the item does not update running process environments, so wait for Secret reconciliation and roll out Atlas afterward. Standalone defaults remain disabled. By explicit operator request, the initial value is temporarily the public Codex client used in `earendil-works/pi@be14d9732f98fcc33929cf103a92b96afaa6523e`, `packages/ai/src/auth/oauth/openai-codex.ts`, not an Atlas-specific registration or confirmation of OpenAI approval. Replace the 1Password field once an Atlas client is provisioned. The device flow uses OpenAI's own callback, not a Pi or Atlas redirect. Switching client IDs can require users to reconnect because saved refresh credentials belong to the original client. Real-account authorization still needs deployment validation. `bash test-chatgpt-config.sh` checks this wiring offline, including standalone/demo isolation and replaceable remote references.
- Application replicas are interchangeable: PostgreSQL carries Oban coordination, OAuth state, and shared rate limits; document bytes require shared object storage. Stock PubSub delivers local updates immediately, while support chats/pending POC requests reconcile every 10 seconds and account-handle snapshots every 30 seconds. Cross-replica UI updates are eventually consistent, not an instant distributed fan-out. Every replica must use the same application Secret/signing/encryption keys. No Erlang discovery, distribution ports, or sticky ingress affinity is needed. `DATABASE_URL` must provide direct PostgreSQL or session pooling because Oban's LISTEN/NOTIFY cannot use transaction-mode PgBouncer. Replica-local engineering ingest buffers retain their documented pending-window loss on abrupt termination.
- Atlas releases publish the chart and image at the same version. The chart application version selects the image unless explicitly overridden. Release publication must finish before managed deployment begins.
- Migrations use the same application Secret as the server. External databases provide `DATABASE_URL`; CloudNativePG deployments retain their generated connection Secret.
- `bash test-agent-boundary.sh` checks standalone, managed, and legacy-value rendering without contacting a cluster. Agents require no Kubernetes API token mount or pod/exec RBAC; the separately projected Tuist-audience token must remain intact. The deployment validation script runs these checks.
- `agentSandboxes` is deprecated and retains only legacy Namespace/ServiceAccount objects. The managed overlay keeps it enabled for a non-destructive first upgrade, but no longer grants pod or exec access. Only the namespace has `helm.sh/resource-policy: keep`; its service account is deleted when the flag is disabled. Deploy this retention annotation before disabling the flag; disabling it directly from an older release can delete the namespace and all its workloads. A rollback to an older revision can remove the annotation and restore the old pod/exec permissions. The managed release workflow runs `atlas/deploy/check-sandbox-retention.sh` after release recovery. It compares the stored manifest with the target render and rejects deletion or renaming of a previously managed namespace without live retention, even if ownership annotations were stripped. Manual upgrades must use the same guard. After verifying current retention and checking workloads, an operator may disable the flag and separately remove unused resources. Do not assume a source inventory proves an existing namespace is empty. No live cleanup is part of this change.
- Validate both standalone and managed rendering, chart packaging, and the Compose deployment. The public deployment guide is `atlas/priv/docs/self-hosting.md`.
- GitHub creates new registry packages as private. After the first chart publication, a package administrator must make `charts/atlas` public in package settings for anonymous registry installation. Public GitHub Release chart archives provide an installation fallback. Managed deployment authenticates to the registry.
- The application and migration container share resource settings. Cold startup exceeded the previous memory limit during standalone validation; defaults allow four gibibytes. Erlang detects available processors and container quotas unless `env.ERL_FLAGS` overrides its defaults. Keep sizing guidance aligned with the self-hosting guide.
