# Native workspace, settings, and time-off screenshot previews

These independent Once targets render the production native Settings views with fixed, in-memory API responses. They make screenshots reproducible without real provider credentials, browser authentication, a public development server, or an Atlas-authorized ChatGPT client.

The iOS `--orbit-long-history` fixture supplies 400 messages with consecutive tools and uneven Markdown heights, ending in a very tall reply. Its UI regression checks real final-line visibility on entry and after idle keyboard/multiline-draft changes in light and dark accessibility text. CPU and native scrolling metrics accompany repeated history gestures; simulator numbers are comparative evidence, not physical-device frame-rate claims.

- Fixture apps and UI suites are local opt-in tools, not CI jobs or preview-publication gates. The Atlas native workflow still runs production builds, Rust/CLI/iOS unit tests, language-specific linting, and credential-free packaging/provisioning checks.
- Build from `atlas-native/` with `ONCE_CACHE_PROVIDER=local mise exec -- once build AtlasSettingsIOSPreview` or the Android equivalent `AtlasSettingsAndroidPreview` (with the same Android SDK/NDK environment and compiler `PATH` as the production `build:android` task). Prepare vendored Rust sources serially before direct Once builds.
- `ONCE_CACHE_PROVIDER=local mise exec -- once test AtlasSettingsUITests` drives the iOS preview through native Settings, secure Claude entry, expanded instructions, and ChatGPT sign-in/cancellation in light, dark, accessibility-sized text, and landscape. It checks 44pt actions, a physical tap outside the help link's text, Save availability during secure editing, device-code accessibility, and a late save after leaving/reopening Claude. Preview-only URL handling presents the destination instead of opening a browser. Full-screen screenshot attachments preserve PNG EXIF orientation (landscape wrappers must respect it). Screenshot attachments include `ios-settings`, `ios-claude`, `ios-claude-help`, `ios-claude-keyboard`, and `ios-chatgpt`, with appearance suffixes. Export attachments outside the repository with `xcrun xcresulttool export attachments` using the result bundle reported in the test log.
- The iOS `--dark`, `--large-text`, and delayed-save launch arguments exist only in the preview, never production. The separate UI runner depends on the preview app and never installs over the real Atlas bundle.
- After building the Android preview, run `python3 previews/capture_android.py --adb /path/to/adb --output /tmp/atlas-settings-screenshots` against a booted emulator. Repeat with `--dark`, `--large-text` (2x), or `--landscape`. It restores appearance/font/rotation settings in `finally`.
- The Android script checks secure token input/clearing, 48dp actions, keyboard focus surviving background polling, pending sign-in surviving rotation, cancellation, system Back, and toolbar Up. The preview retains the same activity-independent production model across recreation, saves only its login ID, and cancels a recovered known login after process death.
- The script also enables eight preview-only model/auth regression checks in `android/AtlasAIAccountsModelChecks.kt`: cancellation after authorization won, a late save after reopening, stale credential errors, cancellation of an in-flight start, recovered cancellation retry before another start, terminal login/refresh failures, and sign-out queued behind account work. These run the actual model on Android's main looper with controlled request completions, not a mock model or live server. The sign-out check uses the actual auth worker and a dummy encrypted pending entry inside the preview application's isolated storage; there is no saved session and no network call.
- Both targets reuse actual Settings views/models. Fixtures implement the metadata/device-login contract, use the reserved `atlas.example.org` host and unmistakable `DEMO-CODE`, and never make account-management requests or enter real tokens.
- The iOS preview explicitly includes production Automation models and views because `AtlasWorkspaceView` links to them through Browse. Keep this source list aligned when adding workspace destinations; compiling only the production application does not validate the isolated preview target.
- Preview sources are outside production source globs. Bundle/application IDs end in `.settings-preview` (iOS) or `.preview` (Android). Never add fixture sources, authentication bypasses, or preview launch arguments to production apps.
- The iOS preview's `--time-off` argument renders the production employee screen with in-memory request/history/public-holiday responses. `--fail-holiday-save` exercises failed-save draft retention; appearance flags still apply. `AtlasTimeOffUITests` covers native request/edit sheets, date pickers, 44pt actions, and failure handling in dark/accessibility-sized text. Screenshot attachments are named `ios-time-off-*`.
- Android's isolated `TimeOffPreviewActivity` renders the production time-off screen/model, with native date dialogs, retained drafts across configuration changes, and Back/Up behavior. Launch with `adb shell am start -n dev.tuist.atlas.preview/dev.tuist.atlas.preview.TimeOffPreviewActivity`; `--ez fail-save true` injects a recoverable save failure. Its startup model checks cover range clamping, duplicate-submit prevention, failed-save retention, successful-save/reload-failure distinction, independent pagination, edit/resubmission rules, and cancellation guards. `capture_android.py --time-off` automates request/edit/cancel, native calendar dialogs, 48dp targets, rotation, failed-save retention, and system Back/Up; combine it with the existing `--dark --large-text` or `--landscape` flags. Set `ANDROID_SERIAL` explicitly when several emulators are running. These fixtures never enter production source globs or call a live API.
- The iOS `--workspace` flag opens the five-tab native shell, starting at Orbit (the stable `orbit` destination). Tasks is a native Browse shortcut, and business tests navigate there explicitly. `AtlasWorkspaceUITests` covers stable tabs, native-only pruned Browse/search, Time off, Profile/server details and provider navigation in default and dark/accessibility-sized text. `AtlasBusinessUITests` exercises create/edit/complete/delete in portrait and landscape, manual/imported invoice permissions, required amounts, retained failed drafts, and forbidden Finance. `AtlasBusinessPreviewData` is isolated mutable fixture storage; `--fail-business-save` and `--forbidden-finance` inject failures. Attachments are named `ios-workspace-*`, `ios-task-*`, `ios-account-*`, and `ios-invoice-*`.
- Workspace regression tests also exercise first entry to all five tabs with delayed business responses, compact presence menus in light/dark accessibility text, navigation-control separation and local-only Appearance. `--fail-orbit-refresh` fails only subsequent explicit Orbit loads: in this fixture without live channels, returning through other tabs must retain the first snapshot without an extra view-triggered load, and a failed pull-to-refresh must preserve loaded threads. Production reconciles through the Rust live-list join on each activation. These remain offline presentation fixtures, not HTTP-cache or live-reconnection evidence.
- Workspace fixtures include rich account details/contact drilldowns and a unified-currency bank overview. `AtlasWorkspaceUITests` checks initially expanded large titles, contacts/billing and Finance's no-account/missing-FX/older-server states (`--empty-finance`, `--missing-finance-fx`, `--legacy-finance`), including dark accessibility text. These flags are preview-only and grant no real authorization; backend controller tests cover scopes and revocation.
- `--business-pagination` adds more than 25 Tasks and Accounts to exercise automatic append past the first server page. Business UI tests also select native filter menus, reset criteria and group/filter expired reminders in dark/accessibility text. Fixture filtering precedes pagination just like the API; these tests do not replace backend query/authorization tests. Account images use the production public favicon endpoint independently of fixture-backed Atlas requests; initial placeholders remain available offline.
- Once 0.68.2 emits a runnable UI `.xctestrun` only through `once test`, not `once build`, and does not set a result-bundle path. Fresh checkouts need a whole-target test run before exact-unit discovery. For local evidence, run the whole target through Once on `ONCE_APPLE_SIMULATOR_UDID`, retaining its failure status, logs and reported xcresult, then rerun business/workspace/navigation/Orbit tests using `.once/out/AtlasSettingsUITests/runner/tests.xctestrun` with `xcodebuild test-without-building -resultBundlePath`. Evidence runs may disable slow sysdiagnose collection, not assertions, screenshots, or failure reporting. Export attachments with `xcresulttool` and record CRUD, scrolling, filters and navigation with `simctl io recordVideo`. Collect later evidence even if an earlier run fails, but report every failure. CI no longer uploads an `atlas-native-ui-evidence` artifact; keep local fixture-backed screenshots, recordings and results outside the repository. No real tokens or customer records enter the fixture app.
- UI assertions must account for native accessibility: section headings may be uppercased and labeled-content values combined with their labels. Measure the full link/button's 44pt target, not its child text, and wait for controls to become hittable after dismissing sheets. Set orientation after launch to prevent simulator rotation leaking between tests. Use content-bounded gestures from `AtlasUITestSupport` rather than swiping through floating tabs, fixed actions or keyboards; scroll back toward earlier virtualized controls explicitly.
- Android `BusinessPreviewActivity` renders the actual five-tab shell with production business/profile models and screens. Add `--es tab tasks|accounts|invoices|browse|profile`, `--ez fail-save true`, or `--ez permission-denied true`. Startup `AtlasBusinessModelChecks` checks paging/search, drafts, duplicate writes, successful mutations with failed refresh, deletion, late callbacks, currency separation, imported read-only state and Profile. `AtlasWorkspaceModelChecks` validates the native-only pruned catalog. The older `WorkspacePreviewActivity` remains an isolated directory harness; its legacy `capture_android.py --workspace` browser assertions are not current five-tab acceptance checks. Settings and Time off capture modes remain unchanged.
- `AtlasDestinationChecks` runs at `BusinessPreviewActivity` startup (a failed `check` crashes the preview). It reads the Rust destination allowlist through the production JNI bridge, checks accepted/rejected custom-scheme and HTTPS page/record examples, canonical `/open` sharing URLs, real-browser fallback paths, legacy Android pattern matching, and server canonicalization, the latest-only pending router (server mismatch, session end, sign-out), and direct record loading on the actual `AtlasBusinessModel` with controlled completions: superseded list reads, stale responses, read-only placeholders, unavailable/forbidden/failed/invalid states, retry, Back loading the list, and links never replacing drafts. Run them by installing the preview and starting the activity: `adb shell am start -W -n dev.tuist.atlas.preview/.BusinessPreviewActivity`, then confirm the process is alive (`adb shell pidof dev.tuist.atlas.preview`) and logcat has no `FATAL EXCEPTION`.
- `--es link '<url>'` routes a link through the production parser, router and models against the fixture server `https://atlas.example.org`. UUID `00000000-0000-4000-8000-000000000001` resolves to each resource's first fixture record; any other UUID is unavailable. Combine with `--ez permission-denied true` and an invoice link for the retryable failure state. The production `MainActivity` intent routing, unsaved-work rejection and Recents guard are not in the preview; smoke-test them with `adb shell am start -W -a android.intent.action.VIEW -d '<url>' dev.tuist.atlas`.
- Workspace previews supply in-memory presence events to the production People views; Android also accepts `--es tab people`. `AtlasPresenceModelChecks` covers stale locations, late events after backgrounding, and closing a connection that opens after backgrounding. These fixtures do not open WebSockets or verify the live transport.
- iOS `AtlasNavigationUITests` uses `--workspace --deep-links --business-pagination --destination <URI>` in the isolated preview to exercise the production destination parser/shell, a UUID beyond page one, unavailable-record Retry, server mismatch and native Back. Only preview sources read these arguments. The fixture rejects unknown record reads instead of accidentally creating a row. `--resume-destination <URI>` injects a warm fixture link after background/foreground so the UI test proves that rejection preserves a typed Claude draft and the native setup screen. Screenshot attachments are labeled `ios-navigation-*-preview`. `--revoke-record-access` denies a warm direct-record read after the list has loaded, proving cache invalidation, explicit Retry, and Back without stale rows or mutation controls.
- iOS navigation tests also inject cold/warm HTTPS URLs through the same production parser and retain screenshot evidence with the native browser escape visible. These are fixture navigation tests, not OS domain-verification tests. When iterating with Once 0.68.2, clean the Android target's `.once/out/AtlasSettingsAndroidPreview` directory before final emulator smoke if retained classes mask source edits; do not confuse a stale APK with a parser regression.
- `AtlasOrbitPreviewData` provides offline Rust-snapshot-shaped fixtures to the production iOS thread UI. `AtlasOrbitUITests` checks the flat private/shared conversation list, distinct navbar composition with empty-detail mascot/suggestions, authorized shared deep links, hidden detail tab bar and restored list tabs, current-person bubble alignment, keyboard-safe send action, 44pt controls, expandable tool evidence, and thread details. `--orbit-follow` appends a reply, grows that same message ID in stages and removes activity; combine with `--orbit-prompts` for long lazy history and test with a multiline keyboard-open draft as well as a reader scrolled away. Mention fixtures check the person picker, cancelling the first-share confirmation without promotion, then confirmed sharing and a distinct recap in light and dark accessibility text. Attachments named `ios-orbit-*-preview` are fixture-backed presentation evidence, not model execution, live WebSocket, notification delivery, authorization, or deploy-recovery tests. Shared behavior is tested in Rust, with server durability/security tested separately.
- iOS `--orbit-prompts` supplies long private/shared history and an explicit earlier page, including an attachment-only prompt. Prompt-index checks load that page, jump to an offscreen message, return to latest and retain the draft. Android startup checks cover earlier-history success/failure/retry with text and attachment drafts; prompt previews are bounded and timestamped. Native scroll, keyboard and accessibility presentation still require simulator/device interaction, not just adapter checks.
- iOS `--voice-input` renders the production waveform/discard view and microphone gestures using explicitly labeled fixed samples, never the microphone. Hold/release and tap-stop immediately append editable text without sending; no live transcript or Done step is shown. Permission-prompt cancellation is covered separately with injected Swift permission completions; the fixture never opens system permission dialogs. Composer tests measure identical 44pt send/microphone targets and center alignment with multiline drafts, keyboard and dark accessibility text. Activity tests verify the indicator is in the scrollable timeline, and account-card tests require the NSH card before expanding evidence. Its UI test verifies 44pt actions and typed-draft preservation/append in light and large dark text; it is not speech-recognition evidence. `--orbit-rich` supplies an authorized-server-shaped `account_card` v1 and agent Markdown to the production renderer, with selected-Habibi light/dark accessibility-text screenshots. `--orbit-activity` advances queued/running/compacting/idle without changing message history, checking status presentation rather than live transport. `--delayed-business` delays business responses so initial large-title/top positioning is checked after asynchronous data arrives. These arguments exist only in the isolated preview and do not invoke inference or speech recognition. Physical-device permission/audio/model availability still requires a separate voice-input smoke test.
- Thread tool fixtures include a server-shaped `result_table` v1. iOS tests exercise the actual bundled NSH runtime, measured 44pt source action, Rust-adapter effect, dark/accessibility text, scrolling and the keyboard-safe native composer. `--legacy-thread-cards` removes only the optional component to check older-server text evidence. Do not derive cards from preview tool output in production. The iOS transcript measures its bottom marker in scroll coordinates; do not use a lazy row's appearance/disappearance to drive follow-latest state, which loops layout when a large dynamic-height card scrolls across the viewport.
- Android `ThreadCardPreviewActivity` hosts the production NSH view in an isolated offline scroll view and runs `AtlasOrbitModelChecks`, including matching effects and late events after selection changes. After building/installing the preview run `python3 previews/capture_thread_card.py --adb /path/to/adb --output /tmp/atlas-card` and repeat with `--dark --large-text`. It verifies real table text, a 48dp source action and native evidence reveal, then restores font/night mode. This is renderer/adapter evidence, not a live thread or full Android messaging redesign. Both preview and production APK targets must declare `assets` as well as `asset_dirs` or Once will silently omit the bundled JS.
- Orbit destination checks append the stable capability after the existing six entries and exercise custom/page/record/canonical sharing URLs, browser fallback and legacy Android path patterns. `AtlasOrbitModelChecks` also covers cold unseen-ID selection without a loaded list, latest-only queued selection, unavailable targets retaining Retry/Back, retained-draft link protection and Back before handle open. These startup checks use controlled adapter responses; they do not prove FCM delivery, system notification expansion/lock-screen settings, MainActivity lifecycle, or server authorization. The preview intentionally excludes Firebase/push presentation sources; do not silently add those production services to this isolated target. Device smoke tests remain required; shared Rust state/typed transport tests cover actual protected reads and stale-response/revocation fences.
- Android Orbit checks include the production `AtlasOrbitAttachments.kt` boundary explicitly in the isolated Once target. Controlled model completions exercise upload/retry without native UUIDs or retained upload bytes, attachment-only sends, retained failed chips, authenticated downloads and stale foreground responses. Actual bounded-stream/name/type validation checks include exactly 5 MiB and one byte over, empty streams and unsafe names. Tool-tree checks preserve every original message through consecutive groups, a loaded parent, orphan/off-page links, malformed parents and cycles. They are host-JVM/startup adapter checks, not device photo/document-provider, temporary URI-grant, external viewer, or TalkBack evidence. Keep new automation Bash-only; existing screenshot scripts remain separate opt-in tools.
- Clearly label fixture-backed screenshots. They validate native rendering and navigation, not live OAuth/device authorization, upstream inference, or complete VoiceOver/TalkBack accessibility. Keep screenshot images outside the source branch, host them separately, and link evidence in the pull request.
- `native_themes.json` is preview-only catalog data matching the server presets. The iOS preview validates it through the real Rust bridge, scopes the production theme model around all screens and resets its local appearance on launch unless `--keep-appearance` is supplied. `--old-server` simulates an unavailable optional catalog without touching authentication. `AtlasWorkspaceUITests` selects all six themes in light/dark, checks 44pt theme rows, checks relaunch persistence, and captures older-server fallback with accessibility-sized text. `AtlasNavigationUITests` also verifies that a warm Profile link returns from Appearance without resetting the selected theme. These local opt-in tests export `ios-theme-*` screenshots. Keep this JSON out of production app resources.
