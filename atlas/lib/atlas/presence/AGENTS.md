# Presence

- People and viewing presence share `Atlas.Presence` across dashboard, native APIs and MCP. This first slice has no messaging, edit locks, typing indicators or navigation history.
- The dashboard directory uses Noora's streamed table, avatar-backed text/description cells and availability badges, matching the Users directory. Keep page-header CSS scoped to direct children so it cannot override Noora card headers; use the shared surface-label tokens for light/dark appearance.
- `presence_connections` holds one 20-second lease per user/connection, with the current allowlisted resource/record only. PostgreSQL's clock owns expiry. Native clients keep an authenticated Phoenix Channel; the browser uses its existing LiveView WebSocket. Changes publish a payload-free `:atlas_presence` invalidation through Oban's existing PostgreSQL notifier, then local PubSub subscribers read authorized snapshots and push only changes. No Erlang cluster, sticky routing, snapshot HTTP polling, or additional notification connection is required. This needs direct/session-pooled PostgreSQL, like Oban itself.
- Server-side heartbeats renew leases every ten seconds. The supervised notifier sweeps expired rows every five seconds outside Oban manual/inline test mode. A minute-level repair invalidation recovers notifications missed during a database outage; LISTEN/NOTIFY is not a durable event log. Channel termination and hidden/background clients leave; a lost browser or replica expires. User deletion cascades leases.
- Never expose locations, raw paths, drafts or record names in the company directory. Only report `here` for the caller's authorized, exact resource/record. Presence is a viewing hint, never proof that a person is editing or a concurrency lock. Aggregate multiple devices/tabs by user; leaving one connection must preserve the others.
- Browser visibility and mobile foreground/background govern availability. Graceful leave deletes only that caller's connection. Rust `atlas-native/auth/src/presence.rs` owns WSS, Phoenix framing, bounded latest-only snapshots, heartbeats, reconnect backoff and location validation. Platform adapters own foreground/background, serialized credential refresh before opening, and rendering. Tokens travel through Phoenix's authenticated WebSocket subprotocol, never URL query strings. Channel joins, location updates, invalidations and renewals recheck the stored OAuth grant and current resource permissions.
- Presence heartbeats are intentionally not audit events: retaining each navigation would create a browsing history. Personal-data inventory and backup/expiry limitations live in `atlas/data-export.md`. Public demo must not start presence or expose People.
