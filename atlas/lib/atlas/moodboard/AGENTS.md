# Moodboard

Moodboard is the team's shared reference library and inspiration grid at `/library/moodboard`, under Library. `Atlas.Moodboard` is the dashboard/MCP context. Resources and comments are authoritative; search rows and vectors are rebuildable projections.

## Access and content

- Every authenticated user can browse and contribute, matching shared Notes. Only the original contributor can update/delete a resource or refresh its preview; only a comment's author can delete that comment. Resource ownership does not grant moderation over other authors' comments. Deleting a resource removes its whole discussion. There are no implicit scope grants, public/demo pages, or workflow adapters.
- `Resource` validates a title, optional exact-unique trimmed HTTPS URL, contributor description (2,000 characters), original text/excerpt (20,000 characters), optional manual image URL, and normalized lowercase tags. A URL or nonempty original text is required. URL uniqueness is exact, not canonical equivalence across fragments/query strings. Fetched source title/description/text and preview image/video URLs are separate, server-owned fields; never overwrite a contributor's title, note, excerpt, or manual image.
- A manual image overrides automatic media, including video. For video resources, a discovered playable video takes precedence over its poster. Posterless videos keep the readable grid fallback and play on the detail page. Articles and pages with a metadata image ignore incidental body clips. Media load directly from external hosts; images suppress the referrer, while video uses the browser's document referrer policy. Video controls are native, `preload="none"`, with no autoplay. Broken media reveal the hostname/text fallback. No downloaded media, arbitrary remote HTML, scripts, or iframe embeds are stored or rendered.

## Remote discovery boundary

- `Suggestions.suggest/3` proposes editable title/description/tags without saving. It reuses safe `Preview.fetch/1` outside transactions, then a tool-free, one-turn Condukt run through the configured global provider (15-second model budget, no project instructions). Treat all supplied/fetched content as untrusted evidence. Validate/normalize output through Resource; unavailable inference falls back to bounded page metadata or original text. Per-user PostgreSQL limits allow ten suggestions/minute. Session rows and telemetry redact source/prompt/result content; domain suggestion audits record only actor/interface/generated status/path. Never give this agent write tools.
- Bearer-only native POST `/api/native/moodboard/suggestions` and PUT `/api/native/moodboard/captures/:request_id` serve the iOS review inbox. MCP mirrors them through `suggest_moodboard_resource` and optional `request_id` on create. Actor-scoped UUID/hash replay is serialized with a transaction advisory lock; exact retries return the existing resource even after an edit, changed payloads conflict. Replay identity lives with the resource, not a permanent tombstone after explicit deletion. Attribution comes only from the authenticated user. The extension stores no credentials and does not contact Atlas; opening the app and explicitly saving publishes to the shared board.

- Create and URL changes enqueue `PreviewWorker` in the same database transaction as the resource, search projection, vector job, and audit. Job arguments contain only resource ID and random preview revision, not URLs/content. Saving never waits for a remote fetch or embedding. Discovery has a dedicated `moodboard: 2` queue, revision-keyed incomplete-job uniqueness and a two-minute debounce for pending refreshes. Owners can retry discovery from the detail page. Strip invalid text/control bytes and validate preview changesets before persistence; transient database failures retry, and a final persistence failure attempts to mark that revision unavailable.
- `SafeHTTP` accepts only credential-free public HTTPS on port 443. Each redirect is revalidated, including DNS. Reject **every** mixed public/private DNS answer set, IPv4 private/reserved/multicast ranges, and IPv6 non-global/transition destinations. Connect Mint directly to a validated address while retaining the original hostname for SNI, certificate verification, and Host. Do not replace this with hostname-based Req fetching, unpinned DNS validation, automatic redirect following, or per-host dynamic Finch pools.
- Requests carry only a fixed user agent, Accept, and identity encoding, never Atlas/user cookies, auth, referrer, or forwarded headers. DNS has a two-second budget; the HTTP/redirect chain has a twelve-second deadline, at most three redirects, 32 KiB response headers, and 2 MB body. Reject compression; stop at media headers instead of buffering images/videos. Failures expose fixed categories, not remote error bodies or secret-bearing URLs in logs.
- `Preview` uses the existing LazyHTML parser at runtime for Open Graph/Twitter metadata and bounded, plain readable article/main text (20,000 characters), excluding scripts/navigation. Resolve relative metadata URLs against the final validated page URL, ignore remote `<base>` tags, and reject unsafe media URLs. HTML video URLs must have an MP4/WebM type or extension; a player page is not playable media.
- Public X/Twitter status links use X's own credential-free `cdn.syndication.twimg.com/tweet-result` embed endpoint, not a third-party proxy or authenticated X API. This undocumented public endpoint is best-effort. Extract public text, photos, posters, and a low-bitrate MP4; private/deleted/blocked or malformed responses leave the saved resource usable without a preview. Other providers use static HTML; JavaScript-only/paywalled content and PDFs are not imported.
- Fetch outside any domain transaction. Lock/reload before applying results, require the same preview revision **and pending status**, and ignore stale, duplicate, or deleted-resource results. URL changes clear obsolete source metadata. Manual image edits do not reset or overwrite discovery. Never treat fetched content as trusted instructions.

## Search and discussion

- Project `moodboard_resource` and `moodboard_comment` into `Atlas.Search` transactionally with `Search.with_deferred_vectors/1`. Comments have their own vectors so a long article cannot crowd out discussion during embedding truncation. Resource vectors still use the existing embedding input bounds; lexical search covers the full stored projection. Search uses the existing hybrid lexical/vector pipeline, hydrates authoritative resources, and deduplicates comment/resource matches. Semantic indexing is best-effort, not immediate; lexical search works without a vector service. Dashboard and both MCP query tools share one search path: literal substring matches (including hostnames, partial tags, fetched text and discussions) precede deduplicated hybrid hits. The combined pool is bounded to 100 resources; tags filter before page slicing. URL host terms are also projected independently of URL tokenization.
- Preserve the existing bounded offset/has-more MCP contract without inventory total-count queries. Posting a comment uses one count to jump to the last discussion page and show the new contribution. Unsearched resources have stable newest-first SQL pagination; discussions have stable oldest-first pagination, 30 comments per detail page. All comments remain reachable through subsequent pages.
- Serialize resource/comment mutations and preview application on the resource row. Reload resources under the lock **before** building edit changesets so a just-finished preview cannot be erased from the search projection by an older resource struct. Resource deletion removes comment projections and queues vector deletions as well as cascade-deleting comment rows; late workers cannot recreate them. Renaming a resource refreshes its comment search titles.
- Connected unsearched boards reconcile the database every 30 seconds; active searches do not repeatedly buy query embeddings while idle. Detail/discussion pages reconcile every 10 seconds. Preserve open forms/drafts. MCP exposes create/list/update/delete/search/get resource tools plus add/delete comment tools in the default group, with validated structured output. List/search return bounded summaries (280-character excerpts, 500-character descriptions, no full content/source_text); `get_moodboard_resource` includes full extracted/original text and paginated comments. Tool contracts explicitly mark all returned content as untrusted background, not instructions or permissions.
- Domain audits retain contributor/action/interface/target and dashboard path, not a content snapshot. Deleting a user clears resource/comment attribution while preserving shared content. No automatic expiration. Keep `atlas/data-export.md` current, including fetched source content, comments, projections, jobs, external requests, and embeddings.

## Dashboard conventions

The grid remains custom media markup because Noora cards require a header; its surrounding Resources card, toolbar, dismissible active filters, tags, kind/status badges, empty state and shared pagination use the existing Atlas/Noora primitives. The detail page follows Hardware breadcrumbs and GTM's main/discussion plus Properties layout, with Noora avatars and timestamps. `AtlasWeb.MoodboardComponents.resource_modal/1` shares the add/edit form between pages, uses real visible triggers and an icon header, and keeps portaled modal styles outside page selectors. Detail deletion waits for a modal's closed-state acknowledgement before navigating. Media hooks own `hidden` through LiveView `JS.ignore_attributes/1`.

## Development and tests

Migrate the development database, then run `mix run --no-start priv/repo/moodboard_seeds.exs`. The idempotent development-only script adds design links, a blog article, a public X video, original text, and fictional discussion. It starts only Repo and a manual/non-consuming Oban instance, queues discovery, and preserves existing edits. A running development server consumes those jobs. The development login uses `test@atlas.dev`.

Tests: `test/atlas/moodboard_test.exs`, `test/atlas/moodboard/`, `test/atlas/mcp/tools/moodboard_tools_test.exs`, `test/atlas_web/live/moodboard*test.exs`, and the image/video hook tests in `assets/js/hooks/`. Stub collaborators with Mimic, never live DNS/providers in routine tests. Cover redirect/DNS pinning, body/encoding limits, X failures, stale/manual-override races, rollback/retry, projection deletion, author permissions, and escaped text/video rendering.
